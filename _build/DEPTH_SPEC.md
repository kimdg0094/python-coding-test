## 0. 왜 하는가 — 진단 결과

사이트 평가에서 나온 결손을 데이터로 확인했다.

- Tutorial(101)에만 **✅ 마스터 체크리스트 / ⚠️ 자주 하는 실수**가 있고, 트레일 45개 챕터에는 사실상 없다(체크리스트 1개 파일, 실수 0개).
- **그림·도식이 0건**이다(mermaid 0, SVG 0, 박스드로잉 1개 파일). 격자 밀기·트리·DP 표처럼 그림 없이는 안 붙는 개념이 글로만 설명된다.
- 트레일 구조가 `개념 → 접근 전략 → 문제` 3단이라 **유도·추적·템플릿이 들어갈 자리가 없다.**
- 결과적으로 서술은 정확하지만 **압축된 코테 요약**이고, 이론서를 대체하지 못한다.

목표는 **"사이트만 보고도 처음 배우는 사람이 이해할 수 있는" 수준**이다. 요약을 늘리는 게 아니라, 없던 종류의 설명(그림·유도·추적·정리)을 채운다.

## 2. Part A — 레슨 개념 심화

### 2.1 절대 규칙 (어기면 사이트가 깨진다)

- **기존 줄을 고치거나 지우지 않는다. 오직 새 줄을 끼워 넣는다.** 오타가 보여도 고치지 마라(별도 보고).
- 삽입 위치는 **`**개념**` 블록 안, `**접근 전략**` 줄 바로 앞**뿐이다.
- `**접근 전략**`, `**문제**`, ` ```runner ` 블록과 그 이후는 **한 글자도 건드리지 않는다.**
- ` ```runner ` 안에 중첩 펜스 금지 규칙은 그대로다(러너를 아예 안 만지면 자동으로 지켜진다).

### 2.2 넣을 수 있는 3종 블록

라벨은 아래 형식을 정확히 지킨다(굵게, 단독 줄).

#### (1) `**그림으로 보기**`
글로는 안 붙는 구조·동작을 도식으로 보여준다. **이 챕터에서 가장 중요한 산출물이다.**

- 대상: 자료구조 모양(트리·연결리스트·힙·격자), 상태 변화(밀기·회전·정렬 패스), 표(DP 테이블·누적합), 흐름(BFS 층·재귀 호출).
- ```` ```text ```` 펜스 안에 박스드로잉/ASCII로 그린다. 도식 위나 아래에 한 줄 캡션을 둔다.
- **한 줄 80자 이내.** 넘으면 가로 스크롤이 생겨 읽기 나쁘다.

#### (2) `**손으로 따라가기**`
작은 입력 하나를 골라 **단계별로 추적**한다. "돌려보지 않아도 머릿속에서 실행되는" 상태를 만드는 게 목적이다.

- 마크다운 표를 쓴다. 열은 `단계 | 변수들… | 설명` 형태.
- 입력은 최대한 작게(원소 4~6개, 격자 3×3, 재귀 깊이 3).
- 마지막 줄에 최종 답이 어떻게 나왔는지 한 줄.

#### (3) `**왜 이렇게 되는가**`
공식·점화식·복잡도가 **어디서 나왔는지 유도**한다. 결과만 적지 않는다.

- 점화식: 상태 정의 → 마지막 선택을 무엇으로 쪼개는지 → 식 → 초기값 → 계산 순서.
- 복잡도: 반복/재귀 횟수를 세는 과정을 보여주고 지배항을 남긴다.
- 정당성: 그리디면 교환 논증, 이진탐색이면 단조성, 자료구조면 왜 그 연산이 O(1)/O(log n)인지.

### 2.3 도식 스타일 가이드 (중요)

이 사이트의 코드 폰트는 `JetBrains Mono → D2Coding → Consolas`다. JetBrains Mono에는 **박스드로잉·도형·한글 글리프가 없어** 그 글자들만 다른 폰트로 대체되고, 대체 폰트의 폭이 달라 칸이 어긋난다. 브라우저 실측 결과 ASCII 1.00 / 박스드로잉 0.92 / `◀▶`·한글 1.79 였다.

- ✅ **도식 안 정렬이 필요한 자리에는 ASCII·숫자·박스드로잉만.**
- ✅ 한글 설명이 도식 안에 꼭 필요하면 **줄 끝 `#` 주석으로만** 쓴다(그 뒤에는 정렬할 게 없으므로 무해). 그 외의 한글은 **도식 밖 캡션**으로 뺀다.
- ❌ 박스 **안**이나 줄 **앞**에 한글을 넣어 칸을 맞추려 하지 마라. `레벨0:  [ n ]  합 n` 같은 줄은 폰트가 바뀌면 전부 어긋난다.
- 검증기가 이 규칙을 강제한다: `python _build/verify_depth.py --diagrams`
- **도식은 ASCII만 쓴다.** 박스드로잉(`─│┌┼`)과 도형(`▲▼◀▶●○`)은 폰트마다 폭이 **0.92 / 1.79 / 2.00** 으로 달라져 칸이 어긋난다(브라우저 실측). 어떤 폰트에서도 1.00 인 것은 ASCII 뿐이다.
- 쓸 문자: 테두리 `- | + =` · 방향 `^ v < >` · 표시 `* o # .` · 대각선 `/ \`

```text
  +-----+-----+       ^  up        * = current cell
  |  2  |  2  |    <  o  >         o = visited
  +-----+-----+       v  down
```

좋은 예(2048 좌로 밀기):

```text
  before          after
 +--+--+--+--+   +--+--+--+--+
 | 2| 2| .| 4|   | 4| 4| .| .|    # 2+2 merge -> 4
 +--+--+--+--+   +--+--+--+--+    # then 4 slides left
   0  1  2  3      0  1  2  3
```

좋은 예(BFS 층):

```text
        (1)              dist
       /   \             ----
     (2)   (3)           1 : 0
     / \      \          2 : 1   <- layer 1
   (4) (5)    (6)        3 : 1
                         4 : 2   <- layer 2
```

나쁜 예 1 — 박스드로잉(폰트마다 폭 0.92):

```text
 +------+------+
 | 2500 | 2502 |     <- 테두리에 U+2500 계열을 쓰면 ASCII 줄과 안 맞는다. 금지.
 +------+------+
```

나쁜 예 2 — 칸 안에 한글:

```text
 +------+------+
 | start| visit|     <- 칸 안은 영문/숫자로. 한글은 줄 끝 # 주석으로만.
 +------+------+
```

### 2.4 분량 기준

- **그림이 필요한 레슨에는 반드시 그림을 넣는다.** 최소 기준: 챕터당 `**그림으로 보기**` **3개 이상**.

## 3. Part B — 챕터 마무리 레슨 (`ch{NN}z.md`)

### 3.1 파일 형식

파일은 `## L{K}.` 로 시작한다. `K` = 그 챕터 마지막 레슨 번호 + 1(= `ch{NN}x.md`의 레슨 번호 + 1). 조각 병합 순서가 `'' < a < b < c < x < z`라 이 레슨이 챕터 맨 끝에 온다.

```
## L{K}. 정리 — 개념 지도·체크리스트·자주 하는 실수

**개념**

(아래 5개 절을 이 순서로. `**문제**` 절은 만들지 않는다.)
```

### 3.2 5개 절

굵은 라벨 단독 줄로 구분한다.

1. **`**개념 지도**`** — 챕터 전체를 도식 한 장으로. 개념들이 어떻게 이어지는지(무엇이 무엇의 기초인지, 언제 갈라지는지). 2.3 도식 규칙 적용.

2. **`**뼈대 코드**`** — 이 챕터 유형을 만나면 바로 쓸 수 있는 템플릿 2~5개. ```` ```python ```` 펜스. 문제마다 바뀌는 부분은 `# ← 문제마다 바뀜` 주석으로 표시. 실행 가능한 완전한 코드일 필요는 없다(뼈대).

3. **`**언제 무엇을 쓰나**`** — 선택 기준 표. 열: `상황 | 고르는 것 | 이유 | 복잡도`. 이 챕터 도구들 사이의 갈림길을 표로 못 박는다.

4. **`**✅ 마스터 체크리스트**`** — Tutorial 스타일. `- [ ] 설명할 수 있다: …` 형태로 8~15개. "코드를 짤 수 있다"가 아니라 **"남에게 설명할 수 있다"** 기준으로 쓴다.

5. **`**⚠️ 자주 하는 실수**`** — 5~10개. 각 항목은 반드시 **틀린 코드 → 왜 틀리는지 → 고친 코드** 3단으로. 추상적인 훈계("경계값을 조심하라") 금지, 구체적 코드로.

   ```python
   # ❌ 틀린 코드
   for i in range(n):
       if arr[i] == arr[i+1]:   # i가 마지막일 때 IndexError
   ```

   왜: `range(n)`의 마지막 `i`는 `n-1`이라 `arr[n]`을 읽는다.

   ```python
   # ✅ 고친 코드
   for i in range(n - 1):
       if arr[i] == arr[i+1]:
   ```

6. (선택) **`**다음 챕터로**`** — 이 챕터가 다음 챕터의 무엇으로 이어지는지 2~3줄.

### 3.3 분량

- 챕터당 120~250줄. 도식·표·코드가 대부분이고 산문은 적게.

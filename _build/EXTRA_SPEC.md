# 「추가 연습」 레슨 작성 규격 (python_learning.html 전용)

## 0. 목적
- 각 트레일 챕터의 **맨 끝에 레슨 하나**를 추가한다: `## L{K}. 추가 연습 — 핵심 반복 × 유형 확장`
- 목표는 두 가지: (a) **반복 훈련** — 그 챕터의 핵심 개념을 소재만 바꿔 여러 번 다시 쓰게 한다. (b) **유형 확장** — 백준 단계별/solved.ac CLASS/프로그래머스 고득점 Kit/이코테/NeetCode 150/삼성 SW 역량테스트에 자주 나오는 대표 유형을 **그 챕터 수준으로 새로 창작**해 넣는다(원문 문제를 베끼지 말고 소재·수치·조건을 새로 만든다).
- 산출물: `trails/<trail>/ch{NN}x.md` **새 파일** (접미사 `x`는 기존 `''/a/b/c` 조각 뒤에 병합된다). **기존 파일은 절대 수정하지 않는다(읽기만).**

## 1. 파일 구조 (정확히 이 순서)
```
## L{K}. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch{NN}(챕터 이름)의 핵심을 **반복 훈련**하고, 코딩테스트 단골 유형으로 **확장**하는 연습 세트다. (1~2줄)
- **반복 훈련 개념**: 챕터 핵심 개념 3~5개를 각각 한 줄 + 아주 짧은 코드 패턴(인라인 `code`)으로.
- **코딩테스트 출제 맵**: 이 챕터 유형이 등장하는 외부 자료를 실제 존재하는 이름으로만 언급 — 예) 백준 「단계별로 풀어보기」의 '반복문'·'1차원 배열' 단계, solved.ac CLASS 2, 프로그래머스 「코딩테스트 고득점 Kit」의 '해시'·'스택/큐'·'힙'·'정렬'·'완전탐색'·'탐욕법'·'동적계획법'·'DFS/BFS'·'이분탐색'·'그래프', 『이것이 취업을 위한 코딩테스트다』의 '그리디'·'구현'·'DFS/BFS'·'정렬'·'이진탐색'·'DP'·'최단경로'·'그래프이론' 파트, NeetCode 150의 'Arrays & Hashing'·'Two Pointers'·'Sliding Window'·'Stack'·'Binary Search'·'Linked List'·'Trees'·'Heap'·'Backtracking'·'Tries'·'Graphs'·'1-D/2-D DP'·'Greedy'·'Intervals'·'Bit Manipulation', 삼성 SW 역량테스트의 '시뮬레이션·BFS·백트래킹' 유형. **해당되는 것만** 골라 1~3개 언급.
- **문제 구성표**: 아래 표 (문제 수만큼 행)

| # | 문제 | 난이도 | 반복 개념 | 유형 |
|---|------|--------|-----------|------|
| 1 | 제목 | Easy | cnt 누적 | 반복 훈련 |
| 2 | 제목 | Medium | ... | 유형 확장 (프로그래머스 Kit '해시' 스타일) |

**문제**

**1) 제목** · Easy

- **요구사항**: ...
- **입력**: ...
- **출력**: ...
- **예제**: `입력` → `출력` · `입력2` → `출력2`   (여러 줄 입력은 ` / `로 줄 구분, 기존 챕터 스타일을 따른다)
- **셀프체크**: 경계값·흔한 실수·검산 포인트 1~3개.

```runner
@@SOLUTION
(정답 코드 — 펜스 없이 raw)
@@TESTS
--IN
(입력)
--OUT
(출력)
--IN
(입력2)
--OUT
(출력2)
@@EXPL
(1) 접근·핵심 아이디어

- ...

(2) 코드 단계별

- ...

(3) 스스로 다시 짤 때 생각 순서

- ...
```

**2) 제목** · Easy
... (반복)
```
- `K` = 그 챕터의 **마지막 레슨 번호 + 1**. 챕터가 `ch03a.md`(L1~L5)+`ch03b.md`(L6~L10)처럼 나뉘어 있으면 모든 조각을 보고 마지막 번호를 확인한다.
- 레슨 번호는 챕터 안에서 이어지고, **문제 번호는 레슨 안에서 1부터** 다시 시작한다.
- 파일은 `## L{K}.` 줄로 시작한다(그 위에 `>` 개요 줄이나 다른 제목을 두지 않는다).

## 2. 문제 카드 규칙
- 제목 줄은 정확히 `**N) 제목** · Easy|Medium|Hard` (가운뎃점 `·` U+00B7, 앞뒤 공백 1칸). 제목에 `**`나 `·`를 넣지 않는다.
- 본문 항목 5개(**요구사항**, **입력**, **출력**, **예제**, **셀프체크**)는 **모두 필수**. 입력 범위(제약)를 **입력** 항목에 적는다.
- 본문 안 어떤 줄도 `**숫자)`로 시작하면 안 된다(새 문제로 인식됨).
- **예제**에 적은 입출력은 러너의 @@TESTS에 **그대로** 포함시킨다.

## 3. 러너 블록 규칙 (가장 중요)
- ```` ```runner ```` 안에 `@@SOLUTION` → `@@TESTS` → `@@EXPL` 순서, 각각 정확히 1번.
- 러너 안에 **다른 ``` 펜스 금지**. 풀이(@@EXPL)에서 코드를 보이고 싶으면 인라인 `code`만 쓴다.
- @@SOLUTION
  - 표준입력(`input()` 또는 `sys.stdin`)으로 읽고 `print`로만 출력. **표준 라이브러리만** 사용(외부 패키지 금지). 파일·네트워크·시드 없는 랜덤 금지.
  - 브라우저(Pyodide)에서 실행되므로 **테스트 1개당 1초 이내**. 테스트 입력은 작게(수십~수백 원소). 재귀는 깊이 수천 이하가 되도록 입력 크기를 설계한다(`sys.setrecursionlimit`은 써도 되지만 10만 이하).
  - **문법 수준 제한**: 정답 코드는 **그 챕터까지 배운 문법 범위**에서만 쓴다. 담당 챕터의 기존 정답 코드가 쓰는 문법 수준을 기준으로 삼는다(예: novice-low ch01~03은 함수·리스트·컴프리헨션·람다 금지, ch01은 입력 없이 print만, ch04 이전은 반복문 금지, ch07 이전은 리스트 금지 등). 부득이하게 한 단계 앞선 문법을 쓰면 @@EXPL 첫 줄에 한 줄로 간단히 설명한다.
- @@TESTS: 테스트 **2~4개**. 본문 **예제**와 동일한 케이스 + **경계값 케이스 1개 이상**(최소 크기, 0/음수, 전부 같은 값, 정답이 없는 경우 등). 출력은 정답 코드를 실제로 돌려 얻은 값과 **문자 단위로 정확히** 같아야 한다(검증 스크립트가 확인).
- @@EXPL: `(1) 접근·핵심 아이디어 / (2) 코드 단계별 / (3) 스스로 다시 짤 때 생각 순서` 3부 구성(각 2~5개 불릿). novice-low는 기존 챕터의 `접근: / 코드 진행: / 재작성 사고 순서:` 스타일을 따라도 된다. 풀이는 **왜 이렇게 푸는지**와 **함정(경계값)** 을 반드시 언급한다. 최소 6줄 이상.

## 4. 구성 원칙 (난이도·반복·확장)
- 배치는 **Easy → Medium → Hard 순**. 난이도 비율은 담당 표를 따른다.
- **반복 훈련(전체의 50~60%)**: 챕터 핵심 개념을 **다른 소재·다른 입력 형식**으로 다시 쓰게 한다. 같은 개념을 최소 2~3번 다른 문제로 만나게 할 것(예: "cnt 누적"을 점수·문자·좌표 소재로 3문제). 단, 문장만 바꾼 복제는 금지 — 소재·조건·함정이 달라야 한다.
- **유형 확장(전체의 40~50%)**: 외부 자료의 대표 유형을 이 챕터 수준으로 재구성. 구성표의 「유형」 칸에 어떤 자료 스타일인지 적는다.
- **기존 문제와 중복 금지**: 담당 챕터(모든 조각 파일)의 기존 문제 제목·요구사항을 먼저 읽고, 소재·요구사항이 겹치지 않게 한다.
- **Hard**의 뜻: 무작정 어려움이 아니라 "개념 2~3개 결합 + 경계값 함정 + 약간 긴 구현". 입력 크기는 작게 유지한다.
- 모든 문제는 **정답이 유일**해야 한다(여러 답이 가능한 출력 형식 금지. 예: "아무 순서로 출력" 금지 → 오름차순 등으로 고정).
- 문제 제목은 구체적으로(예: "회의실 최대 배정", "괄호 균형 복구") — "연습 1" 같은 제목 금지.
- 한국어로 쓴다. 코드 주석은 짧게, 한국어 가능.

## 5. 검증 (필수)
```
python _build/verify_file.py trails/<trail>/ch{NN}x.md
```
- `=> OK`가 나올 때까지 수정한다. ERROR 0건, 가능하면 WARN 0건.
- 검증은 정답 실행·출력 일치·구조(항목·번호·난이도·중첩 펜스·C++ 언급)를 모두 본다.

## 6. 금지 사항
- 기존 `.md` 파일 수정 금지(읽기 전용). 빌드 스크립트(`build_html.py`) 실행 금지 — 최종 빌드는 오케스트레이터가 한다.
- C++·다른 언어 언급 금지(파이썬 사이트).
- 외부 문제의 지문·수치를 그대로 옮기는 것 금지(저작권). 유형만 참고해 새로 창작.

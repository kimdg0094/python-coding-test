## L5. 정리 — 개념 지도·체크리스트·자주 하는 실수

**개념**

- 이 레슨은 Ch06(완전탐색 I) 전체를 한 장으로 묶는 정리다. 세 레슨은 "후보가 무엇이냐"만 다를 뿐, **후보를 빠짐없이 나열하고 조건을 검사한다**는 뼈대가 완전히 같다. 그리고 그 앞에는 항상 "다 세도 되는가"를 계산하는 단계가 있다.

**개념 지도**

- 완전탐색의 갈래는 "무엇 하나를 후보로 볼 것인가"로 나뉜다. 후보가 정해지면 개수를 세는 공식도 함께 정해지고, 그 개수가 코드를 짤지 말지를 결정한다.

```text
                     Ch06 : brute force I
                              |
        +---------------------+---------------------+
        |                     |                     |
   ONE NUMBER            ONE RANGE            ONE ARRANGEMENT
   candidate = n         candidate = (i, j)   candidate = (s1..sn)
        |                     |                     |
   L1 digit scan         L2 subarray scan     L3 slot by slot
   for n = a..b          for i , for j        nested for / rec
   to_string or % 10     running sum s        rec(pos) depth n
        |                     |                     |
   count = b - a + 1     count = n(n+1)/2     count = m ^ n
        |                     |                     |
        +---------------------+---------------------+
                              |
              step 0 : count first, then write code
```

- "다 세도 되는가"를 판단하는 자는 하나뿐이다. **후보 수 × 후보 하나당 검사 비용**을 곱해 보고, C++ 기준 1초에 약 10^8 단계라는 예산과 비교한다.

```text
  budget : about 10^8 simple steps per second (C++)

  candidates      x  cost   =  total          verdict
  ----------------------------------------------------------
  10^5 (a..b)        7         7 * 10^5       fine
  2000^2 / 2         1         2 * 10^6       fine     // O(n^2), n=2000
  3^10               10        6 * 10^5       fine
  9^7                7         3 * 10^7       fine
  10^8               1         10^8           tight
  10^5 ^ 2           1         5 * 10^9       impossible
```

- 자리마다 값을 정하는 탐색은 트리로 그리면 개수가 눈에 보인다. 잎 하나가 후보 하나이고, 가지 수가 `m`, 깊이가 `n`이면 잎은 `m^n`개다.

```text
  n = 3 slots, values = {1, 2}   ->   2^3 = 8 leaves

                 root
            /            \
          1                2         slot 1
        /   \            /   \
       1     2          1     2      slot 2
      / \   / \        / \   / \
     1   2 1   2      1   2 1   2    slot 3
```

**뼈대 코드**

- (1) 자리 수 단위: 범위 안의 정수를 하나씩 후보로 본다.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int a, b, k;
    cin >> a >> b >> k;
    int cnt = 0;
    for (int n = a; n <= b; n++) {          // "이상/이하"를 그대로 옮긴다(<= 주의)
        int value = 0;
        for (char ch : to_string(n))        // 자릿수를 봐야 하면 문자열이 가장 짧다
            value += ch - '0';              // 문제마다 바뀜: 계산할 값
        if (value % k == 0) cnt++;          // 문제마다 바뀜: 조건
    }
    cout << cnt << '\n';
    return 0;
}
```

- (2) 구간 단위: 모든 `(i, j)`를 훑되 합은 누적으로 굴린다.

```cpp
long long best = LLONG_MIN;         // 음수 대비: 0으로 두지 않는다
int cnt = 0;
for (int i = 0; i < n; i++) {       // 구간 시작
    long long s = 0;                // 반드시 바깥 루프 '안'에서 초기화
    int mn = arr[i], mx = arr[i];
    for (int j = i; j < n; j++) {   // 구간 끝을 한 칸씩 늘린다
        s += arr[j];                // arr[i..j] 의 합을 O(1) 로 유지
        mn = min(mn, arr[j]);
        mx = max(mx, arr[j]);
        if (s == target) cnt++;     // 문제마다 바뀜: 조건
        best = max(best, s);
        // 조기 종료는 조건이 단조일 때만!
        // if (mx - mn > d) break;
    }
}
```

- (3) 자리마다 값 정하기: 자리 수가 고정이면 중첩 for, 변수면 재귀나 비트마스크.

```cpp
// 자리 수가 코드에 박혀 있을 때 (2자리)
for (int x = 1; x <= d; x++)
    for (int y = 1; y <= d; y++) {
        // 여기서 (x, y) 조건 검사
    }

// 자리 수 n 이 입력으로 올 때 — 위와 완전히 같은 것을 만든다
int n, d, cnt = 0;
vector<int> combo;

void rec(int pos) {
    if (pos == n) {
        bool ok = true;
        for (int i = 0; i + 1 < n; i++)     // 문제마다 바뀜: 조건
            if (combo[i] == combo[i + 1]) { ok = false; break; }
        if (ok) cnt++;
        return;
    }
    for (int v = 1; v <= d; v++) {
        combo[pos] = v;
        rec(pos + 1);
    }
}

// 값이 두 가지({0,1})뿐이면 재귀 없이 비트마스크 한 줄로도 된다
for (int mask = 0; mask < (1 << n); mask++) {   // n >= 31 이면 1LL << n
    // mask 의 각 비트가 한 자리의 값
}
```

- (4) 경우의 수 계산: 코드를 짜기 전에 이 표를 먼저 채운다.

```cpp
// 후보 수 세는 공식 (검산용 — 코드는 완전탐색으로 짜도 된다)
//   범위 정수         : b - a + 1
//   모든 연속 구간    : n * (n + 1) / 2
//   길이 L 고정 구간  : n - L + 1
//   자리 n, 값 m 가지 : m ^ n
//   첫 자리만 0 금지  : (m - 1) * m ^ (n - 1)
//   이웃 자리 상이    : d * (d - 1) ^ (n - 1)
//   n칸 중 k칸만 'A'  : C(n, k) * 2 ^ (n - k)

long long total = 1;
for (int i = 0; i < n; i++) total *= m;     // pow 는 실수라 오차가 난다
cerr << total << " candidates\n";           // 10^8 을 넘으면 다른 방법을 찾는다
```

- (5) 세기·최선값 고르기의 공통 마무리.

```cpp
int cnt = 0;
bool found = false;                 // 최댓값 초기값을 0으로 두지 않는다
long long best = 0;
for (auto& cand : candidates) {     // 위 세 골격 중 하나
    if (!passes(cand)) continue;    // 문제마다 바뀜: 조건
    cnt++;
    long long v = score(cand);      // 문제마다 바뀜: 평가값
    if (!found || v > best) { best = v; found = true; }
}
```

**언제 무엇을 쓰나**

| 상황 | 고르는 것 | 이유 | 복잡도 |
|---|---|---|---|
| a 이상 b 이하의 수를 검사 | `for (int n = a; n <= b; n++)` | 후보가 정수 하나씩이라 가장 단순 | O(b−a) |
| 자릿수 합·포함·회문 판정 | `to_string(n)`으로 한 글자씩 | 0 처리가 자연스럽고 표기를 통째로 본다 | 후보당 O(자리 수) |
| k진 자릿수 값이 필요 | `% k`, `/= k` 반복 | 문자 변환 없이 값 자체를 얻음 | 후보당 O(log n) |
| 모든 연속 구간을 봐야 함 | 이중 for + 누적 합(`long long`) | 구간마다 원소 하나만 더하면 됨 | O(n²) |
| 길이가 정확히 L인 구간 | 시작점만 이동(슬라이딩) | 끝점이 시작점에 종속 | O(n) |
| 구간 폭이 단조로 커짐 | 조건 위반 시 `break` | 더 늘려도 회복 불가 | 평균이 크게 줄어듦 |
| 자리 수가 코드에 고정(2~3) | for 중첩 | 읽기 쉽고 인덱스 실수가 적음 | O(mⁿ) |
| 자리 수가 입력 변수 | 재귀 `rec(pos)` | 중첩 개수를 코드로 못 바꿈 | O(mⁿ) |
| 각 자리의 값이 두 가지 | 비트마스크 `for (mask...)` | 재귀 없이 한 줄, 상수도 빠름 | O(2ⁿ · n) |
| 자리마다 후보 집합이 다름 | 자리별 후보 벡터를 따로 | 자리별 제약을 집합에 반영 | 곱만큼 |
| 후보 수가 10^8을 넘음 | 완전탐색 포기 | 1초 예산 초과 | — |

**✅ 마스터 체크리스트**

- [ ] 설명할 수 있다: 완전탐색의 두 단계("후보를 빠짐없이 나열" + "조건 검사")와, 그 앞에 경우의 수 계산이 오는 이유.
- [ ] 설명할 수 있다: a 이상 b 이하의 정수가 `b - a + 1`개인 이유와, 그것이 `for (n = a; n <= b; n++)`와 맞아떨어지는 이유.
- [ ] 설명할 수 있다: 길이 n 배열의 연속 구간이 `n(n+1)/2`개인 것을 시작점별로 세어 유도할 수 있다.
- [ ] 설명할 수 있다: 안쪽 루프에서 누적 변수를 쓰면 왜 O(n³)이 O(n²)로 줄어드는지.
- [ ] 설명할 수 있다: 자리 n개·값 m가지의 경우의 수가 `mⁿ`인 이유를 곱의 법칙과 트리 잎 개수로 각각.
- [ ] 설명할 수 있다: "이웃한 자리가 달라야 한다"는 제약이 붙으면 왜 `d·(d-1)^(n-1)`이 되는지.
- [ ] 설명할 수 있다: 재귀 `rec(pos)`가 for 중첩과 같은 것을 만든다는 사실과, 그럼에도 재귀가 필요한 상황.
- [ ] 설명할 수 있다: 후보 수와 검사 비용을 곱해 1초 안에 되는지 판단하는 기준(C++ 약 10^8 단계).
- [ ] 설명할 수 있다: `n`을 1 늘리는 것이 `m`을 1 늘리는 것보다 훨씬 위험한 이유.
- [ ] 설명할 수 있다: 문제의 제약이 유난히 작을 때(`n ≤ 7` 등) 그것이 무엇을 뜻하는 신호인지.
- [ ] 설명할 수 있다: 조기 종료(`break`)가 정당한 조건과, 음수가 섞였을 때 위험한 이유.
- [ ] 설명할 수 있다: 구간 합을 `int`로 받으면 왜 조용히 틀리는지, 언제 `long long`이 필요한지.
- [ ] 설명할 수 있다: `1 << n`이 `int` 범위를 넘는 시점과 `1LL << n`이 필요한 이유.
- [ ] 설명할 수 있다: 최댓값 변수의 초기값을 0으로 두면 안 되는 경우와 그 대안.
- [ ] 설명할 수 있다: 완전탐색으로 얻은 답을 닫힌 식(`nCr` 등)으로 검산하는 방법.

**⚠️ 자주 하는 실수**

**1) 범위의 끝이 하나 빠진다**

```cpp
// ❌ 틀린 코드
for (int n = a; n < b; n++) {   // b 자신을 검사하지 않는다
    if (ok(n)) cnt++;
}
```

왜: 문장이 "a 이상 b 이하"인데 `n < b`는 `b-1`에서 멈춘다. 답이 딱 1 모자라게 나오는 전형적인 오답이라, 예제가 우연히 맞으면 끝까지 못 찾는다.

```cpp
// ✅ 고친 코드
for (int n = a; n <= b; n++) {  // "이하"는 <=
    if (ok(n)) cnt++;
}
```

**2) 누적 변수를 바깥에서 한 번만 초기화한다**

```cpp
// ❌ 틀린 코드
long long s = 0;
for (int i = 0; i < n; i++) {        // 시작점이 바뀌어도 s 가 이어진다
    for (int j = i; j < n; j++) {
        s += arr[j];
        if (s == target) cnt++;
    }
}
```

왜: `s`는 "현재 시작점 `i`에서 시작한 구간의 합"이어야 한다. 바깥에 두면 이전 시작점의 합이 그대로 남아, 두 번째 `i`부터는 존재하지 않는 구간의 합을 검사한다.

```cpp
// ✅ 고친 코드
for (int i = 0; i < n; i++) {
    long long s = 0;                 // 시작점이 바뀔 때마다 리셋
    for (int j = i; j < n; j++) {
        s += arr[j];
        if (s == target) cnt++;
    }
}
```

**3) 구간 합을 `int`로 받는다**

```cpp
// ❌ 틀린 코드
int s = 0;
for (int j = i; j < n; j++) {
    s += arr[j];                     // 원소가 1e9 급이면 금방 넘친다
    if (s == target) cnt++;
}
```

왜: `int`는 약 21억까지다. 원소가 10^9이고 구간 길이가 3만 되어도 합이 30억이라 넘치고, 오버플로는 예외를 던지지 않으므로 **음수로 돌아간 값**이 조용히 비교된다. 테스트가 이유 없이 틀린다.

```cpp
// ✅ 고친 코드
long long s = 0;
for (int j = i; j < n; j++) {
    s += arr[j];                     // 누적 변수는 long long 이 기본
    if (s == target) cnt++;
}
```

**4) 최댓값 초기값을 0으로 둔다**

```cpp
// ❌ 틀린 코드
long long best = 0;
for (int i = 0; i + L <= n; i++) {
    long long s = 0;
    for (int j = i; j < i + L; j++) s += arr[j];
    if (s > best) best = s;          // 모든 구간 합이 음수면 0이 남는다
}
```

왜: 값에 음수가 섞이면 "존재하지 않는 답 0"이 실제 최댓값을 이긴다. 초기값은 **후보 중 하나**이거나 `LLONG_MIN`이어야지, 임의의 상수여서는 안 된다.

```cpp
// ✅ 고친 코드
long long best = LLONG_MIN;          // 또는 첫 구간의 합으로 초기화
for (int i = 0; i + L <= n; i++) {
    long long s = 0;
    for (int j = i; j < i + L; j++) s += arr[j];
    best = max(best, s);
}
```

**5) 단조가 아닌 조건에 조기 종료를 건다**

```cpp
// ❌ 틀린 코드
for (int i = 0; i < n; i++) {
    long long s = 0;
    for (int j = i; j < n; j++) {
        s += arr[j];
        if (s > target) break;       // 음수가 있으면 뒤에서 다시 줄어든다
        if (s == target) cnt++;
    }
}
```

왜: `break`가 정당하려면 "더 진행해도 조건이 회복되지 않는다"가 참이어야 한다. 원소가 모두 양수면 합은 커지기만 하니 옳지만, 음수가 섞이면 합이 다시 내려와 `target`이 될 수 있어 답을 놓친다.

```cpp
// ✅ 고친 코드
for (int i = 0; i < n; i++) {
    long long s = 0;
    for (int j = i; j < n; j++) {
        s += arr[j];
        if (s == target) cnt++;      // 음수 가능성이 있으면 끝까지 본다
    }
}
```

**6) 자리 수가 변수인데 for 중첩으로 버틴다**

```cpp
// ❌ 틀린 코드
for (int x = 1; x <= d; x++)         // n 이 3일 때만 맞는 코드
    for (int y = 1; y <= d; y++)
        for (int z = 1; z <= d; z++)
            check(x, y, z);
```

왜: 중첩 개수는 코드를 쓸 때 정해지므로 입력으로 들어오는 `n`에 맞출 수 없다. `n`이 2나 5로 오는 순간 통째로 틀린다. 이럴 때 쓰라고 있는 도구가 재귀(또는 값이 두 가지뿐이면 비트마스크)다.

```cpp
// ✅ 고친 코드
void rec(int pos) {                  // 자리 수를 변수로
    if (pos == n) { check(combo); return; }
    for (int v = 1; v <= d; v++) {
        combo[pos] = v;
        rec(pos + 1);
    }
}
```

**7) 비트 검사에 괄호를 안 씌운다**

```cpp
// ❌ 틀린 코드
for (int mask = 0; mask < (1 << n); mask++)
    for (int i = 0; i < n; i++)
        if (mask & (1 << i) == 1) take(i);   // 항상 거짓에 가깝다
```

왜: C++에서 `&`는 `==`보다 **우선순위가 낮다**(파이썬과 반대!). 그래서 위 식은 `mask & ((1 << i) == 1)`로 묶여, `i > 0`이면 `(1<<i) == 1`이 0이 되고 `mask & 0`은 항상 0이라 아무것도 고르지 않는다. 게다가 켜진 비트의 값은 `1`이 아니라 `2^i`라 `== 1` 비교 자체가 틀렸다.

```cpp
// ✅ 고친 코드
for (int mask = 0; mask < (1 << n); mask++)
    for (int i = 0; i < n; i++)
        if ((mask & (1 << i)) != 0) take(i);  // 괄호로 묶고 != 0 으로 검사
```

**8) `1 << n`을 `int`로 계산한다**

```cpp
// ❌ 틀린 코드
long long total = 1 << n;            // n 이 31 이상이면 int 로 계산돼 터진다
for (long long mask = 0; mask < total; mask++) { }
```

왜: `1`이 `int` 리터럴이라 `1 << n`은 `int` 연산으로 먼저 계산된다. `n = 31`이면 부호 비트를 침범해 음수가 되고, `n ≥ 32`는 정의되지 않은 동작이라 컴파일러가 루프를 통째로 지워 버릴 수도 있다. 왼쪽에 `long long`을 두어도 이미 늦다.

**다음 챕터로**

- 완전탐색은 "정직하게 다 본다"는 가장 안전한 무기이자, 이후 모든 최적화의 **기준선**이다. 더 빠른 풀이를 떠올렸을 때 작은 입력에서 완전탐색 결과와 비교하면 그 풀이가 맞는지 검증할 수 있다.
- 앞으로는 이 뼈대에 "이미 틀린 가지는 더 내려가지 않는다"(가지치기)와 "같은 계산을 두 번 하지 않는다"(기억하기)가 붙는다. 지금 경우의 수를 세는 습관을 들여 두면, 그 최적화가 왜 필요한지도 숫자로 보인다.

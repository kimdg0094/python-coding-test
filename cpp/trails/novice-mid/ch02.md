> 개요: 함수가 자기 자신을 다시 호출하는 재귀를 배운다. 부작용(출력·변경)만 내는 "값을 반환하지 않는 재귀"와, 부분 문제의 답을 모아 최종 답을 만드는 "값을 반환하는 재귀"로 나눠, 종료 조건과 문제 축소라는 재귀의 두 축을 익힌다.

## L1. 값을 반환하지 않는 재귀함수

**개념**

- 재귀함수는 함수가 자기 자신을 다시 호출하는 함수다. 반복문(`for`/`while`) 대신, "지금 할 일 한 조각을 처리하고, 나머지는 나 자신에게 맡긴다"는 방식으로 작업을 쪼갠다.

- 값을 반환하지 않는 재귀는 값을 돌려주지 않는(`void`) 함수로, 출력·전역 변수 변경 같은 부작용(side effect)을 일으키는 것이 목적이다. 예를 들어 "1부터 n까지 한 줄에 하나씩 출력", "정수를 거꾸로 출력" 같은 유형이다.

- 모든 재귀는 두 부분으로 이루어진다.

- 종료 조건(base case): 더 이상 자신을 부르지 않고 멈추는 조건. 이게 없으면 무한 재귀로 프로그램이 죽는다.

- 재귀 호출(recursive call): 문제를 "조금 더 작은 같은 문제"로 바꿔 자신을 다시 부르는 부분.

```cpp
#include <iostream>
using namespace std;

void count_up(int cur, int n) {
    if (cur > n) return;          // 종료 조건: 범위를 넘으면 멈춘다
    cout << cur << "\n";          // 지금 할 일 한 조각
    count_up(cur + 1, n);         // 나머지는 나에게 맡긴다
}

int main() {
    count_up(1, 3);               // 1 / 2 / 3 이 한 줄씩 출력
    return 0;
}
```

- 호출 순서가 중요하다. "일을 먼저 하고 재귀"하면 위에서 아래로(정방향), "재귀를 먼저 하고 일을 나중에" 하면 아래에서 위로(역방향) 처리된다.

```cpp
void count_down(int cur, int n) {
    if (cur > n) return;
    count_down(cur + 1, n);   // 먼저 끝까지 내려가고
    cout << cur << "\n";      // 돌아오면서 출력 → 3 / 2 / 1
}

// count_down(1, 3) 을 호출하면 3 / 2 / 1 순으로 출력
```

> 선행: C++는 함수를 쓰기 전에 선언(또는 정의)이 위에 있어야 한다. 재귀함수는 자기 이름을 본문에서 부르므로, 함수 정의만 있으면 문제없다. 재귀 깊이가 매우 깊으면(수십만 이상) 호출 스택이 넘칠 수 있으니, 그럴 땐 분할 방식으로 깊이를 O(log n)까지 줄이거나 반복문으로 바꾼다.

**그림으로 보기**

- 재귀는 "호출이 아래로 쌓였다가(펼침) 종료 조건에 닿으면 위로 되돌아오는(접힘)" 두 방향 운동이다. `count_down(1, 3)`을 그림으로 보면 이렇다.

```text
   f(1)                              // f = count_down
     |  call
     v
   f(2)
     |  call
     v
   f(3)
     |  call
     v
   f(4)  -->  4 > 3 : return         // base case, nothing printed
     |
     |  now the stack unwinds
     v
   f(3) prints 3  -->  f(2) prints 2  -->  f(1) prints 1
```

- 재귀 호출은 "잠깐 멈추고 다른 나에게 맡기는" 것이라, 호출한 줄의 **다음 줄**은 그 재귀가 전부 끝난 뒤에야 실행된다. 그래서 일 처리를 재귀 앞에 두느냐 뒤에 두느냐로 출력 순서가 통째로 뒤집힌다.

```text
   print BEFORE the call        print AFTER the call
   ---------------------        --------------------
   f(1) : print 1               f(1) : call first
     v                            v
   f(2) : print 2               f(2) : call first
     v                            v
   f(3) : print 3               f(3) : call first
     v                            v
   f(4) : return                f(4) : return
                                  |
   result -> 1 2 3                +-> print 3, 2, 1
                                result -> 3 2 1
```

- 각 프레임은 자기만의 `cur`를 갖는다. C++에서도 매개변수는 호출마다 새로 만들어지는 지역 변수라, `f(2)`의 `cur`가 `f(1)`의 `cur`를 건드리지 않는다.

**손으로 따라가기**

`count_down(1, 3)`을 깊이·인자·동작으로 추적한다. 깊이 3까지만 내려가므로 손으로 끝까지 따라갈 수 있다.

| 단계 | 깊이 | 호출 | 지금 하는 일 | 출력 |
|---|---|---|---|---|
| 1 | 0 | `count_down(1, 3)` | `1 > 3`? 아니오 → 재귀부터 | — |
| 2 | 1 | `count_down(2, 3)` | `2 > 3`? 아니오 → 재귀부터 | — |
| 3 | 2 | `count_down(3, 3)` | `3 > 3`? 아니오 → 재귀부터 | — |
| 4 | 3 | `count_down(4, 3)` | `4 > 3` → `return;` (종료 조건) | — |
| 5 | 2 | 깊이 3에서 돌아옴 | 멈춰 있던 `cout << cur` 실행 | `3` |
| 6 | 1 | 깊이 2에서 돌아옴 | 멈춰 있던 `cout << cur` 실행 | `2` |
| 7 | 0 | 깊이 1에서 돌아옴 | 멈춰 있던 `cout << cur` 실행 | `1` |

- 호출은 1 → 2 → 3 순으로 쌓였는데 출력은 3 → 2 → 1이다. "먼저 쌓인 것이 나중에 풀린다"는 스택의 성질이 그대로 출력 순서가 된 것이다.

**왜 이렇게 되는가**

- **왜 종료 조건이 없으면 프로그램이 죽나**: 호출마다 스택 프레임이 하나씩 쌓이는데, 종료 조건이 없으면 이 프레임이 무한히 쌓여 호출 스택을 다 먹는다. 파이썬은 깊이 약 1000에서 `RecursionError`를 던져 스스로 끊어 줬지만, **C++에는 그런 안전장치가 없다.** 스택이 넘치는 순간 아무 메시지 없이 프로그램이 강제 종료된다(스택 오버플로 = 대개 "Segmentation fault"). 증상이 불친절할 뿐 원인은 똑같이 "종료 조건 누락"이므로, 재귀를 쓰다 원인 불명으로 죽으면 종료 조건부터 의심한다.
- **왜 축소만으로는 부족한가**: `f(cur - 1)`처럼 작아지기만 하고 멈출 선이 없으면 음수 쪽으로 영원히 내려간다. 반대로 종료 조건이 있어도 `f(cur)`처럼 인자가 그대로면 그 조건에 영영 닿지 못한다. **종료 조건과 축소는 짝**이라, 축소가 매 호출마다 종료 조건 쪽으로 한 걸음씩 다가가는지 반드시 확인해야 한다.
- **왜 반환 없는 재귀에도 "결합"이 있나**: 값을 안 돌려줄 뿐, "지금 할 일을 재귀의 앞에 둘지 뒤에 둘지"가 곧 결합 규칙이다. 앞에 두면 얕은 것부터, 뒤에 두면 깊은 것부터 결과가 만들어진다.
- **복잡도**: 호출 한 번의 비용이 O(1)이고 총 호출이 n번이면 시간은 O(n)으로 반복문과 같다. 다만 공간은 다르다 — 가장 깊을 때 프레임이 동시에 n개 살아 있으므로 **추가 공간 O(깊이)** 를 쓴다. 반복문이 O(1) 공간인 것과의 유일한 실질적 차이가 이것이다.
- **C++의 재귀 깊이는 얼마나 여유로운가**: 파이썬은 기본 1000에서 막혀 `setrecursionlimit`을 만져야 했지만, C++ 프레임은 훨씬 가벼워 보통 수만~수십만 깊이까지 견딘다. 그렇다고 무한은 아니다. 스택은 기본적으로 1MB 남짓이고, 프레임 하나가 커질수록 견디는 깊이가 그만큼 줄어든다.
- **C++에서만 조심할 것 — 프레임에 큰 배열을 잡지 않는다**: `void rec(int d) { int tmp[100000]; ... }`처럼 지역 배열을 두면 프레임 하나가 400KB가 되어 깊이 3만 돼도 스택이 터진다. 재귀 함수의 지역 변수는 최소한으로 두고, 큰 배열·격자는 전역에 두거나 `vector`로 힙에 잡아 참조(`&`)로 넘긴다.

**접근 전략**

- 재귀 설계는 항상 두 질문으로 시작한다. (1) "언제 멈추는가?"(종료 조건) (2) "문제를 어떻게 더 작게 만들어 나에게 넘기는가?"(호출을 할수록 종료 조건에 가까워져야 한다). 이 두 개만 맞으면 나머지는 저절로 굴러간다.

- "일 처리"와 "재귀 호출"의 순서를 결정하는 게 핵심 기술이다. 지금 인자에 대한 작업을 재귀 호출 앞에 두면 얕은 것부터, 뒤에 두면 깊은 것부터 처리된다. 정방향 출력은 앞에, 역방향 출력은 뒤에 두면 된다.

- 상태는 인자로 넘긴다. "지금 어디까지 왔는지"(현재 위치·인덱스), "누적된 정보"(지금까지 만든 문자열 등)를 매개변수로 계속 전달하면 전역 변수 없이도 깔끔하게 진행 상태를 관리할 수 있다.

- 반복문으로 쉽게 되는 걸 굳이 재귀로 바꾸라는 게 아니라, "큰 문제 = 작은 문제 + 나머지" 구조가 자연스러운 문제에 쓴다. 시간 복잡도는 보통 호출 횟수와 같다(예: n번 호출이면 O(n)). 호출마다 스택 프레임을 쌓으므로 재귀 깊이만큼 O(깊이)의 추가 공간이 든다는 점을 기억한다.

**문제**

**1) 사이를 채워 출력하기** · Easy

- **요구사항**: 두 정수 a, b (a ≤ b)가 주어질 때, a부터 b까지의 정수를 한 줄에 하나씩 오름차순으로 출력하는 재귀함수를 작성한다. 반복문을 쓰지 말고 재귀로만 구현한다.
- **입력**: 첫 줄에 두 정수 a b (−1000 ≤ a ≤ b ≤ 1000)
- **출력**: a부터 b까지 각 정수를 한 줄에 하나씩
- **예제**: `2 5` → `2\n3\n4\n5` (즉 2, 3, 4, 5가 각 줄에)
- **예제**: `-1 1` → `-1\n0\n1`
- **셀프체크**: a == b일 때 딱 한 줄만 출력되는가? 종료 조건을 "현재 값 > b"로 잡으면 a > b인 입력이 없어도 안전한가? "일을 먼저 하고 재귀"하는 정방향 순서를 지켰는가?

```runner
@@SOLUTION
#include <iostream>
using namespace std;

void out(int cur, int b) {
    if (cur > b) return;
    cout << cur << "\n";
    out(cur + 1, b);
}

int main() {
    int a, b;
    cin >> a >> b;
    out(a, b);
    return 0;
}
@@TESTS
--IN
2 5
--OUT
2
3
4
5
--IN
-1 1
--OUT
-1
0
1
--IN
7 7
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- "지금 값 하나를 출력하고, 나머지 구간은 나 자신에게 넘긴다"는 정방향 재귀다. 종료 조건은 현재 값이 b를 넘어가는 순간이고, 매 호출마다 현재 값을 +1 해서 종료 조건에 다가간다.
- 출력을 재귀 호출보다 "먼저" 하므로 작은 값부터(오름차순) 나온다.

(2) 코드 단계별

- `out(cur, b)`는 현재 처리할 값 `cur`과 끝값 `b`를 인자로 받는 `void` 함수다.
- `cur > b`면 더 출력할 게 없으니 그냥 `return`.
- 아니면 `cur`을 출력하고, `out(cur + 1, b)`로 다음 값을 위임한다.
- `a`, `b`를 `cin`으로 읽어 `out(a, b)`로 시작한다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "언제 멈추지?" → 현재 값이 끝값을 넘으면.
- 다음 "무엇을 한 조각 처리하지?" → 현재 값 한 개 출력.
- 마지막 "어떻게 작아지지?" → 현재 값 +1 로 재귀. 출력이 재귀보다 앞이면 오름차순임을 확인.
```

**2) 자릿수 하나씩 뒤에서부터** · Medium

- **요구사항**: 음이 아닌 정수 n이 주어질 때, n의 각 자릿수를 일의 자리부터 거꾸로 한 줄에 하나씩 출력한다. 재귀로 "마지막 자리를 처리하고, 남은 앞부분을 나에게 넘긴다"는 방식으로 구현한다.
- **입력**: 첫 줄에 정수 n (0 ≤ n ≤ 2,000,000,000)
- **출력**: n의 자릿수를 일의 자리부터 한 줄에 하나씩
- **예제**: `507` → `7\n0\n5`
- **예제**: `0` → `0`
- **셀프체크**: n이 0일 때 아무것도 출력 안 하고 끝나버리지 않는가?(0은 반드시 한 번 출력돼야 한다 — 종료 조건과 "0 자체" 처리를 구분하라.) `n % 10`으로 마지막 자리를, `n / 10`으로 앞부분을 넘기는 축소가 매 호출마다 확실히 작아지는가? n 최대값이 int 범위(약 21억) 근처이니 `long long`으로 받으면 안전하다.

```runner
@@SOLUTION
#include <iostream>
using namespace std;

void rev(long long n) {
    cout << n % 10 << "\n";
    if (n < 10) return;
    rev(n / 10);
}

int main() {
    long long n;
    cin >> n;
    rev(n);
    return 0;
}
@@TESTS
--IN
507
--OUT
7
0
5
--IN
0
--OUT
0
--IN
1000
--OUT
0
0
0
1
@@EXPL
(1) 접근·핵심 아이디어

- "마지막 자리(`n % 10`)를 먼저 처리하고, 앞부분(`n / 10`)을 나에게 넘긴다"는 구조다. 출력을 먼저 하므로 일의 자리부터 거꾸로 나온다.
- 종료 조건이 까다롭다. n이 0이어도 "0"은 한 번 출력돼야 하므로, 출력을 먼저 한 뒤 `n < 10`(한 자리만 남음)일 때 멈춘다. 이렇게 하면 n == 0도 정확히 한 줄 출력된다.

(2) 코드 단계별

- `rev(n)`에서 먼저 `n % 10`(현재 일의 자리)을 출력한다.
- `n < 10`이면 남은 자릿수가 방금 출력한 한 자리뿐이므로 `return`.
- 아니면 `n / 10`(정수 나눗셈, 앞부분)으로 재귀해 계속 뒤에서부터 출력한다.
- 입력 상한이 크므로 `long long`으로 받는다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇을 한 조각 처리?" → 일의 자리 하나 출력.
- "언제 멈추지?" → 자릿수가 하나만 남았을 때. 단 출력을 종료 검사보다 앞에 둬야 0도 나온다.
- "어떻게 작아지지?" → `n / 10`으로 앞부분만 넘김(C++ 정수 나눗셈은 몫). 이걸 종료 검사 뒤에 두는 순서를 손으로 507 → 50 → 5 로 추적해 확인.
```

**3) 별 삼각형 역방향** · Medium

- **요구사항**: 정수 n이 주어질 때, 별(`*`)을 n개인 줄부터 1개인 줄까지 한 줄씩 줄여가며 출력한다. 단, 재귀 호출을 먼저 하고 출력을 나중에 하는 "되돌아오며 출력" 구조를 사용해, 실제로는 함수가 1 → n 방향으로 호출되지만 출력은 n → 1로 나오게 만든다.
- **입력**: 첫 줄에 정수 n (1 ≤ n ≤ 100)
- **출력**: 각 줄에 별. 첫 줄 n개, 다음 줄 n−1개, …, 마지막 줄 1개
- **예제**: `3` → `***\n**\n*`
- **예제**: `1` → `*`
- **셀프체크**: "재귀 먼저, 출력 나중" 순서일 때 정말 큰 줄이 먼저 나오는가? 종료 조건(예: 인자가 n을 넘는 순간)을 명확히 두어 무한 재귀를 막았는가? 각 줄의 별 개수가 인자와 어떻게 대응되는지 손으로 한번 추적했는가?

```runner

(1) 접근·핵심 아이디어

- "재귀를 먼저 하고 출력을 나중에" 하는 되돌아오며 출력 구조다. 함수는 `cur`을 1 → n 방향으로 늘려가며 호출되지만, 출력은 재귀에서 돌아올 때(접힘) 일어나므로 큰 `cur`부터 찍힌다.
- `cur`번째 호출에서 별 `cur`개를 출력하도록 하면, 되돌아오며 n개 → 1개 순으로 나온다.

- `stars(cur, n)`은 `cur > n`이면 `return`(종료 조건).

- 종료 조건은 `cur > n`으로 잡아 무한 재귀 방지.
- cur=1,2,3 호출이 쌓였다가 3,2,1 순으로 출력됨을 손으로 추적해 확인.
```

## L2. 값을 반환하는 재귀함수

**개념**

- 값을 반환하는 재귀는 부분 문제의 답을 `return`으로 돌려받아, 그것을 조합해 지금 문제의 답을 만든다. 핵심 사고방식은 "내가 직접 다 계산하지 않는다. 더 작은 문제의 답은 이미 안다고 가정하고, 그 답에서 한 걸음을 더한다"이다(수학적 귀납법과 같은 구조).

- 대표 예가 팩토리얼이다. `n! = n × (n−1)!`. 즉 `(n−1)!`은 재귀가 알아서 구해준다고 믿고, 나는 거기에 `n`만 곱한다.

```cpp
long long fact(int n) {
    if (n <= 1) return 1;          // 종료 조건: 0! = 1! = 1
    return (long long)n * fact(n - 1);   // 작은 답을 받아 한 걸음 더한다
}

// fact(5) == 120
```

- `fact(3)`이 어떻게 펼쳐지는지 손으로 따라가 보자. 호출은 아래로 내려가며 쌓이고(펼침), 종료 조건에 닿으면 값이 위로 되돌아오며(접힘) 곱해진다.

```text
fact(3) = 3 * fact(2)
        = 3 * (2 * fact(1))
        = 3 * (2 * 1)        // fact(1)이 종료 조건으로 1 반환
        = 3 * 2
        = 6
```

- 값을 반환하는 재귀의 뼈대는 항상 이렇다.

- 종료 조건에서 "가장 작은 경우의 답"을 직접 `return` 한다.

- 그 외에는 자신을 호출해 부분 답을 받고, 그 부분 답으로 지금 답을 계산해 `return` 한다.

- 반환값을 반드시 `return`으로 다시 돌려줘야 한다. `fact(n-1)`만 호출하고 `return`을 빠뜨리면 그 값은 버려지고 함수는 쓰레기 값을 돌려준다(C++에서 반환값이 없는 경로는 미정의 동작).

- 부분 문제가 여러 개일 수도 있다. 피보나치는 두 개의 부분 답을 더한다.

```cpp
long long fib(int n) {
    if (n <= 1) return n;          // fib(0)=0, fib(1)=1
    return fib(n - 1) + fib(n - 2);
}
```

> 선행: 위 피보나치는 같은 값을 여러 번 다시 계산해 n이 커지면 폭발적으로 느려진다(지수 시간). 이번 레슨에서는 "재귀로 답을 조합하는 사고"에 집중하고, 중복 계산을 없애는 기법(메모이제이션·DP)은 이후 트레일에서 다룬다. 또한 C++는 정수 범위가 유한하므로, 결과가 커질 수 있는 계산은 `long long`을 쓰고 오버플로 여부를 항상 의식한다.

**그림으로 보기**

- 값을 반환하는 재귀는 **내려갈 때는 인자를 줄이고, 올라올 때는 답을 조립한다.** `fact(4)`의 두 방향을 한 장에 겹쳐 보면 이렇다.

```text
   unfold (down)                    fold (up)
   -------------                    ---------
   fact(4) = 4 * ?                  <-- 24 = 4 * 6
      |                                      ^
      v                                      |
   fact(3) = 3 * ?                  <--  6 = 3 * 2
      |                                      ^
      v                                      |
   fact(2) = 2 * ?                  <--  2 = 2 * 1
      |                                      ^
      v                                      |
   fact(1) : n <= 1  --> return 1  ----------+   // base case
```

- 왼쪽 열의 `?`는 "아직 모르는 부분 답"이다. 종료 조건에 닿는 순간 맨 아래의 `?`가 확정되고, 그 값이 위로 올라가며 왼쪽의 물음표를 아래에서부터 차례로 메운다.
- 부분 문제가 둘로 갈라지면 그림은 줄이 아니라 **나무**가 된다. 피보나치가 느린 이유가 이 그림에 그대로 보인다.

```text
               fib(4)
              /      \
         fib(3)      fib(2)          // fib(2) is computed twice
        /      \
    fib(2)   fib(1)                  // the tree doubles each level
    /    \
 fib(1) fib(0)                       // 9 calls just for n = 4
```

**손으로 따라가기**

`fact(4)`의 호출과 반환을 (깊이, 인자, 반환값)으로 추적한다. "대기"는 아직 부분 답을 못 받아 멈춰 있는 상태다.

| 단계 | 깊이 | 호출 | 하는 일 | 반환값 |
|---|---|---|---|---|
| 1 | 0 | `fact(4)` | `4 * fact(3)`이 필요 → 대기 | (미정) |
| 2 | 1 | `fact(3)` | `3 * fact(2)`가 필요 → 대기 | (미정) |
| 3 | 2 | `fact(2)` | `2 * fact(1)`이 필요 → 대기 | (미정) |
| 4 | 3 | `fact(1)` | `n <= 1` 종료 조건에 닿음 | `1` |
| 5 | 2 | `fact(2)` 재개 | `2 * 1` 계산 | `2` |
| 6 | 1 | `fact(3)` 재개 | `3 * 2` 계산 | `6` |
| 7 | 0 | `fact(4)` 재개 | `4 * 6` 계산 | `24` |

- 최종 답 `24`는 4단계에서 나온 `1` 하나가 위로 올라오며 5·6·7단계에서 차례로 곱해진 결과다. 종료 조건의 반환값이 틀리면 이 사슬 전체가 통째로 틀어진다.

**왜 이렇게 되는가**

- **왜 재귀에 세 요소가 전부 필요한가**: 하나씩 빼 보면 무엇이 깨지는지가 분명해진다.
  - 종료 조건을 빼면 → 내려가기만 하고 올라올 시작점이 없다. 프레임이 계속 쌓여 스택 오버플로로 강제 종료.
  - 축소를 빼면(`fact(n)`이 `fact(n)`을 부름) → 종료 조건이 있어도 영영 닿지 못한다. 역시 스택 오버플로.
  - 결합을 빼면(`fact(n - 1)`만 부르고 `n *`을 안 함) → 답이 조립되지 않아 부분 답이 그대로 새어 나온다.
- **왜 `return`을 빠뜨리면 쓰레기 값이 나오나**: `void`가 아닌 함수가 `return` 없이 끝나면 C++에서는 **미정의 동작**이다. 파이썬처럼 `None`이 들어오는 것도 아니고, 컴파일이 막히지도 않는다. 레지스터에 남아 있던 값이 답인 척 흘러나와 "어떤 입력에서는 맞고 어떤 입력에서는 틀리는" 최악의 버그가 된다. `g++ -Wall`을 켜면 `warning: control reaches end of non-void function`으로 잡아 주니, 재귀를 쓸 때는 **모든 갈래가 값을 반환**하는지 눈으로 확인한다.
- **왜 종료 조건의 값이 결정적인가**: 위 표에서 보듯 최종 답은 종료 조건의 반환값에 계속 연산을 쌓아 만든 것이다. `fact`의 base case를 `0`으로 두면 `4 * 3 * 2 * 0 = 0`이 되어 전부 0이 된다. 가장 작은 사례를 손으로 검산하는 이유가 이것이다.
- **왜 `long long`으로 받나**: 재귀로 조립한 값은 금방 커진다. `13!`은 약 62억이라 이미 `int` 한계(약 21억)를 넘는데, C++은 오버플로를 알려 주지 않고 조용히 음수를 만든다. `(long long)n * fact(n - 1)`처럼 곱셈 **전에** 한쪽을 64비트로 올려야 하는 것도 같은 이유다 — `int * int` 식은 결과를 `long long`에 담더라도 계산 자체가 32비트로 끝난 뒤에 대입되기 때문이다. 파이썬 정수는 무한히 커졌지만 C++은 그렇지 않다.
- **복잡도는 호출 트리의 노드 수다**:
  - 한 갈래로만 내려가면 노드가 n개 → O(n). 깊이도 n이므로 n이 수십만을 넘어가면 스택을 걱정해야 한다.
  - 두 갈래로 갈라지고 중복을 안 없애면 노드가 레벨마다 2배 → 대략 O(2^n). `fib(4)`가 벌써 9번 호출된다.
  - 매번 절반으로 줄이면 깊이 k에서 크기가 `n / 2^k`, 이것이 1이 되는 `k = log₂ n`이 곧 호출 횟수 → O(log n). 깊이가 O(log n)이면 스택 걱정도 사실상 사라진다.

**접근 전략**

- "부분 답을 안다고 가정"하는 상상이 전부다. `solve(작은 입력)`이 이미 정답을 준다고 믿고, 그 정답에서 지금 입력까지 가는 "한 걸음의 규칙"만 찾으면 된다. 이 규칙이 곧 점화식(재귀식)이다. 예: 합 `sum(n) = n + sum(n-1)`, 거듭제곱 `pow(a,n) = a * pow(a,n-1)`.

- 종료 조건은 "더 쪼갤 필요 없이 답을 바로 아는 가장 작은 경우"로 잡고, 거기서 실제 값을 `return` 한다. 종료 조건의 반환값이 틀리면(예: `fact`에서 1 대신 0을 return) 전체가 무너지니, 가장 작은 사례를 손으로 검산한다.

- 재귀 호출이 두 갈래 이상이면(피보나치, 이진 탐색적 분할 등) 각 갈래의 반환값을 어떻게 합치는지(더하기·최댓값·논리합 등)를 명확히 정한다. "왼쪽 답과 오른쪽 답을 어떤 연산으로 합쳐 내 답을 만드는가?"가 설계의 중심 질문이다.

- 복잡도 감각: 호출마다 한 갈래로만 내려가면 O(n)(선형 재귀). 매 호출이 두 갈래로 갈라지고 중복을 제거하지 않으면 O(2^n)에 가까워 위험하다. 반면 매번 문제 크기를 절반으로 줄이면(예: 빠른 거듭제곱) O(log n)까지 내려간다 — "한 번의 호출로 문제가 얼마나 줄어드는가"가 복잡도를 좌우한다.

**문제**

**1) 1부터 n까지의 합** · Easy

- **요구사항**: 양의 정수 n이 주어질 때, 1 + 2 + … + n의 값을 값을 반환하는 재귀함수로 구한다. `sum(n) = n + sum(n-1)` 꼴의 점화식을 직접 세워 구현한다(반복문·공식 n(n+1)/2 금지).
- **입력**: 첫 줄에 정수 n (1 ≤ n ≤ 1000)
- **출력**: 1부터 n까지의 합
- **예제**: `5` → `15` (1+2+3+4+5)
- **예제**: `1` → `1`
- **셀프체크**: 종료 조건(예: n == 1)에서 올바른 값을 return 하는가? 재귀 호출 앞에 `return`을 빠뜨려 값이 새지 않는가? n == 1일 때 종료 조건과 일반 규칙이 충돌 없이 맞물리는가? (합의 최댓값 500500은 int로도 충분하지만, 습관적으로 `long long`을 써도 좋다.)

```runner
    return n + s(n - 1);

    long long n;

    return 0;

(1) 접근·핵심 아이디어

- 점화식 `sum(n) = n + sum(n-1)`을 그대로 옮긴다. "1..(n-1)까지의 합은 재귀가 이미 구해준다"고 믿고, 거기에 `n`만 더한다(수학적 귀납법과 동일한 구조).
- 종료 조건은 가장 작은 경우 `n == 1`이고, 그 답은 명백히 1이다.

(2) 코드 단계별

- `s(n)`에서 `n == 1`이면 곧바로 `1`을 return(base case).
- 그 외에는 `n + s(n - 1)`을 return. `s(n-1)`이 준 부분 답에 `n`을 더해 지금 답을 만든다.
- `return`을 반드시 붙여야 값이 제대로 돌아온다.

(3) 스스로 다시 짤 때 생각 순서

- "부분 답을 안다고 가정" → `s(n-1)`이 1..(n-1) 합을 준다고 믿는다.
- "한 걸음의 규칙" → 거기에 `n`을 더하면 1..n 합.
- "가장 작은 경우" → n=1이면 합은 1. 이 base case 값을 손으로 검산(s(2)=2+s(1)=2+1=3).
```

**2) 빠른 거듭제곱** · Medium

- **요구사항**: 정수 a와 음이 아닌 정수 b가 주어질 때, a^b를 구한다. 단순히 a를 b번 곱하지 말고, 지수를 절반씩 줄이는 재귀를 사용한다. 짝수 지수는 `a^b = (a^(b/2))^2`, 홀수 지수는 `a^b = a * a^(b-1)`로 나눠, 호출 횟수를 O(log b)로 만든다.
- **입력**: 첫 줄에 두 정수 a b (−100 ≤ a ≤ 100, 0 ≤ b ≤ 60)
- **출력**: a^b의 값 (결과가 int 범위를 넘을 수 있으므로 `long long`으로 계산한다)
- **예제**: `2 10` → `1024`
- **예제**: `3 0` → `1` (어떤 수의 0제곱은 1)
- **예제**: `-2 3` → `-8`
- **셀프체크**: b == 0에서 1을 return 하는 종료 조건이 있는가? 짝수 갈래에서 `a^(b/2)`를 한 번만 계산해 그 결과를 제곱하는가?(같은 걸 두 번 호출하면 O(log b)가 깨진다.) 음수 밑(−2)과 홀수 지수 조합에서 부호가 맞는지 검산했는가? 결과가 최대 100^60 수준까지 커질 수 있으니 예제 범위 안에서 `long long`으로 담기는지 의식했는가?(본 예제들은 모두 `long long` 범위 안이다.)

```runner
@@SOLUTION
#include <iostream>
using namespace std;

long long power(long long a, long long b) {
    if (b == 0) return 1;
    if (b % 2 == 0) {

        return half * half;
    }
    return a * power(a, b - 1);
}

int main() {
    long long a, b;
    cin >> a >> b;
    cout << power(a, b) << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 지수를 절반씩 줄여 O(log b) 호출로 거듭제곱한다. 짝수 지수는 `a^b = (a^(b/2))^2`, 홀수 지수는 `a^b = a * a^(b-1)`.
- 핵심은 짝수 갈래에서 `a^(b/2)`를 변수에 한 번만 담아 제곱하는 것. 두 번 호출하면 절반 줄인 효과가 사라진다.

(2) 코드 단계별

- `power(a, b)`에서 `b == 0`이면 `1`을 return(종료 조건, 어떤 수의 0제곱은 1).
- `b`가 짝수면 `half = power(a, b / 2)`로 한 번만 구해 `half * half`를 return.
- `b`가 홀수면 `a * power(a, b - 1)`로 지수를 1 줄여 짝수로 만든 뒤 위 갈래를 타게 한다.
- 음수 밑도 곱셈 부호가 자동으로 맞으므로 별도 처리 불필요((-2)^3 = -8).
- 값이 커질 수 있어 인자와 반환형을 모두 `long long`으로 둔다(2^60도 안전히 담긴다).

(3) 스스로 다시 짤 때 생각 순서

- "문제를 절반으로 줄이는 규칙" → 짝수면 지수 반으로.
- "절반이 안 되는 경우" → 홀수면 지수 1 줄여 짝수로 만든다.
- "종료 조건" → 지수 0이면 1. `half`를 반드시 한 번만 계산하는지 확인해 O(log b)를 유지.
```

**3) 재귀로 최댓값 찾기** · Hard

- **요구사항**: n개의 정수 배열이 주어질 때, 반복문이나 `std::max_element` 같은 라이브러리 없이 재귀만으로 최댓값을 구한다. 아이디어는 분할이다. 구간 `[lo, hi]`의 최댓값 = 왼쪽 절반의 최댓값과 오른쪽 절반의 최댓값 중 더 큰 값. 원소가 하나인 구간이 종료 조건이다.
- **입력**: 첫 줄에 정수 n (1 ≤ n ≤ 100,000), 둘째 줄에 공백으로 구분된 n개의 정수(각 −10^9 이상 10^9 이하)
- **출력**: 배열의 최댓값
- **예제**: `5` / `3 -1 7 4 2` → `7`
- **예제**: `1` / `-42` → `-42`
- **셀프체크**: 원소가 하나인 구간(lo == hi)에서 그 원소 자체를 return 하는가? 구간을 절반으로 나눌 때 중간 지점 계산이 왼쪽·오른쪽을 빠짐없이·겹침없이 덮는가? 왼쪽 답과 오른쪽 답을 "더 큰 값"으로 합치는 부분이 정확한가? n이 클 때 재귀 깊이가 O(log n)로 얕은 이 분할 방식이 깊이 O(n)짜리 방식보다 안전함을 이해했는가?

```runner
@@SOLUTION
#include <iostream>
#include <vector>
using namespace std;

long long find_max(const vector<long long>& arr, int lo, int hi) {
    if (lo == hi) return arr[lo];
    int mid = (lo + hi) / 2;
    long long left = find_max(arr, lo, mid);
    long long right = find_max(arr, mid + 1, hi);
    return left > right ? left : right;
}

int main() {
    int n;
    cin >> n;
    vector<long long> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    cout << find_max(arr, 0, n - 1) << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 분할 정복이다. 구간 `[lo, hi]`의 최댓값 = "왼쪽 절반의 최댓값"과 "오른쪽 절반의 최댓값" 중 더 큰 값. 왼쪽·오른쪽 답은 재귀가 알아서 구해준다고 믿는다.
- 종료 조건은 원소가 하나인 구간(`lo == hi`)으로, 그 원소 자체가 곧 최댓값이다.

(2) 코드 단계별

- `find_max(arr, lo, hi)`에서 `lo == hi`면 `arr[lo]`를 return(base case). 배열은 복사 비용을 피하려고 `const vector<long long>&`(상수 참조)로 넘긴다.
- `mid = (lo + hi) / 2`(정수 나눗셈)로 구간을 나눈다. 왼쪽은 `[lo, mid]`, 오른쪽은 `[mid+1, hi]`로 겹침·빠짐 없이 덮는다.
- 두 부분 답 `left`, `right`를 받아 삼항 연산자 `left > right ? left : right`로 더 큰 값을 return.
- 값 범위가 ±10^9이라 int로도 되지만, 안전하게 `long long`으로 담는다. 분할 깊이는 O(log n)이라 n이 10만이어도 재귀 스택이 넉넉하다.

(3) 스스로 다시 짤 때 생각 순서

- "부분 답을 안다고 가정" → 왼쪽 절반과 오른쪽 절반의 최댓값을 재귀가 준다.
- "합치는 연산" → 두 값 중 큰 것.
- "가장 작은 경우" → 원소 하나면 그게 답. mid 경계가 `[lo,mid]`/`[mid+1,hi]`로 정확히 나뉘는지, 음수만 있는 배열(-2가 최댓값)에서도 맞는지 검산.
```

## L3. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch2(재귀함수)의 핵심 — 종료 조건과 문제 축소, 출력 순서(재귀 앞/뒤), 부분 답을 받아 조합하는 값 반환 재귀 — 를 **반복 훈련**하고, 코딩테스트에서 재귀로 풀리는 단골 유형으로 **확장**하는 세트다.
- **반복 훈련 개념**
- 출력 순서: 재귀 호출 **앞**에 출력하면 정방향, **뒤**에 두면 역방향. 앞뒤 둘 다 두면 "올라갔다 내려오는" 대칭 출력이 된다.
- 반환 타입 먼저: C++ 재귀함수는 머리에 반환 타입을 적어야 한다. 값을 안 돌려주면 `void`, 개수·합이면 `int`/`long long`, 판정이면 `bool`, 만들어 붙이면 `string`.
- 자릿수 축소: `f(n) = (일의 자리 처리) + f(n / 10)`, 종료는 `n < 10`. C++의 `/`는 정수끼리면 몫이라 파이썬 `//`와 같다. 0도 한 자리임을 잊지 말 것.
- 문자열 축소: `rev(s) = rev(s.substr(1)) + s[0]`, 종료는 `s.size() <= 1`. **`substr`는 새 문자열을 복사**하므로 길이가 크면 인덱스 인자 `f(s, i)`로 바꿔 복사를 없앤다.
- 두 인덱스 축소: `f(s, l, r)` 에서 `l + 1, r - 1`, 종료는 `l >= r`.
- 두 갈래 재귀: `ways(n) = ways(n-1) + ways(n-3)`, `cnt(i, remain) = cnt(i+1, remain-a[i]) + cnt(i+1, remain)` — 갈래별 답을 **더해서** 합친다.
- 깊이와 스택: 파이썬은 깊이가 넘치면 `RecursionError`로 알려 주지만 **C++은 스택이 넘치면 예외 없이 프로세스가 그냥 죽는다**(윈도우 기본 스택 1MB, 리눅스 8MB). 한 호출 프레임이 클수록 더 빨리 터지므로 재귀 함수 안에 `int buf[100000];` 같은 큰 지역 배열을 잡지 말고 전역이나 `vector`로 뺀다.
- 이름 충돌: `using namespace std;` 아래에서 `gcd`(C++17 `std::gcd`), `count`(`std::count`), `bsearch`(`<cstdlib>`) 같은 흔한 이름을 재귀함수 이름으로 쓰면 표준 이름과 겹친다. `my_gcd`, `count_ways`처럼 비켜 짓는다.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '재귀' 단계(팩토리얼·피보나치·하노이 유형), 프로그래머스 「코딩테스트 고득점 Kit」의 '이분탐색'(정렬된 배열에서 절반씩 좁히기), NeetCode 150의 'Backtracking'(원소를 고르거나/안 고르는 두 갈래 탐색). 모두 "종료 조건 + 축소 규칙 + 부분 답 합치기"라는 같은 뼈대로 풀린다.
- **문제 구성표**

**문제**

**1) 짝수 자릿수 세기** · Easy

- **요구사항**: 음이 아닌 정수 `n`의 자릿수 중 짝수(0, 2, 4, 6, 8)의 개수를 값을 반환하는 재귀함수로 구하라. 일의 자리를 처리하고 `n / 10`으로 축소하는 방식이며, 반복문과 `to_string` 같은 문자열 변환은 쓰지 않는다.
- **입력**: 첫 줄에 정수 `n`(0 ≤ n ≤ 10^18).
- **출력**: 짝수 자릿수의 개수.
- **예제**: `2048` → `4` · `135` → `0` · `0` → `1`
- **셀프체크**: `n`의 상한이 10^18이라 `int`(약 21억)로는 절대 담을 수 없다 — 매개변수를 `long long`으로 잡았는가(`int`로 받으면 입력 단계에서 값이 뭉개져 조용히 틀린다)? `n = 0`일 때 "자릿수 0 하나"로 세어 `1`이 나오는가(종료 조건을 `n == 0`으로 잡으면 `0`이 나와 틀린다)? 종료 조건 `n < 10`에서도 그 한 자리를 검사해 반환하는가? 10^18은 19자리이므로 재귀 깊이가 19밖에 안 됨을 확인했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int even_digits(long long n) {
    int cur = ((n % 10) % 2 == 0) ? 1 : 0;
    if (n < 10) return cur;
    return cur + even_digits(n / 10);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    long long n;
    cin >> n;
    cout << even_digits(n) << '\n';
    return 0;
}
@@TESTS
--IN
2048
--OUT
4
--IN
135
--OUT
0
--IN
0
--OUT
1
--IN
1000000000000000000
--OUT
18
@@EXPL
(1) 접근·핵심 아이디어

- "일의 자리가 짝수면 1, 아니면 0"을 지금 몫으로 정하고, 나머지 앞자리(`n / 10`)의 답은 재귀가 준다고 믿고 더한다. 점화식은 `f(n) = cur + f(n / 10)`.
- 함정 둘. (a) `0`이다. 종료 조건을 `n == 0`으로 두면 `0` 입력에서 아무것도 세지 않는다. "한 자리만 남았을 때"(`n < 10`)를 종료로 잡고 그 한 자리도 검사해야 `0 → 1`이 된다. (b) 타입이다. 10^18은 `int` 범위 밖이므로 `long long`이 아니면 읽는 순간 값이 망가진다.

(2) 코드 단계별

- 반환 타입은 `int`(자릿수 개수는 최대 19), 매개변수 타입은 `long long`. 반환과 매개변수의 타입이 달라도 아무 문제 없다.
- `int cur = ((n % 10) % 2 == 0) ? 1 : 0;` — 삼항 연산자 `조건 ? A : B`가 파이썬의 `A if 조건 else B`에 해당한다.
- `n < 10`이면 남은 자리가 지금 자리뿐이므로 `cur`를 그대로 반환(종료 조건).
- 아니면 `cur + even_digits(n / 10)`으로 앞자리 답을 더해 반환. `n`이 음이 아니므로 `/`도 `%`도 파이썬과 결과가 같다(음수였다면 달라진다).
- 10^18(19자리)도 깊이 19라 스택 걱정이 전혀 없다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 값의 크기를 보고 타입을 정한다(`long long`) → "한 조각" = 일의 자리 판정 → "축소" = `n / 10` → "종료" = 한 자리 남음. `0`, `135`(전부 홀수), `2048`(전부 짝수)로 종료 조건이 세 경우 모두 맞는지 손으로 검산.
```

**2) 문자열 뒤집기** · Easy

- **요구사항**: 문자열 `s`를 거꾸로 뒤집은 새 문자열을 값을 반환하는 재귀함수로 만들어라. "첫 글자를 뗀 나머지를 뒤집은 결과 뒤에 첫 글자를 붙인다"는 규칙을 쓴다. 표준 라이브러리의 `reverse`와 반복문은 쓰지 않는다.
- **입력**: 첫 줄에 공백 없는 문자열 `s`(알파벳·숫자, 길이 1~500).
- **출력**: 뒤집은 문자열.
- **예제**: `hello` → `olleh` · `a` → `a`
- **셀프체크**: 반환 타입이 `string`인가? 종료 조건이 길이 1 이하(`s.size() <= 1`)에서 `s` 자체를 반환하는가? `rev(s.substr(1)) + s[0]`에서 첫 글자를 **뒤**에 붙이는가(앞에 붙이면 원래 문자열이 그대로 나온다)? `s[0]`은 `char`인데 `string + char`가 성립하는 것과 달리 `char + char`는 숫자 덧셈이 된다는 걸 아는가? 길이 500이면 깊이 500, 프레임마다 `substr` 복사본이 하나씩 쌓이지만 총 12만 자 정도라 스택·시간 모두 여유가 있는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

string rev(const string& s) {
    if (s.size() <= 1) return s;
    return rev(s.substr(1)) + s[0];
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    string s;
    cin >> s;
    cout << rev(s) << '\n';
    return 0;
}
@@TESTS
--IN
hello
--OUT
olleh
--IN
a
--OUT
a
--IN
abba
--OUT
abba
--IN
ab12
--OUT
21ba
@@EXPL
(1) 접근·핵심 아이디어

- "나머지 부분은 이미 뒤집혀 있다"고 믿는다. `s.substr(1)`(첫 글자를 뗀 부분)을 뒤집은 결과 **뒤에** 첫 글자 `s[0]`을 붙이면 전체가 뒤집힌다. 점화식 `rev(s) = rev(s.substr(1)) + s[0]`.
- 종료 조건은 길이 0 또는 1 — 뒤집어도 자기 자신이므로 `s`를 그대로 반환한다.

(2) 코드 단계별

- 매개변수는 `const string&`로 받아 호출 시 복사를 막는다. 다만 `substr(1)`이 이미 새 문자열을 만들어 넘기므로 실제로는 호출마다 한 벌씩 복사가 생긴다 — 길이 500이면 500 + 499 + … ≈ 12만 자라 괜찮지만, 길이가 10만이면 O(n²)이 되어 터진다. 그때는 `rev(const string& s, int i)`처럼 인덱스를 넘겨 복사를 없앤다.
- `s.size() <= 1`이면 `s` 반환. `size()`는 부호 없는 정수라 `s.size() - 1`을 빈 문자열에 쓰면 거대한 값이 된다 — 여기서는 뺄셈을 피해 `<= 1`로 비교했다.
- `rev(...) + s[0]`: 왼쪽이 `string`이므로 `+ char`가 "뒤에 한 글자 붙이기"로 동작한다. 반대로 `s[0] + rev(...)`라고 쓰면 `char + string`이라 이번에도 문자열이 되지만 붙는 위치가 앞이라 답이 틀린다. `s[0] + s[1]`처럼 `char + char`끼리 더하면 문자열이 아니라 **아스키 코드의 합(숫자)** 이 되니 주의.

(3) 스스로 다시 짤 때 생각 순서

- 반환 타입을 `string`으로 확정 → "축소" = 첫 글자 떼기 → "한 걸음" = 떼어낸 글자를 뒤에 붙이기 → "종료" = 길이 1 이하 → `ab`로 손 추적: `rev("b") + 'a' = "ba"`.
```

**3) 올라갔다 내려오기** · Easy

- **요구사항**: 정수 `n`이 주어질 때 `1, 2, …, n`을 한 줄에 하나씩 출력한 뒤 곧바로 `n, n−1, …, 1`을 이어서 출력하는, 반환 타입이 `void`인 재귀함수를 작성하라. 함수 하나로, 재귀 호출 **앞**과 **뒤**에 각각 출력을 두어 두 방향을 한꺼번에 만든다. 반복문은 쓰지 않는다.
- **입력**: 첫 줄에 정수 `n`(1 ≤ n ≤ 500).
- **출력**: 총 `2n`줄. 앞 `n`줄은 `1..n` 오름차순, 뒤 `n`줄은 `n..1` 내림차순.
- **예제**: `3` → `1 / 2 / 3 / 3 / 2 / 1` · `1` → `1 / 1`
- **셀프체크**: `n = 1`일 때 `1`이 두 번 출력되는가? 재귀 호출 앞의 출력이 오름차순, 뒤의 출력이 내림차순을 만드는 이유를 호출 스택으로 설명할 수 있는가? 종료 조건을 `cur < n`일 때만 재귀하는 식으로 두어 `n`을 넘지 않는가? `void` 함수라 `return;`만 쓸 수 있고 값을 붙이면 컴파일 오류라는 걸 아는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

void climb(int cur, int n) {
    cout << cur << '\n';
    if (cur < n) climb(cur + 1, n);
    cout << cur << '\n';
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    climb(1, n);
    return 0;
}
@@TESTS
--IN
3
--OUT
1
2
3
3
2
1
--IN
1
--OUT
1
1
--IN
2
--OUT
1
2
2
1
@@EXPL
(1) 접근·핵심 아이디어

- 재귀 호출 **앞**의 출력은 내려가면서(1 → n) 찍히고, 호출 **뒤**의 출력은 되돌아오면서(n → 1) 찍힌다. 한 함수에 둘 다 두면 "올라갔다 내려오는" 대칭 출력이 저절로 만들어진다.
- 가장 깊은 호출(`cur == n`)은 재귀 없이 `n`을 두 번 연달아 출력하므로 가운데에 `n, n`이 붙어 나온다.

(2) 코드 단계별

- 반환값이 없으므로 반환 타입은 `void`. `return cur;`처럼 값을 붙이면 컴파일이 안 된다(중간에 빠져나가고 싶다면 `return;`).
- `cout << cur << '\n';` — 내려가며 찍는 출력.
- `cur < n`이면 `climb(cur + 1, n)`로 더 깊이 들어간다(`cur == n`이면 여기서 멈추는 것이 종료 조건).
- `cout << cur << '\n';` — 돌아오며 찍는 출력. 이 줄은 재귀 호출이 완전히 끝난 뒤에 실행된다.
- `n = 500`이면 깊이 500, 프레임에 `int` 두 개뿐이라 스택은 넉넉하다. `endl` 대신 `'\n'`을 써서 1000줄을 찍을 때 매번 버퍼를 비우지 않게 했다.

(3) 스스로 다시 짤 때 생각 순서

- "정방향은 재귀 앞, 역방향은 재귀 뒤" 규칙을 떠올린다 → 둘 다 필요하면 둘 다 둔다 → 종료 조건은 `cur < n`일 때만 호출 → `n = 2`로 호출 스택(1 → 2 → 2 → 1)을 손으로 추적.
```

**4) 배열 전체의 최대공약수** · Medium

- **요구사항**: 두 수의 최대공약수를 유클리드 호제법 `gcd(a, b) = gcd(b, a % b)`로 구하는 재귀함수와, 벡터의 `i`번째부터 끝까지의 최대공약수를 `my_gcd(arr[i], gcd_all(arr, i + 1))`로 구하는 재귀함수를 각각 작성해 배열 전체의 최대공약수를 출력하라. 반복문은 쓰지 않는다. C++17 표준에 `std::gcd`가 있으므로 함수 이름은 `my_gcd`처럼 겹치지 않게 짓는다.
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 500). 둘째 줄에 양의 정수 `n`개(각 1 ≤ v ≤ 10^9).
- **출력**: 배열 전체의 최대공약수.
- **예제**: `4 / 12 18 30 42` → `6` · `1 / 7` → `7`
- **셀프체크**: `using namespace std;` 아래에서 함수 이름을 `gcd`로 지으면 `<numeric>`의 `std::gcd`와 이름이 겹친다 — `my_gcd`처럼 비켜 지었는가? `my_gcd`의 종료 조건은 `b == 0`일 때 `a`를 반환하는 것인가(`a == 0`으로 잡으면 순서가 꼬인다)? `gcd_all`의 종료 조건은 마지막 원소 하나(`i == (int)arr.size() - 1`)일 때 그 값을 반환하는가? 벡터를 `const vector<int>&`로 받아 재귀 호출마다 500개를 복사하지 않게 했는가? 서로소 배열(`8 15 27`)에서 `1`이 나오는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int my_gcd(int a, int b) {
    if (b == 0) return a;
    return my_gcd(b, a % b);
}

int gcd_all(const vector<int>& arr, int i) {
    if (i == (int)arr.size() - 1) return arr[i];
    return my_gcd(arr[i], gcd_all(arr, i + 1));
}

int main() {

    cin.tie(nullptr);

    cin >> n;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    cout << gcd_all(arr, 0) << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 두 층의 재귀다. 안쪽 `my_gcd(a, b)`는 "`b`가 0이면 `a`, 아니면 `my_gcd(b, a % b)`"라는 호제법 점화식. 바깥 `gcd_all(arr, i)`는 "뒤쪽 원소들의 최대공약수는 재귀가 준다"고 믿고 `arr[i]`와 그 답의 최대공약수를 취한다.
- 여러 수의 최대공약수는 `gcd(a, gcd(b, gcd(c, ...)))`처럼 두 수씩 접어 구할 수 있다는 성질을 벡터 재귀로 옮긴 것이다.

(2) 코드 단계별

- `my_gcd`: `b == 0`이면 `a` 반환(종료). 아니면 인자를 `(b, a % b)`로 바꿔 재귀. `a < b`여도 한 번 호출하면 자리가 바뀌므로 따로 처리할 필요 없다. 입력이 모두 양수라 `%`의 부호 문제는 없다(음수가 섞이면 C++의 `%`는 파이썬과 달리 음수를 돌려주므로 `abs`가 필요하다).
- `gcd_all`: 벡터를 반드시 `const vector<int>&`로 받는다. 값으로 받으면 재귀 깊이 500 × 원소 500개 = 25만 번의 복사가 일어나 느려지고 스택도 훨씬 많이 먹는다.
- `i`가 마지막 인덱스면 `arr[i]` 반환(원소 하나의 최대공약수는 자기 자신). `arr.size()`는 부호 없는 `size_t`이므로 `(int)`로 캐스팅해 비교한다.
- 깊이는 `n`(최대 500)이고, `my_gcd` 자체의 깊이는 10^9 범위에서 50 미만이다.

(3) 스스로 다시 짤 때 생각 순서

- 이름이 표준과 겹치지 않는지 먼저 확인 → 두 수의 최대공약수를 완성해 `my_gcd(12, 18) = 6`으로 검산 → "벡터의 나머지 부분 답"을 안다고 가정하고 앞 원소와 접는다(매개변수는 `const&`) → 종료는 원소 하나 → 서로소(`1`)와 원소 1개 케이스로 경계 확인.
```

**5) k진법 문자열 만들기** · Medium

- **요구사항**: 음이 아닌 정수 `n`과 진법 `k`가 주어질 때, `n`을 `k`진법으로 나타낸 문자열을 값을 반환하는 재귀함수로 만들어라. "몫 `n / k`의 표현 뒤에 나머지 `n % k`를 붙인다"는 규칙이며, 종료 조건은 `n < k`(한 자리)다. 반복문과 표준 라이브러리의 진법 변환 기능(`strtol`, `stoi`의 base 인자 등)은 쓰지 않는다.
- **입력**: 한 줄에 `n k`(0 ≤ n ≤ 10^9, 2 ≤ k ≤ 9).
- **출력**: `k`진법 문자열.
- **예제**: `10 2` → `1010` · `255 8` → `377` · `0 5` → `0`
- **셀프체크**: `n = 0`에서 빈 문자열이 아니라 `0`이 나오는가(종료 조건을 `n == 0 → ""`로 두면 틀린다)? 나머지를 재귀 결과의 **뒤**에 붙이는가(앞에 붙이면 자릿수가 뒤집힌다)? 숫자를 문자열로 바꿀 때 `to_string(n % k)`를 썼는가(`n % k`를 그대로 `+`로 붙이면 문자열에 숫자를 더하는 다른 뜻이 된다 — 한 자리라면 `char('0' + n % k)`도 가능)? `10^9`를 2진법으로 바꿔도 깊이 30이라 안전한가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

string convert(int n, int k) {
    if (n < k) return to_string(n);
    return convert(n / k, k) + to_string(n % k);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, k;
    cin >> n >> k;
    cout << convert(n, k) << '\n';
    return 0;
}
@@TESTS

--IN

--IN

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- `n`을 `k`로 나누면 나머지가 가장 낮은 자리, 몫이 그 위 자리들이다. "몫의 `k`진 표현은 재귀가 준다"고 믿고 그 문자열 뒤에 나머지 한 자리를 붙인다. 점화식 `convert(n) = convert(n / k) + to_string(n % k)`.
- 종료 조건은 `n < k`(한 자리) — 이때 `to_string(n)`을 반환하므로 `n = 0`도 `"0"`이 되어 빈 문자열 함정을 피한다.

(2) 코드 단계별

- 반환 타입은 `string`. `to_string(int)`이 숫자를 10진 문자열로 바꿔 주는데, 여기서는 항상 한 자리(`k ≤ 9`이므로 나머지는 0~8)라 그대로 쓸 수 있다.
- `n < k`면 `to_string(n)` 반환.
- 아니면 `convert(n / k, k)`(윗자리들) `+ to_string(n % k)`(가장 낮은 자리). 재귀 앞뒤 순서가 곧 자릿수 순서다. 되돌아오며 뒤에 붙이므로 높은 자리부터 나열된다.
- `9 9`처럼 `n == k`이면 `convert(1) + "0" = "10"`.
- `n`이 음이 아니므로 `/`와 `%`가 파이썬과 같은 값을 준다. 음수였다면 C++의 `%`가 음수를 돌려주어 `to_string`에 `-3` 같은 두 글자가 들어가며 형식이 깨졌을 것이다.

(3) 스스로 다시 짤 때 생각 순서

- "축소" = 몫, "한 조각" = 나머지, "종료" = 한 자리 → 숫자를 문자열로 바꾸는 방법(`to_string` 또는 `char('0' + d)`)을 정한다 → 나머지를 뒤에 붙이는지 `10 2`로 손 추적(`convert(5) + "0"`, `convert(2) + "1"`, …) → `0`과 `n == k` 경계 검산.
```

**6) 1칸 또는 3칸 뛰기** · Medium

- **요구사항**: 한 번에 1칸 또는 3칸을 뛸 수 있을 때, 0번 칸에서 정확히 `n`번 칸에 도착하는 서로 다른 방법의 수를 값을 반환하는 재귀함수로 구하라. 점화식은 "마지막 점프가 1칸인 경우의 수 + 3칸인 경우의 수"다. 음수 칸으로 가는 경우는 0가지, 0번 칸에 이미 있는 경우는 1가지로 둔다.
- **입력**: 첫 줄에 정수 `n`(1 ≤ n ≤ 30).
- **출력**: 방법의 수.
- **예제**: `4` → `3` (1+1+1+1, 1+3, 3+1) · `1` → `1`
- **셀프체크**: `ways(0) = 1`, `ways(음수) = 0`이라는 두 종료 조건을 모두 두었는가(`n - 3`이 음수가 되는 호출을 막지 않으면 무한 재귀 → C++에서는 예외가 아니라 **스택 오버플로로 프로세스가 그냥 죽는다**)? 두 갈래 답을 **더해서** 합치는가? 반환 타입을 `long long`으로 두어 `n`이 커질 때의 오버플로에 대비했는가? `n = 30`이면 호출이 수십만 번이지만, `n`이 훨씬 크면 지수적으로 느려짐을 이해했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

long long ways(int n) {
    if (n < 0) return 0;
    if (n == 0) return 1;
    return ways(n - 1) + ways(n - 3);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    cout << ways(n) << '\n';
    return 0;
}
@@TESTS

--OUT

--IN

--OUT

--IN

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- `n`번 칸에 도착하는 마지막 점프는 1칸이거나 3칸이다. 그러므로 `ways(n) = ways(n - 1) + ways(n - 3)`. 각 갈래의 답은 재귀가 준다고 믿고 두 값을 더한다.
- 종료 조건이 둘이다. `n == 0`은 "출발점에 그냥 서 있는 1가지", `n < 0`은 "지나쳐 버린 0가지". 음수 조건이 없으면 `n - 3`이 계속 작아지며 멈추지 않는다. 파이썬이라면 `RecursionError`가 나서 원인을 알려 주지만, C++은 스택을 다 쓴 순간 아무 메시지 없이 프로세스가 종료된다(디버거 없이는 "그냥 죽었다"로만 보인다).

(2) 코드 단계별

- 반환 타입은 `long long`. `n ≤ 30`에서는 58,425라 `int`로도 되지만, 이런 경우의 수 문제는 상한이 조금만 올라가도 21억을 넘으므로 습관적으로 `long long`을 쓴다.
- `n < 0`이면 `0`, `n == 0`이면 `1` 반환. 순서를 바꿔도 되지만 둘 다 있어야 한다.
- 그 외 `ways(n - 1) + ways(n - 3)`.
- 손 검산: `ways(1) = ways(0) + ways(-2) = 1`, `ways(2) = 1`, `ways(3) = ways(2) + ways(0) = 2`, `ways(4) = ways(3) + ways(1) = 3`.
- 호출 수는 `n`에 대해 지수적으로 늘지만 `n ≤ 30`에서는 수십만 번이라 C++에서는 순식간에 끝난다. 깊이는 최대 `n`이라 스택도 안전하다.

(3) 스스로 다시 짤 때 생각 순서

- "마지막 한 걸음"으로 경우를 나눈다(1칸/3칸) → 갈래 답을 더한다 → 종료 조건은 정확히 도착(1)과 지나침(0) 둘 → 반환 타입을 `long long`으로 → `n = 4`를 손으로 나열(3가지)해 점화식을 검산.
```

**7) 공백을 무시한 회문 판정** · Medium

- **요구사항**: 소문자와 공백으로 된 한 줄이 주어질 때, 공백을 모두 지운 문자열이 회문(앞뒤로 읽어도 같음)인지 판정하라. 판정은 양 끝 인덱스 `l`, `r`을 받는 `bool` 반환 재귀함수 `is_pal(const string& s, int l, int r)`로 하며, 양 끝이 같으면 `l + 1`, `r − 1`로 안쪽을 재귀한다. 반복문과 `reverse`는 쓰지 않는다.
- **입력**: 한 줄 문자열(소문자·공백, 길이 1~1000, 공백을 지운 뒤 길이는 1 이상).
- **출력**: 회문이면 `YES`, 아니면 `NO`.
- **예제**: `never odd or even` → `YES` · `hello world` → `NO`
- **셀프체크**: 공백이 포함된 한 줄이므로 `cin >> s`가 아니라 `getline(cin, s)`로 읽었는가(`>>`는 공백에서 끊긴다)? 종료 조건을 `l >= r`(가운데를 지나거나 만남)로 두어 홀수·짝수 길이를 모두 처리하는가? 양 끝이 다르면 즉시 `false`를 반환하는가(조기 반환)? 시작 인덱스를 `(int)s.size() - 1`로 캐스팅했는가 — `s.size() - 1`은 부호 없는 계산이라 빈 문자열에서 40억 대의 값이 된다? 길이 1000이면 깊이는 최대 500임을 확인했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

bool is_pal(const string& s, int l, int r) {
    if (l >= r) return true;
    if (s[l] != s[r]) return false;
    return is_pal(s, l + 1, r - 1);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    string line;
    getline(cin, line);
    string s;
    for (char ch : line) {
        if (ch != ' ') s += ch;
    }
    cout << (is_pal(s, 0, (int)s.size() - 1) ? "YES" : "NO") << '\n';
    return 0;
}
@@TESTS
--IN
never odd or even
--OUT
YES
--IN
hello world
--OUT
NO
--IN
a
--OUT
YES
--IN
ab a
--OUT
YES
@@EXPL
(1) 접근·핵심 아이디어

- 회문은 "양 끝이 같고, 그 안쪽도 회문"이다. 안쪽이 회문인지는 재귀가 답해 준다고 믿고, 지금은 양 끝 한 쌍만 비교한다. 점화식 `is_pal(l, r) = (s[l] == s[r]) && is_pal(l + 1, r - 1)`.
- 종료 조건 `l >= r`: 짝수 길이는 `l`이 `r`을 지나치고(`l > r`), 홀수 길이는 가운데에서 만난다(`l == r`). 둘 다 "더 비교할 쌍이 없음" = `true`.
- 공백은 판정과 무관하므로 재귀에 들어가기 전에 한 번에 지운다. 문자열을 재귀 인자로 계속 잘라 넘기는 대신 **인덱스 두 개만** 넘기므로 복사가 전혀 없다.

(2) 코드 단계별

- 입력에 공백이 있으므로 `getline(cin, line)`으로 줄 전체를 읽는다. `cin >> line`은 첫 공백에서 끊겨 `never`만 읽는다.
- 공백 제거는 범위 기반 `for (char ch : line)`으로 새 문자열을 만든다. 표준 관용구 `s.erase(remove(s.begin(), s.end(), ' '), s.end());`를 써도 같다.
- `is_pal`: `l >= r`이면 `true`. `s[l] != s[r]`이면 더 볼 것 없이 `false` 조기 반환. 아니면 `is_pal(s, l + 1, r - 1)`의 결과를 그대로 반환한다(`return`을 빠뜨리면 반환값이 정해지지 않아 쓰레기 값이 나온다 — 파이썬처럼 `None`이 되는 게 아니라 정의되지 않은 동작이다).
- 문자열은 `const string&`로 받아 깊이 500번의 복사를 없앤다.
- 시작 호출은 `is_pal(s, 0, (int)s.size() - 1)`. 캐스팅을 빼면 `size()`가 부호 없는 타입이라 빈 문자열에서 `r`이 거대한 값이 되어 범위 밖을 읽는다.

(3) 스스로 다시 짤 때 생각 순서

- "양 끝 한 쌍"이 한 조각, "안쪽으로 한 칸씩"이 축소, "만나거나 지나침"이 종료 → 다르면 조기 종료 → 전처리(공백 제거)는 재귀 밖에서, 재귀에는 인덱스만 넘긴다 → `a`(길이 1)와 `ab a`(공백 포함)로 검산.
```

**8) 하노이 이동 횟수와 k번째 원판** · Hard

- **요구사항**: 원판 `n`개를 옮기는 하노이 탑의 최소 이동 횟수를 점화식 `moves(n) = 2 * moves(n − 1) + 1`(종료 `moves(0) = 0`)의 값 반환 재귀로 구하라. 그리고 그 최소 이동 순서에서 `k`번째 이동에 옮겨지는 원판의 번호(작은 원판이 1, 가장 큰 원판이 `n`)를 재귀로 구하라. 힌트: `n`개 이동 순서는 "`n−1`개 이동 → 원판 `n` 한 번 → `n−1`개 이동"의 구조이므로, `k`가 가운데면 `n`, 앞쪽이면 `n−1`개 문제의 `k`번째, 뒤쪽이면 `n−1`개 문제의 `k − mid`번째다.
- **입력**: 한 줄에 `n k`(1 ≤ n ≤ 30, 1 ≤ k ≤ 2^n − 1).
- **출력**: 첫 줄에 최소 이동 횟수, 둘째 줄에 `k`번째로 옮겨지는 원판 번호.
- **예제**: `3 4` → `7 / 3` · `4 6` → `15 / 2`
- **셀프체크**: 이동 횟수와 `k`를 `long long`으로 잡았는가 — `n = 30`이면 값이 10억 대라 `int`로도 겨우 들어가지만, `n`이 31만 되어도 `int`가 넘친다. 가운데 위치 `mid = moves(n − 1) + 1`을 정확히 계산했는가? `k > mid`일 때 `k − mid`로 옮겨 앞쪽 문제와 같은 번호 체계로 만들었는가? `n = 1`이면 이동 1번, 원판 1인가? 이동 횟수를 `2^n − 1` 공식이나 `pow`가 아닌 재귀로 구했는가(`pow`는 `double`이라 큰 수에서 오차가 난다)?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

long long moves(int n) {
    if (n == 0) return 0;
    return 2 * moves(n - 1) + 1;
}

int disk_at(int n, long long k) {
    long long mid = moves(n - 1) + 1;
    if (k == mid) return n;
    if (k < mid) return disk_at(n - 1, k);
    return disk_at(n - 1, k - mid);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    long long k;
    cin >> n >> k;
    cout << moves(n) << '\n';
    cout << disk_at(n, k) << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 하노이 탑에서 `n`개를 옮기려면 위의 `n−1`개를 보조 기둥으로 보내고(`moves(n−1)`), 가장 큰 원판을 한 번 옮기고(`+1`), 다시 `n−1`개를 그 위로 올린다(`moves(n−1)`). 그래서 `moves(n) = 2·moves(n−1) + 1`.
- 같은 구조를 "순서"에 적용하면 `k`번째 이동이 보인다. 전체 순서는 `[n−1개 순서] [원판 n] [n−1개 순서]`이므로 가운데 위치 `mid = moves(n−1) + 1`을 기준으로 `k`가 가운데면 원판 `n`, 앞이면 앞쪽 부분 문제의 `k`번째, 뒤면 뒤쪽 부분 문제의 `k − mid`번째다. 뒤쪽 순서는 앞쪽과 완전히 같으므로 번호만 당겨 주면 된다.
- 함정 둘: `k − mid`로 옮기지 않고 `k`를 그대로 넘기면 뒤쪽 절반에서 답이 틀린다. 그리고 값이 `2^30`에 가까우므로 타입을 `long long`으로 잡아야 `n`이 조금만 커져도 안전하다.

(2) 코드 단계별

- `moves(int n)`: 반환 타입 `long long`. `n == 0`이면 `0`, 아니면 `2 * moves(n - 1) + 1`. `2 * moves(...)`는 왼쪽이 `long long`이라 계산도 `long long`으로 이뤄진다.
- `disk_at(int n, long long k)`: `mid`를 구해 `k == mid`면 `n` 반환(종료). `k < mid`면 `disk_at(n - 1, k)`, 아니면 `disk_at(n - 1, k - mid)`. 원판 번호는 30 이하라 반환 타입은 `int`로 충분하다.
- `n = 1`이면 `mid = 1`이고 `k`는 1뿐이라 즉시 `1`을 반환하므로 별도 종료 조건이 필요 없다.
- `disk_at`이 매번 `moves`를 다시 계산하지만 깊이가 30이라 총 연산이 500번 미만이다.
- 검산 `4 6`: `mid = 8`, `6 < 8` → `disk_at(3, 6)`: `mid = 4`, `6 > 4` → `disk_at(2, 2)`: `mid = 2` → `2`.

(3) 스스로 다시 짤 때 생각 순서

- 값의 크기를 먼저 어림해 타입을 `long long`으로 → 이동 횟수 점화식을 재귀로 옮기고 `3 → 7`로 검산 → 순서 구조 `[앞][가운데][뒤]`를 그리고 가운데 위치를 `moves(n−1) + 1`로 정한다 → 세 경우(가운데/앞/뒤)로 나눠 뒤쪽은 `k − mid` 보정 → 작은 `n`에서 실제 이동 순서(1,2,1,3,1,2,1)를 손으로 나열해 확인.
```

**9) 재귀 이진 탐색** · Hard

- **요구사항**: 오름차순으로 정렬된 서로 다른 정수 배열에서 값 `x`의 인덱스를 찾는 재귀함수 `int bsearch_rec(const vector<int>& arr, int lo, int hi, int x)`를 작성하라. 가운데 원소와 비교해 같으면 그 인덱스를, 작으면 오른쪽 절반을, 크면 왼쪽 절반을 재귀로 탐색하고, 구간이 비면(`lo > hi`) `-1`을 반환한다. 여러 질의에 대해 각각 답한다. 반복문과 `find`·`binary_search` 같은 표준 탐색 함수는 쓰지 않는다. `<cstdlib>`에 이미 `bsearch`가 있으므로 이름은 `bsearch_rec`처럼 비켜 짓는다.
- **입력**: 첫 줄에 `n q`(1 ≤ n ≤ 1000, 1 ≤ q ≤ 100). 둘째 줄에 오름차순 서로 다른 정수 `n`개(−10^9 ≤ v ≤ 10^9). 다음 `q`개 줄에 찾을 값 `x`.
- **출력**: 질의마다 `x`의 인덱스(0-based), 없으면 `-1`을 한 줄에 하나씩.
- **예제**: `5 3 / 1 3 5 7 9 / 7 / 4 / 1` → `3 / -1 / 0` · `1 2 / 10 / 10 / 5` → `0 / -1`
- **셀프체크**: 구간이 빈 조건 `lo > hi`를 종료 조건으로 두어 없는 값에서도 멈추는가? 오른쪽으로 갈 때 `mid + 1`, 왼쪽으로 갈 때 `mid − 1`로 `mid`를 제외했는가(포함하면 구간이 안 줄어 무한 재귀 → 스택 오버플로로 프로세스가 죽는다)? 재귀 결과를 `return`으로 그대로 돌려주는가(빠뜨리면 반환값이 정의되지 않아 쓰레기 값이 나온다)? 배열이 훨씬 커질 때를 대비해 `mid = lo + (hi - lo) / 2` 형태를 알아 두었는가(`(lo + hi) / 2`는 인덱스 합이 21억을 넘으면 오버플로한다)? 깊이는 log₂(1000) ≈ 10임을 이해했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int bsearch_rec(const vector<int>& arr, int lo, int hi, int x) {
    if (lo > hi) return -1;
    int mid = lo + (hi - lo) / 2;
    if (arr[mid] == x) return mid;
    if (arr[mid] < x) return bsearch_rec(arr, mid + 1, hi, x);
    return bsearch_rec(arr, lo, mid - 1, x);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    for (int i = 0; i < q; i++) {
        int x;
        cin >> x;
        cout << bsearch_rec(arr, 0, n - 1, x) << '\n';
    }
    return 0;
}

(1) 접근·핵심 아이디어

- 정렬된 배열에서는 가운데 값 하나만 보면 `x`가 왼쪽 절반에 있는지 오른쪽 절반에 있는지 확정된다. "절반 구간의 답은 재귀가 준다"고 믿고, 지금은 가운데와 비교만 한다. 매 호출마다 구간이 절반으로 줄어 깊이는 log₂ n.
- 종료 조건이 둘이다. 찾았을 때(`arr[mid] == x`) 인덱스를 반환하고, 구간이 비었을 때(`lo > hi`) `-1`을 반환한다. 후자가 없으면 없는 값에서 멈추지 않는다.
- 함정: 재귀 구간에서 `mid`를 제외해야 한다(`mid + 1`, `mid − 1`). `mid`를 포함하면 원소 2개 구간에서 구간이 줄지 않아 무한 재귀가 되고, C++에서는 그 순간 스택을 다 써서 프로세스가 조용히 죽는다.

(2) 코드 단계별

- 배열은 `const vector<int>&`로 받는다. 값으로 받으면 재귀 호출 10번마다 원소 1000개를 복사한다.
- `lo > hi`면 `-1`.
- `mid = lo + (hi - lo) / 2`. `(lo + hi) / 2`와 결과는 같지만 두 인덱스가 아주 클 때 합이 `int` 범위를 넘는 것을 막는 관용구다.
- `arr[mid] == x`면 `mid` 반환. `arr[mid] < x`면 오른쪽 `[mid + 1, hi]`, 아니면 왼쪽 `[lo, mid − 1]`을 재귀하고 그 결과를 **그대로 반환**한다. 값을 돌려주는 함수에서 `return`을 빠뜨리면 파이썬처럼 `None`이 되는 게 아니라 정의되지 않은 동작이라 쓰레기 값이 나온다.
- 질의마다 `bsearch_rec(arr, 0, n - 1, x)`를 호출. 값이 서로 다르므로 인덱스는 유일하다.

(3) 스스로 다시 짤 때 생각 순서

- 이름이 표준과 겹치지 않는지 확인 → "가운데와 비교 → 절반 버리기"를 축소 규칙으로 → 종료는 "찾음"과 "구간 비었음" 둘 → 경계 `mid ± 1`과 `return`을 확인 → 양 끝 값·없는 값·원소 1개로 검산.
```

**10) 합이 S가 되는 고르기** · Hard

- **요구사항**: 정수 `n`개 중 **하나 이상**을 골라 합이 정확히 `S`가 되는 방법의 수를 재귀로 구하라. `i`번째 원소를 "고른다"와 "안 고른다" 두 갈래로 나누는 재귀함수 `count_ways(arr, i, remain)`을 작성한다(`remain`은 아직 만들어야 하는 합). 모든 원소를 다 살펴본 뒤 `remain == 0`이면 1가지다. 단, 아무것도 고르지 않은 경우는 방법으로 치지 않으므로 `S == 0`일 때 보정이 필요하다. `std::count`와 이름이 겹치므로 함수 이름은 `count_ways`처럼 짓는다.
- **입력**: 첫 줄에 `n S`(1 ≤ n ≤ 15, −10,000 ≤ S ≤ 10,000). 둘째 줄에 정수 `n`개(각 −100 ≤ v ≤ 100).
- **출력**: 방법의 수.
- **예제**: `4 3 / 1 2 3 4` → `2` (3 · 1+2) · `3 0 / 1 -1 2` → `1` (1+(−1))
- **셀프체크**: `using namespace std;` 아래에서 함수 이름을 `count`로 지으면 `<algorithm>`의 `std::count`와 겹친다 — `count_ways`로 지었는가? 종료 조건이 "인덱스가 끝에 도달"이고 그때 `remain == 0`이면 `1`, 아니면 `0`인가? 두 갈래(고름: `remain − arr[i]`, 안 고름: `remain`)의 답을 더하는가? 배열을 `const vector<int>&`로 받아 6만 번의 호출마다 복사가 생기지 않게 했는가? `S == 0`이면 "아무것도 안 고름"이 항상 1가지로 세어지므로 결과에서 1을 빼야 한다는 점을 처리했는가? 음수 원소가 있으므로 `remain < 0`에서 가지치기하면 **틀린다**는 것을 알았는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

long long count_ways(const vector<int>& arr, int i, int remain) {
    if (i == (int)arr.size()) return remain == 0 ? 1 : 0;
    return count_ways(arr, i + 1, remain - arr[i]) + count_ways(arr, i + 1, remain);
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, S;
    cin >> n >> S;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    long long ans = count_ways(arr, 0, S);
    if (S == 0) ans -= 1;
    cout << ans << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 원소마다 "고른다/안 고른다" 두 선택이 있으므로, `i`번째에서 두 갈래로 재귀하고 각 갈래의 방법 수를 더한다. 고르면 남은 목표 `remain`에서 `arr[i]`를 빼고, 안 고르면 그대로 넘긴다. 점화식 `count_ways(i, remain) = count_ways(i+1, remain − arr[i]) + count_ways(i+1, remain)`.
- 종료 조건은 모든 원소를 살펴본 시점(`i == n`). 그때 `remain == 0`이면 지금까지의 선택이 정확히 `S`를 만든 것이므로 1, 아니면 0.
- 함정 셋: (a) `S == 0`이면 "아무것도 안 고르는" 경로도 `remain == 0`으로 1가지로 세어지므로 마지막에 1을 뺀다. (b) 원소에 음수가 있어 `remain`이 음수가 되어도 뒤에서 다시 0이 될 수 있으므로 `remain < 0`에서 멈추는 가지치기는 쓰면 안 된다. (c) 이름 `count`는 `std::count`와 겹친다.

(2) 코드 단계별

- 반환 타입은 `long long`(최대 `2^15`라 `int`로도 되지만 경우의 수는 습관적으로 넉넉히 잡는다). 배열은 `const vector<int>&`로 받아 6만여 번의 호출에서 복사가 생기지 않게 한다.
- `i == (int)arr.size()`이면 `remain == 0 ? 1 : 0` 반환. `arr.size()`가 부호 없는 타입이므로 `(int)` 캐스팅을 붙였다.
- 아니면 고른 갈래와 안 고른 갈래의 반환값을 더해 반환.
- 메인은 `count_ways(arr, 0, S)`를 구한 뒤 `S == 0`일 때만 `ans -= 1`.
- 호출 수는 약 `2^(n+1)`, `n = 15`면 6만여 번이라 충분히 빠르다. 깊이는 `n`이라 스택도 안전하다.

(3) 스스로 다시 짤 때 생각 순서

- 함수 이름이 표준과 겹치지 않는지 확인 → "원소마다 두 선택"을 두 갈래 재귀로 → 상태는 (현재 인덱스, 남은 합), 배열은 `const&` → 종료는 인덱스 끝에서 남은 합이 0인지 → 빈 선택 보정(`S == 0`)과 음수 원소 때문에 가지치기를 하지 않는 이유를 예제 `1 -1 2`로 확인.
```

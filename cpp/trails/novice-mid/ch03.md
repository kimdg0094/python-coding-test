> 개요: 데이터를 정해진 기준으로 줄 세우는 "정렬"을 배운다. 단일 값 정렬에서 출발해, 여러 필드를 하나로 묶는 "객체" 표현을 익히고, 마지막에는 정렬 기준(비교 함수)을 자유자재로 지정해 다중 조건 정렬까지 다룬다.

## L1. 일반 정렬

**개념**

- 정렬(sort)은 데이터를 오름차순 또는 내림차순 등 "정해진 순서"로 재배치하는 것이다. 순위 매기기, 중앙값 찾기, 중복 제거, 이분 탐색 준비 등 수많은 문제의 첫 단추가 된다.
- C++에서는 `<algorithm>`의 `std::sort`를 쓴다. `sort(v.begin(), v.end())`는 `vector`를 그 자리에서 오름차순으로 바꾼다(원본을 정렬된 상태로 덮어쓴다). 반환값은 없다.
- 내림차순은 세 번째 인자로 비교 함수 `greater<int>()`를 넘긴다. 기본은 오름차순이다.

```cpp
vector<int> a = {5, 2, 9, 1};
sort(a.begin(), a.end());              // a = {1, 2, 5, 9}
sort(a.begin(), a.end(), greater<int>());  // a = {9, 5, 2, 1}
```

- 원본 순서를 나중에 다시 써야 하면 사본을 만들어 정렬한다: `vector<int> b = a; sort(b.begin(), b.end());`. 그러면 `a`는 그대로 남는다.
- 정렬 후에는 인덱스 접근이 강력해진다. `v[0]`은 최솟값, `v[v.size()-1]`은 최댓값, `v[k-1]`은 k번째로 작은 값이다.
- 중복 제거가 필요하면 정렬한 뒤 `unique`로 이웃한 중복을 뒤로 몰고 `erase`로 잘라낸다: `sort(...); v.erase(unique(v.begin(), v.end()), v.end());`. `unique`는 "정렬된 상태"를 전제로 이웃 중복만 없애므로 반드시 먼저 정렬해야 한다.

**그림으로 보기**

- `std::sort`는 언제나 **원본을 그 자리에서** 재배치한다. 정렬 전 순서를 남기고 싶으면 먼저 복사를 떠야 한다. 두 경우를 나란히 그리면 헷갈릴 여지가 없다.

```text
   copy first, then sort            sort in place
   ---------------------            -------------
   a : [ 5 , 2 , 9 , 1 ]            a : [ 5 , 2 , 9 , 1 ]
             |                                |
             v  b = a  (deep copy, O(n))      v  swapped in place
   b : [ 1 , 2 , 5 , 9 ]            a : [ 1 , 2 , 5 , 9 ]
   a : [ 5 , 2 , 9 , 1 ]            the original order is gone
```

- 정렬을 마치면 "몇 번째로 큰/작은 값"이 특정 **인덱스에 고정**된다. 정렬이 수많은 문제의 첫 단추가 되는 이유다.

```text
   sorted :  [ 1 , 2 , 4 , 4 , 7 , 9 ]
   index  :    0   1   2   3   4   5
               ^               ^   ^
               |               |   +-- v[n-1] : max
               |               +------ v[4]   : 5th smallest
               +---------------------- v[0]   : min
```

- `sort`가 받는 것은 벡터가 아니라 **반복자 두 개로 표현된 구간** `[begin, end)`다. 끝은 포함되지 않으므로 앞 k개만 정렬하려면 `sort(v.begin(), v.begin() + k)`라고 쓴다.

```text
   v.begin()                         v.end()
      |                                 |
      v                                 v
    [ 5 , 2 , 9 , 1 , 7 ]               .        // end points PAST the last
      |-------|                                  // sort(v.begin(), v.begin()+3)
      this part only
```

**왜 이렇게 되는가**

- **왜 비교 정렬이 O(N log N)인가**: 원소 N개를 늘어놓는 방법은 `N!`가지다. 비교 한 번은 "예/아니오" 두 갈래이므로 후보를 잘해야 절반으로 줄인다. 그러면 `N!`개의 후보를 하나로 좁히는 데 최소 `log₂(N!)`번의 비교가 필요하고, 이 값은 대략 `N log₂ N`이다. 즉 O(N log N)은 라이브러리가 게을러서가 아니라 **비교만으로 정렬하는 모든 방법의 하한**이다. `std::sort`는 이 하한을 상수배로 달성한다 — 퀵소트로 쪼개다 재귀가 너무 깊어지면 힙소트로 갈아타(introsort) 최악에도 O(N log N)을 보장한다.
- **왜 `std::sort`는 아무것도 돌려주지 않나**: 제자리(in-place) 정렬이기 때문이다. 원소들을 서로 자리바꿈해 순서를 만들 뿐 새로 만드는 것이 없으니, 돌려줄 값도 없다. 파이썬의 `sorted(a)`처럼 "정렬된 새 것"이 필요하면 `vector<int> b = a;`로 먼저 복사한 뒤 `b`를 정렬한다 — 이때 복사가 O(N) 시간·공간을 쓴다는 점을 함께 기억한다.
- **왜 `unique` 앞에 정렬이 반드시 필요한가**: `unique`는 전체를 훑는 게 아니라 **바로 앞 원소와만** 비교해 같으면 건너뛴다. 정렬돼 있어야 같은 값이 반드시 이웃하므로, 정렬 없이 부르면 `1 2 1`처럼 떨어져 있는 중복이 살아남는다. 게다가 `unique`는 원소를 실제로 지우지 않고 "남길 구간의 끝" 반복자만 돌려주므로, `v.erase(unique(v.begin(), v.end()), v.end());`로 꼬리를 직접 잘라야 크기가 줄어든다.
- **왜 구간이 `[begin, end)`로 끝을 제외하나**: 이렇게 정하면 구간의 길이가 `end - begin`으로 딱 떨어지고, 빈 구간이 `begin == end`라는 한 가지 모양으로 표현된다. 그래서 `v.end()`는 "마지막 원소"가 아니라 **마지막 다음 자리**를 가리킨다. `*v.end()`를 읽으면 범위 밖 접근이다.
- **정렬 뒤 접근 비용**: 인덱스 하나 읽기는 O(1). 전체 복잡도는 "정렬 O(N log N) + 접근 O(1)"에서 정렬이 지배한다.

**접근 전략**

- "가장 크다/작다", "k번째", "순위", "중앙값", "정렬된 상태에서 이웃끼리 비교"라는 신호가 보이면 먼저 정렬을 떠올린다. 정렬해 두면 원하는 값이 특정 인덱스에 "고정"된다.
- 전형적 절차: (1) 입력을 `vector`로 받는다 → (2) `sort`로 오름/내림 정렬한다 → (3) 필요한 인덱스나 앞쪽 몇 개를 뽑는다.
- 원본을 뭉개면 안 되는 상황이면 `sort` 전에 사본을 떠 둔다. `std::sort`는 제자리(in-place) 정렬이라 원본을 그대로 덮어쓰기 때문이다.
- 복잡도: `std::sort`는 비교 기반으로 원소 N개에 O(N log N). N이 수십만이어도 충분히 빠르다. 정렬 후 인덱스 접근은 O(1).

**문제**

**1) 중복 없는 오름차순** · Easy

- **요구사항**: 정수 N개가 주어질 때, 중복을 제거하고 오름차순으로 출력한다.
- **입력**: 첫 줄에 N. 둘째 줄에 정수 N개(공백 구분).
- **출력**: 중복이 제거된 값들을 오름차순으로 한 줄에 공백으로 구분해 출력.
- **예제**: `6 / 5 3 3 1 5 2` → `1 2 3 5`
- **예제**: `4 / 7 7 7 7` → `7`
- **셀프체크**: 모두 같은 수면 한 개만 남는가. 출력 사이 공백 형식이 맞는가(끝에 불필요한 공백/줄바꿈 주의). `unique`는 정렬된 상태에서만 이웃 중복을 없애므로 반드시 먼저 정렬해야 한다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end());
    a.erase(unique(a.begin(), a.end()), a.end());
    for (int i = 0; i < (int)a.size(); i++) {
        if (i > 0) cout << ' ';
        cout << a[i];
    }
    cout << '\n';
    return 0;
}
@@TESTS
--IN
6
5 3 3 1 5 2
--OUT
1 2 3 5
--IN
4
7 7 7 7
--OUT
7
@@EXPL
(1) 접근·핵심 아이디어

- 중복 제거는 "정렬 후 `unique`+`erase`" 관용구로 한다. `unique`는 정렬된 배열에서 이웃한 같은 값을 하나로 접어 뒤로 몰고, 새 끝 위치를 돌려준다. 그 위치부터 끝까지를 `erase`로 잘라낸다.
- `unique`는 "이웃 중복"만 없애므로, 반드시 먼저 `sort`로 같은 값끼리 붙여 놓아야 한다. 그러면 정렬 + 중복 제거가 한 번에 끝난다.

(2) 코드 단계별

- `cin >> n`으로 개수를 읽고, `vector<int> a(n)`에 정수 N개를 담는다.
- `sort(a.begin(), a.end())`로 오름차순 정렬한다.
- `a.erase(unique(a.begin(), a.end()), a.end())`로 중복을 제거한다.
- 인덱스로 순회하며 첫 원소 앞에는 공백을 두지 않고, 둘째 원소부터 앞에 공백을 찍어 "공백 구분 한 줄"을 만든다. 끝에 불필요한 공백이 붙지 않는다.

(3) 스스로 다시 짤 때 생각 순서

- "중복 없이" → `sort` + `unique`/`erase` 관용구를 떠올린다.
- "오름차순" → `unique`는 정렬을 전제로 한다는 점을 기억하고 반드시 `sort`를 먼저 한다.
- "공백 구분 한 줄" → `if (i > 0) cout << ' '` 로 원소 사이에만 공백을 넣는다.
```

**2) k번째로 작은 수** · Easy

- **요구사항**: 정수 N개와 k가 주어질 때, 정렬했을 때 k번째로 작은 값을 출력한다(중복도 하나의 자리로 센다).
- **입력**: 첫 줄에 N과 k. 둘째 줄에 정수 N개.
- **출력**: k번째로 작은 값 하나.
- **예제**: `6 3 / 7 2 9 4 4 1` → `4`  (정렬: 1 2 4 4 7 9, 3번째는 4)
- **예제**: `5 1 / 10 8 6 4 2` → `2`
- **셀프체크**: k는 1부터 시작하므로 인덱스는 `k-1`이다(off-by-one 함정). 중복이 있어도 자리 수로 세는지 확인. k=N일 때 최댓값이 되는가.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end());
    cout << a[k - 1] << '\n';
    return 0;
}
@@TESTS
--IN
6 3
7 2 9 4 4 1
--OUT
4
--IN
5 1
10 8 6 4 2
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- 정렬해 두면 "k번째로 작은 값"이 특정 인덱스에 고정된다. 오름차순 정렬 후 앞에서 k번째를 뽑으면 된다.
- 핵심 함정은 인덱스다. k는 1부터 세지만 `vector` 인덱스는 0부터이므로 `a[k-1]`이다.

(2) 코드 단계별

- `cin >> n >> k`로 개수와 k를 함께 읽는다.
- `vector<int> a(n)`에 정수 N개를 담는다.
- `sort(a.begin(), a.end())`로 오름차순 정렬한다(중복은 각각 하나의 자리로 남는다).
- `a[k-1]`이 k번째로 작은 값이다. 예: 정렬 `1 2 4 4 7 9`에서 3번째는 인덱스 2 → `4`.

(3) 스스로 다시 짤 때 생각 순서

- "k번째로 작은" → 오름차순 정렬을 먼저 떠올린다.
- "1부터 세는 k" → 인덱스는 `k-1`이라는 off-by-one을 항상 확인한다.
- 검산: k=1이면 최솟값(`a[0]`), k=N이면 최댓값(`a[n-1]`)이 나오는지 머릿속으로 대입해 본다.
```

**3) 상위 3개의 합** · Medium

- **요구사항**: 정수 N개 중 가장 큰 3개의 합을 출력한다. (N은 3 이상)
- **입력**: 첫 줄에 N. 둘째 줄에 정수 N개.
- **출력**: 최댓값 3개의 합.
- **예제**: `6 / 10 20 5 8 30 15` → `65`  (내림차순 30 20 15 ... 상위 3개 합 65)
- **예제**: `3 / -1 -2 -3` → `-6`
- **셀프체크**: 내림차순 정렬 후 앞의 세 개의 합을 쓰면 간단하다. 음수만 있어도 "가장 큰 3개"를 고르는 게 맞는지(값이 큰 순서). 같은 값이 여러 개여도 각각을 하나의 자리로 세는지 확인.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end(), greater<int>());
    long long sum = 0;
    for (int i = 0; i < 3; i++) sum += a[i];
    cout << sum << '\n';
    return 0;
}
@@TESTS
--IN
6
10 20 5 8 30 15
--OUT
65
--IN
3
-1 -2 -3
--OUT
-6
@@EXPL
(1) 접근·핵심 아이디어

- "가장 큰 3개"는 내림차순 정렬 후 맨 앞 세 개다. `sort(..., greater<int>())`로 큰 값을 앞으로 보낸 뒤 앞 세 개를 더한다.
- 음수만 있어도 "값이 큰 순서"의 상위 3개를 고르는 규칙은 동일하다. 예: `-1 -2 -3` → 상위 3개는 전부이므로 합 `-6`.

(2) 코드 단계별

- `vector<int> a(n)`에 정수 N개를 담는다.
- `sort(a.begin(), a.end(), greater<int>())`로 내림차순 정렬한다. 이제 큰 값이 앞쪽에 온다.
- `sum`을 `long long`으로 두고(합이 int 범위를 넘을 수 있으므로 안전) 앞 세 개 `a[0]`, `a[1]`, `a[2]`를 더한다.
- 같은 값이 여러 개여도 각각 하나의 자리로 세므로 그대로 더하면 된다.

(3) 스스로 다시 짤 때 생각 순서

- "가장 큰 K개" → 내림차순 정렬 + 앞에서 K개 더하기를 떠올린다.
- N이 항상 3 이상이므로 `a[0..2]` 접근은 안전하다(범위 밖 접근 걱정 없음).
- 음수 케이스로 "큰 순서"의 의미를 검산한다. 합은 `long long`으로 받아 오버플로를 예방한다.
```


## L2. 객체

**개념**

- 실전 데이터는 값 하나가 아니라 "여러 필드가 묶인 한 덩어리"인 경우가 많다. 예: 학생 = (이름, 점수), 상품 = (이름, 가격, 재고). 이렇게 관련된 값들을 하나로 묶은 것을 여기서는 "객체"라 부른다.
- C++에서 필드 2개짜리 가장 가벼운 묶음은 `pair`다. `first`, `second`로 필드에 접근한다.

```cpp
pair<string, int> student = {"kim", 90};  // (이름, 점수)
string name = student.first;   // "kim"
int score = student.second;    // 90

vector<pair<string,int>> students = {{"kim",90},{"lee",85},{"park",90}};  // 객체들의 vector
for (auto& s : students) cout << s.first << ' ' << s.second << '\n';
```

- 필드가 3개 이상이거나 이름으로 부르고 싶으면 `struct`를 정의해 가독성을 높인다.

```cpp
struct Student { string name; int score; };
Student s = {"kim", 90};
cout << s.name << ' ' << s.score << '\n';
```

- "무엇이 몇 번 나왔는가" 같은 집계에는 `map<키, int>`를 쓴다. `m[key]++`는 키가 없으면 값이 0으로 자동 생성된 뒤 1 증가하므로 빈도 세기에 편하다. 게다가 `std::map`은 키를 오름차순으로 정렬해 보관한다.

```cpp
map<string,int> count;
for (auto& w : words) count[w]++;   // 없던 키는 0에서 시작해 +1
```

**그림으로 보기**

- 한 항목에 붙어 다니는 값들을 벡터 여러 개에 나눠 담으면, 한쪽만 정렬하는 순간 짝이 어긋난다. `pair`로 묶어 한 벡터에 담으면 필드가 통째로 함께 움직인다.

```text
   BAD : two parallel vectors         GOOD : one vector of pairs
   --------------------------         --------------------------
   name  : kim   lee   park           data : ( kim  , 90 )
   score :  90    85     90                  ( lee  , 85 )
                                             ( park , 90 )
   sort(score.begin(), score.end())   sort by .second
   name  : kim   lee   park           data : ( lee  , 85 )
   score :  85    90     90                  ( kim  , 90 )
            ^^    ^^                         ( park , 90 )
            pairing is broken                pairing is kept
```

- 왼쪽에서는 `kim`이 갑자기 85점이 되어 버렸다. 오른쪽은 이름과 점수가 한 덩어리라 아무리 순서를 바꿔도 짝이 유지된다.
- `map<string,int>`의 `operator[]`는 없는 키를 만나면 **그 자리에 원소를 만들어 넣는다.** 이것이 `m[w]++`를 편하게 만들기도 하고, 읽기만 했는데 크기가 커지는 함정이 되기도 한다.

```text
   m["kim"]++          on a MISSING key
   --------------------------------------
   step 1 : insert  ( "kim" , 0 )      // default value for int is 0
   step 2 : return a reference to that 0
   step 3 : ++ turns it into 1

   if (m["lee"] == 0) ...              // READ ONLY? no :
   --> ( "lee" , 0 ) is inserted too, m.size() grows by one
```

**손으로 따라가기**

`count[w]++`가 단어를 하나씩 먹으며 `map`을 어떻게 키우는지 추적한다. 입력은 `apple banana apple cherry`.

| 단계 | 읽은 단어 `w` | `count[w]` 접근 결과 | `++` 후 값 | 단계 후 `count` |
|---|---|---|---|---|
| 1 | apple | 키 없음 → 0으로 자동 생성 | 1 | `{apple: 1}` |
| 2 | banana | 키 없음 → 0으로 자동 생성 | 1 | `{apple: 1, banana: 1}` |
| 3 | apple | 이미 있음 → 1 | 2 | `{apple: 2, banana: 1}` |
| 4 | cherry | 키 없음 → 0으로 자동 생성 | 1 | `{apple: 2, banana: 1, cherry: 1}` |

- 최다 빈도는 `apple`(2회). `operator[]`가 없는 키를 0으로 만들어 주는 덕분에 "이 단어를 처음 보는가"를 `if`로 따로 검사할 필요가 없었다. 또 `map`은 키를 오름차순으로 보관하므로 순회하면 apple → banana → cherry 순으로 나온다.

**왜 이렇게 되는가**

- **왜 `pair`가 필드 묶기에 적합한가**: 두 값이 한 덩어리라 벡터 안에서 아무리 자리를 옮겨도 `first`와 `second`의 짝이 깨지지 않는다. 파이썬 튜플과 달리 C++ `pair`는 내용을 나중에 고칠 수도 있어(`p.second = 95;`) "묶어 두되 값 하나만 갱신"도 자연스럽다.
- **왜 `pair`끼리 비교가 저절로 되나**: `pair`의 `<`는 **사전식(lexicographic)** 으로 정의돼 있다. `first`를 먼저 보고, 같을 때만 `second`를 본다. 사전에서 단어를 찾을 때 첫 글자부터 보는 것과 같은 규칙이다. 덕분에 `vector<pair<int,int>>`는 비교 함수를 안 주고 `sort`만 해도 "1순위 first 오름, 2순위 second 오름"이 공짜로 나온다. `tuple`도 규칙이 같다.
- **왜 `m[key]++`가 오류 없이 되나**: `std::map::operator[]`는 키가 없으면 **그 자리에 기본값 원소를 삽입하고** 그것의 참조를 돌려준다. `int`의 기본값은 0이므로 `++`는 언제나 유효한 정수를 증가시킨다. 파이썬 `dict[k] += 1`이 `KeyError`를 내던 것과 정반대라, 파이썬에서 넘어오면 오히려 편하게 느껴진다.
- **왜 바로 그것이 함정인가**: 같은 이유로 `if (m[k] == 0)`처럼 **읽기만 하려 해도 원소가 생긴다.** `m.size()`가 슬그머니 늘고, 나중에 `m`을 순회하면 넣은 적 없는 키가 값 0으로 튀어나와 "왜 답이 하나 더 많지?"가 된다. 존재 여부만 확인할 때는 `m.count(k)`나 `m.find(k) != m.end()`를 쓴다.
- **왜 빈도 세기가 O(N log N)인가**: `std::map`은 균형 이진 탐색 트리라 조회·삽입 한 번이 O(log N)이다. 단어 N개를 훑으면 O(N log N)이고, 대신 키가 항상 정렬된 상태라 "동점이면 사전순 먼저" 같은 규칙을 공짜로 얻는다. 순서가 필요 없고 속도만 중요하면 해시 기반 `unordered_map`이 평균 O(1)이라 전체가 O(N)이 된다 — 파이썬 `dict`에 해당하는 것이 이쪽이다.

**접근 전략**

- "여러 정보가 한 사람/한 항목에 붙어 다닌다"면 값을 따로따로 여러 `vector`에 나눠 담지 말고 한 `pair`/`struct`로 묶어 한 `vector`에 담는다. 그래야 나중에 통째로 정렬·이동해도 필드가 어긋나지 않는다.
- 필드가 2개고 위치가 명확하면 `pair`, 필드가 많거나 이름으로 다뤄야 읽기 좋으면 `struct`를 고른다.
- "가장 ~한 항목"을 찾을 때는 (1) 기준 필드의 최댓/최솟값을 먼저 구하고 (2) 그 값을 가진 항목(들)을 걸러낸다. 동점 처리 규칙(예: 이름이 앞선 것)을 문제에서 반드시 확인한다.
- 빈도/집계는 `map` 한 번 순회로 O(N log N). 그 뒤 최댓값 찾기도 항목 수에 비례한다. `map`이 키를 정렬해 두는 성질은 동점 시 "사전순 먼저"를 공짜로 얻는 데 쓸 수 있다.

**문제**

**1) 최고 점수 학생** · Easy

- **요구사항**: 학생들의 (이름, 점수)가 주어질 때, 최고 점수를 받은 학생의 이름을 출력한다. 동점이면 이름이 사전순으로 가장 앞선 학생을 출력한다.
- **입력**: 첫 줄에 N. 다음 N줄에 각 줄마다 이름과 점수.
- **출력**: 조건을 만족하는 학생 이름 하나.
- **예제**: `3 / kim 90 / lee 85 / park 90` → `kim`  (최고 90점은 kim, park 동점 → 사전순 kim)
- **예제**: `2 / bob 70 / amy 70` → `amy`
- **셀프체크**: (이름, 점수)를 `pair`로 묶어 `vector`에 담았는가. 최고 점수를 먼저 구한 뒤 그 점수인 학생들 중에서 이름을 비교하는가. 점수를 `int`로 읽어 숫자로 비교하는가(문자열 비교 함정).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<string, int>> students(n);
    for (int i = 0; i < n; i++) {
        string name;
        int score;
        cin >> name >> score;
        students[i] = {name, score};
    }
    int best = students[0].second;
    for (auto& s : students) best = max(best, s.second);
    string ans = "";
    for (auto& s : students) {
        if (s.second == best) {
            if (ans == "" || s.first < ans) ans = s.first;
        }
    }
    cout << ans << '\n';
    return 0;
}
@@TESTS
--IN
3
kim 90
lee 85
park 90
--OUT
kim
--IN
2
bob 70
amy 70
--OUT
amy
@@EXPL
(1) 접근·핵심 아이디어

- 각 학생을 `pair<string,int>`(이름, 점수)로 묶어 한 `vector`에 담는다. 그래야 필드가 어긋나지 않는다.
- "최고 점수 + 동점이면 이름 사전순"은 두 단계로 나눈다. (1) 먼저 최고 점수를 구하고 (2) 그 점수를 가진 학생 이름들 중 사전순으로 가장 작은 것을 고른다.

(2) 코드 단계별

- N줄을 읽으며 `cin >> name >> score`로 이름과 점수를 각각 받는다. 점수는 `int`로 읽어 숫자 비교가 되게 한다(문자열 비교 함정 방지).
- 첫 번째 순회로 `best`(최고 점수)를 `max`로 구한다.
- 두 번째 순회에서 `s.second == best`인 학생만 보고, 아직 답이 없거나(`ans == ""`) 지금 이름이 더 작으면(`s.first < ans`) 답을 갱신한다. 최종적으로 사전순 가장 앞선 이름이 남는다.

(3) 스스로 다시 짤 때 생각 순서

- "가장 ~한 항목" → 기준 값(최고 점수)을 먼저 구한다.
- "동점 처리" → 그 값을 가진 후보만 걸러 두 번째 기준(이름)으로 최솟값을 찾는다.
- 점수는 반드시 `int`로 읽어 비교(문자열 "9" > "85" 같은 오류 방지).
```

**2) 가장 많이 나온 단어** · Medium

- **요구사항**: 단어 N개가 주어질 때, 가장 많이 등장한 단어를 출력한다. 최다 빈도가 여럿이면 사전순으로 가장 앞선 단어를 출력한다.
- **입력**: 첫 줄에 N. 다음 N개의 단어(줄 단위 또는 공백 구분).
- **출력**: 단어 하나.
- **예제**: `6 / apple banana apple cherry banana apple` → `apple`  (apple 3, banana 2, cherry 1)
- **예제**: `4 / dog cat cat dog` → `cat`  (dog 2, cat 2 동점 → 사전순 cat)
- **셀프체크**: `map`으로 빈도를 세었는가. 동점일 때 "빈도가 큰 것 우선, 같으면 이름 작은 것"이라는 두 기준을 함께 처리하는가. 빈도가 아니라 등장 순서로 착각하지 않았는가.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<string> words(n);
    for (int i = 0; i < n; i++) cin >> words[i];
    map<string, int> count;
    for (auto& w : words) count[w]++;
    string bestWord = "";
    int bestFreq = -1;
    for (auto& kv : count) {
        if (kv.second > bestFreq) {
            bestFreq = kv.second;
            bestWord = kv.first;
        }
    }
    cout << bestWord << '\n';
    return 0;
}
@@TESTS
--IN
6
apple banana apple cherry banana apple
--OUT
apple
--IN
4
dog cat cat dog
--OUT
cat
@@EXPL
(1) 접근·핵심 아이디어

- 빈도 세기는 `map<string,int>` 한 번 순회로 끝난다. `count[w]++` — 없던 키는 0에서 시작해 +1.
- 우승자는 두 기준을 함께 본다: 빈도가 큰 것 우선, 같으면 이름이 사전순으로 작은 것. 여기서 `std::map`이 키를 오름차순(사전순)으로 순회한다는 성질을 이용한다. 사전순으로 훑으면서 `kv.second > bestFreq`(엄격한 초과)일 때만 갱신하면, 빈도가 같은 경우에는 먼저 만난(=사전순 앞선) 단어가 유지된다.

(2) 코드 단계별

- 단어 N개를 `vector`로 읽고, `count[w]++`로 빈도 `map`을 채운다.
- `bestFreq`를 -1로 초기화한 뒤 `map`을 사전순으로 순회한다.
- `kv.second > bestFreq`(엄격한 초과)일 때만 최댓값을 갱신하므로, 빈도가 같은 뒤 단어는 갱신되지 않아 사전순 먼저 단어가 살아남는다.
- 최종 `bestWord`가 답이다.

(3) 스스로 다시 짤 때 생각 순서

- "가장 많이" → 빈도 `map`부터 만든다.
- "동점 처리" → `map`의 정렬 순회 + "엄격한 초과 비교"로 사전순 우선을 얻는다. `>=`로 하면 동점일 때 뒤 단어로 덮여버리니 주의.
- 작은 케이스(dog·cat 동점)로 사전순 먼저가 나오는지 반드시 검산한다.
```

**3) 재고 부족 상품 집계** · Medium

- **요구사항**: 상품들의 (이름, 가격, 재고)가 주어진다. 재고가 임계값 T 미만인 상품의 "개수"와 그런 상품들의 "가격 합"을 출력한다.
- **입력**: 첫 줄에 N과 T. 다음 N줄에 이름 가격 재고.
- **출력**: 부족 상품 개수와 가격 합(공백 구분).
- **예제**: `3 5 / pen 100 2 / book 300 10 / ink 50 4` → `2 150`  (재고 2, 4가 5 미만 → pen, ink / 개수 2, 가격 100+50=150)
- **예제**: `2 1 / a 10 0 / b 20 5` → `1 10`
- **셀프체크**: 각 상품의 (이름, 가격, 재고) 세 필드를 제대로 나눠 읽었는가. "T 미만"이 `< T`인지 `<= T`인지 정확히 구분했는가(경계 함정). 조건을 만족하는 항목만 골라 개수와 합을 동시에 누적했는가.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, t;
    cin >> n >> t;
    int cnt = 0;
    long long total = 0;
    for (int i = 0; i < n; i++) {
        string name;
        int price, stock;
        cin >> name >> price >> stock;
        if (stock < t) {
            cnt++;
            total += price;
        }
    }
    cout << cnt << ' ' << total << '\n';
    return 0;
}
@@TESTS
--IN
3 5
pen 100 2
book 300 10
ink 50 4
--OUT
2 150
--IN
2 1
a 10 0
b 20 5
--OUT
1 10
@@EXPL
(1) 접근·핵심 아이디어

- 상품마다 세 필드 `이름 가격 재고`를 읽어 조건 `재고 < T`를 확인한다.
- "T 미만"은 `< T`이지 `<= T`가 아니다. 경계 함정이 핵심. 예: T=5면 재고 5는 포함되지 않고, 재고 2·4만 부족으로 센다.
- 조건을 만족하는 항목에 대해 개수와 가격 합을 동시에 누적한다.

(2) 코드 단계별

- `cin >> n >> t`로 상품 수와 임계값을 읽는다.
- 누적 변수 `cnt`(개수)를 0, `total`(가격 합)을 `long long` 0으로 초기화한다(합이 커질 수 있어 안전).
- 각 줄에서 `cin >> name >> price >> stock`으로 세 필드를 나눠 읽는다.
- `if (stock < t)`일 때만 `cnt++`, `total += price`로 함께 누적한다.
- 마지막에 `cout << cnt << ' ' << total`로 공백 구분 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "조건을 만족하는 것만 집계" → 누적 변수 초기화 후 루프 안에서 `if`로 걸러 누적.
- 부등호 방향("미만" = `<`)을 문제 문장에서 그대로 옮긴다. `<=`와 혼동하지 않기.
- 개수와 합을 각각 다른 루프로 두 번 돌 필요 없이 한 번에 처리한다.
```


## L3. 객체 정렬

**개념**

- 객체(`pair`·`struct`)를 정렬할 때, "무엇을 기준으로 줄 세울지"를 정해 주어야 한다. C++에서는 `std::sort`의 세 번째 인자로 "비교 함수"를 넘긴다. 비교 함수는 두 원소 `a`, `b`를 받아 "`a`가 `b`보다 앞에 와야 하면 `true`"를 돌려준다. 보통 람다(`[](...) { ... }`)로 짧게 쓴다.

```cpp
vector<pair<string,int>> data = {{"kim",90},{"lee",85},{"park",88}};
// 점수 오름차순 -> lee, park, kim
sort(data.begin(), data.end(), [](const pair<string,int>& a, const pair<string,int>& b) {
    return a.second < b.second;   // a.second가 작으면 a가 앞
});
```

- 람다 `[](const auto& a, const auto& b){ return a.second < b.second; }`는 "이름 없는 1회용 비교 함수"다. `<`(작으면 앞)이면 오름차순, `>`(크면 앞)이면 내림차순이 된다.
- 여러 기준을 동시에 쓰려면 "1순위가 같을 때만 2순위를 비교"하도록 단계적으로 반환한다. 1순위로 우열이 갈리면 거기서 결정하고, 같을 때만 2순위를 본다.

```cpp
// 점수 내림차순, 점수가 같으면 이름 오름차순
sort(data.begin(), data.end(), [](const pair<string,int>& a, const pair<string,int>& b) {
    if (a.second != b.second) return a.second > b.second;  // 1순위: 점수 내림
    return a.first < b.first;                              // 2순위: 이름 오름
});
```

- 각 순위의 방향은 부등호로 정한다. 오름차순이면 `<`, 내림차순이면 `>`. 필드마다 방향이 달라도 순위별로 부등호를 따로 쓰면 되므로 자유롭게 조합할 수 있다.

**그림으로 보기**

- 파이썬은 원소를 "비교용 값"으로 갈아 끼우는 `key`를 썼지만, C++ 비교 함수는 **두 원소를 직접 놓고 "a가 b보다 앞이냐"는 질문 하나에만 답한다.** 다중 기준은 그 질문 안에서 위에서 아래로 답을 찾아가는 구조가 된다.

```text
   cmp(a, b) : should a come before b ?
   ------------------------------------
   cmp( ( kim , 90 ) , ( park , 90 ) )
        1st field : 90 == 90         --> undecided, fall through
        2nd field : "kim" < "park"   --> true  : kim first

   cmp( ( kim , 90 ) , ( lee , 85 ) )
        1st field : 90 >  85         --> true  : kim first
                                         the 2nd field is never read
```

- 1순위에서 우열이 갈리면 그 자리에서 `return`으로 나가고, 같을 때만 아래 줄이 실행된다. 그래서 아래 줄은 "1순위가 동점"이 보장된 상태에서만 도는 코드다.

```text
   rule : score DOWN, then name UP
   -------------------------------
   ( kim  , 90 )          ( kim  , 90 )
   ( lee  , 85 )   -->    ( park , 90 )
   ( park , 90 )          ( lee  , 85 )
                            ^      ^
                            |      +-- 90, 90, 85 : descending
                            +--------- kim < park : ascending inside a tie
```

- 마지막으로, `std::sort`는 **안정 정렬이 아니다.** 완전히 동점인 원소들의 상대 순서는 보장되지 않는다. 입력 순서를 지켜야 하면 `stable_sort`를 쓴다.

```text
   input       :  A3  B1  C3  D1  E3   // letter = id, digit = key
   key         :   3   1   3   1   3
   stable_sort :  B1  D1  A3  C3  E3   // B before D, A before C before E
   sort        :  D1  B1  A3  E3  C3   // ties may come out in ANY order
```

**손으로 따라가기**

"점수 내림차순, 같으면 이름 오름차순" 비교 함수가 실제로 어떤 판정을 내리는지 짝별로 확인한다.

| 비교하는 두 원소 | 1순위 `a.second != b.second`? | 반환하는 식 | 결과 | 앞에 오는 쪽 |
|---|---|---|---|---|
| `("kim",90)` vs `("lee",85)` | 90≠85 → 참 | `90 > 85` | `true` | kim |
| `("kim",90)` vs `("park",90)` | 90≠90 → 거짓 | `"kim" < "park"` | `true` | kim |
| `("park",90)` vs `("lee",85)` | 90≠85 → 참 | `90 > 85` | `true` | park |
| `("lee",85)` vs `("kim",90)` | 85≠90 → 참 | `85 > 90` | `false` | kim |

- 이 판정들을 모두 만족하는 배열은 `kim → park → lee` 하나뿐이다. 점수는 내림차순(90, 90, 85), 같은 90 안에서는 이름 오름차순(kim, park)이 되었다.

**왜 이렇게 되는가**

- **왜 부등호 방향이 곧 정렬 방향인가**: 비교 함수는 "a를 b보다 앞에 둘까?"에 답한다. `a.second < b.second`는 "작은 쪽이 앞"이라 오름차순, `>`는 "큰 쪽이 앞"이라 내림차순이다. 파이썬처럼 값에 `-`를 붙여 뒤집을 필요가 없고, 그래서 **문자열 기준도 자유롭게 내림차순으로 둘 수 있다**(`a.first > b.first`). 파이썬에서 문자열 내림차순이 까다로웠던 제약이 C++에는 없다.
- **왜 1순위가 같을 때만 2순위를 보나**: `if (a.second != b.second) return a.second > b.second;`에서 점수가 다르면 답이 그 줄에서 확정돼 함수가 끝난다. 다음 줄까지 흘러왔다는 것은 "점수가 같다"가 이미 증명됐다는 뜻이므로, 거기서 이름을 비교하면 정확히 "동점자 안에서의 순서"가 된다. 파이썬의 튜플 키가 앞 칸부터 비교하던 규칙을 `if`로 직접 적어 놓은 것과 같다.
- **왜 `<=`를 쓰면 프로그램이 죽나 (strict weak ordering)**: `std::sort`는 비교 함수가 **엄격한 약한 순서**를 지킨다고 믿고, 그 믿음 위에서 "여기서 멈출 것"이라는 경계 검사를 생략하며 최적화한다. `a.second <= b.second`처럼 같아도 `true`를 돌려주면 `cmp(a,b)`와 `cmp(b,a)`가 동시에 참이 되어 순서가 모순되고, 정렬기가 구간 밖으로 뛰쳐나가 **런타임에 죽거나 조용히 메모리를 망가뜨린다.** 답이 살짝 틀리는 정도가 아니다. 규칙은 간단하다 — 비교 함수 안에서는 `<`와 `>`만 쓰고 `<=`·`>=`는 절대 쓰지 않는다. 마지막 줄도 `return a.first < b.first;`처럼 엄격한 부등호여야 한다.
- **왜 `std::sort`는 동점 순서를 보장하지 않나**: 안정 정렬이 아니기 때문이다. 파이썬 `sorted`는 안정이라 "동점이면 입력 순서"가 공짜였지만, C++에서는 같은 코드가 실행 환경에 따라 다른 순서를 낼 수 있다. 입력 순서를 동점 규칙으로 써야 한다면 (1) `stable_sort`를 쓰거나 (2) 원래 인덱스를 필드에 넣고 최하위 기준으로 비교한다. `stable_sort`는 안정성을 얻는 대신 추가 메모리를 쓰고 상수가 조금 크다.
- **왜 비교 함수 인자를 `const T&`로 받나**: 정렬 한 번에 비교가 대략 N log N 번 일어난다. 인자를 값으로 받으면 그때마다 `pair<string,int>`가 통째로 복사돼 정렬 본체보다 복사가 더 비싸질 수 있다. `const T&`로 받으면 복사가 0이고, 실수로 원소를 고치는 코드도 컴파일러가 막아 준다.
- **왜 파이썬의 `key`와 비용 구조가 다른가**: 파이썬은 원소마다 `key`를 **딱 한 번** 계산해 두고 그 값만 비교했다. C++ 비교 함수는 **비교할 때마다 매번** 실행된다. 그래서 함수 안에서 문자열을 새로 만들거나 제곱근을 계산하면 그 비용에 log N이 곱해진다. 무거운 기준은 미리 계산해 필드로 넣어 두고, 비교 함수는 필드만 읽게 하는 것이 정석이다.

**접근 전략**

- 문제의 정렬 규칙을 "1순위는 무엇, 같으면 2순위는 무엇, 또 같으면 3순위는 무엇" 형태로 말로 먼저 정리한다. 그 순서대로 비교 함수 안에서 `if (1순위가 다르면) return 1순위 비교;` … 마지막에 `return 최하위 비교;`로 옮기면 그대로 코드가 된다.
- 각 순위마다 오름차순이면 `<`, 내림차순이면 `>`를 쓴다. 필드가 문자열이든 정수든 방향만 맞추면 된다.
- 언제 쓰나: 랭킹표 만들기, 동점자 처리, 구간을 시작점 기준으로 줄 세우기, "길이 먼저 그다음 사전순" 같은 복합 정렬. 실전 정렬 문제의 대부분이 이 다중 키 패턴이다.
- 주의점: 비교 함수의 "필드·부등호 방향"이 규칙과 정확히 일치하는지 예제로 검산한다. 복잡도는 여전히 O(N log N)이며, 비교는 필요할 때마다 두 원소를 놓고 이뤄진다.

**문제**

**1) 성적 순위표** · Medium

- **요구사항**: 학생들의 (이름, 점수)를 점수 내림차순으로 정렬하되, 점수가 같으면 이름 사전순(오름차순)으로 정렬해 출력한다.
- **입력**: 첫 줄에 N. 다음 N줄에 이름 점수.
- **출력**: 정렬된 순서대로 각 줄에 "이름 점수".
- **예제**: `4 / kim 90 / lee 85 / park 90 / choi 85` → `kim 90` / `park 90` / `choi 85` / `lee 85`
- **예제**: `2 / z 50 / a 50` → `a 50` / `z 50`
- **셀프체크**: 비교 함수가 1순위(점수 내림 `>`)와 2순위(이름 오름 `<`)를 단계적으로 처리하는가. 점수를 `int`로 읽었는가. 동점자 순서가 규칙대로 나오는지 예제로 확인했는가.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<string, int>> students(n);
    for (int i = 0; i < n; i++) {
        string name;
        int score;
        cin >> name >> score;
        students[i] = {name, score};
    }
    sort(students.begin(), students.end(), [](const pair<string,int>& a, const pair<string,int>& b) {
        if (a.second != b.second) return a.second > b.second; // 점수 내림
        return a.first < b.first;                             // 이름 오름
    });
    for (auto& s : students) cout << s.first << ' ' << s.second << '\n';
    return 0;
}

- 정렬 규칙을 말로 정리한다: 1순위 점수 내림차순, 같으면 2순위 이름 오름차순.
- 방향이 서로 다르므로 순위별로 부등호를 다르게 쓴다. 점수는 `>`(크면 앞 = 내림), 이름은 `<`(작으면 앞 = 오름).

(2) 코드 단계별

- N줄을 읽어 `pair<string,int>`(이름, 점수) `vector`를 만든다. 점수는 `int`로 읽는다.
- 비교 람다에서 `a.second != b.second`면 점수 비교로 결판낸다(`a.second > b.second` → 점수 큰 쪽이 앞).
- 점수가 같으면 `a.first < b.first`로 이름 사전순 오름차순.
- 정렬된 순서대로 `cout << s.first << ' ' << s.second`로 한 줄씩 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- 규칙을 "1순위 …, 같으면 2순위 …" 문장으로 먼저 적는다.
- 각 순위마다 방향을 정하고, 내림차순은 `>`, 오름차순은 `<` → 비교 함수에 단계적으로 나열.
- 동점 케이스(kim·park 90 / z·a 50)로 순서가 규칙대로 나오는지 검산.
```

**2) 키·몸무게 줄 세우기** · Medium

- **요구사항**: 사람들의 (키, 몸무게)를 키 내림차순으로, 키가 같으면 몸무게 오름차순으로 정렬해 출력한다.
- **입력**: 첫 줄에 N. 다음 N줄에 키 몸무게(정수).
- **출력**: 정렬된 순서대로 각 줄에 "키 몸무게".
- **예제**: `4 / 180 75 / 175 70 / 180 70 / 175 72` → `180 70` / `180 75` / `175 70` / `175 72`
- **예제**: `2 / 170 60 / 170 55` → `170 55` / `170 60`
- **셀프체크**: 두 기준의 방향이 서로 다르다(하나는 내림, 하나는 오름). 순위별로 부등호를 다르게 써서 방향을 각각 맞췄는가. 같은 키에서 몸무게 순서가 오름인지 확인.

@@SOLUTION
#include <bits/stdc++.h>

- 순위별로 부등호를 다르게 쓴다. 1순위 키는 `>`(크면 앞 = 내림), 2순위 몸무게는 `<`(작으면 앞 = 오름).

- 키가 같으면 `a.second < b.second`로 몸무게 오름차순.

- 방향이 엇갈려도 순위별 부등호를 따로 쓰면 그만이다(키 `>`, 몸무게 `<`).
- 같은 키(180끼리, 175끼리)에서 몸무게가 오름차순으로 나오는지 예제로 검산.

**3) 단어 정렬: 길이 먼저, 같으면 사전순** · Medium

- **요구사항**: 단어 N개를 길이 오름차순으로, 길이가 같으면 사전순으로 정렬해 출력한다.
- **입력**: 첫 줄에 N. 다음 N개의 단어.
- **출력**: 정렬된 순서대로 각 단어를 공백으로 구분해 한 줄에 출력.
- **예제**: `5 / banana apple kiwi fig pear` → `fig kiwi pear apple banana`  (길이 3,4,4,5,6 / 길이 4인 kiwi·pear는 사전순)
- **예제**: `3 / bb aa cc` → `aa bb cc`  (모두 길이 2 → 사전순)
- **셀프체크**: 비교 함수가 "길이(오름) → 사전순(오름)" 순서를 지켰는가. 길이가 같은 단어들끼리만 사전순이 되는지 예제로 확인. 중복 단어가 있으면 각각을 그대로 출력하는가(중복 제거 요구가 없음에 주의).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<string> words(n);
    for (int i = 0; i < n; i++) cin >> words[i];
    sort(words.begin(), words.end(), [](const string& a, const string& b) {
        if (a.size() != b.size()) return a.size() < b.size(); // 길이 오름
        return a < b;                                         // 사전순 오름
    });
    for (int i = 0; i < (int)words.size(); i++) {
        if (i > 0) cout << ' ';
        cout << words[i];
    }
    cout << '\n';
    return 0;
}
@@TESTS
--IN
5
banana apple kiwi fig pear
--OUT
fig kiwi pear apple banana
--IN
3
bb aa cc
--OUT
aa bb cc
@@EXPL
(1) 접근·핵심 아이디어

- 정렬 규칙: 1순위 길이 오름차순, 같으면 2순위 사전순(오름차순). 둘 다 오름차순이라 모두 `<`를 쓴다.
- 비교 함수에서 길이가 다르면 `a.size() < b.size()`로 결판내고, 길이가 같을 때만 `a < b`(문자열 사전순 비교)로 넘어간다 — 정확히 원하는 순서다.

(2) 코드 단계별

- 단어 N개를 `vector<string>`으로 읽는다.
- 비교 람다에서 `a.size() != b.size()`면 길이 비교(`a.size() < b.size()` → 짧은 게 앞).
- 길이가 같으면 `a < b`로 사전순. `std::string`의 `<`는 사전순 비교라 그대로 쓰면 된다.
- 인덱스로 순회하며 원소 사이에만 공백을 넣어 한 줄로 출력한다(중복 제거 요구가 없으므로 그대로 둔다).

(3) 스스로 다시 짤 때 생각 순서

- 규칙을 "길이 먼저, 같으면 사전순"으로 적고 그대로 비교 함수에 옮긴다.
- 둘 다 오름차순이면 모두 `<`를 쓰면 된다는 점을 확인한다.
- 길이 4인 `kiwi`·`pear`가 사전순으로 나오는지 예제로 검산한다.
```

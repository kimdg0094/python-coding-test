## L7. 정리 — 개념 지도·체크리스트·자주 하는 실수

**개념**

- 이 레슨은 새로 풀 것을 내지 않는다. Ch8에서 배운 것들이 서로 어떻게 이어지는지 한 장으로 정리하고, 다음에 바로 꺼내 쓸 뼈대와 자주 밟는 지뢰를 모아 둔다.

- 2차원 배열은 겉모습이 아무리 달라도 결국 세 가지 질문으로 갈린다. (1) 표를 어디서 얻는가(입력/직접 생성), (2) 칸의 값을 무엇으로 정하는가(입력값/좌표 규칙/방문 순서), (3) 이웃을 보는가(격자).

- C++에서는 여기에 질문이 하나 더 붙는다. **표를 어디에 얼마나 잡을 것인가.** 크기가 상수여야 하는지, 전역에 둘지, `vector`로 만들지가 코드 첫 줄에서 갈린다.

**개념 지도**

세 갈래가 모두 같은 엔진(모든 칸을 도는 이중 반복)으로 모인다. 갈라지는 곳과 다시 만나는 곳을 함께 보자.

```text
                 2D array : rows of boxes , index is [row][col]
                                   |
     +----------------+------------+------------+----------------+
     |                |                         |                |
  L1 input        L2 create              L3 / L4 fill        L5 grid
  cin >> a[i][j]  int a[N][N] = {0};     i, j -> value       cell (r, c)
  n rows , m cols vector<vector<int>>    pattern / order     4 neighbors
     |                |                         |                |
     +----------------+------------+------------+----------------+
                                   |
                   every branch ends at the same engine
                      for (int i = 0; i < n; i++)
                          for (int j = 0; j < m; j++)
                              ... board[i][j] ...
                                   |
                  +----------------+----------------+
                  |                                 |
            read a cell                       write a cell
            total / cnt / max                 board[i][j] = value
            find a position                   new board : T , rotate
```

읽기만 하면 원본 한 장으로 충분하고, 쓰기가 섞이면 결과를 담을 **새 표**가 필요할 때가 많다. 특히 이웃을 보며 값을 갱신하는 문제는 원본을 덮어쓰면 안 된다.

격자(L5)에서만 추가로 필요한 것이 이웃 좌표와 경계 검사다.

```text
  neighbor offsets              bounds check (n rows, m cols)
   dr[4] = {-1, 1, 0, 0}         nr >= 0 && nr < n && nc >= 0 && nc < m
   dc[4] = { 0, 0,-1, 1}         ^^^^^^^^^^^^^^^^^^^^^^^^ check FIRST
           up dn lt rt           then read board[nr][nc]

        (r-1, c)                 r - 1 = -1  -> reads memory before array
            |                    r + 1 = n   -> reads an unused row
  (r, c-1)-(r, c)-(r, c+1)       BOTH are silent : no error at all
            |
        (r+1, c)                 # 파이썬과 달리 양쪽 다 조용히 틀린다
```

파이썬 문법을 그대로 옮기면 안 되는 자리가 하나 있다.

```text
  python :  0 <= nr < n                  ->  works as expected
  C++    :  0 <= nr < n                  ->  parsed as (0 <= nr) < n
                                             true / false becomes 1 / 0
                                             then compared with n
                                             so it is ALWAYS true if n > 1
  C++ ok :  nr >= 0 && nr < n            # 반드시 두 조건으로 나눠 쓴다
```

**뼈대 코드**

```cpp
// 1) 격자 입력 + 모든 칸 순회 (합·개수·최댓값)
#include <bits/stdc++.h>
using namespace std;

int board[100][100];          // 넉넉히 잡고 앞의 n x m 만 쓴다

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++)
            cin >> board[i][j];

    long long total = 0;      // 합이 커질 수 있으면 long long
    int cnt = 0;
    int mx = board[0][0];     // 0 이 아니라 첫 칸에서 시작 (음수 대비)
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            int v = board[i][j];
            total += v;
            if (v >= 5) cnt++;        // <- 문제마다 바뀜 (세는 조건)
            if (v > mx) mx = v;       // <- > 는 첫 등장, >= 는 마지막 등장
        }
    }
    cout << total << " " << cnt << " " << mx << "\n";
    return 0;
}
```

```cpp
// 2) 새 표를 만들어 칸 규칙대로 채우기 (패턴)
int n, m;
cin >> n >> m;
int board[100][100] = {0};            // = {0} 으로 전체를 0 으로
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        if ((i + j) % 2 == 0) {       // <- 문제마다 바뀜 (칸 조건)
            board[i][j] = 1;          // <- 문제마다 바뀜 (넣을 값)
        }
    }
}
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        if (j > 0) cout << " ";
        cout << board[i][j];
    }
    cout << "\n";
}
```

```cpp
// 3) 순서대로 채우기 (행 우선 / 지그재그)
int num = 1;                          // 이어지는 번호는 반복 '밖'에서
for (int i = 0; i < n; i++) {
    if (i % 2 == 0) {                 // <- 지그재그가 아니면 이 분기를 없앤다
        for (int j = 0; j < m; j++) {
            board[i][j] = num;
            num++;
        }
    } else {
        for (int j = m - 1; j >= 0; j--) {   // 거꾸로: >= 0 이어야 0 열 포함
            board[i][j] = num;
            num++;
        }
    }
}
```

```cpp
// 4) 4방향 이웃 보기 (경계 검사 포함)
int dr[4] = {-1, 1, 0, 0};
int dc[4] = {0, 0, -1, 1};
int res[100][100] = {0};              // 결과는 반드시 새 표에
for (int r = 0; r < n; r++) {
    for (int c = 0; c < m; c++) {
        int cnt = 0;
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d];
            int nc = c + dc[d];
            // 범위 검사를 왼쪽에 두어야 밖의 칸을 읽지 않는다
            if (nr >= 0 && nr < n && nc >= 0 && nc < m) {
                if (board[nr][nc] == 1) cnt++;   // <- 문제마다 바뀜
            }
        }
        res[r][c] = cnt;
    }
}
```

```cpp
// 5) 크기가 바뀌는 변환 (전치 / 시계 90도 회전)
int t[100][100] = {0};                // 결과는 m행 n열 (n, m 자리 교환)
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        t[j][i] = board[i][j];                  // 전치
        // t[j][n - 1 - i] = board[i][j];       // <- 시계 90도면 이 줄
    }
}
for (int i = 0; i < m; i++) {         // 출력 줄 수도 m 으로 바뀐다
    for (int j = 0; j < n; j++) {
        if (j > 0) cout << " ";
        cout << t[i][j];
    }
    cout << "\n";
}
```

**언제 무엇을 쓰나**

| 상황 | 고르는 것 | 이유 | 복잡도 |
| --- | --- | --- | --- |
| 표 크기가 미리 정해져 있다 | `int board[100][100];` | 크기가 상수여야 하므로 넉넉히 잡는다 | — |
| 표 크기를 실행 중에 정한다 | `vector<vector<int>> b(n, vector<int>(m, 0));` | 고정 크기 배열은 상수만 받는다 | — |
| 표가 아주 크다(수백만 칸) | 전역에 선언 | 함수 안에 두면 임시 공간을 넘어 죽는다 | — |
| 표 전체의 합·개수 | 이중 반복 1회 + 누적 변수 | 모든 칸을 한 번씩만 보면 충분 | O(n·m) |
| 행마다 결과가 하나씩 | 바깥 `i`, 안쪽 `j`, 합 초기화는 바깥 반복 **안** | 합의 수명이 "행 하나" | O(n·m) |
| 열마다 결과가 하나씩 | 바깥 `j`, 안쪽 `i` (대입은 여전히 `board[i][j]`) | 열 단위로 훑어야 함 | O(n·m) |
| 칸 값이 좌표로 정해짐 | 0으로 초기화한 표 + `if` 조건식 | 한 칸 기준 질문으로 환원 | O(n·m) |
| 채우는 순서가 관건 | 카운터 `num` + 방문 순서 반복 | 값은 순서대로, 순서만 설계 | O(n·m) |
| 이웃을 봐야 함 | `dr`/`dc` 방향표 + 경계 검사 | 네 방향을 한 반복으로 처리 | O(4·n·m) |
| 결과 크기가 달라짐(전치·회전) | 새 표에 담고 `n`, `m`도 교환 | 행·열 수가 뒤바뀜 | O(n·m) |
| 회전을 `k`번 | `k % 4`로 줄인 뒤 반복 | 4번이면 제자리 | O(n·m) |
| 이웃 값으로 표를 갱신 | 결과 전용 새 표 | 원본을 덮으면 뒷 칸이 오염됨 | O(n·m) |
| 케이스가 여러 개 | 케이스마다 표를 다시 0으로 | 지난 케이스 값이 남는다 | O(n·m) |

**✅ 마스터 체크리스트**

- [ ] 설명할 수 있다: `board[i][j]`에서 `i`가 행이고 `j`가 열인 이유와, `board[i]`가 무엇을 가리키는지.
- [ ] 설명할 수 있다: 고정 크기 배열의 크기가 왜 상수여야 하는지와, `cin >> n;` 뒤에 `int a[n][n];`을 쓸 수 없는 이유.
- [ ] 설명할 수 있다: `int a[100][100] = {0};` 한 줄이 왜 모든 칸을 0으로 만드는지.
- [ ] 설명할 수 있다: `= {0}`을 빠뜨렸을 때 나타나는 증상과, 그것이 파이썬에는 왜 없는 문제인지.
- [ ] 설명할 수 있다: 큰 표를 함수 안에 선언하면 왜 프로그램이 죽는지와, 전역에 두면 무엇이 달라지는지.
- [ ] 설명할 수 있다: 파이썬 `[[0]*m]*n`의 공유 함정이 C++에서는 왜 일어나지 않는지.
- [ ] 설명할 수 있다: 행 우선과 열 우선 순회의 차이, 그리고 무엇을 바깥 반복으로 두면 어느 순서가 되는지.
- [ ] 설명할 수 있다: 거꾸로 도는 반복에서 조건을 `j >= 0`으로 써야 하는 이유와, 반복 변수를 `int`로 두어야 하는 이유.
- [ ] 설명할 수 있다: 체스판·대각선·테두리·십자를 각각 어떤 한 칸 조건식으로 쓰는지.
- [ ] 설명할 수 있다: 반대 대각선 조건이 `i + j == n - 1`인 이유.
- [ ] 설명할 수 있다: 격자 밖 좌표를 읽었을 때 C++이 어느 방향에서도 오류를 내지 않는 이유와, 그것이 왜 더 위험한지.
- [ ] 설명할 수 있다: `0 <= nr < n`을 C++에서 쓰면 왜 검사가 무력해지는지.
- [ ] 설명할 수 있다: `&&`로 조건을 이을 때 범위 검사를 왼쪽에 두어야 하는 이유.
- [ ] 설명할 수 있다: 전치·회전에서 새 표의 크기가 `m행 n열`이 되는 이유와, 출력 줄 수가 함께 바뀌는 이유.
- [ ] 설명할 수 있다: 회전 `k`번을 `k % 4`로 줄여도 되는 이유.
- [ ] 설명할 수 있다: 이웃 개수 지도를 만들 때 원본을 덮어쓰면 왜 틀리는지.
- [ ] 설명할 수 있다: 최댓값 후보의 시작값을 0이 아니라 `board[0][0]`으로 두는 이유.
- [ ] 설명할 수 있다: 모든 칸을 한 번씩 보는 코드의 비용이 왜 `n × m`에 비례하는지.

**⚠️ 자주 하는 실수**

**(1) 행과 열을 뒤바꿔 쓴다**

```cpp
// ❌ 틀린 코드
int n, m;
cin >> n >> m;
for (int i = 0; i < m; i++) {          // 행 수 자리에 m 을 넣었다
    for (int j = 0; j < n; j++) {
        cin >> board[i][j];
    }
}
```

왜: 대괄호 순서는 `[행][열]`이고 행 수는 `n`, 열 수는 `m`이다. 자리를 바꾸면 표가 통째로 어긋난다. 정사각형 입력으로만 시험하면 이 실수가 드러나지 않는다.

```cpp
// ✅ 고친 코드
for (int i = 0; i < n; i++) {          // 행은 n 번
    for (int j = 0; j < m; j++) {      // 열은 m 번
        cin >> board[i][j];
    }
}
```

**(2) 표를 0으로 초기화하지 않는다**

```cpp
// ❌ 틀린 코드
int board[100][100];                   // = {0} 이 없다
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        if (i == j) board[i][j] = 1;   // 대각선만 1 로 바꾼다
    }
}
```

왜: 나머지 칸에는 이전에 그 메모리를 쓰던 쓰레기 값이 그대로 남는다. 대각선 말고는 무엇이 찍힐지 알 수 없고, 실행할 때마다 달라진다.

```cpp
// ✅ 고친 코드
int board[100][100] = {0};             // 모든 칸이 0 에서 시작한다
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        if (i == j) board[i][j] = 1;
    }
}
```

**(3) 파이썬식 범위 검사를 그대로 옮긴다**

```cpp
// ❌ 틀린 코드
if (0 <= nr < n && 0 <= nc < m) {      // 검사가 통째로 무력해진다
    cnt += board[nr][nc];
}
```

왜: C++은 `0 <= nr < n`을 `(0 <= nr) < n`으로 읽는다. 앞의 결과가 1 또는 0이 되고 그것을 `n`과 비교하므로, `n`이 2 이상이면 언제나 참이다. 즉 격자 밖도 그대로 통과한다.

```cpp
// ✅ 고친 코드
if (nr >= 0 && nr < n && nc >= 0 && nc < m) {
    cnt += board[nr][nc];
}
```

**(4) 이웃을 볼 때 경계를 확인하지 않는다**

```cpp
// ❌ 틀린 코드
int total = 0;
total += board[r - 1][c];              // r == 0 이면 배열 앞쪽 메모리를 읽는다
total += board[r][c - 1];              // c == 0 이면 앞 행의 끝 칸을 읽는다
```

왜: C++은 칸 밖 접근을 막지 않는다. 오류도 없고 멈추지도 않으며, 그 자리에 있던 값을 그대로 더한다. 파이썬은 한쪽이라도 `IndexError`로 알려 줬지만 여기서는 아무 신호가 없다.

```cpp
// ✅ 고친 코드
int total = 0;
if (r - 1 >= 0) total += board[r - 1][c];
if (c - 1 >= 0) total += board[r][c - 1];
```

**(5) 범위 검사와 값 검사의 순서를 뒤집는다**

```cpp
// ❌ 틀린 코드
if (board[nr][nc] == 1 && nr >= 0 && nr < n && nc >= 0 && nc < m) {
    cnt++;
}
```

왜: `&&`는 왼쪽부터 계산한다. 왼쪽에서 이미 `board[nr][nc]`를 읽어 버리므로 검사는 아무 역할을 못 한다. 검사는 접근보다 **먼저** 해야 의미가 있다.

```cpp
// ✅ 고친 코드
if (nr >= 0 && nr < n && nc >= 0 && nc < m && board[nr][nc] == 1) {
    cnt++;
}
```

**(6) 행별 합인데 합 변수를 반복 밖에 둔다**

```cpp
// ❌ 틀린 코드
int total = 0;
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        total += board[i][j];
    }
    cout << total << "\n";             // 앞 행의 합이 계속 얹혀 누적된다
}
```

왜: `total`의 수명이 "표 전체"가 되어 버렸다. 행마다 답을 내려면 수명도 "행 하나"여야 하므로, 초기화가 바깥 반복 **안쪽**으로 들어가야 한다.

```cpp
// ✅ 고친 코드
for (int i = 0; i < n; i++) {
    int total = 0;                     // 행이 바뀔 때마다 다시 0
    for (int j = 0; j < m; j++) {
        total += board[i][j];
    }
    cout << total << "\n";
}
```

**(7) 이웃 계산 결과를 원본에 바로 덮어쓴다**

```cpp
// ❌ 틀린 코드
for (int r = 0; r < n; r++) {
    for (int c = 0; c < m; c++) {
        board[r][c] = countNeighbors(r, c);   // 원본을 갱신
    }
}
```

왜: `(0,0)`을 갱신한 뒤 `(0,1)`을 계산할 때, 이미 바뀐 `(0,0)`의 값을 "원래 값"으로 착각해 읽는다. 앞 칸의 결과가 뒤 칸의 입력을 오염시킨다.

```cpp
// ✅ 고친 코드
int res[100][100] = {0};
for (int r = 0; r < n; r++) {
    for (int c = 0; c < m; c++) {
        res[r][c] = countNeighbors(r, c);     // 원본은 그대로 둔다
    }
}
```

**(8) 거꾸로 도는 반복을 잘못 쓴다**

```cpp
// ❌ 틀린 코드
for (int j = m - 1; j > 0; j--) {      // 0 열을 건너뛴다
    board[i][j] = num;
    num++;
}
```

왜: `j > 0`이면 `j`가 0이 되는 순간 반복이 끝나 첫 열이 채워지지 않는다. 0번 칸까지 포함하려면 `j >= 0`이어야 한다. 반복 변수를 음수가 없는 자료형으로 선언하면 `j >= 0`이 영원히 참이라 이번엔 멈추지 않으므로, `int`로 두는 것도 함께 지킨다.

```cpp
// ✅ 고친 코드
for (int j = m - 1; j >= 0; j--) {     // 0 열까지 채운다
    board[i][j] = num;
    num++;
}
```

**(9) 회전한 뒤 크기를 그대로 둔다**

```cpp
// ❌ 틀린 코드
for (int t = 0; t < k; t++) {
    int nb[100][100] = {0};
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++)
            nb[j][n - 1 - i] = board[i][j];
    // n, m 을 안 바꿔 다음 회전에서 어긋난다
}
```

왜: 한 번 회전하면 표가 `n행 m열`에서 `m행 n열`이 된다. `n`과 `m`을 바꾸지 않으면 두 번째 회전의 반복 범위가 실제 크기와 달라져 칸 밖을 읽거나 값이 뒤엉킨다.

```cpp
// ✅ 고친 코드
for (int t = 0; t < k % 4; t++) {      // 4번이면 제자리이므로 미리 줄인다
    int nb[100][100] = {0};
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++)
            nb[j][n - 1 - i] = board[i][j];
    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            board[i][j] = nb[i][j];
    int tmp = n;
    n = m;
    m = tmp;                           // 크기도 함께 교환
}
```

**다음 챕터로**

- 격자 위에서 "이웃을 보고 조건에 따라 움직이는" 사고는 이후 시뮬레이션·탐색 문제의 공통 뼈대다. `dr`/`dc` 방향표와 경계 검사는 그대로 재사용된다.

- 표를 새로 만들어 결과를 담는 습관은 누적합·DP 표처럼 "칸에 계산 결과를 저장하는" 유형으로 이어진다.

- 다음 챕터의 문자열도 "인덱스로 접근하는 한 줄짜리 칸"이라는 점에서 여기의 격자와 같은 감각을 쓴다. 다만 C++ `string`은 크기가 스스로 늘고 줄어든다는 점이 고정 크기 배열과 다르다.

> 개요: 방향 비순환 그래프(DAG)에서 선후 관계를 한 줄로 세우는 위상 정렬을 진입차수(Kahn)와 DFS(후위 순서) 두 관점으로 깊이 다루고, 그 위상 순서를 뼈대로 삼아 "한 방향으로만 흐르는" DP(Graph DP / DAG DP)를 설계하는 법을 익힌다.

## L1. Topological Sort

**개념**

- 위상 정렬은 **방향 비순환 그래프(DAG)**의 정점을, "모든 간선 u→v에서 u가 v보다 앞"이 되도록 일렬로 세우는 것이다. 기초 트레일에서는 진입차수 기반(Kahn)만 봤다면, 여기서는 **두 구현을 모두 손에 익히고 언제 무엇을 고를지**를 정한다.
- **Kahn(진입차수·BFS)**: 진입차수 0인 정점을 큐에 넣고, 꺼내며 이웃의 진입차수를 1씩 깎는다. 담긴 수가 N 미만이면 사이클이다. 사이클 판정과 "레벨(층)" 계산이 자연스럽다.
- **DFS(후위 순서·post-order)**: 각 정점에서 DFS로 끝까지 내려간 뒤, **되돌아 나오는 순간(자식 처리를 다 끝낸 순간)** 그 정점을 스택(벡터)에 쌓는다. 모든 정점을 처리한 뒤 뒤집으면 위상 순서다. 이유: u→v면 v는 u보다 먼저 "완료"되어 먼저 쌓이므로, 뒤집으면 u가 앞에 온다.
- DFS 방식의 사이클 판정은 **3색 칠하기**로 한다. 방문 중(회색) 정점을 다시 만나면 역방향 간선 = 사이클이다. (0=미방문 흰색, 1=방문중 회색, 2=완료 검정.)

```cpp
#include <bits/stdc++.h>
using namespace std;

// (A) Kahn: 진입차수 기반. indeg는 값 복사로 받아 내부에서 소모
vector<int> topoKahn(int n, const vector<vector<int>>& graph, vector<int> indeg) {
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);
    vector<int> order;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : graph[u])
            if (--indeg[v] == 0) q.push(v);
    }
    if ((int)order.size() != n) return {};   // 비면 사이클
    return order;
}

// (B) DFS: 후위 순서 + 3색으로 사이클 검출
vector<int> topoDfs(int n, const vector<vector<int>>& graph) {
    vector<int> color(n + 1, 0);   // 0 흰, 1 회, 2 검
    vector<int> order;
    bool ok = true;
    // 명시적 스택 DFS: 프레임 = (정점, 다음에 볼 자식 index)
    for (int s = 1; s <= n; s++) {
        if (color[s] != 0) continue;
        vector<pair<int,int>> stk = {{s, 0}};
        color[s] = 1;
        while (!stk.empty()) {
            auto& [u, pi] = stk.back();
            if (pi < (int)graph[u].size()) {
                int v = graph[u][pi++];
                if (color[v] == 1) ok = false;       // 방문중을 다시 만남 → 사이클
                else if (color[v] == 0) { color[v] = 1; stk.push_back({v, 0}); }
            } else {
                color[u] = 2;
                order.push_back(u);                  // 완료 시점에 쌓기(post-order)
                stk.pop_back();
            }
        }
    }
    if (!ok) return {};
    reverse(order.begin(), order.end());             // 뒤집으면 위상 순서
    return order;
}
```

**그림으로 보기**

간선은 "먼저 → 나중"이다. 먼저 진입차수(들어오는 화살표 수)를 세어 둔다.

```text
   (1)     (2)        indeg         # u->v 이면 v 쪽 차수를 센다
    | \     |         -----
    v  \    v         1 : 0   4 : 2
   (3)  +->(4)        2 : 0   5 : 1
    |       |         3 : 1   6 : 2
    v       v
   (5)---->(6)
```

진입차수 0인 정점만 큐에 들어간다. 하나 꺼낼 때마다 이웃의 차수가 1씩 줄고, 0이 되는 순간 그 이웃이 새로 큐에 들어간다. 결과적으로 그래프가 한 층씩 벗겨진다.

```text
  layer 0     layer 1     layer 2     layer 3    # 큐에 들어가는 순서
  -------     -------     -------     -------
   (1)         (3)         (5)         (6)
   (2)         (4)
```

사이클이 있으면 큐가 먼저 마른다. 아래는 2->3->4->2 가 돌고 있는 경우다.

```text
   (1)-->(2)-->(3)      indeg
          ^     |       -----
          |     v       1 : 0
          +----(4)      2 : 2     # 1 을 꺼내도 1 로 줄 뿐 0 이 안 된다
                        3 : 1
                        4 : 1
```

1을 꺼내면 2의 차수가 2에서 1로 줄 뿐이라 큐가 비고, 출력은 `[1]` 하나로 끝난다. `order.size() == 1 < 4` — 이것이 곧 사이클 판정이다.

**손으로 따라가기**

위의 6정점 DAG를 Kahn으로 돌린다(큐는 FIFO, 이웃은 번호 오름차순).

| 단계 | 꺼낸 정점 | 진입차수 1..6 | 큐 | 출력 |
|---|---|---|---|---|
| 0 | - | 0 0 1 2 1 2 | [1, 2] | (없음) |
| 1 | 1 | 0 0 0 1 1 2 | [2, 3] | 1 |
| 2 | 2 | 0 0 0 0 1 2 | [3, 4] | 1 2 |
| 3 | 3 | 0 0 0 0 0 2 | [4, 5] | 1 2 3 |
| 4 | 4 | 0 0 0 0 0 1 | [5] | 1 2 3 4 |
| 5 | 5 | 0 0 0 0 0 0 | [6] | 1 2 3 4 5 |
| 6 | 6 | 전부 0 | (빔) | 1 2 3 4 5 6 |

출력 개수가 6 = N이므로 사이클이 없고 `1 2 3 4 5 6`이 위상 순서 하나다. 3단계에서 큐가 `[4, 5]`였으니 4 대신 5를 먼저 꺼낸 `1 2 3 5 4 6`도 똑같이 정답이다 — 답은 여러 개다.

**왜 이렇게 되는가**

- **왜 DAG에서만 가능한가**: 사이클 v1→v2→…→vk→v1이 있다고 하자. 위상 순서가 존재한다면 순서상 v1 < v2 < … < vk < v1이 되어 `v1 < v1`이라는 모순이 나온다. 그러므로 사이클이 하나라도 있으면 어떤 일렬 배치도 존재하지 않는다.
- **Kahn이 사이클을 감지하는 원리**: 정점은 진입차수가 0이 되는 순간에만 큐에 들어가고, 그것은 "선행이 전부 이미 꺼내졌다"는 뜻이다. 사이클 안의 정점은 저마다 사이클 안에 선행을 하나씩 갖고 있으므로 아무도 먼저 0이 될 수 없다. 그래서 사이클 정점과 그 후손은 영영 큐에 못 들어가고, 꺼낸 개수가 N보다 작아진다. "몇 개가 못 들어왔나"가 그대로 사이클에 얽힌 정점 수다.
- **복잡도 O(V + E)**: 각 정점은 큐에 정확히 한 번 들어가고 한 번 나온다 → V번. 간선 u→v의 차수 감소는 u를 꺼내는 딱 한 순간에만 일어난다 → E번. 합이 O(V + E)이고, 인접 리스트와 진입차수 배열로 공간도 O(V + E).
- **DFS 후위 순서를 왜 뒤집는가**: u→v가 있으면 u는 v를 끝까지 처리하고 나서야 완료되므로 v가 먼저 스택에 쌓인다. 즉 완료 순서는 위상 순서의 **역순**이다. 그래서 마지막에 뒤집으면 u가 v보다 앞에 온다.
- **C++ 함정 1 — 전위 감소와 후위 감소.** `--indeg[v] == 0`은 "1 빼고 나서 비교"지만 `indeg[v]-- == 0`은 "빼기 **전** 값과 비교"다. 후자를 쓰면 차수가 0인 정점을 다시 큐에 넣고 차수를 음수로 만들어, 같은 정점이 여러 번 출력된다. 이 한 글자 차이가 조용히 답을 망친다.

```cpp
if (indeg[v]-- == 0) q.push(v);     // 감소 전 값과 비교 — 틀림
if (--indeg[v] == 0) q.push(v);     // 감소 후 값과 비교 — 정답
```

- **C++ 함정 2 — 사전순 최소 위상 순서는 `queue`로 안 나온다.** "가능한 위상 순서 중 사전순으로 가장 앞선 것"을 요구하면 FIFO 큐가 아니라 **최소 힙**을 써야 한다. `priority_queue`는 기본이 최대 힙이므로 비교자를 반드시 지정한다. 알고리즘의 나머지는 한 글자도 바뀌지 않는다.

```cpp
queue<int> q;                                                  // 아무 위상 순서 하나
priority_queue<int, vector<int>, greater<int>> q;              // 사전순 최소
// 꺼낼 때 queue는 q.front(), priority_queue는 q.top() — 이 이름 차이도 자주 틀린다
```

- **C++ 함정 3 — `indeg`를 참조로 받으면 원본이 부서진다.** Kahn은 진입차수를 소모하며 진행하므로, 함수 시그니처를 `vector<int>& indeg`로 두면 호출자의 배열이 전부 0이 되어 두 번째 호출이 엉뚱하게 동작한다. 값 복사(`vector<int> indeg`)로 받거나 함수 안에서 복사본을 만들어라. 반대로 인접 리스트처럼 읽기만 하는 큰 컨테이너는 반드시 `const vector<...>&`로 받아야 복사 비용이 없다.
- **C++ 함정 4 — 재귀 DFS의 스택.** 정점 10만 개가 한 줄로 이어진 DAG에서 재귀 DFS는 깊이 10만이 되어 기본 스택(보통 1MB)을 넘긴다. 파이썬처럼 `RecursionError`가 뜨는 게 아니라 **경고 없이 죽는다**. 위 개념 코드처럼 `vector<pair<int,int>>`에 `(정점, 다음 자식 인덱스)` 프레임을 직접 쌓는 명시적 스택 DFS를 쓰거나, Kahn 쪽을 기본으로 삼아라.

**접근 전략**

- "A를 하려면 B가 먼저"라는 **의존성·선후 관계**가 보이면 위상 정렬이다. 방향은 보통 "선행 → 후행"으로 그린다. 정답 순서가 여러 개일 수 있음을 늘 의식한다.
- **Kahn vs DFS 고르기**: 사이클을 "몇 개가 못 들어왔나"로 판정하거나 **레벨/최소 단계 수**가 필요하면 Kahn이 편하다. **사전순 최소 답**이 필요하면 큐를 `priority_queue<int, vector<int>, greater<int>>`(최소 힙)로 바꾼 Kahn이 자연스럽다(DFS로는 사전순 최소가 까다롭다). 반대로 위상 순서를 이용한 DP를 DFS 재귀 안에서 바로 엮고 싶으면 DFS 방식이 깔끔하다.
- 시간 **O(V + E)**, 공간 **O(V + E)**. 두 방식 모두 동일하다.
- C++ 팁: DFS를 재귀로 짜면 정점이 많을 때 콜 스택이 터진다. **명시적 스택으로 반복 변환**(위 뼈대)하면 힙 메모리를 쓰므로 깊이 걱정이 없다. Kahn은 애초에 재귀가 없어 이 문제가 없다 — 대규모에선 Kahn이 안전패다. 큐는 `std::queue`, 최소 힙은 `std::priority_queue`를 그대로 쓴다.
- 흔한 실수: 진입차수를 방향 반대로 세기(u→v면 **v**의 차수를 올려야 함), 사이클 판정 누락, 무방향 간선을 섞어 넣기(위상 정렬은 방향 그래프 전용).

**문제**

**1) 사전순 최소 작업 순서** · Easy

- **요구사항**: N개 작업과 "u→v(u를 먼저)" 관계 M개가 있다. 가능한 위상 순서 중 **사전순으로 가장 앞선 것**을 출력하라. 사이클이면 `-1`.
- **입력**: 첫 줄 `N M`, 이후 M줄 `u v`.
- **출력**: 사전순 최소 위상 순서(공백 구분 한 줄) 또는 `-1`.
- **예제**:

  - `입력`: `5 4` / `1 4` / `2 4` / `4 5` / `3 5` → `출력`: `1 2 3 4 5`
    (진입0: 1,2,3 중 작은 1 → 2 → 3 → 이제 4 진입0 → 4 → 5)

  - `입력`: `4 4` / `1 2` / `2 3` / `3 4` / `4 2` → `출력`: `-1`
    (2→3→4→2 사이클)
- **셀프체크**: 사전순 최소는 큐를 **최소 힙**(`priority_queue<int, vector<int>, greater<int>>`)으로 바꾼 Kahn이 정답 패턴이다(DFS로 하려 들지 말 것). 매번 "지금 넣을 수 있는 것 중 최소 번호"를 꺼내는지 확인. 사이클 시 결과 길이 < N 판정은 그대로 유효하다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    vector<vector<int>> graph(n + 1);
    vector<int> indeg(n + 1, 0);
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        indeg[v]++;
    }
    // 사전순 최소 → 큐를 최소 힙으로 바꾼 Kahn
    priority_queue<int, vector<int>, greater<int>> pq;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) pq.push(v);
    vector<int> order;
    while (!pq.empty()) {
        int u = pq.top();
        pq.pop();
        order.push_back(u);
        for (int v : graph[u]) {
            if (--indeg[v] == 0) pq.push(v);
        }
    }
    if ((int)order.size() == n) {
        for (int i = 0; i < (int)order.size(); i++) {
            cout << order[i];
            if (i + 1 < (int)order.size()) cout << ' ';
        }
        cout << "\n";
    } else {
        cout << -1 << "\n";
    }
    return 0;
}

(1) 접근·핵심 아이디어

- 위상 순서 중 사전순 최소를 원하면 Kahn의 큐(FIFO)를 **최소 힙**으로 바꾼다. 매번 "현재 진입차수 0인 정점 중 가장 작은 번호"를 먼저 확정하면 그리디하게 사전순 최소가 된다.
- 사이클이면 진입차수 0이 도중에 마르며 결과 길이가 N 미만 → `-1`.

(2) 코드 단계별

- 인접 리스트와 진입차수를 만든다(u→v면 v의 진입차수 증가).
- 진입차수 0인 정점들을 최소 힙(`priority_queue<int, vector<int>, greater<int>>`)에 넣는다.
- 힙에서 최소 정점 `u`를 `top()`으로 꺼내 order에 추가, 이웃들의 진입차수를 깎아 0이 되면 힙에 push.
- 끝나서 order 길이가 N이면 공백으로 이어 출력, 아니면 `-1`.

(3) 스스로 다시 짤 때 생각 순서

- "사전순 최소" 키워드 → DFS가 아니라 heap-Kahn. 일반 Kahn을 먼저 떠올리고 큐→최소 힙만 교체.
- 사이클 판정은 "담긴 개수 < N"으로 그대로 유효함을 확인.
- 방향 실수 주의: 진입차수는 화살표가 들어오는 쪽(v)에 센다. `queue` 대신 `priority_queue`를 쓰는 것만 다르다.
```

**2) 위상 순서 개수 세기(작은 N)** · Medium

- **요구사항**: N ≤ 12인 DAG에서 서로 다른 위상 순서가 **몇 가지**인지 세라. 사이클이면 `0`.
- **입력**: 첫 줄 `N M`, 이후 M줄 `u v`.
- **출력**: 위상 순서의 총 개수.
- **예제**:

  - `입력`: `3 1` / `1 2` → `출력`: `3`
    (1이 2보다 앞이기만 하면 됨. 3의 위치 자유: `1 2 3`, `1 3 2`, `3 1 2` → 3가지)

  - `입력`: `3 3` / `1 2` / `2 3` / `1 3` → `출력`: `1`
    (완전한 사슬 → `1 2 3` 유일)
- **셀프체크**: N ≤ 12로 작으니 **순열 백트래킹**으로 센다. 아직 배치 안 한 정점 중 "선행이 모두 이미 배치된" 것만 다음에 놓으며 재귀로 내려가고, N개를 다 놓으면 경우 1개로 센다. 진입차수 배열을 놓을 때마다 갱신하면 "지금 놓을 수 있는 정점"을 O(N)에 고를 수 있다. 사이클이면 어느 지점에서도 놓을 수 있는 정점이 없어 완전 배치에 도달 못 하니 자연히 0이 나온다(별도 사이클 처리 불필요).
- **더 빠른 대안**: 방문한 정점 집합을 정수 하나(`mask`)로 표현해 `dp[mask]`로 메모하면 O(2^N·N)에 센다. 방문집합을 비트마스크로 다루는 기법은 ch05에서 도입하므로, 지금은 위 백트래킹으로 충분하다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int n, m;
vector<vector<int>> graph;
vector<int> indeg;
vector<bool> placed;
long long cnt = 0;

void backtrack(int depth) {
    if (depth == n) {
        cnt++;
        return;
    }
    for (int v = 1; v <= n; v++) {
        if (!placed[v] && indeg[v] == 0) {
            placed[v] = true;
            for (int w : graph[v]) indeg[w]--;
            backtrack(depth + 1);
            for (int w : graph[v]) indeg[w]++;
            placed[v] = false;
        }
    }
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> m;
    graph.assign(n + 1, {});
    indeg.assign(n + 1, 0);
    placed.assign(n + 1, false);
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        indeg[v]++;
    }
    backtrack(0);
    cout << cnt << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- N ≤ 12로 작으니 "다음에 놓을 정점"을 하나씩 고르는 순열 백트래킹으로 위상 순서의 개수를 직접 센다.
- 매 단계에서 놓을 수 있는 정점 = "아직 안 놓았고 진입차수가 0인 것"(선행이 모두 이미 배치됨). 정점을 놓을 때 그 정점이 가리키는 이웃들의 진입차수를 1씩 깎아 "지금 놓을 수 있는지"를 O(N)에 판단.
- N개를 전부 놓으면 유효한 위상 순서 하나 → `cnt++`. 사이클이면 어느 지점에서도 진입차수 0이 없어 완전 배치에 못 가므로 자연히 0.

(2) 코드 단계별

- 인접 리스트와 진입차수 배열을 만든다.
- `backtrack(depth)`: `depth == n`이면 한 가지 완성으로 세고 리턴.
- 아니면 1..N 중 `placed`가 아니고 `indeg == 0`인 `v`를 골라 놓는다: `placed[v] = true`, 이웃들 `indeg--`, 재귀.
- 재귀에서 돌아오면 상태 원복(`indeg++`, `placed[v] = false`) — 다음 선택지를 위해.
- 모두 끝나면 `cnt` 출력. 경우의 수가 커질 수 있어 `long long`으로 둔다.

(3) 스스로 다시 짤 때 생각 순서

- "서로 다른 위상 순서 개수 + 작은 N" → 완전 탐색(순열 백트래킹) 신호.
- 상태로 무엇을 들고 다닐지: `placed`(배치 여부) + `indeg`(놓을 수 있는지). 놓기/되돌리기를 짝으로 정확히 맞춘다.
- 사이클 별도 처리 불필요(놓을 게 없으면 dead-end → 0). 더 큰 N이면 `dp[mask]` 비트마스크 메모로 O(2^N·N).
```

**3) DFS 후위 순서로 사이클 찾기** · Medium

- **요구사항**: 방향 그래프가 DAG인지 판정하고, DAG면 DFS(후위 순서) 위상 순서를, 아니면 사이클에 속한 정점 하나를 `CYCLE x`(x는 그 정점 번호) 형태로 출력하라.
- **입력**: 첫 줄 `N M`, 이후 M줄 `u v`.
- **출력**: DAG면 위상 순서(공백 구분), 아니면 `CYCLE x`.
- **예제**:

  - `입력`: `3 2` / `1 2` / `2 3` → `출력`: `1 2 3`
    (사이클 없음, 후위 완료 순서 3,2,1을 뒤집어 1 2 3)

  - `입력`: `3 3` / `1 2` / `2 3` / `3 2` → `출력`: `CYCLE 2`
    (2→3→2, 회색 정점 재방문 지점)
- **셀프체크**: 3색 칠하기에서 **회색(방문중) 정점을 다시 만나는 순간**이 사이클 증거다. 그 순간의 정점을 기록해 출력하면 된다(여러 답 가능—문제 규칙대로 하나만). 재귀 깊이가 크면 콜 스택이 터지니 **명시적 스택 DFS**로 바꿔라.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    vector<vector<int>> graph(n + 1);
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
    }

    vector<int> color(n + 1, 0);   // 0 흰(미방문), 1 회(방문중), 2 검(완료)
    vector<int> order;
    int cycleNode = 0;
    bool found = false;

    // 재귀 대신 명시적 스택 DFS(깊이 폭발 방지)
    for (int s = 1; s <= n && !found; s++) {
        if (color[s] != 0) continue;
        vector<pair<int, int>> stk;   // (정점, 다음에 볼 자식 index)
        stk.push_back({s, 0});
        color[s] = 1;
        while (!stk.empty()) {
            int u = stk.back().first;
            int pi = stk.back().second;
            if (pi < (int)graph[u].size()) {
                stk.back().second = pi + 1;
                int v = graph[u][pi];
                if (color[v] == 1) {      // 회색 재방문 → 사이클
                    found = true;
                    cycleNode = v;
                    break;
                } else if (color[v] == 0) {
                    color[v] = 1;
                    stk.push_back({v, 0});
                }
            } else {
                color[u] = 2;
                order.push_back(u);        // 완료 시점에 쌓기(post-order)
                stk.pop_back();
            }
        }
    }

    if (found) {
        cout << "CYCLE " << cycleNode << "\n";
    } else {
        for (int i = (int)order.size() - 1; i >= 0; i--) {
            cout << order[i];
            if (i > 0) cout << ' ';
        }
        cout << "\n";
    }
    return 0;
}

--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- DFS 후위 순서(post-order)로 완료 시점에 정점을 쌓고 뒤집으면 위상 순서가 된다(u→v면 v가 먼저 완료 → 먼저 쌓임 → 뒤집으면 u가 앞).
- 사이클 판정은 3색: 흰(0)·회(1, 방문 중)·검(2, 완료). DFS 중 **회색 정점으로의 간선**을 만나면 역방향 간선 = 사이클, 그 정점을 답으로 출력.
- 정점이 많아도 안전하도록 재귀 대신 명시적 스택으로 DFS를 구현(각 프레임에 "다음에 볼 자식 인덱스"를 함께 저장). 재귀와 달리 힙 메모리를 쓰므로 깊이 제한이 없다.

(2) 코드 단계별

- 인접 리스트를 만든다(방향 그래프).
- 흰색 정점마다 스택 DFS 시작. 스택 top의 `(u, pi)`에서 `pi`번째 자식을 본다.
- 자식 `v`가 회색이면 즉시 사이클(`cycleNode = v`)로 중단. 흰색이면 회색 칠하고 스택에 push.
- 자식을 다 본 정점은 검정으로 칠하고 `order`에 push_back(후위), 스택 pop.
- 사이클을 못 찾았으면 `order`를 뒤에서부터(역순) 출력해 위상 순서를 얻고, 찾았으면 `CYCLE x`.

(3) 스스로 다시 짤 때 생각 순서

- "DAG 판정 + 위상 순서 or 사이클 증거" → DFS 3색이 한 번에 둘 다 준다.
- 후위 순서를 왜 뒤집는지(완료 순서의 역순 = 위상 순서)를 먼저 납득하고 짠다.
- 재귀로 먼저 스케치하되, 깊이 걱정되면 "프레임 = (정점, 다음 자식 index)"로 반복 변환. break로 중단할 때 색 상태가 그대로 남아도 결과에 문제 없다(이미 답을 얻음).
```

## L2. Graph DP

**개념**

- Graph DP(여기서는 **DAG 위의 DP**)는 "각 정점/상태의 답이 그 정점으로 들어오는(또는 나가는) 정점들의 답으로 정해지는" DP다. DAG에는 사이클이 없으므로 **의존 관계에 순환이 없고**, 따라서 "누구를 먼저 계산해야 하는가"가 **위상 순서로 완전히 결정된다**. 이게 핵심 통찰: **위상 순서 = DP를 채우는 안전한 순서**.
- 두 가지 구현 축이 있다.

  - **Push(전방 갱신)**: 위상 순서대로 정점 u를 꺼내며, u의 확정된 값을 이웃 v로 "밀어" 갱신한다. `dp[v] = op(dp[v], dp[u] + w)` 꼴. Kahn과 함께 쓰면 자연스럽다.

  - **Pull(후방 갱신, 메모이제이션)**: `solve(v)` = v의 답을 재귀로 구하되, 먼저 v의 선행들의 `solve`를 호출해 그 값들로 v를 채운다. 위상 순서를 명시적으로 안 만들어도 재귀+메모가 알아서 순서를 지킨다.
- 전형 적용: DAG 최장/최단 경로, "각 정점에 도달하는 경로 수", DAG 위 확률/기댓값 전파, 갈래마다 최적을 고르는 결정 등.

```cpp
#include <bits/stdc++.h>
using namespace std;

// Push 스타일: DAG 최장 경로 길이(간선 가중치 합의 최대). indeg는 값 복사로 소모
// graph[u] = {(v, w)...}
long long dagLongest(int n, const vector<vector<pair<int,int>>>& graph, vector<int> indeg) {
    const long long NEG = LLONG_MIN / 4;
    vector<long long> dp(n + 1, NEG);
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) { dp[v] = 0; q.push(v); }   // 시작 후보: 진입 없는 정점
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (auto& [v, w] : graph[u]) {
            if (dp[u] + w > dp[v]) dp[v] = dp[u] + w;   // 최댓값으로 완화
            if (--indeg[v] == 0) q.push(v);
        }
    }
    long long best = NEG;
    for (int v = 1; v <= n; v++) best = max(best, dp[v]);
    return best;                                        // 전체 최장 경로
}

// Pull 스타일: s에서 "끝까지 가는 경로의 수" (memo[v] < 0 이면 미계산)
long long countPaths(int s, const vector<vector<int>>& graph, vector<long long>& memo) {
    if (memo[s] >= 0) return memo[s];
    long long total = graph[s].empty() ? 1 : 0;        // (문제 정의에 맞게 base 설정)
    for (int v : graph[s]) total += countPaths(v, graph, memo);
    return memo[s] = total;
}
```

**그림으로 보기**

가중 DAG에서 "각 정점에서 끝나는 최장 경로"를 위상 순서대로 확정해 간다.

```text
   (1)--3-->(2)--4-->(4)--2-->(5)    # 간선 위 숫자 = 가중치
    |                 ^
    2                 1
    +----->(3)--------+
```

위상 순서는 1, 2, 3, 4, 5다. 이 순서대로 왼쪽부터 값이 하나씩 굳는다.

```text
  order :  1     2     3     4     5   # 위상 순서
  dp    :  0     3     2     7     9
           |     |     |     |     |
           |     |     |     |     +-- dp[4] + 2 = 9
           |     |     |     +-------- max(dp[2]+4, dp[3]+1) = 7
           |     |     +-------------- dp[1] + 2 = 2
           |     +-------------------- dp[1] + 3 = 3
           +-------------------------- indeg 0 -> base 0
```

dp[4]를 계산하는 순간 dp[2]와 dp[3]은 **이미 확정**돼 있다. 이 보장을 주는 것이 위상 순서다. 순서를 어기면 아직 채워지지 않은 값을 읽어 조용히 틀린다.

**손으로 따라가기**

같은 그래프를 Push(Kahn) 방식으로 채운다. 모든 정점이 시작 후보이므로 dp는 0으로 초기화한다.

| 단계 | 꺼낸 u | 갱신 | dp[1..5] | 큐 |
|---|---|---|---|---|
| 0 | - | 초기화 | 0 0 0 0 0 | [1] |
| 1 | 1 | dp[2]=0+3, dp[3]=0+2 | 0 3 2 0 0 | [2, 3] |
| 2 | 2 | dp[4]=max(0, 3+4)=7 | 0 3 2 7 0 | [3] |
| 3 | 3 | dp[4]=max(7, 2+1)=7 | 0 3 2 7 0 | [4] |
| 4 | 4 | dp[5]=max(0, 7+2)=9 | 0 3 2 7 9 | [5] |
| 5 | 5 | 나가는 간선 없음 | 0 3 2 7 9 | (빔) |

답은 `dp` 전체의 최댓값 9이고 그 경로는 1→2→4→5(3+4+2)다. 3단계에서 dp[4]가 7 그대로인 것에 주목하라 — 두 선행(2와 3) 중 **더 좋은 쪽만 살아남는다**.

**왜 이렇게 되는가**

- **점화식이 나오는 자리**: 상태를 `dp[v]` = "v에서 끝나는 최적값"으로 잡는다. 마지막 선택은 "v로 들어오는 마지막 간선이 무엇인가"다. 그 간선을 u→v(w)로 쪼개면 `dp[v] = op(dp[u] + w)`가 되고, base는 들어오는 간선이 없는 정점(진입차수 0)이다. `op`가 max면 최장, min이면 최단, 덧셈이면 경로 수다 — 뼈대는 같고 연산만 바뀐다.
- **왜 계산 순서가 위상 순서여야 하는가**: `dp[v]`는 오직 **선행들**만 참조한다. 위상 순서로 진행하면 v를 계산하는 시점에 모든 선행이 이미 확정돼 있음이 보장된다. 임의 순서로 돌면 아직 초기값인 선행을 읽고, 그 선행이 나중에 커져도 이미 지나간 v에는 반영되지 않는다.
- **사이클이면 왜 무너지는가**: 사이클 위의 정점들은 서로가 서로의 선행이라 `dp[v]`가 결국 자기 자신에 의존한다. 확정 순서가 존재하지 않고, 최장 경로는 사이클을 돌수록 커져 아예 정의되지 않는다. 그래서 DAG DP 전에는 사이클 판정이 먼저다.
- **Push와 Pull이 같은 이유**: Push는 "확정된 u가 후행 v를 갱신", Pull은 "v가 선행들을 재귀로 확정시킨 뒤 읽기"다. 둘 다 각 간선을 정확히 한 번 쓴다. 메모이제이션 재귀는 위상 순서를 명시적으로 만들지 않을 뿐, 호출 스택이 그 순서를 대신 지켜 준다.
- **복잡도 O(V + E)**: 정점마다 상수 작업, 간선마다 완화 1회. DP의 총비용은 언제나 "상태 수 + 전이 수"인데 여기서는 상태가 V개, 전이의 총합이 E개다.
- **C++ 함정 1 — "도달 불가"를 나타내는 INF의 산술.** 최장 경로에서 미도달을 `LLONG_MIN`으로 두고 `dp[u] + w`를 계산하면 **부호 있는 정수 오버플로**가 되고, 이것은 C++ 표준에서 정의되지 않은 동작(UB)이라 컴파일러가 검사를 통째로 지워 버리기도 한다. 넉넉히 나눈 값(`LLONG_MIN / 4`)을 쓰고, 그래도 `if (dp[u] == NEG) continue;`로 미도달을 먼저 걸러라.

```cpp
const long long NEG = LLONG_MIN;          // dp[u] + w 에서 즉시 오버플로(UB)
const long long NEG = LLONG_MIN / 4;      // 더해도 넘치지 않을 여유를 남긴다
if (dp[u] == NEG) continue;               // 그래도 미도달은 먼저 거른다
```

- **C++ 함정 2 — 경로 수는 금방 넘친다.** "DAG에서 s→t 경로의 개수"는 정점이 40개만 돼도 `2^39` 규모까지 자란다. `int`는 물론 `long long`도 넘길 수 있으니, 문제에 모듈러가 있으면 더할 때마다 `% MOD`를 취하고 없으면 `long long`으로도 부족한지 상한을 먼저 계산하라. 파이썬은 정수가 무한 자릿수라 이 문제가 없지만 C++은 조용히 틀린다.
- **C++ 함정 3 — Pull 방식의 재귀 깊이.** `countPaths` 같은 메모이제이션 재귀는 DAG가 한 줄로 이어지면 깊이가 V가 된다. 정점 10만 개면 스택이 터진다. 정점 수가 크면 Push(Kahn) 쪽으로 바꾸는 것이 가장 안전한 회피책이다.
- **C++ 함정 4 — `memo`의 "아직 계산 안 함" 표시.** `vector<long long> memo(n+1, 0)`으로 두면 "값이 0인 상태"와 "미계산"을 구별할 수 없어 캐시가 영원히 안 걸리거나 0을 정답으로 착각한다. `-1`처럼 정답이 될 수 없는 값으로 초기화하거나 `vector<bool> done`을 따로 둔다.

**접근 전략**

- 문제에서 **방향 간선 + 사이클 없음(또는 "한 방향으로만 진행")**이 보이고, "최대/최소/개수/기댓값을 정점 단위로 누적"한다면 DAG DP다. 격자에서 오른쪽·아래로만 가는 경로 DP도 사실 격자를 DAG로 본 특수 사례다.
- 설계 절차: (1) 상태 정의(보통 `dp[정점]` = 그 정점에서 끝나는/시작하는 최적값·개수) → (2) 점화식과 base(진입차수 0 또는 출발점) → (3) **위상 순서로 채우기**(Push는 Kahn과 병행, Pull은 재귀+메모).
- **방향 선택 주의**: "각 정점으로 **끝나는** 경로"를 원하면 `dp[v] = f(dp[선행들])`(Pull이 자연스러움). "각 정점에서 **시작하는**"이면 반대로 후행들을 본다. 간선을 뒤집어 생각해야 할 때가 잦으니 그래프와 역그래프 둘 다 떠올려라.
- 시간 **O(V + E)**, 공간 **O(V + E)**. 각 정점·간선을 상수 번만 본다.
- C++ 팁: Pull 재귀는 깊이가 크면 콜 스택이 터진다 — Push(Kahn) 반복 방식으로 바꾸면 안전하다. 최댓값 초기화는 오버플로를 피해 `LLONG_MIN / 4` 같은 아주 작은 수로 두고, "도달 불가"와 "값 0"을 헷갈리지 마라(도달 불가는 음의 큰 값으로 남겨 구분). 값이 커질 수 있으면 `long long`을 쓴다.
- 흔한 실수: 위상 순서를 안 지키고 임의 순서로 DP를 채우기(선행이 아직 미확정인 채로 읽음), 그래프에 사이클이 있는데 DAG DP를 그대로 적용하기(먼저 사이클 판정 필요).

**문제**

**1) DAG 최장 경로** · Easy

- **요구사항**: 가중 DAG에서 아무 정점에서 시작해 아무 정점에서 끝나는 경로 중 **간선 가중치 합이 최대**인 값을 구하라(정점 하나만 있는 길이 0 경로도 허용).
- **입력**: 첫 줄 `N M`, 이후 M줄 `u v w`(u→v, 가중치 w).
- **출력**: 최장 경로의 가중치 합.
- **예제**:

  - `입력`: `4 4` / `1 2 3` / `2 3 4` / `1 3 2` / `3 4 1` → `출력`: `8`
    (1→2→3→4 = 3+4+1 = 8)

  - `입력`: `3 2` / `1 2 5` / `3 2 2` → `출력`: `5`
    (1→2 = 5. 3→2 = 2. 둘을 잇는 길은 없음)
- **셀프체크**: 진입차수 0인 정점의 `dp`를 0으로 두고 Push로 완화했는가? 최댓값이라 답은 `max(dp)`. 시작점이 하나로 고정된 게 아니라 **모든 정점이 시작 후보**임을 반영했는지 확인.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int, int>>> graph(n + 1);   // graph[u] = {(v, w)...}
    vector<int> indeg(n + 1, 0);
    for (int i = 0; i < m; i++) {
        int u, v, w;
        cin >> u >> v >> w;
        graph[u].push_back({v, w});
        indeg[v]++;
    }
    // 모든 정점이 시작 후보 → dp[v] = 0으로 시작(길이 0 경로 허용)
    vector<long long> dp(n + 1, 0);
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (auto& e : graph[u]) {
            int v = e.first, w = e.second;
            if (dp[u] + w > dp[v]) dp[v] = dp[u] + w;
            if (--indeg[v] == 0) q.push(v);
        }
    }
    long long best = dp[1];
    for (int v = 2; v <= n; v++) best = max(best, dp[v]);
    cout << best << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- `dp[v]` = "v에서 끝나는 경로의 최대 가중치 합"으로 둔다. 시작점이 고정이 아니므로 모든 정점을 잠재적 시작으로 보아 `dp[v] = 0`으로 초기화(정점 하나짜리 길이 0 경로 허용).
- u→v(w)마다 `dp[v] = max(dp[v], dp[u] + w)`로 완화한다. 이 갱신은 u가 확정된 뒤에만 유효하므로 위상 순서(Kahn Push)로 진행.
- 답은 어느 정점에서 끝나도 되므로 `max(dp)`.

(2) 코드 단계별

- 간선을 `graph[u] = {(v, w)...}`로 저장하고 진입차수를 센다.
- 모든 dp를 0으로 두고(가중치가 음수가 아니라는 전제에서 0 시작이 안전), 진입차수 0 정점을 큐에.
- Kahn으로 `u`를 꺼내며 각 `(v, w)`에 대해 완화 후 진입차수 감소, 0이면 큐에.
- 마지막에 `dp[1..n]` 중 최댓값 출력. 합이 커질 수 있으니 `long long`.

(3) 스스로 다시 짤 때 생각 순서

- "가중 DAG 최장 경로" → 위상 순서 Push DP가 정석. 최단이면 max를 min으로 바꾸는 대칭.
- "시작이 자유"인지 "특정 시작"인지 먼저 확정 → 여기선 자유라 모든 정점 dp=0, 답은 max.
- 음수 가중치가 있을 수 있으면 "도달 불가"와 "값 0"을 구분해야 하니 `LLONG_MIN/4` 같은 음의 큰 값으로 초기화를 고려. 이 문제 예제는 양수라 0 초기화로 충분.
```

**2) 목적지까지 경로 수** · Medium

- **요구사항**: DAG에서 정점 `S`부터 정점 `T`까지 서로 다른 경로의 수를 구하라(경로가 매우 많을 수 있으니 `1000000007`로 나눈 나머지).
- **입력**: 첫 줄 `N M S T`, 이후 M줄 `u v`(u→v).
- **출력**: S→T 경로 수 mod 1e9+7.
- **예제**:

  - `입력`: `4 4 1 4` / `1 2` / `1 3` / `2 4` / `3 4` → `출력`: `2`
    (1→2→4, 1→3→4)

  - `입력`: `5 6 1 5` / `1 2` / `1 3` / `2 4` / `3 4` / `4 5` / `1 5` → `출력`: `3`
    (1→2→4→5, 1→3→4→5, 1→5 직행)
- **셀프체크**: `dp[v]` = v→T 경로 수로 두고 Pull(메모)로 풀면 `dp[T]=1`, `dp[v]=Σ dp[다음]`. 또는 `dp[v]` = S→v 경로 수로 Push. **base를 어느 쪽에 두느냐**로 방향이 갈린다 — 하나로 정하고 일관되게. 나머지 연산을 매 덧셈마다 적용했는가? T에서 나가는 간선이 있어도 답에 영향 없음을 확인.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m, s, t;
    cin >> n >> m >> s >> t;
    vector<vector<int>> graph(n + 1);
    vector<int> indeg(n + 1, 0);
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        indeg[v]++;
    }
    // dp[v] = S에서 v까지 서로 다른 경로 수
    vector<long long> dp(n + 1, 0);
    dp[s] = 1;
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int v : graph[u]) {
            dp[v] = (dp[v] + dp[u]) % MOD;
            if (--indeg[v] == 0) q.push(v);
        }
    }
    cout << dp[t] % MOD << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- `dp[v]` = S에서 v로 가는 경로 수로 정의한다. `dp[S]=1`을 seed로 두고, 위상 순서로 `dp[v] += dp[u]`(u→v 간선마다)를 밀면(Push) 각 정점의 경로 수가 완성된다.
- DAG라 의존에 순환이 없으므로 위상 순서 = 안전한 채움 순서. Kahn을 그대로 재활용한다.
- 경로 수가 폭발할 수 있어 매 덧셈마다 `MOD`로 나눈 나머지를 유지한다.

(2) 코드 단계별

- 첫 줄에서 `N M S T`를 읽고, 이어 간선 M개로 인접 리스트와 진입차수를 만든다.
- `dp[S]=1`로 시작점만 1로 초기화(그 외 0).
- 진입차수 0인 정점을 큐에 넣고 Kahn 진행. `u`를 꺼낼 때마다 이웃 `v`로 `dp[v]=(dp[v]+dp[u])%MOD` 누적하고 진입차수를 깎아 0이 되면 큐에.
- 끝나면 `dp[T]`가 S→T 경로 수. T에서 나가는 간선은 dp[T] 이후 다른 정점만 갱신하므로 답에 영향 없다.

(3) 스스로 다시 짤 때 생각 순서

- "DAG + 경로 수" → 위상 순서 DP. 방향을 하나로 고정: 여기서는 S→v(Push)로 seed는 S.
- 큰 수 → mod를 어디에 넣을지부터 정한다(매 누적마다). 누적 값은 `long long`으로 두어 오버플로를 피한다.
- Pull(메모) 버전으로도 동일하게 풀 수 있음을 기억: `dp[T]=1`, `dp[v]=Σ dp[다음]`, 답은 `dp[S]`.
```

**3) 부품 조립 최소 시간** · Hard

- **요구사항**: 각 부품 v는 만드는 데 `t[v]` 시간이 걸리고, v의 **모든 선행 부품이 완성된 뒤에야** 시작할 수 있다(선행들은 병렬 제작 가능). 선행이 없는 부품은 0시부터 시작. 모든 부품을 완성하는 **최소 총 시간**과, 그 시간을 결정하는 **임계 경로(critical path)** 위 부품 수를 구하라.
- **입력**: 첫 줄 `N M`, 둘째 줄 `t[1..N]`(공백 구분), 이후 M줄 `u v`(u가 v의 선행). 사이클은 없다고 가정.
- **출력**: `최소 총 시간` 한 칸 띄고 `임계 경로 위 부품 수`.
- **예제**:

  - `입력`: `4 3` / `3 2 4 1` / `1 3` / `2 3` / `3 4` → `출력`: `8 3`
    (완성시각: c1=3, c2=2, c3=max(3,2)+4=7, c4=7+1=8. 최소 총 시간 8. 임계 경로 1→3→4, 부품 3개)

  - `입력`: `3 0` / `5 2 9` → `출력`: `9 1`
    (선행 없음 → 각자 0시 시작, 최대 완성 = max(5,2,9)=9. 임계 경로는 부품 하나)
- **셀프체크**: `finish[v] = t[v] + max(finish[선행])`(선행 없으면 max=0)를 위상 순서로 채운다. 답의 시간은 `max(finish)`. 임계 경로 길이는 각 정점에 "여기서 끝나는 최장 사슬의 부품 수"를 함께 DP하면 된다(`parts[v] = 1 + (선행 중 finish가 최대인 것의 parts)`, 동률이면 하나 선택). "시간의 합"이 아니라 "선행들의 최대"임을 놓치지 마라(병렬이라 합이 아님). 사이클이 없다는 전제를 신뢰하되, 위상 순서 없이 아무렇게나 채우면 틀린다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    vector<long long> t(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> t[i];
    vector<vector<int>> graph(n + 1);   // u -> v (u는 v의 선행)
    vector<int> indeg(n + 1, 0);
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        indeg[v]++;
    }

    vector<long long> finish(n + 1, 0);   // v의 완성 시각
    vector<long long> parts(n + 1, 0);    // v에서 끝나는 "finish 최대" 사슬의 부품 수
    vector<long long> predBest(n + 1, 0); // 지금까지 본 선행들의 최대 finish
    vector<long long> predParts(n + 1, 0);// 그 최대 선행 사슬의 부품 수

    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        finish[u] = predBest[u] + t[u];
        parts[u] = predParts[u] + 1;
        for (int v : graph[u]) {
            if (finish[u] > predBest[v]) {
                predBest[v] = finish[u];
                predParts[v] = parts[u];
            }
            if (--indeg[v] == 0) q.push(v);
        }
    }

    long long total = finish[1];
    for (int v = 2; v <= n; v++) total = max(total, finish[v]);
    long long best = 0;
    for (int v = 1; v <= n; v++)
        if (finish[v] == total && parts[v] > best) best = parts[v];
    cout << total << " " << best << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- 선행이 병렬로 만들어지므로 `finish[v] = t[v] + max(finish[선행들])`(선행 없으면 0). "합"이 아니라 "최대"인 게 함정이다.
- 이 점화식은 각 정점의 선행이 모두 확정된 뒤에만 계산 가능하다 → 위상 순서로 채우면 자연히 성립. Kahn(진입차수) Push로 진행한다.
- 임계 경로 부품 수는 finish를 결정한 그 선행의 사슬 길이를 물려받아 `parts[v] = parts[최대 선행] + 1`로 함께 DP한다.

(2) 코드 단계별

- `t[]`, 그래프, 진입차수를 읽는다(`u`가 `v`의 선행이므로 `v`의 진입차수를 올림).
- 진입차수 0인 정점부터 큐에. 꺼낼 때 `finish[u]=predBest[u]+t[u]`, `parts[u]=predParts[u]+1`로 확정.
- 확정된 `u`를 이웃 `v`로 밀며, `finish[u]`가 지금까지의 `predBest[v]`보다 크면 갱신하고 그때의 `parts[u]`도 함께 `predParts[v]`로 물려준다.
- 모든 완성 시각의 최댓값이 답의 시간. 그 시간과 같은 finish를 가진 정점 중 `parts` 최대가 임계 경로 부품 수.

(3) 스스로 다시 짤 때 생각 순서

- "선행이 다 끝나야 시작" → 최대(병렬), 위상 순서 DP라는 신호를 먼저 잡는다.
- 시간 DP를 먼저 완성하고, 그 위에 "무엇이 최댓값을 만들었나"를 따라가는 보조 DP(부품 수)를 얹는다.
- base(선행 없음 → 0시 시작, 부품 1개), 갱신 시 시간과 개수를 한 쌍으로 같이 옮기는 것을 잊지 않는다.
```

> 개요: 이 챕터에서는 키를 배열 인덱스로 바꿔 평균 O(1)에 저장·조회하는 해시 테이블의 원리(해시 함수·충돌 처리)와, C++ 표준 라이브러리의 unordered_map/unordered_set(및 정렬 컨테이너 map/set)을 이용한 실전 활용을 배운다.

## L1. 해싱

**개념**

- **해싱(hashing)**은 임의의 키(문자열·숫자 등)를 정수로 바꾸는 **해시 함수**를 이용해, 그 정수를 배열의 인덱스로 삼아 데이터를 저장·조회하는 기법이다. 정렬이나 비교 없이 "키 → 위치"를 곧바로 계산하므로 **평균 O(1)** 에 삽입·검색·삭제가 된다.
- 왜 쓰는가: "이 값이 이미 있었나?", "이 키에 매핑된 값은?", "각 원소가 몇 번 나왔나?" 같은 질문에 반복 탐색(O(n)) 대신 상수 시간으로 답하기 위해서다. 이진탐색(O(log n))보다도 빠르고, 데이터가 정렬돼 있을 필요도 없다.
- 동작 원리를 단계로:

  1. 크기 `m`인 배열(버킷 배열)을 준비한다.

  2. 키 `k`에 대해 `h = hash(k) % m`을 계산해 들어갈 버킷 번호를 얻는다.

  3. 그 버킷에 (키, 값)을 저장한다. 조회는 같은 계산으로 버킷을 찾아 꺼낸다.

- **충돌(collision)**: 서로 다른 키가 같은 버킷 번호를 가질 수 있다. 이를 처리하는 두 방식이 있다.

  - **체이닝(chaining)**: 각 버킷을 리스트로 두고, 충돌한 키들을 그 리스트에 이어 붙인다. 조회 시 그 리스트만 선형 탐색한다.

  - **개방 주소법(open addressing)**: 버킷이 차 있으면 다음 빈 칸을 규칙(선형 탐사 등)대로 찾아 넣는다.

- **적재율(load factor) α = 원소 수 / 버킷 수**. α가 커지면 충돌이 잦아져 느려지므로, 보통 임계치를 넘으면 배열을 키우고 전부 다시 넣는(**리해싱**) 방식으로 α를 낮게 유지한다. C++의 `unordered_map`/`unordered_set`이 내부적으로 이 일을 자동으로 해준다(기본 `max_load_factor`는 1.0).

```cpp
// 체이닝 방식 해시 셋의 뼈대 (원리 이해용)
#include <bits/stdc++.h>
using namespace std;

struct HashSet {
    int m;
    vector<vector<int>> buckets;
    HashSet(int m = 8) : m(m), buckets(m) {}

    int idx(int key) {
        return ((key % m) + m) % m;   // 해시(여기선 항등) + 나머지로 버킷 선택
    }
    void add(int key) {
        auto &b = buckets[idx(key)];
        for (int x : b) if (x == key) return; // 이미 있으면 중복 저장 안 함
        b.push_back(key);
    }
    bool contains(int key) {
        auto &b = buckets[idx(key)];
        for (int x : b) if (x == key) return true; // 같은 버킷 안에서만 탐색
        return false;
    }
};

int main() {
    // 실전에서는 그냥 표준 컨테이너를 쓴다
    unordered_set<int> s;          // 원소 존재 여부
    s.insert(3);
    cout << (s.count(3) ? 1 : 0) << "\n"; // 1

    // 빈도 세기: 없는 키를 [] 로 처리하면 0으로 자동 생성
    unordered_map<char, int> cnt;
    for (char c : string("banana")) cnt[c]++; // a:3, b:1, n:2

    // 키→리스트 그룹화: [] 접근 시 자동으로 빈 vector 생성
    unordered_map<int, vector<string>> d;
    d[0].push_back("x");
    return 0;
}
```

**그림으로 보기**

- 해시 테이블의 전부는 "키를 계산해서 칸 번호를 얻는다"는 한 줄이다. 버킷이 5칸(`m = 5`)일 때 키 셋을 넣어 보자.

```text
  step 1 : key -> number -> bucket index

   key       hash(key) % 5      bucket
   -----     -------------      ------
   "cat"  ->       3         ->   [3]
   "dog"  ->       1         ->   [1]
   "fox"  ->       3         ->   [3]      # cat과 같은 칸에 떨어졌다
```

```text
  step 2 : chaining puts both keys in the same slot

   [0] |
   [1] | -> "dog"
   [2] |
   [3] | -> "cat" -> "fox"                 # 충돌한 키를 리스트로 매단다
   [4] |
```

- 조회도 같은 계산을 한 번 할 뿐이다. `"fox"`를 찾으려면 3번 칸으로 바로 가서 그 칸의 리스트만 훑는다. 나머지 네 칸은 아예 보지 않는다.

- `vector`를 훑는 것과 무엇이 다른지 나란히 놓으면 분명해진다.

```text
  find(v.begin(), v.end(), x)    s.count(x)  on unordered_set
  ---------------                --------------------------
  [7][2][9][4][1]                hash(x) % m  ->  bucket k
   1  2  3  4  5                 look inside bucket k only
  compare one by one             1 jump + short scan

  worst : n comparisons          average : O(1)
```

- 다만 한 칸에 몰리면 이야기가 달라진다. 적재율 `a = 원소 수 / 버킷 수`가 커지면 체인이 길어진다.

```text
  a = 0.4                        a = 3.0
  [0] |                          [0] | -> x -> x -> x
  [1] | -> x                     [1] | -> x -> x -> x
  [2] |                          [2] | -> x -> x -> x
  [3] | -> x                     [3] | -> x -> x -> x

  average chain 0.4              average chain 3.0
```

- 오른쪽처럼 체인이 길어지면 조회가 다시 선형 탐색에 가까워진다. 그래서 `unordered_map`/`unordered_set`은 적재율이 `max_load_factor`(기본 1.0)를 넘으면 버킷 배열을 키우고 전부 다시 넣는다(리해싱).

- C++에는 "해시" 계열 말고 "정렬" 계열 컨테이너가 하나 더 있다. 같은 질문에 구조가 다르다.

```text
  unordered_set / unordered_map    vs    set / map
  ---------------------------------------------------------
   bucket array + chaining               balanced binary tree
   hash(key) % m  ->  one jump           compare, go left or right
   average O(1),  worst O(n)             always O(log n)
   iteration order : unspecified         iteration order : sorted
   no lower_bound                        lower_bound / upper_bound
   # 순서가 필요 없으면 unordered, 필요하면 정렬 컨테이너
```

**손으로 따라가기**

버킷 5칸짜리 체이닝 해시 테이블에 정수 키 `12, 7, 5, 17, 3`을 순서대로 넣는다(작은 양의 정수는 `std::hash<int>`가 사실상 항등이라 `h = k % 5`).

| 단계 | 넣는 키 | h = 키 % 5 | 넣은 뒤 버킷 상태 |
| --- | --- | --- | --- |
| 1 | 12 | 2 | `[2]: 12` |
| 2 | 7 | 2 | `[2]: 12 → 7` (충돌, 체인 길이 2) |
| 3 | 5 | 0 | `[0]: 5` · `[2]: 12 → 7` |
| 4 | 17 | 2 | `[0]: 5` · `[2]: 12 → 7 → 17` (체인 길이 3) |
| 5 | 3 | 3 | `[0]: 5` · `[2]: 12 → 7 → 17` · `[3]: 3` |

최종 적재율은 5 / 5 = 1.0이다. `5`를 조회하면 0번 칸에서 1번 비교로 끝나지만, `17`은 2번 칸의 체인을 3번 비교해야 나온다. **평균은 짧고 최악은 길다**는 해시의 성격이 이 표에 그대로 있다.

이어서 C++에서 가장 자주 밟는 함정 — `operator[]`가 없는 키를 **만들어 버리는** 것을 추적한다. `unordered_map<int,int> m;`으로 시작해 세 줄을 실행한다.

| 단계 | 코드 | 반환값 | 실행 후 `m.size()` |
| --- | --- | --- | --- |
| 0 | (초기 상태) | — | 0 |
| 1 | `m[7]++;` | 0을 만들고 1로 | **1** (키 7이 생김) |
| 2 | `if (m[9] > 0) ...` | 0 | **2** (키 9까지 생김) |
| 3 | `if (m.count(11)) ...` | 0 | 2 (키 11은 안 생김) |

2단계가 문제다. "있는지 보기만" 하려던 줄이 조용히 원소를 하나 추가했다. 파이썬 `dict[k]`가 `KeyError`로 즉시 알려 주는 상황에서 C++은 아무 말 없이 표를 키운다.

**왜 이렇게 되는가**

- 왜 평균이 O(1)인가: 키가 버킷에 고르게 흩어진다고 보면, 한 버킷의 평균 체인 길이는 정확히 적재율 `a = n / m`이다. 조회 한 번의 비용은 "해시 계산 1회 + 그 칸의 체인 훑기"라서 대략 `1 + a`번의 작업이다. 여기서 n이 커지면 리해싱으로 m도 함께 키워 `a`를 상수(기본 `max_load_factor` 1.0 이하)로 묶어 두므로, `1 + a`는 n과 무관한 상수가 된다. 그래서 평균 O(1)이다.

- 왜 최악은 O(n)인가: 위 유도는 "고르게 흩어진다"는 가정 위에 있다. 모든 키의 해시가 같은 칸으로 떨어지면 체인 하나에 n개가 매달리고, 조회는 그 리스트를 처음부터 훑는 선형 탐색이 된다. 평균 O(1)은 보장이 아니라 기댓값이다. 반면 `std::map`은 균형 이진 탐색 트리라 **최악에도 O(log n)을 보장**한다 — 최악을 막아야 하는 상황에서 정렬 컨테이너가 오히려 안전한 선택이 되는 이유다.

- 왜 `vector` 선형 탐색은 O(n)이고 `unordered_set` 조회는 평균 O(1)인가: 벡터는 값에서 위치를 계산할 방법이 없다. 7이 어디 있는지 알려면 앞에서부터 하나씩 비교하는 수밖에 없어 최악 n번이다. 반면 해시 셋은 값 자체를 계산에 넣어 `hash(x) % m`으로 위치를 **바로 만들어 낸다**. 후보가 처음부터 한 칸으로 좁혀지니 비교 횟수가 원소 수와 무관해진다. 선형 탐색을 n번 반복하면 O(n²)이던 코드가 `unordered_set`으로 바꾸면 O(n)이 되는 이유가 이것이다.

- 왜 키는 불변이어야 하는가: 저장 위치가 `hash(key)`로 정해졌는데 나중에 키 내용이 바뀌면 해시값도 바뀐다. 그러면 원래 칸에 있는 데이터를 새 계산으로는 영영 찾지 못한다. C++은 **키를 `const`로 저장해서** 이 사고를 언어 차원에서 막는다(`map`의 원소 타입이 `pair<const Key, T>`인 것이 그 흔적이다). 파이썬이 "리스트는 키가 될 수 없다"고 거부하는 것과 같은 이유를, C++은 "키는 못 고친다"로 해결한 셈이다.

- **왜 `m[k]`가 없는 키를 자동 생성하는가** — 파이썬과 정반대인 지점: `operator[]`의 반환형이 `T&`, 즉 **참조**다. `m[k] = 5`처럼 대입할 수 있어야 하므로 없는 키라도 돌려줄 실체가 필요하고, 그래서 값 초기화된 원소(`int`면 0, `vector`면 빈 벡터)를 만들어 그 참조를 준다. 덕분에 `cnt[c]++`가 초기화 없이 바로 돌아가는 편리함이 생기지만, **읽기만 하려던 코드가 표를 키우는 부작용**이 따라온다. 존재 확인은 `count`나 `find`로 한다.

  ```cpp
  unordered_map<string,int> m;
  m["a"]++;                       // 0 을 만들고 1 로 — 빈도 세기에는 편하다
  if (m["b"] > 0) { }             // 위험 : 키 "b" 가 0 으로 생겨 버린다
  if (m.count("b")) { }           // 안전 : 있는지만 본다 (삽입 없음)
  auto it = m.find("b");          // 안전 : 없으면 m.end()
  if (it != m.end()) use(it->second);
  // const unordered_map 에서는 [] 자체가 컴파일 에러다 (수정이 필요하므로)
  ```

- 왜 순회 순서를 답으로 쓰면 안 되는가: `unordered_map`의 순회 순서는 **버킷 배열을 훑는 순서**라 해시값·버킷 수·삽입 이력에 따라 달라진다. 삽입 순서도, 정렬 순서도 아니고, 리해싱이 한 번 일어나면 통째로 뒤바뀐다. 출력 순서가 정해진 문제라면 결과를 `vector`에 모아 `sort`하거나, 처음부터 정렬 컨테이너 `map`/`set`을 쓴다.

**접근 전략**

- **핵심 아이디어**: "존재 여부·개수·매핑"을 물으면 해시를 떠올린다. `vector`에서 매번 선형 탐색하면 O(n)이지만, `unordered_set`/`unordered_map`에 담아 두면 조회가 평균 O(1)이라 전체가 O(n)으로 떨어진다.
- **전형적 패턴**:

  - **중복/존재 판정**: `unordered_set`에 넣으며 이미 있는지 확인 (예: 첫 중복 원소, 두 수의 합 문제의 `T - x` 찾기).

  - **빈도 세기**: `unordered_map<키,int>`로 `cnt[x]++`. 애너그램 판정, 최빈값, 조건에 맞는 개수 세기 등.

  - **키→값 매핑/그룹화**: `unordered_map<키, vector<...>>`로 같은 기준을 가진 원소를 모으기(그룹 애너그램 등).

  - **키로 쓸 표준형 만들기**: 문자열을 정렬한 문자열, 길이 26의 빈도 문자열 등으로 정규화해 키로 삼는다. `pair`나 `string`은 그대로 `map`의 키로 쓸 수 있다.

- **언제 고르나**: 순서가 중요하지 않고 "빠른 조회"만 필요할 때는 `unordered_*`. 반대로 "정렬된 순서로 순회", "범위 질의(x 이상 y 이하)"가 필요하면 해시가 아니라 정렬된 `map`/`set`(균형 이진탐색트리, O(log n))이 맞다.
- **복잡도**: 삽입·검색·삭제 평균 **O(1)**, 최악 **O(n)**(모든 키가 한 버킷에 몰릴 때). 공간 **O(n)**. `unordered_*`는 리해싱으로 평균 O(1)을 사실상 보장하고, 정렬된 `map`/`set`은 항상 O(log n)을 보장한다.
- **흔한 실수·주의**: (1) `unordered_map`은 순회 순서가 **정해져 있지 않다**(삽입 순서도, 정렬 순서도 아님) — 순서가 필요하면 결과를 따로 `sort`하거나 정렬된 `map`을 쓴다. (2) `m[k]`로 없는 키를 읽으면 그 키가 **기본값(0/빈 컨테이너)으로 자동 생성**된다 — 존재만 확인할 때는 `m.count(k)`나 `m.find(k)`를 써서 원치 않는 삽입을 막는다. (3) 아주 긴 문자열을 키로 반복 해싱하면 해시 계산 자체가 길이에 비례하는 비용이 된다.

**문제**

**1) 두 수의 합 존재 여부** · Easy

- **요구사항**: 정수 배열과 목표값 `T`가 주어질 때, 서로 다른 두 원소의 합이 `T`가 되는 쌍이 존재하면 `YES`, 없으면 `NO`를 출력한다. 배열을 한 번만 훑어 평균 O(n)에 해결하라(이중 반복 금지).
- **입력**: 첫 줄에 `n`과 `T`, 둘째 줄에 정수 `n`개.
- **출력**: `YES` 또는 `NO`.
- **예제**:

  - `4 9` / `2 7 11 15` → `YES`  (2 + 7 = 9)

  - `3 6` / `1 2 4` → `NO`  (1+2=3, 1+4=5, 2+4=6? → 6이므로 사실 YES)

  > 검산: {1,2,4}에서 2+4=6=T이므로 이 예제의 정답은 `YES`다. 아래로 교체한다.

  - `3 10` / `1 2 4` → `NO`  (합은 3,5,6뿐, 10 없음)

- **셀프체크**: 원소 `x`를 볼 때 `T - x`가 이미 `unordered_set`에 있는지 먼저 확인하고, 없으면 `x`를 넣는다(자기 자신과 더하는 오류 방지). 같은 값이 두 번 있어야 하는 경우(예: `T=8`, 배열에 4가 두 개)도 순서대로 넣으면 자연히 처리됨을 확인하라.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n; long long T;
    cin >> n >> T;
    unordered_set<long long> seen;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        if (seen.count(T - x)) {
            cout << "YES" << "\n";
            return 0;
        }
        seen.insert(x);
    }
    cout << "NO" << "\n";
    return 0;
}
@@TESTS
--IN
4 9
2 7 11 15
--OUT
YES
--IN
5 8
1 4 3 4 9
--OUT
YES
@@EXPL
(1) 접근·핵심 아이디어

- 이중 반복(모든 쌍 검사)은 O(n^2). 대신 지나온 원소를 `unordered_set`에 담아 두고, 현재 원소 `x`를 볼 때 "`T - x`가 이미 나왔는가?"만 O(1)로 물으면 전체가 O(n)이 된다.
- 확인을 먼저 하고 그 다음에 `x`를 넣기 때문에, 같은 인덱스를 자기 자신과 더하는 실수가 생기지 않는다.

(2) 코드 단계별

- `cin`으로 `n`, `T`를 읽는다.
- 빈 `unordered_set<long long>` `seen`을 만든다.
- 각 `x`를 읽을 때마다 `seen.count(T - x)`가 참이면 즉시 `YES`를 출력하고 종료.
- 아니면 `seen.insert(x)`로 넣고 계속.
- 끝까지 못 찾으면 `NO`.

(3) 스스로 다시 짤 때 생각 순서

- "합이 T인 쌍" → 각 원소에 대해 필요한 짝은 `T - x`로 유일하게 정해진다는 점을 먼저 떠올린다.
- 짝을 빠르게 찾으려면 이미 본 값들을 조회 가능한 자료구조(`unordered_set`)에 넣어야 함을 연결한다.
- 자기 자신 중복 더하기를 막으려면 "확인 → 추가" 순서가 핵심임을 기억한다.
- 같은 값이 두 번 필요한 경우(예: 4+4=8)는 첫 4를 넣은 뒤 둘째 4에서 `T-4=4`가 이미 있어 자연히 처리됨을 확인한다.
```

**2) 최빈 단어** · Medium

- **요구사항**: 공백으로 구분된 단어들이 주어질 때, 가장 많이 등장한 단어를 출력한다. 최다 빈도가 여러 개면 그중 **사전순으로 가장 앞선** 단어를 출력한다.
- **입력**: 한 줄에 단어들이 공백으로 구분되어 주어진다.
- **출력**: 단어 하나.
- **예제**:

  - `apple banana apple cherry banana apple` → `apple`  (apple 3, banana 2, cherry 1)

  - `red blue blue red green` → `blue`  (red 2, blue 2, green 1 → 동점이면 사전순 앞: blue < red)

- **셀프체크**: `unordered_map`으로 빈도를 센 뒤, 후보를 고를 때 우선순위를 `(빈도 큰 것, 같으면 사전순 작은 것)`으로 두면 규칙이 한 번에 처리됨을 확인하라. `unordered_map`은 순회 순서가 보장되지 않으므로, 비교 조건에 반드시 사전순 2차 기준을 넣어야 결과가 결정적이 된다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    unordered_map<string, int> cnt;
    string w;
    while (cin >> w) cnt[w]++;

    string bestWord;
    int bestCnt = -1;
    for (auto &kv : cnt) {
        if (kv.second > bestCnt ||
            (kv.second == bestCnt && kv.first < bestWord)) {
            bestCnt = kv.second;
            bestWord = kv.first;
        }
    }
    cout << bestWord << "\n";
    return 0;
}
@@TESTS
--IN
apple banana apple cherry banana apple
--OUT
apple
--IN
red blue blue red green
--OUT
blue
@@EXPL
(1) 접근·핵심 아이디어

- 빈도 세기는 해시(`unordered_map`)의 대표 용도. `while (cin >> w) cnt[w]++;` 로 단어→등장 횟수를 O(n)에 만든다.
- 동점 규칙("사전순 가장 앞")을 함께 처리하려면 후보 갱신 조건을 `(빈도가 더 크거나, 같으면 사전순으로 더 작거나)`로 둔다. `string`의 `<` 연산자가 사전순 비교라 그대로 쓸 수 있다.
- 최댓값 하나만 필요하므로 전체 정렬 없이 한 번 순회하며 `bestWord`/`bestCnt`를 갱신하면 O(n)에 끝난다.

(2) 코드 단계별

- `cin >> w` 로 공백 기준 단어를 모두 읽어 `cnt[w]++` 로 빈도표를 만든다.
- `bestCnt = -1`, `bestWord = ""`(빈 문자열)로 초기화한다.
- `cnt`의 각 `(단어, 빈도)`를 순회하며, 빈도가 더 크거나(빈도 같고 사전순으로 더 작으면) `best`를 갱신한다.
- 순회가 끝나면 `bestWord`를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "가장 많이 나온 것" → 먼저 빈도표를 만든다(`unordered_map`).
- 동점 시 규칙을 비교 조건으로 번역한다: "빈도 큰 것 우선", 같으면 "사전순 작은 것 우선".
- 최댓값 하나만 필요하면 전체 정렬 대신 한 번 순회하며 갱신하면 O(n)에 끝남을 떠올린다.
- `unordered_map`은 순회 순서가 임의이므로, 반드시 2차 기준(사전순)을 비교에 포함해야 결과가 결정적이 됨을 기억한다.
```

**3) 그룹 애너그램 개수** · Medium

- **요구사항**: 문자열 여러 개가 주어질 때, 서로 애너그램(구성 글자와 개수가 같은)인 것끼리 한 그룹으로 묶는다. 만들어지는 **그룹의 개수**를 출력하라.
- **입력**: 첫 줄에 `n`, 다음 `n`줄에 소문자 문자열이 하나씩.
- **출력**: 그룹 개수(정수).
- **예제**:

  - `6` / `eat` / `tea` / `tan` / `ate` / `nat` / `bat` → `3`  ({eat,tea,ate}, {tan,nat}, {bat})

  - `3` / `abc` / `bca` / `xy` → `2`  ({abc,bca}, {xy})

- **셀프체크**: 각 문자열을 **정렬한 문자열**(예: `"eat"→"aet"`)을 키로 삼아 `unordered_set`(또는 `set`)에 넣으면, 서로 애너그램인 것들은 같은 키가 된다. 최종 서로 다른 키의 수가 곧 그룹 수다. 정렬 키 대신 길이 26의 글자 빈도 문자열을 키로 써도 되며, 이 경우 정렬 O(k log k)를 O(k)로 줄일 수 있음을 확인하라(k=문자열 길이).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    set<string> keys;
    for (int i = 0; i < n; i++) {
        string s;
        cin >> s;
        sort(s.begin(), s.end());
        keys.insert(s);
    }
    cout << keys.size() << "\n";
    return 0;
}
@@TESTS
--IN
6
eat
tea
tan
ate
nat
bat
--OUT
3
--IN
3
abc
bca
xy
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- 애너그램끼리는 "글자를 정렬하면 같은 문자열"이 된다(`eat`, `tea`, `ate` → 모두 `aet`). 이 정렬 문자열을 **정규화 키**로 삼는다.
- 그룹의 개수만 필요하므로 각 키를 `set`(중복 자동 제거)에 넣고, 마지막에 서로 다른 키의 수(`keys.size()`)를 세면 된다. 각 그룹 내부 원소를 실제로 모을 필요가 없다.

(2) 코드 단계별

- `cin`으로 `n`과 문자열 `n`개를 읽는다.
- 빈 `set<string>` `keys`를 만든다.
- 각 문자열 `s`에 대해 `sort(s.begin(), s.end())`로 글자를 정렬해 표준형을 만들고 `keys.insert(s)`로 추가한다.
- 서로 애너그램인 문자열들은 같은 키가 되어 `set`에서 자동으로 하나로 합쳐진다.
- 최종 `keys.size()`가 그룹 수다(정수 하나 출력).

(3) 스스로 다시 짤 때 생각 순서

- "애너그램끼리 묶기" → 애너그램을 하나의 표준형으로 바꾸는 방법을 먼저 찾는다: 글자 정렬(또는 길이 26 빈도 문자열).
- 표준형이 같으면 같은 그룹 → 표준형을 키로 쓰는 해시/집합 구조를 떠올린다.
- 개수만 물었으므로 그룹 내용은 버리고 서로 다른 키만 세면 됨을 인식(`set` + `size()`).
- 성능이 중요하면 정렬 키(O(k log k)) 대신 각 글자 개수를 담은 빈도 문자열(O(k))을 키로 쓸 수 있음을 기억한다(k=문자열 길이).
```

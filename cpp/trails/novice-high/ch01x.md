## L7. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch1(시간·공간복잡도)의 핵심 — 연산 횟수를 세고, Big-O로 등급을 매기고, 제한 시간 안에 드는지 판단하고, 같은 문제를 더 싼 복잡도로 다시 짜는 것 — 을 소재만 바꿔 **반복 훈련**하고, 코딩테스트 단골 유형(누적합·한 번 훑기·슬라이딩 윈도우)으로 **확장**하는 연습 세트다.
- **반복 훈련 개념**:
  - 연산 횟수 세기: 안쪽 줄이 몇 번 실행되는지 `cnt++`로 직접 세거나, `n / i`·`2^k - 1` 같은 공식으로 닫는다.
  - 시간 제한 판정: **C++은 1초에 약 `10^8`번** 기본 연산이 현실적인 기준이다(같은 알고리즘을 파이썬으로 짜면 약 `10^7`이라 한 자리 더 빡빡하다). `ops <= 10^8 * t`이면 통과 가능하고, `n`의 최대치는 이 부등식을 만족하는 가장 큰 정수다.
  - `O(n^2)` → `O(n)`: "매번 처음부터 다시 더하기"를 누적합 `pre[i+1] = pre[i] + a[i]` 또는 "지금까지의 최솟값" 변수 하나로 바꾼다.
  - 공간 절약: 길이 `n`짜리 `vector` 대신 직전 값 두 개만 굴리면 공간 `O(1)`. C++엔 `a, b = b, a + b` 같은 동시 대입이 없으니 임시 변수를 하나 두거나 `tie(a, b) = make_pair(b, a + b)`로 쓴다.
  - 로그 축 감각: `i *= 2`로 커지는 반복은 `n`의 이진 자릿수(`64 - __builtin_clzll(n)`)만큼 돌고, 그 안쪽 합은 등비수열이라 `O(n)`에 그친다.
  - 수의 크기 감각: `int`는 약 21억, `long long`은 약 9.2×10^18까지다. 파이썬 정수처럼 무한하지 않으므로 연산 횟수를 "정확한 값으로 찍어라"는 문제에서는 등급이 조금만 높아도 `long long`, 더 높으면 `__int128`이 필요하다.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '누적 합' 단계, NeetCode 150의 'Arrays & Hashing'(Best Time to Buy and Sell Stock 류)·'Sliding Window' 유형, 『이것이 취업을 위한 코딩테스트다』의 '구현' 파트에서 복잡도 기준으로 풀이를 고르는 연습이 이 레슨과 맞닿아 있다.

**문제**

**1) 시간 제한 통과 판정** · Easy

- **요구사항**: 어떤 컴퓨터는 1초에 기본 연산을 `10^8`번 한다(C++로 짠 코드의 현실적인 기준이다). 입력 크기 `n`, 알고리즘 등급 라벨, 제한 시간 `t`초가 주어질 때, 예상 연산 횟수를 계산하고 제한 시간 안에 드는지 판정하라. 등급별 연산 횟수는 다음처럼 정의한다: `n` → `n`번, `nlogn` → `n × L`번(`L`은 `n`의 이진 자릿수, 즉 `n`을 2로 계속 나눠 0이 될 때까지의 횟수), `n2` → `n^2`번, `n3` → `n^3`번, `2n` → `2^n`번.
- **입력**: 한 줄에 `n 라벨 t`가 공백으로 주어진다. (`1 ≤ n ≤ 10^9`, 라벨이 `2n`이면 `n ≤ 60`, `1 ≤ t ≤ 100`)
- **출력**: `예상연산횟수 판정`을 한 줄에. 판정은 연산 횟수가 `10^8 × t` 이하이면 `possible`, 아니면 `impossible`.
- **예제**: `1000000 nlogn 1` → `20000000 possible` · `100000 n2 1` → `10000000000 impossible`
- **셀프체크**: `10^6`의 이진 자릿수가 20이라 `nlogn`이 `2×10^7`인가? 딱 경계(`10000 n2 1` → 정확히 `10^8`)일 때 "이하"라서 `possible`인가? `2^30`은 약 `10.7억`이라 `t=10`(`10^9`)에도 못 드는가? `n3`에 `n = 10^9`를 넣으면 `10^27`이라 `long long`(약 9.2×10^18)으로는 못 담는다는 것을 확인했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

string to_str(__int128 v) {            // __int128 은 cout 으로 바로 못 찍는다
    if (v == 0) return "0";
    string s;
    while (v > 0) {
        s += char('0' + (int)(v % 10));
        v /= 10;
    }
    reverse(s.begin(), s.end());
    return s;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    long long n, t;
    string kind;
    cin >> n >> kind >> t;
    __int128 ops;
    if (kind == "n") {
        ops = (__int128)n;
    } else if (kind == "nlogn") {
        int L = 0;                                 // n 의 이진 자릿수
        for (long long x = n; x > 0; x >>= 1) L++;
        ops = (__int128)n * L;
    } else if (kind == "n2") {
        ops = (__int128)n * n;
    } else if (kind == "n3") {
        ops = (__int128)n * n * n;
    } else {                                       // "2n"
        ops = (__int128)1 << n;
    }
    __int128 limit = (__int128)100000000LL * t;
    cout << to_str(ops) << ' ' << (ops <= limit ? "possible" : "impossible") << '\n';
    return 0;
}
@@TESTS

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 복잡도 판단의 실전 버전이다. Big-O 등급을 실제 연산 횟수로 바꾸고, 초당 `10^8`이라는 C++ 기준과 제한 시간을 곱한 한도와 비교한다. 이 계산 하나로 "이 `n`에 `O(n^2)`가 되는가"를 문제 읽자마자 판단할 수 있다.
- `log n`은 정확한 실수 대신 이진 자릿수로 정의해 정수 계산만으로 답이 유일하게 정해지게 했다. C++엔 `bit_length()` 같은 메서드가 없으니 `for (long long x = n; x > 0; x >>= 1) L++;`로 직접 세거나 `64 - __builtin_clzll(n)`을 쓴다.

(2) 코드 단계별

- `n`, 라벨, `t`를 읽는다. 라벨은 `string`으로 받고 `==`로 비교한다(C++ `string`은 `==`가 내용 비교다).
- 라벨에 따라 `ops`를 계산한다. `n3`에 `n = 10^9`가 오면 `10^27`이라 `long long`으로는 조용히 틀린 값이 나온다. 그래서 계산과 저장을 `__int128`로 하고, 곱셈도 **첫 항부터** `(__int128)n * n * n`처럼 승격시킨다 — `(__int128)(n * n * n)`으로 쓰면 괄호 안에서 이미 넘쳐 소용없다.
- `2^n`은 `(__int128)1 << n`. `1 << n`이라고 쓰면 `int` 시프트라 `n >= 31`에서 망가진다.
- `__int128`은 `cout`이 모르는 타입이라 `to_str`로 10진 문자열을 직접 만든다.
- `limit = 10^8 * t`와 비교해 `ops <= limit`이면 `possible`. 경계가 "이하"이므로 정확히 `10^8`인 경우도 통과다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 기준(C++ 초당 `10^8`)과 한도(`× t`)를 숫자로 적는다.
- 등급별 연산 횟수 공식을 그대로 코드로 옮기되, 각 등급의 **최댓값이 어느 타입에 들어가는지**를 먼저 계산한다(`n^2` → 10^18은 `long long`, `n^3` → 10^27은 `__int128`).
- 경계(같을 때 통과)와 지수 등급의 폭발(`2^30`이 이미 `10^9` 초과)을 예제로 확인한다.
```

**2) 배수 훑기 반복 횟수** · Easy

- **요구사항**: 다음 반복 구조에서 안쪽 줄 `cnt++`가 총 몇 번 실행되는지 구하라. `for (int i = 1; i <= n; i++) for (int j = i; j <= n; j += i) cnt++;` — 즉 `i`마다 `i`의 배수 `i, 2i, 3i, …`를 `n`까지 훑는다. 이 값이 `n^2`보다 훨씬 작음을 확인하기 위해 `n^2`도 함께 출력하라.
- **입력**: 한 줄에 `n`. (`1 ≤ n ≤ 10,000`)
- **출력**: `총실행횟수 n제곱`을 한 줄에.
- **예제**: `10` → `27 100` · `1` → `1 1`
- **셀프체크**: `i`번째 바깥 반복에서 안쪽은 `n / i`번 도는가(`n=10`이면 `10+5+3+2+2+1+1+1+1+1=27`)? 이중 반복이라고 무조건 `O(n^2)`이 아니라, 합 `n/1 + n/2 + … + n/n ≈ n·ln n`이라 `O(n log n)`임을 짚었는가? `n=1`이면 한 번만 도는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    long long n;
    cin >> n;
    long long cnt = 0;
    for (long long i = 1; i <= n; i++)
        for (long long j = i; j <= n; j += i)   // i 의 배수만 훑는다: n / i 번
            cnt++;
    cout << cnt << ' ' << n * n << '\n';
    return 0;
}
@@TESTS
--IN
10
--OUT
27 100
--IN
1
--OUT
1 1
--IN
1000
--OUT
7069 1000000
@@EXPL
(1) 접근·핵심 아이디어

- 바깥 `i`가 정해지면 안쪽은 `i, 2i, …`를 `n`까지 훑으므로 정확히 `n / i`번 돈다(C++의 `/`는 양수끼리면 내림 나눗셈이라 파이썬 `//`와 같다). 총 횟수는 `n/1 + n/2 + … + n/n`이고, 이 합은 조화급수 `n(1 + 1/2 + … + 1/n) ≈ n·ln n`이라 `O(n log n)`이다.
- "이중 반복 = `O(n^2)`"라는 반사적 판단이 틀리는 대표 사례다. `n=1000`이면 `n^2=10^6`인데 실제 실행은 `7069`번뿐이다. 소수 체(에라토스테네스)나 약수 개수 세기가 정확히 이 구조다.

(2) 코드 단계별

- `n`을 읽고 `cnt = 0`으로 시작한다.
- 문제에 적힌 이중 반복을 그대로 돌리며 안쪽에서 `cnt++`. `j += i`가 "i의 배수만"을 뜻한다.
- `cnt`와 `n * n`을 나란히 출력해 차이를 눈으로 확인한다. `n`을 `int`로 두면 `n = 10000`일 때 `n * n = 10^8`은 아슬아슬하게 들어가지만, 이런 "곱해서 찍는" 자리는 습관적으로 `long long`으로 받아 두는 편이 안전하다.

(3) 스스로 다시 짤 때 생각 순서

- 안쪽 반복 횟수를 바깥 변수의 식(`n / i`)으로 적는 습관을 들인다.
- 그 식을 `i=1..n`으로 더한 합이 무엇인지(조화급수 → `n log n`) 판단한다.
- 작은 `n`으로 손 계산(`n=10` → 27)해 공식과 실행이 맞는지 검산한다.
```

**3) 계단 오르기 경우의 수** · Easy

- **요구사항**: `n`칸짜리 계단을 한 번에 1칸 또는 2칸씩 올라 꼭대기(정확히 `n`칸)에 도달하는 방법의 수를 구하라. 단, 길이 `n`의 `vector`를 만들지 말고 **직전 두 값만 담는 변수 두 개**로 공간 `O(1)`에 계산하라.
- **입력**: 한 줄에 `n`. (`1 ≤ n ≤ 80`)
- **출력**: 방법의 수.
- **예제**: `4` → `5` · `1` → `1`
- **셀프체크**: `ways(n) = ways(n-1) + ways(n-2)`(마지막에 1칸 올랐거나 2칸 올랐거나)를 세웠는가? `ways(1)=1, ways(2)=2`가 맞는가? C++엔 `a, b = b, a + b` 같은 동시 대입이 없으니 임시 변수를 두어 갱신 순서 꼬임을 막았는가? `n=80`이면 값이 약 `3.8×10^16`이라 `int`로는 못 담고 `long long`이 필요하다는 것을 확인했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    long long a = 1, b = 1;      // a = ways(i-1), b = ways(i); 시작은 ways(0)=1, ways(1)=1
    for (int i = 0; i < n - 1; i++) {
        long long nb = a + b;    // 동시 대입이 없으니 새 값을 먼저 임시 변수에
        a = b;
        b = nb;
    }
    cout << b << '\n';
    return 0;
}
@@TESTS
--IN

--OUT
5
--IN
1
--OUT
1
--IN
2
--OUT
2
--IN
80
--OUT
37889062373143906
@@EXPL
(1) 접근·핵심 아이디어

- 마지막 걸음이 1칸이면 그 전까지 `n-1`칸, 2칸이면 `n-2`칸을 오른 것이므로 `ways(n) = ways(n-1) + ways(n-2)`. 시작값은 `ways(0)=1`(아무것도 안 오름), `ways(1)=1`.
- 값 `n`을 구하는 데 필요한 것은 직전 두 값뿐이다. 그래서 길이 `n`짜리 `vector`(`O(n)` 공간) 대신 변수 두 개를 굴려 공간 `O(1)`로 줄인다. 시간은 그대로 `O(n)`.

(2) 코드 단계별

- `a = ways(0) = 1`, `b = ways(1) = 1`로 시작한다. 둘 다 `long long` — `int`로 두면 `n = 46` 근처에서 21억을 넘겨 음수가 튀어나온다(경고도 없이 조용히 틀린다).
- `n-1`번 반복하며 `nb = a + b` → `a = b` → `b = nb` 순으로 한 칸씩 전진하면 반복이 끝났을 때 `b = ways(n)`.
- `n=1`이면 반복이 0번이라 `b=1`, `n=2`면 한 번 돌아 `b=2`.

(3) 스스로 다시 짤 때 생각 순서

- 점화식을 먼저 세우고, "직전 몇 개가 필요한가"를 세어 변수 개수를 정한다(여기선 2개).
- 초기값과 반복 횟수를 `n=1, 2`로 맞춰본다.
- C++엔 동시 대입이 없다. `a = b; b = a + b;`라고 쓰면 `a`가 먼저 바뀌어 `b = 2b`가 되어 틀린다. 임시 변수를 쓰거나 `tie(a, b) = make_pair(b, a + b);`처럼 오른쪽을 먼저 다 만든 뒤 대입해야 한다.
```

**4) 일별 매출 구간 합 질의** · Medium

- **요구사항**: `n`일 동안의 일별 매출과 질의 `q`개가 주어진다. 각 질의 `l r`은 `l`일부터 `r`일까지(양 끝 포함, 1-based)의 매출 합을 묻는다. 질의마다 처음부터 더하면 `O(n·q)`이므로, 누적합 배열을 한 번 만들어 각 질의를 `O(1)`에 답하라.
- **입력**: 첫 줄에 `n q`. 둘째 줄에 매출 `n`개(음수 가능). 이어서 `q`개의 줄에 `l r`. (`1 ≤ n, q ≤ 1000`, `1 ≤ l ≤ r ≤ n`, `-1000 ≤ 매출 ≤ 1000`)
- **출력**: 질의마다 구간 합을 한 줄씩.
- **예제**: `5 3 / 3 1 4 1 5 / 1 3 / 2 5 / 4 4` → `8 / 11 / 1`
- **셀프체크**: `pre[i]`를 "앞 `i`개의 합"으로 정의해 `pre[0]=0`, 크기 `n+1`로 잡았는가? 구간 합이 `pre[r] - pre[l-1]`인가(1-based라 `l-1`)? `l == r`인 한 칸 구간, `l=1`인 맨 앞 구간이 맞는가? 전체 시간이 `O(n + q)`인가?

```runner

(1) 접근·핵심 아이디어

- 질의마다 `l..r`을 직접 더하면 한 질의에 최악 `O(n)`, 전체 `O(n·q)`다. 대신 "앞 `i`개의 합" `pre[i]`를 한 번(`O(n)`) 만들어 두면 어떤 구간 합도 `pre[r] - pre[l-1]`로 뺄셈 한 번(`O(1)`)에 나와 전체 `O(n + q)`가 된다.
- `pre[0]=0`을 두는 이유는 `l=1`일 때 `pre[0]`을 빼야 하기 때문 — 이 한 칸이 경계 처리를 없애 준다. `vector<long long> pre(n + 1, 0)`처럼 **크기와 초기값을 함께** 주면 0으로 채워진 채 시작한다(초기화를 빼먹으면 쓰레기값이 들어간다).

(2) 코드 단계별

- `n, q`를 읽고 매출을 읽으면서 곧바로 `pre[i+1] = pre[i] + x`로 채운다. 원본 배열을 따로 둘 필요도 없다.
- 각 질의에서 `pre[r] - pre[l-1]`을 계산해 문자열에 모았다가 한 번에 출력한다. 질의마다 `cout << ... << endl`을 쓰면 `endl`이 매번 버퍼를 비워 느려진다 — `'\n'`을 쓰거나 이렇게 모아 찍는다.
- 음수가 섞여도 뺄셈이므로 그대로 맞는다.

(3) 스스로 다시 짤 때 생각 순서

- "같은 배열에 구간 합 질의가 여러 번" → 누적합을 떠올린다.
- `pre`의 정의(앞 `i`개)와 1-based 입력의 인덱스 대응(`l-1`)을 종이에 한 번 적는다.
- C++ 함정 둘: 합이 커질 수 있으면 `pre`를 `long long`으로 잡는다(`accumulate(v.begin(), v.end(), 0)`처럼 초기값을 `0`으로 주면 `int`로 누적되어 넘친다 — `0LL`로 줘야 한다). 그리고 `v.size()`는 부호 없는 타입이라 `i < v.size() - 1`은 빈 벡터에서 거대한 수가 되어 폭주한다 — `i + 1 < v.size()`로 쓰거나 `(int)v.size()`로 캐스팅한다.
```

**5) 환율 차익 최대** · Medium

- **요구사항**: `n`일 동안의 환율이 주어진다. 어느 하루에 사서 **그보다 뒤의** 하루에 팔 때 얻는 차익(판 값 − 산 값)의 최댓값을 구하라. 모든 (살 날, 팔 날) 쌍을 이중 반복으로 보면 `O(n^2)`이니, "지금까지의 최솟값" 변수 하나로 한 번만 훑어 `O(n)`에 풀어라. 양의 차익이 없으면 `0`만 출력하고, 있으면 차익과 함께 살 날·팔 날(1-based)도 출력한다. 차익이 같은 쌍이 여럿이면 살 날이 빠른 것, 그것도 같으면 팔 날이 빠른 것을 택한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 환율 `n`개. (`1 ≤ n ≤ 1000`, `1 ≤ 환율 ≤ 10^6`)
- **출력**: 양의 차익이 없으면 `0`. 있으면 `최대차익 살날 팔날`을 한 줄에.
- **예제**: `6 / 7 1 5 3 6 4` → `5 2 5` · `4 / 9 7 5 3` → `0`
- **셀프체크**: 각 날에 대해 "오늘 판다면 최선은 지금까지의 최솟값에 산 것"이므로 최솟값과 그 날짜만 들고 다니면 되는 이유를 말할 수 있는가? 갱신을 **엄격히 클 때(`>`)**만 하고 최솟값도 **엄격히 작을 때**만 바꿔야 동률 규칙(빠른 날 우선)이 지켜지는가? `n=1`이거나 계속 내려가기만 하면 `0`인가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<int> p(n);
    for (int i = 0; i < n; i++) cin >> p[i];
    int best = 0;
    int buyDay = 0, sellDay = 0;
    int minVal = p[0];              // 지금까지의 최솟값과 그 날짜
    int minDay = 1;
    for (int i = 1; i < n; i++) {
        if (p[i] - minVal > best) {          // 오늘 팔 때의 차익
            best = p[i] - minVal;
            buyDay = minDay;
            sellDay = i + 1;

            minVal = p[i];
            minDay = i + 1;
        }
    }
    if (best == 0) cout << 0 << '\n';
    else cout << best << ' ' << buyDay << ' ' << sellDay << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 모든 쌍 `(i < j)`를 보면 `n(n-1)/2`번 비교로 `O(n^2)`. 그런데 "j일에 판다"를 고정하면 최선의 살 날은 `j` 이전의 최솟값이 있던 날로 정해진다. 그러니 왼쪽에서 오른쪽으로 한 번 훑으며 `minVal`(지금까지 최솟값)만 유지하면 각 날의 최선 차익이 `p[j] - minVal`로 즉시 나온다 → `O(n)`.
- 순서가 중요하다: 오늘 값으로 먼저 "판다"를 평가한 뒤에 최솟값을 갱신해야 같은 날 사고파는 일이 없다.

(2) 코드 단계별

- `minVal = p[0]`, `minDay = 1`로 시작하고 둘째 날부터 훑는다. `p[0]`을 읽으므로 `n >= 1`이 보장돼야 한다 — `vector`의 범위 밖 접근(`p[0]`이 빈 벡터일 때)은 C++에서 예외가 아니라 그냥 미정의 동작이라 더 위험하다.
- `p[i] - minVal > best`(엄격)일 때만 답을 갱신 → 같은 차익이면 먼저 찾은(살 날·팔 날이 더 빠른) 쌍이 남는다.
- `p[i] < minVal`(엄격)일 때만 최솟값을 갱신 → 같은 값이면 더 빠른 날이 살 날로 유지된다.
- `best`가 0이면 `0`만, 아니면 세 값을 출력. 환율이 `10^6` 이하라 차익도 `10^6` 이하 — 여기선 `int`로 충분하다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇을 고정하면 나머지가 자명해지는가"(팔 날 고정 → 살 날은 이전 최솟값)를 찾는다.
- 유지할 상태를 최소로 정한다: 최솟값과 그 날짜, 지금까지의 최선.
- 평가 → 갱신 순서와 엄격 부등호가 동률 규칙과 "뒤에 판다" 조건을 함께 보장하는지 예제로 확인한다.
```

**6) 두 배씩 커지는 안쪽 반복의 총 횟수** · Medium

- **요구사항**: 다음 코드에서 바깥 `while`이 몇 번 도는지와 안쪽 줄 `cnt++`가 총 몇 번 실행되는지를 **공식으로** 구하라. `long long i = 1;` / `while (i <= n) {` / `    for (long long j = 0; j < i; j++) cnt++;` / `    i *= 2;` / `}`. 겉보기엔 이중 반복이지만 총 실행 횟수가 `2n` 미만임을 확인하라. `n`이 매우 커서 실제로 돌려 볼 수 없으므로 공식이 필요하다.
- **입력**: 한 줄에 `n`. (`1 ≤ n ≤ 10^18`)
- **출력**: `바깥반복횟수 안쪽총실행횟수`를 한 줄에.
- **예제**: `10` → `4 15` · `1` → `1 1`
- **셀프체크**: 바깥은 `i = 1, 2, 4, 8, …`로 `i <= n`인 동안이니 횟수가 `n`의 이진 자릿수인가(`n=10`이면 `1,2,4,8` 4번)? 안쪽 총합은 `1+2+4+…+2^(k-1) = 2^k - 1`(등비수열)이라 `O(n)`인가? `n=16`이면 `i=16`도 포함되어 바깥 5번·안쪽 31번인가? `n`이 `10^18`이라 `int`로는 못 받고 `long long`이 필요한 것을 확인했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    unsigned long long n;
    cin >> n;
    int outer = 0;                                      // i = 1, 2, 4, ... 가 n 이하인 개수
    for (unsigned long long x = n; x > 0; x >>= 1) outer++;
    unsigned long long total = ((unsigned long long)1 << outer) - 1;   // 1 + 2 + ... + 2^(outer-1)
    cout << outer << ' ' << total << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 바깥 변수 `i`가 `+1`이 아니라 `×2`로 커지므로 그 축은 로그다: `2^0, 2^1, …, 2^(k-1) <= n`인 `k`는 `n`의 이진 자릿수와 같다.
- 안쪽은 `i`번 돌므로 총합은 `1 + 2 + 4 + … + 2^(k-1) = 2^k - 1`. `2^(k-1) <= n`이므로 이 값은 `2n` 미만 — 이중 반복인데도 `O(n log n)`이 아니라 `O(n)`이다. "중첩이면 곱한다"가 아니라 "안쪽 횟수를 실제로 더한다"가 정확한 분석이다.

(2) 코드 단계별

- `n`을 `unsigned long long`으로 받는다. `n <= 10^18`이라 `long long`으로도 되지만, 아래에서 `1 << outer`를 할 때 부호 비트를 신경 쓰지 않아도 되게 부호 없는 타입을 쓴다.
- `for (unsigned long long x = n; x > 0; x >>= 1) outer++;`로 이진 자릿수를 센다(`64 - __builtin_clzll(n)`과 같은 값이다. 단 `__builtin_clzll(0)`은 미정의라 `n = 0`을 넣으면 안 된다 — 여기선 `n >= 1`이라 안전).
- 안쪽 총합은 등비수열 합 `(1ULL << outer) - 1`. **`1 << outer`라고 쓰면 `int` 시프트**라 `outer >= 31`에서 망가진다. 반드시 `1ULL`(또는 `(unsigned long long)1`)로 승격시킨다.
- `n=10` → 이진 `1010`(4자리) → 바깥 4번, 안쪽 `15`. `n=16` → `10000`(5자리) → 바깥 5번, 안쪽 `31`.

(3) 스스로 다시 짤 때 생각 순서

- 반복 변수의 증가 방식(`×2`)을 보고 축을 로그로 판정한다.
- 안쪽 횟수를 바깥 변수의 식(`i`)으로 적고, 바깥 전 범위에 대해 더한다(등비수열).
- 경계: `n`이 정확히 2의 거듭제곱일 때 마지막 `i = n`도 포함되는지(`<=`) 확인한다. 그리고 실제로 `while (i <= n) i *= 2;`를 돌리면 마지막 `i *= 2`에서 `i`가 `long long` 범위를 넘어 음수로 돌아 무한 루프가 될 수 있다 — 공식으로 닫는 편이 안전한 이유가 여기 있다.
```

**7) 제한 시간 안의 최대 입력 크기** · Medium

- **요구사항**: 1초에 `10^8`번 연산하는 컴퓨터에서 제한 시간 `t`초 안에 돌릴 수 있는 **가장 큰 입력 크기** `n`을 구하라. 등급 라벨별 연산 횟수는 `n` → `n`, `nlogn` → `n × (n의 이진 자릿수)`, `n2` → `n^2`, `n3` → `n^3`, `2n` → `2^n`, `nfact` → `n!`로 정의한다. 연산 횟수가 `10^8 × t` 이하인 최대 정수 `n`이 답이다.
- **입력**: 한 줄에 `라벨 t`. (`1 ≤ t ≤ 100`)
- **출력**: 최대 `n`.
- **예제**: `n2 1` → `10000` · `2n 1` → `26`
- **셀프체크**: 연산 횟수가 `n`에 대해 단조 증가하므로 이분 탐색이 되는가? `nfact`나 `2n`은 `n`이 조금만 커져도 한도를 훌쩍 넘으니, 비용 함수 안에서 한도를 넘는 순간 바로 멈추게(또는 `n >= 64`면 즉시 초과로) 만들어 거대한 수 계산을 피했는가? `2^26 ≈ 6.7×10^7`은 통과, `2^27 ≈ 1.3×10^8`은 초과라 답 `26`인가? `11! ≈ 4×10^7`, `12! ≈ 4.8×10^8`이라 `nfact 1`은 `11`인가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

string kind;
long long limitv;

__int128 cost(long long n) {
    if (kind == "n") return (__int128)n;
    if (kind == "nlogn") {
        int L = 0;
        for (long long x = n; x > 0; x >>= 1) L++;
        return (__int128)n * L;
    }
    if (kind == "n2") return (__int128)n * n;
    if (kind == "n3") return (__int128)n * n * n;
    if (kind == "2n") {
        if (n >= 64) return (__int128)limitv + 1;      // 64 이상은 한도를 확실히 넘음
        return (__int128)1 << n;
    }
    __int128 f = 1;                                    // "nfact"
    for (long long k = 2; k <= n; k++) {
        f *= k;
        if (f > limitv) break;                         // 넘는 순간 중단 (거대 수 계산 방지)
    }
    return f;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    long long t;
    cin >> kind >> t;
    limitv = 100000000LL * t;
    long long lo = 1, hi = limitv;      // cost(1) <= limit 은 항상 성립
    while (lo < hi) {                   // cost(n) <= limit 인 최대 n 을 이분 탐색
        long long mid = lo + (hi - lo + 1) / 2;
        if (cost(mid) <= limitv) lo = mid;
        else hi = mid - 1;
    }
    cout << lo << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- "복잡도 판단"을 거꾸로 묻는 문제다. 연산 횟수 `cost(n)`은 `n`이 커질수록 커지므로(단조), `cost(n) <= limit`을 만족하는 최대 `n`을 이분 탐색으로 찾는다. 범위 `[1, limit]`에 대해 `log2(10^10) ≈ 34`번만 `cost`를 부르면 된다.
- 함정은 빠르게 폭발하는 등급이다. `2^(5×10^9)`이나 `(5×10^9)!`을 실제로 만들면 멈춰 버린다. 그래서 `2n`은 `n >= 64`면 한도 초과로 단정하고, `nfact`는 곱하다가 한도를 넘는 즉시 멈춘다 — 답에는 영향이 없고 계산만 싸진다.

(2) 코드 단계별

- 라벨과 `t`를 읽어 `limitv = 100000000LL * t`를 만든다. `100000000 * t`라고 쓰면 `int * long long`이라 여기선 괜찮지만, 두 항이 다 `int`인 곱셈(`100000000 * 100`)은 `int`에서 넘친다 — 상수에 `LL`을 붙이는 습관을 들인다.
- `cost(n)`을 라벨별로 정의하되 반환 타입을 `__int128`로 둔다. 탐색 범위 상한이 `10^10`이라 `n3`이면 `10^30`까지 나오는데 `long long`으로는 못 담는다.
- `lo=1, hi=limit`에서 `mid`가 조건을 만족하면 `lo=mid`, 아니면 `hi=mid-1`. 올림 중앙값을 써야 `lo`가 제자리에서 멈추지 않는다.
- **중앙값은 `(lo + hi + 1) / 2`가 아니라 `lo + (hi - lo + 1) / 2`로 쓴다.** 앞의 식은 `lo + hi`가 타입 범위를 넘으면 음수로 돌아 탐색이 무너진다(`int`라면 `lo, hi`가 각 10억만 넘어도 바로 터진다). 뒤의 식은 항상 `[lo, hi]` 안에서만 계산한다.
- `n2 1` → `10^4`(정확히 `10^8`이라 포함), `n3 2` → `584^3 ≈ 1.99×10^8` 통과·`585^3` 초과.

(3) 스스로 다시 짤 때 생각 순서

- "조건을 만족하는 최대 정수"라는 말에서 단조성 확인 → 이분 탐색.
- 비용 함수를 라벨별로 적고, 폭발하는 등급은 한도 초과 시 조기 종료. 남은 등급은 최댓값을 계산해 담을 타입을 정한다.
- 경계: 한도와 정확히 같은 `n`은 포함(`<=`), 이분 탐색의 올림 `mid` 처리, 그리고 오버플로 안전한 중앙값 식.
```

**8) 연속 k일 최대 합과 연산 횟수 비교** · Hard

- **요구사항**: `n`일의 값과 창 크기 `k`가 주어진다. 연속 `k`일 합의 최댓값을 구하라. 동시에 두 방식의 덧셈·뺄셈 횟수를 공식으로 함께 출력하라. **순진 방식**: 창마다 0에서 시작해 `k`개를 더한다 → `k × (n − k + 1)`번. **슬라이딩 방식**: 첫 창은 `k`번 더하고, 이후 창마다 새 값 더하기 1번·빠지는 값 빼기 1번 → `k + 2 × (n − k)`번. 최댓값은 슬라이딩 방식으로 실제 계산해야 한다.
- **입력**: 첫 줄에 `n k`. 둘째 줄에 정수 `n`개(음수 가능). (`1 ≤ k ≤ n ≤ 1000`, `-1000 ≤ 값 ≤ 1000`)
- **출력**: `최대합 순진횟수 슬라이딩횟수`를 한 줄에.
- **예제**: `6 3 / 2 -1 4 3 -5 6` → `6 12 9` · `4 4 / -1 -2 -3 -4` → `-10 4 4`
- **셀프체크**: 창을 한 칸 밀 때 `cur += a[i] - a[i-k]`로 빠지는 원소 인덱스가 정확한가? 첫 창의 합으로 `best`를 초기화해 모두 음수일 때도(둘째 예제) `0`이 아니라 실제 합이 나오는가? `k = n`이면 창이 하나라 순진·슬라이딩 모두 `k`번인가? `k = 1`이면 순진 `n`번, 슬라이딩 `1 + 2(n-1)`번으로 오히려 순진이 적은가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    long long cur = 0;
    for (int i = 0; i < k; i++) cur += a[i];      // 첫 창: k번 덧셈
    long long best = cur;
    for (int i = k; i < n; i++) {                 // 창 밀기: 더하기 1번 + 빼기 1번
        cur += a[i] - a[i - k];
        if (cur > best) best = cur;
    }
    long long naive = (long long)k * (n - k + 1);
    long long sliding = (long long)k + 2LL * (n - k);
    cout << best << ' ' << naive << ' ' << sliding << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 창의 개수는 `n − k + 1`. 순진하게 창마다 `k`개를 더하면 `k(n−k+1)`번으로, `k ≈ n/2`이면 `O(n^2)`급이다. 슬라이딩 윈도우는 인접한 두 창이 `k−1`개를 공유한다는 관찰로, 이전 합에서 빠지는 값을 빼고 새 값을 더해 창마다 2번만 계산한다 → `O(n)`.
- 두 횟수를 공식으로 나란히 출력하게 한 이유는 "복잡도 차이를 숫자로 체감"하기 위해서다. 다만 `k=1`처럼 창이 아주 작으면 슬라이딩이 오히려 더 많은 연산을 한다 — Big-O가 같아도(둘 다 `O(n)`) 상수는 다를 수 있다는 교훈.

(2) 코드 단계별

- 첫 `k`개를 더해 `cur`를 만들고 `best = cur`로 초기화한다(빈 창 대신 실제 첫 창으로 시작해야 전부 음수일 때 안전). `long long`으로 두면 값의 범위가 커져도 그대로 쓸 수 있다.
- `i = k..n-1`에 대해 `cur += a[i] - a[i-k]` — 들어오는 `a[i]`, 나가는 `a[i-k]`.
- 갱신 후 `cur > best`면 `best`를 바꾼다.
- 공식 `naive = k*(n-k+1)`, `sliding = k + 2*(n-k)`를 계산해 함께 출력. `k`와 `n`이 `int`면 `k * (n - k + 1)`은 `int` 곱셈으로 계산된 **뒤에** `long long`에 담기므로, 값이 커질 수 있는 자리에서는 `(long long)k * (n - k + 1)`처럼 **먼저** 승격시켜야 한다.

(3) 스스로 다시 짤 때 생각 순서

- "연속 `k`개 합"을 보면 인접 창의 공유 부분을 떠올려 슬라이딩으로 간다.
- 빠지는 인덱스 `i-k`를 종이에 그려 확인하고, 첫 창으로 `best`를 초기화한다.
- 경계: `k = n`(창 하나), `k = 1`, 전부 음수 — 세 경우를 예제로 검산한다.
```

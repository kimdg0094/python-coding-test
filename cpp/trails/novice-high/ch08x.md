## L10. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch08(동적계획법)의 핵심을 **반복 훈련**하고, 코딩테스트 단골 유형으로 **확장**하는 연습 세트다. 모든 문제에서 "상태 정의 한 문장 → 점화식 → 기저 → 채우는 순서" 네 단계를 매번 다시 쓴다.
- **반복 훈련 개념**:

- 부분문제 합치기 — 개수는 `dp[i] = dp[i-1] + dp[i-2] + ...`, 최적값은 `dp[i] = 값 + min/max(후보)`. 케이스가 상호배타적인지 확인. **개수 DP의 표는 거의 항상 `vector<long long>`**이다.
- 메모이제이션 vs 타뷸레이션 — 재귀 진입부에 `auto it = memo.find(n); if (it != memo.end()) return it->second;` 3줄 vs `for (int i = ...)`로 작은 것부터 채우기. 상태가 희소하면 `unordered_map` 메모, 촘촘하면 `vector` 타뷸.
- 격자 전진 — `dp[r][c] = 결합(dp[r-1][c], dp[r][c-1])`, `vector<vector<long long>> dp(R, vector<long long>(C, 0))`으로 잡고 장애물은 0 또는 `INF`로 차단.
- 조건부 전진 — 직전 선택·연속 횟수·점프 폭을 상태나 후보로 승격: `dp[i] = cost[i] + min(dp[i-1], dp[i-k])`. `i - k < 0`을 조건으로 막는다(C++ 배열은 음수 인덱스가 곧 메모리 침범이다).
- 배낭 — 0/1은 용량 역순 `for (int c = W; c >= w; c--)`, 무한은 정순 `for (int c = w; c <= W; c++)`. "정확히 채우기"는 도달 불가를 큰 음수(`-1e9`)로 표시.
- 두 문자열 — `dp[i][j]`, 끝 글자가 같으면 대각선, 다르면 위/왼쪽(부분수열) 또는 0으로 리셋(부분문자열).

- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '동적 계획법 1' 단계(1·2·3 더하기, 타일링, 가장 큰 증가 부분 수열, 동전 류), 프로그래머스 「코딩테스트 고득점 Kit」의 '동적계획법', NeetCode 150의 '1-D DP'·'2-D DP'(Coin Change·Palindromic Substrings·Longest Common Subsequence 류), 『이것이 취업을 위한 코딩테스트다』의 'DP'와 '그리디' 파트 비교가 이 레슨 수준이다.

**문제**

**1) 복도 타일 색칠 경우의 수** · Easy

- **요구사항**: 길이 `n`, 폭 1인 복도를 타일로 빈틈없이 채운다. 타일은 길이 1짜리 흰색 1종과 길이 2짜리 빨강·파랑 2종이 있다(같은 길이라도 색이 다르면 다른 방법). 채우는 방법의 수를 10007로 나눈 나머지로 출력하라.
- **입력**: 정수 `n`(1 ≤ n ≤ 1000).
- **출력**: 방법의 수 mod 10007.
- **예제**: `2` → `3` · `4` → `11`
- **셀프체크**: 마지막 칸을 "길이 1 타일로 끝냄"(`dp[n-1]`) vs "길이 2 타일로 끝냄"(색 2가지라 `2 * dp[n-2]`)으로 나눴는가? 두 케이스가 겹치지 않는지, 기저 `dp[0] = 1, dp[1] = 1`이 맞는지 `n = 2`(흰흰·빨·파 = 3)로 검산하라. 매 덧셈마다 `% 10007`을 적용했는가? 모듈러 덕분에 값이 10006을 넘지 않아 `int`로 충분하다 — 모듈러가 없었다면 `long long`이라도 n=1000에서 터진다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    const int MOD = 10007;
    vector<int> dp(n + 2, 0);         // n = 1 일 때도 dp[1] 접근이 안전하도록 +2
    dp[0] = 1;
    dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = (dp[i - 1] + 2 * dp[i - 2]) % MOD;   // 최대 10006 + 20012 < int 범위
    }
    cout << dp[n] % MOD << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- `dp[i]` = 길이 i 복도를 채우는 방법 수. 마지막 타일이 길이 1이면 남은 것은 `dp[i-1]`, 길이 2이면 색이 2가지이므로 `2 * dp[i-2]`. 두 케이스는 마지막 타일 길이가 달라 서로 겹치지 않으니 그냥 더한다: `dp[i] = dp[i-1] + 2 * dp[i-2]`.
- 기저: `dp[0] = 1`(아무것도 안 놓는 한 가지), `dp[1] = 1`(흰색 하나). 계단·타일링과 같은 뼈대에 "계수 2"만 붙은 형태다.
- 채우는 순서: `i`가 2에서 `n`까지 오름차순. `dp[i]`가 자기보다 작은 두 칸에만 의존하므로 이 순서면 항상 준비돼 있다.

(2) 코드 단계별

- `n`을 읽고 크기 `n + 2` 표를 만든다. `n = 1`일 때 `dp[1]`에 쓰려면 크기가 최소 2여야 하므로 여유를 둔 것이다(`vector` 범위 밖 쓰기는 파이썬처럼 예외를 던지지 않고 메모리를 망가뜨린다).
- `dp[0] = dp[1] = 1`로 초기화.
- `i`를 2부터 `n`까지 올리며 점화식을 적용하고 매번 `% 10007`.
- `dp[n]` 출력. 시간 O(n).

(3) 스스로 다시 짤 때 생각 순서

- "마지막 타일"로 케이스를 나누고, 각 케이스에 몇 가지 색이 있는지 계수로 붙인다.
- 기저 두 칸을 손으로 확정한 뒤 작은 인덱스부터 채운다.
- **C++ 포인트**: 매 단계 `% MOD`를 취하면 값이 10006 이하로 유지되고 `dp[i-1] + 2*dp[i-2] < 31000`이라 `int`로 안전하다. 반대로 모듈러가 없는 경우의 수 문제였다면 이 점화식은 n=45쯤에서 `int`를, n=90쯤에서 `long long`마저 넘긴다 — "개수 = long long"을 기본으로 삼고, 모듈러가 있으면 그때 int를 고려한다.
- `n = 2`를 직접 나열(3가지)해 점화식 계수를 검산하고, 모듈러는 매 단계에 취한다.
```

**2) 1, 2, 3의 합으로 나타내기(두 방식)** · Easy

- **요구사항**: 정수 `n`을 1, 2, 3의 합으로 나타내는 방법의 수를 구하라(더하는 순서가 다르면 다른 방법: 4 = 1+3 과 3+1은 별개). 질의가 여러 개 주어진다. **메모이제이션(재귀)과 타뷸레이션(반복) 두 방식을 모두 구현**하고, 두 결과가 같음을 확인한 뒤 값을 출력하라(두 값이 다르면 `MISMATCH`를 출력 — 올바른 구현에서는 나오지 않는다).
- **입력**: 첫 줄에 질의 수 `q`(1 ≤ q ≤ 20), 이후 `q`줄에 `n`(1 ≤ n ≤ 30).
- **출력**: 질의마다 방법의 수 한 줄.
- **예제**: `3 / 4 / 7 / 10` → `7 / 44 / 274` · `1 / 1` → `1`
- **셀프체크**: 메모 함수의 기저를 `n == 0 → 1`, `n < 0 → 0`으로 두었는가? 타뷸레이션은 `dp[i-2]`, `dp[i-3]`이 존재할 때만 더해야 한다 — C++에서 `dp[-1]`은 오류를 내지 않고 **표 바깥 메모리를 읽어** 쓰레기 값이 섞이거나 프로그램이 죽는다(파이썬처럼 뒤에서 세지도 않는다). 질의가 여러 개일 때 메모를 질의마다 비우지 않아도 답이 같음을 이해했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

unordered_map<int, long long> memo;   // 방법 A: 메모이제이션 (위 -> 아래)

long long ways(int n) {
    if (n == 0) return 1;             // 기저: 정확히 다 쓴 경우 한 가지
    if (n < 0) return 0;              // 기저: 초과한 경우는 세지 않는다
    auto it = memo.find(n);
    if (it != memo.end()) return it->second;
    long long res = ways(n - 1) + ways(n - 2) + ways(n - 3);
    memo[n] = res;                    // 재귀가 끝난 뒤에 저장한다
    return res;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int q;
    cin >> q;
    vector<int> qs(q);
    int top = 1;
    for (int i = 0; i < q; i++) {
        cin >> qs[i];
        if (qs[i] > top) top = qs[i];
    }

    // 방법 B: 타뷸레이션 (아래 -> 위), 가장 큰 질의까지 한 번에
    vector<long long> dp(top + 1, 0);
    dp[0] = 1;
    for (int i = 1; i <= top; i++) {
        dp[i] = dp[i - 1];
        if (i >= 2) dp[i] += dp[i - 2];   // 인덱스가 음수가 되지 않게 조건으로 막는다
        if (i >= 3) dp[i] += dp[i - 3];
    }

    for (int i = 0; i < q; i++) {
        long long a = ways(qs[i]);
        long long b = dp[qs[i]];
        if (a == b) cout << b << "\n";
        else cout << "MISMATCH" << "\n";
    }
    return 0;
}

(1) 접근·핵심 아이디어

- 마지막에 더한 수가 1, 2, 3 중 무엇인지로 케이스를 나누면 각각 `n-1`, `n-2`, `n-3`을 만드는 문제가 된다: `f(n) = f(n-1) + f(n-2) + f(n-3)`, `f(0) = 1`.
- 같은 점화식을 두 방식으로 구현한다. 메모이제이션은 재귀 정의를 그대로 옮기고 진입부에서 캐시를 조회한다. 타뷸레이션은 0부터 순서대로 표를 채운다. 결과는 같아야 하며, 다르면 둘 중 하나의 기저나 인덱스 처리가 틀린 것이다.

(2) 코드 단계별

- 질의를 모두 읽으며 최댓값 `top`을 함께 구한다.
- `ways(n)`: `n == 0`이면 1, `n < 0`이면 0(잘못된 분해), 메모에 있으면 반환, 없으면 세 재귀의 합을 저장 후 반환. 메모는 전역이라 질의 사이에 공유되어 이득이다(같은 n은 같은 답).
- `dp`: `top`까지 표를 만들고, `i >= 2`, `i >= 3`일 때만 해당 항을 더한다.
- 질의마다 두 값을 비교해 출력.

(3) 스스로 다시 짤 때 생각 순서

- 점화식은 하나, 구현은 둘 — 어느 쪽이든 "기저"와 "의존 순서"를 먼저 적는다.
- **C++ 함정 1(값 범위)**: 세 항을 더하는 트리보나치는 대략 1.84배씩 커진다. n=30은 53,798,080이라 `int`에 겨우 들어가지만 n=45면 넘친다. **개수 DP는 처음부터 `long long`**으로 잡는 것이 안전하다. 특히 `int dp[]`로 계산한 뒤 `long long`에 대입하면 오버플로는 이미 일어난 뒤라 소용이 없다.
- **C++ 함정 2(음수 인덱스)**: 재귀 쪽은 `n < 0` 기저로, 반복 쪽은 `i >= 2` / `i >= 3` 조건으로 각각 막는다. 파이썬은 `dp[-1]`이 마지막 원소를 조용히 반환해 "틀린 답"이 나오지만, C++은 표 밖 메모리를 읽어 **쓰레기 값이나 크래시**가 된다 — 증상이 더 요란한 대신 원인을 찾기 쉽다.
- **C++ 함정 3(메모 저장 시점)**: `memo[n] = ways(n-1) + ...`처럼 한 줄에 쓰지 말고 결과를 지역 변수에 받은 뒤 저장한다. `[]`가 만든 참조는 재귀 도중 맵이 커지면서 무효화될 수 있다(C++17에서는 대입의 오른쪽이 먼저 계산되어 안전하지만, 습관을 안전한 쪽으로 굳히는 편이 낫다).
- `n = 4`를 손으로 나열(1111, 112, 121, 211, 22, 13, 31 = 7)해 두 구현을 동시에 검산한다.
```

**3) 공사 구간을 피한 최소 통행료** · Easy

- **요구사항**: `R x C` 격자의 각 칸에 통행료(양의 정수)가 있고, 공사 중인 칸은 `-1`로 표시되어 지날 수 없다. (0, 0)에서 (R-1, C-1)까지 오른쪽 또는 아래로만 이동할 때, 지나온 칸(시작·도착 포함)의 통행료 합의 최솟값을 구하라. 도착할 수 없으면 `-1`.
- **입력**: 첫 줄에 `R C`(1 ≤ R, C ≤ 20), 이후 `R`줄에 각 칸의 값 `C`개(1 이상 100 이하 또는 `-1`).
- **출력**: 최소 통행료 또는 `-1`.
- **예제**: `3 3 / 1 2 5 / 3 -1 1 / 4 2 1` → `10` · `2 2 / 1 -1 / -1 1` → `-1`
- **셀프체크**: 공사 칸은 `dp`를 `INF`로 남겨 두어 뒤 칸의 최솟값 후보에서 자연히 밀려나게 했는가? 위·왼쪽 후보가 **모두** `INF`이면 그 칸도 도달 불가(`INF`)여야 한다. `INF`를 `INT_MAX`로 두면 `INF + 통행료`가 **오버플로해 음수가 되어** 도달 불가 칸이 최적 후보로 둔갑한다 — `1e9` 정도로 잡거나 아예 더하지 않도록 조건을 걸어야 한다. 시작 칸이나 도착 칸 자체가 `-1`인 경우 `-1`이 나오는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int R, C;
    cin >> R >> C;
    vector<vector<int>> g(R, vector<int>(C));
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            cin >> g[r][c];

    const int INF = 1000000000;       // INT_MAX 를 쓰면 INF + 통행료가 오버플로한다
    vector<vector<int>> dp(R, vector<int>(C, INF));

    for (int r = 0; r < R; r++) {
        for (int c = 0; c < C; c++) {
            if (g[r][c] == -1) continue;          // 공사 칸은 INF 유지
            if (r == 0 && c == 0) { dp[r][c] = g[r][c]; continue; }
            int best = INF;
            if (r > 0 && dp[r - 1][c] < best) best = dp[r - 1][c];
            if (c > 0 && dp[r][c - 1] < best) best = dp[r][c - 1];
            if (best != INF) dp[r][c] = best + g[r][c];   // 도달 가능할 때만 더한다
        }
    }

    int ans = dp[R - 1][C - 1];
    cout << (ans != INF ? ans : -1) << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- `dp[r][c]` = (0, 0)에서 (r, c)까지 갈 때의 최소 통행료. 이 칸에는 위 또는 왼쪽에서만 오므로 `dp[r][c] = g[r][c] + min(dp[r-1][c], dp[r][c-1])`.
- 장애물은 "경로 수 0"이 아니라 "비용 무한대"로 차단한다. `INF`로 남겨 두면 뒤 칸의 최솟값에서 자동으로 제외되고, 도착 칸이 `INF`면 도달 불가다.
- 채우는 순서: 행 우선(위에서 아래, 왼쪽에서 오른쪽). 그러면 `dp[r-1][c]`와 `dp[r][c-1]`이 항상 먼저 완성돼 있다.

(2) 코드 단계별

- 격자를 `vector<vector<int>>`로 읽고 `dp`를 전부 `INF`로 초기화한다.
- 행 우선으로 스캔: 공사 칸은 건너뛰어 `INF` 유지, 시작 칸은 자기 통행료.
- 나머지 칸은 위·왼쪽 중 존재하는 후보의 최솟값 `best`를 구하고, `best`가 `INF`가 아닐 때만 `best + g[r][c]`로 채운다.
- 도착 칸이 `INF`면 `-1`, 아니면 그 값. 시간·공간 O(R·C).

(3) 스스로 다시 짤 때 생각 순서

- 최소 비용 격자 DP에 장애물을 얹는다 → 장애물의 표현은 `INF`.
- **C++ 함정(이 문제의 핵심)**: `INF`의 값 선택이 곧 정확성이다. `INT_MAX`(2,147,483,647)에 통행료 100을 더하면 `int`가 넘쳐 음수가 되고, 그 음수가 최솟값 경쟁에서 이겨 버린다. 해결은 두 가지 — (a) `INF`를 `1e9`처럼 "더해도 안 넘치는" 크기로 잡는다, (b) 이 코드처럼 `best != INF`일 때만 더한다. 둘 다 하면 가장 안전하다.
- 첫 행·첫 열은 한 방향 후보만 있으므로 `r > 0`, `c > 0` 조건으로 경계 밖 참조를 막는다.
- 예제 1에서 두 경로(오른쪽 우선 10 vs 아래 우선 11)를 손으로 비교하고, 1x1 격자 두 경우(`7`, `-1`)로 경계를 검산한다.
```

**4) 무한 구매 예산 최대 만족도** · Easy

- **요구사항**: 상품 `k`종이 있고 각각 가격과 만족도가 정해져 있다. 각 상품은 몇 개든 살 수 있다. 예산 `B`를 넘지 않게 살 때 만족도 합의 최댓값을 구하라(아무것도 안 사도 된다).
- **입력**: 첫 줄에 `k B`(1 ≤ k ≤ 20, 0 ≤ B ≤ 1000), 이후 `k`줄에 `가격 만족도`(1 ≤ 가격 ≤ 1000, 0 ≤ 만족도 ≤ 1000).
- **출력**: 최대 만족도 합.
- **예제**: `2 10 / 3 4 / 5 7` → `14` · `1 4 / 5 9` → `0`
- **셀프체크**: 같은 상품을 여러 개 담아야 하므로 용량 루프를 **정순**(작은 값 → 큰 값)으로 돌렸는가? 역순으로 돌리면 0/1 배낭이 되어 예제 1이 11(3+5)로 틀린다. `B = 0`이거나 모든 가격이 예산보다 크면 0이 나오는가? 루프 변수는 `int`로 둔다 — `size_t`로 두고 역순을 쓰면 0에서 한 번 더 줄어들며 무한 루프가 된다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int k, B;
    cin >> k >> B;
    vector<int> price(k), value(k);
    for (int i = 0; i < k; i++) cin >> price[i] >> value[i];

    vector<int> dp(B + 1, 0);         // dp[c] = 예산 c 이하 최대 만족도
    for (int i = 0; i < k; i++) {
        int p = price[i], v = value[i];
        for (int c = p; c <= B; c++) {            // 정순 = 무한 배낭
            if (dp[c - p] + v > dp[c]) dp[c] = dp[c - p] + v;
        }
    }
    cout << dp[B] << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- `dp[c]` = 예산 `c` 이하로 얻을 수 있는 최대 만족도. 상품 (p, v)를 하나 더 사면 `dp[c] = max(dp[c], dp[c-p] + v)`.
- 무한 배낭이므로 용량을 정순으로 돌린다. 정순이면 `dp[c-p]`가 이미 "이번 상품을 포함해 갱신된 값"이라 같은 상품을 여러 번 담는 효과가 난다. 0/1 배낭(역순)과 루프 방향 하나만 다르다는 점이 이 문제의 학습 포인트다.

(2) 코드 단계별

- `k`, `B`와 상품 목록을 읽는다.
- `dp`를 크기 `B + 1`, 전부 0으로 초기화(아무것도 안 사면 0). `vector<int> dp(B + 1, 0)`은 두 번째 인자로 초기값을 지정한 것이다 — 초기값을 빼면 `vector`는 0으로 채워 주지만, 지역 배열 `int dp[1001];`은 **쓰레기 값**이 들어 있으니 절대 그대로 쓰면 안 된다.
- 각 상품마다 `c`를 `p`부터 `B`까지 정순으로 돌리며 갱신.
- `dp[B]` 출력. 시간 O(k·B).

(3) 스스로 다시 짤 때 생각 순서

- "여러 개 살 수 있다"를 보면 무한 배낭 → 정순 루프를 떠올린다.
- 상태를 "예산 이하 최대"로 잡으면 `dp[B]`가 곧 답(정확히 채울 필요 없음).
- **C++ 함정**: 배낭의 용량 루프는 방향이 답을 바꾼다. 0/1 배낭에서 역순을 쓸 때 `for (size_t c = W; c >= w; c--)`처럼 부호 없는 타입을 쓰면 `w = 0`인 순간 절대 끝나지 않는다. 루프 변수는 `int`로 통일하는 습관이 안전하다.
- 예제 1을 역순으로 돌려 11이 나오는 것을 확인해 루프 방향의 의미를 몸으로 기억한다.
```

**5) 금화 쪼개기(희소 상태 메모)** · Medium

- **요구사항**: 숫자 `n`이 적힌 금화 하나가 있다. 은행에서는 숫자 `n` 금화를 숫자 `n/2`, `n/3`, `n/4`(정수 나눗셈) 금화 세 개로 바꿔 주며, 바꾼 금화도 다시 바꿀 수 있다. 어떤 금화든 적힌 숫자만큼의 은화로 팔 수 있다. 얻을 수 있는 은화의 최댓값을 구하라. 입력은 여러 줄이며 각 줄마다 답을 출력한다.
- **입력**: 한 줄에 정수 `n` 하나씩(0 ≤ n ≤ 10^9), 줄 수는 1 이상 10 이하.
- **출력**: 각 `n`에 대한 최대 은화 수를 한 줄씩.
- **예제**: `12 / 2` → `13 / 2` · `1000000000` → `4243218150`
- **셀프체크**: `n ≤ 10^9`이므로 크기 `n`짜리 표를 채우는 타뷸레이션은 시간·메모리 모두 불가능하다 — 실제로 방문하는 상태는 `n`을 2, 3, 4로 거듭 나눈 값들뿐이라 매우 희소하므로 메모이제이션이 맞는 도구다. 점화식 `f(n) = max(n, f(n/2) + f(n/3) + f(n/4))`에서 `max`의 첫 항 `n`(그냥 파는 경우)을 빠뜨리지 않았는가? **답이 42억을 넘으므로 반환형이 `int`면 조용히 틀린다** — `long long`인지 확인하라.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

unordered_map<long long, long long> memo;   // 상태가 희소하므로 배열이 아니라 해시 맵

long long best(long long n) {
    if (n == 0) return 0;
    auto it = memo.find(n);
    if (it != memo.end()) return it->second;
    long long res = best(n / 2) + best(n / 3) + best(n / 4);   // 쪼갠다
    if (n > res) res = n;                                      // 그냥 판다
    memo[n] = res;
    return res;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    while (cin >> n) cout << best(n) << "\n";   // EOF 까지 반복
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- `f(n)` = 숫자 n 금화로 얻는 최대 은화. 선택은 둘뿐 — 그냥 판다(`n`) 또는 쪼갠 뒤 각각 최적으로 처리한다(`f(n/2) + f(n/3) + f(n/4)`). 둘 중 큰 값이 답이다.
- 상태 공간이 0 ~ 10^9이지만 실제로 호출되는 `n`은 `n`을 2·3·4로 거듭 나눈 값뿐이라 수천 개 수준이다. 이렇게 "넓지만 희소한" 상태 공간에서는 필요한 상태만 계산하는 메모이제이션이 압도적으로 유리하다. `vector<long long> dp(n + 1)`은 10^9칸 = 8GB라 애초에 만들 수 없다.

(2) 코드 단계별

- `unordered_map<long long, long long> memo`를 두고 `best(n)`을 정의: `n == 0`이면 0(기저), 메모에 있으면 반환.
- 없으면 세 조각의 합을 구하고 `n` 자체와 비교해 큰 쪽을 저장 후 반환.
- 입력의 각 정수에 대해 `best`를 호출해 출력. 메모는 전역이라 줄 사이에 공유되어 이득이다.
- `while (cin >> n)`은 스트림이 EOF에 닿거나 정수 파싱에 실패하면 거짓이 되어 자연스럽게 끝난다.

(3) 스스로 다시 짤 때 생각 순서

- "쪼개거나 말거나"의 두 선택을 큰 쪽 고르기로 묶어 점화식을 세운다.
- 입력 범위(10^9)를 보고 표 크기를 가늠해 타뷸레이션이 불가능함을 판단하고, 방문 상태 수가 작음을 근거로 메모를 고른다.
- **C++ 함정(이 문제의 핵심)**: n = 10^9의 답은 4,243,218,150으로 `int` 한계(약 21억)의 두 배다. 반환형·메모 값 타입·인자 타입을 전부 `long long`으로 맞춰야 한다. 하나라도 `int`면 중간에 잘려 **컴파일 오류 없이 틀린 답**이 나온다. 값이 커질 수 있는 DP는 "표 타입부터 정한다"가 첫 단계다.
- **C++ 포인트**: 정수 나눗셈 `n / 2`는 C++에서도 몫만 남기므로 파이썬 `n // 2`와 같다. 단 음수에서는 다르다(C++은 0 방향 절삭, 파이썬은 아래로 내림) — 여기서는 `n ≥ 0`이라 문제되지 않지만 음수가 섞이는 문제에서는 반드시 확인한다.
- 작은 값(`n = 12`: 6 + 4 + 3 = 13 > 12)과 쪼개면 손해인 값(`n = 2`: 1 + 0 + 0 < 2), `n = 0`으로 검산한다.
```

**6) 가장 큰 증가 부분 수열의 합** · Medium

- **요구사항**: 정수 수열에서 순서를 유지하며 고른 순증가 부분 수열 중, 원소 합이 최대인 것의 합을 구하라. 길이가 아니라 **합**이 기준이다(길이가 짧아도 합이 크면 그쪽이 답).
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 500), 둘째 줄에 정수 `n`개(1 이상 1000 이하).
- **출력**: 최대 합.
- **예제**: `6 / 1 100 2 50 60 3` → `113` · `4 / 9 8 7 6` → `9`
- **셀프체크**: `dp[i]` = "i에서 끝나는 증가 부분 수열의 최대 합"으로 두고 초기값을 1이 아니라 `a[i]`로 했는가? 전이는 `dp[j] + 1`이 아니라 `dp[j] + a[i]`다. 예제 1에서 길이 기준 LIS(1 2 50 60, 길이 4)와 합 기준(1 2 50 60 = 113 vs 1 100 = 101)이 이번엔 같은 수열이지만, 일반적으로 다를 수 있음을 이해했는가? 전체 답은 표의 최댓값이지 `dp[n-1]`이 아니다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    vector<long long> dp(n, 0);       // dp[i] = a[i] 로 끝나는 증가 부분 수열의 최대 합
    long long best = 0;
    for (int i = 0; i < n; i++) {
        dp[i] = a[i];                 // 아무것도 못 이으면 자기 혼자
        for (int j = 0; j < i; j++) {
            if (a[j] < a[i] && dp[j] + a[i] > dp[i]) dp[i] = dp[j] + a[i];
        }
        if (dp[i] > best) best = dp[i];
    }
    cout << best << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- LIS와 같은 상태 정의를 쓰되 "길이"를 "합"으로 바꾼다: `dp[i]` = `a[i]`로 끝나는 증가 부분 수열의 최대 합. 앞의 `j` 중 `a[j] < a[i]`인 것들에서 `dp[j] + a[i]`의 최댓값, 아무것도 못 이으면 자기 혼자 `a[i]`.
- 정답은 특정 칸이 아니라 모든 `dp[i]`의 최댓값이다. 앞에서부터 채우면 `dp[j]`(j < i)가 항상 먼저 준비된다.

(2) 코드 단계별

- 배열을 읽고 각 `i`에 대해 `dp[i] = a[i]`로 시작.
- `j`를 0부터 `i-1`까지 돌며 `a[j] < a[i]`이고 `dp[j] + a[i]`가 더 크면 갱신.
- `dp[i]`로 전역 최댓값 `best`를 갱신하고 마지막에 출력. 이중 루프라 O(n^2).

(3) 스스로 다시 짤 때 생각 순서

- "증가 부분 수열"이면 LIS 뼈대(i에서 끝나는 것)를 먼저 가져온다.
- 무엇을 최대화하는지(길이 → 합)에 따라 초기값과 `+1` 자리를 `a[i]`로 바꾼다.
- **C++ 포인트**: 여기서는 n=500, 값 ≤1000이라 합이 최대 50만이므로 `int`로도 충분하지만 `long long`으로 잡아 뒀다. 값이나 개수가 커지는 변형(원소가 10^9까지, n이 10^5까지)에서는 합이 곧 `int`를 넘는다. 비교식 `dp[j] + a[i]`는 `dp`가 `long long`이면 `a[i]`도 자동으로 넓혀져 계산되므로 안전하다 — 반대로 둘 다 `int`면 **더한 뒤에** 넓혀져 이미 늦다.
- 감소 수열(가장 큰 원소 하나가 답), 원소 하나뿐인 경우로 검산한다.
```

**7) 징검다리 1칸 또는 k칸 최소 비용** · Medium

- **요구사항**: 돌 `n`개가 일렬로 놓여 있고 각 돌을 밟는 비용이 정해져 있다. 0번 돌에서 시작해 `n-1`번 돌에 도착해야 하며, 한 번에 앞으로 1칸 또는 정확히 `k`칸 이동할 수 있다(뒤로는 불가). 밟은 돌(시작·도착 포함)의 비용 합의 최솟값을 구하라.
- **입력**: 첫 줄에 `n k`(1 ≤ n ≤ 1000, 1 ≤ k ≤ n), 둘째 줄에 비용 `n`개(0 이상 1000 이하).
- **출력**: 최소 비용.
- **예제**: `6 3 / 1 9 9 1 9 1` → `12` · `1 1 / 4` → `4`
- **셀프체크**: `dp[i]` = "i번 돌에 도착했을 때의 최소 비용"으로 두고 후보를 `dp[i-1]`과 (`i >= k`일 때만) `dp[i-k]` 둘로 잡았는가? `k = 1`이면 두 후보가 같아 그냥 전부 밟는 합이 된다. `k = n`이면 `i - k`가 음수라 점프 후보가 한 번도 없다 — C++에서 `dp[음수]`는 표 바깥 메모리 접근이므로 조건으로 반드시 막아야 한다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, k;
    cin >> n >> k;
    vector<int> cost(n);
    for (int i = 0; i < n; i++) cin >> cost[i];

    vector<int> dp(n, 0);
    dp[0] = cost[0];                  // 시작 돌은 반드시 밟는다
    for (int i = 1; i < n; i++) {
        int best = dp[i - 1];                          // 1칸 전에서 온다
        if (i >= k && dp[i - k] < best) best = dp[i - k];   // k칸 전에서 온다
        dp[i] = best + cost[i];
    }
    cout << dp[n - 1] << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- `dp[i]` = i번 돌에 도착하는 최소 비용. i에 오는 방법은 "i-1에서 1칸" 또는 "i-k에서 k칸" 둘뿐이므로 `dp[i] = cost[i] + min(dp[i-1], dp[i-k])`. `i < k`이면 두 번째 후보는 존재하지 않는다.
- 1칸 이동이 항상 가능하므로 모든 돌은 도달 가능하다 — 따로 `INF`를 둘 필요가 없다.
- 1·2칸 계단 문제의 "2"를 일반 "k"로 바꾼 조건부 전진 DP다. 후보가 상수 개라 O(n).

(2) 코드 단계별

- `n`, `k`, 비용 배열을 읽고 `dp[0] = cost[0]`.
- `i`를 1부터 `n-1`까지: 기본 후보 `dp[i-1]`, `i >= k`이면 `dp[i-k]`와 비교해 작은 쪽을 `best`로.
- `dp[i] = best + cost[i]`.
- `dp[n-1]` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "어디서 올 수 있는가"를 나열해 후보 집합을 만든다(1칸 전, k칸 전).
- **C++ 함정**: `i - k < 0`을 조건문으로 걸러야 한다. 파이썬이라면 `dp[-1]`이 "마지막 원소"를 조용히 반환해 결과만 틀리지만, C++ `vector`의 `[]`는 범위 검사를 하지 않아 **표 바깥 메모리를 읽는다**(디버그 빌드가 아니면 경고도 없다). 값 검사가 필요하면 `dp.at(i - k)`가 예외를 던져 주지만, 애초에 조건으로 막는 편이 빠르고 명확하다.
- `k = 1`(전부 밟기), `k = n`(점프 불가), 예제 1(0→3→4→5 = 12)로 검산한다.
```

**8) 가장 긴 공통 부분 문자열** · Medium

- **요구사항**: 두 문자열의 공통 **부분 문자열**(연속한 글자 구간) 중 가장 긴 것의 길이를 구하라. 부분수열(비연속)이 아니라 연속이어야 한다.
- **입력**: 첫 줄에 문자열 A, 둘째 줄에 문자열 B(각 소문자, 길이 1 이상 300 이하).
- **출력**: 최대 길이(공통 글자가 없으면 0).
- **예제**: `abcdxyz / xyzabcd` → `4` · `abc / def` → `0`
- **셀프체크**: LCS(부분수열)와 달리 끝 글자가 다르면 "위·왼쪽 중 큰 값"이 아니라 **0**이어야 한다 — 연속이 끊기기 때문이다. `dp[i][j]` = "A의 i번째 글자와 B의 j번째 글자에서 **끝나는** 공통 부분 문자열의 길이"라는 정의를 쓰면, 답은 `dp[m][n]`이 아니라 표 전체의 최댓값이다. 인덱스는 1부터 쓰고 실제 글자는 `a[i-1]`로 읽는 관례를 지켰는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    string a, b;
    cin >> a >> b;
    int m = (int)a.size(), n = (int)b.size();

    vector<int> prev(n + 1, 0), cur(n + 1, 0);   // 행 두 줄만 유지(롤링)
    int best = 0;
    for (int i = 1; i <= m; i++) {
        fill(cur.begin(), cur.end(), 0);         // 다르면 0 이므로 매 행을 비우고 시작
        for (int j = 1; j <= n; j++) {
            if (a[i - 1] == b[j - 1]) {
                cur[j] = prev[j - 1] + 1;        // 대각선에서 하나 늘어난다
                if (cur[j] > best) best = cur[j];
            }
        }
        prev = cur;
    }
    cout << best << "\n";
    return 0;
}

--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- `dp[i][j]` = A[i-1]과 B[j-1]에서 끝나는 공통 부분 문자열의 길이. 두 글자가 같으면 대각선에서 하나 늘어나고(`dp[i-1][j-1] + 1`), 다르면 연속이 끊기므로 0이다.
- "끝나는" 위치를 상태로 잡았기 때문에 전체 답은 표의 최댓값이다. LCS와 표 모양은 같지만 "다를 때 0"과 "답 = 최댓값" 두 가지가 다르다.
- 채우는 순서: i를 1부터, 그 안에서 j를 1부터. `dp[i][j]`가 `dp[i-1][j-1]`(왼쪽 위)에만 의존하므로 이 순서면 충분하다.

(2) 코드 단계별

- `cin >> a >> b`로 두 문자열을 읽는다(공백이 없는 한 줄씩이므로 `getline` 없이도 된다).
- 이전 행 `prev`와 현재 행 `cur`만 유지하는 롤링으로 공간 O(n).
- **매 행 시작에서 `cur`를 0으로 비운다** — 글자가 다를 때 아무것도 대입하지 않으므로, 비우지 않으면 두 행 전의 값이 남아 오답이 된다(파이썬처럼 매번 새 리스트를 만드는 코드였다면 자동으로 해결되던 부분이다).
- 글자가 같을 때만 `cur[j] = prev[j-1] + 1`을 쓰고 `best`를 갱신한다.
- 행을 바꿔 가며 끝까지 채운 뒤 `best` 출력. 시간 O(m·n).

(3) 스스로 다시 짤 때 생각 순서

- "연속"이라는 단어를 보면 부분수열 DP의 "위·왼쪽 중 큰 값" 전이를 0으로 바꾼다.
- 상태를 "여기서 끝나는"으로 정의했으면 답이 마지막 칸이 아님을 기억한다.
- **C++ 포인트**: `a.size()`는 `size_t`(부호 없음)라 `int m`으로 받아 두면 `i - 1`, `j - 1` 같은 연산을 마음 놓고 쓸 수 있다. `for (int i = 1; i <= a.size(); i++)`처럼 직접 비교하면 부호 있는/없는 비교 경고가 뜬다.
- 공통 글자가 전혀 없는 경우(0), 한 글자 문자열(1)로 검산한다.
```

**9) 그리디가 틀리는 동전** · Medium

- **요구사항**: 동전 종류와 금액 `M`이 주어진다. 두 가지 방법으로 "동전 개수"를 구해 공백으로 구분해 출력하라. (a) **그리디**: 큰 액면부터 가능한 한 많이 쓰는 방식으로 진행한 개수 — 끝까지 진행해도 금액이 정확히 만들어지지 않으면 `-1`. (b) **DP**: 정확히 `M`을 만드는 최소 개수 — 만들 수 없으면 `-1`.
- **입력**: 첫 줄에 `k M`(1 ≤ k ≤ 10, 0 ≤ M ≤ 1000), 둘째 줄에 서로 다른 액면 `k`개(1 이상 1000 이하).
- **출력**: `그리디개수 DP최소개수`.
- **예제**: `3 12 / 1 6 10` → `3 2` · `2 6 / 3 4` → `-1 2`
- **셀프체크**: 그리디는 액면을 내림차순으로 정렬한 뒤 몫과 나머지로 진행하고, 마지막 나머지가 0이 아니면 `-1`인가? DP는 `dp[0] = 0`, 나머지 `INF`로 시작해 `dp[x] = min(dp[x-c] + 1)`인가? `INF`를 `1e9`로 두면 `dp[x-c] + 1`이 넘치지 않는다(`INT_MAX`면 넘친다). 예제 1(10+1+1 = 3개 vs 6+6 = 2개), 예제 2(그리디는 4를 먼저 써서 2가 남아 실패, DP는 3+3)로 "그리디가 틀리는 두 가지 방식(비최적·실패)"을 모두 확인했는가? `M = 0`이면 둘 다 0.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int k, M;
    cin >> k >> M;
    vector<int> coins(k);
    for (int i = 0; i < k; i++) cin >> coins[i];

    // (a) 그리디: 큰 액면부터 최대한
    vector<int> desc = coins;
    sort(desc.begin(), desc.end(), greater<int>());
    int rest = M, g = 0;
    for (int c : desc) {
        g += rest / c;
        rest %= c;
    }
    int greedy = (rest == 0 ? g : -1);

    // (b) DP: 정확히 M 을 만드는 최소 개수
    const int INF = 1000000000;       // INT_MAX 였다면 dp[x-c] + 1 이 오버플로한다
    vector<int> dp(M + 1, INF);
    dp[0] = 0;
    for (int x = 1; x <= M; x++) {
        for (int c : coins) {
            if (c <= x && dp[x - c] + 1 < dp[x]) dp[x] = dp[x - c] + 1;
        }
    }
    int best = (dp[M] != INF ? dp[M] : -1);

    cout << greedy << ' ' << best << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 그리디는 "큰 동전을 많이 쓰면 개수가 준다"는 직관인데, 이는 액면이 서로 배수 관계일 때만 보장된다. 배수 관계가 아니면 (i) 개수가 최소가 아니거나(1·6·10으로 12), (ii) 아예 금액을 못 만들 수 있다(3·4로 6).
- DP는 `dp[x]` = 금액 x의 최소 개수로 모든 마지막 동전을 후보로 비교하므로 항상 최적이다. 두 결과를 나란히 두면 "언제 DP가 필요한가"가 눈에 보인다.
- 채우는 순서: 금액 `x`를 1부터 `M`까지 오름차순. `dp[x-c]`는 `x`보다 작으므로 항상 먼저 완성돼 있다.

(2) 코드 단계별

- 그리디: 액면 사본을 `sort(..., greater<int>())`로 내림차순 정렬하고, `rest / c`를 개수에 더한 뒤 `rest %= c`. 끝에 `rest`가 0이 아니면 `-1`. 원본 `coins`는 DP에서 그대로 써야 하므로 사본에 정렬한다(사실 DP는 순서와 무관하지만, "정렬이 원본을 바꾼다"는 점을 의식하는 습관이 중요하다).
- DP: `dp[0] = 0`, 나머지 `INF`. `x`를 1부터 `M`까지 올리며 각 동전 `c ≤ x`에 대해 `dp[x-c] + 1`이 더 작으면 갱신.
- `dp[M]`이 `INF`면 `-1`. 두 값을 한 줄에 출력. 시간 O(k log k + M·k).

(3) 스스로 다시 짤 때 생각 순서

- 동전 문제를 보면 먼저 "액면이 배수 관계인가"를 묻는다 — 아니면 그리디를 버리고 DP.
- **C++ 함정**: `INF`를 `INT_MAX`로 잡으면 `dp[x - c] + 1`에서 곧바로 `int` 오버플로가 나고, 그 결과가 음수라 비교에서 이겨 표가 오염된다. `1e9`처럼 "+1을 여러 번 해도 안전한" 값으로 두거나 `dp[x-c] != INF`를 먼저 검사한다.
- `M = 0`이면 `dp`의 크기가 1이고 루프가 한 번도 돌지 않아 `dp[0] = 0`이 그대로 답이 된다 — 크기 `M + 1`로 잡았기 때문에 성립한다.
- 그리디가 틀리는 방식이 두 가지(비최적, 실패)임을 예제로 확인해 둔다. `M = 0`(둘 다 0), 홀수 금액을 짝수 동전으로(둘 다 -1)로 경계를 검산한다.
```

**10) 정확히 채우는 배낭** · Medium

- **요구사항**: 물건 `N`개 각각의 무게와 가치가 주어진다. 각 물건은 최대 1개만 담을 수 있다. 담은 물건의 무게 합이 **정확히** `W`가 되도록 고를 때 가치 합의 최댓값을 구하라. 정확히 `W`를 만들 수 없으면 `-1`.
- **입력**: 첫 줄에 `N W`(1 ≤ N ≤ 50, 1 ≤ W ≤ 1000), 이후 `N`줄에 `무게 가치`(1 ≤ 무게 ≤ 1000, 0 ≤ 가치 ≤ 1000).
- **출력**: 최대 가치 또는 `-1`.
- **예제**: `3 5 / 2 3 / 3 4 / 5 6` → `7` · `2 4 / 3 5 / 3 5` → `-1`
- **셀프체크**: "이하"가 아니라 "정확히"이므로 `dp`를 0이 아니라 **도달 불가를 뜻하는 큰 음수**로 초기화하고 `dp[0] = 0`만 도달 가능으로 두었는가? 전이에서 `dp[c-w]`가 도달 불가면 건너뛰는가(안 건너뛰면 `-1e9 + 가치`가 여전히 음수라 답은 맞지만 의미가 흐려진다)? 0/1이므로 용량 루프는 역순이다. 가치 0인 물건으로 정확히 채우면 답은 `-1`이 아니라 `0`임을 확인하라.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int N, W;
    cin >> N >> W;
    const int NEG = -1000000000;      // 도달 불가 표시(더해도 int 를 넘지 않는 크기)
    vector<int> dp(W + 1, NEG);
    dp[0] = 0;                        // 무게 0 은 아무것도 안 담아 만들 수 있다

    for (int i = 0; i < N; i++) {
        int w, v;
        cin >> w >> v;
        for (int c = W; c >= w; c--) {            // 역순 = 0/1 배낭
            if (dp[c - w] != NEG && dp[c - w] + v > dp[c]) dp[c] = dp[c - w] + v;
        }
    }
    cout << (dp[W] != NEG ? dp[W] : -1) << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- `dp[c]` = 무게 합이 **정확히** c가 되도록 담았을 때의 최대 가치. 도달 불가를 표현해야 하므로 큰 음수로 초기화하고 `dp[0] = 0`만 시작점으로 둔다.
- 전이는 0/1 배낭과 같다: `dp[c] = max(dp[c], dp[c-w] + v)`, 단 `dp[c-w]`가 도달 가능할 때만. 용량 역순으로 돌려 같은 물건을 두 번 담지 않는다.
- 왜 역순인가: 정순이면 `dp[c-w]`가 이미 이번 물건으로 갱신된 값이라 같은 물건을 여러 번 담게 된다(그게 무한 배낭). 역순이면 `dp[c-w]`가 아직 "이번 물건 이전"의 값이다.

(2) 코드 단계별

- `dp`를 `NEG`로 채우고 `dp[0] = 0`.
- 물건마다 `c`를 `W`부터 `w`까지 역순으로 돌리며, `dp[c-w]`가 `NEG`가 아니고 `dp[c-w] + v`가 더 크면 갱신.
- 끝나면 `dp[W]`가 `NEG`이면 `-1`, 아니면 그 값. 시간 O(N·W).

(3) 스스로 다시 짤 때 생각 순서

- "이하"인지 "정확히"인지 문장에서 확인하고, "정확히"면 초기값을 0에서 도달 불가 값으로 바꾼다.
- **C++ 함정**: 파이썬의 `float('-inf')`에 해당하는 정수는 없다. `INT_MIN`을 쓰면 `INT_MIN + v`가 **언더플로**해 거대한 양수로 뒤집혀 오답이 된다. `-1e9`처럼 "여러 번 더해도 안전한" 값을 쓰고, 여기에 더해 `dp[c-w] != NEG` 조건으로 도달 불가 상태에서의 전이를 아예 막는다.
- 루프 변수를 `int`로 둔다. `for (size_t c = W; c >= w; c--)`는 `w = 0`인 변형에서 절대 끝나지 않는다.
- 가치 0으로 정확히 채우는 경우(답 0)와 만들 수 없는 경우(답 -1)를 구분해 검산한다.
```

**11) 최소 동전 개수와 그 조합의 수** · Hard

- **요구사항**: 서로 다른 액면의 동전이 무한히 있다. 금액 `M`을 정확히 만드는 **최소 동전 개수**와, 그 최소 개수로 만드는 서로 다른 **조합의 수**(같은 동전 묶음은 순서와 무관하게 하나로 센다)를 공백으로 구분해 출력하라. 만들 수 없으면 `-1` 하나만 출력한다.
- **입력**: 첫 줄에 `k M`(1 ≤ k ≤ 10, 0 ≤ M ≤ 1000), 둘째 줄에 서로 다른 액면 `k`개(1 이상 1000 이하).
- **출력**: `최소개수 조합수` 또는 `-1`.
- **예제**: `4 5 / 1 2 3 4` → `2 2` · `2 7 / 2 4` → `-1`
- **셀프체크**: 최소 개수 표 `best[x]`와 조합 수 표 `ways[x]`를 **같은 전이에서 함께** 갱신하되, 후보가 더 작으면 `ways`를 덮어쓰고 같으면 더하는 규칙을 썼는가? 조합(순서 무시)을 세려면 동전 루프가 바깥, 금액 루프가 안쪽이어야 한다(뒤집으면 1+4와 4+1을 따로 세어 틀린다). **`ways`는 `long long`인가** — 조합 수는 개수 DP라 액면이 촘촘하면 금세 21억을 넘는다. `M = 0`이면 `0 1`(아무것도 안 쓰는 한 가지)이 나오는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int k, M;
    cin >> k >> M;
    vector<int> coins(k);
    for (int i = 0; i < k; i++) cin >> coins[i];

    const int INF = 1000000000;
    vector<int> best(M + 1, INF);         // best[x] = 금액 x 의 최소 동전 개수
    vector<long long> ways(M + 1, 0);     // ways[x] = 그 최소 개수를 이루는 조합 수
    best[0] = 0;
    ways[0] = 1;                          // 빈 조합 하나

    for (int c : coins) {                 // 동전이 바깥 루프 -> 순서 무시(조합)
        for (int x = c; x <= M; x++) {    // 금액 정순 -> 같은 동전을 여러 번 사용
            if (best[x - c] == INF) continue;
            int cand = best[x - c] + 1;
            if (cand < best[x]) {         // 더 좋은 최적이 나오면 경우의 수를 갈아엎는다
                best[x] = cand;
                ways[x] = ways[x - c];
            } else if (cand == best[x]) { // 같은 최적이면 경로가 늘어난 것
                ways[x] += ways[x - c];
            }
        }
    }

    if (best[M] == INF) cout << -1 << "\n";
    else cout << best[M] << ' ' << ways[M] << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 두 표를 동시에 채운다. `best[x]`는 최소 개수, `ways[x]`는 그 최소 개수를 달성하는 조합의 수. 전이에서 새 후보 `best[x-c] + 1`이 기존보다 작으면 최적이 바뀌므로 `ways[x] = ways[x-c]`로 덮어쓰고, 같으면 또 다른 최적 경로가 추가된 것이므로 `ways[x] += ways[x-c]`.
- 조합(순서 무시)을 세려면 "동전 종류를 하나씩 추가하며 금액을 정순으로" 도는 무한 배낭 형태여야 한다. 동전 루프가 바깥이면 "동전 c를 0개 쓰는 경우"와 "1개 이상 쓰는 경우"가 겹치지 않게 나뉘어 중복이 없다.
- 채우는 순서: 바깥이 동전(종류를 하나씩 개방), 안쪽이 금액 오름차순(같은 동전 재사용 허용).

(2) 코드 단계별

- `best[0] = 0`, `ways[0] = 1`, 나머지는 `INF`/0.
- 동전 `c`마다 `x`를 `c`부터 `M`까지 정순으로: `best[x-c]`가 `INF`면 건너뜀.
- 후보 `cand`가 더 작으면 `best`·`ways`를 덮어쓰고, 같으면 `ways`를 더한다.
- `best[M]`이 `INF`면 `-1`, 아니면 두 값 출력. 시간 O(k·M).

(3) 스스로 다시 짤 때 생각 순서

- "최솟값 + 그 최솟값을 이루는 경우의 수"는 표 두 개를 한 전이에서 함께 갱신하는 정형 패턴임을 떠올린다.
- 순서 무시(조합)면 동전 바깥 루프, 순서 구분(순열)이면 금액 바깥 루프 — 어느 쪽인지 문제에서 확인한다.
- **C++ 함정(이 문제의 핵심)**: `best`는 최대 1000이라 `int`면 되지만, `ways`는 **개수**라 다르다. 액면이 촘촘하고 `M`이 크면 같은 최소 개수를 이루는 조합의 수가 폭발적으로 늘어 `int`를 넘긴다. 두 표의 타입을 따로 판단하는 것이 요령이다 — "최적값 표는 값 범위, 개수 표는 조합 폭발"을 각각 보고 정한다. 문제에 모듈러가 명시돼 있다면 `ways[x] = (ways[x] + ways[x-c]) % MOD`로 매 덧셈마다 나눈다.
- `M = 0`(0 1), 불가능(-1), 예제 1(1+4, 2+3 → 2가지)로 검산한다.
```

**12) 보석을 정확히 K개 줍는 경로 수** · Hard

- **요구사항**: `R x C` 격자의 각 칸은 빈칸(`.`), 보석(`*`), 벽(`#`) 중 하나다. (0, 0)에서 (R-1, C-1)까지 오른쪽 또는 아래로만 이동할 때, 지나는 칸(시작·도착 포함)에 있는 보석 수가 **정확히** `K`개인 경로의 수를 구하라. 벽은 지날 수 없다.
- **입력**: 첫 줄에 `R C K`(1 ≤ R, C ≤ 15, 0 ≤ K ≤ 30), 이후 `R`줄에 길이 `C`인 문자열.
- **출력**: 경로의 수(정수).
- **예제**: `2 2 1 / .* / *.` → `2` · `3 3 2 / .*. / *#* / .*.` → `2`
- **셀프체크**: 경로 수 격자 DP에 "지금까지 주운 보석 수"를 상태 차원으로 추가해 `dp[r][c][k]`로 잡았는가? 보석 칸에 들어올 때는 `k-1`짜리 상태에서 전이해야 한다(`k < 보석수`면 불가). 시작 칸이 보석이면 `dp[0][0][1] = 1`, 아니면 `dp[0][0][0] = 1`. 3차원 `vector`는 `vector<vector<vector<long long>>> dp(R, vector<vector<long long>>(C, vector<long long>(K+1, 0)))`처럼 안쪽부터 만든다. 1x1 격자에서 시작 칸이 `*`이고 `K = 0`이면 답이 0인가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int R, C, K;
    cin >> R >> C >> K;
    vector<string> grid(R);
    for (int r = 0; r < R; r++) cin >> grid[r];

    // dp[r][c][k] = (r, c) 도착 시점에 보석을 정확히 k 개 주운 경로 수
    vector<vector<vector<long long>>> dp(
        R, vector<vector<long long>>(C, vector<long long>(K + 1, 0)));

    for (int r = 0; r < R; r++) {
        for (int c = 0; c < C; c++) {
            char ch = grid[r][c];
            if (ch == '#') continue;               // 벽은 모든 k 에서 0 으로 남긴다
            int gem = (ch == '*' ? 1 : 0);
            for (int k = 0; k <= K; k++) {
                if (k < gem) continue;             // 이 칸 보석보다 적게 주울 수는 없다
                if (r == 0 && c == 0) {
                    dp[r][c][k] = (k == gem ? 1 : 0);
                    continue;
                }
                long long total = 0;
                if (r > 0) total += dp[r - 1][c][k - gem];
                if (c > 0) total += dp[r][c - 1][k - gem];
                dp[r][c][k] = total;
            }
        }
    }
    cout << dp[R - 1][C - 1][K] << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 경로 수 격자 DP(`dp[r][c] = 위 + 왼쪽`)만으로는 "보석을 몇 개 주웠는지"를 구분할 수 없다. 그래서 주운 개수 `k`를 상태 차원으로 승격해 `dp[r][c][k]` = (r, c)에 도착했을 때 지금까지 보석 `k`개를 주운 경로 수로 둔다.
- 이 칸에 보석이 있으면(`gem = 1`) 들어오기 전에는 `k - 1`개였어야 하므로 `dp[r][c][k] = dp[r-1][c][k-gem] + dp[r][c-1][k-gem]`. 벽은 모든 `k`에서 0으로 남긴다.
- 채우는 순서: 행 우선. `k`는 안쪽 루프로 돌아도 되는데, 전이가 항상 "이전 칸"을 보기 때문이지 "같은 칸의 다른 k"를 보지 않기 때문이다.

(2) 코드 단계별

- 격자와 `K`를 읽고 3차원 표를 0으로 만든다. `vector<vector<vector<long long>>>`은 안쪽 차원부터 크기와 초기값을 지정해 중첩한다.
- 행 우선으로 스캔하며 벽이면 건너뛴다. `gem`을 정하고 `k`를 0부터 `K`까지 돌리되 `k < gem`이면 불가.
- 시작 칸은 `k == gem`일 때만 1. 나머지는 위·왼쪽의 `k - gem` 상태를 더한다.
- `dp[R-1][C-1][K]` 출력. 시간·공간 O(R·C·K).

(3) 스스로 다시 짤 때 생각 순서

- "정확히 K개"라는 조건이 붙으면 경로 수만으로는 부족하니 조건 값을 상태에 넣는다.
- 보석 칸에 들어올 때 인덱스가 `k - 1`로 밀린다는 점과 `k < gem`인 불가 상태를 먼저 처리한다 — 이 검사를 빼면 `dp[...][−1]`이 되어 표 바깥 메모리를 읽는다.
- **C++ 포인트**: 경로 수 표는 `long long`으로 둔다. 15x15에서는 최대 경로 수가 C(28,14) ≈ 4,011만이라 `int`로도 되지만, 격자가 20x20만 돼도 C(38,19) ≈ 172억으로 `int`를 훌쩍 넘는다. 격자 경로 수는 격자 크기에 지수적으로 커지므로 처음부터 `long long`이 안전하다.
- 예제 2(가운데 벽으로 두 경로만 남고 각각 보석 2개)와 1x1 보석 칸 `K = 0`(0)으로 검산한다.
```

**13) 가치 있는 회의 고르기** · Hard

- **요구사항**: 회의 `n`개가 시작 시각, 끝 시각, 가치로 주어진다. 시간이 겹치지 않게(한 회의의 끝 시각과 다른 회의의 시작 시각이 같으면 겹치지 않음) 회의들을 골라 **가치 합**을 최대로 하라. 개수가 아니라 가치 합이므로 "끝나는 시각 순 그리디"는 틀릴 수 있다.
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 200), 이후 `n`줄에 `시작 끝 가치`(0 ≤ 시작 < 끝 ≤ 10000, 1 ≤ 가치 ≤ 1000).
- **출력**: 최대 가치 합.
- **예제**: `3 / 1 3 5 / 2 5 20 / 4 6 5` → `20` · `2 / 1 2 3 / 2 3 4` → `7`
- **셀프체크**: 끝 시각 순으로 정렬한 뒤 `dp[i]` = "앞 i개 회의만 고려한 최대 가치"로 두고, i번째 회의를 "안 고름(`dp[i-1]`)" vs "고름(가치 + i번째 시작 전에 끝나는 마지막 회의까지의 `dp`)"으로 나눴는가? 정렬 키를 `(끝, 시작, 가치)` 순서로 두면 `tuple`의 기본 비교가 그대로 쓰인다. 예제 1에서 그리디(끝 시각 순 최대 개수)는 (1,3)+(4,6) = 10을 고르지만 정답은 (2,5) 하나로 20임을 확인하라. n이 작으므로 "시작 전에 끝나는 마지막 회의"는 뒤에서부터 선형 탐색해도 된다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<tuple<int, int, int>> ivs(n);   // (끝, 시작, 가치) 순서로 담아 기본 비교 활용
    for (int i = 0; i < n; i++) {
        int s, e, v;
        cin >> s >> e >> v;
        ivs[i] = make_tuple(e, s, v);
    }
    sort(ivs.begin(), ivs.end());          // 끝 시각 오름차순

    vector<int> dp(n + 1, 0);              // dp[i] = 앞 i 개 회의에서의 최대 가치
    for (int i = 1; i <= n; i++) {
        int s = get<1>(ivs[i - 1]);        // 시작 시각
        int v = get<2>(ivs[i - 1]);        // 가치
        dp[i] = dp[i - 1];                 // i 번째 회의를 안 고름
        int j = i - 1;                     // s 이전에 끝나는 마지막 회의 찾기
        while (j > 0 && get<0>(ivs[j - 1]) > s) j--;
        if (dp[j] + v > dp[i]) dp[i] = dp[j] + v;   // i 번째 회의를 고름
    }
    cout << dp[n] << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 회의실 배정(개수 최대)은 끝 시각 그리디로 풀리지만, 가치가 붙으면 "짧고 많은 회의"보다 "길고 비싼 회의 하나"가 나을 수 있어 그리디가 깨진다. 이런 경우 선택/비선택을 모두 비교하는 DP가 필요하다.
- 끝 시각 순으로 정렬하면 `dp[i]` = 앞 i개만 고려한 최대 가치가 잘 정의된다. i번째를 고르면 그 시작 시각 이전에 끝나는 회의들까지의 답 `dp[j]`에 가치를 더하고, 안 고르면 `dp[i-1]`. 둘 중 최대.
- 채우는 순서: 정렬된 순서대로 i를 1부터 n까지. `dp[j]`(j < i)와 `dp[i-1]`이 항상 먼저 준비된다.

(2) 코드 단계별

- 회의를 `tuple<int,int,int>`에 `(끝, 시작, 가치)` 순서로 담는다. `tuple`의 `<`는 앞 원소부터 차례로 비교하므로 `sort` 한 줄이면 끝 시각 오름차순이 된다(원소를 꺼낼 때는 `get<0>`, `get<1>`, `get<2>`).
- `dp[0] = 0`. `i`마다 먼저 `dp[i] = dp[i-1]`(안 고름).
- `j`를 `i-1`에서 시작해 `ivs[j-1]`의 끝 시각이 시작 `s`보다 크면 하나씩 줄여, 겹치지 않는 마지막 회의 인덱스를 찾는다(끝 = 시작 접점 허용이므로 부등호는 `>`).
- `dp[j] + v`가 더 크면 갱신. 마지막 `dp[n]` 출력. 시간 O(n^2)(n이 작아 충분).

(3) 스스로 다시 짤 때 생각 순서

- "개수"가 아니라 "가치 합"이면 그리디 반례부터 만들어 보고 DP로 전환한다.
- 끝 시각 정렬 → "앞 i개" 상태 → 고름/안 고름 두 전이의 뼈대를 세운다.
- **C++ 포인트**: 파이썬은 `ivs.sort()` 한 번으로 튜플이 사전순 정렬되는데, C++도 `tuple`/`pair`라면 똑같이 동작한다. 다만 `sort`는 **안정 정렬이 아니므로** 같은 튜플이 아닌 이상 동점 순서를 값에 기대면 안 된다 — 이 문제는 비교에 세 원소가 모두 들어가 동점이면 완전히 같은 회의이므로 안전하다.
- 접점(끝 = 시작) 허용 조건을 부등호에 정확히 반영하고, 회의 하나뿐인 경우와 긴 회의 하나가 최적인 경우로 검산한다.
```

**14) 팰린드롬 부분 문자열의 개수** · Hard

- **요구사항**: 문자열 `S`의 연속 부분 문자열 중 팰린드롬(앞뒤가 같은 문자열)인 것의 개수를 구하라. 시작 위치나 끝 위치가 다르면 내용이 같아도 서로 다른 것으로 센다(`aaa`의 `a` 세 개는 각각 센다).
- **입력**: 한 줄에 `S`(소문자, 길이 1 이상 300 이하).
- **출력**: 팰린드롬 부분 문자열의 개수.
- **예제**: `aaa` → `6` · `abcb` → `5`
- **셀프체크**: 구간 DP `dp[i][j]` = "S[i..j]가 팰린드롬인가"를 두고, `S[i] == S[j]`이면서 (길이가 2 이하이거나 안쪽 `dp[i+1][j-1]`이 참)일 때 참으로 정했는가? 안쪽 구간이 먼저 계산되어 있어야 하므로 **길이가 짧은 구간부터** 채우는 순서가 필수다(i를 0부터 돌리면 안쪽이 아직 비어 있다). 표는 `vector<vector<char>>`로 두는 편이 낫다 — `vector<vector<bool>>`은 비트로 압축된 특수 구현이라 원소 참조가 일반 `bool&`가 아니다. 모든 부분 문자열을 뒤집어 비교하는 O(n^3)과 비교해 이 방법이 O(n^2)임을 이해했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    string s;
    cin >> s;
    int n = (int)s.size();

    // dp[i][j] = s[i..j] 가 팰린드롬인가. vector<bool> 대신 char 로 둔다.
    vector<vector<char>> dp(n, vector<char>(n, 0));
    long long cnt = 0;

    for (int length = 1; length <= n; length++) {      // 짧은 구간부터
        for (int i = 0; i + length - 1 < n; i++) {
            int j = i + length - 1;
            if (s[i] != s[j]) continue;
            if (length <= 2 || dp[i + 1][j - 1]) {     // 길이 1,2 는 안쪽을 볼 필요 없음
                dp[i][j] = 1;
                cnt++;
            }
        }
    }
    cout << cnt << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 구간 `[i, j]`가 팰린드롬이려면 양 끝이 같고 안쪽 `[i+1, j-1]`도 팰린드롬이어야 한다. 안쪽은 더 짧은 구간이므로 "짧은 구간의 답으로 긴 구간의 답을 만드는" 구간 DP다: `dp[i][j] = (s[i] == s[j]) && (길이 <= 2 || dp[i+1][j-1])`.
- 길이 1은 항상 팰린드롬, 길이 2는 두 글자만 같으면 되므로 안쪽을 볼 필요가 없다(기저).
- 채우는 순서가 이 문제의 전부다 — **길이를 바깥 루프**로 두어야 안쪽 구간이 항상 먼저 완성된다. i를 0부터 도는 흔한 격자 순서로 채우면 `dp[i+1][j-1]`이 아직 0이라 조용히 틀린다.
- 참인 칸의 개수가 답이다. 상태 O(n^2), 전이 O(1)이라 O(n^2).

(2) 코드 단계별

- `n x n` 표를 0으로 만든다.
- `length`를 1부터 `n`까지 바깥 루프로, 그 길이의 모든 시작 `i`(끝 `j = i + length - 1`)를 안쪽 루프로 돈다. 루프 조건을 `i + length - 1 < n`으로 쓰면 `j`가 범위를 벗어나지 않는다.
- 양 끝이 다르면 건너뛰고, 같으면 길이 2 이하이거나 `dp[i+1][j-1]`이 참일 때 `dp[i][j] = 1`, `cnt++`.
- `cnt` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "부분 구간의 성질이 안쪽 구간에 의존"하면 구간 DP를 떠올리고, 채우는 순서를 길이 순으로 잡는다.
- 안쪽이 없는 길이 1·2를 기저로 분리한다.
- **C++ 함정**: `vector<vector<bool>>`은 표준이 비트 단위로 압축하도록 특수화한 컨테이너라 `dp[i][j]`가 진짜 `bool&`가 아닌 프록시 객체를 돌려준다. 대부분의 경우 동작하지만 `auto &x = dp[i][j];`나 `bool *p = &dp[i][j];`가 컴파일되지 않고 성능도 예측하기 어렵다. 불리언 표는 `vector<vector<char>>`(또는 `vector<char>` 1차원)로 두는 편이 안전하다.
- `aaa`(1+1+1+1+1+1 = 6), 글자가 모두 다른 문자열(길이 n만큼), 한 글자(1)로 검산한다.
```

> 개요: 데이터를 "연속된 한 덩어리(배열)"로 담을지 "노드를 링크로 잇는 사슬(연결 리스트)"로 담을지에 따라 접근/삽입/삭제 비용이 달라진다. 이 챕터에서는 배열·동적 배열의 원리와 상수시간 인덱싱, 단일·이중·원형 연결 리스트의 포인터 조작, 그리고 순회를 추상화하는 Iterator를 배우고 각 연산의 시간·공간 복잡도를 손에 익힌다.

## L1. 배열

**개념**

- 배열(array)은 같은 크기의 원소를 메모리에 "연속"으로 배치한 자료구조다. 시작 주소에서 `index × 원소크기`만큼 더한 위치를 바로 계산할 수 있어, 몇 번째 원소든 O(1)에 읽고 쓴다(임의 접근, random access).
- 대신 크기가 고정이라는 게 원리상 핵심이다. 중간에 원소를 끼워 넣거나 빼려면, 뒤쪽 원소들을 한 칸씩 밀거나 당겨야 하므로 최악 O(n)이 든다.
- C++의 `std::vector`는 사실 뒤에서 배울 "동적 배열"이지만, 인덱싱·순회 관점에서는 배열처럼 생각하면 된다. 진짜 고정폭 배열이 필요하면 C 스타일 `int arr[n]`이나 `std::array<int, N>`, 혹은 미리 `vector<int> arr(n, 0)`으로 잡아두는 방식을 쓴다.
- "배열 문제"의 본질은 대개 인덱스를 정확히 다루는 것이다: 경계(0번째, n-1번째), 오프셋, 앞으로/뒤로 밀기.

```cpp
int n = 5;
vector<int> arr(n, 0);      // 크기 n을 미리 확보 (연속된 칸)
arr[2] = 7;                 // 인덱스로 O(1) 접근/수정
// 인덱스 i 자리에 값 x 삽입하고 뒤로 밀기 (O(n))
void insert_at(vector<int>& a, int i, int x) {
    a.push_back(0);                         // 칸 하나 늘림
    for (int j = (int)a.size() - 1; j > i; j--)
        a[j] = a[j - 1];                    // 뒤에서부터 한 칸씩 밀기
    a[i] = x;
}
```

**접근 전략**

- 핵심 아이디어: "어디에 무엇이 있는지 인덱스로 즉시 안다"를 활용한다. 값을 찾는 문제라면 값→인덱스 매핑, 위치 기반 문제라면 오프셋 계산을 먼저 설계한다.
- 전형적 절차: (1) 필요한 크기를 파악해 미리 확보할지 결정 → (2) 접근/수정은 인덱스로, 삽입/삭제는 "밀기"의 방향(앞→뒤 or 뒤→앞)을 정한다 → (3) 경계 인덱스(0, n-1)를 따로 점검한다. 뒤로 미는 삽입은 반드시 "뒤에서부터" 복사해야 값이 안 덮인다.
- 언제 쓰나: 순서가 있고 인덱스로 자주 접근하며, 중간 삽입/삭제가 드물 때. 반대로 중간 삽입/삭제가 잦으면 연결 리스트(L3~)를 고려한다.
- 복잡도: 접근/수정 O(1), 중간 삽입/삭제 O(n), 공간 O(n). 흔한 실수: 밀기 방향을 반대로 해서 값이 덮이는 것, `n-1` 대신 `n`을 써서 나는 인덱스 초과.

**문제**

**1) K칸 회전** · Easy

- **요구사항**: 길이 `n`인 정수 배열을 오른쪽으로 `k`칸 순환 이동시킨 결과를 출력하라(맨 뒤 원소가 앞으로 돌아온다). STL `rotate`를 쓰지 말고 새 배열에 인덱스 계산으로 배치하라.
- **입력**: 첫 줄에 `n k`(1 ≤ n ≤ 100, 0 ≤ k ≤ 1000). 둘째 줄에 정수 `n`개.
- **출력**: 회전된 배열을 공백으로 구분해 한 줄.
- **예제**: `5 2 / 1 2 3 4 5` → `4 5 1 2 3` · `4 6 / 10 20 30 40` → `30 40 10 20`
- **셀프체크**: `k`가 `n`보다 클 때 `k % n`으로 줄였는가? `k=0`, `k`가 `n`의 배수일 때 원본 그대로 나오는가? 새 인덱스는 `(i + k) % n`으로 정확한가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    int n, k;
    cin >> n >> k;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    k %= n;
    vector<int> res(n);
    for (int i = 0; i < n; i++) res[(i + k) % n] = arr[i];
    for (int i = 0; i < n; i++) {
        cout << res[i];
        if (i + 1 < n) cout << ' ';
    }
    cout << '\n';
    return 0;
}
@@TESTS
--IN
5 2
1 2 3 4 5
--OUT
4 5 1 2 3
--IN
3 1
7 8 9
--OUT
9 7 8
@@EXPL
(1) 접근·핵심 아이디어

- 오른쪽으로 `k`칸 회전하면 원래 `i`번 원소가 새 배열의 `(i + k) % n` 자리로 간다. 이 한 줄 공식이 전부다.
- `k`가 `n`보다 클 수 있으니 먼저 `k %= n`으로 줄인다. 그러면 `k=0`이나 `n`의 배수일 때 원본 그대로 나온다.

(2) 코드 단계별

- 입력을 읽어 `vector<int> arr`를 만들고 `k %= n`으로 정규화한다.
- 새 배열 `res`를 만들어 각 `i`마다 `res[(i + k) % n] = arr[i]`로 제자리에 배치한다(STL 회전 없이 인덱스 계산만).
- 공백으로 이어 한 줄 출력.

(3) 스스로 다시 짤 때 생각 순서

- "회전은 각 원소의 목적지 인덱스를 계산하는 문제"로 바꿔 생각한다 → 목적지는 `(i + k) % n`.
- `k`를 `% n`으로 줄이는 전처리만 잊지 않으면 경계(k=0, k=배수, k>n)가 자동으로 맞는다.
```

**2) 중복 없는 삽입 위치** · Medium

- **요구사항**: 오름차순 정렬된 배열에 값 `x`를 삽입해도 정렬이 유지되게 하는 위치(인덱스)를 찾고, 그 자리에 실제로 삽입한 배열을 출력하라. 단 `x`가 이미 있으면 삽입하지 않고 그대로 둔다.
- **입력**: 첫 줄에 `n`과 `x`. 둘째 줄에 오름차순 정수 `n`개(중복 없음).
- **출력**: 첫 줄에 삽입 위치 인덱스(삽입 안 하면 기존 x의 인덱스), 둘째 줄에 결과 배열.
- **예제**: `4 25 / 10 20 30 40` → `2` / `10 20 25 30 40` · `4 20 / 10 20 30 40` → `1` / `10 20 30 40`
- **셀프체크**: 삽입은 "뒤에서부터 밀기"로 O(n)에 했는가? 맨 앞(`x`가 최솟값), 맨 뒤(`x`가 최댓값) 경계가 맞는가? 이미 존재하는 값 처리로 분기했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    int n, x;
    cin >> n >> x;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    int pos = n;
    for (int i = 0; i < n; i++) {
        if (arr[i] >= x) { pos = i; break; }
    }
    if (pos < n && arr[pos] == x) {
        cout << pos << '\n';
        for (int i = 0; i < n; i++) { cout << arr[i]; if (i + 1 < n) cout << ' '; }
        cout << '\n';
    } else {
        arr.push_back(0);
        for (int j = (int)arr.size() - 1; j > pos; j--) arr[j] = arr[j - 1];
        arr[pos] = x;
        cout << pos << '\n';
        for (int i = 0; i < (int)arr.size(); i++) { cout << arr[i]; if (i + 1 < (int)arr.size()) cout << ' '; }
        cout << '\n';
    }
    return 0;
}
@@TESTS
--IN
4 25
10 20 30 40
--OUT
2
10 20 25 30 40
--IN
4 5
10 20 30 40
--OUT
0
5 10 20 30 40
@@EXPL
(1) 접근·핵심 아이디어

- 정렬을 유지하려면 `x`가 들어갈 자리는 "처음으로 `x` 이상인 원소의 위치"다. 그 위치를 왼쪽부터 훑어 찾는다.
- 그 자리에 이미 `x`가 있으면(중복) 삽입하지 않고 위치와 원본을 그대로 출력한다.

(2) 코드 단계별

- `pos`를 `n`(맨 뒤)으로 시작해, `arr[i] >= x`인 첫 `i`를 찾으면 `pos = i`로 갱신하고 멈춘다.
- `arr[pos] == x`이면 이미 존재 → 그 인덱스와 원본을 출력.
- 아니면 `push_back`으로 한 칸 늘리고 뒤에서부터 밀어 `pos` 자리를 비운 뒤 `x`를 넣는다(O(n)). 밀기는 반드시 뒤에서부터 해야 값이 안 덮인다.

(3) 스스로 다시 짤 때 생각 순서

- "삽입 위치 = 처음으로 x 이상인 인덱스"라는 정의를 먼저 세운다. 없으면 맨 뒤(n).
- 중복 분기를 그 정의 위에 얹고(그 자리 값이 x면 삽입 생략), 실제 삽입은 뒤→앞 밀기로 처리한다.
```

**3) 최대 부분합 구간** · Medium

- **요구사항**: 정수 배열에서 연속된 부분 배열의 합 중 최댓값과, 그 구간의 시작·끝 인덱스(0-based, 여러 개면 가장 앞·짧은 것)를 구하라.
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 1000). 둘째 줄에 정수 `n`개(음수 가능).
- **출력**: `최대합 시작인덱스 끝인덱스`.
- **예제**: `5 / -2 3 -1 4 -5` → `6 1 3` · `3 / -1 -2 -3` → `-1 0 0`
- **셀프체크**: 모두 음수일 때 "빈 구간(합 0)"이 아니라 원소 하나를 답으로 내는가? 현재 합이 음수가 되면 시작을 새로 잡는 아이디어(누적합/카데인)를 인덱스 추적과 함께 구현했는가? 복잡도가 O(n²) 이내인가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    int n;
    cin >> n;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    long long best = arr[0];
    int best_l = 0, best_r = 0;
    long long cur = arr[0];
    int start = 0;
    for (int i = 1; i < n; i++) {
        if (cur < 0) { cur = arr[i]; start = i; }
        else cur += arr[i];
        if (cur > best) { best = cur; best_l = start; best_r = i; }
    }
    cout << best << ' ' << best_l << ' ' << best_r << '\n';
    return 0;
}
@@TESTS
--IN
5
-2 3 -1 4 -5
--OUT
6 1 3
--IN
6
1 -2 3 -1 4 -1
--OUT
6 2 4
@@EXPL
(1) 접근·핵심 아이디어

- 카데인(Kadane) 알고리즘: 왼쪽부터 현재 구간합 `cur`를 굴리되, `cur`가 음수가 되면 지금까지의 앞부분은 버리고 현재 원소에서 새로 시작한다(구간 시작 `start`도 그때 갱신).
- 최댓값을 "엄격히 클 때(`> best`)만" 갱신하면, 같은 합이 여러 번 나와도 가장 앞·가장 짧은 구간이 유지된다.

(2) 코드 단계별

- 첫 원소로 `best`, `cur`, `start`를 초기화한다(모두 음수여도 빈 구간이 아니라 원소 하나가 답이 됨). 합의 오버플로 여유를 위해 `best`/`cur`는 `long long`으로 둔다.
- `i=1..n-1`: `cur < 0`이면 `cur = arr[i]`, `start = i`로 새 시작. 아니면 `cur += arr[i]`.
- 갱신 후 `cur > best`이면 `best`와 구간 `[start, i]`를 기록한다.
- 마지막에 `best 시작 끝`을 출력. 전체 O(n).

(3) 스스로 다시 짤 때 생각 순서

- "누적합이 음수가 되면 계속 들고 가는 게 손해"라는 카데인의 직관을 먼저 잡는다 → 그 순간 start를 새로 찍는다.
- 인덱스를 답으로 내야 하므로 `cur`와 함께 `start`, `best_l/best_r`를 나란히 추적한다. 동률에서 앞·짧은 것을 원하면 갱신 조건을 `>`(엄격)로 둔다.
```

## L2. Dynamic Array

**개념**

- 동적 배열(dynamic array)은 "고정 크기 배열"의 한계를 감춰, 원소를 계속 뒤에 붙일 수 있게 만든 구조다. C++ `std::vector`, 자바 `ArrayList`가 이것이다.
- 원리: 실제로는 여유 공간(capacity)이 있는 배열을 들고 있다가, 다 차면 보통 2배(구현에 따라 1.5배) 크기의 새 배열을 만들어 전부 복사(resize)한 뒤 거기에 이어 담는다. 크기(size)와 용량(capacity)은 다른 값이다.
- 이 "가끔 일어나는 O(n) 복사"를 여러 번의 `push_back`에 나눠 평균 내면, `push_back` 한 번의 **상환(amortized) 비용은 O(1)**이 된다. 이게 동적 배열의 핵심 성질이다.
- 끝(뒤)에서의 추가/삭제는 O(1)로 싸지만, 앞이나 중간은 여전히 밀기 때문에 O(n)이다. 그래서 "앞에서 자주 넣고 뺀다"면 동적 배열이 아니라 덱(Ch5)이나 연결 리스트가 낫다.

```cpp
struct DynArray {
    int cap = 1, sz = 0;
    int* data = new int[cap];
    void push_back(int x) {
        if (sz == cap) {                 // 꽉 차면 2배로 확장
            cap *= 2;
            int* nd = new int[cap];
            for (int i = 0; i < sz; i++)  // 전체 복사 O(n)
                nd[i] = data[i];
            delete[] data;
            data = nd;
        }
        data[sz++] = x;                  // 대개는 O(1)
    }
};
```

**접근 전략**

- 핵심 아이디어: "뒤에서 붙이고 뒤에서 뺀다"를 O(1)로 활용하고, 확장 복사는 어쩌다 한 번임을 상환 분석으로 안심한다. size와 capacity를 헷갈리지 말 것.
- 전형적 절차: (1) 데이터를 계속 모으는 상황이면 `vector::push_back`으로 뒤에 쌓기 → (2) 확장 비용이 걱정되면 "총 복사 횟수는 2n 이하"라는 상환 논리로 O(n)임을 확인 → (3) 앞/중간 조작이 필요하면 자료구조를 바꾼다.
- 언제 쓰나: 원소 개수를 미리 모를 때, 뒤로만 늘려가며 임의 접근이 필요할 때. `pop_back()`(뒤 제거)도 O(1)이라 스택으로도 쓴다(Ch5 예고).
- 복잡도: push_back/pop_back 뒤쪽 상환 O(1), 접근 O(1), 앞/중간 삽입·삭제 O(n), 공간 O(n)(용량 여유 포함). 흔한 실수: `vector::erase(begin())`(앞 제거)은 O(n)인데 무심코 반복문에서 써서 O(n²)이 되는 것.

**문제**

**1) 확장 횟수 세기** · Easy

- **요구사항**: 초기 용량 1, 가득 차면 2배로 커지는 동적 배열에 값을 `m`개 push_back할 때, "확장(재할당)이 몇 번 일어나는지"와 최종 용량을 구하라.
- **입력**: 한 줄에 정수 `m`(1 ≤ m ≤ 10^9).
- **출력**: `확장횟수 최종용량`.
- **예제**: `5` → `3 8` · `1` → `0 1`
- **셀프체크**: 용량이 1→2→4→8… 로 커지며, `m`개를 담으려면 용량 ≥ m이어야 함을 반영했는가? `m=1`이면 초기 용량 1로 충분해 확장 0번인가? 큰 `m`도 반복(로그 횟수)으로 빠르게 처리되는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    long long m;
    cin >> m;
    long long cap = 1;
    int expands = 0;
    while (cap < m) { cap *= 2; expands++; }
    cout << expands << ' ' << cap << '\n';
    return 0;
}
@@TESTS
--IN
5
--OUT
3 8
--IN
1
--OUT
0 1
@@EXPL
(1) 접근·핵심 아이디어

- 용량은 1→2→4→8…로 2배씩 커지고, `m`개를 담으려면 "용량 ≥ m"이 되어야 한다. 그때까지 몇 번 곱했는지가 확장 횟수다.
- 원소를 하나씩 세지 않고 용량만 2배씩 키우므로 반복은 로그(log m) 번뿐이라 `m`이 10^9이어도 즉시 끝난다. 용량이 2배로 커지다 int 범위를 넘길 수 있으니 `cap`은 `long long`으로 둔다.

(2) 코드 단계별

- `cap=1`, `expands=0`에서 시작한다.
- `cap < m`인 동안 `cap *= 2`, `expands++`을 반복한다.
- 루프가 끝나면 `cap >= m`이 되어 있고, `expands`가 확장 횟수다. 둘을 출력.

(3) 스스로 다시 짤 때 생각 순서

- "언제까지 늘리나 = 용량이 m 이상이 될 때까지"라는 종료 조건을 먼저 정한다.
- `m=1`이면 처음부터 `cap=1 >= 1`이라 루프가 한 번도 안 돌아 확장 0번이 자연히 나온다(경계 확인).
```

**2) 뒤에서만 다루는 편집기** · Medium

- **요구사항**: 빈 동적 배열에서 시작해 명령을 처리하라. `push x`(뒤에 추가), `pop`(뒤 제거, 비었으면 무시), `get i`(i번째 값 출력), `top`(마지막 값 출력, 비었으면 `empty`). 모든 명령은 앞/중간을 건드리지 않아 O(1)로 처리되어야 한다.
- **입력**: 첫 줄에 명령 수 `q`. 다음 `q`줄에 명령.
- **출력**: `get`/`top`마다 결과를 한 줄씩.
- **예제**: `push 3 / push 5 / top / pop / top / get 0` → `5` / `3` / `3`
- **셀프체크**: `pop`이 `vector::pop_back()`(뒤, O(1))인가 `erase(begin())`(앞, O(n))인가? 빈 상태의 `pop`/`top` 경계를 처리했는가? `get i`가 범위를 벗어나는 경우는 입력에서 없다고 가정해도 되지만 top의 empty는 반드시 처리했는가?

```runner
- `erase(begin())`(앞 제거, O(n))을 쓰지 않는 게 핵심—문제의 의도가 모든 연산 O(1)이다.

(3) 스스로 다시 짤 때 생각 순서

- 빈 상태의 `pop`(무시)과 `top`(empty 출력) 두 경계만 분기하면 나머지는 인덱스 접근으로 끝난다.
```

**3) 상환 비용 시뮬레이션** · Hard

- **요구사항**: 위와 같은 2배 확장 규칙에서, `n`개를 순서대로 push_back할 때 발생한 "총 원소 복사 횟수"의 누계를 구하라(각 확장 때 기존 size만큼 복사). 그리고 이 값이 `2n`을 넘지 않음을 스스로 확인하라(출력은 총 복사 횟수만).
- **입력**: 한 줄에 `n`(1 ≤ n ≤ 10^9).
- **출력**: 총 복사 횟수.
- **예제**: `5` → `7` · `4` → `3`
- **셀프체크**: `n=5`에서 확장은 size가 1,2,4일 때 일어나 복사가 1+2+4=7인가? 결과가 항상 `2n` 미만이어서 push_back 상환 O(1)이 성립함을 이해했는가? `n`이 커도 로그 번의 확장만 계산하는가(원소마다 세지 않기)?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    long long n;
    cin >> n;
    long long cap = 1, copies = 0;
    while (cap < n) { copies += cap; cap *= 2; }
    cout << copies << '\n';
    return 0;
}
@@TESTS
--IN

--OUT

--IN
4
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 확장은 배열이 "가득 찬 순간"(size == cap)에 일어나고, 그때 기존 `cap`개를 새 배열로 복사한다. 확장 후 용량은 2배가 된다.
- 그래서 복사 총량은 확장이 일어나는 매 시점의 용량(1, 2, 4, …)을 더한 값이다. 원소를 하나씩 세지 않고 용량만 2배씩 키우며 더하면 로그 번에 끝난다. 누계가 int를 넘을 수 있으니 `copies`는 `long long`.

(2) 코드 단계별

- `cap=1`, `copies=0`에서 시작한다.
- `cap < n`인 동안: 이번 확장에서 `cap`개를 복사하므로 `copies += cap`, 그리고 `cap *= 2`.
- 루프 종료 시 `copies`가 총 복사 횟수다. `n=5`면 1+2+4=7, `n=4`면 1+2=3.

(3) 스스로 다시 짤 때 생각 순서

- "복사량 = 확장 시점마다의 용량들의 합"이라는 관찰을 먼저 한다 → 1+2+4+…는 등비수열이라 2n 미만(상환 O(1)의 근거).
- 그 합을 `while (cap < n)`으로 용량을 2배씩 키우며 누적하면 원소마다 세지 않고도 정확히 구해진다.
```

## L3. 단일 연결 리스트

**개념**

- 단일 연결 리스트(singly linked list)는 각 원소를 "노드"로 만들어, 노드마다 값(val)과 "다음 노드로 가는 링크(next)"를 갖는 사슬 구조다. 배열처럼 연속 메모리가 아니라, 링크를 따라가야 다음 원소에 도달한다.
- 그래서 임의 접근이 안 된다: `i`번째를 보려면 head부터 `i`번 링크를 따라가야 해 O(n). 대신 어떤 노드의 위치(포인터)만 알면, 그 앞/뒤에 노드를 꽂거나 빼는 것은 링크 몇 개만 바꿔 O(1)이다.
- 항상 시작점(head)을 들고 다니며, 마지막 노드의 next는 `nullptr`(끝 표시)이다. 삽입·삭제의 정석은 "끊고 다시 잇는" 링크 재배선이다.
- C++ 표준에는 `std::forward_list`(단일)·`std::list`(이중)가 있지만, 포인터 조작 원리를 익히려면 `struct Node`로 직접 구현하는 게 중요하다(양끝 O(1)이 필요하면 실무에선 `list`/`deque`를 쓴다).

```cpp
struct Node {
    int val;
    Node* next;
    Node(int v) : val(v), next(nullptr) {}
};

// head 앞에 삽입 (O(1))
Node* push_front(Node* head, int x) {
    Node* node = new Node(x);
    node->next = head;
    return node;                       // 새 head 반환
}

// 값이 target인 첫 노드 삭제 (O(n))
Node* remove(Node* head, int target) {
    Node dummy(0); dummy.next = head;      // 더미로 head 삭제도 통일
    Node* cur = &dummy;
    while (cur->next) {
        if (cur->next->val == target) {
            cur->next = cur->next->next;   // 링크 건너뛰기 = 삭제
            break;
        }
        cur = cur->next;
    }
    return dummy.next;
}
```

**접근 전략**

- 핵심 아이디어: "밀기"가 아니라 "링크 재배선"으로 삽입/삭제한다. 바꿔야 할 노드의 **직전 노드**를 손에 쥐는 게 관건이라, cur와 prev(또는 dummy head) 두 포인터를 굴린다.
- 전형적 절차: (1) 더미(sentinel) 헤드를 두면 "맨 앞 삭제"와 "중간 삭제"를 한 코드로 처리해 실수가 준다 → (2) 삽입은 `node->next = cur->next; cur->next = node;` 순서를 지킨다(순서 바꾸면 뒤가 유실) → (3) 삭제는 `prev->next = cur->next`로 건너뛴다.
- 언제 쓰나: 앞쪽/중간 삽입·삭제가 잦고 임의 접근은 드물 때, 원소 개수가 유동적일 때. 뒤집기·병합처럼 링크만 바꾸면 되는 문제에 강하다.
- 복잡도: 접근/탐색 O(n), 위치를 알 때 삽입/삭제 O(1), 공간 O(n). 흔한 실수: 재배선 순서를 틀려 리스트가 끊기거나 순환이 생기는 것, 마지막 노드 next(`nullptr`) 경계 누락.

**문제**

**1) 리스트 뒤집기** · Easy

- **요구사항**: `n`개의 정수를 순서대로 head 앞에 삽입(push_front)해 만든 연결 리스트를, head부터 출력하라. 결과가 입력의 역순이 됨을 확인하고, 이어서 "링크를 뒤집는" 함수를 구현해 다시 원래 순서로 출력하라.
- **입력**: 첫 줄에 `n`. 둘째 줄에 정수 `n`개.
- **출력**: 첫 줄에 push_front로 만든 리스트, 둘째 줄에 그것을 뒤집은 리스트(각각 공백 구분).
- **예제**: `5 / 1 2 3 4 5` → `5 4 3 2 1` / `1 2 3 4 5` · `3 / 7 8 9` → `9 8 7` / `7 8 9`
- **셀프체크**: 뒤집기를 prev/cur/next 세 포인터로 O(n)·O(1)공간에 했는가? 마지막에 head를 새 시작점으로 갱신했는가? 빈 리스트/원소 1개 경계에서 죽지 않는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
struct Node { int val; Node* next; Node(int v): val(v), next(nullptr) {} };
int main() {
    int n;
    cin >> n;
    vector<int> vals(n);
    for (int i = 0; i < n; i++) cin >> vals[i];
    Node* head = nullptr;
    for (int v : vals) {            // push_front: 입력 역순으로 쌓임
        Node* node = new Node(v);
        node->next = head;
        head = node;
    }
    bool first = true;
    for (Node* cur = head; cur; cur = cur->next) {
        if (!first) cout << ' ';
        cout << cur->val; first = false;
    }
    cout << '\n';
    Node* prev = nullptr;          // 링크 뒤집기 (prev/cur/next 세 포인터)
    Node* cur = head;
    while (cur) {
        Node* nxt = cur->next;
        cur->next = prev;
        prev = cur;
        cur = nxt;
    }
    head = prev;
    first = true;
    for (Node* c = head; c; c = c->next) {
        if (!first) cout << ' ';
        cout << c->val; first = false;
    }
    cout << '\n';
    return 0;
}
@@TESTS
--IN

1 2 3 4 5
--OUT
5 4 3 2 1
1 2 3 4 5
--IN
3
7 8 9
--OUT
9 8 7
7 8 9
@@EXPL
(1) 접근·핵심 아이디어

- `push_front`(새 노드를 head 앞에 붙이기)를 반복하면 리스트는 입력의 역순이 된다. 그래서 첫 줄 출력은 입력을 거꾸로 뒤집은 모양이다.
- 이어서 링크 방향을 뒤집으면 다시 원래 입력 순서가 된다. 뒤집기는 prev/cur/next 세 포인터로 O(n)·추가공간 O(1)에 한다.

(2) 코드 단계별

- 입력값마다 `node->next = head; head = node;`로 앞에 삽입 → 첫 순회 출력은 역순.
- 뒤집기 루프: `nxt`에 다음 노드를 백업하고 `cur->next = prev`로 화살표를 반대로, 그다음 `prev, cur`를 한 칸 전진. 끝나면 `head = prev`가 새 시작점.
- 두 번째 순회로 뒤집힌 리스트(=원래 입력 순서)를 출력.

(3) 스스로 다시 짤 때 생각 순서

- "링크를 반대로 걸려면 다음 노드를 먼저 백업해야 한다"가 핵심 → `nxt = cur->next`를 제일 먼저.
- 네 줄(`nxt=...`, `cur->next=prev`, `prev=cur`, `cur=nxt`)의 순서만 지키면 빈 리스트/원소 1개에서도 자연히 안전하다(루프가 안 돌거나 한 번만 돎).
```

**2) 특정 값 모두 삭제** · Medium

- **요구사항**: 정수 연결 리스트에서 값이 `x`인 노드를 모두 삭제한 결과를 출력하라. 더미 헤드를 써서 맨 앞 노드가 `x`인 경우도 자연스럽게 처리하라.
- **입력**: 첫 줄에 `n`과 `x`. 둘째 줄에 정수 `n`개(입력 순서대로 뒤에 연결).
- **출력**: 삭제 후 리스트(공백 구분). 모두 삭제되면 `empty`.
- **예제**: `6 2 / 1 2 2 3 2 4` → `1 3 4` · `3 5 / 5 5 5` → `empty`
- **셀프체크**: 연속된 `x`도 빠짐없이 지워지는가(삭제 후 cur를 전진시키지 않아야 함)? 더미 헤드 덕에 맨 앞 삭제 분기를 없앴는가? 한 번의 순회(O(n))로 끝나는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
struct Node { int val; Node* next; Node(int v): val(v), next(nullptr) {} };
int main() {
    int n, x;
    cin >> n >> x;
    vector<int> vals(n);
    for (int i = 0; i < n; i++) cin >> vals[i];
    Node* head = nullptr; Node* tail = nullptr;
    for (int v : vals) {               // 뒤에 연결
        Node* node = new Node(v);
        if (!head) head = tail = node;
        else { tail->next = node; tail = node; }
    }
    Node dummy(0);
    dummy.next = head;
    Node* cur = &dummy;
    while (cur->next) {
        if (cur->next->val == x) cur->next = cur->next->next;   // 삭제, cur 전진 안 함
        else cur = cur->next;
    }
    head = dummy.next;
    if (!head) { cout << "empty" << '\n'; return 0; }
    bool first = true;
    for (Node* c = head; c; c = c->next) {
        if (!first) cout << ' ';
        cout << c->val; first = false;
    }
    cout << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 더미(sentinel) 헤드를 앞에 붙이면 "맨 앞 노드가 x"인 경우도 중간 삭제와 똑같이 처리된다—별도 분기가 사라진다.
- 삭제의 정석은 직전 노드에서 `cur->next = cur->next->next`로 링크를 건너뛰는 것이다.

(2) 코드 단계별

- 입력을 뒤에 이어 단일 연결 리스트를 만든다.
- `dummy`부터 시작해 `cur->next->val == x`면 그 노드를 건너뛰고(이때 cur를 전진하지 않아 연속된 x도 모두 지움), 아니면 cur를 한 칸 전진.
- 남은 값이 없으면 `empty`.

(3) 스스로 다시 짤 때 생각 순서

- "삭제하려면 직전 노드를 쥐어야 한다"는 원칙에서 더미 헤드 아이디어가 나온다.
- 삭제 시 cur를 전진시키지 않는다는 한 가지만 지키면 연속 중복도 한 번의 순회로 처리된다.
```

**3) 두 정렬 리스트 병합** · Hard

- **요구사항**: 각각 오름차순으로 정렬된 두 연결 리스트를 하나의 오름차순 연결 리스트로 병합해 출력하라. 새 노드를 만들지 말고 기존 노드의 링크만 재배선하라.
- **입력**: 첫 줄에 `a b`(두 리스트 길이). 둘째 줄에 첫 리스트 `a`개(오름차순), 셋째 줄에 둘째 리스트 `b`개(오름차순).
- **출력**: 병합된 리스트(공백 구분). 둘 다 비면 `empty`.
- **예제**: `3 3 / 1 3 5 / 2 4 6` → `1 2 3 4 5 6` · `2 3 / 1 4 / 2 3 5` → `1 2 3 4 5`
- **셀프체크**: 더미 헤드에 작은 쪽 노드를 이어 붙이는 투 포인터로 O(a+b)에 처리했는가? 한쪽이 먼저 소진되면 남은 쪽을 통째로 링크로 이었는가? 값이 같을 때(안정성) 처리가 일관적인가?

```runner
Node* build(const vector<int>& vals) {
    Node* head = nullptr; Node* tail = nullptr;
    for (int v : vals) {
        Node* node = new Node(v);
        if (!head) head = tail = node;
        else { tail->next = node; tail = node; }
    }
    return head;

int main() {
    int a, b;
    cin >> a >> b;

    for (int i = 0; i < b; i++) cin >> vb[i];

        else { tail->next = q; q = q->next; }

(3) 스스로 다시 짤 때 생각 순서

- "결과 꼬리(tail)에 작은 노드를 계속 매단다"는 골격을 먼저 세우고 더미로 시작점을 통일한다.
- 마지막에 남은 체인을 한 번에 잇는다는 것만 기억하면 루프가 O(a+b)로 끝난다.
```

## L4. Doubly-LinkedList

**개념**

- 이중 연결 리스트(doubly-linked list)는 각 노드가 next뿐 아니라 "이전 노드(prev)"도 가리키는 구조다. 양방향으로 이동할 수 있어, 어떤 노드를 손에 쥐면 그 노드 자체를 O(1)에 삭제할 수 있다(단일 리스트는 직전 노드가 필요했다).
- 보통 양끝에 더미 노드(head 센티넬, tail 센티넬)를 두면 "맨 앞/맨 뒤" 삽입·삭제가 경계 분기 없이 O(1)로 깔끔해진다.
- 삽입은 링크 4개(양쪽 노드의 next/prev), 삭제는 링크 2개를 바꾼다. prev가 있어서 앞으로도, 뒤로도 순회할 수 있는 게 단일 리스트와의 본질적 차이다.
- C++ 표준 `std::list`가 이중 연결 리스트로 구현되어 양끝·임의 위치 O(1) 삽입/삭제를 제공한다. 원리 학습은 직접 `struct Node`로, 실전은 `list`로 생각하면 된다.

```cpp
struct Node {
    int val;
    Node* prev;
    Node* next;
    Node(int v) : val(v), prev(nullptr), next(nullptr) {}
};

// a 바로 뒤에 x 삽입 (O(1))
void insert_after(Node* a, int x) {
    Node* node = new Node(x);
    Node* b = a->next;
    node->prev = a; node->next = b;
    a->next = node;
    if (b) b->prev = node;
}

void erase(Node* node) {                 // 노드 자체를 삭제 (O(1))
    node->prev->next = node->next;
    if (node->next) node->next->prev = node->prev;
}
```

**접근 전략**

- 핵심 아이디어: prev 링크 덕분에 "직전 노드를 다시 찾을 필요가 없다". 커서(현재 위치)를 들고 좌우로 움직이는 문제, 임의 노드 즉시 삭제 문제에 강하다.
- 전형적 절차: (1) head/tail 더미 센티넬을 만들어 빈 리스트도 노드 2개짜리로 시작 → (2) 삽입은 "양쪽 이웃을 먼저 확보 → 새 노드의 prev/next 세팅 → 이웃들의 링크를 새 노드로" 순으로 4개를 빠짐없이 → (3) 삭제는 이웃끼리 직접 연결.
- 언제 쓰나: 텍스트 에디터 커서, LRU 캐시, 양방향 순회, "포인터를 들고 다니며 그 자리를 지운다" 류. 양끝만 다루면 그냥 `list`/`deque`.
- 복잡도: 위치를 알 때 삽입/삭제 O(1), 접근/탐색 O(n), 공간 O(n)(노드마다 링크 2개). 흔한 실수: 링크 4개 중 일부를 빠뜨려 한 방향만 이어지는 것, 센티넬 없이 head/tail 경계를 직접 다루다 `nullptr->prev` 역참조.

**문제**

**1) 양방향 출력** · Easy

- **요구사항**: `n`개의 정수를 뒤에 차례로 추가해 이중 연결 리스트를 만든 뒤, head→tail 방향과 tail→head 방향으로 각각 출력하라.
- **입력**: 첫 줄에 `n`. 둘째 줄에 정수 `n`개.
- **출력**: 첫 줄에 정방향, 둘째 줄에 역방향(각각 공백 구분).
- **예제**: `4 / 10 20 30 40` → `10 20 30 40` / `40 30 20 10` · `1 / 7` → `7` / `7`
- **셀프체크**: 역방향을 배열 뒤집기가 아니라 prev 링크를 따라 만들었는가? tail을 정확히 잡았는가? 원소 1개일 때 양쪽이 같은가?

```runner
@@SOLUTION

(1) 접근·핵심 아이디어

- 역방향 출력은 배열을 뒤집는 게 아니라 tail에서 prev 링크를 따라가며 만든다—이중 리스트의 존재 이유를 그대로 활용한다.

(2) 코드 단계별

- 값을 순서대로 넣으며 head/tail을 갱신한다. 첫 노드면 head=tail, 이후엔 tail 뒤에 연결.
- 정방향: head→next로 순회. 역방향: tail→prev로 순회.

(3) 스스로 다시 짤 때 생각 순서

- 삽입 시 "새 노드의 prev와 기존 tail의 next"를 둘 다 세팅한다는 것만 놓치지 않으면 된다.
- 역순은 tail을 정확히 잡고 prev를 따라가면 자동. 원소 1개면 head==tail이라 양방향 출력이 같아진다.
```

**2) 커서 텍스트 에디터** · Medium

- **요구사항**: 처음 빈 텍스트에 커서가 있다. 명령을 처리하라: `P c`(커서 왼쪽에 문자 c 추가), `L`(커서 왼쪽으로 한 칸, 맨 앞이면 무시), `D`(커서 오른쪽으로 한 칸, 맨 뒤면 무시), `B`(커서 왼쪽 문자 삭제, 없으면 무시). 최종 문자열을 출력하라.
- **입력**: 첫 줄에 명령 수 `q`. 다음 `q`줄에 명령.
- **출력**: 최종 텍스트(문자 사이 공백 없이). 빈 문자열이면 `empty`.
- **예제**: `P a / P b / P c / L / L / P x / B` → `abc` · `P a / P b / L / P x` → `axb`
- **셀프체크**: 첫 예제에서 `P a P b P c`로 `abc`, `L L`로 커서가 `a`와 `b` 사이, `P x`로 `axbc`, 마지막 `B`가 커서 왼쪽 `x`를 지워 다시 `abc`가 됨을 검산했는가? 커서를 이중 링크의 노드 포인터로 표현했는가? `std::list`로도 풀리지만 좌우 이동·삽입·삭제가 모두 O(1)인가? 경계(맨 앞 L, 맨 뒤 D, 빈 상태 B)를 무시 처리했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

(1) 접근·핵심 아이디어

- 이중 연결 리스트에 head/tail 센티넬을 두고, 커서를 "커서 바로 왼쪽 노드"의 포인터로 표현한다(맨 앞이면 head 센티넬). 이러면 삽입/삭제 지점이 항상 `cursor` 기준으로 명확해진다.
- 좌우 이동은 `cursor = cursor->prev/next`, 삽입은 링크 4개 재배선, 삭제는 이웃끼리 잇기—모두 O(1).

(2) 코드 단계별

- `P c`: cursor 바로 뒤에 노드를 끼우고, 그 노드를 새 cursor로 삼는다(삽입 문자가 커서 왼쪽).
- `L`: cursor가 head가 아니면 한 칸 왼쪽으로. `D`: cursor->next가 tail이 아니면 한 칸 오른쪽으로.
- `B`: cursor가 head가 아니면 cursor 노드(커서 왼쪽 문자)를 이웃끼리 이어 삭제하고 cursor를 그 왼쪽으로 옮긴다.
- 끝에서 head->next부터 tail 전까지 값을 이어 문자열을 만든다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "커서를 무엇으로 표현할지" 정한다 → 여기선 왼쪽 노드 포인터. 그러면 P/L/D/B가 모두 cursor 한 변수로 기술된다.
- 센티넬 두 개로 맨 앞 L·맨 뒤 D·빈 상태 B의 경계를 `!= head`/`->next != tail` 비교만으로 무시 처리한다.
```

**3) LRU 순서 관리** · Hard

- **요구사항**: 용량 `k`인 캐시가 있다. `access x` 명령이 오면: 이미 있으면 그 노드를 "가장 최근"으로 옮기고, 없으면 새로 추가하되 용량 초과 시 "가장 오래된" 원소를 제거한다. 모든 명령 후 최근→오래된 순서로 원소들을 출력하라.
- **입력**: 첫 줄에 `k q`. 다음 `q`줄에 `access x`.
- **출력**: 최근 사용 순서(공백 구분). 비면 `empty`.
- **예제**: `2 5 / access 1 / access 2 / access 1 / access 3 / access 4` → `4 3` · `3 4 / access 1 / access 2 / access 3 / access 2` → `2 3 1`
- **셀프체크**: 첫 예제에서 `1 2` 후 `1` 재접근으로 `1 2`(최근순), `3` 추가로 용량 초과 → 오래된 `2` 제거 `3 1`, `4` 추가로 `1` 제거 → `4 3`이 맞는가? 이동/삭제를 값→노드 `unordered_map` + 이중 링크로 O(1)에 했는가? 센티넬로 양끝 처리를 단순화했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
struct Node { int val; Node* prev; Node* next; Node(int v=0): val(v), prev(nullptr), next(nullptr) {} };
int main() {
    int k, q;
    cin >> k >> q;
    Node* head = new Node();   // 센티넬 (head->next = 가장 최근)
    Node* tail = new Node();   // 센티넬 (tail->prev = 가장 오래된)
    head->next = tail;
    tail->prev = head;
    unordered_map<int, Node*> pos;
    auto remove = [](Node* node) {
        node->prev->next = node->next;
        node->next->prev = node->prev;
    };
    auto add_front = [&](Node* node) {
        Node* nxt = head->next;
        node->prev = head;
        node->next = nxt;
        head->next = node;
        nxt->prev = node;
    };
    string op;
    for (int i = 0; i < q; i++) {
        int x;
        cin >> op >> x;            // op == "access"
        auto it = pos.find(x);
        if (it != pos.end()) {
            Node* node = it->second;
            remove(node);
            add_front(node);
        } else {
            if ((int)pos.size() >= k) {
                Node* oldest = tail->prev;
                remove(oldest);
                pos.erase(oldest->val);
            }
            Node* node = new Node(x);
            add_front(node);
            pos[x] = node;
        }
    }
    bool first = true;
    string out;
    for (Node* cur = head->next; cur != tail; cur = cur->next) {
        if (!first) out += ' ';
        out += to_string(cur->val); first = false;
    }
    cout << (out.empty() ? "empty" : out) << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 이중 연결 리스트(head/tail 센티넬)로 사용 순서를 유지하고, `unordered_map`(값→노드)으로 임의 노드를 O(1)에 찾는다. 이 조합이 LRU의 표준 구조다.
- head 바로 뒤가 "가장 최근", tail 바로 앞이 "가장 오래된"이다.

(2) 코드 단계별

- `access x`가 이미 있으면: 그 노드를 `remove` 후 `add_front`로 옮겨 최근으로 만든다.
- 없으면: 용량이 찼을 때 `tail->prev`(가장 오래된)를 제거하고 map에서도 지운 뒤, 새 노드를 앞에 추가한다.
- 마지막에 head→tail 방향으로 순회하면 최근→오래된 순서가 나온다.

(3) 스스로 다시 짤 때 생각 순서

- "최근 순서 유지 = 이중 링크, 임의 접근 = unordered_map"이라는 두 축을 먼저 세운다.
- 센티넬을 두면 맨 앞/맨 뒤 삽입·삭제에서 nullptr 경계 분기가 사라져 remove/add_front를 각각 한 함수(람다)로 통일할 수 있다.
```

## L5. Iterator

**개념**

- Iterator(반복자)는 "컬렉션의 원소를 하나씩, 순서대로 꺼내는 방법"을 자료구조 내부 구현과 분리해 추상화한 것이다. 사용하는 쪽은 "다음 원소 주세요"만 알면 되고, 그게 배열이든 연결 리스트든 상관없다.
- 선행(이 개념들은 여기서 처음 소개): C++의 반복자는 포인터를 일반화한 객체다. 컨테이너는 `begin()`(첫 원소를 가리키는 반복자)과 `end()`("마지막 다음"을 가리키는 경계 반복자)를 준다. 반복자 `it`는 `*it`로 현재 값을 읽고, `++it`로 다음으로 전진하며, `it != end()`로 "끝인지"를 판단한다. `for (auto it = v.begin(); it != end; ++it)`가 바로 이 세 연산의 반복이고, 범위 기반 `for (auto x : v)`는 그걸 감춘 문법이다.
- 직접 반복자를 만들 때는 "현재 어디까지 봤는지"라는 상태를 객체 안에 담는다. 간단하게는 `has_next()`(더 있나?)와 `next()`(값 반환 + 상태 전진) 두 메서드를 가진 구조체로 표현해도 같은 개념이 성립한다. 상태가 없으면 반복은 성립하지 않는다.

```cpp
struct RangeIter {          // 0,1,2,...,n-1을 하나씩 내보내는 반복자
    int cur, n;
    RangeIter(int n_) : cur(0), n(n_) {}
    bool has_next() const { return cur < n; }
    int next() { return cur++; }        // 값 반환 후 상태 전진
};

RangeIter it(3);
while (it.has_next())                   // 0, 1, 2 출력 후 has_next()가 false
    cout << it.next() << '\n';
```

- 특히 연결 리스트에 반복자를 붙이면, 노드/링크를 노출하지 않고도 값만 하나씩 자연스럽게 순회할 수 있다. 상태(현재 노드)를 반복자 안에 담는 게 핵심이다. 아래처럼 `has_next`/`next`만 노출하면 사용하는 쪽은 내부가 배열인지 사슬인지 알 필요가 없다.

```cpp
struct ListIter {
    Node* cur;                          // Node{val,next} 사슬의 현재 위치
    ListIter(Node* head) : cur(head) {}
    bool has_next() const { return cur != nullptr; }
    int next() { int v = cur->val; cur = cur->next; return v; }
};

for (ListIter it(head); it.has_next(); )   // 내부 구조를 숨기고 값만 소비
    cout << it.next() << '\n';
```

**접근 전략**

- 핵심 아이디어: "순회 방법"을 값 소비와 분리한다. 반복자는 "현재 어디까지 봤는지"라는 상태를 스스로 들고 있어, 한 번 소비하면 앞으로만 나아간다(대개 재사용 불가).
- 전형적 절차: (1) 순회 상태(현재 노드/인덱스)를 정한다 → (2) `has_next()`에서 "끝인지"를, `next()`에서 "값 반환 + 상태 전진"을 구현한다(또는 컨테이너의 begin/end 반복자를 그대로 쓴다) → (3) 필요하면 필터·변환을 반복자 위에 얹어 필요한 순간에만 값을 뽑는다(지연 소비).
- 언제 쓰나: 큰(또는 무한) 수열을 메모리에 다 안 올리고 흘려보낼 때, 서로 다른 자료구조를 같은 방식으로 다루고 싶을 때, 두 수열을 나란히 소비(merge)할 때.
- 복잡도: 원소 하나 꺼내기 O(1), 전체 순회 O(n), 반복자의 추가 공간 O(1)(전체를 리스트로 모으지 않으므로). 흔한 실수: 이미 소진된 반복자를 또 소비해 아무것도 안 나오는 것, `has_next()` 경계를 틀려 `end()`를 넘어 역참조하거나 무한 루프.

**문제**

**1) 스킵 반복자** · Easy

- **요구사항**: 정수 리스트와 간격 `s`가 주어질 때, 0번째부터 `s`칸씩 건너뛴 값들만 순서대로 내보내는 반복자를 만들어 출력하라. 전체 리스트를 새로 만들지 말고 하나씩 흘려보내라.
- **입력**: 첫 줄에 `n s`(1 ≤ s ≤ n). 둘째 줄에 정수 `n`개.
- **출력**: 뽑힌 값들을 공백으로 구분해 한 줄.
- **예제**: `6 2 / 1 2 3 4 5 6` → `1 3 5` · `5 3 / 10 20 30 40 50` → `10 40`
- **셀프체크**: 인덱스 0, s, 2s… 를 정확히 뽑는가? `s=1`이면 전체가 그대로 나오는가? 반복자 상태(현재 인덱스)를 안에서 관리하고 하나씩 소비했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
// 스킵 반복자: 현재 인덱스 i를 상태로 들고 step만큼 전진하며 값을 하나씩 내보낸다.
struct SkipIter {
    const vector<int>& seq;
    int i, step;
    SkipIter(const vector<int>& s, int st): seq(s), i(0), step(st) {}
    bool has_next() const { return i < (int)seq.size(); }
    int next() { int v = seq[i]; i += step; return v; }
};
int main() {
    int n, s;
    cin >> n >> s;
    vector<int> vals(n);
    for (int i = 0; i < n; i++) cin >> vals[i];
    SkipIter it(vals, s);
    bool first = true;
    while (it.has_next()) {
        if (!first) cout << ' ';
        cout << it.next(); first = false;
    }
    cout << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 인덱스 0, s, 2s, … 만 골라 하나씩 내보내는 반복자를 만든다. 새 리스트를 통째로 만들지 않고 필요한 순간에 값을 흘려보낸다(지연 소비).
- 반복자 상태는 "현재 인덱스 i" 하나뿐이며, `next()`마다 `step`만큼 전진한다.

(2) 코드 단계별

- `SkipIter`: `i=0`에서 시작해 `has_next()`가 `i < 크기`를, `next()`가 `seq[i]`를 반환하고 `i += step`.
- 메인에서 `while (it.has_next())`로 소비해 공백으로 이어 출력.
- `s=1`이면 전체가 그대로, 큰 s면 듬성듬성 뽑힌다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇을 상태로 들 것인가"를 먼저 정한다 → 여기선 현재 인덱스 i.
- `next()`에서 값을 반환한 뒤 상태를 step만큼 전진시키는 한 줄만 지키면 반복 골격이 완성된다.
```

**2) 지연 병합 반복자** · Medium

- **요구사항**: 각각 오름차순인 두 정수 수열의 반복자를 받아, 전체를 오름차순으로 하나씩 내보내는 "병합 반복자"를 만들어라. 두 수열을 통째로 합쳐 정렬하지 말고, 두 반복자를 나란히 소비하며 작은 쪽을 내보내라.
- **입력**: 첫 줄에 `a b`. 둘째 줄에 첫 수열 `a`개(오름차순), 셋째 줄에 둘째 수열 `b`개(오름차순).
- **출력**: 병합 결과(공백 구분).
- **예제**: `3 3 / 1 3 5 / 2 4 6` → `1 2 3 4 5 6` · `2 4 / 1 5 / 2 3 4 6` → `1 2 3 4 5 6`
- **셀프체크**: 각 반복자에서 "현재 값"을 하나씩만 앞서 들고 비교했는가(전체를 리스트로 안 모음)? 한쪽이 끝나면 다른 쪽을 끝까지 내보냈는가? 각 반복자의 소진(has_next 거짓)을 종료 판단에 썼는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
// 배열 반복자: 현재 인덱스를 상태로, 하나씩만 앞서 들고 소비한다.
struct VecIter {
    const vector<int>& v;
    int i;
    VecIter(const vector<int>& x): v(x), i(0) {}
    bool has_next() const { return i < (int)v.size(); }
    int next() { return v[i++]; }
};
int main() {
    int a, b;
    cin >> a >> b;
    vector<int> va(a), vb(b);
    for (int i = 0; i < a; i++) cin >> va[i];
    for (int i = 0; i < b; i++) cin >> vb[i];
    VecIter it1(va), it2(vb);
    bool first = true;
    auto emit = [&](int x) { if (!first) cout << ' '; cout << x; first = false; };
    // 두 반복자에서 현재 값을 하나씩만 앞서 들고 작은 쪽을 내보낸다.
    bool have1 = it1.has_next(), have2 = it2.has_next();
    int x1 = have1 ? it1.next() : 0;
    int x2 = have2 ? it2.next() : 0;
    while (have1 && have2) {
        if (x1 <= x2) { emit(x1); have1 = it1.has_next(); if (have1) x1 = it1.next(); }
        else { emit(x2); have2 = it2.has_next(); if (have2) x2 = it2.next(); }
    }
    while (have1) { emit(x1); have1 = it1.has_next(); if (have1) x1 = it1.next(); }
    while (have2) { emit(x2); have2 = it2.has_next(); if (have2) x2 = it2.next(); }
    cout << '\n';
    return 0;
}

- 두 정렬 수열을 통째로 합쳐 정렬하지 않고, 두 반복자에서 "현재 값"을 하나씩만 앞서 들고 작은 쪽을 내보낸다(투 포인터의 반복자 버전).
- `has_next()`로 소진을 판단한다: 거짓이면 그 반복자가 끝난 것. 현재 값을 `have1/have2` 플래그와 함께 들고 다닌다.

(2) 코드 단계별

- 시작 시 각 반복자에서 첫 값 `x1, x2`를 하나씩 당겨온다(있을 때만).
- 둘 다 값이 있으면 `x1 <= x2`인 쪽을 내보내고 그쪽만 다음 값으로 갱신한다(동률이면 왼쪽 먼저—안정적).
- 한쪽이 끝나면 남은 반복자의 값을 끝까지 흘려보낸다.

(3) 스스로 다시 짤 때 생각 순서

- "각 스트림에서 값 하나씩만 미리 들고 비교"라는 그림을 먼저 그린다.
- 종료 판정을 `has_next()`/플래그로 통일하면 소진 처리와 잔여 소비 루프가 깔끔해진다.
```

**3) 무한 수열의 앞 K개** · Hard

- **요구사항**: "규칙으로 끝없이 생성되는 수열"의 반복자를 만들고, 그 앞에서 조건을 만족하는 값 `k`개만 뽑아 출력하라. 규칙: 1부터 시작해 각 항은 이전 항 + (그 항의 자릿수 합). 조건: 짝수인 항만.
- **입력**: 한 줄에 `k`(1 ≤ k ≤ 20).
- **출력**: 조건을 만족하는 앞 `k`개(공백 구분).
- **예제**: 수열은 1, 2, 4, 8, 16, 23, 28, 38, 49, 62, 70, 77, 91, 101, … 이고 짝수만 앞에서 뽑으면 2, 4, 8, 16, 28, 38, 62, 70, … 이다. `4` → `2 4 8 16` · `6` → `2 4 8 16 28 38`
- **셀프체크**: 무한 반복자를 만들고 `k`개를 채우면 즉시 멈췄는가(전체를 안 만든다)? 각 항 = 이전 항 + 자릿수합 계산이 맞는가(예: 16 → 16+1+6=23)? 조건 필터(짝수)를 반복자 위에 얹었는가? 첫 항 1은 홀수라 건너뛰고 2부터 뽑히는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
// 무한 수열 반복자: 다음 항 = 현재 항 + (현재 항의 자릿수 합). 상태(cur)만 들고 끝없이 생성.
struct SeqIter {
    long long cur;
    SeqIter(): cur(1) {}
    long long next() {
        long long v = cur;
        long long s = 0;
        for (long long t = cur; t > 0; t /= 10) s += t % 10;
        cur = cur + s;
        return v;
    }
};
int main() {
    int k;
    cin >> k;
    SeqIter it;
    bool first = true;
    int cnt = 0;
    while (cnt < k) {
        long long v = it.next();
        if (v % 2 == 0) {          // 짝수 필터
            if (!first) cout << ' ';
            cout << v; first = false;
            cnt++;
        }
    }
    cout << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- "끝없이 생성되는 수열"을 상태 `cur` 하나만 든 반복자 `SeqIter`로 표현한다. `next()`가 현재 값을 반환하고 다음 항으로 상태를 갱신하므로 전체를 미리 만들지 않는다.
- 소비하는 쪽에서 짝수만 골라 세다가 k개가 차면 즉시 루프를 끝낸다—이것이 지연 소비의 이점이다.

(2) 코드 단계별

- `SeqIter`: `cur=1`에서 시작해 `next()`가 `cur`을 반환하고, 다음 항은 `cur + (cur의 자릿수 합)`으로 갱신한다(예: 16 → 16+1+6=23).
- 메인: `it.next()`로 하나씩 받아 짝수면 출력하고 개수를 센다. 개수가 k가 되면 `while`을 끝낸다.
- 첫 항 1은 홀수라 건너뛰고 2부터 뽑힌다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "다음 항 = 현재 항 + 자릿수합"이라는 생성 규칙을 `next()` 안에 담는다.
- 그 위에 "짝수 필터 + k개에서 멈춤"을 얹으면 무한 수열이라도 유한하게 소비된다.
```

## L6. 원형 연결 리스트

**개념**

- 원형 연결 리스트(circular linked list)는 마지막 노드의 next가 `nullptr`이 아니라 다시 head를 가리켜, 링크를 따라가면 끝없이 도는 구조다(이중 원형이면 head의 prev가 tail).
- "끝"이 없으므로 순회를 멈추려면 "시작 노드로 돌아왔는지"를 기준으로 삼는다. 라운드 로빈(순번 돌리기), 버퍼 재활용처럼 "돌면서 반복 처리"에 자연스럽다.
- 보통 tail 하나만 들고 있으면 `tail->next`가 head라, 맨 앞/맨 뒤 삽입을 모두 O(1)로 할 수 있다는 실용적 이점이 있다.
- C++에서는 `std::deque`의 양끝 O(1) 연산으로 원형 순회를 흉내 내기 좋다: 맨 앞 원소를 빼서 맨 뒤에 붙이면(`push_back(front()); pop_front();`) 왼쪽으로 한 칸 굴린 것과 같아 다음 사람이 앞에 온다. 요세푸스류 문제의 표준 도구다.

```cpp
#include <deque>
// n명이 원을 이룰 때, k번째마다 제거하는 순서
vector<int> josephus(int n, int k) {
    deque<int> dq;
    for (int i = 1; i <= n; i++) dq.push_back(i);
    vector<int> order;
    while (!dq.empty()) {
        for (int r = 0; r < (k - 1) % (int)dq.size(); r++) {  // 제거 대상을 맨 앞으로
            dq.push_back(dq.front());
            dq.pop_front();
        }
        order.push_back(dq.front());
        dq.pop_front();
    }
    return order;
}
// josephus(7, 3) -> {3, 6, 2, 7, 5, 1, 4}
```

**접근 전략**

- 핵심 아이디어: "끝이 없으니 시작점 기준으로 한 바퀴를 감지한다". 등간격으로 돌며 하나씩 처리(제거/방문)하는 문제는 원형 구조 + 회전으로 깔끔해진다.
- 전형적 절차: (1) 원소를 원형(또는 `deque`)에 담고 → (2) "k-1칸 전진 후 현재를 처리"를 남은 게 없을 때까지 반복 → (3) 직접 구현이면 삭제할 노드의 직전을 쥐고 `prev->next = cur->next`, tail 갱신에 주의.
- 언제 쓰나: 요세푸스/폭탄 돌리기, 라운드 로빈 스케줄링, 순환 버퍼, "N번째마다"류. 한 바퀴 이상 도는 시뮬레이션.
- 복잡도: `deque`로 한 칸씩 굴리는 회전은 굴린 칸 수에 비례. 요세푸스를 매번 k칸 굴리면 O(n·k), 남은 수만큼 굴리면 대략 O(n²) 상한. 공간 O(n). 흔한 실수: 순환이라 종료 조건을 안 걸어 무한 루프, `k`가 원소 수보다 클 때 `%`로 줄이지 않아 헛도는 것.

**문제**

**1) 라운드 로빈 호명** · Easy

- **요구사항**: 1~`n`번이 원을 이룬다. 1번부터 시작해 시계 방향으로 `m`번 호명할 때(호명해도 빠지지 않고 계속 돔), 호명되는 번호를 순서대로 출력하라.
- **입력**: 한 줄에 `n m`(1 ≤ n ≤ 100, 1 ≤ m ≤ 1000).
- **출력**: 호명 순서 `m`개(공백 구분).
- **예제**: `3 5` → `1 2 3 1 2` · `4 2` → `1 2`
- **셀프체크**: `i`번째 호명이 `(i mod n)+1`(1-based)로 나오는가? `m > n`이어도 계속 순환하는가? 인덱스 `%`로 O(m)에 처리했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    int n, m;
    cin >> n >> m;
    bool first = true;
    for (int i = 0; i < m; i++) {
        if (!first) cout << ' ';
        cout << (i % n) + 1; first = false;
    }
    cout << '\n';
    return 0;
}
@@TESTS
--IN
3 5
--OUT
1 2 3 1 2
--IN
1 4
--OUT
1 1 1 1
@@EXPL
(1) 접근·핵심 아이디어

- 1~n이 원을 이루므로 i번째(0-based) 호명은 `(i % n) + 1`로 바로 구할 수 있다. 원형 순회의 핵심은 나머지 연산 `% n`이다.
- 호명해도 빠지지 않으므로 원소 수가 줄지 않아, 인덱스만 계속 도는 가장 단순한 형태다.

(2) 코드 단계별

- 0부터 m-1까지 반복하며 `(i % n) + 1`을 출력한다(1-based 번호).
- 공백으로 이어 한 줄 출력.

(3) 스스로 다시 짤 때 생각 순서

- "i번째로 도는 위치 = i를 n으로 나눈 나머지"라는 공식을 먼저 세운다.
- 1-based 보정(+1)과 `m > n`일 때도 그대로 순환한다는 점만 확인하면 끝.
```

**2) 폭탄 돌리기(요세푸스)** · Medium

- **요구사항**: 1~`n`번이 원을 이룬다. 1번부터 세기 시작해 `k`번째 사람을 제거하고, 그 다음 사람부터 다시 `k`를 센다. 제거되는 순서를 모두 출력하라(요세푸스 순열).
- **입력**: 한 줄에 `n k`(1 ≤ k ≤ n ≤ 1000).
- **출력**: 제거 순서 `n`개(공백 구분).
- **예제**: `7 3` → `3 6 2 7 5 1 4` · `5 2` → `2 4 1 5 3`
- **셀프체크**: `n=7,k=3`에서 첫 제거가 3번, 그 다음이 6번인지 손으로 확인했는가? "k-1칸 왼쪽으로 굴린 뒤 맨 앞을 제거"가 맞는가? 마지막 한 명까지 정확히 제거되는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    int n, k;
    cin >> n >> k;
    deque<int> dq;
    for (int i = 1; i <= n; i++) dq.push_back(i);
    bool first = true;
    while (!dq.empty()) {
        // 제거 대상이 맨 앞에 오도록 왼쪽으로 k-1칸 굴림
        for (int r = 0; r < (k - 1) % (int)dq.size(); r++) {
            dq.push_back(dq.front());
            dq.pop_front();
        }
        if (!first) cout << ' ';
        cout << dq.front(); first = false;
        dq.pop_front();
    }
    cout << '\n';
    return 0;
}
@@TESTS
--IN
7 3
--OUT
3 6 2 7 5 1 4
--IN
6 3
--OUT
3 6 4 2 5 1
@@EXPL
(1) 접근·핵심 아이디어

- 원을 `deque`로 표현하고, "k번째 사람"이 항상 맨 앞으로 오게 왼쪽으로 굴린 뒤 `pop_front`로 제거한다.
- 1번부터 세기 시작하므로 k번째는 맨 앞에서 `k-1`칸 뒤에 있다. 맨 앞을 빼서 뒤에 붙이는 것을 `k-1`번 하면 그 사람이 맨 앞으로 온다. 남은 인원보다 `k`가 클 수 있으니 `(k-1) % size`로 회전량을 줄인다.

(2) 코드 단계별

- `deque`에 1~n을 담아 원형처럼 쓴다.
- 남은 사람이 있는 동안: 왼쪽으로 `(k-1) % size`칸 굴려 제거 대상을 앞에 오게 하고, `front()`를 출력한 뒤 `pop_front()`로 뺀다.
- 다음 라운드는 방금 제거된 자리의 "다음 사람"이 자연히 맨 앞이 되어 이어 센다.

(3) 스스로 다시 짤 때 생각 순서

- "제거 대상을 맨 앞으로 옮긴다"는 한 문장으로 회전량 `k-1`을 유도한다.
- pop_front 후 재정렬이 필요 없다는 점(다음 시작이 자동으로 앞)을 확인하면 루프가 단순해진다.
```

**3) 원형 버퍼 최종 상태** · Hard

- **요구사항**: 크기 `c`인 원형 버퍼(용량 고정)가 있다. `put x`는 값을 다음 쓰기 위치에 넣고 포인터를 한 칸 전진(가득 차면 가장 오래된 값을 덮어씀), `pop`은 가장 오래된 값을 하나 꺼내 출력하고 읽기 포인터를 전진(비었으면 `empty`). 모든 명령 후 버퍼에 남아있는 값을 오래된 순서대로 출력하라.
- **입력**: 첫 줄에 `c q`. 다음 `q`줄에 명령.
- **출력**: `pop`마다 결과를 한 줄씩. 마지막 줄에 남은 값들을 오래된 순서로(비면 `empty`).
- **예제**: `3 5 / put 1 / put 2 / put 3 / put 4 / pop` → `2` / `3 4` · `2 3 / put 5 / pop / pop` → `5` / `empty` / `empty`
- **셀프체크**: 첫 예제에서 용량 3에 1,2,3 후 `put 4`가 가장 오래된 1을 덮어 버퍼가 `2 3 4`가 되고, `pop`이 2를 내보내 `3 4`가 남는지 검산했는가? 읽기/쓰기 포인터를 `% c`로 굴렸는가? 가득 참(overwrite)과 빔(empty pop) 경계를 나눴는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;
int main() {
    int c, q;
    cin >> c >> q;
    vector<int> buf(c, 0);
    int read = 0, count = 0;
    string cmd;
    for (int i = 0; i < q; i++) {
        cin >> cmd;
        if (cmd == "put") {
            int x; cin >> x;
            int w = (read + count) % c;
            buf[w] = x;
            if (count < c) count++;
            else read = (read + 1) % c;   // 가장 오래된 값 덮어씀
        } else if (cmd == "pop") {
            if (count == 0) cout << "empty" << '\n';
            else {
                cout << buf[read] << '\n';
                read = (read + 1) % c;
                count--;
            }
        }
    }
    if (count == 0) cout << "empty" << '\n';
    else {
        string rem;
        for (int j = 0; j < count; j++) {
            if (j) rem += ' ';
            rem += to_string(buf[(read + j) % c]);
        }
        cout << rem << '\n';
    }
    return 0;
}
@@TESTS
--IN
3 5
put 1
put 2
put 3
put 4
pop
--OUT
2
3 4
--IN
3 6
put 10
put 20
pop
put 30
put 40
pop
--OUT
10
20
30 40
@@EXPL
(1) 접근·핵심 아이디어

- 고정 크기 배열 `buf`와 읽기 포인터 `read`, 저장 개수 `count`로 원형 버퍼를 표현한다. 쓰기 위치는 `(read + count) % c`로 유도되므로 별도 write 포인터가 필요 없다.
- 가득 찬 상태(`count == c`)에서 `put`이 오면 가장 오래된 값을 덮어써야 하므로, 쓰기 후 `read`를 한 칸 전진시켜 count는 그대로 c로 유지한다.

(2) 코드 단계별

- `put`: `w = (read+count)%c` 자리에 값을 넣는다. 아직 여유가 있으면 `count++`, 꽉 찼으면 `read` 전진(오래된 것 하나 밀려남).
- `pop`: `count == 0`이면 `empty`, 아니면 `buf[read]`를 출력하고 `read`를 전진, `count--`.
- 마지막에 오래된 순서 `buf[(read+j)%c]`(j=0..count-1)로 남은 값을 만든다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "쓰기 위치를 read+count로 계산"한다는 불변식을 잡으면 포인터가 하나로 준다.
- overwrite(가득 참)와 empty(빈 pop) 두 경계만 정확히 처리하면 나머지는 `% c` 산술로 자연히 돈다.
```

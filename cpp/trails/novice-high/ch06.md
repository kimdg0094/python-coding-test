> 개요: 계층적 데이터를 표현하는 트리 자료구조를 배운다. 트리의 기본 용어와 이진 트리, 세 가지 순회(전위·중위·후위), 정렬된 탐색을 지원하는 이진 탐색 트리(BST), 그리고 최댓값/최솟값을 빠르게 뽑는 힙(heap)까지 다룬다. (언어 C++)

## L1. 트리

**개념**

- 트리(tree)는 노드(node)들이 부모-자식 관계로 연결된 계층적 자료구조다. 사이클이 없고, 연결되어 있으며, 노드가 N개면 간선(edge)은 정확히 N-1개다.

- 왜 쓰는가: 폴더/파일 구조, 조직도, HTML DOM, 수식 파싱 등 "하나가 여러 개를 거느리는" 계층 관계를 표현하기에 자연스럽다. 배열/벡터는 일렬(선형)이라 계층 표현이 어렵다.

- 핵심 용어(꼭 구분):

  - 루트(root): 부모가 없는 최상위 노드. 트리에 딱 하나.

  - 리프(leaf, 단말): 자식이 없는 노드.

  - 부모/자식(parent/child), 형제(sibling): 같은 부모를 공유하는 노드들.

  - 깊이(depth): 루트에서 그 노드까지의 간선 수(루트는 0).

  - 높이(height): 그 노드에서 가장 먼 리프까지의 간선 수. 트리의 높이 = 루트의 높이.

  - 서브트리(subtree): 어떤 노드와 그 자손 전체가 이루는 작은 트리.

- 표현 방법(C++):

  - 인접 리스트: `vector<vector<int>> children(N);` 에 자식 번호를 담는다.

  - 부모 배열: `vector<int> parent(N);` 에 v의 부모 번호를 저장(루트는 -1). 입력이 "각 노드의 부모"로 주어질 때 편하다.

```cpp
#include <bits/stdc++.h>
using namespace std;

// 부모 정보로 자식 리스트 만들기 (노드 0..N-1, 루트의 부모는 -1)
int buildChildren(const vector<int>& parent, vector<vector<int>>& children) {
    int N = (int)parent.size();
    children.assign(N, {});
    int root = -1;
    for (int v = 0; v < N; v++) {
        if (parent[v] == -1) root = v;
        else children[parent[v]].push_back(v);
    }
    return root;
}

// 재귀로 서브트리 크기(자기 포함) 세기
int subtreeSize(int v, const vector<vector<int>>& children) {
    int size = 1;
    for (int c : children[v]) size += subtreeSize(c, children);
    return size;
}
```

**그림으로 보기**

- 용어는 따로 외우는 게 아니라 한 그림 위에서 서로의 관계로 익힌다. 괄호 안이 노드 이름이고, 줄 끝 `#` 뒤가 설명이다.

```text
              (A)                    # depth 0
             /   \
          (B)     (C)                # depth 1
          / \       \
       (D) (E)      (F)              # depth 2
                      \
                      (G)            # depth 3

  root    : A                    # 부모가 없는 유일한 노드
  leaf    : D, E, G              # 자식이 하나도 없는 노드
  parent  : parent(D) = B
  child   : children(C) = [F]
  sibling : D, E                 # 부모가 B로 같다
  depth   : depth(F) = 2         # 루트에서 그 노드까지의 간선 수
  height  : height(A) = 3        # A에서 가장 먼 리프까지의 간선 수
  count   : 7 nodes, 6 edges     # 노드 N개면 간선은 항상 N-1개
```

- 깊이는 "위에서 나까지", 높이는 "나에서 아래 끝까지"다. 방향이 반대라 헷갈리기 쉽다.

- 서브트리는 "어떤 노드와 그 아래 전부"를 통째로 떼어낸 작은 트리다.

```text
  subtree(B)              subtree(C)
      (B)                     (C)
      / \                       \
   (D) (E)                      (F)
                                  \
                                  (G)

  size = 3                size = 3       # 자기 자신을 포함해서 센다
```

- 같은 트리를 C++이 어떻게 메모리에 담는지도 그림으로 붙여 둔다. 입력 형태에 따라 둘 중 하나를 고른다.

```text
  vector<vector<int>> children      # 자식 리스트 (노드 0..6 = A..G)
  ---------------------------------------------------------
   children[0] : 1 2                # A 의 자식은 B, C
   children[1] : 3 4                # B 의 자식은 D, E
   children[2] : 5                  # C 의 자식은 F
   children[3] :                    # D 는 리프 (빈 vector)
   children[5] : 6

  vector<int> parent                # 부모 배열 (루트는 -1)
  ---------------------------------------------------------
   idx     : 0   1   2   3   4   5   6
   parent  : -1  0   0   1   1   2   5
```

**손으로 따라가기**

`parent = [-1, 0, 0, 1, 1]` (노드 5개)로 자식 리스트를 만드는 과정.

| 단계 | v | parent[v] | 하는 일 | children 상태 |
| --- | --- | --- | --- | --- |
| 1 | 0 | -1 | 루트 발견 → `root = 0` | `[[], [], [], [], []]` |
| 2 | 1 | 0 | `children[0]`에 1 추가 | `[[1], [], [], [], []]` |
| 3 | 2 | 0 | `children[0]`에 2 추가 | `[[1,2], [], [], [], []]` |
| 4 | 3 | 1 | `children[1]`에 3 추가 | `[[1,2], [3], [], [], []]` |
| 5 | 4 | 1 | `children[1]`에 4 추가 | `[[1,2], [3,4], [], [], []]` |

이어서 `subtreeSize(0)`이 재귀로 답을 만들어 올리는 순서.

| 순서 | 호출 | 자식 | 반환값 |
| --- | --- | --- | --- |
| 1 | `subtreeSize(3)` | 없음 | 1 |
| 2 | `subtreeSize(4)` | 없음 | 1 |
| 3 | `subtreeSize(1)` | 3, 4 | 1 + 1 + 1 = 3 |
| 4 | `subtreeSize(2)` | 없음 | 1 |
| 5 | `subtreeSize(0)` | 1, 2 | 1 + 3 + 1 = 5 |

리프에서 1로 시작해 부모로 올라가며 합쳐지고, 마지막에 루트가 전체 노드 수 5를 반환한다.

**왜 이렇게 되는가**

- 왜 간선이 정확히 N-1개인가: 루트를 뺀 모든 노드가 "자신과 부모를 잇는 간선"을 정확히 하나씩 갖는다. 노드와 간선이 1:1로 짝지어지고 루트 하나만 짝이 없으므로 간선 수 = N - 1이다. 반대로 간선이 N개 이상이면 어딘가에 사이클이 생겨 트리가 아니다.

- 왜 순회가 O(N)인가: 각 노드를 한 번 방문하며 그 노드의 자식 리스트를 훑는다. 모든 노드의 자식 리스트 길이를 다 더하면 "간선을 한 번씩 센 것"과 같아 N-1이다. 총 작업량은 노드 방문 N + 자식 훑기 (N-1) = O(N)이다.

- 왜 깊이는 내려가며 계산하고 크기·높이는 올라오며 계산하는가: `depth[c]`는 부모의 깊이 하나만 알면 곧바로 `depth[v] + 1`로 정해진다(위 정보만 필요). 반면 `size[v]`는 자식들의 답이 전부 나와야 더할 수 있다(아래 정보가 필요). 그래서 깊이는 재귀 인자로 내려보내고, 크기·높이는 반환값으로 받아 올린다.

- 왜 C++에서도 깊은 재귀가 위험한가: 각 노드가 자식을 하나만 갖는 사슬 모양이면 깊이가 N-1이라 호출 프레임이 N개까지 쌓인다. C++엔 파이썬 같은 "재귀 한도" 설정이 없고, 대신 **콜 스택 자체가 넘치면 스택 오버플로로 프로그램이 그냥 죽는다**(보통 1MB 안팎이라 프레임 하나가 40~60바이트여도 수만 단계에서 위험해진다). 예외가 아니라 세그멘테이션 폴트라 어디서 죽었는지도 안 알려 준다. N이 수십만이면 명시적 스택 DFS로 바꾸는 것이 안전하다.

  ```cpp
  // 재귀 대신 명시적 스택 — 깊이가 아무리 깊어도 안전하다
  vector<int> order;  vector<int> st{root};
  while (!st.empty()) {
      int v = st.back(); st.pop_back();   // pop 은 값을 안 돌려준다
      order.push_back(v);
      for (int c : children[v]) st.push_back(c);
  }
  vector<int> size(N, 1);
  for (int i = (int)order.size() - 1; i >= 0; i--) {   // 역순 = 자식이 먼저 확정
      int v = order[i];
      if (parent[v] != -1) size[parent[v]] += size[v];
  }
  ```

- 왜 자식 리스트를 `const vector<vector<int>>&`로 넘기는가: 값으로 넘기면 호출할 때마다 **전체 인접 리스트가 통째로 복사된다.** 노드 10만 개짜리 트리에서 재귀 호출 10만 번이면 복사만으로 프로그램이 끝나지 않는다. 참조 `&`는 주소 하나만 넘기므로 O(1)이고, `const`를 붙이면 실수로 고치는 것까지 막아 준다. C++ 트리 코드에서 가장 흔한 성능 사고가 이 `&` 하나를 빠뜨리는 것이다.

**접근 전략**

- 핵심 아이디어: 트리 문제는 대부분 "루트에서 시작해 자식으로 내려가는 재귀"로 푼다. 각 노드에서 (1) 나 자신을 처리하고 (2) 자식들을 재귀 호출한 결과를 모은다. 깊이는 부모 깊이+1로 내려가며 전달하고, 높이/서브트리 크기는 자식들의 결과를 받아 올라오며 합친다.

- 전형적 절차: 입력을 인접/부모 배열로 변환 → 루트를 찾음 → 루트부터 DFS(재귀). "내려가며 계산"(깊이)인지 "올라오며 계산"(높이·크기·합)인지 먼저 구분한다.

- 언제 쓰나: 계층·포함·"~의 모든 자손" 같은 관계를 다룰 때. 부모 배열만 주어져도 위 방식으로 트리를 재구성한다.

- 복잡도: 트리 전체를 한 번 순회하므로 시간 O(N), 재귀 스택/자식 리스트로 공간 O(N). 주의: C++도 깊은 재귀는 콜 스택 오버플로가 날 수 있으니, 사슬이 매우 길면 명시적 스택 DFS로 바꾼다. 루트가 여러 개거나 사이클이 있으면 트리가 아니다(입력 검증 함정).

**문제**

**1) 트리의 높이와 리프 수** · Easy

- **요구사항**: 각 노드의 부모가 주어진 트리에서, 트리의 높이(루트에서 가장 깊은 리프까지의 간선 수)와 리프 노드의 개수를 구하라.

- **입력**: 첫 줄에 노드 수 N. 둘째 줄에 `parent[0..N-1]` (루트는 -1). 노드 번호는 0..N-1.

- **출력**: 높이와 리프 수를 공백으로 구분해 한 줄.

- **예제**:

  - `5 / -1 0 0 1 1` → `2 3`  (루트 0; 0의 자식 1,2; 1의 자식 3,4. 리프는 2,3,4 → 3개. 가장 깊은 경로 0→1→3 은 간선 2개)

  - `1 / -1` → `0 1`  (노드 하나. 루트이자 리프, 높이 0)

- **셀프체크**: 노드가 1개면 높이 0·리프 1인가? 리프 판정을 "자식 리스트가 비었는가"로 했는가(부모 배열만 보고 판정하면 틀림)? 깊은 트리에서 재귀가 스택을 넘지 않는지 점검했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int n;
vector<vector<int>> children;

int height(int v) {
    if (children[v].empty()) return 0;
    int best = 0;
    for (int c : children[v]) best = max(best, height(c));
    return best + 1;
}

int main() {
    cin >> n;
    vector<int> parent(n);
    children.assign(n, {});
    int root = -1;
    for (int v = 0; v < n; v++) {
        cin >> parent[v];
        if (parent[v] == -1) root = v;
        else children[parent[v]].push_back(v);
    }
    int h = height(root);
    int leaves = 0;
    for (int v = 0; v < n; v++)
        if (children[v].empty()) leaves++;
    cout << h << " " << leaves << "\n";
    return 0;
}
@@TESTS
--IN
5
-1 0 0 1 1
--OUT
2 3
--IN
4
-1 0 1 2
--OUT
3 1
@@EXPL
(1) 접근·핵심 아이디어

- 부모 배열을 자식 리스트로 뒤집으면 트리를 위에서 아래로 탐색할 수 있다. 높이는 "자식들 높이의 최댓값 + 1"로 올라오며 계산하고, 리프는 "자식이 하나도 없는 노드"다.

(2) 코드 단계별

- `parent[v]`를 훑어 루트(-1)를 찾고, 나머지는 `children[parent[v]].push_back(v)`로 담는다.
- `height(v)`는 자식이 없으면 0(간선 기준), 있으면 자식 높이의 최댓값에 1을 더해 반환한다.
- 리프 수는 `children[v]`가 빈 노드의 개수로 센다.

(3) 스스로 다시 짤 때 생각 순서

- 부모 배열 → 자식 리스트 변환과 루트 찾기를 먼저 한다.
- 높이는 "올라오며 합치는" 재귀임을 떠올린다(리프에서 0 시작).
- 리프 판정은 반드시 자식 리스트가 비었는지로 한다. 깊은 사슬은 재귀 대신 명시적 스택으로 바꿀 수 있음을 기억한다.
```

**2) 두 노드의 최소 공통 조상(LCA) — 부모 타고 올라가기** · Medium

- **요구사항**: 각 노드의 부모가 주어진 트리에서 두 노드 u, v의 최소 공통 조상(둘 다의 조상이면서 가장 깊은 노드)을 구하라. 자기 자신도 자신의 조상으로 본다.

- **입력**: 첫 줄 N. 둘째 줄 `parent[0..N-1]`(루트 -1). 셋째 줄에 정수 두 개 u v.

- **출력**: LCA 노드 번호.

- **예제**:

  - `7 / -1 0 0 1 1 2 2` (u v = `3 4`) → `1`  (3의 조상: 3,1,0 / 4의 조상: 4,1,0 → 공통 중 가장 깊은 건 1)

  - `7 / -1 0 0 1 1 2 2` (u v = `3 5`) → `0`  (3의 조상: 3,1,0 / 5의 조상: 5,2,0 → 공통은 0)

- **셀프체크**: u의 조상 집합을 `set`으로 모은 뒤 v에서 부모를 타고 올라가며 처음 만나는 조상을 답으로 했는가? u가 v의 조상인 경우(예: u=1, v=3 → 답 1)도 맞는가? 루트를 넘어 -1로 넘어가지 않게 종료 조건을 뒀는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> parent(n);
    for (int v = 0; v < n; v++) cin >> parent[v];
    int u, v;
    cin >> u >> v;

    set<int> anc;
    for (int x = u; x != -1; x = parent[x]) anc.insert(x);

    int y = v;
    while (anc.find(y) == anc.end()) y = parent[y];
    cout << y << "\n";
    return 0;
}
@@TESTS
--IN
7
-1 0 0 1 1 2 2
3 4
--OUT
1
--IN
7
-1 0 0 1 1 2 2
1 3
--OUT
1
@@EXPL
(1) 접근·핵심 아이디어

- u에서 루트까지 부모를 타고 올라가며 만나는 노드를 모두 "u의 조상 집합"으로 모은다. 그다음 v에서 부모를 타고 올라가면서 이 집합에 처음 들어 있는 노드가 곧 가장 깊은 공통 조상(LCA)이다. 자기 자신도 조상으로 본다.

(2) 코드 단계별

- `x = u`에서 시작해 `x != -1`인 동안 `anc`에 담고 `x = parent[x]`로 올라간다.
- `y = v`에서 시작해 `y`가 `anc`에 없으면 계속 `parent[y]`로 올라간다.
- 처음으로 `anc`에 속하는 `y`를 출력한다. u가 v의 조상이면 v가 올라오다 u를 만나 바로 답이 된다.

(3) 스스로 다시 짤 때 생각 순서

- "한쪽 조상을 전부 기록 → 다른 쪽에서 올라가며 첫 교집합" 패턴을 떠올린다.
- 루트의 부모가 -1이므로 for/while 조건으로 -1을 넘지 않게 한다.
- 자기 자신 포함 규칙(u=v면 답 u)을 `set`에 u/v 자신도 넣어 처리한다.
```

**3) 서브트리 노드 수 질의** · Medium

- **요구사항**: 부모 정보로 트리를 만들고, 주어진 각 질의 노드 q에 대해 q를 루트로 하는 서브트리의 노드 수(자기 포함)를 출력하라.

- **입력**: 첫 줄 N. 둘째 줄 `parent[0..N-1]`(루트 -1). 셋째 줄 질의 수 Q. 넷째 줄 질의 노드 q들.

- **출력**: 각 질의의 답을 한 줄에 하나씩.

- **예제**:

  - `6 / -1 0 0 1 1 2` , `Q=3` , `0 1 2` → `6` / `3` / `2`  (0의 서브트리=전체 6; 1의 서브트리={1,3,4}=3; 2의 서브트리={2,5}=2)

  - `3 / -1 0 1` , `Q=1` , `1` → `2`  (1의 서브트리={1,2})

- **셀프체크**: 서브트리 크기를 한 번의 DFS로 모든 노드에 대해 미리 계산해 두었는가(질의마다 다시 세면 O(NQ)로 느려짐)? 크기 계산이 "자식들 크기 합 + 1"인가? 리프의 크기는 1인가?

```runner
        else children[parent[v]].push_back(v);
```

## L2. 이진 트리 개념

**개념**

- 이진 트리(binary tree)는 모든 노드가 자식을 최대 2개(왼쪽·오른쪽)만 갖는 트리다. 왼쪽/오른쪽 구분이 있다는 점이 일반 트리와 다르다(자식이 하나여도 "왼쪽인지 오른쪽인지"가 의미를 갖는다).

- 왜 쓰는가: 자식 수가 2개로 고정되면 구조가 단순해져 순회·탐색·삽입 알고리즘을 깔끔하게 정의할 수 있다. 뒤에 배울 BST와 힙이 모두 이진 트리다.

- 종류:

  - 정 이진 트리(full): 모든 노드가 자식 0개 또는 2개.

  - 완전 이진 트리(complete): 마지막 레벨을 제외하고 꽉 차 있고, 마지막 레벨은 왼쪽부터 채워짐. → 배열로 표현하기 좋다(힙의 기반).

  - 균형 이진 트리: 좌우 높이 차가 작아 높이가 O(log N)에 가까움.

- 표현 방법:

  - 노드 객체(포인터/인덱스): 각 노드가 `left`, `right` 참조(또는 인덱스)를 가짐. 삽입/삭제가 유연.

  - 배열 인덱싱(1-based): 노드 i의 왼쪽 자식 `2*i`, 오른쪽 자식 `2*i+1`, 부모 `i/2`. 완전 이진 트리에 특히 잘 맞는다.

```cpp
#include <bits/stdc++.h>
using namespace std;

// 포인터 기반 노드
struct Node {
    int val;
    Node* left = nullptr;
    Node* right = nullptr;
    Node(int v) : val(v) {}
};

// 배열 기반(1-based). tree[1]이 루트.
// 왼쪽 자식: 2*i, 오른쪽 자식: 2*i+1, 부모: i/2 (정수 나눗셈=몫)
int leftIdx(int i)  { return 2 * i; }
int rightIdx(int i) { return 2 * i + 1; }
int parentIdx(int i){ return i / 2; }
```

- 성질: 높이 h인 이진 트리의 노드 수는 최대 2^(h+1) - 1개. 노드가 N개인 완전 이진 트리의 높이는 floor(log2 N).

**그림으로 보기**

- 완전 이진 트리는 "빈칸 없이 왼쪽부터 채운" 모양이라 배열에 그대로 눕힐 수 있다. 대괄호 안이 배열 인덱스다.

```text
  complete binary tree, 1-based array

              [1]                    idx : 1  2  3  4  5  6  7
            /     \                  val : A  B  C  D  E  F  G
         [2]       [3]
        /   \     /   \              left(i)   = 2*i
     [4]   [5] [6]   [7]             right(i)  = 2*i + 1
                                     parent(i) = i / 2
```

```text
  same tree, 0-based array (C++ vector)

              [0]                    idx : 0  1  2  3  4  5  6
            /     \                  val : A  B  C  D  E  F  G
         [1]       [2]
        /   \     /   \              left(i)   = 2*i + 1
     [3]   [4] [5]   [6]             right(i)  = 2*i + 2
                                     parent(i) = (i-1) / 2
```

- 두 그림은 **모양이 같고 번호만 1씩 밀린 것**이다. 공식이 달라 보이는 이유가 여기서 끝난다.

- 공식이 왜 저 모양인지는 레벨별 시작 번호를 적어 보면 드러난다.

```text
  1-based : each level starts at a power of two

  level 0 : [1]                      1 node    starts at 2^0 = 1
  level 1 : [2][3]                   2 nodes   starts at 2^1 = 2
  level 2 : [4][5][6][7]             4 nodes   starts at 2^2 = 4
  level 3 : [8] ... [15]             8 nodes   starts at 2^3 = 8

  node i on level d is the (i - 2^d)-th node of that level
  its two children start at the 2*(i - 2^d)-th slot of level d+1
  index = 2^(d+1) + 2*(i - 2^d) = 2*i          # 2^(d+1) = 2 * 2^d
```

- 임의 모양이면 배열 대신 `struct Node`를 쓴다. 두 표현이 담는 것을 나란히 두면 이렇다.

```text
  struct Node          vs      vector / array
  ---------------------------------------------------------
   val   : 3                    tree[i]        # 값은 어느 쪽이든 있다
   left  : Node*  ---> ...      2*i   (1-based)
   right : Node*  ---> ...      2*i+1
   "no child" = nullptr         "no child" = index out of range
   # 배열 표현은 빈칸이 없어야만 성립한다
```

**손으로 따라가기**

노드 5개(1-based, 값 A~E)인 완전 이진 트리에서 자식 인덱스를 직접 계산해 본다.

| i | `2*i` | `2*i+1` | 왼쪽 자식 | 오른쪽 자식 |
| --- | --- | --- | --- | --- |
| 1 | 2 | 3 | 2 (있음) | 3 (있음) |
| 2 | 4 | 5 | 4 (있음) | 5 (있음) |
| 3 | 6 | 7 | 6 > 5 → 없음 | 7 > 5 → 없음 |
| 4 | 8 | 9 | 없음 | 없음 |
| 5 | 10 | 11 | 없음 | 없음 |

자식 인덱스가 N을 넘으면 그 자식은 존재하지 않는다. 따라서 리프는 3, 4, 5이고 트리의 높이는 2다.

**왜 이렇게 되는가**

- 왼쪽 자식이 `2*i`인 이유: 위 그림처럼 레벨 d는 인덱스 `2^d`에서 시작하고 노드가 `2^d`개 있다. 레벨 d의 왼쪽에서 k번째(0부터 셈) 노드는 인덱스 `2^d + k`이고, 그 자식 둘은 레벨 d+1에서 왼쪽부터 `2k`, `2k+1`번째 자리를 차지한다. 그러니 왼쪽 자식 인덱스는 `2^(d+1) + 2k = 2*(2^d + k) = 2*i`가 된다. 오른쪽은 그 바로 다음 칸이라 `2*i + 1`이다.

- 0-based 공식이 `2*i+1`, `2*i+2`인 이유: 0-based 인덱스 `j`는 1-based 인덱스 `j+1`과 같은 자리다. 1-based에서 왼쪽 자식은 `2*(j+1)`이고, 이를 다시 0-based로 되돌리려 1을 빼면 `2*j + 1`이다. 오른쪽은 한 칸 뒤라 `2*j + 2`. 부모는 이 식을 뒤집어 `(j-1)/2`다.

- 왜 높이가 약 log2(N)인가: 레벨 d에 들어갈 수 있는 노드는 최대 `2^d`개다. 높이 h까지 다 채우면 `1 + 2 + 4 + ... + 2^h = 2^(h+1) - 1`개다. 노드 N개를 담으려면 `2^(h+1) - 1 >= N`이어야 하므로 `h >= log2(N+1) - 1`, 즉 완전 이진 트리의 높이는 `floor(log2 N)`이다. 이 값이 뒤에 나올 BST·힙 연산 비용의 근거가 된다.

- 왜 완전 이진 트리에만 배열 표현이 좋은가: 위 인덱스 공식은 "중간에 빈칸이 없다"는 전제 위에서 성립한다. 한쪽으로 치우친 트리를 배열에 담으면 쓰지 않는 칸이 지수적으로 늘어(최악 `2^N` 크기) 메모리가 터진다. 임의 모양이면 `struct Node`의 포인터나 자식 인덱스 배열을 쓴다.

- C++의 정수 나눗셈이 여기서 도움이 되는 이유: 부모 공식 `i / 2`는 파이썬의 `i // 2`와 같은 몫 계산이다. C++의 `/`는 정수끼리면 자동으로 몫만 남기므로 `floor`를 부를 필요가 없다. 다만 **음수에서는 0 쪽으로 자른다**(`-3 / 2 == -1`, 파이썬 `-3 // 2 == -2`). 트리 인덱스는 항상 0 이상이라 이 차이가 문제되지 않지만, 다른 문제에서 음수 나눗셈을 파이썬 감각으로 쓰면 조용히 틀린다.

  ```cpp
  int leftIdx(int i)   { return 2 * i; }        // 1-based
  int parentIdx(int i) { return i / 2; }        // 정수 나눗셈 = 몫
  // 0-based 로 바꾸면 전부 1씩 밀린다 — 두 공식을 한 파일에서 섞지 말 것
  int leftIdx0(int i)   { return 2 * i + 1; }
  int parentIdx0(int i) { return (i - 1) / 2; }
  ```

- 배열 표현에서 가장 조심할 것: C++ `vector`는 범위를 벗어난 `tree[i]` 접근을 **검사하지 않는다.** 파이썬 리스트가 `IndexError`를 내는 자리에서 C++은 남의 메모리를 그냥 읽어 쓰레기 값을 돌려주거나 프로그램을 죽인다. 그래서 자식으로 내려가기 전에 `if (2*i <= N)` 같은 범위 검사를 **반드시 손으로** 넣어야 한다. `vector`를 만들 때 `vector<int> tree(N + 1)`처럼 1-based면 크기를 하나 더 잡는 것도 같은 이유다.

**접근 전략**

- 핵심 아이디어: "이 문제에 포인터 표현이 맞나, 배열 표현이 맞나"를 먼저 정한다. 입력이 완전 이진 트리거나 "i번 노드의 자식은 2i, 2i+1" 규칙이면 배열이 훨씬 간단하다. 임의 모양(왼쪽/오른쪽이 자유롭게 비는)이면 인덱스/자식 배열이 낫다.

- 전형적 절차: 노드 구조 정의 → 재귀로 좌우 서브트리를 각각 처리 → 좌우 결과를 합쳐 현재 노드 답 계산. 이진 트리 재귀의 뼈대는 항상 `if (자식 없음) return 기저값;` 으로 시작한다(자식 없음을 0 인덱스나 nullptr로 표현).

- 언제 쓰나: 좌우 구분이 의미 있는 계층(수식 트리, 결정 트리)이나, 뒤의 BST·힙처럼 이진 구조 위에 규칙을 얹을 때.

- 복잡도: 노드 N개를 한 번씩 방문하는 재귀는 시간 O(N), 공간은 재귀 스택 O(높이) — 균형 트리면 O(log N), 한쪽으로 치우치면 O(N). 흔한 실수: "없는 자식"(0 또는 nullptr) 처리를 빠뜨려 에러; 배열 표현에서 0-based/1-based 인덱스를 섞어 쓰기.

**문제**

**1) 이진 트리의 높이와 노드 수** · Easy

- **요구사항**: 각 노드의 왼쪽·오른쪽 자식이 주어진 이진 트리에서 높이(간선 기준)와 전체 노드 수를 구하라.

- **입력**: 첫 줄에 노드 수 N(노드 번호 1..N, 루트는 1). 이후 N줄, i번째 줄에 `left_i right_i`(자식이 없으면 0).

- **출력**: 높이와 노드 수를 공백으로 구분.

- **예제**:

  - `3 / 2 3 / 0 0 / 0 0` → `1 3`  (루트 1의 자식 2,3. 둘 다 리프. 높이 1)

  - `3 / 2 0 / 3 0 / 0 0` → `2 3`  (1→2→3 일직선. 높이 2)

**2) 완전 이진 트리인지 판정** · Medium

- **요구사항**: 이진 트리가 완전 이진 트리(마지막 레벨 전까지 꽉 차고, 마지막 레벨은 왼쪽부터 채워짐)인지 판정하라.

- **입력**: 첫 줄 N(루트 1). 이후 N줄, i번째 줄 `left_i right_i`(없으면 0).

- **출력**: 완전 이진 트리면 `YES`, 아니면 `NO`.

- **예제**:

  - `5 / 2 3 / 4 5 / 0 0 / 0 0 / 0 0` → `YES`  (레벨0: 1, 레벨1: 2,3, 레벨2: 4,5 왼쪽부터. 완전)

  - `5 / 2 3 / 0 4 / 5 0 / 0 0 / 0 0` → `NO`  (2의 왼쪽이 비었는데 오른쪽(4)이 있음 → 왼쪽부터 채움 규칙 위반)

- **셀프체크**: BFS로 레벨 순회하며 "빈 자리(0)를 한 번 본 뒤에 실제 노드가 또 나오면 완전이 아니다"로 판정했는가? 노드 하나(N=1)는 YES인가? 왼쪽이 없는데 오른쪽만 있는 경우를 걸렀는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> leftc(n + 1, 0), rightc(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> leftc[i] >> rightc[i];

    queue<int> q;
    q.push(1);
    bool seenNone = false, complete = true;
    while (!q.empty()) {
        int node = q.front(); q.pop();
        if (node == 0) {
            seenNone = true;
        } else {
            if (seenNone) { complete = false; break; }
            q.push(leftc[node]);
            q.push(rightc[node]);
        }
    }
    cout << (complete ? "YES" : "NO") << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 완전 이진 트리는 레벨 순서(BFS)로 훑으면 실제 노드가 앞쪽에 연속으로 나오고, 빈 자리(0)를 한 번 본 뒤에는 더 이상 실제 노드가 나오면 안 된다. 이 성질을 그대로 검사한다.

(2) 코드 단계별

- 큐에 루트 1을 넣고 BFS를 돈다. 실제 노드는 자식 두 개(0 포함)를 항상 큐에 넣는다.
- 0(빈 자리)을 만나면 `seenNone`을 켠다.
- 그 뒤에 실제 노드(0이 아닌 값)가 또 나오면 왼쪽부터 채움 규칙 위반이므로 `NO`.

(3) 스스로 다시 짤 때 생각 순서

- "완전 = 레벨 순회에서 빈칸 이후 실제 노드 없음"을 핵심으로 잡는다.
- 자식이 없어도 0을 큐에 넣어야 빈칸의 순서가 유지된다.
- 한쪽만 있는 경우(0 다음에 실제 노드)가 자동으로 걸러진다. N=1은 큐에 0만 이어져 YES.
```

**3) 배열 표현 완전 이진 트리의 부모-자식 합** · Easy

- **요구사항**: 1-based 배열로 저장된 완전 이진 트리(값이 배열 순서대로 주어짐)에서, 각 내부 노드에 대해 "자기 값 + 자식 값들의 합"이 최대인 노드의 번호를 구하라(동점이면 작은 번호).

- **입력**: 첫 줄 N. 둘째 줄에 노드 1..N의 값 A[1..N].

- **출력**: 해당 노드 번호.

- **예제**:

  - `5 / 1 2 3 4 5` → `2`  (노드1: 1+2+3=6, 노드2: 2+4+5=11 → 최대는 2)

  - `3 / 5 1 1 ` → `1`  (노드1: 5+1+1=7, 노드2·3은 리프 → 자기값만 1 → 최대는 1)

- **셀프체크**: 노드 i의 자식 인덱스 `2*i`, `2*i+1`이 N을 넘으면 그 자식은 없다고 처리했는가? 리프는 자기 값만 더하는가? 1-based 인덱스를 일관되게 썼는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> a[i];

    long long bestVal = 0;
    int bestNode = 1;
    bool first = true;
    for (int i = 1; i <= n; i++) {
        long long s = a[i];
        if (2 * i <= n) s += a[2 * i];
        if (2 * i + 1 <= n) s += a[2 * i + 1];
        if (first || s > bestVal) {
            bestVal = s;
            bestNode = i;
            first = false;
        }
    }
    cout << bestNode << "\n";
    return 0;
}
@@TESTS

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 1-based 배열 완전 이진 트리에서 노드 i의 자식은 `2*i`, `2*i+1`이다. 각 노드마다 "자기 값 + 존재하는 자식 값들"을 더해 최댓값을 갖는 노드 번호를 찾는다. 동점이면 먼저 나온(작은) 번호가 유지된다.

(2) 코드 단계별

- 값 배열 A를 1-based로 읽는다.
- i를 1..N으로 돌며 `s = a[i]`에서 시작해 `2*i`, `2*i+1`이 N 이하일 때만 그 자식 값을 더한다.
- `s`가 지금까지 최댓값보다 클 때만 갱신하므로 동점에서는 작은 번호가 남는다.

(3) 스스로 다시 짤 때 생각 순서

- 1-based 자식 공식 `2*i`, `2*i+1`을 정확히 쓴다(0-based와 혼동 금지).
- 자식 인덱스가 N을 넘으면 그 자식은 없음 → 더하지 않는다(리프는 자기 값만).
- 동점 처리를 위해 비교는 `>`만 쓰고 `>=`는 쓰지 않는다.
```


## L3. 이진 트리와 탐색

**개념**

- 이진 트리 순회(traversal)는 모든 노드를 빠짐없이 한 번씩 방문하는 방법이다. 깊이 우선(DFS) 계열에 3가지가 있고, "현재 노드를 언제 방문(처리)하느냐"로 구분한다.

  - 전위(preorder): **현재 → 왼쪽 → 오른쪽**. 루트를 먼저 본다. 트리 복사·직렬화에 유용.

  - 중위(inorder): **왼쪽 → 현재 → 오른쪽**. BST에서 이 순서가 곧 오름차순 정렬 결과(뒤 레슨).

  - 후위(postorder): **왼쪽 → 오른쪽 → 현재**. 자식을 다 처리한 뒤 부모 → 서브트리 삭제·크기/합 계산·수식 계산에 유용.

- 별도로 레벨 순회(level-order, BFS): 위에서 아래로, 같은 레벨은 왼쪽→오른쪽. 큐(`<queue>`의 `queue`)로 구현.

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Node {
    int val;
    Node* left = nullptr;
    Node* right = nullptr;
    Node(int v) : val(v) {}
};

void preorder(Node* node, vector<int>& out) {
    if (!node) return;
    out.push_back(node->val);   // 현재
    preorder(node->left, out);  // 왼쪽
    preorder(node->right, out); // 오른쪽
}

void inorder(Node* node, vector<int>& out) {
    if (!node) return;
    inorder(node->left, out);
    out.push_back(node->val);   // 현재를 가운데에
    inorder(node->right, out);
}

void postorder(Node* node, vector<int>& out) {
    if (!node) return;
    postorder(node->left, out);
    postorder(node->right, out);
    out.push_back(node->val);   // 현재를 마지막에
}

void levelOrder(Node* root, vector<int>& out) {
    if (!root) return;
    queue<Node*> q;
    q.push(root);
    while (!q.empty()) {
        Node* node = q.front(); q.pop();
        out.push_back(node->val);
        if (node->left)  q.push(node->left);
        if (node->right) q.push(node->right);
    }
}
```

**그림으로 보기**

- 아래 트리 하나를 세 순회가 각각 어떤 순서로 방문하는지, **노드 옆에 방문 번호를 직접 붙여** 비교한다. 모양은 셋 다 똑같고 번호만 다르다.

- 레벨 순회(BFS)는 위 셋과 계열이 다르다. 깊이로 파고들지 않고 층을 하나씩 완성한다.

- C++ 코드에서 셋을 가르는 것은 딱 한 줄의 위치다. 세로로 세워 보면 한눈에 들어온다.

```text

   go(left);           out.push_back(v);   go(right);
   go(right);          go(right);          out.push_back(v);

```

**손으로 따라가기**

노드 5개짜리 작은 트리 `A(B(D, E), C)`에서 `dfs` 한 번이 세 벡터를 동시에 채우는 과정을 추적한다.

```text

       /   \
    (B)     (C)
    / \
 (D) (E)
```

| 1 | `dfs(A)` 진입 | A | A | | |
| 2 | `dfs(B)` 진입 | A B | A B | | |
| 3 | `dfs(D)` 진입 | A B D | A B D | | |
| 4 | D의 왼쪽 없음 → D 중위 | A B D | A B D | D | |
| 5 | D의 오른쪽 없음 → D 후위 | A B | A B D | D | D |
| 6 | B의 왼쪽 끝남 → B 중위 | A B | A B D | D B | D |
| 7 | `dfs(E)` 진입·종료 | A B | A B D E | D B E | D E |
| 8 | B의 오른쪽 끝남 → B 후위 | A | A B D E | D B E | D E B |
| 9 | A의 왼쪽 끝남 → A 중위 | A | A B D E | D B E A | D E B |
| 10 | `dfs(C)` 진입·종료 | A | A B D E C | D B E A C | D E B C |
| 11 | A의 오른쪽 끝남 → A 후위 | (빔) | A B D E C | D B E A C | D E B C A |

최종: 전위 `A B D E C`, 중위 `D B E A C`, 후위 `D E B C A`. 세 결과가 **한 번의 DFS**에서 `push_back` 시점만 달리해 동시에 만들어졌다.

**왜 이렇게 되는가**

- 왜 `push_back` 위치 하나로 순서가 갈리는가: 재귀 `dfs(v)`는 "왼쪽 서브트리 전체 처리"와 "오른쪽 서브트리 전체 처리"라는 두 덩어리를 순서대로 실행한다. 결과 벡터에서 v가 놓일 자리는 이 두 덩어리에 대한 상대 위치뿐이라 가능한 경우가 앞·가운데·뒤 세 가지밖에 없다. 그게 전위·중위·후위다.

- 왜 후위가 "올라오며 합치는 계산"에 맞는가: 후위는 v를 처리하는 시점에 v의 두 서브트리가 **이미 전부 끝나 있다**. 서브트리 크기·합·높이처럼 자식의 답이 있어야 내 답이 정해지는 계산은 이 시점에서만 안전하다. 반대로 전위는 v를 처리할 때 부모 정보만 확정돼 있어 깊이·누적 경로합처럼 위에서 내려오는 계산에 맞는다. C++에서 `delete`로 트리를 해제할 때 후위를 쓰는 것도 같은 이유다 — 부모를 먼저 지우면 자식으로 가는 포인터를 잃는다.

- 왜 전위+중위로 트리가 복원되는가: 전위의 첫 원소는 언제나 루트다. 중위에서 그 루트를 찾으면 왼쪽 조각이 통째로 왼 서브트리, 오른쪽 조각이 통째로 오른 서브트리다(중위 정의상 루트가 두 서브트리 사이에 딱 한 번 나오므로). 조각 크기가 정해지면 전위도 같은 크기로 잘리고, 같은 논리를 재귀로 반복하면 트리가 유일하게 정해진다. 반면 전위+후위는 자식이 하나뿐인 노드에서 그 자식이 왼쪽인지 오른쪽인지 구분할 근거가 없어 유일하지 않다.

- 복잡도: 각 노드에서 진입·중위·후위 시점이 한 번씩만 생기므로 이벤트 수는 정확히 3N, 즉 시간 O(N)이다. 공간은 동시에 쌓이는 재귀 프레임 수라서 트리의 높이 O(h)다 — 균형이면 O(log N), 사슬이면 O(N). BFS 큐는 한 층을 통째로 담으므로 가장 넓은 층의 폭만큼, 최악 O(N)이다.

- C++ 반복형 전위에서 좌우 push 순서가 뒤집히는 이유: 명시적 스택은 LIFO라 **나중에 넣은 것이 먼저 나온다.** 왼쪽을 먼저 방문하려면 오른쪽을 먼저 `push`해야 한다. 그리고 `st.top()`으로 읽고 `st.pop()`으로 버리는 2단계, 빈 스택 접근 금지가 여기서도 그대로 적용된다.

  ```cpp
  void preorderIter(Node* root, vector<int>& out) {
      if (!root) return;
      stack<Node*> st;
      st.push(root);
      while (!st.empty()) {
          Node* v = st.top(); st.pop();      // 읽고 나서 버린다
          out.push_back(v->val);
          if (v->right) st.push(v->right);   // 오른쪽을 먼저 넣어야
          if (v->left)  st.push(v->left);    // 왼쪽이 먼저 나온다
      }
  }
  ```

- 왜 결과 벡터를 `vector<int>& out`으로 받는가: 재귀 함수가 벡터를 값으로 반환하면 호출마다 복사가 생겨 N번 호출에 O(N²) 복사가 쌓인다. 참조로 하나를 돌려 쓰면 복사가 아예 없다. 위 코드들이 전부 `vector<int>& out`을 인자로 받는 이유가 이것이다. 반대로 `Node*`는 포인터라 복사해도 8바이트뿐이니 값으로 넘겨도 무방하다.

**접근 전략**

- 핵심 아이디어: 세 순회의 코드 뼈대는 동일하고 "현재 노드를 `push_back` 하는 위치"만 다르다. 문제에서 요구하는 방문 순서를 보고 전/중/후를 고른다. "부모보다 자식을 먼저 끝내야 하는 계산"(서브트리 합, 삭제)이면 후위, "루트부터 찍어야" 하면 전위.

- 재귀 ↔ 스택 변환: 재귀가 깊어 스택 오버플로가 걱정되면 명시적 스택(`stack` 또는 `vector`)으로 바꾼다. 전위는 스택에 넣을 때 "오른쪽을 먼저 push, 왼쪽을 나중에 push"해야 왼쪽이 먼저 나온다.

- 순회 결과로 트리 복원: 전위+중위 또는 후위+중위가 있으면 트리를 유일하게 복원할 수 있다(전위의 첫 원소가 루트 → 중위에서 그 위치를 찾아 좌/우로 분할). 전위+후위만으로는 일반적으로 유일하지 않다(주의).

- 언제 쓰나: 트리를 특정 순서로 나열·직렬화·계산할 때. 레벨 순회는 "가장 가까운 것부터", "레벨별 처리"에 쓴다.

- 복잡도: 세 순회 모두 각 노드 1회 방문이라 시간 O(N). 공간은 재귀 스택/명시 스택이 O(높이)(최악 O(N)), 레벨 순회 큐는 최악 O(N)(가장 넓은 레벨 폭). 흔한 실수: 중위/후위에서 `push_back` 위치를 잘못 두기, 명시 스택 전위에서 좌/우 push 순서 뒤집기.

**문제**

**1) 세 가지 순회 출력** · Easy

- **요구사항**: 이진 트리를 전위·중위·후위 순서로 각각 출력하라.

- **입력**: 첫 줄 N(루트 1). 이후 N줄, i번째 줄 `left_i right_i`(없으면 0). 노드 i의 값은 i라고 본다.

- **출력**: 세 줄 — 전위, 중위, 후위 결과(공백 구분).

- **예제**:

  - `3 / 2 3 / 0 0 / 0 0` → `1 2 3` / `2 1 3` / `2 3 1`

  - `3 / 2 0 / 0 3 / 0 0` (1의 왼쪽 2, 2의 오른쪽 3) → `1 2 3` / `2 3 1` / `3 2 1`
    - 검산(전위): 1 → 왼쪽(2 → 왼쪽 없음 → 2 자신 → 오른쪽 3) → 오른쪽 없음 = 1 2 3
    - 검산(중위): 1의 왼쪽 서브트리 먼저 = (2의 왼쪽 없음 → 2 → 2의 오른쪽 3) = 2 3, 그 뒤 1 = 2 3 1
    - 검산(후위): (2의 왼쪽 없음 → 2의 오른쪽 3 → 2) = 3 2, 그 뒤 1 = 3 2 1

- **셀프체크**: 자식 0(없음)을 재귀 기저로 처리했는가? 중위에서 현재 노드를 좌·우 사이에 넣었는가? 후위에서 마지막에 넣었는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

vector<int> leftc, rightc;
vector<int> pre, ino, post;

void dfs(int v) {
    if (v == 0) return;
    pre.push_back(v);
    dfs(leftc[v]);
    ino.push_back(v);
    dfs(rightc[v]);
    post.push_back(v);
}

void printVec(const vector<int>& v) {
    for (size_t i = 0; i < v.size(); i++) {
        if (i) cout << " ";
        cout << v[i];
    }
    cout << "\n";
}

int main() {
    int n;
    cin >> n;
    leftc.assign(n + 1, 0);
    rightc.assign(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> leftc[i] >> rightc[i];
    dfs(1);
    printVec(pre);
    printVec(ino);
    printVec(post);
    return 0;
}

(1) 접근·핵심 아이디어

- 세 순회의 뼈대는 같고 "현재 노드를 언제 리스트에 넣느냐"만 다르다. 한 번의 DFS에서 방문 진입 시(전위), 왼쪽을 마친 뒤(중위), 오른쪽까지 마친 뒤(후위)에 각각 `push_back`하면 세 결과를 동시에 만든다.

(2) 코드 단계별

- 자식 배열을 읽고 노드 값은 번호 그대로 쓴다(0은 없음).
- `dfs(v)`에서 v==0이면 즉시 반환(기저). 아니면 pre push → 왼쪽 재귀 → ino push → 오른쪽 재귀 → post push.
- 세 벡터를 각각 공백으로 이어 세 줄로 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- 전/중/후 = `push_back` 위치만 다르다는 점을 먼저 떠올린다.
- 재귀 기저 `if (v == 0) return;`을 맨 앞에 둔다.
- 중위는 좌·우 사이, 후위는 맨 끝이라는 위치를 정확히 지킨다.
```

**2) 전위+중위로 후위 복원** · Medium

- **요구사항**: 어떤 이진 트리의 전위 순회와 중위 순회 결과(노드 값은 서로 다른 정수)가 주어진다. 이 트리의 후위 순회를 출력하라.

- **입력**: 첫 줄 N. 둘째 줄 전위 수열(N개). 셋째 줄 중위 수열(N개).

- **출력**: 후위 순회 결과(공백 구분).

- **예제**:

  - `3` , 전위 `1 2 3` , 중위 `2 1 3` → `2 3 1`  (전위 첫 1=루트, 중위에서 1의 왼쪽 {2}=왼서브, 오른쪽 {3}=오른서브)

  - `5` , 전위 `1 2 4 5 3` , 중위 `4 2 5 1 3` → `4 5 2 3 1`
    - 검산: 루트 1. 중위에서 1 왼쪽 {4,2,5}, 오른쪽 {3}. 왼서브의 전위 `2 4 5` → 루트 2, 중위 {4}|{5} → 후위 4 5 2. 오른서브 후위 3. 전체 후위 = (왼)4 5 2 (오)3 (루트)1 = 4 5 2 3 1

- **셀프체크**: 전위의 첫 원소를 루트로 잡고 중위에서 그 위치로 좌/우를 나눴는가? 값→중위인덱스 맵으로 분할 위치를 O(1)에 찾았는가(매번 선형 탐색하면 느림)? 후위는 "왼 처리 → 오 처리 → 루트"로 모았는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> pre;
unordered_map<int,int> pos;
vector<int> post;
int preIdx = 0;

void build(int inLo, int inHi) {
    if (inLo > inHi) return;
    int root = pre[preIdx++];
    int mid = pos[root];
    build(inLo, mid - 1);
    build(mid + 1, inHi);
    post.push_back(root);
}

int main() {
    cin >> n;
    pre.resize(n);
    for (int i = 0; i < n; i++) cin >> pre[i];
    for (int i = 0; i < n; i++) {
        int x; cin >> x;
        pos[x] = i;
    }
    build(0, n - 1);
    for (int i = 0; i < n; i++) {
        if (i) cout << " ";
        cout << post[i];
    }
    cout << "\n";
    return 0;
}
@@TESTS

2 1 3
--OUT
2 3 1
--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 전위의 첫 원소가 항상 루트다. 중위에서 그 루트의 위치를 찾으면 왼쪽 조각이 왼 서브트리, 오른쪽 조각이 오른 서브트리다. 전위 포인터를 앞으로 진행시키며 왼→오 순으로 재귀하고, 돌아오는 길에 루트를 `push_back`하면 후위가 만들어진다.

(2) 코드 단계별

- 값→중위인덱스 `pos`(unordered_map)로 분할 위치를 O(1)에 찾는다.
- `build(inLo, inHi)`는 전위 포인터에서 루트를 하나 소비하고, 중위에서 그 위치 `mid`를 기준으로 왼쪽 구간, 오른쪽 구간을 재귀한다.
- 두 재귀가 끝난 뒤 루트를 `post`에 넣는다(후위 = 왼→오→루트).

(3) 스스로 다시 짤 때 생각 순서

- "전위 첫 = 루트, 중위에서 좌/우 분할" 규칙을 먼저 확립한다.
- 전위 소비 순서(루트 → 왼 서브트리 전체 → 오 서브트리 전체)에 맞춰 왼쪽을 먼저 재귀한다.
- 후위 출력이라 `push_back`은 두 재귀 뒤에 둔다. 선형 탐색을 피하도록 맵으로 위치를 캐싱한다.
```

**3) 트리의 레벨별 최댓값** · Medium

- **요구사항**: 이진 트리에서 각 레벨(깊이)마다 노드 값의 최댓값을 위 레벨부터 순서대로 출력하라.

- **입력**: 첫 줄 N(루트 1). 둘째 줄에 노드 값 V[1..N]. 이후 N줄, i번째 줄 `left_i right_i`(없으면 0).

- **출력**: 레벨 0부터 최댓값들을 공백으로 구분해 한 줄.

- **예제**:

  - `3` , 값 `3 5 2` , `2 3 / 0 0 / 0 0` → `3 5`  (레벨0: {3}→3, 레벨1: {5,2}→5)

  - `5` , 값 `1 9 4 2 8` , `2 3 / 4 5 / 0 0 / 0 0 / 0 0` → `1 9 8`  (레벨0:{1}, 레벨1:{9,4}→9, 레벨2:{2,8}→8)

- **셀프체크**: BFS 큐를 레벨 단위로 "현재 큐 크기만큼" 끊어 처리했는가? 각 레벨의 최댓값을 정확히 그 레벨 노드들만으로 구했는가? 빈 자식(0)을 큐에 안 넣었는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> val(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> val[i];
    vector<int> leftc(n + 1, 0), rightc(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> leftc[i] >> rightc[i];

    vector<long long> res;
    queue<int> q;
    q.push(1);
    while (!q.empty()) {
        int sz = (int)q.size();
        long long curMax = LLONG_MIN;
        for (int i = 0; i < sz; i++) {
            int node = q.front(); q.pop();
            curMax = max(curMax, val[node]);
            if (leftc[node] != 0) q.push(leftc[node]);
            if (rightc[node] != 0) q.push(rightc[node]);
        }
        res.push_back(curMax);
    }
    for (size_t i = 0; i < res.size(); i++) {
        if (i) cout << " ";
        cout << res[i];
    }
    cout << "\n";
    return 0;
}

**이 풀이의 새 문법**

- `LLONG_MIN`: `<climits>`가 제공하는 `long long`의 최솟값 상수. "지금까지 본 값보다 항상 작게" 시작해야 하는 최댓값 갱신의 초기값으로 쓴다.

(1) 접근·핵심 아이디어

- 레벨 순회(BFS)에서 큐에 든 원소들은 항상 "같은 레벨"이다. 한 레벨을 처리할 때 현재 큐 크기만큼만 끊어서 꺼내면 그 레벨의 노드들만 모아 최댓값을 구할 수 있다.

(2) 코드 단계별

- 값 배열과 자식 배열을 1-based로 읽는다.
- 큐에 루트 1을 넣고, 매 반복에서 `sz = q.size()`로 이번 레벨 크기를 고정한 뒤 그만큼만 pop한다.
- pop하며 그 레벨 최댓값을 갱신하고, 0이 아닌 자식만 큐에 넣는다. 레벨이 끝나면 최댓값을 결과에 추가한다.

(3) 스스로 다시 짤 때 생각 순서

- "레벨별 처리 = BFS에서 큐 크기만큼 끊기"를 핵심으로 잡는다.
- `sz`를 루프 시작 시 한 번 고정해야 다음 레벨 노드가 섞이지 않는다.
- 빈 자식(0)은 큐에 넣지 않아 존재하는 노드만 다음 레벨로 넘어간다.
```


## L4. 이진 탐색 트리

**개념**

- 이진 탐색 트리(BST, Binary Search Tree)는 "왼쪽 서브트리의 모든 값 < 노드 값 < 오른쪽 서브트리의 모든 값"이라는 규칙을 지키는 이진 트리다(중복은 보통 없다고 가정).

- 왜 쓰는가: 탐색·삽입·삭제를 트리 높이에 비례한 시간에 처리한다. 균형이 잡히면 O(log N)로 정렬 상태를 유지하며 동적으로 원소를 넣고 뺄 수 있다. 정렬 배열은 삽입/삭제가 O(N)인데 BST는 그보다 빠를 수 있다.

- 핵심 동작:

  - 탐색: 루트에서 시작해 찾는 값이 작으면 왼쪽, 크면 오른쪽으로 내려간다.

  - 삽입: 탐색과 같은 경로로 내려가 빈 자리(없는 자식)에 새 노드를 단다.

  - 중위 순회하면 값이 오름차순으로 나온다(BST의 결정적 성질).

  - 삭제: 자식 0개면 그냥 제거, 1개면 그 자식으로 대체, 2개면 오른쪽 서브트리의 최솟값(또는 왼쪽 서브트리의 최댓값)으로 값을 바꾸고 그 노드를 삭제.

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Node {
    int val;
    Node* left = nullptr;
    Node* right = nullptr;
    Node(int v) : val(v) {}
};

Node* insert(Node* root, int val) {
    if (!root) return new Node(val);
    if (val < root->val)      root->left  = insert(root->left, val);
    else if (val > root->val) root->right = insert(root->right, val);
    // val == root->val 이면 무시(중복 없음 가정)
    return root;
}

bool search(Node* root, int val) {
    while (root) {
        if (val == root->val) return true;
        root = (val < root->val) ? root->left : root->right;
    }
    return false;
}
```

**그림으로 보기**

- BST의 규칙은 "노드 하나"가 아니라 **서브트리 전체**에 걸린다. 왼쪽에 있는 값은 하나도 빠짐없이 나보다 작다.

```text
  BST rule : all of left subtree < node < all of right subtree

              (8)
            /     \
         (3)       (10)
        /   \         \
     (1)    (6)       (14)
            / \       /
         (4) (7)   (13)
```

- 탐색은 매 단계에서 한쪽 서브트리를 통째로 버린다. 값 7을 찾는 경로.

```text
  search 7 : one comparison, one direction

              (8)          7 < 8   -> go left
            /
         (3)               7 > 3   -> go right
            \
            (6)            7 > 6   -> go right
               \
               (7)         found                # 비교 4번 = 높이+1
```

- 중위 순회는 이 트리를 그대로 정렬 결과로 펴 준다.

```text
  inorder walk of the same tree

  (1) (3) (4) (6) (7) (8) (10) (13) (14)
   ^                                   ^
  min                                 max       # 언제나 오름차순
```

- 삭제는 자식 수에 따라 세 경우로 갈린다.

```text
  case 1 : no child                  # 그냥 떼어낸다

      (6)                (6)
      / \        ->         \
   (4) (7)                  (7)          delete 4
```

```text
  case 2 : one child                 # 그 자식을 자리에 끌어올린다

     (10)              (10)
        \       ->        \
        (14)              (13)           delete 14
        /
     (13)
```

```text
  case 3 : two children              # 오른쪽 서브트리의 최솟값으로 값을 덮는다

        (3)                (4)
       /   \              /   \
    (1)     (6)   ->   (1)     (6)       delete 3
            / \                  \
         (4) (7)                 (7)     successor of 3 is 4
```

- 최악의 경우: 정렬된 순서로 넣으면 트리가 한쪽 사슬이 된다.

```text
  insert 1, 2, 3, 4, 5 in this order

   (1)
      \
      (2)
         \
         (3)
            \
            (4)
               \
               (5)      # 높이 N-1, 사실상 연결 리스트
```

- 그래서 실전 C++에서는 직접 만든 BST보다 표준 컨테이너를 쓴다. 둘의 관계는 이렇다.

```text
  hand-written BST   vs   std::set / std::map
  ---------------------------------------------------------
   shape : depends on insert order   shape : always balanced
   worst : O(N) if sorted input      worst : O(log N) guaranteed
   inorder walk = sorted             for (x : s) = sorted
   # std::set 은 균형 이진 탐색 트리(보통 red-black tree)다
   # 개념은 BST 로 이해하고, 코드는 set / map 을 쓴다
```

**손으로 따라가기**

빈 BST에 `4 2 6 1 3`을 차례로 삽입한다.

| 단계 | 넣는 값 | 비교 경로 | 최종 자리 |
| --- | --- | --- | --- |
| 1 | 4 | (트리가 빔) | 루트 |
| 2 | 2 | 2 < 4 → 왼쪽 | 4의 왼쪽 자식 |
| 3 | 6 | 6 > 4 → 오른쪽 | 4의 오른쪽 자식 |
| 4 | 1 | 1 < 4 → 왼쪽, 1 < 2 → 왼쪽 | 2의 왼쪽 자식 |
| 5 | 3 | 3 < 4 → 왼쪽, 3 > 2 → 오른쪽 | 2의 오른쪽 자식 |

완성된 트리를 중위 순회하면 `1 2 3 4 6` — 넣은 순서와 무관하게 오름차순이다.

**왜 이렇게 되는가**

- 왜 중위 순회가 정렬 결과인가: 서브트리 크기에 대한 귀납으로 보인다. 노드가 없으면 빈 수열이라 정렬돼 있다. 노드 v에서는 (왼 서브트리의 중위) + (v) + (오른 서브트리의 중위) 순으로 나오는데, 귀납 가정으로 앞뒤 두 조각은 각각 정렬돼 있고, BST 규칙이 "왼쪽 전부 < v < 오른쪽 전부"를 보장하므로 셋을 이어 붙인 수열도 정렬돼 있다. 따라서 어떤 순서로 삽입했든 중위 결과는 같은 오름차순이다.

- 왜 탐색·삽입·삭제가 O(높이)인가: 매 단계에서 값을 한 번 비교하고 왼쪽·오른쪽 중 **한쪽으로만** 내려간다. 되돌아오는 일이 없으므로 방문 노드 수는 루트에서 리프까지의 길이, 즉 최대 h+1개다. 비교와 이동이 각각 O(1)이라 전체가 O(h)다.

- 왜 균형이면 O(log N), 치우치면 O(N)인가: h는 트리 모양이 결정한다. 좌우가 고르면 매번 후보가 절반씩 줄어 h ≈ log2 N이고, 정렬된 값을 순서대로 넣으면 새 값이 늘 오른쪽 끝에 붙어 h = N-1이 된다. 위 사슬 그림에서 5를 찾으려면 5번 비교해야 하니 벡터를 처음부터 훑는 것과 다를 게 없다. BST의 O(log N)은 "구조가 균형일 때만" 성립하는 조건부 성능이다.

- 왜 자식 2개 삭제에 오른쪽 서브트리의 최솟값을 쓰는가: 삭제할 자리를 채울 값은 "왼쪽 전부보다는 크고 오른쪽 나머지 전부보다는 작은" 값이어야 BST 규칙이 유지된다. 중위 순서에서 v의 바로 다음 값(오른쪽 서브트리의 최솟값)이 정확히 그런 값이고, 왼쪽 서브트리의 최댓값(바로 앞 값)도 마찬가지다. 게다가 그 최솟값 노드는 왼쪽 자식이 없어 case 1이나 case 2로 쉽게 지워진다.

- 왜 재귀 삽입이 `Node*`를 반환하고 그 값을 다시 대입해야 하는가: `insert(root->left, val)` 안에서 `root->left`는 **값이 복사돼 넘어간 포인터**다. 그 안에서 `new Node(val)`을 만들어도 부모의 `left` 필드는 여전히 `nullptr`이다. 그래서 돌려받은 포인터를 `root->left = insert(root->left, val);`처럼 **다시 대입**해야 트리가 자란다. (`Node*&`처럼 포인터의 참조로 받으면 대입 없이도 되지만, 반환-대입 형태가 더 흔하고 읽기 쉽다.)

  ```cpp
  root->left = insert(root->left, val);   // 돌려받은 서브트리를 다시 매단다
  insert(root->left, val);                // 이렇게 쓰면 트리가 자라지 않는다
  ```

- C++ 실전에서는 대개 `std::set`/`std::map`을 쓴다: 직접 만든 BST는 정렬된 입력에서 O(N)으로 무너지지만, `std::set`은 내부적으로 균형을 잡는 이진 탐색 트리(보통 red-black tree)라 **어떤 입력에서도 O(log N)을 보장**한다. 게다가 `lower_bound`/`upper_bound`로 "x 이상인 첫 값" 같은 근접 질의가 바로 되고, 범위 기반 for 문으로 순회하면 그게 곧 중위 순회다. 개념은 BST로 이해하되 코드는 표준 컨테이너를 쓰는 것이 정석이다.

  ```cpp
  set<int> s = {4, 2, 6, 1, 3};
  for (int x : s) cout << x << ' ';        // 1 2 3 4 6  (중위 순회 = 정렬)
  auto it = s.lower_bound(5);              // 5 이상인 첫 값 -> 6   O(log N)
  if (s.count(3)) s.erase(3);              // 존재 확인 후 삭제      O(log N)
  ```

**접근 전략**

- 핵심 아이디어: "작으면 왼쪽, 크면 오른쪽" 규칙으로 한 방향씩만 내려가므로 매 단계 후보가 절반가량 준다(이진 탐색과 같은 발상, 단 자료는 트리). 탐색·삽입 코드가 사실상 동일한 경로를 따른다.

- 정렬 활용: BST에 값을 다 넣고 중위 순회하면 정렬된 수열을 얻는다. "정렬 상태 유지 + 특정 값의 순위/범위" 문제에 잘 맞는다. k번째 작은 값은 중위 순회 중 k번째 원소.

- 언제 쓰나: 동적으로 원소가 추가/삭제되면서 "존재 여부, 정렬 순서, 근접 값(바로 큰/작은 값)"을 물을 때. 단, C++ 실전에서 균형까지 필요하면 직접 구현보다 표준 라이브러리 `set`/`map`(내부적으로 균형 BST)이 더 실용적일 때가 많다(개념은 BST로 이해하되 도구 선택은 상황에 맞게).

- 복잡도: 탐색·삽입·삭제 모두 O(높이). 균형 잡히면 O(log N), 최악(정렬된 값을 순서대로 삽입 → 한쪽으로 치우친 사슬)은 O(N). 중위 순회 O(N). 공간 O(N). 흔한 실수: 포인터 기반에서 삽입 결과를 부모에 다시 연결하지 않아 트리가 안 자람; 삭제에서 자식 2개 케이스 누락; 중복 값 처리 미정의.

> 참고: 표준 라이브러리 `std::set`/`std::map`은 균형 이진 탐색 트리(레드-블랙 트리)로 구현돼 삽입·탐색·삭제가 O(log N)이다. BST 개념을 직접 구현해 본 뒤에는 실전에서 이 컨테이너를 대안으로 고려한다.

**문제**

**1) BST 삽입 후 중위 순회** · Easy

- **요구사항**: 정수들을 주어진 순서대로 빈 BST에 삽입한 뒤, 중위 순회 결과를 출력하라(결과는 오름차순이 됨을 확인).

- **입력**: 첫 줄 N. 둘째 줄에 서로 다른 정수 N개(삽입 순서).

- **출력**: 중위 순회 결과(공백 구분).

- **예제**:

  - `5 / 4 2 6 1 3` → `1 2 3 4 6`  (삽입해 만든 BST를 중위 순회하면 오름차순)

  - `3 / 2 1 3` → `1 2 3`

- **셀프체크**: 삽입에서 빈 자식 자리(-1)에 새 노드를 제대로 연결했는가? 중위 순회가 왼→현재→오 순인가? 어떤 삽입 순서든 중위 결과가 오름차순으로 같은지 확인했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

struct Node { int val, left, right; };

int main() {
    int n;
    cin >> n;
    vector<int> nums(n);
    for (int i = 0; i < n; i++) cin >> nums[i];

    vector<Node> t;
    t.reserve(n);
    int root = -1;
    for (int x : nums) {
        if (root == -1) {
            t.push_back({x, -1, -1});
            root = 0;
            continue;
        }
        int cur = root;
        while (true) {
            if (x < t[cur].val) {
                if (t[cur].left == -1) { t.push_back({x, -1, -1}); t[cur].left = (int)t.size() - 1; break; }
                cur = t[cur].left;
            } else if (x > t[cur].val) {
                if (t[cur].right == -1) { t.push_back({x, -1, -1}); t[cur].right = (int)t.size() - 1; break; }
                cur = t[cur].right;
            } else break;
        }
    }

    vector<int> out;
    vector<int> stk;
    int cur = root;
    while (!stk.empty() || cur != -1) {
        while (cur != -1) { stk.push_back(cur); cur = t[cur].left; }
        cur = stk.back(); stk.pop_back();
        out.push_back(t[cur].val);
        cur = t[cur].right;
    }
    for (size_t i = 0; i < out.size(); i++) {
        if (i) cout << " ";
        cout << out[i];
    }
    cout << "\n";
    return 0;
}

(2) 코드 단계별

- 노드를 `vector<Node>`에 담고 자식은 인덱스(-1은 없음)로 가리킨다(서로 다른 정수 가정).
- 각 값에 대해 루트부터 while로 내려가며 비교, 빈 자식 자리(-1)를 만나면 새 노드를 만들어 연결한다.
- 중위 순회는 명시적 스택으로 왼쪽 끝까지 내려가며 push → pop해서 값 출력 → 오른쪽으로 이동을 반복한다.

(3) 스스로 다시 짤 때 생각 순서

- 삽입 경로("작으면 왼쪽")를 while로 구현하고 빈 자리(-1)에 연결한다.
- 중위 순회 = 왼→현재→오임을 떠올린다. 반복형 중위는 "왼쪽 끝까지 push → pop 출력 → 오른쪽"이 뼈대다.
- 어떤 순서로 넣어도 중위 결과가 정렬됨을 확인한다(내림차순 입력도 같은 정렬 결과).
```

**2) BST에서 k번째로 작은 값** · Medium

- **요구사항**: 값들을 BST에 넣은 뒤 k번째로 작은 값을 구하라(k는 1-based).

- **입력**: 첫 줄 N과 k. 둘째 줄에 서로 다른 정수 N개(삽입 순서).

- **출력**: k번째로 작은 값.

- **예제**:

  - `5 2 / 4 2 6 1 3` → `2`  (정렬하면 1 2 3 4 6, 2번째는 2)

  - `4 4 / 10 20 5 15` → `20`  (정렬 5 10 15 20, 4번째는 20)

- **셀프체크**: 중위 순회를 하며 방문 카운트가 k가 되는 순간의 값을 답으로 했는가? k를 찾는 즉시 순회를 멈춰 낭비를 줄였는가(선택)? k가 N보다 크면 어떻게 처리할지 정의했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

struct Node { int val, left, right; };

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> nums(n);
    for (int i = 0; i < n; i++) cin >> nums[i];

    vector<Node> t;
    t.reserve(n);
    int root = -1;
    for (int x : nums) {
        if (root == -1) { t.push_back({x, -1, -1}); root = 0; continue; }
        int cur = root;
        while (true) {
            if (x < t[cur].val) {
                if (t[cur].left == -1) { t.push_back({x, -1, -1}); t[cur].left = (int)t.size() - 1; break; }
                cur = t[cur].left;
            } else if (x > t[cur].val) {
                if (t[cur].right == -1) { t.push_back({x, -1, -1}); t[cur].right = (int)t.size() - 1; break; }
                cur = t[cur].right;
            } else break;
        }
    }

    int count = 0, ans = 0;
    vector<int> stk;
    int cur = root;
    while (!stk.empty() || cur != -1) {
        while (cur != -1) { stk.push_back(cur); cur = t[cur].left; }
        cur = stk.back(); stk.pop_back();
        count++;
        if (count == k) { ans = t[cur].val; break; }
        cur = t[cur].right;
    }
    cout << ans << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- BST의 중위 순회는 오름차순이므로, 중위 순회하며 방문 개수를 세다가 k번째로 꺼내는 값이 곧 "k번째로 작은 값"이다. k에 도달하면 즉시 멈춰 불필요한 순회를 줄인다.

(2) 코드 단계별

- 삽입은 앞 문제와 같이 "작으면 왼쪽, 크면 오른쪽"으로 내려가 빈 자리(-1)에 연결한다.
- 반복형 중위 순회로 왼쪽 끝까지 내려간 뒤 pop할 때마다 `count`를 1 늘린다.
- `count == k`가 되는 순간의 값을 답으로 저장하고 순회를 중단한다.

(3) 스스로 다시 짤 때 생각 순서

- "k번째 작은 값 = 중위 순회 k번째 방문"을 핵심으로 잡는다.
- 반복형 중위 뼈대(왼쪽 끝까지 push → pop → 오른쪽)를 그대로 쓰되 pop 시점에 카운트한다.
- k에 도달하면 break로 조기 종료한다(k가 N 이하라고 가정).
```

**3) 삽입/탐색 질의 처리** · Medium

- **요구사항**: 초기 빈 BST에 대해 두 종류 질의를 처리하라. `1 x`는 x를 삽입(이미 있으면 무시), `2 x`는 x가 트리에 있으면 `YES` 없으면 `NO` 출력.

- **입력**: 첫 줄 질의 수 Q. 이후 Q줄, 각 줄 `타입 값`.

- **출력**: 타입 2 질의마다 한 줄씩 `YES`/`NO`.

- **예제**:

  - `5` , `1 5` / `1 3` / `2 3` / `2 8` / `1 8` → `YES` / `NO`
    - 검산: 5,3 삽입 → 3 조회 YES, 8 조회 NO, 이후 8 삽입.

  - `4` , `2 1` / `1 1` / `2 1` / `2 2` → `NO` / `YES` / `NO`

- **셀프체크**: 탐색을 반복문(while)으로 O(높이)에 했는가? 삽입에서 중복을 무시했는가? 최악(정렬 순 삽입) 입력에서 한쪽 사슬이 되어 느려질 수 있음을 인지했는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

struct Node { int val, left, right; };

vector<Node> t;
int root = -1;

void insert(int x) {
    if (root == -1) { t.push_back({x, -1, -1}); root = 0; return; }
    int cur = root;
    while (true) {
        if (x < t[cur].val) {
            if (t[cur].left == -1) { t.push_back({x, -1, -1}); t[cur].left = (int)t.size() - 1; return; }
            cur = t[cur].left;
        } else if (x > t[cur].val) {
            if (t[cur].right == -1) { t.push_back({x, -1, -1}); t[cur].right = (int)t.size() - 1; return; }
            cur = t[cur].right;
        } else return;
    }
}

bool search(int x) {
    int cur = root;
    while (cur != -1) {
        if (x == t[cur].val) return true;
        cur = (x < t[cur].val) ? t[cur].left : t[cur].right;
    }
    return false;
}

int main() {
    int Q;
    cin >> Q;
    for (int i = 0; i < Q; i++) {
        int type, x;
        cin >> type >> x;
        if (type == 1) insert(x);
        else cout << (search(x) ? "YES" : "NO") << "\n";
    }
    return 0;
}

(1) 접근·핵심 아이디어

- BST에서 삽입과 탐색은 사실상 같은 경로를 따른다. "작으면 왼쪽, 크면 오른쪽"으로 내려가며, 삽입은 빈 자리에 노드를 달고 탐색은 값이 일치하는지 확인한다. 중복 삽입은 무시한다.

(2) 코드 단계별

- 노드를 `vector<Node>`에 담고 자식은 인덱스(-1은 없음)로 가리킨다.
- `insert(x)`는 while로 내려가다 빈 자식 자리(-1)에 새 노드를 연결한다. 같은 값을 만나면 그냥 return(중복 무시).
- `search(x)`는 while로 내려가며 일치하면 true, 끝(-1)까지 못 만나면 false.
- 타입 1은 삽입, 타입 2는 탐색 결과 YES/NO를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- 삽입·탐색이 같은 하강 경로임을 떠올려 while 뼈대를 공유한다.
- 중복은 `x == t[cur].val`에서 아무 것도 안 하고 종료해 무시한다.
- 탐색은 반복문으로 O(높이)에 끝낸다(정렬 순 삽입이면 사슬이 되어 느려질 수 있음을 인지).
```

## L5. Heap

**개념**

- 힙(heap)은 "부모가 자식보다 우선(작거나/크거나)"이라는 규칙만 지키는 완전 이진 트리다. 최소 힙(min-heap)은 부모 ≤ 자식이라 루트가 항상 최솟값, 최대 힙(max-heap)은 부모 ≥ 자식이라 루트가 항상 최댓값.

- 왜 쓰는가: "지금 남은 것 중 최소(또는 최대)를 반복해서 빠르게 꺼내야 할 때". 정렬 배열은 삽입이 O(N)이지만 힙은 삽입·삭제가 O(log N)이면서 최솟값 조회는 O(1). 우선순위 큐(priority queue)의 표준 구현.

- 배열 표현(완전 이진 트리라 딱 맞음, 0-based): 노드 i의 왼쪽 자식 `2*i+1`, 오른쪽 자식 `2*i+2`, 부모 `(i-1)/2`.

- 주의(인덱스 기준 대조): L2의 배열 이진 트리는 **1-based**로 왼쪽 자식 `2*i`, 오른쪽 자식 `2*i+1`, 부모 `i/2`였다. 힙을 배열로 직접 구현할 때는 흔히 **0-based**를 써서 공식이 `2*i+1`/`2*i+2`/`(i-1)/2`로 달라진다. 같은 "완전 이진 트리 → 배열" 아이디어지만 시작 인덱스가 0인지 1인지에 따라 +1이 붙고 안 붙으니, 두 공식을 섞어 쓰지 않도록 주의한다.

  | 기준 | 왼쪽 자식 | 오른쪽 자식 | 부모 |
  | --- | --- | --- | --- |
  | 1-based(L2 트리) | `2*i` | `2*i+1` | `i/2` |
  | 0-based(힙) | `2*i+1` | `2*i+2` | `(i-1)/2` |

- 핵심 동작(최소 힙):

  - push: 배열 끝에 추가 후, 부모보다 작으면 부모와 교환하며 위로(up-heapify/sift-up).

  - pop(최솟값 제거): 루트를 배열 마지막 원소로 덮고 크기 줄인 뒤, 자식 중 더 작은 쪽과 비교·교환하며 아래로(down-heapify/sift-down).

- C++ `<queue>`의 `priority_queue`: 기본은 **최대 힙**(`top()`이 최댓값). 최소 힙이 필요하면 `priority_queue<int, vector<int>, greater<int>>`로 비교자를 바꾼다. (`<algorithm>`의 `make_heap`/`push_heap`/`pop_heap`으로 벡터를 직접 힙으로 다룰 수도 있다.)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 최소 힙: 비교자를 greater<int>로 지정
    priority_queue<int, vector<int>, greater<int>> minh;
    minh.push(5);
    minh.push(1);
    minh.push(3);
    cout << minh.top() << "\n";  // 1 (항상 최솟값, O(1))
    minh.pop();                  // 최솟값 제거 (O(log N))

    // 기본은 최대 힙: top()이 최댓값
    priority_queue<int> maxh;
    for (int x : {5, 1, 3}) maxh.push(x);
    int biggest = maxh.top();    // 5
    return 0;
}
```

**그림으로 보기**

- 힙은 "완전 이진 트리 모양"과 "부모 ≤ 자식"이라는 두 규칙만 지킨다. 형제끼리의 크기는 **아무 상관 없다** — 그래서 정렬보다 싸다.

```text
  min-heap [1, 3, 5, 7, 9]        # 0-based vector<int>

        (1)                       idx : 0  1  2  3  4
       /   \                      arr : 1  3  5  7  9
    (3)     (5)
    / \                           3 and 5 are NOT ordered
 (7) (9)                          # 형제 간 순서는 규칙이 아니다
```

- push는 끝에 붙인 뒤 부모와 비교하며 **위로** 올라간다(sift-up). 값 2를 넣어 보자.

```text
  step 0 : push_back 2 at the end

        (1)                       idx : 0  1  2  3  4  5
       /   \                      arr : 1  3  5  7  9  2
    (3)     (5)
    / \     /                     new index 5
 (7) (9) (2)                      parent = (5-1)/2 = 2
```

```text
  step 1 : arr[5]=2 < arr[2]=5  -> swap

        (1)                       arr : 1  3  2  7  9  5
       /   \
    (3)     (2)                   now at index 2
    / \     /                     parent = (2-1)/2 = 0
 (7) (9) (5)
```

```text
  step 2 : arr[2]=2 > arr[0]=1  -> stop

        (1)                       arr : 1  3  2  7  9  5
       /   \
    (3)     (2)                   # 올라간 거리는 최대 트리 높이만큼
```

- pop은 반대다. 루트를 꺼내고 **마지막 원소를 루트로 옮긴 뒤** 아래로 내려보낸다(sift-down).

```text
  step 0 : take out root 1, move last element 5 to index 0

        (5)                       arr : 5  3  2  7  9
       /   \
    (3)     (2)                   returned value : 1
    / \
 (7) (9)
```

```text
  step 1 : children of 0 are 1 and 2 -> min(3, 2) = 2

        (2)                       arr : 2  3  5  7  9
       /   \                      swap arr[0] and arr[2]
    (3)     (5)
    / \                           # 더 작은 자식과 바꿔야 규칙이 지켜진다
 (7) (9)
```

```text
  step 2 : index 2 -> child 2*2+1 = 5 is out of range -> stop

        (2)                       arr : 2  3  5  7  9
       /   \
    (3)     (5)                   heap property restored
```

- 그런데 C++ `priority_queue`는 위 그림과 **부호가 반대**다. 기본이 최대 힙이라 루트가 최댓값이다.

```text
  C++ default is a MAX heap  (python heapq is a MIN heap)
  ---------------------------------------------------------
   priority_queue<int> pq;                       # top() = 최댓값
        (9)
       /   \                                     arr : 9  7  5 ...
    (7)     (5)                                  parent >= child

   priority_queue<int, vector<int>, greater<int>> pq;   # top() = 최솟값
        (1)
       /   \                                     parent <= child
    (3)     (5)
   # 비교자 자리에 greater 를 넣어야 위쪽 그림들과 같은 최소 힙이 된다
```

**손으로 따라가기**

빈 최소 힙에 `5 1 4 2`를 차례로 push할 때 배열이 어떻게 바뀌는지 추적한다(0-based, 부모 = `(i-1)/2`).

| 단계 | push | 끝에 붙인 뒤 | sift-up 비교 | 결과 배열 |
| --- | --- | --- | --- | --- |
| 1 | 5 | `[5]` | 루트라 비교 없음 | `[5]` |
| 2 | 1 | `[5, 1]` | idx1의 부모 idx0: 1 < 5 → 교환 | `[1, 5]` |
| 3 | 4 | `[1, 5, 4]` | idx2의 부모 idx0: 4 > 1 → 정지 | `[1, 5, 4]` |
| 4 | 2 | `[1, 5, 4, 2]` | idx3의 부모 idx1: 2 < 5 → 교환 → idx1의 부모 idx0: 2 > 1 → 정지 | `[1, 2, 4, 5]` |

최종 `[1, 2, 4, 5]`는 정렬된 것처럼 보이지만 우연이다. 보장되는 건 `arr[0]`이 최솟값이라는 것뿐이다. 여기서 pop을 하면 1을 반환하고 마지막 5를 루트로 올린 뒤 sift-down해 `[2, 5, 4]`가 된다.

같은 입력을 C++ 컨테이너 두 개에 넣어 보면 기본값의 차이가 그대로 드러난다.

| 넣은 값 | `priority_queue<int>` | `priority_queue<int, vector<int>, greater<int>>` |
| --- | --- | --- |
| 5, 1, 4, 2 | `top()` = **5** (최댓값) | `top()` = **1** (최솟값) |
| pop 순서 | 5 → 4 → 2 → 1 | 1 → 2 → 4 → 5 |

**왜 이렇게 되는가**

- 왜 push/pop이 O(log N)인가: 힙은 항상 완전 이진 트리라 L2에서 유도한 대로 높이가 `floor(log2 N)`이다. sift-up은 부모로 한 칸씩만 올라가고 sift-down은 자식으로 한 칸씩만 내려가므로, 이동 횟수는 아무리 많아야 높이만큼이다. 한 칸 이동에 드는 비교·교환이 O(1)이니 전체가 O(log N)이다. 반면 루트는 늘 `arr[0]`(=`top()`)에 있으므로 극값 조회는 O(1)다.

- 왜 sift-down에서 "더 작은 자식"과 바꿔야 하는가: 더 큰 자식과 바꾸면 그 자식이 새 부모가 되면서 나머지 형제보다 커져 규칙이 깨진다. 두 자식 중 작은 쪽을 올려야 올라간 값이 양쪽 자식보다 확실히 작아진다(최대 힙이면 반대로 더 큰 자식).

- 왜 완전 이진 트리 모양을 고집하는가: 모양이 완전해야 배열에 빈칸 없이 담기고 인덱스 공식(`2i+1`, `2i+2`, `(i-1)/2`)이 성립한다. 그래서 push는 "벡터 맨 뒤에 `push_back`", pop은 "맨 뒤 원소를 루트로" 옮기는 것만으로 모양이 유지된다. 임의 위치를 지우지 않는 이유도 여기 있다 — `priority_queue`에 중간 원소 삭제 기능이 아예 없는 것이 그 증거다.

- 왜 정렬보다 유리한가: 전부 정렬하면 O(N log N)이고, 원소가 하나 추가될 때마다 정렬 상태를 유지하려면 삽입에 O(N)이 든다. 힙은 "전체 순서"를 포기하고 "극값 하나"만 보장하므로 삽입·삭제가 O(log N)으로 떨어진다. 필요한 정보가 극값 하나뿐일 때 정렬은 과한 작업이다.

- **왜 C++ 기본이 최대 힙인가, 그리고 왜 그것이 함정인가**: `priority_queue`의 셋째 인자는 비교자이고 기본값이 `less<T>`다. 표준은 "비교자가 `true`를 주는 쪽이 아래로 간다"로 정의하므로 `less`면 큰 값이 위로 올라와 **최대 힙**이 된다. 파이썬 `heapq`는 정반대로 최소 힙이라, 파이썬 코드를 옮길 때 `heappop`을 `pq.top(); pq.pop();`으로만 바꾸면 **에러 없이 정반대 답**이 나온다. 최소 힙이 필요하면 반드시 비교자를 `greater<T>`로 바꾼다.

  ```cpp
  priority_queue<int> maxh;                                  // 기본 = 최대 힙
  priority_queue<int, vector<int>, greater<int>> minh;       // 최소 힙
  minh.push(5); minh.push(1);
  int x = minh.top();   // 1  <- 읽기
  minh.pop();           //    <- 버리기 (값을 안 돌려준다)
  // int x = minh.pop();   컴파일 에러 : pop 의 반환형은 void
  ```

- 파이썬의 `-x` 뒤집기를 C++에서 굳이 쓸 필요가 없는 이유: 파이썬엔 최대 힙이 없어서 부호를 뒤집는 우회가 필요했지만(`a < b`면 `-a > -b`라 성립한다), C++은 비교자를 갈아 끼우면 그만이다. 부호 뒤집기는 되돌리기를 잊는 순간 음수가 그대로 출력되는 버그를 만드니 쓰지 않는 편이 낫다. 다만 `pair`를 넣을 때 **첫 원소로 먼저 비교하고 같으면 둘째 원소로 비교**하는 규칙은 파이썬 튜플과 같으므로, `(비용, 번호)` 우선순위 큐 패턴은 그대로 옮겨 쓸 수 있다.

  ```cpp
  // (비용, 정점) 최소 힙 — 다익스트라에서 그대로 쓰는 형태
  priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;
  pq.push({7, 3});
  pq.push({2, 5});
  auto [cost, node] = pq.top(); pq.pop();   // {2, 5} 가 먼저 나온다
  ```

- 빈 힙 접근은 여기서도 미정의 동작: `pq.empty()`가 참인데 `top()`이나 `pop()`을 부르면 파이썬처럼 `IndexError`가 나지 않고 쓰레기 값을 읽거나 프로그램이 죽는다. `while (!pq.empty())` 조건을 먼저 두는 습관이 정확성의 일부다.

**접근 전략**

- 핵심 아이디어: "매번 전체를 정렬할 필요 없이, 극값(최소/최대) 하나만 빠르게 필요"할 때 힙을 쓴다. 넣고 빼는 사이사이에 데이터가 계속 바뀌어도 루트(`top()`)만 보면 현재 극값을 O(1)에 알 수 있다.

- 전형적 패턴:

  - 우선순위 큐: `pair<우선순위, 데이터>`를 push하면 우선순위(첫 원소) 기준으로 정렬돼 pop된다(동점이면 두 번째 원소로 비교되니 비교 가능한 값을 넣거나 카운터를 끼운다).

  - k개 유지: "가장 큰 k개"는 크기 k의 최소 힙을 유지하며 루트(최솟값)보다 큰 값이 오면 교체 → k번째 큰 값 등을 O(N log k)에.

  - 여러 정렬 스트림 병합, 다익스트라(뒤 챕터)의 핵심 도구.

- 최소/최대 힙: C++ `priority_queue`는 기본 최대 힙이다. 최소 힙은 `greater<T>` 비교자를 쓰거나 값을 부호 반전(`-x`)해 넣는 방법도 있다.

- 언제 쓰나: "다음으로 처리할 가장 급한/작은/큰 것"을 반복 선택할 때. 정렬은 한 번에 끝나지만 힙은 삽입·삭제가 섞여 계속 갱신되는 상황에 강하다.

- 복잡도: push/pop 각각 O(log N), 최솟값 조회(peek/`top`) O(1), `make_heap` O(N), 힙 정렬(전부 push 후 전부 pop) O(N log N). 공간 O(N). 흔한 실수: `priority_queue`가 기본 최대 힙임을 잊고 최소 힙처럼 씀; `top()` peek 후 `pop()`을 안 해 같은 값 중복 처리; 빈 힙에서 `top()`/`pop()` 호출(먼저 `empty()` 검사).

**1) 최소 힙 시뮬레이션** · Easy

- **요구사항**: 두 종류 질의를 처리하라. `1 x`는 x를 힙에 추가, `2`는 힙에서 최솟값을 꺼내 출력(비었으면 `0` 출력). 최소 힙으로 동작해야 한다.

- **입력**: 첫 줄 Q. 이후 Q줄, `1 x` 또는 `2`.

- **출력**: 타입 2 질의마다 결과를 한 줄씩.

- **예제**:

  - `5` , `1 5` / `1 1` / `2` / `2` / `2` → `1` / `5` / `0`
    - 검산: {5,1} → pop 1 → pop 5 → 빈 힙에서 pop → 0.

  - `4` , `2` / `1 3` / `1 2` / `2` → `0` / `2`
    - 검산: 빈 상태 pop → 0, {3,2} → pop 2.

- **셀프체크**: 빈 힙 pop을 0으로 안전 처리했는가(`empty()` 검사)? `priority_queue`를 최소 힙(`greater`)으로 설정했는가? peek이 아니라 실제 pop 했는가?

```runner
(2) 코드 단계별

- 질의 타입을 읽어 1이면 값 x를 `push`.
- 2이면 힙이 비어 있지 않을 때만 `top()`으로 최솟값을 꺼내 출력하고 `pop()`, 비었으면 "0".
- 결과를 줄바꿈으로 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- 값을 꺼낼 때는 `top()`으로 보고 반드시 `pop()`으로 제거해야 원소가 빠진다.
- 빈 힙 접근을 막기 위해 `if (!h.empty())` 가드를 반드시 둔다.
```

**2) K번째로 큰 수 유지** · Medium

- **요구사항**: 정수 스트림이 하나씩 들어온다. 각 정수를 받은 뒤, 지금까지 들어온 수 중 K번째로 큰 값을 출력하라(아직 K개 미만이면 `-1`). 크기 K의 최소 힙을 유지해 O(log K)에 갱신하라.

- **입력**: 첫 줄 N과 K. 둘째 줄에 정수 N개(도착 순서).

- **출력**: 각 도착 시점의 답을 공백으로 구분해 한 줄.

- **예제**:

  - `5 2 / 3 1 5 4 2` → `-1 1 3 4 4`
    - 검산: 3(개수1<2 →-1) / +1={1,3} 2번째 큰=1 / +5={1,3,5} 2번째 큰=3 / +4 top2={5,4} →4 / +2 top2={5,4} →4.

  - `3 1 / 7 2 9` → `7 7 9`
    - 검산: K=1은 지금까지 최댓값. 7 / max(7,2)=7 / max(7,9)=9.

- **셀프체크**: 크기 K 최소 힙에서 새 값이 루트보다 클 때만 pop 후 push 했는가? K째 큰 값이 그때의 힙 루트(`top()`)인가? K개 미만일 때 -1을 냈는가?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> nums(n);
    for (int i = 0; i < n; i++) cin >> nums[i];

    priority_queue<int, vector<int>, greater<int>> h; // min-heap of size k
    vector<string> out;
    for (int x : nums) {
        if ((int)h.size() < k) {
            h.push(x);
        } else if (x > h.top()) {
            h.pop();
            h.push(x);
        }
        if ((int)h.size() < k) out.push_back("-1");
        else out.push_back(to_string(h.top()));
    }
    for (size_t i = 0; i < out.size(); i++) {
        if (i) cout << " ";
        cout << out[i];
    }
    cout << "\n";
    return 0;
}
@@TESTS
--IN
5 2
3 1 5 4 2
--OUT
-1 1 3 4 4
--IN
3 1
7 2 9
--OUT
7 7 9
@@EXPL
(1) 접근·핵심 아이디어

- "K번째로 큰 값"은 지금까지 값 중 상위 K개만 유지하면 알 수 있다. 크기 K의 최소 힙에 상위 K개를 담으면, 그 힙의 루트(`top()`)가 곧 상위 K개 중 가장 작은 값 = K번째로 큰 값이다.

(2) 코드 단계별

- 힙 크기가 K 미만이면 무조건 push한다.
- 이미 K개면 새 값 x가 루트(`top()`, 현재 K번째 큰 값)보다 클 때만 pop 후 push로 교체한다.
- 매 시점에 K개 미만이면 -1, 아니면 루트 `top()`을 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "상위 K개 유지 → 크기 K 최소 힙, 루트가 K번째 큰 값"을 핵심으로 잡는다.
- 새 값이 루트보다 클 때만 교체해야 항상 "가장 큰 K개"가 유지된다.
- 아직 K개가 안 찼으면 -1을 출력한다.
```

**3) 두 힙으로 중앙값 유지** · Hard

- **요구사항**: 정수가 하나씩 들어올 때마다 지금까지 수의 중앙값을 출력하라. 개수가 짝수면 가운데 두 값 중 작은 쪽(아래 중앙값)을 출력한다. 최대 힙(작은 절반)과 최소 힙(큰 절반)을 균형 있게 유지하라.

- **입력**: 첫 줄 N. 둘째 줄에 정수 N개(도착 순서).

- **출력**: 각 도착 시점의 중앙값을 공백으로 구분해 한 줄.

- **예제**:

  - `5 / 5 2 8 1 9` → `5 2 5 2 5`
    - 검산(정렬 후 아래 중앙값): [5]→5 / [2,5]→2 / [2,5,8]→5 / [1,2,5,8]→2 / [1,2,5,8,9]→5.

  - `4 / 4 4 4 4` → `4 4 4 4`  (모두 4)

- **셀프체크**: 작은 절반은 최대 힙(기본 `priority_queue`), 큰 절반은 최소 힙(`greater`)으로 나눴는가? 매 삽입 후 두 힙 크기 차가 1 이하가 되도록 재조정했는가? 아래 중앙값이 "작은 절반 힙의 top"이 되도록 크기 규칙을 맞췄는가(작은 절반 크기 ≥ 큰 절반 크기)?

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> nums(n);
    for (int i = 0; i < n; i++) cin >> nums[i];

    priority_queue<int> low;                                    // max-heap: 작은 절반
    priority_queue<int, vector<int>, greater<int>> high;        // min-heap: 큰 절반
    vector<string> out;
    for (int x : nums) {
        if (low.empty() || x <= low.top()) low.push(x);
        else high.push(x);
        if ((int)low.size() > (int)high.size() + 1) {
            high.push(low.top()); low.pop();
        } else if ((int)high.size() > (int)low.size()) {
            low.push(high.top()); high.pop();
        }
        out.push_back(to_string(low.top()));
    }
    for (size_t i = 0; i < out.size(); i++) {
        if (i) cout << " ";
        cout << out[i];
    }
    cout << "\n";
    return 0;
}
@@TESTS
--IN
5
5 2 8 1 9
--OUT
5 2 5 2 5
--IN
3
1 2 3
--OUT
1 1 2
@@EXPL
(1) 접근·핵심 아이디어

- 수들을 "작은 절반"과 "큰 절반"으로 나눠 각각 최대 힙(작은 절반의 최댓값이 top)과 최소 힙(큰 절반의 최솟값이 top)에 담는다. 작은 절반 크기를 큰 절반 이상으로 유지하면, 아래 중앙값이 항상 작은 절반 힙의 top이 된다.

(2) 코드 단계별

- 새 값 x가 작은 절반의 최댓값 이하면 `low`(기본 최대 힙)에, 아니면 `high`(최소 힙)에 넣는다.
- 재조정: `low`가 `high`보다 2 이상 크면 `low` top을 `high`로 옮기고, `high`가 `low`보다 크면 `high` top을 `low`로 옮긴다. 이러면 항상 `low.size() == high.size()` 또는 `low.size() == high.size()+1`.
- 아래 중앙값은 `low.top()`(작은 절반 최대 힙의 루트).

(3) 스스로 다시 짤 때 생각 순서

- "중앙값 = 두 힙 분할, 작은 절반 최대 힙 / 큰 절반 최소 힙"을 핵심으로 잡는다.
- 삽입 위치는 현재 작은 절반의 top과 비교해 정한다.
- 크기 규칙(작은 절반 ≥ 큰 절반, 차이 1 이하)을 재조정으로 강제하면 아래 중앙값이 `low.top()`으로 항상 나온다.
```

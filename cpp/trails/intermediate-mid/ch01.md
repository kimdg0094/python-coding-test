> 언어 C++

> 개요: 이 챕터에서는 해시 기반(unordered_map·unordered_set)과 정렬 기반(map·set) 컨테이너의 차이·용법을 실전 관점에서 익히고, 우선순위 큐(priority_queue)와 이중 연결 리스트를 직접 다뤄 "무엇을 언제 쓰는가"를 판단하는 감각을 기른다.

## L1. HashMap

**개념**

- HashMap은 "키 → 값" 대응을 평균 O(1)에 저장·조회·삭제하는 자료구조다. C++에서는 `std::unordered_map`이 곧 HashMap이며, 키를 해시 함수로 버킷에 흩뿌려 저장하기 때문에 삽입 순서와 무관하게 상수 시간 접근이 가능하다(단, 키는 해시 가능한 타입이어야 한다 — 기본 타입·string은 표준 해시가 제공된다).

- 언제 쓰나: 빈도수 세기, 값→인덱스 역참조, 그룹핑, 캐싱/메모이제이션, "이미 본 적 있는가" 판정 등. 정렬이 필요 없고 "빠른 룩업"만 필요하면 1순위 선택이다.

- 동작 단계: (1) 키를 해시값으로 변환 → (2) 해시값으로 버킷 위치 결정 → (3) 충돌 시 같은 버킷 안에서 키를 비교. `unordered_map`은 순서를 전혀 보장하지 않는다(삽입 순서·정렬 순서 모두 아님). 정렬된 순회가 필요하면 `std::map`(L2)을 쓴다.

```cpp
#include <bits/stdc++.h>
using namespace std;

unordered_map<int,int> cnt;      // {값: 등장횟수}
for (int x : arr) cnt[x]++;      // 없던 키는 자동으로 0에서 시작 후 증가

unordered_map<string, vector<int>> groups;  // 그룹핑
groups[name].push_back(score);   // 없던 키는 빈 벡터가 자동 생성

// 안전한 조회
auto it = d.find(key);           // 존재 여부는 find로
int v = (it != d.end()) ? it->second : 0;   // 없으면 기본값 0
if (d.count(key)) { /* ... */ }  // 존재 여부만 볼 때
```

**접근 전략**

- "무언가를 세거나, 매핑하거나, 중복/존재 여부를 O(1)에 물어봐야 한다"면 `unordered_map`을 떠올린다. 값을 누적할 땐 `map[key]++`나 `map[key].push_back(...)`가 "없으면 기본값 생성 후 갱신"을 알아서 해 준다. 키가 `(좌표)` 같은 복합값이면 `pair`를 직접 넣을 수 없으니(표준 해시 없음) 정렬이 필요 없더라도 `map<pair<int,int>,...>`를 쓰거나 좌표를 하나의 정수로 인코딩한다.

- 시간복잡도: 조회/삽입/삭제 평균 O(1), 최악 O(n)(해시 충돌 극단). 공간복잡도 O(n). 흔한 실수: `m[key]`로 조회하면 없던 키가 기본값으로 "삽입"되어 버린다 → 존재만 확인할 땐 `find`/`count`를 쓴다. 정렬된 순서로 순회하려면 `unordered_map`이 아니라 `map`(또는 키를 뽑아 정렬)이 필요. 반복 중 원소를 지우려면 `it = m.erase(it)`처럼 반환된 이터레이터로 진행해야 무효화를 피한다.

**문제**

**1) 두 수의 합 인덱스** · Easy

- **요구사항**: 정수 배열과 목표값 T가 주어질 때, 더해서 T가 되는 서로 다른 두 원소의 인덱스(1-based)를 오름차순으로 출력한다. 답은 유일하다고 가정한다. 배열을 한 번만 순회하며 해시맵을 쓸 것.

- **입력**: 첫 줄에 N과 T. 둘째 줄에 N개의 정수.

- **출력**: 두 인덱스를 공백으로.

- **예제**: `4 9 / 2 7 11 15` → `1 2` , `5 6 / 3 2 4 8 1 5` → `2 5`

- **셀프체크**: 각 원소 x를 볼 때 "T-x를 이전에 본 적 있는가"를 해시맵(값→인덱스)으로 물으면 O(N). 같은 원소를 두 번 쓰지 않도록 "현재 원소를 넣기 전에 조회"하는 순서가 함정.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, t;
    cin >> n >> t;
    vector<int> arr(n);
    for (int i = 0; i < n; i++) cin >> arr[i];
    unordered_map<int,int> seen;
    for (int i = 0; i < n; i++) {
        int need = t - arr[i];
        auto it = seen.find(need);
        if (it != seen.end()) {
            cout << it->second + 1 << " " << i + 1 << "\n";
            return 0;
        }
        seen[arr[i]] = i;
    }
    return 0;
}
@@TESTS
--IN
4 9
2 7 11 15
--OUT
1 2
--IN
4 8
1 3 5 10
--OUT
2 3
@@EXPL
(1) 접근·핵심 아이디어

- 각 원소 x에 대해 짝은 `T-x`로 고정된다. "지금까지 본 값 중에 `T-x`가 있었나?"를 O(1)에 물으려면 값→인덱스 해시맵이 필요하다. 전체를 한 번만 훑으면 O(N)이다.

(2) 코드 단계별

- N, T를 읽고 배열을 채운다.
- 배열을 왼쪽부터 훑으며, 현재 x에 대해 `need = T - x`를 먼저 `seen`에서 `find`로 조회한다. 있으면 (저장된 인덱스, 현재 인덱스)를 1-based로 출력하고 종료.
- 없으면 현재 x를 `seen[arr[i]] = i`로 등록한다. "조회 → 등록" 순서를 지켜야 같은 원소를 두 번 쓰지 않는다.

(3) 스스로 다시 짤 때 생각 순서

- 브루트포스 이중 루프(O(N^2))를 먼저 떠올린 뒤, "짝은 결정적이다"를 인식해 해시로 한 축을 O(1)로 줄인다.
- 인덱스 순서(작은 쪽 먼저)는 왼쪽에서 오른쪽으로 훑는 특성상 저장된 인덱스가 항상 더 작으므로 자연히 오름차순이 된다.
- 함정 체크: 등록보다 조회를 먼저 할 것, 출력은 1-based일 것.
```

**2) 애너그램 그룹 수** · Medium

- **요구사항**: 문자열 목록에서 서로 애너그램인 것끼리 묶었을 때 그룹의 개수를 출력한다.

- **입력**: 첫 줄 N, 이후 N줄에 소문자 문자열.

- **출력**: 그룹 개수.

- **예제**: `3 / eat tea ate` → `1` , `4 / abc bca xy z` → `3`

- **셀프체크**: 각 문자열을 정렬한 문자열(또는 26자 카운트 문자열)을 키로 쓰면 애너그램은 같은 키가 된다. `set`에 정규화 키를 모아 크기를 세면 답. 정렬 키는 O(L log L), 카운트 키는 O(L). 빈 그룹/중복 입력 경계 확인.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    set<string> keys;
    for (int i = 0; i < n; i++) {
        string w;
        cin >> w;
        sort(w.begin(), w.end());
        keys.insert(w);
    }
    cout << keys.size() << "\n";
    return 0;
}
@@TESTS
--IN
3
eat tea ate
--OUT
1
--IN
4
abc bca xy z
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 애너그램의 정의는 "문자 구성이 같다"이다. 각 문자열을 문자 정렬해 정규화하면 애너그램끼리는 완전히 같은 키가 된다. 서로 다른 키의 개수가 곧 그룹 수이므로 `set`에 정규화 키를 모아 크기를 센다. (개수만 필요하므로 `unordered_set`을 써도 되지만, `set`이든 `unordered_set`이든 크기는 같다.)

(2) 코드 단계별

- N을 읽고 이어지는 N개의 단어를 `cin >> w`로 하나씩 얻는다(공백/개행 분리라 한 줄에 몰려 있어도 동작).
- 각 단어 w에 대해 `sort(w.begin(), w.end())`로 문자를 사전순 정렬한다. 이것이 정규화 키.
- 모든 키를 `set`에 넣고 마지막에 `keys.size()`를 출력한다. 같은 애너그램은 같은 키라 자동으로 하나로 합쳐진다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇이 같으면 같은 그룹인가?"를 먼저 정의한다 → 정렬 키(또는 26칸 카운트 문자열).
- 그룹 "개수"만 필요하므로 그룹 내용을 저장할 필요 없이 서로 다른 키의 수만 세면 된다 → set.
- 성능이 중요하면 정렬(O(L log L)) 대신 길이 26 카운트 배열을 문자열로 인코딩(O(L))해 키로 써도 된다.
```

**3) 최다 빈도 상위 K개** · Medium

- **요구사항**: 정수 배열에서 등장 빈도가 높은 순으로 상위 K개 값을 출력한다. 빈도가 같으면 값이 작은 것을 먼저.

- **입력**: 첫 줄 N K, 둘째 줄 N개 정수.

- **출력**: 상위 K개 값을 공백으로.

- **예제**: `6 2 / 1 1 1 2 2 3` → `1 2` , `5 1 / 4 4 5 5 6` → `4`

- **셀프체크**: 해시맵으로 빈도를 센 뒤 `(빈도 내림차순, 값 오름차순)` 기준 정렬해 앞 K개. 정렬 O(M log M)(M=서로 다른 값 수). 동점 처리 규칙(값 오름차순)을 정렬 비교자에 반영했는지, K가 M보다 큰 경우도 체크.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    map<int,int> cnt;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        cnt[x]++;
    }
    vector<pair<int,int>> items(cnt.begin(), cnt.end()); // (value, freq)
    sort(items.begin(), items.end(), [](const pair<int,int>& a, const pair<int,int>& b){
        if (a.second != b.second) return a.second > b.second; // freq desc
        return a.first < b.first;                             // value asc
    });
    int take = min(k, (int)items.size());
    for (int i = 0; i < take; i++) {
        if (i) cout << " ";
        cout << items[i].first;
    }
    cout << "\n";
    return 0;
}
@@TESTS
--IN
6 2
1 1 1 2 2 3
--OUT
1 2
--IN
5 1
4 4 5 5 6
--OUT
4
@@EXPL
(1) 접근·핵심 아이디어

- 빈도수 문제이므로 맵으로 값→등장횟수를 O(N)에 만든다. 그다음 "빈도 내림차순, 동점이면 값 오름차순"이라는 정렬 규칙을 그대로 정렬 비교자로 표현하고 앞 K개를 취한다.

(2) 코드 단계별

- N, K와 배열을 읽으며 `cnt[x]++`로 각 값의 빈도를 센다(여기선 `map`을 써서 `(값, 빈도)` 쌍을 추출).
- `(값, 빈도)` 쌍들을 벡터로 옮긴 뒤 람다 비교자로 정렬한다. 첫 기준 `a.second > b.second`는 빈도 큰 순, 둘째 기준 `a.first < b.first`는 값 작은 순(동점 타이브레이커).
- 정렬된 항목에서 앞 `min(K, M)`개의 값만 공백으로 출력한다. K가 서로 다른 값 수 M보다 커도 `take`가 알아서 잘라 준다.

(3) 스스로 다시 짤 때 생각 순서

- "세고 → 정렬 규칙을 언어로 적고 → 그 규칙을 비교자로 옮긴다"가 골격이다.
- 내림차순은 비교자에서 `>`, 동점 시 오름차순은 `<`로 방향을 명확히 나눈다.
- 부분만 필요하면 `partial_sort`나 크기 K 힙(L5)으로 O(M log K)에 줄일 수도 있지만, 동점 규칙을 담기엔 비교자 + `sort`가 가장 직관적이다.
```


## L2. TreeMap

**개념**

- TreeMap은 "키가 항상 정렬된 상태로 유지되는 맵"이다. C++의 `std::map`이 이에 해당하며 내부적으로 균형 이진탐색트리(레드-블랙 트리)라서 삽입·삭제·조회가 O(log n)이고, "K 이상인 가장 작은 키(`lower_bound`)", "범위 순회", "최소/최대 키(`begin`/`rbegin`)" 같은 정렬 질의를 지원한다.

- C++에서는 상황에 따라 골라 쓴다: (1) 삽입이 끝난 뒤 조회만 한다면 정렬한 `vector` + `lower_bound`/`upper_bound`(`<algorithm>`), (2) 삽입/삭제가 섞이면 `std::map`/`std::multiset`(모든 연산 O(log n)), (3) 값 범위가 작으면 좌표압축 + BIT/세그먼트로 우회.

- 핵심 연산은 "정렬된 키 배열에서의 이분 위치 찾기"다. `lower_bound(a.begin(), a.end(), x)`는 "x 이상 첫 원소" 위치(= x 미만 원소 개수), `upper_bound(...)`는 "x 초과 첫 원소" 위치(= x 이하 원소 개수)를 준다. 이 둘로 "x 이상 첫 원소", "x 이하 마지막 원소", "[lo, hi] 구간 개수"를 모두 계산한다.

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> a;                    // 정렬 상태로 유지
sort(a.begin(), a.end());
// x 이상 첫 원소 위치 (인덱스)
int i = lower_bound(a.begin(), a.end(), x) - a.begin();
// x 초과 첫 원소 위치 (인덱스)
int j = upper_bound(a.begin(), a.end(), x) - a.begin();
// [L,R] 구간 원소 수
int cntLR = upper_bound(a.begin(), a.end(), R)
          - lower_bound(a.begin(), a.end(), L);
```

**접근 전략**

- "정렬 순서로 최소/최대를 계속 꺼내거나, 특정 값에 가장 가까운 키를 찾거나, 값 범위 개수를 물어봐야 한다"면 TreeMap 계열(`map`/`set`)을 떠올린다. 삽입/삭제가 없고 쿼리만이면 미리 정렬 후 `lower_bound`/`upper_bound`로 충분. 삽입·삭제가 뒤섞이면 `map`/`multiset`을 쓰거나(정렬된 vector에 삽입하면 이동이 O(n)이라 대량이면 느림) 좌표압축+세그먼트/BIT로 우회한다.

- 시간복잡도: BST 기반(`map`/`set`)이면 각 연산 O(log n). 정렬 vector에 원소를 끼워 넣는 삽입은 O(n)(이동 비용)이라 N이 크면 병목 → 주의. 공간 O(n). 흔한 실수: `lower_bound`와 `upper_bound` 혼동(경계 포함 여부가 뒤집힘), 중복 키 처리(`map`은 키 유일 → 여러 개면 `multiset`/`multimap`). 팁: 삽입 없이 "여러 쿼리를 오프라인"으로 처리 가능하면 정렬한 vector + 이분탐색이 가장 단순하고 빠르다.

- 중복이 있을 때 둘의 차이가 극명하다. 정렬배열 `a = {1, 2, 2, 2, 5}`(인덱스 0~4)에서:

| x | `lower_bound` | `upper_bound` | 의미 |
| --- | --- | --- | --- |
| 2 | 1 | 4 | lower=첫 2 위치, upper=마지막 2의 다음 |
| 3 | 4 | 4 | 없는 값은 둘이 같음(삽입될 자리) |
| 1 | 0 | 1 | lower=x 미만 개수(0), upper=x 이하 개수(1) |

  `upper_bound(a,x) - lower_bound(a,x)`가 곧 x의 등장 횟수(2는 3개). L4의 successor/predecessor도 이 둘로 만든다.

**문제**

**1) 가장 가까운 값** · Easy

- **요구사항**: 정렬해 둘 수 있는 정수 집합에 대해, 각 쿼리 값 x에 대해 x와의 절댓값 차가 가장 작은 원소를 출력한다. 동률이면 작은 값을 출력.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수, 셋째 줄 Q, 넷째 줄 Q개의 쿼리.

- **출력**: 각 쿼리의 답을 공백으로.

- **예제**: `5 / 1 4 6 9 12 / 2 / 5 11` → `4 12` , `3 / 10 20 30 / 1 / 25` → `20`

- **셀프체크**: 정렬 후 `lower_bound`로 삽입 위치 i를 찾고 후보는 a[i], a[i-1] 둘뿐. 경계(i=0, i=N)에서 인덱스 범위 초과 주의. 동률 규칙을 후보 비교에 반영. 전체 O((N+Q) log N).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end());
    int q;
    cin >> q;
    for (int t = 0; t < q; t++) {
        int x;
        cin >> x;
        int i = (int)(lower_bound(a.begin(), a.end(), x) - a.begin());
        long long best = 0;
        bool has = false;
        for (int j : {i - 1, i}) {
            if (j >= 0 && j < n) {
                long long d = llabs((long long)a[j] - x);
                if (!has || d < llabs(best - x) ||
                    (d == llabs(best - x) && a[j] < best)) {
                    best = a[j];
                    has = true;
                }
            }
        }
        if (t) cout << " ";
        cout << best;
    }
    cout << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 정렬해 두면 x에 가장 가까운 값은 반드시 "x가 삽입될 자리 바로 왼쪽/오른쪽" 둘 중 하나다. `lower_bound`로 그 자리 i를 찾고 후보 a[i-1], a[i]만 비교하면 된다.

(2) 코드 단계별

- 배열을 읽어 정렬하고, 쿼리들을 읽는다.
- 각 x에 대해 `i = lower_bound(...) - a.begin()`으로 삽입 위치를 구한다.
- 후보 인덱스 i-1, i를 순회하되 `0 <= j < n` 범위 안일 때만 본다.
- best와 비교: 절댓값 차가 더 작거나, 같으면 값이 더 작은 쪽으로 갱신(동률 시 작은 값 규칙).
- 모든 쿼리 답을 공백으로 출력.

(3) 스스로 다시 짤 때 생각 순서

- "정렬 + 이분탐색"으로 후보를 O(log N)에 2개로 좁힌다는 큰 그림을 먼저 잡는다.
- 경계(i=0이면 왼쪽 없음, i=n이면 오른쪽 없음)를 인덱스 범위 검사로 한 번에 처리한다.
- 동률 규칙을 비교식에 명시적으로 넣는다(`==`일 때 작은 값 선택).
```

**2) 범위 내 개수 쿼리** · Medium

- **요구사항**: 정수 배열이 주어지고 여러 개의 [L, R] 쿼리에 대해 값이 L 이상 R 이하인 원소의 개수를 각각 출력한다.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수, 셋째 줄 Q, 이후 Q줄에 L R.

- **출력**: 각 쿼리 답을 줄마다.

- **예제**: `5 / 3 1 4 1 5 / 2 / 1 3 / 4 5` (줄바꿈 표기) → `3` 그리고 `2` , `4 / 10 20 20 30 / 1 / 20 20` → `2`

- **셀프체크**: 한 번 정렬한 뒤 각 쿼리는 `upper_bound(a,R) - lower_bound(a,L)`. 정렬 O(N log N), 쿼리당 O(log N). L>R 방어, 중복 값 포함 여부가 lower/upper 선택의 핵심.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end());
    int q;
    cin >> q;
    for (int i = 0; i < q; i++) {
        int l, r;
        cin >> l >> r;
        int cnt = (int)(upper_bound(a.begin(), a.end(), r)
                      - lower_bound(a.begin(), a.end(), l));
        cout << cnt << "\n";
    }
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- 정렬 배열에서 "[L, R] 구간 원소 수 = (R 이하 개수) - (L 미만 개수)"이다. `upper_bound(a, R)`은 R 이하 개수, `lower_bound(a, L)`은 L 미만 개수를 (이터레이터 위치로) 주므로 둘의 차가 정답. 양 끝을 포함하려면 오른쪽은 upper, 왼쪽은 lower를 써야 한다.

(2) 코드 단계별

- 배열을 읽어 한 번만 정렬한다.
- 각 쿼리 (L, R)에 대해 `upper_bound(a, R) - lower_bound(a, L)`을 계산해 개수를 얻는다(두 이터레이터의 차 = 원소 수).
- 결과를 줄마다 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "누적/개수 질의는 정렬 후 이분탐색"이라는 패턴을 떠올린다.
- 경계 포함 여부에 따라 lower/upper를 고른다: 포함(≤, ≥)이 헷갈리면 중복 값 예시로 표를 그려 확인한다.
- 정렬은 딱 한 번, 쿼리마다 O(log N)이라는 비용 구조를 인지한다.
```

**3) 스트리밍 중앙 근처 조회** · Hard

- **요구사항**: 정수를 하나씩 삽입하는 연산과 "현재까지 삽입된 값 중 x 이상인 가장 작은 값을 출력"하는 연산이 섞여 들어온다. 없으면 -1.

- **입력**: 첫 줄 Q, 이후 각 줄에 `1 v`(삽입) 또는 `2 x`(조회).

- **출력**: 조회마다 결과를 줄마다.

- **예제**: `5 / 1 10 / 1 5 / 2 6 / 1 6 / 2 6` → `10` 그리고 `6` , `3 / 1 3 / 2 4 / 2 3` → `-1` 그리고 `3`

- **셀프체크**: 삽입·조회가 섞이므로 정렬 유지가 필요. `multiset`이면 삽입과 `lower_bound` 모두 O(log n). 조회는 `lower_bound(x)`가 `end()`면 -1.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int q;
    cin >> q;
    multiset<int> a;
    for (int i = 0; i < q; i++) {
        int op, v;
        cin >> op >> v;
        if (op == 1) {
            a.insert(v);
        } else {
            auto it = a.lower_bound(v);
            if (it != a.end()) cout << *it << "\n";
            else cout << -1 << "\n";
        }
    }
    return 0;
}
@@TESTS

2 6

2 6
--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 삽입과 "x 이상 최소값" 조회가 섞이므로 정렬 상태를 계속 유지해야 한다. `multiset`은 삽입 시 자동으로 정렬 위치에 넣고, 멤버 `lower_bound(x)`가 "x 이상 첫 값"의 이터레이터를 O(log n)에 준다. 그 이터레이터가 `end()`면 그런 값이 없으므로 -1.

(2) 코드 단계별

- Q를 읽고 연산을 순서대로 처리한다.
- `1 v`: `a.insert(v)`로 정렬 유지 삽입(중복 허용이라 `multiset`).
- `2 x`: `auto it = a.lower_bound(x)`. `it != a.end()`면 `*it`(x와 같거나 큰 첫 값)를 출력, 아니면 -1.
- 조회 결과를 줄마다 출력.

(3) 스스로 다시 짤 때 생각 순서

- 삽입/조회 혼합 → 정렬 유지 컨테이너가 필요하다는 신호. `multiset`이 정석(중복 값이 들어올 수 있으니 `set`이 아니라 `multiset`).
- "x 이상 최소값"은 멤버 `lower_bound`, "x 초과 최소값"은 멤버 `upper_bound`임을 구분한다.
- `multiset`의 멤버 `lower_bound`를 쓴다(전역 `std::lower_bound`는 균형트리에서 O(n)이라 비효율).
```


## L3. HashSet

**개념**

- HashSet은 "값의 집합"을 다루는 자료구조로, 중복을 자동 제거하고 원소의 존재 여부를 평균 O(1)에 판정한다. C++의 `std::unordered_set`이 이에 해당한다. 값→값이 아니라 "있다/없다"만 저장하는 HashMap의 특수형이라 보면 된다.

- 언제 쓰나: 중복 제거, "이미 방문했는가" 체크(그래프/시뮬레이션의 visited), 두 집합의 교집합·합집합·차집합 계산, "본 적 있는 상태" 판정으로 사이클/중복 탐지.

- 별도의 집합 연산 연산자는 없지만, 한쪽을 순회하며 다른 쪽에 `count`로 물어 교집합/합집합/차집합 크기를 O(|A|+|B|)에 계산한다. 좌표 같은 복합 키는 표준 해시가 없으므로 `set<pair<...>>`를 쓰거나 정수로 인코딩한다.

```cpp
#include <bits/stdc++.h>
using namespace std;

unordered_set<int> seen;
for (int x : stream) {
    if (seen.count(x)) { /* 중복 발견 */ }  // 존재 판정 O(1)
    seen.insert(x);
}

// 교집합 크기
int inter = 0;
for (int x : A) if (B.count(x)) inter++;
// 합집합 크기 = |A| + |B| - 교집합
int uni = (int)A.size() + (int)B.size() - inter;
```

**접근 전략**

- "중복을 없애야 한다 / 존재 여부만 빠르게 물으면 된다 / 집합 간 관계(교·합·차)를 계산한다"면 `unordered_set`을 선택한다. 방문 상태를 좌표 `(r,c)`로 관리하는 패턴은 격자 문제의 단골인데, `pair`는 기본 해시가 없으므로 `r*W + c` 같은 정수 인코딩으로 넣거나 정렬 필요 없어도 `set<pair<int,int>>`를 쓴다. 값 자체가 필요 없고 "봤는지"만 중요하면 `unordered_map`보다 `unordered_set`이 의미가 명확하다.

- 시간복잡도: insert/count/erase 평균 O(1), 집합 연산은 두 집합 크기의 합에 비례 O(|A|+|B|). 공간 O(n). 흔한 실수: 순서가 필요한데 `unordered_set`을 써서 순서가 뒤섞임(해시셋은 순서 보장 없음 → 정렬 순회가 필요하면 `set`), `erase(x)`는 없어도 조용히 0을 반환하지만 이터레이터로 지울 땐 무효화 주의. 팁: 큰 배열의 존재 판정을 선형 탐색(`find`)으로 하면 O(n)이니 반드시 해시셋으로 바꿔라.

**문제**

**1) 유일 원소 개수** · Easy

- **요구사항**: 정수 배열에서 서로 다른 값의 개수를 출력한다.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수.

- **출력**: 서로 다른 값의 개수.

- **예제**: `5 / 1 2 2 3 3` → `3` , `4 / 7 7 7 7` → `1`

- **셀프체크**: 모두 `unordered_set`에 넣고 크기를 출력. O(N). 빈 배열, 음수, 큰 값 범위여도 해시셋은 문제없음. 선형 탐색으로 세면 O(N^2)이 되는 함정을 피했는지.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    unordered_set<string> s;
    for (int i = 0; i < n; i++) {
        string x;
        cin >> x;
        s.insert(x);
    }
    cout << s.size() << "\n";
    return 0;
}
@@TESTS
--IN

1 2 2 3 3
--OUT
3
--IN
4

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- "서로 다른 값의 개수"는 곧 집합의 크기다. 모든 토큰을 `unordered_set`에 넣으면 중복이 자동 제거되므로 최종 `size()`가 답이다. 정수로 변환할 필요도 없이 문자열 토큰 그대로 넣어도 동일 값은 동일 토큰이라 결과가 같다.

(2) 코드 단계별

- N을 읽고 이어지는 N개의 토큰을 `cin >> x`로 하나씩 얻어 `s.insert(x)`.
- 중복이 자동으로 사라진 `s`의 `size()`를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "중복 제거 후 개수"라는 요구를 그대로 해시셋으로 옮긴다.
- 선형 탐색으로 세는 O(N^2) 유혹을 피하고, 존재/중복 판정은 항상 해시셋(평균 O(1))으로 한다는 원칙을 확인한다.
```

**2) 공통 관심사** · Medium

- **요구사항**: 두 사람이 각각 좋아하는 항목 목록을 준다. 둘 다 좋아하는 항목의 개수와, 적어도 한 명이 좋아하는 항목의 개수를 출력한다.

- **입력**: 첫 줄 A의 개수, 둘째 줄 A의 항목들. 셋째 줄 B의 개수, 넷째 줄 B의 항목들.

- **출력**: 교집합 크기와 합집합 크기를 공백으로.

- **예제**: `3 / apple banana cherry / 2 / banana grape` → `1 4` , `2 / x y / 2 / x y` → `2 2`

- **셀프체크**: 각 목록을 `unordered_set`으로 만들고, A를 순회하며 B에 `count`가 있으면 교집합 카운트. 합집합 = |A| + |B| - 교집합. 각 목록 내 중복은 셋이 자동 제거하므로 입력에 중복이 있어도 안전. 시간 O(|A|+|B|).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int a;
    cin >> a;
    unordered_set<string> A;
    for (int i = 0; i < a; i++) { string s; cin >> s; A.insert(s); }
    int b;
    cin >> b;
    unordered_set<string> B;
    for (int i = 0; i < b; i++) { string s; cin >> s; B.insert(s); }
    int inter = 0;
    for (const string& s : A) if (B.count(s)) inter++;
    int uni = (int)A.size() + (int)B.size() - inter;
    cout << inter << " " << uni << "\n";
    return 0;
}
@@TESTS
--IN

apple banana cherry
2
banana grape
--OUT
1 4
--IN
2
x y
2
x y
--OUT
2 2
@@EXPL
(1) 접근·핵심 아이디어

- "둘 다 좋아함"은 교집합, "적어도 한 명"은 합집합이다. 두 목록을 각각 `unordered_set`으로 만들면 목록 내부 중복이 자동 제거되고, 한쪽을 순회하며 다른 쪽에 `count`로 물어 교집합 크기를 센다. 합집합 크기는 `|A| + |B| - 교집합`이라는 포함-배제로 바로 구한다.

(2) 코드 단계별

- A 개수와 항목들을 읽어 `unordered_set A`에, B도 마찬가지로 `unordered_set B`에 담는다(중복 자동 제거).
- A의 각 원소가 B에 있으면(`B.count(s)`) 교집합 카운터를 증가시킨다.
- `inter`(교집합 크기)와 `|A| + |B| - inter`(합집합 크기)를 공백으로 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- 문제의 "둘 다 / 적어도 한 명"을 집합 언어(교집합/합집합)로 번역한다.
- 목록을 셋으로 바꾸는 순간 중복 걱정이 사라진다는 점을 이용한다.
- 합집합은 두 크기를 더하고 겹친 만큼(교집합) 한 번 빼는 포함-배제로 계산한다.
```

**3) 첫 중복 위치** · Medium

- **요구사항**: 정수 스트림에서 "직전까지 나온 값이 다시 등장하는" 최초 지점의 1-based 인덱스를 출력한다. 중복이 전혀 없으면 -1.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수.

- **출력**: 인덱스 또는 -1.

- **예제**: `5 / 3 1 3 2 1` → `3` , `3 / 1 2 3` → `-1`

- **셀프체크**: seen 셋을 유지하며 왼쪽부터 훑다가 처음으로 `seen.count(x)`인 순간의 인덱스를 출력. O(N). "넣기 전에 검사"하는 순서를 지켰는지, 전부 유일할 때 -1 반환 경계를 확인.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    unordered_set<int> seen;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        if (seen.count(x)) {
            cout << i + 1 << "\n";
            return 0;
        }
        seen.insert(x);
    }
    cout << -1 << "\n";
    return 0;
}
@@TESTS
--IN
5

- 전부 유일한 경우의 -1 반환 경계를 잊지 않는다.
```

## L4. TreeSet

**개념**

- TreeSet은 "정렬 상태가 유지되는 집합"이다. HashSet이 순서 없이 존재만 관리한다면, TreeSet은 원소를 항상 정렬해 두어 최소/최대 원소, "x보다 큰 가장 작은 원소(successor)", "x보다 작은 가장 큰 원소(predecessor)", 범위 순회를 O(log n)에 제공한다. C++의 `std::set`이 이에 해당하며(중복을 허용하려면 `std::multiset`), TreeMap에서 값을 뺀 형태다.

- 대체법: (1) 삽입 후 조회만 → 정렬한 `vector` + `lower_bound`/`upper_bound`, (2) 삽입/삭제가 섞이면 `std::set`/`std::multiset`(O(log n) 삽입/삭제/이분탐색), (3) 값 범위가 작으면 좌표압축 + BIT/세그먼트로 "존재 개수"를 관리.

- 대표 질의 successor/predecessor는 이분탐색으로 만든다: 정렬 배열 a에서 `upper_bound(a, x)` 위치가 "x 초과 첫 원소"(successor), `lower_bound(a, x) - 1` 위치가 "x 미만 마지막 원소"(predecessor). `std::set`이면 멤버 `upper_bound`/`lower_bound`와 이터레이터 감소로 같은 일을 O(log n)에 한다.

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> a;                    // 정렬 유지 (또는 std::set)
sort(a.begin(), a.end());

// x보다 큰 최소 원소 (successor)
int successor(const vector<int>& a, int x) {
    int i = upper_bound(a.begin(), a.end(), x) - a.begin();
    return (i < (int)a.size()) ? a[i] : -1;   // 없으면 -1
}
// x보다 작은 최대 원소 (predecessor)
int predecessor(const vector<int>& a, int x) {
    int i = (int)(lower_bound(a.begin(), a.end(), x) - a.begin()) - 1;
    return (i >= 0) ? a[i] : -1;              // 없으면 -1
}
```

**접근 전략**

- "정렬된 집합에서 가장 가까운 큰/작은 원소를 반복해서 찾거나, 삽입·삭제 후에도 정렬 순서를 유지해야 한다"면 TreeSet(`set`/`multiset`)을 떠올린다. 예약 시스템(빈 자리 찾기), 스카이라인, 슬라이딩 구간에서 최소/최대 유지 등이 전형. 삽입이 없으면 정렬한 vector + 이분탐색으로 끝나지만, 삭제가 잦으면 vector의 erase가 O(n)이므로 `set`이 유리하다.

- 시간복잡도: `set`/`multiset` 기반이면 삽입·삭제·successor·predecessor 모두 O(log n). 정렬 vector에 삽입/삭제는 O(n). 공간 O(n). 흔한 실수: `upper_bound`/`lower_bound`로 successor·predecessor를 만들 때 경계(빈 결과)를 -1로 처리하지 않아 범위 밖 접근. 중복 원소가 있으면 "집합"이 아니므로 필요 시 넣기 전에 존재 검사(또는 `multiset`). 팁: "정렬 + 이분탐색"으로 풀리는지 먼저 의심하라 — TreeSet 문제의 절반은 오프라인 정렬로 단순화된다.

**문제**

**1) 다음으로 큰 예약 시각** · Easy

- **요구사항**: 이미 잡힌 시각들의 집합이 주어지고, 각 쿼리 t에 대해 t보다 "크거나 같은" 가장 이른 시각을 출력한다. 없으면 -1.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수(시각), 셋째 줄 Q, 넷째 줄 Q개의 t.

- **출력**: 각 답을 공백으로.

- **예제**: `4 / 2 5 8 13 / 2 / 6 14` → `8 -1` , `3 / 1 3 5 / 1 / 3` → `3`

- **셀프체크**: "크거나 같은"이므로 `lower_bound`가 정답 위치. 위치가 끝이면 -1. 정렬 O(N log N), 쿼리당 O(log N). "크거나 같은"과 "초과"를 혼동하지 않았는지.

```runner
(2) 코드 단계별

- 시각들을 읽어 정렬하고 쿼리들을 읽는다.

(3) 스스로 다시 짤 때 생각 순서

- "이상(≥)"이면 `lower_bound`, "초과(>)"면 `upper_bound`라는 대응을 확실히 한다.
- 결과 위치가 유효 범위를 벗어나는 경계(값 없음)를 -1로 처리한다.
- 정렬은 한 번, 쿼리마다 O(log N)이라는 구조를 인지한다.
```

**2) 앞뒤 가장 가까운 원소** · Medium

- **요구사항**: 정수 집합과 쿼리 x가 주어질 때, x보다 작은 최대 원소(pred)와 x보다 큰 최소 원소(succ)를 출력한다. 각각 없으면 -1.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수, 셋째 줄 Q, 이후 Q줄에 x.

- **출력**: 각 줄에 pred succ.

- **예제**: `5 / 1 4 6 9 12 / 1 / 6` → `4 9` , `3 / 10 20 30 / 1 / 30` → `20 -1`

- **셀프체크**: pred는 `lower_bound(a,x)-1`, succ는 `upper_bound(a,x)`. x가 집합에 있어도 자기 자신은 제외됨을 확인(strict). 경계에서 -1. 각 쿼리 O(log N).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    sort(a.begin(), a.end());
    int q;
    cin >> q;

        int x;
        cin >> x;

        int ri = (int)(upper_bound(a.begin(), a.end(), x) - a.begin());
        int pred = (li >= 0) ? a[li] : -1;
        int succ = (ri < n) ? a[ri] : -1;
        cout << pred << " " << succ << "\n";
    }
    return 0;
}

(1) 접근·핵심 아이디어

- strict predecessor(x보다 작은 최대)는 `lower_bound(a, x) - 1` 위치, strict successor(x보다 큰 최소)는 `upper_bound(a, x)` 위치다. lower/upper를 이렇게 쓰면 x 자신이 집합에 있어도 자동으로 제외된다(lower는 x 앞에서 멈추고, upper는 x 뒤로 넘어감).

(2) 코드 단계별

- 배열을 정렬하고 쿼리를 읽는다.
- 각 x에 대해 `li = lower_bound(a, x) - a.begin() - 1`(pred 후보 인덱스), `ri = upper_bound(a, x) - a.begin()`(succ 후보 인덱스).
- `li >= 0`이면 a[li], 아니면 -1이 pred. `ri < n`이면 a[ri], 아니면 -1이 succ.
- "pred succ"를 줄마다 출력.

(3) 스스로 다시 짤 때 생각 순서

- "x 자신 제외"라는 strict 조건에서 왜 lower-1과 upper인지 중복 배열 예시로 확인한다.
- 양쪽 경계(빈 결과)를 -1로 처리해 범위 밖 접근을 막는다.
- pred/succ 공식은 TreeSet류 문제의 만능 도구이므로 손에 익혀 둔다.
```

**3) 삽입·삭제 후 최솟값** · Hard

- **요구사항**: `1 v`(v 삽입), `2 v`(v 삭제, 없으면 무시), `3`(현재 최솟값 출력, 비어 있으면 -1) 연산을 순서대로 처리한다.

- **입력**: 첫 줄 Q, 이후 각 줄에 연산.

- **출력**: `3` 연산마다 결과를 줄마다.

- **예제**: `5 / 1 5 / 1 3 / 3 / 2 3 / 3` → `3` 그리고 `5` , `3 / 1 7 / 2 7 / 3` → `-1`

- **셀프체크**: 삽입·삭제·최솟값이 섞이므로 정렬 유지 필요. `multiset`이면 삽입/삭제 O(log n), 최솟값은 `*begin()`. 삭제 시 존재하지 않는 값 무시(`find` 후 있을 때만 erase), 빈 상태의 -1 경계가 함정. `erase(v)`는 같은 값 전부를 지우므로 하나만 지우려면 이터레이터로 지운다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int q;
    cin >> q;
    multiset<int> a;
    for (int i = 0; i < q; i++) {
        int op;
        cin >> op;
        if (op == 1) {
            int v; cin >> v;
            a.insert(v);
        } else if (op == 2) {
            int v; cin >> v;
            auto it = a.find(v);
            if (it != a.end()) a.erase(it);   // 하나만 삭제
        } else {
            if (!a.empty()) cout << *a.begin() << "\n";
            else cout << -1 << "\n";
        }
    }
    return 0;
}

- 삽입·삭제·최솟값 조회가 섞이므로 정렬 상태를 유지하는 `multiset`을 쓴다. 삽입은 `insert`, 삭제는 `find`로 위치를 찾아 있을 때만 이터레이터로 `erase`(하나만), 최솟값은 정렬 컨테이너의 첫 원소 `*a.begin()`이다.

(2) 코드 단계별

- `1 v`: `a.insert(v)`로 정렬 유지 삽입.
- `2 v`: `auto it = a.find(v)`로 위치를 찾고, `it != a.end()`일 때만 `a.erase(it)`(없으면 무시). 이터레이터 버전 erase라 같은 값이 여러 개여도 하나만 지운다.

- 삭제는 "존재할 때만" 지워야 하므로 `find` 결과가 `end()`가 아닌지 확인한다. 값 인자 `erase(v)`는 동일 값을 모두 지우니, 하나만 지우려면 반드시 이터레이터로 지운다.
- 빈 상태의 -1 경계를 처리한다.
```

## L5. Priority Queue

**개념**

- 우선순위 큐는 "가장 우선순위 높은 원소를 O(log n)에 꺼내는" 자료구조로, 보통 이진 힙으로 구현한다. C++는 `std::priority_queue`를 제공하는데, 기본은 **최대 힙**이다: `push`로 넣고 `top`으로 항상 "가장 큰 값"을 보고 `pop`으로 제거한다. 삽입·삭제 O(log n), 최댓값 확인 `top()`은 O(1)이다.

- 언제 쓰나: 매 순간 최소/최대를 반복해서 꺼내야 할 때 — 다익스트라, K개 병합, 스케줄링(가장 빨리 끝나는 작업), 실시간 K번째 값 유지 등. "정렬을 매번 다시 하지 않고, 최소만(또는 최대만) 빠르게 뽑고 싶다"가 신호다.

- C++ `priority_queue`의 기본은 최대 힙이다. **최소 힙**이 필요하면 `priority_queue<int, vector<int>, greater<int>>`처럼 비교자를 바꾸거나(권장), 값의 부호를 뒤집어 넣는다. 우선순위 기준을 커스터마이즈하려면 `pair<우선순위, 데이터>`를 넣거나 커스텀 비교자를 준다. `pair`는 first 우선 비교라 동점 시 second로 자동 타이브레이크된다.

```cpp
#include <bits/stdc++.h>
using namespace std;

priority_queue<int> maxh;                                  // 최대 힙 (기본)
maxh.push(x);
int biggest = maxh.top(); maxh.pop();

priority_queue<int, vector<int>, greater<int>> minh;       // 최소 힙
minh.push(x);
int smallest = minh.top(); minh.pop();

// (우선순위, 데이터) — 다익스트라 등
priority_queue<pair<long long,int>,
               vector<pair<long long,int>>,
               greater<>> pq;                              // 거리 작은 순
pq.push({dist, node});
auto [d, u] = pq.top(); pq.pop();
```

**접근 전략**

- "최소(또는 최대)를 계속 꺼내되, 그 사이 새 원소가 계속 들어온다"면 힙이다. 전부 모아 정렬하면 O(n log n)이지만, 스트리밍처럼 삽입·추출이 섞이면 힙이 필수. 상위/하위 K개 유지에는 "크기를 K로 제한한 힙"이 정석(전체 정렬 O(n log n) 대신 O(n log K)). 다익스트라에서는 `(거리, 정점)`을 넣고, pop 시 기록된 거리보다 크면 skip하는 lazy deletion 패턴을 쓴다.

- 시간복잡도: push/pop O(log n), top O(1). 초기 원소가 다 있으면 벡터로 만든 뒤 `priority_queue`에 range 생성자로 넘겨 O(n)에 힙화한다. 공간 O(n). 흔한 실수: 기본이 **최대** 힙임을 잊고 최소 힙처럼 쓰는 것(→ `greater<>` 비교자 지정), `top()`을 `pop()` 없이 여러 번 부르며 진행했다고 착각, 힙 중간 원소의 임의 삭제는 O(log n)에 안 되므로 lazy deletion으로 우회. 팁: 최소/최대 K개만 필요하면 `nth_element`나 `partial_sort`도 대안이지만, 스트리밍 유지에는 힙이 정석이다.

**문제**

**1) K번째로 작은 값(스트리밍)** · Medium

- **요구사항**: `1 v`(값 추가), `2`(현재까지 값 중 K번째로 작은 값 출력, 원소 수가 K 미만이면 -1) 연산을 처리한다.

- **입력**: 첫 줄 Q K, 이후 각 줄에 연산.

- **출력**: `2` 연산마다 결과를 줄마다.

- **예제**: `5 2 / 1 5 / 1 2 / 2 / 1 1 / 2` → `5` 그리고 `2` , `3 1 / 1 9 / 1 4 / 2` → `4`

- **셀프체크**: 크기 K인 "최대 힙"을 유지 — 항상 가장 작은 K개만 담고, 그 최대(=힙 top)가 K번째로 작은 값. 새 값이 top보다 작으면 교체. 삽입 O(log K), 조회 O(1). K번째로 "작은" 것은 최대 힙, "큰" 것은 최소 힙이라는 방향을 헷갈리지 말 것.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int q, k;
    cin >> q >> k;
    priority_queue<int> h; // 최대 힙: 가장 작은 K개만 유지, top = K번째로 작은 값
    for (int i = 0; i < q; i++) {
        int op;
        cin >> op;
        if (op == 1) {
            int v; cin >> v;
            if ((int)h.size() < k) {
                h.push(v);
            } else if (v < h.top()) {
                h.pop();
                h.push(v);
            }
        } else {
            if ((int)h.size() == k) cout << h.top() << "\n";
            else cout << -1 << "\n";
        }
    }
    return 0;
}

- "K번째로 작은 값"은 "가장 작은 K개" 중 가장 큰 값이다. 크기 K로 제한한 최대 힙(C++ `priority_queue` 기본)에 가장 작은 K개만 유지하면, 힙의 top(=그 K개의 최댓값)이 곧 K번째로 작은 값이다.

(2) 코드 단계별

- 방향 확인: K번째로 "작은"은 최대 힙, "큰"은 최소 힙. 반대로 하면 유지 대상이 뒤집힌다.
- 새 값이 들어올 때 K개 초과분을 버리는 교체 조건(top보다 작을 때만)을 정확히 쓴다.
```

**2) 최소 비용으로 밧줄 잇기** · Medium

- **요구사항**: 길이가 주어진 밧줄들을 모두 하나로 잇는다. 두 밧줄을 이을 때 비용은 두 길이의 합이고, 이 비용이 누적된다. 총비용의 최솟값을 출력한다.

- **입력**: 첫 줄 N, 둘째 줄 N개의 길이.

- **출력**: 최소 총비용.

- **예제**: `3 / 1 2 3` → `9` , `4 / 4 3 2 6` → `29`

- **셀프체크**: 매번 "가장 짧은 두 개"를 합치는 그리디(허프만). 최소 힙에서 둘 pop → 합을 비용에 더하고 다시 push, 하나 남을 때까지. 검산: {1,2,3}→1+2=3(누적3) 남은 {3,3}→3+3=6(누적9). {2,3,4,6}→2+3=5(5) {4,5,6}→4+5=9(14) {6,9}→15(29). N개면 N-1번, O(N log N). N=1이면 비용 0. (가장 작은 둘을 먼저 합치는 것이 왜 최적인지는 ch04 그리디에서 교환 논증으로 다룬다 — 여기서는 힙 사용법에 집중한다.)

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    priority_queue<long long, vector<long long>, greater<long long>> pq; // 최소 힙
    for (int i = 0; i < n; i++) {
        long long x; cin >> x;
        pq.push(x);
    }
    long long total = 0;
    while ((int)pq.size() > 1) {
        long long x = pq.top(); pq.pop();
        long long y = pq.top(); pq.pop();
        long long c = x + y;
        total += c;
        pq.push(c);
    }
    cout << total << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- 허프만 병합 문제다. 매 단계에서 가장 짧은 두 밧줄을 합치는 것이 총비용을 최소화한다. 짧은 것을 먼저 합칠수록 그 합이 이후 합산에 여러 번 더해지는 횟수가 줄기 때문이다. "가장 짧은 둘"을 반복해 꺼내려면 최소 힙이 자연스럽다(`priority_queue`는 기본이 최대 힙이라 `greater<>` 비교자로 최소 힙을 만든다).

(2) 코드 단계별

- 길이들을 읽어 최소 힙에 넣는다.
- 원소가 2개 이상인 동안: 최소 두 개를 pop해 합 c를 만들고, c를 총비용에 더한 뒤 c를 다시 push한다.
- 하나만 남으면 종료하고 누적된 총비용을 출력한다. 값이 커질 수 있으니 `long long`으로 누적한다.

(3) 스스로 다시 짤 때 생각 순서

- "매번 최소 둘을 합친다"는 그리디를 떠올리고, 반복적 최소 추출 → 최소 힙을 선택한다.
- 합친 결과를 다시 힙에 넣어 계속 후보로 삼는다(누적 비용은 합칠 때마다 더한다).
- N=1이면 합칠 게 없어 비용 0이 되는 경계를 확인한다.
```

**3) 스트림의 중앙값** · Hard

- **요구사항**: 정수를 하나씩 삽입할 때마다 현재까지의 중앙값을 출력한다. 개수가 짝수면 두 중앙값 중 작은 쪽을 출력.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수.

- **출력**: 각 삽입 후 중앙값을 공백으로.

- **예제**: `5 / 2 1 5 7 2` → `2 1 2 2 2` , `4 / 4 1 2 3` → `4 1 2 2`

- **셀프체크**: 두 힙 — 아래 절반은 최대 힙, 위 절반은 최소 힙 — 을 크기 균형(아래가 위보다 0 또는 1 큼)으로 유지하면 아래 힙 top이 중앙값. 삽입마다 O(log n). 첫 예제 검산: [2]→2, [1,2]→1, [1,2,5]→2, [1,2,5,7]→작은쪽2, [1,2,2,5,7]→2. 균형 재조정 순서가 함정.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    priority_queue<int> low;                                 // 최대 힙: 아래 절반
    priority_queue<int, vector<int>, greater<int>> high;     // 최소 힙: 위 절반
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        if (low.empty() || x <= low.top()) low.push(x);
        else high.push(x);
        // 균형: low 는 high 보다 0 또는 1 커야 한다
        if ((int)low.size() > (int)high.size() + 1) {
            high.push(low.top()); low.pop();
        } else if ((int)high.size() > (int)low.size()) {
            low.push(high.top()); high.pop();
        }
        if (i) cout << " ";
        cout << low.top();
    }
    cout << "\n";
    return 0;
}
@@TESTS
--IN

2 1 5 7 2
--OUT
2 1 2 2 2
--IN
4
4 1 2 3
--OUT
4 1 2 2
@@EXPL
(1) 접근·핵심 아이디어

- 두 힙으로 데이터를 아래 절반/위 절반으로 나눈다. 아래 절반은 최대 힙, 위 절반은 최소 힙(`greater<>`). 두 힙의 크기를 "아래가 위보다 0 또는 1 큼"으로 유지하면, 짝수 개일 때 두 중앙값 중 작은 쪽이, 홀수 개일 때 진짜 중앙값이 항상 아래 힙의 top이 된다.

(2) 코드 단계별

- 각 새 값 x를: 아래 힙이 비었거나 x가 아래 top 이하이면 아래(low)에, 아니면 위(high)에 넣는다.
- 균형 재조정: 아래가 위보다 2 이상 크면 아래 top을 위로 옮기고, 위가 아래보다 크면 위 top을 아래로 옮긴다. 결과적으로 항상 `low.size() - high.size() ∈ {0, 1}`.
- 매 삽입 후 `low.top()`(아래 힙 top)을 중앙값으로 공백 구분 출력.

(3) 스스로 다시 짤 때 생각 순서

- "중앙값을 O(1)에 보려면 중앙을 경계로 두 덩어리로 쪼갠다"는 발상 → 최대 힙 + 최소 힙.
- 넣을 힙을 top 비교로 정하고, 그다음 크기 불균형을 한 개씩 넘겨 바로잡는다(순서 중요).
- 짝수일 때 "작은 쪽"을 원하므로 아래 힙이 항상 같거나 하나 더 크게 유지 → 아래 top이 답.
```


## L6. Doubly-LinkedList

**개념**

- 이중 연결 리스트는 각 노드가 앞·뒤 두 포인터(prev, next)를 가져 양방향으로 이동할 수 있는 선형 자료구조다. 배열과 달리 "중간 임의 노드의 삽입·삭제"를 그 노드에 대한 참조만 있으면 O(1)에 처리한다(원소 이동이 없다). 대신 인덱스 임의 접근은 O(n)이다. C++ 표준에는 `std::list`가 이중 연결 리스트이며, 이터레이터가 곧 "노드 참조" 역할을 한다.

- 언제 쓰나: 잦은 중간 삽입/삭제가 핵심이고 "어떤 노드 옆에" 넣고 빼는 위치가 참조로 주어질 때 — LRU 캐시(해시맵+이중연결리스트), 에디터의 커서 이동, 실행 취소/재실행, "옆 사람 제거" 류 시뮬레이션. 양끝 삽입·삭제만 필요하면 `std::deque`가 훨씬 간단하고 빠르다.

- 핵심은 포인터 재연결이다. 직접 구현할 땐 노드 x를 삭제하려면 `x->prev->next = x->next; x->next->prev = x->prev`. 양끝 처리를 단순화하려고 보통 head/tail "센티넬(더미) 노드"를 두어 경계 분기를 없앤다. 배열로 흉내 낼 땐 `nxt[i]`, `prv[i]` 두 배열로 링크를 표현하면 포인터 없이 O(1) 재연결이 된다.

```cpp
#include <bits/stdc++.h>
using namespace std;

// std::list 활용: 이터레이터가 노드 참조
list<int> L;
auto it = L.insert(pos, x);   // pos 앞에 x 삽입, 이터레이터 반환 O(1)
L.erase(it);                  // it가 가리키는 노드 삭제 O(1)
L.push_front(x); L.push_back(x);   // 양끝 삽입 O(1)

// 배열 기반 링크 (노드 번호로 관리)
vector<int> nxt(N + 1), prv(N + 1);
void removeNode(int x) {      // x를 리스트에서 분리 O(1)
    nxt[prv[x]] = nxt[x];
    prv[nxt[x]] = prv[x];
}
```

**접근 전략**

- "중간 삽입·삭제가 잦고, 삭제할 위치를 인덱스가 아니라 참조/값→노드 매핑으로 알 수 있다"면 이중 연결 리스트다. 값→이터레이터 해시맵(`unordered_map<int, list<int>::iterator>`)을 곁들이면 "특정 값의 노드를 O(1)에 찾아 O(1)에 제거"가 가능해진다(LRU의 핵심). 센티넬 노드나 `std::list` 자체를 쓰면 head/tail 경계를 매번 분기하지 않아 버그가 줄어든다. 양끝만 다루면 굳이 직접 구현 말고 `deque`(양끝 push/pop O(1))를 쓰는 게 정석.

- 시간복잡도: 참조(이터레이터)가 있을 때 삽입·삭제 O(1), 탐색(값으로 찾기)은 해시맵 없으면 O(n). 공간 O(n)(노드당 포인터 2개 오버헤드). 흔한 실수: 직접 구현 시 삭제할 때 양쪽 링크를 모두 갱신하지 않아 리스트가 끊김, 마지막/처음 노드 삭제 시 경계 갱신 누락(센티넬 또는 `std::list`로 해결), `std::list`에서 `erase` 후 무효화된 이터레이터를 다시 쓰는 것. 팁: 순수 양끝 큐/스택이면 `deque`가 정답, 두 스택으로 흉내 낼 수 있는 커서 문제도 흔하다.

**문제**

**1) 커서 텍스트 편집** · Medium

- **요구사항**: 문자들이 일렬로 있고 커서가 있다. `L`(커서 왼쪽 이동), `R`(오른쪽 이동), `P x`(커서 왼쪽에 문자 x 삽입), `B`(커서 왼쪽 문자 삭제) 연산을 처리하고 최종 문자열을 출력한다. 커서는 처음 맨 뒤에 있다.

- **입력**: 첫 줄 초기 문자열, 둘째 줄 연산 수 M, 이후 M줄에 연산.

- **출력**: 최종 문자열.

- **예제**: `abc / 2 / L / B` (커서 뒤→L로 c앞→B는 앞 문자 a? ) → `ac` , `x / 2 / P y / P z` → `xyz`

- **셀프체크**: 이 문제는 "커서 기준 양쪽 삽입/삭제"라 두 개의 스택(또는 센티넬 이중연결리스트)으로 O(1)씩. 예제1 검산: `abc` 커서 맨뒤 → L(커서가 c 앞) → B(커서 왼쪽=b 삭제) → `ac`. 각 연산 O(1), 전체 O(M). 경계(빈 왼쪽에서 B, 끝에서 R)를 무시하도록 처리.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    getline(cin, s);            // 초기 문자열 (공백 없다고 가정)
    int m;
    cin >> m;
    vector<char> left(s.begin(), s.end());  // top = 커서 바로 왼쪽
    vector<char> right;                     // top = 커서 바로 오른쪽
    for (int i = 0; i < m; i++) {
        string op;
        cin >> op;
        if (op == "L") {
            if (!left.empty()) { right.push_back(left.back()); left.pop_back(); }
        } else if (op == "R") {
            if (!right.empty()) { left.push_back(right.back()); right.pop_back(); }
        } else if (op == "P") {
            string x; cin >> x;
            left.push_back(x[0]);
        } else if (op == "B") {
            if (!left.empty()) left.pop_back();
        }
    }
    string res(left.begin(), left.end());
    for (int i = (int)right.size() - 1; i >= 0; i--) res.push_back(right[i]);
    cout << res << "\n";
    return 0;
}
@@TESTS

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 커서 기준의 양쪽 삽입/삭제는 "두 스택" 기법으로 모든 연산을 O(1)에 처리한다. 커서 왼쪽 문자들을 `left`(top이 커서 바로 왼쪽), 오른쪽 문자들을 `right`(top이 커서 바로 오른쪽)에 담는다. 커서 이동은 한 스택의 top을 다른 스택으로 옮기는 것이다.

(2) 코드 단계별

- 초기 문자열을 `getline`으로 읽어 `left`에 통째로 담는다(커서가 맨 뒤 = 모든 글자가 왼쪽). `right`는 비어 있다.
- `L`: `left`가 비어 있지 않으면 back을 `right`로 옮긴다(커서 왼쪽으로 한 칸).
- `R`: `right`가 비어 있지 않으면 back을 `left`로 옮긴다(오른쪽으로 한 칸).
- `P x`: 커서 왼쪽에 삽입 = `left`에 push_back.
- `B`: 커서 왼쪽 문자 삭제 = `left`가 비어 있지 않으면 pop_back.
- 최종 문자열은 `left`(순서대로) + `right`를 뒤집은 것.

(3) 스스로 다시 짤 때 생각 순서

- "커서 양옆 O(1) 조작"을 보면 두 스택(또는 센티넬 이중연결리스트)을 떠올린다.
- 각 연산이 어느 스택의 top을 건드리는지 그림으로 정리한다(L/R은 top 이동, P/B는 left만).
- 마지막에 right는 커서에서 먼 순서로 쌓였으므로 뒤집어 붙인다. 경계(빈 스택에서 L/R/B)는 무시. `getline`으로 첫 줄을 읽은 뒤 `cin >> m`으로 넘어가는 입력 순서에 유의.
```

**2) 요세푸스 제거 순서** · Medium

- **요구사항**: 1..N이 원형으로 있고, 1번부터 시작해 K번째 사람을 반복해서 제거한다. 제거되는 순서를 출력한다.

- **입력**: 첫 줄 N K.

- **출력**: 제거 순서를 공백으로.

- **예제**: `7 3` → `3 6 2 7 5 1 4` , `5 2` → `2 4 1 5 3`

- **셀프체크**: 원형 이중 연결 리스트에서 K-1칸 전진 후 현재 노드 제거(O(1) 재연결)를 N번. 제거 후 다음 시작은 제거된 노드의 다음. 전체 O(N·K). 검산(N=5,K=2): 시작1→2제거, 3→4제거, 5→1제거, 3→5제거, 남은3. 원형이라 head/tail 개념 없이 자기 참조로 닫는 처리가 함정.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> nxt(n + 1), prv(n + 1);
    for (int i = 1; i <= n; i++) {
        nxt[i] = (i < n) ? i + 1 : 1;
        prv[i] = (i > 1) ? i - 1 : n;
    }
    int cur = 1;
    for (int r = 0; r < n; r++) {
        for (int step = 0; step < k - 1; step++) cur = nxt[cur];
        if (r) cout << " ";
        cout << cur;
        int p = prv[cur], q = nxt[cur];
        nxt[p] = q; prv[q] = p;      // cur 를 링크에서 분리
        cur = q;                     // 다음 시작 = 제거 노드의 다음
    }
    cout << "\n";
    return 0;
}
@@TESTS
--IN
7 3
--OUT
3 6 2 7 5 1 4
--IN
5 2
--OUT
2 4 1 5 3
@@EXPL
(1) 접근·핵심 아이디어

- 원형 이중 연결 리스트를 배열 `nxt`, `prv`로 표현한다(노드 i의 다음/이전). 1번에서 시작해 K-1칸 전진한 노드가 이번에 제거될 사람이다. 제거는 양쪽 링크를 이어 붙이는 O(1) 연산이고, 다음 카운트는 제거된 노드의 다음에서 시작한다. 이를 N번 반복.

(2) 코드 단계별

- `nxt[i]`, `prv[i]`를 1..N 원형으로 초기화(N의 다음은 1, 1의 이전은 N).
- `cur = 1`에서 시작. 각 라운드마다 `cur = nxt[cur]`를 K-1번 반복해 K번째 사람에 도달.
- 그 노드를 출력하고, `nxt[prv]=nxt`, `prv[nxt]=prv`로 링크에서 분리한다.
- 다음 시작 `cur`는 제거된 노드의 다음(q)으로 둔다. N번 반복하며 제거 순서를 공백 출력.

(3) 스스로 다시 짤 때 생각 순서

- "원형으로 돌며 K번째 제거"를 보면 원형 연결 리스트(배열 nxt/prv)를 떠올린다.
- 시작점(1번)에서 첫 제거까지 몇 칸 전진하는지 손으로 세어 K-1임을 확정한다.
- 제거 후 재연결과 다음 시작 위치(제거 노드의 다음)를 정확히 갱신한다. 원형이라 head/tail 경계 분기가 없다.
```

**3) 최근 사용 캐시(LRU) 시뮬레이션** · Hard

- **요구사항**: 용량 C의 캐시가 있다. `1 k`(키 k 접근: 있으면 최근 사용으로 갱신, 없으면 삽입하고 가득 차 있으면 가장 오래된 것 제거), 각 연산 후 캐시에 남은 키들을 "최근 사용 순"으로 출력한다.

- **입력**: 첫 줄 C Q, 이후 Q줄에 `1 k`.

- **출력**: 각 연산 후 최근→오래된 순으로 키를 공백으로(빈 줄 가능).

- **예제**: `2 3 / 1 1 / 1 2 / 1 1` → 각 줄 `1` , `1 2` , `1 2` ; `1 2 / 1 5 / 1 6` → `5` , `6 5`

- **셀프체크**: 이중 연결 리스트(사용 순서) + 해시맵(키→이터레이터). 접근 시 해당 노드를 떼어 맨 앞으로 이동(O(1)), 초과 시 맨 뒤 노드 제거. 모든 연산 O(1). 첫 예제 검산: [1]→[2,1]→1재접근 앞으로 [1,2]. 링크 이동 시 해시맵의 이터레이터가 유지되는지, 제거된 키를 해시맵에서도 지웠는지 확인.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    int c, q;
    cin >> c >> q;
    list<int> order;                              // front = 최근, back = 오래된
    unordered_map<int, list<int>::iterator> pos;  // 키 -> 노드 이터레이터
    vector<string> out;
    for (int i = 0; i < q; i++) {
        int op, k;
        cin >> op >> k;
        auto it = pos.find(k);
        if (it != pos.end()) {                    // 이미 존재 -> 최근으로 이동
            order.erase(it->second);
            order.push_front(k);
            pos[k] = order.begin();
        } else {                                  // 신규
            if ((int)order.size() >= c) {         // 용량 초과 -> 가장 오래된 것 제거
                int last = order.back();
                order.pop_back();
                pos.erase(last);
            }
            order.push_front(k);
            pos[k] = order.begin();
        }
        string line;
        bool first = true;
        for (int key : order) {                   // front -> back = 최근 -> 오래된
            if (!first) line += " ";
            line += to_string(key);
            first = false;
        }
        out.push_back(line);
    }
    for (size_t i = 0; i < out.size(); i++) {
        cout << out[i];
        if (i + 1 < out.size()) cout << "\n";
    }
    cout << "\n";
    return 0;
}
@@TESTS
--IN
2 3
1 1
1 2
1 1
--OUT
1
2 1
1 2
--IN
1 2
1 5
1 6
--OUT
5
6
@@EXPL
(1) 접근·핵심 아이디어

- LRU 캐시의 정석은 "사용 순서를 담은 이중 연결 리스트 + 키→노드 해시맵"이다. `std::list`의 front 쪽이 최근, back 쪽이 오래된 것. 접근한 키는 리스트에서 떼어(`erase`) 맨 앞에 다시 붙인다(`push_front`). 용량 초과 삽입이면 맨 뒤(가장 오래된) 노드를 제거한다. `list`의 이터레이터는 다른 원소를 지워도 무효화되지 않아 해시맵에 그대로 저장해 둘 수 있다 — 모든 연산이 O(1).

(2) 코드 단계별

- `list<int> order`와 `unordered_map<int, list<int>::iterator> pos`로 순서와 위치를 관리한다.
- `1 k`: 이미 있으면(`pos.find`) 그 이터레이터로 `erase` 후 `push_front`, `pos[k]`를 새 `begin()`으로 갱신(최근으로). 없으면 용량이 찼을 때 `order.back()`(가장 오래된)을 pop하고 `pos`에서도 지운 뒤, `push_front` + `pos` 갱신.
- 매 연산 후 front→back 순으로 순회해 "최근→오래된" 순으로 키를 모아 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "최근 사용 순 유지 + O(1) 이동/제거"를 보면 이중 연결 리스트 + 해시맵(LRU 표준 조합)을 떠올린다.
- `std::list`를 쓰면 front 삽입·back 제거·중간 erase가 모두 O(1)이고 이터레이터가 안정적이라 해시맵에 저장할 수 있다.
- 제거할 때 리스트뿐 아니라 존재 맵(`pos`)에서도 반드시 지운다. 최근 갱신은 "떼서 앞으로"로 구현한다.
```

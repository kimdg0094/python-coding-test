## L3. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch03(Parametric Search)의 핵심 — 정렬·단조성 위에서 **경계를 찾는 이진탐색**과, "최적값 찾기"를 "후보 X가 가능한가?"라는 **판정 문제로 뒤집는 파라메트릭 서치** — 를 소재만 바꿔 **반복 훈련**하고, 코딩테스트 단골 유형(공유기 설치·입국심사·징검다리·K번째 쌍 거리 류)으로 **확장**하는 연습 세트다.
- **반복 훈련 개념**:
  - 경계 탐색(lower/upper bound): `lower_bound(v.begin(), v.end(), x)`는 `v[i] >= x`인 첫 위치, `upper_bound(...)`는 `v[i] > x`인 첫 위치를 **반복자**로 돌려준다(`- v.begin()`으로 인덱스로 바꾼다). 누적합처럼 **단조 증가하는 배열이면 정렬 배열과 똑같이** 쓴다. `set`/`map`에서는 반드시 멤버 함수 `s.lower_bound(x)`를 써야 O(log n)이고, 전역 `std::lower_bound`를 걸면 O(n)이 된다.
  - 조건 만족 최댓값(`T...T F...F`의 마지막 T): `if (ok(mid)) { ans = mid; lo = mid + 1; } else hi = mid - 1;`
  - 조건 만족 최솟값(`F...F T...T`의 첫 T): `if (ok(mid)) { ans = mid; hi = mid - 1; } else lo = mid + 1;`
  - 파라메트릭 서치: 답 후보 X를 고정하면 O(N) 판정 `feasible(X)`가 쉬운 문제 → 단조 방향 확인 → 범위 `[lo, hi]`를 넉넉히 → 판정 결과로 한쪽을 버린다. 전체 O(N log(범위)).
  - 중간값은 항상 `long long mid = lo + (hi - lo) / 2;`로 쓴다. `(lo + hi) / 2`는 두 값이 클 때 덧셈에서 넘친다.
  - 실수 이진탐색: `while (hi - lo > eps)`는 정밀도 한계에서 영원히 끝나지 않을 수 있다. **고정 횟수** `for (int it = 0; it < 100; it++)`로 돌려 정밀도를 확보하고, 출력은 `(long long)lo`처럼 정수로 내려 정답을 하나로 만든다.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '이분 탐색' 단계(공유기 설치·K번째 수 류), 프로그래머스 「코딩테스트 고득점 Kit」의 '이분탐색'(입국심사·징검다리 류), NeetCode 150의 'Binary Search'(Koko 바나나·K번째 쌍 거리 류).

**문제**

**1) 누적 목표 달성 첫날** · Easy

- **요구사항**: N일 동안 매일 저금한 금액이 주어진다. 목표 금액 x가 여러 개 주어질 때, 각 x에 대해 **누적 저금액이 처음으로 x 이상이 되는 날**(1일부터 셈)을 구하라. N일이 지나도 x에 못 미치면 `-1`.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 매일 저금액 N개(1 ≤ 값 ≤ 10^4), 셋째 줄 질의 수 Q(1 ≤ Q ≤ 10^5), 넷째 줄 목표 금액 Q개(1 ≤ x ≤ 10^9).
- **출력**: 질의마다 답을 한 줄씩.
- **예제**: `5 / 3 1 4 1 5 / 3 / 4 9 20` → `2 / 4 / -1` · `1 / 7 / 2 / 7 8` → `1 / -1`
- **셀프체크**: 저금액이 모두 양수라 누적합은 **단조 증가** → 정렬 배열처럼 `lower_bound`를 쓸 수 있다. 반환된 반복자가 `end()`면 끝까지 못 미친 것(-1). `- prefix.begin()`으로 얻은 인덱스는 0-based이므로 날짜는 +1. 예제1의 누적합 `3 4 8 9 14`에서 x=9는 인덱스 3(4일째), x=4는 정확히 같은 값이 있으니 `lower_bound`(이상)를 써야 2일째가 나온다 — `upper_bound`면 3일째로 틀린다. 누적합은 최대 10^5·10^4 = 10^9이라 `int` 경계에 가까우니 `long long`으로 둔다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<long long> prefix(n);
    long long total = 0;
    for (int i = 0; i < n; i++) {
        long long v;
        cin >> v;
        total += v;
        prefix[i] = total;            // 양수만 더하므로 단조 증가
    }

    int q;
    cin >> q;
    string out;
    for (int i = 0; i < q; i++) {
        long long x;
        cin >> x;
        // prefix[pos] >= x 인 첫 위치. vector는 임의 접근이라 O(log N).
        int pos = (int)(lower_bound(prefix.begin(), prefix.end(), x) - prefix.begin());
        out += (pos < n) ? to_string(pos + 1) : string("-1");
        out += '\n';
    }
    cout << out;
    return 0;
}

(1) 접근·핵심 아이디어

- "처음으로 x 이상이 되는 날"은 누적합 배열에서 `prefix[i] >= x`인 **가장 왼쪽 인덱스**, 즉 lower_bound다. 저금액이 전부 양수라 누적합이 단조 증가하므로 정렬 배열과 똑같이 이진탐색이 성립한다.
- 질의가 최대 10^5개라 매 질의마다 O(N)으로 훑으면 10^10 — 누적합을 한 번 만들고(O(N)) 질의마다 O(log N)으로 답한다.

(2) 코드 단계별

- 저금액을 더해 가며 `prefix`를 만든다. 값 타입은 `long long`(합이 10^9까지 간다).
- 각 질의 x에 대해 `lower_bound(prefix.begin(), prefix.end(), x)`로 `prefix[pos] >= x`인 첫 위치를 구하고 `- prefix.begin()`으로 인덱스로 바꾼다.
- `pos == n`이면 모든 누적합이 x보다 작다는 뜻이므로 -1, 아니면 날짜 `pos + 1`.
- 결과를 문자열 하나에 모아 한 번에 출력한다. 질의가 10^5개라 `cout <<`를 매번 부르는 것보다 빠르다.

(3) 스스로 다시 짤 때 생각 순서

- "처음으로 ~ 이상"이라는 말에서 lower_bound(`>=`)를 떠올리고, 그 대상이 정렬 배열이 아니라 **단조인 누적합**임을 확인한다.
- `lower_bound`와 `upper_bound`의 차이(값이 정확히 같은 날 처리)를 예제로 검산한다.
- 함정 — `lower_bound`는 **반복자**를 돌려준다. 인덱스가 필요하면 `- v.begin()`을 빼야 하고, "못 찾음"은 `== v.end()`(= 인덱스가 `n`)로 판정한다. 파이썬 `bisect`가 바로 정수를 주는 것과 다른 지점이다.
- 함정 2 — 이 문제는 대상이 `vector`(임의 접근)라 전역 `std::lower_bound`가 O(log N)이다. 같은 함수를 `set`/`map`에 걸면 반복자가 한 칸씩 걸어가 O(n)이 되므로, 그때는 멤버 함수 `s.lower_bound(x)`를 쓴다.
- 경계: 반환 인덱스가 N이면 -1, 첫날에 이미 달성하면 1.
```

**2) 블록 피라미드 최대 층수** · Easy

- **요구사항**: 블록 n개로 피라미드를 쌓는다. 맨 위 1층에 1개, 2층에 2개, …, k층에 k개가 필요하다. **완성된 층만** 세었을 때 만들 수 있는 최대 층수를 구하라. 제곱근 공식이나 부동소수 없이 정수 이진탐색으로 푼다.
- **입력**: 한 줄에 정수 n(0 ≤ n ≤ 10^18).
- **출력**: 최대 층수.
- **예제**: `8` → `3` · `10` → `4`
- **셀프체크**: `ok(h) = h*(h+1)/2 <= n`은 h가 커질수록 `T...T F...F`(최댓값 패턴). n=8: 1+2+3=6 ≤ 8이지만 1+2+3+4=10 > 8이므로 3. n=0이면 0층. `hi`를 답보다 작게 잡지 않도록 `hi = 2*10^9`(그때 합이 약 2·10^18 > n) 정도로 넉넉히. **파이썬과 달리 C++ 정수는 오버플로가 난다** — n이 10^18이면 `mid`가 2·10^9까지 가고 `mid*(mid+1)`은 4·10^18로 `long long` 상한(약 9.2·10^18)에 아슬아슬하게 들어간다. 짝·홀로 나눠 먼저 2로 나누면 여유가 두 배가 된다. `int`로 두면 `mid`부터 이미 넘친다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> n;                        // 10^18 -> int로는 절대 못 받는다

    long long lo = 0, hi = 2000000000LL, ans = 0;  // h(h+1)/2 <= 1e18 이면 h < 2e9
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;        // (lo+hi)/2는 큰 값에서 넘친다
        // 곱하기 전에 2로 나눠 중간값을 절반으로 줄인다
        long long need = (mid % 2 == 0) ? (mid / 2) * (mid + 1)
                                        : mid * ((mid + 1) / 2);
        if (need <= n) {
            ans = mid;
            lo = mid + 1;            // 최댓값 -> 더 높은 층 시도
        } else {
            hi = mid - 1;
        }
    }
    cout << ans << "\n";
    return 0;
}
@@TESTS

(1) 접근·핵심 아이디어

- h층까지 완성하려면 `1+2+...+h = h(h+1)/2`개가 필요하다. 이 값이 n 이하인 최대 h를 찾는 문제이므로, `ok(h) = h(h+1)/2 <= n`이라는 단조 조건(`T...T F...F`)의 마지막 T를 이진탐색한다.
- `(sqrt(8n+1)-1)/2` 공식은 n이 10^18이면 `double`의 유효 자릿수(약 15~16자리)를 넘어 한 층이 틀릴 수 있다. 정수 이진탐색은 그런 걱정이 없다.

(2) 코드 단계별

- `lo=0, hi=2000000000, ans=0`으로 시작한다(n=0이면 루프에서 `ans`가 0으로 남는다).
- `mid`의 필요 블록 수를 계산해 n 이하면 `ans=mid`, `lo=mid+1`(더 높이 시도), 아니면 `hi=mid-1`.
- 루프 종료 후 `ans` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "완성 가능한 최대 층"은 조건 만족 최댓값 → 성공 시 오른쪽으로 민다.
- 함정 1 — **`mid = (lo + hi) / 2`의 덧셈 오버플로.** 이 문제에서는 `hi`가 2·10^9이라 합이 4·10^9로 `long long` 안이지만, 답 범위가 10^18 근처인 문제에서는 `lo + hi`가 그대로 넘쳐 `mid`가 음수가 된다. 그러면 배열 인덱스가 음수가 되거나 루프가 끝나지 않는다. 처음부터 **`lo + (hi - lo) / 2`**로 쓰는 습관을 들인다(뺄셈은 두 값이 같은 부호면 절대 넘치지 않는다).
- 함정 2 — **곱셈 오버플로.** `mid * (mid + 1)`은 `mid`가 2·10^9일 때 4·10^18이라 아직 `long long` 안이지만, 상한을 조금만 넉넉히 잡으면(예: `hi = 4e9`) 곧장 넘친다. `mid`와 `mid+1` 중 하나는 반드시 짝수이므로 **곱하기 전에 그쪽을 2로 나누면** 결과가 절반이 되어 여유가 두 배 생긴다. 더 확실하게는 `__int128`로 계산하거나, 나눗셈으로 뒤집어 `mid <= n / (mid+1) * 2` 형태를 쓴다.
- 함정 3 — 입력 자체가 10^18이므로 `int n`으로 받으면 그 순간 값이 망가진다. 문제의 제약을 먼저 읽고 타입을 정한다.
- 범위는 넉넉하게. `hi`가 답보다 작으면 조용히 오답이 나오므로, 필요 블록 수가 n을 확실히 넘는 `hi`를 잡는다.
- 경계 n=0, n=1, 정확히 삼각수인 n(10 → 4층)을 검산한다.
```

**3) 텐트 간격 최대화** · Medium

- **요구사항**: 일직선 야영장에 텐트를 칠 수 있는 자리 N곳의 좌표가 주어진다(서로 다름). 이 중 C곳을 골라 텐트를 칠 때, **가장 가까운 두 텐트 사이의 거리**가 최대가 되도록 하고 그 거리를 출력하라.
- **입력**: 첫 줄 N과 C(2 ≤ C ≤ N ≤ 10^5), 둘째 줄 좌표 N개(0 ≤ 좌표 ≤ 10^9, 정렬돼 있지 않음).
- **출력**: 가능한 최소 간격의 최댓값.
- **예제**: `5 3 / 1 2 8 4 9` → `3` · `4 4 / 10 3 7 1` → `2`
- **셀프체크**: 판정 `feasible(d)` = "간격을 d 이상으로 두고 C개 설치할 수 있나?" — 정렬 후 **가장 왼쪽 자리에 무조건 첫 텐트**, 이후 `x - last >= d`인 자리마다 설치하며 개수를 센다(그리디). d가 커질수록 설치 가능 개수는 줄어드니 `T...T F...F` → 최댓값 패턴. 예제1: 정렬 `1 2 4 8 9`, d=3이면 1,4,8 → 3개 가능, d=4면 1,8 → 2개 불가 → 3. `sort`를 잊지 말 것. `lo=1`, `hi=max-min`으로 잡는다(간격 0은 항상 가능하므로 탐색에 넣을 필요가 없다).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int n, c;
vector<long long> xs;

// 간격 d 이상으로 c개 설치 가능?
bool feasible(long long d) {
    int cnt = 1;
    long long last = xs[0];          // 첫 텐트는 가장 왼쪽 자리
    for (int i = 1; i < n; i++) {
        if (xs[i] - last >= d) {
            cnt++;
            last = xs[i];
            if (cnt >= c) return true;
        }
    }
    return cnt >= c;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> c;
    xs.resize(n);
    for (int i = 0; i < n; i++) cin >> xs[i];
    sort(xs.begin(), xs.end());      // 입력은 무작위 순서

    long long lo = 1, hi = xs[n - 1] - xs[0], ans = 0;
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;
        if (feasible(mid)) {
            ans = mid;               // 최댓값 -> 더 넓은 간격 시도
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    cout << ans << "\n";
    return 0;
}
@@TESTS

(1) 접근·핵심 아이디어

- "최소 간격을 최대화"는 직접 구하기 어렵지만, 간격 d를 고정하면 "d 이상 떨어뜨려 C개를 놓을 수 있나?"는 정렬 후 왼쪽부터 그리디로 O(N)에 판정된다. 첫 텐트를 가장 왼쪽에 두는 것이 항상 손해가 아니다(더 오른쪽에 두면 이후 자리가 줄어들 뿐).
- d가 커질수록 놓을 수 있는 개수는 단조 감소하므로 `feasible`은 `T...T F...F`. 마지막 T가 답 → 파라메트릭 서치.

(2) 코드 단계별

- 좌표를 `sort`한다.
- `feasible(d)`: `last`를 첫 좌표로 두고, `xs[i] - last >= d`인 좌표를 만날 때마다 설치·갱신. C개가 되면 즉시 `true`로 조기 종료.
- 구간 `[1, max-min]`에서 성공하면 `ans=mid; lo=mid+1`, 실패하면 `hi=mid-1`.
- C ≥ 2이므로 `hi = xs[n-1] - xs[0]`은 항상 유효하고, d=1은 서로 다른 좌표에선 항상 가능하다.

(3) 스스로 다시 짤 때 생각 순서

- "최소를 최대로" → 파라메트릭. 이진탐색 대상은 "간격 d".
- 판정을 그리디 O(N)으로 짜고, 첫 텐트를 왼쪽 끝에 두는 것이 왜 안전한지 한 줄로 설명할 수 있어야 한다.
- 단조 방향 확인(d↑ → 개수↓) → 최댓값 패턴 → 성공 시 `lo=mid+1`.
- 함정 — 판정 함수가 큰 `vector`를 쓴다면 값으로 넘기지 말 것. `bool feasible(long long d, vector<long long> xs)`처럼 짜면 호출마다(약 30번) 10^5개 원소를 통째로 복사한다. 전역으로 두거나 `const vector<long long>&`로 참조를 받는다. 파이썬은 리스트를 넘겨도 참조라 이 문제가 없지만 C++은 기본이 복사다.
- 함정 2 — 좌표 차이는 최대 10^9이라 `int`에도 들어가지만, 같은 골격의 다른 문제(좌표가 10^18인 경우)를 대비해 `long long`으로 통일해 두면 타입 사고가 사라진다.
- 경계: C=N이면 답은 인접 좌표 차의 최솟값(예제2), N=2면 `max-min`.
```

**4) 시간 내 분류 최소 속도** · Medium

- **요구사항**: 택배 더미 N개에 각각 a_i개의 상자가 있다. 작업자는 시간당 k개를 처리하는 속도로 일하며, **한 시간에는 한 더미만** 다룬다(더미에 k개 미만이 남아 있어도 그 시간은 다른 더미로 넘어가지 못한다). H시간 안에 모든 더미를 처리할 수 있는 **최소 속도 k**를 구하라.
- **입력**: 첫 줄 N과 H(1 ≤ N ≤ H ≤ 10^9), 둘째 줄 a_i N개(1 ≤ a_i ≤ 10^9).
- **출력**: 최소 속도 k.
- **예제**: `4 8 / 5 9 10 14` → `5` · `3 3 / 4 8 6` → `8`
- **셀프체크**: 속도 k일 때 더미 a_i는 `ceil(a_i / k) = (a_i + k - 1) / k` 시간이 걸리고, 총합이 H 이하면 가능. **`a_i + k - 1`은 최대 2·10^9이라 `int`로는 넘친다** — 올림 나눗셈은 반드시 `long long`으로. k가 클수록 시간은 줄어드니 `F...F T...T` → **최솟값 패턴**(성공 시 `hi=mid-1`). 예제1: k=5면 1+2+2+3=8 ≤ 8 가능, k=4면 2+3+3+4=12 > 8 불가 → 5. H=N이면 더미마다 정확히 1시간에 끝내야 하므로 답은 `max(a)`(예제2). `hi=max(a)`로 두면 항상 한 번은 성공한다. `lo=0`은 0 나눗셈이므로 `lo=1`.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n, h;
    cin >> n >> h;
    vector<long long> piles((size_t)n);
    for (long long i = 0; i < n; i++) cin >> piles[(size_t)i];

    // 속도 k로 h시간 안에 끝나나?
    auto feasible = [&](long long k) -> bool {
        long long hours = 0;
        for (long long a : piles) {
            hours += (a + k - 1) / k;   // 올림 나눗셈 (int면 a+k-1에서 넘친다)
            if (hours > h) return false; // 조기 종료가 곧 오버플로 방어
        }
        return true;
    };

    long long lo = 1, hi = *max_element(piles.begin(), piles.end());
    long long ans = hi;                 // 속도 max(a)면 더미당 1시간 -> 항상 가능
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;
        if (feasible(mid)) {
            ans = mid;                  // 최솟값 -> 더 느린 속도 시도
            hi = mid - 1;
        } else {
            lo = mid + 1;
        }
    }
    cout << ans << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 최소 속도를 바로 계산할 수는 없지만, 속도 k를 고정하면 총 소요 시간 `sum(ceil(a_i / k))`은 O(N)에 계산된다. 이 값이 H 이하인지가 판정이다.
- k가 커질수록 각 더미의 시간은 줄거나 같으므로 판정은 `F...F T...T`. 첫 T(최솟값)가 답이므로 성공 시 `hi=mid-1`로 왼쪽을 탐색한다.

(2) 코드 단계별

- N, H와 더미 크기를 `long long`으로 읽는다.
- `feasible(k)`: 올림 나눗셈 `(a + k - 1) / k`를 더하며 H를 넘는 순간 `false`로 조기 종료. 람다에 `[&]`로 캡처하면 `piles`와 `h`를 복사 없이 쓴다.
- 구간 `[1, max(piles)]`. `hi`는 반드시 가능하므로 `ans`의 초깃값으로 둔다.
- 성공 시 `ans=mid; hi=mid-1`, 실패 시 `lo=mid+1`. 마지막 `ans` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "H시간 안에 가능한 최소 속도" → 파라메트릭, 최솟값 패턴.
- 함정 1 — **올림 나눗셈의 오버플로.** `(a + k - 1) / k`에서 `a`와 `k`가 각각 10^9이면 분자가 2·10^9으로 `int` 상한(약 2.147·10^9)에 걸린다. 조금만 더 큰 입력에서 음수가 되어 조용히 오답이 난다. 분자를 `long long`으로 만들거나, `a / k + (a % k ? 1 : 0)`처럼 더하기를 피하는 형태로 쓴다.
- 함정 2 — C++의 정수 나눗셈은 **0 방향 절단**이다. 양수만 다루면 내림과 같지만 음수가 섞이면 `-7 / 2 == -3`(파이썬은 -4)이라 올림/내림 관용구가 통째로 깨진다. 이 문제는 양수뿐이라 안전하지만, 음수가 나올 수 있는 문제에서는 나눗셈 전에 부호를 확인한다.
- 함정 3 — `k = 0`이면 0으로 나누기(정의되지 않은 동작, 대개 프로그램이 죽는다)다. `lo`를 1부터 시작해 원천 차단한다.
- 판정에서 올림을 정확히 쓴다(`a / k`로 내리면 남은 상자를 무시해 틀린다).
- 경계: H=N이면 `max(a)`, N=1이면 `ceil(a/k) <= H`인 최소 k.
```

**5) 키오스크 N명 처리 최소 시간** · Medium

- **요구사항**: 무인 발권기(키오스크) M대가 있고, i번째 기계는 한 사람을 처리하는 데 t_i분이 걸린다. N명이 줄을 서 있고, 각 사람은 비어 있는 아무 기계나 골라 쓸 수 있다(느린 기계를 피하고 기다렸다가 빠른 기계를 쓰는 것도 가능). 모든 사람의 처리가 끝나는 **최소 시간(분)** 을 구하라.
- **입력**: 첫 줄 M과 N(1 ≤ M ≤ 10^5, 1 ≤ N ≤ 10^9), 둘째 줄 t_i M개(1 ≤ t_i ≤ 10^9).
- **출력**: 최소 시간.
- **예제**: `3 10 / 3 5 8` → `16` · `1 4 / 6` → `24`
- **셀프체크**: 시간 T 안에 처리 가능한 인원은 `sum(T / t_i)`. T가 커질수록 늘어나니 `F...F T...T` → 최솟값 패턴. 예제1: T=15면 5+3+1=9 < 10 불가, T=16이면 5+3+2=10 ≥ 10 가능 → 16. `hi`는 "가장 빠른 기계 하나로 전부 처리" `min(t)*N`으로 잡으면 반드시 가능 — **이 값이 10^9 × 10^9 = 10^18이라 `long long`이 아니면 그 자리에서 넘친다.** 게다가 몫의 합을 끝까지 더하면 10^5 × 10^18로 `long long`도 넘치므로, N에 도달하는 순간 조기 종료해야 한다(파이썬은 정수에 상한이 없어 이 걱정이 없었다).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    long long m, n;
    cin >> m >> n;
    vector<long long> times((size_t)m);
    for (long long i = 0; i < m; i++) cin >> times[(size_t)i];

    // T분 안에 n명 이상 처리 가능?
    auto feasible = [&](long long T) -> bool {
        long long done = 0;
        for (long long t : times) {
            done += T / t;
            if (done >= n) return true;  // 조기 종료: 합이 long long을 넘지 않게
        }
        return false;
    };

    long long lo = 1;
    long long hi = *min_element(times.begin(), times.end()) * n;  // 1e18 -> long long 필수
    long long ans = hi;                 // 가장 빠른 기계 하나로 전부 -> 항상 가능
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;   // (lo+hi)는 2e18로 넘칠 수 있다
        if (feasible(mid)) {
            ans = mid;                  // 최솟값 -> 더 짧은 시간 시도
            hi = mid - 1;
        } else {
            lo = mid + 1;
        }
    }
    cout << ans << "\n";
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- 어느 사람이 어느 기계를 쓰는지 배정을 직접 최적화하는 대신, 시간 T를 고정하고 "T분 동안 기계들이 처리할 수 있는 총 인원 `sum(T / t_i)`이 N 이상인가?"만 묻는다. 각 기계는 독립적으로 T 동안 `T / t_i`명을 처리할 수 있으므로 이 합이 곧 최대 처리 인원이다.
- T가 커질수록 합은 단조 증가 → `F...F T...T`. 첫 T가 최소 시간.

(2) 코드 단계별

- M, N과 처리 시간을 `long long`으로 읽는다.
- `feasible(T)`: 몫의 합이 N 이상인지 O(M). N에 도달하면 즉시 `true`.
- `hi = min(times) * n`은 반드시 가능한 값이므로 `ans` 초깃값으로 둔다. `lo=1`.
- 성공 시 `ans=mid; hi=mid-1`, 실패 시 `lo=mid+1`.

(3) 스스로 다시 짤 때 생각 순서

- "모두 끝나는 최소 시간" + "T를 정하면 처리 인원 계산이 쉬움" → 파라메트릭, 최솟값 패턴.
- 함정 1 — **탐색 범위 자체가 오버플로한다.** `min(t) * n`은 10^9 × 10^9 = 10^18이다. `int`면 물론이고, `int` 두 개를 곱해 `long long`에 넣는 `long long hi = minT * n;`(둘 다 `int`)도 **곱셈이 `int`로 먼저 이뤄진 뒤** 대입되므로 망가진다. 피연산자 중 하나를 `long long`으로 만들어야 한다(`(long long)minT * n`). 위 코드처럼 처음부터 전부 `long long`으로 선언하면 이 사고가 없다.
- 함정 2 — **`mid = (lo + hi) / 2`가 넘친다.** `hi`가 10^18이면 `lo + hi`가 2·10^18로 아직 `long long` 안이지만, 상한이 조금만 커지면 곧장 음수가 된다. `lo + (hi - lo) / 2`로 쓴다.
- 함정 3 — **합계도 넘친다.** 파이썬은 `sum(T // t for t in times)`를 끝까지 더해도 안전했지만, C++에서 M=10^5, 각 몫이 10^18이면 합이 10^23이 되어 `long long`을 훌쩍 넘는다. N에 도달하는 순간 `return true`로 빠져나오면 합이 `N + (한 항의 최댓값)` 이하로 묶인다. 조기 종료는 성능 최적화가 아니라 **정확성 장치**다.
- hi를 답보다 작게 잡으면 오답. "가장 빠른 기계 하나로 전부"가 확실한 상한이다.
- 경계: 기계 1대(예제2)면 `t*N`, N=1이면 `min(t)`.
```

**6) 보조금 상한액 최대화** · Medium

- **요구사항**: N개 동아리가 각자 보조금을 요청했다. 총예산 B 안에서 **상한액 C**를 정해, 요청액이 C 이하인 동아리에는 요청액 그대로, C를 넘는 동아리에는 C만큼 지급한다. 지급 총액이 B를 넘지 않는 **최대 상한액 C**를 구하라(요청액 합이 B 이하면 가장 큰 요청액이 답).
- **입력**: 첫 줄 N과 B(1 ≤ N ≤ 10^4, 1 ≤ B ≤ 10^9), 둘째 줄 요청액 N개(1 ≤ 값 ≤ 10^5).
- **출력**: 최대 상한액.
- **예제**: `4 500 / 130 90 160 170` → `140` · `3 1000 / 200 300 100` → `300`
- **셀프체크**: `feasible(C) = sum(min(r, C)) <= B`. C가 커질수록 지급액은 늘어나니 `T...T F...F` → 최댓값 패턴. 예제1: C=140이면 130+90+140+140=500 ≤ 500 가능, C=141이면 502 초과 → 140. 범위는 `lo=0`(예산이 너무 작으면 상한 0), `hi=max(req)`(그 이상 올려도 지급액이 변하지 않음). 합은 최대 10^4 × 10^5 = 10^9이라 `int` 경계에 붙어 있으니 `long long`. `min(r, cap)`의 두 인자는 타입이 같아야 한다(`min(r, 0)`처럼 섞으면 컴파일 오류).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long b;
    cin >> n >> b;
    vector<long long> req(n);
    for (int i = 0; i < n; i++) cin >> req[i];

    // 상한 cap으로 지급해도 예산 안?
    auto feasible = [&](long long cap) -> bool {
        long long sum = 0;
        for (long long r : req) {
            sum += min(r, cap);        // 두 인자 모두 long long
            if (sum > b) return false;
        }
        return true;
    };

    long long lo = 0, hi = *max_element(req.begin(), req.end()), ans = 0;
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;
        if (feasible(mid)) {
            ans = mid;                 // 최댓값 -> 상한을 더 올려 시도
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    cout << ans << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 상한 C를 고정하면 지급 총액 `sum(min(r_i, C))`는 O(N)에 계산된다. 이 값이 예산 이하인지가 판정이다.
- C를 올리면 어떤 항도 줄지 않으므로 총액은 단조 증가 → 판정은 `T...T F...F`. 마지막 T(최대 C)가 답.

(2) 코드 단계별

- N, B와 요청액을 읽는다.
- `feasible(cap)`: 각 요청액과 cap 중 작은 값의 합이 B 이하인지. B를 넘는 순간 조기 종료.
- 구간 `[0, max(req)]`에서 성공하면 `ans=mid; lo=mid+1`, 실패하면 `hi=mid-1`.
- `ans` 출력. 예산이 충분하면 `max(req)`까지 전부 성공해 그 값이 답이 된다.

(3) 스스로 다시 짤 때 생각 순서

- "총액 제한 안에서 상한 최대" → 파라메트릭, 최댓값 패턴.
- 판정식에 `min(r, C)`를 정확히 쓴다(그냥 `C*N`으로 계산하면 요청액보다 많이 주는 셈이라 틀림).
- 함정 1 — **`std::min`/`std::max`는 두 인자의 타입이 정확히 같아야 한다.** `min(r, cap)`에서 `r`이 `int`이고 `cap`이 `long long`이면 "템플릿 인자를 추론할 수 없다"는 컴파일 오류가 난다. 같은 타입으로 맞추거나 `min<long long>(r, cap)`처럼 명시한다.
- 함정 2 — `*max_element(...)`는 반복자를 돌려주므로 앞에 `*`를 붙여 값을 꺼내야 한다. 빈 컨테이너에 부르면 `end()`를 역참조하게 되니 N ≥ 1인지 확인한다.
- 함정 3 — 합은 최대 10^9으로 `int`에 아슬아슬하게 들어가지만, 조기 종료 없이 끝까지 더하는 코드에서는 넘칠 수 있다. 누적 변수는 `long long`으로.
- 경계: C=0도 후보(예제3), 예산 충분 시 `max(req)`.
```

**7) 가장 가까운 정류장** · Medium

- **요구사항**: 직선 도로 위 정류장 N개의 좌표가 오름차순으로 주어진다(서로 다름). 질의 위치 q마다 **가장 가까운 정류장의 좌표**를 출력하라. 거리가 같은 정류장이 둘이면 **좌표가 작은 쪽**.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 오름차순 좌표 N개, 셋째 줄 Q(1 ≤ Q ≤ 10^5), 넷째 줄 질의 위치 Q개(모든 좌표·위치는 0 이상 10^9 이하 정수).
- **출력**: 질의마다 좌표를 한 줄씩.
- **예제**: `5 / 1 4 7 10 20 / 4 / 5 9 0 25` → `4 / 10 / 1 / 20` · `3 / 2 6 10 / 2 / 4 8` → `2 / 6`
- **셀프체크**: `pos = lower_bound(st, q) - st.begin()`로 "q 이상인 첫 정류장" 위치를 잡으면 후보는 `st[pos]`(오른쪽)와 `st[pos-1]`(왼쪽) 둘뿐이다. pos=0이면 왼쪽 후보가 없고, pos=N이면 오른쪽 후보가 없다 — 두 경계를 빠뜨리면 `vector`가 범위를 검사하지 않으므로 예외 대신 쓰레기값이 나온다. 동률이면 작은 좌표이므로 왼쪽 후보를 `<=`로 우선한다(예제2: q=4에 2와 6이 거리 2로 같음 → 2).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<long long> st(n);
    for (int i = 0; i < n; i++) cin >> st[i];

    int q;
    cin >> q;
    string out;
    for (int t = 0; t < q; t++) {
        long long x;
        cin >> x;
        int pos = (int)(lower_bound(st.begin(), st.end(), x) - st.begin());
        long long best = 0;
        bool has = false;
        if (pos < n) {                       // 오른쪽 후보
            best = st[pos];
            has = true;
        }
        if (pos > 0) {                       // 왼쪽 후보(동률이면 우선)
            long long left = st[pos - 1];
            if (!has || x - left <= best - x) best = left;
            has = true;
        }
        out += to_string(best);
        out += '\n';
    }
    cout << out;
    return 0;
}

(1) 접근·핵심 아이디어

- 정렬된 좌표에서 q에 가장 가까운 값은 "q 이상인 첫 원소"와 "그 바로 왼쪽 원소" 둘 중 하나다. lower_bound 한 번(O(log N))으로 두 후보를 얻고 거리를 비교하면 된다.
- 동률 규칙(작은 좌표)은 왼쪽 후보를 `<=`로 먼저 채택해 처리한다.

(2) 코드 단계별

- 좌표 배열과 질의를 읽는다(좌표는 이미 오름차순이라 정렬이 필요 없다).
- `pos = lower_bound(st.begin(), st.end(), x) - st.begin()`. `pos < n`이면 오른쪽 후보 `st[pos]`를 일단 `best`로.
- `pos > 0`이면 왼쪽 후보 `st[pos-1]`을 보고, 오른쪽 후보가 없거나 거리가 같거나 더 가까우면 `best`를 왼쪽으로 교체.
- 질의마다 `best`를 모아 출력.

(3) 스스로 다시 짤 때 생각 순서

- "가장 가까운 값" → lower_bound 후 양옆 두 후보만 비교한다는 틀을 세운다.
- 후보가 하나뿐인 경계(pos=0, pos=N)를 먼저 처리한다. 파이썬이라면 `st[pos]`가 IndexError를 내며 즉시 알려 주지만, C++의 `vector::operator[]`는 범위를 검사하지 않아 쓰레기값을 조용히 읽는다 — 그래서 경계 검사를 **코드로 명시하는 것**이 더 중요하다. 디버깅할 때 `.at()`으로 바꾸면 예외가 잡힌다.
- 함정 — "값이 없음"을 파이썬처럼 `None`으로 둘 수 없으니 `bool has` 같은 플래그나 `LLONG_MAX` 같은 감시값을 쓴다. 감시값을 쓸 때는 그 값으로 거리를 계산하다 오버플로하지 않는지 확인한다.
- 동률 규칙이 "작은 쪽"이면 왼쪽을 `<=`로, "큰 쪽"이면 오른쪽을 우선하도록 부등호 하나만 바꾼다.
```

**8) 휴게소 폐쇄 후 최소 간격 최대화** · Hard

- **요구사항**: 길이 D인 고속도로의 시작점 0과 끝점 D에는 폐쇄할 수 없는 휴게소가 있고, 그 사이에 휴게소 N개가 있다. 사이 휴게소 중 **최대 K개를 폐쇄**해, 남은 휴게소(0과 D 포함)들의 **인접 간격의 최솟값**을 최대화하고 그 값을 출력하라.
- **입력**: 첫 줄 D, N, K(1 ≤ D ≤ 10^9, 1 ≤ N ≤ 10^5, 0 ≤ K ≤ N), 둘째 줄 사이 휴게소 위치 N개(0 < 위치 < D, 서로 다름, 정렬돼 있지 않음).
- **출력**: 최소 간격의 최댓값.
- **예제**: `20 5 2 / 3 6 10 14 17` → `4` · `10 3 0 / 2 5 7` → `2`
- **셀프체크**: 판정 `feasible(g)` = "모든 간격을 g 이상으로 만들기 위해 폐쇄해야 하는 개수가 K 이하인가?" 왼쪽부터 훑으며 **`p - last >= g` 이고 `D - p >= g`일 때만 유지**(뒤 조건이 없으면 끝점 D와 너무 가까운 휴게소를 유지해 버린다), 아니면 폐쇄로 센다. g가 커질수록 폐쇄 수가 늘어나니 `T...T F...F` → 최댓값 패턴, `hi=D`(전부 폐쇄하면 간격 D). 예제1: g=4면 3 폐쇄, 6·10·14 유지, 17 폐쇄(20-17 < 4) → 2개 ≤ 2 가능; g=5면 3·10·17 폐쇄로 3개 > 2 불가 → 4. K=0이면 폐쇄 없이 현재 최소 간격이 답(예제2).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

long long d;
long long k;
vector<long long> pos;

// 최대 k개만 닫고 모든 간격 >= g 가능?
bool feasible(long long g) {
    long long removed = 0, last = 0;   // last: 마지막으로 유지한 휴게소(처음엔 시작점 0)
    for (size_t i = 0; i < pos.size(); i++) {
        long long p = pos[i];
        if (p - last >= g && d - p >= g) {   // 앞 간격·끝점까지 간격 모두 확보될 때만 유지
            last = p;
        } else {
            removed++;
            if (removed > k) return false;
        }
    }
    return true;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    long long n;
    cin >> d >> n >> k;
    pos.resize((size_t)n);
    for (long long i = 0; i < n; i++) cin >> pos[(size_t)i];
    sort(pos.begin(), pos.end());

    long long lo = 1, hi = d, ans = 0;
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;
        if (feasible(mid)) {
            ans = mid;                 // 최댓값 -> 더 넓은 간격 시도
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    cout << ans << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- "최소 간격을 최대화"는 파라메트릭 신호다. 간격 g를 고정하면 "간격을 전부 g 이상으로 만들 때 폐쇄해야 하는 최소 개수"를 그리디로 O(N)에 셀 수 있다: 왼쪽부터 보며 앞 휴게소와 g 이상 떨어져 있고 끝점 D까지도 g 이상 남는 휴게소만 유지, 나머지는 폐쇄.
- 유지 가능한 휴게소를 가장 왼쪽 것부터 채택하는 것이 유지 개수를 최대화(= 폐쇄 최소화)한다. g가 커질수록 유지 조건이 엄격해져 폐쇄 수는 단조 증가 → `T...T F...F`, 마지막 T가 답.

(2) 코드 단계별

- 위치를 `sort`한다. `last=0`(시작점), `removed=0`.
- 각 위치 p에 대해 `p - last >= g && d - p >= g`면 `last=p`로 유지, 아니면 `removed++`. K를 넘는 순간 `false`.
- 구간 `[1, D]`에서 성공 시 `ans=mid; lo=mid+1`, 실패 시 `hi=mid-1`.
- `hi=D`: 사이 휴게소를 전부 닫으면 0과 D만 남아 간격 D가 가능(K=N일 때).

(3) 스스로 다시 짤 때 생각 순서

- "최소를 최대로 + K개 제거" → 파라메트릭, 판정은 그리디로 "제거 개수 세기".
- 끝점 D가 고정이라는 점을 판정에 반드시 반영한다(`d - p >= g`). 이 조건을 빼면 마지막 유지 휴게소와 D 사이가 g 미만인데도 `true`가 나온다.
- 함정 — 판정 함수가 이진탐색마다 불리므로(약 30번) 큰 `vector`를 **값으로 넘기면** 30번의 전체 복사가 일어난다. 전역에 두거나 `const vector<long long>&`로 받는다. C++에서 함수 인자의 기본은 복사라는 점이 파이썬과 결정적으로 다르다.
- 함정 2 — 반복문 인덱스를 `size_t`로 쓰면서 `i >= 0` 같은 조건을 섞지 않도록 주의한다. 여기서는 정방향이라 안전하지만, 역방향으로 바꾸는 변형에서는 `int`로 돌려야 한다.
- 단조 방향(g↑ → 제거↑) → 최댓값 패턴. K=0(제거 불가), K=N(전부 제거) 두 극단을 검산한다.
```

**9) 피자 균등 분배 최대 넓이** · Hard

- **요구사항**: 반지름이 정수인 원형 피자 N판이 있다. K명에게 **넓이가 똑같은 조각을 하나씩** 나눠 주려 한다. 한 조각은 반드시 한 판에서 잘라내며(두 판의 조각을 합치지 않음), 남는 부분은 버린다. 한 조각의 **최대 넓이**를 구해 **소수점 아래를 버린 정수**로 출력하라(원주율은 `acos(-1.0)`).
- **입력**: 첫 줄 N과 K(1 ≤ N ≤ 10^4, 1 ≤ K ≤ 10^6), 둘째 줄 반지름 N개(1 ≤ r ≤ 10^4).
- **출력**: 최대 조각 넓이를 내림한 정수.
- **예제**: `2 3 / 1 2` → `4` · `3 4 / 3 3 2` → `14`
- **셀프체크**: 넓이 A를 고정하면 판 i에서 `(long long)(pi*r_i*r_i / A)`조각이 나오고, 총합이 K 이상이면 가능. A가 커질수록 조각 수는 줄어드니 `T...T F...F`. 답이 실수(π의 유리수배)라 정수 이진탐색이 안 되므로 `[0, max(넓이)]`에서 **100회 고정 반복** 실수 이분을 돌린다 — `while (hi - lo > 1e-9)`는 값이 클 때 `double`의 표현 한계 때문에 두 값이 더 이상 가까워지지 못해 **영원히 끝나지 않을 수 있다.** 예제1: 넓이 π(≈3.14)와 4π(≈12.57). A=4π/3≈4.19면 0+3=3 ≥ 3 가능, 그보다 크면(예: 4π/2≈6.28) 0+2=2 불가 → 4.19 → 4.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long k;
    cin >> n >> k;
    const double PI = acos(-1.0);          // M_PI는 표준이 아니라 이식성이 떨어진다
    vector<double> areas(n);
    double maxArea = 0.0;
    for (int i = 0; i < n; i++) {
        long long r;
        cin >> r;
        areas[i] = PI * (double)r * (double)r;
        maxArea = max(maxArea, areas[i]);
    }

    // 넓이 a 조각을 k개 이상 만들 수 있나?
    auto feasible = [&](double a) -> bool {
        if (a <= 0.0) return true;         // 0으로 나누기 방어
        long long cnt = 0;
        for (double s : areas) {
            cnt += (long long)(s / a);     // 양수라 절단 = 내림
            if (cnt >= k) return true;
        }
        return false;
    };

    double lo = 0.0, hi = maxArea;
    for (int it = 0; it < 100; it++) {     // 고정 횟수: eps 비교는 끝나지 않을 수 있다
        double mid = lo + (hi - lo) / 2;
        if (feasible(mid)) lo = mid;       // 가능 -> 더 큰 조각 시도
        else hi = mid;
    }
    cout << (long long)lo << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 조각 넓이 A를 고정하면 각 판에서 나오는 조각 수는 `floor(넓이_i / A)`이고, 합이 K 이상이면 가능. A가 커질수록 합은 줄어드니 `T...T F...F`(최댓값 패턴).
- 답이 정수가 아니라 실수이므로, 정수 `while (lo <= hi)` 대신 `[lo, hi]` 실수 구간을 100번 반으로 접는다. 100번이면 구간 폭이 초기 폭의 2^-100 배가 되어 출력 정밀도(정수 내림)에는 차고 넘친다.

(2) 코드 단계별

- 반지름을 읽어 넓이 `PI*r*r` 배열을 만든다. `acos(-1.0)`이 이식성 있는 π다(`M_PI`는 표준 헤더가 보장하지 않는다).
- `feasible(a)`: 각 넓이를 a로 나눈 몫을 더하며 K에 도달하면 즉시 `true`.
- `lo=0.0, hi=max(areas)`. 100회 반복: 성공이면 `lo=mid`(더 큰 조각), 실패면 `hi=mid`.
- 마지막 `lo`를 `(long long)`으로 내려 출력.

(3) 스스로 다시 짤 때 생각 순서

- 답이 정수가 아니면 "고정 횟수 실수 이분"으로 전환한다는 규칙을 떠올린다.
- 함정 1 — **`while (hi - lo > eps)`를 쓰지 않는다.** `double`은 값이 클수록 표현 가능한 간격도 커진다(10^8 근처에서는 이웃한 두 `double` 사이가 이미 10^-8보다 크다). 그래서 `eps`를 작게 잡으면 `hi - lo`가 그 아래로 내려가지 못해 루프가 영원히 돈다. 반대로 크게 잡으면 정밀도가 모자란다. **고정 횟수 반복**은 두 문제를 동시에 없앤다 — 100회면 어떤 초기 폭이든 실수 표현 한계까지 좁혀진다.
- 함정 2 — 실수 이분에서는 `lo = mid + 1` 같은 정수식 갱신을 쓰지 않는다. `lo = mid`, `hi = mid`로 구간을 그대로 물려준다(정수 이분에서 `lo = mid`를 쓰면 무한 루프지만, 횟수가 고정된 실수 이분에서는 안전하다).
- 함정 3 — `(long long)(s / a)`는 **0 방향 절단**이다. 여기서는 양수뿐이라 내림과 같지만, 음수가 섞이면 `floor()`를 명시해야 한다. 그리고 `a`가 0에 가까우면 몫이 폭발하므로 조기 종료(`cnt >= k`)로 값이 커지기 전에 빠져나온다.
- 판정은 정수 문제와 똑같이 O(N) 몫의 합. 단조 방향 확인 → 최댓값 패턴.
- 출력 규칙(내림 정수)에 맞춰 `(long long)lo`. 경계: K가 매우 커서 조각이 1보다 작아지면 0(예제4), 판 하나에 한 명이면 π의 내림 3(예제3).
```

**10) K번째로 가까운 두 집 사이 거리** · Hard

- **요구사항**: 직선 도로 위 집 N채의 좌표가 주어진다(같은 좌표 가능). 모든 두 집 쌍 (i < j)의 거리 `|x_i - x_j|`를 오름차순으로 나열했을 때 **K번째 값**을 구하라. 쌍의 개수는 N(N-1)/2개로 매우 많으니 전부 만들어 정렬하면 안 된다.
- **입력**: 첫 줄 N과 K(2 ≤ N ≤ 10^5, 1 ≤ K ≤ N(N-1)/2), 둘째 줄 좌표 N개(0 ≤ 좌표 ≤ 10^9).
- **출력**: K번째로 작은 거리.
- **예제**: `4 3 / 1 3 6 10` → `4` · `3 3 / 5 5 5` → `0`
- **셀프체크**: "거리 d 이하인 쌍이 몇 개인가?"는 정렬 후 **투 포인터**로 O(N)에 센다(j를 오른쪽으로 옮기며 `x[j]-x[i] > d`인 동안 i를 전진, `j - i`를 누적). 이 개수는 d에 대해 단조 증가하므로 "개수 ≥ K"는 `F...F T...T` → 첫 T가 K번째 거리(최솟값 패턴). **개수와 K는 최대 N(N-1)/2 ≈ 5·10^9이라 `int`로는 넘친다** — 둘 다 `long long`. 예제1: 거리들 `2 3 4 5 7 9`에서 3번째 = 4; d=3이면 개수 2 < 3, d=4면 3 ≥ 3. 같은 좌표가 있으면 거리 0이 답일 수 있으니 `lo=0`. 검색 대상은 "인덱스"가 아니라 **"거리 값"** 임에 주의.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    long long k;                       // K는 5e9까지 -> int로는 못 받는다
    cin >> n >> k;
    vector<long long> xs(n);
    for (int i = 0; i < n; i++) cin >> xs[i];
    sort(xs.begin(), xs.end());

    // 거리 <= d 인 쌍의 개수 (투 포인터)
    auto countLE = [&](long long d) -> long long {
        long long cnt = 0;             // 최대 5e9 -> long long
        int i = 0;
        for (int j = 0; j < n; j++) {
            while (xs[j] - xs[i] > d) i++;
            cnt += (long long)(j - i); // i..j-1 각각이 j와 쌍을 이룬다
        }
        return cnt;
    };

    long long lo = 0, hi = xs[n - 1] - xs[0];
    long long ans = hi;                // 최대 거리면 모든 쌍 포함 -> 항상 가능
    while (lo <= hi) {
        long long mid = lo + (hi - lo) / 2;
        if (countLE(mid) >= k) {       // k번째가 mid 이하 -> 더 작게 시도
            ans = mid;
            hi = mid - 1;
        } else {
            lo = mid + 1;
        }
    }
    cout << ans << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- K번째 거리를 직접 뽑으려면 모든 쌍을 만들어야 하지만, "거리 d 이하인 쌍의 개수"는 정렬 후 투 포인터로 O(N)에 센다. 이 개수를 `cnt(d)`라 하면 K번째 거리는 `cnt(d) >= K`를 만족하는 **최소 d**다(정확히 K번째 값에서 처음으로 개수가 K 이상이 된다).
- d가 커지면 `cnt(d)`는 줄지 않으므로 `F...F T...T` 단조성이 성립 → 값(거리)을 이진탐색한다. 전체 O(N log N + N log(범위)).

(2) 코드 단계별

- 좌표를 `sort`한다.
- `countLE(d)`: j를 0부터 훑으며 `xs[j] - xs[i] > d`인 동안 i를 전진시키고, `j - i`(i..j-1이 j와 만드는 쌍 수)를 누적. i는 뒤로 가지 않으므로 O(N).
- `lo=0`(같은 좌표 가능), `hi=max-min`(모든 쌍 포함이라 항상 성공)에서 `countLE(mid) >= k`면 `ans=mid; hi=mid-1`, 아니면 `lo=mid+1`.
- 첫 성공값 `ans` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "K번째로 작은 값"을 "값 d 이하가 K개 이상인 최소 d"로 바꿔 읽는다 — 이 치환이 이 유형의 전부다.
- 함정 1 — **개수의 오버플로.** N=10^5면 쌍의 수가 약 5·10^9으로 `int`(약 2.1·10^9)를 두 배 넘게 초과한다. `cnt`뿐 아니라 **입력으로 받는 K도 `long long`**이어야 한다. `int`로 받으면 큰 K가 음수로 들어와 판정이 처음부터 참이 되어 답이 0으로 나온다. 파이썬에서는 정수 상한이 없어 생각할 필요조차 없던 지점이다.
- 함정 2 — `cnt += j - i`에서 `j`, `i`가 `int`면 뺄셈이 `int`로 이뤄진 뒤 `long long`에 더해진다. 여기서는 차가 최대 10^5라 안전하지만, 곱셈이 섞이는 변형(`(long long)(j - i) * something`)에서는 **곱하기 전에** 한쪽을 `long long`으로 올려야 한다.
- 개수 세기를 투 포인터로 O(N)에 만들고, 단조 방향(d↑ → 개수↑) → 최솟값 패턴.
- 함정 3 — 투 포인터의 `i`는 절대 뒤로 가지 않는다. `j` 루프 안에서 `i`를 0으로 되돌리면 O(N²)이 되어 판정 한 번이 10^10이 된다.
- 경계: 좌표 중복(거리 0), N=2(쌍 하나), K가 최대(= 최대 거리)를 검산한다.
```

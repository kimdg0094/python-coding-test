> 개요: 재귀 기반 깊이 우선 탐색(DFS)을 그래프와 격자에서 자유자재로 다루는 법을 배운다. 방문 관리·연결요소·경로 추적·되돌아오기(백트래킹과의 경계)까지, DFS를 "실전 도구"로 쓰는 감각을 잡는다.
>
> 전에 배운 것 → 이번에 새로: Ch2의 재귀/백트래킹은 "정답 후보를 만들며 파고들었다"면, 이번 DFS는 같은 재귀 뼈대에 **`visited` 방문 관리**를 얹어 "이미 본 노드·칸을 다시 밟지 않으며 그래프/격자를 빠짐없이 순회"하는 데 쓴다. 즉 새로 추가되는 핵심은 방문 배열과 인접 구조(인접리스트·4방향 이동)다.

## L1. DFS

**개념**

- DFS(Depth-First Search, 깊이 우선 탐색)는 한 갈래를 갈 수 있는 데까지 끝까지 파고든 뒤, 막히면 직전 갈림길로 되돌아와(backtrack) 다음 갈래를 탐색하는 그래프 순회 방식이다. "일단 깊게, 막히면 되돌아온다"가 전부다.
- 이미 DFS의 존재는 알고 있을 것이다. 이 레슨의 목표는 재설명이 아니라, DFS를 (1) 인접리스트 그래프, (2) 2차원 격자 두 무대에서 확실하게 구현하고, (3) 방문 처리 위치·시점을 정확히 통제하며, (4) 연결요소·경로·사이클 등 전형 응용으로 확장하는 것이다.
- 동작 원리(재귀 관점, 단계):

  1. 현재 노드를 방문 처리한다(`visited[cur] = true`).
  2. 현재 노드에서 갈 수 있는 인접 노드를 하나씩 본다.
  3. 아직 방문하지 않은 인접 노드가 있으면 그 노드로 재귀 호출한다(더 깊이 들어감).
  4. 더 갈 곳이 없으면 함수가 반환되며 자동으로 직전 노드로 되돌아온다(콜스택이 backtrack을 대신해 준다).

- 핵심은 "재귀 호출 = 스택에 프레임을 쌓는 것"이라는 관점이다. 명시적 스택(`std::stack`)으로 반복 구현도 가능하지만, DFS는 재귀로 쓰는 편이 짧고 자연스럽다. 다만 C++는 OS 스택이 유한하므로 깊이가 수십만을 넘길 위험이 크면 반복 DFS가 안전하다.

```cpp
#include <bits/stdc++.h>
using namespace std;

int N, M;
vector<vector<int>> graph;      // 인접리스트
vector<bool> visited;           // 그래프용 방문 배열
vector<string> grid;            // 2차원 격자
vector<vector<bool>> vis2d;     // 격자용 방문 배열

// (1) 인접리스트 그래프 DFS
void dfs(int cur) {
    visited[cur] = true;
    // (필요하면) 여기서 방문 순서 기록, 카운트 증가 등
    for (int nxt : graph[cur]) {
        if (!visited[nxt]) dfs(nxt);
    }
}

// (2) 2차원 격자 DFS
int dr[4] = {-1, 1, 0, 0};
int dc[4] = {0, 0, -1, 1};      // 상하좌우
void dfs_grid(int r, int c) {
    vis2d[r][c] = true;
    for (int d = 0; d < 4; d++) {
        int nr = r + dr[d], nc = c + dc[d];
        if (nr >= 0 && nr < N && nc >= 0 && nc < M
            && !vis2d[nr][nc] && grid[nr][nc] == '1') {
            dfs_grid(nr, nc);
        }
    }
}
```

**접근 전략**

- 방문 처리 "위치"를 명확히 정하라. 가장 안전한 패턴은 "함수에 들어오자마자 현재 노드를 방문 처리"(위 코드). 반대로 "다음 노드로 재귀하기 직전에 미리 방문 처리"하는 스타일도 있는데, 후자는 시작 노드를 별도로 방문 처리해야 하고 중복 진입을 부르기 쉬우니, 익숙해지기 전엔 "들어오자마자 방문" 한 가지로 통일하는 것을 권한다.
- 전형 응용 4가지를 패턴으로 외워 두면 대부분이 조합이다.

  1. 연결요소(Connected Component) 세기: 모든 정점을 순회하며 `visited`가 안 된 정점에서 DFS를 시작할 때마다 카운트 +1. 격자에서는 "덩어리(섬)"의 개수·크기를 세는 문제로 자주 나온다.
  2. 도달 가능성/경로 존재: 시작점에서 DFS 후 목표점의 `visited`를 확인.
  3. 경로 복원: 재귀에 `path` 벡터를 넘겨 진입 시 `push_back`, 반환 직전 `pop_back`(백트래킹). 특정 경로를 "만들며" 탐색할 때.
  4. 사이클 탐지: 방문 상태를 3색(0=미방문, 1=현재 스택에 있음, 2=완료)으로 관리해 "현재 재귀 경로 위의 노드로 되돌아가는 간선"이 있으면 사이클(주로 방향 그래프). 무방향 그래프는 "부모가 아닌 방문 노드로 가는 간선"이 사이클.

- 언제 DFS를 고르나: "모든 정점/칸을 빠짐없이 방문", "덩어리/영역", "경로가 존재하는가", "가능한 조합을 깊이 만들며 탐색" 같은 요구에 자연스럽다. 반대로 "최단 거리(간선 가중치 동일)"는 DFS가 아니라 BFS가 정석이다(DFS는 최단을 보장하지 않는다). 다음 챕터의 BFS와 역할을 헷갈리지 말 것.
- 복잡도: 인접리스트 기준 시간 O(V + E), 격자(N×M)는 O(N·M). 공간은 `visited` O(V) 또는 O(N·M)에 더해 재귀 콜스택 깊이만큼 O(V)(최악, 일자형 그래프)가 추가로 든다.
- C++ 구현 팁:

  - C++ 재귀는 OS 스택(보통 1~8MB)에 프레임을 쌓는다. 정점/칸이 수십만~백만이고 그래프가 "일자형(뱀 모양)"이면 재귀 깊이가 폭발해 스택 오버플로로 죽을 수 있다. 이럴 땐 `std::stack`을 쓰는 **반복 DFS**로 바꾸면 힙에 상태를 쌓으므로 안전하다.
  - 입출력이 많으면 `ios::sync_with_stdio(false); cin.tie(nullptr);`로 속도를 확보한다.
  - `graph`는 `vector<vector<int>> graph(V + 1)` 인접리스트로. `visited`는 격자면 `vector<vector<bool>>`, 그래프면 `vector<bool>`/`unordered_set<int>`.
  - 격자 한 줄을 `string`으로 읽으면 각 칸은 문자 `'0'`/`'1'`이다. 숫자로 비교할 땐 `grid[r][c] == '1'`처럼 문자 리터럴로 비교하거나 `grid[r][c] - '0'`으로 정수화한다.
  - 흔한 실수: (a) 방문 처리를 안 하거나 늦게 해서 같은 노드에 무한 재귀, (b) 격자 범위 검사(`0 <= nr < N`)를 빠뜨려 인덱스 오류, (c) DFS로 최단거리를 구하려 함, (d) 깊은 재귀에서 스택 오버플로(반복 DFS로 회피).

**문제**

**1) 섬의 개수와 가장 큰 섬** · Easy

- **요구사항**: `N×M` 격자에서 `1`은 땅, `0`은 바다다. 상하좌우로 인접한 땅끼리는 같은 섬이다(대각선은 연결 아님). 섬의 총 개수와, 가장 큰 섬의 넓이(칸 수)를 구하라.
- **입력**: 첫 줄에 `N M`. 이어서 `N`개의 줄에 각 줄 `M`개의 `0/1`이 공백 없이 주어진다. (`1 ≤ N, M ≤ 1000`)
- **출력**: `섬의 개수`와 `가장 큰 섬의 넓이`를 공백으로 구분해 한 줄에.
- **예제**:

  - `입력`:
    ```
    5 5
    11000
    11000
    00100
    00011
    00011
    ```
    → `출력`: `3 4`
  - `입력`:
    ```
    3 3
    101
    010
    101
    ```
    → `출력`: `5 1`

- **셀프체크**: 방문 안 된 땅에서 DFS를 시작할 때마다 섬 카운트를 늘리고, 그 DFS가 방문한 칸 수가 그 섬의 넓이다. 1000×1000이면 최대 백만 칸 → 재귀 DFS는 콜스택 깊이가 최악에 백만에 근접(한 줄로 이어진 뱀 모양)해 스택 오버플로로 죽을 수 있으니, `std::stack` 기반 반복 DFS로 짜는 것이 안전하다. 두 번째 예제의 답이 "섬 5개, 각 넓이 1"이 되는지 직접 확인해 보라(대각선은 연결이 아님).

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int N, M;
vector<string> grid;
vector<vector<bool>> visited;
int dr[4] = {-1, 1, 0, 0};
int dc[4] = {0, 0, -1, 1};

int flood(int sr, int sc) {
    // 반복(명시적 스택) DFS: 1000x1000 뱀 모양에서도 콜스택 폭발이 없다.
    stack<pair<int,int>> st;
    st.push({sr, sc});
    visited[sr][sc] = true;
    int area = 0;
    while (!st.empty()) {
        auto [r, c] = st.top(); st.pop();
        area++;
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < N && nc >= 0 && nc < M
                && !visited[nr][nc] && grid[nr][nc] == '1') {
                visited[nr][nc] = true;
                st.push({nr, nc});
            }
        }
    }
    return area;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> N >> M;
    grid.resize(N);
    for (int i = 0; i < N; i++) cin >> grid[i];
    visited.assign(N, vector<bool>(M, false));

    int count = 0, best = 0;
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < M; j++) {
            if (grid[i][j] == '1' && !visited[i][j]) {
                count++;
                int a = flood(i, j);
                if (a > best) best = a;
            }
        }
    }
    cout << count << " " << best << "\n";
    return 0;
}

--OUT

--IN

--OUT

(1) 접근·핵심 아이디어

- 격자 전체를 훑다가 "아직 방문 안 된 땅(`1`)"을 만나면 거기서 하나의 섬 탐색(플러드 필)을 시작한다. 탐색을 시작할 때마다 섬 개수를 +1 하고, 그 탐색이 밟은 칸 수가 곧 그 섬의 넓이다.
- 인접은 상하좌우 4방향만(대각선 제외). 두 번째 예제에서 대각선으로만 붙은 `1`들이 전부 따로따로 세어져 "섬 5개, 넓이 1"이 되는 것이 이 규칙의 확인 포인트다.
- 재귀 대신 **명시적 스택(`std::stack`)**으로 DFS를 돌린다. 1000×1000에서 한 줄로 이어진 섬은 재귀 깊이가 백만에 육박해 C++ 콜스택으로는 오버플로 위험이 크기 때문.

(2) 코드 단계별

- 격자를 `vector<string>`으로 읽으면 각 칸은 문자 `'0'`/`'1'`이고, `visited`는 같은 크기의 `vector<vector<bool>>`로 만든다.
- `flood(sr, sc)`: 시작 칸을 스택에 넣고 방문 처리한 뒤, 스택에서 꺼낼 때마다 `area++`. 4방향 이웃이 범위 안·미방문·땅(`'1'`)이면 방문 처리 후 스택에 push. 스택에 넣을 때 바로 방문 처리해야 같은 칸이 중복으로 안 들어간다.
- 이중 for로 모든 칸을 보며 미방문 땅에서 `flood`를 호출, 반환된 넓이로 `count`와 `best`(최대 넓이)를 갱신한다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "연결요소 개수 세기" 뼈대를 떠올린다: 미방문 시작점마다 count+1 + 탐색.
- 여기에 "탐색이 방문한 칸 수 = 넓이"를 얹어 최댓값을 함께 추적.
- 방문 처리 시점(스택에 넣기 직전)과 4방향 오프셋 `dr/dc`, 범위 검사만 정확히 하면 끝. 깊이가 클 수 있으니 재귀보다 반복 스택을 기본으로 택한다.
```

**2) 미로 탈출 가능 여부** · Medium

- **요구사항**: `N×M` 격자 미로에서 `0`은 벽, `1`은 이동 가능한 길이다. 시작 칸 `(sr, sc)`에서 상하좌우로만 이동해 도착 칸 `(er, ec)`에 도달할 수 있는지 판정하라. 도달 가능하면 방문한(도달 가능한) 칸의 총 개수도 함께 출력한다.
- **입력**: 첫 줄 `N M`. 다음 `N`줄에 격자(`0/1`, 공백 없이). 마지막 줄에 `sr sc er ec` (0-based 좌표). (`1 ≤ N, M ≤ 500`, 시작·도착 칸은 항상 `1`)
- **출력**: 도달 가능하면 `YES`와 시작 칸에서 도달 가능한 칸의 개수를 공백으로. 불가능하면 `NO`만.
- **예제**:

  - `입력`:
    ```
    3 4
    1101
    1001
    1111
    0 0 0 3
    ```
    → `출력`: `YES 9`
  - `입력`:
    ```
    3 3
    100
    010
    001
    0 0 2 2
    ```
    → `출력`: `NO`

- **셀프체크**: 시작 칸에서 DFS로 도달 가능한 모든 칸을 방문 처리한 뒤 도착 칸의 방문 여부만 보면 된다. 첫 예제에서 시작 `(0,0)`의 연결 덩어리 칸 수를 세어 보면: `(0,0),(0,1),(1,0),(2,0),(2,1),(2,2),(2,3),(1,3),(0,3)`으로 9칸이고 도착 `(0,3)`도 이 덩어리에 포함 → `YES 9`. `(0,3)`이 도착이지만 위쪽 한 칸으로 곧장 닿는 게 아니라 아래로 우회해(오른쪽 열을 타고 내려갔다 올라와) 이어진다는 점을 확인하라. 두 번째 예제는 대각선 이동이 없어 어디로도 못 가므로 `NO`.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int N, M;
    cin >> N >> M;
    vector<string> grid(N);
    for (int i = 0; i < N; i++) cin >> grid[i];
    int sr, sc, er, ec;
    cin >> sr >> sc >> er >> ec;

    vector<vector<bool>> visited(N, vector<bool>(M, false));
    int dr[4] = {-1, 1, 0, 0};
    int dc[4] = {0, 0, -1, 1};

    // 시작 칸에서 반복 DFS로 도달 가능한 칸을 모두 방문 처리하며 개수를 센다.
    stack<pair<int,int>> st;
    st.push({sr, sc});
    visited[sr][sc] = true;
    int cnt = 0;
    while (!st.empty()) {
        auto [r, c] = st.top(); st.pop();
        cnt++;
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < N && nc >= 0 && nc < M
                && !visited[nr][nc] && grid[nr][nc] == '1') {
                visited[nr][nc] = true;
                st.push({nr, nc});
            }
        }
    }

    if (visited[er][ec]) cout << "YES " << cnt << "\n";
    else cout << "NO\n";
    return 0;
}

(1) 접근·핵심 아이디어

- "도달 가능한가?"는 결국 시작 칸이 속한 연결요소 문제다. 시작 칸에서 DFS로 갈 수 있는 모든 길 칸을 방문 처리하고, 마지막에 도착 칸이 방문됐는지만 확인하면 된다.
- 도달 가능하면 그 연결요소의 칸 수가 곧 "도달 가능한 칸의 개수"이므로 탐색 중에 세어 두면 추가 작업이 필요 없다.
- 이동은 상하좌우 4방향뿐. 두 번째 예제처럼 대각선으로만 이어진 길은 서로 끊긴 것으로 취급되어 `NO`가 된다.

(2) 코드 단계별

- 격자와 시작·도착 좌표를 읽는다(좌표는 0-based). 격자 각 칸은 문자 `'0'`/`'1'`이다.
- 시작 칸을 `std::stack`에 넣고 방문 처리한 뒤, 스택에서 꺼낼 때마다 `cnt++`. 4방향 이웃이 범위 안·미방문·길(`'1'`)이면 방문 처리 후 push.
- 탐색이 끝나면 `visited[er][ec]`가 `true`면 `YES`와 `cnt`를, 아니면 `NO`만 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "경로 존재 = 같은 연결요소인가"로 문제를 바꿔 생각한다.
- 시작점 하나에서만 DFS/BFS를 돌리면 되고(전체 순회 아님), 방문 표시와 카운트를 동시에 한다.
- 마지막에 도착 칸의 방문 플래그만 보면 판정 끝. 출력 형식(도달 시 개수 동반, 불가 시 `NO`만)에 유의한다.
```

**3) 방향 그래프 사이클 판정** · Medium

- **요구사항**: 정점 `N`개, 방향 간선 `M`개인 그래프가 주어진다. 이 그래프에 사이클이 존재하는지 판정하라(자기 자신으로의 간선도 사이클로 본다).
- **입력**: 첫 줄 `N M`. 이어서 `M`개의 줄에 `u v` (정점 `u`에서 `v`로 가는 방향 간선, 1-based). (`1 ≤ N ≤ 10^5`, `0 ≤ M ≤ 2×10^5`)
- **출력**: 사이클이 있으면 `YES`, 없으면 `NO`.
- **예제**:

  - `입력`:
    ```
    3 3
    1 2
    2 3
    3 1
    ```
    → `출력`: `YES`
  - `입력`:
    ```
    4 3
    1 2
    1 3
    2 4
    ```
    → `출력`: `NO`

- **셀프체크**: 3색(0/1/2) DFS로 판정한다. 노드에 진입할 때 `state=1`(현재 재귀 경로 위), 자식 탐색을 마치면 `state=2`(완료). 탐색 도중 `state=1`인 노드를 다시 만나면 그 노드가 지금 내 재귀 경로 상에 있다는 뜻이므로 사이클이다. 단순히 `visited` 하나로만 판정하면 "이미 완료된 다른 갈래를 다시 만나는 경우"까지 사이클로 오판하니 주의(그래서 2색이 아니라 3색). 시작 정점이 여러 개일 수 있으니 모든 정점에 대해 미방문이면 DFS를 돌려야 한다. `N`이 10만이라 재귀로 짜면 스택 오버플로 위험이 크니, 스택에 `(노드, 다음 이웃 인덱스)` 상태를 담는 반복 DFS로 3색을 그대로 흉내 낸다. 첫 예제는 `1→2→3→1`로 사이클, 둘째는 DAG라 사이클 없음.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int N, M;
    cin >> N >> M;
    vector<vector<int>> graph(N + 1);
    for (int i = 0; i < M; i++) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
    }

    // 3색 반복 DFS: 0=미방문, 1=현재 경로 위, 2=완료
    vector<int> state(N + 1, 0);
    vector<int> iter(N + 1, 0);  // 각 노드에서 다음에 볼 이웃 인덱스
    bool has_cycle = false;

    for (int start = 1; start <= N && !has_cycle; start++) {
        if (state[start] != 0) continue;
        stack<int> st;
        st.push(start);
        state[start] = 1;
        iter[start] = 0;
        while (!st.empty()) {
            int node = st.top();
            if (iter[node] < (int)graph[node].size()) {
                int nxt = graph[node][iter[node]++];
                if (state[nxt] == 1) {        // 현재 경로 위의 노드 -> 사이클
                    has_cycle = true;
                    break;
                } else if (state[nxt] == 0) { // 미방문 -> 더 깊이
                    state[nxt] = 1;
                    iter[nxt] = 0;
                    st.push(nxt);
                }
                // state[nxt] == 2 (완료)면 무시
            } else {
                state[node] = 2;             // 자식 다 봤음 -> 완료
                st.pop();
            }
        }
    }

    cout << (has_cycle ? "YES" : "NO") << "\n";
    return 0;
}

(1) 접근·핵심 아이디어

- 방향 그래프의 사이클은 "지금 내가 밟고 있는 재귀 경로 위의 노드로 되돌아가는 간선"이 있으면 존재한다. 이를 정확히 잡으려면 방문 상태를 3색으로 관리한다: 0=미방문, 1=현재 DFS 경로 위(스택에 살아 있음), 2=완료(자식까지 다 봄).
- 탐색 중 이웃이 `state=1`이면 그 노드는 지금 내 경로 상에 있으므로 사이클. `state=2`(이미 완료된 다른 갈래)는 사이클이 아니므로 무시해야 한다. `visited` 한 개(2색)로는 이 둘을 구분 못 해 오판한다.
- 자기 자신으로의 간선(`u→u`)도 진입 직후 `u`가 `state=1`인 상태에서 자신을 만나므로 자연히 사이클로 잡힌다.

(2) 코드 단계별

- 인접리스트 `graph`를 `vector<vector<int>>`로 만들고 `state`를 0으로 초기화한다.
- 시작 정점이 여러 개일 수 있으니 1..N을 훑으며 미방문 정점마다 DFS 시작.
- 재귀 대신 반복 DFS: 스택에 노드를 담고, `iter[node]`로 "그 노드에서 다음에 볼 이웃 인덱스"를 따로 기억한다. 이웃을 하나 볼 때: `state=1`이면 사이클 확정, `state=0`이면 그 이웃을 1로 칠하고 스택에 push, `state=2`면 건너뛴다. 이웃을 다 보면 그 노드를 2(완료)로 칠하고 pop.
- 어느 순간이든 사이클을 찾으면 즉시 종료하고 `YES`, 끝까지 없으면 `NO`.

(3) 스스로 다시 짤 때 생각 순서

- "재귀 경로 위로 되돌아가는 역방향 간선 = 사이클"이라는 정의를 먼저 확실히 한다.
- 그 정의를 코드로 옮기려면 상태가 3개 필요하다는 점(진입/완료 구분)을 떠올린다.
- 재귀로 쓰면 짧지만 N이 10만이라 스택 오버플로 위험이 크니, 스택에 노드를, 별도 배열 `iter`에 이웃 인덱스를 담는 반복 DFS로 3색을 그대로 흉내 낸다. 마지막으로 "모든 정점에서 시작"과 "자기 루프 처리"를 점검한다.
```

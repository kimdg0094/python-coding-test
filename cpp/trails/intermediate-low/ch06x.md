## L4. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch6(DP II)의 핵심 세 유형 — 원하는 state를 정의해 한 칸씩 나아가는 DP, 직전 상황에 영향받는 연속 DP, 두 문자열을 나란히 비교하는 String Matching — 을 **반복 훈련**하고, 코딩테스트 단골 유형으로 **확장**하는 연습 세트다. 새 문법은 없다. 모든 문제에서 "상태 정의(한 문장) → 전이 → 초기값·답 위치"를 먼저 적고 코드를 쓴다.

- **반복 훈련 개념**
- 직전 선택을 state로 승격: 다음 결정에 필요한 최소 정보만 축으로 — `nred = other; nother = 2*(red+other);` 를 먼저 계산한 뒤 대입, `nda = a[i] + max(da, db - c)`
- 상태 갱신 순서: C++엔 `a, b = b, a` 같은 동시 대입이 없다. 새 값을 **임시 변수에 먼저 담고** 나중에 옮긴다(두 값 교환뿐이면 `swap(a, b)`)
- 오르막/내리막·잔액 같은 "지금 모드"를 state로: `up[i] = down[j] + 1`, `dp[i+1][j+1] += dp[i][j]`(잔액 +1)
- 연속 DP의 한 줄 전이 "이어붙이기 vs 새로 시작": `cur = max(x, cur + x)`, `cur = (a[i] > a[i-1]) ? cur + 1 : 1`, 전역 답은 `best`에 따로 기록
- 두 문자열 표 `dp[i][j]`: 같으면 대각선, 다르면 위·왼쪽 — `if (T[j-1] == ch) dp[j] += dp[j-1];`, `L[i][j] = L[i+1][j+1] + 1`
- 도달 불가 상태는 `-1e18`로 막고(`LLONG_MIN`은 더하는 순간 넘친다) 답 위치(마지막 칸의 어느 상태가 유효한지)를 마지막에 다시 확인
- 뺄셈이 섞인 MOD 연산은 음수가 된다: C++의 `%`는 피제수 부호를 따르므로 `(s - dp[c]) % MOD` 뒤에 `+ MOD` 한 번을 더 붙여 `((x % MOD) + MOD) % MOD`로 만든다

- **코딩테스트 출제 맵**: 이 챕터의 유형은 백준 「단계별로 풀어보기」의 '동적 계획법 1'·'동적 계획법 2' 단계(이친수·LCS 2·연속합 류), 프로그래머스 「코딩테스트 고득점 Kit」의 '동적계획법', NeetCode 150의 '1-D DP'·'2-D DP'(Distinct Subsequences·Regular Expression Matching·Maximum Subarray 변형 류)에 그대로 등장한다. 이 레슨의 유형 확장 문제는 그 대표 유형을 소재·수치·조건을 새로 만들어 이 챕터 수준으로 재구성한 것이다.

**문제**

**1) 빨강 연속 금지 화단 칠하기** · Easy

- **요구사항**: 일렬로 놓인 n개의 화단 칸을 빨강·노랑·파랑 세 색 중 하나로 칠한다. 단 **빨강은 두 칸 연속으로 올 수 없다**(노랑·파랑은 연속 허용). 가능한 칠하기의 수를 1,000,000,007로 나눈 나머지로 구하라.
- **입력**: 한 줄에 정수 n (1 ≤ n ≤ 100,000)
- **출력**: 경우의 수(MOD)
- **예제**: `1` → `3` · `2` → `8` · `3` → `22`
- **셀프체크**: 다음 칸을 정하려면 "직전 칸이 빨강인가"만 알면 되므로 상태는 두 개(`red`, `other`)면 충분하다. `n=2`에서 9가지 중 빨강-빨강 하나만 빠져 8이 되는가? `other`로 가는 전이에 2(노랑·파랑 두 색)를 곱했는가? `2 * (red + other)`는 최대 약 `4×10⁹`로 `int`를 넘기므로 `long long`이어야 하고, 두 상태는 **임시 변수에 먼저 담아** 한꺼번에 옮긴다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    const long long MOD = 1000000007LL;
    // red = 마지막 칸이 빨강인 경우의 수, other = 마지막 칸이 노랑/파랑인 경우의 수
    long long red = 1, other = 2;              // 첫 칸: 빨강 1가지, 그 외 2가지
    for (int i = 2; i <= n; i++) {
        long long nred = other % MOD;          // 빨강 앞에는 빨강이 못 온다
        long long nother = 2 * (red + other) % MOD;   // 노랑/파랑은 무엇 뒤에든 가능(2색)
        red = nred;                            // 새 값을 먼저 만든 뒤 옮긴다
        other = nother;
    }
    cout << (red + other) % MOD << '\n';
    return 0;
}
@@TESTS

@@EXPL
(1) 접근·핵심 아이디어

- "빨강 다음에 빨강 금지"는 직전 칸의 색이 다음 선택을 막는 신호다. 다음 결정에 필요한 정보는 "직전이 빨강인가" 하나뿐이므로, 노랑과 파랑은 하나의 상태로 묶어도 된다.
- 상태 정의: `red[i]` = i번째 칸이 빨강인 칠하기 수, `other[i]` = i번째 칸이 노랑 또는 파랑인 칠하기 수.
- 전이: `red[i] = other[i-1]`(빨강 앞은 반드시 노랑/파랑), `other[i] = 2·(red[i-1] + other[i-1])`(노랑·파랑 2색은 무엇 뒤에든 가능). 초기값 `red[1]=1`, `other[1]=2`. 답은 `red[n] + other[n]`.
- 시간 O(n), 공간 O(1)(두 변수만 굴림).

(2) 코드 단계별

- `red = 1, other = 2`로 첫 칸을 초기화. 타입은 `long long`이다. `red + other`가 최대 약 `2×10⁹`, 거기에 2를 곱하면 `4×10⁹`로 `int` 상한(약 `2.147×10⁹`)을 확실히 넘긴다. `int`로 두면 음수가 되고, 그 음수에 `% MOD`를 하면 C++에서는 음수 나머지가 나와 답이 완전히 망가진다.
- `i=2..n`마다 새 값을 **임시 변수 `nred`, `nother`에 먼저 담고** 그 뒤에 대입한다. 파이썬의 `red, other = new_red, new_other` 같은 동시 대입이 C++엔 없으므로, `red`를 먼저 덮어쓰면 `nother` 계산에 새 값이 섞여 오답이 된다(두 값을 맞바꾸기만 할 때는 `swap(a, b)`로 충분하다).
- 매 단계 `% MOD`.
- `n=1`이면 루프가 돌지 않아 `1 + 2 = 3`. `n=2` → `red=2`(노빨, 파빨), `other=6` → 8. `n=3` → `red=6`, `other=16` → 22.

(3) 스스로 다시 짤 때 생각 순서

- "무엇 다음에 무엇이 못 오나" → 직전 색을 상태로. 제약과 무관한 색들은 하나로 묶어 상태 수를 줄인다.
- 각 상태로 들어오는 전이를 적고, 여러 색이 묶인 상태는 색 수를 곱한다 → 곱셈이 생겼으니 타입을 `long long`으로.
- 임시 변수로 순서를 지키고, MOD, 답은 모든 상태의 합.
```

**2) 연속 상승 구간 최장 길이** · Easy

- **요구사항**: 정수 수열에서 **연속한** 구간 중 값이 계속 엄격히 증가하는(각 항이 직전 항보다 큼) 가장 긴 구간의 길이를 구하라. 길이 1인 구간도 상승 구간으로 본다.
- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 둘째 줄에 n개의 정수(-10⁹ 이상 10⁹ 이하)
- **출력**: 최장 연속 상승 구간의 길이
- **예제**: `7 / 1 3 5 2 4 6 7` → `4` · `3 / 5 4 3` → `1` · `4 / 2 2 2 2` → `1`
- **셀프체크**: LIS(순서만 지키면 됨)가 아니라 **연속** 구간이다 — Kadane처럼 `cur`를 "i를 끝으로 하는 상승 구간 길이"로 두고 이어붙이거나 1로 리셋한다. 같은 값(`2 2`)은 상승이 아니므로 리셋. `n=1`이면 1. 값이 ±10⁹이므로 `int`에 담기지만, 두 값을 **빼서** 비교하면 `10⁹ - (-10⁹) = 2×10⁹`로 넘친다 — 뺄셈 대신 `a[i] > a[i-1]` 비교를 쓴다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    int best = 1, cur = 1;                 // cur = i를 끝으로 하는 연속 상승 구간 길이
    for (int i = 1; i < n; i++) {
        if (a[i] > a[i - 1]) cur += 1;     // 이어붙이기
        else cur = 1;                      // 여기서 새로 시작
        if (cur > best) best = cur;
    }
    cout << best << '\n';
    return 0;
}

@@EXPL
(1) 접근·핵심 아이디어

- "연속 구간"이므로 Kadane 계열이다. 상태 `cur` = i번째 원소를 끝으로 하는 연속 상승 구간의 길이. 직전 원소보다 크면 이어붙여 `cur+1`, 아니면 여기서 새로 시작해 `1`.
- 전역 답 `best`는 `cur`와 별도로 기록한다 — `cur`는 항상 "i를 끝으로" 하는 값이라 마지막 `cur`가 최대라는 보장이 없다.
- 시간 O(n), 공간 O(1). LIS(부분수열)와 달리 이전 모든 원소를 볼 필요가 없다는 점이 "연속"의 힘이다.

(2) 코드 단계별

- `best = cur = 1`로 시작(원소 하나짜리 구간).
- `a[i] > a[i-1]`이면 `cur += 1`, 아니면 `cur = 1`. 같은 값은 `>`가 거짓이라 자동으로 리셋된다.
- 대소 비교를 `a[i] - a[i-1] > 0`으로 바꿔 쓰면 안 된다. 값이 ±10⁹까지라 `10⁹ - (-10⁹) = 2×10⁹`가 `int` 상한을 넘어 음수로 뒤집히고, 상승 구간이 끊긴 것처럼 판정된다. **정수 비교는 빼지 말고 그대로 비교한다** — C++에서 반복해서 나오는 규칙이다.
- 입력이 10만 개이므로 `ios_base::sync_with_stdio(false); cin.tie(nullptr);`를 켜 둔다. 이것 없이 `cin`을 쓰면 C stdio와 동기화하느라 몇 배 느려진다.
- `1 3 5 2 4 6 7` → `2 4 6 7`로 4. 감소만 하거나 전부 같으면 1. `n=1`이면 루프가 돌지 않아 1.

(3) 스스로 다시 짤 때 생각 순서

- "연속"인지 "순서만"인지 먼저 판별 → 연속이면 `cur` 굴리기.
- 이어붙이기 조건(엄격 증가 `>`)과 리셋값(1)을 정한다. 뺄셈으로 바꾸지 않는다.
- `best`를 분리 기록, 경계(n=1, 전부 같음) 확인.
```

**3) 매표소 거스름돈 순서의 수** · Medium

- **요구사항**: 입장권은 5천원이다. 5천원 지폐를 내는 손님 a명과 만원 지폐를 내는 손님 b명이 한 줄로 선다. 매표소는 처음에 거스름돈이 한 푼도 없고, 만원 손님에게는 그때까지 받아 둔 5천원 지폐 한 장을 거슬러 줘야 한다. 같은 지폐를 내는 손님끼리는 구분하지 않을 때, 모든 손님에게 거스름돈을 줄 수 있는 줄 서기 순서의 수를 1,000,000,007로 나눈 나머지로 구하라.
- **입력**: 한 줄에 정수 a, b (0 ≤ a, b ≤ 50)
- **출력**: 가능한 순서의 수(MOD). 불가능하면 0
- **예제**: `2 1` → `2` · `3 3` → `5` · `1 2` → `0`
- **셀프체크**: 다음 손님을 받을 수 있는지는 "지금 5천원 지폐를 몇 장 들고 있나"(잔액)에만 달려 있다 → 상태 `dp[i][j]` = i명을 처리했고 잔액이 j장. i와 j를 알면 지금까지 온 5천원 손님 수 `(i+j)/2`, 만원 손님 수 `(i-j)/2`가 결정되므로 남은 손님 수 제한을 걸 수 있다. `a < b`면 답이 0, `a=b=0`이면 빈 줄 1가지. 두 정수의 나눗셈 `(i+j)/2`는 C++에서도 몫만 남지만, 여기서는 `i+j`가 항상 짝수라 버림이 일어나지 않는다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int a, b;
    cin >> a >> b;                          // a: 5천원 손님 수, b: 만원 손님 수
    const long long MOD = 1000000007LL;
    if (a < b) {
        cout << 0 << '\n';
        return 0;
    }
    int total = a + b;
    // dp[i][j] = i명을 처리했고 지금 5천원 지폐를 j장 들고 있는 순서의 수
    vector<vector<long long>> dp(total + 1, vector<long long>(a + 1, 0));
    dp[0][0] = 1;
    for (int i = 0; i < total; i++) {
        for (int j = 0; j <= a; j++) {
            long long cur = dp[i][j];
            if (cur == 0) continue;
            int used5 = (i + j) / 2;        // 지금까지 온 5천원 손님 수
            int used10 = (i - j) / 2;       // 지금까지 온 만원 손님 수
            if (used5 < a)                  // 다음 손님이 5천원 -> 잔액 +1
                dp[i + 1][j + 1] = (dp[i + 1][j + 1] + cur) % MOD;
            if (used10 < b && j >= 1)       // 다음 손님이 만원 -> 거슬러 주고 잔액 -1
                dp[i + 1][j - 1] = (dp[i + 1][j - 1] + cur) % MOD;
        }
    }
    cout << dp[total][a - b] << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 줄 서기 순서를 앞에서부터 한 명씩 확정해 나갈 때, 다음 손님을 받을 수 있는지는 "지금 5천원 지폐를 몇 장 갖고 있나"에만 달려 있다. 이 **잔액**이 상태 축이다.
- 상태 정의: `dp[i][j]` = 앞 i명을 처리했고 현재 5천원 지폐를 j장 보유한 유효한 순서의 수. 5천원 손님이 오면 `j+1`, 만원 손님이 오면 `j ≥ 1`일 때만 `j-1`.
- i명 중 5천원 손님이 x명, 만원 손님이 y명이면 `x+y=i`, `x-y=j`이므로 `x=(i+j)/2`, `y=(i-j)/2`로 유일하게 결정된다. 덕분에 "남은 5천원 손님이 있나(`x<a`)", "남은 만원 손님이 있나(`y<b`)"를 상태에 따로 넣지 않고도 걸러낼 수 있다.
- 전이: `dp[i+1][j+1] += dp[i][j]`(x<a), `dp[i+1][j-1] += dp[i][j]`(y<b, j≥1). 초기 `dp[0][0]=1`, 답 `dp[a+b][a-b]`. 시간 O((a+b)·a), 공간 O((a+b)·a).

(2) 코드 단계별

- `a < b`면 만원 손님이 더 많아 반드시 거스름돈이 모자라므로 즉시 0. 이 분기가 없으면 뒤에서 `dp[total][a-b]`의 두 번째 인덱스가 **음수**가 되어 범위 밖 메모리를 읽는다(파이썬이라면 뒤에서부터 세어 엉뚱한 값을 냈을 자리다).
- `dp`는 `vector<vector<long long>> dp(total + 1, vector<long long>(a + 1, 0))`. 경우의 수이므로 `long long`, 안쪽 크기까지 반드시 지정한다.
- 각 `(i, j)`에서 값이 0이면 건너뛰고, `used5`, `used10`을 계산해 두 전이를 조건부로 적용하며 `% MOD`.
- `j + 1`이 `a`를 넘지 않는 것은 `used5 < a` 조건이 보장한다(`j ≤ used5`이므로 `j + 1 ≤ a`). 이런 "조건이 인덱스를 지켜 준다"는 논리는 반드시 한 번 손으로 확인하고 넘어간다.
- `2 1` → `5,5,10`·`5,10,5` 두 가지. `3 3` → 카탈랑 수 5. `1 2` → 0. `0 0` → 루프가 돌지 않고 `dp[0][0] = 1`. `5 5` → 42.

(3) 스스로 다시 짤 때 생각 순서

- "다음 손님을 받을 수 있나"를 결정하는 최소 정보 → 잔액 j. 상태 `dp[i][j]`.
- (i, j)로부터 각 종류 손님 수를 역산해 남은 손님 제한을 건다.
- 불가능 조건(`a<b`)을 먼저 걸러 인덱스가 음수가 되지 않게 하고, 답 위치 `dp[a+b][a-b]`를 확인.
```

**4) 지그재그 부분수열 최장 길이** · Medium

- **요구사항**: 수열에서 순서를 유지하며(연속일 필요 없음) 원소를 골라, 인접한 두 원소의 차이 부호가 양수·음수로 **번갈아** 나타나게 만들 때(차이 0은 불가) 가장 긴 것의 길이를 구하라. 첫 차이는 양수·음수 어느 쪽이든 된다. 길이 1은 항상 가능하다.
- **입력**: 첫 줄 n (1 ≤ n ≤ 1000), 둘째 줄에 n개의 정수(0 이상 10⁴ 이하)
- **출력**: 최장 지그재그 부분수열의 길이
- **예제**: `6 / 1 7 4 9 2 5` → `6` · `4 / 1 2 3 4` → `2` · `3 / 3 3 3` → `1`
- **셀프체크**: LIS처럼 `dp[i]`를 "i를 마지막으로"로 잡되, 다음에 무엇을 붙일 수 있는지는 **마지막 변화가 오르막이었나 내리막이었나**에 달려 있으므로 상태를 `up[i]`, `down[i]` 둘로 나눈다. `a[j] < a[i]`면 `down[j]` 뒤에 오르막으로 붙고, `a[j] > a[i]`면 `up[j]` 뒤에 내리막으로 붙는다. 같은 값은 어느 쪽에도 못 붙는다. 답은 두 배열 전체의 최댓값 — `max(*max_element(up...), *max_element(down...))`처럼 반복자를 역참조해 꺼낸다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    // up[i]   = a[i]로 끝나며 마지막 변화가 오르막인 최장 지그재그 길이
    // down[i] = a[i]로 끝나며 마지막 변화가 내리막인 최장 지그재그 길이
    vector<int> up(n, 1), down(n, 1);
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (a[j] < a[i] && down[j] + 1 > up[i]) up[i] = down[j] + 1;    // 내리막 뒤 오르막
            if (a[j] > a[i] && up[j] + 1 > down[i]) down[i] = up[j] + 1;    // 오르막 뒤 내리막
        }
    }
    int ans = max(*max_element(up.begin(), up.end()),
                  *max_element(down.begin(), down.end()));
    cout << ans << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- LIS 골격("i를 마지막으로 쓰는 최장 길이")에 **마지막 변화의 방향**을 상태로 추가한다. 다음 원소를 붙일 수 있는지가 그 방향에 달려 있기 때문이다.
- 상태 정의: `up[i]` = `a[i]`로 끝나고 마지막 변화가 오르막인 최장 지그재그 길이, `down[i]` = 마지막 변화가 내리막인 최장 길이. 원소 하나만으로는 방향이 없으니 둘 다 1로 시작.
- 전이: `j < i`에 대해 `a[j] < a[i]`면 `up[i] = max(up[i], down[j] + 1)`(내리막으로 끝난 수열 뒤에 오르막을 붙임), `a[j] > a[i]`면 `down[i] = max(down[i], up[j] + 1)`. 같은 값은 차이 0이라 어느 전이도 없다.
- 답은 두 배열 전체의 최댓값. 시간 O(n²)(n=1000이면 50만 쌍), 공간 O(n).

(2) 코드 단계별

- `vector<int> up(n, 1), down(n, 1);`로 전부 1로 초기화. 두 번째 인자 `1`을 빼면 0으로 채워져 길이 1짜리 기저가 사라진다.
- 이중 루프에서 `a[j]`와 `a[i]`의 대소에 따라 **반대 방향 배열**의 값 +1로 갱신한다. `up[i] = up[j] + 1`처럼 같은 배열을 참조하면 번갈아 조건이 깨져 그냥 LIS가 되어 버린다.
- 두 조건은 `else if`가 아니라 각각 `if`다. `a[j] < a[i]`와 `a[j] > a[i]`는 동시에 참일 수 없으니 결과는 같지만, 조건을 독립적으로 적어야 나중에 "같을 때"를 추가하기 쉽다.
- 답은 `*max_element(...)`로 꺼낸다. `max_element`는 값이 아니라 **반복자**를 돌려주므로 `*`를 빼면 컴파일 오류가 난다. 두 배열의 최댓값을 다시 `max`로 묶는다.
- `1 7 4 9 2 5` → 오르내림이 완벽히 번갈아 6. `1 2 3 4` → 오르막만 있으니 아무 두 개로 2. `3 3 3` → 1. 10개짜리 예제는 `1 17 5 13 10 16 8` 같은 조합으로 7.

(3) 스스로 다시 짤 때 생각 순서

- "붙일 수 있는 조건이 직전 변화의 방향에 달렸다" → 방향을 상태로 나눠 `up`/`down` 두 배열.
- 각 배열이 **반대 배열**에서 오는 전이만 적는다(오르막 뒤엔 내리막, 내리막 뒤엔 오르막).
- 초기값 1, 같은 값 제외, 답은 두 배열 전체의 최댓값.
```

**5) 두 가게 교대 근무 최대 수입** · Medium

- **요구사항**: n일 동안 매일 A 가게 또는 B 가게 중 한 곳에서 반드시 일한다. i일에 A에서 일하면 a[i], B에서 일하면 b[i]를 번다. 전날과 **다른 가게**로 옮기는 날에는 이동비 c가 든다(첫날은 이동비 없음). n일 동안의 순수입(번 돈 − 이동비 합)의 최댓값을 구하라.
- **입력**: 첫 줄 n, c (1 ≤ n ≤ 100,000, 0 ≤ c ≤ 1000), 둘째 줄에 a[1..n], 셋째 줄에 b[1..n] (각 0 이상 1000 이하)
- **출력**: 최대 순수입
- **예제**: `4 5 / 10 1 1 10 / 1 10 10 1` → `30` · `3 100 / 5 1 5 / 1 5 1` → `11`
- **셀프체크**: 오늘의 결정에 필요한 과거 정보는 "어제 어느 가게였나"뿐이다 → 상태 2개 `da`, `db`. `da = a[i] + max(da, db - c)`에서 두 상태를 **임시 변수로 먼저 계산한 뒤** 옮겼는가? `c=0`이면 매일 큰 쪽을 고르는 그리디와 같아지는지, `c`가 아주 크면 한 가게에 머무는 두 경우 중 최대가 되는지 확인. 최대 수입은 `10⁵ × 1000 = 10⁸`으로 `int`에 들어가지만, 누적 합계는 습관적으로 `long long`으로 둔다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    long long c;
    cin >> n >> c;
    vector<long long> a(n), b(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    for (int i = 0; i < n; i++) cin >> b[i];

    // da = 오늘 A 가게에서 일했을 때 최대 순수입, db = 오늘 B 가게
    long long da = a[0], db = b[0];             // 첫날은 이동비 없음
    for (int i = 1; i < n; i++) {
        long long nda = a[i] + max(da, db - c); // 어제도 A vs 어제 B에서 이동
        long long ndb = b[i] + max(db, da - c);
        da = nda;                               // 임시 변수를 먼저 다 계산한 뒤 옮긴다
        db = ndb;
    }
    cout << max(da, db) << '\n';
    return 0;
}

--IN

--IN

@@EXPL
(1) 접근·핵심 아이디어

- "가게를 바꾸면 비용"은 직전 선택이 오늘의 값을 바꾸는 신호다. 오늘 결정에 필요한 과거 정보는 "어제 어느 가게였나" 하나뿐이므로 상태는 두 개다.
- 상태 정의: `da[i]` = i일에 A에서 일했을 때 i일까지의 최대 순수입, `db[i]` = i일에 B에서 일했을 때의 최대 순수입.
- 전이: `da[i] = a[i] + max(da[i-1], db[i-1] - c)`(어제도 A였으면 이동비 없음, 어제 B였으면 `-c`), `db[i]`는 대칭. 초기 `da[0]=a[0]`, `db[0]=b[0]`. 답은 마지막 날 두 상태의 최댓값 — 어느 가게로 끝나도 되므로 둘 다 유효.
- 시간 O(n), 공간 O(1).

(2) 코드 단계별

- 첫날 값으로 `da`, `db`를 초기화한다.
- 매일 `nda`, `ndb`를 **먼저 둘 다 계산한 뒤** 대입한다. `da = a[i] + max(da, db - c);`를 먼저 실행하고 다음 줄에서 `db`를 계산하면, 그 `db` 계산이 오늘 값으로 바뀐 `da`를 참조해 "같은 날 두 번 일한" 답이 나온다. C++엔 동시 대입이 없으므로 임시 변수가 필수다.
- `max(da, db - c)`의 두 인자는 타입이 같아야 한다. `da`가 `long long`인데 `c`를 `int`로 두면 `db - c`도 `long long`으로 승격되어 여기서는 문제가 없지만, `max(0, someLongLong)`처럼 리터럴과 섞는 순간 "no matching function" 컴파일 오류가 난다 — `max<long long>(...)`이나 캐스팅으로 맞춘다.
- 마지막에 `max(da, db)`.
- 첫 예제: A→B→B→A로 `10+10+10+10 − 5·2 = 30`. 둘째: 이동비 100이라 A에 머물러 `5+1+5 = 11`. `n=1`이면 루프가 돌지 않아 `max(3, 9) = 9`. `c=0`이면 매일 큰 쪽 `9+9 = 18`.

(3) 스스로 다시 짤 때 생각 순서

- "직전 선택이 오늘 비용을 바꾸나?" → 직전 선택(가게)을 상태로.
- 각 상태로 들어오는 두 경로(유지/전환)를 적고 전환에만 `-c`.
- 임시 변수로 동시 갱신을 흉내 내고, 답은 마지막 날 두 상태의 `max`.
```

**6) 부분수열 등장 횟수** · Medium

- **요구사항**: 문자열 S에서 글자를 골라(순서 유지, 연속일 필요 없음) 문자열 T를 만드는 서로 다른 방법의 수를 구하라. 고른 글자의 **위치 집합**이 다르면 다른 방법이다. 답을 1,000,000,007로 나눈 나머지로 출력한다.
- **입력**: 한 줄에 S와 T (공백 구분, 소문자, 1 ≤ |S| ≤ 1000, 1 ≤ |T| ≤ 200)
- **출력**: 방법의 수(MOD). 없으면 0
- **예제**: `banana an` → `3` · `aaa aa` → `3` · `abc abd` → `0`
- **셀프체크**: `dp[i][j]` = S의 앞 i글자로 T의 앞 j글자를 만드는 방법 수. S의 글자를 "안 쓰는" 경우(`dp[i-1][j]`)는 항상 있고, 같은 글자면 "쓰는" 경우(`dp[i-1][j-1]`)를 더한다. 1차원으로 압축할 때 j를 **내림차순**으로 돌아야 같은 S 글자를 두 번 쓰지 않는다(0/1 배낭과 같은 이유). `dp[0]=1`(빈 T) 기저를 두었는가? 내림차순 루프 변수는 `int`로 둔다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    string S, T;
    cin >> S >> T;
    const long long MOD = 1000000007LL;
    int m = (int)T.size();

    // dp[j] = 지금까지 본 S의 접두사 안에서 T[:j]가 부분수열로 나타나는 방법 수
    vector<long long> dp(m + 1, 0);
    dp[0] = 1;                                   // 빈 T는 항상 1가지
    for (char ch : S) {
        for (int j = m; j >= 1; j--) {           // 내림차순: 같은 글자를 두 번 쓰지 않도록
            if (T[j - 1] == ch) dp[j] = (dp[j] + dp[j - 1]) % MOD;
        }
    }
    cout << dp[m] << '\n';
    return 0;
}

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 두 문자열을 나란히 비교하는 2차원 표. 상태 정의: `dp[i][j]` = S의 앞 i글자 안에서 T의 앞 j글자를 부분수열로 만드는 방법 수.
- S의 i번째 글자를 **안 쓰면** `dp[i-1][j]`가지, 그 글자가 `T[j-1]`와 같아서 **쓰면** `dp[i-1][j-1]`가지. 전이 `dp[i][j] = dp[i-1][j] + [S[i-1]==T[j-1]]·dp[i-1][j-1]`.
- 경계: `dp[i][0] = 1`(빈 T를 만드는 방법은 아무것도 안 고르는 1가지), `dp[0][j>0] = 0`. 답 `dp[|S|][|T|]`. LCS와 같은 표 모양이지만 `max`가 아니라 **덧셈**이고, 다를 때 왼쪽 칸은 참조하지 않는다는 점이 다르다.
- 시간 O(|S|·|T|), 공간 O(|T|)(행 압축).

(2) 코드 단계별

- `vector<long long> dp(m + 1, 0)`에 `dp[0]=1`인 1차원 배열로 시작(현재 행). 경우의 수이므로 `long long`.
- `for (char ch : S)`로 S의 글자를 하나씩 본다. 범위 기반 for는 `char` 복사라 부담이 없다(원소가 큰 컨테이너였다면 `const auto&`로 받는다).
- `j`를 `m`부터 1까지 **내림차순**으로 돌며 `T[j-1]==ch`면 `dp[j] += dp[j-1]`. 내림차순이라 `dp[j-1]`은 아직 이번 글자를 반영하지 않은 "이전 행" 값이다 — 오름차순으로 돌면 `aaa/aa`에서 같은 `a`를 두 번 써 답이 부풀려진다.
- 루프 변수 `j`는 **부호 있는 `int`**. `size_t j = m; j >= 1; j--`는 여기서는 멈추지만, 조건을 `j >= 0`으로 한 글자만 바꾸는 순간 0에서 감소해 거대한 양수로 뒤집혀 무한 루프가 된다. 역방향 루프는 습관적으로 `int`.
- `banana an` → `a`(2번째)·`n`(3번째), `a`(2)·`n`(5), `a`(4)·`n`(5) = 3. `aaa aa` → 3개 중 2개 고르기 = 3. `abc abcd` → T가 더 길어 0.

(3) 스스로 다시 짤 때 생각 순서

- "S 안에서 T가 몇 번" → `dp[i][j]` 표, 안 쓰기 + (같으면) 쓰기.
- 빈 T 기저 `dp[0]=1`을 먼저 둔다.
- 1차원 압축 시 내림차순(`int` 인덱스), MOD, 답 `dp[m]`.
```

**7) 원형 화환 3색 칠하기 경우의 수** · Medium

- **요구사항**: n개의 구슬이 **원형**으로 이어진 화환을 빨강·노랑·파랑 세 색으로 칠한다. 이웃한 두 구슬은 서로 다른 색이어야 하며, 첫 구슬과 마지막 구슬도 이웃이다. 가능한 칠하기의 수를 1,000,000,007로 나눈 나머지로 구하라(회전·뒤집기로 같아지는 것도 서로 다른 것으로 센다).
- **입력**: 한 줄에 정수 n (2 ≤ n ≤ 100,000)
- **출력**: 경우의 수(MOD)
- **예제**: `3` → `6` · `4` → `18` · `2` → `6`
- **셀프체크**: 일렬이면 직전 색만 상태로 두면 되지만, 원형은 마지막 구슬이 **첫 구슬**과도 달라야 한다. 첫 구슬 색을 하나로 고정해(예: 색 0) 일렬 DP를 돌린 뒤 마지막이 색 0이 아닌 경우만 세고 3배 하면 된다. `n=3` → 3·2·1 = 6, `n=4` → 18이 나오는가? `n=2`는 두 구슬이 서로 이웃이므로 3·2 = 6. **전이가 `s - dp[c]`라 뺄셈이 들어간다 — C++의 `%`는 음수를 그대로 남기므로 `((s - dp[c]) % MOD + MOD) % MOD`로 감싸야 한다.**

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    const long long MOD = 1000000007LL;
    // 첫 칸의 색을 0으로 고정하고 마지막에 3배. dp[c] = 현재 칸 색이 c인 경우의 수
    long long dp[3] = {1, 0, 0};
    for (int i = 2; i <= n; i++) {
        long long s = (dp[0] + dp[1] + dp[2]) % MOD;
        long long nd[3];
        for (int c = 0; c < 3; c++)
            nd[c] = ((s - dp[c]) % MOD + MOD) % MOD;   // 직전과 다른 색 (음수 방지)
        dp[0] = nd[0];
        dp[1] = nd[1];
        dp[2] = nd[2];
    }
    cout << 3 * ((dp[1] + dp[2]) % MOD) % MOD << '\n';  // 마지막은 첫 칸(색 0)과 달라야
    return 0;
}

(1) 접근·핵심 아이디어

- 일렬 색칠은 "직전 색"만 상태로 두면 되지만, 원형에서는 마지막 구슬이 첫 구슬과도 달라야 한다. 첫 구슬 색을 상태에 넣으면 3배가 되지만, 세 색은 대칭이므로 **첫 색을 0으로 고정**하고 결과를 3배 하면 충분하다.
- 상태 정의: `dp[i][c]` = 첫 구슬이 색 0일 때 i번째 구슬이 색 c인 일렬 칠하기 수. 전이 `dp[i][c] = Σ dp[i-1][c']`(c' ≠ c) = `(전체 합) − dp[i-1][c]`. 초기 `dp[1] = {1, 0, 0}`.
- 답은 마지막 구슬이 첫 구슬(색 0)과 달라야 하므로 `3·(dp[n][1] + dp[n][2])`. 시간 O(n), 공간 O(1).

(2) 코드 단계별

- `dp = {1, 0, 0}`으로 첫 구슬을 색 0으로 고정.
- 매 구슬마다 `s = (dp[0]+dp[1]+dp[2]) % MOD`를 구하고 각 색을 `s - dp[c]`로 갱신(직전과 같은 색만 제외).
- **여기가 이 문제의 C++ 함정이다.** `s`와 `dp[c]`는 각각 `% MOD`를 거친 값이라 `s < dp[c]`가 얼마든지 생기고, 그러면 `s - dp[c]`가 음수다. 파이썬의 `%`는 결과가 항상 0 이상이라 `(s - dp[c]) % MOD`만으로 알아서 양수가 되지만, **C++의 `%`는 피제수의 부호를 따르므로 `-3 % 10`이 `-3`**이다. 음수가 그대로 `dp`에 들어가면 다음 합이 어긋나고 최종 출력도 음수가 나온다. `((x) % MOD + MOD) % MOD` 관용구로 감싸는 것이 표준 처방이다.
- 세 값을 갱신할 때도 `nd[3]`에 먼저 담고 나중에 옮긴다. `dp[0]`을 먼저 덮으면 `s`는 이미 구해 놨으니 사실 괜찮지만, `s`를 매번 다시 계산하는 식으로 코드를 고치는 순간 깨진다 — 임시 배열을 쓰는 습관이 안전하다.
- 끝에서 `3 * ((dp[1] + dp[2]) % MOD) % MOD`. `3 * (약 2×10⁹)`는 `6×10⁹`이라 `int`로는 넘치고, `dp`가 `long long`이므로 곱셈도 `long long`으로 이뤄진다.
- `n=3` → `dp = {0,1,1}`(2번째), `{2,1,1}`(3번째)에서 `3·(1+1) = 6`. `n=4` → 18, `n=2` → 6, `n=10` → 1026(닫힌 식 `2ⁿ + 2·(−1)ⁿ`과 일치).

(3) 스스로 다시 짤 때 생각 순서

- "원형 = 첫 칸과 마지막 칸도 이웃" → 첫 색을 고정해 일렬 문제로 바꾸고 대칭으로 곱한다.
- 직전 색 상태 3개, 전이는 "전체 − 같은 색" → 뺄셈이 보이면 곧바로 `+ MOD` 보정을 붙인다.
- 답 위치를 "마지막 색 ≠ 첫 색"으로 제한, 3배, MOD.
```

**8) 한 번 삭제 허용 최대 연속합** · Hard

- **요구사항**: 정수 수열에서 연속한 구간을 하나 고른 뒤, 그 구간 안의 원소를 **최대 하나** 지울 수 있다(안 지워도 된다). 지운 뒤 남은 원소가 1개 이상이어야 하며, 남은 원소 합의 최댓값을 구하라.
- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 둘째 줄에 n개의 정수(-10⁴ 이상 10⁴ 이하)
- **출력**: 최대 합
- **예제**: `4 / 1 -2 0 3` → `4` · `5 / 2 -5 3 -1 4` → `8` · `4 / -1 -1 -1 -1` → `-1`
- **셀프체크**: Kadane의 `cur`를 "삭제를 아직 안 한 구간"(`keep`)과 "이미 하나 지운 구간"(`dele`) 두 상태로 나눈다. `dele[i] = max(keep[i-1], dele[i-1] + a[i])` — 앞 항은 **a[i]를 지우는** 경우라 `a[i]`를 더하지 않는다. `dele[0]`은 원소 하나를 지우면 빈 구간이 되므로 "무효"다. 전부 음수면 하나만 남긴 `-1`이 답(0 아님). **무효 값을 `LLONG_MIN`으로 두면 `dele + x`에서 곧바로 오버플로한다 — `-1e18`처럼 더해도 안전한 값을 쓴다.**

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<long long> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    const long long NEG = -1000000000000000000LL;   // LLONG_MIN 금지: 더하면 넘친다
    long long keep = a[0];                 // i를 끝으로 하고 아직 삭제 안 함
    long long dele = NEG;                  // i를 끝으로 하고 이미 하나 삭제함
    long long best = a[0];
    for (int i = 1; i < n; i++) {
        long long x = a[i];
        long long ndele = max(keep, dele + x);   // x를 삭제 vs 이미 삭제한 구간에 x 추가
        long long nkeep = max(x, keep + x);      // 새로 시작 vs 이어붙이기
        keep = nkeep;
        dele = ndele;
        best = max({best, keep, dele});
    }
    cout << best << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- 최대 연속합(Kadane)에 "하나를 지울 수 있다"는 선택이 붙었다. 지웠는지 여부가 이후 전이를 바꾸므로 **삭제 여부**를 상태로 승격한다.
- 상태 정의: `keep[i]` = i를 끝으로 하고 아직 아무것도 안 지운 구간의 최대합, `dele[i]` = i를 끝으로 하고 정확히 하나를 지운 구간의 최대합(i 자신이 지워진 경우 포함).
- 전이: `keep[i] = max(a[i], keep[i-1] + a[i])`(보통 Kadane), `dele[i] = max(keep[i-1], dele[i-1] + a[i])` — 첫 항은 `a[i]`를 지우고 그 앞 구간을 그대로 두는 것(그래서 `a[i]`를 더하지 않음), 둘째 항은 이미 지운 구간에 `a[i]`를 이어붙이는 것.
- 초기 `keep[0] = a[0]`, `dele[0] = 무효`. 답은 모든 i의 `max(keep[i], dele[i])`. 시간 O(n), 공간 O(1).

(2) 코드 단계별

- `keep = a[0]`, `dele = NEG`, `best = a[0]`.
- **`NEG`를 무엇으로 두느냐가 이 문제의 C++ 급소다.** 파이썬은 `float('-inf') + x`가 그대로 `-inf`라 아무 값이나 써도 됐지만, C++의 정수에는 무한대가 없다. `LLONG_MIN`(약 `-9.22×10¹⁸`)에 `x`를 더하면 부호 있는 정수 오버플로 — 표준상 **정의되지 않은 동작**이고, 실제로는 양수로 뒤집혀 `dele`가 갑자기 최댓값이 된다. `-1e18`로 두면 `10⁴`를 몇 번 더해도 여전히 압도적으로 작아 "무효"의 뜻을 유지한다.
- 각 `x`에서 `ndele`를 **먼저** 계산한다(이전 `keep`이 필요) → `nkeep` 계산 → 옮기기 → `best` 갱신. 여기서도 임시 변수가 동시 대입을 대신한다.
- `max({best, keep, dele})`는 중괄호로 감싼 초기화 리스트 버전이다. `max(best, keep, dele)`처럼 인자 셋을 그냥 넘기면 그런 오버로드가 없어 컴파일 오류가 난다.
- `1 -2 0 3` → `-2`를 지워 `1+0+3 = 4`. `2 -5 3 -1 4` → `-5`를 지워 `2+3-1+4 = 8`. 전부 `-1`이면 `-1`(빈 구간 0은 불가). `n=1`이면 루프 없이 `a[0]`.

(3) 스스로 다시 짤 때 생각 순서

- "Kadane + 한 번의 예외 행동" → 예외를 썼는지 여부를 상태로 두 개 굴린다.
- `dele`로 들어오는 두 경로(지금 지움 / 전에 지움)를 구분해 `a[i]`를 더할지 말지 결정.
- "무효" 초기값은 더해도 안전한 `-1e18`, 전부 음수 케이스, `best` 분리 기록.
```

**9) 사전순 최소 LCS 복원** · Hard

- **요구사항**: 두 문자열 A, B의 최장 공통 부분수열(LCS) 길이를 구하고, 그 길이를 갖는 공통 부분수열이 여러 개면 **사전순으로 가장 앞서는** 것을 출력하라.
- **입력**: 한 줄에 A와 B (공백 구분, 소문자, 각 길이 1 이상 100 이하)
- **출력**: 첫 줄에 LCS 길이. 길이가 1 이상이면 둘째 줄에 사전순 최소 LCS 문자열(길이 0이면 첫 줄만 출력)
- **예제**: `abcbdab bdcaba` → `4 / bcab` · `xyxy yxyx` → `3 / xyx` · `ace bdf` → `0`
- **셀프체크**: 뒤에서 앞으로 채운 `L[i][j]` = `A[i:]`와 `B[j:]`의 LCS 길이 표를 쓰면 "지금 위치에서 앞으로 몇 글자 더 얻을 수 있나"를 바로 알 수 있다. 복원은 앞에서부터 `a`~`z` 순으로 후보 글자를 시도해, 그 글자를 A·B에서 **가장 먼저** 나오는 위치로 잡고도 `L`이 유지되면(`L[pa+1][pb+1] + 1 == L[i][j]`) 채택한다. `abcbdab / bdcaba`의 길이 4 LCS가 `bcab`, `bcba`, `bdab` 세 개이고 사전순 최소가 `bcab`임을 확인. 접미사 표를 채우는 내림차순 루프의 인덱스는 부호 있는 `int`로 둔다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

vector<array<int, 26>> buildNext(const string& s) {
    int len = (int)s.size();
    // nxt[i][c] = s[i:]에서 문자 c가 처음 나오는 위치 (없으면 -1)
    vector<array<int, 26>> nxt(len + 1);
    nxt[len].fill(-1);
    for (int i = len - 1; i >= 0; i--) {
        nxt[i] = nxt[i + 1];               // vector<array> 대입은 값 복사다
        nxt[i][s[i] - 'a'] = i;
    }
    return nxt;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    string A, B;
    cin >> A >> B;
    int n = (int)A.size(), m = (int)B.size();

    // L[i][j] = A[i:]와 B[j:]의 LCS 길이 (뒤에서 앞으로 채움)
    vector<vector<int>> L(n + 1, vector<int>(m + 1, 0));
    for (int i = n - 1; i >= 0; i--) {
        for (int j = m - 1; j >= 0; j--) {
            if (A[i] == B[j]) L[i][j] = L[i + 1][j + 1] + 1;
            else L[i][j] = max(L[i + 1][j], L[i][j + 1]);
        }
    }

    vector<array<int, 26>> na = buildNext(A), nb = buildNext(B);
    string res;
    int i = 0, j = 0;
    while (L[i][j] > 0) {
        for (int c = 0; c < 26; c++) {              // 작은 글자부터 시도
            int pa = na[i][c], pb = nb[j][c];
            if (pa == -1 || pb == -1) continue;
            if (L[pa + 1][pb + 1] + 1 == L[i][j]) { // 이 글자를 골라도 최대 길이 유지
                res += char('a' + c);
                i = pa + 1;
                j = pb + 1;
                break;
            }
        }
    }
    cout << res.size() << '\n';
    if (!res.empty()) cout << res << '\n';
    return 0;
}

(1) 접근·핵심 아이디어

- LCS 길이는 보통 접두사 표 `dp[i][j]`로 구하지만, 문자열을 **앞에서부터** 결정하려면 "여기서부터 끝까지 앞으로 얼마나 더 얻을 수 있나"가 필요하다. 그래서 상태를 접미사로 정의한다: `L[i][j]` = `A[i:]`와 `B[j:]`의 LCS 길이. 전이는 LCS와 같고(같으면 대각선 +1, 다르면 아래·오른쪽 `max`) 채우는 방향만 뒤→앞이다.
- 복원은 그리디다. 현재 위치 `(i, j)`에서 `a`부터 `z`까지 차례로, 그 글자가 A와 B에서 다음에 나오는 **가장 이른** 위치 `(pa, pb)`를 찾아 `L[pa+1][pb+1] + 1 == L[i][j]`이면 채택한다. 이 조건은 "이 글자를 지금 고르고도 남은 최대 길이를 잃지 않는다"는 뜻이고, 작은 글자부터 시도하므로 사전순 최소가 보장된다.
- 다음 위치를 매번 스캔하면 느리니 `nxt[i][c]`(i 이후 글자 c의 첫 위치)를 뒤에서부터 미리 만든다. 시간 O(n·m + (n+m)·26), 공간 O(n·m + (n+m)·26).

(2) 코드 단계별

- `L`을 `(n+1)×(m+1)`로 만들고 `i`, `j`를 모두 내림차순으로 돌며 채운다. `L[n][·] = L[·][m] = 0`이 자동 경계다. 내림차순 루프 인덱스는 반드시 `int` — `size_t`로 두면 0에서 감소해 뒤집히며 무한 루프가 된다.
- `buildNext`: 반환 타입은 `vector<array<int,26>>`. `nxt[len].fill(-1)`로 마지막 행을 채우고, `i`를 뒤에서 앞으로 가며 `nxt[i] = nxt[i+1];`로 직전 행을 **복사**한 뒤 `s[i]`의 위치만 덮어쓴다. C++의 `array`·`vector` 대입은 값 복사라 파이썬의 `[:]` 슬라이스가 필요 없다 — 반대로 파이썬에서 슬라이스를 빼먹으면 같은 리스트를 공유해 표 전체가 망가진다.
- 매개변수는 `const string&`. 값으로 받으면 문자열을 통째로 복사한다.
- `while (L[i][j] > 0)`: 26글자를 순서대로 시도해 첫 채택 글자를 붙이고 `(i, j) = (pa+1, pb+1)`로 이동. 채택 가능한 글자는 반드시 존재한다(`L[i][j] > 0`이면 어떤 공통 글자로 시작하는 LCS가 있으므로) — 그래서 이 `while`은 반드시 끝난다.
- 문자를 붙일 때 `res += char('a' + c);`. `'a' + c`는 `int`라 캐스팅 없이 `+=` 하면 숫자를 더하는 다른 오버로드가 잡힐 수 있으니 `char`로 변환한다.
- 길이를 출력하고, 길이가 0이 아니면 문자열도 출력. `abcbdab / bdcaba` → `bcab`. `xyxy / yxyx` → `xyx`. 공통 글자가 없으면 `0`만.

(3) 스스로 다시 짤 때 생각 순서

- "복원 + 사전순" → 접미사 LCS 표(`L[i][j]`)로 남은 최대 길이를 알 수 있게 만든다.
- 앞에서부터 `a`~`z` 순으로 "골라도 최대 길이 유지" 조건을 검사하는 그리디를 짠다.
- 다음 위치 표로 탐색을 O(1)로 만들고, 길이 0일 때 출력 형식을 확인.
```

**10) 와일드카드 패턴 매칭** · Hard

- **요구사항**: 패턴 p와 문자열 s가 주어진다. 패턴에서 `?`는 아무 글자 **한 개**, `*`는 아무 글자 **0개 이상**(빈 문자열 포함)과 매칭되고, 그 외 글자는 그대로 일치해야 한다. p가 s **전체**와 매칭되면 `yes`, 아니면 `no`를 출력하라. 여러 쌍이 주어진다.
- **입력**: 첫 줄 T (1 ≤ T ≤ 20), 이후 T줄에 패턴 p와 문자열 s (공백 구분, p는 소문자·`?`·`*`, s는 소문자, 각 길이 1 이상 200 이하)
- **출력**: 각 쌍마다 `yes` 또는 `no`를 한 줄씩
- **예제**: `4 / a*c abc / a?c ac / *b* abc / a*b*c abbbc` → `yes / no / yes / yes` · `3 / * a / ab abc / a*a a` → `yes / no / no`
- **셀프체크**: `dp[i][j]` = `s[:i]`가 `p[:j]`와 매칭되는가. `*`는 "한 글자 더 먹기(`dp[i-1][j]`)" 또는 "0글자(`dp[i][j-1]`)" 두 갈래. 빈 s에 대한 첫 행 `dp[0][j]`는 앞이 전부 `*`일 때만 참이 되는데, 이 초기화를 빠뜨리면 `*b*`가 틀린다. `a*a`와 `a`는 `a`가 두 번 필요하므로 `no`. 부분 매칭이 아니라 **전체** 매칭(`ab` vs `abc`는 `no`)임을 확인. 표는 `vector<vector<char>>`로 두는 편이 `vector<bool>`보다 다루기 쉽다.

```runner
@@SOLUTION
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    int T;
    cin >> T;
    for (int k = 0; k < T; k++) {
        string p, s;
        cin >> p >> s;
        int n = (int)s.size(), m = (int)p.size();
        // dp[i][j] = s[:i]가 p[:j]와 매칭되는가
        vector<vector<char>> dp(n + 1, vector<char>(m + 1, 0));
        dp[0][0] = 1;
        for (int j = 1; j <= m; j++)
            if (p[j - 1] == '*') dp[0][j] = dp[0][j - 1];      // '*'가 0글자와 매칭
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (p[j - 1] == '*')
                    dp[i][j] = (dp[i - 1][j] || dp[i][j - 1]) ? 1 : 0;  // 한 글자 더 vs 0글자
                else if (p[j - 1] == '?' || p[j - 1] == s[i - 1])
                    dp[i][j] = dp[i - 1][j - 1];
            }
        }
        cout << (dp[n][m] ? "yes" : "no") << '\n';
    }
    return 0;
}

(1) 접근·핵심 아이디어

- 두 문자열(패턴·대상)을 나란히 비교하는 2차원 표. 상태 정의: `dp[i][j]` = `s`의 앞 i글자가 `p`의 앞 j글자와 완전히 매칭되는가(참/거짓).
- 전이는 `p[j-1]`의 종류로 갈린다. 일반 글자 또는 `?`: `s[i-1]`와 맞으면 대각선 `dp[i-1][j-1]`. `*`: 두 가지 — `*`가 `s[i-1]`를 한 글자 더 먹고 계속 `*`로 남는 `dp[i-1][j]`, 또는 `*`가 0글자와 매칭되어 사라지는 `dp[i][j-1]`. 둘 중 하나라도 참이면 참.
- 경계: `dp[0][0] = true`(빈 s와 빈 p). `dp[0][j]`는 `p[:j]`가 전부 `*`일 때만 참 — 앞에서부터 전파. `dp[i][0]`(빈 패턴, 비어 있지 않은 s)은 거짓.
- 답 `dp[|s|][|p|]`. 시간 O(|s|·|p|), 공간 O(|s|·|p|).

(2) 코드 단계별

- 입력 순서가 **패턴 먼저, 문자열 나중**임에 주의해 `cin >> p >> s`로 받는다. 표의 행은 `s`, 열은 `p`이므로 `n = s.size()`, `m = p.size()`로 이름을 정확히 붙여 두지 않으면 인덱스가 뒤집힌다.
- 표는 `vector<vector<char>>`로 만든다. `vector<bool>`은 비트 하나에 값을 눌러 담는 특수화라 원소의 참조(`bool&`)를 얻을 수 없고, `auto x = dp[i][j];`가 `bool`이 아닌 프록시 객체가 되는 등 예상 밖 동작이 많다. 표는 `char`(또는 `uint8_t`)로 두는 편이 안전하고 대개 더 빠르다.
- 각 쌍마다 `dp[0][0]=1`, 첫 행은 `*`가 이어지는 동안만 참으로 채운다. 이 줄이 없으면 `*b* / abc`처럼 패턴이 `*`로 시작하는 경우가 전부 `no`가 된다.
- 이중 루프에서 `p[j-1]`가 `*`면 `dp[i-1][j] || dp[i][j-1]`, `?`거나 같은 글자면 `dp[i-1][j-1]`, 아니면 0인 채로 둔다(`vector`를 0으로 초기화했으므로 `else` 분기가 필요 없다).
- 매 쌍마다 표를 새로 만든다. 바깥 루프 밖에서 한 번만 만들고 재사용하려면 명시적으로 0으로 다시 채워야 한다 — 이전 쌍의 결과가 남아 있으면 조용히 틀린 답이 나온다.
- `a*c / abc` → `*`가 `b`를 먹어 `yes`. `a?c / ac` → `?`가 먹을 글자가 없어 `no`. `a*b*c / abbbc` → `yes`. `ab / abc` → 전체 매칭 실패 `no`. `a*a / a` → `no`. `a**b / ab` → `yes`. `?*? / a` → `no`.

(3) 스스로 다시 짤 때 생각 순서

- "전체 매칭 + 와일드카드" → `dp[i][j]` 표, 패턴 글자 종류별로 전이를 나눈다.
- `*`의 두 갈래(한 글자 더 / 0글자)와 첫 행 초기화(앞이 전부 `*`)를 먼저 처리.
- 불리언 표는 `vector<vector<char>>`, 여러 쌍이면 매번 새로 초기화, 답은 표의 오른쪽 아래 칸.
```

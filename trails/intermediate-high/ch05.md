> 개요: 이 챕터에서는 "차원을 늘리거나 상태를 압축하는" 고급 DP를 다룬다. 양방향으로 훑는 Bitonic DP, 작은 구간을 큰 구간으로 합쳐 올라가는 구간 DP(Interval DP), 집합을 정수 하나로 다루는 비트마스크, 그리고 그 둘을 합쳐 방문 상태를 압축하는 Bitmask DP를 익힌다.

## L1. Bitonic Cycle

**개념**

- Bitonic(양방향) DP는 "한 방향으로 쭉 갔다가 반대 방향으로 되돌아오는" 경로를 두 개의 단조(monotone) 경로로 쪼개어 계산하는 기법이다.
- 대표 문제는 **Bitonic TSP(양방향 순회 경로)**: 평면 위 점들을 x좌표 기준으로 정렬한 뒤, 가장 왼쪽 점에서 출발해 오른쪽으로만 이동하다가 가장 오른쪽 점을 찍고, 다시 왼쪽으로만 이동해 출발점으로 돌아온다. 모든 점을 정확히 한 번씩 지나면서 총 이동 거리를 최소화한다.
- 핵심 아이디어: 왕복 경로를 "위쪽 체인"과 "아래쪽 체인" 두 개의 단조 증가 경로로 본다. 각 중간 점은 둘 중 하나의 체인에만 속한다. 그래서 "지금까지 두 체인의 끝점이 어디냐"만 상태로 잡으면 된다.
- 상태 정의(정렬된 인덱스 기준): 점 0..k까지 이미 배치했고 두 체인의 끝점이 각각 i, j(둘 중 하나는 항상 k)라 하자. `dp[i][j]` = 한 체인 끝이 i, 다른 체인 끝이 j일 때 두 체인 길이의 최소 합. 대칭이므로 `i < j`만 두고 항상 j를 "가장 최근에 배치한 점"으로 유지한다.

```python
# pts: x 기준 오름차순 정렬된 좌표 리스트, d(a,b)=두 점 거리
# dp[i][j] (i<j): 한 체인 끝 i, 다른 체인 끝 j 일 때 최소 길이 합
# j를 프런티어로 두고 j를 1씩 늘려간다.
dp[0][1] = d(0, 1)
for j in range(2, n):
    for i in range(0, j - 1):            # i, j-1 은 이어져 있던 체인, j를 j-1 뒤에 붙임
        dp[i][j] = dp[i][j - 1] + d(j - 1, j)
    # i == j-1 : j를 '다른' 체인 끝 k 뒤에 붙이는 경우(체인 전환)
    dp[j - 1][j] = min(dp[k][j - 1] + d(k, j) for k in range(0, j - 1))
answer = dp[n - 2][n - 1] + d(n - 2, n - 1)   # 마지막 두 점을 이어 왕복 완성
```

**그림으로 보기**

- Bitonic 왕복 경로는 "오른쪽으로 가는 체인"과 "왼쪽으로 돌아오는 체인" 두 개를 겹쳐 놓은 것이다. x로 정렬해 두면 두 체인 모두 인덱스가 증가하는 방향이라, 남는 정보는 "두 체인의 끝점이 어디냐"뿐이다.

```text
   x-sorted  :  p0  p1  p2  p3  p4
   go right  :  p0 - p1 - p3 - p4        # upper chain
   come back :  p4 - p2 - p0             # lower chain

        p1 ----------- p3
       /                 \
     p0                   p4             # 각 점은 정확히 한 체인에만 속한다
       \                 /
        ------ p2 -------
```

- 상태 `dp[i][j]`는 "`0..j`를 다 배치했고 두 체인 끝이 `i`, `j`"인 상태다. 프런티어 `j`를 하나씩 늘리면 전이는 두 가지뿐이다.

```text
   frontier j :  1 -> 2 -> 3 -> ... -> n-1

   (A) extend  :  ... (j-1) - (j)     dp[i][j]   = dp[i][j-1] + d(j-1, j)
   (B) switch  :  ... (k)   - (j)     dp[j-1][j] = min over k of
                                          dp[k][j-1] + d(k, j)
```

- 산 모양(bitonic) 부분수열도 발상이 같다. 꼭대기를 고정하면 왼쪽은 증가, 오른쪽은 감소라 **양쪽을 따로 구해 붙이면** 된다.

```text
   a   =  1   5   3   4   2
   inc :  1   6   4   8   3       # inc[i] : i 에서 끝나는 증가 최대합
   dec :  1  11   5   6   2       # dec[i] : i 에서 시작하는 감소 최대합
   sum :  1  12   6  10   3       # inc + dec - a[i]  (꼭대기 중복 제거)
              ^
              peak i = 1  ->  1 + 5 + 4 + 2 = 12
```

**손으로 따라가기**

- `a = [1, 5, 3, 4, 2]`로 `inc`를 왼쪽부터 채운다. `inc[i]`는 "`i`에서 끝나는 증가 부분수열의 최대 합"이다.

| i | a[i] | 왼쪽에서 `a[j] < a[i]`인 j | 그중 최대 inc[j] | inc[i] |
|---|---|---|---|---|
| 0 | 1 | 없음 | 0 | 1 |
| 1 | 5 | 0 | 1 | 6 |
| 2 | 3 | 0 | 1 | 4 |
| 3 | 4 | 0, 2 | 4 | 8 |
| 4 | 2 | 0 | 1 | 3 |

- `dec`는 반드시 **오른쪽 끝부터** 채운다. 그래야 `dec[j]`가 준비된 상태로 읽힌다.

| i | a[i] | 오른쪽에서 `a[j] < a[i]`인 j | 그중 최대 dec[j] | dec[i] |
|---|---|---|---|---|
| 4 | 2 | 없음 | 0 | 2 |
| 3 | 4 | 4 | 2 | 6 |
| 2 | 3 | 4 | 2 | 5 |
| 1 | 5 | 2, 3, 4 | 6 | 11 |
| 0 | 1 | 없음 | 0 | 1 |

- 답은 `max(inc[i] + dec[i] - a[i])`다. `i=1`에서 `6 + 11 - 5 = 12`가 최대이고, 실제 부분수열은 `1, 5, 4, 2`다.

**왜 이렇게 되는가**

- **왜 꼭대기에서 `a[i]`를 빼는가**: `inc[i]`와 `dec[i]`는 둘 다 자기 자신 `a[i]`를 포함한다. 그대로 이어 붙이면 꼭대기 원소가 두 번 더해지므로 정확히 한 번 빼야 한다.

- **왜 상태가 "두 끝점"만으로 충분한가**: 일반 순회 문제는 "누구를 방문했는지"를 기억해야 해서 상태가 `2^n`으로 폭발한다. 그런데 x로 정렬한 bitonic 경로에서는 두 체인 모두 인덱스가 증가하므로, 프런티어 `j`까지의 점은 **전부** 어느 한 체인에 이미 들어가 있다. 즉 방문 집합이 `{0..j}`로 자동 결정돼 기억할 필요가 없고, 남는 자유도는 두 끝점뿐이다. 그래서 상태 수가 `O(n^2)`로 떨어지고 지수 문제가 다항식이 된다.

- **왜 한쪽 끝이 항상 `j` 또는 `j-1`인가**: 가장 최근에 배치한 점은 뒤에 아무것도 없으므로 어느 한 체인의 끝일 수밖에 없다. 그래서 `dp[i][j]`에서 큰 쪽 인덱스를 프런티어로 고정해도 일반성을 잃지 않고, `i < j` 절반만 채우면 된다.

- **복잡도**: 상태가 `O(n^2)`이고 (A) 전이는 상태마다 O(1), (B) 전이는 `j`마다 `k`를 한 번 훑어 O(n)이라 전체가 O(n^2)이다. 산 모양 부분수열 쪽은 `inc`, `dec`를 각각 이중 루프로 채우므로 O(n^2), 공간은 배열 두 개라 O(n)이다.

**접근 전략**

- 절차: (1) x좌표 기준 정렬(같으면 y로 tie-break) → (2) 거리 테이블 준비 → (3) 위 점화식으로 `dp` 채우기 → (4) 마지막에 끝점 두 개를 이어 사이클을 닫는다.
- 언제 고르나: "왕복/양방향으로 훑되 각 원소를 한 번만", "x(혹은 어떤 축)로 정렬하면 단조성이 생김" 같은 신호가 보이면 Bitonic을 떠올린다. 일반 TSP는 지수/비트마스크지만, 이 단조 제약 덕분에 다항식으로 풀린다.
- 시간 O(n²), 공간 O(n²)(거리 테이블 포함). 정렬은 O(n log n).
- 주의점: 좌표 실수 거리라 부동소수 비교/출력 자릿수에 유의(보통 소수 둘째 자리 반올림). i<j 대칭을 깨서 상태를 중복 정의하면 값이 어긋난다. 파이썬에선 거리 계산에 `math.hypot(dx, dy)`(= `sqrt(dx**2+dy**2)`, 두 좌표 차의 유클리드 거리) 사용, `dp`는 2차원 리스트로 잡고 INF는 `float('inf')`.

**문제**

**1) 양방향 순회 경로** · Medium

- **요구사항**: 평면 위 n개의 점을 x 기준으로 정렬해, 최좌측→최우측→최좌측으로 돌아오는 Bitonic 왕복 경로의 최소 총 길이를 구하라. 각 점은 정확히 한 번 방문.
- **입력**: 첫 줄 n. 이후 n줄에 정수 좌표 `x y` (x는 서로 다름).
- **출력**: 최소 길이(소수 둘째 자리 반올림).
- **예제**: `5 / 0 0 / 1 3 / 2 1 / 4 2 / 5 0` → `13.96` (위쪽 체인 0-1-3-4, 아래쪽 0-2-4로 나뉜 최적)
- **예제**: `3 / 0 0 / 1 1 / 2 0` → `4.83` (0→1→2→0, 2*(√2)+2 = 2.828+2)
- **셀프체크**: n=2 경계(왕복=2*d), 같은 x가 없다는 가정, i<j 상태만 채우는지, 부동소수 출력 형식.

```runner
@@SOLUTION
import sys, math

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    pts = []
    for _ in range(n):
        x = int(data[idx]); y = int(data[idx+1]); idx += 2
        pts.append((x, y))
    pts.sort()
    if n == 1:
        print("0.00"); return
    def d(a, b):
        return math.hypot(pts[a][0]-pts[b][0], pts[a][1]-pts[b][1])
    INF = float('inf')
    dp = [[INF]*n for _ in range(n)]
    dp[0][1] = d(0, 1)
    for j in range(2, n):
        for i in range(0, j-1):
            dp[i][j] = dp[i][j-1] + d(j-1, j)
        best = INF
        for k in range(0, j-1):
            best = min(best, dp[k][j-1] + d(k, j))
        dp[j-1][j] = best
    ans = dp[n-2][n-1] + d(n-2, n-1)
    print(f"{ans:.2f}")

main()

(1) 접근·핵심 아이디어

- 왕복(bitonic) 경로를 x 오름차순으로 정렬한 뒤 "위쪽 체인 + 아래쪽 체인" 두 단조 경로로 쪼갠다. 각 중간 점은 둘 중 하나의 체인에만 속한다.
- 상태 `dp[i][j]`(i<j) = 한 체인 끝이 i, 다른 체인 끝이 j일 때 두 체인 길이의 최소 합. 프런티어 j를 1씩 늘려가며 채운다.

(2) 코드 단계별

- 입력을 읽고 x(같으면 y) 기준 정렬. `d(a,b)`는 `math.hypot`로 유클리드 거리.
- `dp[0][1] = d(0,1)`로 시작. j=2..n-1에 대해: i<j-1이면 점 j를 j-1이 끝인 체인 뒤에 잇는다(`dp[i][j-1]+d(j-1,j)`).
- `dp[j-1][j]`는 체인을 전환하는 경우 — 다른 체인 끝 k에서 j로 잇는 최소값 `min(dp[k][j-1]+d(k,j))`.
- 마지막에 끝 두 점을 이어 사이클을 닫는다: `dp[n-2][n-1] + d(n-2,n-1)`. 소수 둘째 자리로 출력.

(3) 스스로 다시 짤 때 생각 순서

- "왕복 + 각 점 한 번 + x로 정렬하면 단조" → bitonic DP 신호.
- 상태를 "두 체인의 끝점"으로 잡고 프런티어 j를 늘리는 방향으로 전이를 나눈다(같은 체인 연장 vs 체인 전환).
- 마지막에 끝점을 이어 닫는 것과 부동소수 출력 형식을 잊지 않는다.
```

**2) 산 모양 수열의 최대 합** · Medium

- **요구사항**: 길이 n 수열에서 몇 개 원소를 골라(원래 순서 유지) 값이 증가하다가 감소하는 "산 모양(bitonic)" 부분수열을 만든다. 고른 원소들의 **합**이 최대가 되게 하라(꼭대기 하나 필수, 순수 증가/감소도 허용).
- **입력**: 첫 줄 n, 둘째 줄 정수 n개.
- **출력**: 최대 합.
- **예제**: `5 / 1 5 3 4 2` → `12` (1,5,3,... 보다 1,4,2? → 최적은 5+4+2? =11 vs 1+5+3+... 검토, 실제 최대는 1+5+ (감소)3 or 1+5+4? 순서상 5뒤 4 →1+5+4+2=12)
- **예제**: `4 / 4 3 2 1` → `10` (순수 감소 전체 = 4+3+2+1)
- **셀프체크**: 증가합 `inc[i]`와 감소합 `dec[i]`를 따로 구해 `inc[i]+dec[i]-a[i]` 최대. 꼭대기가 양끝일 때(순증가/순감소) 포함되는지, 모두 음수 값 처리.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1+n]]
    inc = [0]*n
    dec = [0]*n
    for i in range(n):
        best = 0
        for j in range(i):
            if a[j] < a[i] and inc[j] > best:
                best = inc[j]
        inc[i] = best + a[i]
    for i in range(n-1, -1, -1):
        best = 0
        for j in range(i+1, n):
            if a[j] < a[i] and dec[j] > best:
                best = dec[j]
        dec[i] = best + a[i]
    ans = max(inc[i] + dec[i] - a[i] for i in range(n))
    print(ans)

main()
@@TESTS
--IN

1 5 3 4 2
--OUT
12
--IN
4
4 3 2 1
--OUT
10
@@EXPL
(1) 접근·핵심 아이디어

- "증가하다 감소"하는 산 모양 부분수열의 최대 합. 각 위치 i를 꼭대기로 고정했을 때의 최대 합은 (i에서 끝나는 증가 부분수열 최대 합) + (i에서 시작하는 감소 부분수열 최대 합) - a[i](꼭대기 중복 제거)이다.
- 순증가/순감소도 허용되므로 양끝을 꼭대기로 두는 경우가 자연스럽게 포함된다.

(2) 코드 단계별

- `inc[i]`: i에서 끝나는 증가 부분수열의 최대 합. j<i이고 a[j]<a[i]인 것 중 `inc[j]` 최대에 a[i]를 더한다(없으면 a[i]).
- `dec[i]`: i에서 시작하는 감소 부분수열의 최대 합. j>i이고 a[j]<a[i]인 것 중 `dec[j]` 최대에 a[i]를 더한다(오른쪽부터 채운다).
- 답은 모든 i에 대해 `inc[i] + dec[i] - a[i]`의 최대값.

(3) 스스로 다시 짤 때 생각 순서

- "산 모양(증가 후 감소)" → 꼭대기를 기준으로 좌·우를 분리하는 LIS류 두 방향 DP를 떠올린다.
- 왼쪽은 증가 최대합, 오른쪽은 감소 최대합을 각각 O(n^2)로 채운다.
- 꼭대기를 두 번 세지 않도록 a[i]를 한 번 빼는 것을 잊지 않는다.
```

**3) 왕복 순회(마을 방문)** · Hard

- **요구사항**: 1차원 좌표 위 마을들을 왼쪽에서 오른쪽으로 가며 일부를 방문하고, 오른쪽 끝에서 되돌아오며 나머지를 모두 방문한다(각 마을 정확히 1회, 갈 때/올 때 중 한 번). 총 이동 거리를 최소화하라.
- **입력**: 첫 줄 n, 둘째 줄 서로 다른 정수 좌표 n개.
- **출력**: 최소 총 이동 거리(정수).
- **예제**: `4 / 0 3 5 8` → `16` (끝점 0↔8 왕복 = 2*8, 모든 중간점은 경로상에 이미 포함)
- **예제**: `5 / 1 2 3 4 10` → `18` (2*(10-1))
- **셀프체크**: 1차원이면 x단조라 답이 2*(max-min)이 되는 이유를 스스로 증명(중간점은 갈 때/올 때 어느 쪽에 넣어도 거리 불변). 2차원으로 일반화하면 L1-1의 O(n²) DP가 필요.

```runner
@@SOLUTION

    ans = 2 * (max(xs) - min(xs))

- 최소·최대 사이의 모든 중간 점은 갈 때든 올 때든 이미 경로가 지나가므로, 어느 쪽에 배정해도 총 거리는 `2*(max-min)`로 일정하다.

- 좌표들을 읽어 최댓값·최솟값을 구한다.
- 답은 `2*(max-min)`. n<=1이면 이동이 없으므로 0.

- 왕복 경로의 총 길이는 왕복 폭 `2*(max-min)`으로 고정됨을 관찰한다(중간점 배정 무관).
- 따라서 DP 없이 최대-최소만으로 상수 시간에 답이 나온다.
```

## L2. 작은 구간에서 큰 구간으로 확장되는 DP

**개념**

- 구간 DP(Interval DP)는 상태를 "구간 [i, j]"로 잡고, **길이가 짧은 구간의 답을 먼저 구해 긴 구간의 답을 합치는** DP다. 전형적으로 `dp[i][j]`를 "구간 [i, j]를 하나로 만드는(합치는/괄호 치는/제거하는) 최적값"으로 정의한다.
- 왜 쓰나: "인접한 것을 짝지어 합친다", "괄호를 어디에 치나", "양끝을 동시에 본다", "구간을 두 조각으로 쪼갠다"처럼 **분할 지점 k를 고르는** 구조가 나오면 구간 DP다.
- 동작 원리(3단계): (1) 길이 1(또는 2) 구간을 base case로 초기화 → (2) 구간 길이 `length`를 2부터 n까지 늘려가며 → (3) 각 [i, j]에 대해 분할점 k(i≤k<j)를 모두 시도해 `dp[i][k]`와 `dp[k+1][j]`를 합치고, 합칠 때 드는 비용을 더한다.
- 핵심은 **"바깥에서 안으로"가 아니라 "안에서 바깥으로"** 채운다는 것. 그래서 이중 반복의 바깥 루프가 반드시 "구간 길이"여야 한다.

```python
pre = 누적합  # 구간 합을 O(1)로
for length in range(2, n + 1):            # 짧은 구간부터
    for i in range(0, n - length + 1):
        j = i + length - 1
        dp[i][j] = INF
        cost = pre[j + 1] - pre[i]         # 합칠 때 드는 비용(문제마다 다름)
        for k in range(i, j):              # 분할점
            dp[i][j] = min(dp[i][j],
                           dp[i][k] + dp[k + 1][j] + cost)
# dp[0][n-1] 이 정답
```

**그림으로 보기**

- 구간 DP 표는 위쪽 삼각형만 쓴다. 채우는 순서는 행 순서가 아니라 **대각선 순서**, 즉 구간 길이 오름차순이다.

```text
   n = 4 ,  dp[i][j] with i <= j

            j=0   j=1   j=2   j=3
    i=0     L1    L2    L3    L4
    i=1      .    L1    L2    L3
    i=2      .     .    L1    L2
    i=3      .     .     .    L1

    L1 -> L2 -> L3 -> L4        # 대각선을 한 줄씩 바깥으로 밀며 채운다
    # L1 = 길이 1 (base) , L4 = 구간 전체
```

- 한 구간의 답은 "마지막에 합쳐지는 경계 `k`"를 모두 시도해서 얻는다. 왼쪽 조각과 오른쪽 조각은 둘 다 더 짧은 구간이라 이미 채워져 있다.

```text
   [ i .......... k ][ k+1 ....... j ]
     \____________/    \___________/
        dp[i][k]        dp[k+1][j]     # 둘 다 길이가 더 짧다
   dp[i][j] = min over k ( dp[i][k] + dp[k+1][j] + cost(i, j) )
```

- `a = 4 1 2 3`을 합치는 최적 순서. 작은 덩이부터 붙여야 큰 합이 여러 번 다시 더해지지 않는다.

```text
   a  =  4    1    2    3
                \  /
                (3)              # 1 + 2 = 3     -> cost 3
                  \    /
                   (6)           # 3 + 3 = 6     -> cost 6
          \       /
           (10)                  # 4 + 6 = 10    -> cost 10
   total cost = 3 + 6 + 10 = 19
```

**손으로 따라가기**

- `a = [4, 1, 2, 3]`, 누적합 `pre = [0, 4, 5, 7, 10]`. 길이 2부터 순서대로 채운다.

| 길이 | 구간 [i,j] | cost(구간합) | 분할 후보 `dp[i][k] + dp[k+1][j]` | dp[i][j] |
|---|---|---|---|---|
| 2 | [0,1] | 5 | k=0 : 0+0 = 0 | 0+5 = **5** |
| 2 | [1,2] | 3 | k=1 : 0+0 = 0 | 0+3 = **3** |
| 2 | [2,3] | 5 | k=2 : 0+0 = 0 | 0+5 = **5** |
| 3 | [0,2] | 7 | k=0 : 0+3 = 3 / k=1 : 5+0 = 5 | 3+7 = **10** |
| 3 | [1,3] | 6 | k=1 : 0+5 = 5 / k=2 : 3+0 = 3 | 3+6 = **9** |
| 4 | [0,3] | 10 | k=0 : 0+9 = 9 / k=1 : 5+5 = 10 / k=2 : 10+0 = 10 | 9+10 = **19** |

- 마지막 줄에서 `dp[1][3] = 9`가 이미 준비돼 있다는 점이 핵심이다. 길이 순서를 지키지 않으면 그 자리가 아직 초기값이라 답이 조용히 어긋난다.

**왜 이렇게 되는가**

- **왜 바깥 루프가 구간 길이여야 하는가**: `dp[i][j]`는 `dp[i][k]`(길이 `k-i+1`)와 `dp[k+1][j]`(길이 `j-k`)를 읽는데, `i <= k < j`라서 둘 다 `j-i+1`보다 **반드시 짧다**. 짧은 것부터 채우면 읽는 순간 항상 완성돼 있다. 흔히 쓰는 `for i in range(n): for j in range(i, n)` 순서는 `dp[k+1][j]`의 행 번호 `k+1`이 `i`보다 커서 아직 안 채워진 자리를 읽는다(`i`를 내림차순으로 돌리면 그 순서로도 성립한다).

- **왜 합치는 비용이 구간 전체 합인가**(파일 합치기): 마지막 병합은 `[i..k]`를 뭉친 한 덩이와 `[k+1..j]`를 뭉친 한 덩이를 붙이는 것이고, 그 비용은 두 덩이 크기의 합, 즉 `sum(a[i..j])`다. 이 값은 `k`와 무관하므로 `min` 밖으로 뺄 수 있고, 누적합 하나면 O(1)에 구해진다.

- **왜 base case가 0인가**: 길이 1 구간은 이미 한 덩이라 더 합칠 것이 없으니 비용 0이다. 이 값이 모든 계산의 바닥이 된다. "구간이 팰린드롬인가" 같은 참·거짓 표라면 길이 1은 항상 참이 바닥이다.

- **복잡도 세기**: 길이 `L`인 구간은 `n-L+1`개이고 각각 분할점이 `L-1`개다. 합하면 `Σ_{L=2..n} (n-L+1)(L-1) ≈ n^3/6`이라 O(n^3)이다. 상태만 보면 `n^2/2`개이고 상태당 O(n)이 붙는 구조라고 읽으면 된다. 공간은 표 하나라 O(n^2)이고, n이 500쯤이면 표는 감당되지만 `n^3`이 1억을 넘어 파이썬에서는 상수 관리가 필요하다.

**접근 전략**

- 절차: 상태 `dp[i][j]` 의미를 한 문장으로 못 쓰면 아직 설계가 덜 된 것. "구간 전체를 하나로 만들 때의 최적값"으로 정의하고, base case(길이 1은 0 또는 자기 자신)를 먼저 고정한다. 그다음 "마지막에 합쳐지는 두 덩어리의 경계 k"를 상상하면 점화식이 나온다.
- 대표 유형: 돌/파일 합치기(합칠 때 두 더미 합만큼 비용), 행렬 곱 순서(괄호), 팰린드롬 분할, 풍선 터뜨리기(양끝 곱), 문자열을 특정 규칙으로 지우기.
- 시간 O(n³)(구간 O(n²) × 분할점 O(n)), 공간 O(n²). Knuth 최적화가 적용되는 특수 형태면 O(n²)까지 줄기도 한다.
- 주의점: 바깥 루프를 길이로 하지 않으면 `dp[i][k]`가 아직 안 채워져 틀린다. 구간 합은 누적합으로 상수 시간에. 재귀(메모이제이션)로 짤 땐 `sys.setrecursionlimit(10**6)`와 `functools.lru_cache` 또는 2차원 배열 memo. INF/미방문 구분에 주의.

**문제**

**1) 파일 합치기** · Medium

- **요구사항**: 일렬로 놓인 n개의 파일을 인접한 두 개씩만 합칠 수 있다. 두 파일을 합치는 비용은 두 파일 크기의 합이다. 모든 파일을 하나로 합칠 때 총비용의 최솟값을 구하라.
- **입력**: 첫 줄 n, 둘째 줄 파일 크기 n개.
- **출력**: 최소 총비용.
- **예제**: `4 / 4 1 2 3` → `19`
- **예제**: `3 / 10 20 30` → `90` (10+20=30, 그다음 30+30=60, 총 90)
- **셀프체크**: 인접만 합칠 수 있음(임의 두 개가 아님 → 허프만이 아니라 구간 DP). 구간 합을 매번 새로 더하면 O(n⁴)이 되니 누적합 필수. n=1이면 0.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1+n]]
    if n == 1:
        print(0); return
    pre = [0]*(n+1)
    for i in range(n):
        pre[i+1] = pre[i] + a[i]
    INF = float('inf')
    dp = [[0]*n for _ in range(n)]
    for length in range(2, n+1):
        for i in range(0, n-length+1):
            j = i + length - 1
            best = INF
            cost = pre[j+1] - pre[i]
            for k in range(i, j):
                v = dp[i][k] + dp[k+1][j] + cost
                if v < best:
                    best = v
            dp[i][j] = best
    print(dp[0][n-1])

main()

(1) 접근·핵심 아이디어

- 인접한 두 파일만 합칠 수 있으므로 전형적인 구간 DP다. `dp[i][j]` = 구간 [i,j]의 파일들을 하나로 합치는 최소 총비용.
- 마지막에 합쳐지는 경계 k를 상상하면, [i,k]를 하나로, [k+1,j]를 하나로 만든 뒤 둘을 합친다. 이때 합치는 비용은 구간 전체 합 `sum(a[i..j])`.

(2) 코드 단계별

- 누적합 `pre`로 구간 합을 O(1)에 구한다.
- 구간 길이를 2부터 n까지 늘리며(안에서 바깥으로), 각 [i,j]에 대해 분할점 k(i<=k<j)를 모두 시도.
- `dp[i][j] = min_k(dp[i][k] + dp[k+1][j]) + (pre[j+1]-pre[i])`. 길이 1은 0.

(3) 스스로 다시 짤 때 생각 순서

- "인접한 것을 짝지어 합친다 + 분할점 선택" → 구간 DP.
- 상태를 "[i,j] 전체를 하나로 만드는 최소 비용"으로 정의하고 base(길이 1 = 0)를 고정.
- 바깥 루프를 반드시 구간 길이로 두어 짧은 구간이 먼저 채워지게 하고, 합치는 비용은 누적합으로 처리.
```

**2) 행렬 곱셈 순서** · Medium

- **요구사항**: 행렬 A1..An을 곱할 때 곱셈 순서(괄호)에 따라 곱셈 연산 횟수가 달라진다. 스칼라 곱셈 횟수를 최소화하라. Ai의 크기는 `p[i-1] x p[i]`.
- **입력**: 첫 줄 n, 둘째 줄 정수 n+1개 `p0 p1 ... pn`.
- **출력**: 최소 곱셈 횟수.
- **예제**: `3 / 10 20 30 40` → `18000` ((A1A2)A3 = 10·20·30 + 10·30·40 = 6000+12000)
- **예제**: `2 / 5 10 20` → `1000` (5·10·20)
- **예제**: `3 / 40 20 30 10` → `26000`
- **셀프체크**: `dp[i][j]` 정의 시 합치는 비용이 `p[i]*p[k+1]*p[j+1]`처럼 인덱스가 헷갈리기 쉬움 — 작은 예제로 손검산. 대각선(길이1)은 0.

```runner

                v = dp[i][k] + dp[k+1][j] + p[i]*p[k+1]*p[j+1]
                if v < best:
                    best = v
            dp[i][j] = best
    print(dp[0][n-1])

- 행렬 A_(i+1)..A_(j+1)를 곱하는 최소 스칼라 곱셈 횟수를 `dp[i][j]`로 둔다(0-index로 크기 배열 p 사용, A_(k+1)는 `p[k] x p[k+1]`).
- 마지막에 곱해지는 괄호 경계 k를 정하면, 왼쪽 결과는 `p[i] x p[k+1]`, 오른쪽 결과는 `p[k+1] x p[j+1]` 크기이고 둘을 곱하는 비용은 `p[i]*p[k+1]*p[j+1]`.

(2) 코드 단계별

- 크기 배열 p(길이 n+1)를 읽는다.
- 구간 길이를 2부터 늘리며 각 [i,j]에서 분할점 k를 모두 시도: `dp[i][j] = min_k(dp[i][k]+dp[k+1][j] + p[i]*p[k+1]*p[j+1])`.
- 길이 1(대각선)은 0. 최종 `dp[0][n-1]`.

(3) 스스로 다시 짤 때 생각 순서

- "곱셈 순서(괄호)를 어디에 치나 + 분할점" → 구간 DP.
- 인덱스가 헷갈리므로 "왼쪽 곱 결과 행/열, 오른쪽 곱 결과 행/열"을 작은 예제로 손검산해 `p[i]*p[k+1]*p[j+1]`을 확정한다.
- 바깥 루프는 구간 길이, base는 길이 1 = 0.
```

**3) 팰린드롬 분할** · Hard

- **요구사항**: 문자열 s를 여러 조각으로 나누되 모든 조각이 팰린드롬이 되게 한다. 필요한 최소 "자르기 횟수"를 구하라.
- **입력**: 한 줄에 소문자 문자열 s (길이 ≤ 2000).
- **출력**: 최소 자르기 횟수.
- **예제**: `aab` → `1` ("aa" | "b")
- **예제**: `abccba` → `0` (전체가 팰린드롬)
- **예제**: `abcde` → `4`
- **셀프체크**: 두 단계 DP — 먼저 `pal[i][j]`(구간이 팰린드롬인지)를 구간 DP로 채우고, 그다음 위치별 최소 컷 `dp`를 계산. 길이 2 구간의 팰린드롬 판정 예외, O(n²) 시간/공간이 2000 크기에서 감당되는지.

```runner
@@SOLUTION
import sys

def main():
    s = sys.stdin.readline().strip()
    n = len(s)
    if n == 0:
        print(0); return
    pal = [[False]*n for _ in range(n)]
    for i in range(n):
        pal[i][i] = True
    for length in range(2, n+1):
        for i in range(0, n-length+1):
            j = i + length - 1
            if s[i] == s[j]:
                if length == 2:
                    pal[i][j] = True
                else:
                    pal[i][j] = pal[i+1][j-1]
    INF = float('inf')
    dp = [0]*n
    for j in range(n):
        if pal[0][j]:
            dp[j] = 0
        else:
            best = INF
            for i in range(1, j+1):
                if pal[i][j] and dp[i-1] + 1 < best:
                    best = dp[i-1] + 1
            dp[j] = best
    print(dp[n-1])
```

## L3. Bitmask

**개념**

- 비트마스크는 **작은 집합을 정수 하나로 표현**하는 기법이다. 원소 i가 집합에 있으면 정수의 i번째 비트를 1로 둔다. 예를 들어 `{0, 1, 3}` = 이진수 `1011` = 11.
- 왜 쓰나: 집합을 배열/`set`으로 들고 다니면 복사·비교가 느리고, DP의 상태 키로 쓰기 어렵다. 정수 하나면 비교·해시·배열 인덱스가 O(1)이고 부분집합 열거도 비트 연산으로 빠르다.
- 필수 연산(원소 i, 마스크 m 기준):

```python
m | (1 << i)        # 원소 i 추가
m & ~(1 << i)       # 원소 i 제거
m ^ (1 << i)        # 원소 i 토글
(m >> i) & 1        # 원소 i 포함 여부 (1이면 포함)
bin(m).count("1")   # 켜진 비트 수(집합 크기)   # 또는 m.bit_count() (py3.10+)
m & (m - 1)         # 가장 낮은 켜진 비트 하나 끄기
m & (-m)            # 가장 낮은 켜진 비트만 남기기 (LSB)
(1 << n) - 1        # 전체 집합(원소 0..n-1 전부)
```

- 부분집합 열거(마스크 m의 모든 부분집합을 도는 관용구):

```python
sub = m
while True:
    ...            # sub 사용
    if sub == 0: break
    sub = (sub - 1) & m
```

**그림으로 보기**

- 마스크와 부분집합은 일대일로 대응한다. `n = 3`이면 정수 `0..7`이 부분집합 8개를 남김없이 가리킨다.

```text
   n = 3 ,  elements = { 0 , 1 , 2 }

   mask    b2 b1 b0     subset
     0      0  0  0     { }
     1      0  0  1     {0}
     2      0  1  0     {1}
     3      0  1  1     {0,1}
     4      1  0  0     {2}
     5      1  0  1     {0,2}
     6      1  1  0     {1,2}
     7      1  1  1     {0,1,2}
```

- 비트 연산 하나하나가 집합 연산 하나에 대응한다. `m = 10110`(= 22, 집합 `{1,2,4}`)에 하나씩 적용해 보자.

```text
   bit          :  4 3 2 1 0
   m            :  1 0 1 1 0      # {1, 2, 4}
   1 << 2       :  0 0 1 0 0
   m | (1<<2)   :  1 0 1 1 0      # 원소 2 추가 (이미 있어 그대로)
   m & ~(1<<2)  :  1 0 0 1 0      # 원소 2 제거
   m ^ (1<<2)   :  1 0 0 1 0      # 원소 2 토글
   (m >> 2) & 1 :  1              # 원소 2 포함 여부
   m & (m - 1)  :  1 0 1 0 0      # 최하위 1 하나 끄기
   m & (-m)     :  0 0 0 1 0      # 최하위 1만 남기기
```

- 부분집합 순회 관용구는 "1 빼고 마스크로 걸러내기"를 반복해, 부분집합을 큰 값부터 작은 값 순으로 정확히 한 번씩 방문한다.

```text
   mask =  1 0 1 0        ( = {1, 3} )

   sub  =  1 0 1 0        {1,3}
        -> 1 0 0 0        {3}        # sub = (sub - 1) & mask
        -> 0 0 1 0        {1}
        -> 0 0 0 0        { }
        -> stop                      # sub == 0 이면 종료
```

**손으로 따라가기**

- `a = [1, 2, 4]`, 전체 합 `total = 7`. 마스크 0~7을 전부 훑으며 한 팀의 합과 두 팀 차이를 적는다.

| mask | 이진 | 고른 원소 | 합 s | `abs(total - 2*s)` |
|---|---|---|---|---|
| 0 | `000` | 없음 | 0 | 7 |
| 1 | `001` | a0=1 | 1 | 5 |
| 2 | `010` | a1=2 | 2 | 3 |
| 3 | `011` | a0, a1 | 3 | **1** |
| 4 | `100` | a2=4 | 4 | **1** |
| 5 | `101` | a0, a2 | 5 | 3 |
| 6 | `110` | a1, a2 | 6 | 5 |
| 7 | `111` | 전부 | 7 | 7 |

- 최솟값은 1이다. `mask=3`과 `mask=4`는 서로 여집합이라 같은 분할을 두 번 센 것이고, 표 전체가 위아래로 대칭인 이유도 그것이다. 그래서 마스크를 절반만 돌아도 답이 같다.

**왜 이렇게 되는가**

- **왜 정수 하나로 집합을 표현할 수 있는가**: `n`비트 정수는 각 비트를 0/1로 독립 선택한 결과라 `2^n`가지이고, 크기 `n` 집합의 부분집합도 `2^n`개다. "원소 `i`가 있다 ↔ 비트 `i`가 1"이라는 대응은 서로 다른 집합을 서로 다른 정수로 보내므로 일대일 대응이다. 덕분에 집합을 배열 인덱스로 그대로 쓸 수 있다.

- **`sub = (sub-1) & mask`의 원리**: `sub - 1`은 `sub`의 가장 낮은 1비트를 0으로 바꾸고 그보다 아래를 전부 1로 채운다. 여기에 `& mask`를 하면 마스크에 없는 비트가 지워져 다시 `mask`의 부분집합이 된다. 값은 매번 반드시 줄어들고, 건너뛴 값들은 `mask`의 부분집합이 아닌 것들뿐이다. 그래서 **모든 부분집합을 내림차순으로 정확히 한 번씩** 방문하게 된다.

- **`m & (m-1)`과 `m & (-m)`**: `m-1`은 최하위 1비트를 0으로, 그 아래를 전부 1로 만든다. `m`과 AND하면 그 최하위 1비트만 사라진다(그 아래는 원래 0이었으니 영향이 없다). 파이썬 정수는 2의 보수 의미로 동작해 `-m = ~m + 1`이므로, `m & (-m)`은 최하위 1비트만 남긴다. 앞의 것은 "켜진 비트 세기" 루프에, 뒤의 것은 "가장 낮은 원소 하나 고르기"에 쓴다.

- **복잡도**: 모든 마스크를 돌며 켜진 비트를 훑으면 `2^n × n`이라 `n = 20`에서 약 2천만 번이다. 파이썬에서는 이미 무거운 규모다. "모든 마스크의 모든 부분집합"은 `Σ_m 2^popcount(m) = 3^n`인데, 각 원소가 (부분집합에 있음 / 마스크에만 있음 / 아예 없음) 셋 중 하나이기 때문이다. `n = 16`이면 `3^16 ≈ 4300만`으로 경계선이다.

**접근 전략**

- 절차: 원소가 **약 20개 이하**로 작을 때 "모든 집합/부분집합을 한 번씩 본다"가 필요하면 비트마스크를 쓴다. `2^n`개의 마스크를 `range(1 << n)`으로 순회하고, 각 마스크에서 켜진 비트를 훑어 원소를 복원한다.
- 언제 고르나: "N개를 켜고/끄는 모든 경우", "부분집합의 합/곱", "겹치지 않게 고르기(집합 교집합=0 판정)" 같은 문제. 상태 개수가 `2^n`이라 n이 크면 못 쓴다(대략 n ≤ 20~22).
- 시간: 전체 마스크 순회 O(2^n × n), "모든 마스크의 모든 부분집합" 열거는 O(3^n)(각 원소가 포함/부분집합-포함/제외 3택). 공간 O(2^n) 또는 O(1).
- 주의점: 파이썬 정수는 임의 정밀도라 오버플로 걱정은 없지만 `2^n` 자체가 커지면 메모리/시간이 폭발. 연산자 우선순위 함정 — `(m >> i) & 1`처럼 **반드시 괄호**. `1 << i`를 `1 << (i)`로 명확히. 부분집합 열거 관용구에서 `sub==0`을 한 번은 처리하고 루프를 끝내는 순서를 지켜라(빈 집합 포함 여부).

**문제**

**1) 팀 나누기(부분집합 균형)** · Easy

**3) 최소 인원으로 전 과제 커버** · Medium

- **요구사항**: 처리해야 할 스킬이 m개(m ≤ 20). 각 지원자는 특정 스킬 집합을 커버한다. 모든 스킬을 커버하는 데 필요한 최소 인원 수를 구하라(불가능하면 -1).
- **입력**: 첫 줄 m p(p=지원자 수). 이후 p줄, 각 줄은 그 지원자가 커버하는 스킬 번호들(0-index).
- **출력**: 최소 인원(불가능 -1).
- **예제**: `3 3 / 0 1 / 1 2 / 2` → `2` (지원자0{0,1} + 지원자1{1,2} = 전체)
- **예제**: `2 1 / 0` → `-1` (스킬 1을 아무도 못 함)
- **셀프체크**: 각 지원자의 스킬 집합을 마스크로 미리 변환. 상태 = "지금까지 커버한 스킬 마스크", `dp[mask]`=최소 인원(사실상 set cover). 전체 마스크 도달 불가면 -1. 이건 이미 마스크를 **DP 상태**로 쓴 것 → 다음 레슨 L4로 자연스럽게 연결된다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split('\n')
    first = data[0].split()
    m = int(first[0]); p = int(first[1])
    masks = []
    for r in range(1, p+1):
        parts = data[r].split()
        mk = 0
        for x in parts:
            mk |= (1 << int(x))
        masks.append(mk)
    full = (1 << m) - 1
    INF = float('inf')
    dp = [INF]*(1 << m)
    dp[0] = 0
    for state in range(1 << m):
        if dp[state] == INF:
            continue
        for mk in masks:
            ns = state | mk
            if dp[state] + 1 < dp[ns]:
                dp[ns] = dp[state] + 1
    print(dp[full] if dp[full] != INF else -1)

main()

@@EXPL
(1) 접근·핵심 아이디어

- 각 지원자가 커버하는 스킬 집합을 비트마스크로 바꾸면 전형적인 최소 집합 커버(set cover)다. 상태 `dp[state]` = state 스킬들을 커버하는 최소 인원.
- 전이: 상태 state에 어떤 지원자 마스크 mk를 추가하면 `state | mk`로 가며 인원이 1 증가.

(2) 코드 단계별

- 지원자별 스킬 마스크 목록을 만든다.
- `dp[0]=0`에서 시작해 모든 state를 오름차순 순회하며 도달 가능한 state에서 각 지원자 마스크로 전이.
- 최종 `dp[full]`. INF면 -1(전체 커버 불가).

(3) 스스로 다시 짤 때 생각 순서

- "모든 스킬을 덮는 최소 인원, m<=20" → 마스크를 DP 상태로 쓰는 set cover.
- 각 후보(지원자)를 하나 추가하는 전이를 정의하고, state를 오름차순으로 돌아 최소 인원을 완화(relax)한다.
- 도달 불가(INF)는 -1로 출력.
```

## L4. Bitmask DP

**개념**

- 비트마스크 DP는 **"어떤 원소들을 이미 처리(방문/선택/사용)했는가"를 비트마스크로 압축해 DP 상태에 넣는** 기법이다. "방문 집합"처럼 순서·조합이 폭발하는 상태를 `2^n`개의 정수로 눌러 담는다.
- 대표 두 형태:
  1. **외판원 순회(TSP)**: `dp[mask][u]` = "집합 mask의 도시들을 방문했고 현재 u에 있을 때"의 최소 비용. 다음 도시 v로 확장하며 `mask | (1<<v)`.
  2. **할당/매칭**: `dp[mask]` = "mask에 해당하는 작업/자리들이 채워졌을 때"의 최적값. 켜진 비트 수 = 지금 배정 중인 사람 번호로 쓰는 트릭.
- 동작 원리(TSP): 시작 도시를 0으로 고정 → `dp[1][0]=0`(0만 방문, 0에 있음) → 모든 mask, 모든 현재 위치 u에 대해 아직 안 간 v로 전이 → 마지막에 전체 방문 후 0으로 복귀 비용을 더해 최솟값.

```python
# TSP: dist[u][v], 도시 0 출발·복귀
dp = [[INF] * n for _ in range(1 << n)]
dp[1][0] = 0
for mask in range(1 << n):
    for u in range(n):
        if dp[mask][u] == INF or not (mask >> u) & 1:
            continue
        for v in range(n):
            if (mask >> v) & 1:            # 이미 방문
                continue
            nm = mask | (1 << v)
            dp[nm][v] = min(dp[nm][v], dp[mask][u] + dist[u][v])
full = (1 << n) - 1
answer = min(dp[full][u] + dist[u][0] for u in range(1, n))
```

**그림으로 보기**

- 비트마스크 DP의 상태는 `(방문 집합, 현재 위치)` 두 칸이다. 지나온 순서가 달라도 이 두 값이 같으면 앞으로 할 선택이 완전히 같으므로 한 칸으로 합쳐진다.

```text
   dist :  d(0,1)=1 , d(1,2)=2 , d(0,2)=3

   0 -> 1 -> 2      cost 1 + 2 = 3      # 끝점 2
   0 -> 2 -> 1      cost 3 + 2 = 5      # 끝점 1
   # 방문 집합은 둘 다 {0,1,2} 지만 끝점이 달라 서로 다른 상태다

   state = ( mask , u )
   dp[0111][2] = 3
   dp[0111][1] = 5
```

- 표는 마스크 오름차순으로 채운다. 전이가 항상 비트를 하나 켜는 방향이라 `mask < mask | (1<<v)`이고, 읽는 자리는 늘 이미 끝난 자리다.

```text
   0001 -> 0011 -> 0111 -> 1111
   0001 -> 0101 -> 0111
   0001 -> 1001 -> 1011 -> 1111
      # 어느 경로든 마스크 값은 커지기만 한다

   mask ascending  =>  source is finished before it is read
```

- 상태 수는 `2^n × n`이다. `n`이 조금만 커져도 표가 감당이 안 되는 이유가 이 표에 다 들어 있다.

```text
   n        :  10       15       16        20        24
   2^n      :  1024     32768    65536     1048576   16777216
   2^n * n  :  1.0e4    4.9e5    1.0e6     2.1e7     4.0e8
   #           ^ 여유    ^ 여유   ^ 경계선  ^ 위험     ^ 불가
```

**손으로 따라가기**

- 도시 3개, 대칭 거리 `d(0,1)=1`, `d(1,2)=2`, `d(0,2)=3`. `dp[001][0] = 0`에서 시작해 마스크 오름차순으로 채운다.

| mask | u | dp | 어디서 왔나 |
|---|---|---|---|
| `001` | 0 | 0 | 시작 상태(0만 방문, 0에 있음) |
| `011` | 1 | 1 | `dp[001][0] + d(0,1) = 0 + 1` |
| `101` | 2 | 3 | `dp[001][0] + d(0,2) = 0 + 3` |
| `111` | 2 | 3 | `dp[011][1] + d(1,2) = 1 + 2` |
| `111` | 1 | 5 | `dp[101][2] + d(2,1) = 3 + 2` |

- 마지막에 출발지로 돌아오는 비용을 더한다. `dp[111][1] + d(1,0) = 5 + 1 = 6`, `dp[111][2] + d(2,0) = 3 + 3 = 6`. 둘 다 6이고 그것이 답이다(경로 `0 → 1 → 2 → 0` = `1 + 2 + 3`).

**왜 이렇게 되는가**

- **왜 `(mask, u)`면 충분한가**: 남은 비용은 "아직 안 간 도시들"과 "지금 위치"에만 달려 있다. 안 간 도시는 `mask`의 여집합으로 결정되고 위치는 `u`다. 그래서 같은 `(mask, u)`에 도달한 여러 경로 중 비용이 가장 작은 것만 남겨도 최종 최적해가 보존된다(최적 부분 구조). 이것이 순서를 통째로 기억하지 않아도 되는 이유다.

- **왜 상태 수가 `2^n × n`인가**: `mask`가 `2^n`가지, `u`가 `n`가지다. 각 상태에서 다음 도시 후보가 최대 `n`개이므로 시간은 `O(2^n × n^2)`, 메모리는 `O(2^n × n)`이다. `n = 16`이면 시간이 약 `1.7×10^7`이라 파이썬에서도 가능하지만, `n = 20`이면 `4×10^8`이라 사실상 불가능하다. **비트마스크 DP에서 `n <= 20` 안팎이라는 제한은 정확히 이 계산에서 나온다.**

- **왜 마스크를 오름차순으로 순회하는가**: 전이가 `mask -> mask | (1<<v)`(단 `v`는 아직 0)뿐이라 목적지 값이 항상 출발지보다 크다. 즉 정수 오름차순 순회가 그대로 위상 정렬이라 별도 정렬이 필요 없다. 반대로 "이미 켜진 비트를 끄는" 전이가 섞이면 이 순서가 깨지고, 그때는 순회 순서를 다시 설계해야 한다.

- **왜 배정형은 1차원으로 줄어드는가**: 사람을 0번부터 순서대로 배정하면 "지금 몇 번 사람 차례인가"가 이미 채워진 작업 수, 즉 `popcount(mask)`로 결정된다. 상태에 따로 담을 필요가 없어 `dp[mask]` 하나로 충분하고, 시간도 `O(2^n × n)`으로 준다. 반면 TSP는 "마지막에 어디 있었나"가 다음 비용을 바꾸므로 둘째 차원을 뺄 수 없다.

- **왜 `dp[1][0] = 0`으로 시작하는가**: 사이클이라 출발지를 어디로 잡아도 최소 비용은 같다. 0으로 고정하면 같은 사이클을 `n`번 세는 낭비가 사라진다. 초기 상태는 "0만 방문했고 0에 있음"이므로 마스크가 `1`, 위치가 `0`, 비용이 `0`이다.

**접근 전략**

- 절차: (1) 상태에 "집합"이 필요한가? 원소 수 n ≤ 약 20인가? 확인 → (2) `dp[mask][...]` 의미를 한 문장으로 정의 → (3) 전이(안 쓴 원소를 하나 켜는 방향)를 쓰고 → (4) mask를 오름차순으로 순회하면 부분집합이 먼저 계산되므로 forward DP가 자연스럽다.
- 할당 문제 트릭: 사람 i를 순서대로 배정하면 `i = bin(mask).count("1")`(이미 배정된 사람 수)로 지금 배정할 사람을 알 수 있어 `dp[mask]` 1차원으로 충분하다.
- 시간: TSP는 O(2^n × n²), 할당형은 O(2^n × n). 공간: TSP O(2^n × n), 할당형 O(2^n). n=16이면 대략 각각 수천만 연산 — 파이썬에선 아슬아슬하니 내부 루프 최적화(불필요한 분기 제거, 지역 변수화) 필요.
- 주의점: `dp` 초기화 INF와 도달 가능성 구분. 시작점 고정(TSP에서 순환 대칭 제거)으로 계산량 절반. 파이썬에선 `dp`를 리스트-of-리스트로, INF는 `float('inf')`보다 큰 정수 상수(예: `10**18`)가 min 비교에서 더 빠를 수 있다. 마스크 순회는 반드시 오름차순. 재귀+메모(`lru_cache`)도 가능하나 `2^n` 상태면 반복 DP가 대개 빠르다.

**문제**

**1) 외판원 순회(TSP)** · Hard

- **요구사항**: n개 도시(n ≤ 16)와 이동 비용 `dist[i][j]`가 주어진다. 도시 0에서 출발해 모든 도시를 정확히 한 번씩 방문하고 0으로 돌아오는 최소 비용을 구하라.
- **입력**: 첫 줄 n, 이후 n×n 비용 행렬.
- **출력**: 최소 순회 비용.
- **예제**: `4 / 0 10 15 20 / 10 0 35 25 / 15 35 0 30 / 20 25 30 0` → `80` (0→1→3→2→0)
- **예제**: `2 / 0 5 / 5 0` → `10`
- **셀프체크**: 대각선(자기 자신)은 0이자 사용 안 함. 갈 수 없는 간선은 큰 값으로. `dp[full][u] + dist[u][0]`에서 u는 0이 아닌 도시들만. n=16이면 `2^16=65536` 마스크 × 16² — 파이썬 시간 여유 확인.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    dist = []
    idx = 1
    for i in range(n):
        row = [int(data[idx+j]) for j in range(n)]
        idx += n
        dist.append(row)
    if n == 1:
        print(0); return
    INF = float('inf')

    dp[1][0] = 0

                    dp[nm][v] = nc

(2) 코드 단계별

- 상태를 (방문 집합, 현재 위치)로 잡고 시작점을 0으로 고정해 대칭 제거.
```

**2) 작업 배정** · Medium

- **요구사항**: n명의 사람에게 n개의 작업을 1:1로 배정한다. 사람 i가 작업 j를 하면 비용 `cost[i][j]`. 총비용을 최소화하라(n ≤ 20).
- **입력**: 첫 줄 n, 이후 n×n 비용 행렬.
- **출력**: 최소 총비용.
- **예제**: `4 / 9 2 7 8 / 6 4 3 7 / 5 8 1 8 / 7 6 9 4` → `13` (0→작업1(2), 1→작업3(7)? 실제 최적 조합 합13)
- **예제**: `2 / 1 5 / 5 1` → `2`
- **셀프체크**: `dp[mask]`에서 `mask`는 "이미 배정된 작업 집합", 배정 중인 사람은 `popcount(mask)`. 사람 수 = 작업 수 전제. 1차원 DP로 공간 절약되는지, 전이에서 이미 켜진 비트 건너뛰기.

```runner
@@SOLUTION
import sys

def main():

    cost = []
    idx = 1
    for i in range(n):

        idx += n
        cost.append(row)

            continue

            nc = dp[mask] + cost[i][j]

                dp[nm] = nc

- 트릭: 사람을 순서대로 배정하면 지금 배정할 사람 번호는 `popcount(mask)`(이미 채워진 작업 수 = 이미 배정된 사람 수). 그래서 1차원 DP로 충분.

- `dp[0]=0`에서 시작. mask 오름차순 순회.
- `i = bin(mask).count("1")`가 지금 배정할 사람. i<n일 때 아직 안 쓴 작업 j마다 `dp[mask | (1<<j)]`를 `dp[mask]+cost[i][j]`로 완화.

(3) 스스로 다시 짤 때 생각 순서

- "n명 n작업 1:1 최소 비용 + n<=20" → 배정형 비트마스크 DP.
- 사람을 순서대로 처리하면 popcount로 현재 사람을 알 수 있어 상태가 "배정된 작업 집합" 1차원으로 압축된다.
- 이미 켜진 비트(배정된 작업)는 건너뛴다.
```

**3) 초대장 그룹 나누기(집합 분할 DP)** · Hard

- **요구사항**: n명(n ≤ 16)을 여러 그룹으로 나눈다. 각 그룹은 "유효한 그룹" 집합(입력으로 주어진 마스크 목록) 중 하나여야 한다. 모든 사람을 겹치지 않게 덮는 데 필요한 최소 그룹 수를 구하라(불가능 -1).
- **입력**: 첫 줄 n g(g=유효 그룹 수). 이후 g줄, 각 줄은 그 그룹에 속한 사람 번호들.
- **출력**: 최소 그룹 수(불가능 -1).
- **예제**: `4 3 / 0 1 / 2 3 / 0 1 2 3` → `1` (전체를 덮는 그룹 하나)
- **예제**: `4 2 / 0 1 / 2 3` → `2`
- **예제**: `3 1 / 0 1` → `-1` (사람 2를 못 덮음)
- **셀프체크**: `dp[mask]` = mask의 사람들을 덮는 최소 그룹 수. 전이는 "아직 안 덮인 사람 중 가장 낮은 번호를 반드시 포함하는 그룹"만 시도하면 중복/속도가 개선(부분집합 열거 O(3^n) → 가지치기). full 도달 불가면 -1. `mask & (-mask)`로 최저 비트 찾기 활용.

```runner

import sys

def main():
    data = sys.stdin.read().split('\n')
    first = data[0].split()
    n = int(first[0]); g = int(first[1])
    groups = []
    for r in range(1, g+1):
        parts = data[r].split()
        mk = 0
        for x in parts:
            mk |= (1 << int(x))
        groups.append(mk)
    full = (1 << n) - 1
    INF = float('inf')
    dp = [INF]*(1 << n)
    dp[0] = 0
    for state in range(1 << n):
        if dp[state] == INF or state == full:
            continue
        low = (~state) & (state + 1)
        for mk in groups:
            if (mk & low) and (mk & state) == 0:
                ns = state | mk
                if dp[state] + 1 < dp[ns]:
                    dp[ns] = dp[state] + 1
    print(dp[full] if dp[full] != INF else -1)

main()

(1) 접근·핵심 아이디어

- 사람 집합을 겹치지 않는 유효 그룹들로 덮는 최소 그룹 수(정확 커버, exact cover). `dp[mask]` = mask의 사람들을 덮는 최소 그룹 수.
- 가지치기: 아직 안 덮인 사람 중 가장 낮은 번호를 반드시 포함하는 그룹만 시도하면 같은 분할을 순서만 바꿔 여러 번 세는 낭비를 없앤다.

(2) 코드 단계별

- 유효 그룹들을 마스크로 변환.
- `dp[0]=0`에서 state 오름차순 순회. `low = (~state) & (state+1)`로 아직 안 덮인 최저 비트를 구한다.
- 그 low를 포함하고(mk & low), state와 겹치지 않는(mk & state == 0) 그룹 mk만 골라 `state|mk`로 전이하며 그룹 수 +1.
- 최종 `dp[full]`, 불가면 -1.

(3) 스스로 다시 짤 때 생각 순서

- "겹치지 않게 모두 덮는 최소 그룹 + n<=16" → 마스크를 상태로 쓰는 정확 커버 DP.
- 중복 계산을 막기 위해 "가장 낮은 미덮인 사람을 반드시 포함하는 그룹"만 전이한다.
- `(~state)&(state+1)`로 최저 미덮 비트를 뽑고, 그룹과 state의 교집합이 0인지 확인한다.
```

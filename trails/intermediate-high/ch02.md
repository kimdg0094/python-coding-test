> 개요: 이 챕터에서는 원소들의 소속 그룹을 거의 상수 시간에 합치고 묻는 Disjoint Set(Union-Find)을 먼저 익히고, 이를 기반으로 최소 신장 트리(MST)를 구하는 두 대표 전략 — 간선 정렬 후 하나씩 붙이는 Kruskal과 정점을 하나씩 확장하는 Prim — 을 실전 구현 관점에서 다룬다.

## L1. Disjoint Set (Union Find)

**개념**

- Disjoint Set(서로소 집합, Union-Find)은 "여러 원소가 어떤 그룹에 속하는가"를 관리하는 자료구조다. 두 가지 연산만 지원한다: `find(x)`(x가 속한 그룹의 대표원소를 반환)와 `union(a, b)`(a의 그룹과 b의 그룹을 하나로 합침). "이 둘이 같은 그룹인가?"는 `find(a) == find(b)`로 답한다.

- 왜 필요한가: "친구의 친구는 친구"처럼 연결 관계가 계속 추가될 때, 매번 BFS/DFS로 연결 여부를 다시 확인하면 질의마다 O(V+E)가 든다. Union-Find는 각 그룹을 "대표원소를 뿌리로 하는 트리"로 표현해, 합치기·묻기를 거의 상수 시간에 처리한다. MST(Kruskal), 사이클 판정, 그룹 개수 세기, 오프라인 연결성 질의에 필수다.

- 동작 원리(단계):

  - 초기화: 각 원소가 자기 자신을 부모로 갖는 크기 1짜리 트리(즉 자기 그룹의 대표)로 시작한다. `parent[i] = i`.
  - `find(x)`: 부모를 따라 뿌리(자기 자신이 부모인 노드)까지 올라가 그 뿌리를 반환한다.
  - `union(a, b)`: 두 뿌리를 찾아 한쪽 뿌리를 다른 쪽 뿌리 밑에 매단다.

- 두 가지 최적화(이게 핵심이다):

  - 경로 압축(path compression): `find` 도중 지나간 노드들의 부모를 곧바로 뿌리로 바꿔, 다음 `find`가 한 번에 뿌리에 닿게 한다. 트리를 납작하게 만든다.
  - 랭크/크기 합치기(union by rank/size): 항상 "작은(또는 낮은) 트리"를 "큰(또는 높은) 트리" 밑에 붙여 트리가 길쭉해지는 것을 막는다.

  두 최적화를 함께 쓰면 연산당 평균 비용이 사실상 상수(역아커만 함수 α)로 줄어든다.

```python
# 경로 압축 + 크기 기준 합치기 뼈대
parent = list(range(n))
size = [1] * n

def find(x):                 # 반복 버전(재귀 깊이 문제 회피)
    root = x
    while parent[root] != root:
        root = parent[root]
    while parent[x] != root:  # 경로 압축: 지나온 노드를 뿌리에 직결
        parent[x], x = root, parent[x]
    return root

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False          # 이미 같은 그룹(붙이면 사이클)
    if size[ra] < size[rb]:   # 작은 쪽을 큰 쪽 밑에
        ra, rb = rb, ra
    parent[rb] = ra
    size[ra] += size[rb]
    return True               # 실제로 합쳐짐
```

**그림으로 보기**

`union`은 두 트리의 **뿌리끼리** 붙이는 연산이다. 크기가 작은 쪽을 큰 쪽 밑으로 넣는다.

```text
  before union(3, 6)                     after
     (1)               (5)                 (1)
     / \               / \                / | \
   (2) (3)          (6)  (7)            (2)(3)(5)
                                               / \
                                            (6)  (7)

  size[1] = 4        size[5] = 3         size[1] = 7

  find(3) = 1 , find(6) = 5 ; tree 5 is smaller -> hang 5 under 1
```

경로 압축은 `find`가 지나간 노드를 **전부 뿌리 직속으로** 바꿔 트리를 납작하게 만든다.

```text
   before find(5)            after find(5)
        (1)                       (1)
         |                    /  /  |  \
        (2)                 (2)(3)(4)(5)
         |
        (3)                every node on the walked path is
         |                 relinked straight to the root
        (4)
         |                 next find(5) : 1 hop instead of 4
        (5)
```

**손으로 따라가기**

원소 0~5로 시작해 연산 6개를 처리한다. `parent`는 인덱스 0..5 순서로 적었다.

| 단계 | 연산 | parent (0..5) | size 변화 | 결과 |
| --- | --- | --- | --- | --- |
| 0 | 초기화 | `0 1 2 3 4 5` | 전부 1 | 그룹 6개 |
| 1 | `union(0,1)` | `0 0 2 3 4 5` | size[0]=2 | 1이 0 밑으로 |
| 2 | `union(2,3)` | `0 0 2 2 4 5` | size[2]=2 | 3이 2 밑으로 |
| 3 | `union(1,2)` | `0 0 0 2 4 5` | size[0]=4 | 뿌리 2가 뿌리 0 밑으로 |
| 4 | `find(3)` | `0 0 0 0 4 5` | 변화 없음 | 3→2→0으로 오르며 압축, 0 반환 |
| 5 | `union(4,5)` | `0 0 0 0 4 4` | size[4]=2 | 5가 4 밑으로 |
| 6 | `find(0)==find(5)` | 변화 없음 | 변화 없음 | 0 ≠ 4 → NO |

4단계가 핵심이다. `find(3)`은 답 하나를 얻으려고 두 칸을 걸었지만, 그 대가로 `parent[3]`이 0으로 바뀌어 다음부터는 한 칸이면 끝난다.

**왜 이렇게 되는가**

- **union by size만으로도 높이가 `log2 n` 이하인 이유.** 어떤 원소 `x`의 깊이가 1 늘어나는 순간은 `x`가 속한 트리 전체가 다른 트리 밑으로 들어갈 때뿐이다. 그런데 우리는 항상 **작은 쪽을 큰 쪽 밑에** 넣으므로 그때 `x`가 속한 집합의 크기는 최소 2배가 된다. 크기가 `n`을 넘을 수 없으니 2배가 되는 일은 최대 `log2 n`번, 따라서 깊이도 `log2 n`을 넘지 않는다.
- **경로 압축이 왜 공짜에 가까운가.** 길이 `L`짜리 경로를 한 번 걸으면 그 위 `L`개 노드가 모두 뿌리에 직결된다. 즉 "이번에 지불한 `L`의 비용"이 "다음에는 그 길을 다시 걷지 않는다"는 보증으로 바뀐다. 비싼 탐색은 스스로를 없애 버리므로 같은 비용이 반복되지 않는다.
- **거의 O(1)(역아커만)의 의미.** 두 최적화를 함께 쓰면 `m`번 연산의 총비용이 `O(m · α(n))`임이 증명되어 있다. `α`는 아커만 함수의 역함수로 **극도로 천천히** 자라서, `n`이 관측 가능한 우주의 원자 수만큼 커도 `α(n) ≤ 5`다. 그래서 실무에서는 상수로 취급한다. "정확히 O(1)"은 아니지만 코딩테스트 범위에서는 구분이 무의미하다.
- **최적화를 빼먹으면 어떻게 되는가.** union by size를 빼면 한 줄로 늘어진 트리가 생겨 `find`가 O(n)이 되고 `m`번 연산이 O(nm)까지 나빠진다. 경로 압축만 있어도 실전에서는 대체로 충분하지만, 위 보장은 둘 다 있어야 성립한다.
- **왜 뿌리끼리 붙여야 하는가.** `parent[a] = b`처럼 원소끼리 직접 연결하면 `a`가 원래 속했던 트리의 나머지 노드들이 여전히 옛 뿌리를 가리켜, 한 집합이 두 뿌리로 쪼개져 보인다. 그러면 `find` 결과가 서로 달라져 "같은 그룹인가" 판정이 즉시 깨진다.

**접근 전략**

- 핵심 아이디어: "합집합 질의가 반복되는 연결성 문제"라면 Union-Find를 의심하라. 원소를 0..n-1 정수로 정규화하고(문자열 이름이면 dict로 인덱스 매핑), 관계가 들어올 때마다 `union`, 물어볼 때 `find` 비교. 그룹 개수는 "뿌리인 원소(`find(i)==i`)의 수" 또는 union이 실제 성공한 횟수로 `n -= 1` 카운팅하면 된다.

- 전형 패턴: (1) 사이클 판정 — 무방향 그래프에서 간선 `(a,b)`를 넣을 때 이미 `find(a)==find(b)`면 그 간선이 사이클을 만든다. (2) 연결 요소 수 — 모든 간선 union 후 서로 다른 뿌리의 개수. (3) 오프라인 질의 — "합쳐라/같은가"류 질의를 순서대로 처리. (4) MST의 Kruskal에서 "이 간선을 써도 되는가(다른 컴포넌트인가)" 판정.

- 시간·공간 복잡도: 두 최적화 적용 시 연산 1회 평균 사실상 O(α(n))≈O(1), 전체 m개 연산이면 O(m·α(n)). 공간은 `parent`(그리고 `size` 또는 `rank`) O(n). 흔한 실수·주의점: (1) 경로 압축을 재귀로 짜면 원소가 많을 때 재귀 깊이 초과가 날 수 있으니 반복 버전을 쓰거나 `sys.setrecursionlimit`을 올린다. (2) `union` 전에 반드시 `find`로 "뿌리끼리" 붙여야 한다 — `parent[a]=b`처럼 원소끼리 직접 붙이면 트리가 깨진다. (3) union by size/rank를 빼먹으면 최악의 경우 한 줄로 늘어난 트리에서 `find`가 O(n)이 될 수 있다. (4) Union-Find는 "합치기"만 잘하고 "분리(삭제)"는 기본적으로 지원하지 않는다.

**문제**

**1) 같은 그룹인지 판정** · Easy

- **요구사항**: 원소 0..n-1과 연산 목록이 주어진다. 연산 `0 a b`는 a와 b를 같은 그룹으로 합치고, 연산 `1 a b`는 a와 b가 같은 그룹인지 물어 "YES"/"NO"를 출력한다. Union-Find로 처리하라(BFS 재탐색 금지).
- **입력**: 정점 수 `n`, 연산 리스트(각 `[type, a, b]`)
- **출력**: 각 `1` 질의마다 "YES" 또는 "NO"
- **예제**: `n=5, ops=[[0,0,1],[0,1,2],[1,0,2],[1,0,3],[0,3,4],[1,3,0]]` → `YES, NO, NO` / `n=3, ops=[[1,0,2],[0,0,2],[1,0,2]]` → `NO, YES`
- **셀프체크**: 첫 예제에서 0-1-2가 한 그룹이 되어 `find(0)==find(2)`이므로 YES, 아직 3은 따로라 `1 0 3`은 NO, 3-4를 합쳐도 0과는 무관해 `1 3 0`은 NO가 맞는가? `find`를 경로 압축으로 짰는가?

```runner
def main():

    idx = 0
    n = int(data[idx]); idx += 1

        if t == 0:

        else:

- 먼저 `parent`/`size` 배열과 `find`(반복+경로압축), `union`(크기 기준) 뼈대를 적는다.
- 그다음 입력 루프에서 `type`으로 분기: 0이면 합치고, 1이면 대표원소가 같은지 비교.
```

**2) 연결 요소의 개수** · Medium

- **요구사항**: 정점 `n`개와 무방향 간선 목록이 주어질 때 연결 요소(서로 도달 가능한 정점 그룹)의 수를 구하라. Union-Find로 모든 간선을 합친 뒤, 남은 그룹의 수를 세라.
- **입력**: 정점 수 `n`, 간선 리스트 `edges`(각 `[a, b]`)
- **출력**: 연결 요소의 개수(정수)
- **예제**: `n=7, edges=[[0,1],[1,2],[3,4],[5,6],[4,5]]` → `2` / `n=4, edges=[]` → `4`
- **셀프체크**: 첫 예제에서 {0,1,2}, {3,4,5,6} 두 덩어리가 되어 2가 맞는가? "union이 성공(다른 그룹을 실제로 합침)할 때마다 그룹 수를 1 줄인다"로 세면 초기값 `n`에서 시작하는가? 간선이 없으면 각 정점이 독립 그룹이라 답이 `n`인가?

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1
    parent = list(range(n))
    size = [1] * n

    def find(x):
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:
            parent[x], x = root, parent[x]
        return root

    comp = n
    for _ in range(m):
        a = int(data[idx]); b = int(data[idx + 1]); idx += 2
        ra, rb = find(a), find(b)
        if ra != rb:
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra
            size[ra] += size[rb]
            comp -= 1
    print(comp)

main()

- 매번 뿌리를 세는 대신, 초기 그룹 수를 `n`으로 두고 union이 실제로 두 그룹을 합칠 때마다 `comp`를 1 줄이는 방식이 간결하다.

(2) 코드 단계별

- `n`, 간선 수 `m`을 읽고 `parent`/`size` 초기화, `comp = n`.
- 각 간선 `(a, b)`에서 두 뿌리를 찾아 다르면 크기 기준으로 합치고 `comp -= 1`.
- 이미 같은 그룹이면 아무것도 하지 않는다(그룹 수 불변).
- 마지막에 `comp` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "모든 간선을 합친 뒤 그룹 수"라는 목표를 먼저 잡는다.
- 그룹 수 세는 두 방법(뿌리 개수 세기 vs union 성공마다 감소) 중 후자가 코드가 짧다.
- 간선이 0개면 루프를 돌지 않아 `comp`가 그대로 `n`으로 남는지 확인한다.
```

**3) 사이클을 만드는 첫 간선** · Medium

- **요구사항**: 무방향 그래프의 간선들을 주어진 순서대로 하나씩 추가한다. 어떤 간선을 추가하는 순간 처음으로 사이클이 생긴다면, 그 간선의 1-based 순번을 출력하라. 끝까지 사이클이 없으면 0을 출력한다.
- **입력**: 정점 수 `n`, 순서 있는 간선 리스트 `edges`(각 `[a, b]`)
- **출력**: 사이클을 최초로 만드는 간선의 순번(없으면 0)
- **예제**: `n=4, edges=[[0,1],[1,2],[2,0],[2,3]]` → `3` / `n=3, edges=[[0,1],[1,2]]` → `0`

## L2. Kruskal

**개념**

- 최소 신장 트리(MST, Minimum Spanning Tree)는 가중치 무방향 연결 그래프에서 "모든 정점을 잇되(신장), 사이클 없이(트리), 간선 가중치 합이 최소"가 되도록 뽑은 간선 집합이다. 정점이 V개면 MST는 항상 정확히 V-1개의 간선으로 이루어진다.

- Kruskal 알고리즘은 "간선 중심(edge-based)" 접근이다. 아이디어는 단순하다: 가장 싼 간선부터 차례로 보면서, 그 간선이 사이클을 만들지 않으면 채택하고 만들면 버린다. 채택된 간선이 V-1개가 되면 완성. 이 "탐욕적 선택"이 최적 MST를 준다는 것이 Kruskal 정리다.

- **왜 안전한가(cut property 직관)**: 정점들을 두 그룹으로 가르는 어떤 절단이든, 그 절단을 건너는 간선 중 **가장 싼 것**은 반드시 어떤 MST에 포함된다. 만약 그 싼 간선을 안 쓰고 더 비싼 간선으로 두 그룹을 이었다면, 그 비싼 간선을 싼 것으로 바꿔 끼워 총합을 줄일 수 있어 모순이기 때문이다. Kruskal은 매번 "두 컴포넌트를 처음 잇는 가장 싼 간선"을 고르므로 이 안전한 선택만 반복하는 셈이고, Prim도 "트리와 바깥을 가르는 절단의 최소 간선"을 고르므로 같은 근거로 옳다.

- 동작 원리(단계):

  - 1단계: 모든 간선을 가중치 오름차순으로 정렬한다.
  - 2단계: Union-Find를 정점 수만큼 초기화한다.
  - 3단계: 정렬 순서대로 간선 `(u, v, w)`를 본다. `find(u) != find(v)`(서로 다른 컴포넌트)면 `union` 하고 `w`를 총합에 더한다. 같은 컴포넌트면 넣는 순간 사이클이 되므로 건너뛴다.
  - 4단계: 채택 간선이 V-1개가 되면 즉시 종료(그 뒤 간선은 볼 필요 없음).

- 왜 Union-Find인가: 3단계의 "사이클이 생기는가?"를 매번 그래프 탐색으로 확인하면 느리다. Union-Find의 `find`로 "두 정점이 이미 같은 트리에 있는가"를 거의 상수 시간에 판정하는 것이 Kruskal의 핵심 도구다.

```python
# Kruskal 뼈대 (find/union은 L1의 것을 재사용)
def kruskal(n, edges):        # edges: (u, v, w) 리스트
    edges.sort(key=lambda e: e[2])   # 가중치 오름차순
    total, count = 0, 0
    for u, v, w in edges:
        if union(u, v):              # 다른 컴포넌트면 True 반환하며 합침
            total += w
            count += 1
            if count == n - 1:       # V-1개 모으면 끝
                break
    return total if count == n - 1 else -1   # 못 채우면 비연결(MST 없음)
```

```text
     (0)----1----(1)            sorted edges
       \         / \            -------------
        3       2   \             w=1 : 0-1
         \     /     6            w=2 : 1-2
          \   /       \           w=3 : 0-2

             4           \        w=6 : 1-4
```

정렬 순서대로 보면서 "사이클이면 버리고, 아니면 채택"을 반복한다.

```text
  take 0-1 (w1)      take 1-2 (w2)      skip 0-2 (w3)
    (0)--(1)           (0)--(1)           (0)--(1)
                         \  /               \  /      # 0 and 2 are
    (2) (3) (4)           (2)                (2)      # already joined
                       (3)   (4)          (3)   (4)

  take 2-3 (w4)      take 3-4 (w5)  ->  4 edges = V-1, stop
    (0)--(1)           (0)--(1)
      \  /               \  /             total = 1 + 2 + 4 + 5 = 12
       (2)                (2)
        |                  |
       (3)   (4)          (3)--(4)
```

컷 성질(cut property)은 크루스칼과 프림 양쪽의 정당성 근거다.

```text
   S = { 0, 1, 2 }               V - S = { 3, 4 }

   edges crossing the cut :    2-3  w = 4    <- minimum
                               1-4  w = 6

   swap argument : take any spanning tree using 1-4 but not 2-3.
   Adding 2-3 creates a cycle, and a cycle that leaves S must come
   back, so it also contains 1-4. Remove 1-4 : still spanning, and
   the cost dropped by 6 - 4 = 2. So skipping the cheapest crossing
   edge is never optimal.
```

**손으로 따라가기**

위 그래프에 크루스칼을 그대로 돌린 기록이다. 시작 상태는 `{0} {1} {2} {3} {4}` 다섯 그룹.

| 순서 | 간선 (w) | find 비교 | 사이클? | 채택? | 누적 가중치 | 컴포넌트 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0-1 (1) | 0 ≠ 1 | 아니오 | 채택 | 1 | {0,1} {2} {3} {4} |
| 2 | 1-2 (2) | 0 ≠ 2 | 아니오 | 채택 | 3 | {0,1,2} {3} {4} |
| 3 | 0-2 (3) | 0 = 0 | **예** | 버림 | 3 | {0,1,2} {3} {4} |
| 4 | 2-3 (4) | 0 ≠ 3 | 아니오 | 채택 | 7 | {0,1,2,3} {4} |
| 5 | 3-4 (5) | 0 ≠ 4 | 아니오 | 채택 | 12 | {0,1,2,3,4} |

채택 간선이 4개 = V-1이 된 순간 종료한다. 남은 `1-4 (6)`은 볼 필요도 없다. MST 비용은 12.

**왜 이렇게 되는가**

- **컷 성질.** 정점 집합을 임의로 `S`와 `V-S`로 가르자. 그 컷을 건너는 간선 중 가장 싼 간선 `e`는 어떤 MST에 반드시 포함된다. 근거는 위 그림의 교환 논증이다. `e`를 쓰지 않는 신장 트리 `T`가 있다면 `T`에 `e`를 넣어 생기는 사이클은 `S`를 나갔다가 반드시 돌아오므로 컷을 건너는 다른 간선 `f`를 포함한다. `f`를 빼면 여전히 신장 트리이고 비용이 `w(f) - w(e) ≥ 0`만큼 줄어든다. 따라서 `e`를 쓰는 최소 신장 트리가 항상 존재한다.
- **크루스칼이 안전한 선택만 하는 이유.** 오름차순으로 보다가 `find(u) != find(v)`여서 채택하는 순간, `u`가 속한 컴포넌트를 `S`로 두면 `(u,v)`는 그 컷을 건너는 간선이다. 그리고 그보다 싼 간선은 이미 전부 검토했는데도 아직 `S`와 바깥이 이어지지 않았으므로, `(u,v)`가 그 컷을 건너는 **가장 싼** 간선이다. 즉 매 채택이 컷 성질이 보장하는 안전한 선택이다.
- **프림의 정당성도 같은 근거다.** 프림에서 `S`는 "지금까지 만든 트리"이고, 힙에서 꺼낸 최소 간선이 정확히 그 컷을 건너는 최소 간선이다. 두 알고리즘은 어떤 컷을 쓰느냐만 다를 뿐 근거가 동일하다. 그래서 두 알고리즘의 MST 비용은 항상 같다.
- **왜 채택 간선이 정확히 V-1개인가.** 채택할 때마다 컴포넌트 수가 정확히 1씩 줄어든다(두 덩어리가 하나가 되므로). 처음이 V개, 끝이 1개이니 채택 횟수는 V-1이다. 거꾸로 끝까지 돌렸는데 V-1개를 못 채웠다면 컴포넌트가 2개 이상 남았다는 뜻이고, 그래프가 비연결이라 MST 자체가 없다.
- **복잡도 유도.** 정렬 O(E log E)에 Union-Find 연산 2E회분 O(E·α(V))가 더해진다. `E ≤ V²`이므로 `log E ≤ 2 log V`, 즉 O(E log E) = O(E log V)이고, `α` 항은 로그에 흡수되어 **정렬이 지배한다**. 공간은 간선 저장 O(E)와 `parent/size` O(V).
- **언제 크루스칼이 유리한가.** 간선 목록이 이미 주어졌고 `E`가 `V`에 가까운 희소 그래프면 정렬 한 번으로 끝나 가장 간결하다. 반대로 `E ≈ V²`인 밀집 그래프에서는 간선을 다 만들어 정렬하는 비용만 O(V² log V)라 부담이므로, L3의 O(V²) 배열 프림이 낫다.

**접근 전략**

- 핵심 아이디어: "간선 목록이 주어지고 전체를 최소 비용으로 잇는" 문제면 Kruskal을 떠올려라. 특히 간선 수 E가 그리 크지 않거나(정렬이 감당됨), 그래프가 희소(E ≈ V)할 때 Kruskal이 깔끔하다. 구현은 "정렬 + Union-Find" 두 조각의 조립이라 외우기 쉽다.

- 전형 패턴: (1) 최소 비용 네트워크/도로/케이블 연결. (2) "일부 간선은 이미 연결됨" — 그 간선들을 먼저 union 해두고 남은 것만 Kruskal(비용 0으로 미리 합친 셈). (3) 좌표로 주어진 점들 — 모든 쌍 간선을 만들어(완전그래프) MST(단, V가 크면 간선 O(V²) 폭발 주의, 이럴 땐 Prim이 유리). (4) "최대 신장 트리"는 내림차순 정렬로 같은 틀. (5) MST를 못 만들면(간선 부족) 그래프가 비연결이라는 신호.

- 시간·공간 복잡도: 정렬이 지배해 O(E log E)(= O(E log V), 정점 수로 봐도 동치). Union-Find 연산 총합은 O(E·α(V))로 사실상 선형이라 정렬에 흡수된다. 공간은 간선 저장 O(E) + Union-Find O(V). 흔한 실수·주의점: (1) MST 완성 조건은 "채택 간선 = V-1개"다 — 이 개수를 세어 비연결(-1) 여부를 판단하라. (2) 파이썬에서 간선을 `(w, u, v)`로 담아 `edges.sort()`만 해도 가중치 우선 정렬이 되니 편하다. (3) 무방향 그래프이므로 같은 쌍을 양방향으로 중복해 넣지 않도록(중복은 성능만 낭비, 정답엔 무해). (4) 큰 입력은 `input()` 대신 `sys.stdin`으로 읽어라.

```runner
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1
    edges = []
    for _ in range(m):
        a = int(data[idx]); b = int(data[idx + 1]); c = int(data[idx + 2]); idx += 3
        edges.append((c, a, b))
    edges.sort()

    parent = list(range(n))
    size = [1] * n

    def find(x):
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:
            parent[x], x = root, parent[x]
        return root

    for w, a, b in edges:
        ra, rb = find(a), find(b)
        if ra == rb:
            continue
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        total += w
        count += 1
        if count == n - 1:
            break
    print(total if count == n - 1 else -1)

- 간선을 가중치로 정렬하는 것부터 시작한다(`(w, u, v)` 튜플이 편하다).
- Union-Find `find`/`union`을 붙이고, "다른 컴포넌트일 때만 채택"으로 사이클을 피한다.
- 완성 조건은 개수(`count == n-1`)로 판정하고, 이걸로 비연결(-1)까지 함께 처리한다.
```

**2) 일부가 이미 연결된 도로망** · Medium

- **요구사항**: 도시 `n`개 중 일부 쌍은 이미 도로로 연결되어 있다(비용 0으로 취급). 추가로 건설 가능한 도로 목록 `(a, b, cost)`가 주어질 때, 모든 도시를 연결하는 데 필요한 최소 추가 비용을 구하라.
- **입력**: 도시 수 `n`, 이미 연결된 쌍 리스트 `fixed`(각 `[a, b]`), 건설 후보 리스트 `edges`(각 `[a, b, cost]`)
- **출력**: 최소 추가 건설 비용(연결 불가 시 -1)
- **예제**: `n=5, fixed=[[0,1],[1,2]], edges=[[2,3,4],[3,4,2],[0,4,10],[1,3,7]]` → `6` / `n=4, fixed=[[0,1]], edges=[[2,3,5]]` → `-1`
- **셀프체크**: 이미 연결된 쌍을 먼저 union 해 {0,1,2}를 한 덩어리로 만든 뒤 Kruskal을 돌렸는가? 첫 예제에서 남은 도시 3, 4를 붙이려면 2-3(4)과 3-4(2)를 골라 4+2=6이 최소인가?(0-4=10보다 싸다) 둘째 예제는 {0,1}과 {2,3}이 절대 이어지지 않아 -1이 맞는가?

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    f = int(data[idx]); idx += 1

    parent = list(range(n))
    size = [1] * n

    def find(x):
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:
            parent[x], x = root, parent[x]
        return root

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        return True

    comp = n
    for _ in range(f):
        a = int(data[idx]); b = int(data[idx + 1]); idx += 2
        if union(a, b):
            comp -= 1

    m = int(data[idx]); idx += 1
    edges = []
    for _ in range(m):
        a = int(data[idx]); b = int(data[idx + 1]); c = int(data[idx + 2]); idx += 3
        edges.append((c, a, b))
    edges.sort()

    total = 0
    for w, a, b in edges:
        if comp == 1:
            break
        if union(a, b):
            total += w
            comp -= 1
    print(total if comp == 1 else -1)

- 그 상태에서 건설 후보 간선들로 Kruskal을 돌리면, 남은 컴포넌트를 잇는 최소 추가 비용이 나온다.

- 후보 간선 수 `m`을 읽어 `(cost, a, b)`로 정렬.
- 정렬 순서대로 union: 새로 합쳐지면 비용 누적. 이미 연결된 쌍은 사이클이라 건너뜀.

(3) 스스로 다시 짤 때 생각 순서

- 고정 간선을 union 한 뒤 남은 컴포넌트 수를 추적할 카운터(`comp`)를 둔다.
- 이후는 표준 Kruskal과 동일하며, 완성 판정을 `comp == 1`로 하면 비연결(-1)까지 잡힌다.
```

**3) 행성 터널 연결(좌표 기반)** · Hard

- **요구사항**: 좌표평면(또는 공간) 위 `n`개 점이 있다. 두 점 사이 연결 비용은 x, y(3D면 x, y, z) 좌표 차의 절댓값 중 **최솟값** `min(|x1-x2|, |y1-y2|, ...)`이다. 모든 점을 잇는 최소 총비용(MST 비용)을 구하라.
- **입력**: 점 수 `n`, 각 점의 좌표 리스트 `pts`(각 `[x, y]`)
- **출력**: 최소 총비용
- **예제**: `pts=[[0,0],[0,3],[4,0],[4,3]]` → `0` / `pts=[[1,1],[3,5],[6,2]]` → `3`
- **셀프체크**: 모든 쌍을 간선으로 만들면 O(n²)라 n이 크면 터진다는 걸 인지하고, 대신 "x로 정렬해 인접한 것끼리, y로 정렬해 인접한 것끼리만 간선을 만든다"는 좌표별 정렬 기법을 떠올렸는가?(각 축에서 MST에 필요한 간선은 인접 점 사이에만 존재) 첫 예제는 (0,0)-(4,0)에서 y차 0, (0,0)-(0,3)에서 x차 0 등으로 비용 0 간선만으로 다 이어져 총합 0이 맞는가? 둘째 예제는 min 비용 간선들로 2가 나오는지 손으로 확인했는가?

```runner
import sys

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    d = int(data[idx]); idx += 1
    pts = []
    for _ in range(n):
        coord = [int(data[idx + k]) for k in range(d)]
        idx += d
        pts.append(coord)

    edges = []
    for axis in range(d):
        order = sorted(range(n), key=lambda i: pts[i][axis])
        for i in range(1, n):
            u = order[i - 1]; v = order[i]
            w = abs(pts[u][axis] - pts[v][axis])
            edges.append((w, u, v))
    edges.sort()

    parent = list(range(n))
    size = [1] * n

    def find(x):
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:
            parent[x], x = root, parent[x]
        return root

    total, count = 0, 0
    for w, u, v in edges:
        ru, rv = find(u), find(v)
        if ru == rv:
            continue
        if size[ru] < size[rv]:
            ru, rv = rv, ru
        parent[rv] = ru
        size[ru] += size[rv]
        total += w
        count += 1
        if count == n - 1:
            break
    print(total)

- 핵심 관찰: 어떤 축에서 MST에 쓰일 수 있는 간선은 "그 축으로 정렬했을 때 인접한 두 점" 사이에만 존재한다. 따라서 각 축마다 정렬해 인접 쌍만 간선으로 만들면 O(n·d)개 간선으로 충분하고, 여기에 Kruskal을 돌린다.
- 둘째 예제 검산: 세 쌍의 비용이 (0,1)=2, (0,2)=1, (1,2)=3이므로 작은 둘을 골라 1+2=3이 MST 비용이다.

(2) 코드 단계별

- 점 수 `n`, 차원 `d`, 각 점 좌표를 읽는다.
- 각 축 `axis`에 대해 그 좌표로 정렬한 인덱스 순서를 만들고, 인접한 두 점 사이 간선 `(|차이|, u, v)`를 후보에 추가.
- 후보 간선을 정렬한 뒤 Union-Find로 Kruskal 수행, 채택 간선이 n-1개면 종료.
- MST 총비용 출력.

(3) 스스로 다시 짤 때 생각 순서

- "완전그래프 MST인데 O(n²) 간선은 부담" → 축별 정렬로 간선 수를 O(n·d)로 줄이는 아이디어를 떠올린다.
- 왜 인접 쌍만으로 충분한가: 정렬 순서에서 떨어진 두 점을 잇는 비용은 그 사이 인접 간선들의 비용 이상이므로 MST에 굳이 필요 없다.
- 간선 후보를 만든 뒤엔 표준 Kruskal(정렬 + Union-Find)로 마무리한다.
```

## L3. Prim

**개념**

- Prim 알고리즘도 MST를 구하지만 "정점 중심(vertex-based)" 접근이다. Kruskal이 간선을 전역 정렬해 아무 데서나 붙여 나간다면, Prim은 한 정점에서 시작해 "지금까지 만든 트리에 붙일 수 있는 가장 싼 간선"으로 트리를 한 정점씩 키워 나간다. Dijkstra와 뼈대가 거의 같아, Dijkstra를 안다면 자연스럽게 이해된다.

- 동작 원리(단계):

  - 1단계: 아무 시작 정점 하나를 트리에 넣는다. 그 정점에서 나가는 모든 간선을 우선순위 큐(최소 힙)에 `(가중치, 도착정점)`으로 넣는다.
  - 2단계: 힙에서 가장 싼 간선을 꺼낸다. 그 도착 정점이 이미 트리에 있으면 버리고(이미 방문), 아니면 트리에 추가하고 그 가중치를 총합에 더한다.
  - 3단계: 새로 추가된 정점에서 나가는 간선들을 힙에 넣는다.
  - 4단계: 트리에 정점이 V개가 될 때까지 반복.

- Dijkstra와의 차이(중요): Dijkstra는 "시작점으로부터의 누적 거리"를 최소화하지만, Prim은 "트리에 붙이는 단 하나의 간선 가중치"만 본다. 즉 힙에 넣는 키가 Dijkstra는 `dist[cur] + w`, Prim은 그냥 `w`다. 이 한 줄 차이가 최단경로 트리와 최소 신장 트리를 가른다.

```python
import heapq

def prim(n, adj, start=0):        # adj[u] = [(v, w), ...]
    visited = [False] * n
    heap = [(0, start)]           # (간선 가중치, 정점)
    total, cnt = 0, 0
    while heap and cnt < n:
        w, u = heapq.heappop(heap)
        if visited[u]:            # 이미 트리에 있으면 무시(지연 삭제)
            continue
        visited[u] = True
        total += w
        cnt += 1
        for v, wv in adj[u]:
            if not visited[v]:
                heapq.heappush(heap, (wv, v))
    return total if cnt == n else -1   # 다 못 넣으면 비연결
```

**그림으로 보기**

L2와 같은 그래프에서 정점 0부터 트리를 키워 보자.

```text
   graph                          adjacency list
     (0)----1----(1)              0 : (1,w1) (2,w3)
       \         / \              1 : (0,w1) (2,w2) (4,w6)
        3       2   \             2 : (1,w2) (0,w3) (3,w4)
         \     /     6            3 : (2,w4) (4,w5)
          \   /       \           4 : (3,w5) (1,w6)
           (2)         \
            \           \
             4           \
              \           \
              (3)----5----(4)
```

`[ ]`는 트리 안, `( )`는 아직 밖에 있는 정점이다. 트리는 언제나 **한 덩어리**로 한 정점씩 자란다.

```text
   Prim from 0

   t=1   [0]  (1) (2) (3) (4)            total  0
   t=2   [0]=[1]  (2) (3) (4)            total  1     edge 0-1  w1
   t=3   [0]=[1]=[2]  (3) (4)            total  3     edge 1-2  w2
   t=4   [0]=[1]=[2]=[3]  (4)            total  7     edge 2-3  w4
   t=5   [0]=[1]=[2]=[3]=[4]             total 12     edge 3-4  w5
```

크루스칼과 나란히 놓으면 차이가 분명해진다.

```text
   Kruskal : many islands appear first, then merge

     after w=1   {0,1}  {2}  {3}  {4}
     after w=2   {0,1,2}  {3}  {4}
     after w=4   {0,1,2,3}  {4}
     after w=5   {0,1,2,3,4}

   Prim : never more than one island - it always grows from 0.
   Same total (12) either way : both obey the cut property.
```

**손으로 따라가기**

힙 기반 프림을 정점 0에서 시작해 돌린 기록이다. 힙 원소는 `(가중치, 정점)`.

| 단계 | pop | 판정 | 트리에 편입 | 누적 | push되는 후보 |
| --- | --- | --- | --- | --- | --- |
| 1 | (0, 0) | 새 정점 | 0 | 0 | (1,1) (3,2) |
| 2 | (1, 1) | 새 정점 | 1 | 1 | (2,2) (6,4) |
| 3 | (2, 2) | 새 정점 | 2 | 3 | (4,3) |
| 4 | (3, 2) | 이미 방문 | 건너뜀 | 3 | 없음 |
| 5 | (4, 3) | 새 정점 | 3 | 7 | (5,4) |
| 6 | (5, 4) | 새 정점 | 4 | 12 | 없음 |

정점 5개를 모두 넣어 `cnt == n`으로 종료. 총합 12는 L2에서 크루스칼로 구한 값과 정확히 같다. 4단계의 "이미 방문했으면 건너뛰기"(지연 삭제)가 빠지면 정점 2가 한 번 더 더해져 답이 15로 틀어진다.

**왜 이렇게 되는가**

- **프림의 정당성.** 매 단계에서 `S`를 "지금까지 트리에 넣은 정점 집합"이라 하면, 힙에서 꺼낸 간선은 `S`와 `V-S`를 잇는 간선 중 최소 가중치다. L2의 컷 성질에 따라 그 간선은 어떤 MST에 반드시 포함되므로, 프림은 안전한 선택만 V-1번 반복하는 셈이다.
- **왜 힙 키가 `w`인가.** Dijkstra는 "시작점에서의 총 거리"를 재므로 키가 `dist[u] + w`다. 프림은 "지금 트리에 붙이는 간선 하나"만 재므로 키가 `w`다. 최소화 대상이 다르다 — Dijkstra는 각 정점까지의 경로 합을, 프림은 뽑은 간선들의 총합을 줄인다. 키를 `dist+w`로 잘못 쓰면 최단경로 트리가 나와 총합이 커진다.
- **지연 삭제가 왜 정당한가.** 힙에는 같은 정점이 여러 후보 가중치로 중복해 들어간다. 그런데 그 정점이 **처음** 꺼내지는 순간의 값이 그중 최소이므로, 뒤에 나오는 중복은 항상 더 비싸다. 그래서 그냥 버려도 답이 변하지 않는다. 대신 `visited` 검사를 반드시 **꺼낸 직후에** 해야 한다 — push할 때만 걸러서는 그사이 방문된 정점을 못 막는다.
- **복잡도 세기(힙 버전).** 각 간선이 최대 한 번씩 push되므로 힙 크기는 O(E)이고, push/pop이 각각 O(log E) = O(log V)다. 따라서 O(E log V).
- **복잡도 세기(배열 버전).** V번 반복하며 매번 "아직 안 쓴 정점 중 `key`가 최소인 것"을 선형 탐색(O(V))하고, 뽑은 정점의 이웃 `key`를 갱신한다(O(V)). 합쳐 O(V²)이며 힙이 필요 없다.
- **어느 쪽이 유리한가.** `E log V`와 `V²`를 비교하면 된다. 희소 그래프(`E ≈ V`)면 `V log V < V²`이라 힙 프림이나 크루스칼이 이기고, 밀집 그래프(`E ≈ V²`)면 `V² log V > V²`이라 배열 프림이 이긴다. 좌표로 주어진 완전그래프처럼 간선을 나열하는 것 자체가 O(V²)인 경우, 거기에 정렬까지 붙는 크루스칼보다 배열 프림이 유리하다.
- **시작 정점이 답을 바꾸지 않는 이유.** 어디서 시작하든 매 단계의 선택은 "그 시점의 컷을 건너는 최소 간선"이고, 컷 성질은 시작점과 무관하게 성립한다. 그래서 뽑히는 간선 집합이 달라질 수는 있어도(동점 간선이 있을 때) 총합은 항상 같다.

**접근 전략**

- 핵심 아이디어: "인접 리스트로 그래프가 주어지고, 정점 수 대비 간선이 많은(밀집) 그래프"거나 "간선을 미리 다 나열하기 어렵고 정점에서 뻗어가는 게 자연스러운" 문제면 Prim이 유리하다. 힙 기반 Prim은 Dijkstra 코드에서 거리 갱신 부분만 "간선 가중치 그대로"로 바꾸면 되니, Dijkstra를 재활용한다고 생각하면 빠르다.

- Kruskal vs Prim 선택 기준: 간선을 정렬만 하면 되는 희소 그래프(E ≈ V)나 "간선 리스트가 이미 주어진" 형태면 Kruskal이 간결하다. 반대로 밀집 그래프(E ≈ V²)에서는 힙 Prim의 O(E log V)가, 혹은 인접행렬 + 배열 Prim의 O(V²)가 유리할 수 있다(V²이 E log V보다 작을 때). 좌표 완전그래프처럼 E가 O(V²)로 폭발하는데 V²이 감당되면 배열 기반 Prim이 정렬 없이 깔끔하다.

- 시간·공간 복잡도: 힙(우선순위 큐) 기반 Prim은 O(E log V). 인접행렬 + "매번 최소 키 정점 선형 탐색" 방식은 O(V²)로, 밀집 그래프에서 오히려 이득. 공간은 인접 리스트 O(V+E) + 힙 O(E) 또는 인접행렬 O(V²). 흔한 실수·주의점: (1) 힙에서 꺼낸 정점이 이미 방문됐으면 반드시 건너뛰어라(지연 삭제) — 안 그러면 같은 정점을 여러 번 트리에 더해 답이 틀린다. (2) 무방향 그래프이므로 인접 리스트에 간선을 **양방향**으로 넣어야 한다(`adj[u].append((v,w))`와 `adj[v].append((u,w))` 둘 다). (3) 시작 간선 가중치는 0으로 넣어야 총합이 맞는다(시작 정점 진입 비용 없음). (4) 정점을 V개 다 못 넣고 힙이 비면 비연결. (5) `heapq`는 최소 힙이므로 최대 신장 트리를 원하면 가중치 부호를 뒤집는다.

**문제**

**1) 인접 리스트로 MST 비용** · Easy

- **요구사항**: 무방향 가중 그래프가 간선 목록으로 주어진다. Prim 알고리즘(우선순위 큐 기반)으로 MST의 총 가중치를 구하라. 그래프가 비연결이면 -1을 출력한다.
- **입력**: 정점 수 `n`, 간선 리스트 `edges`(각 `[a, b, w]`, 0-based)
- **출력**: MST 총 가중치(또는 -1)
- **예제**: `n=4, edges=[[0,1,10],[0,2,6],[0,3,5],[1,3,15],[2,3,4]]` → `19` / `n=3, edges=[[0,1,7]]` → `-1`
- **셀프체크**: 인접 리스트를 양방향으로 채웠는가? 첫 예제에서 2-3(4), 0-3(5), 0-1(10)을 골라 4+5+10=19, 정점 4개를 모두 트리에 넣었는가? 힙에서 이미 방문한 정점을 꺼냈을 때 건너뛰는 처리를 했는가? 둘째 예제는 정점 2만 고립되어 -1인가?

```runner
@@SOLUTION
import sys
import heapq

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1
    adj = [[] for _ in range(n)]
    for _ in range(m):
        a = int(data[idx]); b = int(data[idx + 1]); w = int(data[idx + 2]); idx += 3
        adj[a].append((b, w))
        adj[b].append((a, w))

    visited = [False] * n
    heap = [(0, 0)]
    total, cnt = 0, 0
    while heap and cnt < n:
        w, u = heapq.heappop(heap)
        if visited[u]:
            continue
        visited[u] = True
        total += w
        cnt += 1
        for v, wv in adj[u]:
            if not visited[v]:
                heapq.heappush(heap, (wv, v))
    print(total if cnt == n else -1)

main()

@@EXPL
(1) 접근·핵심 아이디어

- Prim은 한 정점에서 시작해 "지금 트리에 붙일 수 있는 가장 싼 간선"으로 트리를 한 정점씩 키운다. 힙에 넣는 키는 누적 거리가 아니라 간선 가중치 `w` 그 자체다(이 점이 Dijkstra와의 결정적 차이).
- 힙에서 꺼낸 정점이 이미 방문됐으면 건너뛰는 "지연 삭제"가 핵심이다.

(2) 코드 단계별

- 간선을 인접 리스트에 양방향으로 채운다(`adj[a]`에 `(b,w)`, `adj[b]`에 `(a,w)`).
- `heap`에 시작 간선 `(0, 0)`을 넣고 시작(진입 비용 0).
- 힙에서 최소 가중치 간선을 꺼내 방문 안 한 정점이면 트리에 추가(`total += w`, `cnt += 1`)하고, 그 정점의 인접 간선들을 힙에 push.
- 정점을 n개 다 넣으면 `total`, 힙이 먼저 비면 비연결(-1).

(3) 스스로 다시 짤 때 생각 순서

- Dijkstra 뼈대를 떠올리되, 힙 키를 `dist+w`가 아니라 `w`로 바꾼다.
- 무방향이므로 인접 리스트를 반드시 양방향으로 채운다.
- 꺼낸 정점의 방문 여부를 먼저 확인해 중복 추가를 막고, `cnt == n`으로 완성/비연결을 판정한다.
```

**2) 밀집 그래프에서의 선택** · Medium

- **요구사항**: 인접행렬 `g`(g[i][j] = i와 j 사이 간선 가중치, 없으면 큰 값 또는 0)로 주어진 밀집 그래프의 MST 비용을 구하라. 정점이 많고 간선이 촘촘하므로, 힙 대신 O(V²) 배열 기반 Prim으로 구현하는 것이 왜 유리한지 근거와 함께 답하라(코드 전체가 아니라 아이디어·복잡도 설명 중심).
- **입력**: 정점 수 `n`, 인접행렬 `g`(대칭, `g[i][j]`가 0이면 간선 없음으로 간주)
- **출력**: MST 총 비용과, O(V²) 방식이 유리한 이유 한 줄
- **예제**: `n=3, g=[[0,1,3],[1,0,2],[3,2,0]]` → `3` / `n=4, g=[[0,4,0,0],[4,0,2,0],[0,2,0,3],[0,0,3,0]]` → `9`
- **셀프체크**: 배열 기반 Prim에서 "각 정점마다 트리까지의 최소 간선 값 `key[]`를 유지하고, 매 단계 아직 안 넣은 정점 중 `key`가 최소인 것을 선형 탐색으로 고른다"는 절차를 떠올렸는가? 첫 예제는 1(0-1)+2(1-2)=3인가? 둘째 예제는 0-1(4)+1-2(2)+2-3(3)=9인가? E가 O(V²)라 `E log V`가 `V²`보다 커질 수 있어 O(V²) 방식이 낫다는 논리를 제시했는가?

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    g = []
    for i in range(n):
        row = [int(data[idx + j]) for j in range(n)]
        idx += n
        g.append(row)

    INF = float('inf')
    key = [INF] * n
    used = [False] * n
    key[0] = 0
    total = 0
    for _ in range(n):
        u = -1
        best = INF
        for v in range(n):
            if not used[v] and key[v] < best:
                best = key[v]; u = v
        if u == -1 or key[u] == INF:
            print(-1)
            return
        used[u] = True
        total += key[u]
        for v in range(n):
            if not used[v] and g[u][v] != 0 and g[u][v] < key[v]:
                key[v] = g[u][v]
    print(total)

main()

@@EXPL
(1) 접근·핵심 아이디어

- 밀집 그래프(간선이 O(V²))에서는 힙 Prim의 O(E log V)가 오히려 커진다. 이럴 땐 배열 기반 Prim의 O(V²)가 유리하다: `E log V ≈ V² log V > V²`.
- `key[v]` = 정점 v를 현재 트리에 붙이는 최소 간선 가중치. 매 단계 아직 안 넣은 정점 중 `key`가 최소인 것을 선형 탐색으로 고른다(힙 불필요).

(2) 코드 단계별

- 인접행렬 `g`를 읽는다(`g[i][j]==0`이면 간선 없음).
- `key[0]=0`으로 시작, n번 반복.
- 매 반복: 아직 안 쓴 정점 중 `key`가 최소인 `u`를 선형 탐색으로 선택. 없거나 INF면 비연결(-1).
- `u`를 트리에 넣고(`total += key[u]`), `u`의 인접 정점들의 `key`를 `g[u][v]`로 갱신(더 작으면).
- 반복 종료 후 `total` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "간선이 촘촘하면 힙보다 배열이 낫다"는 복잡도 감각(`V² < E log V`)을 먼저 세운다.
- `key`/`used` 배열을 두고 "최소 key 정점 선택 → 트리 편입 → 이웃 key 갱신"의 세 단계를 n번 반복하는 틀을 적는다.
- `g[u][v]==0`을 "간선 없음"으로 처리하고, 최소 정점이 INF면 비연결(-1)로 판정한다.
```

**3) 발전소 하나에서 시작하는 전력망** · Medium

- **요구사항**: `n`개 마을에 전력을 공급한다. 이미 발전소가 있는 마을 하나(예: 0번)에서 시작해, 모든 마을에 전력이 닿도록 송전선을 깔되 총 길이를 최소화하려 한다. 송전선 후보 `(a, b, len)`이 주어질 때 최소 총 길이를 구하라(연결 불가 시 -1). Prim으로 "발전소에서부터 트리를 키워가는" 관점으로 풀어라.
- **입력**: 마을 수 `n`, 시작 마을 `start`, 간선 리스트 `edges`(각 `[a, b, len]`)
- **출력**: 최소 총 송전선 길이(또는 -1)
- **예제**: `n=5, start=0, edges=[[0,1,2],[0,3,6],[1,2,3],[1,3,8],[1,4,5],[2,4,7],[3,4,9]]` → `16` / `n=2, start=0, edges=[]` → `-1`
- **셀프체크**: 시작 정점을 `start`로 두어도 MST 총 비용은 시작점과 무관하게 같다는 사실을 이해했는가?(Prim은 어디서 시작해도 같은 MST 비용) 첫 예제에서 0-1(2), 1-2(3), 1-4(5), 0-3(6)을 골라 2+3+5+6=16이 되고 정점 5개가 모두 연결되는가? 둘째 예제는 간선이 없어 마을 1을 못 이어 -1인가? 힙에 시작 간선을 `(0, start)`로 넣어 시작했는가?

```runner
(1) 접근·핵심 아이디어

- 발전소가 있는 마을 `start`에서 트리를 키워가는 Prim이 자연스럽다. 다만 MST 총비용은 시작점과 무관하게 항상 같으므로, 시작점을 `start`로 바꾸는 것은 관점의 문제일 뿐 결과 비용은 동일하다.
- 힙 키는 간선 길이 `w` 그 자체(누적이 아님).

(2) 코드 단계별

- `n`, 시작 마을 `start`, 간선 수 `m`을 읽고 인접 리스트를 양방향으로 채운다.
- `heap`에 `(0, start)`를 넣고 시작(발전소 진입 비용 0).
- 힙에서 최소 길이 간선을 꺼내 방문 안 한 정점이면 편입(`total += w`, `cnt += 1`)하고 인접 간선 push.
- 정점을 모두 넣으면 `total`, 힙이 먼저 비면 -1.

(3) 스스로 다시 짤 때 생각 순서

- L3-1의 Prim과 동일한 뼈대에서 시작 정점만 `start`로 바꾸면 됨을 인식한다.
- 힙 초기값을 `(0, start)`로 넣는 것이 "발전소에서 출발"의 구현.
- 무방향 양방향 채우기, 지연 삭제(방문 확인), `cnt == n` 완성 판정을 그대로 적용한다.
```

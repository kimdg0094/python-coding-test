## L7. if else if else 조건문

**개념**

- 여러 갈래로 나뉘는 상황을 "만약 A라면 …, 아니고 B라면 …, 그것도 아니면 …" 처럼 순서대로 검사하는 구조다.

- 파이썬에서는 `if` → `elif` → `else` 를 이어서 쓴다. `elif` 는 "else if"를 줄인 말이다.

- 위에서부터 조건을 하나씩 검사하다가, 처음으로 참이 되는 가지 하나만 실행하고 나머지는 건너뛴다.

- 어느 조건도 참이 아니면 마지막 `else` 가 실행된다. `else` 는 생략할 수도 있다.

- 조건이 겹칠 수 있을 때, 순서가 결과를 바꾼다. 좁은 조건(더 까다로운 조건)을 위에 두는 게 안전하다.

```python
score = 85
if score >= 90:
    print("A")
elif score >= 80:   # 90 미만이면서 80 이상
    print("B")
elif score >= 70:
    print("C")
else:
    print("F")
# 출력: B
```

- 위 예시에서 `score = 85` 는 `score >= 90` 이 거짓이라 다음으로 넘어가고, `score >= 80` 이 참이라 "B"만 출력한다. 아래 `elif` 와 `else` 는 실행되지 않는다.

**그림으로 보기**

```text
   0 ─────────── 70 ────────── 80 ────────── 90 ────────── 100
   |     "F"      |    "C"      |    "B"      |     "A"     |
                  ^             ^             ^
                  |             |             └ >= 90  -> A
                  |             └─────────────── >= 80  -> B
                  └───────────────────────────── >= 70  -> C
```

경계값은 `>=`를 쓴 갈래에 **포함**된다. 그래서 70은 `C`, 80은 `B`, 90은 `A`다.

**왜 이렇게 되는가**

- `score >= 70`은 90점에도 참이다. 조건만 놓고 보면 A·B·C 세 줄이 모두 90점을 받아 줄 수 있다.

- `elif` 사슬은 그중 **가장 위에 있는 것**을 고른다. 따라서 "누가 위에 있는가"가 곧 "누가 이기는가"다.

- 큰 기준(90)을 위에 두면 90점은 A에서 잡히고, C 줄까지 내려올 수 있는 값은 자연히 90 미만·80 미만인 것들만 남는다. 그래서 각 줄은 하한 하나만 적으면 된다.

- 요령: **겹치는 조건은 좁은 것부터.** `>=` 사슬이면 큰 값부터, `<` 사슬이면 작은 값부터 쓴다.

## L8. 비교 연산자와 조건문

**개념**

- 조건문의 조건은 보통 두 값을 "비교"해서 참/거짓을 만든다. 이때 쓰는 기호가 비교 연산자다.

- 비교 연산자는 6가지다.

- `==` : 같다 (등호 두 개. 값을 넣는 `=` 와 다르다!)
- `!=` : 같지 않다
- `>` : 크다
- `<` : 작다
- `>=` : 크거나 같다 (이상)
- `<=` : 작거나 같다 (이하)

- 비교의 결과는 참(`True`) 또는 거짓(`False`) 이며, `if` 는 결과가 참일 때만 안쪽을 실행한다.

- 가장 흔한 실수: 같은지 비교하려는데 `=` 하나만 쓰는 것. 비교는 반드시 `==` 다.

```python
a = 7
if a % 2 == 0:
    print("짝수")
else:
    print("홀수")
# a % 2 는 7을 2로 나눈 나머지 = 1, 1 == 0 은 거짓 → "홀수"
```

- `%` 는 나머지 연산자다(Ch3 사칙연산에서 배움). 어떤 수를 2로 나눈 나머지가 0이면 짝수, 아니면 홀수다.

**그림으로 보기**

```text
   x        :  58  59  60  61  62
   x >= 60  :   F   F   T   T   T
   x >  60  :   F   F   F   T   T
                        ^
                        the only column where they differ
```

`=`가 붙으면 경계값 자신이 참 쪽으로 들어온다. 지문의 "이상·이하"는 경계 포함(`>=`, `<=`), "초과·미만"은 경계 제외(`>`, `<`)다.

**왜 이렇게 되는가**

- 비교 연산자는 두 값을 받아 `True` 또는 `False` 하나를 만들어 낸다. `if`는 그 결과만 본다. 즉 `if a > b:` 는 `if (비교의 결과):` 와 같다.

- `=`는 비교가 아니라 **값을 넣는** 기호다. `if a = 1:` 처럼 쓰면 "넣기"를 조건 자리에 놓은 셈이라 파이썬이 문법 오류로 거절한다. 비교는 언제나 `==`.

- 경계 실수를 잡는 가장 싼 방법: 기준값 그 자체와 기준값 ±1, 이렇게 세 개를 대입해 본다. 60점 문제라면 59·60·61.

**문제**

**1) 두 수 비교** · Easy

- **요구사항**: 정수 두 개를 입력받아 대소 관계를 출력하세요.
- **입력**: 한 줄에 정수 두 개 `a b` (공백으로 구분)
- **출력**: `a` 가 크면 `>`, `b` 가 크면 `<`, 둘이 같으면 `=` 를 출력한다.
- **예제**: `3 5` → `<` / `8 8` → `=` / `10 2` → `>`
- **셀프체크**: 세 경우(크다/작다/같다)를 모두 다뤘는가? 같은지 비교할 때 `==` 를 썼는가(`=` 아님)? 값 입력은 `a, b = input().split()` 로 나눈 뒤 `a = int(a); b = int(b)` 로 하나씩 정수로 바꿔 받는다.

```runner
@@SOLUTION
a, b = input().split()
a = int(a)
b = int(b)
if a > b:
    print(">")
elif a < b:
    print("<")
else:
    print("=")
@@TESTS
--IN
3 5
--OUT
<
--IN
8 8
--OUT
=
--IN
10 2
--OUT
>
@@EXPL
접근: 두 수의 대소 관계는 "크다 / 작다 / 같다" 세 경우로 갈리므로 `if / elif / else` 세 갈래로 나눈다. 앞의 두 경우가 모두 아니면 남는 건 "같다" 뿐이라 마지막을 else로 둔다.

코드 진행:

- 한 줄에 두 값이 오므로 `input().split()` 으로 나눈 뒤 각각 `int()` 로 정수 변환한다.
- `a > b` 면 `>`, 아니면 다음으로 넘어가 `a < b` 면 `<`.
- 두 경우 모두 아니면(즉 크지도 작지도 않으면) 같은 것이므로 `else` 에서 `=`.
- 비교는 반드시 `==`, `>`, `<` 같은 비교 연산자를 쓴다. 같음 판단을 굳이 따로 쓰지 않고 else로 처리한 점이 깔끔하다.

스스로 다시 짤 때: (1) 결과가 세 갈래(> < =)임을 먼저 떠올린다. (2) 두 값을 split 후 정수로 바꾼다. (3) 큰 경우와 작은 경우를 if/elif로 쓰고, 남는 "같다"는 else로 처리한다. (4) `8 8` 같은 같음 입력이 `=` 로 나오는지, 대소 입력이 방향에 맞게 나오는지 확인한다.
```

**2) 짝수인지 홀수인지** · Easy

- **요구사항**: 정수 하나를 입력받아 짝수면 `even`, 홀수면 `odd` 를 출력하세요.
- **입력**: 정수 하나 `n` (음수일 수도 있음)
- **출력**: `even` 또는 `odd`
- **예제**: `4` → `even` / `7` → `odd` / `0` → `even`
- **셀프체크**: 0은 짝수로 처리되는가? 판단은 `n % 2 == 0` 으로 한다. (음수도 `% 2` 결과가 파이썬에서는 0 또는 1이니 그대로 동작한다.)

```runner
@@SOLUTION
n = int(input())
if n % 2 == 0:
    print("even")
else:
    print("odd")
@@TESTS
--IN
4
--OUT
even
--IN
7
--OUT
odd
--IN
0
--OUT
even
--IN
-3
--OUT
odd
@@EXPL
접근: 짝수는 2로 나눈 나머지가 0인 수다. 그래서 `n % 2 == 0` 이면 짝수(even), 아니면 홀수(odd)로 판별한다.

코드 진행:

- `int(input())` 으로 정수 하나를 받는다.
- `n % 2` 는 n을 2로 나눈 나머지(0 또는 1)다. `== 0` 이면 짝수.
- 참이면 `even`, 아니면 `else` 로 `odd`.
- `0 % 2` 는 0이라 0은 짝수(even)로 처리된다. 파이썬에서는 음수도 `% 2` 결과가 0 또는 1이라 `-3 % 2` 는 1 → odd로 잘 나온다.

스스로 다시 짤 때: (1) "짝수 = 2로 나눈 나머지 0" 이라고 정의를 떠올린다. (2) `n % 2` 로 나머지를 구한다. (3) `== 0` 이면 even, 아니면 odd. (4) 경계 `0`이 even인지, 음수 입력도 정상 동작하는지 확인한다.
```

## L9. and 기호

**개념**

- 두 조건이 "동시에" 참이어야 할 때 `and` 로 이어 붙인다. "그리고"에 해당한다.

- `조건A and 조건B` 는 A와 B가 **둘 다 참**일 때만 참이 된다. 하나라도 거짓이면 전체가 거짓이다.

- 예: "나이가 20 이상 **그리고** 회원이다" → `age >= 20 and is_member`

- 흔한 실수: "3보다 크고 7보다 작다"를 수학처럼 `3 < x < 7` 로 쓰고 싶어지는데, 초급 단계에서는 두 조건으로 나눠 `x > 3 and x < 7` 로 쓰는 습관을 들이자.

```python
x = 5
if x > 3 and x < 7:
    print("사이에 있음")
else:
    print("범위 밖")
# x > 3 (참) 그리고 x < 7 (참) → 둘 다 참 → "사이에 있음"
```

**그림으로 보기**

```text
   A and B  ->  True only when BOTH are True
   ┌─────────┬─────────┬─────────┐
   │         │ B=True  │ B=False │
   ├─────────┼─────────┼─────────┤
   │ A=True  │  True   │  False  │
   │ A=False │  False  │  False  │
   └─────────┴─────────┴─────────┘
```

같은 이야기를 수직선 위에서 보면, `and`는 두 조건이 참인 구간이 **겹치는 부분**만 남긴다.

```text
   x     :  1   2   3   4   5   6   7   8
   x > 3 :  F   F   F   T   T   T   T   T
   x < 7 :  T   T   T   T   T   T   F   F
   and   :  F   F   F   T   T   T   F   F
                        ^   ^   ^
```

**왜 이렇게 되는가**

- `and`는 통과 구간의 교집합이다. 그래서 조건을 붙일수록 통과하는 값은 **줄어들지 결코 늘지 않는다.**

- "10 이상 20 이하"처럼 양쪽이 막힌 범위는 조건이 두 개다. 아래 경계 `n >= 10`과 위 경계 `n <= 20`을 각각 쓰고 `and`로 묶는다. 한쪽만 쓰면 반대쪽이 무한히 열린다.

- 파이썬은 `A and B`에서 `A`가 거짓이면 `B`를 아예 계산하지 않는다. 어차피 전체가 거짓이기 때문이다.

## L10. or 기호

**개념**

- 두 조건 중 "하나라도" 참이면 될 때 `or` 로 이어 붙인다. "또는"에 해당한다.

- `조건A or 조건B` 는 A, B 중 **적어도 하나가 참**이면 참이 된다. 둘 다 거짓일 때만 전체가 거짓이다.

- 예: "토요일 **또는** 일요일이면 주말" → `day == 6 or day == 7`

- `and` 와 헷갈리지 말자. `and` 는 "둘 다", `or` 는 "하나라도".

```python
day = 7
if day == 6 or day == 7:
    print("주말")
else:
    print("평일")
# day == 6 (거짓) 또는 day == 7 (참) → 하나가 참 → "주말"
```

**그림으로 보기**

```text
   A or B  ->  False only when BOTH are False
   ┌─────────┬─────────┬─────────┐
   │         │ B=True  │ B=False │
   ├─────────┼─────────┼─────────┤
   │ A=True  │  True   │  True   │
   │ A=False │  True   │  False  │
   └─────────┴─────────┴─────────┘

   day    :  1   2   3   4   5   6   7
   day==6 :  F   F   F   F   F   T   F
   day==7 :  F   F   F   F   F   F   T
   or     :  F   F   F   F   F   T   T
```

**왜 이렇게 되는가**

- `or`는 두 조건이 참인 구간을 **합친다.** 조건을 붙일수록 통과하는 값이 늘어난다.

- `day == 6 or 7`이 언제나 참이 되는 이유: 파이썬은 이 식을 `(day == 6) or (7)`로 읽는다. `7`은 0이 아닌 수라 그 자체로 "참" 취급이므로, 왼쪽이 거짓이어도 전체가 참이 된다. 비교식은 `or` 양쪽에 온전히 적어야 한다.

- `and`와 `or`는 서로 뒤집힌 관계다. "10 이상 20 이하"(`and`)의 반대는 "10 미만 **또는** 20 초과"(`or`)다. 범위 안·밖 문제는 둘 중 쓰기 편한 쪽으로 바꿔 쓸 수 있다.

## L11. and, or 혼합

**개념**

- `and` 와 `or` 를 한 조건에 함께 쓸 수 있다. 이때 우선순위는 `and` 가 `or` 보다 먼저 계산된다(곱셈이 덧셈보다 먼저인 것과 비슷).

- 즉 `A or B and C` 는 `A or (B and C)` 로 해석된다. 헷갈릴 때는 **괄호 `( )` 로 묶어** 의도를 분명히 하는 것이 가장 안전하다.

- 여러 조건을 조합할 때는 "무엇을 묶어야 하는가"를 먼저 말로 정리하면 좋다. 예: "(3의 배수) 또는 (5의 배수)".

```python
x = 15
if x % 3 == 0 or x % 5 == 0:
    print("3 또는 5의 배수")
# 15 % 3 == 0 (참) → or 이므로 전체 참
```

```python
age = 25
member = 1
if age >= 20 and (member == 1 or age >= 65):
    print("입장 가능")
# 괄호로 or 부분을 먼저 묶어 의도를 명확히 했다
```

**그림으로 보기**

```text
   priority :   not   >   and   >   or

   A or B and C      is read as      A or (B and C)
                                          ^^^^^^^^^   computed first

   want (A or B) and C ?   ->   write the parentheses yourself
```

**손으로 따라가기**

`x = 1`일 때, 어디를 먼저 묶느냐에 따라 답이 정반대가 된다.

| 식 | 먼저 계산 | 그다음 | 결과 |
| --- | --- | --- | --- |
| `x > 0 or x > 10 and x < 0` (괄호 없음) | `x > 10 and x < 0` → 거짓 | `참 or 거짓` | **참** |
| `(x > 0 or x > 10) and x < 0` | `x > 0 or x > 10` → 참 | `참 and 거짓` | **거짓** |

글자는 같은데 결과가 갈린다. 괄호가 없으면 파이썬은 항상 위쪽처럼(`and`부터) 읽는다.

**왜 이렇게 되는가**

- 우선순위는 `not` → `and` → `or` 순이다. 사칙연산에서 `2 + 3 * 4`가 `2 + (3 * 4)`인 것과 똑같은 이야기다.

- 그래서 `or`로 묶고 싶은 부분은 **반드시 직접 괄호를 쳐야 한다.** 괄호를 안 치면 파이썬이 `and`부터 묶어 버린다.

- 실전 요령: 코드로 옮기기 전에 조건을 말로 "( ) 그리고 ( )" 꼴로 먼저 적는다. 말에서 묶인 덩어리가 그대로 괄호가 된다.

## L12. 중첩 조건문

**개념**

- 조건문 안에 또 다른 조건문을 넣는 것을 "중첩(nested) 조건문"이라 한다.

- 바깥 `if` 가 참일 때만 안쪽 `if` 를 검사한다. "먼저 큰 갈래를 나누고, 그 안에서 다시 세분한다"는 흐름이다.

- 파이썬은 **들여쓰기**로 안팎을 구분한다. 안쪽 블록은 바깥보다 한 단계 더 들여 쓴다(보통 공백 4칸). 들여쓰기가 어긋나면 오류가 나거나 엉뚱하게 동작한다.

- 많은 경우 중첩 대신 `and` 로 합칠 수도 있다. 하지만 "먼저 A를 통과한 사람만 다시 B/C로 나눈다"처럼 단계가 나뉠 때는 중첩이 더 자연스럽다.

```python
score = 85
if score >= 60:        # 먼저 합격 여부
    if score >= 90:    # 합격자 중에서 다시 우수 여부
        print("합격-우수")
    else:
        print("합격")
else:
    print("불합격")
# score=85: 바깥 참(60 이상) → 안쪽에서 90 미만 → "합격"
```

**그림으로 보기**

```text
   score
     │
     ▼
  [ score >= 60 ] ── F ──► "fail"      # outer else
     │ T
     ▼
  [ score >= 90 ] ── F ──► "pass"      # inner else
     │ T
     ▼
   "pass+"
```

같은 구조를 수직선 위에 놓으면, 바깥 조건이 한 번 자르고 안쪽 조건이 그중 한쪽만 다시 자르는 모양이 된다.

```text
   0 ─────────────── 60 ──────────── 90 ──────────── 100
        "fail"            "pass"          "pass+"
   |<- outer else ->|<------ outer if body -------->|
                    |<- inner else ->|<- inner if ->|
```

바깥이 거짓인 구간에서는 안쪽 조건을 **아예 검사하지 않는다.**

**왜 이렇게 되는가**

- 중첩은 "이미 통과한 대상에게만 다시 묻는다"는 구조다. 그래서 안쪽 조건은 바깥 조건이 참이라는 사실을 깔고 갈 수 있다.

- 결과만 보면 `if A:` 안의 `if B:` 는 `if A and B:` 와 같다. 다만 **바깥이 거짓일 때 따로 할 일(`else`)이 있으면** 중첩이 필요하다. `and`로 합쳐 버리면 "A가 거짓"과 "A는 참인데 B가 거짓"을 구분할 수 없다.

- 들여쓰기가 곧 소속이다. 안쪽 `else`는 안쪽 `if`와, 바깥 `else`는 바깥 `if`와 같은 깊이에 놓인다. 깊이를 한 단계만 틀려도 짝이 바뀌어 뜻이 달라진다.

- **입력**: 정수 하나 `n`

코드 진행:

- `int(input())` 으로 정수 하나를 받는다.
- 바깥 `if n > 0` 로 양수 여부를 가른다. `0` 은 `n > 0` 이 거짓이므로 바깥 else로 빠져 `not positive`.

스스로 다시 짤 때: (1) 경계 `0`을 어디로 보낼지 먼저 정한다(양수 아님). (2) 바깥 if로 `n > 0` 을 검사하고, 그 안에 `% 2` 홀짝 if/else를 한 단계 더 들여 넣는다. (3) 양수가 아닌 경우는 바깥 else 하나로 처리한다. (4) `0`과 음수가 모두 not positive로 나오는지, 양수 4와 7이 각각 even/odd로 갈리는지 확인한다.

- **예제**: `0 1` → `please login` / `1 1` → `admin` / `1 0` → `user`
- **셀프체크**: 로그인 실패면 관리자 여부와 무관하게 `please login` 이 나오는가? (`0 1` 에서 확인) 바깥에서 로그인을 먼저 거른 뒤 안쪽에서 권한을 나눴는가?

login, is_admin = input().split()

@@TESTS

코드 진행:

- `input().split()` 으로 두 값을 나눈 뒤 각각 `int()` 로 정수 변환한다.
- 바깥 `if login == 1` 로 로그인 성공/실패를 가른다.

- 바깥 `else`(로그인 실패)는 관리자 여부를 아예 보지 않고 `please login` 만 낸다. 그래서 `0 1` 도 `please login` 이 된다.

스스로 다시 짤 때: (1) "로그인 먼저 → 그다음 권한" 순서를 정한다. (2) 바깥 if로 로그인을 거르고, 성공 블록 안에 관리자 판별 if/else를 한 단계 더 들여 넣는다. (3) 실패는 바깥 else 하나로 끝낸다. (4) `0 1` 이 admin이 아니라 please login으로 나오는지 확인해 바깥 조건이 안쪽을 막고 있는지 검증한다.

**3) 세 수 중 최댓값** · Hard

- **요구사항**: 정수 세 개를 입력받아 가장 큰 값을 출력하세요. 단, 중첩 조건문(if 안의 if)을 사용해서 해결합니다.
- **입력**: 한 줄에 정수 세 개 `a b c` (공백 구분, 서로 다르다고 가정)
- **출력**: 세 값 중 가장 큰 수 하나
- **예제**: `3 7 5` → `7` / `10 2 8` → `10` / `1 4 9` → `9`
- **셀프체크**: 먼저 `a > b` 인지로 크게 나눈 뒤, 각 갈래 안에서 남은 수와 다시 비교했는가? (예: `a > b` 가 참이면 안쪽에서 `a` 와 `c` 를 비교) 모든 예제에서 정답이 나오는지 손으로 대입해 검산했는가?

```runner
@@SOLUTION
a, b, c = input().split()
a = int(a)
b = int(b)
c = int(c)
if a > b:
    if a > c:
        print(a)
    else:
        print(c)
else:
    if b > c:
        print(b)
    else:
        print(c)
@@TESTS
--IN
3 7 5
--OUT
7
--IN
10 2 8
--OUT
10
--IN
1 4 9
--OUT
9
@@EXPL
접근: 세 수의 최댓값을 중첩 조건문으로 구한다. "먼저 두 수(a, b) 중 이긴 쪽을 고르고, 그 승자를 남은 c와 다시 겨룬다"는 토너먼트식 사고다.

코드 진행:

- `input().split()` 으로 세 조각을 나눈 뒤 `int()` 로 각각 정수로 바꾼다.
- 바깥 `if a > b` 로 크게 두 갈래를 만든다.
- `a > b` 가 참인 갈래(즉 a가 b보다 큼): 안쪽에서 `a > c` 면 a가 최종 최댓값, 아니면 c.
- `a > b` 가 거짓인 갈래(b가 a 이상): 안쪽에서 `b > c` 면 b, 아니면 c.
- 서로 다른 세 수라는 가정 덕분에 같음 처리는 신경 쓰지 않아도 된다.

스스로 다시 짤 때: (1) "두 수 먼저 비교 → 이긴 수를 세 번째와 비교" 라는 2단계 흐름을 말로 정리한다. (2) 바깥 if로 a와 b를 가르고, 각 가지 안에서 살아남은 수와 c를 비교하는 안쪽 if를 넣는다. (3) 안쪽 블록 들여쓰기를 한 단계 더 준다. (4) 세 예제를 손으로 대입해 각 경로가 맞는 값을 내는지 검산한다.
```

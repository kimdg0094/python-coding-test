## L4. 정리 — 개념 지도·체크리스트·자주 하는 실수

**개념**

Ch03의 도구는 기호 여섯 개(`+`, `-`, `*`, `/`, `//`, `%`)와 괄호가 전부입니다. 그런데 입문자가 가장 많이 틀리는 곳도 바로 여기입니다. **어떤 나눗셈을 고를지**와 **어디를 먼저 계산할지** 두 가지에서 갈리기 때문입니다. 이 둘을 지도와 표로 못 박아 둡니다.

**개념 지도**

연산자는 크게 두 갈래입니다. 하나는 "무엇을 가져올 것인가(나눗셈 세 가지)", 다른 하나는 "어느 순서로 계산할 것인가"입니다.

```text
                    numbers  ->  operators  ->  a number

                       +   -   *
                           │
             ┌─────────────┴──────────────┐
        which division?               which order?
             │                            │
     ┌───────┼───────┐            *  /  //  %   first
     /       //      %            +  -          later
     │       │       │            ( )           forces the order
   float    int     int
   2.333     2       1        # example: 7 and 3
```

`//` 와 `%` 는 늘 짝으로 움직입니다. 둘을 합치면 원래 수가 정확히 복원됩니다.

```text
  a  =  (a // b) * b  +  (a % b)          always true

  137 seconds into minutes and seconds

  137 // 60  ->  2         # how many full minutes
  137 %  60  ->  17        # seconds left over
    2 * 60 + 17  =  137    # check: nothing lost
```

합과 평균은 "먼저 모아서 하나로 만들고, 그다음 개수로 나눈다"는 한 가지 흐름입니다.

```text
  a  b  c  d                  total = a + b + c + d
  ┌─┬─┬─┬─┐
  │3│5│8│4│  --- add --->     20
  └─┴─┴─┴─┘                    │
                      ┌────────┴────────┐
                    / 4                // 4
                     5.0                5
                   float               int      # count = 4 values
```

**뼈대 코드**

이 챕터 문제는 아래 네 가지 뼈대 중 하나에 값만 갈아 끼우면 됩니다.

```python
# 1) 두 수를 받아 여러 결과를 줄마다 출력하기
a, b = input().split()
a = int(a)
b = int(b)
print(a + b)                   # ← 문제마다 바뀜
print(a - b)                   # 뺄셈은 "앞 - 뒤" 순서를 지킨다
print(a * b)
```

```python
# 2) 몫과 나머지로 단위 쪼개기 (시간·묶음·거스름돈)
n = int(input())
big = n // 60                  # ← 나누는 단위가 문제마다 바뀜
small = n % 60
print(big, small)
```

```python
# 3) 합과 평균 구하기
a, b, c = input().split()      # ← 값 개수만큼 변수를 늘린다
a = int(a)
b = int(b)
c = int(c)
total = a + b + c              # 합을 먼저 변수에 담는다
avg = total / 3                # ← 나누는 수는 "값의 개수"
print(total)
print(avg)
```

```python
# 4) 공식을 그대로 옮기고 자릿수를 맞춰 출력하기
x = float(input())
result = (x * 9 / 5) + 32      # ← 공식이 문제마다 바뀜. 괄호로 순서를 확인
print(f'{result:.2f}')         # ← 자릿수도 문제마다 바뀜
```

**언제 무엇을 쓰나**

| 상황 | 고르는 것 | 이유 | 복잡도 |
|------|-----------|------|--------|
| 소수까지 정확한 나눗셈 | `/` | 결과가 언제나 실수라 소수가 보존된다 | O(1) |
| 정수 결과만 필요하다 | `//` | 소수점 아래를 버린(내린) 몫을 준다 | O(1) |
| 남는 양이 궁금하다 | `%` | 나누고 남은 값을 준다 | O(1) |
| 단위를 쪼갠다(초→분·초) | `// 단위` 와 `% 단위` | 큰 단위는 몫, 남는 것은 나머지 | O(1) |
| 짝수·배수 여부를 본다 | `n % 2`, `n % k` | 나머지가 `0` 이면 나누어떨어진다 | O(1) |
| 자릿수를 뽑는다 | `// 10`, `% 10` | 10묶음의 개수와 남는 낱개 | O(1) |
| 소수 평균이 필요하다 | `(합) / 개수` | `/` 라서 `.0` 이 붙는 실수로 나온다 | O(1) |
| 정수 평균이 필요하다 | `(합) // 개수` | 소수점 아래를 버려 정수로 나온다 | O(1) |
| 합 전체를 나눠야 한다 | `total` 에 담고 `total / n` | 괄호를 빠뜨릴 자리가 아예 없어진다 | O(1) |
| 계산 순서를 바꿔야 한다 | `( )` 로 묶기 | 곱셈·나눗셈이 먼저라는 기본 순서를 덮어쓴다 | O(1) |
| 출력 자릿수가 정해져 있다 | `f'{x:.2f}'` | 반올림하고 모자란 자리는 `0` 으로 채운다 | O(1) |
| 음수가 섞인 나눗셈 | `//` 인지 `int(/)` 인지 먼저 결정 | `-7 // 2` 는 `-4`, `int(-7 / 2)` 는 `-3` | O(1) |

**✅ 마스터 체크리스트**

- [ ] 설명할 수 있다: `/` 의 결과가 왜 언제나 실수인가.
- [ ] 설명할 수 있다: `7 / 2`, `7 // 2`, `7 % 2` 의 결과와 자료형이 각각 무엇인가.
- [ ] 설명할 수 있다: `//` 가 "버림"이 아니라 "내림"이라는 말의 뜻은 무엇인가.
- [ ] 설명할 수 있다: `-7 // 2` 가 왜 `-3` 이 아니라 `-4` 인가.
- [ ] 설명할 수 있다: `a = (a // b) * b + (a % b)` 가 왜 항상 성립하는가.
- [ ] 설명할 수 있다: `137` 초를 분과 초로 나눌 때 어디에 `//` 를, 어디에 `%` 를 쓰는가.
- [ ] 설명할 수 있다: `2 + 3 * 4` 가 왜 `20` 이 아니라 `14` 인가.
- [ ] 설명할 수 있다: `a + b + c / 3` 이 평균이 아닌 이유를 계산 순서로.
- [ ] 설명할 수 있다: 평균에서 나누는 수를 무엇으로 정하는가.
- [ ] 설명할 수 있다: 합을 `total` 변수에 먼저 담으면 어떤 실수가 줄어드는가.
- [ ] 설명할 수 있다: 같은 평균인데 `/` 와 `//` 의 출력이 어떻게 달라지는가.
- [ ] 설명할 수 있다: 정수와 실수를 섞어 계산하면 결과의 자료형은 무엇이 되는가.
- [ ] 설명할 수 있다: 출력에 `.0` 이 붙는 경우와 붙지 않는 경우를 어떻게 구분하는가.

**⚠️ 자주 하는 실수**

**(1) `/` 와 `//` 를 혼동한다**

```python
# ❌ 틀린 코드
a, b = 17, 5
print(a / b)             # 3.4  ("한 사람이 3.4개" 는 답이 될 수 없다)
```

왜: 사람 수로 나눠 갖는 개수처럼 **정수로 떨어져야 하는 답**에는 `/` 를 쓰면 안 됩니다. `/` 는 소수를 그대로 남깁니다.

```python
# ✅ 고친 코드
a, b = 17, 5
print(a // b)            # 3
print(a % b)             # 2 (남는 개수)
```

**(2) 평균에서 괄호를 빠뜨린다**

```python
# ❌ 틀린 코드
a, b, c = 10, 20, 30
print(a + b + c / 3)     # 40.0
```

왜: `/` 가 `+` 보다 먼저 계산되어 `c` 만 3으로 나뉩니다. `10 + 20 + 10.0` 이 되어 평균과 전혀 다른 값이 나옵니다.

```python
# ✅ 고친 코드
a, b, c = 10, 20, 30
total = a + b + c        # 합을 먼저 하나의 값으로 만든다
print(total / 3)         # 20.0
```

**(3) 나누는 수를 값의 개수가 아닌 것으로 쓴다**

```python
# ❌ 틀린 코드
a, b, c, d = 3, 5, 8, 4
total = a + b + c + d
print(total / 3)         # 값은 4개인데 3으로 나눴다
```

왜: 평균은 "합 ÷ **값의 개수**"입니다. 개수를 잘못 세면 식의 모양은 맞아도 답이 틀립니다.

```python
# ✅ 고친 코드
a, b, c, d = 3, 5, 8, 4
total = a + b + c + d
print(total / 4)
```

**(4) 문자열을 정수로 바꾸지 않고 계산한다**

```python
# ❌ 틀린 코드
a, b = input().split()
print(a + b)             # 입력 "7 3" -> 73
```

왜: `split()` 이 돌려준 조각은 아직 글자입니다. 문자열끼리의 `+` 는 덧셈이 아니라 이어 붙이기라서 오류 없이 틀린 답이 나옵니다.

```python
# ✅ 고친 코드
a, b = input().split()
a = int(a)
b = int(b)
print(a + b)             # 10
```

**(5) 뺄셈·나눗셈의 순서를 뒤집는다**

```python
# ❌ 틀린 코드
a, b = 2, 5
print(b - a)             # 3  ("앞 - 뒤" 를 요구했는데 뒤집었다)
```

왜: `+` 와 `*` 는 순서를 바꿔도 결과가 같지만, `-` 와 `/` 는 다릅니다. 문제가 정한 순서를 그대로 옮겨야 합니다.

```python
# ✅ 고친 코드
a, b = 2, 5
print(a - b)             # -3
```

**(6) 출력 자릿수를 맞추지 않는다**

```python
# ❌ 틀린 코드
x = 0.1 + 0.2
print(x)                 # 0.30000000000000004
```

왜: 실수는 2진수로 저장되면서 아주 작은 오차가 생깁니다. 그대로 출력하면 예상 밖의 꼬리가 붙습니다.

```python
# ✅ 고친 코드
x = 0.1 + 0.2
print(f'{x:.2f}')        # 0.30
```

**(7) 음수에서 `//` 와 `int()` 를 같은 것으로 본다**

```python
# ❌ 틀린 코드
n = -7
print(int(n / 2))        # -3
print(n // 2)            # -4  (두 줄의 결과가 다르다)
```

왜: `//` 는 작은 쪽으로 **내리고**, `int()` 는 0 쪽으로 **자릅니다.** 양수에서는 같아 보이지만 음수에서 갈립니다.

```python
# ✅ 고친 코드
n = -7
print(n // 2)            # -4 : 몫이 필요하면 이쪽
print(int(n / 2))        # -3 : 0 쪽으로 자르고 싶을 때만
```

**(8) 나누는 수가 `0` 이 될 수 있는데 그냥 나눈다**

```python
# ❌ 틀린 코드
a, b = input().split()
a = int(a)
b = int(b)
print(a // b)            # b 가 0 이면 ZeroDivisionError
```

왜: 어떤 수도 0으로 나눌 수 없습니다. `/`, `//`, `%` 모두 오른쪽이 `0` 이면 그 자리에서 프로그램이 멈춥니다.

```python
# ✅ 고친 코드
# 문제 조건에 "사람 수는 1 이상" 처럼 적혀 있는지 먼저 확인한다.
# 조건이 보장되면 그대로 두고, 보장되지 않으면 조건문(Ch04 이후)으로 걸러 낸다.
a, b = input().split()
a = int(a)
b = int(b)               # b >= 1 이 문제에서 보장될 때만 안전하다
print(a // b)
```

**다음 챕터로**

- Ch01~Ch03으로 "읽고 → 계산하고 → 출력한다"는 한 줄 흐름이 완성되었습니다. 여기까지는 코드가 위에서 아래로 한 번만 흐릅니다.

- 지금 익힌 "먼저 계산되는 덩어리를 눈으로 찾는 습관"은 조건식이 길어질수록 더 중요해집니다.

## L14. 정리 — 조건문 개념 지도·체크리스트·자주 하는 실수

**개념**

이 챕터에서 배운 것을 한자리에 모은다. 새 문법은 없다. 흩어져 있던 조각이 어떻게 하나로 이어지는지 확인하고, 입문자가 실제로 넘어지는 지점을 미리 밟아 보는 자리다.

**개념 지도**

조건문의 재료는 딱 하나, **참·거짓 값**이다. 비교 연산자가 그 값을 만들고, `and`/`or`가 여러 개를 하나로 합치고, `if` 계열 문법이 그 값을 보고 갈 길을 정한다.

```text
   +----------+  +---------------+   +----------------------------+
   |  values  |->|  comparison   |-->|  True / False              |
   |  a , b   |  |  ==  !=  >    |   |  ( this is what if reads ) |
   +----------+  |  <   >=  <=   |   +--------------+-------------+
                 +---------------+                  |
                 +---------------+                  |
                 |  and  or  ( ) |------------------+
                 |  join several |                  |
                 +---------------+                  v
```

참·거짓 값 하나가 만들어지면, 그다음은 "갈래를 어떤 모양으로 놓을 것인가"만 남는다.

```text
   branch shapes                        how many run
   ---------------------------------    ----------------------------
   if                                   0 or 1
   if / else                            exactly 1
   if / elif / else                     exactly 1  (order matters)
   if  +  if   (side by side)           0 .. n
   nested if   (if inside if)           stage by stage
   a if cond else b                     picks a VALUE, not code
```

위 표의 마지막 줄만 성격이 다르다. 삼항 연산자는 "실행할 코드"가 아니라 "값"을 고른다.

**뼈대 코드**

**1) 두 갈래 — 결과가 정확히 둘일 때**

```python
x = int(input())            # ← 문제마다 바뀜 (입력 형태)
if x >= 60:                 # ← 문제마다 바뀜 (가르는 기준)
    print("Pass")           # ← 문제마다 바뀜 (참일 때 할 일)
else:
    print("Fail")           # ← 문제마다 바뀜 (거짓일 때 할 일)
```

**2) 구간 나누기 — 겹치는 범위를 순서로 푼다**

```python
score = int(input())
if score >= 90:             # ← 큰 기준부터 내려간다
    print("A")
elif score >= 80:           # ← 여기 왔다는 건 이미 90 미만이라는 뜻
    print("B")
elif score >= 70:           # ← 기준 개수만큼 elif를 늘린다
    print("C")
else:                       # ← 남은 전부
    print("D")
```

**3) 독립 판정 여러 개 — 동시에 참일 수 있을 때**

```python
n = int(input())
if n % 2 == 0:              # ← 판정 1
    print("two")
if n % 3 == 0:              # ← 판정 2 (앞 결과와 무관하게 다시 검사)
    print("three")
```

**4) 깃발 변수 — "아무것도 안 했는가"를 기억하기**

```python
n = int(input())
done = False                # ← 아직 아무 일도 하지 않았다
if n % 3 == 0:
    print("Fizz")
    done = True             # ← 뭔가 했다고 표시
if n % 5 == 0:
    print("Buzz")
    done = True
if done == False:           # ← 위에서 하나도 안 걸렸을 때만
    print(n)                # ← 문제마다 바뀜 (기본 동작)
```

**5) 단계형 분기 — 통과한 것만 다시 나눌 때**

```python
a, b = input().split()
a = int(a)
b = int(b)
if a > 0:                   # ← 1단계: 큰 갈래
    if b > 0:               # ← 2단계: 1단계를 통과한 경우에만 검사
        print("both")
    else:
        print("only a")
else:
    print("none")           # ← 1단계에서 떨어진 경우
```

**6) 값 하나 고르기 — 삼항 연산자**

```python
n = int(input())
label = "even" if n % 2 == 0 else "odd"   # ← 조건과 두 값만 바뀜
print(label)
```

**언제 무엇을 쓰나**

| 상황 | 고르는 것 | 이유 | 복잡도 |
| --- | --- | --- | --- |
| 조건이 참일 때만 뭔가 한다 | `if` | 거짓일 때 할 일이 아예 없다 | 비교 1회 |
| 결과가 정확히 두 가지 | `if / else` | 반대 조건을 파이썬이 만들어 준다 | 비교 1회 |
| 결과가 셋 이상, 그중 하나만 | `if / elif / else` | 위에서 처음 참인 하나만 실행 | 비교 최대 (갈래 수 − 1)회 |
| 판정이 여러 개이고 동시에 참일 수 있다 | `if`를 나란히 | 서로 막지 않고 각각 검사 | 비교 (판정 수)회 |
| 두 조건이 동시에 참이어야 한다 | `and` | 통과 구간의 겹치는 부분만 남긴다 | 비교 2회 |
| 둘 중 하나만 참이면 된다 | `or` | 통과 구간을 합친다 | 비교 2회 |
| 양쪽이 막힌 범위(이상 그리고 이하) | `and`로 두 경계 | 아래 경계와 위 경계는 별개 조건 | 비교 2회 |
| 통과한 대상만 다시 나눈다 | 중첩 `if` | 바깥이 거짓일 때 따로 할 일이 있다 | 단계마다 1회 |
| 값 하나만 고르면 끝난다 | 삼항 연산자 | 결과가 값이라 변수·`print`에 바로 들어간다 | 비교 1회 |
| 구간 경계가 겹친다 | `elif` + 큰 기준부터 | 위 갈래가 상한을 대신 잘라 준다 | 비교 최대 (구간 수 − 1)회 |

**✅ 마스터 체크리스트**

- [ ] 설명할 수 있다: `if` 아래 들여쓴 줄과 들여쓰지 않은 줄이 각각 언제 실행되는지.
- [ ] 설명할 수 있다: `if / else`의 두 갈래가 절대 동시에 실행되지 않는 이유.
- [ ] 설명할 수 있다: `elif` 사슬이 "처음 참인 갈래 하나만" 실행한다는 것과, 그래서 순서가 답을 바꾼다는 것.
- [ ] 설명할 수 있다: 성적 등급을 `>=`로 쓸 때 왜 큰 점수부터 검사해야 하는지, 순서를 뒤집으면 무슨 일이 생기는지.
- [ ] 설명할 수 있다: 나란한 `if` 두 개와 `if / elif`가 어떤 입력에서 결과가 갈리는지, 예를 하나 들어서.
- [ ] 설명할 수 있다: `>=`와 `>`가 경계값에서 어떻게 다른지, 지문의 "이상·초과"가 각각 어느 쪽인지.
- [ ] 설명할 수 있다: `=`와 `==`의 역할 차이, 그리고 조건 자리에 `=`를 쓰면 왜 안 되는지.
- [ ] 설명할 수 있다: `and`와 `or`의 참·거짓 표를 보지 않고 말로.
- [ ] 설명할 수 있다: `and`가 `or`보다 먼저 계산된다는 것과, 괄호가 꼭 필요한 상황의 예 하나.
- [ ] 설명할 수 있다: 중첩 `if`와 `and`로 합친 조건이 언제 같고 언제 다른지.
- [ ] 설명할 수 있다: 삼항 연산자가 고르는 것이 "코드"가 아니라 "값"이라는 뜻.
- [ ] 설명할 수 있다: 세 갈래(양수·음수·0)를 겹침 없이·빠짐 없이 나누는 방법.
- [ ] 설명할 수 있다: 어떤 조건 코드를 보고 경계 검산용 입력 세 개(기준, 기준−1, 기준+1)를 즉시 만드는 법.

**⚠️ 자주 하는 실수**

**1) `elif` 대신 `if`를 나열해 여러 갈래가 함께 실행됨**

```python
# ❌ 틀린 코드
score = 95
if score >= 70:
    print("C")
if score >= 80:
    print("B")
if score >= 90:
    print("A")
# 출력: C / B / A 세 줄
```

왜: 세 `if`는 서로 독립이라 앞이 참이어도 뒤가 다시 검사된다. 95는 세 조건에 모두 걸려 세 줄이 나온다. 등급을 하나만 내려면 갈래가 배타적이어야 한다.

```python
# ✅ 고친 코드
score = 95
if score >= 90:
    print("A")
elif score >= 80:
    print("B")
elif score >= 70:
    print("C")
# 출력: A 한 줄
```

**2) `elif` 사슬의 순서가 거꾸로**

```python
# ❌ 틀린 코드
score = 95
if score >= 70:
    print("C")
elif score >= 80:
    print("B")
elif score >= 90:
    print("A")
# 출력: C   (A는 영원히 나오지 않는다)
```

왜: `score >= 70`은 95에도 참이다. `elif` 사슬은 처음 참인 갈래에서 끝나므로 아래 두 줄은 도달조차 하지 못한다. 겹치는 범위는 **좁은 조건(큰 기준)부터** 써야 한다.

```python
# ✅ 고친 코드
score = 95
if score >= 90:
    print("A")
elif score >= 80:
    print("B")
elif score >= 70:
    print("C")
```

**3) 경계값에서 `>`와 `>=`를 바꿔 씀**

```python
# ❌ 틀린 코드
score = 60
if score > 60:          # 지문은 "60점 이상 합격"인데 60이 빠진다
    print("Pass")
else:
    print("Fail")
# 출력: Fail
```

왜: "이상"은 경계 포함이라 `>=`, "초과"가 `>`다. 지문의 두 글자가 부등호의 `=` 한 글자를 결정한다.

```python
# ✅ 고친 코드
score = 60
if score >= 60:
    print("Pass")
else:
    print("Fail")
# 출력: Pass
```

**4) 비교 자리에 `=`를 씀**

```python
# ❌ 틀린 코드
n = 3
if n = 3:
    print("three")
# SyntaxError: invalid syntax
```

왜: `=`는 값을 넣는 기호라 조건 자리에 올 수 없다. 비교는 언제나 `==`다. 다행히 이 실수는 실행 전에 오류로 잡힌다.

```python
# ✅ 고친 코드
n = 3
if n == 3:
    print("three")
```

**5) `or` 양쪽에 비교식을 온전히 쓰지 않음**

```python
# ❌ 틀린 코드
day = 3
if day == 6 or 7:
    print("weekend")
# 출력: weekend   (평일 3인데도 나온다)
```

왜: 파이썬은 이 식을 `(day == 6) or (7)`로 읽는다. `7`은 0이 아닌 수라 그 자체로 참 취급이므로 전체가 항상 참이 된다. 오류가 나지 않아 더 위험하다.

```python
# ✅ 고친 코드
day = 3
if day == 6 or day == 7:
    print("weekend")
else:
    print("weekday")
# 출력: weekday
```

**6) 괄호 없이 `and`와 `or`를 섞음**

```python
# ❌ 틀린 코드
x = 1
if x > 0 or x > 10 and x < 0:
    print("hit")
# 의도: (x > 0 or x > 10) and x < 0  ->  아무것도 안 나와야 함
# 실제: x > 0 or (x > 10 and x < 0)  ->  hit 이 나온다
```

왜: `and`가 `or`보다 먼저 계산된다. 사칙연산에서 `*`가 `+`보다 먼저인 것과 같다. `or` 쪽을 먼저 묶고 싶으면 직접 괄호를 쳐야 한다.

```python
# ✅ 고친 코드
x = 1
if (x > 0 or x > 10) and x < 0:
    print("hit")
# 아무것도 출력되지 않는다
```

**7) 들여쓰기로 조건 밖 코드가 조건 안으로 들어감**

```python
# ❌ 틀린 코드
score = 40
if score >= 60:
    print("Pass")
    print("done")       # 항상 찍고 싶었는데 if 안에 들어갔다
# 출력: (없음)
```

왜: 파이썬은 들여쓰기 깊이로 소속을 정한다. `if`보다 한 단계 더 들어간 줄은 조건이 참일 때만 실행된다.

```python
# ✅ 고친 코드
score = 40
if score >= 60:
    print("Pass")
print("done")           # if와 같은 깊이 = 조건과 무관하게 항상 실행
# 출력: done
```

**8) `else`에 조건을 붙임**

```python
# ❌ 틀린 코드
n = 5
if n > 0:
    print("plus")
else n < 0:
    print("minus")
# SyntaxError: invalid syntax
```

왜: `else`는 "위 조건들이 전부 거짓인 나머지 전부"라서 조건을 받지 않는다. 조건을 더 걸고 싶으면 `elif`다.

```python
# ✅ 고친 코드
n = 5
if n > 0:
    print("plus")
elif n < 0:
    print("minus")
else:
    print("zero")
```

**다음 챕터로**

조건문은 "한 번 갈라지는" 문법이다. 다음 챕터의 반복문은 같은 판단을 **여러 번** 반복하면서 값이 매번 바뀌는 상황을 다룬다. 여기서 익힌 `if`가 반복문 안으로 들어가면 "훑으면서 조건에 맞는 것만 고르기"가 되고, `and`/`or`와 깃발 변수는 "하나라도 있는가·모두 그런가"를 판정하는 도구로 그대로 이어진다.

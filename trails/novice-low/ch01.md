> 개요: 이 챕터에서는 화면에 값을 보여 주는 `print`를 익히고, 값을 담아 두는 변수와 기본 자료형, 여러 값을 원하는 형식으로 출력하는 법, 그리고 변수의 값을 바꾸고 옮기고 서로 교환하는 방법까지 배운다.

## L1. 기본 출력

**개념**

- 프로그램이 만든 결과를 사람이 볼 수 있게 화면에 보여 주는 것을 "출력"이라고 한다.
- 파이썬에서는 `print(...)` 함수로 출력한다. 괄호 안에 보여 주고 싶은 값을 넣는다.
- 글자(문자열)를 그대로 출력하려면 작은따옴표 `'...'` 나 큰따옴표 `"..."` 로 감싼다.
- 숫자는 따옴표 없이 그대로 쓴다. `print(10)` 은 `10` 을 출력한다.
- `print` 는 한 번 호출될 때마다 자동으로 줄을 바꾼다. 그래서 `print` 를 두 번 쓰면 두 줄로 나온다.

```python
print('Hello')
print(2025)
```

위 코드의 출력:

```
Hello
2025
```

**그림으로 보기**

`print` 한 번은 두 가지 일을 한다. ① 괄호 안 값을 화면에 찍는다 ② 줄을 바꾼다. 아래에서 `[NL]` 은 눈에 보이지 않는 줄바꿈 표시다.

```text
  code                  what print sends out
  -------------------   --------------------------
  print('Hello')        H e l l o [NL]
  print(2025)           2 0 2 5 [NL]

  screen
  +---------+
  | Hello   |   <- from print #1
  | 2025    |   <- from print #2
  +---------+
```

따옴표는 화면에 나오지 않는다. "여기부터 여기까지가 글자다"라고 파이썬에게 알려 주는 표시일 뿐이다.

```text
  print('Hello')
        ^     ^
        |     + string ends here
        + string starts here

  print(2025)        # no quotes -> a number, not letters
```

**왜 이렇게 되는가**

- 파이썬은 코드를 왼쪽부터 읽다가 따옴표를 만나면 "여기서 문자열이 시작된다"고 판단하고, **같은 종류**의 따옴표를 다시 만날 때까지를 한 덩어리 글자로 취급한다.
- 그래서 `print('It's a book')` 은 두 번째 `'`(즉 `It` 뒤의 것)에서 문자열이 끝났다고 보고, 남은 `s a book'` 을 무엇으로 읽어야 할지 몰라 오류를 낸다.
- 바깥을 `"..."` 로 바꾸면 안쪽의 `'` 는 "끝을 알리는 따옴표"가 아니라 평범한 글자가 되어 그대로 출력된다.
- 규칙은 하나로 정리된다. **문장 안에 들어 있는 따옴표와 반대 종류로 바깥을 감싼다.**
- 숫자에 따옴표를 붙이지 않는 이유도 같다. 따옴표를 붙이면 "계산할 수 있는 수"가 아니라 "그냥 그렇게 생긴 글자"가 되어 버린다.

## L2. 변수와 자료형

**개념**

- 변수는 값을 담아 두는 "이름표가 붙은 상자"다. `x = 5` 는 `x` 라는 이름에 값 `5` 를 넣는 것이다.
- `=` 는 "같다"가 아니라 "오른쪽 값을 왼쪽 이름에 넣어라"라는 뜻이다. (이걸 대입이라 한다.)
- 변수에 담긴 값은 그 이름만 써서 다시 꺼내 쓸 수 있다. `print(x)` 는 `x` 가 담고 있는 값을 출력한다.
- 값에는 종류가 있고 이를 "자료형"이라 한다. 기초 자료형 세 가지:

- 정수형(int): 소수점이 없는 수. 예: `3`, `-7`, `0`
- 실수형(float): 소수점이 있는 수. 예: `3.14`, `-0.5`, `2.0`
- 문자열(str): 따옴표로 감싼 글자. 예: `'hi'`, `"12"`

- 같은 겉모습이라도 자료형이 다를 수 있다. `5` 는 정수, `5.0` 은 실수, `'5'` 는 문자열이다.

```python
age = 20
pi = 3.14
name = 'Ann'
print(name)
print(age)
```

출력:

```
Ann
20
```

**그림으로 보기**

변수는 "이름표가 붙은 상자"다. 상자 안에는 값이, 상자 밖에는 이름이 붙는다. 값을 꺼내 쓸 때는 이름만 부르면 된다.

```text
  age = 20            pi = 3.14           name = 'Ann'

  +---------+         +---------+         +---------+
  |   20    |         |  3.14   |         |  'Ann'  |
  +---------+         +---------+         +---------+
      age                  pi                name        # name tag
      int                float               str         # data type
```

겉모습이 비슷해도 상자에 들어 있는 값의 "종류"가 다르면 할 수 있는 일이 달라진다.

```text
   5     -> int    a number. 5 + 5 is 10
   5.0   -> float  a number that carries a decimal point
  '5'    -> str    one letter. '5' + '5' is '55', not 10
```

**왜 이렇게 되는가**

- `x = 5` 의 `=` 는 수학의 "같다"가 아니라 **명령**이다. "오른쪽 값을 만들어 왼쪽 이름표에 붙여라."
- 방향이 정해져 있다는 뜻이다. 그래서 `5 = x` 는 오류다(왼쪽에는 이름이 와야 한다). 반대로 수학에서는 말이 안 되는 `x = x + 1` 이 코드에서는 자연스럽다(L5에서 다룬다).
- 자료형이 왜 필요한가: 컴퓨터는 "값"만 보고는 그 값으로 무엇을 해야 할지 정할 수 없다. `5 + 5` 는 `10`, `'5' + '5'` 는 `'55'` 처럼, **같은 `+` 기호가 자료형에 따라 다른 뜻**이 되기 때문이다.
- 따옴표 유무 하나로 자료형이 갈리므로, 값을 담기 전에 "이건 계산할 수인가, 보여 줄 글자인가"를 먼저 정하는 습관이 중요하다.

## L3. 출력 형식

**개념**

- 한 줄에 여러 값을 함께 보여 주고 싶을 때, `print` 괄호 안에 값을 쉼표 `,` 로 나열하면 된다.
- 쉼표로 나열하면 값 사이에 자동으로 공백 한 칸이 들어간다. 예: `print('a', 'b')` → `a b`
- 문자열과 숫자를 섞어서 나열해도 된다. 자료형이 달라도 쉼표로 이으면 함께 출력된다.
- 문자열끼리는 `+` 로 이어 붙일 수도 있다. 이때는 공백이 자동으로 들어가지 않는다. 예: `print('a' + 'b')` → `ab`
- 정리하면, 쉼표는 "공백을 넣어 나란히", `+` 는 "빈틈없이 붙여서"이다. (`+` 는 문자열끼리만, 숫자끼리만 가능하며 서로 섞으면 오류가 난다.)

```python
name = 'Ann'
age = 20
print(name, age)
print('Age:', age)
```

출력:

```
Ann 20
Age: 20
```

**그림으로 보기**

같은 두 값이라도 쉼표로 잇느냐 `+` 로 잇느냐에 따라 화면에 찍히는 글자가 달라진다. 아래 칸 하나가 화면의 글자 한 칸이다.

```text
  a = 'Sea'   b = 'side'

  print(a, b)     +-+-+-+-+-+-+-+-+
                  |S|e|a| |s|i|d|e|    # comma puts ONE space between
                  +-+-+-+-+-+-+-+-+
                   0 1 2 3 4 5 6 7

  print(a + b)    +-+-+-+-+-+-+-+
                  |S|e|a|s|i|d|e|      # + glues them, no space
                  +-+-+-+-+-+-+-+
                   0 1 2 3 4 5 6
```

라벨을 붙일 때 공백이 두 칸이 되는 사고는 여기서 생긴다. 쉼표가 이미 한 칸을 넣어 주기 때문이다.

```text
  print('Age:', 20)     ->  A g e : _ 2 0        # _ marks the space
                                    ^
                                    put in by the comma

  print('Age: ', 20)    ->  A g e : _ _ 2 0      # two spaces: wrong
                                    ^ ^
                                    | + from the comma
                                    + typed inside the string
```

> 선행: 쉼표가 넣는 공백은 `sep=` 로, 끝의 줄바꿈은 `end=` 로 바꿀 수 있다(정식 설명은 L9). "값 **사이**에 무엇을 넣을지"가 `sep`, "값을 다 찍은 **뒤**에 무엇을 붙일지"가 `end` 라고만 알아 두면 아래 그림이 읽힌다.

```text
  call                        cells sent to the screen      screen shows
  -------------------------   -------------------------     ------------
  print('a', 'b')             [a][_][b][NL]                 a b
  print('a', 'b', sep='-')    [a][-][b][NL]                 a-b
  print('a', 'b', sep='')     [a][b][NL]                    ab

  print('a', end='')          [a]                           a
  print('b')                  [b][NL]                       ab
                                                            ^^
  # [_] = one space   [NL] = newline   end='' means "no newline yet"
```

**왜 이렇게 되는가**

- `+` 는 "양쪽 값을 하나로 합쳐라"라는 요청이고, **합치는 방법은 자료형이 정한다.** 숫자끼리면 수를 더하고, 문자열끼리면 뒤에 이어 붙인다.
- 그래서 `'Sea' + 'side'` 는 `'Seaside'`, `3 + 4` 는 `7` 이다. 기호는 같지만 하는 일이 다르다.
- 문자열과 숫자를 섞어 `'Age: ' + 20` 이라고 쓰면 파이썬은 `20` 을 글자로 볼지, `'Age: '` 를 수로 볼지 정할 근거가 없다. 마음대로 추측하면 나중에 더 큰 사고가 나므로, 추측하지 않고 그 자리에서 오류(TypeError)를 낸다.
- 반면 쉼표 나열은 값을 합치는 게 아니라 **각 값을 따로 글자로 바꿔 차례로 찍는 것**이다. 그래서 자료형이 섞여 있어도 문제가 없다. 초보자에게 쉼표가 더 안전한 이유다.

## L4. 소수점 맞춰 출력

**개념**

- 실수를 출력할 때 소수점 아래 자릿수를 정해서 깔끔하게 보여 주고 싶을 때가 있다.
- 이때 f-문자열(f-string)을 쓴다. 문자열 앞에 `f` 를 붙이고, 값을 넣을 자리에 `{ }` 를 쓴다.
- `{값:.2f}` 는 "이 값을 소수점 아래 2자리 실수로 출력하라"는 뜻이다. `.` 뒤 숫자가 자릿수, 끝의 `f` 는 실수(float) 형식을 뜻한다.
- 지정한 자릿수에 맞춰 반올림된다. 예: `3.14159` 를 `.2f` 로 하면 `3.14`, `2.005` 는 상황에 따라 반올림된다.
- 정해진 자릿수보다 짧으면 `0` 으로 채운다. 예: `2.5` 를 `.3f` 로 하면 `2.500`.

```python
pi = 3.14159
print(f'{pi:.2f}')
print(f'{pi:.4f}')
```

출력:

```
3.14
3.1416
```

> 선행: `{ }` 안에 변수를 넣으면 그 값이 문자열 안으로 들어간다. 지금은 "소수점 자릿수 맞추기" 용도로만 쓴다.

**그림으로 보기**

소수점 아래 자리에 번호를 매겨 두면 `.Nf` 가 무엇을 보고 결정하는지 눈에 보인다. **남길 자리 바로 다음 자리**가 5 이상이면 올림, 아니면 버림이다.

```text
  pi = 3.14159

        3 . 1 4 1 5 9
            ^ ^ ^ ^ ^
            1 2 3 4 5          # position after the decimal point

  f'{pi:.2f}'   keep 1..2  ->  look at position 3 = 1  ->  1 < 5  -> down
                result: 3.14

  f'{pi:.4f}'   keep 1..4  ->  look at position 5 = 9  ->  9 >= 5 -> up
                result: 3.1416          # the 5 at position 4 becomes 6
```

자리가 모자랄 때는 `0` 으로 채운다. 값이 커지는 게 아니라 보이는 모양만 채워진다.

```text
  price = 5          f'{price:.2f}'  ->  5 . 0 0
                                             ^ ^
                                             filled with 0

  v = 2.5            f'{v:.3f}'      ->  2 . 5 0 0
```

**왜 이렇게 되는가**

- 컴퓨터는 실수를 2진수(0과 1)로 저장한다. 10진수 `0.1` 을 2진수로 옮기면 `0.0001100110011…` 처럼 **끝없이 반복**되는 수라, 정해진 칸 안에 다 담지 못하고 어딘가에서 잘라야 한다.
- 10진수로 `1/3` 을 적으면 `0.3333…` 이 되어 유한한 칸에 정확히 못 적는 것과 똑같은 사정이다. 잘린 만큼 아주 작은 오차가 남는다.
- 그래서 `0.1 + 0.2` 를 그대로 출력하면 `0.3` 이 아니라 `0.30000000000000004` 가 나온다. 파이썬의 버그가 아니라 저장 방식의 결과다.
- `.2f` 처럼 자릿수를 정해 출력하면 오차가 붙어 있는 꼬리가 잘려 나가 사람이 기대하는 모양이 된다. 코딩테스트에서 실수 답에 "소수점 아래 N자리까지"라는 조건이 붙는 이유가 바로 이것이다.
- 한 가지 더: `.Nf` 는 변수 값을 바꾸지 않는다. **보여 주는 모양만** 바꾼다. `print(f'{pi:.2f}')` 를 해도 `pi` 는 여전히 `3.14159` 다.

## L5. 변수 값 변경

**개념**

- 변수에는 값을 다시 대입해서 언제든 바꿀 수 있다. 상자에 들어 있던 값을 빼고 새 값을 넣는 것과 같다.
- 나중에 대입한 값이 이전 값을 덮어쓴다. 마지막으로 넣은 값만 남는다.
- 같은 변수를 계산에 써서 새 값을 만들 수도 있다. `x = x + 1` 은 "지금 `x` 값에 1을 더한 결과를 다시 `x` 에 넣어라"라는 뜻이다.
- 이때 오른쪽이 먼저 계산되고, 그 결과가 왼쪽 변수에 대입된다.
- 자주 쓰는 축약: `x += 1` 은 `x = x + 1` 과 같다. `-=`, `*=` 도 같은 방식이다.

```python
x = 10
x = 20      # 값이 20으로 바뀜
x = x + 5   # 20 + 5 = 25
print(x)
```

출력:

```
25
```

**그림으로 보기**

상자는 하나뿐이다. 새 값을 넣으면 들어 있던 값은 그 자리에서 사라진다.

```text
  x = 10          x = 20          x = x + 5
  +------+        +------+        +------+
  |  10  |  --->  |  20  |  --->  |  25  |
  +------+        +------+        +------+
     x               x               x
                 # 10 is gone     # 20 + 5 computed first, then stored
```

`x = x + 5` 한 줄은 사실 두 단계다. 오른쪽을 먼저 계산해 손에 들고, 그다음 상자에 넣는다.

```text
  x = x + 5

  step 1  read the box     x -> 20
  step 2  compute right    20 + 5 -> 25          # x is still 20 here
  step 3  store into x     x <- 25               # now the box holds 25

  x += 5     is a short way of writing exactly the same three steps
```

**손으로 따라가기**

`count` 를 0에서 시작해 1씩 세 번 더하는 과정이다. 각 줄에서 "오른쪽 계산"은 **아직 바뀌기 전의 값**으로 이루어진다는 점을 확인한다.

| 단계 | 실행한 줄 | 계산 전 `count` | 오른쪽 계산 | 계산 후 `count` |
|------|-----------|-----------------|-------------|-----------------|
| 1 | `count = 0` | (없음) | `0` | `0` |
| 2 | `count = count + 1` | `0` | `0 + 1 = 1` | `1` |
| 3 | `count = count + 1` | `1` | `1 + 1 = 2` | `2` |
| 4 | `count = count + 1` | `2` | `2 + 1 = 3` | `3` |

마지막 줄의 `count` 가 `3` 이므로 `print(count)` 는 `3` 을 출력한다.

**왜 이렇게 되는가**

- `x = x + 1` 이 처음에 이상해 보이는 이유는 `=` 를 "같다"로 읽기 때문이다. 수학에서 `x = x + 1` 은 성립할 수 없는 식이다.
- 코드에서 `=` 는 **왼쪽으로 값을 밀어 넣는 화살표(`←`)** 다. 실행 순서가 정해져 있다: ① 오른쪽 식을 계산한다(이때 `x` 는 아직 옛 값) ② 그 결과를 왼쪽 이름에 붙인다.
- 그래서 옛 값과 새 값이 한 줄 안에 공존할 수 있다. `x = x * 2` 도 "지금 값을 두 배로 만들어 다시 담아라"라는 뜻이 된다.
- `+=`, `-=`, `*=` 는 이 두 단계를 그대로 줄여 쓴 것뿐이다. 새로운 규칙이 아니라 같은 동작의 짧은 표기다.

## L6. 다른 변수로부터 값 변경

**개념**

- 한 변수의 값을 다른 변수에 그대로 옮겨 담을 수 있다. `b = a` 는 "`a` 의 현재 값을 `b` 에 넣어라"라는 뜻이다.
- 이때 값이 복사되어 들어간다. 대입 이후 `a` 가 바뀌어도 이미 복사된 `b` 는 영향을 받지 않는다.
- 여러 변수를 조합해 새 값을 만들 수도 있다. `c = a + b` 는 `a` 와 `b` 의 값을 더해 `c` 에 넣는다.
- 오른쪽 식이 먼저 계산되고, 그 결과가 왼쪽 변수에 대입된다는 원칙은 항상 같다.

```python
a = 5
b = a       # b에 5가 복사됨
a = 100     # a만 바뀜
print(a)
print(b)
```

출력:

```
100
5
```

**그림으로 보기**

`b = a` 는 상자를 공유하는 게 아니라, `a` 안의 값을 **복사해서** `b` 라는 다른 상자에 넣는 것이다. 상자는 처음부터 끝까지 두 개다.

```text
  step 1: a = 5        step 2: b = a         step 3: a = 100

  +-----+              +-----+ +-----+       +-----+ +-----+
  |  5  |              |  5  | |  5  |       | 100 | |  5  |
  +-----+              +-----+ +-----+       +-----+ +-----+
     a                    a       b             a       b
                          +-copy--+          # only a changed
```

`c = a + b` 도 같은 순서다. 오른쪽에서 값을 읽어 계산한 뒤, 그 결과만 새 상자에 넣는다. 재료가 된 `a`, `b` 는 그대로 남는다.

```text
  a = 6      b = 4

  +-----+   +-----+
  |  6  |   |  4  |        read
  +-----+   +-----+
     a         b
     +----+----+
        6 + 4
          |
          v
      +------+
      |  10  |             # a and b are untouched
      +------+
          c
```

**왜 이렇게 되는가**

- 대입은 언제나 "오른쪽 → 왼쪽" 한 방향이다. `b = a` 를 실행하는 순간 파이썬이 하는 일은 딱 하나, **그 시점의 `a` 값을 읽어 `b` 에 넣는 것**이다.
- 그 뒤로 두 이름 사이에는 아무 연결도 남지 않는다. 연결선을 만든 게 아니라 값을 한 번 베낀 것이기 때문이다. 그래서 `a = 100` 을 해도 `b` 는 복사하던 순간의 `5` 를 그대로 갖고 있다.
- 반대로 `b = a` 를 **한 번 더** 실행하면 그때의 `a` 값이 다시 복사되어 `b` 도 `100` 이 된다. 값은 "복사한 시점"에만 옮겨진다.
- 정리하면 값이 바뀌는 순간은 오직 그 변수가 `=` 의 왼쪽에 나올 때뿐이다. 이 원칙 하나로 L7(교환)과 L8(동시 대입)이 모두 설명된다.

## L7. 두 변수 값을 교환

**개념**

- 두 변수의 값을 맞바꾸는 것을 "교환(swap)"이라 한다. `a` 에는 `b` 의 값, `b` 에는 `a` 의 값이 들어가게 만든다.
- 그냥 `a = b` 를 먼저 하면 `a` 의 원래 값이 사라져서 잃어버린다. 그래서 임시 변수가 필요하다.
- 방법: 임시 변수 `temp` 에 `a` 를 잠시 넣어 두고 → `a = b` → `b = temp` 순서로 옮긴다.
- 임시 변수는 값을 잠깐 보관하는 "임시 상자"다. 교환이 끝나면 더는 신경 쓰지 않아도 된다.

```python
a = 1
b = 2
temp = a    # temp에 1을 보관
a = b       # a는 이제 2
b = temp    # b는 보관해 둔 1
print(a, b)
```

출력:

```
2 1
```

**그림으로 보기**

먼저 **왜 임시 변수가 필요한지**부터 그림으로 본다. `a = b` 를 먼저 하면 `a` 에 들어 있던 값이 덮어써져 영영 사라진다.

```text
  wrong:  a = b  first

  +---+ +---+          +---+ +---+
  | 1 | | 2 |   --->   | 2 | | 2 |      # the old 1 is lost
  +---+ +---+          +---+ +---+
    a     b              a     b
                       # b = a now gives 2, not 1
```

임시 상자에 먼저 옮겨 두면 잃어버릴 값이 없다. 세 단계를 그대로 따라가 보자.

```text
  step 0        step 1        step 2        step 3
  (start)       temp = a      a = b         b = temp

  +---++---+    +---++---+    +---++---+    +---++---+
  | 1 || 2 |    | 1 || 2 |    | 2 || 2 |    | 2 || 1 |
  +---++---+    +---++---+    +---++---+    +---++---+
    a    b        a    b        a    b        a    b

                +---+         +---+         +---+
                | 1 |         | 1 |         | 1 |
                +---+         +---+         +---+
                 temp          temp          temp
```

**손으로 따라가기**

`a = 10`, `b = 20` 을 교환하는 과정이다. 매 줄에서 **어떤 상자가 바뀌는지** 한 칸씩 확인한다.

| 단계 | 실행한 줄 | `a` | `b` | `temp` | 설명 |
|------|-----------|-----|-----|--------|------|
| 0 | (시작) | 10 | 20 | (없음) | 두 값이 제자리에 있다 |
| 1 | `temp = a` | 10 | 20 | 10 | `a` 값을 임시 상자에 복사(원본은 그대로) |
| 2 | `a = b` | 20 | 20 | 10 | `a` 의 10이 덮어써지지만 `temp` 에 살아 있다 |
| 3 | `b = temp` | 20 | 10 | 10 | 보관해 둔 10을 `b` 로 옮긴다 |

3단계가 끝나면 `a` 는 20, `b` 는 10이 되어 `print(a, b)` 가 `20 10` 을 출력한다. `temp` 에 남은 값은 더 쓰지 않으므로 신경 쓰지 않아도 된다.

**왜 이렇게 되는가**

- 대입은 "복사해서 덮어쓰기"다. 덮어쓰는 순간 그 자리에 있던 값은 **다른 어딘가에 복사본이 없으면 되찾을 방법이 없다.**
- 그래서 교환의 규칙은 하나로 정리된다. **덮어쓰기 때문에 사라질 값을 먼저 다른 곳에 복사해 둔다.**
- 세 변수를 한 칸씩 미는 경우(`a←b`, `b←c`, `c←원래 a`)도 같은 규칙이다. 마지막에 필요한 원래 `a` 만 `temp` 에 지켜 두면, 나머지는 앞에서부터 순서대로 밀면 된다.
- 반대로 미는 방향을 거꾸로 잡으면 `temp` 가 필요 없어지기도 한다. 핵심은 순서를 외우는 게 아니라 "이 줄에서 사라지는 값이 나중에 쓰이는가"를 매번 확인하는 것이다.

**문제**

## L8. 변수값 동시에 복사

**개념**

- 파이썬은 여러 변수에 값을 한 번에 대입할 수 있다. `a, b = 1, 2` 는 `a` 에 `1`, `b` 에 `2` 를 동시에 넣는다.
- 이 방식의 규칙: 오른쪽 값들이 "모두 먼저" 계산된 다음, 왼쪽 변수들에 순서대로 담긴다.
- 2단계로 생각하면 쉽다. ① 오른쪽을 먼저 계산해 임시 상자에 담아 둔다 → ② 그 담아 둔 값을 왼쪽 변수에 순서대로 붓는다. 오른쪽을 다 담은 뒤에 붓기 때문에, 붓는 도중 값이 서로 섞이지 않는다.
- 그래서 교환도 한 줄로 된다. `a, b = b, a` 는 임시 변수 없이 두 값을 맞바꾼다(오른쪽 `b, a` 를 먼저 상자에 담아 두기 때문).
- 같은 원리로 여러 변수에 같은 값을 한꺼번에 넣을 수도 있다. `x = y = 0` 은 `x` 와 `y` 를 모두 `0` 으로 만든다.

```python
a, b = 3, 7
a, b = b, a     # 임시 변수 없이 교환
print(a, b)
```

출력:

```
7 3
```

**그림으로 보기**

동시 대입은 언제나 **2단계**다. ① 오른쪽을 전부 옛 값으로 계산해 임시 상자에 담는다 ② 그 상자를 왼쪽 이름에 순서대로 붓는다. 파이썬이 `temp` 를 대신 만들어 주는 셈이다.

```text
  a = 1   b = 2        line:  a, b = b, a + b

  stage 1  build the right side using the OLD values
           (  b  ,  a + b  )
           (  2  ,  1 + 2  )
           (  2  ,    3    )   ---> parked in one temporary box

  stage 2  pour that box into the left names, in order
           a <- 2
           b <- 3

  +---+ +---+          +---+ +---+
  | 1 | | 2 |   --->   | 2 | | 3 |
  +---+ +---+          +---+ +---+
    a     b              a     b
```

교환이 한 줄로 되는 것도 같은 이유다. 오른쪽 `b, a` 가 옛 값으로 먼저 담기므로 붓는 도중에 값이 섞이지 않는다.

```text
  a = 8   b = 3        line:  a, b = b, a

  stage 1   ( b , a )  ->  ( 3 , 8 )      # both read BEFORE anything changes
  stage 2   a <- 3         b <- 8
```

**손으로 따라가기**

`a = 1`, `b = 2` 에서 `a, b = b, a + b` 를 실행하는 과정이다. 오른쪽 값을 **모두 적어 놓고** 왼쪽에 붓는 순서를 지킨다.

| 단계 | 하는 일 | 그때의 `a` | 그때의 `b` | 만들어진 값 |
|------|---------|-----------|-----------|-------------|
| 1 | 줄 시작 시점의 값을 적는다 | 1 | 2 | — |
| 2 | 오른쪽 첫 칸 `b` 계산 | 1 | 2 | `2` |
| 3 | 오른쪽 둘째 칸 `a + b` 계산 | 1 | 2 | `1 + 2 = 3` |
| 4 | 임시 상자 완성 | 1 | 2 | `(2, 3)` |
| 5 | 왼쪽에 순서대로 붓기 | 2 | 3 | — |

결과는 `a = 2`, `b = 3` 이라 `print(a, b)` 가 `2 3` 을 출력한다.

같은 줄을 "한 개씩 차례로" 처리했다고 착각하면 답이 달라진다. 비교해 보자.

| 착각한 계산 | 순서 | 결과 |
|-------------|------|------|
| `a = b` 를 먼저 하고 | `a` 가 2가 됨 | 이어서 `b = a + b` → `2 + 2 = 4` |
| 그래서 나오는 답 | — | `2 4` (틀림) |
| 실제 동시 대입 | 오른쪽 전부 먼저 | `2 3` (맞음) |

**왜 이렇게 되는가**

- 파이썬은 `=` 오른쪽을 **하나의 묶음(튜플)** 으로 먼저 완성한다. `b, a + b` 를 만나면 `(2, 3)` 이라는 값 한 덩어리를 먼저 만든다.
- 이 덩어리가 만들어지는 동안에는 왼쪽 변수 중 어느 것도 아직 바뀌지 않았다. 그래서 오른쪽에 등장하는 모든 변수는 **그 줄이 시작될 때의 값**으로 읽힌다.
- 그다음에야 덩어리를 왼쪽 이름에 앞에서부터 하나씩 붓는다. 이 시점에는 계산할 것이 남아 있지 않으므로, 붓는 도중 값이 서로 섞이는 일이 생길 수 없다.
- 그래서 임시 변수가 필요 없다. 정확히 말하면 **파이썬이 임시 상자를 대신 만들어 준 것**이지, 임시 보관이라는 원리가 사라진 게 아니다.
- `x = y = 0` 은 이것과 다른 문법이다. 값 `0` 하나를 `x` 에도 `y` 에도 각각 넣는다는 뜻이며, 두 변수를 연결하는 것이 아니다(L6의 복사 독립성과 같다).

**2) 임시 변수 없이 교환** · Medium

- **예제**: (입력 없음) → `3 8`

**3) 동시 대입의 함정** · Hard

- **요구사항**: `a = 1`, `b = 2` 로 시작한다. 한 줄의 동시 대입 `a, b = b, a + b` 를 실행한 뒤, `a` 와 `b` 를 한 줄에 공백으로 띄워 출력하라.
- **입력**: 없음
- **출력**: 대입 후의 `a`, `b` 를 공백을 두고 한 줄에
- **예제**: (입력 없음) → `2 3`
- **셀프체크**: 오른쪽 `b, a + b` 가 "옛날 값"으로 먼저 계산된다. 즉 `b`(=2)와 `a+b`(=1+2=3)를 먼저 구한 뒤 `a=2`, `b=3` 이 된다. 만약 `a` 를 먼저 바꾼 뒤 계산했다면 틀린 결과가 나온다.

```runner
@@SOLUTION
a = 1
b = 2
a, b = b, a + b
print(a, b)
@@TESTS
--IN

--OUT
2 3
@@EXPL
(1) 접근 개념: 동시 대입에서 오른쪽 식은 모두 "옛 값"으로 먼저 계산된 뒤에 왼쪽에 담긴다. 그래서 `a`가 바뀌기 전 값으로 `a + b`가 계산된다.

(2) 코드 진행

- `a = 1`, `b = 2` 로 시작한다.
- `a, b = b, a + b` — 오른쪽을 먼저 계산한다. 이때 `b`는 2, `a + b`는 `1 + 2 = 3`. 즉 오른쪽은 `(2, 3)`.
- 그 값을 왼쪽에 담는다. `a`는 2, `b`는 3.
- `print(a, b)` — `2 3`.

(3) 재작성 사고 순서

- 동시 대입은 "오른쪽 전부 먼저 계산 → 왼쪽에 순서대로 대입" 2단계로 생각한다.
- 오른쪽 계산에는 아직 바뀌지 않은 옛 값을 쓴다.
- `a`가 먼저 2로 바뀐 뒤 `a+b`를 계산했다면 `2+2=4`가 되어 틀린다. 그런 착오가 없는지 확인한다.
```

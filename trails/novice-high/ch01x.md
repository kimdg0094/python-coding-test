## L7. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch1(시간·공간복잡도)의 핵심 — 연산 횟수를 세고, Big-O로 등급을 매기고, 제한 시간 안에 드는지 판단하고, 같은 문제를 더 싼 복잡도로 다시 짜는 것 — 을 소재만 바꿔 **반복 훈련**하고, 코딩테스트 단골 유형(누적합·한 번 훑기·슬라이딩 윈도우)으로 **확장**하는 연습 세트다.
- **반복 훈련 개념**:
  - 연산 횟수 세기: 안쪽 줄이 몇 번 실행되는지 `cnt += 1`로 직접 세거나, `n // i`·`2^k - 1` 같은 공식으로 닫는다.
  - 시간 제한 판정: 초당 약 `10^8`번 연산을 기준으로 `ops <= 10**8 * t`이면 통과 가능, `n`의 최대치는 이 부등식을 만족하는 가장 큰 정수.
  - `O(n^2)` → `O(n)`: "매번 처음부터 다시 더하기"를 누적합 `pre[i+1] = pre[i] + a[i]` 또는 "지금까지의 최솟값" 변수 하나로 바꾼다.
  - 공간 절약: 길이 `n` 배열 대신 직전 값 두 개 `a, b = b, a + b`만 굴리면 공간 `O(1)`.
  - 로그 축 감각: `i *= 2`로 커지는 반복은 `n.bit_length()`번 돌고, 그 안쪽 합은 등비수열이라 `O(n)`에 그친다.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '누적 합' 단계, NeetCode 150의 'Arrays & Hashing'(Best Time to Buy and Sell Stock 류)·'Sliding Window' 유형, 『이것이 취업을 위한 코딩테스트다』의 '구현' 파트에서 복잡도 기준으로 풀이를 고르는 연습이 이 레슨과 맞닿아 있다.
- **문제 구성표**:

| # | 문제 | 난이도 | 반복 개념 | 유형 |
|---|------|--------|-----------|------|
| 1 | 시간 제한 통과 판정 | Easy | 연산 횟수 계산 + `10^8·t` 비교 | 반복 훈련 |
| 2 | 배수 훑기 반복 횟수 | Easy | 중첩 반복 횟수 세기(조화급수) | 반복 훈련 |
| 3 | 계단 오르기 경우의 수 | Easy | 배열 대신 변수 두 개(공간 `O(1)`) | 반복 훈련 |

**문제**

**1) 시간 제한 통과 판정** · Easy

- **요구사항**: 어떤 컴퓨터는 1초에 기본 연산을 `10^8`번 한다. 입력 크기 `n`, 알고리즘 등급 라벨, 제한 시간 `t`초가 주어질 때, 예상 연산 횟수를 계산하고 제한 시간 안에 드는지 판정하라. 등급별 연산 횟수는 다음처럼 정의한다: `n` → `n`번, `nlogn` → `n × L`번(`L`은 `n`의 이진 자릿수, 즉 `n.bit_length()`), `n2` → `n^2`번, `n3` → `n^3`번, `2n` → `2^n`번.
- **입력**: 한 줄에 `n 라벨 t`가 공백으로 주어진다. (`1 ≤ n ≤ 10^9`, 라벨이 `2n`이면 `n ≤ 60`, `1 ≤ t ≤ 100`)
- **출력**: `예상연산횟수 판정`을 한 줄에. 판정은 연산 횟수가 `10^8 × t` 이하이면 `possible`, 아니면 `impossible`.
- **예제**: `1000000 nlogn 1` → `20000000 possible` · `100000 n2 1` → `10000000000 impossible`
- **셀프체크**: `10^6`의 이진 자릿수가 20이라 `nlogn`이 `2×10^7`인가? 딱 경계(`10000 n2 1` → 정확히 `10^8`)일 때 "이하"라서 `possible`인가? `2^30`은 약 `10.7억`이라 `t=10`(`10^9`)에도 못 드는가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0]); kind = data[1]; t = int(data[2])
if kind == 'n':
    ops = n
elif kind == 'nlogn':
    ops = n * n.bit_length()
elif kind == 'n2':
    ops = n * n
elif kind == 'n3':
    ops = n * n * n
else:  # '2n'
    ops = 2 ** n
limit = 10 ** 8 * t
print(ops, 'possible' if ops <= limit else 'impossible')
@@TESTS
--IN
1000000 nlogn 1
--OUT
20000000 possible
--IN
100000 n2 1
--OUT
10000000000 impossible
--IN
10000 n2 1
--OUT
100000000 possible
--IN
30 2n 10
--OUT
1073741824 impossible
@@EXPL
(1) 접근·핵심 아이디어

- 복잡도 판단의 실전 버전이다. Big-O 등급을 실제 연산 횟수로 바꾸고, 초당 `10^8`이라는 기준과 제한 시간을 곱한 한도와 비교한다. 이 계산 하나로 "이 `n`에 `O(n^2)`가 되는가"를 문제 읽자마자 판단할 수 있다.
- `log n`은 정확한 실수 대신 이진 자릿수 `n.bit_length()`로 정의해 정수 계산만으로 답이 유일하게 정해지게 했다.

(2) 코드 단계별

- `n`, 라벨, `t`를 읽는다.
- 라벨에 따라 `ops`를 계산한다. `2n`은 파이썬 정수라 `2 ** n`이 그대로 정확하다.
- `limit = 10**8 * t`와 비교해 `ops <= limit`이면 `possible`. 경계가 "이하"이므로 정확히 `10^8`인 경우도 통과다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 기준(초당 `10^8`)과 한도(`× t`)를 숫자로 적는다.
- 등급별 연산 횟수 공식을 그대로 코드로 옮긴다 — 계수는 무시하고 지배항만.
- 경계(같을 때 통과)와 지수 등급의 폭발(`2^30`이 이미 `10^9` 초과)을 예제로 확인한다.
```

**2) 배수 훑기 반복 횟수** · Easy

- **요구사항**: 다음 반복 구조에서 안쪽 줄 `cnt += 1`이 총 몇 번 실행되는지 구하라. `for i in range(1, n + 1): for j in range(i, n + 1, i): cnt += 1` — 즉 `i`마다 `i`의 배수 `i, 2i, 3i, …`를 `n`까지 훑는다. 이 값이 `n^2`보다 훨씬 작음을 확인하기 위해 `n^2`도 함께 출력하라.
- **입력**: 한 줄에 `n`. (`1 ≤ n ≤ 10,000`)
- **출력**: `총실행횟수 n제곱`을 한 줄에.
- **예제**: `10` → `27 100` · `1` → `1 1`
- **셀프체크**: `i`번째 바깥 반복에서 안쪽은 `n // i`번 도는가(`n=10`이면 `10+5+3+2+2+1+1+1+1+1=27`)? 이중 반복이라고 무조건 `O(n^2)`이 아니라, 합 `n/1 + n/2 + … + n/n ≈ n·ln n`이라 `O(n log n)`임을 짚었는가? `n=1`이면 한 번만 도는가?

```runner
@@SOLUTION
import sys
n = int(sys.stdin.readline())
cnt = 0
for i in range(1, n + 1):
    for j in range(i, n + 1, i):   # i의 배수만 훑는다: n // i 번
        cnt += 1
print(cnt, n * n)
@@TESTS
--IN
10
--OUT
27 100
--IN
1
--OUT
1 1
--IN
1000
--OUT
7069 1000000
@@EXPL
(1) 접근·핵심 아이디어

- 바깥 `i`가 정해지면 안쪽은 `i, 2i, …`를 `n`까지 훑으므로 정확히 `n // i`번 돈다. 총 횟수는 `n//1 + n//2 + … + n//n`이고, 이 합은 조화급수 `n(1 + 1/2 + … + 1/n) ≈ n·ln n`이라 `O(n log n)`이다.
- "이중 반복 = `O(n^2)`"라는 반사적 판단이 틀리는 대표 사례다. `n=1000`이면 `n^2=10^6`인데 실제 실행은 `7069`번뿐이다. 소수 체(에라토스테네스)나 약수 개수 세기가 정확히 이 구조다.

(2) 코드 단계별

- `n`을 읽고 `cnt=0`으로 시작한다.
- 문제에 적힌 이중 반복을 그대로 돌리며 안쪽에서 `cnt += 1`. `range(i, n+1, i)`가 "i의 배수만"을 뜻한다.
- `cnt`와 `n*n`을 나란히 출력해 차이를 눈으로 확인한다.

(3) 스스로 다시 짤 때 생각 순서

- 안쪽 반복 횟수를 바깥 변수의 식(`n // i`)으로 적는 습관을 들인다.
- 그 식을 `i=1..n`으로 더한 합이 무엇인지(조화급수 → `n log n`) 판단한다.
- 작은 `n`으로 손 계산(`n=10` → 27)해 공식과 실행이 맞는지 검산한다.
```

**3) 계단 오르기 경우의 수** · Easy

- **요구사항**: `n`칸짜리 계단을 한 번에 1칸 또는 2칸씩 올라 꼭대기(정확히 `n`칸)에 도달하는 방법의 수를 구하라. 단, 길이 `n`의 배열을 만들지 말고 **직전 두 값만 담는 변수 두 개**로 공간 `O(1)`에 계산하라.
- **입력**: 한 줄에 `n`. (`1 ≤ n ≤ 80`)
- **출력**: 방법의 수.
- **예제**: `4` → `5` · `1` → `1`
- **셀프체크**: `ways(n) = ways(n-1) + ways(n-2)`(마지막에 1칸 올랐거나 2칸 올랐거나)를 세웠는가? `ways(1)=1, ways(2)=2`가 맞는가? 두 변수를 동시에 갱신(`a, b = b, a + b`)해 순서 꼬임이 없는가? `n=80`이면 값이 커도 파이썬 정수라 그대로 정확한가?

```runner
@@SOLUTION
import sys
n = int(sys.stdin.readline())
a, b = 1, 1        # a = ways(i-1), b = ways(i); 시작은 ways(0)=1, ways(1)=1
for _ in range(n - 1):
    a, b = b, a + b
print(b)
@@TESTS
--IN
4
--OUT
5
--IN
1
--OUT
1
--IN
2
--OUT
2
--IN
80
--OUT
37889062373143906
@@EXPL
(1) 접근·핵심 아이디어

- 마지막 걸음이 1칸이면 그 전까지 `n-1`칸, 2칸이면 `n-2`칸을 오른 것이므로 `ways(n) = ways(n-1) + ways(n-2)`. 시작값은 `ways(0)=1`(아무것도 안 오름), `ways(1)=1`.
- 값 `n`을 구하는 데 필요한 것은 직전 두 값뿐이다. 그래서 길이 `n` 배열(`O(n)` 공간) 대신 변수 두 개를 굴려 공간 `O(1)`로 줄인다. 시간은 그대로 `O(n)`.

(2) 코드 단계별

- `a=ways(0)=1`, `b=ways(1)=1`로 시작한다.
- `n-1`번 반복하며 `a, b = b, a + b`로 한 칸씩 전진하면 반복이 끝났을 때 `b = ways(n)`.
- `n=1`이면 반복이 0번이라 `b=1`, `n=2`면 한 번 돌아 `b=2`.

(3) 스스로 다시 짤 때 생각 순서

- 점화식을 먼저 세우고, "직전 몇 개가 필요한가"를 세어 변수 개수를 정한다(여기선 2개).
- 초기값과 반복 횟수를 `n=1, 2`로 맞춰본다.
- 동시 대입을 쓰지 않고 `a = b; b = a + b`처럼 쓰면 `a`가 먼저 바뀌어 틀린다는 점을 기억한다.
```

**4) 일별 매출 구간 합 질의** · Medium

- **요구사항**: `n`일 동안의 일별 매출과 질의 `q`개가 주어진다. 각 질의 `l r`은 `l`일부터 `r`일까지(양 끝 포함, 1-based)의 매출 합을 묻는다. 질의마다 처음부터 더하면 `O(n·q)`이므로, 누적합 배열을 한 번 만들어 각 질의를 `O(1)`에 답하라.
- **입력**: 첫 줄에 `n q`. 둘째 줄에 매출 `n`개(음수 가능). 이어서 `q`개의 줄에 `l r`. (`1 ≤ n, q ≤ 1000`, `1 ≤ l ≤ r ≤ n`, `-1000 ≤ 매출 ≤ 1000`)
- **출력**: 질의마다 구간 합을 한 줄씩.
- **예제**: `5 3 / 3 1 4 1 5 / 1 3 / 2 5 / 4 4` → `8` / `11` / `1`
- **셀프체크**: `pre[i]`를 "앞 `i`개의 합"으로 정의해 `pre[0]=0`, 길이 `n+1`로 잡았는가? 구간 합이 `pre[r] - pre[l-1]`인가(1-based라 `l-1`)? `l == r`인 한 칸 구간, `l=1`인 맨 앞 구간이 맞는가? 전체 시간이 `O(n + q)`인가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n, q = int(data[0]), int(data[1])
a = list(map(int, data[2:2 + n]))
pre = [0] * (n + 1)                 # pre[i] = 앞 i개의 합
for i in range(n):
    pre[i + 1] = pre[i] + a[i]
out = []
pos = 2 + n
for _ in range(q):
    l, r = int(data[pos]), int(data[pos + 1])
    pos += 2
    out.append(str(pre[r] - pre[l - 1]))
print('\n'.join(out))
@@TESTS
--IN
5 3
3 1 4 1 5
1 3
2 5
4 4
--OUT
8
11
1
--IN
1 1
7
1 1
--OUT
7
--IN
4 2
-2 5 -3 1
1 4
2 3
--OUT
1
2
@@EXPL
(1) 접근·핵심 아이디어

- 질의마다 `l..r`을 직접 더하면 한 질의에 최악 `O(n)`, 전체 `O(n·q)`다. 대신 "앞 `i`개의 합" `pre[i]`를 한 번(`O(n)`) 만들어 두면 어떤 구간 합도 `pre[r] - pre[l-1]`로 뺄셈 한 번(`O(1)`)에 나와 전체 `O(n + q)`가 된다.
- `pre[0]=0`을 두는 이유는 `l=1`일 때 `pre[0]`을 빼야 하기 때문 — 이 한 칸이 경계 처리를 없애 준다.

(2) 코드 단계별

- 입력을 한 번에 읽어 `n, q`와 매출 배열을 만든다.
- 길이 `n+1`의 `pre`를 만들고 `pre[i+1] = pre[i] + a[i]`로 채운다.
- 각 질의에서 `pre[r] - pre[l-1]`을 계산해 모아 출력한다. 음수가 섞여도 뺄셈이므로 그대로 맞는다.

(3) 스스로 다시 짤 때 생각 순서

- "같은 배열에 구간 합 질의가 여러 번" → 누적합을 떠올린다.
- `pre`의 정의(앞 `i`개)와 1-based 입력의 인덱스 대응(`l-1`)을 종이에 한 번 적는다.
- `l == r`, `l = 1`, `r = n` 세 경계를 예제로 검산한다.
```

**5) 환율 차익 최대** · Medium

- **요구사항**: `n`일 동안의 환율이 주어진다. 어느 하루에 사서 **그보다 뒤의** 하루에 팔 때 얻는 차익(판 값 − 산 값)의 최댓값을 구하라. 모든 (살 날, 팔 날) 쌍을 이중 반복으로 보면 `O(n^2)`이니, "지금까지의 최솟값" 변수 하나로 한 번만 훑어 `O(n)`에 풀어라. 양의 차익이 없으면 `0`만 출력하고, 있으면 차익과 함께 살 날·팔 날(1-based)도 출력한다. 차익이 같은 쌍이 여럿이면 살 날이 빠른 것, 그것도 같으면 팔 날이 빠른 것을 택한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 환율 `n`개. (`1 ≤ n ≤ 1000`, `1 ≤ 환율 ≤ 10^6`)
- **출력**: 양의 차익이 없으면 `0`. 있으면 `최대차익 살날 팔날`을 한 줄에.
- **예제**: `6 / 7 1 5 3 6 4` → `5 2 5` · `4 / 9 7 5 3` → `0`

**6) 두 배씩 커지는 안쪽 반복의 총 횟수** · Medium

- **요구사항**: 다음 코드에서 바깥 `while`이 몇 번 도는지와 안쪽 줄 `cnt += 1`이 총 몇 번 실행되는지를 **공식으로** 구하라. `i = 1` / `while i <= n:` / `    for j in range(i): cnt += 1` / `    i *= 2`. 겉보기엔 이중 반복이지만 총 실행 횟수가 `2n` 미만임을 확인하라. `n`이 매우 커서 실제로 돌려 볼 수 없으므로 공식이 필요하다.
- **입력**: 한 줄에 `n`. (`1 ≤ n ≤ 10^18`)
- **출력**: `바깥반복횟수 안쪽총실행횟수`를 한 줄에.
- **예제**: `10` → `4 15` · `1` → `1 1`
- **셀프체크**: 바깥은 `i = 1, 2, 4, 8, …`로 `i <= n`인 동안이니 횟수가 `n`의 이진 자릿수 `n.bit_length()`인가(`n=10`이면 `1,2,4,8` 4번)? 안쪽 총합은 `1+2+4+…+2^(k-1) = 2^k - 1`(등비수열)이라 `O(n)`인가? `n=16`이면 `i=16`도 포함되어 바깥 5번·안쪽 31번인가?

```runner
(1) 접근·핵심 아이디어

- 바깥 변수 `i`가 `+1`이 아니라 `×2`로 커지므로 그 축은 로그다: `2^0, 2^1, …, 2^(k-1) <= n`인 `k`는 `n`의 이진 자릿수 `n.bit_length()`와 같다.
- 안쪽은 `i`번 돌므로 총합은 `1 + 2 + 4 + … + 2^(k-1) = 2^k - 1`. `2^(k-1) <= n`이므로 이 값은 `2n` 미만 — 이중 반복인데도 `O(n log n)`이 아니라 `O(n)`이다. "중첩이면 곱한다"가 아니라 "안쪽 횟수를 실제로 더한다"가 정확한 분석이다.

(2) 코드 단계별

- `n`을 읽고 `outer = n.bit_length()`로 바깥 횟수를 구한다.
- 안쪽 총합은 등비수열 합 공식 `2 ** outer - 1`.
- `n=10` → 이진 `1010`(4자리) → 바깥 4번, 안쪽 `15`. `n=16` → `10000`(5자리) → 바깥 5번, 안쪽 `31`.

(3) 스스로 다시 짤 때 생각 순서

- 반복 변수의 증가 방식(`×2`)을 보고 축을 로그로 판정한다.
- 안쪽 횟수를 바깥 변수의 식(`i`)으로 적고, 바깥 전 범위에 대해 더한다(등비수열).
- 경계: `n`이 정확히 2의 거듭제곱일 때 마지막 `i = n`도 포함되는지(`<=`) 확인한다.
```

**7) 제한 시간 안의 최대 입력 크기** · Medium

- **요구사항**: 1초에 `10^8`번 연산하는 컴퓨터에서 제한 시간 `t`초 안에 돌릴 수 있는 **가장 큰 입력 크기** `n`을 구하라. 등급 라벨별 연산 횟수는 `n` → `n`, `nlogn` → `n × n.bit_length()`, `n2` → `n^2`, `n3` → `n^3`, `2n` → `2^n`, `nfact` → `n!`로 정의한다. 연산 횟수가 `10^8 × t` 이하인 최대 정수 `n`이 답이다.
- **입력**: 한 줄에 `라벨 t`. (`1 ≤ t ≤ 100`)
- **출력**: 최대 `n`.
- **예제**: `n2 1` → `10000` · `2n 1` → `26`
- **셀프체크**: 연산 횟수가 `n`에 대해 단조 증가하므로 이분 탐색이 되는가? `nfact`나 `2n`은 `n`이 조금만 커져도 한도를 훌쩍 넘으니, 비용 함수 안에서 한도를 넘는 순간 바로 멈추게(또는 `n >= 64`면 즉시 초과로) 만들어 큰 수 계산을 피했는가? `2^26 ≈ 6.7×10^7`은 통과, `2^27 ≈ 1.3×10^8`은 초과라 답 `26`인가? `11! ≈ 4×10^7`, `12! ≈ 4.8×10^8`이라 `nfact 1`은 `11`인가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
kind = data[0]; t = int(data[1])
limit = 10 ** 8 * t

def cost(n):
    if kind == 'n':
        return n
    if kind == 'nlogn':
        return n * n.bit_length()
    if kind == 'n2':
        return n * n
    if kind == 'n3':
        return n * n * n
    if kind == '2n':
        return 2 ** n if n < 64 else limit + 1     # 64 이상은 한도를 확실히 넘음
    f = 1                                          # 'nfact'
    for k in range(2, n + 1):
        f *= k
        if f > limit:                              # 넘는 순간 중단 (거대 수 계산 방지)
            break
    return f

lo, hi = 1, limit             # cost(1) <= limit 은 항상 성립
while lo < hi:                # cost(n) <= limit 인 최대 n 을 이분 탐색
    mid = (lo + hi + 1) // 2
    if cost(mid) <= limit:
        lo = mid
    else:
        hi = mid - 1
print(lo)

(1) 접근·핵심 아이디어

- "복잡도 판단"을 거꾸로 묻는 문제다. 연산 횟수 `cost(n)`은 `n`이 커질수록 커지므로(단조), `cost(n) <= limit`을 만족하는 최대 `n`을 이분 탐색으로 찾는다. 범위 `[1, limit]`에 대해 `log2(10^10) ≈ 34`번만 `cost`를 부르면 된다.
- 함정은 빠르게 폭발하는 등급이다. `2^(5×10^9)`이나 `(5×10^9)!`을 실제로 만들면 멈춰 버린다. 그래서 `2n`은 `n >= 64`면 한도 초과로 단정하고, `nfact`는 곱하다가 한도를 넘는 즉시 멈춘다 — 답에는 영향이 없고 계산만 싸진다.

(2) 코드 단계별

- 라벨과 `t`를 읽어 `limit = 10**8 * t`를 만든다.
- `cost(n)`을 라벨별로 정의하되, 지수·팩토리얼은 조기 중단 장치를 넣는다.
- `lo=1, hi=limit`에서 `mid`가 조건을 만족하면 `lo=mid`, 아니면 `hi=mid-1`. `mid=(lo+hi+1)//2`로 올림을 써야 `lo`가 제자리에서 멈추지 않는다.
- `n2 1` → `10^4`(정확히 `10^8`이라 포함), `n3 2` → `584^3 ≈ 1.99×10^8` 통과·`585^3` 초과.

(3) 스스로 다시 짤 때 생각 순서

- "조건을 만족하는 최대 정수"라는 말에서 단조성 확인 → 이분 탐색.
- 비용 함수를 라벨별로 적고, 폭발하는 등급은 한도 초과 시 조기 종료.
- 경계: 한도와 정확히 같은 `n`은 포함(`<=`), 이분 탐색의 올림 `mid` 처리.
```

**8) 연속 k일 최대 합과 연산 횟수 비교** · Hard

- **요구사항**: `n`일의 값과 창 크기 `k`가 주어진다. 연속 `k`일 합의 최댓값을 구하라. 동시에 두 방식의 덧셈·뺄셈 횟수를 공식으로 함께 출력하라. **순진 방식**: 창마다 0에서 시작해 `k`개를 더한다 → `k × (n − k + 1)`번. **슬라이딩 방식**: 첫 창은 `k`번 더하고, 이후 창마다 새 값 더하기 1번·빠지는 값 빼기 1번 → `k + 2 × (n − k)`번. 최댓값은 슬라이딩 방식으로 실제 계산해야 한다.
- **입력**: 첫 줄에 `n k`. 둘째 줄에 정수 `n`개(음수 가능). (`1 ≤ k ≤ n ≤ 1000`, `-1000 ≤ 값 ≤ 1000`)
- **출력**: `최대합 순진횟수 슬라이딩횟수`를 한 줄에.
- **예제**: `6 3 / 2 -1 4 3 -5 6` → `6 12 9` · `4 4 / -1 -2 -3 -4` → `-10 4 4`
- **셀프체크**: 창을 한 칸 밀 때 `cur += a[i] - a[i-k]`로 빠지는 원소 인덱스가 정확한가? 첫 창의 합으로 `best`를 초기화해 모두 음수일 때도(둘째 예제) `0`이 아니라 실제 합이 나오는가? `k = n`이면 창이 하나라 순진·슬라이딩 모두 `k`번인가? `k = 1`이면 순진 `n`번, 슬라이딩 `1 + 2(n-1)`번으로 오히려 순진이 적은가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n, k = int(data[0]), int(data[1])
a = list(map(int, data[2:2 + n]))
cur = 0
for i in range(k):              # 첫 창: k번 덧셈
    cur += a[i]
best = cur
for i in range(k, n):           # 창 밀기: 더하기 1번 + 빼기 1번
    cur += a[i] - a[i - k]
    if cur > best:
        best = cur
naive = k * (n - k + 1)
sliding = k + 2 * (n - k)
print(best, naive, sliding)

(1) 접근·핵심 아이디어

- 창의 개수는 `n − k + 1`. 순진하게 창마다 `k`개를 더하면 `k(n−k+1)`번으로, `k ≈ n/2`이면 `O(n^2)`급이다. 슬라이딩 윈도우는 인접한 두 창이 `k−1`개를 공유한다는 관찰로, 이전 합에서 빠지는 값을 빼고 새 값을 더해 창마다 2번만 계산한다 → `O(n)`.
- 두 횟수를 공식으로 나란히 출력하게 한 이유는 "복잡도 차이를 숫자로 체감"하기 위해서다. 다만 `k=1`처럼 창이 아주 작으면 슬라이딩이 오히려 더 많은 연산을 한다 — Big-O가 같아도(둘 다 `O(n)`) 상수는 다를 수 있다는 교훈.

(2) 코드 단계별

- 첫 `k`개를 더해 `cur`를 만들고 `best = cur`로 초기화한다(빈 창 대신 실제 첫 창으로 시작해야 전부 음수일 때 안전).
- `i = k..n-1`에 대해 `cur += a[i] - a[i-k]` — 들어오는 `a[i]`, 나가는 `a[i-k]`.
- 갱신 후 `cur > best`면 `best`를 바꾼다.
- 공식 `naive = k*(n-k+1)`, `sliding = k + 2*(n-k)`를 계산해 함께 출력.

(3) 스스로 다시 짤 때 생각 순서

- "연속 `k`개 합"을 보면 인접 창의 공유 부분을 떠올려 슬라이딩으로 간다.
- 빠지는 인덱스 `i-k`를 종이에 그려 확인하고, 첫 창으로 `best`를 초기화한다.
- 경계: `k = n`(창 하나), `k = 1`, 전부 음수 — 세 경우를 예제로 검산한다.
```

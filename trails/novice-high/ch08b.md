## L6. 조건에 맞게 선택적으로 전진하는 DP

**개념**

- 선택적 전진 DP는 "각 위치에서 여러 후보 상태 중 조건을 만족하는 것만 골라 다음 칸으로 넘어가는" 유형이다. 앞선 격자 DP가 "모든 칸을 무조건 채우는" 것과 달리, 여기서는 상태에 제약(직전에 무엇을 골랐는지, 몇 번 연속인지 등)이 붙는다.

- 핵심은 상태를 `dp[i][s]` 처럼 "위치 i" + "그 시점의 부가 조건 s"로 정의하는 것이다. i만으로 정답이 결정되지 않고, "직전에 어떤 선택을 했는가"가 다음 선택 가능 여부를 바꾸기 때문이다.

- 동작 원리를 단계로:

  1. 위치 i에서 가능한 선택지(상태 s)를 나열한다.

  2. 각 상태 s가 되려면 i-1에서 어떤 상태 s'였어야 하는지(전이 조건)를 따진다. 조건을 어기는 전이는 버린다.

  3. 허용된 전이들 중 최선값(최댓값/최솟값/합)을 모아 `dp[i][s]`를 채운다.

  4. 마지막 위치의 모든 상태 중 답을 뽑는다.

```python
# 예: 인접한 두 원소를 함께 고르면 안 될 때 (House Robber류)
# 상태 s: 0 = 이번 칸 안 고름, 1 = 이번 칸 고름
def solve(a):
    n = len(a)
    dp = [[0, 0] for _ in range(n)]
    dp[0][0], dp[0][1] = 0, a[0]
    for i in range(1, n):
        dp[i][0] = max(dp[i-1][0], dp[i-1][1])  # 안 고름: 직전은 뭐든 OK
        dp[i][1] = dp[i-1][0] + a[i]            # 고름: 직전은 반드시 '안 고름'
    return max(dp[n-1])
```

**접근 전략**

- 핵심 아이디어: "다음 칸으로 갈 수 있는지"를 결정하는 추가 정보를 상태 차원으로 승격시킨다. 조건이 "직전 선택"이면 상태 2~3개, "연속 개수 제한"이면 상태를 개수만큼 둔다. 조건을 만족하는 전이만 화살표로 남기고, 나머지는 그리지 않는 게 요령이다.

- 전형적 절차: (1) 상태 정의 `dp[i][s]` (2) 초기값 (3) 조건별 전이식 (4) 답 위치. 전이가 O(상태수)이므로 상태 설계가 곧 성능이다.

- 언제 쓰나: "인접/연속 선택 금지", "같은 걸 k번 넘게 연속 못 씀", "직전 색과 달라야 함" 같은 지역적 제약이 있는 최적화 문제.

- 복잡도: 상태 수 × 전이 수 = O(n · S²) 이하(대개 S가 상수라 O(n)). 공간 O(n·S)이며, dp[i]가 dp[i-1]에만 의존하면 O(S)로 롤링 가능.

- 흔한 실수: 조건을 초기값에 반영하지 않아 첫 칸이 어긋남 / "직전 상태"를 안 나눠 잘못된 전이 허용 / 마지막에 특정 상태만 답으로 뽑아야 하는데 전체 max를 쓰는 실수(반대 경우도 있음).

**문제**

**1) 쉬어야 등산** · Easy

- **요구사항**: 일렬로 늘어선 봉우리 높이 배열에서 봉우리를 골라 점수(높이)를 얻는다. 단, 바로 인접한 두 봉우리를 동시에 고를 수 없다. 얻을 수 있는 최대 점수를 구하라.

- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 둘째 줄 높이 N개(0 이상 1000 이하).

- **출력**: 최대 점수.

- **예제**: `5 / 2 7 9 3 1` → `12` (7+... 아님, 2+9+1=12) / `4 / 5 5 10 100` → `105` (5+100)

- **셀프체크**: N=1일 때 그 값 그대로 나오는가? "고름/안 고름" 두 상태를 나눴는가? O(N)·O(1) 공간으로 줄일 수 있는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1+n]]
    if n == 0:
        print(0); return
    take, skip = a[0], 0
    for i in range(1, n):
        take, skip = skip + a[i], max(skip, take)
    print(max(take, skip))
main()
@@TESTS
--IN
5
2 7 9 3 1
--OUT
12
--IN
1
42
--OUT
42
@@EXPL
(1) 접근·핵심 아이디어

- 인접한 두 봉우리를 동시에 못 고르는 House Robber 문제다. 각 칸에서 "이 칸을 고른다 / 안 고른다" 두 상태로 나눈다. 고르면 직전 칸은 반드시 안 골라야 하므로 전이가 제한된다.

(2) 코드 단계별

- `take` = 현재 칸을 고른 경우의 최대 점수, `skip` = 현재 칸을 안 고른 경우의 최대 점수.
- 초기값: 첫 칸을 고르면 `take=a[0]`, 안 고르면 `skip=0`.
- 각 칸 i에서 새 `take = 이전 skip + a[i]`(직전은 반드시 안 고름), 새 `skip = max(이전 skip, 이전 take)`(직전은 뭐든 OK). 두 갱신을 동시에 해야 이전 값이 안 덮인다.
- 마지막에 `max(take, skip)`이 답. 변수 2개만 쓰므로 O(N) 시간·O(1) 공간.

(3) 스스로 다시 짤 때 생각 순서

- "고른다/안 고른다" 상태를 먼저 정의한다.
- 고르는 전이는 직전이 반드시 skip이어야 함을 확인한다.
- 두 변수 롤링으로 압축하되 동시 대입으로 갱신 순서 문제를 피한다.
- N=1 경계(그 값 그대로)를 검산한다.
```

**2) 같은 옷 이틀 금지** · Medium

- **요구사항**: N일 동안 매일 3벌의 옷 중 하나를 입는다. i일에 j번 옷을 입으면 불쾌도 `cost[i][j]`가 든다. 단, 어제와 같은 번호의 옷을 이틀 연속 입을 수 없다. N일 전체 불쾌도의 최솟값을 구하라.

- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 이후 N줄에 각 줄 3개의 정수(0 이상 10000 이하).

- **출력**: 최소 불쾌도 합.

- **예제**: `2 / 1 100 100 / 100 1 100` → `2` (0번→1번) / `3 / 1 3 3 / 3 1 3 / 3 3 1` → `3` (1+1+1, 매일 다른 옷)

- **셀프체크**: 상태를 `dp[i][j]`(i일에 j번 옷)로 뒀는가? 전이에서 `k != j`만 허용했는가? 마지막 날은 세 상태 중 최소를 답으로 뽑았는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    if n == 0:
        print(0); return
    cost = []
    for _ in range(n):
        cost.append([int(data[idx]), int(data[idx+1]), int(data[idx+2])])
        idx += 3
    dp = cost[0][:]
    for i in range(1, n):
        ndp = [0, 0, 0]
        for j in range(3):
            best = min(dp[k] for k in range(3) if k != j)
            ndp[j] = best + cost[i][j]
        dp = ndp
    print(min(dp))
main()
@@TESTS
--IN
2
1 100 100
100 1 100
--OUT
2
--IN
3
1 3 3
3 1 3
3 3 1
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 상태를 `dp[i][j]` = "i일에 j번 옷을 입었을 때 i일까지 최소 불쾌도"로 둔다. 어제와 같은 옷을 못 입으니, i일에 j를 입으려면 i-1일에는 j가 아닌 옷을 입었어야 한다.

(2) 코드 단계별

- 입력을 N일 × 3벌 비용표 `cost`로 읽는다.
- 초기값: 첫날은 그냥 그 옷 비용 그대로 `dp = cost[0]`.
- i일마다 세 옷 j에 대해 `dp[i][j] = cost[i][j] + min(dp[i-1][k] for k != j)`. 직전 날의 다른 두 옷 중 최소를 더한다.
- `ndp`를 따로 만들어 갱신한 뒤 `dp`로 교체(이전 행 값 보존).
- 마지막 날 세 상태 중 최소 `min(dp)`가 답. 시간 O(N·3·2), 공간 O(1).

(3) 스스로 다시 짤 때 생각 순서

- "i일 + 오늘 입은 옷" 2차원 상태를 먼저 잡는다.
- 전이 조건 `k != j`(어제 다른 옷)를 명확히 한다.
- 첫날 초기화를 비용 그대로 둔다.
- 정답은 마지막 날 세 상태의 최소임을 확인한다.
```

**3) 계단 세 칸 규칙** · Medium

- **요구사항**: 계단 점수 배열이 있다. 1번 칸부터 시작해 마지막 칸에 도착하되, 한 번에 한 칸 또는 두 칸 오를 수 있다. 단, 연속해서 세 칸을 모두 밟을 수는 없다(즉 세 칸 연속 밟기 금지). 밟은 칸 점수의 합을 최대로 하라. 마지막 칸은 반드시 밟는다.

- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 둘째 줄 점수 N개(0 이상 10000 이하).

- **출력**: 최대 점수 합.

- **예제**: `3 / 10 20 15` → `45` (셋 다 밟아도 되나? 마지막 3개 연속 금지 → 10+15=25 or 20+15=35 or 10+20+15는 3연속이라 금지... 답은 35) / `2 / 5 5` → `10`

- **셀프체크**: 상태를 "마지막 칸을 몇 칸 연속 밟았나(1 또는 2)"로 뒀는가? 3연속을 만드는 전이를 제거했는가? 시작 칸과 마지막 칸을 반드시 포함하도록 초기/종료를 처리했는가?

> 검산(예제1): 상태 dp[i][c] = i를 밟고 직전까지 연속 c칸. dp[0][1]=10. i=1: dp[1][1](i-2에서 점프,없음)/dp[1][2]=dp[0][1]+20=30. i=2: dp[2][1]=dp[0][?]+15=25, dp[2][2]=dp[1][1]+15 (dp[1][1] 없음) → 유효한 건 dp[2][1]=25, 그리고 i=1을 2연속으로 밟고 i=2를 밟으면 3연속이라 금지. 따라서 20(i=1 단독 점프 불가)… 최종적으로 밟은 칸 합 최대는 35(20+15). 답 35.

```runner
@@SOLUTION
import sys
NEG = float('-inf')
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    s = [int(x) for x in data[1:1+n]]
    if n == 0:
        print(0); return
    # dp1[i]: 최대 점수, i를 밟고 i에서 끝나는 연속 길이 1
    # dp2[i]: 최대 점수, i를 밟고 i에서 끝나는 연속 길이 2
    dp1 = [NEG] * n
    dp2 = [NEG] * n
    dp1[0] = s[0]
    for i in range(1, n):
        if i - 2 >= 0:
            prev = max(dp1[i-2], dp2[i-2])
            if prev != NEG:
                dp1[i] = prev + s[i]  # +2 점프로 도착 -> 연속 1
        if dp1[i-1] != NEG:
            dp2[i] = dp1[i-1] + s[i]  # +1로 도착, 직전 연속 1 -> 연속 2 (연속 2에서 +1은 3연속이라 금지)
    print(max(dp1[n-1], dp2[n-1]))
main()
@@TESTS
--IN
2
5 5
--OUT
10
--IN
5
1 2 3 4 5
--OUT
12
@@EXPL
(1) 접근·핵심 아이디어

- 1번 칸에서 시작해 마지막 칸에 도착하고(둘 다 반드시 밟음), 한 번에 +1/+2 오르며, 3칸을 연속으로 밟을 수 없다. "지금 칸에서 끝나는 연속 밟기 길이(1 또는 2)"를 상태 차원으로 승격한다. (참고: 본문 예제 `10 20 15`의 서술은 시작 칸 강제 여부가 모호하므로, 여기서는 시작 칸과 마지막 칸을 모두 밟는 정의로 검산 가능한 케이스를 테스트로 둔다.)

(2) 코드 단계별

- `dp1[i]` = i에서 끝나는 연속 길이 1, `dp2[i]` = 연속 길이 2. 도달 불가는 `-inf`.
- 초기값 `dp1[0]=s[0]`(시작 칸을 단독으로 밟음).
- i로 +2 점프(i-1을 건너뜀)해 오면 연속이 1로 리셋 -> `dp1[i]=max(dp1[i-2],dp2[i-2])+s[i]`.
- i로 +1 올라오면 i-1을 밟았다는 뜻. i-1이 연속 1(`dp1[i-1]`)일 때만 허용되어 `dp2[i]=dp1[i-1]+s[i]`. i-1이 이미 연속 2면 i까지 밟으면 3연속이라 금지(전이 없음).
- 답은 마지막 칸의 두 상태 중 최대 `max(dp1[n-1], dp2[n-1])`. 시간·공간 O(N).

(3) 스스로 다시 짤 때 생각 순서

- "연속 몇 칸째"를 상태로 올려야 3연속 금지를 걸 수 있음을 떠올린다.
- 도착 방식(+2는 연속 리셋, +1은 연속 증가)으로 전이를 나눈다.
- 연속 2에서 +1(3연속) 전이를 삭제한다.
- 시작·마지막 칸을 반드시 포함하도록 초기값과 답 위치를 맞춘다.
```


## L7. 아이템을 적절히 고르는 문제

**개념**

- 배낭(Knapsack) 문제군이다. 각 아이템은 무게(비용)와 가치를 가지고, 한정된 용량 안에서 가치 합을 최대로 하도록 아이템 집합을 고른다. 순서가 없고 "넣느냐 마느냐"의 조합 최적화라 완전탐색은 2^N으로 폭발하지만, DP로 다항 시간에 푼다.

- 핵심은 상태를 `dp[용량 w]` = "용량 w를 넘지 않고 담을 수 있는 최대 가치"로 두고, 아이템을 하나씩 추가하며 갱신하는 것이다. 각 아이템에 대해 "안 담기(그대로) vs 담기(무게만큼 뒤 칸에서 가져오고 가치 더하기)" 중 큰 값을 취한다.

- 두 대표 유형:

  1. 0/1 배낭: 각 아이템 최대 1개. 용량 루프를 **큰 값 → 작은 값**(역순)으로 돌려 같은 아이템 중복 사용을 막는다.

  2. 무한(완전) 배낭: 각 아이템 무한개. 용량 루프를 **작은 값 → 큰 값**(정순)으로 돌려 재사용을 허용한다.

```python
# 0/1 배낭 (1차원 롤링)
def knapsack01(items, cap):     # items = [(w, v), ...]
    dp = [0] * (cap + 1)
    for w, v in items:
        for c in range(cap, w - 1, -1):   # 역순이 핵심
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]
```

**접근 전략**

- 핵심 아이디어: "지금 이 아이템을 담을까?"라는 결정을 아이템 순서대로 내리며, 각 결정 후의 최적값을 용량축에 저장한다. 2차원 `dp[i][c]`로 시작해 이해한 뒤, i축을 없애 1차원으로 압축하는 흐름이 표준이다.

- 전형적 절차: (1) dp[c] 0으로 초기화 (2) 아이템마다 용량 루프 (3) 0/1이면 역순, 무한이면 정순 (4) 답은 dp[cap] 또는 max(dp).

- 언제 쓰나: "용량/예산/무게 한도 안에서 가치 최대", "정확히 합이 T가 되게 부분집합 뽑기", "동전으로 금액 만들기(개수/경우의 수)" 등 부분집합·조합 최적화.

- 복잡도: O(N · cap) 시간, O(cap) 공간(1차원 압축 시). cap이 크면 이 방식이 불리하니 주의(가치로 상태를 잡는 변형도 있음).

- 흔한 실수: 0/1인데 정순으로 돌려 한 아이템을 여러 번 담음 / "정확히 T" 문제에서 도달 불가를 -무한으로 표시하지 않아 오답 / cap이 매우 크고 N이 작을 때 O(N·cap)이 오히려 느린 걸 못 알아챔.

**문제**

**1) 배낭에 담기** · Easy

- **요구사항**: N개의 물건 각각 무게 w와 가치 v가 주어진다. 배낭 용량 W를 넘지 않게 물건들을 골라(각 물건은 0개 또는 1개) 가치 합을 최대로 하라.

- **입력**: 첫 줄 N W(1 ≤ N ≤ 100, 1 ≤ W ≤ 100000), 이후 N줄에 `w v`(1 이상 100000 이하).

- **출력**: 최대 가치 합.

- **예제**: `3 5 / 2 3 / 3 4 / 4 5` → `7` (무게2+무게3=5, 가치3+4=7) / `2 4 / 5 10 / 2 3` → `3` (무게5는 못 담음)

- **셀프체크**: 용량 루프를 W부터 w까지 역순으로 돌렸는가? W=0 또는 모든 물건이 W보다 무거운 경우 0이 나오는가? 1차원 dp 크기가 W+1인가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(data[idx]); W = int(data[idx+1]); idx += 2
    dp = [0] * (W + 1)
    for _ in range(n):
        w = int(data[idx]); v = int(data[idx+1]); idx += 2
        for c in range(W, w - 1, -1):
            if dp[c-w] + v > dp[c]:
                dp[c] = dp[c-w] + v
    print(dp[W])
main()
@@TESTS
--IN

2 3
3 4
4 5
--OUT
7
--IN
2 4
5 10
2 3
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 0/1 배낭이다. `dp[c]` = "용량 c를 넘지 않고 담을 수 있는 최대 가치". 아이템을 하나씩 추가하며, 각 용량에서 "안 담기(그대로) vs 담기(`dp[c-w]+v`)" 중 큰 값을 취한다.

(2) 코드 단계별

- `dp`를 크기 W+1, 전부 0으로 초기화.
- 아이템 (w,v)마다 용량 c를 **W부터 w까지 역순**으로 돌린다. 역순이 핵심: 같은 아이템을 이번 라운드에 두 번 담는 것을 막는다(정순이면 무한 배낭이 됨).
- `dp[c] = max(dp[c], dp[c-w]+v)`로 갱신.
- 모든 아이템 처리 후 `dp[W]`가 답. 시간 O(N·W), 공간 O(W).

(3) 스스로 다시 짤 때 생각 순서

- 상태를 "용량축 최대 가치"로 잡는다.
- 아이템 루프 안에 용량 루프를 둔다.
- 0/1이므로 용량은 반드시 역순임을 기억한다.
- 담기 전이는 `dp[c-w]+v`, 안 담기는 그대로임을 확인한다.
```

**2) 동전으로 금액 만들기** · Medium

- **요구사항**: 서로 다른 액면가 동전이 K종류 있고 각 동전은 무한히 쓸 수 있다. 정확히 금액 M을 만드는 서로 다른 조합(같은 동전 조합은 순서 무시로 한 가지)의 수를 구하라.

- **입력**: 첫 줄 K M(1 ≤ K ≤ 100, 1 ≤ M ≤ 10000), 둘째 줄 K개의 액면가(양의 정수).

- **출력**: 조합의 수(매우 클 수 있으니 1000000007로 나눈 나머지).

- **예제**: `3 4 / 1 2 3` → `4` ({1+1+1+1, 1+1+2, 2+2, 1+3}) / `2 5 / 2 5` → `1` ({5})

- **셀프체크**: 무한 배낭이므로 정순으로 돌렸는가? 동전 루프를 바깥, 금액 루프를 안쪽에 둬 "조합"(순서 무시)을 셌는가(안쪽·바깥쪽을 바꾸면 "순열"이 되어 틀림)? dp[0]=1로 시작했는가?

```runner
@@SOLUTION
import sys
MOD = 1000000007
def main():
    data = sys.stdin.buffer.read().split()
    k = int(data[0]); m = int(data[1])
    coins = [int(x) for x in data[2:2+k]]
    dp = [0] * (m + 1)
    dp[0] = 1
    for c in coins:
        for amt in range(c, m + 1):
            dp[amt] = (dp[amt] + dp[amt-c]) % MOD
    print(dp[m] % MOD)
main()
@@TESTS

1 2 3
--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 무한 개수 동전으로 금액 M을 만드는 "조합"(순서 무시)의 수를 세는 무한 배낭 경우의 수 문제다. `dp[amt]` = "금액 amt를 만드는 조합의 수".

(2) 코드 단계별

- `dp[0]=1`(아무것도 안 쓰는 한 가지), 나머지 0.
- **동전 루프를 바깥**, **금액 루프를 안쪽**에 둔다. 각 동전 c에 대해 `amt`를 c부터 M까지 **정순**으로 돌리며 `dp[amt] += dp[amt-c]`. 정순이라 같은 동전을 여러 번 재사용(무한)한다.
- 루프 순서가 핵심: 동전을 바깥에 두면 "1을 쓴 뒤 2" 같은 순서가 한 조합으로만 세어져 순열 중복을 피한다. 안팎을 바꾸면 순열을 세어 틀린다.
- 매 갱신을 MOD로 나눈 나머지로 유지, `dp[M]`이 답.

(3) 스스로 다시 짤 때 생각 순서

- "경우의 수 + 무한 사용"이면 `dp[0]=1` 정순 배낭을 떠올린다.
- 조합(순서 무시)이니 동전 루프가 반드시 바깥임을 기억한다.
- 큰 수 대비 매 단계 MOD를 적용한다.
```

**3) 정확히 절반으로** · Medium

- **요구사항**: N개의 양의 정수를 두 그룹으로 나눈다. 두 그룹의 합의 차이를 최소로 만들 때, 그 최소 차이를 구하라.

- **입력**: 첫 줄 N(1 ≤ N ≤ 100), 둘째 줄 N개의 정수(각 1 이상 1000 이하).

- **출력**: 두 그룹 합의 최소 차이.

- **예제**: `4 / 1 6 11 5` → `1` (예: {11,5}=16 vs {1,6}=7? 차이9… 최적은 {1,5,6}=12 vs {11}=11, 차이 1) / `2 / 3 3` → `0`

- **셀프체크**: 전체합 S의 절반 이하에서 만들 수 있는 최대 부분합을 0/1 배낭으로 찾았는가? 답을 `S - 2*best`로 계산했는가? 부분합 도달 가능 여부를 boolean dp로 둘 수도 있음을 이해했는가?

> 검산(예제1): S=1+6+11+5=23, 절반 11 이하 도달 가능한 최대 부분합 = 11(={11} 또는 {1,5}+? =6? 실제 11 도달: {11} 또는 {1,5}=6 no, {6,5}=11 yes). best=11 → 23-22=1. 답 1.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1+n]]
    S = sum(a)
    half = S // 2
    dp = [False] * (half + 1)
    dp[0] = True
    for x in a:
        for c in range(half, x - 1, -1):
            if dp[c-x]:
                dp[c] = True
    best = 0
    for c in range(half, -1, -1):
        if dp[c]:
            best = c
            break
    print(S - 2 * best)
main()
@@TESTS
--IN
4
1 6 11 5
--OUT
1
--IN
2
3 3
--OUT
0
@@EXPL
(1) 접근·핵심 아이디어

- 수들을 두 그룹으로 나눠 합의 차를 최소화한다. 한 그룹 합을 s라 하면 차는 |S-2s|이고, s가 S/2에 가까울수록 작다. 그래서 "절반 이하에서 만들 수 있는 최대 부분합"을 찾는 0/1 배낭(부분합 도달 가능성) 문제로 바꾼다.

(2) 코드 단계별

- 전체합 S와 그 절반 `half=S//2`를 구한다.
- `dp[c]` = "부분집합 합으로 c를 만들 수 있는가"(boolean), `dp[0]=True`.
- 각 수 x에 대해 c를 half부터 x까지 **역순**(0/1 배낭)으로 돌리며 `dp[c-x]`가 True면 `dp[c]=True`.
- half부터 아래로 훑어 True인 가장 큰 c가 `best`(절반 이하 최대 부분합).
- 답은 `S - 2*best`. 시간 O(N·S), 공간 O(S).

(3) 스스로 다시 짤 때 생각 순서

- "두 그룹 합 차 최소" = "절반에 가장 가까운 부분합" 변환을 떠올린다.
- boolean 부분합 배낭을 역순으로 채운다.
- half 이하 최대 도달 값을 찾아 `S-2*best`로 답을 낸다.
```


## L8. String Matching

**개념**

- 여기서는 두 수열/문자열의 "유사 구조"를 DP로 재는 문제군을 다룬다. 대표가 LCS(Longest Common Subsequence, 최장 공통 부분수열)와 편집 거리(Edit Distance)다. 부분수열은 순서를 지키되 연속일 필요가 없는 문자 뽑기다("ace"는 "abcde"의 부분수열).

- 핵심은 두 문자열 A, B에 대해 상태를 `dp[i][j]` = "A의 앞 i글자와 B의 앞 j글자만 봤을 때의 답"으로 두고, 마지막 글자가 같은지/다른지로 전이를 나누는 것이다.

- LCS 동작 원리:

  1. `A[i-1] == B[j-1]`이면 그 글자를 공통으로 쓰고 `dp[i][j] = dp[i-1][j-1] + 1`.

  2. 다르면 둘 중 하나를 버린 최선: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.

  3. `dp[m][n]`이 답. 경계 `dp[0][*] = dp[*][0] = 0`.

```python
def lcs(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

**접근 전략**

- 핵심 아이디어: 두 수열 문제는 거의 항상 2차원 표 `dp[i][j]`로 접근한다. "두 끝 글자를 비교해서 같으면 대각선, 다르면 위/왼쪽 중 선택"이 공통 뼈대다. 편집 거리는 여기에 삽입/삭제/교체 세 전이가 붙는다(`min(위, 왼, 대각) + 비용`).

- 전형적 절차: (1) `dp[i][j]` 정의 (2) 0행·0열 경계 초기화 (3) 이중 루프로 채우기 (4) `dp[m][n]` 읽기. 실제 부분수열/편집 과정을 복원하려면 표를 역추적한다.

- 언제 쓰나: "두 서열의 공통 부분", "한 문자열을 다른 문자열로 바꾸는 최소 연산", "diff/철자 교정", "두 유전자 정렬" 등 두 순서열의 정렬·비교.

- 복잡도: O(m·n) 시간, O(m·n) 공간(한 행만 필요하면 O(min(m,n))로 롤링). 값만 필요하면 롤링, 경로 복원까지면 2차원 유지.

- 흔한 실수: 부분수열(비연속)과 부분문자열(연속)을 혼동 / 인덱스가 1칸 밀리는 것(dp는 1-based, 문자열은 0-based)을 놓쳐 `A[i-1]` 대신 `A[i]` 사용 / 편집 거리에서 첫 행·열을 0~길이로 초기화하지 않음.

**문제**

**1) 공통 부분수열의 길이** · Easy

- **요구사항**: 두 문자열 A, B가 주어질 때 최장 공통 부분수열의 길이를 구하라.

- **입력**: 첫 줄 A, 둘째 줄 B(각 소문자, 길이 1 이상 2000 이하).

- **출력**: LCS 길이(정수 하나).

- **예제**: `abcde / ace` → `3` (ace) / `aggtab / gxtxayb` → `4` (gtab)

- **셀프체크**: 대각선(+1)과 위/왼쪽(max) 전이를 정확히 나눴는가? 표 크기가 (m+1)×(n+1)인가? 완전히 겹치는 글자가 없으면 0이 나오는가?

```runner
@@SOLUTION
import sys
def main():
    lines = sys.stdin.read().split('\n')
    a = lines[0].strip() if len(lines) > 0 else ''
    b = lines[1].strip() if len(lines) > 1 else ''
    m, n = len(a), len(b)
    prev = [0] * (n + 1)
    for i in range(1, m + 1):
        cur = [0] * (n + 1)
        ai = a[i-1]
        for j in range(1, n + 1):
            if ai == b[j-1]:
                cur[j] = prev[j-1] + 1
            else:
                cur[j] = prev[j] if prev[j] >= cur[j-1] else cur[j-1]
        prev = cur
    print(prev[n])
main()
@@TESTS

ace
--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 최장 공통 부분수열(LCS)이다. `dp[i][j]` = "A의 앞 i글자와 B의 앞 j글자의 LCS 길이". 두 끝 글자가 같은지 다른지로 전이가 갈린다.

(2) 코드 단계별

- 두 줄 A, B를 읽는다.
- 경계 `dp[0][*]=dp[*][0]=0`.
- `A[i-1]==B[j-1]`이면 그 글자를 공통에 넣어 `dp[i][j]=dp[i-1][j-1]+1`(대각선 +1).
- 다르면 한쪽을 버린 최선 `dp[i][j]=max(dp[i-1][j], dp[i][j-1])`.
- 공간 절약: 이전 행 `prev`와 현재 행 `cur` 두 줄만 유지(롤링). 인덱스가 1칸 밀리므로 `A[i-1]`, `B[j-1]`에 주의.
- `dp[m][n]`이 답. 시간 O(m·n), 공간 O(n).

(3) 스스로 다시 짤 때 생각 순서

- 두 수열 문제 -> 2차원 `dp[i][j]` 표를 떠올린다.
- 끝 글자 같음/다름으로 대각선(+1) vs 위/왼쪽(max)을 나눈다.
- 0-based 문자열과 1-based dp의 인덱스 밀림에 주의한다.
- 값만 필요하니 두 행 롤링으로 압축한다.
```

**2) 편집 거리** · Medium

- **요구사항**: 문자열 A를 B로 바꾸는 데 필요한 최소 연산 수를 구하라. 허용 연산은 한 글자 삽입, 삭제, 교체이며 각 1회로 센다.

- **입력**: 첫 줄 A, 둘째 줄 B(각 소문자, 길이 0 이상 1000 이하; 빈 줄 가능).

- **출력**: 최소 연산 수.

- **예제**: `kitten / sitting` → `3` (k→s, e→i, +g) / `flaw / lawn` → `2` (앞 f 삭제, 뒤 n 삽입)

- **셀프체크**: `dp[0][j]=j`, `dp[i][0]=i`로 초기화했는가? 같은 글자면 대각선 그대로, 다르면 `min(삽입, 삭제, 교체)+1`인가? 한쪽이 빈 문자열이면 다른 쪽 길이가 답인가?

```runner
@@SOLUTION
import sys
def main():
    lines = sys.stdin.read().split('\n')
    a = lines[0] if len(lines) > 0 else ''
    b = lines[1] if len(lines) > 1 else ''
    a = a.rstrip('\r'); b = b.rstrip('\r')
    m, n = len(a), len(b)
    prev = list(range(n + 1))
    for i in range(1, m + 1):
        cur = [i] + [0] * n
        ai = a[i-1]
        for j in range(1, n + 1):
            if ai == b[j-1]:
                cur[j] = prev[j-1]
            else:
                cur[j] = 1 + min(prev[j], cur[j-1], prev[j-1])
        prev = cur
    print(prev[n])
main()
@@TESTS
--IN
kitten
sitting
--OUT
3
--IN
flaw
lawn
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- 편집 거리(Levenshtein). `dp[i][j]` = "A의 앞 i글자를 B의 앞 j글자로 바꾸는 최소 연산 수". 삽입/삭제/교체 세 연산이 각각 위/왼쪽/대각선 전이에 대응한다.

(2) 코드 단계별

- 경계 초기화: `dp[0][j]=j`(빈 A에 j번 삽입), `dp[i][0]=i`(A에서 i번 삭제). 코드에서는 첫 행 `range(n+1)`, 각 행 시작 `cur[0]=i`.
- 끝 글자가 같으면 연산 없이 `dp[i][j]=dp[i-1][j-1]`(대각선 그대로).
- 다르면 `1 + min(dp[i-1][j] 삭제, dp[i][j-1] 삽입, dp[i-1][j-1] 교체)`.
- 두 행 롤링(`prev`, `cur`)으로 공간 O(n). `dp[m][n]`이 답. 빈 문자열도 `.rstrip('\r')`로 안전 처리.

(3) 스스로 다시 짤 때 생각 순서

- LCS 표에 삽입/삭제/교체 세 전이를 더한다고 생각한다.
- 0행·0열을 0~길이로 초기화하는 것을 잊지 않는다.
- 같은 글자 = 비용 0(대각선), 다른 글자 = min 세 방향 +1.
- 한쪽이 비면 다른 쪽 길이가 답이 되는지 경계로 검산한다.
```

**3) 회문으로 만들기** · Hard

- **요구사항**: 문자열 S에서 글자를 삭제만 해서(순서 유지) 회문(앞뒤 대칭)을 만들 때, 최소 삭제 횟수를 구하라.

- **입력**: 한 줄에 S(소문자, 길이 1 이상 1000 이하).

- **출력**: 최소 삭제 횟수.

- **예제**: `aebcbda` → `2` ("bcb" 또는 "abcba"? 최장 회문 부분수열 길이 5 → 삭제 2) / `abcd` → `3` (한 글자만 남기면 회문)

- **셀프체크**: "S와 S를 뒤집은 문자열의 LCS 길이 = 최장 회문 부분수열 길이"임을 이용했는가? 답이 `len(S) - LPS`인가? 길이 1은 이미 회문이라 0인가?

> 검산(예제1): S="aebcbda", reverse="adbcbea". 둘의 LCS를 채우면 "abcba"(길이5)가 잡힌다 → LPS=5 → 7-5=2. 답 2.

```runner
@@SOLUTION
import sys
def main():
    s = sys.stdin.readline().rstrip('\n').rstrip('\r')
    t = s[::-1]
    n = len(s)
    prev = [0] * (n + 1)
    for i in range(1, n + 1):
        cur = [0] * (n + 1)
        si = s[i-1]
        for j in range(1, n + 1):
            if si == t[j-1]:
                cur[j] = prev[j-1] + 1
            else:
                cur[j] = prev[j] if prev[j] >= cur[j-1] else cur[j-1]
        prev = cur
    lps = prev[n]
    print(n - lps)
main()
@@TESTS

--IN

@@EXPL
**이 풀이의 새 문법**

- `s[::-1]`: 슬라이싱에 "간격(step)" -1을 줘서 문자열(또는 리스트)을 통째로 뒤집은 새 값을 만든다. `s[start:stop:step]`에서 시작·끝을 생략하고 step만 -1로 준 형태다.

(1) 접근·핵심 아이디어

- 삭제만으로 회문을 만들 때 남길 수 있는 최대 길이가 "최장 회문 부분수열(LPS)"이고, 삭제 횟수는 `len(S) - LPS`다. 핵심 성질: LPS(S) = LCS(S, reverse(S)). 회문 부분수열은 뒤집어도 같으므로 원문과 역문 양쪽에 공통으로 나타난다.

(2) 코드 단계별

- S와 그 역문 T=S[::-1]을 만든다.
- 둘의 LCS를 두 행 롤링으로 계산: 같으면 대각선 +1, 다르면 위/왼쪽 max.
- `dp[n][n]`이 LPS 길이.
- 답은 `len(S) - LPS`. 시간 O(n²), 공간 O(n).

(3) 스스로 다시 짤 때 생각 순서

- "삭제만으로 회문" -> "남기는 최장 회문 부분수열" 변환을 떠올린다.
- LPS = LCS(S, reverse(S)) 성질을 이용해 LCS 코드를 재사용한다.
- 답을 `len - LPS`로 낸다. 길이 1은 이미 회문이라 0인지 검산한다.
```


## L9. Greedy Algorithm

**개념**

- 그리디(탐욕법)는 매 단계에서 "지금 당장 가장 좋아 보이는" 국소 최적을 고르고, 그 선택을 뒤집지 않는 방법이다. 이 국소 선택이 전체 최적으로 이어질 때만 옳다. DP가 모든 경우를 표에 쌓아 비교한다면, 그리디는 정렬·우선순위로 한 방향만 훑어 훨씬 빠르다.

- 그리디가 성립하려면 대개 두 성질이 있다:

  1. 탐욕적 선택 속성: 국소 최적 선택이 전체 최적해의 일부가 됨.

  2. 최적 부분구조: 선택 후 남은 문제도 같은 방식으로 최적.

- 전형적 형태는 "적절한 기준으로 정렬한 뒤 앞에서부터 조건을 만족하면 집는" 패턴이다. 회의실 배정(끝나는 시각 오름차순), 거스름돈(큰 동전부터), 최소 신장 트리(간선 가중치 오름차순) 등이 그 예다.

```python
# 활동 선택: 끝나는 시각 기준 정렬 후, 겹치지 않으면 채택
def activity_select(intervals):     # intervals = [(start, end), ...]
    intervals.sort(key=lambda x: x[1])   # 끝나는 시각 오름차순
    count, last_end = 0, -1
    for s, e in intervals:
        if s >= last_end:            # 직전과 안 겹치면
            count += 1
            last_end = e
    return count
```

**접근 전략**

- 핵심 아이디어: "무엇을 기준으로 정렬하면 앞에서부터 욕심내도 안전한가?"를 찾는 게 전부다. 기준을 정했으면 반례를 손으로 만들어 보고, 안 깨지면 채택한다. 대부분의 그리디 오답은 "정렬 기준이 틀려서"다.

- 전형적 절차: (1) 정렬 기준 후보 세우기 (2) 교환 논증(두 선택을 바꿔도 손해 없음)으로 정당성 확인 (3) 한 번 훑으며 조건 만족 시 채택 (4) 필요하면 heapq로 "매 순간 최선"을 O(log n)에 뽑기.

- 언제 쓰나: 정렬 한 번으로 국소 최적이 전체 최적이 되는 스케줄링·구간·교환 문제. 확신이 없으면 작은 입력으로 그리디 vs 완전탐색을 비교해 반례를 찾는다(반례가 있으면 DP로).

- 복잡도: 대개 정렬이 지배해 O(n log n) 시간, O(n) 또는 O(1) 공간. heapq를 쓰면 원소당 O(log n).

- 흔한 실수: 반례 검증 없이 "그럴듯한" 기준을 믿음(예: 회의 문제에서 시작 시각·소요 시간으로 정렬하면 틀림) / 그리디가 안 되는 문제(0/1 배낭)에 억지로 적용 / 동점 처리 기준을 빠뜨림.

**문제**

**1) 회의실 배정** · Easy

- **요구사항**: N개의 회의가 시작·종료 시각으로 주어진다. 한 회의실에서 시간이 겹치지 않게 최대한 많은 회의를 배정할 때, 최대 개수를 구하라(한 회의의 끝 시각과 다른 회의의 시작 시각이 같으면 겹치지 않는 것으로 본다).

- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 이후 N줄에 `시작 끝`(0 이상 1000000000 이하, 시작 ≤ 끝).

- **출력**: 배정 가능한 최대 회의 수.

- **예제**: `3 / 1 3 / 2 4 / 3 5` → `2` ((1,3),(3,5)) / `4 / 1 4 / 3 5 / 0 6 / 5 7` → `2` ((1,4),(5,7))

- **셀프체크**: 끝나는 시각 오름차순으로 정렬했는가(시작 기준은 틀림)? `s >= last_end` 조건인가? 시작=끝 회의(길이 0) 같은 경계를 처리했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    ivs = []
    idx = 1
    for _ in range(n):
        s = int(data[idx]); e = int(data[idx+1]); idx += 2
        ivs.append((s, e))
    ivs.sort(key=lambda x: (x[1], x[0]))
    count = 0
    last = -1
    for s, e in ivs:
        if s >= last:
            count += 1
            last = e
    print(count)
main()

(1) 접근·핵심 아이디어

- 활동 선택(회의실 배정) 그리디. "끝나는 시각이 빠른 회의를 먼저 잡으면 뒤에 더 많은 회의가 들어갈 여지가 남는다"는 교환 논증으로 최적이 보장된다. 시작 시각이나 소요 시간 기준은 반례가 있어 틀린다.

(2) 코드 단계별

- 회의들을 끝 시각 오름차순으로 정렬(`key=(x[1], x[0])`, 동점은 시작 시각으로 안정화).
- `last`(마지막으로 잡은 회의의 끝)를 -1로 시작.
- 앞에서부터 훑으며 `s >= last`(직전 회의와 안 겹침, 끝=시작 접점 허용)이면 채택하고 `last=e`, `count+=1`.
- `count`가 답. 시간 O(n log n)(정렬 지배).

(3) 스스로 다시 짤 때 생각 순서

- "최대 개수 스케줄링" -> 끝 시각 오름차순 그리디를 떠올린다.
- 겹침 조건을 `s >= last_end`(접점 허용)로 정확히 쓴다.
- 정렬 기준을 반례로 검증(시작 기준은 깨짐)한다.
```

**2) 거스름돈 최소 동전** · Easy

- **요구사항**: 액면가가 서로 배수 관계인 동전 종류가 주어진다(예: 500, 100, 50, 10). 금액 M을 만들 때 필요한 동전의 최소 개수를 구하라.

- **입력**: 첫 줄 K M(1 ≤ K ≤ 10, 0 ≤ M ≤ 1000000000), 둘째 줄 K개의 액면가(배수 관계 보장, 내림차순 아님).

- **출력**: 최소 동전 개수.

- **예제**: `4 1260 / 500 100 50 10` → `6` (500×2+100×2+50+10) / `2 4200 / 1000 100` → `6` (1000×4+100×2)

- **셀프체크**: 큰 액면부터 최대한 쓰는 그리디가 "배수 관계"에서만 안전함을 이해했는가(임의 액면이면 DP 필요)? 액면을 내림차순 정렬했는가? M=0이면 0인가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    k = int(data[0]); m = int(data[1])
    coins = [int(x) for x in data[2:2+k]]
    coins.sort(reverse=True)
    cnt = 0
    for c in coins:
        if m <= 0:
            break
        cnt += m // c
        m %= c
    print(cnt)
main()

(1) 접근·핵심 아이디어

- 액면이 서로 배수 관계일 때는 "큰 동전부터 최대한 쓰는" 그리디가 최적이다. 큰 동전 하나가 항상 작은 동전들의 정확한 배수로 대체되므로, 큰 걸 덜 쓰고 작은 걸 더 쓰면 개수만 늘어난다. (배수 관계가 아니면 반례가 있어 DP가 필요하다.)

(2) 코드 단계별

- 액면을 내림차순 정렬.
- 큰 액면 c부터 `cnt += m // c`(그 액면을 쓸 수 있는 최대 개수)를 더하고 `m %= c`(남은 금액).
- m이 0이 되면 종료. `cnt`가 답. 시간 O(K log K).

(3) 스스로 다시 짤 때 생각 순서

- "배수 관계"라는 조건에서만 그리디가 안전함을 먼저 확인한다.
- 내림차순 정렬 후 나눗셈 몫과 나머지로 훑는다.
- M=0이면 0이 나오는지 경계로 검산한다.
```

**3) 밧줄 잇기 비용** · Medium

- **요구사항**: 길이가 서로 다른 N개의 밧줄을 모두 하나로 잇는다. 두 밧줄을 이으면 비용은 두 길이의 합이고, 이어진 밧줄은 다시 다른 것과 이을 수 있다. 전체를 하나로 만드는 최소 총비용을 구하라.

- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 둘째 줄 N개의 길이(1 이상 10000 이하).

- **출력**: 최소 총비용.

- **예제**: `3 / 1 2 3` → `9` ((1+2)=3, 그 3+3=6, 총 3+6=9) / `4 / 4 3 2 6` → `29`

- **셀프체크**: 매번 가장 짧은 두 개를 골라 잇는 게 최적임을 알았는가(허프만 아이디어)? `heapq`로 최소 두 개를 O(log n)에 뽑았는가? N=1이면 이을 게 없어 0인가?

> 검산(예제2, N=4 길이 4 3 2 6): 힙 [2,3,4,6] → 2+3=5(누적5), 힙[4,5,6] → 4+5=9(누적14), 힙[6,9] → 6+9=15(누적29). 답 29.

```runner
@@SOLUTION
import sys, heapq
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    lens = [int(x) for x in data[1:1+n]]
    if n <= 1:
        print(0); return
    heapq.heapify(lens)
    total = 0
    while len(lens) > 1:
        a = heapq.heappop(lens)
        b = heapq.heappop(lens)
        s = a + b
        total += s
        heapq.heappush(lens, s)
    print(total)
main()
@@TESTS
--IN

1 2 3
--OUT
9
--IN
4
4 3 2 6
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 밧줄을 이을 때마다 그 합이 비용이 되고, 이어진 밧줄은 이후 이음에 계속 다시 더해진다. 짧은 밧줄일수록 여러 번 더해져도 손해가 작으므로, 매번 가장 짧은 두 개를 골라 잇는 게 최적(허프만 코딩과 같은 원리)이다.

(2) 코드 단계별

- 길이 배열을 최소 힙으로 만든다(`heapq.heapify`).
- 힙에서 가장 작은 두 개 a, b를 꺼내 합 s=a+b를 비용에 더하고, 합쳐진 s를 다시 힙에 넣는다.
- 힙에 하나만 남을 때까지 반복. 누적 `total`이 답.
- N=1이면 이을 게 없어 0. 시간 O(N log N).

(3) 스스로 다시 짤 때 생각 순서

- "합이 계속 재사용된다" -> 작은 것부터 합쳐야 함(허프만)을 떠올린다.
- 매 순간 최소 두 개를 O(log N)에 뽑으려 `heapq`를 쓴다.
- 합을 도로 힙에 넣어 다음 이음에 반영한다.
- N=1 경계(0)를 처리한다.
```

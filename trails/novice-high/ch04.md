> 개요: 정렬된 데이터에서 탐색 범위를 절반씩 줄여 O(log n)에 원하는 값을 찾는 이진탐색을 배우고, 중복이 있을 때 "값의 시작/끝 경계"를 찾는 Lower/Upper Bound와 이를 정답 자체가 아니라 "조건을 만족하는 최소/최대 답"에 적용하는 파라메트릭 서치(정답에 대한 이분탐색)까지 확장한다.

## L1. 이진탐색

**개념**

- 이진탐색(binary search)은 **정렬된** 배열에서 목표값을 찾는 알고리즘이다. 선형탐색이 앞에서부터 하나씩 O(n)으로 확인하는 것과 달리, 이진탐색은 매번 탐색 구간의 **가운데 원소**와 목표값을 비교해 구간을 절반으로 줄인다.
- 동작 원리(단계):

  1. 탐색 구간을 `lo=0`, `hi=n-1`로 잡는다(닫힌 구간 [lo, hi]).
  2. 중간 인덱스 `mid = (lo + hi) // 2`를 계산한다.
  3. `arr[mid] == target`이면 찾은 것 → 인덱스 반환.
  4. `arr[mid] < target`이면 목표는 오른쪽에 있으므로 `lo = mid + 1`.
  5. `arr[mid] > target`이면 목표는 왼쪽에 있으므로 `hi = mid - 1`.
  6. `lo <= hi`인 동안 2~5를 반복. 구간이 비면(`lo > hi`) 없는 것 → -1 반환.

- 매 반복마다 후보 개수가 n → n/2 → n/4 … 로 줄어 최대 약 log₂n번 만에 끝난다. 원소 10억(≈2³⁰) 개도 약 30번 비교면 충분하다.

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2      # 오버플로 걱정 없는 파이썬이라 이대로 OK
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

**그림으로 보기**

정렬된 8칸 배열에서 `target = 23`을 찾는 과정이다. `L`=lo, `M`=mid, `H`=hi이고,
각 단계 줄에 찍힌 세 글자가 그 순간의 탐색 구간 `[lo, hi]`와 비교 지점이다.

```text
 idx     0    1    2    3    4    5    6    7
      ┌────┬────┬────┬────┬────┬────┬────┬────┐
 arr  │  3 │  8 │ 12 │ 17 │ 23 │ 29 │ 34 │ 41 │
      └────┴────┴────┴────┴────┴────┴────┴────┘
 s1      L              M                   H    # 17 < 23  -> lo = mid+1
 s2                          L    M         H    # 29 > 23  -> hi = mid-1
 s3                         LMH                  # 23 == 23 -> return 4
```

단계마다 mid 한 곳만 비교하고, 살아남는 구간은 `[0,7]` → `[4,7]` → `[4,4]`로
절반씩 줄어든다. 이 "절반씩"을 계단으로 그리면 이렇다.

```text
  step 0  |================================|  64  # 살아남은 후보 개수
  step 1  |================|                  32
  step 2  |========|                          16
  step 3  |====|                               8
  step 4  |==|                                 4
  step 5  |=|                                  2
  step 6  ||                                   1  # 2^6 = 64
```

닫힌 구간 `[lo, hi]`과 반열린 구간 `[lo, hi)`는 hi가 **구간 안**이냐 **한 칸 밖**
이냐가 다르고, 그래서 종료 조건과 갱신식이 통째로 달라진다.

```text
  closed  [lo, hi]           half-open  [lo, hi)
  ┌────┬────┬────┬────┐      ┌────┬────┬────┬────┐
  │  L │  . │  . │  H │      │  L │  . │  . │  . │ H
  └────┴────┴────┴────┘      └────┴────┴────┴────┘
  hi is INSIDE               hi is ONE PAST the end
  while lo <= hi             while lo < hi
  hi = mid - 1               hi = mid
  lo = mid + 1               lo = mid + 1
  stops at lo == hi + 1      stops at lo == hi
```

**손으로 따라가기**

위 배열 `[3, 8, 12, 17, 23, 29, 34, 41]`에서 `target = 23`(있는 값)을 찾는다.

| 단계 | lo | hi | mid | arr[mid] | 비교 | 다음 구간 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 7 | 3 | 17 | 17 < 23 | lo = 4 → [4, 7] |
| 2 | 4 | 7 | 5 | 29 | 29 > 23 | hi = 4 → [4, 4] |
| 3 | 4 | 4 | 4 | 23 | 23 == 23 | 일치 → 인덱스 4 반환 |

같은 배열에서 `target = 20`(없는 값)을 찾으면 구간이 텅 비면서 끝난다.

| 단계 | lo | hi | mid | arr[mid] | 비교 | 다음 구간 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 7 | 3 | 17 | 17 < 20 | lo = 4 → [4, 7] |
| 2 | 4 | 7 | 5 | 29 | 29 > 20 | hi = 4 → [4, 4] |
| 3 | 4 | 4 | 4 | 23 | 23 > 20 | hi = 3 → [4, 3] |
| 4 | 4 | 3 | — | — | lo > hi | 구간이 빔 → -1 반환 |

두 추적 모두 8개짜리 배열을 3~4번 비교로 끝냈다. `log₂8 = 3`과 맞는다.

**왜 이렇게 되는가**

- **왜 정렬(단조성)이 필요한가.** 배열이 오름차순이면 `arr[mid] < target`인 순간
  `arr[0] ≤ arr[1] ≤ … ≤ arr[mid] < target`이 자동으로 따라온다. 즉 왼쪽 절반
  **전체**가 target이 아님이 한 번의 비교로 증명된다. 정렬돼 있지 않으면
  `arr[mid] < target`이어도 왼쪽에 target이 있을 수 있어 절반을 버릴 근거가 사라진다.
  이진탐색이 쓸 수 있는 조건은 "정렬"이 아니라 정확히는 **단조성**이다. 그래서 배열이
  아니라 답의 후보 범위에도(파라메트릭 서치) 그대로 걸 수 있다.
- **왜 log₂n번인가.** 후보 개수는 매 반복마다 최소 절반으로 줄어든다.
  n → n/2 → n/4 → … → n/2^k. 후보가 1개가 되는 순간이 마지막이므로 `n / 2^k = 1`,
  즉 `2^k = n`, `k = log₂n`이다. n = 10억이면 2³⁰ ≈ 10.7억이라 30번, n = 100만이면
  2²⁰ ≈ 104만이라 20번이다. 선형탐색의 10억 번과 비교하면 3천만 배 차이다.
- **`mid = (lo + hi) // 2`와 무한루프.** `//`는 내림이라 `lo < hi`일 때
  `lo ≤ mid < hi`가 항상 성립한다. 즉 mid는 **hi가 될 수 없다**. 그래서 `hi = mid`는
  구간을 반드시 줄이지만, `lo = mid`는 lo가 그대로일 수 있어 멈추지 않는다.

```text
  lo = 3, hi = 4   ->   mid = (3 + 4) // 2 = 3
  (a) lo = mid       -> lo = 3    # 그대로! 무한루프
  (b) lo = mid + 1   -> lo = 4    # 구간이 반드시 줄어든다
  (c) mid = (3+4+1)//2 = 4        # 올림 mid를 쓰면 lo = mid도 안전
```

  규칙으로 못 박으면 이렇다. **내림 mid(`(lo+hi)//2`)를 쓰면 `lo = mid + 1`만 허용**,
  `lo = mid`가 꼭 필요하면 **올림 mid(`(lo+hi+1)//2`)로 바꾼다.**
- **왜 O(1) 공간인가.** 반복 구현은 `lo, mid, hi` 세 정수만 들고 있고 배열을 복사하지
  않는다. 재귀로 짜면 호출 스택이 log₂n칸 쌓여 공간이 O(log n)이 된다.

**접근 전략**

- 핵심 아이디어: "정렬되어 있다 → 가운데를 보면 답이 왼쪽인지 오른쪽인지 **단조적으로** 결정된다"는 성질을 이용해 매번 후보를 반으로 버린다. 정렬이 안 돼 있으면 먼저 `sorted()` 하거나(이 자체가 O(n log n)) 다른 방법을 써야 한다.
- 전형적 패턴: (1) 값을 배열에서 직접 찾을 때는 위 골격을 그대로 쓴다. (2) 파이썬 실무에서는 원소 존재 여부만 필요하면 `target in set(arr)`(O(1) 평균)이 더 편하고, 정렬 배열에서 위치가 필요하면 표준 라이브러리 `bisect`(다음 레슨)를 쓴다. 이진탐색을 직접 구현하는 이유는 "정답 조건이 단조인 문제"에 응용하기 위해서다.
- 경계 설정의 두 유파: 닫힌 구간 `[lo, hi]` (`while lo <= hi`, `hi=mid-1`) 과 반열린 구간 `[lo, hi)` (`while lo < hi`, `hi=mid`)가 있다. **한 문제 안에서는 한 방식만** 일관되게 써라. 섞으면 무한루프나 off-by-one이 난다.
- 복잡도: 시간 O(log n), 공간 O(1)(반복 구현). 재귀로 짜면 호출 스택 때문에 공간 O(log n).
- 흔한 실수: (a) 정렬 안 된 배열에 적용, (b) `lo=mid`/`hi=mid`로 두어 구간이 안 줄고 무한루프, (c) 종료 조건 `<=` vs `<` 혼동, (d) 답을 "찾았는지"와 "삽입 위치"를 헷갈림(존재하지 않을 때 -1을 줄지, 들어갈 자리를 줄지 명확히).

**문제**

**1) 정렬 배열에서 값 찾기** · Easy

- **요구사항**: 오름차순 정렬된 정수 배열과 목표값 `target`이 주어질 때, `target`이 있으면 그 인덱스(0-based)를, 없으면 -1을 출력한다. 값은 서로 다르다고 가정한다. 반드시 O(log n)으로 풀어라.
- **입력**: 첫 줄에 n, 둘째 줄에 공백으로 구분된 오름차순 정수 n개, 셋째 줄에 target.
- **출력**: 인덱스 또는 -1.
- **예제**:
  - `7 / 1 3 5 7 9 11 13 / 7` → `3`
  - `7 / 1 3 5 7 9 11 13 / 8` → `-1`
- **셀프체크**: n=1일 때 동작하는가? target이 배열 최솟값보다 작거나 최댓값보다 클 때 -1을 내는가? `while` 종료 후에도 return을 빠뜨리지 않았는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    arr = [int(data[idx + i]) for i in range(n)]; idx += n
    target = int(data[idx]); idx += 1
    lo, hi = 0, n - 1
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            ans = mid
            break
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    print(ans)
main()
@@TESTS
--IN
7
1 3 5 7 9 11 13
7
--OUT
3
--IN
7
1 3 5 7 9 11 13
8
--OUT
-1
@@EXPL
접근·핵심 아이디어

- 정렬 배열이므로 가운데 원소와 target을 비교하면 답이 왼쪽인지 오른쪽인지 단조적으로 결정된다. 매번 후보를 절반씩 버려 O(log n)에 찾는다.
- 닫힌 구간 `[lo, hi]` 방식(`while lo <= hi`, `hi=mid-1`)을 일관되게 쓴다.

코드 단계별

- `n`, 배열, `target`을 읽는다.
- `lo=0`, `hi=n-1`로 시작, 못 찾은 기본값 `ans=-1`.
- `mid=(lo+hi)//2`. `arr[mid] == target`이면 인덱스를 답으로 확정하고 종료.
- `arr[mid] < target`이면 오른쪽으로(`lo=mid+1`), 크면 왼쪽으로(`hi=mid-1`).
- 구간이 비면(`lo>hi`) 없는 것 → -1.

스스로 다시 짤 때 생각 순서

1. 경계 유파를 하나로: 닫힌 구간 `[lo, hi]`, 종료 조건 `lo <= hi`.
2. 세 갈래 비교(같다/작다/크다)로 mid 처리.
3. 못 찾았을 때의 반환값(-1)을 루프 밖에 반드시 준비.
4. n=1, 최솟값 미만/최댓값 초과 target 등 경계 케이스 확인.
```

**2) 완벽한 제곱근** · Medium

- **요구사항**: 음이 아닌 정수 x가 주어질 때 `floor(sqrt(x))`(x의 제곱근 이하 최대 정수)를 이진탐색으로 구하라. `math.sqrt`나 `** 0.5`는 부동소수 오차가 있으니 쓰지 말고 정수 연산만 사용한다.
- **입력**: 한 줄에 정수 x (0 ≤ x ≤ 10¹⁸).
- **출력**: floor(sqrt(x)).
- **예제**:
  - `8` → `2` (2²=4≤8, 3²=9>8)
  - `16` → `4`
  - `0` → `0`
- **셀프체크**: 탐색 대상은 배열이 아니라 "답의 후보 범위 [0, x]"다. `mid*mid <= x`가 참인 가장 큰 mid를 찾는 구조로 바꿀 수 있는가? x가 10¹⁸일 때 mid*mid가 커도 파이썬 정수라 안전한가? x=1일 때 답 1이 나오는가?

```runner
@@SOLUTION
import sys
def main():
    x = int(sys.stdin.read().split()[0])
    lo, hi = 0, x
    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= x:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    print(ans)
main()
@@TESTS
--IN
8
--OUT
2
--IN
1000000000000000000
--OUT
1000000000
@@EXPL
접근·핵심 아이디어

- 배열이 아니라 "답의 후보 범위 `[0, x]`"에 이분탐색을 건다. `mid*mid <= x`는 mid가 커질수록 True→False로 단조 감소하므로, True인 **가장 큰 mid**가 floor(sqrt(x))다.
- 정수 곱 `mid*mid`만 쓰므로 `math.sqrt`/`**0.5`의 부동소수 오차를 피한다. 파이썬 정수는 임의 정밀도라 x=10^18에서도 안전하다.

코드 단계별

- 정수 `x`를 읽는다.
- 후보 구간 `lo=0`, `hi=x`로 잡는다(x=0이면 곧바로 0).
- `mid*mid <= x`면 조건 만족 → `ans=mid`로 기록하고 더 큰 값을 시도(`lo=mid+1`), 아니면 `hi=mid-1`.
- 루프 종료 후 `ans`가 floor(sqrt(x)).

스스로 다시 짤 때 생각 순서

1. "무엇에 이분탐색?" → 제곱근의 후보 정수 `[0, x]`.
2. 단조 술어 정의: `mid*mid <= x` (참 구간이 왼쪽).
3. 참 중 최댓값을 원하므로 참일 때 `lo=mid+1` + `ans` 갱신.
4. 경계 검산: x=0→0, x=1→1, 완전제곱수/비제곱수 모두 floor가 맞는지.
```

**3) 회전된 정렬 배열에서 찾기** · Hard

- **요구사항**: 서로 다른 값으로 오름차순 정렬된 배열을 어떤 지점에서 회전시킨 배열(예: `[4,5,6,7,0,1,2]`)과 target이 주어진다. target의 인덱스, 없으면 -1을 O(log n)으로 출력하라.
- **입력**: 첫 줄 n, 둘째 줄 회전된 배열, 셋째 줄 target.
- **출력**: 인덱스 또는 -1.
- **예제**:
  - `7 / 4 5 6 7 0 1 2 / 0` → `4`
  - `7 / 4 5 6 7 0 1 2 / 3` → `-1`
- **셀프체크**: mid를 기준으로 `[lo..mid]`와 `[mid..hi]` 중 **한쪽은 반드시 정렬**되어 있다. 그 정렬된 쪽에 target이 범위상 포함되는지로 버릴 절반을 정하는가? 회전이 없는(=정상 정렬) 경우에도 같은 로직이 맞는가? 원소 1개일 때는?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    arr = [int(data[idx + i]) for i in range(n)]; idx += n
    target = int(data[idx]); idx += 1
    lo, hi = 0, n - 1
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            ans = mid
            break
        if arr[lo] <= arr[mid]:
            if arr[lo] <= target < arr[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:
            if arr[mid] < target <= arr[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    print(ans)
main()
@@TESTS

4 5 6 7 0 1 2
0
--OUT
4
--IN

@@EXPL
접근·핵심 아이디어

- 회전된 정렬 배열이라도 mid를 기준으로 왼쪽 `[lo..mid]`와 오른쪽 `[mid..hi]` 중 **한쪽은 반드시 정렬**되어 있다.
- 정렬된 쪽의 값 범위에 target이 들어가는지 보고, 들어가면 그쪽으로, 아니면 반대쪽으로 구간을 반씩 버린다. 그래서 O(log n)을 유지한다.

코드 단계별

- `n`, 회전 배열, `target`을 읽고 닫힌 구간 `[0, n-1]`로 시작.
- `arr[mid] == target`이면 인덱스를 답으로 확정.
- `arr[lo] <= arr[mid]`이면 왼쪽 절반이 정렬됨 → `arr[lo] <= target < arr[mid]`면 왼쪽(`hi=mid-1`), 아니면 오른쪽(`lo=mid+1`).
- 그렇지 않으면 오른쪽 절반이 정렬됨 → `arr[mid] < target <= arr[hi]`면 오른쪽(`lo=mid+1`), 아니면 왼쪽(`hi=mid-1`).
- 못 찾으면 -1. 원소 1개(`lo==hi`)나 회전 없는 정상 정렬에서도 같은 로직이 성립한다.

스스로 다시 짤 때 생각 순서

1. 일반 이분탐색 골격에서 "어느 절반이 정렬인가?"를 먼저 판정(`arr[lo] <= arr[mid]`).
2. 정렬된 쪽에만 안전하게 범위 포함 검사를 적용(부등호 경계 `<=`, `<` 주의).
3. target이 그 범위 안이면 정렬된 쪽으로, 아니면 반대쪽으로 이동.
4. 경계값(첫/끝 원소, 원소 1개, 회전 0) 케이스를 손으로 검산.
```


## L2. Lower/Upper Bound

**개념**

- 값이 **중복**될 수 있는 정렬 배열에서는 "target이 있는지"만으로 부족하고, target이 **어디서 시작해 어디서 끝나는지**가 필요할 때가 많다. 이때 쓰는 두 경계가 Lower Bound와 Upper Bound다.
- **Lower Bound**: `target 이상(≥)`인 첫 위치. 즉 target을 정렬을 깨지 않고 넣을 수 있는 **가장 왼쪽** 인덱스.
- **Upper Bound**: `target 초과(>)`인 첫 위치. 즉 넣을 수 있는 **가장 오른쪽** 인덱스.
- 두 경계로 여러 질문에 답한다:

  - target의 등장 횟수 = `upper - lower`.
  - target이 존재하는가 = `lower < n and arr[lower] == target`.
  - target 이하 원소 개수 = `upper`, target 미만 원소 개수 = `lower`.

- 구현은 이진탐색 골격을 반열린 구간 `[lo, hi)`로 쓰되, "찾으면 멈춤"이 아니라 **조건을 만족하는 경계를 계속 좁혀 나간다**는 점이 핵심이다.

```python
# arr가 오름차순일 때
def lower_bound(arr, target):        # arr[i] >= target 인 첫 i
    lo, hi = 0, len(arr)             # 반열린 구간 [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < target:        # mid는 아직 부족 → 오른쪽
            lo = mid + 1
        else:                        # arr[mid] >= target → 후보, 왼쪽도 확인
            hi = mid
    return lo

def upper_bound(arr, target):        # arr[i] > target 인 첫 i
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= target:       # 같아도 오른쪽으로
            lo = mid + 1
        else:
            hi = mid
    return lo
```

> 파이썬 표준: `bisect.bisect_left(arr, x)` = lower bound, `bisect.bisect_right(arr, x)` = upper bound. 실무에서는 이 둘을 쓰면 되고, 직접 구현은 원리 이해와 "정답에 대한 이분탐색(파라메트릭 서치)" 응용을 위해서다.

**그림으로 보기**

중복이 섞인 배열 `[1, 2, 2, 2, 3, 3, 5, 5]`에서 `target = 2`의 두 경계를 본다.
두 경계는 각각 **서로 다른 술어의 "첫 True"**다.

```text
 idx     0    1    2    3    4    5    6    7
      ┌────┬────┬────┬────┬────┬────┬────┬────┐
 arr  │  1 │  2 │  2 │  2 │  3 │  3 │  5 │  5 │
      └────┴────┴────┴────┴────┴────┴────┴────┘
 >=2     F    T    T    T    T    T    T    T    # lower = 첫 T
 > 2     F    F    F    F    T    T    T    T    # upper = 첫 T
              ▲              ▲
           lower=1        upper=4
```

`>=2` 줄은 F가 끝나고 T가 시작되는 지점이 1, `> 2` 줄은 그 지점이 4다.
그래서 lower_bound(2) = 1, upper_bound(2) = 4다. 배열을 세 구간으로 잘라 보면
두 경계가 정확히 "칼금" 두 개라는 것이 더 분명해진다.

```text
        arr[i] < 2    arr[i] == 2        arr[i] > 2
      ┌────────────┬───────────────┬────────────────────┐
      │      1     │   2   2   2   │   3   3   5   5    │
      └────────────┴───────────────┴────────────────────┘
                   ▲               ▲
                lower=1         upper=4
      # 등장 횟수 = upper - lower = 4 - 1 = 3
```

두 화살표는 **원소가 아니라 원소 사이의 틈**을 가리킨다는 점이 중요하다. 그래서
`upper - lower`가 곧 개수가 되고, target이 없으면 두 화살표가 **같은 틈**에 겹쳐
`upper - lower = 0`이 된다.

**손으로 따라가기**

같은 배열에 `lower_bound(arr, 2)`를 반열린 구간 `[lo, hi)`로 돌린다. 시작은
`lo = 0`, `hi = 8`(원소 수 n, 마지막 인덱스 7이 아님에 주의).

| 단계 | lo | hi | mid | arr[mid] | `arr[mid] < 2` | 갱신 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 8 | 4 | 3 | 거짓 | hi = 4 (mid도 후보라 버리지 않음) |
| 2 | 0 | 4 | 2 | 2 | 거짓 | hi = 2 |
| 3 | 0 | 2 | 1 | 2 | 거짓 | hi = 1 |
| 4 | 0 | 1 | 0 | 1 | 참 | lo = 1 |
| 5 | 1 | 1 | — | — | — | `lo == hi` → 종료, 답 1 |

이어서 `upper_bound(arr, 2)`. 부등호 한 글자(`<` → `<=`)만 바뀌었다.

| 단계 | lo | hi | mid | arr[mid] | `arr[mid] <= 2` | 갱신 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 8 | 4 | 3 | 거짓 | hi = 4 |
| 2 | 0 | 4 | 2 | 2 | 참 | lo = 3 |
| 3 | 3 | 4 | 3 | 2 | 참 | lo = 4 |
| 4 | 4 | 4 | — | — | — | `lo == hi` → 종료, 답 4 |

등장 횟수는 `4 - 1 = 3`개, 등장 구간은 인덱스 `[1, 3]`이다.

**왜 이렇게 되는가**

- **불변식(invariant)을 문장으로 못 박자.** 반열린 구간 구현에서 루프가 도는 내내
  다음 두 문장이 항상 참이다.

  1. `lo` 왼쪽(인덱스 `< lo`)의 원소는 **전부 조건 False**다.
  2. `hi` 이상(인덱스 `>= hi`)의 원소는 **전부 조건 True**다.

  시작할 때 `lo = 0`(왼쪽이 비었으니 참), `hi = n`(오른쪽이 비었으니 참)이라 성립하고,
  `arr[mid]`가 False면 `lo = mid + 1`, True면 `hi = mid`로 갱신해도 두 문장이 유지된다.
  루프가 끝나 `lo == hi`가 되면 "왼쪽 전부 False, 자기부터 전부 True"이므로 그 자리가
  **첫 True**다. 답이 왜 `lo`인지가 여기서 나온다.
- **왜 `hi = n`이어야 하는가.** 답의 후보에는 "조건을 만족하는 원소가 하나도 없다"는
  경우, 즉 **인덱스 n**도 포함된다. `hi = n - 1`로 시작하면 이 후보가 처음부터 빠져
  target이 배열 최댓값보다 클 때 답이 n이 아니라 n-1로 잘못 나온다.
- **왜 무한루프가 안 나는가.** `lo < hi`이면 `lo ≤ mid < hi`이므로 `hi = mid`는 hi를
  최소 1 줄이고, `lo = mid + 1`은 lo를 최소 1 늘린다. 구간 길이가 매 회 반드시 줄어
  유한 번에 `lo == hi`에 도달한다.
- **왜 부등호 한 글자로 두 함수가 갈리는가.** lower는 "`>= target`인 첫 위치", upper는
  "`> target`인 첫 위치"다. 조건을 뒤집어 "왼쪽에 남길 False"로 쓰면 각각
  `arr[mid] < target`, `arr[mid] <= target`이 된다. 즉 **같은 값을 왼쪽에 둘 것인가**
  하나만 다르다. 이 한 글자가 "중복 구간의 시작"과 "중복 구간의 끝 다음"을 가른다.
- **왜 개수 세기가 O(log n)인가.** 경계를 찾은 뒤 `upper - lower`는 뺄셈 한 번이다.
  경계에서 시작해 `while arr[i] == target: i += 1`로 세면 중복이 n개일 때 O(n)이 되어
  이진탐색을 한 이유가 사라진다.

**접근 전략**

- 핵심 아이디어: 배열을 "조건 False … False | True … True" 처럼 **한 지점을 기준으로 단조롭게** 나눌 수 있으면, 그 경계(첫 True)를 이진탐색으로 찾을 수 있다. lower bound의 조건은 `arr[mid] >= target`, upper bound의 조건은 `arr[mid] > target`이다.
- 전형적 절차: (1) 배열을 정렬(또는 이미 정렬됨) 확인. (2) "무엇이 True/False로 갈리는가"의 술어(predicate)를 명확히 정의. (3) 반열린 구간 `[0, n]`으로 두고 첫 True 위치를 찾는다. `hi`를 `n`(마지막+1)으로 두어야 "모두 조건 미달"인 경우 답이 n으로 나온다.
- 파라메트릭 서치(정답에 대한 이분탐색): 답 자체가 배열에 없어도, "답을 x로 정하면 조건을 만족하는가?"가 x에 대해 단조(작으면 안 됨→커지면 됨, 또는 반대)이면 답의 범위에 이진탐색을 건다. 예: "각 묶음 최대합을 M 이하로 하면 K개 이하로 나눌 수 있는가?"는 M이 커질수록 True가 되므로 최소 M을 lower-bound식으로 찾는다.
- 언제 고르나: 중복 값의 개수/구간을 세거나, "조건을 만족하는 최소/최대 값"을 구할 때. 단순 존재 확인이면 L1 이진탐색이나 `set`으로 충분하다.
- 복잡도: 두 경계 모두 시간 O(log n), 공간 O(1). 파라메트릭 서치는 O(log(범위) × 판정비용).
- 흔한 실수: (a) `hi`를 `n-1`로 두어 "전부 target보다 작을 때" 답을 못 냄(반드시 `n`), (b) lower와 upper의 부등호(`<` vs `<=`)를 헷갈림, (c) 등장 횟수를 셀 때 `upper - lower`가 아니라 별도 반복으로 세어 O(n)이 됨, (d) 파라메트릭 서치에서 판정 조건의 단조성 방향을 반대로 잡음.

**문제**

**1) 값의 등장 구간** · Easy

- **요구사항**: 오름차순 정렬된 정수 배열(중복 가능)과 target이 주어질 때, target이 처음 등장하는 인덱스와 마지막으로 등장하는 인덱스를 출력하라. 없으면 `-1 -1`. O(log n)으로.
- **입력**: 첫 줄 n, 둘째 줄 정렬된 정수 배열, 셋째 줄 target.
- **출력**: `첫인덱스 마지막인덱스` (공백 구분) 또는 `-1 -1`.
- **예제**:
  - `8 / 1 2 2 2 3 3 5 5 / 2` → `1 3`
  - `8 / 1 2 2 2 3 3 5 5 / 4` → `-1 -1`
  - `8 / 1 2 2 2 3 3 5 5 / 5` → `6 7`
- **셀프체크**: 첫 인덱스 = lower_bound, 마지막 인덱스 = upper_bound - 1로 얻는가? 존재 판정을 lower 결과로 어떻게 하는가(`lower==n` 또는 `arr[lower]!=target`이면 없음)? target이 배열 최댓값보다 클 때 upper가 n으로 나와도 안전한가?

```runner
@@SOLUTION
import sys
from bisect import bisect_left, bisect_right
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    arr = [int(data[idx + i]) for i in range(n)]; idx += n
    target = int(data[idx]); idx += 1
    lo = bisect_left(arr, target)
    hi = bisect_right(arr, target)
    if lo == n or arr[lo] != target:
        print("-1 -1")
    else:
        print(lo, hi - 1)
main()
@@TESTS
--IN

1 2 2 2 3 3 5 5
2
--OUT
1 3
--IN
8
1 2 2 2 3 3 5 5
4
--OUT

@@EXPL
접근·핵심 아이디어

- 중복이 있는 정렬 배열에서 target의 첫 등장 = lower bound(`>= target`인 첫 위치), 마지막 등장 = upper bound(`> target`인 첫 위치) - 1이다.
- 존재 여부는 lower 결과로 판정한다: `lower == n`(전부 target보다 작음)이거나 `arr[lower] != target`이면 배열에 없다.

코드 단계별

- `n`, 배열, `target`을 읽는다.
- `lo = bisect_left(arr, target)`로 첫 등장 후보, `hi = bisect_right(arr, target)`로 초과 첫 위치를 구한다.
- `lo == n` 또는 `arr[lo] != target`이면 존재하지 않으므로 `-1 -1` 출력.
- 그렇지 않으면 첫 인덱스 `lo`, 마지막 인덱스 `hi - 1`을 공백 구분해 출력.

스스로 다시 짤 때 생각 순서

1. 두 경계 정의부터: lower = 첫 `>=`, upper = 첫 `>`.
2. 등장 구간 = `[lower, upper-1]`, 등장 횟수 = `upper - lower`.
3. 존재 판정은 반드시 lower로: `lower == n` 경계(최댓값 초과)까지 안전하게 처리.
4. 없을 때만 `-1 -1`, 있을 때만 `lo hi-1` 출력하도록 분기.
```

**2) 특정 값 이하 원소 개수 질의** · Medium

- **요구사항**: 정수 배열과 여러 개의 질의값이 주어진다. 각 질의값 q에 대해 "배열에서 q 이하인 원소의 개수"를 출력하라. 배열은 입력 순서가 뒤섞여 있을 수 있다.
- **입력**: 첫 줄 n, 둘째 줄 정수 n개(정렬 안 됨), 셋째 줄 질의 개수 m, 넷째 줄 질의값 m개.
- **출력**: 각 질의의 답을 공백으로 구분해 한 줄에.
- **예제**:
  - `5 / 3 1 4 1 5 / 3 / 0 3 9` → `0 3 5` (정렬하면 1 1 3 4 5; 0이하 0개, 3이하 3개, 9이하 5개)
  - `4 / 10 20 30 40 / 2 / 25 40` → `2 4`
- **셀프체크**: 먼저 한 번 정렬(O(n log n)) 후 각 질의를 upper_bound로 O(log n)에 답하는가(q **이하** → `>` 술어의 첫 위치 = q 이하 개수)? "미만"이 아니라 "이하"임을 부등호에 반영했는가? 질의가 많을수록(m ≫ n) 이 방법의 이점이 큰 이유를 말할 수 있는가?

```runner
@@SOLUTION
import sys
from bisect import bisect_right
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    arr = [int(data[idx + i]) for i in range(n)]; idx += n
    m = int(data[idx]); idx += 1
    queries = [int(data[idx + i]) for i in range(m)]; idx += m
    arr.sort()
    res = [str(bisect_right(arr, q)) for q in queries]
    print(" ".join(res))
main()
@@TESTS

--OUT

--IN

2

--OUT

@@EXPL
접근·핵심 아이디어

- "q 이하인 원소 개수"는 정렬된 배열에서 `q`보다 **큰** 첫 위치(upper bound)와 같다. 그 인덱스가 곧 앞쪽(=q 이하)의 개수이기 때문이다.
- 배열을 한 번만 정렬해 두면 각 질의를 O(log n)에 답할 수 있어, 질의 수 m이 클수록(m ≫ n) 매번 세는 O(n·m)보다 훨씬 유리하다.

코드 단계별

- `n`, 배열, `m`, 질의값들을 순서대로 읽는다(배열은 정렬 안 된 상태).
- `arr.sort()`로 한 번 오름차순 정렬한다.
- 각 질의 `q`마다 `bisect_right(arr, q)`(= upper bound)를 구하면 그 값이 "q 이하 원소 개수"다.
- 결과를 공백으로 이어 한 줄에 출력한다.

스스로 다시 짤 때 생각 순서

1. "이하"인가 "미만"인가부터 확정 → 이하이므로 `>` 술어의 첫 위치 = `bisect_right`.
2. 반복 질의를 빠르게 하려면 먼저 정렬(전처리 1회).
3. `bisect_left`(미만 개수)와 `bisect_right`(이하 개수)를 혼동하지 않기.
4. 출력은 질의 입력 순서대로, 공백으로 join.
```

**3) 나무 자르기(파라메트릭 서치)** · Hard

- **요구사항**: 높이가 서로 다른 나무 n그루가 있다. 절단기 높이 H를 정하면 H보다 높은 나무는 (높이−H)만큼 잘려 그 합이 가져가는 나무 길이가 된다. 필요한 길이 M 이상을 얻으면서 나무를 최대한 적게 자르도록 하는 **H의 최댓값**(정수)을 구하라.
- **입력**: 첫 줄 n M, 둘째 줄 나무 높이 n개.
- **출력**: 조건을 만족하는 H의 최댓값.
- **예제**:
  - `4 7 / 20 15 10 17` → `15` (H=15: (20-15)+(17-15)=5+2=7 ≥ 7; H=16이면 4+1=5 < 7)
  - `5 20 / 4 42 40 26 46` → `36` ((42-36)+(40-36)+(46-36)=6+4+10=20 ≥ 20; H=37이면 5+3+9=17<20)
- **셀프체크**: 판정 `f(H) = (H로 잘라 얻는 길이) >= M`은 H가 커질수록 True→False로 **단조 감소**한다. 즉 True인 가장 큰 H를 찾는 문제다. 탐색 범위는 `[0, max(높이)]`로 잡는가? 얻는 길이 합이 int 범위를 넘어도 파이썬이라 괜찮은가? H를 나무 높이 배열이 아니라 "답의 후보"에 이분탐색하고 있음을 이해했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    M = int(data[idx]); idx += 1
    h = [int(data[idx + i]) for i in range(n)]; idx += n
    lo, hi = 0, max(h)
    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        got = sum(x - mid for x in h if x > mid)
        if got >= M:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    print(ans)
main()
@@TESTS
--IN
4 7
20 15 10 17
--OUT
15
--IN
5 20
4 42 40 26 46
--OUT
36
@@EXPL
접근·핵심 아이디어

- 답 H 자체를 배열에서 찾는 게 아니라 "답의 후보 범위 `[0, max(높이)]`"에 이분탐색을 건다(파라메트릭 서치).
- 판정 `f(H) = (H로 잘라 얻는 길이) >= M`은 H가 커질수록 얻는 길이가 줄어 True→False로 단조 감소한다. 따라서 True를 유지하는 **가장 큰 H**가 답이다.

코드 단계별

- `n M`과 높이 배열을 읽는다.
- `lo=0`, `hi=max(h)`로 후보 구간을 잡는다.
- `mid`로 잘랐을 때 얻는 길이 `got = sum(x-mid for x in h if x>mid)`를 계산한다.
- `got >= M`이면 이 H로 충분하므로 `ans=mid`로 기록하고 더 높은 H를 시도(`lo=mid+1`), 부족하면 `hi=mid-1`로 낮춘다.
- 얻는 길이 합은 커도 파이썬 정수라 오버플로가 없다.

스스로 다시 짤 때 생각 순서

1. "무엇에 이분탐색하는가?" → 나무 높이가 아니라 **절단기 높이 H**(답의 후보).
2. 단조성 방향 확인: H↑ ⇒ 얻는 길이↓ ⇒ 조건 True에서 False로.
3. True 중 최댓값을 구하므로 조건 만족 시 `lo=mid+1`, `ans` 갱신.
4. 범위 `[0, max(h)]`, 닫힌 구간 `while lo<=hi`로 일관되게 처리.
```

> 개요: 이 챕터에서는 큰 문제를 겹치는 작은 부분문제로 쪼개 그 답을 저장·재활용하는 동적계획법(DP)을 배운다. 재귀+메모이제이션(위→아래)과 반복+테이블(아래→위) 두 구현 방식을 익히고, 부분문제를 단순 합치는 DP와 격자를 한 칸씩 전진하는 DP로 감각을 다진다.

## L1. 동적계획법

**개념**

- 동적계획법(Dynamic Programming, DP)은 "큰 문제의 답이 작은 문제의 답으로 결정되고(최적 부분구조), 그 작은 문제들이 여러 번 겹쳐서 나타날 때(중복 부분문제)" 각 부분문제를 딱 한 번만 풀어 저장해두고 재사용하는 기법이다.
- 순수 재귀는 같은 부분문제를 지수적으로 다시 계산해 느리다. DP는 이미 계산한 답을 표(dict/list)에 적어두고 다음에 그대로 꺼내 쓰므로, 부분문제 개수만큼만 계산한다.
- DP를 설계하는 절차:

  1. 상태(state) 정의: "무엇을 알면 나머지가 결정되는가"를 변수로 잡는다. 예) `dp[i]` = i번째까지 고려했을 때의 답.
  2. 점화식(recurrence): `dp[i]`를 더 작은 `dp[...]`들로 표현한다.
  3. 기저(base case): 가장 작은 부분문제의 답을 직접 정한다.
  4. 계산 순서: 작은 부분문제가 먼저 준비되도록 순서를 정한다(재귀+메모 또는 반복+테이블).

- 대표 예: 피보나치. `f(n) = f(n-1) + f(n-2)`, `f(0)=0, f(1)=1`. 상태는 n 하나, 부분문제는 n+1개뿐이라 O(n)에 끝난다.

```python
# 순수 재귀: f(n-1)과 f(n-2)를 계속 다시 계산 → O(2^n)
def fib_slow(n):
    if n < 2:
        return n
    return fib_slow(n - 1) + fib_slow(n - 2)

# DP: 이미 구한 값을 재사용 → O(n)
def fib_dp(n):
    dp = [0, 1]
    for i in range(2, n + 1):
        dp.append(dp[i - 1] + dp[i - 2])
    return dp[n]
```

**접근 전략**

- 핵심 아이디어: "이 문제를 그대로 조금 더 작은 같은 문제로 표현할 수 있는가?"를 먼저 묻는다. 그렇다면 완전탐색(재귀)으로 관계식을 세운 뒤, 겹치는 부분문제가 보이면 그 값을 저장해 DP로 바꾼다.
- 전형적 절차: (1) 완전탐색 재귀를 먼저 떠올려 점화식을 유도한다 → (2) 상태 변수를 명확히 한다 → (3) 저장 공간(표)을 준비한다 → (4) 기저와 순서를 정한다.
- 언제 쓰나: 최적화(최소/최대/개수 세기) 문제이면서, 선택을 순서대로 하면서 "지금까지의 결과"만 알면 다음이 정해지는 구조일 때. 그리고 같은 상황이 반복 계산될 때.
- 복잡도: (상태 개수) x (한 상태를 채우는 비용). 피보나치는 상태 O(n), 채우는 비용 O(1)이라 시간 O(n)·공간 O(n)(직전 2개만 쓰면 O(1)).
- 흔한 실수: 상태에 필요한 정보를 빠뜨려 서로 다른 상황을 같은 칸에 겹쳐 쓰는 것. `dp[i]`가 정확히 무엇을 뜻하는지 한 문장으로 못 쓰면 상태 정의가 덜 된 것이다.

**문제**

**1) 계단 오르기 경우의 수** · Easy

- **요구사항**: 한 번에 1칸 또는 2칸 오를 수 있을 때, n번째 계단에 도달하는 서로 다른 방법의 수를 구하라.
- **입력**: 정수 n (0 ≤ n ≤ 40)
- **출력**: 방법의 수(정수)
- **예제**: `3` → `3` (1+1+1, 1+2, 2+1) / `5` → `8`
- **셀프체크**: 점화식이 `dp[n]=dp[n-1]+dp[n-2]`임을 스스로 설명할 수 있는가? `n=0`일 때 답이 1(가만히 있음)임을 기저로 잡았는가? n=40에서도 O(n)으로 끝나는가?

```runner
@@SOLUTION
import sys
def main():
    n = int(sys.stdin.readline())
    if n == 0:
        print(1)
        return
    dp = [0] * (n + 1)
    dp[0] = 1
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    print(dp[n])
main()
@@TESTS
--IN
3
--OUT
3
--IN
10
--OUT
89
@@EXPL
(1) 접근·핵심 아이디어

- n번째 계단에 도달하는 마지막 걸음은 "1칸 올라옴" 또는 "2칸 올라옴" 둘 중 하나다. 두 경우가 상호배타적이므로 방법 수는 `dp[n-1] + dp[n-2]`로 그냥 더하면 된다. 피보나치와 같은 점화식이다.
- 기저: `dp[0]=1`(가만히 있는 방법 1가지), `dp[1]=1`.

(2) 코드 단계별

- `n==0`이면 곧바로 1을 출력.
- 크기 `n+1` 표를 만들고 `dp[0]=dp[1]=1`로 초기화.
- `i`를 2부터 n까지 올리며 `dp[i]=dp[i-1]+dp[i-2]`로 채운다.
- `dp[n]`을 출력. 상태 n+1개, 각 O(1)이라 O(n).

(3) 스스로 다시 짤 때 생각 순서

- "마지막 한 걸음"으로 경우를 나눈다 → 각 경우가 더 작은 같은 문제(dp[n-1], dp[n-2])가 됨을 확인.
- 두 경우가 겹치지 않으니 합으로 결합.
- 기저 dp[0], dp[1]을 손으로 확정한 뒤 작은 인덱스부터 반복으로 채운다.
```

**2) 최소 동전 개수** · Medium

- **요구사항**: 서로 다른 액면의 동전들이 무한히 있을 때, 금액 M을 만드는 데 필요한 최소 동전 개수를 구하라. 만들 수 없으면 -1.
- **입력**: 첫 줄에 동전 종류 수 k와 금액 M, 둘째 줄에 k개의 액면가.
- **출력**: 최소 동전 개수 또는 -1.
- **예제**: `3 11 / 1 5 6` → `2` (5+6) / `2 3 / 2 4` → `-1`
- **셀프체크**: `dp[x]`를 "금액 x를 만드는 최소 동전 수"로 정의했는가? 도달 불가를 무한대로 표시해 마지막에 -1로 바꿨는가? 그리디(큰 동전부터)가 왜 틀릴 수 있는지 예제 `1 5 6`으로 확인했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    k = int(data[idx]); idx += 1
    M = int(data[idx]); idx += 1
    coins = [int(data[idx + i]) for i in range(k)]
    INF = float('inf')
    dp = [0] + [INF] * M
    for x in range(1, M + 1):
        for c in coins:
            if c <= x and dp[x - c] + 1 < dp[x]:
                dp[x] = dp[x - c] + 1
    print(dp[M] if dp[M] != INF else -1)
main()
@@TESTS
--IN
3 11
1 5 6
--OUT
2
--IN
2 3
2 4
--OUT
-1
@@EXPL
**이 풀이의 새 문법**

- `float('inf')`: 어떤 수보다도 큰 부동소수 "무한대" 값. "아직 도달 불가/최솟값 비교 전" 상태를 표시하는 초깃값으로 흔히 쓴다.

(1) 접근·핵심 아이디어

- `dp[x]` = 금액 x를 만드는 데 필요한 최소 동전 수. 마지막에 어떤 동전 c를 하나 쓴다고 가정하면 `dp[x] = min(dp[x-c] + 1)`(모든 동전 c에 대해, 단 `c<=x`).
- 도달 불가는 INF로 두고, 최종 `dp[M]`이 INF면 -1 출력. 그리디는 `1 5 6`로 11 만들 때 6+5=2개가 최적인데 큰 동전부터면 6+1+1+1+1+1=6개로 틀린다.

(2) 코드 단계별

- 입력을 통째로 읽어 k, M, 동전 목록을 파싱.
- `dp[0]=0`, 나머지는 INF로 초기화.
- x를 1..M로 올리며 각 동전 c에 대해 `dp[x-c]+1`이 더 작으면 갱신.
- `dp[M]`이 INF면 -1, 아니면 그 값 출력. 시간 O(M·k).

(3) 스스로 다시 짤 때 생각 순서

- "마지막에 쓴 동전"으로 경우를 나눈다 → 각 경우가 dp[x-c] 부분문제.
- 개수 세기가 아니라 최솟값이므로 min으로 결합, +1은 방금 쓴 동전.
- 도달 불가 표시(INF)와 최종 -1 변환을 잊지 말 것. dp[0]=0 기저부터 작은 금액 순으로 채운다.
```

**3) 1로 만들기** · Medium

- **요구사항**: 정수 N에 대해 (a) 1을 뺀다 (b) 2로 나눈다(2의 배수일 때) (c) 3으로 나눈다(3의 배수일 때) 연산을 써서 1로 만들 때, 사용하는 연산의 최소 횟수를 구하라.
- **입력**: 정수 N (1 ≤ N ≤ 1,000,000)
- **출력**: 최소 연산 횟수.
- **예제**: `10` → `3` (10→9→3→1) / `1` → `0`
- **셀프체크**: `dp[x]`를 "x를 1로 만드는 최소 횟수"로 정의하고 세 후보 중 최소를 골랐는가? 나눗셈은 배수일 때만 후보에 넣었는가? N=1,000,000에서 O(N)으로 도는가?

```runner
@@SOLUTION
import sys
def main():
    N = int(sys.stdin.readline())
    dp = [0] * (N + 1)
    for x in range(2, N + 1):
        best = dp[x - 1] + 1
        if x % 2 == 0 and dp[x // 2] + 1 < best:
            best = dp[x // 2] + 1
        if x % 3 == 0 and dp[x // 3] + 1 < best:
            best = dp[x // 3] + 1
        dp[x] = best
    print(dp[N])
main()
@@TESTS
--IN
10
--OUT
3
--IN
1
--OUT
0
@@EXPL
(1) 접근·핵심 아이디어

- `dp[x]` = x를 1로 만드는 최소 연산 횟수. x에서 갈 수 있는 곳은 `x-1`(항상), `x/2`(2의 배수일 때), `x/3`(3의 배수일 때)뿐. 각 후보의 `dp[...] + 1` 중 최소가 `dp[x]`다.
- 작은 값의 답이 큰 값보다 먼저 필요하므로 x를 오름차순으로 채우는 태뷸레이션이 자연스럽다. 기저 `dp[1]=0`.

(2) 코드 단계별

- 크기 `N+1` 표를 0으로 만들고(`dp[1]=0` 자동 포함), x를 2부터 N까지 반복.
- 기본 후보 `dp[x-1]+1`을 best로 두고, x가 2의 배수면 `dp[x//2]+1`, 3의 배수면 `dp[x//3]+1`과 비교해 더 작으면 갱신.
- `dp[N]` 출력. 상태 N개·각 O(1)이라 O(N).

(3) 스스로 다시 짤 때 생각 순서

- "x에서 한 번에 갈 수 있는 다음 상태"를 나열한다 → 세 종류(빼기·2나눗셈·3나눗셈).
- 나눗셈은 나누어떨어질 때만 후보에 포함한다는 조건을 먼저 확정.
- 오름차순으로 채우면 필요한 작은 dp가 항상 준비돼 있음을 확인. 최솟값 문제이니 min으로 결합, +1은 이번 한 연산.
```


## L2. Memoization

**개념**

- 메모이제이션(Memoization)은 DP를 "위에서 아래로(top-down)" 구현하는 방식이다. 원래의 재귀 구조를 그대로 두되, 계산한 부분문제의 답을 표에 기록(memo)해두고, 다음에 같은 부분문제가 호출되면 재계산 없이 표에서 꺼낸다.
- 절차: (1) 재귀 함수로 점화식을 그대로 옮긴다 → (2) 함수 맨 앞에서 "이미 표에 답이 있으면 그걸 반환" → (3) 없으면 계산해서 표에 저장한 뒤 반환.
- 장점: 문제를 재귀로 자연스럽게 표현할 수 있고, 실제로 필요한 부분문제만 계산한다(도달 안 하는 상태는 건드리지 않음). 단점: 재귀 호출 깊이만큼 호출 스택을 쓴다(파이썬 기본 재귀 한도 주의).
- 파이썬 실용: 표는 보통 `dict`나 `list`를 쓰고, "아직 계산 안 함"을 나타내는 초기값(예: `None`, `-1`)을 둔다. 표준 라이브러리 `functools.lru_cache`(또는 `cache`) 데코레이터를 함수에 붙이면 인자별 결과를 자동으로 메모해 준다. `@lru_cache(...)`처럼 함수 정의 바로 위에 `@이름` 한 줄을 적으면, 그 함수를 호출할 때마다 파이썬이 자동으로 감싸 캐시 조회·저장을 대신 처리해 준다(직접 memo 딕셔너리를 짜지 않아도 됨).

```python
import sys
from functools import lru_cache
sys.setrecursionlimit(1_000_000)  # 재귀가 깊어질 수 있으니 한도 상향

# 방법 A: 직접 memo 딕셔너리
memo = {}
def fib(n):
    if n < 2:
        return n
    if n in memo:          # 이미 계산했으면 재사용
        return memo[n]
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]

# 방법 B: lru_cache가 알아서 메모
@lru_cache(maxsize=None)
def fib2(n):
    if n < 2:
        return n
    return fib2(n - 1) + fib2(n - 2)
```

**접근 전략**

- 핵심 아이디어: "완전탐색 재귀를 이미 만들었다면, 함수 진입부에 캐시 조회 3~4줄만 추가하면 곧바로 DP가 된다." 점화식이 자연스럽게 재귀로 떠오르는 문제에서 가장 빠르게 코드로 옮기는 방법이다.
- 전형적 절차: 재귀 정의 → memo 저장소 준비(전역 dict/list 또는 `@lru_cache`) → 진입부 캐시 히트 반환 → 계산 후 저장. 상태(함수 인자)가 곧 표의 키다.
- 언제 쓰나: 상태 공간이 넓거나 희소해서 실제로 방문하는 상태만 계산하고 싶을 때, 또는 점화식은 알지만 "어떤 순서로 채워야 하는지"가 헷갈릴 때(재귀가 순서를 알아서 처리해줌).
- 복잡도: 서로 다른 상태 개수를 S, 한 상태 처리 비용을 C라 하면 시간 O(S·C). 공간은 표 O(S) + 재귀 스택(최대 깊이).
- 흔한 실수: (1) 함수 인자가 아닌 외부 가변 상태에 의존하면 캐시가 오염된다(`lru_cache`는 인자만 키로 봄). (2) 재귀 깊이 초과로 RecursionError → `setrecursionlimit` 상향 또는 Tabulation으로 전환. (3) 리스트를 인자로 넘기면 `lru_cache`가 실패(해시 불가)하므로 tuple 등 불변값으로 상태를 표현한다.

**문제**

**1) 재귀 → 메모 전환** · Easy

- **요구사항**: 아래처럼 정의된 함수 w를 계산하라. `a≤0 또는 b≤0 또는 c≤0`이면 1. `a>20 또는 b>20 또는 c>20`이면 `w(20,20,20)`. `a<b<c`이면 `w(a,b,c-1)+w(a,b-1,c-1)-w(a,b-1,c)`. 그 외에는 `w(a-1,b,c)+w(a-1,b-1,c)+w(a-1,b,c-1)-w(a-1,b-1,c-1)`.
- **입력**: 세 정수 a b c (각각 -50 이상 50 이하). 여러 줄이 주어지고 `-1 -1 -1`이 나오면 종료.
- **출력**: 각 줄마다 `w(a, b, c) = 결과` 형식.
- **예제**: `1 1 1` → `w(1, 1, 1) = 2` / `2 2 2` → `w(2, 2, 2) = 4`
- **셀프체크**: 상태 `(a,b,c)`를 그대로 dict 키로 썼는가? 메모 없이 돌리면 큰 값에서 왜 폭발하는지 이해했는가? 클램프 규칙(20 초과 처리)을 캐시 키에 반영했는가?

```runner
(2) 코드 단계별

- 진입부: 어느 하나라도 0 이하면 1 반환. 어느 하나라도 20 초과면 `w(20,20,20)` 반환(이 값 자체도 메모됨).
- 캐시 히트: `(a,b,c)`가 memo에 있으면 즉시 반환.
- 없으면 `a<b<c` 여부에 따라 두 점화식 중 하나로 계산해 memo에 저장 후 반환.
- 입력을 줄 단위로 읽어 `-1 -1 -1`이면 종료, 그 외에는 `w(a, b, c) = 결과` 형식으로 모아 출력.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 순수 재귀로 정의를 1:1 옮긴다(조기 반환 → 두 재귀식).

- 캐시 조회/저장 3줄을 진입부와 계산 뒤에 끼워 넣는다. 클램프 규칙 덕에 키 공간이 유한(21^3 이하)임을 확인.
```

**2) 포도주 시식** · Medium

- **요구사항**: 일렬로 놓인 포도주 잔의 양이 주어진다. 왼쪽부터 선택하되 "연속해서 3잔"은 마실 수 없다(각 잔은 마시거나 건너뛴다). 마신 포도주 양의 최댓값을 구하라.
- **입력**: 첫 줄에 잔 수 n (1 ≤ n ≤ 10,000), 이후 n개의 양(0 이상 1,000 이하).
- **출력**: 최대 양.
- **예제**: `6 / 6 10 13 9 8 1` → `33` (6,10,-,9,8,- 선택) / `3 / 1 1 1` → `2`
- **셀프체크**: 상태를 "지금 잔 인덱스 i와 직전까지 연속으로 몇 잔 마셨는지"로 잡았는가, 아니면 "i번째까지의 최댓값"으로 잡았는가? 두 정의 모두 가능함을 이해했는가? n=10,000에서 재귀 깊이가 문제되면 어떻게 대응할지 생각했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    a = [int(data[idx + i]) for i in range(n)]
    NEG = float('-inf')
    dp0, dp1, dp2 = 0, NEG, NEG
    for i in range(n):
        v = a[i]
        ndp0 = max(dp0, dp1, dp2)
        ndp1 = dp0 + v
        ndp2 = dp1 + v if dp1 != NEG else NEG
        dp0, dp1, dp2 = ndp0, ndp1, ndp2
    print(max(dp0, dp1, dp2))

(1) 접근·핵심 아이디어

- 상태를 "현재 위치에서 직전까지 연속으로 몇 잔 마셨는가(0/1/2)"로 잡는다. `dp0`=직전 잔을 안 마심, `dp1`=연속 1잔째 마심, `dp2`=연속 2잔째 마심. 연속 3잔이 금지이므로 dp2 다음에 또 마실 수는 없다.
- n=10,000이라 재귀 메모는 깊이 문제가 있어 여기서는 세 변수만 굴리는 반복(rolling)으로 O(n)·O(1) 구현했다.

(2) 코드 단계별

- 잔 수 n과 양 배열을 읽는다.
- 각 잔 i에서: `ndp0`=이번 잔을 건너뜀 = 직전 세 상태의 최대. `ndp1`=이번 잔을 마시는데 직전이 안 마신 상태(dp0)에서 옴. `ndp2`=직전이 연속 1잔(dp1)에서 이어 마심(dp1이 불가능이면 NEG).
- 세 변수를 갱신하며 끝까지 진행, 마지막에 세 상태의 최댓값을 출력.

(3) 스스로 다시 짤 때 생각 순서

- "연속 3잔 금지"를 상태로 흡수한다 → 연속 마신 개수 0/1/2를 상태에 넣는다.
- 각 잔에서 "마신다/안 마신다"로 전이식을 세운다. 마시면 연속 카운트 +1, 건너뛰면 0으로 리셋.
- 재귀 깊이(n=1e4)를 피하려 rolling 변수로 바꾸고, 불가능 상태는 NEG로 막아 잘못된 전이를 차단.
```

**3) 정수 삼각형(위→아래 메모)** · Medium

- **요구사항**: 꼭대기에서 시작해 아래로 내려가며(바로 아래 또는 오른쪽 아래로만 이동) 만나는 수의 합이 최대가 되는 경로의 합을 구하라.
- **입력**: 첫 줄에 층 수 h, 이후 h개의 줄에 각 층의 정수들.
- **출력**: 최대 합.
- **예제**: `3 / 7 / 3 8 / 8 1 0` → `18` (7→3→8) / `1 / 5` → `5`
- **셀프체크**: 재귀 함수를 `best(r, c)` = "(r,c)에서 바닥까지 가는 최대 합"으로 정의했는가? `best(r,c) = tri[r][c] + max(best(r+1,c), best(r+1,c+1))`이 맞는가? 같은 `(r,c)`가 여러 경로에서 재호출됨을 확인하고 메모를 붙였는가?

```runner
@@SOLUTION
import sys
sys.setrecursionlimit(1000000)
def main():
    data = sys.stdin.read().split()
    idx = 0
    h = int(data[idx]); idx += 1
    tri = []
    for r in range(h):
        row = [int(data[idx + c]) for c in range(r + 1)]
        idx += r + 1
        tri.append(row)
    memo = {}
    def best(r, c):
        if r == h - 1:
            return tri[r][c]
        if (r, c) in memo:
            return memo[(r, c)]
        res = tri[r][c] + max(best(r + 1, c), best(r + 1, c + 1))
        memo[(r, c)] = res
        return res
    print(best(0, 0))
main()

(1) 접근·핵심 아이디어

- `best(r, c)` = 칸 (r,c)에서 출발해 바닥까지 내려가며 얻는 최대 합. 아래로는 `(r+1,c)` 또는 `(r+1,c+1)`로만 갈 수 있으므로 `best(r,c) = tri[r][c] + max(best(r+1,c), best(r+1,c+1))`.
- 같은 아래쪽 칸이 여러 상위 경로에서 반복 호출되므로 `(r,c)`를 키로 memo한다(위→아래 top-down DP).

(2) 코드 단계별

- 층 수 h와 각 층의 정수들을 파싱해 2차원 리스트 tri로 만든다.
- 재귀 `best`: 마지막 층이면 그 칸 값 자체가 답(기저). 그 외에는 memo 조회 후 없으면 점화식으로 계산·저장.
- `best(0,0)` 출력. 상태 수는 삼각형 칸 수라 O(h^2).

(3) 스스로 다시 짤 때 생각 순서

- "이 칸에서 바닥까지의 최대"라는 하향식 정의를 세운다 → 두 자식 중 큰 쪽을 물려받고 자기 값을 더한다.
- 바닥 층을 기저로 확정.
- 자식이 겹쳐 호출됨을 확인하고 memo(dict)를 붙여 재계산을 없앤다.
```


## L3. Tabulation

**개념**

- 태뷸레이션(Tabulation)은 DP를 "아래에서 위로(bottom-up)" 구현하는 방식이다. 재귀 없이, 가장 작은 부분문제부터 표(table)를 반복문으로 하나씩 채워 올라간다.
- 절차: (1) 표(list, 종종 1차원/2차원)를 만든다 → (2) 기저 칸을 직접 채운다 → (3) 작은 부분문제가 이미 채워져 있도록 하는 순서로 반복문을 돌며 점화식으로 각 칸을 계산한다 → (4) 목표 칸을 읽는다.
- 메모이제이션과 같은 답을 내지만 구현이 다르다: 메모는 "필요할 때 재귀로 파고들어" 채우고, 태뷸레이션은 "미리 정한 순서로 전부" 채운다.
- 장점: 재귀 스택이 없어 깊이 제한/스택 오버플로 걱정이 없고, 보통 상수배 빠르며, "직전 몇 칸만 필요"하면 공간을 O(1)로 줄이는 최적화(rolling array)가 쉽다. 단점: 채우는 순서를 사람이 직접 정확히 정해야 한다.

```python
# 피보나치 태뷸레이션 (전체 표)
def fib_tab(n):
    if n < 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):   # 작은 것부터 순서대로
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

# 직전 2칸만 쓰는 공간 최적화 → O(1) 공간
def fib_rolling(n):
    prev, cur = 0, 1
    if n == 0:
        return 0
    for _ in range(2, n + 1):
        prev, cur = cur, prev + cur
    return cur
```

**접근 전략**

- 핵심 아이디어: "표를 어떤 순서로 채우면 오른쪽 칸을 계산할 때 필요한 왼쪽 칸이 항상 이미 채워져 있는가?"를 정하는 것이 전부다. 점화식의 화살표 방향(무엇이 무엇에 의존)을 보고 반복 순서를 뒤집으면 된다.
- 전형적 절차: 표 크기·의미 정의 → 기저 채우기 → 의존성이 만족되는 순서로 이중/삼중 반복 → 답 칸 읽기. 필요하면 "직전 행/열만 유지"로 공간 축소.
- 언제 쓰나: 상태를 거의 다 방문하고, 순서를 명확히 정할 수 있을 때. 재귀 깊이가 매우 깊어질 위험이 있을 때(예: n이 수십만) 메모 대신 태뷸레이션이 안전하다.
- 복잡도: 표 칸 수 x 칸당 비용. 1차원 O(n), 2차원 O(n·m) 등. 공간은 표 크기지만 rolling으로 한 차원을 줄일 수 있다.
- 흔한 실수: (1) 채우는 순서를 틀려서 아직 안 채운 칸을 참조. (2) 기저 칸을 빼먹거나 잘못 초기화. (3) rolling 최적화 시 이번 턴에서 덮어써야 할 값을 미리 지워 이전 값을 잃는 것(갱신 순서 주의).

**문제**

**1) 이친수(01로 시작 안 하고 1이 연속 안 하는 수) 개수** · Easy

- **요구사항**: 길이가 정확히 N인 이진 문자열 중, 맨 앞이 1이고 "1이 두 번 연속" 나오지 않는 것의 개수를 구하라(이런 수를 이친수라 한다).
- **입력**: 정수 N (1 ≤ N ≤ 90)
- **출력**: 개수(파이썬 정수라 오버플로 걱정 없음).
- **예제**: `1` → `1` (1) / `3` → `2` (101, 100)
- **셀프체크**: `dp0[i]`(길이 i, 끝이 0), `dp1[i]`(길이 i, 끝이 1)로 상태를 나눴는가? `dp1[i]=dp0[i-1]`, `dp0[i]=dp0[i-1]+dp1[i-1]`이 맞는지 손으로 검산했는가? N=90에서 수가 매우 커도 파이썬이 처리함을 이해했는가?

```runner
- 1 뒤에는 1이 못 오므로 `dp1[i]=dp0[i-1]`. 0은 아무 뒤나 올 수 있어 `dp0[i]=dp0[i-1]+dp1[i-1]`. 기저(길이 1)는 "1"만 가능하니 `dp1=1, dp0=0`.

(2) 코드 단계별

- N=1이면 곧바로 1 출력(문자열 "1" 하나).
- `dp0=0, dp1=1`로 시작해 i를 2부터 N까지 진행하며 위 두 전이식으로 갱신(rolling 변수 2개).
- 최종 답은 `dp0 + dp1`. 파이썬 정수는 임의 정밀도라 N=90의 큰 값도 정확히 나온다.

(3) 스스로 다시 짤 때 생각 순서

- 금지 패턴("11")을 상태로 흡수 → 끝자리 0/1을 상태에 넣는다.
- "1 뒤에는 1 불가" 규칙을 전이식으로 옮긴다(dp1은 dp0에서만 온다).
- 길이 1의 기저를 손으로 확정하고, 길이를 늘리며 두 값을 합쳐 올라간다.
```

**2) 가장 긴 증가하는 부분 수열(LIS) 길이** · Medium

- **요구사항**: 정수 수열에서 순서를 유지한 채 고른 부분수열 중, 값이 순증가하는 가장 긴 것의 길이를 구하라.
- **입력**: 첫 줄에 길이 n (1 ≤ n ≤ 1,000), 이후 n개의 정수.
- **출력**: 최대 길이.
- **예제**: `6 / 10 20 10 30 20 50` → `4` (10 20 30 50) / `1 / 7` → `1`
- **셀프체크**: `dp[i]` = "i에서 끝나는 증가수열의 최대 길이"로 정의했는가? `dp[i] = 1 + max(dp[j])` (단 `j<i`이고 `a[j]<a[i]`)를 이중 루프로 채웠는가? 순서상 `dp[j]`가 `dp[i]`보다 먼저 채워짐을 확인했는가? O(n^2)임을 인지했는가?

```runner
@@SOLUTION

def main():

    best = 1
    for i in range(n):
        for j in range(i):
            if a[j] < a[i] and dp[j] + 1 > dp[i]:
                dp[i] = dp[j] + 1
        if dp[i] > best:
            best = dp[i]
    print(best)

5
@@EXPL
(1) 접근·핵심 아이디어

- `dp[i]` = i번째 원소에서 끝나는 증가하는 부분수열의 최대 길이. i 앞의 모든 j 중 `a[j] < a[i]`인 것들의 `dp[j]`에 1을 더한 최댓값이 `dp[i]`다. 아무 것도 못 이으면 자기 혼자라 1.
- 정답은 모든 `dp[i]`의 최댓값. 앞에서부터 채우면 `dp[j]`(j<i)가 항상 먼저 준비된다.

(2) 코드 단계별

- 배열을 읽고 `dp`를 전부 1로 초기화.
- 각 i에 대해 j를 0..i-1로 돌며 `a[j]<a[i]`이고 `dp[j]+1`이 더 크면 갱신.
- 갱신된 `dp[i]`로 전역 최댓값 best를 갱신하고, 끝에 best 출력. 이중 루프라 O(n^2).

(3) 스스로 다시 짤 때 생각 순서

- "i에서 끝난다"로 상태를 고정 → 마지막 원소가 a[i]인 증가수열의 최대 길이.
- 바로 앞에 올 수 있는 후보 j(값이 더 작은)들을 훑어 가장 긴 것에 이어 붙인다.
- 앞에서부터 채우면 의존성이 만족됨을 확인. 전체 답은 특정 칸이 아니라 max(dp)임을 잊지 말 것.
```

**3) 연속합 최대(최대 부분배열 합)** · Medium

- **요구사항**: 정수 배열에서 연속한 구간(길이 1 이상)의 합 중 최댓값을 구하라.
- **입력**: 첫 줄에 n (1 ≤ n ≤ 100,000), 이후 n개의 정수(음수 포함).
- **출력**: 최대 연속합.
- **예제**: `10 / 10 -4 3 1 5 6 -35 12 21 -1` → `33` (12+21) / `5 / -3 -2 -5 -1 -4` → `-1`
- **셀프체크**: `dp[i]` = "i에서 끝나는 연속합의 최대"로 두고 `dp[i]=max(a[i], dp[i-1]+a[i])`를 세웠는가? 전체 답은 `max(dp)`임을 이해했는가? 전부 음수인 경우도 정답이 나오는가? rolling으로 O(1) 공간이 되는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    cur = a[0]
    best = a[0]
    for i in range(1, n):
        cur = max(a[i], cur + a[i])
        if cur > best:
            best = cur
    print(best)
main()
@@TESTS
--IN
10
10 -4 3 1 5 6 -35 12 21 -1
--OUT
33
--IN
5
-3 -2 -5 -1 -4
--OUT
-1
@@EXPL
(1) 접근·핵심 아이디어

- `dp[i]` = i에서 끝나는 연속 구간의 최대 합. 마지막 원소 a[i]는 반드시 포함하므로 "여기서 새로 시작(a[i])" 또는 "직전 구간에 이어붙임(dp[i-1]+a[i])" 둘 중 큰 쪽이다: `dp[i]=max(a[i], dp[i-1]+a[i])`.
- 전체 답은 max(dp). 구간 길이 1 이상이라 전부 음수여도 "가장 덜 음수인 한 개"가 답이 된다(그래서 best 초기값을 a[0]로).

(2) 코드 단계별

- 배열을 읽고 `cur=best=a[0]`로 시작(직전 dp와 전역 최댓값).
- i를 1..n-1로 돌며 `cur = max(a[i], cur + a[i])`로 갱신하고, best를 그때그때 갱신.
- best 출력. dp 배열 없이 변수 두 개만 쓰는 rolling이라 O(1) 공간.

(3) 스스로 다시 짤 때 생각 순서

- "i에서 끝나는 최대 연속합"으로 상태를 고정 → 선택은 "이어붙이기 vs 새로 시작" 둘뿐.
- 전역 답은 특정 dp[i]가 아니라 모든 i의 최댓값임을 확인.
- 전부 음수 케이스가 깨지지 않도록 best 초기값을 0이 아닌 a[0]로 둔다. 마지막에 dp[i-1]만 쓰이니 변수 하나로 축약.
```


## L4. subproblem을 그대로 합치면 되는 DP

**개념**

- 어떤 DP는 각 칸의 답이 "더 작은 부분문제들의 답을 별다른 가공 없이 그대로 더하거나(합), 최소/최대를 취하기만" 하면 나온다. 즉 부분문제끼리 서로 방해하지 않아 결과를 단순 결합하는 유형이다.
- 이런 문제의 신호: 선택이 독립적이고, "지금 칸까지의 답 = (한 단계 전 후보들의 답) 중 하나를 골라 상수 연산으로 결합". 겹치는 조건이나 뒤늦게 되돌려야 하는 상호작용이 없다.
- 대표 패턴:

  1. 개수 세기(합): `dp[i] = dp[i-1] + dp[i-2] + ...` (계단·타일링·이친수). 각 경로가 서로소라 그냥 더한다.
  2. 최적값(min/max): `dp[i] = 값(i) + min(dp[후보들])` (정수 삼각형, 최소 비용 경로). 부분문제 최적을 그대로 물려받는다.

- 핵심은 "결합 연산이 결합법칙적이고 부작용이 없다"는 점이다. 그래서 상태를 나열하고 바로 앞 후보들을 합치면 끝난다.
- 모듈러 산술 미니박스: 개수 세기 DP는 답이 엄청나게 커지므로 문제에서 "`m`(예: `10007`, `1,000,000,007=1e9+7`)으로 나눈 나머지"를 요구한다. 나머지 연산에는 분배 성질이 있다.

  - `(a + b) % m = ((a % m) + (b % m)) % m`, 곱도 `(a * b) % m = ((a % m) * (b % m)) % m`.
  - 그래서 마지막에 한 번 나머지를 취하든, 중간 덧셈마다 나머지를 취하든 최종 결과는 같다. 오히려 매 단계 나머지를 취해야 값이 폭주하지 않아 안전하다(파이썬은 큰 정수를 지원하지만 관례상, 그리고 다른 언어 호환을 위해 매번 취한다).
  - `10007`, `1e9+7` 같은 값은 경쟁 프로그래밍에서 "충분히 큰 소수"로 흔히 쓰는 관례적 상수다(소수라 나눗셈·조합 계산까지 확장하기 좋다).

```python
# 타일링: 2xN 바닥을 2x1 세로 타일과 1x2 가로 타일(두 개)로 채우는 경우의 수
# dp[i] = dp[i-1](세로 하나 추가) + dp[i-2](가로 두 개 추가)
def tiling(n):
    if n <= 1:
        return 1
    dp = [0] * (n + 1)
    dp[0], dp[1] = 1, 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]   # 두 부분문제를 '그냥' 더함
    return dp[n]
```

**접근 전략**

- 핵심 아이디어: "마지막 한 수(마지막 선택)로 경우를 나누면, 각 경우가 곧바로 더 작은 같은 문제가 되는가?"를 확인한다. 그렇다면 그 작은 문제들의 답을 합치거나(개수) min/max로 고르면(최적) 된다.
- 전형적 절차: 마지막 선택 기준으로 케이스 분할 → 각 케이스를 `dp[더 작은 인덱스]`로 표현 → 합 또는 min/max로 결합 → 기저 설정.
- 언제 쓰나: 선택들이 서로 독립적이고, 뒤의 선택이 앞의 선택을 무효화하지 않을 때. "카운팅 DP"와 "단순 경로 최적화 DP"가 대부분 여기에 속한다.
- 복잡도: 상태당 결합하는 후보 수가 상수 k면 O(n·k). 후보가 앞의 전부이면 O(n^2).
- 흔한 실수: (1) 서로 겹치는(중복 세는) 케이스로 나눠 합에서 과다 계산 — 케이스가 상호배타적인지 반드시 확인. (2) 개수 세기에서 modulo가 요구되면 매 덧셈마다 나머지를 취해야 함. (3) 최적화에서 도달 불가 후보를 무한대로 두지 않아 잘못된 min이 나오는 것.

**문제**

**1) 2xN 타일링(모듈러)** · Easy

- **요구사항**: 2xN 직사각형을 2x1, 1x2 타일로 채우는 경우의 수를 10007로 나눈 나머지로 구하라.
- **입력**: 정수 N (1 ≤ N ≤ 1,000)
- **출력**: 경우의 수 mod 10007.
- **예제**: `2` → `2` / `9` → `55`
- **셀프체크**: `dp[i]=dp[i-1]+dp[i-2]`가 상호배타적 케이스인지(마지막을 세로로 vs 가로 두 장으로) 설명 가능한가? 매 덧셈 뒤 `% 10007`을 적용했는가? 기저 `dp[1]=1, dp[2]=2`가 맞는가?

```runner
@@SOLUTION
import sys
def main():
    N = int(sys.stdin.readline())
    MOD = 10007
    if N == 1:
        print(1)
        return
    dp = [0] * (N + 1)
    dp[1] = 1
    dp[2] = 2
    for i in range(3, N + 1):
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD
    print(dp[N] % MOD)
main()
@@TESTS
--IN
2
--OUT
2
--IN
9
--OUT
55
@@EXPL
(1) 접근·핵심 아이디어

- 2xN을 채우는 경우의 수를 마지막 열 기준으로 나눈다. 마지막을 세로 타일 하나로 채우면 남은 것은 2x(N-1) → `dp[N-1]`. 마지막 두 열을 가로 타일 두 장으로 채우면 남은 것은 2x(N-2) → `dp[N-2]`. 두 경우는 겹치지 않아 그냥 더한다: `dp[N]=dp[N-1]+dp[N-2]`.
- 답이 커지므로 매 덧셈 뒤 `% 10007`. 기저 `dp[1]=1, dp[2]=2`.

(2) 코드 단계별

- N=1이면 1 출력.
- `dp[1]=1, dp[2]=2`로 초기화하고 i를 3..N으로 돌며 `dp[i]=(dp[i-1]+dp[i-2]) % 10007`.
- `dp[N] % 10007` 출력. 시간 O(N).

(3) 스스로 다시 짤 때 생각 순서

- "마지막 열을 어떻게 채우나"로 케이스 분할 → 세로 1장(dp[N-1]) 또는 가로 2장(dp[N-2]).
- 두 케이스가 상호배타적이니 합으로 결합.
- 개수 세기이므로 modulo가 요구됨 → 매 덧셈마다 %를 취해 값 폭주를 막고, 기저 두 칸을 손으로 확정한다.
```

**2) 정수 삼각형 최대 경로합(아래→위 합치기)** · Medium

- **요구사항**: L2-3과 같은 삼각형에서 최대 경로합을 태뷸레이션(아래에서 위로 합치기)으로 구하라.
- **입력**: 첫 줄 층 수 h, 이후 h줄의 정수들.
- **출력**: 최대 합.
- **예제**: `4 / 7 / 3 8 / 8 1 0 / 2 7 4 4` → `20` (7→3→8→2) / `2 / 1 / 2 3` → `4`
- **셀프체크**: 맨 아랫줄을 그대로 `dp`로 두고 위로 올라가며 `dp[c] = tri[r][c] + max(dp[c], dp[c+1])`로 합쳤는가? 이 결합이 두 아래 부분문제를 "그대로" max로 고르는 것임을 이해했는가? 최종 답이 `dp[0]`인가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    h = int(data[idx]); idx += 1
    tri = []
    for r in range(h):
        row = [int(data[idx + c]) for c in range(r + 1)]
        idx += r + 1
        tri.append(row)
    dp = tri[h - 1][:]
    for r in range(h - 2, -1, -1):
        for c in range(r + 1):
            dp[c] = tri[r][c] + max(dp[c], dp[c + 1])
    print(dp[0])
main()
@@TESTS
--IN
3
7
3 8
8 1 0
--OUT
18
--IN
2
1
2 3
--OUT
4
@@EXPL
(1) 접근·핵심 아이디어

- 태뷸레이션으로 아래에서 위로 합친다. `dp[c]` = 현재 처리 중인 행에서 c번째 칸을 밟았을 때 바닥까지의 최대 합. 맨 아랫줄은 자기 값이 곧 답이므로 그대로 dp로 둔다.
- 한 층 위로 올라갈 때 각 칸은 바로 아래 두 칸 `dp[c], dp[c+1]` 중 큰 것을 물려받아 자기 값을 더한다: `dp[c] = tri[r][c] + max(dp[c], dp[c+1])`.
- (주의) 이 러너의 테스트는 최대 경로합이 명확히 검산되는 삼각형으로 골랐다. 첫 번째는 7→3→8=18.

(2) 코드 단계별

- 삼각형을 2차원 리스트로 파싱하고, 마지막 행 복사본을 dp로 삼는다.
- r을 아래에서 위(h-2 → 0)로 내리며 각 칸 c에 대해 위 점화식으로 dp를 갱신(현재 행의 dp[c]는 아래 행 기준으로 덮어쓴다).
- 꼭대기까지 올라오면 `dp[0]`이 정답. 시간 O(h^2), 공간 O(h)(한 행짜리 dp).

(3) 스스로 다시 짤 때 생각 순서

- 재귀 정의 `best(r,c)=tri+max(자식 둘)`를 아래→위 반복으로 뒤집는다.
- 바닥을 기저로 dp에 심고, 위로 올라가며 "두 아래 후보 중 max"를 그대로 골라 결합(부작용 없는 단순 결합).
- dp를 in-place로 덮어써도 이번 행 계산에 필요한 아래 행 값이 아직 살아 있음을 확인한다.
```

**3) 붙어있지 않게 고른 최대 합(하우스 로버)** · Medium

- **요구사항**: 일렬로 값들이 있을 때 인접한 두 개를 동시에 고를 수 없다는 조건에서 고른 값의 최대 합을 구하라.
- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 이후 n개의 음이 아닌 정수.
- **출력**: 최대 합.
- **예제**: `5 / 2 7 9 3 1` → `12` (2+9+1) / `4 / 5 5 10 100` → `105` (5+100)
- **셀프체크**: 마지막 원소를 "고른다 / 안 고른다"로 케이스를 나눴는가? `dp[i] = max(dp[i-1], dp[i-2] + a[i])`가 두 부분문제의 단순 max임을 확인했는가? 두 케이스가 상호배타적인가? rolling으로 O(1) 공간이 되는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    if n == 1:
        print(a[0])
        return
    prev2 = 0
    prev1 = a[0]
    for i in range(1, n):
        cur = max(prev1, prev2 + a[i])
        prev2, prev1 = prev1, cur
    print(prev1)
main()
@@TESTS
--IN
5
2 7 9 3 1
--OUT
12
--IN
4
5 5 10 100
--OUT
105
@@EXPL
(1) 접근·핵심 아이디어

- `dp[i]` = 앞에서 i번째까지 봤을 때 인접 금지 조건에서의 최대 합. 마지막 원소 a[i]를 "안 고르면" 답은 `dp[i-1]`, "고르면" i-1은 못 고르니 `dp[i-2] + a[i]`. 두 케이스가 상호배타적이라 max로 결합: `dp[i]=max(dp[i-1], dp[i-2]+a[i])`.
- 기저 `dp[0]=a[0]`, `dp[-1]`은 없는 것과 같아 0으로 둔다.

(2) 코드 단계별

- 배열을 읽고 n=1이면 a[0] 출력.
- `prev2=0`(dp[i-2]), `prev1=a[0]`(dp[i-1])로 시작.
- i를 1..n-1로 돌며 `cur=max(prev1, prev2+a[i])`를 계산하고 두 변수를 한 칸씩 밀어준다.
- 마지막 `prev1`이 답. dp 배열 없이 O(1) 공간.

(3) 스스로 다시 짤 때 생각 순서

- "마지막 원소를 고르나 마나"로 케이스 분할 → 고르면 i-1 금지(dp[i-2]에서), 안 고르면 dp[i-1] 그대로.
- 두 케이스는 겹치지 않으니 단순 max로 결합.
- dp[i-1], dp[i-2] 둘만 쓰이므로 변수 두 개로 rolling해 공간을 O(1)로 줄인다.
```


## L5. 격자 안에서 한 칸씩 전진하는 DP

**개념**

- 2차원 격자(그리드) 위에서 정해진 방향(보통 오른쪽/아래)으로만 한 칸씩 이동하며 답을 누적하는 DP다. 상태는 대개 `dp[r][c]` = "(r, c) 칸에 도달했을 때의 답(경로 수, 최소/최대 비용 등)".
- 이동 방향이 제한적이라 각 칸은 정해진 몇 개의 이전 칸(위 칸, 왼쪽 칸 등)에서만 온다. 그래서 점화식이 `dp[r][c] = 결합(dp[r-1][c], dp[r][c-1])` 꼴로 깔끔하게 나온다.
- 절차:

  1. 각 칸의 의미(도달 경로 수 / 최소 합 등)를 정한다.
  2. 첫 행·첫 열(가장자리)의 기저를 먼저 채운다 — 이들은 한 방향에서만 올 수 있다.
  3. 왼쪽 위에서 오른쪽 아래로 훑으며(위·왼쪽이 이미 채워지는 순서) 점화식으로 채운다.
  4. 장애물(막힌 칸)은 그 칸을 "도달 불가(경로 수 0 / 비용 무한대)"로 두고 건너뛴다.

```python
# 좌상단(0,0)에서 우하단(R-1,C-1)까지 오른쪽/아래로만 갈 때 경로 수
def count_paths(R, C):
    dp = [[0] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            if r == 0 and c == 0:
                dp[r][c] = 1            # 시작칸: 경로 1개
            else:
                up   = dp[r-1][c] if r > 0 else 0
                left = dp[r][c-1] if c > 0 else 0
                dp[r][c] = up + left    # 위·왼쪽에서 오는 경로를 합침
    return dp[R-1][C-1]
```

**접근 전략**

- 핵심 아이디어: "이 칸에 도달하는 방법은 오직 위 칸 또는 왼쪽 칸을 거치는 것"이라는 이동 제약을 그대로 점화식으로 옮긴다. 경로 수면 더하고, 비용 최적화면 min/max를 취한 뒤 현재 칸 값을 더한다.
- 전형적 절차: 격자 크기의 dp 표 생성 → 시작칸/가장자리 기저 채움 → 행 우선(또는 열 우선)으로 스캔하며 채움 → 목표칸 읽기. 장애물은 도달 불가 값으로 처리.
- 언제 쓰나: "격자에서 한쪽 구석에서 반대 구석까지, 제한된 방향 이동"이 명시된 문제(경로 개수, 최소/최대 합, 사탕/보석 줍기 등).
- 복잡도: 칸 수만큼 각 한 번 채우므로 시간 O(R·C), 공간 O(R·C). 한 행씩만 필요하면 dp를 1차원으로 줄여 공간 O(C).
- 흔한 실수: (1) 첫 행/첫 열 기저를 일반 점화식으로 잘못 처리해 인덱스 음수 참조. (2) 시작·도착칸 자체가 장애물인 경우 답을 0/무한대로 처리하지 못함. (3) 방향이 오른쪽·아래 외에 대각선도 허용되면 후보 칸을 하나 더 넣어야 하는데 빠뜨림.

**문제**

**1) 격자 경로의 수(장애물 포함)** · Easy

- **요구사항**: R x C 격자에서 (0,0)→(R-1,C-1)로 오른쪽/아래로만 이동한다. 일부 칸은 장애물(#)로 지날 수 없다. 서로 다른 경로의 수를 구하라.
- **입력**: 첫 줄에 R C, 이후 R줄에 `.`(빈 칸)과 `#`(장애물)로 된 격자.
- **출력**: 경로 수.
- **예제**: `3 3 / ... / .#. / ...` → `2` / `2 2 / .# / ..` → `1`
- **셀프체크**: 장애물 칸을 dp 0으로 두고 건너뛰었는가? 시작칸이 장애물이면 답이 0인가? 첫 행/열에서 앞쪽에 장애물이 있으면 그 뒤가 모두 0이 되는지 확인했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    R = int(data[0]); C = int(data[1])
    grid = data[2:2 + R]
    dp = [[0] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            if grid[r][c] == '#':
                dp[r][c] = 0
                continue
            if r == 0 and c == 0:
                dp[r][c] = 1
            else:
                up = dp[r - 1][c] if r > 0 else 0
                left = dp[r][c - 1] if c > 0 else 0
                dp[r][c] = up + left
    print(dp[R - 1][C - 1])
main()

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- `dp[r][c]` = (0,0)에서 (r,c)까지 오른쪽/아래로만 가는 경로 수. 각 칸은 위 칸과 왼쪽 칸에서만 올 수 있으므로 `dp[r][c] = dp[r-1][c] + dp[r][c-1]`.
- 장애물(`#`)은 지날 수 없으니 그 칸의 경로 수를 0으로 못 박는다. 시작칸이 장애물이면 자연히 답 0.

(2) 코드 단계별

- 첫 줄에서 R, C를 읽고 이어지는 R개의 문자열을 격자로 받는다.
- 행 우선으로 스캔: `#`이면 dp 0. 시작칸이면 1. 나머지는 위/왼쪽 값을 더하되 경계 밖은 0으로 취급.
- `dp[R-1][C-1]` 출력. 시간·공간 O(R·C).

(3) 스스로 다시 짤 때 생각 순서

- "이 칸에 오는 길은 위 아니면 왼쪽"이라는 이동 제약을 점화식으로 옮긴다(경로 수이니 합).
- 장애물을 도달 불가(경로 0)로 처리하는 규칙을 스캔 맨 앞에 둔다.
- 왼쪽 위→오른쪽 아래 순서로 훑으면 위·왼쪽이 항상 먼저 채워짐을 확인. 첫 행/열은 경계 밖 참조를 0으로 막는다.
```

**2) 최소 비용 격자 경로** · Medium

- **요구사항**: 각 칸에 비용이 있는 R x C 격자에서 (0,0)→(R-1,C-1)로 오른쪽/아래로만 이동할 때, 지나온 칸 비용 합의 최솟값을 구하라(시작·도착칸 포함).
- **입력**: 첫 줄 R C, 이후 R줄에 각 칸의 비용(0 이상 정수).
- **출력**: 최소 비용 합.
- **예제**: `2 2 / 1 3 / 1 5` → `7` (1→1→5) / `3 3 / 1 3 1 / 1 5 1 / 4 2 1` → `7` (1→3→1→1→1)
- **셀프체크**: `dp[r][c] = cost[r][c] + min(dp[r-1][c], dp[r][c-1])`를 세웠는가? 첫 행/열은 한 방향 누적합으로 채웠는가? 두 번째 예제 경로를 손으로 검산했는가(1+3+1+1+1=7)?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    R = int(data[idx]); C = int(data[idx + 1]); idx += 2
    cost = []
    for r in range(R):
        row = [int(data[idx + c]) for c in range(C)]
        idx += C
        cost.append(row)
    INF = float('inf')
    dp = [[INF] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            if r == 0 and c == 0:
                dp[r][c] = cost[r][c]
            else:
                up = dp[r - 1][c] if r > 0 else INF
                left = dp[r][c - 1] if c > 0 else INF
                dp[r][c] = cost[r][c] + min(up, left)
    print(dp[R - 1][C - 1])
main()
@@TESTS
--IN
2 2
1 3
1 5
--OUT
7
--IN
3 3
1 3 1
1 5 1
4 2 1
--OUT
7
@@EXPL
(1) 접근·핵심 아이디어

- `dp[r][c]` = (0,0)에서 (r,c)까지 오른쪽/아래로만 갈 때 지나온 칸 비용 합의 최솟값. 이 칸에는 위 또는 왼쪽에서 오므로 둘 중 작은 누적합에 자기 칸 비용을 더한다: `dp[r][c] = cost[r][c] + min(dp[r-1][c], dp[r][c-1])`.
- 시작칸은 자기 비용, 첫 행/첫 열은 한 방향(왼쪽만/위쪽만) 누적합. 경계 밖 후보는 INF로 막아 min에서 제외된다.

(2) 코드 단계별

- R, C와 비용 격자를 파싱.
- 행 우선 스캔: 시작칸은 `cost[0][0]`. 나머지는 위/왼쪽 dp(없으면 INF) 중 min에 자기 비용을 더함.
- `dp[R-1][C-1]` 출력. 두 번째 예제 경로 1→3→1→1→1=7을 손으로 확인 가능. 시간·공간 O(R·C).

(3) 스스로 다시 짤 때 생각 순서

- "이 칸에는 위/왼쪽에서만 온다"를 최적화 버전으로 옮긴다(경로 수의 합 대신 min 후 자기 비용 더하기).
- 첫 행/열은 한 방향만 가능 → 경계 밖을 INF로 두면 자동으로 처리됨.
- 왼쪽 위→오른쪽 아래 순서면 의존성이 만족됨을 확인하고 목표칸을 읽는다.
```

**3) 두 방향 최대 사탕(대각선 포함 전진)** · Hard

- **요구사항**: R x C 격자의 각 칸에 사탕 수가 있다. (0,0)에서 (R-1,C-1)까지 이동하되, 한 번에 오른쪽·아래·오른쪽아래(대각선) 중 하나로 갈 수 있다. 지나온 칸 사탕 합의 최댓값을 구하라.
- **입력**: 첫 줄 R C, 이후 R줄에 각 칸의 사탕 수(0 이상 정수).
- **출력**: 최대 사탕 합.
- **예제**: `2 2 / 1 2 / 3 4` → `8` ((0,0)→(1,0)→(1,1): 1+3+4) / `2 3 / 1 9 1 / 1 1 1` → `12` (1→9→1→1)
- **셀프체크**: 후보를 세 칸 `dp[r-1][c], dp[r][c-1], dp[r-1][c-1]`로 확장했는가? 첫 행/첫 열에서 존재하지 않는 후보를 무한소/제외 처리했는가? 대각선을 넣었을 때 첫 예제가 왜 대각선(1+4=5)보다 아래-오른쪽(1+3+4=8)이 큰지 확인했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    R = int(data[idx]); C = int(data[idx + 1]); idx += 2
    g = []
    for r in range(R):
        row = [int(data[idx + c]) for c in range(C)]
        idx += C
        g.append(row)
    NEG = float('-inf')
    dp = [[NEG] * C for _ in range(R)]
    for r in range(R):
        for c in range(C):
            if r == 0 and c == 0:
                dp[r][c] = g[r][c]
            else:
                cand = NEG
                if r > 0:
                    cand = max(cand, dp[r - 1][c])
                if c > 0:
                    cand = max(cand, dp[r][c - 1])
                if r > 0 and c > 0:
                    cand = max(cand, dp[r - 1][c - 1])
                dp[r][c] = g[r][c] + cand
    print(dp[R - 1][C - 1])
main()
@@TESTS
--IN
2 2
1 2
3 4
--OUT
8
--IN
2 3
1 9 1
1 1 1
--OUT
12
@@EXPL
(1) 접근·핵심 아이디어

- `dp[r][c]` = (0,0)에서 (r,c)까지 오른쪽·아래·대각선(오른쪽아래) 이동으로 모을 수 있는 사탕 합의 최댓값. 이 칸에 오는 직전 칸이 세 곳(`(r-1,c)`, `(r,c-1)`, `(r-1,c-1)`)이므로 그중 최대에 자기 칸 값을 더한다.
- 첫 예제에서 대각선 한 번(1→4=5)보다 아래-오른쪽(1→3→4=8)이 커서 답이 8이다. 대각선이 항상 이득은 아님을 보여준다.

(2) 코드 단계별

- R, C와 사탕 격자를 파싱하고 dp를 NEG로 초기화.
- 행 우선 스캔: 시작칸은 자기 값. 나머지는 존재하는 세 후보(위/왼쪽/대각선) 중 max에 자기 값을 더함. 경계 밖 후보는 조건문으로 제외.
- `dp[R-1][C-1]` 출력. 시간·공간 O(R·C).

(3) 스스로 다시 짤 때 생각 순서

- 이동 방향이 셋으로 늘었으니 후보 칸도 셋으로 확장(위·왼쪽·대각선).
- 첫 행/열에서 없는 후보는 `if r>0 / if c>0`로 걸러 잘못된 참조/무한소를 방지.
- 최대 합이니 세 후보 중 max를 고른 뒤 자기 값을 더한다. 대각선이 반드시 최적이 아님을 예제로 검산.
```

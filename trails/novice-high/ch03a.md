> 개요: 비교 기반의 기초 정렬(거품·선택·삽입)과 비교하지 않고 자릿수로 나누는 기수 정렬을 원리·복잡도까지 익히고, 각 정렬이 어떤 상황에서 유리한지 속도를 비교한다.

## L1. 거품 정렬

**개념**

- 거품 정렬(Bubble Sort)은 이웃한 두 원소를 비교해 순서가 어긋나면 자리를 바꾸는 것을 반복하는 정렬이다. 한 번 훑을 때마다 가장 큰(또는 작은) 값이 거품처럼 끝으로 "떠오르며" 제자리를 찾는다.
- 왜 배우나: 가장 단순해서 "인접 교환으로 순서를 맞춘다"는 정렬의 기본 감각을 익히기 좋고, 뒤에 나오는 안정 정렬(Stable Sort) 개념의 출발점이다. 실전 성능은 나쁘니 원리 학습용으로 본다.
- 동작 원리(오름차순)

- 1단계: 왼쪽부터 인접한 두 원소 `a[j]`, `a[j+1]`을 비교한다.
- 2단계: `a[j] > a[j+1]`이면 두 값을 교환한다.
- 3단계: 배열 끝까지 훑으면 가장 큰 값이 맨 뒤에 확정된다.
- 4단계: 확정된 뒷부분을 제외하고 1~3단계를 반복한다. 한 번의 훑기에서 교환이 한 번도 없었다면 이미 정렬된 것이므로 멈춘다(조기 종료).

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):   # 뒤쪽 i개는 이미 확정
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:              # 이번 훑기에 교환 없음 → 정렬 완료
            break
    return a
```

**그림으로 보기**

```text
 pass 1                # [ ] 안의 값이 오른쪽으로 밀려가며 끝에 쌓인다
  [5] 1  4  2  8      compare (5,1)  5>1  -> swap
   1 [5] 4  2  8      compare (5,4)  5>4  -> swap
   1  4 [5] 2  8      compare (5,2)  5>2  -> swap
   1  4  2 [5] 8      compare (5,8)  5<8  -> keep
   1  4  2  5 [8]     end of pass 1
                ^^^   # 이 칸 확정. 다음 패스 범위는 n-1-i 로 줄어든다
```

큰 값이 거품처럼 오른쪽 끝으로 떠오른다. 한 패스가 끝날 때마다 뒤쪽에서 한 칸씩 "확정 구간"이 자라므로, 안쪽 루프 범위를 `range(n - 1 - i)`로 줄이는 것이다.

```text
 fixed zone grows from the right     # | 오른쪽은 다시 보지 않는다
  pass 0 :  1  4  2  5 |8
  pass 1 :  1  2  4 |5  8
  pass 2 :  1  2 |4  5  8            # 이 패스에서 교환 0 -> 조기 종료
```

**손으로 따라가기**

`a = [5, 1, 4, 2, 8]`을 오름차순으로 정렬한다.

| 패스 i | 비교 범위 j | 교환 | 패스 후 배열 | 확정 |
|---|---|---|---|---|
| 0 | 0..3 | 3회 | `1 4 2 5 8` | `8` |
| 1 | 0..2 | 1회 | `1 2 4 5 8` | `5 8` |
| 2 | 0..1 | 0회 | `1 2 4 5 8` | 조기 종료 |

패스 2에서 교환이 한 번도 없었으므로 `swapped` 플래그가 `False`가 되어 남은 패스를 건너뛴다. 이미 정렬된 입력이라면 이 조기 종료 덕분에 패스 한 번(비교 n-1회)만에 끝나 O(n)이 된다.

**왜 이렇게 되는가**

- 비교 횟수를 직접 세어 보자. 패스 0은 `n-1`번, 패스 1은 `n-2`번, …, 마지막 패스는 1번 비교한다.
- 합하면 (n-1) + (n-2) + … + 1 = n(n-1)/2 = (n² - n)/2. 지배항은 n²/2이므로 O(n²)이다.
- n=5면 4+3+2+1 = 10번, n=1000이면 약 50만 번. n이 10배가 되면 비교는 100배가 된다.
- 최선이 O(n)인 이유: 이미 정렬돼 있으면 첫 패스에서 교환이 0이라 바깥 루프가 즉시 끊긴다. 비교는 n-1번만 하고 끝난다. 이 조기 종료가 없으면 최선도 O(n²)이다.
- 안정성: 교환 조건이 `a[j] > a[j+1]`(등호 없음)이라 값이 같으면 서로 넘어가지 않는다. 같은 값끼리의 앞뒤 순서가 절대 뒤집히지 않으므로 안정 정렬이다. `>=`로 바꾸는 순간 안정성이 깨진다.

**접근 전략**

- 핵심 아이디어: "인접한 쌍을 비교·교환"만으로 큰 값을 끝으로 밀어낸다. 매 패스마다 정렬 대상 구간이 뒤에서부터 하나씩 줄어든다(`n-1-i`).
- 전형 패턴: 바깥 루프 = 패스 횟수, 안쪽 루프 = 이번 패스에서 비교할 범위. `swapped` 플래그로 조기 종료를 넣으면 "거의 정렬된 입력"에서 빨라진다.
- 언제 쓰나: 실무에선 거의 안 쓴다. 데이터가 아주 작거나, 안정성이 필요하고 구현이 단순해야 할 때, 또는 학습·면접에서 원리를 물을 때.
- 복잡도: 시간 최악·평균 O(n²), 최선 O(n)(이미 정렬 + 조기 종료). 공간 O(1)(제자리 교환). 안정 정렬이다(같은 값끼리 순서 유지).
- 흔한 실수: 안쪽 범위를 `range(n-1)`로 고정해 이미 확정된 뒷부분을 또 비교(비효율). 등호까지 교환(`>=`)하면 안정성이 깨진다 — 반드시 `>`만 교환.

**문제**

**1) 패스별 스냅샷** · Easy

- **요구사항**: 거품 정렬을 오름차순으로 수행하되, 바깥 루프의 한 패스가 끝날 때마다 그 순간의 배열 상태를 한 줄씩 출력하라. 조기 종료가 발생하면 더 이상 출력하지 않는다.
- **입력**: 첫 줄에 정수 개수 N(1 ≤ N ≤ 100), 둘째 줄에 공백으로 구분된 N개의 정수.
- **출력**: 각 패스 종료 후의 배열을 공백으로 구분해 한 줄씩.
- **예제**: `3 / 5 1 4 2 8` → 첫 패스 후 `1 4 2 5 8`, 둘째 패스 후 `1 2 4 5 8`, 셋째 패스는 교환이 없어 종료(출력 안 함). 즉 출력은 두 줄: `1 4 2 5 8` 과 `1 2 4 5 8`
- **예제**: `4 / 2 1 3 4` → 첫 패스 후 `1 2 3 4`, 둘째 패스는 교환 없어 종료. 출력 한 줄: `1 2 3 4`
- **셀프체크**: 첫 예제에서 첫 패스 상세 — (5,1)교환→`1 5 4 2 8`, (5,4)교환→`1 4 5 2 8`, (5,2)교환→`1 4 2 5 8`, (5,8)유지. 조기 종료를 넣지 않으면 마지막 불필요한 패스가 한 줄 더 출력되는 함정.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    out = []
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:          # 이번 패스에 교환 없음 → 조기 종료(출력 안 함)
            break
        out.append(" ".join(map(str, a)))
    print("\n".join(out))

main()
@@TESTS
--IN
5
5 1 4 2 8
--OUT
1 4 2 5 8
1 2 4 5 8
--IN
4
2 1 3 4
--OUT
1 2 3 4
@@EXPL
(1) 접근·핵심 아이디어

- 거품 정렬은 "한 패스 = 인접쌍을 왼→오로 훑으며 큰 값을 뒤로 밀기"다. 이 문제는 각 패스가 끝난 직후의 배열을 한 줄씩 기록하되, 교환이 한 번도 없던 패스는 이미 정렬 완료이므로 출력하지 않고 멈추는 게 핵심.

(2) 코드 단계별

- 바깥 루프 `i`: 패스 번호. 안쪽 범위는 `n-1-i`로 줄인다(뒤쪽 `i`개는 이미 확정).
- 안쪽 루프에서 `a[j] > a[j+1]`이면 교환하고 `swapped=True`.
- 패스가 끝났을 때 `swapped`가 False면 `break` — 이 패스 결과는 append하지 않는다(불필요한 마지막 줄 방지).
- 교환이 있었으면 그 순간의 배열을 문자열로 만들어 `out`에 쌓고, 마지막에 개행으로 이어 출력.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "패스마다 스냅샷"이라는 뼈대를 세우고, 그 다음 "교환 없으면 멈추고 그 패스는 안 찍는다"를 조건 배치로 옮긴다.
- 함정 점검: `swapped` 판정을 append보다 먼저 두어야 조기 종료 패스가 출력에 섞이지 않는다. 안쪽 범위 축소(`n-1-i`)는 결과에 영향 없지만 습관으로.
```

**2) 교환 횟수 세기** · Easy

- **요구사항**: 거품 정렬로 오름차순 정렬하는 동안 실제로 발생한 값 교환(swap) 횟수를 세어 출력하라. (조기 종료를 적용해도 교환 횟수 자체는 동일하다.)
- **입력**: 첫 줄 N(1 ≤ N ≤ 1000), 둘째 줄 N개의 정수.
- **출력**: 총 교환 횟수 하나.
- **예제**: `5 / 5 1 4 2 8` → `4`
- **예제**: `4 / 4 3 2 1` → `6`
- **셀프체크**: 이 값은 정확히 배열의 역위(inversion, i<j인데 a[i]>a[j]인 쌍) 개수와 같다. `4 3 2 1`의 역위 쌍은 6개(모든 쌍이 역순)이므로 6. 조기 종료 유무는 교환 횟수에 영향 없음.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    cnt = 0
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                cnt += 1               # 실제 교환마다 카운트
                swapped = True
        if not swapped:
            break
    print(cnt)

main()
@@TESTS
--IN
5
5 1 4 2 8
--OUT
4
--IN
4
4 3 2 1
--OUT
6
@@EXPL
(1) 접근·핵심 아이디어

- 거품 정렬을 그대로 돌리되, 값을 교환하는 그 순간마다 카운터를 1 증가시킨다. 이 총합은 배열의 역위(inversion) 개수와 정확히 같다 — 인접 교환 한 번이 역위 하나를 없애기 때문. 조기 종료를 넣든 안 넣든 실제 교환 횟수는 변하지 않는다.

(2) 코드 단계별

- 표준 거품 정렬의 이중 루프를 세운다(안쪽 범위 `n-1-i`).
- `a[j] > a[j+1]`일 때만 교환하고 그 자리에서 `cnt += 1`.
- `swapped` 플래그로 조기 종료해도 되지만, 교환이 없어 멈추는 것이므로 카운트에는 영향 없음.
- 마지막에 `cnt` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "정렬 자체는 그대로, 교환 지점에 카운터만 얹는다"로 생각하면 단순하다.
- 검산은 역위 개수로: 모든 `i<j` 쌍 중 `a[i]>a[j]`인 것을 세면 같은 값이 나와야 한다. `4 3 2 1`은 모든 6쌍이 역순 → 6.
```

**3) K번 훑은 결과** · Medium

- **요구사항**: 거품 정렬을 정확히 K번의 패스만 수행한 뒤의 배열을 출력하라(정렬이 도중에 끝나면 남은 패스는 하지 않는다). 인접 비교는 항상 배열 왼쪽 끝에서 시작한다.
- **입력**: 첫 줄에 N과 K(1 ≤ K ≤ N ≤ 100), 둘째 줄 N개 정수.
- **출력**: K패스 후의 배열을 공백으로 구분해 출력.
- **예제**: `5 1 / 5 1 4 2 8` → `1 4 2 5 8` (한 패스 후)
- **예제**: `5 2 / 5 1 4 2 8` → `1 2 4 5 8` (두 패스 후)
- **셀프체크**: K가 필요한 패스 수보다 크면 그냥 완전 정렬 결과가 나온다. 매 패스에서 비교 범위를 `n-1-i`로 줄이지 않고 고정하면 결과 배열은 같지만 비교 횟수가 달라진다 — 결과 검증엔 영향 없으나 복잡도 감각을 위해 줄이는 습관.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    k = int(data[1])
    a = [int(x) for x in data[2:2 + n]]
    for i in range(k):               # 정확히 K번의 패스만
        swapped = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:              # 도중에 정렬 완료되면 남은 패스 생략
            break
    print(" ".join(map(str, a)))

main()
@@TESTS
--IN
5 1
5 1 4 2 8
--OUT
1 4 2 5 8
--IN
5 2
5 1 4 2 8
--OUT
1 2 4 5 8
@@EXPL
(1) 접근·핵심 아이디어

- 완전 정렬이 아니라 "딱 K번의 패스만" 돌린 중간 상태를 출력한다. 각 패스는 왼쪽 끝에서 시작하는 표준 거품 패스이고, 뒤쪽 확정 구간(`i`개)은 비교에서 제외한다. 도중에 교환이 전혀 없으면 이미 정렬된 것이므로 남은 패스는 하지 않는다.

(2) 코드 단계별

- 입력에서 `n`, `k`, 배열을 읽는다.
- 바깥 루프를 `range(k)`로 제한 — 여기가 "정확히 K번" 규칙.
- 안쪽은 `range(n-1-i)`로 인접 비교·교환.
- `swapped`가 False면 조기 종료(K보다 적게 돌 수 있음).
- 루프가 끝나면 현재 배열을 출력.

(3) 스스로 다시 짤 때 생각 순서

- "표준 거품 정렬에서 바깥 루프 상한을 `k`로 바꾼다"가 전부다.
- K가 필요한 패스 수보다 크면 조기 종료 덕에 그냥 완전 정렬 결과가 나온다.
- 함정: 안쪽 범위를 `n-1`로 고정해도 결과는 같지만 확정 구간을 다시 훑는 낭비 — `n-1-i`로 줄이는 습관을 들인다.
```


## L2. 선택 정렬

**개념**

- 선택 정렬(Selection Sort)은 아직 정렬되지 않은 구간에서 최솟값(오름차순 기준)을 골라, 그 구간의 맨 앞과 교환하는 것을 반복하는 정렬이다. "매 단계에서 제자리에 들어갈 값을 선택한다"가 핵심.
- 왜 배우나: 교환(swap) 횟수가 최대 n-1로 매우 적다는 독특한 성질이 있어, "쓰기 비용이 비싼 상황"에서의 정렬을 이해하는 데 좋다.
- 동작 원리(오름차순)

- 1단계: 위치 i(0부터)를 정한다. i부터 끝까지가 "미정렬 구간".
- 2단계: 미정렬 구간에서 최솟값의 인덱스 `min_idx`를 찾는다.
- 3단계: `a[i]`와 `a[min_idx]`를 교환한다. 이제 i 자리가 확정된다.
- 4단계: i를 1 늘려 2~3단계를 n-1번 반복한다.

```python
def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if a[j] < a[min_idx]:
                min_idx = j
        a[i], a[min_idx] = a[min_idx], a[i]  # 최솟값을 앞으로
    return a
```

**그림으로 보기**

```text
 selection sort on [29, 10, 14, 37, 13]
 i=0   [29 10 14 37 13]   min=10 (idx 1)  swap(0,1)
       10 | 29 14 37 13
 i=1   10 |[29 14 37 13]  min=13 (idx 4)  swap(1,4)
       10 13 | 14 37 29
 i=2   10 13 |[14 37 29]  min=14 (idx 2)  swap(2,2)
       10 13 14 | 37 29
 i=3   10 13 14 |[37 29]  min=29 (idx 4)  swap(3,4)
       10 13 14 29 | 37
 # | 왼쪽이 확정 구간, [ ] 안이 아직 안 본 구간
```

거품 정렬이 "인접 교환으로 밀어낸다"면 선택 정렬은 "구간 전체를 훑어 최솟값의 자리를 알아낸 뒤 딱 한 번 바꾼다". 그래서 비교는 똑같이 많은데 교환만 극적으로 적다.

```text
 unstable case               # 값이 같은 2 를 앞의 것부터 2a, 2b 라 하자
  [2a 2b 1]   i=0 : min = 1 (idx 2)  ->  swap(0, 2)
  [1  2b 2a]                 # 멀리 있는 값과 바꾸느라 2a 가 2b 뒤로 갔다
```

**손으로 따라가기**

`a = [29, 10, 14, 37, 13]`.

| i | 미정렬 구간 | 비교 횟수 | min 값(인덱스) | 교환 | 결과 |
|---|---|---|---|---|---|
| 0 | `29 10 14 37 13` | 4 | 10 (1) | (0,1) | `10 29 14 37 13` |
| 1 | `29 14 37 13` | 3 | 13 (4) | (1,4) | `10 13 14 37 29` |
| 2 | `14 37 29` | 2 | 14 (2) | (2,2) | `10 13 14 37 29` |
| 3 | `37 29` | 1 | 29 (4) | (3,4) | `10 13 14 29 37` |

비교는 4+3+2+1 = 10번, 교환은 4번(그중 i=2는 제자리 교환이라 실제로는 무의미). 마지막 원소는 자동으로 제자리이므로 바깥 루프가 `n-1`번만 돌면 된다.

**왜 이렇게 되는가**

- 비교 횟수: i=0에서 `n-1`번, i=1에서 `n-2`번, …, i=n-2에서 1번 → 합이 n(n-1)/2. 입력이 무엇이든 이 값은 변하지 않는다.
- 그래서 최선·평균·최악이 모두 O(n²)이다. 거품·삽입과 달리 "이미 정렬됨"을 알아챌 장치가 없다. 최솟값이 어디 있는지는 끝까지 봐야만 알기 때문이다.
- 교환은 바깥 루프마다 정확히 한 번이라 최대 `n-1`번. 원소 하나를 옮기는 비용이 비교 비용보다 훨씬 큰 상황(레코드가 크거나 쓰기가 느린 저장매체)에서 선택 정렬이 살아남는 이유다.
- 불안정한 이유: 교환 상대가 "바로 옆"이 아니라 "멀리 있는 최솟값 자리"다. 그 사이를 건너뛰며 같은 값의 앞뒤 관계를 무너뜨릴 수 있다. 위 `[2a 2b 1]` 예가 최소 반례다.

**접근 전략**

- 핵심 아이디어: 비교로 최솟값의 "위치"만 추적하다가, 패스가 끝날 때 딱 한 번 교환한다. 비교는 많지만 교환은 최소.
- 전형 패턴: 바깥 루프가 확정 위치 i, 안쪽 루프가 최소 인덱스 탐색. 최솟값 대신 최댓값을 뒤로 보내는 변형도 동일 원리.
- 언제 쓰나: 교환/쓰기 비용이 비교보다 훨씬 비쌀 때(예: 큰 레코드를 실제로 옮겨야 하고 이동 비용이 클 때). 입력 상태와 무관하게 비교 횟수가 일정해 예측 가능.
- 복잡도: 시간 최악·평균·최선 모두 O(n²)(조기 종료가 없음 — 이미 정렬돼 있어도 매번 전 구간을 비교). 교환은 O(n). 공간 O(1). 기본 구현은 불안정 정렬(멀리 있는 원소와 교환하며 같은 값의 상대 순서가 뒤집힐 수 있음).
- 흔한 실수: 안쪽 루프에서 값을 즉시 교환해 버리는 것(그러면 교환이 많아지고 사실상 다른 알고리즘이 됨) — 인덱스만 갱신하고 루프가 끝난 뒤 한 번만 교환. 불안정하다는 점을 안정으로 착각.

**문제**

**1) 교환 로그** · Easy

- **요구사항**: 선택 정렬(오름차순)을 수행하며, 각 패스에서 실제로 교환이 일어난 경우 `i min_idx` 두 인덱스를 한 줄로 출력하라. `i == min_idx`라 교환이 필요 없으면 출력하지 않는다.
- **입력**: 첫 줄 N(1 ≤ N ≤ 100), 둘째 줄 N개의 서로 다른 정수.
- **출력**: 교환이 발생한 패스마다 `i min_idx`를 한 줄씩(0-based 인덱스).
- **예제**: `3 / 3 1 2` → i=0에서 최솟값 1은 인덱스1 → `0 1`, 이후 배열 `1 3 2`; i=1에서 최솟값 2는 인덱스2 → `1 2`. 출력 두 줄: `0 1` / `1 2`
- **예제**: `3 / 1 2 3` → 모든 패스에서 min_idx==i, 교환 없음 → 출력 없음(빈 출력)
- **셀프체크**: 이미 정렬된 입력도 조기 종료가 없어 안쪽 비교는 전부 수행되지만, 교환은 0번이라 로그는 비어야 한다. min_idx를 0으로 초기화하는 실수(반드시 i로 초기화).

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    out = []
    for i in range(n - 1):
        min_idx = i                  # 반드시 i로 초기화
        for j in range(i + 1, n):
            if a[j] < a[min_idx]:
                min_idx = j
        if min_idx != i:             # 교환이 실제로 필요할 때만 로그
            out.append(f"{i} {min_idx}")
            a[i], a[min_idx] = a[min_idx], a[i]
    print("\n".join(out))

main()

--OUT

@@EXPL
**이 풀이의 새 문법**

- `f"{i} {min_idx}"`: f-string(포맷 문자열). 문자열 앞에 `f`를 붙이고 `{}` 안에 변수를 넣으면, 그 변수의 값이 문자열로 자동 치환된다(`str(i) + " " + str(min_idx)`와 같은 결과).

(1) 접근·핵심 아이디어

- 선택 정렬에서 각 패스는 "미정렬 구간의 최솟값 인덱스를 찾아 맨 앞과 한 번 교환"이다. 이 문제는 그 교환이 실제로 일어난 패스만 `i min_idx`로 기록한다. `min_idx == i`(이미 그 자리가 최솟값)면 교환이 없으므로 출력하지 않는다.

(2) 코드 단계별

- 바깥 루프 `i`가 확정할 위치. `min_idx = i`로 초기화가 핵심(0이 아니라 i).
- 안쪽 루프에서 `a[j] < a[min_idx]`면 `min_idx` 갱신 — 값을 옮기지 않고 인덱스만 추적.
- 루프가 끝난 뒤 `min_idx != i`일 때만 `out`에 `"i min_idx"`를 넣고 교환.
- 마지막에 개행으로 이어 출력(교환이 없었으면 빈 출력).

(3) 스스로 다시 짤 때 생각 순서

- "인덱스만 추적, 패스 끝에 한 번 교환"이라는 선택 정렬의 본질을 먼저 세운다.
- 그 위에 "교환한 경우만 로그" 조건을 얹는다 — 로그와 실제 교환을 같은 `if` 안에 두면 자연히 일치.
- 함정: `min_idx`를 0으로 초기화하면 첫 원소가 항상 최소로 오해되어 틀린다. 이미 정렬된 입력은 로그가 완전히 비어야 정상.
```

**2) 최소 교환 정렬** · Medium

- **요구사항**: 서로 다른 정수 배열을 오름차순으로 만들 때 선택 정렬 방식으로 필요한 "실제 교환 횟수"를 출력하라(i==min_idx면 교환 안 함).
- **입력**: 첫 줄 N(1 ≤ N ≤ 1000), 둘째 줄 N개의 서로 다른 정수.
- **출력**: 실제 교환 횟수 하나.
- **예제**: `5 / 5 1 4 2 8` → `2`
- **예제**: `4 / 1 2 3 4` → `0`
- **셀프체크**: 첫 예제 추적 — i=0 최솟값1(idx1) 교환→`1 5 4 2 8`; i=1 최솟값2(idx3) 교환→`1 2 4 5 8`; i=2 최솟값4(idx2==i) 교환없음; i=3 최솟값5(idx3==i) 교환없음. 총 2회. 이미 정렬이면 0회.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    cnt = 0
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if a[j] < a[min_idx]:
                min_idx = j
        if min_idx != i:             # i==min_idx면 교환 안 함
            a[i], a[min_idx] = a[min_idx], a[i]
            cnt += 1
    print(cnt)

main()
@@TESTS

5 1 4 2 8
--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 선택 정렬로 정렬하면서 "실제로 값을 맞바꾼" 패스의 수만 센다. 각 패스에서 찾은 최솟값이 이미 제자리(`min_idx == i`)면 교환을 건너뛰므로 카운트하지 않는다. 그래서 이 값은 거품/삽입의 교환·이동 횟수(역위 개수)와는 다른, 훨씬 작은 값이 된다(최대 n-1).

(2) 코드 단계별

- 표준 선택 정렬의 이중 루프.
- 안쪽에서 최솟값 인덱스만 추적.
- `min_idx != i`일 때만 교환하고 `cnt += 1`.
- 마지막에 `cnt` 출력.

(3) 스스로 다시 짤 때 생각 순서

- L2-1(교환 로그)에서 로그 대신 카운터를 두면 그대로 이 문제가 된다.
- 핵심은 "필요 없는 교환은 세지 않는다"는 조건. 이미 정렬된 입력이면 매 패스가 제자리라 0이 나와야 정상.
```

**3) k번째 확정값** · Medium

- **요구사항**: 선택 정렬을 오름차순으로 진행할 때, 바깥 루프의 i=0,1,2,...에서 매 패스가 끝나면 위치 i의 값이 확정된다. 주어진 k(1-based)에 대해, k번째로 "확정되는" 값을 출력하라.
- **입력**: 첫 줄 N과 k(1 ≤ k ≤ N ≤ 100), 둘째 줄 N개의 정수.
- **출력**: k번째로 확정되는 값 하나.
- **예제**: `5 1 / 5 1 4 2 8` → `1` (첫 패스에서 최솟값 1이 확정)
- **예제**: `5 3 / 5 1 4 2 8` → `4` (확정 순서: 1,2,4,...)
- **셀프체크**: 선택 정렬은 작은 값부터 순서대로 확정하므로, k번째 확정값 = 배열을 정렬했을 때의 k번째 작은 값(정렬 후 인덱스 k-1). 즉 실제 정렬을 돌리지 않고 `sorted(a)[k-1]`로도 검산 가능. 단, 문제 의도는 정렬 과정 이해이므로 직접 패스를 돌려볼 것.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    k = int(data[1])
    a = [int(x) for x in data[2:2 + n]]
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if a[j] < a[min_idx]:
                min_idx = j
        a[i], a[min_idx] = a[min_idx], a[i]
        if i + 1 == k:               # i패스 끝 = (i+1)번째 확정
            print(a[i])
            return
    # k == n 인 경우: 마지막 위치는 자동 확정
    print(a[k - 1])

main()
@@TESTS
--IN

5 1 4 2 8
--OUT

--IN

5 1 4 2 8
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 선택 정렬은 매 패스에서 남은 값 중 최솟값을 위치 `i`에 확정한다. 따라서 확정 순서는 "가장 작은 값 → 다음 작은 값 → ..."이고, k번째로 확정되는 값은 정렬 후 인덱스 `k-1`의 값과 같다. 문제 의도대로 실제 패스를 돌리며 k번째 확정 시점의 값을 뽑는다.

(2) 코드 단계별

- 표준 선택 정렬을 진행한다.
- 각 패스가 끝나면 위치 `i`가 확정되므로, `i+1`(1-based)이 `k`와 같아지는 순간 `a[i]`를 출력하고 종료.
- `k == n`이면 마지막 위치는 바깥 루프(`n-1`까지)가 직접 확정하지 않지만, 정렬이 끝난 뒤 `a[n-1]`이 자동으로 최댓값으로 확정되므로 루프 후 `a[k-1]` 출력으로 처리.

(3) 스스로 다시 짤 때 생각 순서

- "확정 순서 = 오름차순"이라는 성질을 먼저 인지하면 `sorted(a)[k-1]`로 즉시 검산할 수 있다.
- 코드는 정렬 과정 이해가 목적이므로 패스를 돌리되, k와 `i+1`을 맞추는 인덱스 변환(1-based ↔ 0-based)만 조심.
- 경계: `k == n`일 때 루프 안에서 안 잡히므로 루프 뒤 출력으로 보강.
```


## L3. 삽입 정렬

**개념**

- 삽입 정렬(Insertion Sort)은 앞쪽을 "이미 정렬된 부분"으로 보고, 그 다음 원소를 하나씩 꺼내 정렬된 부분의 올바른 위치에 끼워 넣는 정렬이다. 카드를 손에 정렬하며 정리하는 방식과 같다.
- 왜 배우나: 거의 정렬된 데이터에서 매우 빠르고(최선 O(n)), 안정적이며 제자리 정렬이라 실전에서 작은 배열이나 "부분적으로 정렬된" 상황에 유용하다. 파이썬 표준 정렬(Timsort)도 작은 구간엔 삽입 정렬을 쓴다.
- 동작 원리(오름차순)

- 1단계: 인덱스 i=1부터 시작. `key = a[i]`를 꺼낸다.
- 2단계: `key`보다 큰 앞쪽 원소들을 한 칸씩 오른쪽으로 민다(`a[j+1] = a[j]`).
- 3단계: 밀기가 멈춘 자리에 `key`를 넣는다.
- 4단계: i를 끝까지 늘리며 반복. 앞부분은 항상 정렬된 상태를 유지한다.

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:  # key보다 크면 뒤로 민다
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key                # 빈 자리에 삽입
    return a
```

**그림으로 보기**

```text
 insertion sort on [5, 2, 4, 6, 1]     # | | 안이 이미 정렬된 앞부분
 i=1  key=2   |5| 2 4 6 1        5>2  shift  ->  |2 5| 4 6 1
 i=2  key=4   |2 5| 4 6 1        5>4  shift  ->  |2 4 5| 6 1
 i=3  key=6   |2 4 5| 6 1        5<6  stop   ->  |2 4 5 6| 1
 i=4  key=1   |2 4 5 6| 1        4 shifts    ->  |1 2 4 5 6|
```

```text
 i=4, key=1        # 앞부분을 한 칸씩 밀어 빈 자리를 만든다
   2  4  5  6 [ ]    j=3   a[4] = a[3] = 6
   2  4  5 [ ] 6     j=2   a[3] = a[2] = 5
   2  4 [ ] 5  6     j=1   a[2] = a[1] = 4
   2 [ ] 4  5  6     j=0   a[1] = a[0] = 2
  [ ] 2  4  5  6     j=-1  stop -> a[0] = key = 1
   1  2  4  5  6     # key 를 먼저 꺼내 뒀기에 덮어써도 잃지 않는다
```

**손으로 따라가기**

`a = [5, 2, 4, 6, 1]`.

| i | key | 비교 | 이동(shift) | 삽입 위치 | 결과 |
|---|---|---|---|---|---|
| 1 | 2 | 1회 | 1회 | 0 | `2 5 4 6 1` |
| 2 | 4 | 2회 | 1회 | 1 | `2 4 5 6 1` |
| 3 | 6 | 1회 | 0회 | 3 | `2 4 5 6 1` |
| 4 | 1 | 4회 | 4회 | 0 | `1 2 4 5 6` |

i=3에서 비교 한 번에 멈춘 것에 주목하자. 앞부분이 이미 정렬돼 있으므로 `a[j] > key`가 처음부터 거짓이면 그 자리가 곧 정답이다. 거의 정렬된 입력에서 삽입 정렬이 빠른 이유가 이 조기 탈출이다.

**왜 이렇게 되는가**

- 이동 횟수는 역위(inversion) 개수와 정확히 같다. 역위란 `i < j`인데 `a[i] > a[j]`인 쌍이다. `key`를 왼쪽으로 한 칸 미는 사건은 그 쌍 하나를 해소하는 것과 1:1로 대응한다.
- 그래서 최악은 완전 역순 입력이다. 역위가 모든 쌍이므로 n(n-1)/2개 → O(n²).
- 최선은 이미 정렬된 입력이다. 역위가 0개라 while이 매번 즉시 멈추고, 바깥 루프 n-1번의 비교만 남아 O(n)이 된다.
- 평균적으로 무작위 배열의 역위는 대략 n(n-1)/4개라 여전히 O(n²)이지만, "거의 정렬됨"에서는 역위가 적어 실측이 극적으로 빨라진다. 파이썬의 Timsort가 짧은 구간을 삽입 정렬로 처리하는 근거다.
- 안정성: `while a[j] > key`에 등호가 없으므로 `key`와 같은 값을 만나면 밀기를 멈춘다. `key`는 같은 값 바로 뒤에 놓이고, 결국 입력 순서가 유지된다. `>=`로 바꾸면 같은 값을 넘어가 버려 안정성이 깨진다.
- while 조건의 `j >= 0`이 먼저 오는 것도 이유가 있다. 파이썬의 `and`는 왼쪽이 거짓이면 오른쪽을 평가하지 않으므로, `j`가 -1이 되는 순간 `a[-1]`을 읽지 않고 안전하게 빠져나온다.

**접근 전략**

- 핵심 아이디어: 정렬된 앞부분을 유지하며 새 원소를 "밀어내기+삽입"으로 넣는다. 교환이 아니라 이동(shift)이라 같은 값을 만나면 멈춰 안정성이 보장된다.
- 안정성(stability)이란: 정렬 기준 값이 같은 원소들끼리는 정렬 전의 원래 순서가 그대로 보존되는 성질이다. 왜 중요한지는 뒤의 L9(Stable Sort)에서 "다단 정렬"로 자세히 다루는데, 미리 감을 잡자면 — 학생을 "점수 내림차순, 점수가 같으면 먼저 접수한 순서"로 줄 세울 때, 접수 순서로 정렬해 둔 상태에서 안정 정렬로 점수만 정렬하면 점수가 같은 학생끼리 접수 순서가 자동으로 유지된다. 안정성이 없으면 이 "같은 값 안에서의 순서 보존"이 깨져 2차 기준이 뒤섞인다.
- 전형 패턴: 바깥 루프가 삽입 대상 i, 안쪽 while이 삽입 위치 탐색 겸 이동. `a[j] > key`에서 등호를 넣지 않아야 안정적.
- 언제 쓰나: 데이터가 작거나 거의 정렬돼 있을 때, 스트리밍처럼 원소가 하나씩 들어와 정렬 상태를 유지해야 할 때(온라인 정렬). 안정성이 필요할 때.
- 복잡도: 시간 최악·평균 O(n²), 최선 O(n)(이미 정렬 — while이 즉시 멈춤). 공간 O(1). 안정 정렬. 이동 횟수는 역위(inversion) 개수와 같다.
- 흔한 실수: while 조건에서 `j >= 0`을 빼먹어 인덱스 음수 접근. 밀기 도중 `key`를 덮어써 값을 잃는 것(반드시 먼저 `key`에 보관). `>=`로 안정성 훼손.

**문제**

**1) 단계별 삽입** · Easy

- **요구사항**: 삽입 정렬(오름차순)에서 i=1,2,...,N-1 각 단계가 끝날 때마다 배열 전체 상태를 한 줄씩 출력하라.
- **입력**: 첫 줄 N(2 ≤ N ≤ 100), 둘째 줄 N개의 정수.
- **출력**: 각 i 단계 종료 후의 배열을 공백으로 구분해 한 줄씩(총 N-1줄).
- **예제**: `5 / 5 1 4 2 8` → `1 5 4 2 8` / `1 4 5 2 8` / `1 2 4 5 8` / `1 2 4 5 8`
- **예제**: `3 / 3 2 1` → `2 3 1` / `1 2 3`
- **셀프체크**: 첫 예제 i=4에서 key=8은 앞의 5보다 커서 이동 없이 제자리 → 배열 불변(마지막 줄이 직전과 같음)이 정상. 상태를 매번 복사해 출력하지 않으면(같은 리스트 참조) 나중 출력이 오염될 수 있으니 주의.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    out = []
    for i in range(1, n):
        key = a[i]                   # 먼저 보관(덮어써서 잃지 않게)
        j = i - 1
        while j >= 0 and a[j] > key:  # key보다 크면 오른쪽으로 민다
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
        out.append(" ".join(map(str, a)))  # 매 단계 스냅샷
    print("\n".join(out))

main()

(1) 접근·핵심 아이디어

- 삽입 정렬은 `i=1..N-1`에서 `a[i]`(=key)를 꺼내 앞의 정렬된 부분 알맞은 자리에 끼워 넣는다. 이 문제는 각 `i` 단계가 끝난 직후의 배열 전체를 한 줄씩 출력한다(총 N-1줄). key가 이미 제자리면 배열이 그대로라 직전 줄과 같아질 수 있다.

(2) 코드 단계별

- `key = a[i]`로 값을 먼저 보관(밀기 중 덮어써 잃지 않도록).
- `j`를 `i-1`부터 내려가며 `a[j] > key`인 동안 `a[j+1]=a[j]`로 오른쪽 이동.
- 멈춘 자리 `j+1`에 `key` 삽입.
- 그 순간의 배열을 문자열로 만들어 `out`에 저장(리스트를 매번 문자열화하므로 참조 오염 걱정 없음).

(3) 스스로 다시 짤 때 생각 순서

- "정렬된 앞부분 + 새 원소 끼우기" 뼈대를 세우고, 각 `i` 끝에 스냅샷 append를 붙인다.
- 함정: `while` 조건에 `j >= 0`을 반드시 포함(음수 인덱스 방지). 등호(`>=`)를 쓰면 안정성이 깨지므로 `>`만.
- key가 최댓값 위치면 이동 0회라 배열 불변 → 마지막 줄이 직전과 같은 게 정상.
```

**2) 이동 횟수** · Medium

- **요구사항**: 삽입 정렬로 오름차순 정렬할 때, 원소를 한 칸 오른쪽으로 미는 연산(`a[j+1]=a[j]`)이 총 몇 번 실행되는지 출력하라. (마지막에 key를 제자리에 넣는 대입은 세지 않는다.)
- **입력**: 첫 줄 N(1 ≤ N ≤ 2000), 둘째 줄 N개의 정수.
- **출력**: 총 이동 횟수 하나.
- **예제**: `5 / 5 1 4 2 8` → `4`
- **예제**: `4 / 4 3 2 1` → `6`
- **셀프체크**: 이 이동 횟수는 역위(inversion) 개수와 정확히 같다(거품의 교환 횟수와 동일 값). `5 1 4 2 8`의 역위: (5,1)(5,4)(5,2)(4,2) = 4개. `4 3 2 1`은 모든 6쌍이 역순 → 6. 이미 정렬이면 0.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    moves = 0
    for i in range(1, n):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            moves += 1               # 밀기 1회 = 이동 1회
            j -= 1
        a[j + 1] = key               # 이 대입은 세지 않음
    print(moves)

main()
@@TESTS
--IN
5
5 1 4 2 8
--OUT
4
--IN
4
4 3 2 1
--OUT
6
@@EXPL
(1) 접근·핵심 아이디어

- 삽입 정렬에서 원소를 오른쪽으로 미는 연산(`a[j+1]=a[j]`)만 카운트한다. 마지막에 key를 빈 자리에 넣는 대입은 "삽입"이지 "밀기"가 아니므로 세지 않는다. 이 총 이동 횟수는 배열의 역위(inversion) 개수와 정확히 같다.

(2) 코드 단계별

- 표준 삽입 정렬의 `for`+`while` 구조.
- `while` 안에서 `a[j+1]=a[j]`를 실행할 때마다 `moves += 1`.
- 루프 종료 후의 `a[j+1]=key`는 카운트에서 제외(while 밖에 위치).
- 최종 `moves` 출력.

(3) 스스로 다시 짤 때 생각 순서

- L3-1(단계별 삽입)에서 스냅샷 대신 while 내부에 카운터만 얹으면 된다.
- 카운터 위치가 관건: while 안(밀기)에만 두고, 삽입 대입에는 두지 않는다.
- 검산: 역위 개수와 같아야 한다. `5 1 4 2 8`의 역위는 (5,1)(5,4)(5,2)(4,2) = 4.
```

**3) 온라인 삽입** · Medium

- **요구사항**: 정수가 하나씩 스트림으로 들어온다. 매번 새 정수를, 지금까지 유지해 온 오름차순 정렬 리스트의 올바른 위치에 삽입한 뒤, 삽입된 위치의 인덱스(0-based)를 출력하라.
- **입력**: 첫 줄 M(1 ≤ M ≤ 100000), 다음 줄에 M개의 정수(스트림 순서).
- **출력**: 각 정수를 삽입한 위치 인덱스를 공백으로 구분해 한 줄로.
- **예제**: `5 / 5 1 4 2 8` → `0 0 1 1 4`
- **예제**: `3 / 2 2 2` → `0 0 0` (같은 값은 맨 앞 삽입 시 항상 인덱스 0)
- **셀프체크**: 추적 — 5→[5] idx0; 1→[1,5] idx0; 4→[1,4,5] idx1; 2→[1,2,4,5] idx1; 8→[1,2,4,5,8] idx4. M이 크므로 순수 삽입 정렬의 while 이동은 O(n) per step이라 최악 O(M²)이지만 위치 찾기는 이진탐색(Ch4 선행)으로 O(log n)까지 줄일 수 있다 — 이번 레슨 범위에선 선형 탐색으로 충분. 같은 값 처리 시 "첫 등장 위치"에 넣어 안정성 유지.

```runner
@@SOLUTION
import sys
import bisect

def main():
    data = sys.stdin.read().split()
    m = int(data[0])
    nums = [int(x) for x in data[1:1 + m]]
    arr = []
    res = []
    for x in nums:
        pos = bisect.bisect_left(arr, x)  # 같은 값이면 첫 등장 위치
        arr.insert(pos, x)
        res.append(str(pos))
    print(" ".join(res))

main()
@@TESTS
--IN
5
5 1 4 2 8
--OUT
0 0 1 1 4
--IN
3
2 2 2
--OUT
0 0 0
@@EXPL
**이 풀이의 새 문법**

- `bisect.bisect_left(arr, x)`: 정렬된 리스트 `arr`에서 `x`를 넣어도 정렬이 유지되는 가장 왼쪽 위치(인덱스)를 O(log n)에 찾는 표준 라이브러리 함수(원리는 Ch4에서 자세히 다룸).

(1) 접근·핵심 아이디어

- 정수가 하나씩 들어올 때마다 지금까지 유지한 오름차순 리스트의 올바른 자리에 넣고, 그 삽입 위치를 출력한다. 같은 값이 이미 있으면 "첫 등장 위치"(가장 왼쪽)에 넣어 안정성을 지킨다 — 이 위치가 곧 `bisect_left`가 주는 인덱스다.

(2) 코드 단계별

- 빈 리스트 `arr`로 시작.
- 각 값 `x`에 대해 `bisect.bisect_left(arr, x)`로 삽입 위치 `pos`를 찾는다. `bisect_left`는 같은 값이 있으면 그 왼쪽을 가리키므로 안정.
- `arr.insert(pos, x)`로 실제 삽입, `pos`를 결과에 기록.
- 모든 값 처리 후 공백으로 이어 출력.

(3) 스스로 다시 짤 때 생각 순서

- "정렬 리스트에 하나씩 끼우기 + 그 위치 출력"이 핵심. 위치 찾기는 선형 스캔으로도 되지만, 같은 값 왼쪽에 멈추도록 `>` 대신 `>=`가 나올 때 멈추는 조건을 정확히 잡아야 한다.
- 표준 라이브러리 `bisect_left`가 바로 그 "첫 등장 위치"를 주므로 안정성·경계를 한 번에 해결.
- 함정: `bisect_right`를 쓰면 같은 값 뒤에 들어가 안정성이 달라진다 — 반드시 `bisect_left`.
```


## L4. 기수 정렬

**개념**

- 기수 정렬(Radix Sort)은 값을 서로 비교하지 않고, 자릿수(digit) 단위로 여러 번 "안정적으로" 나눠 담아 정렬하는 비교하지 않는(non-comparison) 정렬이다. 비음수 정수처럼 자릿수 개념이 있는 데이터에 쓴다.
- 왜 배우나: 비교 정렬의 하한 O(n log n)을 우회해, 자릿수 d와 진법 크기가 작을 때 O(d·n)에 정렬할 수 있음을 보여준다. "정렬 = 비교"라는 고정관념을 깨는 대표 예.
- 동작 원리(LSD, 최하위 자리부터, 10진법·비음수 가정)

- 1단계: 가장 낮은 자리(1의 자리)를 기준 삼아, 0~9의 버킷(bucket)에 원소를 넣는다.
- 2단계: 버킷 0부터 9까지 순서대로 다시 꺼내 배열을 재구성한다. 이 과정은 반드시 안정적이어야 한다(같은 자릿값이면 들어온 순서 유지).
- 3단계: 다음 자리(10의 자리, 100의 자리, ...)로 올라가며 최대값의 자릿수만큼 1~2단계를 반복한다.
- 4단계: 최상위 자리까지 끝나면 전체가 정렬된다. 낮은 자리부터 안정 분배했기 때문에 높은 자리를 처리해도 아래 자리 순서가 보존된다.

```python
def radix_sort(a):                 # a: 비음수 정수 리스트
    if not a:
        return a
    exp = 1                        # 현재 자리의 자릿값(1,10,100,...)
    mx = max(a)
    while mx // exp > 0:
        buckets = [[] for _ in range(10)]
        for x in a:
            buckets[(x // exp) % 10].append(x)   # 현재 자릿수로 분배
        a = [x for b in buckets for x in b]       # 0→9 순서로 재수집(안정)
        exp *= 10
    return a
```

```text
 stability is correctness here   # 21 과 25 는 10 의 자리가 같다
  after exp=1   :  ... 21 ...  25 ...   # 1 의 자리로 이미 정렬된 상태
  exp=10  b2 (stable)   : [21, 25]      # 들어온 순서 유지 -> 아래 자리 보존
  exp=10  b2 (unstable) : [25, 21]      # 아래 자리 정렬이 파괴된다
```

**손으로 따라가기**

작은 예 `[53, 3, 42, 7, 35]`로 두 패스를 따라간다.

| 패스 | 기준 | 버킷 | 수집 결과 |
|---|---|---|---|
| exp=1 | 1의 자리 | b2:42 · b3:53,3 · b5:35 · b7:7 | `42 53 3 35 7` |
| exp=10 | 10의 자리 | b0:3,7 · b3:35 · b4:42 · b5:53 | `3 7 35 42 53` |

최대값 53의 자릿수가 2이므로 두 패스로 끝난다. exp=10의 b0에서 3과 7의 순서가 유지된 것이 결정적이다 — 그 순서는 이전 패스가 만든 "1의 자리 정렬 결과"다.

**왜 이렇게 되는가**

- 귀납으로 보면 명확하다. exp=10^t 패스를 마친 시점에 배열은 "아래 t+1자리 기준으로 정렬"돼 있다고 주장하자.
- t=0(1의 자리)은 자명하다. t-1까지 성립한다고 가정하고 t번째 자리로 버킷 분배를 하면, 자릿값이 다른 값들은 새 기준으로 올바르게 갈린다.
- 자릿값이 같은 값들은 같은 버킷에 들어가는데, 안정 분배라 이전 순서(= 아래 t자리 정렬 결과)가 그대로 남는다. 따라서 아래 t+1자리 기준으로 정렬된다. 귀납 완료.
- 이 논증에서 "안정"을 빼면 마지막 문장이 무너진다. 그래서 기수 정렬에서 안정성은 성능 취향이 아니라 정확성의 전제다.
- 복잡도: 한 패스는 분배 O(n) + 수집 O(n + b)이고, 패스는 d번이므로 O(d·(n + b)). 진법 b=10은 상수, d는 최대값의 자릿수 = log10(max)이다. 값의 범위가 n에 비해 작으면 d가 사실상 상수라 O(n)에 수렴한다.
- 반대로 값의 범위가 어마어마하게 크면 d가 커져 이점이 사라진다. "자릿수가 적을 때"라는 전제를 확인하고 써야 한다.

**접근 전략**

- 핵심 아이디어: "낮은 자리부터, 자릿수별로, 안정적으로 재배치"를 반복한다. 각 자리 처리는 O(n)이고, 자릿수 d번 반복하므로 전체 O(d·n).
- 전형 패턴: `(x // exp) % 10`으로 현재 자릿수를 뽑고, 10개 버킷에 분배한 뒤 0→9 순서로 이어붙인다. 각 패스가 안정적이어야 전체가 올바르게 정렬됨(안정성이 알고리즘의 정확성 그 자체).
- 언제 쓰나: 키가 고정 폭 정수/문자열이고, 값의 범위(자릿수·진법)가 n에 비해 작을 때. 음수가 있으면 부호 분리 처리나 오프셋(모든 값에 상수를 더해 비음수화)이 필요.
- 복잡도: 시간 O(d·(n + b))(d=자릿수, b=진법=10). 공간 O(n + b)(버킷 저장). 안정 정렬. n이 크고 d가 작으면 O(n)에 수렴해 비교 정렬보다 빠를 수 있다.
- 흔한 실수: 버킷 재수집을 0→9가 아닌 순서로 하거나 안정성이 없는 방식으로 하면 결과가 틀린다. 반복 종료 조건을 최대값의 자릿수로 잡지 않으면(예: 고정 횟수) 큰 값이 덜 정렬된다. 음수·소수 처리 미고려.

**문제**

**1) 자리별 스냅샷** · Easy

- **요구사항**: 비음수 정수 배열에 LSD 기수 정렬을 적용하며, 각 자리(1의 자리, 10의 자리, ...) 처리를 마칠 때마다 그 순간의 배열을 한 줄씩 출력하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 1000), 둘째 줄 N개의 비음수 정수.
- **출력**: 각 자리 패스 종료 후의 배열을 공백으로 구분해 한 줄씩.
- **예제**: `4 / 170 45 75 90` → 1의 자리 후 `170 90 45 75`, 10의 자리 후 `45 170 75 90`, 100의 자리 후 `45 75 90 170`
- **예제**: `3 / 3 30 300` → 1의 자리 후 `30 300 3`? 검산 필요 → 아래 셀프체크 참고
- **셀프체크**: 두 번째 예제 검산 — 1의 자리 값: 3→3, 30→0, 300→0. 안정 분배로 버킷0=[30,300], 버킷3=[3] → 재수집 `30 300 3`. 10의 자리: 3→0,30→3,300→0 → 버킷0=[3,300], 버킷3=[30] → `3 300 30`. 100의 자리: 3→0,300→3,30→0 → 버킷0=[3,30],버킷3=[300] → `3 30 300`. 첫 예제의 첫 패스는 1의 자리 값(0,5,5,0)이므로 버킷0=[170,90], 버킷5=[45,75] → `170 90 45 75`가 맞다. 안정성이 깨지면 스냅샷이 달라짐.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    out = []
    mx = max(a)
    exp = 1
    while mx // exp > 0:              # 최대값의 자릿수만큼 반복
        buckets = [[] for _ in range(10)]
        for x in a:
            buckets[(x // exp) % 10].append(x)  # 현재 자릿수로 분배
        a = [x for b in buckets for x in b]     # 0→9 순서로 안정 재수집
        out.append(" ".join(map(str, a)))       # 이 자리 처리 후 스냅샷
        exp *= 10
    print("\n".join(out))

main()

(1) 접근·핵심 아이디어

- LSD 기수 정렬은 1의 자리부터 시작해 자리를 올려가며, 매번 10개 버킷(0~9)에 현재 자릿값으로 분배한 뒤 0→9 순서로 안정적으로 다시 이어붙인다. 이 문제는 "각 자리 패스가 끝난 직후"의 배열을 한 줄씩 출력한다. 스냅샷은 반드시 실제 안정 재수집 결과여야 한다.

(2) 코드 단계별

- `mx = max(a)`, `exp = 1`로 시작. `while mx // exp > 0`로 최대값 자릿수만큼 반복.
- 각 반복에서 `buckets` 10개를 만들고, `(x // exp) % 10`으로 현재 자릿수를 뽑아 분배.
- `[x for b in buckets for x in b]`로 버킷 0→9 순서로 이어붙여 새 배열 구성(안정).
- 그 배열을 스냅샷으로 저장하고 `exp *= 10`.

(3) 스스로 다시 짤 때 생각 순서

- "분배 → 0~9 순서로 재수집 → 반복"이 뼈대. 재수집 순서(0→9)와 버킷 내부 순서 유지가 안정성이자 정확성의 핵심.
- 스냅샷은 매 자리 패스 끝에 한 번씩. 종료 조건은 고정 횟수가 아니라 `mx // exp > 0`이어야 큰 값이 덜 정렬되지 않는다.
- 주의: 중간 스냅샷은 "직전 패스 결과 배열"을 그대로 분배한 값이므로, 직관적 정렬 순서와 달라 보일 수 있다(예: 두 번째 예제 중간 줄).
```

**2) 최소 패스 수** · Easy

- **요구사항**: 비음수 정수 배열을 LSD 기수 정렬로 정렬할 때 필요한 자릿수 패스 횟수(= 배열 최대값의 자릿수)를 출력하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 둘째 줄 N개의 비음수 정수.
- **출력**: 패스 횟수 하나.
- **예제**: `4 / 170 45 75 90` → `3` (최대값 170은 세 자리)
- **예제**: `3 / 0 7 9` → `1` (최대값 9는 한 자리; 0도 한 자리로 취급)
- **셀프체크**: 패스 수 = `len(str(max(a)))` 또는 while `mx//exp>0` 반복 횟수. 최대값이 0이면 자릿수 1로 취급(빈 배열이 아닌 한). 진법을 10이 아닌 값으로 바꾸면 패스 수가 달라진다는 점(자릿수 정의가 진법에 의존).

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    mx = max(a)
    passes = 0
    exp = 1
    while mx // exp > 0:              # 자릿수 세기
        passes += 1
        exp *= 10
    if passes == 0:                  # 최대값이 0이면 1자리로 취급
        passes = 1
    print(passes)

main()
@@TESTS
--IN

170 45 75 90
--OUT

--IN

0 7 9
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- LSD 기수 정렬의 패스 수는 배열 최대값의 (10진) 자릿수와 같다. 실제 정렬을 돌릴 필요 없이, 최대값이 몇 자리인지만 세면 된다. 다만 최대값이 0인 특수 경우는 자릿수를 1로 처리한다.

(2) 코드 단계별

- `mx = max(a)`.
- `exp`를 1,10,100,...로 올리며 `mx // exp > 0`인 동안 `passes`를 증가 — 실제 기수 정렬의 while 반복 횟수와 동일.
- `mx`가 0이면 while이 한 번도 안 돌아 `passes==0`이 되므로 1로 보정.
- `passes` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "패스 수 = 최대값 자릿수"를 떠올리면 `len(str(max(a)))`로도 즉시 검산 가능(단, 음수·부호는 이 문제 범위 밖).
- while 방식은 기수 정렬 본체의 종료 조건과 같은 식이라 개념적으로 더 안전.
- 경계: 최대값 0 → 1자리. 빈 배열은 제약상 없음(N≥1).
```

**3) 음수 포함 기수 정렬** · Hard

- **요구사항**: 음수가 섞인 정수 배열을 기수 정렬 아이디어로 오름차순 정렬하라(파이썬 `sorted` 사용 금지, 비교 기반 정렬 금지). 힌트: 모든 값에 상수를 더해 비음수로 만든 뒤 정렬하고 원복하거나, 음수/양수를 분리해 각각 처리한다.
- **입력**: 첫 줄 N(1 ≤ N ≤ 100000), 둘째 줄 N개의 정수(범위 -10^6 ~ 10^6).
- **출력**: 오름차순 정렬된 N개의 정수를 공백으로 구분해 한 줄로.
- **예제**: `5 / 5 -1 4 -2 8` → `-2 -1 4 5 8`
- **예제**: `4 / -10 -3 -30 -1` → `-30 -10 -3 -1`
- **셀프체크**: 오프셋 방식 — `off = -min(a)` 를 모두 더하면 최솟값이 0이 되어 비음수 기수 정렬 가능, 끝에 `off`를 빼서 원복. `5 -1 4 -2 8`은 off=2 → `7 1 6 0 10` 정렬 → `0 1 6 7 10` 원복 → `-2 -1 4 5 8`. 분리 방식이면 음수는 절댓값 기준 내림차순으로 앞에 붙여야 함(함정: 음수 부분 순서 뒤집기 잊기).

```runner
@@SOLUTION
import sys

def radix_sort_nonneg(a):
    if not a:
        return a
    mx = max(a)
    exp = 1
    while mx // exp > 0:
        buckets = [[] for _ in range(10)]
        for x in a:
            buckets[(x // exp) % 10].append(x)
        a = [x for b in buckets for x in b]
        exp *= 10
    return a

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(x) for x in data[1:1 + n]]
    off = -min(a)                    # 최솟값을 0으로 끌어올리는 오프셋
    shifted = [x + off for x in a]   # 전부 비음수화
    shifted = radix_sort_nonneg(shifted)
    res = [x - off for x in shifted] # 원복
    print(" ".join(map(str, res)))

main()
@@TESTS
--IN
5
5 -1 4 -2 8
--OUT
-2 -1 4 5 8
--IN
4
-10 -3 -30 -1
--OUT
-30 -10 -3 -1
@@EXPL
(1) 접근·핵심 아이디어

- 기수 정렬은 비음수 정수에만 곧바로 적용된다. 음수가 섞이면 "모든 값에 상수를 더해 비음수로 만든 뒤 정렬하고, 끝에 그 상수를 다시 빼서 원복"하는 오프셋 기법을 쓴다. `off = -min(a)`를 더하면 최솟값이 정확히 0이 되어 안전하다. 비교 기반 정렬과 `sorted`는 쓰지 않는다.

(2) 코드 단계별

- `off = -min(a)`를 계산해 모든 값에 더한 `shifted`(전부 ≥ 0)를 만든다.
- `radix_sort_nonneg`로 비음수 기수 정렬(1의 자리부터 안정 분배·재수집).
- 정렬 결과에서 다시 `off`를 빼 원래 스케일로 되돌린다.
- 공백으로 이어 출력.

(3) 스스로 다시 짤 때 생각 순서

- 핵심은 "비음수화 → 표준 기수 정렬 → 원복"의 3단계. 오프셋만 정확히 잡으면 본체는 L4 개념의 기수 정렬 그대로다.
- 검산: `5 -1 4 -2 8` → off=2 → `7 1 6 0 10` → 정렬 `0 1 6 7 10` → 원복 `-2 -1 4 5 8`.
- 함정: `sorted`나 비교 정렬을 쓰면 규칙 위반. 분리 방식(음수/양수 따로)을 쓸 경우 음수 부분은 절댓값 내림차순으로 이어붙여야 한다 — 오프셋 방식이 실수 여지가 적다.
```


## L5. 정렬 속도 비교

**개념**

- 정렬 알고리즘마다 비교·이동·교환 횟수와 복잡도가 다르므로, 입력의 크기·분포·요구사항(안정성·메모리)에 따라 최적의 선택이 달라진다. 이 레슨은 지금까지의 정렬을 한 표로 비교하고, 상황별로 무엇을 고를지 판단하는 감각을 기른다.
- 비교 요약(오름차순, n=원소 수, d=자릿수)

- 거품 정렬: 시간 O(n²)/최선 O(n), 공간 O(1), 안정 O. 교환 많음. 학습용.
- 선택 정렬: 시간 O(n²)(최선도 O(n²)), 공간 O(1), 안정 X. 교환 최소(≤n-1). 쓰기 비쌀 때.
- 삽입 정렬: 시간 O(n²)/최선 O(n), 공간 O(1), 안정 O. 거의 정렬된 입력·작은 n에 강함. 온라인 정렬 가능.
- 기수 정렬: 시간 O(d·n), 공간 O(n), 안정 O. 비교 안 함. 고정폭 정수/문자열, 범위가 작을 때.
- 판단 기준

- 입력이 거의 정렬됨 → 삽입(조기 종료로 O(n)에 근접).
- 교환/쓰기 비용이 매우 큼 → 선택(교환 최소).
- 키가 작은 범위의 정수 → 기수(O(n) 가능).
- 안정성이 필요 → 거품·삽입·기수(선택은 기본형이 불안정).
- 실무 일반 → 파이썬 `sorted`(Timsort, O(n log n), 안정) — 직접 O(n²) 정렬 대신 표준을 쓰는 게 정답인 경우가 대부분.

```python
# 실무 관점: 대부분은 내장 정렬이 최선. 안정 + O(n log n) 보장.
sorted(a)                       # 새 리스트 반환(오름차순)
a.sort()                        # 제자리 정렬
sorted(a, key=lambda x: (-x))   # 키로 커스텀(예: 내림차순)
# O(n²) 삽입/거품은 n이 작거나(≈ 수십) 거의 정렬된 특수 상황에서만 유리.
```

```text
             [a c b]   [c a b]         [b c a]   [c b a]
 # 잎 6개 = 3! 개의 가능한 순열. 비교 한 번이 가지 2개로 갈린다
 # 깊이 3 = 최악의 비교 횟수
```

```text
 growth                    # n 이 커질 때의 연산 횟수 감각
   n        n^2          n log2 n     ratio
   10       100          33           3 x
   100      10,000       664          15 x
   1,000    1,000,000    9,966        100 x
   10,000   100,000,000  132,877      753 x
 # n 이 10배가 되면 n^2 은 100배, n log n 은 약 13배만 커진다
```

**왜 이렇게 되는가**

비교 기반 정렬의 하한이 Ω(n log n)인 이유를 위 결정 트리로 유도한다.

- 어떤 비교 정렬이든 실행 과정은 "비교 → 예/아니오로 갈림"의 연속이므로 이진 트리 하나로 그릴 수 있다. 잎 하나가 최종 출력 순열 하나에 대응한다.
- 입력이 서로 다른 n개라면 가능한 순열이 n!가지이고, 알고리즘은 이들을 모두 구별해 낼 수 있어야 하므로 잎이 최소 n!개 필요하다.
- 높이 h인 이진 트리의 잎은 아무리 많아야 2^h개다. 따라서 2^h ≥ n!, 즉 h ≥ log2(n!).
- 스털링 근사로 log2(n!) ≈ n log2 n − 1.44n이므로 h = Ω(n log n).
- h는 "최악 입력에서의 비교 횟수"다. 결론: 비교만으로 정렬하는 한 최악 비교 횟수를 n log n 아래로 내릴 수 없다. 병합·힙 정렬은 이 하한을 실제로 달성하는 최적 알고리즘이다.
- 기수 정렬이 이 하한을 피해 가는 것은 규칙을 어겨서가 아니다. 값을 서로 비교하지 않고 "자릿수로 주소를 계산해" 나눠 담기 때문에, 애초에 결정 트리 모델 밖에 있다. 대신 키가 고정폭 정수여야 한다는 조건을 낸다.

**손으로 따라가기**

`n = 1000`, 각 연산이 1억분의 1초 걸린다고 두고 대략의 실행 시간을 견적한다.

| 알고리즘 | 연산 수 어림 | n=1,000 | n=100,000 |
|---|---|---|---|
| 거품·선택·삽입 | n²/2 | 50만 (0.005초) | 50억 (약 50초) |
| 병합·힙·Timsort | n log2 n | 1만 (0.0001초) | 170만 (0.017초) |
| 기수(d=6) | 6n | 6천 | 60만 |

n=1,000까지는 무엇을 써도 통과한다. 갈림길은 n=10만 부근에서 생긴다 — O(n²)은 시간 초과, O(n log n)은 여유. "제한이 10^5 이상이면 O(n²) 정렬은 후보에서 지운다"가 실전 판단 기준이다.

**접근 전략**

- 핵심 아이디어: "최악 복잡도"만 보지 말고 (1) 입력 분포(거의 정렬? 무작위?), (2) n의 크기, (3) 안정성 필요 여부, (4) 메모리 여유, (5) 비교 vs 이동 비용을 종합해 고른다.
- 전형 패턴: 문제에서 n의 상한과 값의 범위를 먼저 확인 → n이 크고(예: 10^5 이상) 값이 임의면 O(n log n)(내장 정렬)로, 값이 작은 정수면 기수/계수 정렬을, n이 작으면 아무거나 써도 됨.
- 언제 어떤 걸: 위 "판단 기준" 리스트를 체크리스트로 사용. 특히 "안정성"은 (값, 부가정보) 튜플을 정렬할 때 원래 순서 보존이 필요한지로 판단.
- 복잡도 감각: O(n²)와 O(n log n)의 실제 차이 — n=1000이면 대략 10^6 vs 10^4로 100배, n=10^5면 10^10 vs 1.7·10^6로 약 6000배. 그래서 n이 커질수록 알고리즘 선택이 실행 가능/불가능을 가른다. 흔한 실수: 최선 복잡도만 보고 선택 정렬을 "빠르다"고 오해(선택은 최선도 O(n²)).

**문제**

**1) 연산 횟수 예측** · Easy

- **요구사항**: 정렬 알고리즘 이름과 배열이 주어질 때, 오름차순 정렬 과정에서 발생하는 "핵심 연산" 횟수를 출력하라. 거품=교환 횟수, 선택=실제 교환 횟수, 삽입=이동 횟수로 정의한다.
- **입력**: 첫 줄에 알고리즘 이름(`bubble`|`selection`|`insertion`)과 N(1 ≤ N ≤ 2000), 둘째 줄 N개의 정수.
- **출력**: 정의된 핵심 연산 횟수 하나.
- **예제**: `bubble 5 / 5 1 4 2 8` → `4`
- **예제**: `selection 5 / 5 1 4 2 8` → `2`
- **예제**: `insertion 5 / 5 1 4 2 8` → `4`
- **셀프체크**: 같은 입력이라도 정의된 연산이 달라 값이 다르다(거품 교환=역위=4, 삽입 이동=역위=4, 선택 실제 교환=2). 거품·삽입이 같은 4인 건 둘 다 역위 개수와 같기 때문. 선택은 역위와 무관.

```runner
@@SOLUTION
import sys

def bubble_swaps(a):
    a = a[:]
    n = len(a)
    cnt = 0
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                cnt += 1
                swapped = True
        if not swapped:
            break
    return cnt

def selection_swaps(a):
    a = a[:]
    n = len(a)
    cnt = 0
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if a[j] < a[min_idx]:
                min_idx = j
        if min_idx != i:
            a[i], a[min_idx] = a[min_idx], a[i]
            cnt += 1
    return cnt

def insertion_moves(a):
    a = a[:]
    moves = 0
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            moves += 1
            j -= 1
        a[j + 1] = key
    return moves

def main():
    data = sys.stdin.read().split()
    name = data[0]
    n = int(data[1])
    a = [int(x) for x in data[2:2 + n]]
    if name == "bubble":
        print(bubble_swaps(a))
    elif name == "selection":
        print(selection_swaps(a))
    else:
        print(insertion_moves(a))

main()

(2) 코드 단계별

- 세 함수 `bubble_swaps`, `selection_swaps`, `insertion_moves`를 각각 정의(입력 배열은 복사해 원본 보존).
- 거품: 교환마다 `cnt += 1`.
- 선택: `min_idx != i`일 때만 교환·카운트.

- 앞의 L1-2 / L2-2 / L3-2에서 만든 카운팅 로직을 함수로 묶고, 이름으로 디스패치만 하면 된다.
- 정의 차이를 헷갈리지 말 것: 선택만 "실제 교환"(제자리 제외), 나머지 둘은 역위와 동일.
```

**2) 알고리즘 추천** · Medium

- **요구사항**: 상황 설명(n의 크기, 값 범위, 거의 정렬 여부, 안정성 필요 여부)이 주어질 때 가장 적합한 정렬을 이 레슨 표 기준으로 하나 출력하라. 후보: `insertion`, `selection`, `radix`, `builtin`(파이썬 내장).
- **입력**: 네 줄 — 1행 n(정수), 2행 값 범위 폭 R(최대-최소, 정수), 3행 `sorted` 또는 `random`, 4행 `stable` 또는 `any`.
- **출력**: 추천 알고리즘 이름 하나.
- **예제**: `100000 / 500 / random / stable` → `radix` (n 크고 값 범위 작음 → 기수)
- **예제**: `30 / 1000000000 / sorted / stable` → `insertion` (거의/이미 정렬 + 작은 n → 삽입, 최선 O(n))
- **셀프체크**: 판단 규칙 예시 — (R이 n보다 충분히 작으면 radix) > (거의 정렬 또는 작은 n이면 insertion) > (그 외 큰 n 무작위면 builtin). selection은 "쓰기 비용 큼"이 명시될 때만. 규칙 우선순위를 어떻게 정하냐에 따라 답이 갈릴 수 있으니, 문제에서 준 조건을 기준으로 일관되게 적용하는지 확인.

```runner
@@SOLUTION

    lines = sys.stdin.read().split("\n")

    n = int(vals[0])

    order = vals[2]
    stab = vals[3]
    if r < n:                        # 값 범위가 n보다 작으면 기수

    elif order == "sorted" or n <= 100:  # 거의 정렬 or 작은 n → 삽입
        print("insertion")
    else:                            # 그 외 큰 무작위 → 내장 정렬
        print("builtin")

(2) 코드 단계별

- 네 줄을 읽어 `n`, `R`, 정렬여부(order), 안정성요구(stab)로 파싱.

- 임계값(여기선 `R < n`, `n <= 100`)은 "값 범위가 원소 수보다 작으면 기수가 유리", "수십 규모면 삽입도 충분"이라는 감각에서 나온다.
- 예제 검증: (100000,500)은 R<n → radix. (30, 10억, sorted)는 R≥n이지만 sorted → insertion.
```

**3) 정렬 안정성 판정** · Medium

- **요구사항**: `(키, 원래인덱스)` 쌍 목록을 특정 정렬로 "키 기준" 오름차순 정렬했을 때, 같은 키를 가진 원소들의 원래 인덱스 순서가 보존되면(=안정) `STABLE`, 하나라도 뒤집히면 `UNSTABLE`을 출력하라. 정렬은 지정된 알고리즘(`bubble`|`selection`|`insertion`)으로 직접 수행하되 키만 비교한다.
- **입력**: 첫 줄 알고리즘 이름과 N(1 ≤ N ≤ 1000), 다음 N줄에 각 원소의 키(정수). 원래 인덱스는 입력 순서(0-based).
- **출력**: `STABLE` 또는 `UNSTABLE`.
- **예제**: `selection 4 / 2 / 2 / 1 / 1` → `UNSTABLE`
- **예제**: `insertion 4 / 2 / 2 / 1 / 1` → `STABLE`
- **셀프체크**: 첫 예제(선택 정렬) 추적 — 키 `[2,2,1,1]`(인덱스 0,1,2,3). i=0 최솟값1은 첫 등장 idx2 → idx0과 교환 → 키순서 `[1,2,2,1]` 인덱스 `[2,1,0,3]`. 벌써 키2의 원래 인덱스가 1,0으로 뒤집힘 → UNSTABLE. 삽입 정렬은 `a[j] > key`에서 등호를 안 넘겨 같은 키를 지나치지 않으므로 STABLE. 등호 비교(`>=` vs `>`)를 어디에 두느냐가 안정성의 핵심 함정.

```runner
@@SOLUTION
import sys

def bubble(arr):
    n = len(arr)
    for i in range(n - 1):
        for j in range(n - 1 - i):
            if arr[j][0] > arr[j + 1][0]:   # 키만 비교, 등호는 교환 안 함
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
    return arr

def selection(arr):
    n = len(arr)
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            if arr[j][0] < arr[min_idx][0]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr

def insertion(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j][0] > key[0]:  # 등호 아님 → 같은 키 안 넘김
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr

def main():
    data = sys.stdin.read().split()
    name = data[0]
    n = int(data[1])
    keys = [int(x) for x in data[2:2 + n]]
    arr = [(k, idx) for idx, k in enumerate(keys)]  # (키, 원래 인덱스)
    if name == "bubble":
        arr = bubble(arr)
    elif name == "selection":
        arr = selection(arr)
    else:
        arr = insertion(arr)
    stable = True
    for i in range(1, n):            # 같은 키의 원래 인덱스가 뒤집혔는지 검사
        if arr[i][0] == arr[i - 1][0] and arr[i][1] < arr[i - 1][1]:
            stable = False
            break
    print("STABLE" if stable else "UNSTABLE")

main()

(1) 접근·핵심 아이디어

- 각 원소를 `(키, 원래인덱스)`로 만들고 "키만" 비교하는 지정 정렬로 정렬한다. 정렬 후, 같은 키를 가진 원소들의 원래 인덱스가 여전히 증가 순서면 안정(STABLE), 한 번이라도 감소하면 불안정(UNSTABLE)이다. 거품·삽입은 등호를 넘기지 않아(`>`) 같은 키의 상대 순서를 보존하지만, 선택 정렬 기본형은 멀리 있는 원소와 통째로 교환하며 순서가 뒤집힐 수 있다.

(2) 코드 단계별

- `arr = [(k, idx) for idx, k in enumerate(keys)]`로 원래 인덱스를 붙인다.
- 이름에 맞는 정렬 함수를 호출하되, 비교는 전부 `[0]`(키)만 사용.
- 정렬 후 인접쌍을 훑어 `arr[i][0] == arr[i-1][0]`(같은 키)인데 `arr[i][1] < arr[i-1][1]`(원래 인덱스 역전)이면 UNSTABLE.
- 하나도 없으면 STABLE.

(3) 스스로 다시 짤 때 생각 순서

- 안정성 정의를 "최종 배열에서 같은 키의 원래 인덱스 순서 보존"으로 못박고, 그걸 인접쌍 검사로 옮긴다.
- 선택 정렬의 불안정은 특정 입력에서만 드러난다. `[2,2,1]`(선택)은 최솟값 1을 맨 앞으로 보내며 두 개의 2 순서가 뒤집혀 UNSTABLE이 되는 대표 사례. 같은 입력을 삽입으로 돌리면 STABLE.
- 함정: 비교에 등호(`>=`)를 넣으면 안정 알고리즘도 불안정해진다 — 반드시 `>`(선택은 `<`).
```

> 개요: 계층적 데이터를 표현하는 트리 자료구조를 배운다. 트리의 기본 용어와 이진 트리, 세 가지 순회(전위·중위·후위), 정렬된 탐색을 지원하는 이진 탐색 트리(BST), 그리고 최댓값/최솟값을 빠르게 뽑는 힙(heap)까지 다룬다.

## L1. 트리

**개념**

- 트리(tree)는 노드(node)들이 부모-자식 관계로 연결된 계층적 자료구조다. 사이클이 없고, 연결되어 있으며, 노드가 N개면 간선(edge)은 정확히 N-1개다.

- 왜 쓰는가: 폴더/파일 구조, 조직도, HTML DOM, 수식 파싱 등 "하나가 여러 개를 거느리는" 계층 관계를 표현하기에 자연스럽다. 배열/리스트는 일렬(선형)이라 계층 표현이 어렵다.

- 핵심 용어(꼭 구분):

  - 루트(root): 부모가 없는 최상위 노드. 트리에 딱 하나.

  - 리프(leaf, 단말): 자식이 없는 노드.

  - 부모/자식(parent/child), 형제(sibling): 같은 부모를 공유하는 노드들.

  - 깊이(depth): 루트에서 그 노드까지의 간선 수(루트는 0).

  - 높이(height): 그 노드에서 가장 먼 리프까지의 간선 수. 트리의 높이 = 루트의 높이.

  - 서브트리(subtree): 어떤 노드와 그 자손 전체가 이루는 작은 트리.

- 표현 방법(파이썬):

  - 인접 리스트: `children = [[] for _ in range(N)]` 에 자식 번호를 담는다.

  - 부모 배열: `parent[v]` 에 v의 부모 번호를 저장(루트는 -1). 입력이 "각 노드의 부모"로 주어질 때 편하다.

```python
# 부모 정보로 자식 리스트 만들기 (노드 0..N-1, 루트의 부모는 -1)
def build_children(parent):
    N = len(parent)
    children = [[] for _ in range(N)]
    root = -1
    for v in range(N):
        if parent[v] == -1:
            root = v
        else:
            children[parent[v]].append(v)
    return root, children

# 재귀로 서브트리 크기(자기 포함) 세기
def subtree_size(v, children):
    size = 1
    for c in children[v]:
        size += subtree_size(c, children)
    return size
```

**접근 전략**

- 핵심 아이디어: 트리 문제는 대부분 "루트에서 시작해 자식으로 내려가는 재귀"로 푼다. 각 노드에서 (1) 나 자신을 처리하고 (2) 자식들을 재귀 호출한 결과를 모은다. 깊이는 부모 깊이+1로 내려가며 전달하고, 높이/서브트리 크기는 자식들의 결과를 받아 올라오며 합친다.

- 전형적 절차: 입력을 인접/부모 배열로 변환 → 루트를 찾음 → 루트부터 DFS(재귀). "내려가며 계산"(깊이)인지 "올라오며 계산"(높이·크기·합)인지 먼저 구분한다.

- 언제 쓰나: 계층·포함·"~의 모든 자손" 같은 관계를 다룰 때. 부모 배열만 주어져도 위 방식으로 트리를 재구성한다.

- 복잡도: 트리 전체를 한 번 순회하므로 시간 O(N), 재귀 스택/자식 리스트로 공간 O(N). 주의: 파이썬 기본 재귀 한도(약 1000)라 깊은 트리는 `sys.setrecursionlimit`을 올려야 한다. 루트가 여러 개거나 사이클이 있으면 트리가 아니다(입력 검증 함정).

**문제**

**1) 트리의 높이와 리프 수** · Easy

- **요구사항**: 각 노드의 부모가 주어진 트리에서, 트리의 높이(루트에서 가장 깊은 리프까지의 간선 수)와 리프 노드의 개수를 구하라.

- **입력**: 첫 줄에 노드 수 N. 둘째 줄에 `parent[0..N-1]` (루트는 -1). 노드 번호는 0..N-1.

- **출력**: 높이와 리프 수를 공백으로 구분해 한 줄.

- **예제**:

  - `5 / -1 0 0 1 1` → `2 3`  (루트 0; 0의 자식 1,2; 1의 자식 3,4. 리프는 2,3,4 → 3개. 가장 깊은 경로 0→1→3 은 간선 2개)

  - `1 / -1` → `0 1`  (노드 하나. 루트이자 리프, 높이 0)

- **셀프체크**: 노드가 1개면 높이 0·리프 1인가? 리프 판정을 "자식 리스트가 비었는가"로 했는가(부모 배열만 보고 판정하면 틀림)? 깊은 트리에서 재귀 한도를 올렸는가?

```runner
@@SOLUTION
import sys
sys.setrecursionlimit(300000)
data = sys.stdin.read().split()
idx = 0
n = int(data[idx]); idx += 1
parent = [int(data[idx + i]) for i in range(n)]; idx += n
children = [[] for _ in range(n)]
root = -1
for v in range(n):
    if parent[v] == -1:
        root = v
    else:
        children[parent[v]].append(v)

def height(v):
    if not children[v]:
        return 0
    return 1 + max(height(c) for c in children[v])

h = height(root)
leaves = sum(1 for v in range(n) if not children[v])
print(h, leaves)
@@TESTS
--IN

-1 0 0 1 1
--OUT
2 3
--IN
4
-1 0 1 2
--OUT
3 1
@@EXPL
(1) 접근·핵심 아이디어

- 부모 배열을 자식 리스트로 뒤집으면 트리를 위에서 아래로 탐색할 수 있다. 높이는 "자식들 높이의 최댓값 + 1"로 올라오며 계산하고, 리프는 "자식이 하나도 없는 노드"다.

(2) 코드 단계별

- `parent[v]`를 훑어 루트(-1)를 찾고, 나머지는 `children[parent[v]]`에 v를 추가한다.
- `height(v)`는 자식이 없으면 0(간선 기준), 있으면 자식 높이의 최댓값에 1을 더해 반환한다.
- 리프 수는 `children[v]`가 빈 노드의 개수로 센다.

(3) 스스로 다시 짤 때 생각 순서

- 부모 배열 → 자식 리스트 변환과 루트 찾기를 먼저 한다.
- 높이는 "올라오며 합치는" 재귀임을 떠올린다(리프에서 0 시작).
- 리프 판정은 반드시 자식 리스트가 비었는지로 한다. 깊은 사슬을 대비해 재귀 한도를 올린다.
```

**2) 두 노드의 최소 공통 조상(LCA) — 부모 타고 올라가기** · Medium

- **요구사항**: 각 노드의 부모가 주어진 트리에서 두 노드 u, v의 최소 공통 조상(둘 다의 조상이면서 가장 깊은 노드)을 구하라. 자기 자신도 자신의 조상으로 본다.

- **입력**: 첫 줄 N. 둘째 줄 `parent[0..N-1]`(루트 -1). 셋째 줄에 정수 두 개 u v.

- **출력**: LCA 노드 번호.

- **예제**:

  - `7 / -1 0 0 1 1 2 2` (u v = `3 4`) → `1`  (3의 조상: 3,1,0 / 4의 조상: 4,1,0 → 공통 중 가장 깊은 건 1)

  - `7 / -1 0 0 1 1 2 2` (u v = `3 5`) → `0`  (3의 조상: 3,1,0 / 5의 조상: 5,2,0 → 공통은 0)

- **셀프체크**: u의 조상 집합을 set으로 모은 뒤 v에서 부모를 타고 올라가며 처음 만나는 조상을 답으로 했는가? u가 v의 조상인 경우(예: u=1, v=3 → 답 1)도 맞는가? 루트를 넘어 -1로 넘어가지 않게 종료 조건을 뒀는가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
idx = 0
n = int(data[idx]); idx += 1
parent = [int(data[idx + i]) for i in range(n)]; idx += n
u = int(data[idx]); v = int(data[idx + 1])

anc = set()
x = u
while x != -1:
    anc.add(x)
    x = parent[x]

y = v
while y not in anc:
    y = parent[y]
print(y)
@@TESTS
--IN
7
-1 0 0 1 1 2 2
3 4
--OUT
1
--IN
7
-1 0 0 1 1 2 2
1 3
--OUT
1
@@EXPL
(1) 접근·핵심 아이디어

- u에서 루트까지 부모를 타고 올라가며 만나는 노드를 모두 "u의 조상 집합"으로 모은다. 그다음 v에서 부모를 타고 올라가면서 이 집합에 처음 들어 있는 노드가 곧 가장 깊은 공통 조상(LCA)이다. 자기 자신도 조상으로 본다.

(2) 코드 단계별

- `x = u`에서 시작해 `x != -1`인 동안 `anc`에 담고 `x = parent[x]`로 올라간다.
- `y = v`에서 시작해 `y`가 `anc`에 없으면 계속 `parent[y]`로 올라간다.
- 처음으로 `anc`에 속하는 `y`를 출력한다. u가 v의 조상이면 v가 올라오다 u를 만나 바로 답이 된다.

(3) 스스로 다시 짤 때 생각 순서

- "한쪽 조상을 전부 기록 → 다른 쪽에서 올라가며 첫 교집합" 패턴을 떠올린다.
- 루트의 부모가 -1이므로 while 조건으로 -1을 넘지 않게 한다.
- 자기 자신 포함 규칙(u=v면 답 u)을 set에 u/v 자신도 넣어 처리한다.
```

**3) 서브트리 노드 수 질의** · Medium

- **요구사항**: 부모 정보로 트리를 만들고, 주어진 각 질의 노드 q에 대해 q를 루트로 하는 서브트리의 노드 수(자기 포함)를 출력하라.

- **입력**: 첫 줄 N. 둘째 줄 `parent[0..N-1]`(루트 -1). 셋째 줄 질의 수 Q. 넷째 줄 질의 노드 q들.

- **출력**: 각 질의의 답을 한 줄에 하나씩.

- **예제**:

  - `6 / -1 0 0 1 1 2` , `Q=3` , `0 1 2` → `6` / `3` / `2`  (0의 서브트리=전체 6; 1의 서브트리={1,3,4}=3; 2의 서브트리={2,5}=2)

  - `3 / -1 0 1` , `Q=1` , `1` → `2`  (1의 서브트리={1,2})

- **셀프체크**: 서브트리 크기를 한 번의 DFS로 모든 노드에 대해 미리 계산해 두었는가(질의마다 다시 세면 O(NQ)로 느려짐)? 크기 계산이 "자식들 크기 합 + 1"인가? 리프의 크기는 1인가?

```runner
@@SOLUTION
import sys
sys.setrecursionlimit(300000)
data = sys.stdin.read().split()
idx = 0
n = int(data[idx]); idx += 1
parent = [int(data[idx + i]) for i in range(n)]; idx += n
q = int(data[idx]); idx += 1
queries = [int(data[idx + i]) for i in range(q)]; idx += q

children = [[] for _ in range(n)]
root = -1
for v in range(n):
    if parent[v] == -1:
        root = v
    else:
        children[parent[v]].append(v)

size = [1] * n
order = []
stack = [root]
while stack:
    v = stack.pop()
    order.append(v)
    for c in children[v]:
        stack.append(c)
for v in reversed(order):
    if parent[v] != -1:
        size[parent[v]] += size[v]

out = []
for query in queries:
    out.append(str(size[query]))
print('\n'.join(out))
@@TESTS
--IN

-1 0 0 1 1 2
3
0 1 2
--OUT

2
--IN
5
-1 0 0 0 0
2
0 2
--OUT

1
@@EXPL
(1) 접근·핵심 아이디어

- 서브트리 크기는 "자식들 크기의 합 + 1"이다. 질의마다 다시 세면 느리므로, 한 번의 순회로 모든 노드의 크기를 미리 구해 두고 질의는 O(1)로 답한다.

(2) 코드 단계별

- 부모 배열을 자식 리스트로 변환하고 루트를 찾는다.
- 스택 DFS로 방문 순서 `order`를 만든 뒤, 그 역순(자식이 먼저 확정됨)으로 훑으며 `size[parent[v]] += size[v]`로 크기를 누적한다.
- 각 질의 노드 q에 대해 미리 구한 `size[q]`를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "질의가 많다 → 전처리로 전부 계산" 판단을 먼저 한다.
- 후위(자식 먼저) 순서가 필요함을 떠올리고, 재귀 대신 방문 역순으로 안전하게 누적한다.
- 리프는 초깃값 1 그대로, 내부 노드는 자식 합이 더해진다.
```


## L2. 이진 트리 개념

**개념**

- 이진 트리(binary tree)는 모든 노드가 자식을 최대 2개(왼쪽·오른쪽)만 갖는 트리다. 왼쪽/오른쪽 구분이 있다는 점이 일반 트리와 다르다(자식이 하나여도 "왼쪽인지 오른쪽인지"가 의미를 갖는다).

- 왜 쓰는가: 자식 수가 2개로 고정되면 구조가 단순해져 순회·탐색·삽입 알고리즘을 깔끔하게 정의할 수 있다. 뒤에 배울 BST와 힙이 모두 이진 트리다.

- 종류:

  - 정 이진 트리(full): 모든 노드가 자식 0개 또는 2개.

  - 완전 이진 트리(complete): 마지막 레벨을 제외하고 꽉 차 있고, 마지막 레벨은 왼쪽부터 채워짐. → 배열로 표현하기 좋다(힙의 기반).

  - 균형 이진 트리: 좌우 높이 차가 작아 높이가 O(log N)에 가까움.

- 표현 방법:

  - 노드 객체(포인터): 각 노드가 `left`, `right` 참조를 가짐. 삽입/삭제가 유연.

  - 배열 인덱싱(1-based): 노드 i의 왼쪽 자식 `2*i`, 오른쪽 자식 `2*i+1`, 부모 `i//2`. 완전 이진 트리에 특히 잘 맞는다.

```python
# 포인터 기반 노드
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

# 배열 기반(1-based). tree[1]이 루트.
# 왼쪽 자식: 2*i, 오른쪽 자식: 2*i+1, 부모: i//2
def left(i):  return 2 * i
def right(i): return 2 * i + 1
def parent(i): return i // 2
```

- 성질: 높이 h인 이진 트리의 노드 수는 최대 2^(h+1) - 1개. 노드가 N개인 완전 이진 트리의 높이는 floor(log2 N).

**접근 전략**

- 핵심 아이디어: "이 문제에 포인터 표현이 맞나, 배열 표현이 맞나"를 먼저 정한다. 입력이 완전 이진 트리거나 "i번 노드의 자식은 2i, 2i+1" 규칙이면 배열이 훨씬 간단하다. 임의 모양(왼쪽/오른쪽이 자유롭게 비는)이면 포인터/자식 배열이 낫다.

- 전형적 절차: 노드 구조 정의 → 재귀로 좌우 서브트리를 각각 처리 → 좌우 결과를 합쳐 현재 노드 답 계산. 이진 트리 재귀의 뼈대는 항상 `if node is None: return 기저값` 으로 시작한다.

- 언제 쓰나: 좌우 구분이 의미 있는 계층(수식 트리, 결정 트리)이나, 뒤의 BST·힙처럼 이진 구조 위에 규칙을 얹을 때.

- 복잡도: 노드 N개를 한 번씩 방문하는 재귀는 시간 O(N), 공간은 재귀 스택 O(높이) — 균형 트리면 O(log N), 한쪽으로 치우치면 O(N). 흔한 실수: `None` 자식 처리를 빠뜨려 에러; 배열 표현에서 0-based/1-based 인덱스를 섞어 쓰기.

**문제**

**1) 이진 트리의 높이와 노드 수** · Easy

- **요구사항**: 각 노드의 왼쪽·오른쪽 자식이 주어진 이진 트리에서 높이(간선 기준)와 전체 노드 수를 구하라.

- **입력**: 첫 줄에 노드 수 N(노드 번호 1..N, 루트는 1). 이후 N줄, i번째 줄에 `left_i right_i`(자식이 없으면 0).

- **출력**: 높이와 노드 수를 공백으로 구분.

- **예제**:

  - `3 / 2 3 / 0 0 / 0 0` → `1 3`  (루트 1의 자식 2,3. 둘 다 리프. 높이 1)

  - `3 / 2 0 / 3 0 / 0 0` → `2 3`  (1→2→3 일직선. 높이 2)

- **셀프체크**: 자식 값 0을 "없음"으로 제대로 처리했는가? 높이를 `max(왼쪽 높이, 오른쪽 높이)+1`(간선 기준이면 리프에서 0)로 계산했는가? 한쪽만 있는 노드도 맞는가?

```runner
- 이진 트리 높이는 "좌우 서브트리 높이의 최댓값 + 1"이다. 간선 기준 높이를 맞추려면 빈 자식(0)을 -1로 두어, 리프(자식이 둘 다 0)의 높이가 0이 되게 한다. 노드 수는 입력 N 그대로다.

(2) 코드 단계별

- i번째 줄에서 `left[i]`, `right[i]`를 읽어 배열에 저장한다(0은 자식 없음).

- 재귀 뼈대 `if v == 0: return 기저값`으로 시작한다.
- 한쪽 자식만 있는 노드도 max가 자동으로 처리해 준다.
```

**2) 완전 이진 트리인지 판정** · Medium

- **요구사항**: 이진 트리가 완전 이진 트리(마지막 레벨 전까지 꽉 차고, 마지막 레벨은 왼쪽부터 채워짐)인지 판정하라.

- **입력**: 첫 줄 N(루트 1). 이후 N줄, i번째 줄 `left_i right_i`(없으면 0).

- **출력**: 완전 이진 트리면 `YES`, 아니면 `NO`.

- **예제**:

  - `5 / 2 3 / 4 5 / 0 0 / 0 0 / 0 0` → `YES`  (레벨0: 1, 레벨1: 2,3, 레벨2: 4,5 왼쪽부터. 완전)

  - `5 / 2 3 / 0 4 / 5 0 / 0 0 / 0 0` → `NO`  (2의 왼쪽이 비었는데 오른쪽(4)이 있음 → 왼쪽부터 채움 규칙 위반)

- **셀프체크**: BFS로 레벨 순회하며 "None을 한 번 본 뒤에 실제 노드가 또 나오면 완전이 아니다"로 판정했는가? 노드 하나(N=1)는 YES인가? 왼쪽이 없는데 오른쪽만 있는 경우를 걸렀는가?

```runner
- 한쪽만 있는 경우(0 다음에 실제 노드)가 자동으로 걸러진다. N=1은 큐에 0만 이어져 YES.
```

**3) 배열 표현 완전 이진 트리의 부모-자식 합** · Easy

- **요구사항**: 1-based 배열로 저장된 완전 이진 트리(값이 배열 순서대로 주어짐)에서, 각 내부 노드에 대해 "자기 값 + 자식 값들의 합"이 최대인 노드의 번호를 구하라(동점이면 작은 번호).

- **입력**: 첫 줄 N. 둘째 줄에 노드 1..N의 값 A[1..N].

- **출력**: 해당 노드 번호.

- **예제**:

  - `5 / 1 2 3 4 5` → `2`  (노드1: 1+2+3=6, 노드2: 2+4+5=11 → 최대는 2)

  - `3 / 5 1 1 ` → `1`  (노드1: 5+1+1=7, 노드2·3은 리프 → 자기값만 1 → 최대는 1)

- **셀프체크**: 노드 i의 자식 인덱스 `2*i`, `2*i+1`이 N을 넘으면 그 자식은 없다고 처리했는가? 리프는 자기 값만 더하는가? 1-based 인덱스를 일관되게 썼는가?

```runner
@@SOLUTION
import sys

    a[i] = int(data[idx]); idx += 1

    s = a[i]
    if 2 * i <= n:
        s += a[2 * i]
    if 2 * i + 1 <= n:
        s += a[2 * i + 1]
    if best_val is None or s > best_val:
        best_val = s
        best_node = i
print(best_node)

@@EXPL
(1) 접근·핵심 아이디어

- 1-based 배열 완전 이진 트리에서 노드 i의 자식은 `2*i`, `2*i+1`이다. 각 노드마다 "자기 값 + 존재하는 자식 값들"을 더해 최댓값을 갖는 노드 번호를 찾는다. 동점이면 먼저 나온(작은) 번호가 유지된다.

(2) 코드 단계별

- 값 배열 A를 1-based로 읽는다.
- i를 1..N으로 돌며 `s = a[i]`에서 시작해 `2*i`, `2*i+1`이 N 이하일 때만 그 자식 값을 더한다.
- `s`가 지금까지 최댓값보다 클 때만 갱신하므로 동점에서는 작은 번호가 남는다.

(3) 스스로 다시 짤 때 생각 순서

- 1-based 자식 공식 `2*i`, `2*i+1`을 정확히 쓴다(0-based와 혼동 금지).
- 자식 인덱스가 N을 넘으면 그 자식은 없음 → 더하지 않는다(리프는 자기 값만).
- 동점 처리를 위해 비교는 `>`만 쓰고 `>=`는 쓰지 않는다.
```


## L3. 이진 트리와 탐색

**개념**

- 이진 트리 순회(traversal)는 모든 노드를 빠짐없이 한 번씩 방문하는 방법이다. 깊이 우선(DFS) 계열에 3가지가 있고, "현재 노드를 언제 방문(처리)하느냐"로 구분한다.

  - 전위(preorder): **현재 → 왼쪽 → 오른쪽**. 루트를 먼저 본다. 트리 복사·직렬화에 유용.

  - 중위(inorder): **왼쪽 → 현재 → 오른쪽**. BST에서 이 순서가 곧 오름차순 정렬 결과(뒤 레슨).

  - 후위(postorder): **왼쪽 → 오른쪽 → 현재**. 자식을 다 처리한 뒤 부모 → 서브트리 삭제·크기/합 계산·수식 계산에 유용.

- 별도로 레벨 순회(level-order, BFS): 위에서 아래로, 같은 레벨은 왼쪽→오른쪽. 큐(`collections.deque`)로 구현.

```python
def preorder(node, out):
    if node is None: return
    out.append(node.val)      # 현재
    preorder(node.left, out)  # 왼쪽
    preorder(node.right, out) # 오른쪽

def inorder(node, out):
    if node is None: return
    inorder(node.left, out)
    out.append(node.val)      # 현재를 가운데에
    inorder(node.right, out)

def postorder(node, out):
    if node is None: return
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.val)      # 현재를 마지막에

from collections import deque
def level_order(root, out):
    if root is None: return
    q = deque([root])
    while q:
        node = q.popleft()
        out.append(node.val)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
```

**접근 전략**

- 핵심 아이디어: 세 순회의 코드 뼈대는 동일하고 "현재 노드를 append 하는 위치"만 다르다. 문제에서 요구하는 방문 순서를 보고 전/중/후를 고른다. "부모보다 자식을 먼저 끝내야 하는 계산"(서브트리 합, 삭제)이면 후위, "루트부터 찍어야" 하면 전위.

- 재귀 ↔ 스택 변환: 재귀가 깊어 스택 오버플로가 걱정되면 명시적 스택으로 바꾼다. 전위는 스택에 넣을 때 "오른쪽을 먼저 push, 왼쪽을 나중에 push"해야 왼쪽이 먼저 나온다.

- 순회 결과로 트리 복원: 전위+중위 또는 후위+중위가 있으면 트리를 유일하게 복원할 수 있다(전위의 첫 원소가 루트 → 중위에서 그 위치를 찾아 좌/우로 분할). 전위+후위만으로는 일반적으로 유일하지 않다(주의).

- 언제 쓰나: 트리를 특정 순서로 나열·직렬화·계산할 때. 레벨 순회는 "가장 가까운 것부터", "레벨별 처리"에 쓴다.

- 복잡도: 세 순회 모두 각 노드 1회 방문이라 시간 O(N). 공간은 재귀 스택/명시 스택이 O(높이)(최악 O(N)), 레벨 순회 큐는 최악 O(N)(가장 넓은 레벨 폭). 흔한 실수: 중위/후위에서 append 위치를 잘못 두기, 명시 스택 전위에서 좌/우 push 순서 뒤집기.

**문제**

**1) 세 가지 순회 출력** · Easy

- **입력**: 첫 줄 N(루트 1). 이후 N줄, i번째 줄 `left_i right_i`(없으면 0). 노드 i의 값은 i라고 본다.

  - `3 / 2 3 / 0 0 / 0 0` → `1 2 3` / `2 1 3` / `2 3 1`

**2) 전위+중위로 후위 복원** · Medium

- **요구사항**: 어떤 이진 트리의 전위 순회와 중위 순회 결과(노드 값은 서로 다른 정수)가 주어진다. 이 트리의 후위 순회를 출력하라.

- **입력**: 첫 줄 N. 둘째 줄 전위 수열(N개). 셋째 줄 중위 수열(N개).

- **출력**: 후위 순회 결과(공백 구분).

- **예제**:

  - `3` , 전위 `1 2 3` , 중위 `2 1 3` → `2 3 1`  (전위 첫 1=루트, 중위에서 1의 왼쪽 {2}=왼서브, 오른쪽 {3}=오른서브)

  - `5` , 전위 `1 2 4 5 3` , 중위 `4 2 5 1 3` → `4 5 2 3 1`
    - 검산: 루트 1. 중위에서 1 왼쪽 {4,2,5}, 오른쪽 {3}. 왼서브의 전위 `2 4 5` → 루트 2, 중위 {4}|{5} → 후위 4 5 2. 오른서브 후위 3. 전체 후위 = (왼)4 5 2 (오)3 (루트)1 = 4 5 2 3 1

- **셀프체크**: 전위의 첫 원소를 루트로 잡고 중위에서 그 위치로 좌/우를 나눴는가? 값→중위인덱스 dict로 분할 위치를 O(1)에 찾았는가(매번 index() 하면 느림)? 후위는 "왼 처리 → 오 처리 → 루트"로 모았는가?

```runner
@@SOLUTION

def build(in_lo, in_hi):
    if in_lo > in_hi:

    root = pre[pre_idx[0]]
    pre_idx[0] += 1
    mid = pos[root]
    build(in_lo, mid - 1)
    build(mid + 1, in_hi)
    post.append(root)

build(0, n - 1)
print(' '.join(map(str, post)))

**이 풀이의 새 문법**

- `{val: i for i, val in enumerate(ino)}`: 딕셔너리 컴프리헨션. 리스트 컴프리헨션과 같은 문법으로 `{키: 값 for ...}` 형태를 써서 "값 → 인덱스" 매핑 dict를 한 줄에 만든다.
- `pre_idx = [0]`: 재귀 함수 `build` 안에서 바깥의 "전위 포인터"를 계속 늘려야 하는데, 함수 안에서 바깥 변수를 직접 재대입할 수 없어(변수 스코프 문제) 원소 1개짜리 리스트에 담아 `pre_idx[0] += 1`처럼 내용만 바꾸는 우회 기법이다.

(1) 접근·핵심 아이디어

- 전위의 첫 원소가 항상 루트다. 중위에서 그 루트의 위치를 찾으면 왼쪽 조각이 왼 서브트리, 오른쪽 조각이 오른 서브트리다. 전위 포인터를 앞으로 진행시키며 왼→오 순으로 재귀하고, 돌아오는 길에 루트를 append하면 후위가 만들어진다.

(2) 코드 단계별

- 값→중위인덱스 `pos` dict로 분할 위치를 O(1)에 찾는다.
- `build(in_lo, in_hi)`는 전위 포인터에서 루트를 하나 소비하고, 중위에서 그 위치 `mid`를 기준으로 왼쪽 구간, 오른쪽 구간을 재귀한다.
- 두 재귀가 끝난 뒤 루트를 `post`에 넣는다(후위 = 왼→오→루트).

(3) 스스로 다시 짤 때 생각 순서

- "전위 첫 = 루트, 중위에서 좌/우 분할" 규칙을 먼저 확립한다.
- 전위 소비 순서(루트 → 왼 서브트리 전체 → 오 서브트리 전체)에 맞춰 왼쪽을 먼저 재귀한다.
- 후위 출력이라 append는 두 재귀 뒤에 둔다. index()를 매번 부르지 않도록 dict로 위치를 캐싱한다.
```

**3) 트리의 레벨별 최댓값** · Medium

- **요구사항**: 이진 트리에서 각 레벨(깊이)마다 노드 값의 최댓값을 위 레벨부터 순서대로 출력하라.

- **입력**: 첫 줄 N(루트 1). 둘째 줄에 노드 값 V[1..N]. 이후 N줄, i번째 줄 `left_i right_i`(없으면 0).

- **출력**: 레벨 0부터 최댓값들을 공백으로 구분해 한 줄.

- **예제**:

  - `3` , 값 `3 5 2` , `2 3 / 0 0 / 0 0` → `3 5`  (레벨0: {3}→3, 레벨1: {5,2}→5)

  - `5` , 값 `1 9 4 2 8` , `2 3 / 4 5 / 0 0 / 0 0 / 0 0` → `1 9 8`  (레벨0:{1}, 레벨1:{9,4}→9, 레벨2:{2,8}→8)

- **셀프체크**: BFS 큐에 (노드, 깊이)를 함께 넣거나 레벨 단위로 큐 크기만큼 끊어 처리했는가? 각 레벨의 최댓값을 정확히 그 레벨 노드들만으로 구했는가? 빈 자식(0)을 큐에 안 넣었는가?

```runner
        if right[node] != 0:
```

## L4. 이진 탐색 트리

**개념**

- 이진 탐색 트리(BST, Binary Search Tree)는 "왼쪽 서브트리의 모든 값 < 노드 값 < 오른쪽 서브트리의 모든 값"이라는 규칙을 지키는 이진 트리다(중복은 보통 없다고 가정).

- 왜 쓰는가: 탐색·삽입·삭제를 트리 높이에 비례한 시간에 처리한다. 균형이 잡히면 O(log N)로 정렬 상태를 유지하며 동적으로 원소를 넣고 뺄 수 있다. 정렬 배열은 삽입/삭제가 O(N)인데 BST는 그보다 빠를 수 있다.

- 핵심 동작:

  - 탐색: 루트에서 시작해 찾는 값이 작으면 왼쪽, 크면 오른쪽으로 내려간다.

  - 삽입: 탐색과 같은 경로로 내려가 빈 자리(None)에 새 노드를 단다.

  - 중위 순회하면 값이 오름차순으로 나온다(BST의 결정적 성질).

  - 삭제: 자식 0개면 그냥 제거, 1개면 그 자식으로 대체, 2개면 오른쪽 서브트리의 최솟값(또는 왼쪽 서브트리의 최댓값)으로 값을 바꾸고 그 노드를 삭제.

```python
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

def insert(root, val):
    if root is None:
        return Node(val)
    if val < root.val:
        root.left = insert(root.left, val)
    elif val > root.val:
        root.right = insert(root.right, val)
    # val == root.val 이면 무시(중복 없음 가정)
    return root

def search(root, val):
    while root is not None:
        if val == root.val:
            return True
        root = root.left if val < root.val else root.right
    return False
```

**접근 전략**

- 핵심 아이디어: "작으면 왼쪽, 크면 오른쪽" 규칙으로 한 방향씩만 내려가므로 매 단계 후보가 절반가량 준다(이진 탐색과 같은 발상, 단 자료는 트리). 탐색·삽입 코드가 사실상 동일한 경로를 따른다.

- 정렬 활용: BST에 값을 다 넣고 중위 순회하면 정렬된 수열을 얻는다. "정렬 상태 유지 + 특정 값의 순위/범위" 문제에 잘 맞는다. k번째 작은 값은 중위 순회 중 k번째 원소.

- 언제 쓰나: 동적으로 원소가 추가/삭제되면서 "존재 여부, 정렬 순서, 근접 값(바로 큰/작은 값)"을 물을 때. 단, 파이썬 실전에서 균형까지 필요하면 직접 구현보다 정렬 리스트+`bisect`가 더 실용적일 때가 많다(개념은 BST로 이해하되 도구 선택은 상황에 맞게).

- 복잡도: 탐색·삽입·삭제 모두 O(높이). 균형 잡히면 O(log N), 최악(정렬된 값을 순서대로 삽입 → 한쪽으로 치우친 사슬)은 O(N). 중위 순회 O(N). 공간 O(N). 흔한 실수: 삽입을 반환값으로 부모에 다시 연결하지 않아 트리가 안 자람; 삭제에서 자식 2개 케이스 누락; 중복 값 처리 미정의.

> 선행: `bisect`(이진탐색 챕터에서 다룸)는 정렬 리스트에서 삽입 위치를 O(log N)에 찾는 표준 도구다. BST의 대안으로 언급만 한다.

**3) 삽입/탐색 질의 처리** · Medium

```runner
    if root is None:
        root = x
        left[x] = None; right[x] = None
        return
    cur = root
    while True:
        if x < cur:
            if left[cur] is None:
                left[cur] = x; left[x] = None; right[x] = None; return
            cur = left[cur]
        elif x > cur:
            if right[cur] is None:
                right[cur] = x; left[x] = None; right[x] = None; return
            cur = right[cur]
        else:
            return

def search(x):
    cur = root
    while cur is not None:
        if x == cur:
            return True
        cur = left[cur] if x < cur else right[cur]
    return False

for _ in range(Q):
    t = int(data[idx]); x = int(data[idx + 1]); idx += 2
    if t == 1:
        insert(x)
    else:
        out.append("YES" if search(x) else "NO")
print('\n'.join(out))
```

## L5. Heap

**개념**

- 힙(heap)은 "부모가 자식보다 우선(작거나/크거나)"이라는 규칙만 지키는 완전 이진 트리다. 최소 힙(min-heap)은 부모 ≤ 자식이라 루트가 항상 최솟값, 최대 힙(max-heap)은 부모 ≥ 자식이라 루트가 항상 최댓값.

- 왜 쓰는가: "지금 남은 것 중 최소(또는 최대)를 반복해서 빠르게 꺼내야 할 때". 정렬 배열은 삽입이 O(N)이지만 힙은 삽입·삭제가 O(log N)이면서 최솟값 조회는 O(1). 우선순위 큐(priority queue)의 표준 구현.

- 배열 표현(완전 이진 트리라 딱 맞음, 파이썬은 0-based): 노드 i의 왼쪽 자식 `2*i+1`, 오른쪽 자식 `2*i+2`, 부모 `(i-1)//2`.

- 주의(인덱스 기준 대조): L2의 배열 이진 트리는 **1-based**로 왼쪽 자식 `2*i`, 오른쪽 자식 `2*i+1`, 부모 `i//2`였다. 여기 힙은 파이썬 리스트에 맞춰 **0-based**라 공식이 `2*i+1`/`2*i+2`/`(i-1)//2`로 달라진다. 같은 "완전 이진 트리 → 배열" 아이디어지만 시작 인덱스가 0인지 1인지에 따라 +1이 붙고 안 붙으니, 두 공식을 섞어 쓰지 않도록 주의한다.

  | 기준 | 왼쪽 자식 | 오른쪽 자식 | 부모 |
  | --- | --- | --- | --- |
  | 1-based(L2 트리) | `2*i` | `2*i+1` | `i//2` |
  | 0-based(L5 힙) | `2*i+1` | `2*i+2` | `(i-1)//2` |

- 핵심 동작(최소 힙):

  - push: 배열 끝에 추가 후, 부모보다 작으면 부모와 교환하며 위로(up-heapify/sift-up).

  - pop(최솟값 제거): 루트를 배열 마지막 원소로 덮고 크기 줄인 뒤, 자식 중 더 작은 쪽과 비교·교환하며 아래로(down-heapify/sift-down).

- 파이썬 `heapq`: 리스트를 최소 힙으로 다루는 표준 모듈. 최대 힙이 필요하면 값의 부호를 뒤집어 넣는다(`-x`).

```python
import heapq
h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
print(h[0])            # 1 (항상 최솟값, O(1))
print(heapq.heappop(h))# 1 (최솟값 꺼내며 제거, O(log N))

# 리스트를 한 번에 힙으로 (O(N))
data = [5, 1, 3, 2]
heapq.heapify(data)

# 최대 힙 흉내: 부호 반전해서 넣고, 꺼낼 때 다시 반전
maxh = []
for x in [5, 1, 3]:
    heapq.heappush(maxh, -x)
biggest = -heapq.heappop(maxh)   # 5
```

**접근 전략**

- 핵심 아이디어: "매번 전체를 정렬할 필요 없이, 극값(최소/최대) 하나만 빠르게 필요"할 때 힙을 쓴다. 넣고 빼는 사이사이에 데이터가 계속 바뀌어도 루트만 보면 현재 극값을 O(1)에 알 수 있다.

- 전형적 패턴:

  - 우선순위 큐: (우선순위, 데이터) 튜플을 push하면 우선순위 기준으로 정렬돼 pop된다(동점 시 두 번째 원소로 비교되니 비교 가능한 값을 넣거나 카운터를 끼운다).

  - k개 유지: "가장 큰 k개"는 크기 k의 최소 힙을 유지하며 루트(최솟값)보다 큰 값이 오면 교체 → k번째 큰 값 등을 O(N log k)에.

  - 여러 정렬 스트림 병합, 다익스트라(뒤 챕터)의 핵심 도구.

- 최대 힙: 파이썬엔 없으니 `-x`로 넣거나 `(-priority, item)` 튜플을 쓴다.

- 언제 쓰나: "다음으로 처리할 가장 급한/작은/큰 것"을 반복 선택할 때. 정렬은 한 번에 끝나지만 힙은 삽입·삭제가 섞여 계속 갱신되는 상황에 강하다.

- 복잡도: push/pop 각각 O(log N), 최솟값 조회(peek) O(1), heapify O(N), 힙 정렬(전부 push 후 전부 pop) O(N log N). 공간 O(N). 흔한 실수: `heapq`가 기본 최소 힙임을 잊고 최대 힙처럼 씀; `h[0]` peek 후 pop 안 해서 같은 값 중복 처리; 튜플 우선순위 동점에서 두 번째 원소가 비교 불가(객체)라 에러.

**문제**

**1) 최소 힙 시뮬레이션** · Easy

- **요구사항**: 두 종류 질의를 처리하라. `1 x`는 x를 힙에 추가, `2`는 힙에서 최솟값을 꺼내 출력(비었으면 `0` 출력). 최소 힙으로 동작해야 한다.

- **입력**: 첫 줄 Q. 이후 Q줄, `1 x` 또는 `2`.

- **출력**: 타입 2 질의마다 결과를 한 줄씩.

- **예제**:

  - `5` , `1 5` / `1 1` / `2` / `2` / `2` → `1` / `5` / `0`
    - 검산: {5,1} → pop 1 → pop 5 → 빈 힙에서 pop → 0.

  - `4` , `2` / `1 3` / `1 2` / `2` → `0` / `2`
    - 검산: 빈 상태 pop → 0, {3,2} → pop 2.

- **셀프체크**: 빈 힙 pop을 0으로 안전 처리했는가(예외 안 나게)? `heapq`를 최소 힙 그대로 썼는가? peek이 아니라 실제 pop 했는가?

**2) K번째로 큰 수 유지** · Medium

- **요구사항**: 정수 스트림이 하나씩 들어온다. 각 정수를 받은 뒤, 지금까지 들어온 수 중 K번째로 큰 값을 출력하라(아직 K개 미만이면 `-1`). 크기 K의 최소 힙을 유지해 O(log K)에 갱신하라.

- **입력**: 첫 줄 N과 K. 둘째 줄에 정수 N개(도착 순서).

- **출력**: 각 도착 시점의 답을 공백으로 구분해 한 줄(또는 줄바꿈).

- **예제**:

  - `5 2 / 3 1 5 4 2` → `-1 1 3 4 4`
    - 검산: 3(개수1<2 →-1) / +1={1,3} 2번째 큰=1 / +5={1,3,5} 2번째 큰=3 / +4 top2={5,4} →4 / +2 top2={5,4} →4.

  - `3 1 / 7 2 9` → `7 7 9`
    - 검산: K=1은 지금까지 최댓값. 7 / max(7,2)=7 / max(7,9)=9.

- **셀프체크**: 크기 K 최소 힙에서 새 값이 루트보다 클 때만 pop 후 push 했는가? K째 큰 값이 그때의 힙 루트(`h[0]`)인가? K개 미만일 때 -1을 냈는가?

```runner
@@SOLUTION
import sys
import heapq
data = sys.stdin.read().split()
idx = 0
n = int(data[idx]); k = int(data[idx + 1]); idx += 2
nums = [int(data[idx + i]) for i in range(n)]; idx += n

h = []
out = []
for x in nums:
    if len(h) < k:
        heapq.heappush(h, x)
    elif x > h[0]:
        heapq.heapreplace(h, x)
    if len(h) < k:
        out.append("-1")
    else:
        out.append(str(h[0]))
print(' '.join(out))

- "K번째로 큰 값"은 지금까지 값 중 상위 K개만 유지하면 알 수 있다. 크기 K의 최소 힙에 상위 K개를 담으면, 그 힙의 루트(`h[0]`)가 곧 상위 K개 중 가장 작은 값 = K번째로 큰 값이다.

(2) 코드 단계별

- 힙 크기가 K 미만이면 무조건 push한다.
- 이미 K개면 새 값 x가 루트(`h[0]`, 현재 K번째 큰 값)보다 클 때만 `heapreplace`(pop 후 push)로 교체한다.
- 매 시점에 K개 미만이면 -1, 아니면 루트 `h[0]`을 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "상위 K개 유지 → 크기 K 최소 힙, 루트가 K번째 큰 값"을 핵심으로 잡는다.
- 새 값이 루트보다 클 때만 교체해야 항상 "가장 큰 K개"가 유지된다.
- 아직 K개가 안 찼으면 -1을 출력한다. `heapreplace`는 pop+push를 한 번에 처리해 효율적이다.
```

**3) 두 힙으로 중앙값 유지** · Hard

- **요구사항**: 정수가 하나씩 들어올 때마다 지금까지 수의 중앙값을 출력하라. 개수가 짝수면 가운데 두 값 중 작은 쪽(아래 중앙값)을 출력한다. 최대 힙(작은 절반)과 최소 힙(큰 절반)을 균형 있게 유지하라.

- **입력**: 첫 줄 N. 둘째 줄에 정수 N개(도착 순서).

- **출력**: 각 도착 시점의 중앙값을 공백으로 구분해 한 줄.

- **예제**:

  - `5 / 5 2 8 1 9` → `5 2 5 2 5`
    - 검산(정렬 후 아래 중앙값): [5]→5 / [2,5]→2 / [2,5,8]→5 / [1,2,5,8]→2 / [1,2,5,8,9]→5.

  - `4 / 4 4 4 4` → `4 4 4 4`  (모두 4)

- **셀프체크**: 작은 절반은 최대 힙(부호 반전), 큰 절반은 최소 힙으로 나눴는가? 매 삽입 후 두 힙 크기 차가 1 이하가 되도록 재조정했는가? 아래 중앙값이 "작은 절반 힙의 top"이 되도록 크기 규칙을 맞췄는가(작은 절반 크기 ≥ 큰 절반 크기)? 최대 힙 top을 꺼낼 때 부호를 되돌렸는가?

```runner
@@SOLUTION
import sys
import heapq
data = sys.stdin.read().split()
idx = 0
n = int(data[idx]); idx += 1
nums = [int(data[idx + i]) for i in range(n)]; idx += n

low = []   # max-heap (부호 반전 저장): 작은 절반
high = []  # min-heap: 큰 절반
out = []
for x in nums:
    if not low or x <= -low[0]:
        heapq.heappush(low, -x)
    else:
        heapq.heappush(high, x)
    if len(low) > len(high) + 1:
        heapq.heappush(high, -heapq.heappop(low))
    elif len(high) > len(low):
        heapq.heappush(low, -heapq.heappop(high))
    out.append(str(-low[0]))
print(' '.join(out))

(1) 접근·핵심 아이디어

- 수들을 "작은 절반"과 "큰 절반"으로 나눠 각각 최대 힙(작은 절반의 최댓값이 top)과 최소 힙(큰 절반의 최솟값이 top)에 담는다. 작은 절반 크기를 큰 절반 이상으로 유지하면, 아래 중앙값이 항상 작은 절반 힙의 top이 된다.

(2) 코드 단계별

- 새 값 x가 작은 절반의 최댓값 이하면 `low`(부호 반전 최대 힙)에, 아니면 `high`(최소 힙)에 넣는다.
- 재조정: `low`가 `high`보다 2 이상 크면 `low` top을 `high`로 옮기고, `high`가 `low`보다 크면 `high` top을 `low`로 옮긴다. 이러면 항상 `len(low) == len(high)` 또는 `len(low) == len(high)+1`.
- 아래 중앙값은 `-low[0]`(최대 힙 top의 부호를 되돌린 값).

(3) 스스로 다시 짤 때 생각 순서

- "중앙값 = 두 힙 분할, 작은 절반 최대 힙 / 큰 절반 최소 힙"을 핵심으로 잡는다.
- 삽입 위치는 현재 작은 절반의 top과 비교해 정한다.
- 크기 규칙(작은 절반 ≥ 큰 절반, 차이 1 이하)을 재조정으로 강제하면 아래 중앙값이 `-low[0]`으로 항상 나온다. 최대 힙은 `-x`로 저장하고 꺼낼 때 부호를 되돌린다.
```

> 개요: 그리디(탐욕법)는 매 순간 국소적으로 최선인 선택을 반복해 전역 최적해를 얻는 기법이다. 이 챕터에서는 교환 논증으로 그리디의 정당성을 증명하는 법과, "상태를 반전(뒤집기)할 수 있는" 유형에서 그리디가 어떻게 결정론적 최적 전략이 되는지를 익힌다.

## L1. Greedy Algorithm

**개념**

- 그리디(Greedy, 탐욕법)는 문제를 여러 단계로 나눈 뒤, **각 단계에서 현재 기준으로 가장 좋아 보이는 선택을 확정**하고 되돌아보지 않는(irrevocable) 전략이다.

- DP는 "모든 선택지를 상태로 저장해 비교"하지만, 그리디는 "한 가지 선택만 남기고 나머지를 버린다". 그래서 훨씬 빠르지만, **버린 선택이 정말 손해가 아님을 증명**해야 정당하다.

- 그리디가 성립하려면 보통 두 성질이 필요하다.

  - **탐욕적 선택 속성(greedy-choice property)**: 국소 최적 선택 하나가 전역 최적해의 일부가 될 수 있다.

  - **최적 부분 구조(optimal substructure)**: 그 선택을 확정한 뒤 남는 작은 문제도 같은 방식으로 최적이면 전체가 최적이다.

- 정당성 증명의 표준 도구가 **교환 논증(exchange argument)**이다. "임의의 최적해를 가져와, 그리디의 선택과 다른 부분을 그리디 선택으로 바꿔치기(swap)해도 답이 나빠지지 않음"을 보이면, 그리디 해가 최적임이 따라온다.

```python
# 그리디의 뼈대: "정렬 기준"을 정하고 순서대로 확정
def greedy(items):
    items.sort(key=...)      # 무엇을 기준으로 먼저 볼지가 핵심
    result = []
    for x in items:
        if feasible(result, x):  # 지금 x를 확정해도 규칙을 안 깨면
            result.append(x)     # 즉시 확정, 되돌아보지 않음
    return result
```

**접근 전략**

- 그리디 문제의 90%는 **"무엇을 기준으로 정렬/선택할 것인가"를 찾는 문제**다. 후보 기준(값이 작은 것부터, 끝나는 시각이 이른 것부터, 비율이 큰 것부터 등)을 몇 개 세우고, 각 기준에 대해 **반례를 직접 만들어 본다**. 반례가 안 나오는 기준을 골라 교환 논증으로 확신을 얻는다.

- 대표 패턴 3가지를 기억하자.

  - **활동 선택형(구간 스케줄링)**: "겹치지 않게 최대 개수" → **끝나는 시각이 이른 순**으로 정렬해 그리디. (일찍 끝나야 뒤 공간이 넓어진다.)

  - **비율/단가형(분할 가능 배낭)**: 쪼갤 수 있으면 **가치/무게 비율이 큰 순**. (0/1 배낭은 그리디 불가 → DP.)

  - **정렬 후 짝짓기/누적형**: 작은 것끼리 붙이면 비용이 커지는 구조(예: 파일 합치기)는 **매번 가장 작은 두 개를 합치는** 우선순위 큐 그리디.

- **복잡도**: 대개 정렬이 지배해 시간 O(N log N), 공간 O(N)(정렬·결과 저장). 우선순위 큐를 매 단계 쓰면 O(N log N)로 동일하다.

- **흔한 실수·팁**

  - "국소 최적이 전역 최적"을 **증명 없이 가정**하는 것이 가장 큰 함정이다. 반례를 찾아 최소 한 번은 검증하라.

  - 정렬 기준이 비율일 때 부동소수 오차 대신 **교차곱**(`a.v*b.w vs b.v*a.w`)으로 비교하면 안전하다.

  - 파이썬에선 매번 최솟값을 꺼내는 그리디에 `heapq`(min-heap)를, 정렬 기준이 복합적이면 `key=lambda x: (x[1], x[0])`로 튜플 정렬을 쓴다.

**문제**

**1) 회의실 하나로 최대 회의 잡기** · Easy

- **요구사항**: 시작·종료 시각이 주어진 N개의 회의 중, 시간이 겹치지 않게 회의실 하나에 배정할 수 있는 **최대 회의 수**를 구하라. (한 회의가 끝난 시각과 다른 회의가 시작하는 시각이 같으면 겹치지 않는다.)

- **입력**: 첫 줄 N (1 ≤ N ≤ 100000). 다음 N줄에 각 회의의 시작 s, 종료 e (0 ≤ s ≤ e ≤ 10^9).

- **출력**: 배정 가능한 최대 회의 수.

- **예제**: `3 / 1 4 / 3 5 / 0 6` → `1` , `5 / 1 3 / 2 4 / 3 5 / 5 7 / 6 8` → `3`

  - (검산 1: 세 회의가 3~4 구간에서 셋 다 겹친다(1-4, 3-5, 0-6). 서로 겹치지 않게는 하나만 배정 가능 → 1.)

  - (검산 2: 종료시각 순 정렬 [1-3, 2-4, 3-5, 5-7, 6-8]. 1-3 take(end=3) → 2-4 시작2<3 skip → 3-5 시작3≥3 take(end=5) → 5-7 시작5≥5 take(end=7) → 6-8 시작6<7 skip. 선택 = {1-3, 3-5, 5-7} → 3개.)

- **셀프체크**: 정렬 기준을 "시작 시각"으로 잡으면 반례가 생김을 확인하라(긴 회의가 앞을 다 막는다). "종료 시각" 기준이어야 함을 스스로 납득할 것. N이 크므로 O(N log N) 유지.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    meetings = []
    for _ in range(n):
        s = int(data[idx]); e = int(data[idx + 1]); idx += 2
        meetings.append((e, s))   # (종료, 시작)으로 담아 종료 기준 정렬
    meetings.sort()
    cnt = 0
    last_end = -1
    for e, s in meetings:
        if s >= last_end:         # 이전 회의 종료 이후 시작하면 배정 가능
            cnt += 1
            last_end = e
    print(cnt)

main()

(1) 접근·핵심 아이디어

- 겹치지 않게 최대 개수를 고르는 활동 선택 문제. **종료 시각이 이른 회의부터** 확정하는 그리디가 최적이다. 일찍 끝날수록 뒤에 남는 시간이 넓어져 더 많은 회의를 담을 수 있다(교환 논증: 최적해의 첫 회의를 '가장 일찍 끝나는 회의'로 바꿔도 개수가 줄지 않음).
- 시작=종료가 붙는 것은 겹치지 않으므로 `s >= last_end` 조건(등호 포함)을 쓴다.

(2) 코드 단계별

- N과 각 회의 (s, e)를 읽어 `(e, s)` 튜플로 저장(종료 기준 정렬용).
- 튜플 정렬 → 종료 시각 오름차순.
- last_end=-1에서 시작. 각 회의를 보며 시작 s가 last_end 이상이면 확정(cnt++), last_end를 이 회의 종료로 갱신.
- cnt 출력.

(3) 스스로 다시 짤 때 생각 순서

- "시작 시각 정렬"은 긴 회의가 앞을 막는 반례가 있음을 떠올려 배제.
- "종료 시각 정렬 + 마지막 종료 이후 시작이면 take" 골격을 세운다.
- 경계(끝=시작 허용)를 `>=`로 처리하고, N이 크므로 O(N log N) 정렬로 마무리.
```

**2) 동전 개수 최소화(정규 화폐)** · Easy

- **요구사항**: 금액 M을 만들 때 필요한 동전의 **최소 개수**를 구하라. 동전 종류는 큰 값이 항상 작은 값의 배수인 "정규 체계"(예: 1, 5, 10, 50, 100, ...)로 주어져 그리디가 성립한다.

- **입력**: 첫 줄 K(동전 종류 수)와 M. 다음 줄에 K개의 동전 액면가(오름차순, 각 값은 이전 값의 배수).

- **출력**: 최소 동전 개수.

- **예제**: `4 1260 / 1 10 100 1000` → `9` , `2 30 / 1 7` → (아래 셀프체크 참고)

  - (검산 1: 1000×1=1000, 남은 260 → 100×2=200, 남은 60 → 10×6=60, 남은 0. 총 1+2+6=9.)

- **셀프체크**: 두 번째 예제의 동전 {1,7}은 "배수 관계가 아니다". 배수 조건이 깨지면 그리디(큰 것부터)가 최적이 아닐 수 있음을 확인하라. 예: 동전 {1, 6, 10}으로 금액 12를 만들 때 그리디는 10+1+1=3개지만 최적은 6+6=2개다. 이런 **반례**를 스스로 만들어, 이 문제의 그리디는 오직 "배수 조건" 덕에만 성립함을 명심하라.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.buffer.read().split()
    k = int(data[0]); m = int(data[1])
    coins = [int(data[2 + i]) for i in range(k)]
    coins.sort(reverse=True)     # 큰 액면부터
    cnt = 0
    for c in coins:
        if m >= c:
            cnt += m // c        # 이 동전을 최대한 많이
            m %= c
    print(cnt)

main()
@@TESTS
--IN
4 1260
1 10 100 1000
--OUT
9
--IN
4 4200
1 5 50 100
--OUT
42
@@EXPL
(1) 접근·핵심 아이디어

- 동전이 "정규 체계"(큰 값이 항상 작은 값의 배수)라서, 큰 동전을 최대한 쓰는 그리디가 최적이다. 배수 조건 덕분에 큰 동전 하나를 작은 동전 여럿으로 바꾸면 개수가 반드시 늘어나므로, 큰 것부터 최대한 쓰는 게 손해가 없다(교환 논증).
- 큰 액면부터 `m // c`개씩 쓰고 나머지 `m %= c`를 다음 동전으로 넘긴다.

(2) 코드 단계별

- K, M과 K개의 액면가를 읽는다.
- 액면가를 내림차순 정렬.
- 각 동전 c에 대해 `m // c`를 cnt에 더하고 `m`을 `m % c`로 갱신.
- cnt 출력. 액면에 1이 포함되므로 항상 정확히 M을 만들 수 있다.

(3) 스스로 다시 짤 때 생각 순서

- "배수 조건 → 큰 것부터 그리디가 최적"을 먼저 확정(조건이 깨지면 DP 필요).
- 내림차순으로 훑으며 `//`로 개수, `%`로 잔액 갱신.
- 1원 동전이 있으니 마지막엔 잔액이 반드시 0이 된다.
```

**3) 로프로 버티는 최대 중량** · Medium

- **요구사항**: N개의 로프가 있고 각 로프의 최대 견딜 수 있는 중량이 주어진다. 여러 로프를 **병렬로** 사용해 물체를 들면, 물체 무게는 사용한 로프들에 균등하게 분배된다. 즉 k개의 로프를 쓰면 각 로프에 무게/k가 걸리므로, 그중 가장 약한 로프의 한계 × k 까지 들 수 있다. 들 수 있는 **최대 중량**을 구하라.

- **입력**: 첫 줄 N (1 ≤ N ≤ 100000). 다음 N줄에 각 로프의 한계 중량(자연수).

- **출력**: 최대 중량.

- **예제**: `2 / 10 / 15` → `20` , `3 / 10 / 15 / 20` → `30`

  - (검산 1: 로프 정렬 [10,15]. 15만 쓰면 15. 둘 다 쓰면 최소값 10 × 2개 = 20. max=20.)

  - (검산 2: 정렬 [10,15,20]. 20만=20, {15,20} 사용시 15×2=30, {10,15,20} 사용시 10×3=30. 최댓값 30.)

- **셀프체크**: "약한 순으로 정렬 후, k번째로 강한 로프까지 쓸 때 값 = (내림차순 정렬한 k번째 값) × k"를 훑으며 최댓값을 취한다. 왜 내림차순으로 훑을 때 앞에서부터 k개가 항상 최적 후보인지(더 강한 것만 골라야 손해가 없음) 교환 논증으로 설명해 보라. 복잡도 O(N log N).

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    ropes = [int(x) for x in data[1:1 + n]]
    ropes.sort(reverse=True)          # 강한 순 정렬
    best = 0
    for k in range(1, n + 1):
        # 가장 강한 k개를 쓰면 그중 최소는 ropes[k-1], 균등분배로 k배 견딤
        val = ropes[k - 1] * k
        if val > best:
            best = val
    print(best)

main()

@@EXPL
(1) 접근·핵심 아이디어

- k개의 로프를 병렬로 쓰면 무게가 균등 분배되어 가장 약한 로프의 한계 × k까지 든다. 어떤 k개를 고를지가 문제인데, k개를 쓸 거라면 **가장 강한 k개**를 고르는 것이 항상 최선(더 약한 걸 넣으면 최소값만 낮아짐). 교환 논증: 선택한 집합에 최강 k개가 아닌 로프가 있으면, 그것을 더 강한 미사용 로프로 바꿔도 최소값이 줄지 않으므로 답이 나빠지지 않는다.
- 따라서 내림차순 정렬 후 "앞에서 k개"만 후보로 보면 되고, 그때 최소값은 정확히 ropes[k-1]. 모든 k에 대해 ropes[k-1]*k의 최댓값이 답.

(2) 코드 단계별

- N과 로프 한계들을 읽는다.
- 내림차순 정렬.
- k=1..N을 훑으며 `ropes[k-1] * k`를 계산하고 최댓값 best 갱신.
- best 출력.

(3) 스스로 다시 짤 때 생각 순서

- "k개를 쓸 때 값은 최소 로프 × k" 공식을 먼저 세운다.
- k개를 쓸 거면 강한 것부터 고르는 게 이득임을 교환 논증으로 납득 → 내림차순 정렬.
- 정렬 후 각 prefix의 마지막 원소(=그 prefix의 최소)에 개수를 곱해 최댓값을 취하면 O(N log N).
```

## L2. 상태 반전이 가능한 문제

**개념**

- 어떤 문제는 각 원소가 두 상태(예: 켜짐/꺼짐, +/−, 앞면/뒷면) 중 하나이고, **한 번의 조작이 특정 원소(들)의 상태를 반전(toggle)**시킨다. 목표는 최소 조작 횟수로 원하는 상태를 만드는 것이다.

- 이런 유형의 핵심 통찰은 두 가지다.

  - **반전은 짝수 번이면 원상복귀**: 같은 위치를 두 번 뒤집으면 안 한 것과 같다. 따라서 각 조작을 "할지/말지(0 또는 1번)"만 결정하면 되고, 순서는 결과에 영향이 없다(반전끼리 교환 가능, XOR 성질).

  - **앞에서부터 강제 확정(그리디)**: 왼쪽 끝 원소의 상태를 바꾸는 방법이 **유일**하다면, 그 원소를 올바르게 만들 조작은 지금 할지 말지가 강제로 정해진다. 이렇게 왼→오로 훑으며 "지금 위치가 틀렸으면 그 위치를 고치는 유일한 조작을 반드시 수행"하면, 남은 자유도가 사라져 답이 결정된다.

- 즉 이 유형은 "겉보기엔 완전탐색(2^N)"이지만, **왼쪽부터의 강제성** 덕분에 O(N) 그리디로 풀리는 경우가 많다. 조작이 "연속한 구간을 통째로 뒤집는다" 같은 형태면 **누적 XOR / imos(차이 배열)** 로 각 위치의 실제 상태를 O(1)에 추적한다.

```python
# 예: i를 누르면 i, i+1, i+2 세 칸이 뒤집히는 스위치.
# 왼쪽부터: 지금 칸이 목표와 다르면 여기서 반드시 눌러야 한다(유일한 기회).
def solve(a, target):
    flip = 0                    # 지금까지 열린 반전들의 누적 XOR(현재 칸 반전 여부)
    diff = [0]*(len(a)+1)       # imos: 반전 효과가 끝나는 지점 표시
    cnt = 0
    for i in range(len(a)):
        flip ^= diff[i]                     # i에 도달한 시점의 누적 반전 상태
        cur = a[i] ^ flip                   # 현재 칸의 실제 값
        if cur != target[i]:                # 틀렸으면 여기서 눌러야만 고침
            cnt += 1
            flip ^= 1                        # 지금부터 반전 시작
            diff[min(i+WIDTH, len(a))] ^= 1  # WIDTH칸 뒤에서 효과 종료
    # 마지막에 오른쪽 끝이 목표와 맞는지 검증(못 맞추면 불가능)
    return cnt
```

**접근 전략**

- **1단계: 상태를 이진화(XOR)로 모델링**한다. "뒤집기"는 XOR 1과 같으므로, 최종 상태 = 초기 상태 XOR (그 칸을 덮은 조작 수의 홀짝). 순서 무관·짝수 상쇄 성질을 먼저 확인하라.

- **2단계: 강제성 찾기**. "가장 왼쪽(또는 가장 바깥) 원소를 바꿀 수 있는 조작이 유일한가?"를 묻는다. 유일하면 그 원소의 정답 조작이 강제로 정해지고, 이를 반복하며 전체가 결정된다.

- **3단계: 구간 반전이면 imos**. 조작이 "i부터 i+w-1까지 반전"이면, 각 칸의 현재 반전 여부를 매번 다시 세지 말고 `diff[]`(차이 배열)에 시작/끝을 기록해 누적 XOR로 O(1) 갱신한다. 이것이 없으면 O(N·w)로 느려진다.

  - 이 `diff`/누적 XOR는 ch02 L4 imos의 XOR 버전이다. ch02 imos는 "구간에 `+v`, 끝+1에 `-v`" 후 **덧셈 누적합**으로 겹친 횟수를 복원했다. 여기서는 반전이 **XOR(mod 2 덧셈)**이라, `+1/-1` 대신 시작·끝 지점에 `^1`을 찍고 **누적 XOR**로 각 칸의 반전 홀짝을 복원한다. 즉 imos의 덧셈 군(group)을 XOR 군으로 바꾼 것뿐이라 구조가 동일하다.

- **여러 시작 상태가 필요한 경우(예: 원형·양끝 자유)**: 맨 앞 조작의 on/off 등 **작은 자유도만 완전탐색**(보통 2가지)하고, 나머지는 위 그리디로 확정한 뒤 최솟값을 취한다. (전형: "전구 스위치" 문제에서 첫 스위치 누름 여부 2가지 시도.)

- **복잡도**: 강제 그리디 + imos로 **시간 O(N)**, 공간 O(N). 앞 원소 자유도를 c가지 시도하면 O(c·N)이지만 c는 상수(보통 2).

- **흔한 실수·팁**

  - **끝부분 검증 누락**: 왼쪽부터 다 맞췄어도 오른쪽 끝 몇 칸은 더 이상 건드릴 조작이 없어 목표와 다를 수 있다. 마지막에 반드시 "전부 목표와 일치하는지" 확인하고, 아니면 **불가능(-1)** 처리.

  - `flip`을 매 칸 새로 계산하려 하지 말고 **누적 XOR 변수 하나로 흘려보내는** 것이 imos의 핵심이다.

  - 파이썬에선 상태를 `0/1` 정수 리스트로 두고 XOR(`^`)을 쓰면 조건 분기가 깔끔하다. 문자열 `"01..."`은 인덱싱만 하고 비교는 정수로.

**문제**

**1) 스위치 뒤집기(3칸 반전)** · Medium

- **요구사항**: N개의 전구가 일렬로 있고 각 전구는 0(꺼짐) 또는 1(켜짐)이다. 위치 i를 누르면 i, i+1, i+2 세 칸(존재하는 칸만)의 상태가 반전된다. **모든 전구를 0으로** 만들 때 필요한 최소 누름 횟수를 구하라. 불가능하면 -1.

- **입력**: 첫 줄 N (1 ≤ N ≤ 200000). 다음 줄에 0/1로 이루어진 길이 N의 초기 상태.

- **출력**: 최소 누름 횟수 또는 -1.

- **예제**: `5 / 11100` → `1` , `4 / 1000` → `-1`

  - (검산 1: 위치 0을 한 번 누르면 칸0,1,2 반전 → 11100 → 00000. 1회.)

  - (검산 2: 1000. i=0이 유일하게 칸0을 바꿈 → 눌러야 함(cnt1) → 0111(칸0,1,2 반전). i=1은 칸1이 1이라 눌러야 함(cnt2) → 0011→칸1,2,3 반전 후 0 0 0 0? 재검: 0111에서 i=1 누르면 칸1,2,3 반전 → 0 0 0 1. i=2: 칸2가 0이라 안 누름. i=3,4 없음(N=4). 마지막 칸3=1 → 목표 0 아님 → 불가능 -1.)

- **셀프체크**: "왼쪽 칸을 바꾸는 조작이 유일하다"는 강제성을 확인하라. N=200000이므로 매 칸 3개를 직접 뒤집으면 O(3N)=OK지만, 습관적으로 imos/누적XOR로 O(N) 구현해 보라. 마지막 2칸 검증을 빠뜨리면 오답.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split("\n")
    n = int(data[0].strip())
    s = data[1].strip()
    a = [ord(c) - 48 for c in s]
    W = 3
    diff = [0] * (n + 1)   # imos: 반전 효과 종료 지점에 ^1
    flip = 0               # 현재 칸까지의 누적 반전 홀짝
    cnt = 0
    for i in range(n):
        flip ^= diff[i]
        cur = a[i] ^ flip
        if cur != 0:                 # 지금 칸이 1이면 여기서 눌러야만 0으로
            if i + W > n:            # i, i+1, i+2가 범위 밖이면 누를 수 없음
                print(-1)
                return
            cnt += 1
            flip ^= 1
            diff[i + W] ^= 1         # W칸 뒤에서 이 반전 효과 종료
    print(cnt)

main()

@@EXPL
(1) 접근·핵심 아이디어

- 위치 i를 누르면 i, i+1, i+2가 반전된다. 왼쪽 끝 칸 i를 바꿀 수 있는 조작은 오직 "i 누르기"(i-1, i-2는 이미 왼쪽으로 지나감). 그래서 왼→오로 훑으며 현재 칸이 1이면 여기서 반드시 눌러야 하는 강제 그리디.
- 매 칸 3개를 직접 뒤집으면 O(3N)이라 통과하지만, imos(차이 배열)의 XOR 버전을 쓰면 각 칸의 실제 반전 홀짝을 O(1)에 복원해 O(N)이 된다. `diff[i+W] ^= 1`로 "여기서 시작한 반전은 W칸 뒤에 끝난다"를 기록한다.

(2) 코드 단계별

- 상태 문자열을 0/1 리스트로 변환. `diff` 배열과 누적 `flip`을 준비.
- i 순회: `flip ^= diff[i]`로 i 지점의 누적 반전을 갱신, `cur = a[i]^flip`이 실제 값.
- `cur != 0`이면 눌러야 한다. 그런데 i+3이 범위를 넘으면(i+W>n) 이 칸을 덮는 조작이 없으므로 -1.
- 누를 수 있으면 cnt++, `flip ^= 1`, `diff[i+W] ^= 1`로 효과 종료를 예약.
- 끝까지 통과하면 cnt가 답. 오른쪽 끝 칸들은 i+W>n 검사에서 자동으로 -1로 걸러진다.

(3) 스스로 다시 짤 때 생각 순서

- "왼쪽 칸을 고치는 유일한 조작은?" → 강제성 확인.
- 구간 반전이므로 매번 3칸 세지 말고 imos의 XOR 버전(diff + 누적 XOR)으로 상태를 흘려보낸다.
- 마지막 몇 칸은 더 누를 수 없어 목표와 다를 수 있으니, i+W>n일 때 반드시 불가능 처리.
```

**2) A를 B로: 접미사 뒤집기** · Medium

- **요구사항**: 0/1 문자열 A를 B로 바꾸려 한다. 한 번의 조작은 "임의의 위치 i부터 **끝까지**(접미사 전체)를 모두 반전"이다. A를 B로 만드는 **최소 조작 횟수**를 구하라. (항상 가능하다.)

- **입력**: 두 줄에 각각 같은 길이의 문자열 A, B (길이 ≤ 200000).

- **출력**: 최소 조작 횟수.

- **예제**: `0000 / 1111` → `1` , `0101 / 0011` → `2`

  - (검산 1: 접미사 전체(i=0)를 한 번 반전하면 0000→1111. 1회.)

  - (검산 2: A=0101, B=0011. 왼→오로 "지금까지의 반전 홀짝"을 flip이라 하자. 위치0: A0^flip(0)=0=B0 → 유지. 위치1: 1^0=1 ≠ B1=0 → 여기서 접미사 반전(cnt1), flip=1. 위치2: A2=0, 0^1=1 ≠ B2=1? B2=1이므로 1=1 → 유지. 위치3: A3=1, 1^1=0 = B3=1? B3=1인데 0≠1 → 반전(cnt2), flip=0. 총 2회.)

- **셀프체크**: "접미사 반전"은 **경계에서만 상태가 바뀐다**는 성질(연속 구간의 '변화 지점' 개수 = 조작 수)로도 셀 수 있다. 두 방법(왼→오 그리디 vs 인접 XOR 패턴 변화 세기)이 같은 답을 주는지 확인하라. 복잡도 O(N).

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split("\n")
    a = data[0].strip()
    b = data[1].strip()
    n = len(a)
    flip = 0   # 지금까지의 접미사 반전 누적 홀짝
    cnt = 0
    for i in range(n):
        cur = (ord(a[i]) - 48) ^ flip     # i에 실제로 적용된 A[i] 값
        if cur != (ord(b[i]) - 48):       # B[i]와 다르면 여기서 접미사 반전
            cnt += 1
            flip ^= 1
    print(cnt)

main()

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 조작이 "위치 i부터 끝까지 전부 반전"이므로, i에서 한 번 누르면 i 이후 모든 칸의 반전 홀짝이 바뀐다. 왼쪽 칸 A[i]를 바꿀 유일한 방법은 정확히 위치 i에서 누르는 것뿐(그보다 왼쪽에서 누르면 이미 맞춰둔 앞칸이 다시 바뀜).
- 그래서 왼→오로 진행하며 "지금까지 나를 덮은 접미사 반전이 몇 번인가(flip 홀짝)"만 들고 다니면, 현재 칸의 실제 값 = A[i] XOR flip. 이게 B[i]와 다르면 반드시 여기서 눌러 flip을 토글한다.

(2) 코드 단계별

- 두 줄 A, B를 읽고 길이 n을 구한다.
- flip=0으로 시작. i=0..n-1: `cur = A[i] ^ flip`을 계산(문자 '0'/'1'을 `ord-48`로 정수화).
- `cur != B[i]`이면 cnt를 늘리고 `flip ^= 1`(이 지점부터 접미사가 반전 상태로 바뀜).
- 끝까지 돌면 cnt가 최소 조작 수. 접미사 반전은 항상 가능하므로 불가능 케이스는 없다.

(3) 스스로 다시 짤 때 생각 순서

- "왼쪽 칸을 바꾸는 유일한 조작은 그 자리에서 누르는 것"이라는 강제성을 먼저 확인.
- 접미사 반전은 순서 무관·짝수 상쇄이므로 누적 홀짝(flip) 하나로 상태를 흘려보낸다.
- A[i]^flip을 B[i]와 비교, 다르면 누르고 flip 토글. 이는 곧 A^B 패턴의 '인접 변화 지점 개수'와 같다.
```

**3) 동전 뒤집기 최소화(H/T 정렬)** · Hard

- **요구사항**: N개의 동전이 일렬로 있고 각 칸은 H(앞) 또는 T(뒤)이다. 한 번의 조작은 위치 i를 골라 **i번째와 i+1번째, 두 칸을 동시에 반전**(H↔T)한다. 모든 동전을 **전부 H**로 만들 때 최소 조작 횟수를 구하라. 불가능하면 -1.

- **입력**: 첫 줄 N (1 ≤ N ≤ 200000). 다음 줄에 H/T로 이루어진 길이 N의 문자열.

- **출력**: 최소 조작 횟수 또는 -1.

- **예제**: `2 / TT` → `1` , `4 / THTH` → `-1`

  - (검산 1: TT. i=0을 누르면 칸0,1 반전 → HH. 1회.)

  - (검산 2: THTH를 왼→오. 칸0=T ≠ H → i=0 눌러 칸0,1 반전 → HHTH(칸0 T→H, 칸1 H→T… 여기서 칸1 H→T). 정리하면 H H T H. 칸1=H OK. 칸2=T ≠ H → i=2 눌러 칸2,3 반전 → H H H T(칸2 T→H, 칸3 H→T). 칸3=T ≠ H이고 더 쓸 조작(i=3은 칸3,4를 반전하는데 칸4가 없음)이 없음 → 불가능 -1.)

- **셀프체크**: 위 조작은 **인접 두 칸 동시 반전**이므로 "T의 개수 홀짝" 같은 불변량(invariant)이 생긴다. 각 조작이 T 개수를 어떻게 바꾸는지(0 또는 ±2) 따져 **패리티로 불가능을 미리 판정**할 수 있는지 탐구하라. 왼→오 강제 그리디로 조작 수를 세고, 마지막 칸 검증으로 -1을 걸러라. 복잡도 O(N).

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split("\n")
    n = int(data[0].strip())
    s = data[1].strip()
    a = [1 if c == 'T' else 0 for c in s]  # T=1(뒤집어야 함), H=0
    cnt = 0
    for i in range(n):
        if a[i] == 1:                 # 지금 칸이 T면 여기서 반드시 눌러야 함
            if i + 1 >= n:            # 마지막 칸이 T면 짝이 없어 고칠 수 없음
                print(-1)
                return
            cnt += 1
            a[i] ^= 1
            a[i + 1] ^= 1             # i, i+1 두 칸 동시 반전
    print(cnt)

main()

@@EXPL
(1) 접근·핵심 아이디어

- 목표는 전부 H. 각 칸을 T=1(반전 필요), H=0으로 본다. 한 조작은 인접한 i, i+1 두 칸을 동시에 뒤집는다.
- 가장 왼쪽 칸 i의 상태를 바꿀 수 있는 조작은 "i를 누르는 것" 딱 하나뿐이다(i-1을 누르면 이미 확정된 왼쪽을 다시 건드림). 따라서 왼→오로 훑으며 현재 칸이 T면 **여기서 반드시** 눌러야 한다 — 선택의 여지가 없는 강제 그리디.

(2) 코드 단계별

- 문자열을 0/1 리스트로 변환(T→1, H→0).
- i=0..n-1 순회: `a[i]==1`이면 눌러야 하는데, 마지막 칸(i+1이 범위 밖)이면 고칠 방법이 없으므로 -1 출력 후 종료.
- 누를 수 있으면 cnt 증가, `a[i]`와 `a[i+1]`을 XOR로 뒤집는다.
- 끝까지 무사히 통과하면 cnt가 답. 왼쪽부터 다 0으로 확정되므로 별도 최종 검증은 마지막 칸의 짝 없음 체크로 이미 처리된다.

(3) 스스로 다시 짤 때 생각 순서

- "왼쪽 칸을 바꾸는 유일한 조작은?"을 먼저 물어 강제성을 확보한다.
- T=1로 이진화하고 왼→오 그리디로 필요한 곳에서만 누른다.
- 마지막 칸이 아직 T인데 짝이 없으면 불가능(-1). 인접 반전은 T 개수를 0 또는 ±2로만 바꾸므로 홀짝 불변량으로도 -1을 예측할 수 있다.
```

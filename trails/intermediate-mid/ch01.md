> 개요: 이 챕터에서는 해시 기반(HashMap·HashSet)과 정렬 기반(TreeMap·TreeSet) 컨테이너의 차이·용법을 실전 관점에서 익히고, 우선순위 큐(heapq)와 이중 연결 리스트를 직접 다뤄 "무엇을 언제 쓰는가"를 판단하는 감각을 기른다.

## L1. HashMap

**개념**

- HashMap은 "키 → 값" 대응을 평균 O(1)에 저장·조회·삭제하는 자료구조다. 파이썬에서는 내장 `dict`가 곧 HashMap이며, 키를 해시 함수로 버킷에 흩뿌려 저장하기 때문에 삽입 순서와 무관하게 상수 시간 접근이 가능하다(단, 키는 해시 가능한 불변 객체여야 한다).

- 언제 쓰나: 빈도수 세기, 값→인덱스 역참조, 그룹핑, 캐싱/메모이제이션, "이미 본 적 있는가" 판정 등. 정렬이 필요 없고 "빠른 룩업"만 필요하면 1순위 선택이다.

- 동작 단계: (1) 키를 해시값으로 변환 → (2) 해시값으로 버킷 위치 결정 → (3) 충돌 시 같은 버킷 안에서 키를 비교. 파이썬 dict는 삽입 순서를 보존(3.7+)하지만 이는 "정렬"이 아니라 "삽입 순서"임에 유의.

```python
from collections import defaultdict, Counter

# 1) 빈도수 세기
cnt = Counter(arr)              # {값: 등장횟수}

# 2) 그룹핑 (기본값 자동 생성)
groups = defaultdict(list)
for name, score in data:
    groups[name].append(score)

# 3) 안전한 조회
v = d.get(key, 0)              # 없으면 기본값 0
if key in d: ...              # 존재 여부는 in
```

**그림으로 보기**

- dict는 "키를 해시값으로 바꾸고, 그 값으로 들어갈 칸(버킷)을 계산해 저장하는" 표다. 위치가 계산으로 정해지므로, 찾을 때도 앞에서부터 훑지 않고 곧장 그 칸으로 간다.

```text
  d = {}                          # table size = 8
  hash("ab") % 8 = 3
  hash("cd") % 8 = 6
  hash("ef") % 8 = 3              # slot 3 is taken -> collision

  slot     0    1    2    3    4    5    6    7
         ┌────┬────┬────┬────┬────┬────┬────┬────┐
  key    │ .  │ .  │ .  │ ab │ ef │ .  │ cd │ .  │
  value  │ .  │ .  │ .  │ 10 │ 20 │ .  │ 30 │ .  │
         └────┴────┴────┴────┴────┴────┴────┴────┘
                          ▲    ▲
                          │    └── ef : slot 3 busy -> next free slot
                          └─────── ab : slot 3 empty -> stored here
```

- 조회는 값이 몇 개든 항상 같은 세 단계다. **단계 수가 n과 무관하다**는 것이 O(1)의 정체다.

```text
  d["cd"]  ->  1) h = hash("cd")         # key    -> number
               2) i = h % 8 = 6          # number -> slot
               3) key at slot 6 == "cd"  # confirm, then return 30
```

**왜 이렇게 되는가**

- **왜 평균 O(1)인가**: 조회 비용은 "빈 칸이 나올 때까지 몇 칸을 더 보느냐"이고, 이는 표가 얼마나 꽉 찼는지(적재율 = 원소 수 / 칸 수)에만 달렸다. 파이썬 dict는 적재율이 약 2/3를 넘으면 표를 2배로 키우고 전부 재배치한다. 덕분에 적재율이 항상 상수 이하로 유지되고, 기대 탐색 칸 수도 n과 무관한 상수가 된다. 표를 키우는 O(n) 비용은 그전까지의 n번 삽입에 나눠 분담되므로(분할상환) 삽입도 평균 O(1)이다.

- **왜 최악은 O(n)인가**: 모든 키의 해시가 한 칸으로 몰리면 한 줄로 늘어서서 결국 선형 탐색이 된다. 일부러 충돌을 유도한 입력이 아니면 코딩테스트에서 만나기 어렵고, 그래서 "평균 O(1)"을 실전 기준으로 쓴다.

- **왜 리스트는 키가 될 수 없는가**: 저장 위치가 `hash(key)`로 정해지는데 리스트는 내용이 바뀌면 해시도 바뀐다. 넣을 때의 칸과 찾을 때의 칸이 달라져 "분명 넣었는데 없다"가 된다. 그래서 파이썬은 가변 객체의 해시를 아예 금지한다(튜플은 되고, 리스트는 TypeError).

**접근 전략**

- "무언가를 세거나, 매핑하거나, 중복/존재 여부를 O(1)에 물어봐야 한다"면 dict를 떠올린다. 값을 누적할 땐 `defaultdict(int/list/set)`, 단순 카운팅은 `Counter`가 코드를 크게 줄여준다. 키가 (좌표) 같은 튜플이어도 되지만 리스트는 키가 될 수 없다(가변이라 해시 불가).

- 시간복잡도: 조회/삽입/삭제 평균 O(1), 최악 O(n)(해시 충돌 극단). 공간복잡도 O(n). 흔한 실수: `d[key] += 1`을 존재하지 않는 키에 하면 KeyError → `defaultdict(int)`나 `d.get(key,0)+1` 사용. 정렬된 순서로 순회하려면 dict가 아니라 정렬(또는 TreeMap 대체)이 필요. 반복 중 dict 크기를 바꾸면 RuntimeError이니 `list(d.items())`로 복사 후 순회.

**문제**

**1) 두 수의 합 인덱스** · Easy

- **요구사항**: 정수 배열과 목표값 T가 주어질 때, 더해서 T가 되는 서로 다른 두 원소의 인덱스(1-based)를 오름차순으로 출력한다. 답은 유일하다고 가정한다. 배열을 한 번만 순회하며 dict를 쓸 것.

- **입력**: 첫 줄에 N과 T. 둘째 줄에 N개의 정수.

- **출력**: 두 인덱스를 공백으로.

- **예제**: `4 9 / 2 7 11 15` → `1 2` , `5 6 / 3 2 4 8 1 5` → `2 5`

- **셀프체크**: 각 원소 x를 볼 때 "T-x를 이전에 본 적 있는가"를 dict(값→인덱스)로 물으면 O(N). 같은 원소를 두 번 쓰지 않도록 "현재 원소를 넣기 전에 조회"하는 순서가 함정.

```runner
@@SOLUTION
import sys
def main():
    data=sys.stdin.read().split()
    idx=0
    n=int(data[idx]); idx+=1
    t=int(data[idx]); idx+=1
    arr=[int(data[idx+i]) for i in range(n)]
    seen={}
    for i,x in enumerate(arr):
        need=t-x
        if need in seen:
            print(seen[need]+1, i+1)
            return
        seen[x]=i
main()
@@TESTS
--IN
4 9
2 7 11 15
--OUT
1 2
--IN
4 8
1 3 5 10
--OUT
2 3
@@EXPL
(1) 접근·핵심 아이디어

- 각 원소 x에 대해 짝은 `T-x`로 고정된다. "지금까지 본 값 중에 `T-x`가 있었나?"를 O(1)에 물으려면 값→인덱스 dict가 필요하다. 전체를 한 번만 훑으면 O(N)이다.

(2) 코드 단계별

- 입력을 통째로 읽어 N, T, 배열을 파싱한다.
- 배열을 왼쪽부터 훑으며, 현재 x에 대해 `need = T - x`를 먼저 `seen`에서 조회한다. 있으면 (저장된 인덱스, 현재 인덱스)를 1-based로 출력하고 종료.
- 없으면 현재 x를 `seen[x] = i`로 등록한다. "조회 → 등록" 순서를 지켜야 같은 원소를 두 번 쓰지 않는다.

(3) 스스로 다시 짤 때 생각 순서

- 브루트포스 이중 루프(O(N^2))를 먼저 떠올린 뒤, "짝은 결정적이다"를 인식해 해시로 한 축을 O(1)로 줄인다.
- 인덱스 순서(작은 쪽 먼저)는 왼쪽에서 오른쪽으로 훑는 특성상 저장된 인덱스가 항상 더 작으므로 자연히 오름차순이 된다.
- 함정 체크: 등록보다 조회를 먼저 할 것, 출력은 1-based일 것.
```

**2) 애너그램 그룹 수** · Medium

- **요구사항**: 문자열 목록에서 서로 애너그램인 것끼리 묶었을 때 그룹의 개수를 출력한다.

- **입력**: 첫 줄 N, 이후 N줄에 소문자 문자열.

- **출력**: 그룹 개수.

- **예제**: `3 / eat tea ate` → `1` , `4 / abc bca xy z` → `3`

- **셀프체크**: 각 문자열을 정렬한 문자열(또는 26자 카운트 튜플)을 키로 쓰면 애너그램은 같은 키가 된다. `len(set(정규화키들))`이 답. 정렬 키는 O(L log L), 카운트 튜플 키는 O(L). 빈 그룹/중복 입력 경계 확인.

```runner
@@SOLUTION
import sys
def main():
    data=sys.stdin.read().split()
    n=int(data[0])
    words=data[1:1+n]
    keys=set()
    for w in words:
        keys.add("".join(sorted(w)))
    print(len(keys))
main()
@@TESTS
--IN
3
eat tea ate
--OUT
1
--IN
4
abc bca xy z
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 애너그램의 정의는 "문자 구성이 같다"이다. 각 문자열을 문자 정렬해 정규화하면 애너그램끼리는 완전히 같은 키가 된다. 서로 다른 키의 개수가 곧 그룹 수이므로 `set`에 정규화 키를 모아 크기를 센다.

(2) 코드 단계별

- N을 읽고 이어지는 N개의 단어를 얻는다(공백 분리라 한 줄에 몰려 있어도 동작).
- 각 단어 w에 대해 `"".join(sorted(w))`로 문자를 사전순 정렬한 문자열을 만든다. 이것이 정규화 키.
- 모든 키를 `set`에 넣고 마지막에 `len(set)`을 출력한다. 같은 애너그램은 같은 키라 자동으로 하나로 합쳐진다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇이 같으면 같은 그룹인가?"를 먼저 정의한다 → 정렬 키(또는 26칸 카운트 튜플).
- 그룹 "개수"만 필요하므로 그룹 내용을 저장할 필요 없이 서로 다른 키의 수만 세면 된다 → set.
- 성능이 중요하면 정렬(O(L log L)) 대신 길이 26 카운트 튜플(O(L))을 키로 써도 된다.
```

**3) 최다 빈도 상위 K개** · Medium

- **요구사항**: 정수 배열에서 등장 빈도가 높은 순으로 상위 K개 값을 출력한다. 빈도가 같으면 값이 작은 것을 먼저.

- **입력**: 첫 줄 N K, 둘째 줄 N개 정수.

- **출력**: 상위 K개 값을 공백으로.

- **예제**: `6 2 / 1 1 1 2 2 3` → `1 2` , `5 1 / 4 4 5 5 6` → `4`

- **셀프체크**: Counter로 빈도를 센 뒤 `(-빈도, 값)` 기준 정렬해 앞 K개. 정렬 O(M log M)(M=서로 다른 값 수). 동점 처리 규칙(값 오름차순)을 정렬 키에 반영했는지, K가 M보다 큰 경우도 체크.

```runner
@@SOLUTION
import sys
from collections import Counter
def main():
    data=sys.stdin.read().split()
    n=int(data[0]); k=int(data[1])
    arr=[int(data[2+i]) for i in range(n)]
    cnt=Counter(arr)
    items=sorted(cnt.items(), key=lambda p:(-p[1], p[0]))
    res=[str(v) for v,_ in items[:k]]
    print(" ".join(res))
main()
@@TESTS
--IN
6 2
1 1 1 2 2 3
--OUT
1 2
--IN
5 1
4 4 5 5 6
--OUT
4
@@EXPL
(1) 접근·핵심 아이디어

- 빈도수 문제이므로 `Counter`로 값→등장횟수를 O(N)에 만든다. 그다음 "빈도 내림차순, 동점이면 값 오름차순"이라는 정렬 규칙을 그대로 정렬 키로 표현하고 앞 K개를 취한다.

(2) 코드 단계별

- N, K와 배열을 읽는다.
- `Counter(arr)`로 각 값의 빈도를 센다.
- `sorted(..., key=lambda p:(-p[1], p[0]))`로 정렬한다. 첫 키 `-p[1]`은 빈도 큰 순, 둘째 키 `p[0]`은 값 작은 순(동점 타이브레이커).
- 정렬된 항목에서 앞 K개의 값만 문자열로 뽑아 공백으로 출력한다. K가 서로 다른 값 수 M보다 커도 슬라이스가 알아서 잘라 준다.

(3) 스스로 다시 짤 때 생각 순서

- "세고 → 정렬 규칙을 언어로 적고 → 그 규칙을 튜플 키로 옮긴다"가 골격이다.
- 내림차순은 값에 마이너스를 붙여 오름차순 정렬로 바꾸는 관용구를 기억한다.
- 부분만 필요하면 전체 정렬 대신 `heapq.nlargest`도 가능하지만, 동점 규칙을 키에 담기엔 sorted가 가장 직관적이다.
```


## L2. TreeMap

**개념**

- TreeMap은 "키가 항상 정렬된 상태로 유지되는 맵"이다. 내부적으로 균형 이진탐색트리 구조라서 삽입·삭제·조회가 O(log n)이고, "K 이상인 가장 작은 키(lower_bound)", "범위 순회", "최소/최대 키" 같은 정렬 질의를 지원한다.

- 파이썬에는 내장 TreeMap이 없다. 실전에서는 상황에 따라 세 가지로 대체한다: (1) 삽입이 끝난 뒤 조회만 한다면 정렬 리스트 + `bisect`, (2) 삽입/삭제가 섞이면 `sortedcontainers.SortedDict`(외부 라이브러리, 코딩테스트에서 종종 허용), (3) 값의 개수 관리만 필요하면 정렬 키 + heap/BIT 등 우회.

- 핵심 연산은 "정렬된 키 배열에서의 이분 위치 찾기"다. `bisect_left(a, x)`는 x를 넣을 왼쪽 위치 = "x 미만 원소 개수", `bisect_right(a, x)`는 "x 이하 원소 개수"를 준다. 이 둘로 "x 이상 첫 원소", "x 이하 마지막 원소", "[lo, hi] 구간 개수"를 모두 계산한다.

```python
import bisect

a = []                          # 정렬 상태 유지
bisect.insort(a, x)            # 정렬 위치에 삽입 O(n)
i = bisect.bisect_left(a, x)  # x 이상 첫 원소 위치
j = bisect.bisect_right(a, x) # x 초과 첫 원소 위치
# [L,R] 구간 원소 수 = bisect_right(a,R) - bisect_left(a,L)
```

**그림으로 보기**

- 정렬 리스트 + `bisect`는 TreeMap을 흉내 내는 가장 가벼운 방법이다. 들어갈 자리는 이분탐색으로 O(log n)에 찾지만, 실제로 끼워 넣으려면 뒤쪽 원소를 전부 한 칸씩 밀어야 한다.

```text
  a = [1, 4, 6, 9, 12]        insort(a, 7)

  1) find the slot : bisect_left(a, 7) = 3          # O(log n)
        idx    0    1    2    3    4
            ┌────┬────┬────┬────┬────┐
            │  1 │  4 │  6 │  9 │ 12 │
            └────┴────┴────┴────┴────┘
                              ^ 7 goes here

  2) shift the tail : 9 and 12 each move one cell   # O(n)
        idx    0    1    2    3    4    5
            ┌────┬────┬────┬────┬────┬────┐
            │  1 │  4 │  6 │  7 │  9 │ 12 │
            └────┴────┴────┴────┴────┴────┘
                              ^ new
```

- 중복이 있을 때 `bisect_left`와 `bisect_right`가 각각 어느 경계에 서는지 한 장으로 굳혀 둔다.

```text
  a = [1, 2, 2, 2, 5]
        idx    0    1    2    3    4
            ┌────┬────┬────┬────┬────┐
            │  1 │  2 │  2 │  2 │  5 │
            └────┴────┴────┴────┴────┘
                    ^              ^
                    │              └── bisect_right(a, 2) = 4
                    └───────────────── bisect_left (a, 2) = 1

  count(2) = 4 - 1 = 3
  ge = a[bisect_left (a, x)]      # x 이상인 첫 값
  gt = a[bisect_right(a, x)]      # x 초과인 첫 값
```

**왜 이렇게 되는가**

- **`bisect`는 왜 O(log n)인가**: 후보 구간을 매번 정확히 절반으로 자른다. `n → n/2 → n/4 → … → 1`이 되기까지 자른 횟수 k는 `n / 2^k = 1`, 즉 `k = log2 n`이다. n이 백만이어도 20번이면 끝난다.

- **그런데 삽입은 왜 O(n)인가**: 파이썬 리스트는 원소가 메모리에 연속으로 붙어 있는 배열이다. 중간에 자리를 만들려면 그 뒤의 원소를 **전부** 한 칸씩 뒤로 옮겨야 한다. "위치를 아는 것(O(log n))"과 "자리를 만드는 것(O(n))"은 별개의 비용이고, 둘을 더하면 큰 쪽인 O(n)이 지배한다. 그래서 `insort`를 N번 하면 전체가 O(N²)이 된다.

- **그럼 언제 써도 되는가**: (1) 삽입이 다 끝난 뒤 조회만 한다면 정렬 한 번 O(N log N) + 쿼리당 O(log N)로 최적이다. (2) 삽입 총량이 수천 수준이면 O(N²)이라도 충분히 빠르다. (3) 삽입·삭제가 수십만 번 섞이면 정렬 리스트로는 안 되고, `SortedList`(원소를 작은 블록으로 쪼개 이동 비용을 √n 수준으로 낮춘다)나 좌표압축+BIT로 간다.

**접근 전략**

- "정렬 순서로 최소/최대를 계속 꺼내거나, 특정 값에 가장 가까운 키를 찾거나, 값 범위 개수를 물어봐야 한다"면 TreeMap 계열을 떠올린다. 삽입/삭제가 없고 쿼리만이면 미리 정렬 후 bisect로 충분. 삽입·삭제가 뒤섞이면 `SortedList/SortedDict`를 쓰거나(insort는 O(n)이라 대량이면 느림) 좌표압축+세그먼트/BIT로 우회한다.

- 시간복잡도: BST 기반이면 각 연산 O(log n). 정렬 리스트+`insort`는 삽입이 O(n)(이동 비용)이라 N이 크면 병목 → 주의. 공간 O(n). 흔한 실수: bisect_left와 bisect_right 혼동(경계 포함 여부가 뒤집힘), 중복 키 처리. 파이썬 팁: 삽입 없이 "여러 쿼리를 오프라인"으로 처리 가능하면 정렬+bisect가 가장 단순하고 빠르다.

- 중복이 있을 때 둘의 차이가 극명하다. 정렬배열 `a = [1, 2, 2, 2, 5]`(인덱스 0~4)에서:

| x | `bisect_left` | `bisect_right` | 의미 |
| --- | --- | --- | --- |
| 2 | 1 | 4 | 왼쪽=첫 2 위치, 오른쪽=마지막 2의 다음 |
| 3 | 4 | 4 | 없는 값은 둘이 같음(삽입될 자리) |
| 1 | 0 | 1 | 왼쪽=x 미만 개수(0), 오른쪽=x 이하 개수(1) |

  `bisect_right(a, x) - bisect_left(a, x)`가 곧 x의 등장 횟수(2는 3개). L4의 successor/predecessor도 이 둘로 만든다.

**문제**

**1) 가장 가까운 값** · Easy

- **요구사항**: 정렬해 둘 수 있는 정수 집합에 대해, 각 쿼리 값 x에 대해 x와의 절댓값 차가 가장 작은 원소를 출력한다. 동률이면 작은 값을 출력.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수, 셋째 줄 Q, 넷째 줄 Q개의 쿼리.

- **출력**: 각 쿼리의 답을 공백으로.

- **예제**: `5 / 1 4 6 9 12 / 2 / 5 11` → `4 12` , `3 / 10 20 30 / 1 / 25` → `20`

- **셀프체크**: 정렬 후 `bisect_left`로 삽입 위치 i를 찾고 후보는 a[i], a[i-1] 둘뿐. 경계(i=0, i=N)에서 인덱스 범위 초과 주의. 동률 규칙을 후보 비교에 반영. 전체 O((N+Q) log N).

```runner
@@SOLUTION
import sys, bisect
def main():
    data=sys.stdin.read().split()
    idx=0
    n=int(data[idx]); idx+=1
    a=[int(data[idx+i]) for i in range(n)]; idx+=n
    a.sort()
    q=int(data[idx]); idx+=1
    qs=[int(data[idx+i]) for i in range(q)]
    res=[]
    for x in qs:
        i=bisect.bisect_left(a,x)
        best=None
        for j in (i-1,i):
            if 0<=j<n:
                if best is None or abs(a[j]-x)<abs(best-x) or (abs(a[j]-x)==abs(best-x) and a[j]<best):
                    best=a[j]
        res.append(str(best))
    print(" ".join(res))
main()

(1) 접근·핵심 아이디어

- 정렬해 두면 x에 가장 가까운 값은 반드시 "x가 삽입될 자리 바로 왼쪽/오른쪽" 둘 중 하나다. `bisect_left`로 그 자리 i를 찾고 후보 a[i-1], a[i]만 비교하면 된다.

(2) 코드 단계별

- 배열을 읽어 정렬하고, 쿼리들을 읽는다.
- 각 x에 대해 `i = bisect_left(a, x)`로 삽입 위치를 구한다.
- 후보 인덱스 i-1, i를 순회하되 `0 <= j < n` 범위 안일 때만 본다.
- best와 비교: 절댓값 차가 더 작거나, 같으면 값이 더 작은 쪽으로 갱신(동률 시 작은 값 규칙).
- 모든 쿼리 답을 공백으로 출력.

(3) 스스로 다시 짤 때 생각 순서

- "정렬 + 이분탐색"으로 후보를 O(log N)에 2개로 좁힌다는 큰 그림을 먼저 잡는다.
- 경계(i=0이면 왼쪽 없음, i=n이면 오른쪽 없음)를 인덱스 범위 검사로 한 번에 처리한다.
- 동률 규칙을 비교식에 명시적으로 넣는다(`==`일 때 작은 값 선택).
```

**2) 범위 내 개수 쿼리** · Medium

- **요구사항**: 정수 배열이 주어지고 여러 개의 [L, R] 쿼리에 대해 값이 L 이상 R 이하인 원소의 개수를 각각 출력한다.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수, 셋째 줄 Q, 이후 Q줄에 L R.

- **출력**: 각 쿼리 답을 줄마다.

- **예제**: `5 / 3 1 4 1 5 / 2 / 1 3 / 4 5` (줄바꿈 표기) → `3` 그리고 `2` , `4 / 10 20 20 30 / 1 / 20 20` → `2`

- **셀프체크**: 한 번 정렬한 뒤 각 쿼리는 `bisect_right(a,R) - bisect_left(a,L)`. 정렬 O(N log N), 쿼리당 O(log N). L>R 방어, 중복 값 포함 여부가 bisect 선택의 핵심.

```runner
@@SOLUTION
import sys, bisect
def main():
    data=sys.stdin.buffer.read().split()
    idx=0
    n=int(data[idx]); idx+=1
    a=[int(data[idx+i]) for i in range(n)]; idx+=n
    a.sort()
    q=int(data[idx]); idx+=1
    out=[]
    for _ in range(q):
        l=int(data[idx]); r=int(data[idx+1]); idx+=2
        out.append(str(bisect.bisect_right(a,r)-bisect.bisect_left(a,l)))
    print("\n".join(out))
main()
@@TESTS

--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 정렬 배열에서 "[L, R] 구간 원소 수 = (R 이하 개수) - (L 미만 개수)"이다. `bisect_right(a, R)`은 R 이하 개수, `bisect_left(a, L)`은 L 미만 개수를 주므로 둘의 차가 정답. 양 끝을 포함하려면 오른쪽은 right, 왼쪽은 left를 써야 한다.

(2) 코드 단계별

- 배열을 읽어 한 번만 정렬한다.
- 각 쿼리 (L, R)에 대해 `bisect_right(a, R) - bisect_left(a, L)`을 계산해 개수를 얻는다.
- 결과를 줄마다 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "누적/개수 질의는 정렬 후 이분탐색"이라는 패턴을 떠올린다.
- 경계 포함 여부에 따라 left/right를 고른다: 포함(≤, ≥)이 헷갈리면 중복 값 예시로 표를 그려 확인한다.
- 정렬은 딱 한 번, 쿼리마다 O(log N)이라는 비용 구조를 인지한다.
```

**3) 스트리밍 중앙 근처 조회** · Hard

- **요구사항**: 정수를 하나씩 삽입하는 연산과 "현재까지 삽입된 값 중 x 이상인 가장 작은 값을 출력"하는 연산이 섞여 들어온다. 없으면 -1.

- **입력**: 첫 줄 Q, 이후 각 줄에 `1 v`(삽입) 또는 `2 x`(조회).

- **출력**: 조회마다 결과를 줄마다.

- **예제**: `5 / 1 10 / 1 5 / 2 6 / 1 6 / 2 6` → `10` 그리고 `6` , `3 / 1 3 / 2 4 / 2 3` → `-1` 그리고 `3`

- **셀프체크**: 삽입·조회가 섞이므로 정렬 유지가 필요. `SortedList`가 있으면 삽입/lower_bound 모두 O(log n). 없으면 `insort`(O(n))로 구현하되 Q가 크면 느릴 수 있음을 인지. 조회는 `bisect_left` 위치가 배열 끝이면 -1.

```runner
@@SOLUTION
import sys, bisect
def main():
    data=sys.stdin.buffer.read().split()
    idx=0
    q=int(data[idx]); idx+=1
    a=[]
    out=[]
    for _ in range(q):
        op=int(data[idx]); v=int(data[idx+1]); idx+=2
        if op==1:
            bisect.insort(a, v)
        else:
            i=bisect.bisect_left(a, v)
            out.append(str(a[i]) if i<len(a) else "-1")
    print("\n".join(out))
main()
@@TESTS

2 6

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 삽입과 "x 이상 최소값" 조회가 섞이므로 정렬 상태를 계속 유지해야 한다. `bisect.insort`로 정렬 위치에 삽입하고, 조회는 `bisect_left(a, x)` 위치의 원소가 곧 "x 이상 첫 값"이다. 그 위치가 배열 끝이면 그런 값이 없으므로 -1.

(2) 코드 단계별

- Q를 읽고 연산을 순서대로 처리한다.
- `1 v`: `insort(a, v)`로 정렬 유지 삽입.
- `2 x`: `i = bisect_left(a, x)`. `i < len(a)`면 a[i](x와 같거나 큰 첫 값)를 출력, 아니면 -1.
- 조회 결과를 줄마다 모아 출력.

(3) 스스로 다시 짤 때 생각 순서

- 삽입/조회 혼합 → 정렬 유지 컨테이너가 필요하다는 신호. 표준 라이브러리만 쓰면 정렬 리스트+bisect.
- "x 이상 최소값"은 `bisect_left`(같은 값 포함), "x 초과 최소값"은 `bisect_right`임을 구분한다.
- 대량 삽입이면 insort의 O(n) 이동 비용이 병목이 될 수 있음을 인지(여기선 표준 라이브러리 범위에서 정석 구현).
```


## L3. HashSet

**개념**

- HashSet은 "값의 집합"을 다루는 자료구조로, 중복을 자동 제거하고 원소의 존재 여부를 평균 O(1)에 판정한다. 파이썬 내장 `set`이 이에 해당한다. 값→값이 아니라 "있다/없다"만 저장하는 HashMap의 특수형이라 보면 된다.

- 언제 쓰나: 중복 제거, "이미 방문했는가" 체크(그래프/시뮬레이션의 visited), 두 집합의 교집합·합집합·차집합 계산, "본 적 있는 상태" 판정으로 사이클/중복 탐지.

- 집합 연산이 언어 차원에서 매우 빠르고 간결하다: `a & b`(교집합), `a | b`(합집합), `a - b`(차집합), `a ^ b`(대칭차). frozenset은 불변이라 다른 set의 원소나 dict 키가 될 수 있다.

```python
seen = set()
for x in stream:
    if x in seen:          # 존재 판정 O(1)
        ...                # 중복 발견
    seen.add(x)

inter = A & B              # 교집합
uni   = A | B              # 합집합
only_a = A - B            # 차집합
```

**그림으로 보기**

- set은 dict에서 "값" 칸만 뺀 것이다. 같은 해시 표 위에 키만 놓이므로 존재 판정 비용이 dict와 똑같다. 리스트와의 차이를 한 장으로 보자.

```text
  x = 8

  x in list  : compare one by one, up to n times    # O(n)
        [ 7 ][ 3 ][ 9 ][ 4 ][ 8 ][ 1 ]
          1    2    3    4    5                     <- comparisons

  x in set   : compute the slot, look once          # O(1)
        hash(8) % 8 = 0
        slot    0    1    2    3    4    5    6    7
             ┌────┬────┬────┬────┬────┬────┬────┬────┐
             │  8 │  1 │ .  │  3 │ .  │  4 │ .  │  7 │
             └────┴────┴────┴────┴────┴────┴────┴────┘
                ^ found in 1 step
```

- 집합 연산은 두 표를 한 번씩 훑는 일이다. 네 연산이 각각 어느 덩어리를 가리키는지 그림으로 굳혀 둔다.

```text
  A = {1, 2, 3, 4}          B = {3, 4, 5}

      ┌──────────┬──────────┬──────────┐
      │   1  2   │   3  4   │    5     │
      └──────────┴──────────┴──────────┘
         A - B       A & B      B - A
      |----------A----------|                    # A
                 |----------B----------|         # B
      |--------------union-------------|         # A | B
      |----------|          |----------|         # A ^ B
```

**왜 이렇게 되는가**

- **`x in list`는 O(n), `x in set`은 O(1)인 이유**: 리스트는 x가 어디 있을지 알 방법이 없어 앞에서부터 하나씩 비교한다. set은 x 자신이 자기 자리를 알려준다(`hash(x)`로 칸 번호가 나온다). N개짜리 데이터에 Q번 존재 질의를 하면 리스트는 O(NQ), set은 O(N+Q)다. N=Q=10만이면 100억 대 20만이라 통과와 시간초과를 가른다.

- **집합 연산의 비용**: `A & B`는 **작은 쪽**을 훑으며 각 원소를 큰 쪽에서 O(1)에 확인하므로 O(min(|A|,|B|))다. `A | B`는 양쪽을 전부 담아야 하므로 O(|A|+|B|). 큰 집합 둘의 교집합이라도 한쪽이 작으면 싸다는 점을 기억해 둘 것.

- **set은 왜 순서가 없는가**: 원소의 위치가 삽입 순서가 아니라 해시값으로 정해지기 때문이다. 순회 순서는 "칸 번호 순"이라 사람이 예상하는 순서와 무관하고, 원소 구성이 조금만 달라져도 바뀐다. 순서가 필요하면 반드시 `sorted(s)`로 명시해야 한다.

**접근 전략**

- "중복을 없애야 한다 / 존재 여부만 빠르게 물으면 된다 / 집합 간 관계(교·합·차)를 계산한다"면 set을 선택한다. 방문 상태를 좌표 튜플 `(r,c)`로 넣어 visited로 쓰는 패턴은 격자 문제의 단골. 값 자체가 필요 없고 "봤는지"만 중요하면 dict보다 set이 의미가 명확하다.

- 시간복잡도: add/in/discard 평균 O(1), 집합 연산은 두 집합 크기의 합에 비례 O(|A|+|B|). 공간 O(n). 흔한 실수: 리스트를 원소로 넣으려다 TypeError(불변만 가능 → 튜플/frozenset), 순서가 필요한데 set을 써서 순서가 뒤섞임(set은 순서 보장 없음), `remove`는 없으면 KeyError지만 `discard`는 조용히 통과. 팁: 큰 배열의 존재 판정을 `if x in list`로 하면 O(n)이니 반드시 set으로 바꿔라.

**문제**

**1) 유일 원소 개수** · Easy

- **요구사항**: 정수 배열에서 서로 다른 값의 개수를 출력한다.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수.

- **출력**: 서로 다른 값의 개수.

- **예제**: `5 / 1 2 2 3 3` → `3` , `4 / 7 7 7 7` → `1`

**2) 공통 관심사** · Medium

- **요구사항**: 두 사람이 각각 좋아하는 항목 목록을 준다. 둘 다 좋아하는 항목의 개수와, 적어도 한 명이 좋아하는 항목의 개수를 출력한다.

- **입력**: 첫 줄 A의 개수, 둘째 줄 A의 항목들. 셋째 줄 B의 개수, 넷째 줄 B의 항목들.

**3) 첫 중복 위치** · Medium

- **요구사항**: 정수 스트림에서 "직전까지 나온 값이 다시 등장하는" 최초 지점의 1-based 인덱스를 출력한다. 중복이 전혀 없으면 -1.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수.

- **출력**: 인덱스 또는 -1.

- **예제**: `5 / 3 1 3 2 1` → `3` , `3 / 1 2 3` → `-1`

- **셀프체크**: seen set을 유지하며 왼쪽부터 훑다가 처음으로 `x in seen`인 순간의 인덱스를 출력. O(N). "넣기 전에 검사"하는 순서를 지켰는지, 전부 유일할 때 -1 반환 경계를 확인.

```runner
@@SOLUTION
import sys
def main():
    data=sys.stdin.read().split()
    n=int(data[0])
    arr=[int(data[1+i]) for i in range(n)]
    seen=set()
    for i,x in enumerate(arr):
        if x in seen:
            print(i+1); return
        seen.add(x)
    print(-1)
main()
@@TESTS

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- "직전까지 나온 값이 다시 등장하는 최초 지점"은 왼쪽부터 훑으며 이미 본 값의 집합을 유지하다가, 현재 값이 그 집합에 있으면 그 위치가 답이다. 존재 판정을 O(1)에 하려면 set이 필수.

(2) 코드 단계별

- N과 배열을 읽는다.
- `seen` 집합을 두고 왼쪽부터 순회한다.
- 현재 x가 이미 `seen`에 있으면 1-based 인덱스를 출력하고 종료(첫 중복이므로 즉시 반환).
- 없으면 `seen.add(x)`로 등록. 루프가 끝까지 돌면 중복이 없으므로 -1.

(3) 스스로 다시 짤 때 생각 순서

- "이미 본 적 있나?"를 O(1)에 묻는 것이 핵심 → set.
- "검사 → 등록" 순서를 지켜야 자기 자신을 중복으로 착각하지 않는다.
- 전부 유일한 경우의 -1 반환 경계를 잊지 않는다.
```


## L4. TreeSet

**개념**

- TreeSet은 "정렬 상태가 유지되는 집합"이다. HashSet이 순서 없이 존재만 관리한다면, TreeSet은 원소를 항상 정렬해 두어 최소/최대 원소, "x보다 큰 가장 작은 원소(successor)", "x보다 작은 가장 큰 원소(predecessor)", 범위 순회를 O(log n)에 제공한다. TreeMap에서 값을 뺀 형태다.

- 파이썬 내장은 없다. 대체법: (1) 삽입 후 조회만 → 정렬 리스트 + `bisect`, (2) 삽입/삭제가 섞이면 `sortedcontainers.SortedList`(O(log n) 삽입/삭제/이분탐색), (3) 값 범위가 작으면 좌표압축 + BIT/세그먼트로 "존재 개수"를 관리.

- 대표 질의 successor/predecessor는 bisect로 만든다: 정렬 배열 a에서 `bisect_right(a, x)` 위치가 "x 초과 첫 원소"(successor), `bisect_left(a, x) - 1` 위치가 "x 미만 마지막 원소"(predecessor).

```python
import bisect
a = []                          # 정렬 유지 (또는 SortedList)

def successor(x):              # x보다 큰 최소 원소
    i = bisect.bisect_right(a, x)
    return a[i] if i < len(a) else None

def predecessor(x):           # x보다 작은 최대 원소
    i = bisect.bisect_left(a, x) - 1
    return a[i] if i >= 0 else None
```

**그림으로 보기**

- 정렬된 집합을 한 줄에 놓으면 pred/succ는 "x의 왼쪽 첫 점 / 오른쪽 첫 점"이다. `bisect_left`와 `bisect_right`가 각각 어느 경계에 서는지 확인하자.

```text
  a = [1, 4, 6, 9, 12]        x = 6

        idx    0    1    2    3    4
            ┌────┬────┬────┬────┬────┐
            │  1 │  4 │  6 │  9 │ 12 │
            └────┴────┴────┴────┴────┘
                    ^    ^    ^
                    │    │    └── bisect_right(a,6) = 3 -> succ = a[3] = 9
                    │    └─────── bisect_left (a,6) = 2
                    └──────────── left - 1        = 1 -> pred = a[1] = 4

  x = 7  (not in a)
        bisect_left = bisect_right = 3
        pred = a[2] = 6         succ = a[3] = 9

  x = 0   -> left - 1 = -1        nothing on the left
  x = 99  -> right    =  5 = n    nothing on the right
```

**손으로 따라가기**

- 같은 배열 `a = [1, 4, 6, 9, 12]`(n=5)에 쿼리 네 개를 넣어 본다.

| 쿼리 x | `bisect_left` | `bisect_right` | pred = `a[left-1]` | succ = `a[right]` |
|---|---|---|---|---|
| 1 | 0 | 1 | `left-1 = -1` → 없음 | `a[1] = 4` |
| 6 | 2 | 3 | `a[1] = 4` | `a[3] = 9` |
| 7 | 3 | 3 | `a[2] = 6` | `a[3] = 9` |
| 12 | 4 | 5 | `a[3] = 9` | `right = 5 = n` → 없음 |

- x가 집합에 있든(1, 6, 12) 없든(7) **같은 두 줄이 그대로 동작한다**. left는 x 앞에서 멈추고, right는 x를 넘어가기 때문이다.

**왜 이렇게 되는가**

- **왜 `left-1`과 `right`인가**: 정의상 `bisect_left(a,x)`는 "x 미만인 원소의 개수"다. 그 개수가 k면 인덱스 `0..k-1`이 전부 x 미만이므로 마지막인 `a[k-1]`이 곧 x 미만 최대값 = pred다. 마찬가지로 `bisect_right(a,x)`는 "x 이하인 원소의 개수"이므로 인덱스 k부터가 x 초과이고, 그 첫 원소 `a[k]`가 succ다. x가 배열에 있든 없든, 중복이 몇 개든 이 논리는 그대로 성립한다.

- **왜 삭제가 병목이 되는가**: `a.pop(i)`는 뒤의 원소를 전부 한 칸씩 앞으로 당긴다(O(n)). 삽입과 대칭이라 "위치 찾기 O(log n) + 자리 메우기 O(n)"이고 큰 쪽이 이긴다. 삽입·삭제가 Q번 섞이면 O(NQ)라, Q가 10만이면 정렬 리스트로는 시간 초과다. 이때가 `SortedList`나 좌표압축+BIT로 갈아탈 지점이다.

**접근 전략**

- "정렬된 집합에서 가장 가까운 큰/작은 원소를 반복해서 찾거나, 삽입·삭제 후에도 정렬 순서를 유지해야 한다"면 TreeSet을 떠올린다. 예약 시스템(빈 자리 찾기), 스카이라인, 슬라이딩 구간에서 최소/최대 유지 등이 전형. 삽입이 없으면 정렬+bisect로 끝나지만, 삭제가 잦으면 정렬 리스트의 pop이 O(n)이므로 SortedList가 유리하다.

- 시간복잡도: BST/SortedList 기반이면 삽입·삭제·successor·predecessor 모두 O(log n). 정렬 리스트+insort/삭제는 O(n). 공간 O(n). 흔한 실수: bisect_left/right로 successor·predecessor를 만들 때 경계(빈 결과)를 None으로 처리하지 않아 IndexError. 중복 원소가 있으면 "집합"이 아니므로 필요 시 넣기 전에 존재 검사. 팁: "정렬 + 이분탐색"으로 풀리는지 먼저 의심하라 — TreeSet 문제의 절반은 오프라인 정렬로 단순화된다.

**문제**

**1) 다음으로 큰 예약 시각** · Easy

- **요구사항**: 이미 잡힌 시각들의 집합이 주어지고, 각 쿼리 t에 대해 t보다 "크거나 같은" 가장 이른 시각을 출력한다. 없으면 -1.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수(시각), 셋째 줄 Q, 넷째 줄 Q개의 t.

- **출력**: 각 답을 공백으로.

- **예제**: `4 / 2 5 8 13 / 2 / 6 14` → `8 -1` , `3 / 1 3 5 / 1 / 3` → `3`

- **셀프체크**: "크거나 같은"이므로 `bisect_left`가 정답 위치. 위치가 끝이면 -1. 정렬 O(N log N), 쿼리당 O(log N). "크거나 같은"과 "초과"를 혼동하지 않았는지.

```runner
@@SOLUTION
import sys, bisect
def main():
    data=sys.stdin.read().split()
    idx=0
    n=int(data[idx]); idx+=1
    a=[int(data[idx+i]) for i in range(n)]; idx+=n
    a.sort()
    q=int(data[idx]); idx+=1
    qs=[int(data[idx+i]) for i in range(q)]
    res=[]
    for t in qs:
        i=bisect.bisect_left(a,t)
        res.append(str(a[i]) if i<len(a) else "-1")
    print(" ".join(res))
main()
@@TESTS
--IN

2
6 14
--OUT

--IN
3
1 3 5
1
3
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- "t 이상 가장 이른 시각"은 정렬 배열에서 `bisect_left(a, t)` 위치의 원소다. left는 t와 같은 값도 포함하므로 "크거나 같은"에 정확히 맞는다. 위치가 배열 끝(len)이면 t 이상 값이 없으므로 -1.

(2) 코드 단계별

- 시각들을 읽어 정렬하고 쿼리들을 읽는다.
- 각 t에 대해 `i = bisect_left(a, t)`. `i < len(a)`면 a[i]를 출력, 아니면 -1.
- 답을 공백으로 연결해 출력.

(3) 스스로 다시 짤 때 생각 순서

- "이상(≥)"이면 `bisect_left`, "초과(>)"면 `bisect_right`라는 대응을 확실히 한다.
- 결과 위치가 유효 범위를 벗어나는 경계(값 없음)를 -1로 처리한다.
- 정렬은 한 번, 쿼리마다 O(log N)이라는 구조를 인지한다.
```

**2) 앞뒤 가장 가까운 원소** · Medium

- **요구사항**: 정수 집합과 쿼리 x가 주어질 때, x보다 작은 최대 원소(pred)와 x보다 큰 최소 원소(succ)를 출력한다. 각각 없으면 -1.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수, 셋째 줄 Q, 이후 Q줄에 x.

- **출력**: 각 줄에 pred succ.

- **예제**: `5 / 1 4 6 9 12 / 1 / 6` → `4 9` , `3 / 10 20 30 / 1 / 30` → `20 -1`

- **셀프체크**: pred는 `bisect_left(a,x)-1`, succ는 `bisect_right(a,x)`. x가 집합에 있어도 자기 자신은 제외됨을 확인(strict). 경계에서 -1. 각 쿼리 O(log N).

```runner
@@SOLUTION
import sys, bisect
def main():
    data=sys.stdin.buffer.read().split()
    idx=0
    n=int(data[idx]); idx+=1
    a=[int(data[idx+i]) for i in range(n)]; idx+=n
    a.sort()
    q=int(data[idx]); idx+=1
    out=[]
    for _ in range(q):
        x=int(data[idx]); idx+=1
        li=bisect.bisect_left(a,x)-1
        ri=bisect.bisect_right(a,x)
        pred=a[li] if li>=0 else -1
        succ=a[ri] if ri<n else -1
        out.append(f"{pred} {succ}")
    print("\n".join(out))
main()
@@TESTS
--IN
5
1 4 6 9 12
1
6
--OUT
4 9
--IN
3
10 20 30
1
30
--OUT
20 -1
@@EXPL
(1) 접근·핵심 아이디어

- strict predecessor(x보다 작은 최대)는 `bisect_left(a, x) - 1` 위치, strict successor(x보다 큰 최소)는 `bisect_right(a, x)` 위치다. left/right를 이렇게 쓰면 x 자신이 집합에 있어도 자동으로 제외된다(left는 x 앞에서 멈추고, right는 x 뒤로 넘어감).

(2) 코드 단계별

- 배열을 정렬하고 쿼리를 읽는다.
- 각 x에 대해 `li = bisect_left(a, x) - 1`(pred 후보 인덱스), `ri = bisect_right(a, x)`(succ 후보 인덱스).
- `li >= 0`이면 a[li], 아니면 -1이 pred. `ri < n`이면 a[ri], 아니면 -1이 succ.
- "pred succ"를 줄마다 출력.

(3) 스스로 다시 짤 때 생각 순서

- "x 자신 제외"라는 strict 조건에서 왜 left-1과 right인지 중복 배열 예시로 확인한다.
- 양쪽 경계(빈 결과)를 -1로 처리해 IndexError를 막는다.
- pred/succ 공식은 TreeSet류 문제의 만능 도구이므로 손에 익혀 둔다.
```

**3) 삽입·삭제 후 최솟값** · Hard

- **요구사항**: `1 v`(v 삽입), `2 v`(v 삭제, 없으면 무시), `3`(현재 최솟값 출력, 비어 있으면 -1) 연산을 순서대로 처리한다.

- **입력**: 첫 줄 Q, 이후 각 줄에 연산.

- **출력**: `3` 연산마다 결과를 줄마다.

- **예제**: `5 / 1 5 / 1 3 / 3 / 2 3 / 3` → `3` 그리고 `5` , `3 / 1 7 / 2 7 / 3` → `-1`

- **셀프체크**: 삽입·삭제·최솟값이 섞이므로 정렬 유지 필요. SortedList면 삽입/삭제 O(log n), 최솟값은 a[0]. 없으면 정렬 리스트+insort/삭제(O(n))로 구현하되 Q가 크면 병목. 삭제 시 존재하지 않는 값 무시, 빈 상태의 -1 경계가 함정.

```runner
@@SOLUTION
import sys, bisect
def main():
    data=sys.stdin.buffer.read().split()
    idx=0
    q=int(data[idx]); idx+=1
    a=[]
    out=[]
    for _ in range(q):
        op=int(data[idx]); idx+=1
        if op==1:
            v=int(data[idx]); idx+=1
            bisect.insort(a, v)
        elif op==2:
            v=int(data[idx]); idx+=1
            i=bisect.bisect_left(a, v)
            if i<len(a) and a[i]==v:
                a.pop(i)
        else:
            out.append(str(a[0]) if a else "-1")
    print("\n".join(out))
```

## L5. Priority Queue

**개념**

- 우선순위 큐는 "가장 우선순위 높은 원소를 O(log n)에 꺼내는" 자료구조로, 보통 이진 힙으로 구현한다. 파이썬은 `heapq` 모듈로 리스트를 최소 힙처럼 다룬다: `heappush`로 넣고 `heappop`으로 항상 "가장 작은 값"을 꺼낸다. 삽입·삭제 O(log n), 최솟값 확인 heap[0]은 O(1)이다.

- 언제 쓰나: 매 순간 최소/최대를 반복해서 꺼내야 할 때 — 다익스트라, K개 병합, 스케줄링(가장 빨리 끝나는 작업), 실시간 K번째 값 유지 등. "정렬을 매번 다시 하지 않고, 최소만 빠르게 뽑고 싶다"가 신호다.

- 파이썬 heapq는 최소 힙만 제공한다. 최대 힙이 필요하면 값의 부호를 뒤집어 `-x`로 넣거나, 튜플 `(우선순위, 데이터)`로 넣어 우선순위 기준 정렬을 만든다. 동점일 때 데이터끼리 비교가 일어나 에러가 날 수 있으니 `(우선순위, 삽입순번, 데이터)`처럼 타이브레이커를 끼운다.

```python
import heapq

h = []
heapq.heappush(h, (dist, node))   # (우선순위, 데이터)
d, u = heapq.heappop(h)           # 최소 우선순위 pop

# 최대 힙: 부호 반전
heapq.heappush(maxh, -x)
biggest = -heapq.heappop(maxh)

# 상위 K개 유지: 크기 K인 최소 힙
if len(h) < K: heapq.heappush(h, x)
elif x > h[0]: heapq.heapreplace(h, x)  # K번째로 큰 값 유지
```

**그림으로 보기**

- 힙은 개념적으로 완전이진트리지만 실제로는 **배열 하나**다. 부모·자식 관계가 인덱스 산술로 정해지므로 포인터가 필요 없다.

```text
  the shape we imagine

        (1)                  idx 0
       /   \
    (3)     (2)              idx 1, 2
    / \
  (7) (5)                    idx 3, 4

  what is really stored

     idx    0    1    2    3    4
          ┌────┬────┬────┬────┬────┐
          │  1 │  3 │  2 │  7 │  5 │
          └────┴────┴────┴────┴────┘

     parent(i) = (i - 1) // 2
     left(i)   = 2*i + 1
     right(i)  = 2*i + 2
     rule : a[parent] <= a[child]        # 최소 힙 조건
```

- push는 **맨 뒤에 붙인 뒤 위로 올라간다(sift-up)**. 부모보다 작으면 자리를 맞바꾸고, 아니면 거기서 멈춘다.

```text
  heappush(h, 0)        h = [1, 3, 2, 7, 5]

  step 0 : append at the end
     [ 1, 3, 2, 7, 5, 0 ]         at idx5, parent = (5-1)//2 = 2
                      ^
  step 1 : 0 < a[2] = 2  -> swap
     [ 1, 3, 0, 7, 5, 2 ]         now at idx2, parent = (2-1)//2 = 0
             ^
  step 2 : 0 < a[0] = 1  -> swap
     [ 0, 3, 1, 7, 5, 2 ]         now at the root -> stop
       ^
```

- pop은 뿌리를 꺼내고 **맨 뒤 원소를 뿌리에 올린 뒤 아래로 내려간다(sift-down)**. 이때 반드시 **두 자식 중 작은 쪽**과 비교한다.

```text
  heappop(h)            h = [0, 3, 1, 7, 5, 2]      returns 0

  step 0 : move the last element (2) to the root
     [ 2, 3, 1, 7, 5 ]            children of idx0 : a[1]=3, a[2]=1
       ^
  step 1 : the smaller child is 1 (idx2), and 2 > 1 -> swap
     [ 1, 3, 2, 7, 5 ]            now at idx2, its children do not exist
             ^
  step 2 : no child -> stop
```

- 중앙값을 O(1)에 보려면 힙 두 개로 데이터를 반으로 갈라 둔다. 경계에 앉은 두 top이 중앙 근처 값이다.

```text
  values seen so far : 1 2 2 5 7

  low  = max-heap over the smaller half   (heapq stores -x inside)
     idx    0    1    2
          ┌────┬────┬────┐
          │  2 │  1 │  2 │      top = 2      <- the median
          └────┴────┴────┘

  high = min-heap over the larger half
     idx    0    1
          ┌────┬────┐
          │  5 │  7 │           top = 5
          └────┴────┘

  invariant : len(low) - len(high) is 0 or 1
              max(low) <= min(high)
```

**손으로 따라가기**

- 빈 힙에 5개를 넣고 2개를 뺀다. 배열 상태를 단계마다 적어 본다(파이썬 `heapq`는 0-인덱스 최소 힙).

| 단계 | 연산 | 힙 배열 | 무슨 일이 일어났나 |
|---|---|---|---|
| 0 | 시작 | `[]` | 빈 힙 |
| 1 | push 5 | `[5]` | 뿌리에 그대로 |
| 2 | push 3 | `[3, 5]` | idx1에 붙임 → 부모 5보다 작아 1회 교환 |
| 3 | push 8 | `[3, 5, 8]` | idx2에 붙임 → 부모 3보다 크므로 제자리 |
| 4 | push 1 | `[1, 3, 8, 5]` | idx3 → 부모 5와 교환 → 부모 3과 교환(2회) |
| 5 | push 4 | `[1, 3, 8, 5, 4]` | idx4 → 부모 `a[1]=3`보다 크므로 제자리 |
| 6 | pop → `1` | `[3, 4, 8, 5]` | 마지막 4를 뿌리로 → 자식(3, 8) 중 3과 교환 |
| 7 | pop → `3` | `[4, 5, 8]` | 마지막 5를 뿌리로 → 자식(4, 8) 중 4와 교환 |

- 두 번의 pop이 `1`, `3`을 작은 순서대로 뱉었다. 4단계의 배열 `[1, 3, 8, 5]`에 주목하자 — 정렬된 배열(`[1,3,5,8]`)이 아니지만 "부모 ≤ 자식"은 전부 만족한다. **힙은 전체를 정렬하지 않고 최솟값만 뿌리에 유지한다.**

**왜 이렇게 되는가**

- **왜 push/pop이 O(log n)인가**: 완전이진트리는 각 층이 꽉 찬 뒤에야 다음 층이 시작된다. 층 0에 1개, 층 1에 2개, 층 2에 4개… 층 h까지 채우면 `1+2+4+…+2^h = 2^(h+1) - 1`개다. 원소가 n개면 `2^h ≤ n`, 즉 **높이 `h ≤ log2 n`**이다. sift-up은 뿌리까지, sift-down은 잎까지 한 층에 비교·교환을 상수 번만 하며 이동하므로 총비용이 높이에 비례해 O(log n)이 된다. n이 백만이어도 높이는 20이다.

- **왜 `heapify`는 O(n)인가**: 잎에서 뿌리 쪽으로 sift-down을 하면 높이 k인 노드는 최대 k번만 내려간다. 그런데 높이 k인 노드는 약 `n / 2^(k+1)`개뿐이다. 총비용은 `Σ k · n/2^(k+1) = n · Σ k/2^(k+1) ≤ n`이라 선형이다. "하나씩 push해서 O(n log n)"보다 확실히 싸므로, **처음부터 배열이 다 있으면 `heapify`를 쓴다.**

- **왜 최댓값은 O(1)에 못 보는가**: 힙 조건은 "부모 ≤ 자식"뿐이고 **형제 사이에는 아무 순서도 없다**. 최댓값은 반드시 잎 중 하나지만 어느 잎인지 알 방법이 없어 잎 전체를 훑어야 하고 O(n)이 든다. 최소와 최대를 둘 다 O(log n)에 원하면 힙 하나로는 안 되고 힙 두 개나 정렬 구조가 필요하다.

- **왜 최대 힙을 부호 반전으로 만드는가**: `x ≤ y`와 `-x ≥ -y`가 동치이므로, 부호를 뒤집어 넣으면 "가장 작은 `-x`"가 곧 "가장 큰 `x`"다. 값 자체를 바꿔 저장하는 것이므로 **넣을 때와 뺄 때 모두** 부호를 처리해야 한다는 점이 함정이다.

**접근 전략**

- "최소(또는 최대)를 계속 꺼내되, 그 사이 새 원소가 계속 들어온다"면 힙이다. 전부 모아 정렬하면 O(n log n)이지만, 스트리밍처럼 삽입·추출이 섞이면 힙이 필수. 상위/하위 K개 유지에는 "크기를 K로 제한한 힙"이 정석(전체 정렬 O(n log n) 대신 O(n log K)). 다익스트라에서는 `(거리, 정점)` 튜플을 넣고, pop 시 기록된 거리보다 크면 skip하는 lazy deletion 패턴을 쓴다.

- 시간복잡도: push/pop O(log n), peek O(1), `heapify`로 리스트 전체를 O(n)에 힙화. 공간 O(n). 흔한 실수: heapq는 최대 힙이 없다(부호 반전 잊음), 튜플 동점 시 두 번째 요소 비교로 TypeError(타이브레이커 필요), 힙 중간 원소의 임의 삭제는 O(log n)에 안 되므로 lazy deletion으로 우회. 팁: `heapq.nlargest(k, it)` / `nsmallest`는 K개만 필요할 때 간결하고 빠르다. `heapreplace`(pop 후 push)는 두 연산을 한 번에.

**문제**

**1) K번째로 작은 값(스트리밍)** · Medium

- **요구사항**: `1 v`(값 추가), `2`(현재까지 값 중 K번째로 작은 값 출력, 원소 수가 K 미만이면 -1) 연산을 처리한다.

- **입력**: 첫 줄 Q K, 이후 각 줄에 연산.

- **출력**: `2` 연산마다 결과를 줄마다.

- **예제**: `5 2 / 1 5 / 1 2 / 2 / 1 1 / 2` → `5` 그리고 `2` , `3 1 / 1 9 / 1 4 / 2` → `4`

- **셀프체크**: 크기 K인 "최대 힙"(부호 반전)을 유지 — 항상 가장 작은 K개만 담고, 그 최대(=힙 top)가 K번째로 작은 값. 새 값이 top보다 작으면 교체. 삽입 O(log K), 조회 O(1). K번째로 "작은" 것은 최대 힙, "큰" 것은 최소 힙이라는 방향을 헷갈리지 말 것.

```runner
@@SOLUTION
import sys, heapq
def main():

    for _ in range(q):
        op=int(data[idx]); idx+=1
        if op==1:

            if len(h)<k:
                heapq.heappush(h, -v)
            elif v < -h[0]:
                heapq.heapreplace(h, -v)
        else:
            out.append(str(-h[0]) if len(h)==k else "-1")
    print("\n".join(out))
main()

(1) 접근·핵심 아이디어

- "K번째로 작은 값"은 "가장 작은 K개" 중 가장 큰 값이다. 크기 K로 제한한 최대 힙(파이썬은 값에 -를 붙여 최소 힙으로 흉내)에 가장 작은 K개만 유지하면, 힙의 top(=음수로 저장된 최댓값)이 곧 K번째로 작은 값이다.

(2) 코드 단계별

- Q, K를 읽는다. 힙 h는 부호 반전된 값을 담는다(top이 실제 최댓값).
- `1 v`: 아직 K개 미만이면 그냥 push. 이미 K개면, 새 v가 현재 top(`-h[0]`)보다 작을 때만 `heapreplace`로 top을 교체(더 작은 K개 유지).
- `2`: 원소가 K개면 `-h[0]`(K번째로 작은 값), 아니면 -1을 출력.

(3) 스스로 다시 짤 때 생각 순서

- "K번째로 작은 = 작은 K개의 최댓값"으로 재해석한다. 그 최댓값을 O(1)에 보려면 최대 힙.
- 방향 확인: K번째로 "작은"은 최대 힙, "큰"은 최소 힙. 반대로 하면 유지 대상이 뒤집힌다.
- 새 값이 들어올 때 K개 초과분을 버리는 교체 조건(top보다 작을 때만)을 정확히 쓴다.
```

**2) 최소 비용으로 밧줄 잇기** · Medium

- **요구사항**: 길이가 주어진 밧줄들을 모두 하나로 잇는다. 두 밧줄을 이을 때 비용은 두 길이의 합이고, 이 비용이 누적된다. 총비용의 최솟값을 출력한다.

- **입력**: 첫 줄 N, 둘째 줄 N개의 길이.

- **출력**: 최소 총비용.

- **예제**: `3 / 1 2 3` → `9` , `4 / 4 3 2 6` → `29`

- **셀프체크**: 매번 "가장 짧은 두 개"를 합치는 그리디(허프만). 최소 힙에서 둘 pop → 합을 비용에 더하고 다시 push, 하나 남을 때까지. 검산: {1,2,3}→1+2=3(누적3) 남은 {3,3}→3+3=6(누적9). {2,3,4,6}→2+3=5(5) {4,5,6}→4+5=9(14) {6,9}→15(29). N개면 N-1번, O(N log N). N=1이면 비용 0. (가장 작은 둘을 먼저 합치는 것이 왜 최적인지는 ch04 그리디에서 교환 논증으로 다룬다 — 여기서는 힙 사용법에 집중한다.)

```runner
@@SOLUTION
import sys, heapq
def main():
    data=sys.stdin.read().split()
    n=int(data[0])
    a=[int(data[1+i]) for i in range(n)]
    heapq.heapify(a)
    total=0
    while len(a)>1:
        x=heapq.heappop(a)
        y=heapq.heappop(a)
        c=x+y
        total+=c
        heapq.heappush(a, c)
    print(total)
main()
@@TESTS
--IN

1 2 3
--OUT

--IN
4
4 3 2 6
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 허프만 병합 문제다. 매 단계에서 가장 짧은 두 밧줄을 합치는 것이 총비용을 최소화한다. 짧은 것을 먼저 합칠수록 그 합이 이후 합산에 여러 번 더해지는 횟수가 줄기 때문이다. "가장 짧은 둘"을 반복해 꺼내려면 최소 힙이 자연스럽다.

(2) 코드 단계별

- 길이 배열을 읽어 `heapify`로 O(N) 힙화한다.
- 원소가 2개 이상인 동안: 최소 두 개를 pop해 합 c를 만들고, c를 총비용에 더한 뒤 c를 다시 push한다.
- 하나만 남으면 종료하고 누적된 총비용을 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "매번 최소 둘을 합친다"는 그리디를 떠올리고, 반복적 최소 추출 → 최소 힙을 선택한다.
- 합친 결과를 다시 힙에 넣어 계속 후보로 삼는다(누적 비용은 합칠 때마다 더한다).
- N=1이면 합칠 게 없어 비용 0이 되는 경계를 확인한다.
```

**3) 스트림의 중앙값** · Hard

- **요구사항**: 정수를 하나씩 삽입할 때마다 현재까지의 중앙값을 출력한다. 개수가 짝수면 두 중앙값 중 작은 쪽을 출력.

- **입력**: 첫 줄 N, 둘째 줄 N개 정수.

- **출력**: 각 삽입 후 중앙값을 공백으로.

- **예제**: `5 / 2 1 5 7 2` → `2 1 2 2 2` , `4 / 4 1 2 3` → `4 1 2 2`

- **셀프체크**: 두 힙 — 아래 절반은 최대 힙, 위 절반은 최소 힙 — 을 크기 균형(아래가 위보다 0 또는 1 큼)으로 유지하면 아래 힙 top이 중앙값. 삽입마다 O(log n). 첫 예제 검산: [2]→2, [1,2]→1, [1,2,5]→2, [1,2,5,7]→작은쪽2, [1,2,2,5,7]→2. 균형 재조정 순서가 함정.

```runner
@@SOLUTION
import sys, heapq
def main():
    data=sys.stdin.read().split()
    n=int(data[0])
    arr=[int(data[1+i]) for i in range(n)]
    low=[]
    high=[]
    out=[]
    for x in arr:
        if not low or x <= -low[0]:
            heapq.heappush(low, -x)
        else:
            heapq.heappush(high, x)
        if len(low) > len(high)+1:
            heapq.heappush(high, -heapq.heappop(low))
        elif len(high) > len(low):
            heapq.heappush(low, -heapq.heappop(high))
        out.append(str(-low[0]))
    print(" ".join(out))
main()
@@TESTS

--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 두 힙으로 데이터를 아래 절반/위 절반으로 나눈다. 아래 절반은 최대 힙(부호 반전), 위 절반은 최소 힙. 두 힙의 크기를 "아래가 위보다 0 또는 1 큼"으로 유지하면, 짝수 개일 때 두 중앙값 중 작은 쪽이, 홀수 개일 때 진짜 중앙값이 항상 아래 힙의 top이 된다.

(2) 코드 단계별

- 각 새 값 x를: 아래 힙이 비었거나 x가 아래 top 이하이면 아래(low)에, 아니면 위(high)에 넣는다.
- 균형 재조정: 아래가 위보다 2 이상 크면 아래 top을 위로 옮기고, 위가 아래보다 크면 위 top을 아래로 옮긴다. 결과적으로 항상 `len(low) - len(high) ∈ {0, 1}`.
- 매 삽입 후 `-low[0]`(아래 힙 top)을 중앙값으로 기록해 공백으로 출력.

(3) 스스로 다시 짤 때 생각 순서

- "중앙값을 O(1)에 보려면 중앙을 경계로 두 덩어리로 쪼갠다"는 발상 → 최대 힙 + 최소 힙.
- 넣을 힙을 top 비교로 정하고, 그다음 크기 불균형을 한 개씩 넘겨 바로잡는다(순서 중요).
- 짝수일 때 "작은 쪽"을 원하므로 아래 힙이 항상 같거나 하나 더 크게 유지 → 아래 top이 답.
```


## L6. Doubly-LinkedList

**개념**

- 이중 연결 리스트는 각 노드가 앞·뒤 두 포인터(prev, next)를 가져 양방향으로 이동할 수 있는 선형 자료구조다. 배열과 달리 "중간 임의 노드의 삽입·삭제"를 그 노드에 대한 참조만 있으면 O(1)에 처리한다(원소 이동이 없다). 대신 인덱스 임의 접근은 O(n)이다.

- 언제 쓰나: 잦은 중간 삽입/삭제가 핵심이고 "어떤 노드 옆에" 넣고 빼는 위치가 참조로 주어질 때 — LRU 캐시(해시맵+이중연결리스트), 에디터의 커서 이동, 실행 취소/재실행, "옆 사람 제거" 류 시뮬레이션. 양끝 삽입·삭제만 필요하면 `collections.deque`가 훨씬 간단하고 빠르다.

- 핵심은 포인터 재연결이다. 노드 x를 삭제하려면 `x.prev.next = x.next; x.next.prev = x.prev`. 양끝 처리를 단순화하려고 보통 head/tail "센티넬(더미) 노드"를 두어 경계 분기를 없앤다.

```python
class Node:
    __slots__ = ('val', 'prev', 'next')
    def __init__(self, val):
        self.val, self.prev, self.next = val, None, None

def remove(x):                 # x를 리스트에서 분리 O(1)
    x.prev.next = x.next
    x.next.prev = x.prev

def insert_after(p, x):        # p 뒤에 x 삽입 O(1)
    x.prev, x.next = p, p.next
    p.next.prev = x
    p.next = x
```

**그림으로 보기**

- 노드 하나를 떼어내는 일은 "양옆이 서로를 가리키게 하는" 대입 두 줄이다. 원소를 옮기지 않으므로 리스트가 아무리 길어도 O(1)이다.

```text
  before remove(C)
     HEAD <-> A <-> B <-> C <-> D <-> TAIL
                          ^ we already hold this node

  step 1 : B.next = C.next   -> D
  step 2 : D.prev = C.prev   -> B

  after
     HEAD <-> A <-> B <-> D <-> TAIL       # C detached, nothing shifted
```

- 커서 편집은 "커서 양쪽을 스택 두 개로" 보면 이동·삽입·삭제가 전부 top 조작이 된다.

```text
  text "abc", cursor at the end

     left = [ a, b, c ]    right = [ ]     # a b c |
                    ^ top                  #       ^ cursor

  L  : pop from left, push to right
     left = [ a, b ]       right = [ c ]   # a b | c

  B  : pop from left
     left = [ a ]          right = [ c ]   # a | c

  answer = left + reversed(right) = "ac"
```

- LRU는 이 리스트 위에 dict를 얹어 "키 → 노드"를 O(1)에 찾는 구조다. 찾기와 이동이 둘 다 O(1)이라야 전체가 O(1)이 된다.

```text
  recency list :  HEAD <-> k2 <-> k1 <-> k3 <-> TAIL
                          newest           oldest

  dict : k1 -> node(k1)      access k1
         k2 -> node(k2)        1) node = dict[k1]     # O(1) find
         k3 -> node(k3)        2) remove(node)        # O(1) unlink
                               3) add_front(node)     # O(1) relink

  after        :  HEAD <-> k1 <-> k2 <-> k3 <-> TAIL
  evict when full : the node sitting just before TAIL
```

**왜 이렇게 되는가**

- **왜 참조가 있으면 O(1)인가**: 배열의 중간 삭제는 뒤 원소를 전부 당겨야 하지만(O(n)), 연결 리스트는 "누가 누구를 가리키는가"만 고치면 되고 그 대상은 언제나 좌우 이웃 둘뿐이다. 길이와 무관하게 대입 두 번이라 O(1)이다. 단, **그 노드를 이미 손에 쥐고 있어야** 한다. 인덱스나 값으로 찾아가야 한다면 그 탐색에 O(n)이 들어 이점이 통째로 사라진다 — LRU가 dict를 곁들이는 이유가 정확히 이것이다.

- **왜 센티넬(더미) 노드를 두는가**: 맨 앞 노드를 지울 때 `x.prev`가 None이면 `x.prev.next`에서 터진다. 양끝에 값 없는 더미를 하나씩 두면 **모든 실제 노드가 "좌우 이웃이 반드시 있는" 상태**가 되어 경계 분기가 통째로 사라진다. 연결 리스트 버그의 대부분이 양끝에서 나오므로, 노드 두 개로 사는 안전이다.

- **양끝만 쓴다면 왜 deque인가**: `collections.deque`는 고정 크기 블록을 이어 붙인 구조라 `append/appendleft/pop/popleft`가 모두 O(1)이고, C로 구현되어 노드마다 파이썬 객체를 만드는 직접 구현보다 훨씬 빠르다. 반면 `deque`는 중간 삽입·삭제가 O(n)이다. **중간을 건드릴 일이 없으면 직접 만들지 말고, 건드려야 하면 직접 만들어라**가 갈림길이다.

**접근 전략**

- "중간 삽입·삭제가 잦고, 삭제할 위치를 인덱스가 아니라 참조/값→노드 매핑으로 알 수 있다"면 이중 연결 리스트다. 값→노드 dict를 곁들이면 "특정 값의 노드를 O(1)에 찾아 O(1)에 제거"가 가능해진다(LRU의 핵심). 센티넬 노드를 쓰면 head/tail이 None인지 매번 분기하지 않아 버그가 줄어든다. 양끝만 다루면 굳이 직접 구현 말고 `deque`(양끝 push/pop O(1))를 쓰는 게 정석.

- 시간복잡도: 참조가 있을 때 삽입·삭제 O(1), 탐색(값으로 찾기)은 dict 없으면 O(n). 공간 O(n)(노드당 포인터 2개 오버헤드). 흔한 실수: 삭제 시 양쪽 링크를 모두 갱신하지 않아 리스트가 끊김, 마지막/처음 노드 삭제 시 head/tail 갱신 누락(센티넬로 해결). 파이썬 팁: `sys.setrecursionlimit`은 여기선 무관하지만, 노드 클래스에 `__slots__`를 주면 메모리·속도 이득. 순수 양끝 큐/스택이면 deque가 정답.

**문제**

**1) 커서 텍스트 편집** · Medium

- **요구사항**: 문자들이 일렬로 있고 커서가 있다. `L`(커서 왼쪽 이동), `R`(오른쪽 이동), `P x`(커서 왼쪽에 문자 x 삽입), `B`(커서 왼쪽 문자 삭제) 연산을 처리하고 최종 문자열을 출력한다. 커서는 처음 맨 뒤에 있다.

- **입력**: 첫 줄 초기 문자열, 둘째 줄 연산 수 M, 이후 M줄에 연산.

- **출력**: 최종 문자열.

- **예제**: `abc / 2 / L / B` (커서 뒤→L로 c앞→B는 앞 문자 a? ) → `ac` , `x / 2 / P y / P z` → `xyz`

- **셀프체크**: 이 문제는 "커서 기준 양쪽 삽입/삭제"라 두 개의 스택(또는 센티넬 이중연결리스트)으로 O(1)씩. 예제1 검산: `abc` 커서 맨뒤 → L(커서가 c 앞) → B(커서 왼쪽=b 삭제) → `ac`. 각 연산 O(1), 전체 O(M). 경계(빈 왼쪽에서 B, 끝에서 R)를 무시하도록 처리.

```runner
@@SOLUTION
import sys
def main():
    lines=sys.stdin.read().split("\n")
    s=lines[0]
    m=int(lines[1])
    left=list(s)
    right=[]
    li=2
    for _ in range(m):
        parts=lines[li].split(); li+=1
        op=parts[0]
        if op=="L":
            if left:
                right.append(left.pop())
        elif op=="R":
            if right:
                left.append(right.pop())
        elif op=="P":
            left.append(parts[1])
        elif op=="B":
            if left:
                left.pop()
    print("".join(left)+"".join(reversed(right)))
main()
@@TESTS
--IN

B
--OUT
ac
--IN
x
2
P y
P z
--OUT

@@EXPL
**이 풀이의 새 문법**

- `reversed(seq)`: 시퀀스를 역순으로 순회하는 이터레이터를 만든다. `"".join(reversed(right))`는 right 리스트를 뒤에서부터 이어 붙인 문자열을 만든다.

(1) 접근·핵심 아이디어

- 커서 기준의 양쪽 삽입/삭제는 "두 스택" 기법으로 모든 연산을 O(1)에 처리한다. 커서 왼쪽 문자들을 `left` 스택(top이 커서 바로 왼쪽), 오른쪽 문자들을 `right` 스택(top이 커서 바로 오른쪽)에 담는다. 커서 이동은 한 스택의 top을 다른 스택으로 옮기는 것이다.

(2) 코드 단계별

- 초기 문자열을 `left`에 통째로 담는다(커서가 맨 뒤 = 모든 글자가 왼쪽). `right`는 비어 있다.
- `L`: `left`가 비어 있지 않으면 pop한 문자를 `right`에 push(커서 왼쪽으로 한 칸).
- `R`: `right`가 비어 있지 않으면 pop해 `left`에 push(오른쪽으로 한 칸).
- `P x`: 커서 왼쪽에 삽입 = `left`에 push.
- `B`: 커서 왼쪽 문자 삭제 = `left`가 비어 있지 않으면 pop.
- 최종 문자열은 `left`(순서대로) + `right`를 뒤집은 것.

(3) 스스로 다시 짤 때 생각 순서

- "커서 양옆 O(1) 조작"을 보면 두 스택(또는 센티넬 이중연결리스트)을 떠올린다.
- 각 연산이 어느 스택의 top을 건드리는지 그림으로 정리한다(L/R은 top 이동, P/B는 left만).
- 마지막에 right는 커서에서 먼 순서로 쌓였으므로 뒤집어 붙인다. 경계(빈 스택에서 L/R/B)는 무시.
```

**2) 요세푸스 제거 순서** · Medium

- **요구사항**: 1..N이 원형으로 있고, 1번부터 시작해 K번째 사람을 반복해서 제거한다. 제거되는 순서를 출력한다.

- **입력**: 첫 줄 N K.

- **출력**: 제거 순서를 공백으로.

- **예제**: `7 3` → `3 6 2 7 5 1 4` , `5 2` → `2 4 1 5 3`

- **셀프체크**: 원형 이중 연결 리스트에서 K-1칸 전진 후 현재 노드 제거(O(1) 재연결)를 N번. 제거 후 다음 시작은 제거된 노드의 다음. 전체 O(N·K). 검산(N=5,K=2): 시작1→2제거, 3→4제거, 5→1제거, 3→5제거, 남은3. 원형이라 head/tail 개념 없이 자기 참조로 닫는 처리가 함정.

```runner
@@SOLUTION
import sys
def main():
    data=sys.stdin.read().split()
    n=int(data[0]); k=int(data[1])
    nxt=[0]*(n+1)
    prv=[0]*(n+1)
    for i in range(1,n+1):
        nxt[i]=i+1 if i<n else 1
        prv[i]=i-1 if i>1 else n
    res=[]
    cur=1
    for _ in range(n):
        for _ in range(k-1):
            cur=nxt[cur]
        res.append(cur)
        p=prv[cur]; q=nxt[cur]
        nxt[p]=q; prv[q]=p
        cur=q
    print(" ".join(map(str,res)))
main()
@@TESTS
--IN
7 3
--OUT
3 6 2 7 5 1 4
--IN
5 2
--OUT
2 4 1 5 3
@@EXPL
(1) 접근·핵심 아이디어

- 원형 이중 연결 리스트를 배열 `nxt`, `prv`로 표현한다(노드 i의 다음/이전). 1번에서 시작해 K-1칸 전진한 노드가 이번에 제거될 사람이다. 제거는 양쪽 링크를 이어 붙이는 O(1) 연산이고, 다음 카운트는 제거된 노드의 다음에서 시작한다. 이를 N번 반복.

(2) 코드 단계별

- `nxt[i]`, `prv[i]`를 1..N 원형으로 초기화(N의 다음은 1, 1의 이전은 N).
- `cur = 1`에서 시작. 각 라운드마다 `cur = nxt[cur]`를 K-1번 반복해 K번째 사람에 도달.
- 그 노드를 결과에 기록하고, `nxt[prv]=nxt`, `prv[nxt]=prv`로 링크에서 분리한다.
- 다음 시작 `cur`는 제거된 노드의 다음(q)으로 둔다. N번 반복 후 제거 순서를 공백 출력.

(3) 스스로 다시 짤 때 생각 순서

- "원형으로 돌며 K번째 제거"를 보면 원형 연결 리스트(배열 nxt/prv)를 떠올린다.
- 시작점(1번)에서 첫 제거까지 몇 칸 전진하는지 손으로 세어 K-1임을 확정한다.
- 제거 후 재연결과 다음 시작 위치(제거 노드의 다음)를 정확히 갱신한다. 원형이라 head/tail 경계 분기가 없다.
```

**3) 최근 사용 캐시(LRU) 시뮬레이션** · Hard

- **요구사항**: 용량 C의 캐시가 있다. `1 k`(키 k 접근: 있으면 최근 사용으로 갱신, 없으면 삽입하고 가득 차 있으면 가장 오래된 것 제거), 각 연산 후 캐시에 남은 키들을 "최근 사용 순"으로 출력한다.

- **입력**: 첫 줄 C Q, 이후 Q줄에 `1 k`.

- **출력**: 각 연산 후 최근→오래된 순으로 키를 공백으로(빈 줄 가능).

- **예제**: `2 3 / 1 1 / 1 2 / 1 1` → 각 줄 `1` , `1 2` , `1 2` ; `1 2 / 1 5 / 1 6` → `5` , `6 5`

- **셀프체크**: 이중 연결 리스트(사용 순서) + dict(키→노드). 접근 시 해당 노드를 떼어 맨 앞으로 이동(O(1)), 초과 시 tail 앞 노드 제거. 모든 연산 O(1). 첫 예제 검산: [1]→[2,1]→1재접근 앞으로 [1,2]. 링크 이동 시 dict의 노드 참조가 유지되는지, 제거된 키를 dict에서도 지웠는지 확인.

```runner

import sys
def main():
    data=sys.stdin.read().split("\n")
    first=data[0].split()
    c=int(first[0]); q=int(first[1])
    nxt={}; prv={}
    HEAD=object(); TAIL=object()
    nxt[HEAD]=TAIL; prv[TAIL]=HEAD
    keys=set()
    def add_front(k):
        f=nxt[HEAD]
        nxt[HEAD]=k; prv[k]=HEAD
        nxt[k]=f; prv[f]=k
    def remove(k):
        p=prv[k]; nn=nxt[k]
        nxt[p]=nn; prv[nn]=p
    out=[]
    li=1
    for _ in range(q):
        parts=data[li].split(); li+=1
        k=parts[1]
        if k in keys:
            remove(k)
            add_front(k)
        else:
            if len(keys)>=c:
                last=prv[TAIL]
                remove(last)
                keys.discard(last)
            add_front(k)
            keys.add(k)
        res=[]
        cur=nxt[HEAD]
        while cur is not TAIL:
            res.append(cur)
            cur=nxt[cur]
        out.append(" ".join(res))
    print("\n".join(out))
main()

**이 풀이의 새 문법**

- `object()`: 아무 속성도 없는 유일한 객체 인스턴스를 생성한다. 다른 어떤 값과도 같지 않으므로 HEAD/TAIL처럼 "구분만 되면 되는" 센티넬 표식으로 쓴다.

(1) 접근·핵심 아이디어

- LRU 캐시의 정석은 "사용 순서를 담은 이중 연결 리스트 + 키→노드 dict"다. HEAD 쪽이 최근, TAIL 쪽이 오래된 것. 접근한 키는 리스트에서 떼어(remove) 맨 앞에 다시 붙인다(add_front). 용량 초과 삽입이면 TAIL 바로 앞(가장 오래된) 노드를 제거한다. 모든 연산이 O(1).

(2) 코드 단계별

- HEAD/TAIL 센티넬을 두고 `nxt`, `prv` dict로 링크를 관리한다(경계 분기 제거).
- `1 k`: 이미 있으면 remove 후 add_front(최근으로 갱신). 없으면 용량이 찼을 때 `prv[TAIL]`(가장 오래된)을 remove하고 keys에서도 지운 뒤, add_front + keys에 추가.
- 매 연산 후 HEAD 다음부터 TAIL 전까지 순회해 "최근→오래된" 순으로 키를 모아 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "최근 사용 순 유지 + O(1) 이동/제거"를 보면 이중 연결 리스트 + dict(LRU 표준 조합)를 떠올린다.
- 센티넬 HEAD/TAIL을 쓰면 맨 앞 삽입·맨 뒤 제거를 분기 없이 처리할 수 있다.
- 제거할 때 링크뿐 아니라 존재 집합(keys)에서도 반드시 지운다. 최근 갱신은 "떼서 앞으로"로 구현한다.
```

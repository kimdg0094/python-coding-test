## L3. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch04(Greedy)의 핵심 — "무엇을 기준으로 정렬·선택할 것인가"를 정하고 **교환 논증으로 정당성을 확인**하는 그리디, 그리고 **왼쪽부터 강제 확정되는 상태 반전** 유형 — 을 소재만 바꿔 **반복 훈련**하고, 코딩테스트 단골 유형(구명보트·큰 수 만들기·마감 작업 선택·구간 커버 류)으로 **확장**하는 연습 세트다.
- **반복 훈련 개념**:
  - 정렬 기준 확정 후 순서대로 결정: `items.sort(key=...)` → 순서대로 보며 규칙을 안 깨면 즉시 확정. 기준의 반례를 먼저 찾아보고, 없으면 교환 논증으로 확신을 얻는다.
  - 정렬 후 짝짓기(투 포인터): 두 배열을 정렬하고 `i`, `j`를 한 방향으로만 전진 — `if b[j] >= a[i]: i += 1; j += 1` / `else: j += 1`.
  - 구간 스케줄링 + `heapq`: 시작 시각 순으로 훑으며 힙에 "진행 중인 구간의 종료 시각"을 두고 `if heap[0] <= s: heappop(heap)` 후 `heappush(heap, e)`.
  - 상태 반전(왼→오 강제): `if a[i-1] != goal[i-1]: press(i)` — 왼쪽 칸을 고칠 마지막 기회에서 반드시 누른다. 자유도가 남으면 첫 조작(또는 행 전체)을 완전탐색한 뒤 나머지를 강제한다.
  - 스택 그리디(사전순 최소): `while stack and k > 0 and stack[-1] > ch: stack.pop(); k -= 1` 후 `stack.append(ch)`.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '그리디 알고리즘' 단계(ATM 대기·회의실 배정·동전 류), 프로그래머스 「코딩테스트 고득점 Kit」의 '탐욕법'(구명보트·큰 수 만들기·체육복 류), 『이것이 취업을 위한 코딩테스트다』의 '그리디' 파트, NeetCode 150의 'Greedy'·'Intervals'.
- **문제 구성표**:

**문제**

**1) 창구 총 대기시간 최소화** · Easy

- **요구사항**: 창구 하나에 N명이 줄을 선다. i번째 사람의 업무 처리 시간은 t_i분이고, 줄 서는 순서는 자유롭게 정할 수 있다. 각 사람이 **자기 업무가 끝날 때까지 기다린 시간**(앞사람들의 처리 시간 합 + 자기 처리 시간)의 총합이 최소가 되도록 배치하고, 그 최솟값을 출력하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 t_i N개(1 ≤ t_i ≤ 10^3).
- **출력**: 총 대기 시간의 최솟값.
- **예제**: `4 / 5 2 8 1` → `28` · `3 / 4 4 4` → `24`
- **셀프체크**: 처리 시간이 짧은 사람부터. i번째로 서는 사람의 t는 자기 뒤 모든 사람의 대기에도 더해지므로 총합에 (N-i+1)번 기여한다 → 큰 t가 앞에 있으면 인접한 둘을 바꿔서 손해 없이 줄일 수 있다(교환 논증). 예제1: 정렬 `1 2 5 8` → 누적 1, 3, 8, 16 → 합 28. 정렬 없이 입력 순서대로 더하면 5, 7, 15, 16 → 43으로 틀린다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    t = sorted(int(v) for v in data[1:1 + n])   # 짧은 업무부터
    total, cur = 0, 0
    for x in t:
        cur += x                 # 이 사람이 끝나는 시각
        total += cur             # = 이 사람의 대기 시간
    print(total)

main()
@@TESTS
--IN
4
5 2 8 1
--OUT
28
--IN
3
4 4 4
--OUT
24
--IN
1
7
--OUT
7
@@EXPL
(1) 접근·핵심 아이디어

- 순서를 정했을 때 총 대기 시간은 "누적합의 합"이다. 앞에 선 사람의 처리 시간은 뒤에 선 모든 사람의 대기에 반복해서 더해지므로, 짧은 업무를 앞에 둘수록 총합이 작다.
- 교환 논증: 인접한 두 사람 a(앞)·b(뒤)에서 `t_a > t_b`라면 둘을 바꿔도 다른 사람의 대기는 그대로이고, 두 사람의 대기 합은 `t_a + (t_a + t_b)`에서 `t_b + (t_b + t_a)`로 `t_a - t_b`만큼 줄어든다. 따라서 오름차순이 아닌 배치는 항상 개선 가능 → 오름차순이 최적.

(2) 코드 단계별

- 처리 시간을 읽어 오름차순 정렬한다.
- `cur`에 처리 시간을 누적하며(= 이 사람이 끝나는 시각), 그 값을 `total`에 더한다.
- `total` 출력. N=1이면 그 사람의 처리 시간 그대로.

(3) 스스로 다시 짤 때 생각 순서

- "앞사람의 시간이 뒷사람 전원에게 더해진다"는 구조를 먼저 본다 → 작은 것을 앞에.
- 정렬 기준의 정당성을 인접 교환으로 한 줄 증명한다.
- 누적합을 한 번 더 누적하는 이중 합을 O(N)으로 계산한다(정렬 O(N log N)이 지배).
```

**2) 상자에 물품 최대 매칭** · Easy

- **요구사항**: 상자 N개(크기 b_j)와 물품 M개(크기 s_i)가 있다. 물품은 **자기 크기 이상인 상자**에만 들어가고, 상자 하나에는 물품 하나만 넣는다. 최대 몇 개의 물품을 상자에 넣을 수 있는가.
- **입력**: 첫 줄 N M(1 ≤ N, M ≤ 10^5), 둘째 줄 상자 크기 N개, 셋째 줄 물품 크기 M개(1 ≤ 크기 ≤ 10^9).
- **출력**: 넣을 수 있는 최대 물품 수.
- **예제**: `3 3 / 4 6 2 / 3 5 7` → `2` · `2 3 / 10 10 / 1 1 1` → `2`
- **셀프체크**: 둘 다 오름차순 정렬 후, 가장 작은 물품부터 "그 물품이 들어가는 가장 작은 상자"에 넣는다. 교환 논증: 작은 물품에 큰 상자를 쓰면 큰 물품이 들어갈 상자가 사라질 수 있지만, 반대로 바꿔도 개수는 줄지 않는다. 투 포인터 `i`(물품), `j`(상자): `box[j] >= item[i]`면 둘 다 전진(매칭), 아니면 이 상자는 어떤 남은 물품도 못 담으니 `j`만 전진. 예제1: 상자 `2 4 6`, 물품 `3 5 7` → 3→4, 5→6, 7은 못 넣음 → 2.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0]); m = int(data[1])
    boxes = sorted(int(v) for v in data[2:2 + n])
    items = sorted(int(v) for v in data[2 + n:2 + n + m])
    i = j = cnt = 0
    while i < m and j < n:
        if boxes[j] >= items[i]:     # 가장 작은 물품을 담을 수 있는 가장 작은 상자
            cnt += 1
            i += 1
            j += 1
        else:                        # 이 상자는 남은 어떤 물품도 못 담음
            j += 1
    print(cnt)

main()

--IN

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 작은 물품은 어느 상자에나 잘 들어가고, 작은 상자는 작은 물품만 담을 수 있다. 그래서 **가장 작은 물품을 그것이 들어가는 가장 작은 상자**에 넣는 것이 자원을 가장 아끼는 선택이다.
- 교환 논증: 어떤 최적 매칭에서 가장 작은 물품 s가 상자 B에 있고, 더 작은 상자 B'(s가 들어감)가 다른 물품 s'에 쓰였거나 비어 있다고 하자. s와 s'의 상자를 맞바꾸면 s' ≥ s이고 B ≥ B' ≥ s이므로 s'가 B에 들어갈지가 문제인데, 원래 s'가 B'에 들어갔다면 s' ≤ B' ≤ B라 여전히 들어간다. 개수는 그대로 → 그리디 선택을 포함하는 최적해가 존재한다.

(2) 코드 단계별

- 상자·물품을 각각 오름차순 정렬한다.
- 투 포인터: `boxes[j] >= items[i]`면 매칭(cnt, i, j 모두 증가), 아니면 상자만 버린다(j 증가).
- 둘 중 하나가 소진되면 종료, cnt 출력.

(3) 스스로 다시 짤 때 생각 순서

- "한쪽은 한 번만 쓰이고, 조건이 크기 비교"면 정렬 후 투 포인터 매칭을 떠올린다.
- 어느 포인터를 언제 전진시킬지 규칙 두 줄을 먼저 확정한다.
- 경계: 물품이 모두 상자보다 크면 0, 상자가 남아도 물품이 없으면 종료.
```

**3) 모든 강의 수용 최소 강의실 수** · Medium

- **요구사항**: 강의 N개의 시작·종료 시각이 주어진다. 한 강의실에서는 시간이 겹치는 강의를 동시에 할 수 없다(한 강의의 종료 시각과 다른 강의의 시작 시각이 같으면 같은 강의실 사용 가능). **모든 강의**를 배정하는 데 필요한 **최소 강의실 수**를 구하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 이후 N줄에 `s e`(0 ≤ s < e ≤ 10^9).
- **출력**: 최소 강의실 수.
- **예제**: `3 / 1 3 / 2 4 / 3 5` → `2` · `4 / 0 10 / 2 3 / 4 5 / 6 7` → `2`
- **셀프체크**: 이번엔 **시작 시각 순** 정렬이다(L1의 "최대 회의 수"는 종료 시각 순이었다 — 목적이 다르면 기준도 다르다). 최소 힙에 "진행 중인 강의의 종료 시각"을 두고, 새 강의 s가 힙 최소값 이상이면 그 강의실을 재사용(pop) 후 push, 아니면 새 강의실(push만). 힙 크기의 최댓값이 답 = 어느 순간 동시에 진행되는 강의의 최대 수. 등호 `heap[0] <= s`를 `<`로 쓰면 예제1의 `1 3`과 `3 5`가 다른 강의실로 잡혀 3이 나온다.

```runner
@@SOLUTION
import sys, heapq

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    lect = []
    for i in range(n):
        s = int(data[1 + 2 * i]); e = int(data[2 + 2 * i])
        lect.append((s, e))
    lect.sort()                       # 시작 시각 순
    ends = []                         # 진행 중 강의의 종료 시각(최소 힙)
    best = 0
    for s, e in lect:
        if ends and ends[0] <= s:     # 가장 일찍 끝나는 강의실이 비었으면 재사용
            heapq.heappop(ends)
        heapq.heappush(ends, e)
        if len(ends) > best:
            best = len(ends)
    print(best)

main()

(1) 접근·핵심 아이디어

- 필요한 강의실 수의 하한은 "어느 시각에 동시에 진행되는 강의의 최대 수"이고, 시작 시각 순으로 배정하면 정확히 그만큼만 쓴다. 강의를 시작 순으로 보며, 이미 끝난 강의실이 있으면 재사용하고 없으면 새로 연다.
- 정당성: 새 강의를 배정하는 시점에 비어 있는 강의실이 하나라도 있는데 새 강의실을 열 이유가 없고, 비어 있는 강의실이 없다면 지금 진행 중인 강의 수 + 1개가 동시에 겹치므로 어떤 배정도 그만큼은 필요하다.
- "가장 일찍 끝나는 진행 중 강의"를 빠르게 알기 위해 종료 시각 최소 힙을 쓴다.

(2) 코드 단계별

- `(s, e)`를 모아 시작 시각 순으로 정렬한다.
- 각 강의에서 힙 최소 종료 시각이 `s` 이하면 pop(그 강의실 비움), 그다음 `e`를 push.
- push 후 힙 크기가 동시 진행 수이므로 최댓값을 갱신한다.

(3) 스스로 다시 짤 때 생각 순서

- "겹치지 않게 최대 개수"(종료 순)와 "전부 배정에 필요한 최소 수"(시작 순 + 힙)를 구분한다.
- 등호 처리(종료 = 시작 허용)를 `<=`로 둔다.
- 힙 크기 최댓값이 답임을 "동시 진행 수"로 해석해 검산한다. 복잡도 O(N log N).
```

**4) 2인승 카트 최소 대수** · Medium

- **요구사항**: 놀이공원 카트는 한 대에 **최대 2명**까지 타고, 탑승자 무게 합이 L을 넘으면 안 된다. 사람 N명의 무게가 주어질 때(모두 L 이하) 전원을 태우는 **최소 카트 대수**를 구하라.
- **입력**: 첫 줄 N L(1 ≤ N ≤ 10^5, 1 ≤ L ≤ 10^4), 둘째 줄 무게 N개(1 ≤ w_i ≤ L).
- **출력**: 최소 대수.
- **예제**: `5 120 / 90 30 60 70 40` → `3` · `3 50 / 50 50 50` → `3`
- **셀프체크**: 정렬 후 가장 무거운 사람(`hi`)을 태울 때, 가장 가벼운 사람(`lo`)과 합이 L 이하면 함께 태우고 아니면 혼자 태운다. 교환 논증: 가장 무거운 사람과 짝이 될 수 있는 사람이 있다면 가장 가벼운 사람을 붙여도 손해가 없다(가벼운 사람의 원래 짝은 대신 그 사람과 짝이 될 수 있음). 예제1: 정렬 `30 40 60 70 90` → (90,30), (70,40), (60) → 3. `lo == hi`(한 명 남음)일 때 한 대 더 세는 것을 잊지 말 것.

```runner
@@SOLUTION
import sys

def main():
```

**5) 자릿수 K개 지워 최소 수 만들기** · Medium

- **요구사항**: 숫자 문자열 num(선행 0 없음)에서 자릿수 **K개를 지워**(남은 자릿수의 순서는 유지) 만들 수 있는 **가장 작은 수**를 구하라. 결과의 선행 0은 제거하고, 남은 것이 0뿐이면 `0`.
- **입력**: 한 줄에 `num K`(1 ≤ len(num) ≤ 10^5, 0 ≤ K < len(num)).
- **출력**: 최소 수(선행 0 없이).
- **예제**: `7412358 3` → `1235` · `20305 1` → `305`
- **셀프체크**: 왼쪽부터 스택에 쌓되, 새 자릿수가 스택 맨 위보다 **작으면** 맨 위를 지운다(k 소모). 앞자리가 작을수록 수가 작으므로 "내림 지점의 큰 앞자리"를 지우는 것이 최적(교환 논증). 다 훑고도 k가 남으면 스택은 오름차순이므로 **뒤에서** k개 제거. 예제2: `2` 뒤에 `0`이 오면 2를 지워 `0305` → 선행 0 제거 → `305`. `lstrip('0')` 결과가 빈 문자열이면 `0`.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    num = data[0]; k = int(data[1])
    stack = []
    for ch in num:
        while stack and k > 0 and stack[-1] > ch:   # 앞자리가 더 크면 지운다
            stack.pop()
            k -= 1
        stack.append(ch)
    if k > 0:                          # 남은 k: 스택은 오름차순 → 뒤에서 제거
        stack = stack[:-k]
    ans = "".join(stack).lstrip("0")
    print(ans if ans else "0")

main()

- 두 수의 길이가 같으면 앞자리부터 비교하므로, 앞쪽 자릿수를 작게 만드는 것이 우선이다. 왼쪽부터 보다가 `stack[-1] > ch`인 "내림 지점"을 만나면 큰 앞자리를 지우는 것이 그 자리를 작게 만드는 유일한 방법이다.
- 교환 논증: 어떤 최적해가 내림 지점의 큰 앞자리 d를 남기고 다른 자리 x를 지웠다면, x 대신 d를 지워도 앞쪽에서 더 작은 자릿수가 먼저 오므로 결과가 커지지 않는다. 따라서 "내림 지점에서 앞자리 제거"를 반복하는 스택 그리디가 최적이다.
- 끝까지 봤는데 k가 남았다면 스택이 오름차순(내림 지점이 없었다)이므로 가장 큰 뒷자리부터 지운다.

(2) 코드 단계별

- 자릿수를 순서대로 보며, k가 남아 있고 스택 맨 위가 현재 자릿수보다 크면 pop·k 감소를 반복한 뒤 push.
- 루프 후 k가 남으면 `stack[:-k]`.
- 선행 0을 `lstrip("0")`으로 제거하고, 빈 문자열이면 `"0"` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "K개 지워 사전순/수치 최소" → 스택 그리디 틀을 꺼낸다(최대를 만들 땐 부등호만 반대).
- 남은 k의 뒤쪽 제거와 선행 0 처리 두 가지 마무리를 잊지 않는다.
- 경계: 0이 앞으로 오는 경우(예제2·3), 완전 내림차순(예제4), 전부 같은 자릿수(`1111 2` → `11`, 남은 k를 뒤에서 지우는 경우).
```

**6) 만들 수 없는 최소 금액** · Medium

- **요구사항**: 동전 N개의 액면이 주어진다(같은 액면이 여러 개일 수 있다). 이 동전들 중 **일부(0개 이상)를 골라 합**으로 만들 수 없는 **가장 작은 양의 정수 금액**을 구하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 액면 N개(1 ≤ 액면 ≤ 10^6).
- **출력**: 만들 수 없는 최소 금액.
- **예제**: `6 / 1 1 2 5 10 20` → `40` · `3 / 2 3 4` → `1`
- **셀프체크**: 오름차순 정렬 후 "1부터 `reach`까지 전부 만들 수 있다"를 유지한다. 다음 동전 c가 `reach + 1`보다 크면 `reach + 1`은 어떤 조합으로도 못 만든다 → 답. 아니면 `reach += c`(1..reach의 각 합에 c를 더해 1..reach+c 전부 가능 — 귀납 논증). 예제1: reach 0→1→2→4→9→19→39, 다음 동전 없음 → 40. 첫 동전이 1이 아니면 답은 1(예제2). 정렬을 잊으면 큰 동전이 먼저 나와 조기에 잘못 끊긴다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    coins = sorted(int(v) for v in data[1:1 + n])
    reach = 0                        # 1..reach 는 전부 만들 수 있음
    for c in coins:
        if c > reach + 1:            # reach+1 을 만들 방법이 없다
            break
        reach += c                   # 1..reach+c 전부 가능해짐
    print(reach + 1)

main()

(1) 접근·핵심 아이디어

- 불변식 "1부터 reach까지는 전부 만들 수 있다"를 작은 동전부터 확장한다. 동전 c(≤ reach+1)를 추가하면, 기존 합 0..reach 각각에 c를 더한 c..reach+c도 가능해지고 c ≤ reach+1이라 구간이 끊기지 않으므로 1..reach+c 전부 가능하다.
- 반대로 c > reach+1이면, 지금까지의 동전으로는 reach+1을 못 만들고(최대 reach), 남은 동전은 전부 c 이상이라 하나만 써도 reach+1을 넘는다. 따라서 reach+1이 답이다.
- 이 논증이 "작은 동전부터 본다"는 정렬 기준의 정당성이다.

(2) 코드 단계별

- 액면을 오름차순 정렬, `reach=0`.
- 각 동전 c에 대해 `c > reach + 1`이면 중단, 아니면 `reach += c`.
- `reach + 1` 출력(끝까지 다 더했으면 총합+1).

(3) 스스로 다시 짤 때 생각 순서

- "만들 수 없는 최소"를 보면 "연속으로 만들 수 있는 구간 [1, reach]"를 키우는 그림을 그린다.
- 끊기는 조건(`c > reach + 1`)과 확장 규칙을 귀납으로 검산한다.
- 경계: 1이 없으면 답 1, 동전 하나 `1`이면 답 2.
```

**7) 양옆까지 반전하는 스위치** · Medium

- **요구사항**: 전구 N개가 일렬로 있고 각 전구는 0(꺼짐) 또는 1(켜짐)이다. 스위치 i를 누르면 전구 i-1, i, i+1(존재하는 것만)의 상태가 반전된다. 초기 상태를 **목표 상태**로 만드는 최소 누름 횟수를 구하라. 불가능하면 -1.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 초기 상태(길이 N의 0/1 문자열), 셋째 줄 목표 상태(길이 N).
- **출력**: 최소 누름 횟수 또는 -1.
- **예제**: `3 / 000 / 111` → `1` · `2 / 01 / 00` → `-1`
- **셀프체크**: 전구 0을 바꿀 수 있는 스위치는 0번과 1번 두 개라 강제성이 바로 생기지 않는다 → **스위치 0을 누를지 말지 2가지**를 완전탐색하고, 그 뒤 i=1..N-1에서 "전구 i-1이 목표와 다르면 스위치 i를 반드시 누른다"(전구 i-1을 고칠 마지막 기회)로 강제 확정. 마지막에 전구 N-1이 목표와 같은지 검증하고, 두 경우 중 가능한 것의 최솟값. 예제1: 스위치 1 한 번으로 000→111. 예제2: 두 스위치 모두 전구 0,1을 같이 뒤집으므로 01을 00으로 만들 수 없다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    init = [ord(c) - 48 for c in data[1]]
    goal = [ord(c) - 48 for c in data[2]]

    def press(a, i):                  # 스위치 i: i-1, i, i+1 반전
        for j in (i - 1, i, i + 1):
            if 0 <= j < n:
                a[j] ^= 1

    def solve(first):                 # first=1이면 스위치 0을 누르고 시작
        a = init[:]
        cnt = 0
        if first:
            press(a, 0)
            cnt = 1
        for i in range(1, n):
            if a[i - 1] != goal[i - 1]:   # 전구 i-1을 고칠 마지막 기회 = 스위치 i
                press(a, i)
                cnt += 1
        return cnt if a[n - 1] == goal[n - 1] else -1

    results = [r for r in (solve(0), solve(1)) if r != -1]
    print(min(results) if results else -1)

main()

- 반전은 두 번 하면 원상복귀이고 순서가 무관하므로 각 스위치는 0/1번만 누른다. 전구 i-1을 건드리는 스위치는 i-2, i-1, i 셋인데, 왼쪽부터 확정해 나가면 i-2, i-1은 이미 결정됐으므로 **전구 i-1의 최종 상태는 스위치 i로만 바꿀 수 있다** → 강제.
- 단, 전구 0은 스위치 0과 1 둘 다 건드려 첫 결정이 강제되지 않는다. 그래서 스위치 0을 누를지 말지 2가지만 완전탐색하고 나머지는 강제 그리디로 결정한다. 마지막 전구 N-1은 더 이상 고칠 스위치가 없으므로 끝에서 검증한다.

- 끝에서 전구 N-1이 목표와 같으면 횟수, 아니면 -1.
- 두 경우 결과 중 -1이 아닌 것의 최솟값을 출력, 둘 다 -1이면 -1.

(3) 스스로 다시 짤 때 생각 순서

- "왼쪽 칸을 고치는 조작이 유일한가?"를 묻고, 유일하지 않으면 그 자유도(여기선 1비트)만 완전탐색한다.
- 나머지는 강제 그리디, 끝 검증으로 불가능을 걸러낸다. 전체 O(2·N).
- 경계: N=1(스위치 0만 존재), N=2(두 스위치가 같은 효과 → 홀수 차이면 불가능).
```

**8) 마감 있는 과제 최대 점수** · Hard

- **요구사항**: 과제 N개가 있고, 각 과제는 마감일 d_i와 점수 p_i를 가진다. 하루에 과제 하나만 완료할 수 있고(1일부터 시작), 과제는 **d_i일 이내(d_i일 포함)** 에 완료해야 점수를 얻는다. 얻을 수 있는 **최대 총점**을 구하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 이후 N줄에 `d p`(1 ≤ d ≤ 10^5, 1 ≤ p ≤ 10^4).
- **출력**: 최대 총점.
- **예제**: `4 / 1 30 / 2 20 / 2 10 / 1 40` → `60` · `3 / 3 5 / 3 6 / 3 7` → `18`
- **셀프체크**: 마감 오름차순으로 훑으며 점수를 **최소 힙**에 넣고, 힙 크기가 현재 마감 d를 넘으면(d일까지는 최대 d개만 할 수 있으므로) 가장 낮은 점수를 버린다. 교환 논증: 마감 d 이하 과제 중 d개를 초과해 고를 수 없고, 초과분을 버릴 때 가장 낮은 점수를 버리는 것이 손해 없다. 힙에 남은 점수의 합이 답. 예제1: 마감 1인 두 과제(30, 40) 중 40만, 마감 2까지 두 개 → 40+20 = 60. 마감이 같은 과제가 여럿이어도 규칙은 같다.

```runner
@@SOLUTION
import sys, heapq

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    tasks = []
    for i in range(n):
        d = int(data[1 + 2 * i]); p = int(data[2 + 2 * i])
        tasks.append((d, p))
    tasks.sort()                      # 마감 오름차순
    chosen = []                       # 선택한 과제 점수의 최소 힙
    for d, p in tasks:
        heapq.heappush(chosen, p)
        if len(chosen) > d:           # d일까지 d개 초과는 불가 → 가장 낮은 점수 포기
            heapq.heappop(chosen)
    print(sum(chosen))

main()

(1) 접근·핵심 아이디어

- 선택한 과제 집합이 "실행 가능"하려면, 모든 d에 대해 "마감 ≤ d인 선택 과제 수 ≤ d"여야 한다(마감 순으로 하루 하나씩 처리하면 충분하고, 위반하면 어떻게 배치해도 불가능). 이 조건은 마감 오름차순으로 훑으며 개수만 세면 확인된다.
- 교환 논증: 마감 d 과제까지 넣었을 때 개수가 d를 넘으면 하나를 버려야 하는데, 지금 힙에 있는 것 중 가장 낮은 점수 q를 버리는 것이 최선이다. 어떤 최적해가 q를 남기고 더 높은 점수 r을 버렸다면, q와 r을 바꿔도 마감 조건(개수)은 동일하게 만족하면서 총점은 커지거나 같다.
- 따라서 "넣고, 초과하면 최소 버림"을 반복한 힙의 합이 최대 총점이다. 복잡도 O(N log N).

(2) 코드 단계별

- `(d, p)`를 마감 오름차순 정렬한다.
- 각 과제 점수를 최소 힙에 push, 힙 크기가 `d`를 넘으면 pop(가장 낮은 점수 제거).
- 힙에 남은 점수의 합을 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "마감 + 하루 하나 + 최대 이득"을 보면 마감 정렬 + 힙 교체 틀을 떠올린다.
- 실행 가능 조건(마감 ≤ d인 선택 수 ≤ d)을 먼저 명시하고, 초과 시 최소를 버리는 것이 왜 안전한지 교환으로 설명한다.
- 경계: 같은 마감 여러 개(예제1·2), 마감 1이 여러 개면 하나만(예제3), 전부 선택 가능한 경우(예제4).
```

**9) 정원 전체에 물 주는 최소 스프링클러** · Hard

- **요구사항**: 정원은 수직선 위 구간 [0, L]이다. 스프링클러 N개가 있고, i번째는 위치 x_i에서 반경 r_i까지, 즉 구간 [x_i − r_i, x_i + r_i]을 적신다. [0, L]의 **모든 지점**을 적시기 위해 켜야 하는 스프링클러의 **최소 개수**를 구하라. 불가능하면 -1.
- **입력**: 첫 줄 L N(1 ≤ L ≤ 10^9, 1 ≤ N ≤ 10^5), 이후 N줄에 `x r`(0 ≤ x ≤ L, 0 ≤ r ≤ 10^9).
- **출력**: 최소 개수 또는 -1.
- **예제**: `10 4 / 2 3 / 6 2 / 9 1 / 3 1` → `3` · `5 2 / 1 1 / 4 1` → `-1`
- **셀프체크**: 구간을 시작점 순으로 정렬하고, `covered`(현재까지 덮인 오른쪽 끝, 처음 0)를 유지한다. 시작점이 `covered` 이하인 구간들 중 **오른쪽 끝이 가장 큰 것**을 골라 `covered`를 갱신하고 개수 +1. 갱신이 안 되면(구멍) -1. 교환 논증: 같은 지점을 이어 덮을 수 있는 후보 중 더 멀리 뻗는 것을 골라도 이후 선택지가 줄지 않는다. 예제1: [-1,5]로 5까지, [4,8]로 8까지, [8,10]으로 10 → 3. 구간 끝이 정확히 맞닿는 것(2와 2)은 덮인 것으로 본다. r=0인 스프링클러는 점만 적셔 도움이 안 된다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    L = int(data[0]); n = int(data[1])
    iv = []
    for i in range(n):
        x = int(data[2 + 2 * i]); r = int(data[3 + 2 * i])
        iv.append((x - r, x + r))
    iv.sort()                         # 시작점 순
    covered, cnt, i = 0, 0, 0
    while covered < L:
        best = covered
        while i < n and iv[i][0] <= covered:   # 덮인 끝에 닿는 구간들 중
            if iv[i][1] > best:
                best = iv[i][1]                # 가장 멀리 뻗는 것
            i += 1
        if best == covered:           # 더 못 뻗음 → 구멍
            print(-1)
            return
        covered = best
        cnt += 1
    print(cnt)

main()

(1) 접근·핵심 아이디어

- [0, L]을 왼쪽부터 덮어 나간다. 현재 덮인 끝 `covered`에서 "시작점 ≤ covered"인 구간만이 끊김 없이 이어 덮을 수 있고, 그중 오른쪽 끝이 가장 큰 구간을 고르는 것이 최선이다.
- 교환 논증: 최적해가 이 자리에서 덜 뻗는 구간 A를 골랐다면, A를 가장 멀리 뻗는 구간 B로 바꿔도 B가 덮는 범위가 A를 포함하므로(둘 다 covered에서 시작 가능) 이후 필요한 구간이 늘지 않는다. 따라서 매 단계 "가장 멀리 뻗는 구간" 선택을 포함하는 최적해가 존재한다.
- 시작점 순으로 정렬해 두면 포인터 `i`가 뒤로 가지 않으므로 전체 O(N log N).

(2) 코드 단계별

- 각 스프링클러를 `(x - r, x + r)` 구간으로 바꿔 시작점 순 정렬.
- `covered < L`인 동안: 시작점이 `covered` 이하인 구간들을 모두 보며 최대 오른쪽 끝 `best`를 찾는다.
- `best`가 `covered`와 같으면(뻗지 못함) -1, 아니면 `covered = best`, 개수 +1.
- 루프가 끝나면 개수 출력.

(3) 스스로 다시 짤 때 생각 순서

- "구간으로 선분 전체 덮기 최소 개수"를 보면 정렬 + "닿는 것 중 가장 멀리" 그리디를 떠올린다.
- 구멍 판정(`best == covered`)을 빠뜨리면 무한 루프가 되므로 반드시 넣는다.
- 경계: 하나로 전부 덮는 경우(예제3), 끝이 맞닿는 구간들(예제4), 시작 0을 덮는 구간이 없는 경우(-1).
```

**10) 격자 타일 행·열 뒤집기 최대 흰색** · Hard

- **요구사항**: N×N 격자에 타일이 있고 각 타일은 W(흰색) 또는 B(검은색)이다. 한 번의 조작으로 **한 행 전체** 또는 **한 열 전체**의 타일을 모두 뒤집는다(W↔B). 조작 횟수에 제한이 없을 때 **흰 타일 개수의 최댓값**을 구하라.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10), 이후 N줄에 길이 N의 W/B 문자열.
- **출력**: 흰 타일 최대 개수.
- **예제**: `2 / WB / BW` → `4` · `3 / WBW / BWB / WBW` → `9`
- **셀프체크**: 같은 행(열)을 두 번 뒤집으면 원상복귀이므로 각 행·열은 0/1번, 순서 무관. 행 뒤집기 조합 2^N을 완전탐색하면, **각 열은 독립**이라 "그 열의 흰색 수 w와 N−w 중 큰 값"을 택하면 된다(열을 뒤집을지 말지가 강제 결정됨). N ≤ 10이라 1024 × 100 연산. 예제1: 두 번째 행을 뒤집어 `WB/WB`, 두 번째 열을 뒤집어 `WW/WW` → 4. 행과 열을 둘 다 완전탐색하면 4^N이 되니 한쪽만.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    grid = [[1 if c == 'W' else 0 for c in data[1 + i]] for i in range(n)]
    best = 0
    for mask in range(1 << n):        # 행 뒤집기 조합 완전탐색
        total = 0
        for c in range(n):
            white = 0
            for r in range(n):
                white += grid[r][c] ^ ((mask >> r) & 1)   # 행 r 반전 반영
            total += max(white, n - white)                # 열 반전은 유리한 쪽으로 강제
        if total > best:
            best = total
    print(best)

main()

(1) 접근·핵심 아이디어

- 반전은 XOR이므로 각 행·열 조작은 0/1번만 의미가 있고 순서는 무관하다. 그래도 행 N개 + 열 N개의 on/off는 2^(2N)이라 그대로는 크다.
- 핵심은 **행을 고정하면 열은 강제로 결정된다**는 점이다. 행 뒤집기 조합을 정하고 나면 각 열의 흰색 개수 w가 정해지고, 그 열을 뒤집을지는 `max(w, N - w)`로 즉시 결정된다(열끼리 서로 영향이 없다). 따라서 자유도는 행 2^N만 완전탐색하고 열은 그리디로 확정 → O(2^N · N^2).

(2) 코드 단계별

- 격자를 W=1, B=0 정수로 저장한다.
- `mask`(N비트)로 어떤 행을 뒤집을지 정한다. 행 r의 반전 여부는 `(mask >> r) & 1`.
- 각 열마다 반전을 반영한 흰색 수 `white`를 세고 `max(white, n - white)`를 더한다.
- 모든 mask 중 최댓값 출력.

(3) 스스로 다시 짤 때 생각 순서

- "행/열 단위 반전 + 최적화"를 보면 "한쪽 자유도만 완전탐색, 나머지는 강제"라는 L2의 틀을 떠올린다.
- 열이 독립이라는 점(열 반전은 다른 열의 흰색 수를 바꾸지 않음)을 확인해 그리디 정당성을 확보한다.
- 경계: N=1(뒤집어서 W 하나), 이미 전부 W인 경우, 대각선만 W인 경우(예제4 — 7이 최대인지 손으로 몇 가지 mask를 시도해 검산).
```

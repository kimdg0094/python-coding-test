> 개요: "값을 하나씩 확인"하는 대신 정렬·단조성을 이용해 탐색 공간을 절반씩 줄이는 이진탐색을 실전 관점(경계·lower/upper bound·실수 이분)에서 다시 다지고, 이 아이디어를 "최적값 찾기"를 "예/아니오 결정문제"로 바꿔 푸는 Parametric Search(매개변수 탐색)로 확장한다.

## L1. 이진탐색

**개념**

- 이진탐색(Binary Search)은 **정렬된**(또는 단조성이 성립하는) 탐색 공간에서, 가운데를 확인해 "찾는 값이 왼쪽인지 오른쪽인지" 판단하며 매번 후보 범위를 절반으로 줄이는 탐색이다. N개를 순차로 보면 O(N)이지만, 반씩 버리면 O(log N)이다.
- 왜 다시 배우나: 기초에서 "값이 있는지" 찾는 것만 익혔다면, 실전에선 **경계(boundary)를 찾는 것**이 훨씬 중요하다. "x 이상이 처음 나오는 위치", "x 이하가 마지막인 위치", "조건을 만족하는 최소/최대" 같은 질문은 전부 경계 탐색이고, 이것이 다음 레슨 Parametric Search의 토대다.
- 핵심은 **불변식(invariant)** 이다: 매 순간 "정답이 반드시 `[lo, hi]` 안에 있다"를 유지하도록 `lo`, `hi`, `mid` 갱신 규칙을 정한다. 이 불변식이 흔들리면 무한 루프나 off-by-one이 난다.
- 두 가지 대표 경계

- lower_bound: `a[i] >= x`를 만족하는 **가장 왼쪽** 인덱스(= x가 삽입될 수 있는 가장 왼쪽 위치, = x보다 작은 원소 개수).
- upper_bound: `a[i] > x`를 만족하는 **가장 왼쪽** 인덱스(= x 이하인 원소 개수). `upper - lower`가 곧 x의 등장 횟수.

```python
# [lo, hi) 반열린 구간 컨벤션 — 경계 탐색에 가장 안전한 형태
def lower_bound(a, x):          # a[i] >= x 인 첫 인덱스
    lo, hi = 0, len(a)          # hi는 "유효 인덱스 밖"까지 포함(= len)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:          # mid는 확실히 아님 → 오른쪽만 후보
            lo = mid + 1
        else:                   # mid도 후보일 수 있음 → 자신 포함해 왼쪽
            hi = mid
    return lo                   # lo == hi, 답의 위치

def upper_bound(a, x):          # a[i] > x 인 첫 인덱스
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= x:         # x 이하는 전부 왼쪽으로 밀어냄
            lo = mid + 1
        else:
            hi = mid
    return lo
```

**접근 전략**

- 핵심 아이디어: "찾는다"를 "**조건 `cond(mid)`이 참/거짓으로 한 번 바뀌는 경계를 찾는다**"로 바꿔 생각한다. 배열 인덱스든, 정답 후보 값이든, `cond`가 `False False ... False True True ... True`처럼 **단조로우면** 이진탐색이 성립한다. lower/upper bound는 이 틀의 특수한 경우다.
- 전형 절차: (1) 탐색 대상과 구간 `[lo, hi]`를 정한다 → (2) 불변식(정답이 구간 안)을 정한다 → (3) `mid`가 조건을 만족하면 어느 쪽을 버릴지 정한다 → (4) 루프 종료 시 `lo`(또는 `ans`)가 답. 반열린 `[lo, hi)`(위 코드)와 닫힌 `[lo, hi]`(아래 팁) 둘 중 **하나의 컨벤션만** 골라 일관되게 쓴다.
- 파이썬 실전: 표준 라이브러리 `bisect`를 적극 쓴다 — `bisect.bisect_left(a, x)` = lower_bound, `bisect.bisect_right(a, x)` = upper_bound, `bisect.insort(a, x)`는 정렬 유지 삽입. 정렬된 리스트에 대한 "x의 개수"는 `bisect_right - bisect_left`. 직접 구현은 경계 감각을 익힐 때만 하고, 실전 정답 코드는 `bisect`로 짧고 안전하게.
- 닫힌 구간 `[lo, hi]`로 "조건 만족 최대값"을 찾는 팁: `while lo <= hi: mid=(lo+hi)//2; if ok(mid): ans=mid; lo=mid+1 else: hi=mid-1`. "최댓값"은 성공 시 `lo=mid+1`, "최솟값"은 성공 시 `hi=mid-1` — 어느 쪽 경계를 밀지만 바뀐다.
- 복잡도: 시간 O(log N)(정렬이 안 돼 있으면 정렬 O(N log N)이 선행), 공간 O(1)(반복 구현). 재귀로 짜면 스택 O(log N).
- 흔한 실수: (1) `mid = (lo+hi)//2`에서 "최댓값 탐색" 시 `lo=mid`로 두면 무한 루프 — 이땐 `mid=(lo+hi+1)//2`로 올림을 써야 한다. (2) 정렬 안 된 배열에 이진탐색(무조건 정렬 선행). (3) 반열린/닫힌 컨벤션을 섞어 off-by-one. (4) `while lo < hi`인데 `lo=mid`(전진 안 함) → 무한 루프.

- (1)의 무한 루프를 `lo=3, hi=4`로 구체화: `mid=(3+4)//2=3`(내림), `ok(mid)`가 참이라 `lo=mid=3`으로 두면 `lo`도 `hi`도 그대로라 영원히 반복된다. 올림 `mid=(3+4+1)//2=4`를 쓰면 `lo=4=hi`가 되어 종료한다 — "성공 시 `lo=mid`"와 "올림 mid"는 반드시 짝으로 쓴다.

**문제**

**1) 값의 개수와 경계** · Easy

- **요구사항**: 오름차순 정렬된 배열과 질의 값 x가 여러 개 주어진다. 각 x에 대해 lower_bound 인덱스, upper_bound 인덱스, 그리고 x의 등장 횟수(`upper - lower`)를 출력하라. `bisect`를 써도 되지만 경계 뜻을 직접 설명할 수 있어야 한다.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 오름차순 정수 N개, 셋째 줄 질의 개수 Q, 넷째 줄 질의 값 Q개.
- **출력**: 각 질의마다 `lower upper count`를 한 줄씩.
- **예제**: `7 / 1 2 4 4 4 7 9 / 3 / 4 5 10` → `2 5 3` / `5 5 0` / `7 7 0`
- **예제**: `7 / 1 2 4 4 4 7 9 / 2 / 1 9` → `0 1 1` / `6 7 1`
- **셀프체크**: x=4는 인덱스 2,3,4에 있으므로 lower=2, upper=5, 개수 3. 배열에 없는 x=5는 lower==upper(개수 0)이고 그 값은 "5를 넣는다면 들어갈 위치"다. x=10처럼 모든 원소보다 크면 lower=upper=N(=7). 함정: upper_bound를 `>=`로 짜면 lower와 같아져 개수가 0으로 잘못 나온다 — upper는 반드시 `<= x`를 왼쪽으로 밀어야 한다.

```runner
@@SOLUTION
import sys, bisect

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    a = [int(data[idx + i]) for i in range(n)]; idx += n
    q = int(data[idx]); idx += 1
    out = []
    for _ in range(q):
        x = int(data[idx]); idx += 1
        lo = bisect.bisect_left(a, x)   # a[i] >= x 첫 인덱스
        up = bisect.bisect_right(a, x)  # a[i] > x 첫 인덱스
        out.append(f"{lo} {up} {up - lo}")
    print("\n".join(out))

main()
@@TESTS
--IN

1 2 4 4 4 7 9
3
4 5 10
--OUT
2 5 3
5 5 0
7 7 0
--IN
7
1 2 4 4 4 7 9
2
1 9
--OUT
0 1 1
6 7 1
@@EXPL
(1) 접근·핵심 아이디어

- lower_bound는 `a[i] >= x`인 가장 왼쪽 인덱스(= x보다 작은 원소 개수), upper_bound는 `a[i] > x`인 가장 왼쪽 인덱스(= x 이하 원소 개수). 둘의 차 `upper - lower`가 곧 x의 등장 횟수다.
- 배열이 이미 오름차순이므로 두 경계 모두 O(log N) 이진탐색으로 구한다. 표준 라이브러리 `bisect.bisect_left` = lower, `bisect.bisect_right` = upper.

(2) 코드 단계별

- 입력 전체를 한 번에 읽어 토큰으로 쪼갠다(대량 질의 대비).
- 배열 `a`와 질의를 파싱한다.
- 각 질의 x마다 `bisect_left`, `bisect_right`를 호출하고 그 차이로 개수를 계산해 `lower upper count` 한 줄을 만든다.
- 결과를 개행으로 join 해 한 번에 출력.

(3) 스스로 다시 짤 때 생각 순서

- "경계 두 개를 구하는 문제"임을 먼저 인식한다: lower는 `>=`, upper는 `>`.
- 직접 짤 거면 `[lo, hi)` 반열린 구간으로 `a[mid] < x`면 `lo=mid+1`, 아니면 `hi=mid`(lower) / `a[mid] <= x`면 `lo=mid+1`(upper).
- 함정 점검: upper를 `>=`로 짜면 lower와 같아진다. 없는 값·범위 밖 값(전부보다 큰 x → lower=upper=N)을 검산.
```

**2) 정수 제곱근** · Easy

- **요구사항**: 비음수 정수 x가 주어질 때, `m*m <= x`를 만족하는 **가장 큰** 정수 m(= 내림 제곱근 ⌊√x⌋)을 이진탐색으로 구하라. 부동소수 `**0.5`나 `math.isqrt`는 쓰지 말고 정수 이진탐색으로 직접 구현한다.
- **입력**: 한 줄에 정수 x(0 ≤ x ≤ 10^18).
- **출력**: ⌊√x⌋ 하나.
- **예제**: `10` → `3`  (3²=9≤10<16=4²)
- **예제**: `16` → `4`
- **예제**: `26` → `5`  (5²=25≤26<36)
- **셀프체크**: "조건 만족 최댓값" 패턴이다 — `ok(m) = (m*m <= x)`는 `True...True False...False`로 단조. 닫힌 구간 `[0, x]`에서 `ok(mid)`면 `ans=mid; lo=mid+1`, 아니면 `hi=mid-1`. x가 10^18이라 `mid*mid`는 최대 10^36이지만 파이썬 정수는 임의 정밀도라 오버플로 걱정이 없다(C/자바였다면 오버플로 주의). x=0,1의 경계와 `mid=(lo+hi)//2` 무한 루프 여부를 꼭 점검.

```runner
@@SOLUTION
import sys

def main():
    x = int(sys.stdin.read().split()[0])
    lo, hi, ans = 0, x, 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= x:      # ok(mid): 더 큰 m도 노려봄
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    print(ans)

main()
@@TESTS
--IN
10
--OUT
3
--IN
26
--OUT
5
@@EXPL
(1) 접근·핵심 아이디어

- `ok(m) = (m*m <= x)`는 m이 커질수록 `True...True False...False`로 딱 한 번 바뀌는 단조 조건. 우리가 원하는 답은 마지막 True, 즉 "조건을 만족하는 최댓값 m"이다.
- 닫힌 구간 `[0, x]`에서 이진탐색으로 그 경계를 찾는다. 부동소수 `**0.5`는 큰 수에서 반올림 오차가 나므로 정수 이진탐색이 안전하다.

(2) 코드 단계별

- `lo=0, hi=x, ans=0`으로 초기화(x=0이면 답 0).
- `mid=(lo+hi)//2`에서 `mid*mid <= x`면 성공 → `ans=mid` 저장 후 `lo=mid+1`(더 큰 값 시도).
- 실패면 `hi=mid-1`.
- 루프 종료 시 마지막 성공값 `ans`가 ⌊√x⌋.

(3) 스스로 다시 짤 때 생각 순서

- "최댓값 찾기" → 성공 시 오른쪽(`lo=mid+1`)으로 미는 것을 먼저 확정.
- 구간을 `[0, x]`로 넉넉히(√x ≤ x 이므로 안전). 필요하면 `hi`를 더 조여도 됨.
- 파이썬 정수는 임의 정밀도라 `mid*mid`가 10^36이어도 오버플로 없음. C계열이라면 64비트로도 부족하니 주의.
- 경계 x=0, x=1과 무한 루프 여부(성공 시 `lo=mid` 금지)를 검산.
```

**3) 회전된 정렬 배열에서 찾기** · Medium

- **요구사항**: 서로 다른 정수들이 오름차순 정렬된 뒤 어느 지점에서 한 번 회전(rotate)된 배열이 주어진다(예: `4 5 6 7 0 1 2`). 목표값 t의 인덱스를 O(log N)에 찾아 출력하고, 없으면 `-1`을 출력하라. 배열을 다시 정렬하면 O(N log N)이라 안 된다.
- **입력**: 첫 줄 N(1 ≤ N ≤ 10^5), 둘째 줄 회전된 배열 N개, 셋째 줄 목표값 t.
- **출력**: t의 0-based 인덱스 또는 `-1`.
- **예제**: `7 / 4 5 6 7 0 1 2 / 0` → `4`
- **예제**: `7 / 4 5 6 7 0 1 2 / 3` → `-1`
- **셀프체크**: 회전 배열은 전체로는 정렬이 아니지만, `mid`를 기준으로 **왼쪽 절반과 오른쪽 절반 중 적어도 한쪽은 항상 정렬**돼 있다는 성질을 쓴다. `a[lo] <= a[mid]`면 왼쪽이 정렬 — t가 `[a[lo], a[mid])` 범위면 왼쪽으로, 아니면 오른쪽으로. 그렇지 않으면 오른쪽이 정렬 — 대칭으로 판단. 함정: 등호 위치(`<=`)를 잘못 두면 원소가 하나 남는 경계에서 놓친다. 회전이 0칸(=원래 정렬)인 경우와 t가 배열 끝값인 경우를 따로 검산하라.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    t = int(data[1 + n])
    lo, hi, ans = 0, n - 1, -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == t:
            ans = mid
            break
        if a[lo] <= a[mid]:              # 왼쪽 절반이 정렬됨
            if a[lo] <= t < a[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                            # 오른쪽 절반이 정렬됨
            if a[mid] < t <= a[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    print(ans)

main()
@@TESTS
--IN
7
4 5 6 7 0 1 2
0
--OUT
4
--IN
7
4 5 6 7 0 1 2
3
--OUT
-1
@@EXPL
(1) 접근·핵심 아이디어

- 회전된 정렬 배열은 전체로는 단조가 아니지만, 임의의 `mid`를 기준으로 **왼쪽 `[lo..mid]`과 오른쪽 `[mid..hi]` 중 적어도 한쪽은 반드시 정렬**돼 있다. 그 "정렬된 절반"에 t가 있는지 범위 비교로 확정하고, 없으면 반대쪽으로 이동해 매번 절반을 버린다 → O(log N).

(2) 코드 단계별

- `a[mid] == t`면 즉시 인덱스 반환.
- `a[lo] <= a[mid]`면 왼쪽 절반이 정렬됨: `a[lo] <= t < a[mid]`이면 t는 왼쪽에 있으니 `hi=mid-1`, 아니면 `lo=mid+1`.
- 그렇지 않으면 오른쪽 절반이 정렬됨: `a[mid] < t <= a[hi]`이면 `lo=mid+1`, 아니면 `hi=mid-1`.
- 루프가 끝나면 못 찾은 것이므로 `-1`.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "어느 절반이 정렬됐나"를 `a[lo] <= a[mid]`로 판정하는 것을 축으로 삼는다.
- 정렬된 절반에 대해서만 t의 범위 포함 여부를 안전하게 판단(정렬 안 된 절반은 판단 불가).
- 등호 위치(`<=` vs `<`)를 원소 1~2개 남는 경계에서 검산: 회전 0칸(원래 정렬), t가 배열 끝값, 길이 1 배열 케이스를 꼭 확인.
```


## L2. Parametric Search

**개념**

- Parametric Search(매개변수 탐색)는 **"최적값(최대/최소)을 직접 구하기는 어렵지만, '어떤 값 X가 가능한가?'라는 예/아니오 판정은 쉬운"** 문제에서, 그 판정을 이진탐색과 결합해 최적값을 찾는 기법이다. 한마디로 **"최적화 문제 → 결정 문제(decision problem)로 바꾼 뒤 이진탐색"**.
- 왜/언제 쓰나: "리본을 최대한 길게 잘라 K개 이상 만들기", "나무를 자를 높이의 최댓값", "K개 그룹으로 나눌 때 그룹 합의 최댓값을 최소화" 같은 문제는 답을 바로 계산하기 어렵다. 하지만 **"길이 X로 자르면 K개가 나오나?"** 처럼 후보 X를 하나 정해두고 검사(feasibility check)하는 것은 O(N)에 쉽게 된다. 이 검사가 **단조**(어떤 경계에서 가능→불가능으로 딱 한 번 바뀜)면 이진탐색으로 그 경계를 찾을 수 있다.
- 성립 조건 — **단조성(monotonicity)이 전부다.** 판정 함수 `feasible(X)`가 X에 대해 한 방향으로만 바뀌어야 한다. 예: "자르는 길이 X가 작을수록 조각은 많아진다" → 작은 X는 전부 가능(T), 큰 X는 전부 불가능(F). 즉 `T T T ... T F F ... F`. 이 경계(마지막 T)가 답. 반대로 "X가 클수록 가능"이면 `F...F T...T`가 되고 첫 T가 답.
- 단계로 보기(예: "길이 X로 잘라 K개 이상 만드는 최대 X")

- 1단계: **답의 범위**를 잡는다. 여기선 `lo=1`, `hi=max(cable)`(그보다 길게 자르면 0개).
- 2단계: **판정 함수** `feasible(X)`를 정의한다. `sum(c // X for c in cables) >= K` 이면 True.
- 3단계: 이진탐색. `mid`가 가능하면(True) "더 길게도 되나?" → 답 후보로 저장하고 `lo=mid+1`. 불가능하면 `hi=mid-1`.
- 4단계: 루프가 끝나면 저장해 둔 마지막 성공값(`ans`)이 최적값. **최적값 자체는 이진탐색 대상이 아니라 "판정"의 결과**임에 유의.

```python
# 틀: 최적화 문제를 "feasible(X)?" 결정문제로 바꿔 이진탐색
def feasible(X):
    ...            # O(N) 정도로 "X가 조건을 만족하는가"를 True/False 판정
    return True    # 또는 False

# 예: 조건을 만족하는 "최댓값" 찾기 (T...T F...F 형태)
lo, hi = LO, HI
ans = LO           # 최소한 하나는 항상 가능하다면 초깃값 세팅
while lo <= hi:
    mid = (lo + hi) // 2
    if feasible(mid):
        ans = mid          # 성공 → 더 큰 값도 노려봄
        lo = mid + 1
    else:
        hi = mid - 1       # 실패 → 더 작게
# ans가 최적(최대)값
# "최솟값"을 찾는다면 성공 시 ans=mid; hi=mid-1 로 바꾼다
```

**접근 전략**

- 핵심 아이디어 3단계: (1) **무엇을 이진탐색할지** 정한다 — 보통 "정답이 될 수 있는 값(길이·높이·시간·비용...)"의 범위. (2) **판정 함수 `feasible(X)`** 를 O(N)~O(N log N)으로 설계한다. (3) `feasible`이 **단조인지 반드시 확인** — 종이에 `X`를 키우며 T/F가 한 번만 바뀌는지 그려본다. 단조가 아니면 이 기법을 못 쓴다.
- "최적화를 판정으로 뒤집는" 신호: 문제에 **"~하는 최댓값/최솟값", "적어도 K개", "최대를 최소로", "최소를 최대로"** 같은 말이 있고, 특정 후보값 하나에 대한 검사는 쉬울 때가 전형적이다. "값을 정해두고 세어보기"가 쉬우면 강하게 의심하라.
- 경계·초기값 설정: `lo`, `hi`는 **답이 가질 수 있는 최소/최대**로 넉넉히 잡는다(예: 길이면 `1..max`, 그룹 합이면 `max(a)..sum(a)`). `hi`를 너무 좁게 잡아 정답을 범위 밖으로 빠뜨리는 실수가 흔하다. 성공이 한 번도 없을 수 있으면 `ans`를 실패를 뜻하는 값(예: 0 또는 -1)으로 초기화.
- 복잡도: 전체 O(N · log(범위크기)). 판정 1회가 O(N)이고, 이진탐색 반복이 O(log(hi-lo))이므로 곱한다. 값 범위가 10^9이어도 log는 ~30이라 매우 빠르다. 공간은 O(1)~O(N)(입력 저장).
- 파이썬 실전 팁: 합·개수 판정은 제너레이터로 `sum(c // X for c in cables)`처럼 간결하게. 큰 입력은 `sys.stdin`으로 빠르게 읽고, 합이 int 범위를 넘길 걱정은 파이썬에선 없다(임의 정밀도). 판정 함수는 **부작용 없는 순수 함수**로 짜서 재호출해도 안전하게. 답이 실수(예: 최소 거리 최대화의 소수 답)면 이진탐색을 정수 대신 **고정 횟수(예: 100회) 실수 이분**으로 돌려 정밀도를 맞춘다.
- 흔한 실수: (1) `feasible`의 단조 방향(T→F인지 F→T인지)을 착각해 밀어야 할 경계를 반대로 밀기. (2) "최댓값"인데 성공 시 `hi=mid-1`로 두어 답이 작게 나옴 — 최댓값은 성공 시 **오른쪽**(`lo=mid+1`)으로. (3) `hi` 초기값을 답보다 작게 잡음. (4) 판정 안에서 원본 배열을 수정(다음 호출 오염).

**문제**

**1) 랜선 자르기** · Medium

- **요구사항**: 길이가 제각각인 랜선 N개가 있다. 이들을 잘라 **길이가 모두 같은** 랜선을 **K개 이상** 만들려고 한다(자를 때 자연수 길이만 허용, 남는 부분은 버림). 만들 수 있는 랜선의 **최대 길이**를 구하라. 불가능하면 0.
- **입력**: 첫 줄 K(필요 개수)와 N(가진 랜선 수), 다음 N줄에 각 랜선 길이(1 ≤ 길이 ≤ 2^31-1).
- **출력**: 최대 길이 하나.
- **예제**: `11 4 / 802 / 743 / 457 / 539` → `200`
- **예제**: `4 3 / 100 / 100 / 100` → `50`
- **셀프체크**: 판정 `feasible(L) = sum(c // L for c in cables) >= K`. 예제1에서 L=200이면 조각 수 `4+3+2+2 = 11 ≥ 11`(가능), L=201이면 `3+3+2+2 = 10 < 11`(불가) → 경계 200이 답. "최댓값" 패턴이므로 성공 시 `lo=mid+1`. 예제2: L=50이면 각 `100//50=2`, 합 6 ≥ 4(가능), L=51이면 각 1, 합 3 < 4 → 답 50. `lo`를 0에서 시작하면 `c//0` 0나눗셈 — `lo=1`로 시작. `hi=max(cable)`.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    k = int(data[0]); n = int(data[1])
    cables = [int(data[2 + i]) for i in range(n)]

    def feasible(L):                       # 길이 L로 잘라 K개 이상?
        return sum(c // L for c in cables) >= k

    lo, hi, ans = 1, max(cables), 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            ans = mid                      # 최댓값 → 더 길게 시도
            lo = mid + 1
        else:
            hi = mid - 1
    print(ans)

main()

(1) 접근·핵심 아이디어

- "최대 길이"를 바로 계산하긴 어렵지만, 후보 길이 L을 정해두면 "L로 잘라 K개 이상 만들 수 있나?"는 `sum(c // L for c in cables) >= K`로 O(N)에 판정된다.
- L이 클수록 조각 수는 줄어드니 `feasible`은 `T...T F...F`(최댓값 패턴). 마지막 T가 답 → 이진탐색.

(2) 코드 단계별

- 첫 줄 K, N과 랜선 길이들을 읽는다.
- `feasible(L)`: 각 랜선을 L로 나눈 몫의 합이 K 이상인지.
- 구간 `[1, max(cables)]`에서(0으로 나누기 방지 위해 lo=1), `feasible(mid)`면 `ans=mid; lo=mid+1`, 아니면 `hi=mid-1`.
- 마지막 성공값 `ans` 출력. 한 번도 성공 못 하면 0.

(3) 스스로 다시 짤 때 생각 순서

- "최대 길이", "K개 이상" 키워드 → 최적화를 판정으로 뒤집는 parametric search.
- 판정을 O(N)으로 설계하고 단조 방향 확인: L↑ → 조각↓ → T가 왼쪽.
- 최댓값이므로 성공 시 `lo=mid+1`. 범위 `lo=1`(0 나눗셈 회피), `hi=max`.
- 예제로 경계 검산(L=200 가능, L=201 불가 → 200).
```

**2) 나무 자르기** · Medium

- **요구사항**: 높이가 제각각인 나무 N그루가 일렬로 있다. 절단기 높이 H를 정하면, H보다 큰 나무는 H 위 부분이 잘려 나가고(잘린 양 = 나무높이 − H), H 이하 나무는 그대로다. 잘린 나무의 **총 길이가 M 이상**이 되도록 하면서 **H를 최대**로 하라(H는 음이 아닌 정수).
- **입력**: 첫 줄 N과 M(필요한 나무 길이), 둘째 줄 나무 높이 N개(1 ≤ 높이 ≤ 10^9).
- **출력**: 최대 절단기 높이 H.
- **예제**: `4 7 / 20 15 10 17` → `15`
- **예제**: `5 20 / 4 42 40 26 46` → `36`
- **셀프체크**: 판정 `feasible(H) = sum(max(0, t - H) for t in trees) >= M`. H가 클수록 얻는 나무는 줄어드니 `T...T F...F`(최댓값 패턴). 예제1: H=15면 잘린 양 `(20-15)+(17-15) = 5+2 = 7 ≥ 7`(가능), H=16이면 `4+1 = 5 < 7`(불가) → 답 15. 예제2: H=36이면 `(42-36)+(40-36)+(46-36) = 6+4+10 = 20 ≥ 20`(가능), H=37이면 `5+3+9 = 17 < 20` → 답 36. `hi=max(trees)`(그보다 높으면 0). 합이 크므로 정수 자료형 걱정은 파이썬에선 없지만 C계열이면 64비트 필수. `lo=0`(0높이면 전체를 다 얻음)로 시작.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0]); m = int(data[1])
    trees = [int(data[2 + i]) for i in range(n)]

    def feasible(H):                          # 절단기 높이 H로 M 이상 얻나?
        return sum(t - H for t in trees if t > H) >= m

    lo, hi, ans = 0, max(trees), 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            ans = mid                         # 최댓값 → H를 더 높여봄
            lo = mid + 1
        else:
            hi = mid - 1
    print(ans)

main()

@@EXPL
(1) 접근·핵심 아이디어

- "H를 최대로"가 목표지만, 후보 H를 정하면 "그때 얻는 나무 총량 `sum(max(0, t-H)) >= M`인가?"는 O(N)에 판정된다.
- H가 커질수록 얻는 양은 단조 감소하니 `feasible`은 `T...T F...F`(최댓값 패턴). 마지막 T가 답.

(2) 코드 단계별

- N, M과 나무 높이들을 읽는다.
- `feasible(H)`: H보다 큰 나무들의 초과분 합이 M 이상인지.
- 구간 `[0, max(trees)]`에서 `feasible(mid)`면 `ans=mid; lo=mid+1`, 아니면 `hi=mid-1`.
- 마지막 성공값 `ans`(최대 절단기 높이) 출력.

(3) 스스로 다시 짤 때 생각 순서

- "H를 최대로", "M 이상" → parametric search 신호.
- 판정을 순수 함수로 O(N) 설계, 원본 배열 수정 금지.
- 단조 방향: H↑ → 얻는 양↓ → T가 왼쪽 → 최댓값 → 성공 시 `lo=mid+1`.
- 범위 `lo=0`(0이면 전부 얻음), `hi=max(trees)`(그보다 높으면 0). 합이 커도 파이썬 정수는 안전.
```

**3) 최소를 최대로: 그룹 합의 최댓값 최소화** · Hard

- **요구사항**: 양의 정수 배열을 순서를 유지한 채 **연속된 K개의 그룹(부분배열)** 으로 나눈다. 각 그룹의 원소 합 중 **가장 큰 값**을, 나누는 방법을 잘 골라 **최소화**하라. 그 최소화된 값을 출력한다.
- **입력**: 첫 줄 N과 K(1 ≤ K ≤ N), 둘째 줄 양의 정수 N개(1 ≤ 값 ≤ 10^9).
- **출력**: 가능한 "최대 그룹 합"의 최솟값.
- **예제**: `5 2 / 1 2 3 4 5` → `9`
- **예제**: `5 2 / 7 2 5 10 8` → `18`
- **셀프체크**: 이진탐색 대상은 **"허용할 그룹 합의 상한 X"**. 판정 `feasible(X)` = "각 그룹 합이 X를 넘지 않게 왼쪽부터 탐욕적으로 자를 때, 그룹 수가 K 이하인가?"(그리디로 O(N)). X가 클수록 그룹은 적게 필요하니 `F...F T...T`(첫 T가 답 = **최솟값 패턴**) → 성공 시 `hi=mid-1`. 범위는 `lo=max(a)`(한 그룹이 최소한 가장 큰 원소는 담아야 함), `hi=sum(a)`(전부 한 그룹). 예제1: X=9면 `[1,2,3]|[4,5]` = 6,9 → 2그룹 ≤ 2(가능), X=8이면 `[1,2,3]|[4]|[5]`처럼 최소 3그룹 필요 > 2(불가) → 답 9. 예제2: X=18이면 `[7,2,5]|[10,8]`? = 14,18 → 2그룹(가능), X=17이면 3그룹 필요 → 답 18. 함정: `lo`를 `max(a)`가 아니라 0/1로 잡으면 "한 원소가 X보다 커 무한히 그룹이 늘어나는" 경우를 판정에서 별도 처리해야 하니, `lo=max(a)`로 잡는 게 깔끔하다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    n = int(data[0]); k = int(data[1])
    a = [int(data[2 + i]) for i in range(n)]

    def feasible(X):                 # 그룹 합 상한 X로 자르면 그룹 수 <= K?
        groups, cur = 1, 0
        for v in a:
            if cur + v > X:
                groups += 1
                cur = v
            else:
                cur += v
        return groups <= k

    lo, hi, ans = max(a), sum(a), sum(a)
    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            ans = mid                # 최솟값 → 더 작게 시도
            hi = mid - 1
        else:
            lo = mid + 1
    print(ans)

main()
@@TESTS

1 2 3 4 5
--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- "최대 그룹 합을 최소화"는 직접 계산이 어렵지만, "그룹 합 상한 X를 정하면 그 안에 K개 이하로 나눌 수 있나?"는 왼쪽부터 탐욕적으로 채우며 세는 O(N) 판정으로 쉽다.
- X가 클수록 필요한 그룹 수는 줄어드니 `feasible`은 `F...F T...T`(최솟값 패턴). 첫 T가 답.

(2) 코드 단계별

- N, K와 배열을 읽는다.
- `feasible(X)`: 현재 그룹 합 `cur`에 `v`를 더해 X를 넘으면 새 그룹 시작(`groups+=1; cur=v`), 아니면 누적. 마지막에 `groups <= k`.
- 구간 `[max(a), sum(a)]`에서 `feasible(mid)`면 `ans=mid; hi=mid-1`, 아니면 `lo=mid+1`.
- 첫 성공값(최솟값) `ans` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "최대를 최소로" → parametric search. 이진탐색 대상은 "허용할 그룹 합의 상한 X".
- 판정은 그리디 O(N): 넘치면 새 그룹. 단조 방향 X↑ → 그룹↓ → T가 오른쪽 → 최솟값 → 성공 시 `hi=mid-1`.
```

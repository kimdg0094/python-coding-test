## L4. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch6(DP II)의 핵심 세 유형 — 원하는 state를 정의해 한 칸씩 나아가는 DP, 직전 상황에 영향받는 연속 DP, 두 문자열을 나란히 비교하는 String Matching — 을 **반복 훈련**하고, 코딩테스트 단골 유형으로 **확장**하는 연습 세트다. 새 문법은 없다. 모든 문제에서 "상태 정의(한 문장) → 전이 → 초기값·답 위치"를 먼저 적고 코드를 쓴다.

- **반복 훈련 개념**
- 직전 선택을 state로 승격: 다음 결정에 필요한 최소 정보만 축으로 — `red, other = other, 2*(red+other)`, `da = a[i] + max(da, db - c)`
- 오르막/내리막·잔액 같은 "지금 모드"를 state로: `up[i] = down[j] + 1`, `dp[i+1][j+1] += dp[i][j]`(잔액 +1)
- 연속 DP의 한 줄 전이 "이어붙이기 vs 새로 시작": `cur = max(x, cur + x)`, `cur = cur + 1 if a[i] > a[i-1] else 1`, 전역 답은 `best`에 따로 기록
- 두 문자열 표 `dp[i][j]`: 같으면 대각선, 다르면 위·왼쪽 — `dp[j] += dp[j-1] if T[j-1] == ch`, `L[i][j] = L[i+1][j+1] + 1`
- 도달 불가 상태는 `-inf`로 막고 답 위치(마지막 칸의 어느 상태가 유효한지)를 마지막에 다시 확인

- **코딩테스트 출제 맵**: 이 챕터의 유형은 백준 「단계별로 풀어보기」의 '동적 계획법 1'·'동적 계획법 2' 단계(이친수·LCS 2·연속합 류), 프로그래머스 「코딩테스트 고득점 Kit」의 '동적계획법', NeetCode 150의 '1-D DP'·'2-D DP'(Distinct Subsequences·Regular Expression Matching·Maximum Subarray 변형 류)에 그대로 등장한다. 이 레슨의 유형 확장 문제는 그 대표 유형을 소재·수치·조건을 새로 만들어 이 챕터 수준으로 재구성한 것이다.

- **문제 구성표**

**문제**

**1) 빨강 연속 금지 화단 칠하기** · Easy

- **요구사항**: 일렬로 놓인 n개의 화단 칸을 빨강·노랑·파랑 세 색 중 하나로 칠한다. 단 **빨강은 두 칸 연속으로 올 수 없다**(노랑·파랑은 연속 허용). 가능한 칠하기의 수를 1,000,000,007로 나눈 나머지로 구하라.
- **입력**: 한 줄에 정수 n (1 ≤ n ≤ 100,000)
- **출력**: 경우의 수(MOD)
- **예제**: `1` → `3` · `2` → `8` · `3` → `22`
- **셀프체크**: 다음 칸을 정하려면 "직전 칸이 빨강인가"만 알면 되므로 상태는 두 개(`red`, `other`)면 충분하다. `n=2`에서 9가지 중 빨강-빨강 하나만 빠져 8이 되는가? `other`로 가는 전이에 2(노랑·파랑 두 색)를 곱했는가?

```runner
@@SOLUTION
import sys
def main():
    n = int(sys.stdin.read().split()[0])
    MOD = 1_000_000_007
    # red = 마지막 칸이 빨강인 경우의 수, other = 마지막 칸이 노랑/파랑인 경우의 수
    red, other = 1, 2                      # 첫 칸: 빨강 1가지, 그 외 2가지
    for _ in range(2, n + 1):
        new_red = other                    # 빨강 앞에는 빨강이 못 온다
        new_other = 2 * (red + other)      # 노랑/파랑은 무엇 뒤에든 가능(2색)
        red, other = new_red % MOD, new_other % MOD
    print((red + other) % MOD)
main()
@@TESTS

@@EXPL
(1) 접근·핵심 아이디어

- "빨강 다음에 빨강 금지"는 직전 칸의 색이 다음 선택을 막는 신호다. 다음 결정에 필요한 정보는 "직전이 빨강인가" 하나뿐이므로, 노랑과 파랑은 하나의 상태로 묶어도 된다.
- 상태 정의: `red[i]` = i번째 칸이 빨강인 칠하기 수, `other[i]` = i번째 칸이 노랑 또는 파랑인 칠하기 수.
- 전이: `red[i] = other[i-1]`(빨강 앞은 반드시 노랑/파랑), `other[i] = 2·(red[i-1] + other[i-1])`(노랑·파랑 2색은 무엇 뒤에든 가능). 초기값 `red[1]=1`, `other[1]=2`. 답은 `red[n] + other[n]`.
- 시간 O(n), 공간 O(1)(두 변수만 굴림).

(2) 코드 단계별

- `red, other = 1, 2`로 첫 칸을 초기화.
- `i=2..n`마다 새 값을 둘 다 계산한 뒤 **동시에** 대입한다 — `red`를 먼저 덮어쓰면 `other` 계산에 새 값이 섞여 오답.
- 매 단계 `% MOD`.
- `n=2` → `red=2`(노빨, 파빨), `other=6` → 8. `n=3` → `red=6`, `other=16` → 22.

(3) 스스로 다시 짤 때 생각 순서

- "무엇 다음에 무엇이 못 오나" → 직전 색을 상태로. 제약과 무관한 색들은 하나로 묶어 상태 수를 줄인다.
- 각 상태로 들어오는 전이를 적고, 여러 색이 묶인 상태는 색 수를 곱한다.
- 동시 대입·MOD·답은 모든 상태의 합.
```

**2) 연속 상승 구간 최장 길이** · Easy

- **요구사항**: 정수 수열에서 **연속한** 구간 중 값이 계속 엄격히 증가하는(각 항이 직전 항보다 큼) 가장 긴 구간의 길이를 구하라. 길이 1인 구간도 상승 구간으로 본다.
- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 둘째 줄에 n개의 정수(-10⁹ 이상 10⁹ 이하)
- **출력**: 최장 연속 상승 구간의 길이
- **예제**: `7 / 1 3 5 2 4 6 7` → `4` · `3 / 5 4 3` → `1` · `4 / 2 2 2 2` → `1`
- **셀프체크**: LIS(순서만 지키면 됨)가 아니라 **연속** 구간이다 — Kadane처럼 `cur`를 "i를 끝으로 하는 상승 구간 길이"로 두고 이어붙이거나 1로 리셋한다. 같은 값(`2 2`)은 상승이 아니므로 리셋. `n=1`이면 1.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    best = cur = 1                         # cur = i를 끝으로 하는 연속 상승 구간 길이
    for i in range(1, n):
        if a[i] > a[i - 1]:
            cur += 1                       # 이어붙이기
        else:
            cur = 1                        # 여기서 새로 시작
        if cur > best:
            best = cur
    print(best)
main()

(1) 접근·핵심 아이디어

- "연속 구간"이므로 Kadane 계열이다. 상태 `cur` = i번째 원소를 끝으로 하는 연속 상승 구간의 길이. 직전 원소보다 크면 이어붙여 `cur+1`, 아니면 여기서 새로 시작해 `1`.
- 전역 답 `best`는 `cur`와 별도로 기록한다 — `cur`는 항상 "i를 끝으로" 하는 값이라 마지막 `cur`가 최대라는 보장이 없다.
- 시간 O(n), 공간 O(1). LIS(부분수열)와 달리 이전 모든 원소를 볼 필요가 없다는 점이 "연속"의 힘이다.

(2) 코드 단계별

- `best = cur = 1`로 시작(원소 하나짜리 구간).
- `a[i] > a[i-1]`이면 `cur += 1`, 아니면 `cur = 1`. 같은 값은 `>`가 거짓이라 자동으로 리셋된다.
- 매 단계 `best = max(best, cur)`.
- `1 3 5 2 4 6 7` → `2 4 6 7`로 4. 감소만 하거나 전부 같으면 1. `n=1`이면 루프가 돌지 않아 1.

(3) 스스로 다시 짤 때 생각 순서

- "연속"인지 "순서만"인지 먼저 판별 → 연속이면 `cur` 굴리기.
- 이어붙이기 조건(엄격 증가 `>`)과 리셋값(1)을 정한다.
- `best`를 분리 기록, 경계(n=1, 전부 같음) 확인.
```

**3) 매표소 거스름돈 순서의 수** · Medium

- **요구사항**: 입장권은 5천원이다. 5천원 지폐를 내는 손님 a명과 만원 지폐를 내는 손님 b명이 한 줄로 선다. 매표소는 처음에 거스름돈이 한 푼도 없고, 만원 손님에게는 그때까지 받아 둔 5천원 지폐 한 장을 거슬러 줘야 한다. 같은 지폐를 내는 손님끼리는 구분하지 않을 때, 모든 손님에게 거스름돈을 줄 수 있는 줄 서기 순서의 수를 1,000,000,007로 나눈 나머지로 구하라.
- **입력**: 한 줄에 정수 a, b (0 ≤ a, b ≤ 50)
- **출력**: 가능한 순서의 수(MOD). 불가능하면 0
- **예제**: `2 1` → `2` · `3 3` → `5` · `1 2` → `0`
- **셀프체크**: 다음 손님을 받을 수 있는지는 "지금 5천원 지폐를 몇 장 들고 있나"(잔액)에만 달려 있다 → 상태 `dp[i][j]` = i명을 처리했고 잔액이 j장. i와 j를 알면 지금까지 온 5천원 손님 수 `(i+j)/2`, 만원 손님 수 `(i-j)/2`가 결정되므로 남은 손님 수 제한을 걸 수 있다. `a < b`면 답이 0, `a=b=0`이면 빈 줄 1가지.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    a, b = int(data[0]), int(data[1])      # a: 5천원 손님 수, b: 만원 손님 수
    MOD = 1_000_000_007
    if a < b:
        print(0); return
    total = a + b
    # dp[i][j] = i명을 처리했고 지금 5천원 지폐를 j장 들고 있는 순서의 수
    dp = [[0] * (a + 1) for _ in range(total + 1)]
    dp[0][0] = 1
    for i in range(total):
        for j in range(a + 1):
            cur = dp[i][j]
            if cur == 0:
                continue
            used5 = (i + j) // 2           # 지금까지 온 5천원 손님 수
            used10 = (i - j) // 2          # 지금까지 온 만원 손님 수
            if used5 < a:                  # 다음 손님이 5천원 -> 잔액 +1
                dp[i + 1][j + 1] = (dp[i + 1][j + 1] + cur) % MOD
            if used10 < b and j >= 1:      # 다음 손님이 만원 -> 거슬러 주고 잔액 -1
                dp[i + 1][j - 1] = (dp[i + 1][j - 1] + cur) % MOD
    print(dp[total][a - b])
main()

@@EXPL
(1) 접근·핵심 아이디어

- 줄 서기 순서를 앞에서부터 한 명씩 확정해 나갈 때, 다음 손님을 받을 수 있는지는 "지금 5천원 지폐를 몇 장 갖고 있나"에만 달려 있다. 이 **잔액**이 상태 축이다.
- 상태 정의: `dp[i][j]` = 앞 i명을 처리했고 현재 5천원 지폐를 j장 보유한 유효한 순서의 수. 5천원 손님이 오면 `j+1`, 만원 손님이 오면 `j ≥ 1`일 때만 `j-1`.
- i명 중 5천원 손님이 x명, 만원 손님이 y명이면 `x+y=i`, `x-y=j`이므로 `x=(i+j)/2`, `y=(i-j)/2`로 유일하게 결정된다. 덕분에 "남은 5천원 손님이 있나(`x<a`)", "남은 만원 손님이 있나(`y<b`)"를 상태에 따로 넣지 않고도 걸러낼 수 있다.
- 전이: `dp[i+1][j+1] += dp[i][j]`(x<a), `dp[i+1][j-1] += dp[i][j]`(y<b, j≥1). 초기 `dp[0][0]=1`, 답 `dp[a+b][a-b]`. 시간 O((a+b)·a), 공간 O((a+b)·a).

(2) 코드 단계별

- `a < b`면 만원 손님이 더 많아 반드시 거스름돈이 모자라므로 즉시 0.
- `dp`를 `(a+b+1)×(a+1)` 크기로 만들고 `dp[0][0]=1`.
- 각 `(i, j)`에서 값이 0이면 건너뛰고, `used5`, `used10`을 계산해 두 전이를 조건부로 적용하며 `% MOD`.
- `2 1` → `5,5,10`·`5,10,5` 두 가지. `3 3` → 카탈랑 수 5. `1 2` → 0. `0 0` → 빈 줄 1가지. `5 5` → 42.

(3) 스스로 다시 짤 때 생각 순서

- "다음 손님을 받을 수 있나"를 결정하는 최소 정보 → 잔액 j. 상태 `dp[i][j]`.
- (i, j)로부터 각 종류 손님 수를 역산해 남은 손님 제한을 건다.
- 초기값·불가능 조건(`a<b`)·답 위치 `dp[a+b][a-b]`를 확인.
```

**4) 지그재그 부분수열 최장 길이** · Medium

- **요구사항**: 수열에서 순서를 유지하며(연속일 필요 없음) 원소를 골라, 인접한 두 원소의 차이 부호가 양수·음수로 **번갈아** 나타나게 만들 때(차이 0은 불가) 가장 긴 것의 길이를 구하라. 첫 차이는 양수·음수 어느 쪽이든 된다. 길이 1은 항상 가능하다.
- **입력**: 첫 줄 n (1 ≤ n ≤ 1000), 둘째 줄에 n개의 정수(0 이상 10⁴ 이하)
- **출력**: 최장 지그재그 부분수열의 길이
- **예제**: `6 / 1 7 4 9 2 5` → `6` · `4 / 1 2 3 4` → `2` · `3 / 3 3 3` → `1`
- **셀프체크**: LIS처럼 `dp[i]`를 "i를 마지막으로"로 잡되, 다음에 무엇을 붙일 수 있는지는 **마지막 변화가 오르막이었나 내리막이었나**에 달려 있으므로 상태를 `up[i]`, `down[i]` 둘로 나눈다. `a[j] < a[i]`면 `down[j]` 뒤에 오르막으로 붙고, `a[j] > a[i]`면 `up[j]` 뒤에 내리막으로 붙는다. 같은 값은 어느 쪽에도 못 붙는다. 답은 모든 `up`, `down`의 최댓값.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    # up[i] = a[i]로 끝나며 마지막 변화가 오르막인 최장 지그재그 길이
    # down[i] = a[i]로 끝나며 마지막 변화가 내리막인 최장 지그재그 길이
    up = [1] * n
    down = [1] * n
    for i in range(n):
        for j in range(i):
            if a[j] < a[i] and down[j] + 1 > up[i]:
                up[i] = down[j] + 1        # 내리막 뒤에 오르막
            if a[j] > a[i] and up[j] + 1 > down[i]:
                down[i] = up[j] + 1        # 오르막 뒤에 내리막
    print(max(max(up), max(down)))
main()

(1) 접근·핵심 아이디어

- LIS 골격("i를 마지막으로 쓰는 최장 길이")에 **마지막 변화의 방향**을 상태로 추가한다. 다음 원소를 붙일 수 있는지가 그 방향에 달려 있기 때문이다.
- 상태 정의: `up[i]` = `a[i]`로 끝나고 마지막 변화가 오르막인 최장 지그재그 길이, `down[i]` = 마지막 변화가 내리막인 최장 길이. 원소 하나만으로는 방향이 없으니 둘 다 1로 시작.
- 전이: `j < i`에 대해 `a[j] < a[i]`면 `up[i] = max(up[i], down[j] + 1)`(내리막으로 끝난 수열 뒤에 오르막을 붙임), `a[j] > a[i]`면 `down[i] = max(down[i], up[j] + 1)`. 같은 값은 차이 0이라 어느 전이도 없다.
- 답은 `max(up + down)`. 시간 O(n²)(n=1000이면 50만 쌍), 공간 O(n).

(2) 코드 단계별

- `up`, `down`을 전부 1로 초기화.
- 이중 루프에서 `a[j]`와 `a[i]`의 대소에 따라 반대 방향 배열의 값 +1로 갱신.
- `1 7 4 9 2 5` → 오르내림이 완벽히 번갈아 6. `1 2 3 4` → 오르막만 있으니 아무 두 개로 2. `3 3 3` → 1.
- 10개짜리 예제는 `1 17 5 13 10 16 8` 같은 조합으로 7.

(3) 스스로 다시 짤 때 생각 순서

- "붙일 수 있는 조건이 직전 변화의 방향에 달렸다" → 방향을 상태로 나눠 `up`/`down` 두 배열.
- 각 배열이 반대 배열에서 오는 전이만 적는다(오르막 뒤엔 내리막, 내리막 뒤엔 오르막).
- 초기값 1, 같은 값 제외, 답은 두 배열 전체의 최댓값.
```

**5) 두 가게 교대 근무 최대 수입** · Medium

- **요구사항**: n일 동안 매일 A 가게 또는 B 가게 중 한 곳에서 반드시 일한다. i일에 A에서 일하면 a[i], B에서 일하면 b[i]를 번다. 전날과 **다른 가게**로 옮기는 날에는 이동비 c가 든다(첫날은 이동비 없음). n일 동안의 순수입(번 돈 − 이동비 합)의 최댓값을 구하라.
- **입력**: 첫 줄 n, c (1 ≤ n ≤ 100,000, 0 ≤ c ≤ 1000), 둘째 줄에 a[1..n], 셋째 줄에 b[1..n] (각 0 이상 1000 이하)
- **출력**: 최대 순수입
- **예제**: `4 5 / 10 1 1 10 / 1 10 10 1` → `30` · `3 100 / 5 1 5 / 1 5 1` → `11`
- **셀프체크**: 오늘의 결정에 필요한 과거 정보는 "어제 어느 가게였나"뿐이다 → 상태 2개 `da`, `db`. `da = a[i] + max(da, db - c)`에서 두 상태를 **동시에** 갱신했는가? `c=0`이면 매일 큰 쪽을 고르는 그리디와 같아지는지, `c`가 아주 크면 한 가게에 머무는 두 경우 중 최대가 되는지 확인.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n, c = int(data[idx]), int(data[idx + 1]); idx += 2
    a = [int(data[idx + i]) for i in range(n)]; idx += n
    b = [int(data[idx + i]) for i in range(n)]
    # da = 오늘 A 가게에서 일했을 때 최대 순수입, db = 오늘 B 가게
    da, db = a[0], b[0]                    # 첫날은 이동비 없음
    for i in range(1, n):
        nda = a[i] + max(da, db - c)       # 어제도 A vs 어제 B에서 이동
        ndb = b[i] + max(db, da - c)
        da, db = nda, ndb
    print(max(da, db))
main()

(1) 접근·핵심 아이디어

- "가게를 바꾸면 비용"은 직전 선택이 오늘의 값을 바꾸는 신호다. 오늘 결정에 필요한 과거 정보는 "어제 어느 가게였나" 하나뿐이므로 상태는 두 개다.
- 상태 정의: `da[i]` = i일에 A에서 일했을 때 i일까지의 최대 순수입, `db[i]` = i일에 B에서 일했을 때의 최대 순수입.
- 전이: `da[i] = a[i] + max(da[i-1], db[i-1] - c)`(어제도 A였으면 이동비 없음, 어제 B였으면 `-c`), `db[i]`는 대칭. 초기 `da[0]=a[0]`, `db[0]=b[0]`. 답은 마지막 날 두 상태의 최댓값 — 어느 가게로 끝나도 되므로 둘 다 유효.
- 시간 O(n), 공간 O(1).

(2) 코드 단계별

- 첫날 값으로 `da`, `db`를 초기화.
- 매일 `nda`, `ndb`를 먼저 계산한 뒤 동시에 대입한다(`da`를 먼저 덮으면 `ndb` 계산에 오늘 값이 섞임).
- 마지막에 `max(da, db)`.
- 첫 예제: A→B→B→A로 `10+10+10+10 − 5·2 = 30`. 둘째: 이동비 100이라 A에 머물러 `5+1+5 = 11`. `c=0`이면 매일 큰 쪽 `9+9 = 18`.

(3) 스스로 다시 짤 때 생각 순서

- "직전 선택이 오늘 비용을 바꾸나?" → 직전 선택(가게)을 상태로.
- 각 상태로 들어오는 두 경로(유지/전환)를 적고 전환에만 `-c`.
- 동시 갱신, 답은 마지막 날 두 상태의 max.
```

**6) 부분수열 등장 횟수** · Medium

- **요구사항**: 문자열 S에서 글자를 골라(순서 유지, 연속일 필요 없음) 문자열 T를 만드는 서로 다른 방법의 수를 구하라. 고른 글자의 **위치 집합**이 다르면 다른 방법이다. 답을 1,000,000,007로 나눈 나머지로 출력한다.
- **입력**: 한 줄에 S와 T (공백 구분, 소문자, 1 ≤ |S| ≤ 1000, 1 ≤ |T| ≤ 200)
- **출력**: 방법의 수(MOD). 없으면 0
- **예제**: `banana an` → `3` · `aaa aa` → `3` · `abc abd` → `0`
- **셀프체크**: `dp[i][j]` = S의 앞 i글자로 T의 앞 j글자를 만드는 방법 수. S의 글자를 "안 쓰는" 경우(`dp[i-1][j]`)는 항상 있고, 같은 글자면 "쓰는" 경우(`dp[i-1][j-1]`)를 더한다. 1차원으로 압축할 때 j를 **내림차순**으로 돌아야 같은 S 글자를 두 번 쓰지 않는다(0/1 배낭과 같은 이유). `dp[i][0]=1`(빈 T) 기저를 두었는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    S, T = data[0], data[1]
    MOD = 1_000_000_007
    m = len(T)
    # dp[j] = 지금까지 본 S의 접두사 안에서 T[:j]가 부분수열로 나타나는 방법 수
    dp = [0] * (m + 1)
    dp[0] = 1                              # 빈 T는 항상 1가지
    for ch in S:
        for j in range(m, 0, -1):          # 내림차순: 같은 글자를 두 번 쓰지 않도록
            if T[j - 1] == ch:
                dp[j] = (dp[j] + dp[j - 1]) % MOD
    print(dp[m])
main()

(1) 접근·핵심 아이디어

- 두 문자열을 나란히 비교하는 2차원 표. 상태 정의: `dp[i][j]` = S의 앞 i글자 안에서 T의 앞 j글자를 부분수열로 만드는 방법 수.
- S의 i번째 글자를 **안 쓰면** `dp[i-1][j]`가지, 그 글자가 `T[j-1]`와 같아서 **쓰면** `dp[i-1][j-1]`가지. 전이 `dp[i][j] = dp[i-1][j] + [S[i-1]==T[j-1]]·dp[i-1][j-1]`.
- 경계: `dp[i][0] = 1`(빈 T를 만드는 방법은 아무것도 안 고르는 1가지), `dp[0][j>0] = 0`. 답 `dp[|S|][|T|]`. LCS와 같은 표 모양이지만 `max`가 아니라 **덧셈**이고, 다를 때 왼쪽 칸은 참조하지 않는다는 점이 다르다.
- 시간 O(|S|·|T|), 공간 O(|T|)(행 압축).

(2) 코드 단계별

- `dp[0]=1`, 나머지 0인 1차원 배열로 시작(현재 행).
- S의 글자 `ch`마다 `j`를 `m`부터 1까지 **내림차순**으로 돌며 `T[j-1]==ch`면 `dp[j] += dp[j-1]`. 내림차순이라 `dp[j-1]`은 아직 이번 글자를 반영하지 않은 "이전 행" 값이다 — 오름차순으로 돌면 `aaa/aa`에서 같은 `a`를 두 번 써 답이 부풀려진다.
- `banana an` → `a`(2번째)·`n`(3번째), `a`(2)·`n`(5), `a`(4)·`n`(5) = 3. `aaa aa` → 3개 중 2개 고르기 = 3. `abc abcd` → T가 더 길어 0.

(3) 스스로 다시 짤 때 생각 순서

- "S 안에서 T가 몇 번" → `dp[i][j]` 표, 안 쓰기 + (같으면) 쓰기.
- 빈 T 기저 `dp[·][0]=1`을 먼저 둔다.
- 1차원 압축 시 내림차순, MOD, 답 `dp[m]`.
```

**7) 원형 화환 3색 칠하기 경우의 수** · Medium

- **요구사항**: n개의 구슬이 **원형**으로 이어진 화환을 빨강·노랑·파랑 세 색으로 칠한다. 이웃한 두 구슬은 서로 다른 색이어야 하며, 첫 구슬과 마지막 구슬도 이웃이다. 가능한 칠하기의 수를 1,000,000,007로 나눈 나머지로 구하라(회전·뒤집기로 같아지는 것도 서로 다른 것으로 센다).
- **입력**: 한 줄에 정수 n (2 ≤ n ≤ 100,000)
- **출력**: 경우의 수(MOD)
- **예제**: `3` → `6` · `4` → `18` · `2` → `6`
- **셀프체크**: 일렬이면 직전 색만 상태로 두면 되지만, 원형은 마지막 구슬이 **첫 구슬**과도 달라야 한다. 첫 구슬 색을 하나로 고정해(예: 색 0) 일렬 DP를 돌린 뒤 마지막이 색 0이 아닌 경우만 세고 3배 하면 된다. `n=3` → 3·2·1 = 6, `n=4` → 18이 나오는가? `n=2`는 두 구슬이 서로 이웃이므로 3·2 = 6.

```runner
@@SOLUTION
import sys
def main():
    n = int(sys.stdin.read().split()[0])
    MOD = 1_000_000_007
    # 첫 칸의 색을 0으로 고정하고 마지막에 3배. dp[c] = 현재 칸 색이 c인 경우의 수
    dp = [1, 0, 0]
    for _ in range(2, n + 1):
        s = sum(dp) % MOD
        dp = [(s - dp[0]) % MOD, (s - dp[1]) % MOD, (s - dp[2]) % MOD]   # 직전과 다른 색
    print(3 * (dp[1] + dp[2]) % MOD)       # 마지막 칸은 첫 칸(색 0)과 달라야
main()

(1) 접근·핵심 아이디어

- 일렬 색칠은 "직전 색"만 상태로 두면 되지만, 원형에서는 마지막 구슬이 첫 구슬과도 달라야 한다. 첫 구슬 색을 상태에 넣으면 3배가 되지만, 세 색은 대칭이므로 **첫 색을 0으로 고정**하고 결과를 3배 하면 충분하다.
- 상태 정의: `dp[i][c]` = 첫 구슬이 색 0일 때 i번째 구슬이 색 c인 일렬 칠하기 수. 전이 `dp[i][c] = Σ dp[i-1][c']`(c' ≠ c) = `(전체 합) − dp[i-1][c]`. 초기 `dp[1] = [1, 0, 0]`.
- 답은 마지막 구슬이 첫 구슬(색 0)과 달라야 하므로 `3·(dp[n][1] + dp[n][2])`. 시간 O(n), 공간 O(1).

(2) 코드 단계별

- `dp = [1, 0, 0]`으로 첫 구슬을 색 0으로 고정.
- 매 구슬마다 `s = sum(dp)`를 구하고 각 색을 `s - dp[c]`로 갱신(직전과 같은 색만 제외). `% MOD`에서 음수가 생기지 않도록 파이썬의 `%`가 항상 0 이상을 주는 점을 이용.
- 끝에서 `3 * (dp[1] + dp[2]) % MOD`.
- `n=3` → `dp = [0,1,1]`(2번째), `[2,1,1]`(3번째)에서 `3·(1+1) = 6`. `n=4` → 18, `n=2` → 6, `n=10` → 1026(닫힌 식 `2ⁿ + 2·(−1)ⁿ`과 일치).

(3) 스스로 다시 짤 때 생각 순서

- "원형 = 첫 칸과 마지막 칸도 이웃" → 첫 색을 고정해 일렬 문제로 바꾸고 대칭으로 곱한다.
- 직전 색 상태 3개, 전이는 "전체 − 같은 색".
- 답 위치를 "마지막 색 ≠ 첫 색"으로 제한, 3배, MOD.
```

**8) 한 번 삭제 허용 최대 연속합** · Hard

- **요구사항**: 정수 수열에서 연속한 구간을 하나 고른 뒤, 그 구간 안의 원소를 **최대 하나** 지울 수 있다(안 지워도 된다). 지운 뒤 남은 원소가 1개 이상이어야 하며, 남은 원소 합의 최댓값을 구하라.
- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 둘째 줄에 n개의 정수(-10⁴ 이상 10⁴ 이하)
- **출력**: 최대 합
- **예제**: `4 / 1 -2 0 3` → `4` · `5 / 2 -5 3 -1 4` → `8` · `4 / -1 -1 -1 -1` → `-1`
- **셀프체크**: Kadane의 `cur`를 "삭제를 아직 안 한 구간"(`keep`)과 "이미 하나 지운 구간"(`dele`) 두 상태로 나눈다. `dele[i] = max(keep[i-1], dele[i-1] + a[i])` — 앞 항은 **a[i]를 지우는** 경우라 `a[i]`를 더하지 않는다. `dele[0]`은 원소 하나를 지우면 빈 구간이 되므로 `-inf`. 전부 음수면 하나만 남긴 `-1`이 답(0 아님). 답은 매 칸 `keep`, `dele` 중 최댓값을 따로 기록.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    NEG = float('-inf')
    keep = a[0]                            # i를 끝으로 하고 아직 삭제 안 함
    dele = NEG                             # i를 끝으로 하고 이미 하나 삭제함
    best = a[0]
    for i in range(1, n):
        x = a[i]
        new_dele = max(keep, dele + x)     # x를 삭제(keep 그대로) vs 이미 삭제한 구간에 x 추가
        new_keep = max(x, keep + x)        # 새로 시작 vs 이어붙이기
        keep, dele = new_keep, new_dele
        best = max(best, keep, dele)
    print(best)
main()

(1) 접근·핵심 아이디어

- 최대 연속합(Kadane)에 "하나를 지울 수 있다"는 선택이 붙었다. 지웠는지 여부가 이후 전이를 바꾸므로 **삭제 여부**를 상태로 승격한다.
- 상태 정의: `keep[i]` = i를 끝으로 하고 아직 아무것도 안 지운 구간의 최대합, `dele[i]` = i를 끝으로 하고 정확히 하나를 지운 구간의 최대합(i 자신이 지워진 경우 포함).
- 전이: `keep[i] = max(a[i], keep[i-1] + a[i])`(보통 Kadane), `dele[i] = max(keep[i-1], dele[i-1] + a[i])` — 첫 항은 `a[i]`를 지우고 그 앞 구간을 그대로 두는 것(그래서 `a[i]`를 더하지 않음), 둘째 항은 이미 지운 구간에 `a[i]`를 이어붙이는 것.
- 초기 `keep[0] = a[0]`, `dele[0] = -inf`(원소 하나를 지우면 빈 구간이라 무효). 답은 모든 i의 `max(keep[i], dele[i])`. 시간 O(n), 공간 O(1).

(2) 코드 단계별

- `keep = a[0]`, `dele = -inf`, `best = a[0]`.
- 각 `x`에서 `new_dele`를 **먼저** 계산한다(이전 `keep`이 필요) → `new_keep` 계산 → 동시 대입 → `best` 갱신.
- `1 -2 0 3` → `-2`를 지워 `1+0+3 = 4`. `2 -5 3 -1 4` → `-5`를 지워 `2+3-1+4 = 8`. 전부 `-1`이면 `-1`(빈 구간 0은 불가). `n=1`이면 루프 없이 `a[0]`.

(3) 스스로 다시 짤 때 생각 순서

- "Kadane + 한 번의 예외 행동" → 예외를 썼는지 여부를 상태로 두 개 굴린다.
- `dele`로 들어오는 두 경로(지금 지움 / 전에 지움)를 구분해 `a[i]`를 더할지 말지 결정.
- `dele[0] = -inf`, 전부 음수 케이스, `best` 분리 기록.
```

**9) 사전순 최소 LCS 복원** · Hard

- **요구사항**: 두 문자열 A, B의 최장 공통 부분수열(LCS) 길이를 구하고, 그 길이를 갖는 공통 부분수열이 여러 개면 **사전순으로 가장 앞서는** 것을 출력하라.
- **입력**: 한 줄에 A와 B (공백 구분, 소문자, 각 길이 1 이상 100 이하)
- **출력**: 첫 줄에 LCS 길이. 길이가 1 이상이면 둘째 줄에 사전순 최소 LCS 문자열(길이 0이면 첫 줄만 출력)
- **예제**: `abcbdab bdcaba` → `4 / bcab` · `xyxy yxyx` → `3 / xyx` · `ace bdf` → `0`
- **셀프체크**: 뒤에서 앞으로 채운 `L[i][j]` = `A[i:]`와 `B[j:]`의 LCS 길이 표를 쓰면 "지금 위치에서 앞으로 몇 글자 더 얻을 수 있나"를 바로 알 수 있다. 복원은 앞에서부터 `a`~`z` 순으로 후보 글자를 시도해, 그 글자를 A·B에서 **가장 먼저** 나오는 위치로 잡고도 `L`이 유지되면(`L[pa+1][pb+1] + 1 == L[i][j]`) 채택한다. `abcbdab / bdcaba`의 길이 4 LCS가 `bcab`, `bcba`, `bdab` 세 개이고 사전순 최소가 `bcab`임을 확인.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    A, B = data[0], data[1]
    n, m = len(A), len(B)
    # L[i][j] = A[i:]와 B[j:]의 LCS 길이 (뒤에서 앞으로 채움)
    L = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n - 1, -1, -1):
        for j in range(m - 1, -1, -1):
            if A[i] == B[j]:
                L[i][j] = L[i + 1][j + 1] + 1
            else:
                L[i][j] = max(L[i + 1][j], L[i][j + 1])
    # nxt[i][c] = A[i:]에서 문자 c가 처음 나오는 위치 (없으면 -1)
    def build_next(s):
        nxt = [[-1] * 26 for _ in range(len(s) + 1)]
        for i in range(len(s) - 1, -1, -1):
            nxt[i] = nxt[i + 1][:]
            nxt[i][ord(s[i]) - 97] = i
        return nxt
    na, nb = build_next(A), build_next(B)
    res = []
    i = j = 0
    while L[i][j] > 0:
        for c in range(26):                # 작은 글자부터 시도
            pa, pb = na[i][c], nb[j][c]
            if pa == -1 or pb == -1:
                continue
            if L[pa + 1][pb + 1] + 1 == L[i][j]:   # 이 글자를 골라도 최대 길이 유지
                res.append(chr(97 + c))
                i, j = pa + 1, pb + 1
                break
    print(len(res))
    if res:
        print(''.join(res))
main()

(1) 접근·핵심 아이디어

- LCS 길이는 보통 접두사 표 `dp[i][j]`로 구하지만, 문자열을 **앞에서부터** 결정하려면 "여기서부터 끝까지 앞으로 얼마나 더 얻을 수 있나"가 필요하다. 그래서 상태를 접미사로 정의한다: `L[i][j]` = `A[i:]`와 `B[j:]`의 LCS 길이. 전이는 LCS와 같고(같으면 대각선 +1, 다르면 아래·오른쪽 max) 채우는 방향만 뒤→앞이다.
- 복원은 그리디다. 현재 위치 `(i, j)`에서 `a`부터 `z`까지 차례로, 그 글자가 A와 B에서 다음에 나오는 **가장 이른** 위치 `(pa, pb)`를 찾아 `L[pa+1][pb+1] + 1 == L[i][j]`이면 채택한다. 이 조건은 "이 글자를 지금 고르고도 남은 최대 길이를 잃지 않는다"는 뜻이고, 작은 글자부터 시도하므로 사전순 최소가 보장된다. 같은 글자라면 가장 이른 위치를 잡는 것이 뒤에 남는 여지를 가장 크게 하므로 손해가 없다.
- 다음 위치를 매번 스캔하면 느리니 `nxt[i][c]`(i 이후 글자 c의 첫 위치)를 뒤에서부터 미리 만든다. 시간 O(n·m + (n+m)·26 + LCS길이·26), 공간 O(n·m + (n+m)·26).

(2) 코드 단계별

- `L`을 `(n+1)×(m+1)`로 만들고 `i`, `j`를 모두 내림차순으로 돌며 채운다. `L[n][·] = L[·][m] = 0`이 자동 경계.
- `build_next`: `nxt[len] = 전부 -1`, `i`를 뒤에서 앞으로 가며 직전 행을 복사하고 `s[i]`의 위치만 `i`로 덮어쓴다.
- `while L[i][j] > 0`: 26글자를 순서대로 시도해 첫 채택 글자를 붙이고 `(i, j) = (pa+1, pb+1)`로 이동. 채택 가능한 글자는 반드시 존재한다(`L[i][j] > 0`이면 어떤 공통 글자로 시작하는 LCS가 있으므로).
- 길이를 출력하고, 길이가 0이 아니면 문자열도 출력. `abcbdab / bdcaba` → `bcab`(`bcba`, `bdab`보다 앞섬). `xyxy / yxyx` → `xyx`(`yxy`보다 앞섬). 공통 글자가 없으면 `0`만.

(3) 스스로 다시 짤 때 생각 순서

- "복원 + 사전순" → 접미사 LCS 표(`L[i][j]`)로 남은 최대 길이를 알 수 있게 만든다.
- 앞에서부터 `a`~`z` 순으로 "골라도 최대 길이 유지" 조건을 검사하는 그리디를 짠다.
- 다음 위치 표로 탐색을 O(1)로 만들고, 길이 0일 때 출력 형식을 확인.
```

**10) 와일드카드 패턴 매칭** · Hard

- **요구사항**: 패턴 p와 문자열 s가 주어진다. 패턴에서 `?`는 아무 글자 **한 개**, `*`는 아무 글자 **0개 이상**(빈 문자열 포함)과 매칭되고, 그 외 글자는 그대로 일치해야 한다. p가 s **전체**와 매칭되면 `yes`, 아니면 `no`를 출력하라. 여러 쌍이 주어진다.
- **입력**: 첫 줄 T (1 ≤ T ≤ 20), 이후 T줄에 패턴 p와 문자열 s (공백 구분, p는 소문자·`?`·`*`, s는 소문자, 각 길이 1 이상 200 이하)
- **출력**: 각 쌍마다 `yes` 또는 `no`를 한 줄씩
- **예제**: `4 / a*c abc / a?c ac / *b* abc / a*b*c abbbc` → `yes / no / yes / yes` · `3 / * a / ab abc / a*a a` → `yes / no / no`
- **셀프체크**: `dp[i][j]` = `s[:i]`가 `p[:j]`와 매칭되는가. `*`는 "한 글자 더 먹기(`dp[i-1][j]`)" 또는 "0글자(`dp[i][j-1]`)" 두 갈래. 빈 s에 대한 첫 행 `dp[0][j]`는 앞이 전부 `*`일 때만 참이 되는데, 이 초기화를 빠뜨리면 `*b*`가 틀린다. `a*a`와 `a`는 `a`가 두 번 필요하므로 `no`. 부분 매칭이 아니라 **전체** 매칭(`ab` vs `abc`는 `no`)임을 확인.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    t = int(data[0])
    out = []
    for k in range(t):
        p, s = data[1 + 2 * k], data[2 + 2 * k]
        n, m = len(s), len(p)
        # dp[i][j] = s[:i]가 p[:j]와 매칭되는가
        dp = [[False] * (m + 1) for _ in range(n + 1)]
        dp[0][0] = True
        for j in range(1, m + 1):
            if p[j - 1] == '*':
                dp[0][j] = dp[0][j - 1]    # '*'가 0글자와 매칭
        for i in range(1, n + 1):
            for j in range(1, m + 1):
                if p[j - 1] == '*':
                    dp[i][j] = dp[i - 1][j] or dp[i][j - 1]   # 한 글자 더 먹기 vs 0글자
                elif p[j - 1] == '?' or p[j - 1] == s[i - 1]:
                    dp[i][j] = dp[i - 1][j - 1]
        out.append('yes' if dp[n][m] else 'no')
    print('\n'.join(out))
main()

(1) 접근·핵심 아이디어

- 두 문자열(패턴·대상)을 나란히 비교하는 2차원 표. 상태 정의: `dp[i][j]` = `s`의 앞 i글자가 `p`의 앞 j글자와 완전히 매칭되는가(참/거짓).
- 전이는 `p[j-1]`의 종류로 갈린다. 일반 글자 또는 `?`: `s[i-1]`와 맞으면 대각선 `dp[i-1][j-1]`. `*`: 두 가지 — `*`가 `s[i-1]`를 한 글자 더 먹고 계속 `*`로 남는 `dp[i-1][j]`, 또는 `*`가 0글자와 매칭되어 사라지는 `dp[i][j-1]`. 둘 중 하나라도 참이면 참.
- 경계: `dp[0][0] = True`(빈 s와 빈 p). `dp[0][j]`는 `p[:j]`가 전부 `*`일 때만 참 — 앞에서부터 `dp[0][j] = dp[0][j-1] and p[j-1]=='*'`로 전파. `dp[i][0]`(빈 패턴, 비어 있지 않은 s)은 거짓.
- 답 `dp[|s|][|p|]`. 시간 O(|s|·|p|), 공간 O(|s|·|p|)(두 행으로 줄일 수도 있음).

(2) 코드 단계별

- 각 쌍마다 `(n+1)×(m+1)` 불리언 표를 만들고 `dp[0][0]=True`, 첫 행은 `*`가 이어지는 동안만 참으로 채운다.
- 이중 루프에서 `p[j-1]`가 `*`면 `dp[i-1][j] or dp[i][j-1]`, `?`거나 같은 글자면 `dp[i-1][j-1]`, 아니면 거짓 그대로.
- `a*c / abc` → `*`가 `b`를 먹어 `yes`. `a?c / ac` → `?`가 먹을 글자가 없어 `no`. `a*b*c / abbbc` → 첫 `*`가 `bb`, 둘째 `*`가 0글자 `yes`. `* / a` → `yes`. `ab / abc` → 전체 매칭 실패 `no`. `a*a / a` → `a`가 두 번 필요해 `no`. `a**b / ab` → 연속 `*` 둘 다 0글자 `yes`. `?*? / a` → `?` 두 개에 글자 하나뿐 `no`.

(3) 스스로 다시 짤 때 생각 순서

- "전체 매칭 + 와일드카드" → `dp[i][j]` 표, 패턴 글자 종류별로 전이를 나눈다.
- `*`의 두 갈래(한 글자 더 / 0글자)와 첫 행 초기화(앞이 전부 `*`)를 먼저 처리.
- 답은 표의 오른쪽 아래 칸, 부분 매칭이 아님을 예제로 확인.
```

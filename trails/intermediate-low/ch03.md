> 개요: 재귀 기반 깊이 우선 탐색(DFS)을 그래프와 격자에서 자유자재로 다루는 법을 배운다. 방문 관리·연결요소·경로 추적·되돌아오기(백트래킹과의 경계)까지, DFS를 "실전 도구"로 쓰는 감각을 잡는다.
>
> 전에 배운 것 → 이번에 새로: Ch2의 재귀/백트래킹은 "정답 후보를 만들며 파고들었다"면, 이번 DFS는 같은 재귀 뼈대에 **`visited` 방문 관리**를 얹어 "이미 본 노드·칸을 다시 밟지 않으며 그래프/격자를 빠짐없이 순회"하는 데 쓴다. 즉 새로 추가되는 핵심은 방문 배열과 인접 구조(인접리스트·4방향 이동)다.

## L1. DFS

**개념**

- DFS(Depth-First Search, 깊이 우선 탐색)는 한 갈래를 갈 수 있는 데까지 끝까지 파고든 뒤, 막히면 직전 갈림길로 되돌아와(backtrack) 다음 갈래를 탐색하는 그래프 순회 방식이다. "일단 깊게, 막히면 되돌아온다"가 전부다.
- 이미 DFS의 존재는 알고 있을 것이다. 이 레슨의 목표는 재설명이 아니라, DFS를 (1) 인접리스트 그래프, (2) 2차원 격자 두 무대에서 확실하게 구현하고, (3) 방문 처리 위치·시점을 정확히 통제하며, (4) 연결요소·경로·사이클 등 전형 응용으로 확장하는 것이다.
- 동작 원리(재귀 관점, 단계):

  1. 현재 노드를 방문 처리한다(`visited[cur] = True`).
  2. 현재 노드에서 갈 수 있는 인접 노드를 하나씩 본다.
  3. 아직 방문하지 않은 인접 노드가 있으면 그 노드로 재귀 호출한다(더 깊이 들어감).
  4. 더 갈 곳이 없으면 함수가 반환되며 자동으로 직전 노드로 되돌아온다(콜스택이 backtrack을 대신해 준다).

- 핵심은 "재귀 호출 = 스택에 프레임을 쌓는 것"이라는 관점이다. 명시적 스택으로 반복 구현도 가능하지만, DFS는 재귀로 쓰는 편이 압도적으로 짧고 자연스럽다.

```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)  # 깊은 재귀 대비: DFS의 필수 안전장치

# (1) 인접리스트 그래프 DFS
def dfs(cur):
    visited[cur] = True
    # (필요하면) 여기서 방문 순서 기록, 카운트 증가 등
    for nxt in graph[cur]:
        if not visited[nxt]:
            dfs(nxt)

# (2) 2차원 격자 DFS
dr = (-1, 1, 0, 0)
dc = (0, 0, -1, 1)  # 상하좌우
def dfs_grid(r, c):
    visited[r][c] = True
    for d in range(4):
        nr, nc = r + dr[d], c + dc[d]
        if 0 <= nr < N and 0 <= nc < M and not visited[nr][nc] and grid[nr][nc] == 1:
            dfs_grid(nr, nc)
```

**그림으로 보기**

- DFS는 "한 방향으로 끝까지 → 막히면 되돌아오기"다. 4×4 격자에서 `(0,0)`부터 상·하·좌·우 순서로 재귀했을 때, 각 칸을 몇 번째로 방문하는지 번호를 적었다(`#`은 벽).

```text
   input grid          DFS visit order (up, down, left, right)
   0 1 2 3             ┌──┬──┬──┬──┐
 0 . . . .             │ 1│12│11│10│
 1 . # # .             │ 2│ #│ #│ 9│
 2 . . # .             │ 3│ 4│ #│ 8│
 3 # . . .             │ #│ 5│ 6│ 7│
                       └──┴──┴──┴──┘
```

  번호 1→12가 한 붓 그리기처럼 이어진다. 갈림길에서 옆으로 새지 않고, 막다른 곳에 닿아야 비로소 되돌아온다.

- "되돌아오기"는 코드 어디에도 없다. `return` 한 번이 곧 한 칸 되돌아오기이고, 콜스택이 "직전 갈림길"을 대신 기억해 준다. 위 격자를 따라간 스택의 모양:

```text
  depth   frame                      stack
  -----   ---------------------      -----
    0     dfs(0,0)                   push
    1      dfs(1,0)                  push
    2       dfs(2,0)                 push
    3        dfs(2,1)                push
   ...        ...                    deeper and deeper
   11          dfs(0,1)  dead end    return
   10         dfs(0,2)   resume      return
   ...       ...                     pop, pop, pop ...
    0     dfs(0,0)                   empty
```

  깊이 11까지 쌓였다가 한꺼번에 풀린다. 12칸짜리 격자에서 스택 깊이가 12까지 간다는 것은, 칸이 백만 개면 깊이도 백만이 될 수 있다는 뜻이다.

- 같은 격자를 DFS와 BFS(다음 챕터에서 배운다)로 각각 훑으면 방문 순서가 완전히 달라진다. 벽이 없는 3×4 격자, 시작 `(0,0)`:

```text
  DFS order          BFS order          BFS dist
 ┌──┬──┬──┬──┐      ┌──┬──┬──┬──┐      ┌──┬──┬──┬──┐
 │ 1│ 6│ 7│12│      │ 1│ 3│ 6│ 9│      │ 0│ 1│ 2│ 3│
 │ 2│ 5│ 8│11│      │ 2│ 5│ 8│11│      │ 1│ 2│ 3│ 4│
 │ 3│ 4│ 9│10│      │ 4│ 7│10│12│      │ 2│ 3│ 4│ 5│
 └──┴──┴──┴──┘      └──┴──┴──┴──┘      └──┴──┴──┴──┘
```

  DFS는 `(0,3)`에 12번째로 도착하고, 그때 지나온 경로 길이는 11이다. 실제 최단은 3(맨 오른쪽). **DFS의 "처음 도달"은 최단이 아니다.**

**손으로 따라가기**

위 4×4 격자에서 `dfs(0,0)`을 손으로 따라가 본다. 방향은 상·하·좌·우 순서.

| 단계 | 진입/반환 | 현재 칸 | 스택 깊이 | 왜 그쪽으로 갔나 |
|---|---|---|---|---|
| 1 | 진입 | `(0,0)` | 1 | 위는 범위 밖 → 아래 `(1,0)` |
| 2 | 진입 | `(1,0)` | 2 | 위는 방문됨 → 아래 `(2,0)` |
| 3 | 진입 | `(2,0)` | 3 | 아래 `(3,0)`은 벽 → 오른쪽 `(2,1)` |
| 4 | 진입 | `(2,1)` | 4 | 위 `(1,1)`은 벽 → 아래 `(3,1)` |
| 5 | 진입 | `(3,1)` | 5 | 아래는 범위 밖, 왼쪽은 벽 → 오른쪽 |
| 6 | 진입 | `(3,2)` | 6 | 위 `(2,2)`는 벽 → 오른쪽 |
| 7 | 진입 | `(3,3)` | 7 | 오른쪽은 범위 밖 → 위 `(2,3)` |
| 8~11 | 진입 | `(2,3)`→`(1,3)`→`(0,3)`→`(0,2)` | 8~11 | 오른쪽 벽을 타고 위로, 그다음 왼쪽으로 |
| 12 | 진입 | `(0,1)` | 12 | 상·하·좌·우가 전부 벽이거나 방문됨 = 막다른 곳 |
| 13~24 | 반환 | — | 12 → 0 | 갈 곳이 없으니 프레임이 차례로 반환된다 |

- 방문한 칸은 12개(= 16칸에서 벽 4개를 뺀 전부)이고, 되돌아오는 13~24단계에서는 새로 방문되는 칸이 **하나도 없다**. "탐색이 끝났다"는 곧 "스택이 비었다"는 뜻이다.

**왜 이렇게 되는가**

- **시간복잡도 O(V + E)의 근거**: `visited` 검사 덕분에 `dfs(v)`는 정점마다 **정확히 한 번**만 호출된다 → 호출 횟수 V. 각 호출은 자기 인접리스트를 한 번 훑으므로 모든 호출이 훑는 총량은 `deg(v)`의 합, 즉 무방향이면 2E다. 둘을 더해 O(V + E). 격자는 V = N·M이고 칸마다 이웃이 4개로 상수라 O(4·N·M) = O(N·M)이 된다.
- **방문 표시를 "들어오자마자" 해야 하는 이유**: 표시를 재귀 직전으로 미루면 `a → b → a` 같은 사이클에서 `a`가 아직 미표시라 다시 들어가 무한 재귀가 된다. 진입 즉시 표시하면 "지금 스택 위에 있는 정점 = 이미 표시된 정점"이 되어, 되돌아가는 간선이 자동으로 막힌다.
- **DFS로 최단거리를 못 구하는 이유**: DFS가 정점 `v`에 처음 도달했을 때의 거리는 "탐색 순서가 우연히 만든 어떤 경로의 길이"일 뿐 최소가 아니다(위 그림에서 3 대신 11). DFS로 최단을 구하려면 `visited[nxt] = True → dfs → visited[nxt] = False`로 표시를 되돌리며 **모든 단순 경로를 열거**해야 하는데, 경로 수는 정점 수에 대해 지수적으로 늘어난다. 그래서 "가중치가 같은 최단거리"는 BFS의 몫이다.
- **재귀 깊이는 최악에 V**: 위 그림처럼 한 줄로 이어진 모양에서는 되돌아오기 전에 모든 칸이 스택에 쌓인다. 1000×1000 격자면 깊이가 10^6까지 갈 수 있고, `sys.setrecursionlimit`을 올려도 OS가 주는 스택이 먼저 바닥난다 — 이때가 명시적 스택 DFS로 바꿀 시점이다.

**접근 전략**

- 방문 처리 "위치"를 명확히 정하라. 가장 안전한 패턴은 "함수에 들어오자마자 현재 노드를 방문 처리"(위 코드). 반대로 "다음 노드로 재귀하기 직전에 미리 방문 처리"하는 스타일도 있는데, 후자는 시작 노드를 별도로 방문 처리해야 하고 중복 진입을 부르기 쉬우니, 익숙해지기 전엔 "들어오자마자 방문" 한 가지로 통일하는 것을 권한다.
- 전형 응용 4가지를 패턴으로 외워 두면 대부분이 조합이다.

  1. 연결요소(Connected Component) 세기: 모든 정점을 순회하며 `visited`가 안 된 정점에서 DFS를 시작할 때마다 카운트 +1. 격자에서는 "덩어리(섬)"의 개수·크기를 세는 문제로 자주 나온다.
  2. 도달 가능성/경로 존재: 시작점에서 DFS 후 목표점의 `visited`를 확인.
  3. 경로 복원: 재귀에 `path` 리스트를 넘겨 진입 시 append, 반환 직전 pop(백트래킹). 특정 경로를 "만들며" 탐색할 때.
  4. 사이클 탐지: 방문 상태를 3색(0=미방문, 1=현재 스택에 있음, 2=완료)으로 관리해 "현재 재귀 경로 위의 노드로 되돌아가는 간선"이 있으면 사이클(주로 방향 그래프). 무방향 그래프는 "부모가 아닌 방문 노드로 가는 간선"이 사이클.

- 언제 DFS를 고르나: "모든 정점/칸을 빠짐없이 방문", "덩어리/영역", "경로가 존재하는가", "가능한 조합을 깊이 만들며 탐색" 같은 요구에 자연스럽다. 반대로 "최단 거리(간선 가중치 동일)"는 DFS가 아니라 BFS가 정석이다(DFS는 최단을 보장하지 않는다). 다음 챕터의 BFS와 역할을 헷갈리지 말 것.
- 복잡도: 인접리스트 기준 시간 O(V + E), 격자(N×M)는 O(N·M). 공간은 `visited` O(V) 또는 O(N·M)에 더해 재귀 콜스택 깊이만큼 O(V)(최악, 일자형 그래프)가 추가로 든다.
- 파이썬 구현 팁:

  - `sys.setrecursionlimit(10**6)`를 반드시 켜라. 파이썬 기본 재귀 한도(약 1000)로는 정점이 몇천만 되어도 `RecursionError`가 난다. 단, 실제 콜스택은 OS 스택 크기 제한도 받으므로, 재귀 깊이가 수십만을 넘길 위험이 크면 명시적 스택 기반 반복 DFS로 바꾸는 편이 안전하다.
  - 입력이 많으면 `input = sys.stdin.readline`로 바꾼다.
  - `graph`는 `[[] for _ in range(V+1)]` 인접리스트로. `visited`는 격자면 2차원 리스트, 그래프면 1차원 리스트/`set`.
  - 흔한 실수: (a) 방문 처리를 안 하거나 늦게 해서 같은 노드에 무한 재귀, (b) 격자 범위 검사(`0 <= nr < N`)를 빠뜨려 인덱스 오류, (c) DFS로 최단거리를 구하려 함, (d) 재귀 한도 미설정.

**문제**

**1) 섬의 개수와 가장 큰 섬** · Easy

- **요구사항**: `N×M` 격자에서 `1`은 땅, `0`은 바다다. 상하좌우로 인접한 땅끼리는 같은 섬이다(대각선은 연결 아님). 섬의 총 개수와, 가장 큰 섬의 넓이(칸 수)를 구하라.
- **입력**: 첫 줄에 `N M`. 이어서 `N`개의 줄에 각 줄 `M`개의 `0/1`이 공백 없이 주어진다. (`1 ≤ N, M ≤ 1000`)
- **출력**: `섬의 개수`와 `가장 큰 섬의 넓이`를 공백으로 구분해 한 줄에.
- **예제**:

  - `입력`:
    ```
    5 5
    11000
    11000
    00100
    00011
    00011
    ```
    → `출력`: `3 4`
  - `입력`:
    ```
    3 3
    101
    010
    101
    ```
    → `출력`: `5 1`

- **셀프체크**: 방문 안 된 땅에서 DFS를 시작할 때마다 섬 카운트를 늘리고, 그 DFS가 방문한 칸 수가 그 섬의 넓이다. 1000×1000이면 최대 백만 칸 → 콜스택 깊이가 최악에 백만에 근접할 수 있으니(한 줄로 이어진 뱀 모양) 재귀 한도 설정 필수, 위험하면 반복 DFS 고려. 두 번째 예제의 답이 "섬 5개, 각 넓이 1"이 되는지 직접 확인해 보라(대각선은 연결이 아님).

```runner
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

def main():
    N, M = map(int, input().split())
    grid = [[int(ch) for ch in input().strip()] for _ in range(N)]
    visited = [[False] * M for _ in range(N)]
    dr = (-1, 1, 0, 0)
    dc = (0, 0, -1, 1)

    def flood(sr, sc):
        # 반복(명시적 스택) DFS: 1000x1000 뱀 모양에서도 콜스택 폭발이 없다.
        stack = [(sr, sc)]
        visited[sr][sc] = True
        area = 0
        while stack:
            r, c = stack.pop()
            area += 1
            for d in range(4):
                nr, nc = r + dr[d], c + dc[d]
                if 0 <= nr < N and 0 <= nc < M and not visited[nr][nc] and grid[nr][nc] == 1:
                    visited[nr][nc] = True
                    stack.append((nr, nc))
        return area

    count = 0
    best = 0
    for i in range(N):
        for j in range(M):
            if grid[i][j] == 1 and not visited[i][j]:
                count += 1
                a = flood(i, j)
                if a > best:
                    best = a
    print(count, best)

main()

(1) 접근·핵심 아이디어

- 격자 전체를 훑다가 "아직 방문 안 된 땅(`1`)"을 만나면 거기서 하나의 섬 탐색(플러드 필)을 시작한다. 탐색을 시작할 때마다 섬 개수를 +1 하고, 그 탐색이 밟은 칸 수가 곧 그 섬의 넓이다.
- 인접은 상하좌우 4방향만(대각선 제외). 두 번째 예제에서 대각선으로만 붙은 `1`들이 전부 따로따로 세어져 "섬 5개, 넓이 1"이 되는 것이 이 규칙의 확인 포인트다.
- 재귀 대신 **명시적 스택**으로 DFS를 돌린다. 1000×1000에서 한 줄로 이어진 섬은 콜스택 깊이가 백만에 육박해 재귀로는 위험하기 때문.

(2) 코드 단계별

- `grid`를 정수 2차원 배열로, `visited`를 같은 크기의 불리언 배열로 만든다.
- `flood(sr, sc)`: 시작 칸을 스택에 넣고 방문 처리한 뒤, 스택에서 꺼낼 때마다 `area += 1`. 4방향 이웃이 범위 안·미방문·땅이면 방문 처리 후 스택에 push. 스택을 넣을 때 바로 방문 처리해야 같은 칸이 중복으로 안 들어간다.
- 이중 for로 모든 칸을 보며 미방문 땅에서 `flood`를 호출, 반환된 넓이로 `count`와 `best`(최대 넓이)를 갱신한다.

(3) 스스로 다시 짤 때 생각 순서

- 먼저 "연결요소 개수 세기" 뼈대를 떠올린다: 미방문 시작점마다 count+1 + 탐색.
- 여기에 "탐색이 방문한 칸 수 = 넓이"를 얹어 최댓값을 함께 추적.
- 방문 처리 시점(스택에 넣기 직전)과 4방향 오프셋 `dr/dc`, 범위 검사만 정확히 하면 끝. 깊이가 클 수 있으니 재귀보다 반복 스택을 기본으로 택한다.
```

**2) 미로 탈출 가능 여부** · Medium

- **요구사항**: `N×M` 격자 미로에서 `0`은 벽, `1`은 이동 가능한 길이다. 시작 칸 `(sr, sc)`에서 상하좌우로만 이동해 도착 칸 `(er, ec)`에 도달할 수 있는지 판정하라. 도달 가능하면 방문한(도달 가능한) 칸의 총 개수도 함께 출력한다.
- **입력**: 첫 줄 `N M`. 다음 `N`줄에 격자(`0/1`, 공백 없이). 마지막 줄에 `sr sc er ec` (0-based 좌표). (`1 ≤ N, M ≤ 500`, 시작·도착 칸은 항상 `1`)
- **출력**: 도달 가능하면 `YES`와 시작 칸에서 도달 가능한 칸의 개수를 공백으로. 불가능하면 `NO`만.
- **예제**:

  - `입력`:
    ```
    3 4
    1101
    1001
    1111
    0 0 0 3
    ```
    → `출력`: `YES 8`
  - `입력`:
    ```
    3 3
    100
    010
    001
    0 0 2 2
    ```
    → `출력`: `NO`

- **셀프체크**: 시작 칸에서 DFS로 도달 가능한 모든 칸을 방문 처리한 뒤 도착 칸의 방문 여부만 보면 된다. 첫 예제에서 시작 `(0,0)`의 연결 덩어리 칸 수를 세어 보면: `(0,0),(0,1),(1,0),(2,0),(2,1),(2,2),(2,3),(1,3)`으로 8칸이고 도착 `(0,3)`도 이 덩어리에 포함 → `YES 8`. `(0,3)`이 도착이지만 위쪽 경로가 아니라 아래로 우회해 닿는다는 점을 확인하라. 두 번째 예제는 대각선 이동이 없어 어디로도 못 가므로 `NO`.

```runner
@@SOLUTION
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

def main():
    N, M = map(int, input().split())
    grid = [[int(ch) for ch in input().strip()] for _ in range(N)]
    sr, sc, er, ec = map(int, input().split())
    visited = [[False] * M for _ in range(N)]
    dr = (-1, 1, 0, 0)
    dc = (0, 0, -1, 1)

    # 시작 칸에서 반복 DFS로 도달 가능한 칸을 모두 방문 처리하며 개수를 센다.
    stack = [(sr, sc)]
    visited[sr][sc] = True
    cnt = 0
    while stack:
        r, c = stack.pop()
        cnt += 1
        for d in range(4):
            nr, nc = r + dr[d], c + dc[d]
            if 0 <= nr < N and 0 <= nc < M and not visited[nr][nc] and grid[nr][nc] == 1:
                visited[nr][nc] = True
                stack.append((nr, nc))

    if visited[er][ec]:
        print("YES", cnt)
    else:
        print("NO")

main()

- "도달 가능한가?"는 결국 시작 칸이 속한 연결요소 문제다. 시작 칸에서 DFS로 갈 수 있는 모든 길 칸을 방문 처리하고, 마지막에 도착 칸이 방문됐는지만 확인하면 된다.
- 도달 가능하면 그 연결요소의 칸 수가 곧 "도달 가능한 칸의 개수"이므로 탐색 중에 세어 두면 추가 작업이 필요 없다.
- 이동은 상하좌우 4방향뿐. 두 번째 예제처럼 대각선으로만 이어진 길은 서로 끊긴 것으로 취급되어 `NO`가 된다.

(2) 코드 단계별

- 격자와 시작·도착 좌표를 읽는다(좌표는 0-based).
- 시작 칸을 스택에 넣고 방문 처리한 뒤, 스택에서 꺼낼 때마다 `cnt += 1`. 4방향 이웃이 범위 안·미방문·길(`1`)이면 방문 처리 후 push.
- 탐색이 끝나면 `visited[er][ec]`가 `True`면 `YES`와 `cnt`를, 아니면 `NO`만 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "경로 존재 = 같은 연결요소인가"로 문제를 바꿔 생각한다.
- 시작점 하나에서만 DFS/BFS를 돌리면 되고(전체 순회 아님), 방문 표시와 카운트를 동시에 한다.
- 마지막에 도착 칸의 방문 플래그만 보면 판정 끝. 출력 형식(도달 시 개수 동반, 불가 시 `NO`만)에 유의한다.
```

**3) 방향 그래프 사이클 판정** · Medium

- **요구사항**: 정점 `N`개, 방향 간선 `M`개인 그래프가 주어진다. 이 그래프에 사이클이 존재하는지 판정하라(자기 자신으로의 간선도 사이클로 본다).
- **입력**: 첫 줄 `N M`. 이어서 `M`개의 줄에 `u v` (정점 `u`에서 `v`로 가는 방향 간선, 1-based). (`1 ≤ N ≤ 10^5`, `0 ≤ M ≤ 2×10^5`)
- **출력**: 사이클이 있으면 `YES`, 없으면 `NO`.
- **예제**:

  - `입력`:
    ```
    3 3
    1 2
    2 3
    3 1
    ```
    → `출력`: `YES`
  - `입력`:
    ```
    4 3
    1 2
    1 3
    2 4
    ```
    → `출력`: `NO`

- **셀프체크**: 3색(0/1/2) DFS로 판정한다. 노드에 진입할 때 `state=1`(현재 재귀 경로 위), 자식 탐색을 마치면 `state=2`(완료). 탐색 도중 `state=1`인 노드를 다시 만나면 그 노드가 지금 내 재귀 경로 상에 있다는 뜻이므로 사이클이다. 단순히 `visited` 하나로만 판정하면 "이미 완료된 다른 갈래를 다시 만나는 경우"까지 사이클로 오판하니 주의(그래서 2색이 아니라 3색). 시작 정점이 여러 개일 수 있으니 모든 정점에 대해 미방문이면 DFS를 돌려야 한다. `N`이 10만이라 재귀 깊이가 깊어질 수 있으니 `sys.setrecursionlimit` 설정, 정 불안하면 반복 DFS로 3색 관리. 첫 예제는 `1→2→3→1`로 사이클, 둘째는 DAG라 사이클 없음.

```runner
@@SOLUTION
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

def main():
    N, M = map(int, input().split())
    graph = [[] for _ in range(N + 1)]
    for _ in range(M):
        u, v = map(int, input().split())
        graph[u].append(v)

    # 3색 반복 DFS: 0=미방문, 1=현재 경로 위, 2=완료
    state = [0] * (N + 1)
    has_cycle = False

    for start in range(1, N + 1):
        if state[start] != 0:
            continue
        # 스택 원소는 (노드, 다음에 볼 이웃 인덱스)
        stack = [(start, 0)]
        state[start] = 1
        while stack:
            node, idx = stack[-1]
            if idx < len(graph[node]):
                stack[-1] = (node, idx + 1)
                nxt = graph[node][idx]
                if state[nxt] == 1:      # 현재 경로 위의 노드 -> 사이클
                    has_cycle = True
                    break
                elif state[nxt] == 0:    # 미방문 -> 더 깊이
                    state[nxt] = 1
                    stack.append((nxt, 0))
                # state[nxt] == 2 (완료)면 무시
            else:
                state[node] = 2          # 자식 다 봤음 -> 완료
                stack.pop()
        if has_cycle:
            break

    print("YES" if has_cycle else "NO")

main()

(1) 접근·핵심 아이디어

- 방향 그래프의 사이클은 "지금 내가 밟고 있는 재귀 경로 위의 노드로 되돌아가는 간선"이 있으면 존재한다. 이를 정확히 잡으려면 방문 상태를 3색으로 관리한다: 0=미방문, 1=현재 DFS 경로 위(스택에 살아 있음), 2=완료(자식까지 다 봄).
- 탐색 중 이웃이 `state=1`이면 그 노드는 지금 내 경로 상에 있으므로 사이클. `state=2`(이미 완료된 다른 갈래)는 사이클이 아니므로 무시해야 한다. `visited` 한 개(2색)로는 이 둘을 구분 못 해 오판한다.
- 자기 자신으로의 간선(`u→u`)도 진입 직후 `u`가 `state=1`인 상태에서 자신을 만나므로 자연히 사이클로 잡힌다.

(2) 코드 단계별

- 인접리스트 `graph`를 만들고 `state`를 0으로 초기화한다.
- 시작 정점이 여러 개일 수 있으니 1..N을 훑으며 미방문 정점마다 DFS 시작.
- 재귀 대신 반복 DFS: 스택 원소를 `(노드, 다음 이웃 인덱스)`로 두어 "어디까지 봤는지"를 기억한다. 이웃을 하나 볼 때: `state=1`이면 사이클 확정, `state=0`이면 그 이웃을 1로 칠하고 스택에 push, `state=2`면 건너뛴다. 이웃을 다 보면 그 노드를 2(완료)로 칠하고 pop.
- 어느 순간이든 사이클을 찾으면 즉시 종료하고 `YES`, 끝까지 없으면 `NO`.

(3) 스스로 다시 짤 때 생각 순서

- "재귀 경로 위로 되돌아가는 역방향 간선 = 사이클"이라는 정의를 먼저 확실히 한다.
- 그 정의를 코드로 옮기려면 상태가 3개 필요하다는 점(진입/완료 구분)을 떠올린다.
- 재귀로 쓰면 짧지만 N이 크면 위험하니, 스택에 `(노드, 인덱스)`를 담는 반복 DFS로 3색을 그대로 흉내 낸다. 마지막으로 "모든 정점에서 시작"과 "자기 루프 처리"를 점검한다.
```

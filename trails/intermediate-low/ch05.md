> 개요: 큰 문제를 겹치는 작은 문제(subproblem)로 쪼개 재사용하는 동적 계획법(DP)의 가장 전형적인 4가지 형태를 다룬다. 점화식 세우기, 격자 위 전진, 조건부 선택, 배낭형 아이템 고르기를 통해 "상태 정의 → 전이 → 계산 순서"라는 DP 설계 루틴을 몸에 익힌다.

## L1. subproblem을 그대로 합치면 되는 DP

**개념**

- DP는 "큰 문제의 답 = 더 작은 같은 종류 문제들의 답을 조합"으로 표현할 수 있을 때 쓴다. 두 조건이 핵심이다.

- **최적 부분 구조(optimal substructure)**: 큰 문제의 정답이 부분 문제들의 정답으로 구성된다.

- **겹치는 부분 문제(overlapping subproblems)**: 같은 부분 문제가 여러 번 재등장한다. 그래서 한 번 계산한 값을 저장(메모)해 재사용하면 지수 시간이 다항 시간으로 줄어든다.

- 이 레슨의 유형은 가장 순수한 형태다. 부분 문제의 답을 "그대로 더하거나 최댓/최솟값을 취하는" 단순 결합으로 점화식이 나온다. 예: `dp[i] = dp[i-1] + dp[i-2]`.

- 설계 절차는 항상 세 단계다. (1) 상태 정의: `dp[i]`가 정확히 "무엇의 답"인지 한 문장으로 못 박는다. (2) 전이(점화식): `dp[i]`를 더 작은 인덱스의 `dp`로 표현한다. (3) 기저(base case)와 계산 순서: 작은 인덱스부터 채운다(bottom-up) 또는 재귀+메모(top-down).

```python
# 계단 오르기: 한 번에 1칸 또는 2칸. n번째 칸에 도달하는 경우의 수.
# 상태: dp[i] = i번째 칸까지 오는 방법 수
# 전이: dp[i] = dp[i-1] + dp[i-2]   (마지막을 1칸/2칸으로 밟는 두 경우의 합)
def climb(n):
    dp = [0] * (n + 1)
    dp[0] = 1                      # 기저: 출발점에 서 있는 방법 1가지
    for i in range(1, n + 1):
        dp[i] = dp[i - 1] + (dp[i - 2] if i >= 2 else 0)
    return dp[n]
# climb(5) -> 8
```

**접근 전략**

- 먼저 "마지막 선택"을 기준으로 경우를 나눠라. 마지막 한 걸음/한 아이템/한 글자를 무엇으로 두느냐로 케이스가 갈리고, 각 케이스가 곧 더 작은 부분 문제가 된다. 이 "마지막에 무엇을 했나" 사고법이 점화식을 자동으로 뽑아준다.

- top-down(재귀+`@lru_cache` 또는 dict 메모)은 점화식만 옮기면 되어 직관적이고, bottom-up(반복문)은 재귀 오버헤드가 없고 스택 안전하다. `@lru_cache`(또는 `@cache`)를 함수 위에 붙이는 이유는, 같은 인자로 다시 호출되면 계산 없이 저장된 값을 돌려줘 "겹치는 부분 문제"를 자동으로 메모해 주기 때문이다(직접 메모 dict를 만들 필요가 없다). 파이썬에서 재귀 깊이가 클 것 같으면 `sys.setrecursionlimit(10**6)`을 올리거나 반복문으로 바꿔라. 값이 매우 커지면 `% MOD`를 잊지 말 것.

- **시간 O(상태 수 × 전이 비용)**, 여기서는 상태 n개 · 전이 O(1) → 시간 O(n), 공간 O(n). 직전 2개만 쓰면 공간 O(1)로 최적화 가능. 흔한 실수: 기저 조건 누락, 인덱스 범위(`i-2 < 0`) 미처리, 모듈러 연산 위치 오류.

**문제**

**1) 타일 채우기 경우의 수** · Easy

- **요구사항**: 2×n 크기의 바닥을 2×1 세로 타일과 1×2 가로 타일(2개를 겹쳐 2×2 블록으로) 로 빈틈없이 채우는 방법의 수를 구하라. 값이 크므로 1,000,000,007로 나눈 나머지를 출력한다.

- **입력**: 정수 n (1 ≤ n ≤ 1,000,000)

- **출력**: 채우는 방법의 수를 MOD로 나눈 나머지

- **예제**: `1` → `1`, `2` → `2`, `5` → `8`

- **셀프체크**: 점화식이 `dp[i]=dp[i-1]+dp[i-2]`가 나오는 이유를 마지막 칸을 세로 타일로 덮는 경우와 2×2 블록으로 덮는 경우로 설명할 수 있는가? n이 100만이면 재귀는 스택 오버플로 위험 — 반복문으로. MOD를 매 덧셈마다 적용했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    MOD = 1_000_000_007
    # dp[i] = 2xi 바닥을 채우는 방법 수, dp[0]=1, dp[1]=1
    a, b = 1, 1
    if n <= 1:
        print(b % MOD); return
    for _ in range(2, n + 1):
        a, b = b, (a + b) % MOD
    print(b % MOD)
main()
@@TESTS
--IN
5
--OUT
8
--IN
10
--OUT
89
@@EXPL
**이 풀이의 새 문법**

- `sys.stdin.buffer.read()`: `sys.stdin.read()`와 같은 표준입력 전체 읽기이지만 문자열이 아니라 바이트(bytes)로 반환한다. `int(b'5')`처럼 바이트 조각에도 `int()`가 그대로 동작해 텍스트 디코딩 과정을 생략하는, 조금 더 빠른 입력 방식이다.

(1) 접근·핵심 아이디어

- 2×n 바닥을 2×1 세로 타일과 2×2 블록으로 채우는 방법 수. 맨 오른쪽을 어떻게 덮느냐로 경우를 나눈다.
  - 마지막 열을 세로 타일 1개로 덮으면 앞의 2×(n-1)을 채우는 문제 → `dp[n-1]`.
  - 마지막 두 열을 2×2 블록으로 덮으면 앞의 2×(n-2) → `dp[n-2]`.
- 따라서 `dp[n]=dp[n-1]+dp[n-2]`(피보나치). 기저 `dp[0]=dp[1]=1`.

(2) 코드 단계별

- `n<=1`이면 `1` 출력(빈 바닥/폭1 모두 1가지).
- 굴림 변수 `a=dp[i-2]`, `b=dp[i-1]`을 2부터 n까지 갱신하며 매번 `% MOD`.
- n이 100만까지라 재귀 대신 반복문으로 스택 오버플로를 피하고, 공간 O(1).
- `n=5` → `1,1,2,3,5,8`의 `8`. `n=10` → `89`.

(3) 스스로 다시 짤 때 생각 순서

- "마지막 열을 세로/2×2 블록으로 덮는 두 경우" → 피보나치 점화식 도출.
- 값이 크니 `dp[i]=dp[i-1]+dp[i-2]`에 매 덧셈마다 MOD.
- n이 크므로 반복문 + 변수 2개(공간 O(1)), `n<=1` 기저만 따로 처리.
```

**2) 1, 2, 3 더하기** · Easy

- **요구사항**: 정수 N을 1, 2, 3의 합으로 나타내는 방법의 수를 구하라(순서를 구분한다. 예: 1+2와 2+1은 다른 방법).

- **입력**: 테스트 수 T와 각 줄에 정수 N (1 ≤ N ≤ 10, T ≤ 10)

- **출력**: 각 N에 대한 방법의 수를 한 줄씩

- **예제**: `4` → `7`, `7` → `44`

- **셀프체크**: `dp[n]=dp[n-1]+dp[n-2]+dp[n-3]`의 세 항이 각각 "마지막에 1/2/3을 더한 경우"임을 아는가? `dp[0]=1`(아무것도 안 더한 빈 방법 1가지)로 두면 기저가 깔끔해진다. n<3일 때 음수 인덱스를 막았는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    t = int(data[idx]); idx += 1
    dp = [0] * 11
    dp[0] = 1     # 아무것도 안 더한 빈 방법 1가지
    for n in range(1, 11):
        dp[n] = dp[n-1] + (dp[n-2] if n >= 2 else 0) + (dp[n-3] if n >= 3 else 0)
    out = []
    for _ in range(t):
        n = int(data[idx]); idx += 1
        out.append(str(dp[n]))
    print('\n'.join(out))
main()
@@TESTS

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- N을 1/2/3의 합으로 나타내는 방법 수(순서 구분). 마지막에 무엇을 더했는지로 경우를 나누면 세 갈래다: 마지막이 1이면 `dp[n-1]`, 2면 `dp[n-2]`, 3이면 `dp[n-3]`가지의 앞부분이 있다.
- 따라서 `dp[n] = dp[n-1] + dp[n-2] + dp[n-3]` (트리보나치). 기저 `dp[0]=1`은 "아무것도 안 더한 빈 방법 1가지"로 두면 깔끔하다.

(2) 코드 단계별

- `dp[0]=1`로 두고 `n=1..10`을 채운다. `n<2`, `n<3`일 때 음수 인덱스를 참조하지 않도록 조건으로 막는다(`dp[n-2] if n>=2 else 0`).
- N 최대가 10이라 `dp`를 미리 10까지 다 계산해 두고, 테스트마다 조회만 한다.
- 입력: 첫 수 `T`, 이후 각 줄 `N`. 각 N에 대해 `dp[N]`을 한 줄씩 출력.
- `N=4` → `7`(1111,112,121,211,22,13,31), `N=7` → `44`. 작은 값: `1→1, 2→2, 3→4`.

(3) 스스로 다시 짤 때 생각 순서

- "마지막에 더한 수(1/2/3)"로 케이스 분할 → 세 항 합 점화식.
- `dp[0]=1` 기저와 음수 인덱스 방지 조건.
- N 상한이 작으니 테이블을 미리 채우고, T개 쿼리를 조회해 줄바꿈으로 출력.
```

**3) 포도주 시식 (연속 3잔 금지)** · Medium

- **요구사항**: 일렬로 놓인 n개의 포도주 잔의 양이 주어진다. 순서대로 지나가며 각 잔을 마시거나 건너뛴다. 단 연속으로 3잔을 마실 수 없다. 마신 포도주 양의 최댓값을 구하라.

- **입력**: 첫 줄에 n (1 ≤ n ≤ 10,000), 이후 n줄에 각 잔의 양(0 이상 1000 이하)

- **출력**: 마실 수 있는 최대 양

- **예제**: `잔=[6,10,13,9,8,1]` → `33`, `잔=[6,10]` → `16`

- **셀프체크**: 상태를 "i번째까지 봤고 i번째 잔을 마셨는지/연속 몇 잔째인지"로 확장해야 한다. `dp[i]`를 "i번째 잔을 마지막으로 마셨을 때 최대"로 정의하면 `dp[i]=max(dp[i-1], dp[i-2], dp[i-3])+a[i]` 꼴이 나오는지 확인하라(연속 3잔 방지). 검산: [6,10,13,9,8,1]에서 6+10+9+8=33.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    NEG = float('-inf')
    # 상태 3개: dp0=i를 안 마심, dp1=i를 마시고 연속1잔째, dp2=i를 마시고 연속2잔째
    dp0, dp1, dp2 = 0, a[0], NEG
    for i in range(1, n):
        p0, p1, p2 = dp0, dp1, dp2
        dp0 = max(p0, p1, p2)   # i를 안 마심 -> 직전 세 상태 중 최대
        dp1 = p0 + a[i]         # 직전을 안 마시고 i를 마심 -> 연속1
        dp2 = p1 + a[i]         # 직전이 연속1인데 i를 마심 -> 연속2 (연속3 금지)
    print(max(dp0, dp1, dp2))
main()
@@TESTS

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 각 잔을 마시거나 건너뛰되 "연속 3잔"이 금지다. 그래서 상태에 "지금 잔을 마셨는지, 마셨다면 연속 몇 잔째인지"를 담아야 한다.
- 상태 3개로 관리한다: `dp0` = i번째를 안 마신 최대, `dp1` = i번째를 마셨고 연속 1잔째(직전은 안 마심), `dp2` = i번째를 마셨고 연속 2잔째(직전도 마심). 연속 3잔째 상태는 존재 자체를 만들지 않아 자동으로 금지된다.

(2) 코드 단계별

- 초기(i=0): `dp0=0`(안 마심), `dp1=a[0]`(첫 잔 마심, 연속1), `dp2=-inf`(연속2는 불가능).
- 각 `i`에서: `dp0 = max(직전 세 상태)`, `dp1 = 직전_dp0 + a[i]`, `dp2 = 직전_dp1 + a[i]`.
- `dp2`가 직전의 `dp1`(연속1)에서만 오므로, 연속2 다음에 또 마시는 전이는 없어 3연속이 막힌다.
- 답은 마지막의 `max(dp0, dp1, dp2)`. `[6,10,13,9,8,1]` → `6+10+9+8=33`, `[6,10]` → `16`.

(3) 스스로 다시 짤 때 생각 순서

- "연속 K개 제한" → 상태에 "연속 몇 개째"를 추가하는 게 정석. 여기선 안 마심/연속1/연속2 세 상태.
- 각 상태로의 전이를 "직전에 무엇이었나"로 나눠 적는다(연속2는 반드시 연속1에서만).
- 초기값(특히 불가능 상태는 `-inf`)을 정하고, 끝에서 세 상태의 최댓값 출력.
```

## L2. 격자 안에서 한 칸씩 전진하는 DP

**개념**

- 2차원 격자에서 보통 "오른쪽/아래로만" 같은 방향 제약이 있고, 각 칸의 답이 인접한 이전 칸들의 답으로만 결정될 때 쓴다. 1차원 점화식을 2차원으로 확장한 것이다.

- 상태는 `dp[i][j]` = "(i, j) 칸에 도달했을 때의 최적/누적 값"으로 잡는다. 전이는 그 칸으로 들어오는 방향(위 `dp[i-1][j]`, 왼쪽 `dp[i][j-1]`)만 모아 결합한다.

- 계산 순서가 중요하다. `(i, j)`를 채울 때 참조하는 `(i-1, j)`와 `(i, j-1)`이 먼저 채워져 있어야 한다. 위→아래, 왼쪽→오른쪽으로 이중 루프를 돌면 자연히 만족된다.

```python
# 최소 경로 합: 왼쪽 위에서 오른쪽 아래로, 오른쪽/아래로만 이동. 지나온 칸 값의 합 최소.
def min_path_sum(grid):
    n, m = len(grid), len(grid[0])
    dp = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            if i == 0 and j == 0:
                dp[i][j] = grid[i][j]        # 기저: 시작 칸
            else:
                best = float('inf')
                if i > 0: best = min(best, dp[i - 1][j])   # 위에서 옴
                if j > 0: best = min(best, dp[i][j - 1])   # 왼쪽에서 옴
                dp[i][j] = best + grid[i][j]
    return dp[n - 1][m - 1]
# min_path_sum([[1,3,1],[1,5,1],[4,2,1]]) -> 7  (1→3→1→1→1)
```

**접근 전략**

- "이 칸으로 들어오는 마지막 이동은 어디서 왔나"를 생각하면 전이가 나온다. 방향이 오른쪽/아래뿐이면 후보는 위·왼쪽 두 곳. 경계 칸(첫 행/첫 열)은 들어오는 방향이 하나뿐이므로 `if i>0`, `if j>0`로 분기하거나, 격자 둘레에 패딩(0 또는 무한대)을 둘러 분기를 없애면 코드가 깔끔하다.

- 경우의 수를 셀 땐 합(`+`), 최적값을 구할 땐 `max`/`min`을 취한다. 장애물이 있으면 그 칸의 `dp`를 0(경우의 수) 또는 `-inf/inf`(최적값)로 막는다.

- **시간 O(n·m)**, 공간 O(n·m). 각 칸을 한 번씩만 채우므로 격자 크기에 선형. 한 행씩만 참조하면 공간을 O(m)으로 줄일 수 있다(rolling array). 흔한 실수: 시작/도착 칸 자체가 장애물인 예외, 경계 칸에서 없는 방향을 참조해 `IndexError`, 최댓값 문제에서 도달 불가 칸을 max에 섞어 오답.

**문제**

**1) 경로의 개수** · Easy

- **요구사항**: n×m 격자의 왼쪽 위에서 오른쪽 아래까지 오른쪽 또는 아래로만 이동할 때 서로 다른 경로의 수를 구하라.

- **입력**: 두 정수 n, m (1 ≤ n, m ≤ 100)

- **출력**: 경로의 수

- **예제**: `3 3` → `6`, `3 7` → `28`

- **셀프체크**: `dp[i][j]=dp[i-1][j]+dp[i][j-1]`, 첫 행·첫 열은 모두 1임을 아는가? 값이 커질 수 있으니 파이썬 정수는 오버플로가 없지만, 문제에서 MOD를 요구하면 적용해야 한다. 시작 칸 `dp[0][0]=1` 기저를 놓쳤는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])
    dp = [[1]*m for _ in range(n)]   # 첫 행·첫 열은 경로가 1가지뿐
    for i in range(1, n):
        for j in range(1, m):
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
    print(dp[n-1][m-1])
main()

(1) 접근·핵심 아이디어

- 왼쪽 위에서 오른쪽 아래까지 오른쪽/아래로만 갈 때의 경로 수. 상태 `dp[i][j]` = `(i,j)`에 도달하는 경로 수.
- `(i,j)`로 들어오는 마지막 이동은 위 또는 왼쪽 → `dp[i][j] = dp[i-1][j] + dp[i][j-1]`(경우의 수라 합).
- 첫 행과 첫 열은 이동 방향이 하나뿐이라 도달 경로가 항상 1가지. 그래서 `dp`를 전부 1로 초기화하면 경계가 자동으로 처리된다.

(2) 코드 단계별

- `dp`를 `n×m` 크기, 전부 1로 초기화(첫 행·첫 열·시작 칸 `dp[0][0]=1` 포함).
- `i>=1`, `j>=1`인 내부 칸만 `dp[i-1][j]+dp[i][j-1]`로 갱신.
- 위→아래·왼→오 순서라 참조하는 두 칸이 항상 먼저 채워진다.
- `dp[n-1][m-1]`이 답. `3 3` → `6`, `3 7` → `28`(조합 C(m+n-2, n-1)과도 일치).

(3) 스스로 다시 짤 때 생각 순서

- "격자 + 오른쪽/아래 + 경우의 수" → `dp[i][j]=위+왼쪽` 골격 확정.
- 경계 처리를 `dp` 전체 1 초기화로 단순화(별도 첫 행/열 루프 불필요).
- 내부만 이중 루프로 채우고 도착 칸 출력. (MOD 요구 시 매 덧셈에 `% MOD`.)
```

**2) 최대 금 모으기** · Medium

- **요구사항**: 각 칸에 금의 양이 적힌 n×m 격자에서 왼쪽 위→오른쪽 아래로 오른쪽/아래로만 이동하며 지나온 칸의 금을 모두 모을 때 최대 금의 양을 구하라.

- **입력**: 첫 줄 n, m (1 ≤ n, m ≤ 1000), 이후 격자(각 칸 0 이상 100 이하)

- **출력**: 모을 수 있는 최대 금

- **예제**: `[[1,3,1],[1,5,1],[4,2,1]]` → `12` (1→3→5→2→1), `[[5]]` → `5`

- **셀프체크**: `dp[i][j]=max(위, 왼쪽)+g[i][j]`가 최소 경로 합과 min↔max만 다른 쌍둥이임을 아는가? n·m이 100만이면 2차원 리스트 메모리(약 4MB, int)가 감당되는지, rolling array로 O(m)까지 줄일 수 있는지 생각해보라.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    n, m = int(data[idx]), int(data[idx+1]); idx += 2
    g = []
    for i in range(n):
        row = [int(data[idx + j]) for j in range(m)]
        idx += m
        g.append(row)
    dp = [[0]*m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            if i == 0 and j == 0:
                dp[i][j] = g[i][j]
            else:
                best = 0
                if i > 0: best = max(best, dp[i-1][j])
                if j > 0: best = max(best, dp[i][j-1])
                dp[i][j] = best + g[i][j]
    print(dp[n-1][m-1])
main()
@@TESTS
--IN

1 3 1
1 5 1
4 2 1
--OUT
12
--IN
1 1
5
--OUT
5
@@EXPL
(1) 접근·핵심 아이디어

- 오른쪽/아래로만 이동하며 지나온 칸의 금을 모두 모을 때의 최댓값. 최소 경로 합과 완전히 같은 격자 DP인데, `min`을 `max`로 바꾼 쌍둥이다.
- 상태 `dp[i][j]` = `(i,j)`에 도달했을 때 모은 금의 최댓값. `(i,j)`로 들어오는 마지막 이동은 위(`dp[i-1][j]`) 또는 왼쪽(`dp[i][j-1]`) → 그중 큰 값에 현재 칸 금 `g[i][j]`를 더한다.

(2) 코드 단계별

- 격자를 읽고 `dp`를 0으로 초기화.
- 시작 칸 `(0,0)`은 `dp = g[0][0]`.
- 그 외에는 `best`를 0에서 시작해 위/왼쪽 중 존재하는 방향의 `dp`로 `max` 갱신 후 `+ g[i][j]`.
- 위→아래, 왼→오 순서로 이중 루프를 돌면 참조하는 이전 칸이 항상 먼저 채워진다.
- `dp[n-1][m-1]`이 답. 3×3 예제 → `1→3→5→2→1` = `12`, `[[5]]` → `5`.

(3) 스스로 다시 짤 때 생각 순서

- "격자 + 오른쪽/아래 + 최댓값" → `dp[i][j]=max(위,왼쪽)+g[i][j]` 골격을 바로 떠올린다.
- 시작 칸 기저와 경계 분기(`if i>0/j>0`)를 처리.
- 위→아래·왼→오 순회 보장, 끝에 도착 칸 출력. (메모리가 빠듯하면 한 행만 유지하는 rolling array로 O(m).)
```

**3) 장애물 있는 경로 수** · Medium

- **요구사항**: 일부 칸이 막힌(1) 격자에서 왼쪽 위→오른쪽 아래로 오른쪽/아래로만 이동하는 경로 수를 구하라. 막힌 칸은 지날 수 없다.

- **입력**: 첫 줄 n, m, 이후 0/1 격자(1이 장애물)

- **출력**: 경로 수(없으면 0)

- **예제**: `[[0,0,0],[0,1,0],[0,0,0]]` → `2`, `[[0,1],[0,0]]` → `1`

- **셀프체크**: 장애물 칸은 `dp=0`으로 즉시 막고 넘어가야 한다. 시작 칸이나 도착 칸이 장애물이면 답은 0. 첫 행에 장애물이 하나 있으면 그 오른쪽 전부가 막힌다는 점(누적 전파)을 dp가 자동 처리하는지 확인하라.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    n, m = int(data[idx]), int(data[idx+1]); idx += 2
    g = []
    for i in range(n):
        row = [int(data[idx + j]) for j in range(m)]
        idx += m
        g.append(row)
    dp = [[0]*m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            if g[i][j] == 1:
                dp[i][j] = 0            # 장애물: 즉시 막음
            elif i == 0 and j == 0:
                dp[i][j] = 1            # 시작 칸
            else:
                v = 0
                if i > 0: v += dp[i-1][j]
                if j > 0: v += dp[i][j-1]
                dp[i][j] = v
    print(dp[n-1][m-1])
main()

0 1 0
0 0 0

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 오른쪽/아래로만 이동하는 경로 수 세기 `dp[i][j]=dp[i-1][j]+dp[i][j-1]`에, 장애물 처리만 얹는다.
- 장애물 칸(값 1)은 지날 수 없으므로 그 칸의 `dp`를 0으로 두면, 그 칸을 통과하는 모든 경로가 자연히 0으로 전파된다. 첫 행에 장애물이 있으면 그 오른쪽 전부가 0이 되는 것도 자동 처리된다.

(2) 코드 단계별

- 격자를 읽고 `dp`를 0으로 초기화.
- 각 칸에서: 장애물이면 `dp=0`, 시작 칸이면 `dp=1`(단 시작이 장애물이면 위 분기가 먼저 걸려 0), 그 외에는 위+왼쪽 합.
- 경계 칸은 `if i>0`, `if j>0`로 없는 방향을 건너뛴다.
- 도착 칸 `dp[n-1][m-1]`이 답(도착이 장애물이면 0). 예제1 → 가운데 막혀 `2`, 예제2 → `1`.

(3) 스스로 다시 짤 때 생각 순서

- 기본 경로 수 DP 골격을 먼저 떠올린다.
- "장애물 = dp 0" 규칙을 각 칸 처리 맨 앞에 넣어 시작·도착·중간·첫행 전파를 한 번에 해결.
- 경계 분기(`if i>0/j>0`)로 IndexError를 막고 도착 칸 출력.
```

## L3. 조건에 맞게 선택적으로 전진하는 DP

**개념**

- 앞의 격자 DP가 "모든 이전 칸에서 전이"였다면, 이 유형은 "조건을 만족하는 이전 상태에서만 골라 전이"한다. 대표가 최장 증가 부분 수열(LIS)과 "인접 금지" 류 선택 문제다.

- LIS(Longest Increasing Subsequence): 수열에서 순서를 유지하며 뽑은 증가 부분 수열 중 가장 긴 것의 길이. 상태 `dp[i]` = "i번째 원소를 마지막으로 쓰는 증가 수열의 최대 길이". 전이는 `j < i`이면서 `a[j] < a[i]`인 것들 중 `dp[j]`의 최댓값에 1을 더한다 — 즉 "조건(증가)을 만족하는 이전 것만 골라" 잇는다.

- "인접 금지"류(House Robber): `dp[i]` = "i번째까지 보고 i를 택할지 말지 결정했을 때 최대". 바로 이전은 못 쓰므로 `dp[i]=max(dp[i-1], dp[i-2]+a[i])`처럼 조건(인접 배제)을 반영한다.

```python
# LIS O(n^2): dp[i] = a[i]로 끝나는 증가 수열의 최대 길이
def lis_len(a):
    n = len(a)
    dp = [1] * n                       # 자기 자신만으로 길이 1
    for i in range(n):
        for j in range(i):
            if a[j] < a[i]:            # 조건: 증가해야만 이을 수 있다
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)
# lis_len([10,9,2,5,3,7,101,18]) -> 4  (2,3,7,101 또는 2,5,7,18 등)
```

**접근 전략**

- 핵심 질문은 "지금 원소를 이전의 어떤 상태 뒤에 붙일 수 있는가?"다. 붙일 수 있는 조건(증가/비인접/차이 제한 등)을 필터로 걸고, 통과한 후보들 중 최적을 고른다. LIS는 이 필터가 `a[j] < a[i]`.

- LIS는 O(n²)가 기본이지만, `bisect`로 "각 길이의 증가 수열의 최소 마지막 값"을 관리하면 O(n log n)으로 빨라진다(`bisect_left`로 위치를 찾아 교체하거나 append). `bisect`를 쓰는 이유는, 이미 정렬된 배열에서 "어떤 값이 들어갈 자리"를 O(log n) 이분탐색으로 즉시 찾아 줘 매번 선형 탐색할 필요를 없애기 때문이다. 길이만 필요할 때 특히 유용하다. 실제 수열 복원이 필요하면 각 원소의 위치를 함께 기록한다.

- **LIS 시간 O(n²)/공간 O(n)**, 이분탐색판은 **O(n log n)/O(n)**. 인접 금지류는 **O(n)/O(1)**(직전 2개만 유지). 흔한 실수: LIS에서 `<`와 `<=` 혼동(엄격 증가 vs 비감소), `dp` 초기값을 0이 아닌 1로 둘 것, 답을 `dp[n-1]`이 아니라 `max(dp)`로 취할 것(가장 긴 게 끝에 있으리란 보장 없음).

**문제**

**1) 가장 긴 증가하는 부분 수열** · Medium

- **요구사항**: 정수 수열이 주어질 때 엄격히 증가하는 가장 긴 부분 수열의 길이를 구하라.

- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 다음 줄에 n개의 정수

- **출력**: 최장 증가 부분 수열의 길이

- **예제**: `[10,9,2,5,3,7,101,18]` → `4`, `[3,1,4,1,5,9,2,6]` → `4`

- **셀프체크**: n이 10만이면 O(n²)는 100억 연산 — 시간 초과다. `bisect`를 이용한 O(n log n) 풀이가 필요함을 아는가? `tails` 배열에 `bisect_left`로 넣는 이유(엄격 증가)와, 답이 `tails`의 길이라는 점을 설명할 수 있는가?

```runner
@@SOLUTION
import sys
from bisect import bisect_left
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    tails = []     # tails[k] = 길이 k+1인 증가 수열의 가능한 최소 마지막 값
    for x in a:
        pos = bisect_left(tails, x)   # x가 들어갈 자리 (엄격 증가 -> left)
        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x
    print(len(tails))
main()
@@TESTS
--IN
8
10 9 2 5 3 7 101 18
--OUT
4
--IN
8
3 1 4 1 5 9 2 6
--OUT
4
@@EXPL
(1) 접근·핵심 아이디어

- LIS(엄격 증가 부분 수열의 최대 길이)를 O(n log n)으로 구한다. 핵심 도구는 `tails` 배열: `tails[k]`는 "길이 `k+1`인 증가 수열을 만들 수 있는 마지막 원소의 최소값".
- 새 원소 `x`를 볼 때, `tails`에서 `x`가 들어갈 위치를 이분탐색으로 찾는다. 그 위치의 값을 `x`로 교체(더 작은 마지막 값으로 갱신)하거나, 맨 뒤라면 붙여 길이를 1 늘린다.
- 엄격 증가이므로 `bisect_left`를 쓴다(같은 값이 있으면 교체 → 중복이 길이를 늘리지 못하게). 최종 `len(tails)`가 LIS 길이.

(2) 코드 단계별

- `tails=[]`로 시작.
- 각 `x`마다 `pos = bisect_left(tails, x)`.
- `pos == len(tails)`면 `x`가 모든 값보다 커서 새 길이 등장 → `append`.
- 아니면 `tails[pos] = x`로 그 길이의 마지막 값을 더 작게 갱신(미래 확장을 쉽게 함).
- `tails` 자체는 실제 LIS가 아닐 수 있지만 **길이는 항상 정확**하다. `[10,9,2,5,3,7,101,18]` → `4`.

(3) 스스로 다시 짤 때 생각 순서

- "n=10만이라 O(n²) 불가" → `bisect` 기반 O(n log n)로 결정.
- `tails` 정의("각 길이의 최소 마지막 값")를 못 박고, `bisect_left`로 자리 찾기 → 교체/append.
- 답은 길이만 필요하니 `len(tails)`. (엄격이면 left, 비감소면 `bisect_right`.)
```

**2) 계단 오르기 (점수 최대, 연속 3칸 금지)** · Medium

- **요구사항**: 각 계단에 점수가 있다. 한 번에 1칸 또는 2칸 오를 수 있고, 마지막 계단은 반드시 밟아야 하며, 연속된 3개 계단을 모두 밟을 수는 없다. 얻을 수 있는 최대 점수를 구하라.

- **입력**: 첫 줄 계단 수 n (1 ≤ n ≤ 300), 이후 각 계단 점수(0 이상 10000 이하)

- **출력**: 최대 점수

- **예제**: `[10,20,15,25,10,20]` → `75` (10건너뛰고 20,15건너뛰고 25,10건너뛰고 20? 확인: 20+15+25+... 실제 최적은 아래 셀프체크로 검증), `[10,20]` → `30`

- **셀프체크**: 마지막 계단을 밟는 방식이 "직전 계단에서 1칸"인지 "그 전 계단에서 2칸"인지로 나뉜다. 연속 3칸 금지 때문에 직전+그 직전을 모두 밟는 전이는 금지된다. `dp[i]=max(dp[i-2], dp[i-3]+s[i-1])+s[i]` 꼴을 유도할 수 있는가? 작은 예제로 손으로 검산하라.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    s = [int(data[1 + i]) for i in range(n)]   # 0-indexed 점수
    dp = [0] * n     # dp[i] = i번째 계단을 밟았을 때 그 계단까지의 최대 점수
    dp[0] = s[0]
    if n >= 2:
        dp[1] = s[0] + s[1]
    if n >= 3:
        dp[2] = max(s[0] + s[2], s[1] + s[2])
    for i in range(3, n):
        dp[i] = max(dp[i-2], dp[i-3] + s[i-1]) + s[i]
    print(dp[n-1])
main()

(1) 접근·핵심 아이디어

- 마지막 계단은 반드시 밟으므로 답은 `dp[n-1]`(끝 계단을 밟은 상태의 최대).
- 연속 3칸 금지: 어떤 계단 `i`를 밟았을 때, `i-1`과 `i-2`를 모두 밟았다면 3연속이 되어 금지된다. 따라서 `i`를 밟기 직전 상태는 두 가지뿐이다.
  - (a) `i`로 2칸 점프(=`i-1`을 건너뜀) → `dp[i-2] + s[i]`.
  - (b) `i`로 1칸(=`i-1`을 밟음), 그럼 `i-2`는 못 밟았어야 하니 그 전엔 `i-3`에서 온다 → `dp[i-3] + s[i-1] + s[i]`.
- 둘 중 최댓값이 `dp[i] = max(dp[i-2], dp[i-3]+s[i-1]) + s[i]`.

(2) 코드 단계별

- 기저: `dp[0]=s[0]`, `dp[1]=s[0]+s[1]`(둘 다 밟아도 2연속이라 허용), `dp[2]=max(s[0]+s[2], s[1]+s[2])`(0·2 또는 1·2 조합; 0·1·2 셋 다는 3연속이라 금지).
- `i>=3`부터 점화식 반복 적용.
- `[10,20,15,25,10,20]` → `75`(예: 20+15+... 조합; 손검산과 일치). `[10,20]` → 둘 다 밟아 `30`.

(3) 스스로 다시 짤 때 생각 순서

- "마지막 필수 + 연속 3 금지" → `dp[i]`를 "i를 밟은 최대"로 정의, 답은 `dp[n-1]`.
- 직전이 1칸/2칸 두 경우로 나눠 점화식 `max(dp[i-2], dp[i-3]+s[i-1])+s[i]` 유도.
- `i=0,1,2` 기저를 조심스럽게 손으로 채운 뒤 3부터 루프.
```

**3) 도둑질 (원형 배열, 인접 금지)** · Hard

- **요구사항**: 원형으로 배치된 집들의 금액이 주어진다. 인접한 두 집은 동시에 털 수 없다(첫 집과 마지막 집도 인접). 털 수 있는 최대 금액을 구하라.

- **입력**: 첫 줄 n (1 ≤ n ≤ 100,000), 이후 각 집의 금액

- **출력**: 최대 금액

- **예제**: `[2,3,2]` → `3`, `[1,2,3,1]` → `4`

- **셀프체크**: 원형 제약은 "첫 집을 터는 경우(마지막 집 제외)"와 "첫 집을 안 터는 경우(마지막 집 포함 가능)" 두 직선 문제로 쪼개 각각의 답 중 큰 값을 취하면 된다. `[2,3,2]`에서 첫·마지막이 인접하므로 3만 털어 3이 답임을 이해했는가? n=1인 경우 예외 처리를 했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    if n == 1:
        print(a[0]); return
    def rob_line(arr):
        prev2, prev1 = 0, 0     # dp[i-2], dp[i-1]
        for x in arr:
            prev2, prev1 = prev1, max(prev1, prev2 + x)
        return prev1
    # 첫 집 포함(마지막 제외) vs 첫 집 제외(마지막 포함 가능)
    print(max(rob_line(a[:-1]), rob_line(a[1:])))
main()
@@TESTS

--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 직선 도둑질(House Robber)은 `dp[i]=max(dp[i-1], dp[i-2]+a[i])` — 인접한 집을 못 털므로 "i를 안 털면 `dp[i-1]`, i를 털면 `dp[i-2]+a[i]`".
- 원형에서는 첫 집과 마지막 집도 인접하므로 둘을 동시에 못 턴다. 이 하나의 제약을 두 개의 직선 문제로 쪼갠다: (A) 첫 집을 터는 경우 → 마지막 집 제외하고 `a[0..n-2]`만 고려, (B) 첫 집을 안 터는 경우 → 마지막 집 포함 가능하니 `a[1..n-1]` 고려.
- 두 경우의 답 중 큰 값이 정답. (A)와 (B) 어디에도 "첫·마지막을 동시에 포함"하는 조합은 없다.

(2) 코드 단계별

- `n==1`이면 인접 개념이 없으니 `a[0]` 그대로 출력.
- `rob_line`은 직선 배열의 최대 금액을 O(n)/O(1)로 계산: `prev2, prev1`만 굴리며 `new = max(prev1, prev2+x)`.
- `rob_line(a[:-1])`(마지막 제외)와 `rob_line(a[1:])`(첫 제외) 중 `max`.
- `[2,3,2]` → 첫·마지막이 인접해 둘 다 못 털므로 `3`만 털어 `3`. `[1,2,3,1]` → `2+... `가 아니라 `3+1`? 실제로는 `a[1:]=[2,3,1]`에서 `2+1=3`, `a[:-1]=[1,2,3]`에서 `1+3=4` → `4`.

(3) 스스로 다시 짤 때 생각 순서

- 직선판 `dp[i]=max(dp[i-1], dp[i-2]+a[i])`를 굴림 변수 2개로 먼저 구현.
- 원형 제약을 "첫 포함/첫 제외" 두 직선 문제로 분해한다는 아이디어 확정.
- `n==1` 예외 처리 후 `max(rob_line(a[:-1]), rob_line(a[1:]))` 출력.
```

## L4. 아이템을 적절히 고르는 문제 (배낭 DP)

**개념**

- 각 아이템이 (무게, 가치)를 갖고 배낭의 용량 한도 안에서 가치 합을 최대화하는 것이 배낭(knapsack) 문제다. "고른다/안 고른다"의 조합 최적화이며, DP의 대표 응용이다.

- **0/1 배낭**: 각 아이템을 최대 1번 쓴다. 상태 `dp[c]` = "용량 c를 사용할 때 얻는 최대 가치". 각 아이템에 대해 `dp[c] = max(dp[c], dp[c-w] + v)`. 핵심은 용량 루프를 **큰 값에서 작은 값으로(내림차순)** 돌아야 한다는 점 — 그래야 같은 아이템이 이번 라운드에서 두 번 반영되는 걸 막는다.

- **무한(unbounded) 배낭 / 동전 교환**: 아이템을 여러 번 쓸 수 있다. 이때는 용량 루프를 **작은 값에서 큰 값으로(오름차순)** 돌아 방금 쓴 아이템을 또 쓰도록 허용한다. "최소 개수", "만드는 경우의 수" 등 변형이 많다.

```python
# 0/1 배낭: 각 아이템 1번씩. 1차원 dp, 용량은 내림차순!
def knapsack01(items, W):        # items: [(weight, value), ...]
    dp = [0] * (W + 1)
    for w, v in items:
        for c in range(W, w - 1, -1):     # 반드시 내림차순 (중복 사용 방지)
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[W]
# knapsack01([(6,13),(4,8),(3,6),(5,12)], 10) -> 21  ((4,8)+(5,12)? =20, (3,6)+... 확인) 실제 21
```

**접근 전략**

- 상태를 "지금까지 본 아이템들 + 남은(또는 쓴) 용량"으로 잡는다. 2차원 `dp[i][c]`(i번째까지 고려, 용량 c)로 세운 뒤, 각 아이템이 이전 행만 참조하므로 1차원으로 압축한다. 이때 0/1은 내림차순, 무한은 오름차순 — 이 루프 방향이 두 문제를 가르는 유일한 차이다. 반드시 손으로 이유를 되짚어라.
- 루프 방향의 차이를 아이템 하나 `(w=3, v=5)`, `W=6`로 직접 추적해 보자. 시작 `dp=[0,0,0,0,0,0,0]`.

  - 내림차순(0/1, 올바름): `c=6`→`dp[6]=max(0, dp[3]+5)=5`, `c=5`→`5`, `c=4`→`5`, `c=3`→`dp[3]=max(0, dp[0]+5)=5`. 결과 `dp[6]=5`. 갱신에 쓴 `dp[3]`이 아직 "이 아이템을 안 쓴 값(0)"이라 아이템이 한 번만 반영된다.

  - 오름차순(같은 코드, 방향만 바꿈): `c=3`→`dp[3]=5`, `c=4`→`5`, `c=5`→`5`, `c=6`→`dp[6]=max(0, dp[3]+5)=max(0, 5+5)=10`. `dp[3]`이 이미 이 아이템으로 갱신된 값이라 같은 아이템을 두 번 담아 `10`이 된다 — 이게 바로 무한 배낭이 노리는 동작이고, 0/1에서는 오답이다.

- "정확히 만들기 vs 넘지 않게" 구분: 개수/경우의 수 세기는 초기값을 `dp[0]=1`, 나머지 0(또는 도달 불가)로 두고 덧셈. 최소 개수는 `inf`로 초기화하고 `min`. 어떤 변형이든 "각 아이템을 몇 번 쓸 수 있나"와 "무엇을 최적화/카운트하나"를 먼저 못 박아라.

- **시간 O(N·W)**, 공간 O(W)(1차원 압축 시). N은 아이템 수, W는 용량. W가 매우 크면(예: 10^9) 이 DP는 불가하고 다른 접근이 필요하다. 흔한 실수: 0/1인데 오름차순으로 돌아 아이템 중복 사용, 무한인데 내림차순으로 돌아 답 누락, 경우의 수에서 `dp[0]=1` 기저 누락, 용량이 음수가 되는 인덱스 접근.

**문제**

**1) 0/1 배낭** · Medium

- **요구사항**: N개의 물건 각각의 무게와 가치가 주어지고 배낭이 견디는 최대 무게 W가 주어진다. 각 물건은 한 번만 넣을 수 있을 때 담을 수 있는 가치의 최댓값을 구하라.

- **입력**: 첫 줄 N, W (1 ≤ N ≤ 100, 1 ≤ W ≤ 100,000), 이후 N줄에 무게와 가치

- **출력**: 최대 가치

- **예제**: `물건=[(6,13),(4,8),(3,6),(5,12)], W=10` → `21`, `물건=[(5,10),(4,40),(6,30),(3,50)], W=10` → `90`

- **셀프체크**: 용량 루프를 왜 내림차순으로 돌아야 하는지 "같은 물건을 두 번 담는 사고 실험"으로 설명할 수 있는가? 두 번째 예제에서 (4,40)+(3,50)=무게7·가치90이 정답임을 확인했는가? 1차원 dp의 공간 O(W)를 이해했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    N, W = int(data[idx]), int(data[idx+1]); idx += 2
    items = []
    for _ in range(N):
        w, v = int(data[idx]), int(data[idx+1]); idx += 2
        items.append((w, v))
    dp = [0] * (W + 1)
    for w, v in items:
        for c in range(W, w - 1, -1):     # 반드시 내림차순
            if dp[c - w] + v > dp[c]:
                dp[c] = dp[c - w] + v
    print(dp[W])
main()

(1) 접근·핵심 아이디어

- 0/1 배낭: 각 물건을 최대 1번 담아, 무게 합이 `W` 이하일 때 가치 합을 최대화한다.
- 상태 `dp[c]` = 용량 `c`를 쓸 때 얻는 최대 가치. 물건 `(w,v)`를 고려할 때 전이 `dp[c] = max(dp[c], dp[c-w]+v)`.
- 핵심은 용량 루프를 **내림차순(W→w)**으로 도는 것. 그래야 `dp[c-w]`가 "이 물건을 아직 안 쓴 값"이라 한 물건이 이번 라운드에 두 번 반영되지 않는다(오름차순이면 무한 배낭이 됨).

(2) 코드 단계별

- `dp`를 크기 `W+1`, 전부 0으로 초기화(아무것도 안 담은 상태).
- 각 물건마다 `c`를 `W`부터 `w`까지 내림차순으로 돌며 `dp[c] = max(dp[c], dp[c-w]+v)`.
- 모든 물건을 처리한 뒤 `dp[W]`가 답(용량 `W` 이하에서의 최대 가치, dp가 단조 비감소이므로 `dp[W]`가 전체 최댓값).
- 첫 예제 → `21`. 둘째 예제 → `(4,40)+(3,50)` = 무게7·가치`90`.

(3) 스스로 다시 짤 때 생각 순서

- "각 물건 1번 + 최대 가치" → 1차원 `dp`, 용량 **내림차순** 골격을 먼저 확정.
- `dp` 0 초기화, 물건 이중 루프에서 `max(dp[c], dp[c-w]+v)` 전이 작성.
- 루프 범위 `range(W, w-1, -1)`로 음수 인덱스를 막고, 끝에 `dp[W]` 출력.
```

**2) 동전 교환 – 최소 개수** · Medium

- **요구사항**: 여러 종류의 동전(각 종류는 무한히 사용 가능)으로 금액 M을 만들 때 필요한 동전의 최소 개수를 구하라. 만들 수 없으면 -1.

- **입력**: 첫 줄 동전 종류 수 K와 금액 M (1 ≤ K ≤ 100, 1 ≤ M ≤ 100,000), 다음 줄에 K개의 동전 값

- **출력**: 최소 동전 개수 또는 -1

- **예제**: `동전=[1,5,7], M=15` → `3` (7+7+1 또는 5+5+5), `동전=[2], M=3` → `-1`

- **셀프체크**: `dp[a]=min(dp[a], dp[a-coin]+1)`에서 용량(금액) 루프를 오름차순으로 돌아야 무한 사용이 허용됨을 아는가? 초기값을 `inf`로 두고 마지막에 `inf`면 -1을 출력하는가? M=15에서 그리디(가장 큰 동전 먼저)가 7+7+1=3개로 맞지만, 그리디가 항상 최적이 아님(예: 동전 [1,3,4], M=6 → 그리디 4+1+1=3개, DP 3+3=2개)을 이해했는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    K, M = int(data[idx]), int(data[idx+1]); idx += 2
    coins = [int(data[idx + i]) for i in range(K)]
    INF = float('inf')
    dp = [0] + [INF] * M
    for coin in coins:
        for a in range(coin, M + 1):
            if dp[a - coin] + 1 < dp[a]:
                dp[a] = dp[a - coin] + 1
    print(dp[M] if dp[M] != INF else -1)
main()

(1) 접근·핵심 아이디어

- 무한(unbounded) 배낭형 문제. 상태 `dp[a]` = 금액 `a`를 만드는 데 필요한 최소 동전 개수.
- 각 동전을 여러 번 쓸 수 있어야 하므로, 금액 루프를 **오름차순**으로 돌아 방금 갱신한 `dp[a-coin]`(이미 이 동전을 쓴 값)을 곧바로 재사용한다.
- 그리디(큰 동전부터)가 항상 최적이 아니므로 반드시 DP로 모든 조합을 탐색해야 한다(예: `[1,3,4]`, M=6 → 그리디 3개, DP 2개).

(2) 코드 단계별

- `dp[0]=0`, 나머지 `INF`로 초기화. INF는 "아직 만들 수 없음"을 뜻한다.
- 동전마다, `a`를 `coin`부터 `M`까지 오름차순으로 돌며 `dp[a] = min(dp[a], dp[a-coin]+1)`.
- 마지막에 `dp[M]`이 `INF`면 만들 수 없으므로 `-1`, 아니면 그 값 출력.
- 첫 예제 `[1,5,7]` M=15 → `5+5+5` 또는 `7+7+1`로 3개. 둘째 예제 `[1,3,4]` M=6 → `3+3`으로 2개(그리디의 3개보다 적다).

(3) 스스로 다시 짤 때 생각 순서

- "최소 개수 + 무한 사용" → `dp`를 `INF`로 초기화(`dp[0]=0`), 금액 오름차순 골격.
- 이중 루프에서 `min(dp[a], dp[a-coin]+1)` 전이 작성.
- 끝에서 `INF` 여부로 `-1` 분기 처리.
```

**3) 동전 교환 – 경우의 수** · Hard

- **요구사항**: 여러 종류의 동전(각 무한 사용)으로 금액 M을 만드는 방법의 수를 구하라. 동전을 사용하는 순서는 구분하지 않는다(예: 1+2와 2+1은 같은 방법). 값이 크면 1,000,000,007로 나눈 나머지.

- **입력**: 첫 줄 K, M, 다음 줄에 K개의 동전 값

- **출력**: 방법의 수(MOD)

- **예제**: `동전=[1,2,5], M=5` → `4` (5 / 2+2+1 / 2+1+1+1 / 1×5), `동전=[2], M=3` → `0`

- **셀프체크**: 순서를 구분하지 않으려면 **바깥 루프를 동전, 안쪽 루프를 금액**으로 돌아야 한다(동전을 하나씩 도입). 반대로 돌면 순서를 구분하는 순열 카운트가 되어 오답이다. `dp[0]=1` 기저의 의미(0원을 만드는 방법은 아무것도 안 쓰는 1가지)를 아는가? M=5 예제에서 4가지를 직접 나열해 검산했는가?

import sys
def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    K, M = int(data[idx]), int(data[idx+1]); idx += 2
    coins = [int(data[idx + i]) for i in range(K)]
    MOD = 1_000_000_007
    dp = [0] * (M + 1)
    dp[0] = 1
    for coin in coins:            # 바깥: 동전 (순서 구분 안 함)
        for a in range(coin, M + 1):
            dp[a] = (dp[a] + dp[a - coin]) % MOD
    print(dp[M] % MOD)
main()

(1) 접근·핵심 아이디어

- 각 동전을 무한히 쓸 수 있는 상태에서 "금액 M을 만드는 조합의 수"를 센다. 순서를 구분하지 않으므로 `1+2`와 `2+1`을 같은 것으로 봐야 한다.
- 이를 위해 **바깥 루프를 동전, 안쪽 루프를 금액**으로 돈다. 동전을 한 종류씩 "도입"하면서 갱신하면, 각 조합은 "동전을 값의 오름차순으로 사용한 정해진 순서" 하나로만 세어져 중복이 사라진다.
- 상태 `dp[a]` = 지금까지 도입한 동전들로 금액 `a`를 만드는 방법의 수. 전이 `dp[a] += dp[a-coin]`.

(2) 코드 단계별

- `dp[0]=1` 기저: 0원을 만드는 방법은 아무 동전도 안 쓰는 1가지.
- 바깥에서 동전 `coin`을 하나 고정한 뒤, 안쪽에서 `a`를 `coin`부터 `M`까지 오름차순으로 돌며 `dp[a] += dp[a-coin]`. 오름차순이라 같은 동전을 여러 번 재사용(무한 배낭)한다.
- 만약 바깥/안쪽 루프를 뒤집으면 순열(순서 구분)을 세게 되어 오답. 값이 커질 수 있어 매 덧셈마다 `% MOD`.
- `dp[M]`이 답. 만들 수 없으면 자연히 0이 된다(둘째 예제 `[2]`로 `4`는 만들 수 있어 1, `3`은 0).

(3) 스스로 다시 짤 때 생각 순서

- "무한 사용 + 순서 무시 조합 카운트" → 동전-바깥, 금액-오름차순 안쪽 골격을 먼저 확정.
- `dp[0]=1`, 나머지 0으로 초기화.
- 이중 루프에서 `dp[a] += dp[a-coin]` 쓰고 MOD 적용, 끝에 `dp[M]` 출력.

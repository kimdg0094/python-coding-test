> 개요: 이 챕터에서는 "무엇을 state로 둘지"를 스스로 정의해 한 칸씩 전이시키는 DP, 직전 선택이 다음 선택을 제약하는 연속 구간 DP, 그리고 두 문자열을 나란히 비교하는 String Matching(LCS·편집거리)을 다룬다. 핵심은 점화식이 아니라 "상태 설계"다.

## L1. 원하는 State를 정의하여 한 칸씩 나아가는 DP

**개념**

- 기본 DP(Ch5)에서는 대개 `dp[i]`가 "i번째까지 봤을 때의 최적값" 하나로 충분했다. 하지만 현실 문제는 "i까지 봤다"만으로는 다음 결정을 내릴 수 없는 경우가 많다. 직전에 무엇을 골랐는지, 지금 어떤 모드인지 같은 **추가 정보**가 있어야 전이가 결정된다. 이때 그 정보를 **state(상태)** 로 끌어올려 `dp[i][상태]`로 확장하는 것이 이 레슨의 핵심이다.
- 상태 설계의 원칙은 "미래의 결정에 영향을 주는 최소한의 과거 정보만 담는다"이다. 이를 만족하면 그 이전 과정을 잊어도 되는데(무기억성), 이 성질 덕분에 DP가 성립한다. 상태가 너무 적으면 전이가 불가능하고, 너무 많으면 시간·메모리가 폭발한다. 딱 필요한 만큼만 상태에 넣는 감각이 관건이다.
- 절차는 (1) "i번째 칸에서 결정을 내리려면 무엇을 알아야 하는가?"를 자문해 상태 축을 찾고, (2) `dp[i][state]`의 의미를 한국어 한 문장으로 명확히 적고, (3) 각 상태에서 취할 수 있는 선택지마다 다음 상태로의 전이를 쓰고, (4) 초기값과 답의 위치(마지막 칸의 어느 상태를 봐야 하나)를 정한다.

```python
# 뼈대: dp[i][s] = i번째까지 처리했고 현재 상태가 s일 때의 최적값
# s는 "다음 결정에 필요한 최소 정보"(예: 직전에 샀다/팔았다, 쉬는 중이다 등)
NEG = float('-inf')
dp = [[NEG] * S for _ in range(n + 1)]
dp[0][init_state] = 0                     # 시작 상태 초기화

for i in range(1, n + 1):
    for s in range(S):
        if dp[i-1][s] == NEG:
            continue
        for choice in actions(s):         # 상태 s에서 가능한 행동들
            ns, gain = transit(s, choice, i)
            dp[i][ns] = max(dp[i][ns], dp[i-1][s] + gain)

ans = max(dp[n][s] for s in range(S))     # 마지막 칸에서 허용되는 상태들 중 최적
```

**그림으로 보기**

- 상태 축을 하나 붙인다는 것은 **DP 표가 한 장에서 여러 장으로 늘어난다**는 뜻이다. `dp[i]`가 한 줄짜리 표였다면 `dp[i][s]`는 상태 개수만큼 층이 쌓인 표다.

```text
   plain DP : dp[i]                state DP : dp[i][s]

     i =  0   1   2   3                   i =  0   1   2   3
        +---+---+---+---+        s = cool  +---+---+---+---+
        |   |   |   |   |                  |   |   |   |   |
        +---+---+---+---+                  +---+---+---+---+
                                 s = cash  +---+---+---+---+
                                           |   |   |   |   |
                                           +---+---+---+---+
                                 s = hold  +---+---+---+---+
                                           |   |   |   |   |
                                           +---+---+---+---+
```

- 층이 늘어난 만큼 전이도 "칸 → 칸"이 아니라 "**층 → 층**"이 된다. 쿨다운 주식의 세 층 사이에 어떤 화살표가 있고 없는지가 곧 문제의 규칙이다.

```text
   states :  H = holding ,  C = cash ,  D = cooldown (sold today)

     C  --buy(-p)-->  H       H  --sell(+p)-->  D       D  --wait-->  C
     C  --stay-->  C          H  --stay-->  H

   forbidden :  D  --buy-->  H       # must rest one full day after selling
```

- 금지된 화살표를 코드에서 `if`로 막는 게 아니라, **그 전이를 아예 안 적는 것**이 상태 DP의 요령이다. 존재하지 않는 전이는 절대 일어나지 않는다.

- 색칠하기(집 3채, R/G/B, 인접한 두 집은 다른 색)로 실제 층을 채워 보면 이렇다. 왼쪽이 입력 비용, 오른쪽이 층 3장짜리 `dp`다.

```text
   input cost              dp[i][c] = min total cost of houses 0..i

   house   R   G   B       layer    i=0    i=1    i=2
     0    26  40  83       c = R     26     89     96   # answer <- 96
     1    49  60  57       c = G     40     86    172
     2    13  89  99       c = B     83     83    185
```

- `dp[1][R] = 49 + min(dp[0][G], dp[0][B]) = 49 + 40 = 89`처럼, 각 칸은 **자기 색을 제외한 다른 층들**만 본다. "인접한 두 집은 다른 색"이라는 제약이 "같은 층에서는 이어오지 않는다"로 번역된 것이다.

**손으로 따라가기**

- 위 색칠하기를 한 칸씩 채운다. `dp[i][c]` = i번째 집을 색 `c`로 칠했을 때 0번부터 i번까지의 최소 누적 비용.

| 칸 | 이번 집 비용 | 볼 수 있는 직전 층 | 그중 최소 | dp 값 |
| --- | --- | --- | --- | --- |
| dp[0][R] | 26 | 없음 (첫 집) | 0 | 26 |
| dp[0][G] | 40 | 없음 | 0 | 40 |
| dp[0][B] | 83 | 없음 | 0 | 83 |
| dp[1][R] | 49 | dp[0][G]=40, dp[0][B]=83 | 40 | 89 |
| dp[1][G] | 60 | dp[0][R]=26, dp[0][B]=83 | 26 | 86 |
| dp[1][B] | 57 | dp[0][R]=26, dp[0][G]=40 | 26 | 83 |
| dp[2][R] | 13 | dp[1][G]=86, dp[1][B]=83 | 83 | **96** |
| dp[2][G] | 89 | dp[1][R]=89, dp[1][B]=83 | 83 | 172 |
| dp[2][B] | 99 | dp[1][R]=89, dp[1][G]=86 | 86 | 185 |

- 답은 마지막 집의 세 층 중 최소인 `min(96, 172, 185) = 96`이고, 그 경로는 R(26) → B(57) → R(13)이다. 마지막 집을 어떤 색으로 끝내도 되므로 답이 한 칸이 아니라 **한 열 전체의 최솟값**이라는 점을 확인하라.

**왜 이렇게 되는가**

- 상태 DP도 6단계 절차는 같다. 달라지는 건 ①에서 축이 하나 늘어난다는 것뿐이다. 쿨다운 주식에 적용해 보자.

- **① 상태 정의**: `dp[i][s]` = i일까지 거래를 끝냈고 하루가 끝난 시점의 상황이 `s`일 때의 최대 이익. `s`는 `hold`(주식을 들고 있음), `cash`(현금이고 오늘 살 수 있음), `cool`(오늘 팔아서 내일은 못 삼) 셋이다.

- **② 마지막 선택으로 쪼개기**: i일에 한 행동으로 나눈다 — 아무것도 안 함, 매수, 매도. 어떤 행동이 가능한지는 **어제의 상태**가 결정한다. 바로 이것이 상태 축이 필요한 이유다.

- **③ 선택별 식**: `dp[i][hold] = max(dp[i-1][hold], dp[i-1][cash] - p)`, `dp[i][cash] = max(dp[i-1][cash], dp[i-1][cool])`, `dp[i][cool] = dp[i-1][hold] + p`. `cool`로 들어오는 화살표가 `hold` 하나뿐이라는 점이 "판 날에만 쿨다운"을 표현한다.

- **④ 초기값**: `dp[0][hold] = -p[0]`, `dp[0][cash] = 0`, `dp[0][cool] = -inf`. 첫날에 이미 판 상태는 존재할 수 없으므로 도달 불가를 뜻하는 `-inf`로 막는다. 여기를 0으로 두면 "팔지도 않았는데 이익 0을 챙긴 상태"가 생겨 답이 부풀 수 있다.

- **⑤ 계산 순서**: `i`를 1일부터. 각 `i`에서 세 상태를 **동시에** 계산해 서로 덮어쓰지 않게 한다(굴림 변수로 짤 때 특히 중요).

- **⑥ 답의 위치**: 마지막 날 `hold`는 주식을 들고 끝난 것이라 무효이므로 `max(dp[n-1][cash], dp[n-1][cool], 0)`. **상태를 늘리면 답의 위치도 "어느 상태로 끝나야 유효한가"라는 질문이 된다.**

- **상태를 덜 잡으면 왜 틀리는가 (반례)**: 쿨다운을 무시하고 `hold`/`cash` 두 상태만 두면, `가격 = [1, 3, 2, 4]`에서 "1에 사서 3에 팔고(+2) 2에 사서 4에 판다(+2)"로 4가 나온다. 하지만 3에 판 다음 날은 반드시 쉬어야 하므로 2에 살 수 없다. 실제 최적은 "1에 사서 4에 판다"의 3이다. `cool` 상태가 없으면 "어제 팔았다"는 사실이 어디에도 남지 않아 규칙을 검사할 방법이 사라진다.

- **상태를 필요 이상으로 잡으면 왜 손해인가**: 상태 수는 축들의 **곱**으로 늘어난다. `n`개의 위치 × `S`개의 상태 × `K`개의 여분 축이면 상태 수가 `n·S·K`가 되어 시간과 메모리가 함께 커진다. 예컨대 색칠하기에서 "지금까지 쓴 색의 개수"까지 상태에 넣으면 표가 몇 배로 늘지만 답은 그대로다. **다음 결정에 실제로 쓰이지 않는 정보는 상태가 아니다.**

- **복잡도**: 상태 수 `n·S`, 전이 비용은 상태당 행동 수 `A`. 따라서 `O(n·S·A)`. 색칠하기는 `S=3`, `A=2`라 `O(n)`, 쿨다운 주식은 `S=3`, `A=2`라 역시 `O(n)`이다. 전이가 `dp[i-1]`만 참조하므로 두 줄만 들고 있으면 공간은 `O(S)`로 떨어진다.

**접근 전략**

- 신호는 "직전 행동이 이번 선택을 막거나 값을 바꾼다"이다. 예: 방금 주식을 샀으면 또 살 수 없다(보유/현금 상태), 방금 이 칸을 밟았으면 다음은 못 밟는다(연속 개수 상태), 방금 색 A를 칠했으면 옆은 A가 안 된다(직전 색 상태). 이런 문장이 보이면 그 "직전 행동"을 상태 축으로 승격한다. 상태 후보를 먼저 나열하고, 각 상태에서 가능한 행동과 그 결과 상태를 표로 정리한 뒤 코드로 옮기면 실수가 준다.
- 시간복잡도는 `O(n · S · A)` (S=상태 수, A=상태당 행동 수), 공간은 `O(n · S)`이며 전이가 `dp[i-1]`에만 의존하면 두 줄만 유지해 `O(S)`로 줄인다. 흔한 실수: 도달 불가능한 상태(`-inf`)에서 전이해 엉뚱한 값이 퍼지는 것 — 반드시 `-inf` 가드를 둔다. 또 답을 `dp[n][0]`처럼 특정 상태로 고정하는 실수 — 마지막에 어떤 상태로 끝나야 유효한지 다시 생각한다(예: 주식은 반드시 판 상태여야 하므로 "현금" 상태만 답). 파이썬 팁: 상태가 2~3개면 배열 대신 `buy, sell, cool` 같은 변수 몇 개로 굴리는 게 빠르고 명확하다.

**문제**

**1) 쿨다운 주식** · Medium

- **요구사항**: 하루 최대 1주만 보유 가능. 한 번 팔면 그 다음 날 하루는 반드시 쉬어야(사지 못함) 한다. 여러 번 사고팔 수 있을 때 얻을 수 있는 최대 이익을 구하라. `dp[i][보유], dp[i][현금], dp[i][쿨다운]` 세 상태로 설계하는 것이 정석.
- **입력**: 첫 줄 N(1≤N≤10^5), 둘째 줄 N개의 정수 가격(1≤가격≤10^4).
- **출력**: 최대 이익(거래 안 하면 0).
- **예제**: `4 / 1 2 3 0 2` 형태가 아니라 → 아래처럼 준다. `6 / 1 2 3 0 2 4` → `4`  (1에 사서 3에 팔면 +2, 하루 쉬고 0에 사서... 대신 0에 사서 4에 팔면 +4가 최대 단일. 조합 확인 필요) / `5 / 1 2 3 4 5` → `4`
- **셀프체크**: N=1이면 0인가? "쿨다운" 상태를 빼먹고 "현금"으로 바로 사게 두면 규칙 위반 — 상태 전이표를 다시 그려 확인. 마지막 날 답은 "보유" 상태를 제외한 max인지 점검.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    prices = [int(data[1 + i]) for i in range(n)]
    NEG = float('-inf')
    hold = -prices[0]   # 주식 보유 중
    cash = 0            # 현금 상태(살 수 있음)
    cool = NEG          # 방금 팔아 쿨다운
    for i in range(1, n):
        p = prices[i]
        new_hold = max(hold, cash - p)   # 계속 보유 vs 현금에서 매수
        new_cash = max(cash, cool)       # 계속 현금 vs 쿨다운 해제
        new_cool = hold + p              # 보유분 매도 -> 쿨다운
        hold, cash, cool = new_hold, new_cash, new_cool
    print(max(cash, cool, 0))
main()

- "방금 팔면 하루 쉬어야 한다"는 제약이 곧 상태 축이다. 매일의 상황을 세 가지로 나눈다: `hold`(주식 보유 중), `cash`(현금이며 언제든 매수 가능), `cool`(오늘 막 팔아 다음 날 매수가 막힌 쿨다운).
- 이 세 상태만 알면 다음 날 결정이 완전히 정해지므로 무기억성이 성립한다. 각 상태를 하루씩 앞으로 굴린다.

(2) 코드 단계별

- `hold`는 처음부터 0일에 산 경우 `-prices[0]`, `cash=0`, `cool`은 도달 불가라 `-inf`로 시작.
- 매일 세 전이를 동시에 계산한다. `new_hold = max(계속 보유, 현금에서 매수)`, `new_cash = max(계속 현금, 어제 쿨다운이 풀림)`, `new_cool = hold + p`(오늘 매도).
- 세 값을 한 번에 갱신해야 서로 덮어쓰지 않는다.
- 마지막 날 답은 주식을 든 채(`hold`) 끝나면 손해이므로 제외하고 `max(cash, cool, 0)`. `0`은 아예 거래를 안 한 경우.

(3) 스스로 다시 짤 때 생각 순서

- "직전 행동이 오늘 선택을 막나?"를 먼저 묻는다 → 매도 후 쿨다운이 그 신호.
- 상태 3개를 나열하고 각 상태에서 가능한 행동(유지/매수/매도/쿨다운 해제)과 결과 상태를 표로 그린다.
- 답 위치를 "보유 상태 제외"로 정한다. 마지막에 주식을 들고 있으면 안 되기 때문.
```

**2) 색칠하기(직전 색 제약)** · Medium

- **요구사항**: 집 N채를 빨강/초록/파랑 셋 중 하나로 칠한다. 인접한 두 집은 다른 색이어야 한다. 각 집을 각 색으로 칠하는 비용이 주어질 때 전체 최소 비용을 구하라. `dp[i][c]` = i번째 집을 색 c로 칠했을 때 i까지의 최소 비용.
- **입력**: 첫 줄 N(1≤N≤1000), 이후 N개 줄에 각 집의 R G B 비용(0≤비용≤1000).
- **출력**: 최소 총 비용.
- **예제**: `3 / 26 40 83 / 49 60 57 / 13 89 99` → `84` (26→57→13이면 96... 40→57→13은 위반? 40은 G, 57은 B, 13은 R → 40+57+13=110; 26(R)→60(G)→13(R)=99; 26(R)→57(B)→? 다음 R만 13 → 26+57+13=96; 최소는 실제 계산으로 84 나오는 조합을 찾아 검증) / `2 / 1 100 100 / 100 1 100` → `2`
- **셀프체크**: `dp[i][c] = cost[i][c] + min(dp[i-1][c'] for c' != c)`. 세 색뿐이라 `min`을 매번 도는 게 O(1). 인접 제약을 `!=c`로 정확히 걸었는지, N=1 초기화가 맞는지 확인. 예제 계산은 직접 손으로 전개해 답을 확정할 것.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    cost = []
    for _ in range(n):
        r = int(data[idx]); g = int(data[idx + 1]); b = int(data[idx + 2]); idx += 3
        cost.append((r, g, b))
    dp = list(cost[0])                     # 첫 집: 각 색의 비용 그대로
    for i in range(1, n):
        r, g, b = cost[i]
        ndp = [
            r + min(dp[1], dp[2]),         # R로 칠하면 직전은 G/B 중 최소
            g + min(dp[0], dp[2]),         # G로 칠하면 직전은 R/B 중 최소
            b + min(dp[0], dp[1]),         # B로 칠하면 직전은 R/G 중 최소
        ]
        dp = ndp
    print(min(dp))
```

**3) 연속 3계단 금지** · Hard

## L2. 연속적이지만 직전 상황에 영향을 받는 DP

**개념**

- 이 유형은 "구간이 반드시 연속(끊기지 않음)"이라는 제약이 붙는다. 대표는 **최대 부분합(Kadane)** 과 **최장 증가 부분수열(LIS)** 계열이다. L1과 닮았지만 결정적 차이는, "이번 원소를 이전 것과 이어 붙일지 / 여기서 새로 시작할지"를 매 칸에서 고른다는 점이다. 즉 상태가 "직전 칸을 포함한 채로 이어온 값"이 된다.
- Kadane의 상태는 `cur = i를 끝으로 하는 연속 구간의 최대합`이다. 전이는 단 한 줄: `cur = max(a[i], cur + a[i])`. "이전 구간에 붙이는 게 이득이면 붙이고, 아니면 a[i]에서 새로 시작한다"는 직관 그대로다. 전역 답은 매 칸 `cur`의 최댓값을 따로 기록한다(cur 자체는 i를 끝으로 하는 값이라 전역 최대와 다르다).
- LIS의 상태는 `dp[i] = i번째 원소를 마지막으로 쓰는 증가 수열의 최대 길이`이다. `dp[i] = 1 + max(dp[j] for j<i and a[j]<a[i])`로 O(n²). 여기서 "i를 마지막으로"라는 제약이 핵심 — 이 제약이 있어야 `a[j]<a[i]` 비교가 성립한다. 더 빠른 O(n log n) 방법은 `tails[k] = 길이 k+1짜리 증가수열의 가능한 최소 끝값`을 이분탐색으로 갱신하는 것.

```python
# Kadane: i를 끝으로 하는 최대 연속합
best = cur = a[0]
for x in a[1:]:
    cur = max(x, cur + x)      # 이어붙이기 vs 새로 시작
    best = max(best, cur)

# LIS O(n log n): tails[k] = 길이(k+1) 증가수열의 최소 마지막값
import bisect
tails = []
for x in a:
    i = bisect.bisect_left(tails, x)   # x가 들어갈 자리
    if i == len(tails):
        tails.append(x)                # 더 긴 수열 발견
    else:
        tails[i] = x                   # 같은 길이를 더 낮은 끝값으로 갱신
# 답은 len(tails)  (tails 자체는 실제 LIS가 아님에 주의)
```

**그림으로 보기**

- 이 유형의 상태는 배열이 아니라 **"지금 이어오고 있는 구간"** 하나다. 매 칸에서 결정은 딱 둘 — 지금 구간에 이어 붙이거나, 여기서 새 구간을 시작하거나.

```text
   at position i there are only two options :

     extend  :  [ .... run ending at i-1 .... ][ a[i] ]   value = cur + a[i]
     restart :                                 [ a[i] ]   value = a[i]

   cur  = max( cur + a[i] , a[i] )   # cur < 0 이면 언제나 restart 가 이긴다
   best = max( best , cur )          # 전역 답은 따로 기록한다
```

- `cur`는 "i를 끝으로 하는" 값이라 도중에 줄었다 늘었다 한다. 그래서 전역 최댓값 `best`를 별도로 들고 있어야 한다. 실제 수열로 두 값을 나란히 굴려 보자.

```text
   i       0    1    2    3    4    5    6    7    8
   a[i]   -2    1   -3    4   -1    2    1   -5    4
   cur    -2    1   -2    4    3    5    6    1    5
   best   -2    1    1    4    4    5    6    6    6
                R              R                       # R = restart
```

- `R` 표시가 붙은 두 칸(`i=1`, `i=3`)에서만 새로 시작했다. 두 곳 모두 직전 `cur`가 음수였던 자리다. 그리고 `cur`가 최대인 곳은 `i=6`이지만 `cur`는 그 뒤로 1까지 떨어진다 — `best`를 따로 안 두면 답 6을 놓친다.

- "연속(Kadane)"과 "부분수열(LIS)"의 차이는 **뽑은 원소들이 붙어 있어야 하는가**다. 이 한 가지가 상태 정의를 가른다.

```text
   a = [ 5 , 1 , 6 , 2 , 7 ]

   contiguous (Kadane) : block only    [1,6,2] ok    [5,6,7] no
   subsequence  (LIS)  : order only    [5,6,7] ok    [6,1]   no
```

**손으로 따라가기**

- `a = [-2, 1, -3, 4, -1, 2]`로 Kadane를 한 칸씩 굴린다. `cur` = i를 끝으로 하는 연속 구간의 최대합, `best` = 지금까지 본 `cur` 중 최댓값.

| i | a[i] | 이어붙이기 `cur+a[i]` | 새로 시작 `a[i]` | 고른 것 | cur | best |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | -2 | — | — | 초기값 | -2 | -2 |
| 1 | 1 | -2+1 = -1 | 1 | 새로 시작 | 1 | 1 |
| 2 | -3 | 1-3 = -2 | -3 | 이어붙이기 | -2 | 1 |
| 3 | 4 | -2+4 = 2 | 4 | 새로 시작 | 4 | 4 |
| 4 | -1 | 4-1 = 3 | -1 | 이어붙이기 | 3 | 4 |
| 5 | 2 | 3+2 = 5 | 2 | 이어붙이기 | 5 | **5** |

- 답은 `best = 5`이고 그 구간은 `[4, -1, 2]`다. i=2에서 `cur`가 -2로 떨어졌지만 `best`는 1을 지키고 있었다는 점, 그리고 i=3에서 이어붙이기(2)보다 새로 시작(4)이 커서 앞 구간을 버렸다는 점을 확인하라.

**왜 이렇게 되는가**

- 6단계 절차를 Kadane에 적용한다.

- **① 상태 정의**: `cur[i]` = `a[i]`를 **마지막 원소로 포함하는** 연속 구간의 최대합. "i를 반드시 포함한다"가 없으면 구간이 어디서 끝나는지 몰라 다음 칸에서 이어 붙일 수가 없다. LIS에서 "i를 마지막으로 쓴다"고 못 박은 것과 완전히 같은 이유다.

- **② 마지막 선택으로 쪼개기**: `a[i]`를 포함하는 구간은 `a[i-1]`까지 이어져 온 구간의 연장이거나, `a[i]`에서 새로 시작한 길이 1짜리 구간이거나 둘 중 하나다.

- **③ 선택별 식**: `cur[i] = max(cur[i-1] + a[i], a[i])`. 여기서 `a[i]`는 양쪽 경우에 모두 더해지므로 밖으로 빼면 `cur[i] = a[i] + max(cur[i-1], 0)`과 같다. 즉 **직전 구간의 합이 음수면 버리는 것이 언제나 이득**이라는 뜻이고, 이것이 Kadane의 정당성이다. 음수인 접두사를 붙여서 합이 커지는 일은 없다.

- **④ 초기값**: `cur = best = a[0]`. 원소를 최소 하나는 골라야 하므로 0에서 시작하면 안 된다.

- **⑤ 계산 순서**: 왼쪽에서 오른쪽으로 한 번.

- **⑥ 답의 위치**: `best`(모든 `cur`의 최댓값). `cur`의 마지막 값이 아니다.

- **왜 전부 음수이면 0이 답이 아닌가**: "원소를 최소 1개 골라야 한다"는 조건 때문이다. 빈 구간을 허용하면 답은 언제나 0 이상이 되지만, 문제가 빈 구간을 금지하면 `best`를 `a[0]`으로 시작해 "가장 큰 음수 하나"가 답으로 나오게 해야 한다. 초기값 `0`과 `a[0]` 중 무엇을 쓰느냐가 곧 "빈 구간 허용 여부"를 표현한다.

- **원형 배열이 왜 "전체합 − 최소 구간"인가**: 원형에서 양끝을 감싸는 구간을 골랐다면, 고르지 **않은** 부분은 반드시 가운데의 연속 구간 하나가 된다. 감싼 부분의 합 = 전체합 − 안 고른 부분의 합이므로, 감싼 쪽을 최대로 만들려면 안 고른 쪽을 최소로 만들면 된다. 그래서 최소 연속합 Kadane를 한 번 더 굴리는 것이다. 단 전부 음수이면 "안 고른 부분"이 배열 전체가 되어 감싼 쪽이 빈 구간이 되므로 이 후보는 무효다.

- **복잡도**: 상태 `n`개 × 전이 O(1) = `O(n)`, 공간은 `cur`, `best` 두 변수뿐이라 `O(1)`. LIS는 상태 `n`개 × 전이 O(n) = `O(n²)`이고, 전이를 이분탐색으로 바꾸면 `O(n log n)`이 된다. 상태 수는 그대로인데 **전이 비용만 줄인 것**이다.

**접근 전략**

- "연속 구간"이면 Kadane 계열, "순서를 지키되 띄엄띄엄 골라 단조성"이면 LIS 계열을 떠올린다. 판별 질문: 뽑은 원소들이 원본에서 **붙어 있어야** 하나(연속) 아니면 **순서만** 지키면 되나(부분수열)? 전자는 `cur`를 굴리고, 후자는 `dp[i]`를 i-마지막으로 정의한다. 최소합·최대곱·원형 배열·"최소 길이 K 이상" 같은 변형은 전부 이 두 뼈대의 상태를 살짝 바꾼 것이다(예: 최대곱은 음수 때문에 `cur_max, cur_min` 두 개를 함께 굴린다).
- 복잡도: Kadane는 시간 `O(n)`·공간 `O(1)`. LIS는 순수 DP `O(n²)`·공간 `O(n)`, 이분탐색판 `O(n log n)`·공간 `O(n)`. 흔한 실수: (1) Kadane에서 전역 답을 `cur`로 잘못 출력(반드시 `best` 따로) — 특히 원소가 전부 음수면 빈 구간을 0으로 착각. (2) LIS에서 "증가"가 강증가(<)인지 비감소(≤)인지 문제 조건 확인 — `bisect_left`(강증가) vs `bisect_right`(비감소)로 갈린다. (3) `tails` 배열을 실제 LIS 수열로 오해(길이만 정확). 파이썬 팁: `bisect` 모듈을 쓰면 이분탐색을 직접 안 짜도 된다.
- `bisect_left`와 `bisect_right`가 중복 값에서 어떻게 갈리는지 `a=[1,3,3,5]`로 직접 추적하면 확실하다.

  | 입력 x | `bisect_left`(강증가) tails | `bisect_right`(비감소) tails |
  | --- | --- | --- |
  | 1 | `[1]` | `[1]` |
  | 3 | `[1,3]` | `[1,3]` |
  | 3 | `[1,3]` (자리 1에 3을 덮어써 길이 그대로) | `[1,3,3]` (끝에 append로 길이 +1) |
  | 5 | `[1,3,5]` | `[1,3,3,5]` |
  | 답(len) | 3 (강증가 `1,3,5`) | 4 (비감소 `1,3,3,5`) |

  즉 같은 값을 만났을 때 `bisect_left`는 기존 자리를 "덮어써" 길이를 늘리지 않고(중복 배제 = 강증가), `bisect_right`는 뒤에 붙여 길이를 늘린다(중복 허용 = 비감소). 문제의 "증가" 정의에 맞는 쪽을 골라야 한다.

**문제**

**1) 최대 연속 부분합** · Easy

- **요구사항**: 정수 수열에서 연속한 부분수열의 합 중 최댓값을 구하라(원소를 적어도 1개는 골라야 함).
- **입력**: 첫 줄 N(1≤N≤10^5), 둘째 줄 N개 정수(-10^4≤a≤10^4).
- **출력**: 최대 연속 부분합.
- **예제**: `9 / -2 1 -3 4 -1 2 1 -5 4` → `6` ([4,-1,2,1]) / `3 / -3 -1 -2` → `-1` (전부 음수면 가장 큰 하나)
- **셀프체크**: 전부 음수인 케이스가 함정 — 0을 출력하면 오답. `best`를 `a[0]`으로 초기화했는가? `cur`와 `best`를 헷갈리지 않았는가?

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()

    a = [int(data[1 + i]) for i in range(n)]

    for x in a[1:]:
        cur = max(x, cur + x)      # 이어붙이기 vs 여기서 새로 시작
        best = max(best, cur)      # i를 끝으로 하는 값 중 전역 최대 기록
    print(best)
main()

(1) 접근·핵심 아이디어

- Kadane 알고리즘. 상태 `cur` = i를 끝으로 하는 연속 구간의 최대합. 매 칸에서 "이전 구간에 이어붙이면 이득이면 붙이고, 아니면 a[i]에서 새로 시작"한다.
- 전역 답 `best`는 `cur`와 별도로 기록해야 한다. `cur`는 항상 i를 끝으로 하는 값이라 전역 최대와 다를 수 있기 때문.

(2) 코드 단계별

- `best = cur = a[0]`로 초기화. 원소를 최소 1개 골라야 하므로 첫 원소부터 시작.
- 각 x마다 `cur = max(x, cur + x)`: `x`는 새로 시작, `cur + x`는 이어붙이기.
- `best = max(best, cur)`로 지금까지 본 최대를 갱신.
- 전부 음수여도 `best`가 `a[0]`에서 시작하므로 "가장 큰 하나"인 음수가 정확히 나온다(0으로 착각하지 않음).

(3) 스스로 다시 짤 때 생각 순서

- "연속 구간"이라는 단어를 보면 Kadane를 떠올린다.
- 상태를 "i를 끝으로 하는 최대합"으로 정의하고 한 줄 전이를 적는다.
- `best`를 `cur`와 분리하고, 전부 음수 케이스로 초기화가 맞는지 검산한다.
```

**2) 가장 긴 증가하는 부분수열** · Medium

- **요구사항**: 수열에서 순서를 유지하며(연속일 필요 없음) 강하게 증가하는 부분수열의 최대 길이를 구하라. N이 크므로 O(n log n)을 목표로.
- **입력**: 첫 줄 N(1≤N≤10^5), 둘째 줄 N개 정수.
- **출력**: LIS의 길이.
- **예제**: `6 / 10 20 10 30 20 50` → `4` ([10,20,30,50]) / `8 / 3 1 4 1 5 9 2 6` → `4` ([1,4,5,9] 또는 [3,4,5,9] 등)
- **셀프체크**: N=10^5이면 O(n²)는 위험 → 이분탐색판 필수. `tails`에서 `bisect_left` vs `bisect_right`를 강증가 기준에 맞췄는가? 같은 값이 연속으로 와도 길이가 늘지 않는지 확인.

```runner
@@SOLUTION
import sys
import bisect
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    tails = []                       # tails[k] = 길이 k+1 증가수열의 최소 끝값
    for x in a:
        i = bisect.bisect_left(tails, x)   # 강증가 -> left
        if i == len(tails):
            tails.append(x)          # 더 긴 수열 발견
        else:
            tails[i] = x             # 같은 길이를 더 낮은 끝값으로 갱신
    print(len(tails))
main()

(1) 접근·핵심 아이디어

- LIS를 O(n log n)으로 구하는 `tails` 기법. `tails[k]`는 "길이 k+1인 증가수열이 가질 수 있는 최소 끝값"이다. 끝값을 낮게 유지할수록 뒤에 더 많은 원소를 이어붙일 여지가 커진다.
- `tails`는 항상 정렬 상태라 이분탐색으로 x가 들어갈 자리를 찾는다. 답은 `tails`의 길이(단, `tails` 자체가 실제 LIS 수열은 아님).

(2) 코드 단계별

- 각 x에 대해 `bisect_left(tails, x)`로 자리 i를 찾는다. 강증가(중복 배제)이므로 `left`.
- `i == len(tails)`면 x가 가장 커서 새 길이를 여니 `append`.
- 아니면 `tails[i] = x`로 같은 길이의 끝값을 더 낮게 덮어쓴다(길이는 그대로).
- 같은 값이 반복되면(`5 5 5 5 5`) 매번 자리 0에 덮어써 길이가 1로 유지 → 강증가라 정답 1.

(3) 스스로 다시 짤 때 생각 순서

- "순서만 지키고 연속 아님 + 단조 증가"면 LIS.
- 강증가인지 비감소인지 확인 → `bisect_left`(강증가) vs `bisect_right`(비감소) 선택.
- `tails`는 길이만 정확하다는 점을 기억하고 답으로 `len(tails)`를 낸다.
```

**3) 원형 배열 최대 연속합** · Hard

- **요구사항**: 수열이 원형(마지막 다음이 처음)일 때 연속 부분합의 최댓값을 구하라. 원소는 최소 1개 선택. "원형 구간을 도는 경우"는 곧 "전체합 − 가운데 최소 연속합"과 같다는 관찰이 핵심.
- **입력**: 첫 줄 N(1≤N≤10^5), 둘째 줄 N개 정수(-10^4≤a≤10^4).
- **출력**: 원형에서의 최대 연속합.
- **예제**: `5 / 5 -3 5 -3 5` → `12` (원형으로 5,5,5 세 개를 이음: 마지막 5 + 처음 5 + ... ) / `3 / -2 -3 -1` → `-1` (전부 음수면 감싸는 경우 제외, 일반 Kadane 답)
- **셀프체크**: 두 후보의 max — (a) 일반 Kadane 최대, (b) 전체합 − (최소 연속합). 단, 전부 음수면 (b)가 빈 구간이 되어 0을 뽑아버리는 함정 → 이때는 (a)만 답. 최소 연속합 Kadane도 따로 굴려야 함. 예제로 두 분기를 모두 태워 확인.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    a = [int(data[1 + i]) for i in range(n)]
    # (a) 일반 Kadane 최대 연속합
    best = cur = a[0]
    for x in a[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    # 최소 연속합(비어있지 않음)
    minc = mn = a[0]
    for x in a[1:]:
        minc = min(x, minc + x)
        mn = min(mn, minc)
    total = sum(a)
    if best < 0:
        # 전부 음수 -> 감싸는 경우는 빈 구간이 되어 무효, 일반 Kadane만
        print(best)
    else:
        # (b) 전체합 - 최소 연속합 = 원형으로 감싼 최대
        print(max(best, total - mn))
main()

- 원형 최대 연속합은 두 경우로 나뉜다: (a) 감싸지 않는 보통 구간 → 일반 Kadane 최대, (b) 양끝을 감싸는 구간 → "전체합 − 가운데 최소 연속합". 감싸는 구간의 여집합이 곧 가운데 연속 구간이므로 그 최소를 빼면 감싼 부분이 최대가 된다.
- 답은 두 후보의 max. 단 전부 음수면 (b)의 "가운데 최소"가 전체가 되어 빈 구간(합 0)을 뽑는 함정 → 이때는 (a)만 유효.

(2) 코드 단계별

- 최대 연속합 `best`를 일반 Kadane로 구한다.
- 같은 방식으로 최소 연속합 `mn`을 `min`으로 굴린다(비어있지 않게).
- `total = sum(a)`.
- `best < 0`(전부 음수)이면 감싸는 경우가 무효이므로 `best`를 출력.
- 아니면 `max(best, total - mn)`이 답.

(3) 스스로 다시 짤 때 생각 순서

- "원형"을 보면 "감싼다 = 전체합 − 가운데 최소"라는 관찰을 떠올린다.
- 최대 Kadane와 최소 Kadane를 각각 굴린다.
- 전부 음수 함정을 위해 `best < 0` 분기를 반드시 둔다.
```

## L3. String Matching

**개념**

- 두 문자열을 나란히 놓고 비교하는 DP 계열이다. 축이 둘(문자열 A의 위치 i, B의 위치 j)이라 `dp[i][j]` 2차원 표가 자연스럽다. 대표 두 문제는 **LCS(최장 공통 부분수열)** 와 **Edit Distance(편집 거리)** 이며, 둘 다 "표의 왼쪽·위·대각선 칸만 보고 현재 칸을 채운다"는 동일한 뼈대를 공유한다.
- **LCS**: `dp[i][j]` = A의 앞 i글자와 B의 앞 j글자의 최장 공통 부분수열 길이. 마지막 글자가 같으면(`A[i-1]==B[j-1]`) 대각선에서 +1로 이어 붙인다: `dp[i-1][j-1]+1`. 다르면 A의 끝을 버리거나(`dp[i-1][j]`) B의 끝을 버린 것(`dp[i][j-1]`) 중 큰 쪽. 부분수열이라 순서만 지키면 되고 연속일 필요는 없다는 점이 포인트.
- **Edit Distance(레벤슈타인)**: `dp[i][j]` = A의 앞 i글자를 B의 앞 j글자로 바꾸는 최소 연산 수(삽입/삭제/교체 각 1). 같으면 그대로 대각선 `dp[i-1][j-1]`. 다르면 세 연산 중 최소 +1: 삭제 `dp[i-1][j]`, 삽입 `dp[i][j-1]`, 교체 `dp[i-1][j-1]`. 경계(빈 문자열로/에서의 변환)를 `dp[i][0]=i`, `dp[0][j]=j`로 초기화하는 게 핵심.
- 표를 채우는 방향은 왼쪽 위 → 오른쪽 아래. 각 칸은 항상 자기보다 먼저 계산된 세 칸(위·왼쪽·대각선)만 참조하므로 반복문 두 겹으로 안전하게 채울 수 있다.

```python
# LCS: dp[i][j] = A[:i], B[:j]의 최장 공통 부분수열 길이
n, m = len(A), len(B)
dp = [[0]*(m+1) for _ in range(n+1)]
for i in range(1, n+1):
    for j in range(1, m+1):
        if A[i-1] == B[j-1]:
            dp[i][j] = dp[i-1][j-1] + 1          # 대각선 + 1
        else:
            dp[i][j] = max(dp[i-1][j], dp[i][j-1])  # 위 vs 왼쪽
# 답: dp[n][m]

# Edit Distance: 경계 초기화가 필수
for i in range(n+1): dp[i][0] = i    # A[:i]를 빈 문자열로 → i번 삭제
for j in range(m+1): dp[0][j] = j    # 빈 문자열을 B[:j]로 → j번 삽입
# 채우기: 같으면 대각선, 다르면 1 + min(위, 왼쪽, 대각선)
```

**접근 전략**

- "두 문자열/수열을 비교", "공통", "몇 번 고쳐야", "정렬" 같은 단어가 보이면 2차원 `dp[i][j]`를 떠올린다. 먼저 `dp[i][j]`의 의미를 한국어로 못 박고, "A[i-1]와 B[j-1]가 같을 때 / 다를 때"로 사례를 나눠 각각 어느 칸에서 오는지 그림으로 그린다. LCS·편집거리·최소삽입(문자열을 팰린드롬으로 만들기 = 원문과 뒤집은 문자열의 LCS)·두 수열 정렬 비용 등은 전부 이 프레임의 변주다. 실제 부분수열/연산 순서까지 복원하려면 표를 다 채운 뒤 `dp[n][m]`에서 역추적(어느 칸에서 왔는지 따라 되돌아가기)한다.
- 복잡도: 시간 `O(n·m)`, 공간 `O(n·m)`. 전이가 직전 행(`dp[i-1]`)과 같은 행 왼쪽만 쓰므로 두 행만 유지해 공간 `O(m)`으로 줄일 수 있다(단 역추적하려면 전체 표 필요). 흔한 실수: (1) 인덱스 오프셋 — `dp`는 1-based인데 문자열은 0-based라 `A[i-1]`처럼 −1을 꼭 붙인다. (2) 편집거리에서 경계 초기화 누락 → 빈 문자열 변환 비용이 0으로 잘못 깔림. (3) LCS를 "연속 부분문자열"과 혼동(그건 다른 점화식). 파이썬 팁: 재귀+메모이제이션도 되지만 문자열이 길면 `sys.setrecursionlimit`과 스택 부담 때문에 반복(표 채우기)이 안전하다. 리스트 컴프리헨션으로 표를 만들 때 `[[0]*(m+1) for _ in range(n+1)]`처럼 각 행을 새로 만들 것(`[[0]*(m+1)]*(n+1)`은 같은 행 참조 버그).

**문제**

**1) 최장 공통 부분수열(LCS)** · Medium

- **요구사항**: 두 문자열이 주어질 때, 순서를 유지하며 양쪽에 공통으로 나타나는 부분수열의 최대 길이를 구하라(연속일 필요 없음).
- **입력**: 첫째 줄 문자열 A, 둘째 줄 문자열 B(각 길이 1≤len≤2000, 알파벳 대문자).
- **출력**: LCS의 길이.
- **예제**: `ACAYKP / CAPCAK` → `4` (ACAK) / `ABCBDAB / BDCAB` → `4` (BCAB 또는 BDAB)
- **셀프체크**: "부분문자열(연속)"이 아니라 "부분수열(순서만)"임을 점화식이 반영하는가? `dp` 크기가 `(n+1)×(m+1)`인가? 인덱스 −1 오프셋을 빠뜨리지 않았는가? 길이 2000×2000이면 4백만 칸 — 파이썬에서 아슬하니 표 채우기를 단순 루프로.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split('\n')
    A = data[0].strip()
    B = data[1].strip()
    n, m = len(A), len(B)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        ai = A[i - 1]
        row = dp[i]
        prev = dp[i - 1]
        for j in range(1, m + 1):
            if ai == B[j - 1]:
                row[j] = prev[j - 1] + 1              # 대각선 + 1
            else:
                row[j] = prev[j] if prev[j] >= row[j - 1] else row[j - 1]  # 위 vs 왼쪽
    print(dp[n][m])
main()

@@EXPL
(1) 접근·핵심 아이디어

- `dp[i][j]` = A의 앞 i글자와 B의 앞 j글자의 최장 공통 부분수열 길이. 부분수열이므로 순서만 지키면 되고 연속일 필요는 없다.
- 표의 세 칸(위·왼쪽·대각선)만 보고 채우는 전형적 2차원 DP.

(2) 코드 단계별

- `dp` 크기는 `(n+1)×(m+1)`, 경계는 모두 0(빈 문자열과의 LCS는 0).
- 마지막 글자가 같으면(`A[i-1]==B[j-1]`) 대각선에 +1: `dp[i-1][j-1]+1`.
- 다르면 A의 끝을 버리거나(`dp[i-1][j]`) B의 끝을 버린(`dp[i][j-1]`) 것 중 큰 쪽.
- `dp`는 1-based, 문자열은 0-based라 `A[i-1]`, `B[j-1]`로 −1 오프셋을 꼭 붙인다.
- 답은 `dp[n][m]`. 공통 글자가 전혀 없으면 0(`ABC` vs `DEF`).

(3) 스스로 다시 짤 때 생각 순서

- "두 문자열 공통 + 순서만" → 2차원 `dp[i][j]` LCS.
- "같을 때 / 다를 때"를 나눠 어느 칸에서 오는지 그린다.
- 인덱스 −1 오프셋과 `dp[n][m]` 답 위치를 확인한다.
```

**2) 편집 거리** · Medium

- **요구사항**: 문자열 A를 B로 바꾸는 데 필요한 최소 연산 수를 구하라. 연산은 한 글자 삽입, 삭제, 교체(각 1회 비용).
- **입력**: 첫째 줄 A, 둘째 줄 B(각 길이 1≤len≤1000).
- **출력**: 최소 편집 거리.
- **예제**: `sunday / saturday` → `3` (sunday→saturday: 삽입 a, 삽입 t, 교체 n→r 등 3연산) / `kitten / sitting` → `3` (k→s, e→i, +g)
- **셀프체크**: 경계 `dp[i][0]=i`, `dp[0][j]=j`를 채웠는가? 같을 때 대각선 그대로, 다를 때 `1+min(세 방향)`을 정확히 구분했는가? A==B면 0이 나오는가(예: `abc/abc`→0)? 삽입/삭제 방향이 헷갈리면 표의 위·왼쪽 의미를 다시 확인.

```runner
@@SOLUTION
import sys
def main():
    data = sys.stdin.read().split('\n')
    A = data[0].strip()
    B = data[1].strip()
    n, m = len(A), len(B)
    prev = list(range(m + 1))            # dp[0][j] = j (빈 A를 B[:j]로 -> j번 삽입)
    for i in range(1, n + 1):
        cur = [i] + [0] * m              # dp[i][0] = i (A[:i]를 빈 문자열로 -> i번 삭제)
        ai = A[i - 1]
        for j in range(1, m + 1):
            if ai == B[j - 1]:
                cur[j] = prev[j - 1]     # 같으면 대각선 그대로
            else:
                cur[j] = 1 + min(prev[j], cur[j - 1], prev[j - 1])  # 삭제/삽입/교체
        prev = cur
    print(prev[m])
main()

(1) 접근·핵심 아이디어

- `dp[i][j]` = A의 앞 i글자를 B의 앞 j글자로 바꾸는 최소 연산 수(삽입/삭제/교체 각 1). 경계 초기화가 핵심: `dp[i][0]=i`(전부 삭제), `dp[0][j]=j`(전부 삽입).
- 두 행만 유지(`prev`, `cur`)해 공간을 O(m)으로 줄였다.

(2) 코드 단계별

- `prev`를 `0..m`으로 초기화(빈 A → B[:j]는 j번 삽입).
- 각 행 시작에서 `cur[0] = i`(A[:i] → 빈 문자열은 i번 삭제).
- 글자가 같으면 연산 없이 대각선 `prev[j-1]`.
- 다르면 `1 + min(삭제 prev[j], 삽입 cur[j-1], 교체 prev[j-1])`.
- 행을 넘길 때 `prev = cur`. 답은 `prev[m]`. A==B면 대각선만 타서 0.

(3) 스스로 다시 짤 때 생각 순서

- "몇 번 고쳐야" → 편집거리 2차원 DP.
- 경계(빈 문자열 변환 비용)를 먼저 채운다 — 빠뜨리면 0으로 잘못 깔린다.
- 같을 때 대각선, 다를 때 세 방향 min+1을 구분하고 삭제/삽입/교체가 각각 어느 칸인지 확인.
```

**3) 팰린드롬으로 만드는 최소 삽입** · Hard

- **요구사항**: 문자열에 글자를 삽입해 팰린드롬(뒤집어도 같은 문자열)으로 만들 때 필요한 최소 삽입 횟수를 구하라. 핵심 관찰: 답 = `문자열 길이 − (문자열과 그 역순 문자열의 LCS 길이)`. LCS로 이미 남길 수 있는 대칭 골격을 구하고 나머지를 채우는 셈.
- **입력**: 한 줄에 문자열 S(1≤len≤2000, 소문자).
- **출력**: 최소 삽입 횟수.
- **예제**: `aab` → `1` (baab 또는 aaba: LCS(aab, baa)=2, 3−2=1) / `abcba` → `0` (이미 팰린드롬: LCS(abcba, abcba)=5, 5−5=0)
- **셀프체크**: `S`와 `S[::-1]`의 LCS를 구했는가? 답 공식 `len(S) − LCS`가 맞는지 작은 예로 검산(`ab`→ LCS(ab,ba)=1 → 2−1=1). 왜 이 공식이 성립하는지(LCS가 회문 대칭축 골격이 됨) 스스로 설명할 수 있는가? 길이 2000이면 LCS 표 4백만 칸 — 시간·메모리 확인.

```runner
@@SOLUTION
import sys
def main():
    s = sys.stdin.readline().strip()
    r = s[::-1]
    n = len(s)
    # LCS(s, reversed s) = 가장 긴 회문 부분수열의 길이
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        si = s[i - 1]
        row = dp[i]
        prev = dp[i - 1]
        for j in range(1, n + 1):
            if si == r[j - 1]:
                row[j] = prev[j - 1] + 1
            else:
                row[j] = prev[j] if prev[j] >= row[j - 1] else row[j - 1]
    print(n - dp[n][n])       # 남길 골격(LCS) 밖의 글자 수만큼 삽입
main()

@@EXPL
(1) 접근·핵심 아이디어

- 핵심 관찰: 답 = `len(S) − LCS(S, reverse(S))`. `LCS(S, S[::-1])`는 곧 S의 "가장 긴 회문 부분수열" 길이이고, 그 대칭 골격은 이미 팰린드롬이라 그대로 남긴다. 나머지 글자를 반대편에 하나씩 삽입해 대칭을 채우면 되므로 삽입 횟수 = 골격 밖 글자 수.
- 그래서 문제는 LCS 한 번으로 환원된다.

(2) 코드 단계별

- `r = s[::-1]`로 역순 문자열을 만든다.
- `dp[i][j]` = `s[:i]`와 `r[:j]`의 LCS 길이. 같으면 대각선 +1, 다르면 위·왼쪽 중 큰 쪽.
- `dp[n][n]`이 가장 긴 회문 부분수열 길이.
- 답은 `n - dp[n][n]`. `aab`는 LCS(aab, baa)=2라 3−2=1, `abcba`는 이미 회문이라 5−5=0.

(3) 스스로 다시 짤 때 생각 순서

- "팰린드롬 만들기 최소 삽입"을 보면 "원문 vs 역순의 LCS"로 환원할 수 있는지 떠올린다.
- LCS 표를 그대로 채우되 두 번째 문자열을 `S[::-1]`로 둔다.
- 공식 `len − LCS`를 작은 예(`ab`→1)로 검산하고, 왜 LCS가 회문 골격인지 스스로 설명해 본다.
```

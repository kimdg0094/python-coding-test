## L3. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch10(Ad-Hoc)의 핵심 — "최선 전략이 확실히 정해지는 경우"와 "고려해야 할 대상이 뚜렷이 정해지는 경우" — 를 소재만 바꿔 **반복 훈련**하고, 코딩테스트 단골 그리디·관찰 문제로 **확장**하는 연습 세트다.
- **반복 훈련 개념**:
  - 정렬 후 작은(큰) 것부터 훑기: `xs.sort()` → `for x in xs:` 순서대로 담고, 안 되면 `break`.
  - 교환 논증: "다른 선택을 이 선택으로 바꿔도 손해가 없다"를 작은 예로 확인한 뒤 그리디를 믿는다.
  - 후보 좁히기: 정렬하면 답은 양 끝·인접·상위 k개 중 하나 — `xs[0]`, `xs[-1]`, `xs[k-1]`만 본다.
  - 불변식으로 규칙 찾기: "지금까지 1..target-1 을 전부 만들 수 있다"처럼 상태 하나를 유지하며 갱신한다.
  - 정렬 기준 고르기: 종료 시각·(값, 번호) 튜플처럼 `sort()` 기준을 잘못 잡으면 그리디가 틀린다.
- **코딩테스트 출제 맵**: 프로그래머스 「코딩테스트 고득점 Kit」의 '탐욕법', 『이것이 취업을 위한 코딩테스트다』의 '그리디' 파트, NeetCode 150의 'Greedy'·'Intervals' 유형이 이 챕터의 사고를 그대로 쓴다.
- **문제 구성표**:

**문제**

**1) 예산 안에서 최대 개수 사기** · Easy

- **요구사항**: 가게에 물건 `n`개가 있고 각 가격이 주어진다. 예산 `B`로 서로 다른 물건을 최대한 많이 살 때, 살 수 있는 물건의 최대 개수를 구한다.
- **입력**: 첫 줄에 `n`과 예산 `B`가 공백으로 주어진다. 둘째 줄에 `n`개의 가격이 공백으로 주어진다. (`1 ≤ n ≤ 100`, `1 ≤ 가격, B ≤ 1,000,000`)
- **출력**: 살 수 있는 최대 개수.
- **예제**: `5 20 / 7 3 9 4 12` → `3` · `3 2 / 5 6 7` → `0`
- **셀프체크**: "개수를 최대로"이므로 싼 것부터 담는 것이 최선인 이유(비싼 것을 싼 것으로 바꾸면 남는 돈이 늘기만 한다)를 설명할 수 있는가? 가장 싼 물건조차 못 살 때 `0`이 나오는가? 예산이 딱 맞아 떨어질 때(`<=`) 담기는가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n, B = int(data[0]), int(data[1])
prices = list(map(int, data[2:2 + n]))
prices.sort()
count = 0
for p in prices:
    if p <= B:
        B -= p
        count += 1
    else:
        break
print(count)
@@TESTS
--IN
5 20
7 3 9 4 12
--OUT
3
--IN
3 2
5 6 7
--OUT
0
--IN
4 10
3 3 3 3
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 개수를 최대로 하려면 "싼 것부터" 담는 게 확실한 최선이다. 교환 논증: 어떤 답에 비싼 물건이 들어 있고 더 싼 물건이 빠져 있다면, 둘을 바꿔도 개수는 같고 남는 예산은 늘어난다. 따라서 싼 것부터 담는 선택이 손해 볼 일이 없다.
- 정렬 후 앞에서부터 예산이 허락하는 동안 담고, 처음으로 못 담는 순간 뒤는 더 비싸므로 곧바로 멈춘다.

(2) 코드 단계별

- `n`, `B`, 가격 목록을 읽고 오름차순 정렬한다.
- 각 가격 `p`에 대해 `p <= B`이면 예산에서 빼고 `count`를 1 늘린다. 같을 때도 살 수 있으니 `<=`가 맞다.
- 못 사는 순간 `break` — 정렬돼 있으므로 뒤는 전부 못 산다.
- `count` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "최대 개수 = 싼 것부터"를 먼저 확정하고 정렬 방향(오름차순)을 정한다.
- 남은 예산 `B`를 상태로 들고 훑는다.
- 경계: 하나도 못 살 때 `0`, 예산이 정확히 떨어질 때 `<=`로 포함되는지 확인한다.
```

**2) 두 수 곱의 최댓값** · Easy

- **요구사항**: `n`개의 정수(음수 가능)가 주어진다. 서로 다른 두 원소를 골라 곱했을 때 나올 수 있는 최댓값을 구한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 정수 `n`개가 공백으로 주어진다. (`2 ≤ n ≤ 100`, `-1000 ≤ 값 ≤ 1000`)
- **출력**: 두 수 곱의 최댓값.
- **예제**: `5 / -8 -3 2 5 4` → `24` · `3 / -2 0 3` → `0`
- **셀프체크**: 모든 쌍(`O(n^2)`)을 보지 않아도 되는 이유를 말할 수 있는가? 정렬하면 후보는 "가장 큰 두 수의 곱"과 "가장 작은 두 수의 곱" 딱 둘뿐이다. 음수 두 개의 곱이 양수보다 커지는 경우(첫 예제)를 놓치지 않았는가? `n=2`면 두 후보가 같은 쌍이라 그냥 그 곱이 답이다.

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
xs = list(map(int, data[1:1 + n]))
xs.sort()
print(max(xs[-1] * xs[-2], xs[0] * xs[1]))
@@TESTS
--IN
5
-8 -3 2 5 4
--OUT
24
--IN
3
-2 0 3
--OUT
0
--IN
2
-5 -6
--OUT
30
@@EXPL
(1) 접근·핵심 아이디어

- 곱을 크게 만드는 방법은 두 가지뿐이다: 큰 양수 둘을 곱하거나, 절댓값이 큰 음수 둘을 곱하거나. 정렬하면 전자는 `xs[-1]*xs[-2]`, 후자는 `xs[0]*xs[1]`이다.
- 그 외의 쌍(양수와 음수, 중간값끼리)은 이 두 후보보다 클 수 없다. 그래서 "고려할 대상"이 두 개로 좁혀진다.

(2) 코드 단계별

- `n`과 정수 목록을 읽고 오름차순 정렬.
- 맨 뒤 두 수의 곱과 맨 앞 두 수의 곱 중 큰 값을 출력.
- `n=2`면 두 후보가 같은 쌍이므로 자연히 그 곱이 답이다.

(3) 스스로 다시 짤 때 생각 순서

- "음수×음수는 양수"를 떠올려 후보가 둘임을 먼저 확인한다.
- 정렬 → 양 끝 두 쌍의 곱 → `max` 세 단계로 압축한다.
- 0이 섞인 경우(둘째 예제)에도 두 후보 비교만으로 답이 나오는지 검산한다.
```

**3) 하나 빼서 범위 줄이기** · Easy

- **요구사항**: `n`개의 정수 중 정확히 하나를 제거해, 남은 수들의 "최댓값 − 최솟값"이 가장 작아지도록 할 때 그 값을 구한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 정수 `n`개가 공백으로 주어진다. (`2 ≤ n ≤ 100`)
- **출력**: 남은 수들의 (최댓값 − 최솟값)의 최솟값.
- **예제**: `5 / 1 8 9 10 12` → `4` · `2 / 4 4` → `0`
- **셀프체크**: 중간값을 제거해 봐야 범위는 그대로이므로, 후보는 "최댓값 제거" 또는 "최솟값 제거" 둘뿐임을 납득했는가? 정렬 후 `xs[-2]-xs[0]`과 `xs[-1]-xs[1]`만 비교하면 된다. `n=2`면 하나만 남아 범위 `0`이 나오는가? 모두 같은 값이면 `0`인가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
xs = list(map(int, data[1:1 + n]))
xs.sort()
print(min(xs[-2] - xs[0], xs[-1] - xs[1]))
@@TESTS
--IN
5
1 8 9 10 12
--OUT
4
--IN
2
4 4
--OUT
0
--IN
3
5 5 5
--OUT
0
--IN
4
1 2 3 100
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- 범위(최대−최소)는 양 끝 값으로만 결정된다. 중간에 있는 값을 빼도 양 끝이 그대로라 범위는 변하지 않으므로, 제거해서 효과가 있는 후보는 "현재 최댓값" 아니면 "현재 최솟값"뿐이다.
- 정렬하면 최댓값을 뺀 범위는 `xs[-2]-xs[0]`, 최솟값을 뺀 범위는 `xs[-1]-xs[1]`이다. 둘 중 작은 쪽이 답.

(2) 코드 단계별

- `n`과 정수 목록을 읽고 오름차순 정렬.
- 두 후보 범위를 계산해 `min`으로 출력.
- `n=2`면 `xs[-2]`와 `xs[0]`이 같은 원소라 첫 후보가 `0`이 되어 답 `0`이 자연히 나온다.

(3) 스스로 다시 짤 때 생각 순서

- "범위는 양 끝만 본다"는 관찰을 먼저 세운다 → 후보 2개.
- 정렬 후 인덱스 `0, 1, -2, -1` 네 값만 쓴다.
- 중복 값·`n=2` 경계에서 음수가 나오지 않는지(정렬돼 있으므로 항상 0 이상) 확인한다.
```

**4) 부호 뒤집기 k번 후 최대 합** · Medium

- **요구사항**: `n`개의 정수가 있다. "원소 하나를 골라 부호를 뒤집는" 연산을 **정확히** `k`번 해야 한다(같은 원소를 여러 번 골라도 된다). 연산을 모두 마친 뒤 얻을 수 있는 원소 합의 최댓값을 구한다.
- **입력**: 첫 줄에 `n`과 `k`. 둘째 줄에 정수 `n`개가 공백으로 주어진다. (`1 ≤ n ≤ 100`, `1 ≤ k ≤ 1000`, `-100 ≤ 값 ≤ 100`)
- **출력**: 합의 최댓값.
- **예제**: `5 3 / -4 -2 3 -1 5` → `15` · `3 2 / 2 5 1` → `8`
- **셀프체크**: 음수 중 "가장 작은(절댓값이 큰) 것부터" 뒤집는 것이 최선인 이유를 설명할 수 있는가? 음수를 다 뒤집고도 횟수가 남으면, 남은 횟수가 짝수면 한 원소를 두 번 뒤집어 상쇄하고 홀수면 절댓값이 가장 작은 원소를 한 번 뒤집는다는 경계를 처리했는가? 0이 있으면 홀수 남아도 손해가 없음을 확인했는가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n, k = int(data[0]), int(data[1])
xs = list(map(int, data[2:2 + n]))
xs.sort()
i = 0
while i < n and k > 0 and xs[i] < 0:   # 가장 작은 음수부터 뒤집기
    xs[i] = -xs[i]
    k -= 1
    i += 1
total = sum(xs)
if k % 2 == 1:                          # 홀수 번 남으면 절댓값 최소를 한 번 뒤집음
    total -= 2 * min(xs)
print(total)
@@TESTS
--IN
5 3
-4 -2 3 -1 5
--OUT
15
--IN
3 2
2 5 1
--OUT
8
--IN
3 1
2 5 1
--OUT
6
--IN
3 1
0 4 6
--OUT
10
@@EXPL
(1) 접근·핵심 아이디어

- 음수를 양수로 바꾸면 합이 `2|x|`만큼 늘어나므로, 절댓값이 큰 음수(정렬하면 앞쪽)부터 뒤집는 것이 매 단계 가장 큰 이득이다. 이득이 큰 순서로 쓰는 것이 확실한 최선.
- 음수가 다 떨어졌는데 횟수가 남으면 "정확히 k번"이 함정이다. 짝수 번 남았으면 같은 원소를 두 번 뒤집어 상쇄(손해 0), 홀수 번 남았으면 한 번은 어쩔 수 없이 뒤집어야 하므로 절댓값이 가장 작은 원소를 골라 손해를 최소화한다(0이 있으면 손해 0).

(2) 코드 단계별

- 오름차순 정렬 후, 앞에서부터 음수이고 `k>0`인 동안 부호를 뒤집으며 `k`를 줄인다.
- 합을 구한 뒤, `k`가 홀수면 현재 배열(모두 0 이상)에서 최솟값을 한 번 뒤집은 효과로 `2*min(xs)`를 뺀다.
- 셋째 테스트는 음수가 없고 `k=1`이라 가장 작은 `1`을 뒤집어 `6`, 넷째는 `0`을 뒤집어 손해 없이 `10`.

(3) 스스로 다시 짤 때 생각 순서

- "이득이 큰 것부터"로 정렬 방향(오름차순, 음수 먼저)을 정한다.
- 루프 종료 조건 세 가지(`i<n`, `k>0`, `xs[i]<0`)를 빠짐없이 건다.
- 남은 `k`의 홀짝 처리를 반드시 넣고, 뒤집은 뒤 배열은 전부 0 이상이라 `min`이 곧 절댓값 최소임을 이용한다.
```

**5) 상자와 일꾼 최대 짝짓기** · Medium

- **요구사항**: 상자 `n`개의 무게와 일꾼 `m`명의 힘이 주어진다. 일꾼 한 명은 자기 힘 이상이 아닌, 즉 "무게 ≤ 힘"인 상자를 **최대 한 개** 나를 수 있고, 상자 하나는 한 명만 나른다. 나를 수 있는 상자의 최대 개수를 구한다.
- **입력**: 첫 줄에 `n`과 `m`. 둘째 줄에 상자 무게 `n`개, 셋째 줄에 일꾼 힘 `m`개가 공백으로 주어진다. (`1 ≤ n, m ≤ 100`, 값은 `1 이상 1000 이하`)
- **출력**: 최대 상자 개수.
- **예제**: `4 3 / 5 2 8 3 / 4 9 2` → `3` · `2 2 / 10 12 / 5 6` → `0`
- **셀프체크**: 둘 다 정렬한 뒤 "가장 약한 일꾼에게 가장 가벼운 상자"를 시도하는 게 최선인 이유(약한 일꾼이 무거운 것을 들 수 있다면 더 센 일꾼도 들 수 있으니, 가벼운 것을 약한 쪽에 주는 게 손해 없음)를 납득했는가? 약한 일꾼이 가장 가벼운 상자도 못 들면 그 일꾼은 그냥 건너뛴다. 상자 포인터가 끝을 넘지 않도록 `i < n` 검사를 했는가?

```runner
- 교환 논증: 최적해에서 약한 일꾼이 무거운 상자를 들고 센 일꾼이 가벼운 상자를 든다면, 둘을 바꿔도 여전히 가능하다. 그러니 "가벼운 상자는 약한 일꾼에게"로 바꿔도 손해가 없다.

(2) 코드 단계별

- 상자 포인터 `i`를 0으로 두고 일꾼을 순서대로 보며 `boxes[i] <= w`이면 짝짓고 `i`를 전진.

- 못 드는 일꾼을 건너뛰어도 되는 이유(그보다 가벼운 상자가 없다)를 확인한다.
- 경계: 아무도 못 드는 경우 `0`, 상자가 먼저 떨어지는 경우 인덱스 초과 방지.
```

**6) 팀 최대 전투력** · Medium

- **요구사항**: `n`명의 체력이 주어진다. 몇 명이든 골라 팀을 만들면 팀 전투력은 "(팀원 중 최소 체력) × (팀원 수)"다. 만들 수 있는 팀 전투력의 최댓값을 구한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 체력 `n`개가 공백으로 주어진다. (`1 ≤ n ≤ 100`, `1 ≤ 체력 ≤ 10,000`)
- **출력**: 전투력의 최댓값.
- **예제**: `5 / 10 20 30 25 15` → `60` · `3 / 100 1 1` → `100`
- **셀프체크**: 팀원 수를 `k`명으로 정했다면 "체력 상위 `k`명"을 뽑는 것이 최소 체력을 가장 크게 만들므로, 후보는 내림차순 정렬 후 상위 `k`명(`k=1..n`) 딱 `n`가지뿐임을 납득했는가? 부분집합 `2^n`개를 다 볼 필요가 없다. 한 명짜리 팀(`k=1`)도 후보에 넣었는가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
hp = list(map(int, data[1:1 + n]))
hp.sort(reverse=True)
best = 0
for k in range(1, n + 1):           # 상위 k명 팀: 최소 체력 = hp[k-1]
    best = max(best, hp[k - 1] * k)
print(best)

(1) 접근·핵심 아이디어

- 팀원 수 `k`를 고정하면, 최소 체력을 최대로 하는 선택은 "체력이 큰 순서로 `k`명"이다. 약한 사람을 넣을수록 최소값만 내려가기 때문.
- 따라서 내림차순 정렬 뒤 `k=1..n`에 대해 `hp[k-1] * k`만 계산하면 된다. 후보가 `2^n`개에서 `n`개로 줄어든다.

(2) 코드 단계별

- 체력 목록을 읽고 내림차순 정렬.
- `k`를 1부터 `n`까지 늘리며 상위 `k`명의 최소 체력 `hp[k-1]`에 `k`를 곱해 최댓값을 갱신.
- 첫 예제: `30 25 20 15 10` → `30, 50, 60, 60, 50` 중 `60`.

(3) 스스로 다시 짤 때 생각 순서

- "인원을 고정하면 누구를 뽑을지는 자명하다"는 관찰로 후보를 `n`개로 줄인다.
- 정렬 방향(내림차순)과 인덱스(`k-1`)를 정확히 맞춘다.
- `n=1`, 모두 같은 값 같은 경계에서 공식이 그대로 통하는지 확인한다.
```

**7) 세차장 대기 시간 최소화** · Medium

- **요구사항**: 세차 기계가 한 대뿐인 세차장에 차량 `n`대가 왔다. 각 차량의 세차 소요 시간이 주어진다. 어떤 차량의 "대기 시간"은 앞 차량들의 소요 시간 합에 자기 소요 시간을 더한 값이다. 모든 차량의 대기 시간 합이 최소가 되도록 순서를 정해, 그 최소 합과 순서(차량 번호)를 출력한다. 소요 시간이 같으면 번호가 작은 차량을 먼저 세차한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 소요 시간 `n`개가 공백으로 주어진다. 차량 번호는 입력 순서대로 `1..n`. (`1 ≤ n ≤ 100`, `1 ≤ 소요 시간 ≤ 1000`)
- **출력**: 첫 줄에 대기 시간 합의 최솟값, 둘째 줄에 세차 순서(차량 번호, 공백 구분).
- **예제**: `4 / 5 2 8 2` → `32` / `2 4 1 3` · `1 / 7` → `7` / `1`
- **셀프체크**: 앞에 배치된 차량의 소요 시간은 뒤의 모든 차량 대기에 더해지므로 "짧은 것부터"가 최선인 이유를 교환 논증으로 말할 수 있는가? 동률일 때 번호 작은 차량이 먼저 오도록 `(시간, 번호)` 튜플로 정렬했는가? 누적 시간 `elapsed`와 총합 `total` 두 변수를 구분했는가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
times = list(map(int, data[1:1 + n]))
cars = [(times[i], i + 1) for i in range(n)]
cars.sort()                      # (소요 시간, 번호) 오름차순
total = 0
elapsed = 0
order = []
for t, idx in cars:
    elapsed += t                 # 이 차량의 대기 시간
    total += elapsed
    order.append(str(idx))
print(total)
print(" ".join(order))
@@TESTS

--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- `i`번째로 세차하는 차량의 소요 시간은 뒤의 `n-i`대 대기에 모두 더해진다. 즉 앞에 놓일수록 여러 번 더해지므로, 짧은 것을 앞에 두는 것이 확실한 최선이다.
- 교환 논증: 인접한 두 차량 중 긴 것이 앞에 있다면 둘을 바꿨을 때 다른 차량의 대기는 그대로이고 이 둘의 합만 줄어든다.
- 동률 규칙(번호 작은 것 먼저)은 `(시간, 번호)` 튜플 정렬로 자연히 처리된다.

(2) 코드 단계별

- 소요 시간에 번호를 붙여 `(t, idx)` 튜플 리스트를 만들고 정렬.
- 순서대로 보며 `elapsed`에 소요 시간을 누적(이 차량의 대기 시간)하고, 그 값을 `total`에 더한다.
- 첫 예제: 정렬 `(2,2) (2,4) (5,1) (8,3)` → 대기 `2, 4, 9, 17` 합 `32`.

(3) 스스로 다시 짤 때 생각 순서

- "앞에 있는 것이 여러 번 더해진다" → 짧은 것부터.
- 순서까지 출력해야 하므로 값에 번호를 묶어서 정렬한다(동률 규칙 포함).
- 누적 변수 두 개(`elapsed`, `total`)의 역할을 헷갈리지 않는다.
```

**8) 만들 수 없는 가장 작은 무게** · Hard

- **요구사항**: 추 `n`개의 무게가 주어진다. 추들 중 일부(각 추는 최대 한 번)를 골라 저울 한쪽에 올려 만들 수 있는 무게들을 생각할 때, 만들 수 없는 **가장 작은 양의 정수** 무게를 구한다.
- **입력**: 첫 줄에 `n`. 둘째 줄에 무게 `n`개가 공백으로 주어진다. (`1 ≤ n ≤ 100`, `1 ≤ 무게 ≤ 1000`)
- **출력**: 만들 수 없는 가장 작은 양의 정수.
- **예제**: `5 / 3 1 1 2 8` → `16` · `3 / 2 5 9` → `1`
- **셀프체크**: 부분집합 `2^n`개를 나열하지 않고 푸는 관찰이 핵심이다. 오름차순으로 보며 "지금까지 `1..target-1`을 전부 만들 수 있다"는 상태를 유지할 때, 다음 추 `w`가 `w <= target`이면 `1..target+w-1`까지 전부 만들 수 있게 되고, `w > target`이면 `target`은 영원히 못 만든다 — 왜 그런지 설명할 수 있는가? 무게 1이 없으면 답이 곧바로 `1`인가? 추를 다 써도 끊기지 않으면 마지막 `target`이 답인가?

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
ws = list(map(int, data[1:1 + n]))
ws.sort()
target = 1                 # 1..target-1 은 모두 만들 수 있음
for w in ws:
    if w > target:         # target 을 만들 방법이 없음
        break
    target += w            # 이제 1..target+w-1 까지 가능
print(target)
@@TESTS

--IN

--OUT

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 불변식 하나로 푼다: "지금까지 본 추들로 `1..target-1`을 모두 만들 수 있다." 처음엔 아무것도 없으니 `target=1`.
- 다음 추 `w`(오름차순)가 `w <= target`이면, 기존에 만들던 각 값에 `w`를 더해 `w..target+w-1`도 만들 수 있고 이는 `1..target-1`과 이어지므로 `1..target+w-1` 전부 가능 → `target += w`.
- 반대로 `w > target`이면 남은 추는 전부 `w` 이상이라 `target`은 절대 못 만든다 → 그 순간 `target`이 답. 추를 다 써도 끊기지 않으면 마지막 `target`이 답이다.

(2) 코드 단계별

- 무게를 읽고 오름차순 정렬(작은 것부터 봐야 불변식이 성립).
- `target=1`에서 시작해 각 `w`에 대해 `w > target`이면 중단, 아니면 `target += w`.
- 첫 예제: `1 1 2 3 8` → target `1→2→3→5→8→16`, 모두 통과해 `16`. 둘째 예제는 첫 추 `2 > 1`이라 즉시 `1`.

(3) 스스로 다시 짤 때 생각 순서

- "연속된 구간 `1..target-1`을 유지한다"는 상태 정의를 먼저 잡는다.
- 정렬하지 않으면 큰 추가 먼저 와서 잘못 끊기므로 정렬이 필수임을 확인한다.
- 경계: 무게 1이 없으면 `1`, 추 하나(`1`)만 있으면 `2`, `1 2 4 8`처럼 딱 이어지는 경우 `16`.
```

**9) 검문소 최소 설치** · Hard

- **요구사항**: 직선 도로 위에 순찰 구간 `n`개가 `[s, e]`(양 끝 포함, 정수 좌표)로 주어진다. 정수 지점 몇 곳에 검문소를 세워 **모든 구간이 최소 한 개의 검문소를 포함**하도록 할 때, 필요한 검문소의 최소 개수를 구한다.
- **입력**: 첫 줄에 `n`. 이어서 `n`개의 줄에 각 구간의 `s e`가 공백으로 주어진다. (`1 ≤ n ≤ 100`, `0 ≤ s ≤ e ≤ 1000`)
- **출력**: 검문소의 최소 개수.
- **예제**: `4 / 1 4 / 2 3 / 5 8 / 7 9` → `2` · `3 / 1 10 / 2 3 / 3 5` → `1`
- **셀프체크**: 구간을 "끝점 `e`" 기준으로 정렬하고, 아직 검문소가 없는 구간을 만나면 그 구간의 **끝점**에 세우는 것이 최선인 이유(끝점에 세워야 뒤에 오는 구간들과 최대한 많이 겹친다)를 납득했는가? 마지막에 세운 검문소 위치 `last`와 다음 구간의 시작 `s`를 `s > last`로 비교해 "포함 안 됨"을 판정했는가(같으면 포함)? 길이 0인 구간(`s == e`)도 처리되는가?

```runner
@@SOLUTION
import sys
input = sys.stdin.readline
n = int(input())
segs = []
for _ in range(n):
    s, e = map(int, input().split())
    segs.append((e, s))
segs.sort()                     # 끝점 오름차순
count = 0
last = -1                       # 마지막 검문소 위치 (좌표는 0 이상)
for e, s in segs:
    if s > last:                # 이 구간은 아직 검문소가 없음
        count += 1
        last = e                # 끝점에 세운다
print(count)
@@TESTS

(1) 접근·핵심 아이디어

- 끝점이 가장 이른 구간은 반드시 검문소가 하나 필요하고, 그 검문소를 어디에 두든 "그 구간의 끝점"에 두는 것이 이후 구간들과 가장 많이 겹친다(더 왼쪽에 두면 겹칠 수 있는 구간만 줄어든다). 교환 논증으로 이 선택은 손해가 없다.
- 그래서 끝점 오름차순으로 훑으며, 마지막 검문소 `last`가 현재 구간에 들어 있지 않으면(`s > last`) 현재 구간의 끝점에 새로 세운다.

(2) 코드 단계별

- 각 구간을 `(e, s)`로 저장해 정렬하면 끝점 기준이 된다.
- `last=-1`로 시작(좌표가 0 이상이므로 어떤 구간도 포함하지 않는 값). `s > last`면 `count`를 늘리고 `last = e`.
- 첫 예제: 정렬 `(3,2) (4,1) (8,5) (9,7)` → `3`에 설치(구간 `1 4`도 포함) → `8`에 설치(`7 9`도 포함) → `2`.

(3) 스스로 다시 짤 때 생각 순서

- "가장 빨리 끝나는 구간의 끝점"이 첫 검문소라는 관찰을 세운다.
- 정렬 기준이 시작점이 아니라 끝점임을 재확인한다(시작점 기준이면 반례가 생긴다).
- 포함 판정은 `s <= last <= e`인데 `last`는 항상 이전 구간 끝점 이하이므로 `s > last`만 보면 된다는 점, 그리고 `s == e`인 점 구간도 같은 식으로 처리됨을 확인한다.
```

**10) 한 번 교환으로 가장 큰 수** · Hard

- **요구사항**: 숫자 문자열 `S`가 주어진다(첫 자리는 0이 아님). 서로 다른 두 자리를 골라 **최대 한 번** 맞바꿔 만들 수 있는 가장 큰 수를 구한다. 바꾸지 않는 것이 최선이면 그대로 출력한다.
- **입력**: 한 줄에 숫자 문자열 `S`. (`1 ≤ len(S) ≤ 100`)
- **출력**: 만들 수 있는 가장 큰 수(문자열 그대로).
- **예제**: `2736` → `7236` · `1993` → `9913`
- **셀프체크**: 모든 쌍 교환을 다 만들어 비교해도 되지만, 관찰로 후보가 좁혀진다. 앞자리부터 보며 "이 자리보다 큰 자릿수가 뒤에 있는 첫 번째 자리"를 찾아, 뒤쪽의 **가장 큰 자릿수**와 바꾸면 끝이다. 같은 최대 자릿수가 여러 개면 왜 **가장 뒤의 것**과 바꿔야 하는지(`1993`에서 `9913`이 `9193`보다 큰 이유) 설명할 수 있는가? 이미 내림차순인 수(`9973`)와 한 자리 수는 그대로 나오는가?

```runner
@@SOLUTION
import sys
s = list(sys.stdin.readline().strip())
n = len(s)
for i in range(n):
    j = -1                                # i 뒤에서 가장 큰 자릿수의 '마지막' 위치
    for t in range(i + 1, n):
        if j == -1 or s[t] >= s[j]:
            j = t
    if j != -1 and s[j] > s[i]:           # 더 큰 자릿수가 뒤에 있으면 교환하고 종료
        s[i], s[j] = s[j], s[i]
        break
print("".join(s))

(1) 접근·핵심 아이디어

- 수의 크기는 앞자리가 지배한다. 그래서 가장 앞쪽에서 "뒤에 더 큰 자릿수가 있는 자리"를 찾아 그 자리를 키우는 교환 한 번이 최선이고, 그보다 앞자리는 이미 뒤의 어떤 것보다 크거나 같으므로 건드릴 이유가 없다.
- 교환 상대는 뒤쪽의 가장 큰 자릿수여야 하고, 같은 최댓값이 여러 개면 **가장 뒤의 것**이어야 한다. 앞쪽 큰 자릿수를 빼 오면 그 자리에 작은 수가 들어가 손해지만, 뒤쪽 것을 빼 오면 손해가 뒤로 밀려 더 작다(`1993` → `9913` vs `9193`).

(2) 코드 단계별

- 문자열을 리스트로 바꿔 자리별 교환이 가능하게 한다.
- 각 자리 `i`에 대해 `i+1..n-1`에서 최대 자릿수의 위치 `j`를 찾되, `>=` 비교로 갱신해 동률이면 뒤쪽이 남게 한다.
- `s[j] > s[i]`이면 교환하고 즉시 종료(한 번만). 끝까지 교환할 자리가 없으면 원래 수가 답.

(3) 스스로 다시 짤 때 생각 순서

- "가장 앞에서 키울 수 있는 자리"를 찾는다는 목표를 먼저 세운다.
- 상대는 "뒤쪽 최대 자릿수 중 가장 뒤"라는 규칙을 동률 예제로 검산한다.
- 경계: 이미 내림차순이면 교환 없음, 한 자리 수는 안쪽 루프가 돌지 않아 그대로 출력.
```

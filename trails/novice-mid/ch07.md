> 개요: N개의 물체를 "고른다/안 고른다"로 나누는 부분집합 완전탐색(2^N)과, 정답 후보 "값"을 직접 훑어 조건을 만족하는지 검사하는 값 기준 완전탐색을 배운다.

## L1. 물체 단위로 완전탐색

**개념**

- 지금까지의 완전탐색은 "자리마다 숫자를 정하기"처럼 각 칸에 값을 채웠다. 이번에는 관점을 바꿔, N개의 물체 각각에 대해 **"이 물체를 고를까 / 말까"** 두 가지 결정을 내린다. 이렇게 만들어지는 모든 선택의 조합이 곧 **부분집합(subset)** 이고, 그 개수는 정확히 2^N개다.
- 언제 쓰나: "몇 개를 골라서 …", "어떤 것들을 포함시켜야 …", "고르는 조합 중 최선은?"처럼 **선택의 대상이 개별 물체**이고, 각 물체가 서로 독립적으로 포함/제외될 수 있을 때.
- 핵심 도구는 `itertools`의 **`combinations`**다. `combinations(values, r)`는 "values에서 r개를 골라내는 모든 방법"을 하나씩 만들어 준다. 고르는 개수 r을 0부터 N까지 훑으면 크기별로 모든 부분집합을 빠짐없이 얻는다.

```python
# N개의 물체에 대한 모든 부분집합을 순회
from itertools import combinations

N = 4
values = [3, 7, 4, 9]

for r in range(N + 1):                        # 고르는 개수: 0개, 1개, ... , N개
    for chosen in combinations(values, r):    # 그 개수로 고르는 모든 방법
        total = sum(chosen)
        # 여기서 chosen(고른 물체들)과 total(합)을 평가
```

- `combinations`를 처음 본다면 이렇게 이해하면 된다. `combinations([3, 7, 4], 2)`는 3개 중 2개를 고르는 방법을 `(3, 7)`, `(3, 4)`, `(7, 4)` 순으로 내어 준다. **순서가 다른 것은 같은 것으로 본다** — `(7, 3)`은 따로 나오지 않는다. 부분집합은 "누가 뽑혔는가"만 중요하고 뽑힌 순서에는 뜻이 없으므로 이 성질이 정확히 들어맞는다.
- `range(N + 1)`에서 `+ 1`을 빠뜨리면 안 된다. r이 0부터 N까지여야 공집합(아무것도 안 고름)과 전체집합(전부 고름)이 모두 들어간다.
- 물체의 **값이 아니라 번호**가 필요하면(무게와 가치처럼 배열이 둘 이상일 때) `combinations(range(N), r)`로 인덱스를 고르면 된다.

**그림으로 보기**

- 부분집합을 **고른 개수별로** 묶어 보면 빠짐없이 셌는지 확인하기 쉽다. N=3이고 물체를 `v0, v1, v2`라 하면 이렇게 된다.

```text
   r = 0 :  { }                              # C(3,0) = 1
   r = 1 :  {v0}      {v1}      {v2}         # C(3,1) = 3
   r = 2 :  {v0,v1}   {v0,v2}   {v1,v2}      # C(3,2) = 3
   r = 3 :  {v0,v1,v2}                       # C(3,3) = 1
                                             # sum = 8 = 2^3
                                             # no duplicate, no missing
```

- 같은 것을 "고른다 / 안 고른다"의 갈림길(탐색 공간 트리)로 그리면 아래처럼 된다. 잎 하나가 부분집합 하나이고, 제약을 넘어선 가지는 그 아래를 볼 필요가 없다.

```text
   w = [4, 3, 2],  C = 5     # ( ) = weight so far, X = over C -> cut
   ( 0 )
    +-- take w0=4 -> ( 4 )
    |     +-- take w1=3 -> ( 7 ) X          # 7 > 5, subtree cut
    |     +-- skip  w1   -> ( 4 )
    |           +-- take w2=2 -> ( 6 ) X    # 6 > 5, cut
    |           +-- skip  w2   -> ( 4 )     # ok, total 4
    +-- skip  w0   -> ( 0 )
          +-- take w1=3 -> ( 3 )
          |     +-- take w2=2 -> ( 5 )      # ok, total 5  <- best
          |     +-- skip  w2   -> ( 3 )
          +-- skip  w1   -> ( 0 )
                +-- take w2=2 -> ( 2 )
                +-- skip  w2   -> ( 0 )
```

- `combinations`로 도는 코드는 이 트리의 **잎 8개를 하나도 빠뜨리지 않고 방문**하는 것과 같다. 방문 순서만 다르다 — 트리는 왼쪽 가지부터 내려가고, `combinations`는 고른 개수가 적은 것부터 내어 준다.

**손으로 따라가기**

무게 `w = [4, 3, 2]`, 한도 `C = 5`로 r을 0부터 3까지 돌려 본다. 각 r마다 `combinations(w, r)`이 내어 주는 조합을 나온 순서대로 본다.

| r | chosen | 합 | 합 ≤ 5? | best |
| --- | --- | --- | --- | --- |
| 0 | () | 0 | O | 0 |
| 1 | (4) | 4 | O | 4 |
| 1 | (3) | 3 | O | 4 |
| 1 | (2) | 2 | O | 4 |
| 2 | (4, 3) | 7 | X | 4 |
| 2 | (4, 2) | 6 | X | 4 |
| 2 | (3, 2) | 5 | O | 5 |
| 3 | (4, 3, 2) | 9 | X | 5 |

- 최종 답은 `r = 2`의 `(3, 2)`에서 나온 **5**다. 8가지를 하나도 빠뜨리지 않고 한 번씩만 봤다.

**왜 이렇게 되는가**

- **왜 부분집합이 2^N개인가**: 물체 0을 넣을지 뺄지 2가지, 물체 1도 2가지, … 각 결정이 서로 독립이므로 곱의 법칙으로 `2 × 2 × … × 2`(N번) = 2^N. 위 트리로 보면 깊이가 N이고 매 단계마다 가지가 2배로 늘어 잎이 2^N개다.
- **왜 크기별로 나눠 세면 빠짐없는가**: 모든 부분집합은 원소 개수가 0 ~ N 중 **정확히 하나**로 정해진다. 따라서 서로 다른 r끼리는 겹칠 수 없고(중복 없음), r을 0부터 N까지 전부 돌면 빠지는 것도 없다(누락 없음). 개수를 더하면 C(N,0) + C(N,1) + … + C(N,N) = 2^N으로 위 트리의 잎 개수와 정확히 일치한다.
- **왜 `combinations`는 같은 묶음을 두 번 내지 않는가**: 원본 리스트에서 **위치가 앞선 것부터 순서를 지켜** 뽑기 때문이다. `(3, 7)`을 낸 뒤 `(7, 3)`을 따로 내지 않는 이유가 이것이다. 값이 같은 원소가 여러 개 있어도(예: `[5, 5, 5]`) 위치가 다르면 다른 조합으로 세므로, 부분집합 개수는 언제나 2^N을 유지한다.
- **복잡도가 왜 O(2^N · N)인가**: 조합이 모두 합쳐 2^N개이고, 각 조합마다 합을 구하는 데 최대 N번 더한다. N=20이면 약 10^6 × 20 = 2×10^7로 가능하지만, N=25면 3.4×10^7 × 25 ≈ 8×10^8이라 불가능하다. 그래서 실전 기준선이 **N ≤ 20**이다.

**접근 전략**

- 절차는 세 단계다.

  1. **무엇이 "물체"인가**를 정한다(사람·아이템·구간 등 개별적으로 넣거나 뺄 수 있는 단위).
  2. 고르는 개수 r을 0 ~ N으로 훑고, 각 r마다 `combinations(...)`가 내어 주는 조합에서 **고른 물체들의 특성(합·개수·차이 등)을 계산**한다.
  3. 문제의 **제약(합이 C 이하, 개수가 정확히 K 등)을 통과하는 조합만** 대상으로 놓고, 그중 **정답값(최대·최소·개수 등)을 갱신**한다.

- "무엇이든 고를 수 있고, 고른 것들의 조합을 평가한다"는 신호가 보이면 이 방법을 떠올린다. 분할(두 팀으로 나누기)도 "한쪽 팀에 넣을 물체를 고르는 것"이라 부분집합 문제로 바뀐다 — 나머지는 자동으로 반대편이 된다.
- 복잡도: 조합 2^N개 × 각 조합마다 물체 N개 확인 = **O(2^N · N)**. N이 20 근처를 넘어가면 2^N이 폭발하므로, 대개 **N ≤ 20** 정도일 때만 쓴다. 부분집합 개수가 지수임을 항상 의식할 것.
- **참고**: 같은 일을 정수의 비트로 표현하는 **비트마스크** 풀이도 있다(`for mask in range(1 << N)`). 남의 코드에서 자주 보이는 관용구이고 조금 더 빠르지만, 비트 연산이라는 개념이 하나 더 필요하다. 이 단계에서는 `combinations`로 충분하고, 비트마스크는 Intermediate High에서 본격적으로 배운다.

**문제**

**1) 무게 한도 안에서 최대 채우기** · Easy

- **요구사항**: N개의 물건이 있고 각 물건의 무게가 주어진다. 배낭에 담은 물건 무게의 합이 한도 C를 넘지 않도록 물건을 골라, 담을 수 있는 **무게 합의 최댓값**을 구하라(각 물건은 담거나 안 담거나 둘 중 하나).
- **입력**: 첫 줄에 N과 C. 둘째 줄에 N개의 무게.
- **출력**: C를 넘지 않는 범위에서 담은 무게 합의 최댓값(하나도 안 담으면 0).
- **예제**: `5 13 / 3 7 4 9 2` → `13` (예: 7+4+2), `3 8 / 5 5 5` → `5`
- **셀프체크**: 아무것도 안 고른 조합(`r = 0`)도 유효하니 답은 최소 0. C를 초과하는 조합은 후보에서 반드시 제외했는가? 합이 정확히 C가 되는 경우도 허용된다(≤ 조건).

```runner
@@SOLUTION
import sys
from itertools import combinations

def main():
    data = sys.stdin.read().split()
    idx = 0
    N = int(data[idx]); idx += 1
    C = int(data[idx]); idx += 1
    w = [int(data[idx + i]) for i in range(N)]
    idx += N
    best = 0
    for r in range(N + 1):
        for chosen in combinations(w, r):
            total = sum(chosen)
            if total <= C and total > best:
                best = total
    print(best)

main()
@@TESTS
--IN
5 13
3 7 4 9 2
--OUT
13
--IN
4 10
2 4 5 8
--OUT
10
@@EXPL
(1) 접근·핵심 아이디어

- 각 물건을 "담을까 / 말까"로 나누는 부분집합 완전탐색이다. N개의 물건마다 두 갈래이므로 조합은 모두 2^N개, 이를 담는 개수 r을 0부터 N까지 올려 가며 `combinations`로 하나씩 훑는다.
- 각 조합에서 담긴 물건 무게 합을 구해, C를 넘지 않는 것들 중 최댓값을 답으로 갱신한다.

(2) 코드 단계별

- N, C를 읽고 무게 배열 `w`를 만든다.
- `r`을 0 ~ N까지 돌며, `combinations(w, r)`이 내어 주는 조합마다 `sum(chosen)`으로 무게 합 `total`을 구한다.
- `total <= C`(한도 통과)이고 `total > best`일 때만 `best`를 갱신한다.
- 모든 조합을 본 뒤 `best`를 출력한다. `r = 0`(무게 0)도 포함되므로 답은 항상 최소 0.

(3) 스스로 다시 짤 때 생각 순서

- "각 물건을 독립적으로 담거나 뺀다" → 부분집합, `combinations`로 크기별 2^N개 순회.
- 각 조합에서 무게 합 계산.
- 한도 조건(≤ C, 등호 허용)으로 거른 뒤 최대 무게 합을 갱신해 출력.
```

**2) 실력이 비슷한 두 팀으로** · Medium

- **요구사항**: N명의 참가자 점수가 주어진다. 이들을 **두 팀으로 남김없이** 나누되 두 팀 모두 최소 1명 이상이어야 한다. 이때 두 팀 점수 합의 **차이(절댓값)의 최솟값**을 구하라.
- **입력**: 첫 줄에 N. 둘째 줄에 N개의 점수.
- **출력**: 두 팀 점수 합 차이의 최솟값.
- **예제**: `4 / 1 6 11 5` → `1` (예: {1,11} vs {6,5} = 12 vs 11), `5 / 3 1 4 2 2` → `0`
- **셀프체크**: 한 팀을 고르면 나머지는 자동으로 반대 팀 — 굳이 두 번 세지 말 것. 고르는 인원이 0명이거나 N명인 경우(한 팀이 비는 경우)는 제외했는가? 대칭이라 각 분할을 두 번 보게 되지만, 최솟값을 구하는 데는 문제가 없다.

```runner
@@SOLUTION
import sys
from itertools import combinations

def main():
    data = sys.stdin.read().split()
    N = int(data[0])
    a = [int(data[1 + i]) for i in range(N)]
    total = sum(a)
    best = None
    for r in range(1, N):
        for chosen in combinations(a, r):
            s = sum(chosen)
            diff = abs(s - (total - s))
            if best is None or diff < best:
                best = diff
    print(best)

main()
@@TESTS
--IN
4
1 6 11 5
--OUT
1
--IN
3
10 20 30
--OUT
0
@@EXPL
(1) 접근·핵심 아이디어

- 두 팀으로 나누는 것은 "한 팀에 넣을 사람을 고르는" 부분집합 문제와 같다. 한 팀을 정하면 나머지는 자동으로 반대 팀이 된다.
- 두 팀 모두 최소 1명이어야 하므로, 고르는 인원이 0명(빈 팀)이거나 N명(반대편이 빈 팀)인 경우는 제외한다. 즉 r 범위를 `1 ~ N-1`로 두면 양 끝이 자연스럽게 빠진다.

(2) 코드 단계별

- N과 점수 배열 `a`, 전체합 `total`을 준비한다.
- `r`을 1 ~ N-1까지 돌며, `combinations(a, r)`이 내어 주는 조합의 점수를 더해 한 팀 합 `s`를 만든다.
- 반대 팀 합은 `total - s`이므로 차이는 `abs(s - (total - s))`. `best`와 비교해 더 작으면 갱신한다.
- 모든 조합을 본 뒤 `best`를 출력한다. 대칭이라 각 분할을 두 번 보게 되지만 최솟값을 구하는 데는 영향이 없다.

(3) 스스로 다시 짤 때 생각 순서

- "두 팀으로 나눔 = 한 팀을 고름" → 부분집합, 반대편은 자동 결정.
- 빈 팀 금지 → `r`을 `1 .. N-1`로 제한(0명과 N명 배제).
- 차이 = `abs(s - (total-s))`, 그 최솟값을 갱신해 출력.
```

**3) 예산 안에서 가치 최대로 담기** · Medium

- **요구사항**: N개의 상품이 있고 상품 i는 무게 w_i와 가치 v_i를 가진다. 무게 합이 예산 C 이하가 되도록 상품을 골라 **가치 합을 최대**로 만들어라.
- **입력**: 첫 줄에 N과 C. 이어 N줄에 각 상품의 w_i와 v_i.
- **출력**: 무게 합 ≤ C인 조합 중 가치 합의 최댓값.
- **예제**: `3 7 / 3 4 / 4 5 / 5 6` → `9` (무게 3+4=7, 가치 4+5), `4 5 / 2 3 / 3 4 / 4 5 / 5 6` → `7`
- **셀프체크**: 무게로 걸러내고(제약) 가치로 최댓값을 갱신하는(목표) 두 축을 헷갈리지 말 것. 무게가 큰 상품 하나만 담는 게 답일 수도, 작은 여러 개를 담는 게 답일 수도 있으니 부분집합을 전부 봐야 한다.

```runner
@@SOLUTION
import sys
from itertools import combinations

def main():
    data = sys.stdin.read().split()
    idx = 0
    N = int(data[idx]); idx += 1
    C = int(data[idx]); idx += 1
    w = []
    v = []
    for _ in range(N):
        w.append(int(data[idx])); idx += 1
        v.append(int(data[idx])); idx += 1
    best = 0
    for r in range(N + 1):
        for pick in combinations(range(N), r):
            tw = 0
            tv = 0
            for i in pick:
                tw += w[i]
                tv += v[i]
            if tw <= C and tv > best:
                best = tv
    print(best)

main()
@@TESTS
--IN
3 7
3 4
4 5
5 6
--OUT
9
--IN
3 6
2 5
3 6
4 8
--OUT
13
@@EXPL
(1) 접근·핵심 아이디어

- 상품 각각을 "담을까 / 말까"로 나누는 부분집합 완전탐색이다. 2^N개의 조합을 모두 만들어, 각 조합에서 무게 합과 가치 합을 계산한다.
- 무게와 가치 **두 배열을 동시에** 봐야 하므로 값이 아니라 **번호**를 고른다. `combinations(range(N), r)`이 상품 번호 묶음을 내어 주면, 그 번호로 `w[i]`와 `v[i]`를 함께 꺼내 쓸 수 있다.
- 제약(무게 합 ≤ C)과 목표(가치 합 최대)는 서로 다른 축이다. 무게로 후보를 걸러낸 뒤, 통과한 조합의 가치 합으로 최댓값을 갱신한다.

(2) 코드 단계별

- N, C를 읽고, 이어지는 N줄에서 각 상품의 무게 `w[i]`, 가치 `v[i]`를 순서대로 읽는다.
- `r`을 0 ~ N까지 돌며, `combinations(range(N), r)`이 내어 주는 번호 묶음 `pick`의 각 i마다 `tw += w[i]`, `tv += v[i]`로 무게·가치 합을 누적한다.
- `tw <= C`(제약 통과)이고 `tv > best`(가치가 더 큼)일 때만 `best = tv`로 갱신한다.
- 모든 조합을 본 뒤 `best`를 출력한다. 아무것도 안 담는 `r = 0`(무게 0, 가치 0)도 후보라 답은 최소 0.

(3) 스스로 다시 짤 때 생각 순서

- "각 상품을 독립적으로 넣거나 뺀다" → 부분집합, `combinations`로 크기별 2^N개 순회.
- 배열이 둘이므로 값이 아니라 번호를 고른다 → `combinations(range(N), r)`.
- 각 조합에서 무게 합·가치 합 두 개를 함께 누적.
- 무게 조건(≤ C)으로 거른 것들만 대상으로, 가치 합의 최대를 갱신.
```


## L2. 값을 기준으로 완전탐색

**개념**

- 앞 레슨은 "무엇을 고를지(물체)"를 전부 나열했다. 그런데 문제에 따라 **정답이 될 수 있는 값의 범위가 그 자체로 작을 때**가 있다. 이럴 땐 조합을 나열하는 대신, **정답 후보가 될 만한 "값"을 하나씩 직접 대입해 보고, 그 값이 조건을 만족하는지 검사**한다.
- 언제 쓰나: "조건을 만족하는 **가장 큰/작은 값 X를 구하라**", "높이 H로 잘랐을 때 …", "기준을 v로 잡으면 …"처럼 **답이 하나의 수(임계값·기준값·높이 등)** 이고, 그 수가 정해지면 나머지는 단순 계산으로 판정되는 유형.
- 새 발상은 **"탐색의 대상을 조합이 아니라 답의 값으로 옮기는 것"** 이다. 값의 후보 범위가 [lo, hi]로 좁으면, lo부터 hi까지 모든 값을 훑으며 각각을 판정하면 된다.

```python
# 후보 값 v를 lo..hi까지 직접 대입하며 "조건 만족?"을 검사
lo, hi = min(a), max(a)
answer = -1
for v in range(lo, hi + 1):          # 정답 후보 값을 하나씩
    ok = check(v)                    # v가 조건을 만족하는지 판정(대개 배열 한 번 훑기)
    if ok:
        answer = max(answer, v)      # "가장 큰 v"를 찾는다면 갱신
```

**그림으로 보기**

- 앞 레슨과 무엇이 달라졌는지를 축으로 비교하면 이렇다. 왼쪽은 "무엇을 고르나"를 나열하고, 오른쪽은 "답이 얼마인가"를 나열한다.

```text
   axis = combinations              axis = the answer value
   ------------------               -----------------------
   {}  {a}  {b}  {c}                v = lo, lo+1, ... , hi
   {a,b} {a,c} {b,c} {a,b,c}        for each v : check(v) ?
   2^n things to try                hi - lo + 1 things to try
```

- 판정 결과가 단조로우면(참에서 거짓으로 딱 한 번 뒤집히면) 값 축은 이런 모양이 된다. 답은 뒤집히기 직전 칸이다.

```text
   v     : 0   1   2   3   4   5   6   7   8
   check : O   O   O   O   O   O   X   X   X
                               ^
                               |
                               answer = 5   # last O before the flip
```

**손으로 따라가기**

점수 `a = [1, 3, 3, 5, 7]`에서 "합격자가 3명 이상"이 되는 가장 큰 기준점 v를 찾아본다. 후보는 1부터 7까지.

| v | v 이상인 점수 | cnt | cnt ≥ 3? | ans |
| --- | --- | --- | --- | --- |
| 1 | 1,3,3,5,7 | 5 | O | 1 |
| 2 | 3,3,5,7 | 4 | O | 2 |
| 3 | 3,3,5,7 | 4 | O | 3 |
| 4 | 5,7 | 2 | X | 3 |
| 5 | 5,7 | 2 | X | 3 |
| 6 | 7 | 1 | X | 3 |
| 7 | 7 | 1 | X | 3 |

- v를 키울수록 cnt는 절대 늘지 않는다(단조 감소). 그래서 O가 앞쪽에 몰리고, 마지막 O인 **v=3**이 답이 된다.

**왜 이렇게 되는가**

- **왜 범위를 [min, max]로 잡아도 되나**: 기준점이 최솟값보다 작으면 전원이 통과해 "최솟값일 때"와 판정이 똑같고, 최댓값보다 크면 아무도 통과하지 못한다. 바깥쪽은 이미 본 결과를 되풀이할 뿐이라 볼 필요가 없다. 답이 0부터 가능한 문제(높이 자르기 등)는 lo를 0으로 잡는다.
- **왜 오름차순으로 훑으며 덮어쓰면 최댓값이 되나**: 조건을 만족할 때마다 `ans = v`로 덮어쓰므로, 반복이 끝난 시점에 남아 있는 값은 "만족한 v 중 마지막", 곧 가장 큰 v다. 판정이 단조가 아니어도 이 논리 자체는 그대로 성립한다.
- **왜 등호를 꼭 챙겨야 하나**: "v 이상"은 `>=`, "합이 C 이하"는 `<=`다. 경계 하나를 빠뜨리면 정답이 딱 경계에 걸리는 입력에서만 1씩 어긋나 원인을 찾기 어렵다.
- **복잡도가 왜 O(V · N)인가**: 후보 값이 `V = hi - lo + 1`개이고 각 후보마다 배열을 한 번 훑어 판정하니 N번. 곱해서 V·N이다. V가 수백만이면 이대로는 느리지만, 판정이 단조라면 나중에 배울 이분탐색으로 V를 log V로 줄여 O(N log V)가 된다.

**접근 전략**

- 절차는 이렇다.

  1. **"답이 곧 하나의 값"** 임을 알아챈다(기준선·높이·임계값 등). 조합이 아니라 값을 찾는 문제인지 먼저 판별.
  2. 그 값이 들어갈 수 있는 **범위 [lo, hi]를 잡는다**(보통 입력의 최소~최대, 또는 0~최대).
  3. lo부터 hi까지 후보 v를 훑으며 **check(v)** 를 계산한다(예: v 이상인 원소 개수, 높이 v로 잘랐을 때 얻는 양). 조건을 만족하는 값 중 최대/최소를 답으로 취한다.

- 판정 함수 check(v)는 대개 **배열을 한 번 순회하는 O(N)** 짜리 계산이다. 후보 값이 늘수록 답을 만족하다가 안 하거나(또는 그 반대) 하는 **단조적 경향**이 보이면 이 틀이 특히 잘 맞는다.
- 복잡도: 값 범위 크기 V × 판정 O(N) = **O(V · N)**. 값 범위 V가 수백만처럼 크지만 판정이 단조롭다면 나중에 "이분탐색(binary search on answer)"으로 V를 log로 줄일 수 있다 — 지금은 먼저 "값을 하나씩 훑는" 완전탐색으로 발상 자체에 익숙해지자.

**문제**

**1) 최소 M명을 통과시키는 최고 기준점** · Easy

- **요구사항**: N명의 시험 점수가 주어진다. 합격 기준점 v를 정하면 "점수가 v 이상"인 사람이 합격한다. 합격자가 **최소 M명 이상** 되도록 하는 **기준점 v의 최댓값**을 구하라(v는 정수).
- **입력**: 첫 줄에 N과 M. 둘째 줄에 N개의 점수.
- **출력**: 합격자 수 ≥ M을 만족하는 가장 큰 정수 기준점 v.
- **예제**: `5 3 / 1 3 3 5 7` → `3` (v=3이면 3,3,5,7 → 4명 ≥ 3), `3 2 / 10 20 30` → `20`
- **셀프체크**: 기준점을 높일수록 합격자는 줄어드니, "만족하는 v 중 가장 큰 값"을 찾는 문제다. v 범위를 점수의 최소~최대로 잡았는가? "v 이상"의 등호(≥)를 빠뜨리면 경계에서 답이 어긋난다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    N = int(data[0]); M = int(data[1])
    a = [int(data[2 + i]) for i in range(N)]
    lo, hi = min(a), max(a)
    ans = lo
    for v in range(lo, hi + 1):
        cnt = sum(1 for x in a if x >= v)
        if cnt >= M:
            ans = v
    print(ans)

main()
@@TESTS

1 3 3 5 7
--OUT

--IN
6 4
5 8 8 2 9 6
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 답이 곧 하나의 값(기준점 v)이다. 후보 v를 점수의 최소값부터 최대값까지 직접 대입해 보고, 각 v에서 "합격자 수 ≥ M"인지 판정하는 값 기준 완전탐색이다.
- v를 높일수록 합격자(점수 ≥ v인 사람)는 줄어드니 단조적이다. 조건을 만족하는 v 중 가장 큰 값이 답.

(2) 코드 단계별

- 입력에서 N, M과 점수 배열 `a`를 읽는다.
- 후보 범위를 `lo=min(a)`, `hi=max(a)`로 잡는다(그 밖의 v는 굳이 볼 필요가 없다).
- `v`를 lo ~ hi까지 훑으며, `x >= v`인 원소 개수 `cnt`를 센다.
- `cnt >= M`이면 조건을 만족하므로 `ans = v`로 갱신한다. 오름차순으로 훑으니 마지막 갱신값이 최대 v가 된다.
- `ans`를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "답 = 기준점 하나"임을 알아채고, v 후보를 [min, max]로 제한한다.
- 판정 함수: 배열을 한 번 훑어 `>= v` 개수가 M 이상인가?
- 만족하는 v 중 최대를 원하므로, 낮은 v부터 훑으며 만족할 때마다 답을 덮어쓴다. 등호(≥)를 빠뜨리지 않도록 주의.
```

**2) 나무 자르기: 필요한 만큼 얻는 최대 높이** · Medium

- **요구사항**: N그루의 나무 높이가 주어진다. 절단기 높이를 H로 맞추면, H보다 큰 나무는 (높이 - H)만큼 잘려 그 부분을 가져간다(H 이하 나무는 그대로). 가져가는 나무 길이의 합이 **M 이상**이 되도록 하는 **H의 최댓값**을 구하라(H는 0 이상 정수).
- **입력**: 첫 줄에 N과 M. 둘째 줄에 N개의 나무 높이.
- **출력**: 얻는 나무 길이 합 ≥ M을 만족하는 가장 큰 정수 높이 H.
- **예제**: `4 7 / 20 15 10 17` → `15` (H=15면 (20-15)+(17-15)=7), `5 20 / 4 42 40 26 46` → `36`
- **셀프체크**: 각 나무 기여분은 `max(0, 높이 - H)`다 — 음수가 되지 않게 0으로 막았는가? H를 키우면 얻는 양이 줄어드니, "M 이상을 만족하는 가장 큰 H"가 답이다. H 범위 상한을 가장 높은 나무 높이로 두면 충분하다.

```runner
@@SOLUTION
import sys

def main():
    data = sys.stdin.read().split()
    N = int(data[0]); M = int(data[1])
    h = [int(data[2 + i]) for i in range(N)]
    ans = 0
    for H in range(0, max(h) + 1):
        got = sum(x - H for x in h if x > H)
        if got >= M:
            ans = H
    print(ans)

main()
@@TESTS
--IN
4 7
20 15 10 17
--OUT
15
--IN
3 10
30 25 20
--OUT
22
@@EXPL
(1) 접근·핵심 아이디어

- 답이 될 수 있는 건 "절단기 높이 H"라는 하나의 정수 값이다. 조합을 나열하는 게 아니라, 후보 H를 0부터 가장 높은 나무 높이까지 직접 대입해 보고 조건을 만족하는지 검사하는 값 기준 완전탐색이다.
- H가 정해지면 얻는 양은 단순 계산이다: 나무마다 `max(0, 높이 - H)`를 더한 값. H를 키울수록 얻는 양은 단조 감소하므로, "얻는 양 ≥ M"을 만족하는 H 중 가장 큰 값이 답이다.

(2) 코드 단계별

- 입력에서 N, M과 나무 높이 배열 `h`를 읽는다.
- `H`를 0 ~ max(h)까지 훑는다. 각 H에서 `x > H`인 나무만 `x - H`를 더해 얻는 총량 `got`을 계산한다(H 이하 나무는 기여 0).
- `got >= M`이면 이 H는 조건을 만족하므로 `ans = H`로 갱신한다. H가 커지는 순서로 훑으니 마지막으로 갱신된 값이 최대 H가 된다.
- 반복이 끝나면 `ans`를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "답 = 하나의 높이 H"임을 알아채고, H 범위를 [0, 최대 높이]로 잡는다.
- 판정: 주어진 H에서 `sum(max(0, x-H))` ≥ M 인가?
- 만족하는 H 중 최대를 찾으므로, 오름차순으로 훑으며 만족할 때마다 답을 덮어쓴다.
```

**3) 두 작업자에게 나눠 맡길 때 완료 시각 최소화** · Hard

- **요구사항**: N개의 작업 소요시간이 주어진다. 각 작업을 작업자 1, 2 중 한 명에게 배정한다(동시에 진행). 두 작업자가 맡은 시간 합 중 **더 큰 쪽(전체 완료 시각)** 을 최소로 만들어라.
- **입력**: 첫 줄에 N. 둘째 줄에 N개의 소요시간.
- **출력**: 가능한 배정 중 "두 작업자 시간 합의 최댓값"의 최솟값.
- **예제**: `5 / 1 2 3 4 5` → `8` (예: {3,5}=8 vs {1,2,4}=7), `4 / 8 4 4 4` → `12`
- **셀프체크**: 이 문제는 두 관점이 만난다 — 한 작업자에게 줄 작업을 "고르는" 부분집합 완전탐색(L1)으로 풀 수도 있고, "달성 가능한 완료 시각 값"을 기준으로 판정(L2)할 수도 있다. 어느 쪽이든 한쪽 합 a가 정해지면 다른 쪽은 (전체합 - a)로 결정되고, 그 둘의 최댓값을 최소화한다는 점을 놓치지 말 것. 전체합의 절반에 가까운 분할이 이상적이지만, 그 값에 정확히 맞출 수 없을 수도 있음에 유의.

```runner
@@SOLUTION
import sys
from itertools import combinations

def main():
    data = sys.stdin.read().split()
    N = int(data[0])
    t = [int(data[1 + i]) for i in range(N)]
    total = sum(t)
    best = None
    for r in range(N + 1):
        for chosen in combinations(t, r):
            s = sum(chosen)
            m = max(s, total - s)
            if best is None or m < best:
                best = m
    print(best)

main()
@@TESTS

1 2 3 4 5
--OUT
8
--IN
6
2 2 3 3 4 4
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 작업자 1이 맡을 작업들의 부분집합을 고르면, 나머지는 자동으로 작업자 2의 몫이다. 한쪽 합 s가 정해지면 다른 쪽은 (전체합 - s)로 결정되므로, 두 사람 중 "더 큰 쪽" = `max(s, total - s)`가 그 배정의 완료 시각이다.
- 모든 부분집합(2^N개)을 훑으며 이 완료 시각의 최솟값을 찾으면 된다. 전체합의 절반에 가장 가까운 분할이 좋지만 정확히 맞출 수 없을 수 있으니, 후보를 전부 보는 완전탐색이 안전하다.

(2) 코드 단계별

- 입력을 읽어 시간 배열 `t`와 전체합 `total`을 준비한다.
- `r`을 0 ~ N까지 돌며, `combinations(t, r)`이 내어 주는 조합의 작업 시간을 더해 한쪽 합 `s`를 만든다.
- `max(s, total - s)`가 이 배정의 완료 시각. `best`와 비교해 더 작으면 갱신한다.
- 모든 조합을 본 뒤 `best`를 출력한다. `r = 0`(한쪽이 비고 다른쪽이 전부)도 후보이므로 답은 total 이하로 항상 정의된다.

(3) 스스로 다시 짤 때 생각 순서

- "한쪽을 정하면 반대쪽이 자동 결정" → 부분집합 하나 = 배정 하나임을 먼저 못박는다.
- 완료 시각 = 두 합 중 큰 값 = `max(s, total-s)`.
- 최솟값을 담을 `best`를 None으로 시작해 갱신, 마지막에 출력.
```

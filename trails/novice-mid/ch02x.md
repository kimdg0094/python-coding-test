## L3. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch2(재귀함수)의 핵심 — 종료 조건과 문제 축소, 출력 순서(재귀 앞/뒤), 부분 답을 받아 조합하는 값 반환 재귀 — 를 **반복 훈련**하고, 코딩테스트에서 재귀로 풀리는 단골 유형으로 **확장**하는 세트다.
- **반복 훈련 개념**
- 출력 순서: 재귀 호출 **앞**에 `print`하면 정방향, **뒤**에 두면 역방향. 앞뒤 둘 다 두면 "올라갔다 내려오는" 대칭 출력이 된다.
- 자릿수 축소: `f(n) = (일의 자리 처리) + f(n // 10)`, 종료는 `n < 10`. 0도 한 자리임을 잊지 말 것.
- 문자열 축소: `rev(s) = rev(s[1:]) + s[0]`, 종료는 `len(s) <= 1`.
- 두 인덱스 축소: `f(s, l, r)` 에서 `l += 1, r -= 1`, 종료는 `l >= r`.
- 두 갈래 재귀: `ways(n) = ways(n-1) + ways(n-3)`, `cnt(i, remain) = cnt(i+1, remain-a[i]) + cnt(i+1, remain)` — 갈래별 답을 **더해서** 합친다.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '재귀' 단계(팩토리얼·피보나치·하노이 유형), 프로그래머스 「코딩테스트 고득점 Kit」의 '이분탐색'(정렬된 배열에서 절반씩 좁히기), NeetCode 150의 'Backtracking'(원소를 고르거나/안 고르는 두 갈래 탐색). 모두 "종료 조건 + 축소 규칙 + 부분 답 합치기"라는 같은 뼈대로 풀린다.
- **문제 구성표**

**문제**

**1) 짝수 자릿수 세기** · Easy

- **요구사항**: 음이 아닌 정수 `n`의 자릿수 중 짝수(0, 2, 4, 6, 8)의 개수를 값을 반환하는 재귀함수로 구하라. 일의 자리를 처리하고 `n // 10`으로 축소하는 방식이며, 반복문과 문자열 변환은 쓰지 않는다.
- **입력**: 첫 줄에 정수 `n`(0 ≤ n ≤ 10^18).
- **출력**: 짝수 자릿수의 개수.
- **예제**: `2048` → `4` · `135` → `0` · `0` → `1`
- **셀프체크**: `n = 0`일 때 "자릿수 0 하나"로 세어 `1`이 나오는가(종료 조건을 `n == 0`으로 잡으면 `0`이 나와 틀린다)? 종료 조건 `n < 10`에서도 그 한 자리를 검사해 반환하는가? `10^18`은 19자리이므로 재귀 깊이가 19밖에 안 됨을 확인했는가?

```runner
@@SOLUTION
def even_digits(n):
    cur = 1 if (n % 10) % 2 == 0 else 0
    if n < 10:
        return cur
    return cur + even_digits(n // 10)

print(even_digits(int(input())))
@@TESTS
--IN
2048
--OUT
4
--IN
135
--OUT
0
--IN
0
--OUT
1
--IN
1000000000000000000
--OUT
18
@@EXPL
(1) 접근·핵심 아이디어

- "일의 자리가 짝수면 1, 아니면 0"을 지금 몫으로 정하고, 나머지 앞자리(`n // 10`)의 답은 재귀가 준다고 믿고 더한다. 점화식은 `f(n) = cur + f(n // 10)`.
- 함정은 `0`이다. 종료 조건을 `n == 0`으로 두면 `0` 입력에서 아무것도 세지 않는다. "한 자리만 남았을 때"(`n < 10`)를 종료로 잡고 그 한 자리도 검사해야 `0 → 1`이 된다.

(2) 코드 단계별

- `cur = 1 if (n % 10) % 2 == 0 else 0`으로 현재 일의 자리를 판정.
- `n < 10`이면 남은 자리가 지금 자리뿐이므로 `cur`를 그대로 반환(종료 조건).
- 아니면 `cur + even_digits(n // 10)`으로 앞자리 답을 더해 반환.
- `10^18`(19자리)도 깊이 19라 재귀 한계와 무관하다.

(3) 스스로 다시 짤 때 생각 순서

- "한 조각" = 일의 자리 판정 → "축소" = `n // 10` → "종료" = 한 자리 남음. `0`, `135`(전부 홀수), `2048`(전부 짝수)로 종료 조건이 세 경우 모두 맞는지 손으로 검산.
```

**2) 문자열 뒤집기** · Easy

- **요구사항**: 문자열 `s`를 거꾸로 뒤집은 새 문자열을 값을 반환하는 재귀함수로 만들어라. "첫 글자를 뗀 나머지를 뒤집은 결과 뒤에 첫 글자를 붙인다"는 규칙을 쓴다. 슬라이싱 `[::-1]`, 반복문은 쓰지 않는다.
- **입력**: 첫 줄에 공백 없는 문자열 `s`(알파벳·숫자, 길이 1~500).
- **출력**: 뒤집은 문자열.
- **예제**: `hello` → `olleh` · `a` → `a`
- **셀프체크**: 종료 조건이 길이 1 이하(`len(s) <= 1`)에서 `s` 자체를 반환하는가? `rev(s[1:]) + s[0]`에서 첫 글자를 **뒤**에 붙이는가(앞에 붙이면 원래 문자열이 그대로 나온다)? 길이 500이면 재귀 깊이도 500이라 기본 한계(약 1000) 안인가?

```runner
@@SOLUTION
def rev(s):
    if len(s) <= 1:
        return s
    return rev(s[1:]) + s[0]

print(rev(input().strip()))
@@TESTS
--IN
hello
--OUT
olleh
--IN
a
--OUT
a
--IN
abba
--OUT
abba
--IN
ab12
--OUT
21ba
@@EXPL
(1) 접근·핵심 아이디어

- "나머지 부분은 이미 뒤집혀 있다"고 믿는다. `s[1:]`(첫 글자를 뗀 부분)을 뒤집은 결과 **뒤에** 첫 글자 `s[0]`을 붙이면 전체가 뒤집힌다. 점화식 `rev(s) = rev(s[1:]) + s[0]`.
- 종료 조건은 길이 0 또는 1 — 뒤집어도 자기 자신이므로 `s`를 그대로 반환한다.

(2) 코드 단계별

- `len(s) <= 1`이면 `s` 반환.
- 아니면 `rev(s[1:])`로 짧아진 문자열의 답을 받아 `+ s[0]`.
- 호출마다 길이가 1씩 줄어 깊이는 문자열 길이와 같다. 길이 500이면 깊이 500.

(3) 스스로 다시 짤 때 생각 순서

- "축소" = 첫 글자 떼기 → "한 걸음" = 떼어낸 글자를 뒤에 붙이기 → "종료" = 길이 1 이하. `ab`로 손 추적: `rev("b") + "a" = "ba"`.
```

**3) 올라갔다 내려오기** · Easy

- **요구사항**: 정수 `n`이 주어질 때 `1, 2, …, n`을 한 줄에 하나씩 출력한 뒤 곧바로 `n, n−1, …, 1`을 이어서 출력하는 값을 반환하지 않는 재귀함수를 작성하라. 함수 하나로, 재귀 호출 **앞**과 **뒤**에 각각 출력을 두어 두 방향을 한꺼번에 만든다. 반복문은 쓰지 않는다.
- **입력**: 첫 줄에 정수 `n`(1 ≤ n ≤ 500).
- **출력**: 총 `2n`줄. 앞 `n`줄은 `1..n` 오름차순, 뒤 `n`줄은 `n..1` 내림차순.
- **예제**: `3` → `1` / `2` / `3` / `3` / `2` / `1` · `1` → `1` / `1`
- **셀프체크**: `n = 1`일 때 `1`이 두 번 출력되는가? 재귀 호출 앞의 출력이 오름차순, 뒤의 출력이 내림차순을 만드는 이유를 호출 스택으로 설명할 수 있는가? 종료 조건을 `cur < n`일 때만 재귀하는 식으로 두어 `n`을 넘지 않는가?

```runner
@@SOLUTION
def climb(cur, n):
    print(cur)
    if cur < n:
        climb(cur + 1, n)
    print(cur)

climb(1, int(input()))

@@EXPL
(1) 접근·핵심 아이디어

- 재귀 호출 **앞**의 출력은 내려가면서(1 → n) 찍히고, 호출 **뒤**의 출력은 되돌아오면서(n → 1) 찍힌다. 한 함수에 둘 다 두면 "올라갔다 내려오는" 대칭 출력이 저절로 만들어진다.
- 가장 깊은 호출(`cur == n`)은 재귀 없이 `n`을 두 번 연달아 출력하므로 가운데에 `n, n`이 붙어 나온다.

(2) 코드 단계별

- `print(cur)` — 내려가며 찍는 출력.
- `cur < n`이면 `climb(cur + 1, n)`로 더 깊이 들어간다(`cur == n`이면 여기서 멈추는 것이 종료 조건).
- `print(cur)` — 돌아오며 찍는 출력.
- `n = 1`이면 재귀 없이 `1`이 두 번 나온다.

(3) 스스로 다시 짤 때 생각 순서

- "정방향은 재귀 앞, 역방향은 재귀 뒤" 규칙을 떠올린다 → 둘 다 필요하면 둘 다 둔다 → 종료 조건은 `cur < n`일 때만 호출 → `n = 2`로 호출 스택(1 → 2 → 2 → 1)을 손으로 추적.
```

**4) 배열 전체의 최대공약수** · Medium

- **요구사항**: 두 수의 최대공약수를 유클리드 호제법 `gcd(a, b) = gcd(b, a % b)`로 구하는 재귀함수와, 배열의 `i`번째부터 끝까지의 최대공약수를 `gcd(arr[i], gcd_all(arr, i + 1))`로 구하는 재귀함수를 각각 작성해 배열 전체의 최대공약수를 출력하라. 반복문은 쓰지 않는다.
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 500). 둘째 줄에 양의 정수 `n`개(각 1 ≤ v ≤ 10^9).
- **출력**: 배열 전체의 최대공약수.
- **예제**: `4 / 12 18 30 42` → `6` · `1 / 7` → `7`
- **셀프체크**: `gcd`의 종료 조건은 `b == 0`일 때 `a`를 반환하는 것인가(`a == 0`으로 잡으면 순서가 꼬인다)? `gcd_all`의 종료 조건은 마지막 원소 하나(`i == len(arr) - 1`)일 때 그 값을 반환하는가? 서로소 배열(`8 15 27`)에서 `1`이 나오는가? `gcd_all`의 깊이는 `n`(최대 500)이라 안전한가?

```runner
@@SOLUTION
import sys
input = sys.stdin.readline

def gcd(a, b):
    if b == 0:
        return a
    return gcd(b, a % b)

def gcd_all(arr, i):
    if i == len(arr) - 1:
        return arr[i]
    return gcd(arr[i], gcd_all(arr, i + 1))

n = int(input())
arr = list(map(int, input().split()))
print(gcd_all(arr, 0))
@@TESTS
--IN

--OUT
6
--IN
1
7
--OUT

--IN
3
8 15 27
--OUT
1
--IN
3
5 10 20
--OUT
5
@@EXPL
(1) 접근·핵심 아이디어

- 두 층의 재귀다. 안쪽 `gcd(a, b)`는 "`b`가 0이면 `a`, 아니면 `gcd(b, a % b)`"라는 호제법 점화식. 바깥 `gcd_all(arr, i)`는 "뒤쪽 원소들의 최대공약수는 재귀가 준다"고 믿고 `arr[i]`와 그 답의 `gcd`를 취한다.
- 여러 수의 최대공약수는 `gcd(a, gcd(b, gcd(c, ...)))`처럼 두 수씩 접어 구할 수 있다는 성질을 리스트 재귀로 옮긴 것이다.

(2) 코드 단계별

- `gcd`: `b == 0`이면 `a` 반환(종료). 아니면 인자를 `(b, a % b)`로 바꿔 재귀. `a < b`여도 한 번 호출하면 자리가 바뀌므로 따로 처리할 필요 없다.
- `gcd_all`: `i`가 마지막 인덱스면 `arr[i]` 반환(원소 하나의 최대공약수는 자기 자신). 아니면 `gcd(arr[i], gcd_all(arr, i + 1))`.
- 시작은 `gcd_all(arr, 0)`. 깊이는 `n`이고, `gcd` 자체의 깊이는 10^9 범위에서 50 미만이다.

(3) 스스로 다시 짤 때 생각 순서

- 두 수의 `gcd`를 먼저 완성해 `gcd(12, 18) = 6`으로 검산 → "리스트의 나머지 부분 답"을 안다고 가정하고 앞 원소와 접는다 → 종료는 원소 하나 → 서로소(`1`)와 원소 1개 케이스로 경계 확인.
```

**5) k진법 문자열 만들기** · Medium

- **요구사항**: 음이 아닌 정수 `n`과 진법 `k`가 주어질 때, `n`을 `k`진법으로 나타낸 문자열을 값을 반환하는 재귀함수로 만들어라. "몫 `n // k`의 표현 뒤에 나머지 `n % k`를 붙인다"는 규칙이며, 종료 조건은 `n < k`(한 자리)다. 반복문과 내장 진법 변환 함수는 쓰지 않는다.
- **입력**: 한 줄에 `n k`(0 ≤ n ≤ 10^9, 2 ≤ k ≤ 9).
- **출력**: `k`진법 문자열.
- **예제**: `10 2` → `1010` · `255 8` → `377` · `0 5` → `0`
- **셀프체크**: `n = 0`에서 빈 문자열이 아니라 `0`이 나오는가(종료 조건을 `n == 0 → ""`로 두면 틀린다)? 나머지를 재귀 결과의 **뒤**에 붙이는가(앞에 붙이면 자릿수가 뒤집힌다)? `10^9`를 2진법으로 바꿔도 깊이 30이라 안전한가?

```runner
@@SOLUTION
def convert(n, k):
    if n < k:
        return str(n)
    return convert(n // k, k) + str(n % k)

n, k = map(int, input().split())
print(convert(n, k))

(1) 접근·핵심 아이디어

- `n`을 `k`로 나누면 나머지가 가장 낮은 자리, 몫이 그 위 자리들이다. "몫의 `k`진 표현은 재귀가 준다"고 믿고 그 문자열 뒤에 나머지 한 자리를 붙인다. 점화식 `convert(n) = convert(n // k) + str(n % k)`.
- 종료 조건은 `n < k`(한 자리) — 이때 `str(n)`을 반환하므로 `n = 0`도 `"0"`이 되어 빈 문자열 함정을 피한다.

(2) 코드 단계별

- `n < k`면 `str(n)` 반환.
```

**6) 1칸 또는 3칸 뛰기** · Medium

- **요구사항**: 한 번에 1칸 또는 3칸을 뛸 수 있을 때, 0번 칸에서 정확히 `n`번 칸에 도착하는 서로 다른 방법의 수를 값을 반환하는 재귀함수로 구하라. 점화식은 "마지막 점프가 1칸인 경우의 수 + 3칸인 경우의 수"다. 음수 칸으로 가는 경우는 0가지, 0번 칸에 이미 있는 경우는 1가지로 둔다.

- **출력**: 방법의 수.

**7) 공백을 무시한 회문 판정** · Medium

- **요구사항**: 소문자와 공백으로 된 한 줄이 주어질 때, 공백을 모두 지운 문자열이 회문(앞뒤로 읽어도 같음)인지 판정하라. 판정은 양 끝 인덱스 `l`, `r`을 받는 `bool` 반환 재귀함수 `is_pal(s, l, r)`로 하며, 양 끝이 같으면 `l + 1`, `r − 1`로 안쪽을 재귀한다. 반복문과 슬라이싱 `[::-1]`은 쓰지 않는다.

- **셀프체크**: 종료 조건을 `l >= r`(가운데를 지나거나 만남)로 두어 홀수·짝수 길이를 모두 처리하는가? 양 끝이 다르면 즉시 `False`를 반환하는가(조기 반환)? 공백 제거를 재귀 **전에** 한 번만 하는가? 길이 1000이면 깊이는 최대 500임을 확인했는가?

**8) 하노이 이동 횟수와 k번째 원판** · Hard

- **요구사항**: 원판 `n`개를 옮기는 하노이 탑의 최소 이동 횟수를 점화식 `moves(n) = 2 * moves(n − 1) + 1`(종료 `moves(0) = 0`)의 값 반환 재귀로 구하라. 그리고 그 최소 이동 순서에서 `k`번째 이동에 옮겨지는 원판의 번호(작은 원판이 1, 가장 큰 원판이 `n`)를 재귀로 구하라. 힌트: `n`개 이동 순서는 "`n−1`개 이동 → 원판 `n` 한 번 → `n−1`개 이동"의 구조이므로, `k`가 가운데면 `n`, 앞쪽이면 `n−1`개 문제의 `k`번째, 뒤쪽이면 `n−1`개 문제의 `k − mid`번째다.
- **입력**: 한 줄에 `n k`(1 ≤ n ≤ 30, 1 ≤ k ≤ 2^n − 1).
- **출력**: 첫 줄에 최소 이동 횟수, 둘째 줄에 `k`번째로 옮겨지는 원판 번호.
- **예제**: `3 4` → `7` / `3` · `4 6` → `15` / `2`
- **셀프체크**: 가운데 위치 `mid = moves(n − 1) + 1`을 정확히 계산했는가? `k > mid`일 때 `k − mid`로 옮겨 앞쪽 문제와 같은 번호 체계로 만들었는가? `n = 1`이면 이동 1번, 원판 1인가? `n = 30`도 깊이 30이라 안전한가? 이동 횟수를 `2^n − 1` 공식이 아닌 재귀로 구했는가?

```runner
@@SOLUTION
def moves(n):
    if n == 0:
        return 0
    return 2 * moves(n - 1) + 1

def disk_at(n, k):
    mid = moves(n - 1) + 1
    if k == mid:
        return n
    if k < mid:
        return disk_at(n - 1, k)
    return disk_at(n - 1, k - mid)

n, k = map(int, input().split())
print(moves(n))
print(disk_at(n, k))

(1) 접근·핵심 아이디어

- 하노이 탑에서 `n`개를 옮기려면 위의 `n−1`개를 보조 기둥으로 보내고(`moves(n−1)`), 가장 큰 원판을 한 번 옮기고(`+1`), 다시 `n−1`개를 그 위로 올린다(`moves(n−1)`). 그래서 `moves(n) = 2·moves(n−1) + 1`.
- 같은 구조를 "순서"에 적용하면 `k`번째 이동이 보인다. 전체 순서는 `[n−1개 순서] [원판 n] [n−1개 순서]`이므로 가운데 위치 `mid = moves(n−1) + 1`을 기준으로 `k`가 가운데면 원판 `n`, 앞이면 앞쪽 부분 문제의 `k`번째, 뒤면 뒤쪽 부분 문제의 `k − mid`번째다. 뒤쪽 순서는 앞쪽과 완전히 같으므로 번호만 당겨 주면 된다.
- 함정: `k − mid`로 옮기지 않고 `k`를 그대로 넘기면 뒤쪽 절반에서 답이 틀린다. 또 `moves`와 `disk_at` 모두 종료 조건이 `n`이 작아지며 반드시 도달함을 확인한다.

(2) 코드 단계별

- `moves(n)`: `n == 0`이면 `0`, 아니면 `2 * moves(n - 1) + 1`.
- `disk_at(n, k)`: `mid`를 구해 `k == mid`면 `n` 반환(종료). `k < mid`면 `disk_at(n - 1, k)`, 아니면 `disk_at(n - 1, k - mid)`.
- `n = 1`이면 `mid = 1`이고 `k`는 1뿐이라 즉시 `1`을 반환하므로 별도 종료 조건이 필요 없다.
- 검산 `4 6`: `mid = 8`, `6 < 8` → `disk_at(3, 6)`: `mid = 4`, `6 > 4` → `disk_at(2, 2)`: `mid = 2` → `2`.

(3) 스스로 다시 짤 때 생각 순서

- 이동 횟수 점화식을 먼저 재귀로 옮기고 `3 → 7`로 검산 → 순서 구조 `[앞][가운데][뒤]`를 그리고 가운데 위치를 `moves(n−1) + 1`로 정한다 → 세 경우(가운데/앞/뒤)로 나눠 뒤쪽은 `k − mid` 보정 → 작은 `n`에서 실제 이동 순서(1,2,1,3,1,2,1)를 손으로 나열해 확인.
```

**9) 재귀 이진 탐색** · Hard

- **요구사항**: 오름차순으로 정렬된 서로 다른 정수 배열에서 값 `x`의 인덱스를 찾는 재귀함수 `bsearch(arr, lo, hi, x)`를 작성하라. 가운데 원소와 비교해 같으면 그 인덱스를, 작으면 오른쪽 절반을, 크면 왼쪽 절반을 재귀로 탐색하고, 구간이 비면(`lo > hi`) `-1`을 반환한다. 여러 질의에 대해 각각 답한다. 반복문과 `in`·`index` 같은 선형 탐색은 쓰지 않는다.
- **입력**: 첫 줄에 `n q`(1 ≤ n ≤ 1000, 1 ≤ q ≤ 100). 둘째 줄에 오름차순 서로 다른 정수 `n`개(−10^9 ≤ v ≤ 10^9). 다음 `q`개 줄에 찾을 값 `x`.
- **출력**: 질의마다 `x`의 인덱스(0-based), 없으면 `-1`을 한 줄에 하나씩.
- **예제**: `5 3 / 1 3 5 7 9 / 7 / 4 / 1` → `3` / `-1` / `0` · `1 2 / 10 / 10 / 5` → `0` / `-1`
- **셀프체크**: 구간이 빈 조건 `lo > hi`를 종료 조건으로 두어 없는 값에서도 멈추는가? 오른쪽으로 갈 때 `mid + 1`, 왼쪽으로 갈 때 `mid − 1`로 `mid`를 제외했는가(포함하면 구간이 안 줄어 무한 재귀)? 양 끝 원소(`1`, `9`)와 원소 1개 배열에서 맞는가? 깊이는 log₂(1000) ≈ 10임을 이해했는가?

```runner
    if arr[mid] == x:
        return mid
    if arr[mid] < x:
        return bsearch(arr, mid + 1, hi, x)
    return bsearch(arr, lo, mid - 1, x)

n, q = map(int, input().split())
arr = list(map(int, input().split()))
for _ in range(q):
    x = int(input())
    print(bsearch(arr, 0, n - 1, x))

- 종료 조건이 둘이다. 찾았을 때(`arr[mid] == x`) 인덱스를 반환하고, 구간이 비었을 때(`lo > hi`) `-1`을 반환한다. 후자가 없으면 없는 값에서 멈추지 않는다.

(3) 스스로 다시 짤 때 생각 순서
```

**10) 합이 S가 되는 고르기** · Hard

- **요구사항**: 정수 `n`개 중 **하나 이상**을 골라 합이 정확히 `S`가 되는 방법의 수를 재귀로 구하라. `i`번째 원소를 "고른다"와 "안 고른다" 두 갈래로 나누는 재귀함수 `count(arr, i, remain)`을 작성한다(`remain`은 아직 만들어야 하는 합). 모든 원소를 다 살펴본 뒤 `remain == 0`이면 1가지다. 단, 아무것도 고르지 않은 경우는 방법으로 치지 않으므로 `S == 0`일 때 보정이 필요하다.
- **입력**: 첫 줄에 `n S`(1 ≤ n ≤ 15, −10,000 ≤ S ≤ 10,000). 둘째 줄에 정수 `n`개(각 −100 ≤ v ≤ 100).
- **출력**: 방법의 수.
- **예제**: `4 3 / 1 2 3 4` → `2` (3 · 1+2) · `3 0 / 1 -1 2` → `1` (1+(−1))
- **셀프체크**: 종료 조건이 "인덱스가 끝에 도달"이고 그때 `remain == 0`이면 `1`, 아니면 `0`인가? 두 갈래(고름: `remain − arr[i]`, 안 고름: `remain`)의 답을 더하는가? `S == 0`이면 "아무것도 안 고름"이 항상 1가지로 세어지므로 결과에서 1을 빼야 한다는 점을 처리했는가? 음수 원소가 있으므로 `remain < 0`에서 가지치기하면 **틀린다**는 것을 알았는가? `n = 15`면 호출 약 6만 번임을 확인했는가?

```runner
@@SOLUTION
def count(arr, i, remain):
    if i == len(arr):
        return 1 if remain == 0 else 0
    return count(arr, i + 1, remain - arr[i]) + count(arr, i + 1, remain)

n, S = map(int, input().split())
arr = list(map(int, input().split()))
ans = count(arr, 0, S)
if S == 0:
    ans -= 1
print(ans)
@@TESTS
--IN

(1) 접근·핵심 아이디어

- 원소마다 "고른다/안 고른다" 두 선택이 있으므로, `i`번째에서 두 갈래로 재귀하고 각 갈래의 방법 수를 더한다. 고르면 남은 목표 `remain`에서 `arr[i]`를 빼고, 안 고르면 그대로 넘긴다. 점화식 `count(i, remain) = count(i+1, remain − arr[i]) + count(i+1, remain)`.
- 종료 조건은 모든 원소를 살펴본 시점(`i == n`). 그때 `remain == 0`이면 지금까지의 선택이 정확히 `S`를 만든 것이므로 1, 아니면 0.
- 함정 두 가지: (a) `S == 0`이면 "아무것도 안 고르는" 경로도 `remain == 0`으로 1가지로 세어지므로 마지막에 1을 뺀다. (b) 원소에 음수가 있어 `remain`이 음수가 되어도 뒤에서 다시 0이 될 수 있으므로 `remain < 0`에서 멈추는 가지치기는 쓰면 안 된다.

(2) 코드 단계별

- `i == len(arr)`이면 `1 if remain == 0 else 0` 반환.
- 아니면 고른 갈래와 안 고른 갈래의 반환값을 더해 반환.
- 메인은 `count(arr, 0, S)`를 구한 뒤 `S == 0`일 때만 `ans -= 1`.
- 호출 수는 약 `2^(n+1)`, `n = 15`면 6만여 번이라 충분히 빠르다. 깊이는 `n`이다.

(3) 스스로 다시 짤 때 생각 순서

- "원소마다 두 선택"을 두 갈래 재귀로 → 상태는 (현재 인덱스, 남은 합) → 종료는 인덱스 끝에서 남은 합이 0인지 → 빈 선택 보정(`S == 0`)과 음수 원소 때문에 가지치기를 하지 않는 이유를 예제 `1 -1 2`로 확인.
```

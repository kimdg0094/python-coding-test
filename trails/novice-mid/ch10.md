> 개요: 이 챕터에서는 복잡한 탐색 없이도 "이렇게 하는 것이 반드시 최선"임을 논리로 확신하고 곧장 답을 내는 애드혹(Ad-Hoc) 사고를 배운다. 최선 전략이 확실히 정해지는 경우와, 고려할 후보 대상이 뚜렷이 좁혀지는 경우로 나눠 익힌다.

## L1. 지극히 최선인 전략이 확실히 정해지는 경우

**개념**

- 애드혹(Ad-Hoc)은 정해진 알고리즘 틀(정렬·완전탐색·시뮬레이션 등)에 억지로 끼워 넣기보다, 그 문제만의 성질을 관찰해서 "이렇게 하면 반드시 최선"이라는 규칙을 직접 찾아 푸는 방식이다.

- 이 레슨의 유형은 특히, 조금만 생각해 보면 "누가 봐도 이게 최선"인 행동이 하나로 정해지는 경우다. 그 최선 행동을 매 순간 취하기만 하면(그리디하게) 곧바로 답이 나온다.

- 핵심은 "왜 이게 최선인가"를 스스로 납득하는 것이다. 다른 선택을 했을 때 손해가 나거나, 적어도 손해 보지 않음을 확인하면 그 전략을 믿고 구현하면 된다.

- 새 문법이 필요한 건 아니다. 기존의 반복문·조건문·`max`/`min`·정렬 등을 쓰되, "무엇을 반복하고 무엇을 비교할지"를 관찰로 결정한다는 점이 다르다.

```python
# 예: 동전을 큰 단위부터 쓰면 개수가 최소가 되는 화폐 체계에서
# "가장 큰 동전을 최대한 많이 쓰는 것"이 확실한 최선이다.
coins = [500, 100, 50, 10]
money = 1260
count = 0
for c in coins:
    count += money // c   # 이 동전을 최대한 많이 쓴다
    money %= c
# count == 6  (500*2 + 100*2 + 50*1 + 10*1 = 1260)
```

**접근 전략**

- 절차: (1) 문제를 최대·최소·최적을 묻는 형태로 다시 읽는다. (2) "한 걸음마다 어떤 선택을 하면 손해가 없을까"를 아주 작은 예로 손으로 시험한다. (3) 그 선택이 항상 옳은 이유(교환 논증: 다른 선택을 이 선택으로 바꿔도 결과가 나빠지지 않는다)를 확인한다. (4) 그 선택을 반복하는 짧은 루프로 구현한다.

- 언제 쓰나: 정렬해 놓고 보면 순서가 뻔해지거나, "가장 큰/작은 것부터", "가장 급한 것부터"처럼 우선순위가 자명해질 때. 반대로 앞의 선택이 뒤의 선택 가능성을 크게 바꿔 손해가 생길 수 있으면 그리디가 틀리므로, 반례를 한 번 찾아보는 습관이 중요하다.

- 주의·복잡도: 대부분 한 번 정렬(`O(n log n)`) 후 한 번 훑기(`O(n)`)로 끝나 매우 빠르다. 함정은 "정렬 기준을 무엇으로 삼느냐"이고, 기준만 맞으면 구현은 짧다. 확신이 안 서면 작은 반례로 검증부터 하자.

**문제**

**1) 큰 수 만들기(자릿수 버리기)** · Easy

- **요구사항**: 자릿수만 나열된 하나의 수에서 정확히 `k`개의 자리를 지워, 남은 자리들을 원래 순서 그대로 이어 붙였을 때 가장 큰 수를 만든다.

- **입력**: 첫 줄에 숫자 문자열 `S`(각 문자는 `'0'`~`'9'`)와 지울 개수 `k`가 공백으로 주어진다. (`1 ≤ k < len(S)`)

- **출력**: 만들 수 있는 가장 큰 수(문자열 그대로 출력).

- **예제**: `1924 2` → `94`

- **예제**: `4177252841 4` → `775841`

- **셀프체크**: "앞에서부터 보며, 지금 자리보다 뒤에 더 큰 자리가 오면 지금 자리를 버린다"가 최선인 이유를 납득했는가? 스택(리스트)에 쌓다가 새 자리가 스택 맨 위보다 크고 아직 지울 여유(`k>0`)가 있으면 맨 위를 pop. `k`가 남았다면 뒤에서부터 남은 만큼 잘라낸다. 앞자리 0은 이 문제에선 생기지 않지만 형식은 문자열로 유지.

```runner
@@SOLUTION
import sys
data = sys.stdin.readline().split()
s, k = data[0], int(data[1])
stack = []
for ch in s:
    while stack and k > 0 and stack[-1] < ch:
        stack.pop()
        k -= 1
    stack.append(ch)
if k > 0:
    stack = stack[:len(stack) - k]
print("".join(stack))
@@TESTS
--IN
1924 2
--OUT
94
--IN
4177252841 4
--OUT
775841
@@EXPL
**이 풀이의 새 문법**

- `리스트.pop()`: 리스트의 맨 뒤 원소를 꺼내면서 동시에 제거한다(인자를 안 주면 마지막 원소). `append`로 넣은 것을 다시 빼내는 짝이 되는 동작이라, 이 조합으로 리스트를 "스택"처럼 쓸 수 있다.

(1) 접근·핵심 아이디어

- 남길 자리는 앞에서부터 "가능하면 큰 자리"를 먼저 확정해야 큰 수가 된다. 앞자리가 뒷자리보다 작으면 앞자리를 버리는 게 이득이다(지울 여유가 있을 때).
- 이를 단조 감소에 가까운 스택으로 구현한다. 새 문자가 스택 맨 위보다 크면, 지울 예산(`k`)이 남는 한 맨 위를 pop 해서 더 큰 자리를 앞으로 당긴다.

(2) 코드 단계별

- `S`와 `k`를 읽는다.
- 각 문자에 대해: 스택이 비어있지 않고 `k>0`이며 맨 위가 지금 문자보다 작으면 pop 하고 `k`를 1 줄인다. 그 뒤 지금 문자를 push.
- 끝까지 지울 예산이 남았다면(이미 내림차순이라 pop 못 한 경우) 뒤에서 `k`개를 잘라낸다.
- 스택을 이어붙여 출력.

(3) 스스로 다시 짤 때 생각 순서

- "가장 큰 수 = 앞자리를 최대화"를 먼저 떠올린다.
- 앞자리를 버리는 조건(뒤에 더 큰 게 오고, 예산이 있다)을 스택 pop 규칙으로 옮긴다.
- 예산이 남는 잔여 처리(뒤에서 자르기)를 잊지 않는다.
```

**2) 회의실 하나 배정(최대 개수)** · Medium

- **요구사항**: 회의 `n`개의 시작·종료 시각이 주어진다. 한 회의실에서 서로 시간이 겹치지 않게 회의를 골라, 최대 몇 개까지 진행할 수 있는지 구한다. (한 회의의 종료 시각과 다른 회의의 시작 시각이 같으면 겹치지 않는 것으로 본다)

- **입력**: 첫 줄에 회의 수 `n`. 이어서 `n`개의 줄에 각 회의의 시작 시각 `s`와 종료 시각 `e`가 공백으로 주어진다.

- **출력**: 겹치지 않게 고를 수 있는 회의의 최대 개수.

- **예제**: `3 / 1 4 / 3 5 / 5 7` → `2`
  - (`1 4`를 고르면 `3 5`는 겹쳐 버림, 대신 `5 7` 가능 → 2개)

- **예제**: `5 / 1 3 / 2 4 / 3 5 / 0 6 / 5 7` → `3`
  - (종료 빠른 순으로 `1 3` → `3 5` → `5 7` 선택 → 3개)

- **셀프체크**: 최선 기준은 "시작 시각"이 아니라 "종료 시각이 이른 회의"부터 고르는 것이다. 왜 종료가 이른 것을 먼저 잡아야 뒤에 더 많은 회의를 넣을 여지가 남는지 스스로 논증해 보자. 정렬 후, 마지막으로 고른 회의의 종료 시각 이후에 시작하는 회의를 만날 때마다 선택. 시작=종료가 같을 때 허용하는 경계(`s >= last_end`)에 주의.

```runner
@@SOLUTION
import sys
input = sys.stdin.readline
n = int(input())
meets = []
for _ in range(n):
    s, e = map(int, input().split())
    meets.append((s, e))
meets.sort(key=lambda x: (x[1], x[0]))
count = 0
last_end = -10**18
for s, e in meets:
    if s >= last_end:
        count += 1
        last_end = e
print(count)
@@TESTS
--IN
3
1 4
3 5
5 7
--OUT
2
--IN
5
1 3
2 4
3 5
0 6
5 7
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 활동 선택(activity selection) 그리디. "종료 시각이 이른 회의"를 먼저 확정하면, 남는 시간 축이 최대로 넓어져 이후 더 많은 회의를 담을 수 있다.
- 교환 논증: 어떤 최적해의 첫 회의를 "가장 일찍 끝나는 회의"로 바꿔도 겹침이 늘지 않으므로 손해가 없다.

(2) 코드 단계별

- 회의 수 `n`을 읽고 각 `(s, e)`를 저장.
- 종료 시각 오름차순(동률이면 시작 오름차순)으로 정렬.
- `last_end`를 아주 작은 값으로 두고, 순서대로 보며 `s >= last_end`이면 선택하고 `count`를 늘린 뒤 `last_end = e`로 갱신.
- 경계: 앞 회의 종료 == 다음 회의 시작이면 겹치지 않으므로 `>=`를 쓴다.

(3) 스스로 다시 짤 때 생각 순서

- "많이 담기 = 자리를 빨리 비우기"를 떠올려 종료 기준 정렬을 정한다.
- 마지막 종료 시각 하나만 상태로 들고 훑는다.
- 경계 조건(같을 때 허용)을 예제로 확인한다.
```

**3) 거스름돈 최소 동전** · Medium

- **요구사항**: 사용할 수 있는 동전 단위들이 주어진다. 이 단위들은 "큰 단위가 항상 작은 단위들의 배수"인 성질을 만족한다. 금액 `money`를 거슬러 줄 때 필요한 최소 동전 개수를 구한다.

- **입력**: 첫 줄에 동전 종류 수 `t`. 둘째 줄에 `t`개의 동전 단위가 공백으로 주어진다(오름차순 또는 임의 순서). 셋째 줄에 금액 `money`. (단위들은 배수 성질을 만족한다고 가정)

- **출력**: 최소 동전 개수.

- **예제**: `4 / 10 50 100 500 / 1260` → `6`

- **예제**: `3 / 1 5 25 / 30` → `2`
  - (25 한 개 + 5 한 개 = 30 → 2개)

- **셀프체크**: 배수 성질이 있으므로 "가장 큰 단위부터 최대한" 쓰는 그리디가 항상 최선이다. 입력 단위가 정렬돼 있지 않을 수 있으니 내림차순 정렬 후 진행. 배수 성질이 없는 일반 화폐라면 이 그리디가 틀린다는 점(예: 단위 `1,3,4`로 `6` 만들기)도 기억해 두자.

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split("\n")
t = int(data[0])
coins = list(map(int, data[1].split()))
money = int(data[2])
coins.sort(reverse=True)
count = 0
for c in coins:
    count += money // c
    money %= c
print(count)
@@TESTS
--IN
4
10 50 100 500
1260
--OUT
6
--IN
3
1 5 25
30
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- 배수 체계(canonical coin system)에서는 "큰 단위를 최대한 많이" 쓰는 그리디가 항상 최적이다. 큰 단위 하나를 작은 단위 여러 개로 바꾸면 개수가 늘기만 하기 때문.

(2) 코드 단계별

- 종류 수, 단위 목록, 금액을 순서대로 읽는다.
- 단위를 내림차순 정렬(입력이 정렬돼 있지 않을 수 있음).
- 큰 단위부터 `money // c`개 사용하고 `money %= c`로 나머지를 남긴다. 사용 개수를 `count`에 누적.
- 총 개수를 출력.

(3) 스스로 다시 짤 때 생각 순서

- "배수 성질 → 큰 것부터" 규칙을 먼저 확정.
- 정렬 방향(내림차순)을 놓치지 않는다.
- 몫과 나머지 두 줄로 각 단위를 처리한다.
```

## L2. 고려해야 할 대상이 뚜렷이 정해지는 경우

**개념**

- 이 레슨의 유형은 "무엇을 최선으로 할지"보다, "답이 될 수 있는 후보가 사실은 아주 적다"는 관찰이 핵심이다. 모든 경우를 다 보지 않고, 논리로 후보를 몇 개로 좁힌 뒤 그것만 확인한다.

- 자주 나오는 형태: 답은 반드시 "양 끝 중 하나", "가장 큰 값 또는 가장 작은 값", "정렬했을 때 가운데 값", "인접한 두 원소 사이" 같은 특정 위치에서만 나온다는 성질을 이용한다.

- 즉, "전부 다 시도"에서 "논리로 후보를 좁혀 몇 개만 시도"로 바꾸는 사고다. 후보가 상수 개(예: 2~3개)로 줄면 계산은 거의 즉시 끝난다.

```python
# 예: 수직선 위 여러 점에서 한 점까지 거리 합을 최소로 하는 위치는
# "정렬했을 때 가운데 값(중앙값)"이다. 모든 위치를 다 볼 필요가 없다.
xs = [1, 2, 9, 4, 5]
xs.sort()                 # [1, 2, 4, 5, 9]
mid = xs[len(xs) // 2]    # 가운데 값 = 4  (홀수 개일 때)
```

**접근 전략**

- 절차: (1) "답이 될 수 있는 위치/값이 어디인가"를 먼저 묻는다. (2) 작은 예를 그려 최적점이 항상 특정 위치(끝, 최대/최소, 중앙값, 인접 쌍 등)에 걸리는지 관찰한다. (3) 그 관찰이 참인 이유를 간단히 논증한다. (4) 후보만 골라 값을 계산·비교한다.

- 언제 쓰나: "가장 가까운 두 값의 차", "합이 목표에 가장 가까운 쌍", "한 점으로 모을 때 비용 최소" 같은 문제. 후보를 좁히는 흔한 무기는 "먼저 정렬"이다. 정렬하면 인접한 것들만 비교하면 되거나, 양 끝·가운데가 답이 되는 구조가 드러난다.

- 주의·복잡도: 정렬 `O(n log n)` + 후보 확인 `O(n)` 또는 `O(1)`. 함정은 "후보가 정말 그것뿐인가"의 논증을 건너뛰는 것. 짝수 개의 중앙값, 동점 처리, 후보가 두 개(둘 다 계산해 더 나은 쪽)인 경우 등 경계를 반드시 확인한다.

**문제**

**1) 가장 가까운 두 수의 차** · Easy

- **요구사항**: `n`개의 정수가 주어진다. 서로 다른 두 수를 골랐을 때 두 값의 차(절댓값)가 가장 작은 값을 구한다.

- **입력**: 첫 줄에 `n`. 둘째 줄에 `n`개의 정수가 공백으로 주어진다. (`n ≥ 2`)

- **출력**: 가능한 두 수 차의 최솟값.

- **예제**: `5 / 1 9 4 2 8` → `1`
  - (정렬하면 `1 2 4 8 9`, 인접 차 `1,2,4,1` 중 최소 1)

- **예제**: `3 / 10 3 20` → `7`
  - (정렬 `3 10 20`, 인접 차 `7,10` 중 최소 7)

- **셀프체크**: 모든 쌍(`O(n^2)`)을 볼 필요가 없다. 정렬하면 "차가 최소인 쌍은 반드시 인접한 두 원소"라는 성질이 생긴다 — 이유를 스스로 설명해 보자. 정렬 후 이웃끼리의 차만 비교하면 `O(n log n)`. 중복 값이 있으면 차가 0이 될 수 있음도 확인.

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
xs = list(map(int, data[1:1 + n]))
xs.sort()
best = min(xs[i + 1] - xs[i] for i in range(n - 1))
print(best)
@@TESTS
--IN
5
1 9 4 2 8
--OUT
1
--IN
3
10 3 20
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 정렬하면 값이 오름차순으로 놓이고, 최소 차이는 반드시 "정렬 후 인접한 두 원소" 사이에서 생긴다. 떨어진 두 원소 사이에는 그 사이 값이 끼어 있어 차가 더 클 수밖에 없기 때문.

(2) 코드 단계별

- `n`과 정수 목록을 읽는다.
- 오름차순 정렬.
- 인접한 쌍 `xs[i+1] - xs[i]`를 모두 계산해 최솟값을 취한다.
- 그 값을 출력. (정렬 후라 차는 음수가 아님)

(3) 스스로 다시 짤 때 생각 순서

- "모든 쌍 대신 인접 쌍만"이라는 관찰을 먼저 확신한다.
- 정렬 → 이웃 차 순회 → min 이라는 3단계로 압축한다.
- 중복 값이면 차 0이 나올 수 있음을 예상한다.
```

**2) 한 점으로 모으기(최소 이동)** · Medium

- **요구사항**: 수직선 위 서로 다른 위치에 사람들이 서 있다. 모두가 한 정수 좌표로 모일 때, 각자 이동 거리의 합이 최소가 되도록 하는 그 합을 구한다.

- **입력**: 첫 줄에 사람 수 `n`. 둘째 줄에 각 사람의 좌표 `n`개가 공백으로 주어진다.

- **출력**: 이동 거리 합의 최솟값.

- **예제**: `3 / 1 2 9` → `8`
  - (중앙값 2로 모으면 `|1-2|+|2-2|+|9-2| = 1+0+7 = 8`)

- **예제**: `4 / 1 2 4 5` → `6`
  - (짝수 개: 가운데 두 값 2,4 사이 어디든 최소. 2에 모으면 `1+0+2+3=6`, 4에 모으면 `3+2+0+1=6`)

- **셀프체크**: 최적 모임 위치는 "중앙값"이다. 후보는 사실상 정렬 후 가운데 값 하나(홀수 개)뿐. 짝수 개일 때는 가운데 두 값 사이 어디든 같은 최소이므로, 둘 중 아무거나(예: `xs[n//2]`)로 계산하면 된다. 왜 평균이 아니라 중앙값인지 작은 예로 확인해 보자.

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split()
n = int(data[0])
xs = list(map(int, data[1:1 + n]))
xs.sort()
m = xs[n // 2]
print(sum(abs(x - m) for x in xs))
@@TESTS
--IN
3
1 2 9
--OUT
8
--IN
4
1 2 4 5
--OUT
6
@@EXPL
(1) 접근·핵심 아이디어

- 절댓값 거리 합을 최소로 하는 지점은 중앙값이다. 어떤 지점을 중앙값 쪽으로 옮기면, 왼쪽/오른쪽 점 개수의 차이만큼 총거리가 줄어들어 중앙값에서 최소가 된다.
- 짝수 개면 가운데 두 값 사이 어디든 같은 최소이므로 `xs[n//2]` 하나로 계산해도 답이 같다.

(2) 코드 단계별

- `n`과 좌표 목록을 읽는다.
- 정렬 후 `m = xs[n // 2]`를 중앙값 후보로 잡는다.
- 각 좌표에서 `m`까지의 절댓값 거리를 모두 더해 출력.

(3) 스스로 다시 짤 때 생각 순서

- "평균이 아니라 중앙값"임을 작은 예로 먼저 확인한다.
- 정렬 → 가운데 인덱스 선택 → 거리 합 순으로 작성한다.
- 짝수/홀수 모두 `xs[n//2]`로 통일해도 되는지 검산한다.
```

**3) 합이 목표에 가장 가까운 두 수** · Hard

- **요구사항**: `n`개의 정수와 목표값 `T`가 주어진다. 서로 다른 두 수를 골라 그 합이 `T`에 가장 가까울 때, 그 합을 구한다. `T`와의 차가 같은 후보가 여럿이면 합이 더 작은 것을 답으로 한다.

- **입력**: 첫 줄에 `n`과 `T`가 공백으로 주어진다. 둘째 줄에 `n`개의 정수가 공백으로 주어진다. (`n ≥ 2`)

- **출력**: `T`에 가장 가까운 두 수의 합.

- **예제**: `5 10 / 1 3 5 8 12` → `9`
  - (정렬 `1 3 5 8 12`. 합 후보 중 `1+8=9`, `1+12=13`은 차 3, `3+5=8`은 차 2 ... 실제 최소 차는 `3+8=11`(차1)과 `1+8=9`(차1). 차가 같으면 작은 합 9)

- **예제**: `4 6 / 2 2 4 7` → `6`
  - (`2+4=6` 정확히 일치 → 6)

- **셀프체크**: 모든 쌍 `O(n^2)`도 가능하지만, 정렬 후 양 끝에서 좁혀 오는 투 포인터로 `O(n log n)`에 풀 수 있다. 두 포인터 합이 `T`보다 크면 오른쪽 포인터를 왼쪽으로, 작으면 왼쪽 포인터를 오른쪽으로 옮기며, 지날 때마다 "`T`와의 차, 동점이면 합이 작은 쪽" 기준으로 최선을 갱신한다. 첫 예제의 검산처럼 동점 처리 규칙을 꼭 반영할 것.

```runner
@@SOLUTION
import sys
data = sys.stdin.read().split("\n")
n, T = map(int, data[0].split())
xs = list(map(int, data[1].split()))
xs.sort()
i, j = 0, n - 1
best_sum = None
while i < j:
    cur = xs[i] + xs[j]
    if best_sum is None:
        best_sum = cur
    else:
        d_cur = abs(cur - T)
        d_best = abs(best_sum - T)
        if d_cur < d_best or (d_cur == d_best and cur < best_sum):
            best_sum = cur
    if cur == T:
        break
    elif cur > T:
        j -= 1
    else:
        i += 1
print(best_sum)
@@TESTS
--IN
5 10
1 3 5 8 12
--OUT
9
--IN
4 6
2 2 4 7
--OUT
6
@@EXPL
(1) 접근·핵심 아이디어

- 정렬한 뒤 양 끝 포인터를 쓰면, 합이 크면 오른쪽을 줄이고 작으면 왼쪽을 키우며 단조롭게 `T`에 접근할 수 있다. 매 단계의 합이 후보이므로 그때마다 최선을 갱신한다.
- 동점 규칙: `T`와의 차가 같으면 합이 더 작은 쪽을 택한다.

(2) 코드 단계별

- `n`, `T`와 정수 목록을 읽고 오름차순 정렬.
- `i=0`, `j=n-1`에서 시작. 두 포인터가 만나기 전까지 반복.
- 현재 합 `cur`을 계산하고, `|cur-T|`가 더 작거나(동점이면 `cur`이 더 작으면) 최선을 갱신.
- `cur == T`면 완벽하므로 종료. `cur > T`면 `j`를 줄이고, 아니면 `i`를 늘린다.
- 최종 `best_sum` 출력.

(3) 스스로 다시 짤 때 생각 순서

- "정렬 + 투 포인터로 O(n)"을 먼저 떠올린다.
- 갱신 조건에 동점 처리(더 작은 합)를 반드시 넣는다.
- 포인터 이동 방향(합이 크면 j--, 작으면 i++)을 정확히 맞춘다.
```

> 개요: 완전탐색(brute force)의 첫걸음으로, 답이 될 수 있는 후보를 하나도 빠짐없이 훑어보는 세 가지 기본 뼈대를 익힌다. 한 수씩 훑는 "자리 수 단위", 연속 구간을 훑는 "구간 단위", 각 칸의 값을 조합으로 정하는 "자리마다 숫자 정하기" 완전탐색이다.

## L1. 자리 수 단위로 완전탐색

**개념**

- 완전탐색은 "가능한 후보를 하나도 빠뜨리지 않고 전부 확인"하는 전략이다. 똑똑한 지름길 대신, 모든 경우를 정직하게 세어 정답을 찾는다.
- "자리 수 단위"란 정수 하나하나(또는 한 개의 대상 하나하나)를 후보로 놓고, 범위 안의 모든 수를 순회하며 조건을 검사하는 가장 기본적인 형태다.
- 핵심 도구는 정수를 "자릿수의 나열"로 다루는 것이다. 각 자리 숫자를 꺼내야 조건(자릿수 합, 특정 숫자 포함, 대칭 여부 등)을 검사할 수 있다.

```python
# 정수 n의 각 자리 숫자를 다루는 두 가지 방법
n = 4720

# 방법 A: 문자열로 바꿔서 한 글자씩
for ch in str(n):
    d = int(ch)   # 4, 7, 2, 0 순서로 나옴

# 방법 B: 10으로 나눠가며 뒤에서부터
m = n
while m > 0:
    d = m % 10    # 0, 2, 7, 4 순서(맨 뒷자리부터)
    m //= 10
```

**접근 전략**

- 절차는 항상 같다. (1) 후보 범위를 for로 순회한다 → (2) 각 후보에서 필요한 값을 계산한다(자릿수 합, 특정 숫자 포함 여부 등) → (3) 조건을 만족하면 세거나 기록한다.
- "자릿수를 봐야 하는 조건"이면 대개 `str(n)`으로 바꿔 한 글자씩 보는 방법 A가 가장 짧고 실수가 적다. 자릿수의 합·개수·포함 여부는 이 패턴 하나로 거의 다 처리된다.
- 언제 쓰나: 답 후보의 개수가 "직접 다 세도 될 만큼" 적을 때. 범위가 1부터 N까지면 시간복잡도는 O(N × 자릿수)이고, N이 수백만 이하면 충분히 빠르다. 자릿수는 최대 10 정도라 사실상 O(N)으로 봐도 된다.
- 함정: 경계 포함 여부(a 이상 b "이하"인지 미만인지), 그리고 0이나 음수가 범위에 들어올 때의 처리다. 문제 문장의 "이상/이하"를 그대로 `range(a, b+1)`로 옮겨라.

**문제**

**1) 자릿수 합의 배수** · Easy

- **요구사항**: 정수 a, b, k가 주어진다. a 이상 b 이하의 정수 중에서, 각 자리 숫자의 합이 k의 배수인 수가 몇 개인지 센다.
- **입력**: 첫 줄에 세 정수 a, b, k (1 ≤ a ≤ b ≤ 100000, 1 ≤ k ≤ 50).
- **출력**: 조건을 만족하는 수의 개수.
- **예제**: `10 20 3` → `3`  (12, 15, 18의 자릿수 합은 각각 3, 6, 9로 모두 3의 배수), `1 100 5` → `13`
- **셀프체크**: a, b가 모두 포함(이하/이상)인가? k의 배수에는 자릿수 합이 0이 되는 경우가 없으니 신경 쓸 필요는 없지만, 배수 판정은 `합 % k == 0`으로 정확히.

```runner
@@SOLUTION
a, b, k = map(int, input().split())
cnt = 0
for n in range(a, b + 1):
    s = sum(int(c) for c in str(n))
    if s % k == 0:
        cnt += 1
print(cnt)
@@TESTS
--IN
10 20 3
--OUT
3
--IN
1 30 3
--OUT
10
@@EXPL
(1) 접근·핵심 아이디어

- 범위가 최대 10만이라 a부터 b까지 전부 훑어도 충분한 완전탐색이다. 각 수마다 "자릿수 합"을 구해 k로 나누어떨어지는지만 보면 된다.
- 자릿수 합은 `str(n)`으로 바꿔 한 글자씩 int로 더하는 방법 A가 가장 짧고 실수가 적다.

(2) 코드 단계별

- `range(a, b + 1)`로 a와 b를 모두 포함해 순회한다(문장의 "이상/이하"를 그대로 옮김).
- `sum(int(c) for c in str(n))`으로 각 자리 숫자의 합을 구한다.
- `s % k == 0`이면 배수이므로 카운터를 1 늘리고, 마지막에 개수를 출력한다.

(3) 스스로 다시 짤 때 생각 순서

- "후보를 다 돌아도 되나?" → N이 10만이므로 O(N×자릿수)면 가볍다.
- "각 후보에서 뭘 계산?" → 자릿수 합 하나. 문자열 변환으로 한 줄.
- "조건은?" → 나머지가 0이면 세기. 경계는 `b + 1`을 잊지 말 것.

참고: 두 번째 케이스 `1 30 3`은 정답 코드로 실행하면 10(3,6,9,...,30)이다.
```

**2) 숫자 7이 들어간 수** · Easy

- **요구사항**: a 이상 b 이하의 정수 중에서, 십진 표기에 숫자 7이 한 번이라도 등장하는 수의 개수를 구한다.
- **입력**: 첫 줄에 두 정수 a, b (1 ≤ a ≤ b ≤ 1000000).
- **출력**: 숫자 7을 포함하는 수의 개수.
- **예제**: `1 50` → `5`  (7, 17, 27, 37, 47), `70 80` → `10`  (70~79는 모두 7 포함, 80은 제외)
- **셀프체크**: "포함"은 자리 중 하나라도 7이면 참이다. `'7' in str(n)` 한 줄로 판정된다. 77처럼 7이 두 번 나와도 개수는 1로만 센다(수 자체를 세는 것이지 7의 개수가 아님).

```runner
@@SOLUTION
a, b = map(int, input().split())
cnt = 0
for n in range(a, b + 1):
    if '7' in str(n):
        cnt += 1
print(cnt)
@@TESTS
--IN
1 50
--OUT
5
--IN
70 80
--OUT
10
@@EXPL
(1) 접근·핵심 아이디어

- 후보를 전부 훑는 완전탐색. "십진 표기에 7이 들어가는가"는 자리 중 하나라도 7이면 참이므로, 수를 문자열로 보고 부분 문자열 포함 검사를 하면 끝이다.
- `'7' in str(n)`은 어느 자리에 7이 있든 True를 돌려주므로 자리별 루프가 필요 없다.

(2) 코드 단계별

- `range(a, b + 1)`로 a, b 포함 순회.
- 각 n을 `str(n)`으로 바꾸고 `'7' in ...`으로 7 포함 여부를 판정.
- 참이면 카운터 증가. 77처럼 7이 둘이어도 조건은 한 번만 참이 되어 1만 더해진다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇을 후보로?" → a~b의 각 정수.
- "조건 판정을 가장 간단히?" → 문자열 포함 검사 한 줄.
- "중복 주의?" → 수 자체를 세므로 7이 여러 번이어도 1. 검증: 70~79는 10개 모두 포함(70~79) → 정답 10.
```

**3) 회문 수 세기** · Medium

- **요구사항**: a 이상 b 이하의 정수 중, 앞에서 읽으나 뒤에서 읽으나 같은 수(회문, palindrome)의 개수를 구한다. 예: 121, 33은 회문, 120은 아니다.
- **입력**: 첫 줄에 두 정수 a, b (1 ≤ a ≤ b ≤ 100000).
- **출력**: 회문 수의 개수.
- **예제**: `10 130` → `12`  (11, 22, 33, 44, 55, 66, 77, 88, 99, 101, 111, 121), `1 9` → `9`  (한 자리 수는 모두 회문)
- **셀프체크**: 한 자리 수도 회문으로 센다. 뒤집기는 `s == s[::-1]`로 간단히. 10, 20처럼 0으로 끝나는 수는 절대 회문이 될 수 없음을 검산으로 확인해 보라(뒤집으면 0으로 시작).

```runner
@@SOLUTION
a, b = map(int, input().split())
cnt = 0
for n in range(a, b + 1):
    s = str(n)
    if s == s[::-1]:
        cnt += 1
print(cnt)
@@TESTS
--IN
10 130
--OUT
12
--IN
1 9
--OUT
9
@@EXPL
(1) 접근·핵심 아이디어

- 회문 판정은 "문자열을 뒤집어도 같은가"이다. 파이썬은 `s[::-1]`로 문자열을 한 번에 뒤집을 수 있으니 `s == s[::-1]` 한 줄이면 된다.
- a부터 b까지 모두 순회하며 회문인 수만 센다.

(2) 코드 단계별

- 각 n을 문자열 s로 변환.
- `s[::-1]`은 s를 뒤집은 문자열. 원본과 같으면 회문.
- 한 자리 수(예: 1~9)는 뒤집어도 자기 자신이라 모두 회문으로 세어진다.

(3) 스스로 다시 짤 때 생각 순서

- "판정을 어떻게?" → 슬라이스 뒤집기 `[::-1]`로 대칭 검사.
- "경계 케이스?" → 한 자리 수는 전부 회문(둘째 케이스 1~9 = 9개).
- "0으로 끝나는 수?" → 10,20,... 은 뒤집으면 앞이 0이라 절대 회문 아님. 10~130 사이 회문은 11,22,...,99,101,111,121 총 12개.
```


## L2. 구간 단위로 완전탐색

**개념**

- 이번엔 후보가 "하나의 수"가 아니라 배열의 "연속된 구간(부분 수열, subarray)"이다. 배열에서 연속으로 이어진 한 토막을 골라 그 안의 값들을 검사한다.
- 길이 N인 배열에서 연속 구간은 시작점 i와 끝점 j로 정해진다(i ≤ j). 모든 (i, j) 쌍을 이중 for로 훑는 것이 구간 단위 완전탐색의 뼈대다.
- 구간의 개수는 약 N(N+1)/2개다. 이 모든 구간을 만들어 보고, 각 구간의 합·최대·최소 같은 값으로 조건을 판정한다.

```python
n = len(arr)
for i in range(n):          # 구간 시작
    s = 0
    for j in range(i, n):   # 구간 끝을 하나씩 늘림
        s += arr[j]         # arr[i..j] 구간의 합을 누적으로 유지
        # 여기서 구간 arr[i..j]에 대한 조건을 검사
```

**접근 전략**

- 핵심 아이디어: 끝점 j를 한 칸씩 늘릴 때, 구간 합은 매번 `arr[j]`만 더하면 된다. 매 구간마다 `sum(arr[i:j+1])`을 새로 부르면 느려지므로, 안쪽 루프에서 누적 변수 s를 굴리는 습관을 들여라.
- 길이가 "정확히 L"인 구간만 필요하면 시작점 i만 훑으면 된다: 구간은 `arr[i:i+L]`이고 i는 0부터 N−L까지. 이건 O(N)짜리 슬라이딩이다.
- 언제 쓰나: "연속 구간 중 조건을 만족하는 것의 개수/최댓값/최장 길이"를 물을 때. 모든 (i, j)를 도는 이중 루프는 O(N²), 각 구간에서 추가로 max/min을 다시 계산하면 O(N³)까지 커진다. N이 수천 이하일 때 안전하다.
- 함정: 구간의 경계다. `arr[i:j+1]`은 j를 포함하지만, `range(i, n)`의 j는 인덱스이므로 슬라이스 끝은 반드시 `j+1`이다. 빈 구간을 세면 안 되는지도 확인하라(보통 길이 1 이상).

**문제**

**1) 길이 L 구간의 최대 합** · Easy

- **요구사항**: 길이 N인 정수 배열과 정수 L이 주어진다. 연속한 L개의 원소로 이루어진 구간들 중 합이 가장 큰 값을 구한다.
- **입력**: 첫 줄에 N과 L (1 ≤ L ≤ N ≤ 100000). 둘째 줄에 N개의 정수(각 절댓값 10000 이하).
- **출력**: 길이 L 구간의 최대 합.
- **예제**: `7 2` / `3 -1 4 -1 5 -9 2` → `4`  (구간 합은 2, 3, 3, 4, −4, −7이고 최댓값은 [−1,5]의 4), `5 3` / `1 2 3 4 5` → `12`  ([3,4,5])
- **셀프체크**: 시작점 i는 0부터 N−L까지만 유효하다(그 뒤엔 L개가 안 남음). 합에 음수가 있으니 최댓값 초기값을 0이 아니라 "첫 구간 합" 또는 아주 작은 값으로 잡아라.

```runner
@@SOLUTION
n, L = map(int, input().split())
arr = list(map(int, input().split()))
s = sum(arr[:L])
best = s
for i in range(1, n - L + 1):
    s += arr[i + L - 1] - arr[i - 1]
    if s > best:
        best = s
print(best)
@@TESTS
--IN
7 2
3 -1 4 -1 5 -9 2
--OUT
4
--IN
5 3
1 2 3 4 5
--OUT
12
@@EXPL
(1) 접근·핵심 아이디어

- 길이가 정확히 L인 연속 구간의 최대 합. 시작점 i만 훑으면 되므로 O(N) 슬라이딩 윈도우로 풀 수 있다.
- 창을 한 칸 옮길 때 합은 "새로 들어온 원소를 더하고, 빠진 원소를 뺀다"로 갱신하면 매번 다시 sum 하지 않아도 된다.

(2) 코드 단계별

- 첫 창 `arr[:L]`의 합 s를 구하고 best를 그 값으로 초기화(음수 대비, 0으로 두지 않음).
- i를 1부터 N−L까지 옮기며 `s += arr[i+L-1] - arr[i-1]`로 합을 갱신.
- 매 창마다 best를 갱신하고 마지막에 출력.

(3) 스스로 다시 짤 때 생각 순서

- "고정 길이 창?" → 시작점만 이동, 인덱스 상한은 N−L.
- "합 재계산을 피하려면?" → 들어온 것 더하고 나간 것 빼기.
- "초기 best?" → 첫 창 합(음수 구간 대비). 첫 케이스: 창 합 2,3,3,4,-4,-7 → 최대 4.
```

**2) 합이 target인 연속 구간의 개수** · Medium

- **요구사항**: 정수 배열에서, 원소들의 합이 정확히 target이 되는 "연속 구간"이 몇 개인지 센다. 시작·끝 위치가 다르면 서로 다른 구간으로 센다.
- **입력**: 첫 줄에 N과 target (1 ≤ N ≤ 2000). 둘째 줄에 N개의 정수(각 절댓값 1000 이하).
- **출력**: 합이 target인 연속 구간의 개수.
- **예제**: `5 3` / `1 2 3 1 2` → `3`  (구간 [1,2]=3, [3]=3, [1,2]=3의 세 곳), `4 4` / `2 2 2 2` → `3`  ([2,2]가 세 곳)
- **셀프체크**: 서로 겹치거나 원소를 공유해도 위치가 다르면 별개로 센다. 안쪽 루프에서 s를 누적하면 O(N²)로 충분하다. 음수가 있으면 "합이 target을 넘으면 멈춘다" 같은 조기 종료를 하면 안 된다(뒤에서 다시 줄어들 수 있음).

```runner
@@SOLUTION
n, target = map(int, input().split())
arr = list(map(int, input().split()))
cnt = 0
for i in range(n):
    s = 0
    for j in range(i, n):
        s += arr[j]
        if s == target:
            cnt += 1
print(cnt)
@@TESTS
--IN
5 3
1 2 3 1 2
--OUT
3
--IN
4 4
2 2 2 2
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 모든 연속 구간 (i, j)를 이중 for로 훑는 구간 단위 완전탐색. 위치가 다르면 값이 같아도 다른 구간이므로 그냥 다 세면 된다.
- 안쪽 루프에서 끝점 j를 늘릴 때마다 `arr[j]`만 누적해 O(N²)로 유지한다(매번 slice sum을 부르지 않는다).

(2) 코드 단계별

- 시작점 i마다 s를 0으로 초기화.
- 끝점 j를 i부터 늘리며 `s += arr[j]`로 구간 arr[i..j]의 합을 유지.
- `s == target`이면 카운터 증가. 음수가 있을 수 있으니 조기 종료(break)는 하지 않는다.

(3) 스스로 다시 짤 때 생각 순서

- "무엇을 후보로?" → 모든 (i, j) 연속 구간.
- "합을 싸게 유지?" → 안쪽 루프에서 누적 변수 s.
- "중복 세기?" → 위치 기준이라 값이 같아도 별개. 둘째 케이스 2 2 2 2에서 [2,2]가 3곳 → 3.
```

**3) 최댓값−최솟값 ≤ d인 최장 구간** · Medium

- **요구사항**: 배열에서 "구간 내 최댓값과 최솟값의 차이가 d 이하"인 연속 구간 중 가장 긴 것의 길이를 구한다.
- **입력**: 첫 줄에 N과 d (1 ≤ N ≤ 2000, 0 ≤ d ≤ 100000). 둘째 줄에 N개의 정수.
- **출력**: 조건을 만족하는 가장 긴 구간의 길이.
- **예제**: `7 2` / `5 3 4 6 8 7 7` → `4`  (구간 [6,8,7,7]은 max 8, min 6, 차이 2), `5 0` / `10 11 12 9 20` → `1`  (모든 원소가 달라 같은 값 구간은 길이 1뿐)
- **셀프체크**: d=0이면 "모두 같은 값"인 구간만 해당한다. 각 구간에서 max/min을 다시 계산하면 O(N³)이지만 N이 2000이면 아슬아슬하니, 안쪽 루프를 늘리며 현재 구간의 max·min을 갱신해 O(N²)로 줄이는 편이 안전하다(새 원소 하나와 비교만 하면 됨).

```runner
@@SOLUTION
n, d = map(int, input().split())
arr = list(map(int, input().split()))
best = 0
for i in range(n):
    mn = mx = arr[i]
    for j in range(i, n):
        if arr[j] < mn:
            mn = arr[j]
        if arr[j] > mx:
            mx = arr[j]
        if mx - mn <= d:
            length = j - i + 1
            if length > best:
                best = length
        else:
            break
print(best)
@@TESTS
--IN
7 2
5 3 4 6 8 7 7
--OUT
4
--IN
5 0
10 11 12 9 20
--OUT
1
@@EXPL
(1) 접근·핵심 아이디어

- 각 시작점 i에서 끝점 j를 늘려가며 구간을 확장한다. 구간의 max와 min은 새 원소 하나와 비교만 하면 갱신되므로 O(N²)로 처리된다(매번 max()/min()을 다시 부르는 O(N³)를 피함).
- max−min이 d를 넘는 순간, 그 시작점 i에서는 j를 더 늘려도 폭이 줄지 않으니 break로 다음 i로 넘어가도 된다(새 원소는 폭을 넓히기만 함).

(2) 코드 단계별

- 시작점 i마다 mn, mx를 arr[i]로 초기화.
- j를 늘리며 arr[j]로 mn, mx 갱신.
- `mx - mn <= d`면 현재 길이 j−i+1로 best 갱신, 아니면 break.

(3) 스스로 다시 짤 때 생각 순서

- "구간 폭을 싸게 유지?" → 확장하며 max/min을 원소 비교로 갱신.
- "언제 멈춰도 되나?" → 폭이 d 초과면 더 늘려도 회복 안 됨 → break.
- "d=0 의미?" → 같은 값만 → 서로 다른 값뿐이면 길이 1(둘째 케이스). 첫 케이스 [6,8,7,7]은 폭 2 → 길이 4.
```


## L3. 자리 마다 숫자를 정하는 완전탐색

**개념**

- 지금까지는 "이미 정해진 수/구간"을 훑었다. 이번엔 우리가 직접 만든다. 여러 개의 "자리(slot)"가 있고, 각 자리에 넣을 값을 후보 집합에서 하나씩 골라 조합을 완성한다.
- 자리가 n개이고 각 자리가 고를 수 있는 값이 m가지면, 가능한 조합은 mⁿ개다. 이 모든 조합을 만들어 조건을 검사하는 것이 "자리마다 숫자를 정하는" 완전탐색이다.
- 자리 수가 고정(2~3개)이면 for를 그만큼 중첩하면 되고, 자리 수가 변수 n이면 `itertools.product`로 mⁿ개를 한 번에 뽑아낼 수 있다.

```python
from itertools import product

digits = [1, 2, 3]      # 각 자리에서 고를 수 있는 값
n = 3                   # 자리 수

# 아래 두 코드는 같은 mⁿ개 조합을 만든다
for a in digits:                 # 자리 수가 고정일 때: for 중첩
    for b in digits:
        for c in digits:
            combo = (a, b, c)    # 이 조합을 검사

for combo in product(digits, repeat=n):   # 자리 수가 변수일 때
    ...                                    # combo = (1,1,1), (1,1,2), ...
```

- 한 줄 요약: `product(digits, repeat=n)`은 "digits로 도는 for를 n번 중첩한 것"과 완전히 같은 mⁿ개 조합을 만든다. 다만 for 중첩은 n을 코드로 바꿔야 하지만 `product`는 n을 변수로 받을 수 있다는 점만 다르다.

**접근 전략**

- 핵심 아이디어: "각 자리에 무엇을 넣을지"를 독립적으로 고른다고 보고, 모든 경우의 수(mⁿ)를 빠짐없이 나열한다. 그런 다음 완성된 조합마다 문제의 조건(인접 자리 규칙, 합, 개수 등)을 검사해 세거나 최선값을 갱신한다.
- 자리 수가 고정이면 for 중첩이 직관적이다. 자리 수가 입력으로 주어지면 중첩 개수를 코드로 못 바꾸므로 `product(집합, repeat=n)`을 쓴다. 이게 이 레슨의 새 도구다.
- 언제 쓰나: "조건을 만족하는 n자리 수/코드/배치의 개수" 같은, 만들어야 할 대상의 크기가 작을 때. 복잡도는 O(mⁿ × 검사비용)이라 지수적이므로 mⁿ이 대략 수백만을 넘지 않는지 먼저 가늠하라(예: m=10, n=6이면 100만).
- 함정: 조합의 개수가 폭발한다. n이나 m이 조금만 커져도 mⁿ이 감당 불가로 커지니, 문제의 범위가 이 방법을 허용하는지 반드시 확인. 또 "맨 앞자리는 0이 될 수 없다" 같은 자리별 제약이 있으면 그 자리의 후보 집합만 다르게 잡아야 한다.

**문제**

**1) 이웃한 자리가 다른 수** · Easy

- **요구사항**: n자리 수를 만든다. 각 자리에는 1부터 d까지의 숫자만 넣을 수 있고, 서로 이웃한 두 자리는 숫자가 달라야 한다. 이런 수가 몇 개 만들어지는지 센다.
- **입력**: 첫 줄에 n과 d (1 ≤ n ≤ 7, 2 ≤ d ≤ 9).
- **출력**: 조건을 만족하는 n자리 수의 개수.
- **예제**: `2 3` → `6`  (첫 자리 3가지 × 다른 값 2가지), `3 2` → `2`  (121, 212 두 개뿐)
- **셀프체크**: n=1이면 이웃이 없으니 모든 d개가 답이다. `product(range(1,d+1), repeat=n)`로 뽑고 인접쌍 `combo[i] != combo[i+1]`을 모두 만족하는지 검사. mⁿ이 최대 9⁷이라 약 480만, 아슬하지만 통과 가능.

```runner
@@SOLUTION
from itertools import product
n, d = map(int, input().split())
cnt = 0
for combo in product(range(1, d + 1), repeat=n):
    ok = True
    for i in range(n - 1):
        if combo[i] == combo[i + 1]:
            ok = False
            break
    if ok:
        cnt += 1
print(cnt)
@@TESTS
--IN
2 3
--OUT
6
--IN
3 2
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- n개의 자리에 각각 1~d를 넣는 모든 조합(dⁿ개)을 `product`로 나열하고, "이웃한 두 자리가 다르다"는 조건을 만족하는 것만 센다.
- 자리 수 n이 입력으로 주어지므로 for를 n번 중첩할 수 없다 → `product(범위, repeat=n)`이 필요한 상황.

(2) 코드 단계별

- `product(range(1, d + 1), repeat=n)`으로 각 자리를 1..d에서 고른 모든 튜플을 생성.
- 각 조합에서 인접쌍 `combo[i] == combo[i+1]`이 하나라도 있으면 탈락(ok=False, break).
- 통과한 조합만 카운트.

(3) 스스로 다시 짤 때 생각 순서

- "자리마다 무엇을?" → 1..d 중 하나. 자리 수가 변수 → product.
- "조건?" → 인접 자리 상이. 하나라도 같으면 즉시 제외.
- "경계?" → n=1이면 인접쌍이 없어 모두 통과(d개). 첫 케이스 2 3: 3×2=6.
```

**2) 합이 T가 되는 배치** · Medium

- **요구사항**: n개의 칸이 있고, 각 칸에는 0부터 m까지의 정수를 하나 넣을 수 있다. 모든 칸의 값의 합이 정확히 T가 되는 배치(순서 구분)의 개수를 구한다.
- **입력**: 첫 줄에 세 정수 n, m, T (1 ≤ n ≤ 6, 0 ≤ m ≤ 9, 0 ≤ T ≤ 54).
- **출력**: 합이 T인 배치의 개수.
- **예제**: `2 3 4` → `3`  ((1,3),(2,2),(3,1)), `3 2 3` → `7`  ((0,1,2)와 그 순열들, (1,1,1) 등 7가지)
- **셀프체크**: 칸의 순서를 구분하므로 (1,3)과 (3,1)은 서로 다른 배치다. `product(range(m+1), repeat=n)`로 전부 뽑아 `sum(combo)==T`인 것을 센다. T가 n×m보다 크면 답은 0임을 검산으로 확인.

```runner
@@SOLUTION
from itertools import product
n, m, T = map(int, input().split())
cnt = 0
for combo in product(range(m + 1), repeat=n):
    if sum(combo) == T:
        cnt += 1
print(cnt)
@@TESTS
--IN
2 3 4
--OUT
3
--IN
3 2 3
--OUT
7
@@EXPL
(1) 접근·핵심 아이디어

- n개의 칸에 각각 0~m을 넣는 모든 배치((m+1)ⁿ개)를 나열하고 합이 T인 것만 센다. 순서를 구분하므로 (1,3)과 (3,1)은 별개.
- 자리 수 n이 변수이므로 `product(range(m+1), repeat=n)`으로 조합을 만든다.

(2) 코드 단계별

- `product(range(m + 1), repeat=n)`으로 각 칸을 0..m에서 고른 모든 튜플 생성.
- 각 조합의 `sum(combo)`가 T와 같으면 카운트.
- 순서 구분은 product가 자동으로 처리(같은 값 집합의 다른 순열이 각각 나옴).

(3) 스스로 다시 짤 때 생각 순서

- "칸마다 무엇을?" → 0..m. 순서 구분 필요 → product 그대로 사용.
- "조건?" → 합 == T. sum 한 방.
- "검산?" → T가 n×m 초과면 0. 첫 케이스 2 3 4: (1,3),(2,2),(3,1) → 3.
```

**3) 정확히 k개가 'A'인 문자열** · Medium

- **요구사항**: 길이 n인 문자열을 만든다. 각 칸에는 'A', 'B', 'C' 중 하나가 들어간다. 이 중 'A'가 정확히 k개인 문자열이 몇 개인지 센다.
- **입력**: 첫 줄에 두 정수 n, k (1 ≤ n ≤ 10, 0 ≤ k ≤ n).
- **출력**: 'A'가 정확히 k개인 문자열의 개수.
- **예제**: `3 1` → `12`  ('A' 자리 3곳 × 나머지 두 칸 각각 B/C 2가지 = 3×4), `2 2` → `1`  ("AA" 하나)
- **셀프체크**: 'A'가 "정확히" k개다(이상/이하가 아님). `product('ABC', repeat=n)`로 뽑아 `combo.count('A')==k`를 센다. 3ⁿ이 최대 3¹⁰≈59049로 가볍다. k=0이면 A가 하나도 없는 경우(2ⁿ개)임을 확인해 보라.

```runner
@@SOLUTION
from itertools import product
n, k = map(int, input().split())
cnt = 0
for combo in product('ABC', repeat=n):
    if combo.count('A') == k:
        cnt += 1
print(cnt)
@@TESTS
--IN
3 1
--OUT
12
--IN
2 2
--OUT
1
@@EXPL
**이 풀이의 새 문법**

- `튜플.count(값)` (문자열도 동일): 그 값이 몇 번 들어 있는지 센다. `combo.count('A')`는 조합 `combo` 안에 `'A'`가 몇 개인지 돌려준다.

(1) 접근·핵심 아이디어

- 길이 n의 문자열은 각 칸을 A/B/C 중 하나로 정하는 배치(3ⁿ개)다. 전부 나열하고 'A'가 정확히 k개인 것만 센다.
- 3ⁿ이 최대 3¹⁰≈5.9만이라 완전탐색이 가볍게 통과한다.

(2) 코드 단계별

- `product('ABC', repeat=n)`으로 각 칸을 A/B/C에서 고른 모든 튜플 생성.
- `combo.count('A')`로 그 조합의 A 개수를 세고, k와 정확히 같으면 카운트.
- "정확히"이므로 이상/이하가 아니라 `== k`.

(3) 스스로 다시 짤 때 생각 순서

- "칸마다 무엇을?" → A,B,C 세 가지 → product('ABC', repeat=n).
- "조건?" → A 개수 == k. count 한 줄.
- "검산?" → k=0이면 A 없음(2ⁿ). 첫 케이스 3 1: A 자리 3곳 × 나머지 2칸 각 2가지 = 3×4 = 12.
```

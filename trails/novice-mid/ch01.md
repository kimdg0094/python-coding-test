> 개요: 문제를 작은 단위로 쪼개어 각각을 함수로 만들면 코드가 짧아지고 검증이 쉬워진다. 이 챕터에서는 값을 반환하지 않는/반환하는 함수, 인자 전달 방식(값 vs 참조), 그리고 변수가 살아있는 범위(스코프)를 다뤄 "함수를 무기로 쓰는 감각"을 기른다.

## L1. 값을 반환하지 않는 함수

**개념**

- 값을 반환하지 않는 함수는 "결과를 돌려주지 않고, 대신 어떤 일(부수 효과)을 수행"하는 함수다. 대표적으로 출력, 로그 남기기, 전역/외부 상태 변경 같은 작업을 담당한다.
- 파이썬에서 `return`이 없거나 `return`만 쓰면 그 함수는 `None`을 반환하는 것과 같다. 즉 "반환값을 안 쓴다"는 뜻이지, 값을 못 만든다는 게 아니다.
- 반복되는 절차(예: 표 그리기, 구분선 찍기, 특정 형식으로 출력)를 함수로 묶으면, 부르는 쪽 코드가 "무엇을 하는지"만 읽혀 가독성이 좋아진다.

```python
def print_line(width):
    print('-' * width)   # 하는 일만 있고 돌려주는 값은 없음

def greet(name, times):
    for _ in range(times):
        print(f"Hello, {name}!")

print_line(10)
greet("Sky", 2)
```

**그림으로 보기**

- 함수를 부르면 그 호출만의 작업 공간(스택 프레임)이 하나 쌓이고, 함수가 끝나면 통째로 사라진다. `greet("Sky", 2)`를 부르는 순간을 세 장면으로 나눠 보면 이렇다.

```text
 +--------------+  +--------------+  +--------------+
 |              |  | greet        |  |              |
 |              |  |  name = "Sky"|  |              |
 |              |  |  times = 2   |  |              |
 +--------------+  +--------------+  +--------------+
 | main         |  | main         |  | main         |
 +--------------+  +--------------+  +--------------+
   (1) before        (2) during        (3) after
```

- (1) 호출 전에는 부르는 쪽(`main`) 프레임만 있다. (2) 호출하는 순간 `greet` 프레임이 그 위에 쌓이고, 매개변수 `name`·`times`는 그 안에서만 산다. (3) 함수가 끝나면 프레임이 통째로 사라지므로 `name`을 바깥에서 읽을 수 없다.
- 값을 반환하지 않는 함수는 (3)에서 위로 올려 보내는 값이 없다. 그 빈자리를 파이썬이 `None`으로 채운다.

```text
  print_line(10)  -->  prints "----------"   -->  returns None
                       (the side effect)          (nothing to use)
```

- 화살표 왼쪽은 "무엇을 시켰나", 오른쪽은 "무엇이 돌아왔나"다. 돌아오는 자리가 비어 있으므로 `x = print_line(10)`으로 받으면 `x`는 `None`이 된다.

**왜 이렇게 되는가**

- **왜 `return`이 없는데도 `None`이 나오나**: 파이썬에서 함수 호출 `f(...)`는 값을 하나 갖는 식(expression)이다. 식은 값이 있어야 계산이 끝나므로, 돌려줄 값을 정하지 않은 함수에도 언어가 기본값 `None`을 채워 넣는다. 그래서 "`return` 없음", "`return`만 있음", "`return None`"은 셋 다 완전히 같은 뜻이다.
- **왜 함수로 감싸도 느려지지 않나**: 호출 한 번의 비용은 프레임 하나를 쌓고 지우는 고정 비용이라 O(1)이다. 전체 복잡도는 함수 "안에서" 도는 횟수가 정한다. `print_line(w)`는 길이 `w`짜리 문자열을 만드니 O(w)이고, 이를 `n`번 부르면 O(n·w)다 — 함수로 쪼갰다는 사실 자체는 여기에 아무 항도 더하지 않는다.
- **왜 매개변수 이름이 바깥과 겹쳐도 안전한가**: 매개변수는 (2)의 프레임에서 태어나 (3)에서 사라지는 이름이다. 바깥에 같은 이름이 있어도 서로 다른 상자에 살기 때문에 덮어쓰지 않는다(규칙 자체는 L4에서 다시 본다).

**접근 전략**

- "이 코드 조각이 값을 계산하는가, 아니면 무언가를 실행(출력/변경)하는가?"를 먼저 구분한다. 실행이 목적이면 반환값 없는 함수가 자연스럽다.
- 전형적 패턴: (1) 여러 곳에서 똑같이 반복되는 출력/작업을 발견 → (2) 달라지는 부분만 매개변수로 뽑아냄 → (3) 함수 하나로 묶고 호출로 대체. 이렇게 하면 형식을 바꿀 때 함수 한 곳만 고치면 된다.
- 언제 쓰나: "출력 형식이 정해진 반복 작업", "여러 번 등장하는 절차"가 보일 때. 반대로 결과 숫자를 나중에 재사용해야 하면 L2의 반환형 함수를 쓴다.
- 주의점: 반환값 없는 함수의 결과를 변수에 담으면 `None`이 들어간다(`x = greet(...)` → `x`는 `None`). 복잡도는 함수 자체가 아니라 "안에서 무슨 일을 하느냐"로 결정된다 — 함수로 감싼다고 느려지지 않는다.

**문제**

**1) 액자 출력기** · Easy

- **요구사항**: 문자열 `s`를 받아 위/아래를 `*` 테두리로 감싸 출력하는, 값을 반환하지 않는 함수를 설계하라. 테두리 길이는 `s`의 길이에 맞춘다. 이 함수를 여러 문자열에 대해 호출한다.
- **입력**: 첫 줄에 문자열 개수 `n`(1 ≤ n ≤ 20). 다음 `n`개 줄에 각각 문자열 `s`(공백 없는 알파벳, 길이 1~30).
- **출력**: 각 문자열마다, `*`로 된 윗줄 / `*내용*`처럼 좌우도 감싼 줄 / `*`로 된 아랫줄을 출력. (좌우 `*` 포함해 테두리 길이는 문자열 길이 + 2)
- **예제**: `2 / hi / code` → 
  ```
  ****
  *hi*
  ****
  ******
  *code*
  ******
  ```
- **셀프체크**: 테두리 길이가 `len(s)+2`인가(좌우 별 포함)? `n`번의 호출마다 함수가 상태를 남기지 않고 매번 똑같이 동작하는가? 반환값을 쓰지 않는데 실수로 `return`으로 값을 돌려받으려 하지 않았는가?

```runner
@@SOLUTION
def frame(s):
    border = '*' * (len(s) + 2)
    print(border)
    print('*' + s + '*')
    print(border)

def main():
    import sys
    data = sys.stdin.read().split()
    n = int(data[0])
    for i in range(1, n + 1):
        frame(data[i])

main()
@@TESTS
--IN
2
hi
code
--OUT
****
*hi*
****
******
*code*
******
--IN
1
a
--OUT
***
*a*
***
@@EXPL
**이 풀이의 새 문법**

- `import sys` / `sys.stdin.read().split()`: 표준입력 전체를 한 번에 읽어 공백 기준으로 모두 잘라 리스트로 만든다. 여러 줄에 걸친 입력을 `input()` 여러 번 대신 한 번에 받을 때 쓴다.

(1) 접근·핵심 아이디어

- 값을 반환하지 않고 "출력만" 하는 함수 `frame(s)` 하나를 만들고, 입력 문자열마다 반복 호출한다.
- 테두리 길이는 좌우 `*`를 포함하므로 `len(s) + 2`다. 윗줄/아랫줄은 같은 별 문자열, 가운데 줄은 `*내용*`.

(2) 코드 단계별

- `border = '*' * (len(s) + 2)`로 위·아래 공통 테두리를 미리 계산.
- 윗줄 → `'*' + s + '*'` → 아랫줄 순서로 `print`. 반환값은 없다(부수 효과만).
- `main`에서 첫 토큰을 `n`으로, 이후 `n`개 토큰을 각각 `frame`에 넘겨 호출.

(3) 스스로 다시 짤 때 생각 순서

- "한 문자열을 감싸 출력하는 일"을 함수로 떼어낸다 → 테두리 길이 공식(`+2`)을 확정 → 세 줄 출력 → 메인에서 개수만큼 반복 호출.
```

**2) 구구단 표 그리기** · Medium

- **요구사항**: 한 줄을 출력하는 "값을 반환하지 않는 함수" `print_row(dan)`를 만들어 그 단의 1~9배를 한 줄에 출력하고, 이를 이용해 `a`단부터 `b`단까지 표를 그려라. 표 자체를 그리는 것도 반환값 없는 함수로 감싸라(함수가 함수를 호출).
- **입력**: 한 줄에 두 정수 `a b`(2 ≤ a ≤ b ≤ 9).
- **출력**: `a`단부터 `b`단까지 각 단을 한 줄로. 한 줄은 `dan*1 dan*2 ... dan*9`를 공백으로 구분.
- **예제**: `2 3` → 
  ```
  2 4 6 8 10 12 14 16 18
  3 6 9 12 15 18 21 24 27
  ```
- **셀프체크**: 한 줄의 마지막 숫자 뒤에 불필요한 공백이 붙지 않는가(예: `' '.join(...)` 활용)? 바깥 함수가 안쪽 함수를 단순히 호출만 하고 반환값에 의존하지 않는가? `a == b`인 경계에서 한 줄만 나오는가?

```runner
@@SOLUTION
def print_row(dan):
    print(' '.join(str(dan * i) for i in range(1, 10)))

def print_table(a, b):
    for dan in range(a, b + 1):
        print_row(dan)

def main():
    a, b = map(int, input().split())
    print_table(a, b)

main()
@@TESTS
--IN
2 3
--OUT
2 4 6 8 10 12 14 16 18
3 6 9 12 15 18 21 24 27
--IN
5 5
--OUT
5 10 15 20 25 30 35 40 45
@@EXPL
**이 풀이의 새 문법**

- `' '.join(...)`: 문자열들을 사이에 지정한 구분자(여기선 공백 한 칸)를 넣어 하나로 이어 붙인다. 마지막 원소 뒤에는 구분자가 붙지 않아 줄 끝 여분 공백이 생기지 않는다.
- `(str(dan * i) for i in range(1, 10))`: 괄호로 감싼 이런 식을 제너레이터 표현식이라 하며, 리스트를 미리 만들지 않고 값을 하나씩 만들어 `join`에 바로 넘겨준다.

(1) 접근·핵심 아이디어

- 함수가 함수를 부르는 구조: 한 줄을 찍는 `print_row(dan)`(반환 없음)을 만들고, 표 전체를 그리는 `print_table(a, b)`가 그 줄 함수를 단순 호출만 한다.
- 줄 끝 공백을 피하려면 각 배수를 문자열로 만들어 `' '.join`으로 이어 붙인다.

(2) 코드 단계별

- `print_row`: `range(1, 10)`으로 1~9배를 만들어 `str(dan * i)`들을 공백으로 join 후 출력.
- `print_table`: `range(a, b + 1)`로 각 단을 돌며 `print_row`를 호출. 반환값을 쓰지 않는다.
- `main`: 두 정수를 읽어 `print_table`에 전달.

(3) 스스로 다시 짤 때 생각 순서

- "한 단을 한 줄로 출력"이라는 최소 단위를 함수로 → `join`으로 공백 처리 → 바깥에서 `a..b` 단을 반복 호출 → `a == b`면 자연히 한 줄만 나옴을 확인.
```

**3) 다층 마름모 로그** · Hard

- **요구사항**: 홀수 `k`를 받아 별(`*`)로 만든 마름모 한 개를 가운데 정렬로 출력하는 반환값 없는 함수를 설계하라. 그리고 여러 개의 `k`에 대해 이 함수를 호출하되, 각 마름모 사이에는 빈 줄 하나를 넣는 별도의 "구분 출력" 함수도 만들어 조합하라.
- **입력**: 첫 줄에 개수 `n`(1 ≤ n ≤ 10). 다음 줄에 `n`개의 홀수 `k`(1 ≤ k ≤ 9, 공백 구분).
- **출력**: 각 `k`에 대한 마름모(폭 `k`가 가장 넓은 가운데 줄). 마름모끼리는 빈 줄 1개로 구분(마지막 마름모 뒤에는 빈 줄 없음).
- **예제**: `1 / 3` → 
  ```
   *
  ***
   *
  ```
  (마름모 1개, `k=3`이므로 3줄, 가운데 폭 3, 좌우에 공백 채움)
- **셀프체크**: 각 줄의 앞쪽 공백 수를 정확히 계산했는가(가운데 줄은 공백 0)? 구분용 빈 줄이 "사이에만" 들어가고 맨 끝에는 안 들어가는가? 마름모 그리기 함수와 구분 함수의 책임이 분리되어 있는가?

```runner
@@SOLUTION
def print_diamond(k):
    mid = k // 2
    for i in range(k):
        width = k - 2 * abs(mid - i)
        pad = (k - width) // 2
        print(' ' * pad + '*' * width)

def print_separator():
    print()

def main():
    n = int(input())
    ks = list(map(int, input().split()))
    for idx, k in enumerate(ks):
        print_diamond(k)
        if idx != len(ks) - 1:
            print_separator()

main()
@@TESTS
--IN
1
3
--OUT
 *
***
 *
--IN
2
1 3
--OUT
*

 *
***
 *
@@EXPL
**이 풀이의 새 문법**

- `abs(값)`: 절댓값(부호를 뗀 크기)을 돌려준다. 예: `abs(-3)`은 `3`.
- `enumerate(리스트)`: 반복하면서 각 원소와 함께 그 순서 번호(0부터)를 짝지어 준다. `for idx, k in enumerate(ks):`는 `idx`가 0,1,2..., `k`가 그 위치의 값이 된다.

(1) 접근·핵심 아이디어

- 마름모 하나를 그리는 반환값 없는 함수 `print_diamond(k)`와, 마름모 사이 빈 줄을 찍는 `print_separator()`를 책임 분리해 만든다.
- 가운데 줄(폭 `k`)에서 위·아래로 갈수록 폭이 2씩 줄어든다. `i`번째 줄의 폭은 `k - 2*|mid - i|`, 앞 공백은 `(k - 폭)//2`.

(2) 코드 단계별

- `mid = k // 2`가 가장 넓은 가운데 줄의 인덱스. 각 줄에서 `width`와 `pad`를 계산해 `' ' * pad + '*' * width`를 출력(별 뒤 공백 없음).
- `print_separator`는 `print()` 한 번으로 빈 줄만 찍는다.
- `main`은 마지막 마름모가 아닐 때만(`idx != len-1`) 구분 줄을 넣어, 끝에는 빈 줄이 안 붙게 한다.

(3) 스스로 다시 짤 때 생각 순서

- 한 마름모의 각 줄 폭·앞공백 공식을 먼저 세운다 → 그리기 함수와 구분 함수를 분리 → 메인에서 "사이에만" 구분 줄이 들어가도록 인덱스 조건을 건다.
```

## L2. 값을 반환하는 함수

**개념**

- 값을 반환하는 함수는 입력을 받아 결과값을 계산해 `return`으로 돌려준다. 돌려받은 값을 변수에 담거나, 다른 함수의 인자로 넘기거나, 조건에서 바로 쓸 수 있다. "계산의 부품"을 만드는 도구다.
- `return`을 만나면 함수는 즉시 끝난다. 이를 이용해 "조건이 맞으면 바로 결과를 돌려주고 나가는" 조기 반환(early return)으로 코드를 간결하게 만들 수 있다.
- 여러 값을 한 번에 돌려주려면 튜플로 반환한다: `return mn, mx`. 부르는 쪽에서 `a, b = f(...)`로 받는다.

```python
def is_prime(x):
    if x < 2:
        return False        # 조기 반환
    d = 2
    while d * d <= x:
        if x % d == 0:
            return False
        d += 1
    return True

def min_max(arr):
    return min(arr), max(arr)   # 두 값 동시 반환
```

**그림으로 보기**

- 값을 반환하는 함수는 프레임이 사라질 때 값 하나를 부르던 자리로 "올려 보낸다". 그래서 호출식 `is_prime(9)`가 통째로 `False`라는 값으로 바뀐다.

```text
  caller                     is_prime(9)
  ------                     -----------
  ok = is_prime(9)  --in-->  d = 2 -> 9 % 2 = 1   (keep going)
                             d = 3 -> 9 % 3 == 0
  ok = False        <-out--  return False         (ends right here)
  if ok: ...
```

- `return`을 만나는 순간 남은 줄은 실행되지 않고 프레임이 사라진다. 이것이 조기 반환이다.
- 여러 값을 돌려줄 때도 위로 올라가는 값은 언제나 **하나**다. 쉼표가 그 여러 값을 튜플 한 덩어리로 묶기 때문이다.

```text
   return min(arr), max(arr)
              |        |
              +---+----+
                  v
              ( 1 , 9 )        # one tuple object goes up
                |   |
                v   v
              ( a , b )        # a, b = min_max(arr) unpacks it
```

**손으로 따라가기**

`is_prime(9)`와 `is_prime(7)`을 나란히 추적한다. 반복은 `d * d <= x`인 동안에만 돈다.

| 단계 | x | d | `d*d <= x` | `x % d` | 다음 동작 |
|---|---|---|---|---|---|
| 1 | 9 | 2 | 4 ≤ 9 참 | 1 | 나누어떨어지지 않음 → `d`를 3으로 |
| 2 | 9 | 3 | 9 ≤ 9 참 | 0 | 약수 발견 → `return False`로 즉시 종료 |
| 1 | 7 | 2 | 4 ≤ 7 참 | 1 | 나누어떨어지지 않음 → `d`를 3으로 |
| 2 | 7 | 3 | 9 ≤ 7 거짓 | — | 반복 탈출 → `return True` |

- `9`는 두 번째 단계에서 바로 끊기고, `7`은 `d`가 √7을 넘는 순간 반복이 끝나 `True`가 된다. 두 경우 모두 `d`를 3까지밖에 보지 않았다.

**왜 이렇게 되는가**

- **왜 `d * d <= x`까지만 봐도 되나**: `x = a × b`로 쪼갤 수 있다면 `a ≤ b`라 두고 볼 때 `a × a ≤ a × b = x`이므로 항상 `a ≤ √x`다. 즉 약수가 하나라도 있으면 √x 이하에 반드시 하나가 있다. √x까지 훑어 하나도 못 찾았다면 그 위에도 없다. 그래서 판정 한 번이 O(√x)다.
- **왜 조기 반환이 안전한가**: `return`은 "이 프레임의 답이 확정됐다"는 선언이다. 9의 약수 3을 찾은 순간 남은 `d`를 아무리 봐도 결론이 바뀔 수 없으므로, 더 도는 것은 낭비일 뿐 정답에 영향을 주지 않는다.
- **왜 `return a, b`가 되나**: 파이썬에서 튜플을 만드는 것은 괄호가 아니라 쉼표다. `return min(arr), max(arr)`는 값 두 개를 `(최솟값, 최댓값)`이라는 튜플 하나로 묶어 돌려준다. 받는 쪽 `a, b = ...`는 그 튜플을 다시 두 이름으로 푸는 언패킹이다.
- **복잡도 조립**: 값 `n`개에 대해 `is_prime`을 부르면 O(n·√max)다. "부품 하나의 비용 × 부른 횟수"로 곱해 어림잡는 습관이 함수 단위 설계의 기본이다.

**접근 전략**

- "이 값을 나중에 또 쓸까?"라고 물어본다. 재사용하거나 조립해야 하면 반환형 함수로 만든다. 함수를 "블랙박스 부품"으로 보고 입력→출력 관계만 명확히 정의하면, 큰 문제를 작은 부품의 조합으로 풀 수 있다.
- 전형적 절차: (1) 반복 판정/계산을 하나의 질문으로 정의(예: "소수인가?", "자릿수 합은?") → (2) 그 질문을 반환형 함수로 구현 → (3) 메인에서는 이 함수를 반복 호출하며 세어보거나 걸러낸다. 판정 함수(`bool` 반환)와 변환 함수(값 반환)를 나눠 생각하면 깔끔하다.
- 언제 쓰나: 어떤 성질을 만족하는 값의 개수를 세거나, 값들을 변환·집계할 때. 조기 반환은 "안 되는 경우를 먼저 걸러내는" 상황에서 특히 강력하다.
- 복잡도 감각: 소수 판정은 `√x`까지만 나눠보므로 한 번에 O(√x). 이 함수를 `n`개 수에 대해 부르면 전체 O(n·√max)로 어림잡는다. 함수화 자체는 비용이 거의 없다.

**문제**

**1) 자릿수 합 필터** · Easy

- **요구사항**: 정수 하나의 자릿수 합을 돌려주는 반환형 함수 `digit_sum(x)`를 설계하라. 이를 이용해 주어진 수들 중 "자릿수 합이 `k`의 배수"인 것의 개수를 세어 출력한다.
- **입력**: 첫 줄에 `n`과 `k`(1 ≤ n ≤ 1000, 1 ≤ k ≤ 50). 다음 줄에 `n`개의 양의 정수(각 1 ≤ v ≤ 10^9, 공백 구분).
- **출력**: 자릿수 합이 `k`로 나누어떨어지는 수의 개수.
- **예제**: `5 3 / 12 9 100 57 23` → `3`  
  (자릿수 합: 12→3, 9→9, 100→1, 57→12, 23→5 · 3의 배수는 3,9,12 → 3개)  
  또 다른 예제: `3 5 / 14 50 99` → `1` (합 5,5,18 중 5의 배수는 5,5 → **2개**)
- **셀프체크**: 위 두 번째 예제를 직접 검산해 보라(14→5, 50→5, 99→18 → 5의 배수는 5,5 두 개이므로 답은 `2`). 자릿수 합 계산에서 `x`가 0일 가능성, 큰 수(10^9)에서도 정수 연산이 정확한지 확인했는가? `k`의 배수 판정에 `% k == 0`을 썼는가?

> 참고: 위 예제의 "1"은 오탈자를 유도하는 함정이다 — 반드시 스스로 자릿수 합을 다시 세어 개수를 확정하라.

```runner
@@SOLUTION
def digit_sum(x):
    s = 0
    while x > 0:
        s += x % 10
        x //= 10
    return s

def main():
    n, k = map(int, input().split())
    vals = list(map(int, input().split()))
    cnt = 0
    for v in vals:
        if digit_sum(v) % k == 0:
            cnt += 1
    print(cnt)

main()
@@TESTS
--IN
5 3
12 9 100 57 23
--OUT
3
--IN
3 5
14 50 99
--OUT
2
@@EXPL
(1) 접근·핵심 아이디어

- "자릿수 합"이라는 계산을 값 반환형 함수 `digit_sum(x)`로 부품화하고, 메인에서는 이 부품을 반복 호출해 조건(합이 `k`의 배수)을 만족하는 개수만 센다.
- 둘째 예제의 정답은 `2`다(14→5, 50→5, 99→18 중 5의 배수는 5,5). 문제 본문의 "1"은 함정.

(2) 코드 단계별

- `digit_sum`: `x % 10`으로 마지막 자리를 떼어 더하고 `x //= 10`으로 자리를 줄이며 0이 될 때까지 반복, 합을 반환.
- `main`: `n, k`와 값 목록을 읽어, 각 값의 자릿수 합을 `% k == 0`으로 판정해 카운트.

(3) 스스로 다시 짤 때 생각 순서

- "자릿수 합"을 독립 함수로 정의하고 작은 수로 검증 → 메인에서 배수 판정(`% k == 0`)만 얹어 개수를 센다 → 예제의 함정 값을 직접 검산해 기대 출력을 확정.
```

**2) 최대공약수 부품** · Medium

- **요구사항**: 두 수의 최대공약수를 돌려주는 반환형 함수 `gcd(a, b)`를 유클리드 호제법으로 설계하라(반복이든 재귀 흉내든 자유, 단 반드시 값을 반환). 이를 부품으로 써서 두 분수 `a/b`, `c/d`의 합을 기약분수로 출력한다.
- **입력**: 한 줄에 네 정수 `a b c d`(1 ≤ 각 값 ≤ 10^6, 분모 `b,d`는 0이 아님).
- **출력**: `a/b + c/d`를 기약분수 `p/q` 형태로. 정수가 되면 `q`는 1로 둔다(예: `3/1`).
- **예제**: `1 2 1 3` → `5/6`  (1/2+1/3 = 3/6+2/6 = 5/6, gcd(5,6)=1)  
  `1 6 1 3` → `1/2`  (1/6+2/6 = 3/6 → gcd(3,6)=3 → 1/2)
- **셀프체크**: 통분 후 분자 `p = a*d + c*b`, 분모 `q = b*d`를 만들고 `g = gcd(p, q)`로 약분했는가? `gcd` 함수가 두 인수 중 하나가 다른 하나로 나누어떨어질 때도 올바른 값을 반환하는가? 합이 정수일 때 `/1`을 정확히 출력하는가?

```runner
@@SOLUTION
def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def main():
    a, b, c, d = map(int, input().split())
    p = a * d + c * b
    q = b * d
    g = gcd(p, q)
    print(f"{p // g}/{q // g}")

main()
@@TESTS
--IN
1 2 1 3
--OUT
5/6
--IN
1 2 1 2
--OUT
1/1
@@EXPL
(1) 접근·핵심 아이디어

- 최대공약수 `gcd(a, b)`를 유클리드 호제법으로 만들어 "약분" 부품으로 재사용한다.
- 두 분수의 합은 통분으로 처리: 분자 `p = a*d + c*b`, 분모 `q = b*d`. 그 뒤 `gcd(p, q)`로 나눠 기약분수로 만든다. 합이 정수면 `q//g == 1`이 되어 자연히 `x/1`로 출력된다.

(2) 코드 단계별

- `gcd`: `b`가 0이 될 때까지 `a, b = b, a % b`를 반복하고 마지막 `a`가 최대공약수.
- `main`: 네 정수를 읽어 `p`, `q`를 만들고 `g = gcd(p, q)`로 약분한 `p//g`, `q//g`를 `p/q` 형식으로 출력.

(3) 스스로 다시 짤 때 생각 순서

- 호제법 `gcd`를 먼저 완성해 단독 테스트 → 통분 공식으로 `p`, `q`를 세운다 → 항상 `gcd`로 약분하면 정수·기약 케이스가 한 번에 처리됨을 확인.
```

**3) 팰린드롬 소수 세기** · Hard

- **요구사항**: 두 개의 반환형 함수 — `is_prime(x)`(소수 판정, `bool` 반환)와 `is_palindrome(x)`(자릿수를 뒤집어도 같은지 판정) — 를 각각 설계하라. 구간 `[L, R]`에서 두 조건을 모두 만족하는 수의 개수를 세어 출력한다.
- **입력**: 한 줄에 두 정수 `L R`(2 ≤ L ≤ R ≤ 100000).
- **출력**: `[L, R]` 안에서 소수이면서 동시에 팰린드롬인 수의 개수.
- **예제**: `10 100` → `1`  (이 범위의 팰린드롬 소수는 11 뿐)  
  `1 20` → `4`  (2, 3, 5, 7 — 한 자리 소수는 모두 팰린드롬 · 11은 20 이하지만 여기서는 L=1이므로 2,3,5,7,11 → 5개?)
- **셀프체크**: 두 번째 예제를 스스로 확정하라 — `[1,20]`의 소수는 2,3,5,7,11,13,17,19이고 이 중 팰린드롬은 2,3,5,7,11 → 정답은 `5`(문제에 적힌 4는 11을 빠뜨린 함정). 판정 함수를 두 개로 나눠 각각 독립적으로 테스트했는가? 소수·팰린드롬 판정을 조기 반환으로 짧게 만들었는가? 전체 복잡도는 대략 O((R−L)·√R)임을 감으로 잡았는가?

```runner
@@SOLUTION
def is_prime(x):
    if x < 2:
        return False
    d = 2
    while d * d <= x:
        if x % d == 0:
            return False
        d += 1
    return True

def is_palindrome(x):
    s = str(x)
    return s == s[::-1]

def main():
    L, R = map(int, input().split())
    cnt = 0
    for x in range(L, R + 1):
        if is_prime(x) and is_palindrome(x):
            cnt += 1
    print(cnt)

main()
@@TESTS
--IN
10 100
--OUT
1
--IN
1 20
--OUT
5
@@EXPL
(1) 접근·핵심 아이디어

- 두 개의 독립 판정 함수 `is_prime`(bool)과 `is_palindrome`(bool)을 각각 만들어, 구간을 훑으며 둘 다 참인 수만 센다.
- `[1,20]`의 정답은 `5`(2,3,5,7,11). 문제 본문의 "4"는 11을 빠뜨린 함정.

(2) 코드 단계별

- `is_prime`: 2 미만이면 조기 반환 `False`, 이후 `d*d <= x`까지 나눠떨어지면 `False`, 끝까지 통과하면 `True`(√x까지만 검사).
- `is_palindrome`: 문자열로 바꿔 뒤집은 것과 같은지 비교.
- `main`: `L..R`를 돌며 `is_prime(x) and is_palindrome(x)`가 참이면 카운트.

(3) 스스로 다시 짤 때 생각 순서

- 소수 판정과 팰린드롬 판정을 따로 완성해 각각 작은 값으로 검증 → 메인에서 두 조건을 `and`로 결합 → 함정 예제를 손으로 세어 기대값을 확정.
```

## L3. Call by value / Call by reference

**개념**

- 함수에 값을 넘길 때 "복사본을 넘기는가(값 전달), 원본을 가리키는 참조를 넘기는가(참조 전달)"에 따라 함수 안에서의 변경이 바깥에 영향을 주는지가 갈린다.
- 파이썬은 엄밀히 "객체 참조를 값으로 전달"한다. 실질적으로: **불변(immutable) 객체**(`int`, `float`, `str`, `tuple`)는 값처럼 동작해 함수 안에서 재대입해도 바깥이 안 바뀐다. **가변(mutable) 객체**(`list`, `dict`, `set`)는 참조처럼 동작해 함수 안에서 내용을 수정하면 바깥도 바뀐다.
- 핵심 구분: "재대입(`x = ...`)"은 지역 이름만 새 객체로 바꿀 뿐 원본에 영향 없음. "제자리 수정(`lst[i] = ...`, `lst.append(...)`)"은 같은 객체를 건드리므로 바깥에 반영됨.

> 선행: `sorted(리스트)`는 정렬된 새 리스트를 반환하고 원본은 보존하며, `리스트.sort()`는 원본을 제자리에서 수정한다(자세한 정렬은 Ch3).

```python
def add_one(n):
    n = n + 1            # 지역 n만 바뀜 → 바깥 불변
def push(lst, x):
    lst.append(x)        # 같은 리스트를 수정 → 바깥에 반영
def rebind(lst):
    lst = [0, 0]         # 지역 이름만 새 리스트로 → 바깥 불변

a = 10; arr = [1, 2]
add_one(a)   # a는 여전히 10
push(arr, 3) # arr는 [1, 2, 3]
rebind(arr)  # arr는 여전히 [1, 2, 3]
```

**그림으로 보기**

- 파이썬의 변수는 값을 담는 상자가 아니라 **객체를 가리키는 이름표**다. 함수 호출은 그 객체에 이름표를 하나 더 붙이는 일이고, 그래서 "함수 안에서 무엇을 하느냐"에 따라 바깥이 바뀌기도 하고 안 바뀌기도 한다.

```text
  immutable : n = n + 1                # inside add_one(a)
  ---------------------
   a --> [ 10 ]                        # caller name
   n --> [ 10 ]                        # callee name, SAME object
           |  n = n + 1
           v
   n --> [ 11 ]                        # n now points at a NEW object
   a --> [ 10 ]                        # caller untouched
```

- 정수는 고칠 수 없으므로 `n + 1`은 새 객체를 만든다. `n =`은 그 새 객체로 이름표만 옮긴다. `a`의 이름표는 원래 자리에 그대로 남는다.

```text
  mutable : lst.append(x)              # inside push(arr, x)
  -----------------------
   arr --+
         +--> [ 1 , 2 ]                # ONE list, two names
   lst --+
                  |  lst.append(3)
                  v
   arr --+
         +--> [ 1 , 2 , 3 ]            # SAME object, contents grew
   lst --+
```

- 리스트는 고칠 수 있으므로 `append`는 새 객체를 만들지 않고 그 상자 안을 바꾼다. 이름표 둘이 여전히 같은 상자를 가리키므로 바깥도 함께 바뀐 것처럼 보인다.
- 2차원에서 얕은 복사가 위험한 이유도 같은 그림으로 설명된다.

```text
   grid    --> [ r0 ,  r1 ]            # outer list
                 |     |
   copy    --> [ r0 ,  r1 ]            # copy = grid[:] copies OUTER only
                 |     |
                 v     v
               [1,2] [3,4]             # SAME row objects -> shared
```

**왜 이렇게 되는가**

- **왜 파이썬에는 값 전달·참조 전달 스위치가 없나**: 규칙은 하나뿐이다 — "객체를 가리키는 참조를 값처럼 복사해 넘긴다". 넘어간 참조가 가리키는 객체가 불변이면 고칠 방법이 없어 재대입밖에 못 하고(값 전달처럼 보임), 가변이면 그 자리에서 고칠 수 있다(참조 전달처럼 보임). 두 현상은 같은 규칙의 두 얼굴이다.
- **왜 `lst = [0, 0]`은 바깥에 안 먹히나**: `=`는 객체를 고치는 연산이 아니라 이름표를 옮기는 연산이다. 지역 이름 `lst`만 새 리스트로 옮겨 붙고, 호출자의 이름표는 원래 객체에 남는다. 바깥을 바꾸려면 이름표가 아니라 객체를 건드려야 한다(`lst[0] = ...`, `lst.append(...)`).
- **왜 `grid[:]`가 2차원에서 함정인가**: 슬라이싱은 바깥 리스트의 원소들, 즉 "행 객체를 가리키는 참조들"을 복사한다. 참조를 복사한 것이지 행 자체를 복사한 게 아니므로 `copy[0][0] = 9`는 원본 행을 고친다. 각 행까지 새로 만들려면 `[r[:] for r in grid]`처럼 한 겹 더 복사해야 한다.
- **복사 비용**: 1차원 복사는 O(n), R×C 격자의 행별 복사는 O(R·C) 시간·공간이다. 참조 전달은 O(1)이라 사실상 공짜지만 방어적 복사는 공짜가 아니다. 반복문 안에서 매번 복사하면 O(반복 횟수 × n)으로 조용히 커진다.

**접근 전략**

- 함수가 값을 바꾸길 원하는가? 두 가지 길이 있다. (1) **참조 활용**: 리스트/딕셔너리를 넘겨 함수 안에서 제자리 수정 → 반환 없이 바깥이 바뀜. (2) **값 반환**: 새 값을 계산해 `return`으로 돌려주고 바깥에서 재대입. 정수·문자열을 "바꾸려면" 반드시 (2)를 써야 한다.
- 전형적 함정: 리스트를 함수에 넘겨 정렬/수정했더니 원본까지 바뀌어 버그가 남. 원본을 지키려면 함수 안에서 `lst[:]`나 `list(lst)`로 **복사본**을 만들어 작업한다. 반대로 "함수로 원본을 갱신"하고 싶으면 일부러 제자리 수정을 쓴다.
- 언제 이 개념이 결정적인가: 여러 함수가 하나의 배열/상태를 공유하며 갱신하는 시뮬레이션류. "누가 원본을 바꾸고 누가 복사본만 보는지"를 설계 단계에서 못 박아야 한다.
- 복잡도 감각: 참조 전달은 복사가 없어 O(1)로 넘어가지만, 방어적 복사(`list(lst)`)는 길이 n에 비례해 O(n) 시간·공간이 든다. 큰 배열을 반복적으로 복사하면 비용이 쌓인다.

**문제**

**1) 원본 보존 정렬** · Easy

- **요구사항**: 리스트를 인자로 받아 "오름차순 정렬된 새 리스트를 반환하되 원본은 절대 바꾸지 않는" 함수 `sorted_copy(arr)`를 설계하라. 메인에서 정렬 결과와 원본을 둘 다 출력해 원본이 그대로임을 보인다.
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 1000). 다음 줄에 `n`개의 정수(공백 구분).
- **출력**: 첫 줄에 정렬된 결과를 공백으로, 둘째 줄에 원본을 입력 순서 그대로 공백으로.
- **예제**: `5 / 3 1 2 1 5` → 
  ```

  3 1 2 1 5
  ```
- **셀프체크**: 함수 안에서 `arr.sort()`(제자리 정렬)를 쓰면 원본이 바뀐다 — 대신 복사본을 만들거나 `sorted(arr)`를 반환했는가? 중복값이 있어도 둘째 줄 원본이 손상되지 않는가?

```runner
(3) 스스로 다시 짤 때 생각 순서
```

**2) 이동 로봇 상태 갱신** · Medium

- **요구사항**: 로봇의 위치를 담은 길이 2 리스트 `pos = [r, c]`를 참조로 받아, 명령 문자열대로 제자리 수정하는 "반환값 없는" 함수 `move(pos, cmd)`를 설계하라. 명령은 `U D L R`(각각 r−1, r+1, c−1, c+1). 메인은 이 함수를 반복 호출만 하고, 마지막에 `pos`를 출력한다(참조 전달로 바깥이 갱신됨을 활용).
- **입력**: 첫 줄에 시작 좌표 `r c`. 둘째 줄에 명령 문자열(길이 1~1000, `U/D/L/R`로만 구성).
- **출력**: 모든 명령 수행 후 최종 좌표 `r c`(공백 구분).
- **예제**: `0 0 / RRUD` → `0 2`  
  (R:(0,1) → R:(0,2) → U:(-1,2) → D:(0,2))  
  `2 3 / LLU` → `1 1`  (L:(2,2) → L:(2,1) → U:(1,1))
- **셀프체크**: `move`가 `pos`를 재대입(`pos = [...]`)하지 않고 `pos[0]`, `pos[1]`을 직접 고쳤는가(재대입하면 바깥에 반영 안 됨)? 좌표가 음수가 되어도 그대로 계산하는가(경계 제한 없음)? 함수가 값을 반환하지 않는데 메인이 반환값에 의존하지 않는가?

```runner
@@SOLUTION
def move(pos, cmd):
    if cmd == 'U':
        pos[0] -= 1
    elif cmd == 'D':
        pos[0] += 1
    elif cmd == 'L':
        pos[1] -= 1
    elif cmd == 'R':
        pos[1] += 1

def main():
    r, c = map(int, input().split())
    cmds = input().strip()
    pos = [r, c]
    for ch in cmds:
        move(pos, ch)
    print(pos[0], pos[1])

main()
@@TESTS

RRUD
--OUT

--IN

--OUT

@@EXPL
**이 풀이의 새 문법**

- `문자열.strip()`: 문자열의 앞뒤에 붙은 공백(스페이스·개행 등)만 없앤 새 문자열을 돌려준다. 입력 줄 끝에 섞일 수 있는 여분의 공백/개행을 정리할 때 쓴다.

(1) 접근·핵심 아이디어

- 리스트는 가변 객체라 함수에 넘기면 "참조처럼" 동작한다. `move(pos, cmd)`가 `pos[0]`, `pos[1]`을 제자리 수정하면 반환 없이도 바깥 `pos`가 갱신된다.
- 함정: 함수 안에서 `pos = [...]`로 재대입하면 지역 이름만 바뀌고 바깥은 그대로다. 반드시 인덱스로 직접 수정해야 한다.

(2) 코드 단계별

- `move`: 명령 문자에 따라 `pos[0]`(행) 또는 `pos[1]`(열)을 ±1. 반환값 없음.
- `main`: 시작 좌표로 `pos` 리스트를 만들고 명령 문자열을 하나씩 `move`에 전달, 마지막에 `pos`를 출력.

(3) 스스로 다시 짤 때 생각 순서

- "함수로 바깥 상태를 갱신"이 목표 → 가변 리스트를 넘겨 인덱스 제자리 수정(재대입 금지) → 메인은 호출만 하고 끝에 결과를 읽는다.
```

**3) 방어적 복사 vs 공유** · Hard

- **요구사항**: 하나의 2차원 격자(리스트의 리스트)를 두 함수에 넘긴다. 함수 A는 "원본을 직접 갱신"(제자리 수정)하고, 함수 B는 "복사본에만 적용하고 결과를 반환"해야 한다. 두 방식의 차이를 출력으로 드러내라. 구체적으로: 격자의 특정 행 전체에 값을 더하는 연산을 A(원본 갱신)와 B(복사본 반환)로 각각 구현한다.
- **입력**: 첫 줄에 `R C`(1 ≤ R, C ≤ 50). 다음 `R`개 줄에 격자(정수, 공백 구분). 다음 줄에 `row add`(0-based 행 번호와 더할 값).
- **출력**: 세 개의 격자를 순서대로 출력 — (1) B가 반환한 "복사본에 연산 적용" 결과, (2) B 호출 이후의 원본(바뀌지 않아야 함), (3) A로 원본을 직접 갱신한 뒤의 격자. 각 격자 사이에 빈 줄 1개.
- **예제**: 
  ```
  2 3
  1 2 3
  4 5 6
  0 10
  ```
  → 
  ```
  11 12 13
  4 5 6

  1 2 3
  4 5 6

  11 12 13
  4 5 6
  ```
  (B는 복사본의 0행에 10을 더해 반환 → 첫 블록 · 원본은 그대로 → 둘째 블록 · A는 원본 0행을 직접 +10 → 셋째 블록)
- **셀프체크**: 2차원에서 얕은 복사(`grid[:]`)는 안쪽 행 리스트를 공유해 함정이 된다 — 각 행을 복사(`[row[:] for row in grid]`)했는가? B 호출 후 둘째 블록(원본)이 정말 안 바뀌었는가? A는 반환 없이 `grid[row][j] += add`로 제자리 수정했는가?

```runner

def add_row_copy(grid, row, add):

    for j in range(len(new_grid[row])):

    add_row_inplace(grid, row, add)
    print_grid(grid)

(1) 접근·핵심 아이디어

- 함수 B(`add_row_copy`)는 원본을 건드리지 않도록 깊은 복사(각 행을 `r[:]`)한 뒤 복사본에만 연산하고 반환 → 원본 보존.
- 함수 A(`add_row_inplace`)는 원본 격자를 제자리 수정(`grid[row][j] += add`)해 바깥을 갱신 → 반환 없음.

(2) 코드 단계별

- 입력을 줄 단위로 읽어 `R, C`, 격자, `row add`를 파싱.

(3) 스스로 다시 짤 때 생각 순서

- "복사본만 바꾸기 vs 원본 바꾸기"를 두 함수로 분리 → B는 깊은 복사 후 반환, A는 제자리 수정 → 출력 순서(B결과 → 원본 → A후)를 지켜 두 방식의 차이를 드러낸다.
```

## L4. 변수의 영역

**개념**

- 변수의 영역(스코프)은 "그 이름이 유효한 범위"다. 함수 안에서 처음 대입된 변수는 그 함수의 **지역 변수**이고, 함수 밖에서 정의된 변수는 **전역 변수**다. 함수 안에서는 지역을 먼저 보고, 없으면 바깥(전역)을 찾는다(LEGB 규칙).
- 함수 안에서 전역 변수를 **읽기**만 하면 그냥 보인다. 그러나 함수 안에서 전역 변수에 **대입**하려면 `global` 선언이 필요하다. 선언 없이 대입하면 같은 이름의 새 지역 변수가 생겨 전역은 안 바뀐다(흔한 버그).
- 스코프를 잘 쓰면 함수마다 이름이 충돌하지 않고 독립적으로 동작한다. 반대로 전역 상태를 함수들이 공유하면(카운터, 방문표 등) `global`로 명시적으로 갱신한다.

```python
count = 0                 # 전역

def tick():
    global count          # 전역을 수정하겠다고 선언
    count += 1

def wrong_tick():
    count = 100           # 새 지역 count 생성 → 전역 안 바뀜

def show(x):
    y = x * 2             # y는 지역, 함수 밖에서 못 씀
    return y
```

**그림으로 보기**

- 이름은 공중에 떠 있지 않고 **이름 공간**(namespace)이라는 상자 안에 산다. 전역 상자는 프로그램이 끝날 때까지 남고, 지역 상자는 그 함수가 실행되는 동안에만 존재한다.

```text
  global namespace              local namespace of show(x)
  +--------------------+        +--------------------+
  | count = 0          |        | x = 5              |
  | tick   = <func>    |        | y = 10             |
  | show   = <func>    |        +--------------------+
  +--------------------+         gone when show returns
        ^
        |  lookup order : Local --> Enclosing --> Global --> Builtins
        +-- a name not found in the local box is looked up here
```

- 함수 안에서 이름을 **읽을** 때는 지역 상자를 먼저 보고, 없으면 바깥 상자로 올라간다(LEGB). 그런데 **대입**은 이야기가 완전히 다르다.

```text
  wrong_tick()                   tick()
  ------------                   ------
  count = 100                    global count
       |                         count += 1
       |  makes a LOCAL name          |  rebinds the GLOBAL name
       v                              v
  local  : count = 100           global : count = 1
  global : count = 0  (!)        local  : (none)
```

**왜 이렇게 되는가**

- **왜 `global` 없이 대입하면 지역이 되나**: 파이썬은 함수 본문을 미리 훑어 "이 함수 안에서 대입되는 이름"을 전부 지역 변수로 확정해 둔다. 대입이 함수 맨 아랫줄에 딱 한 번 있어도 그 이름은 함수 전체에서 지역이다. 그래서 `count += 1`(= 읽고 나서 대입)은 아직 값이 없는 지역 `count`를 읽으려다 `UnboundLocalError`를 낸다. `global count`는 "이 이름은 지역으로 만들지 말고 전역 상자를 쓰라"는 지시다.
- **왜 읽기만 할 때는 `global`이 필요 없나**: 대입이 하나도 없으면 그 이름은 지역으로 확정되지 않는다. 그러면 LEGB 탐색이 작동해 자연스럽게 전역 상자에서 찾아 읽는다.
- **왜 리스트는 `global` 없이도 갱신되나**: `visited[v] = True`는 이름 `visited`에 대한 대입이 아니라, 그 이름이 가리키는 객체 안을 고치는 일이다. 대입되는 이름이 없으니 지역화 규칙이 발동하지 않고, LEGB로 찾아낸 전역 리스트를 그대로 제자리 수정한다. 반대로 `visited = [...]`처럼 이름 자체를 다시 묶으려 하면 그 순간부터 `global`이 필요해진다.
- **비용**: 스코프 자체는 실행 시간 비용이 없다(이름이 지역인지 전역인지는 컴파일 단계에서 대부분 결정된다). 다만 전역 공유 상태는 "누가 언제 바꿨는지"를 사람이 추적해야 해서 디버깅 비용이 커진다. 기본값은 "인자로 받고 결과는 반환", 공유가 꼭 필요할 때만 전역이다.

**접근 전략**

- 먼저 "이 변수는 함수마다 독립인가, 여러 함수가 공유하는가?"를 정한다. 독립이면 지역으로 두어 서로 간섭을 막고, 공유(누적 카운터·전역 상태)면 전역 + `global`로 명시적으로 관리한다.
- 전형적 함정: 함수 안에서 전역을 바꾸려다 `global`을 빠뜨려 "값이 안 바뀌는" 버그. 또는 반대로 지역이면 충분한데 전역을 남발해 함수 간 예상치 못한 간섭 발생. 가급적 "값은 인자로 받고 결과는 반환"하는 순수 함수를 기본으로, 꼭 공유가 필요할 때만 전역을 쓴다.
- 언제 전역이 유용한가: 재귀나 여러 보조 함수가 하나의 카운터/누적값/방문 배열을 함께 갱신해야 할 때. 다만 배열·딕셔너리 같은 가변 객체는 (L3에서 봤듯) `global` 없이 제자리 수정만으로도 공유 갱신이 가능함을 기억한다.
- 복잡도 감각: 스코프 자체는 성능 비용이 없다. 다만 전역 공유 상태는 디버깅 난이도(추적 비용)를 올리므로, "필요 최소한만 전역"이 좋은 기본값이다.

**문제**

**1) 전역 카운터** · Easy

- **요구사항**: 전역 변수 `total`(초기 0)과, 이를 `global`로 갱신하는 반환값 없는 함수 `add(x)`를 설계하라. 입력으로 주어진 수들을 `add`로 하나씩 더한 뒤 최종 `total`을 출력한다. 절대 함수의 반환값으로 합을 넘기지 말고, 전역 갱신만으로 처리하라(스코프 학습 목적).
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 1000). 다음 줄에 `n`개의 정수(공백 구분).
- **출력**: 모든 수를 더한 전역 `total`.
- **예제**: `4 / 5 -2 10 3` → `16`  
  `3 / 1 1 1` → `3`
- **셀프체크**: `add` 함수 첫 줄에 `global total`이 있는가(없으면 지역 `total`이 생겨 전역이 0으로 남는다)? 음수도 정상 누적되는가? 메인이 `total`을 직접 읽어 출력하는가?

```runner
@@SOLUTION
total = 0

def add(x):
    global total
    total += x

def main():
    n = int(input())
    vals = list(map(int, input().split()))
    for v in vals:
        add(v)
    print(total)

main()
@@TESTS
--IN
4
5 -2 10 3
--OUT
16
--IN
3
1 1 1
--OUT
3
@@EXPL
(1) 접근·핵심 아이디어

- 전역 `total`을 함수 안에서 "대입"하려면 `global total` 선언이 필수다. 선언이 없으면 함수 안에서 같은 이름의 지역 변수가 새로 생겨 전역은 0으로 남는다(대표적 스코프 버그).
- 반환값으로 합을 넘기지 않고, 오직 전역 갱신만으로 누적한다(학습 목적).

(2) 코드 단계별

- 모듈 최상단에 `total = 0`(전역) 선언.
- `add(x)`는 `global total` 후 `total += x`로 전역을 직접 누적. 반환값 없음.
- `main`은 각 수를 `add`로 더하고, 마지막에 전역 `total`을 직접 읽어 출력.

(3) 스스로 다시 짤 때 생각 순서

- "함수가 전역을 바꾼다" → 함수 첫 줄에 `global` 선언을 잊지 않는다 → 반환 대신 전역 누적 → 메인은 전역을 읽어 출력(음수도 그대로 더해짐).
```

**2) 지역/전역 충돌 진단** · Medium

- **요구사항**: 전역 `mode`(문자열)와, 함수 안에서 같은 이름의 지역 변수를 쓰는 상황을 만들어, "함수가 전역을 읽되 바꾸지는 않는" 함수와 "전역을 실제로 바꾸는" 함수를 구분해 구현하라. 명령에 따라 전역 `mode`를 바꾸거나(전역 갱신) 임시로 지역에서만 다른 값을 써 계산한 뒤 전역은 그대로 두는(지역 사용) 두 동작을 처리한다.
- **입력**: 첫 줄에 초기 `mode`(문자열, 예 `slow`). 둘째 줄에 명령 개수 `q`. 다음 `q`개 줄에 명령: `SET x`(전역 `mode`를 `x`로 영구 변경) 또는 `TEMP x`(이번 줄에서만 지역적으로 `x`인 것처럼 취급해 현재 유효 모드를 출력하되 전역은 안 바꿈) 또는 `SHOW`(현재 전역 `mode` 출력).
- **출력**: `TEMP`와 `SHOW` 명령마다 한 줄씩, 그 시점의 "유효 모드"를 출력.
- **예제**: 
  ```
  slow
  5
  SHOW
  TEMP fast
  SHOW
  SET fast
  SHOW
  ```
  → 
  ```
  slow
  fast
  slow
  fast
  ```
  (SHOW:slow · TEMP fast는 지역적으로 fast 출력하나 전역은 slow 유지 · SHOW:slow · SET fast로 전역 변경 · SHOW:fast)
- **셀프체크**: `TEMP` 처리가 전역 `mode`를 건드리지 않는가(지역 변수/인자로만 계산)? `SET` 처리 함수에는 `global mode`가 있는가? `TEMP` 직후의 `SHOW`가 여전히 이전 전역값을 보이는가(함정 지점)?

```runner
@@SOLUTION
mode = "slow"

def set_mode(x):
    global mode
    mode = x

def temp_mode(x):
    local_mode = x
    return local_mode

def show_mode():
    return mode

def main():
    global mode
    mode = input().strip()
    q = int(input())
    out = []
    for _ in range(q):
        parts = input().split()
        if parts[0] == 'SET':
            set_mode(parts[1])
        elif parts[0] == 'TEMP':
            out.append(temp_mode(parts[1]))
        elif parts[0] == 'SHOW':
            out.append(show_mode())
    print('\n'.join(out))

main()
@@TESTS
--IN

5
SHOW
TEMP fast
SHOW
SET fast
SHOW
--OUT
slow
fast
slow
fast
--IN
a
4
SHOW
SET b
SHOW
TEMP c
--OUT
a
b
c
@@EXPL
(1) 접근·핵심 아이디어

- 전역 `mode`를 "읽기만" 하는 함수(`show_mode`)와 "바꾸는" 함수(`set_mode`)를 구분한다.
- `set_mode`는 `global mode`로 전역을 영구 변경. `temp_mode`는 지역 변수에만 값을 두고 반환할 뿐 전역을 건드리지 않는다 → `TEMP` 직후 `SHOW`는 여전히 이전 전역값(함정 지점).

(2) 코드 단계별

- `set_mode(x)`: `global mode` 후 `mode = x`.
- `temp_mode(x)`: `local_mode = x`를 만들어 반환(전역 불변).
- `show_mode()`: 전역 `mode`를 읽어 반환.
- `main`: 명령을 파싱해 `SET`이면 전역 변경, `TEMP`/`SHOW`면 유효 모드를 출력 버퍼에 모아 마지막에 개행으로 출력.

(3) 스스로 다시 짤 때 생각 순서

- "영구 변경 vs 임시 값"을 두 함수로 분리 → 변경 함수에만 `global`을 붙인다 → `TEMP`는 지역/인자만 쓰므로 이후 `SHOW`가 전역을 그대로 보이는지 확인.
```

**3) 보조 함수들이 공유하는 방문 기록** · Hard

- **요구사항**: 전역 리스트 `visited`(불리언 배열)와 전역 정수 `count`를 두고, 여러 보조 함수가 이를 함께 갱신하는 구조를 설계하라. 정수 배열을 훑으며 "아직 방문 안 한 값을 처음 만나면 방문 표시하고 `count`를 1 늘리는" 동작을 보조 함수로 분리한다. `count`는 `global`로, `visited`는 가변 객체이므로 제자리 수정으로 갱신하는 차이를 스스로 확인하라.
- **입력**: 첫 줄에 `n`(1 ≤ n ≤ 100000)과 값의 상한 `M`(1 ≤ M ≤ 100000). 다음 줄에 `n`개의 정수(각 1 ≤ v ≤ M). 이 문제에서 "방문"은 "그 값을 이번에 처음 봤는지"를 뜻한다.
- **출력**: 배열에 등장한 서로 다른 값의 개수(= 최종 `count`).
- **예제**: `6 5 / 3 3 1 5 1 3` → `3`  (서로 다른 값 3,1,5 → 3개)  
  `4 10 / 7 7 7 7` → `1`
- **셀프체크**: `count`를 늘리는 보조 함수에 `global count`가 있는가? `visited`는 전역이지만 `global` 없이 `visited[v] = True`로 제자리 수정만으로 공유 갱신되는가(왜 `global`이 필요 없는지 설명할 수 있는가)? `visited` 크기를 `M+1`로 잡아 인덱스 범위를 벗어나지 않게 했는가? `n`이 최대(10만)여도 O(n)으로 한 번만 훑는가?

```runner
@@SOLUTION
import sys

count = 0
visited = []

def visit(v):
    global count
    if not visited[v]:
        visited[v] = True
        count += 1

def main():
    global visited, count
    data = sys.stdin.read().split()
    n = int(data[0]); M = int(data[1])
    vals = data[2:2 + n]
    visited = [False] * (M + 1)
    count = 0
    for s in vals:
        visit(int(s))
    print(count)

main()
@@TESTS
--IN
6 5
3 3 1 5 1 3
--OUT
3
--IN
4 10
7 7 7 7
--OUT
1
@@EXPL
(1) 접근·핵심 아이디어

- 서로 다른 값의 개수 = 각 값을 "처음 볼 때만" 세기. 전역 불리언 배열 `visited`로 이미 본 값을 표시하고, 전역 정수 `count`로 개수를 누적한다.
- 스코프 포인트: `count`는 불변 정수라 함수 안에서 대입하려면 `global count`가 필요하지만, `visited`는 가변 리스트라 `visited[v] = True`(제자리 수정)만으로 `global` 없이도 전역이 갱신된다.

(2) 코드 단계별

- `visit(v)`: 아직 방문 안 했으면 `visited[v] = True`로 표시하고 `count += 1`. `count` 갱신 때문에 `global count` 선언.
- `main`: `n, M`을 읽고 `visited`를 크기 `M+1`로 초기화(인덱스 범위 안전) → 각 값을 `visit` 호출 → 최종 `count` 출력.
- 전체를 한 번만 훑으므로 O(n).

(3) 스스로 다시 짤 때 생각 순서

- "처음 본 값만 센다"로 문제를 환원 → 방문표(가변 리스트)와 카운터(정수)를 전역으로 둔다 → 정수는 `global`, 리스트는 제자리 수정으로 갱신되는 차이를 의식 → 인덱스 범위를 `M+1`로 잡아 안전하게 한 번만 순회.
```

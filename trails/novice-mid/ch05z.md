## L5. 정리 — 개념 지도·체크리스트·자주 하는 실수

**개념**

- 이 레슨은 Ch05(시뮬레이션 II) 전체를 한 장으로 묶는 정리다. 세 레슨은 모두 "**작은 상태 몇 개를 들고 한 번 지나간다**"는 같은 습관을 배열·값·격자라는 서로 다른 무대에서 연습한 것이다.

**개념 지도**

- 훑는 대상이 배열이면 `cur/best`, 값이면 `cnt/seen`, 격자면 `dx/dy`가 된다. 셋 다 "전체를 다시 계산하지 않고, 한 걸음마다 상태를 조금씩 고친다"는 점이 같다.

```text
                    Ch05 : simulation II
                             |
      +----------------------+----------------------+
      |                      |                      |
  ONE PASS              RECORD BY VALUE       GRID + DIRECTION
  scan left to right    value is the index    dx / dy arrays
      |                      |                      |
  L1 longest run        L2 count / mark        L3 dx dy technique
  cur , best            cnt[v] += 1            (r+dx[k], c+dy[k])
  fixed window k        seen[v] = True         bounds check first
  variable window       last[v] = i            d = (d + 1) % 4
      |                      |                      |
      +----------------------+----------------------+
                             |
            hold a small state, update it once per step
```

- 그리고 이 챕터에서 반드시 외워야 하는 그림은 이것 하나다. 방향 배열과 실제 이동의 대응을 손으로 그릴 수 있으면 격자 문제의 절반은 끝난 것이다.

```text
              k=0                    neighbour order (up dn lt rt)
           (r-1, c)                  dx = [ -1,  1,  0,  0 ]
              ^                      dy = [  0,  0, -1,  1 ]
              |
   k=2 <--- (r, c) ---> k=3          clockwise ring (rt dn lt up)
              |                      dx = [  0,  1,  0, -1 ]
              v                      dy = [  1,  0, -1,  0 ]
           (r+1, c)                  d = (d + 1) % 4  turns right
              k=1                    d = (d + 3) % 4  turns left

   ┌────┬────┬────┐
   │  0 │  1 │  2 │   8-dir index map
   ├────┼────┼────┤   dx = [ -1, -1, -1,  0,  0,  1,  1,  1 ]
   │  3 │ ** │  4 │   dy = [ -1,  0,  1, -1,  1, -1,  0,  1 ]
   ├────┼────┼────┤
   │  5 │  6 │  7 │   ** = (r, c) itself
   └────┴────┴────┘
```

**뼈대 코드**

- (1) dx/dy 이웃 훑기: 격자 문제의 기본 골격.

```python
dx = [-1, 1, 0, 0]                  # ← 8방향이면 길이 8로 교체
dy = [0, 0, -1, 1]

for r in range(n):
    for c in range(m):
        for k in range(len(dx)):            # 방향 수만큼
            nr, nc = r + dx[k], c + dy[k]
            if 0 <= nr < n and 0 <= nc < m:  # 경계 검사가 먼저!
                use(grid[nr][nc])            # ← 문제마다 바뀜: 합·개수·최댓값
```

- (2) 격자 위를 걷는 시뮬레이션: 상태 → 한 스텝 → 종료 조건. 회전 규칙이 붙는 형태다.

```python
dx = [0, 1, 0, -1]                  # right, down, left, up (시계 순서)
dy = [1, 0, -1, 0]

r = c = 0                           # ← 문제마다 바뀜: 시작 위치
d = 0                               # ← 시작 방향
for step in range(total_steps):     # ← 종료 조건: 횟수·목표 도달·더 못 감
    visit(r, c)                     # 현재 칸에서 할 일
    nr, nc = r + dx[d], c + dy[d]
    if not (0 <= nr < n and 0 <= nc < n and ok(nr, nc)):
        d = (d + 1) % 4             # 못 가면 방향만 튼다
        nr, nc = r + dx[d], c + dy[d]
    r, c = nr, nc
```

- (3) 한 번 훑기: 현재 길이 `cur`와 최댓값 `best`.

```python
best = cur = 1                      # 원소가 1개 이상이면 1에서 출발
for i in range(1, n):
    if a[i] >= a[i - 1]:            # ← 문제마다 바뀜: > , >= , == , 짝수 ...
        cur += 1
    else:
        cur = 1                     # 끊기면 자기 자신부터 다시(0이 아님)
    if cur > best:                  # 갱신은 매 단계, if/else 밖에서
        best = cur
```

- (4) 슬라이딩 창: 길이가 고정일 때와 조건으로 정해질 때.

```python
# 고정 길이 k
s = sum(a[:k])
best = s                            # 음수 대비: 0이 아니라 첫 창 합
for i in range(k, n):
    s += a[i] - a[i - k]            # 들어온 값 더하고 빠진 값 뺀다
    if s > best:
        best = s

# 가변 길이: 조건을 어기면 왼쪽을 민다
left = 0
bad = 0
best = 0
for right in range(n):
    if a[right] == 0:               # ← 문제마다 바뀜: 위반 판정
        bad += 1
    while bad > 1:                  # ← 허용 한도
        if a[left] == 0:
            bad -= 1
        left += 1
    if right - left + 1 > best:
        best = right - left + 1
```

- (5) 배열 기록: 값을 인덱스로 삼아 세거나 표시한다.

```python
R = 100000                          # ← 문제마다 바뀜: 값의 최댓값
cnt = [0] * (R + 1)                 # 크기는 최댓값 + 1
seen = [False] * (R + 1)
last = [-1] * (R + 1)               # -1 = 한 번도 안 나옴

for i, v in enumerate(values):      # enumerate: (위치, 값)을 함께 준다
    cnt[v] += 1
    seen[v] = True
    last[v] = i

answer = [v for v in range(R + 1) if cnt[v] == 2]   # ← 조건은 문제마다
```

**언제 무엇을 쓰나**

| 상황 | 고르는 것 | 이유 | 복잡도 |
|---|---|---|---|
| 조건이 이어지는 최장 구간 | `cur` / `best` 한 번 훑기 | 모든 구간의 오른쪽 끝이 정확히 한 번 후보가 됨 | O(n) |
| 길이가 정확히 k인 창의 합 | 고정 슬라이딩 창 | 이동마다 두 값만 반영하면 됨 | O(n) |
| 위반 개수에 한도가 있는 최장 구간 | 가변 슬라이딩 창 | 왼쪽 포인터가 되돌아가지 않음 | O(n) |
| 몇 번 나왔나 / 누가 빠졌나 | 계수·마킹 배열 | 값이 곧 주소라 탐색이 필요 없음 | O(n + R) |
| 값 범위가 아주 크거나 실수·문자열 | 딕셔너리 | 등장한 값만 저장 | O(n) 평균 |
| 값 범위가 작고 정렬이 필요 | 계수 배열 순회 | 인덱스 순회가 곧 정렬 | O(n + R) |
| 격자에서 이웃을 본다 | dx/dy 4방향 | 갈래마다 if를 쓰지 않아도 됨 | O(n·m·4) |
| 대각선까지 이웃으로 본다 | dx/dy 8방향 | 배열 두 줄만 길이 8로 교체 | O(n·m·8) |
| 벽을 만나면 방향을 튼다 | 시계 순서 배열 + `(d+1)%4` | 나열 순서가 곧 회전 규칙 | 이동당 O(1) |
| 이미 지난 칸을 다시 밟으면 안 된다 | 방문 표시(값 0 여부 등) | 벽과 같은 실패로 취급하면 코드가 하나 | O(1) 판정 |

**✅ 마스터 체크리스트**

- [ ] 설명할 수 있다: `cur`가 "i를 오른쪽 끝으로 하는 최장 길이"라는 정의와, 그래서 한 번 훑기로 빠짐이 없는 이유.
- [ ] 설명할 수 있다: 조건이 끊겼을 때 `cur`를 0이 아니라 1로 되돌리는 이유.
- [ ] 설명할 수 있다: 고정 창에서 빠지는 인덱스가 `i-k`, 들어오는 인덱스가 `i`인 이유.
- [ ] 설명할 수 있다: 가변 창의 `while`이 안에 있는데도 전체가 O(n)인 이유(왼쪽 포인터가 되돌아가지 않음).
- [ ] 설명할 수 있다: `best`를 0이 아니라 첫 값·첫 창 합으로 초기화해야 하는 경우와 그 이유.
- [ ] 설명할 수 있다: 값을 인덱스로 쓰면 접근이 O(1)인 이유와, 배열 크기를 최댓값+1로 잡는 이유.
- [ ] 설명할 수 있다: 계수 배열의 복잡도가 O(n × R)이 아니라 O(n + R)인 이유.
- [ ] 설명할 수 있다: 배열 기록 대신 딕셔너리를 써야 하는 상황의 판단 기준.
- [ ] 설명할 수 있다: `dx[k]`, `dy[k]`가 각각 행·열 변화량이라는 대응과, 4방향 배열을 종이에 그릴 수 있다.
- [ ] 설명할 수 있다: 경계 검사를 빠뜨리면 오류가 아니라 "조용히 틀린 답"이 나오는 이유(음수 인덱스).
- [ ] 설명할 수 있다: `and`의 단축 평가 덕분에 경계 검사와 격자 접근을 한 줄에 이어 써도 안전한 이유.
- [ ] 설명할 수 있다: `(d+1) % 4`가 시계 방향이 되려면 방향 배열을 어떤 순서로 적어야 하는지.
- [ ] 설명할 수 있다: 나선 채우기에서 "벽"과 "이미 채운 칸"을 같은 실패로 취급하는 이유.
- [ ] 설명할 수 있다: 격자 전체 이웃 훑기의 복잡도를 `n·m·방향수`로 계산하고 통과 여부를 판단할 수 있다.

**⚠️ 자주 하는 실수**

**1) dx와 dy의 순서가 서로 어긋난다**

```python
# ❌ 틀린 코드
dx = [-1, 1, 0, 0]      # 상 하 좌 우
dy = [0, 0, 1, -1]      # 상 하 우 좌   <- 짝이 뒤집혔다
```

왜: `dx[2]`는 "좌"인데 `dy[2]`는 "우"라, `k=2`가 뜻하는 방향이 존재하지 않는 이동이 된다. 이웃 합처럼 순서가 상관없는 문제에서는 답이 우연히 맞아 버려 버그를 늦게 발견한다. 회전이 붙는 순간 답이 무너진다.

```python
# ✅ 고친 코드
dx = [-1, 1, 0, 0]      # 상 하 좌 우
dy = [0, 0, -1, 1]      # 같은 인덱스가 같은 방향
```

**2) 경계 검사를 빼먹는다**

```python
# ❌ 틀린 코드
for k in range(4):
    nr, nc = r + dx[k], c + dy[k]
    s += grid[nr][nc]        # nr 이 -1 이면 맨 아랫줄을 읽는다
```

왜: 파이썬의 음수 인덱스는 오류가 아니라 **반대편**을 가리킨다. `grid[-1]`은 마지막 행이므로, 위쪽 경계를 넘은 이동이 조용히 아래쪽 값을 더해 버린다. 예외가 나지 않으니 원인 찾기도 어렵다.

```python
# ✅ 고친 코드
for k in range(4):
    nr, nc = r + dx[k], c + dy[k]
    if 0 <= nr < n and 0 <= nc < m:
        s += grid[nr][nc]
```

**3) 격자를 먼저 읽고 경계를 나중에 검사한다**

```python
# ❌ 틀린 코드
if grid[nr][nc] == '*' and 0 <= nr < n and 0 <= nc < m:
    cnt += 1
```

왜: `and`는 왼쪽부터 계산하므로 경계 검사가 실행되기 전에 이미 `grid[nr][nc]`를 읽는다. 인덱스가 범위를 넘으면 오류가 나거나 반대편 값을 읽는다. 검사는 반드시 접근보다 **왼쪽**에 있어야 한다.

```python
# ✅ 고친 코드
if 0 <= nr < n and 0 <= nc < m and grid[nr][nc] == '*':
    cnt += 1
```

**4) 회전용 방향 배열을 이웃 확인용 순서로 쓴다**

```python
# ❌ 틀린 코드
dx = [-1, 1, 0, 0]       # 상 하 좌 우 (이웃 확인용 순서)
dy = [0, 0, -1, 1]
d = (d + 1) % 4          # 상 -> 하 -> 좌 -> 우 : 회전이 아니라 순간이동
```

왜: `(d+1)%4`는 "배열의 다음 칸"일 뿐이다. 배열이 시계 순서로 놓여 있어야 그 연산이 시계 회전이 된다. 상·하·좌·우 순서에서는 90도가 아니라 180도씩 튀어 나선이나 로봇 경로가 완전히 어긋난다.

```python
# ✅ 고친 코드
dx = [0, 1, 0, -1]       # 우 하 좌 상 (시계 순서)
dy = [1, 0, -1, 0]
d = (d + 1) % 4          # 이제 한 번에 90도 시계 회전
```

**5) `best` 갱신을 `else` 안에 넣는다**

```python
# ❌ 틀린 코드
for i in range(1, n):
    if a[i] > a[i - 1]:
        cur += 1
    else:
        if cur > best:   # 끊길 때만 갱신 -> 마지막 구간을 놓친다
            best = cur
        cur = 1
```

왜: 가장 긴 구간이 배열 **맨 끝**에서 끝나면 `else`가 한 번도 실행되지 않아 그 길이가 반영되지 않는다. `1 2 3 4`처럼 끝까지 이어지는 입력에서 답이 1로 나온다.

```python
# ✅ 고친 코드
for i in range(1, n):
    if a[i] > a[i - 1]:
        cur += 1
    else:
        cur = 1
    if cur > best:       # 매 단계 갱신(분기 밖)
        best = cur
```

**6) 창이 옮겨갈 때 빠지는 인덱스를 잘못 잡는다**

```python
# ❌ 틀린 코드
for i in range(k, n):
    s += a[i] - a[i - k + 1]     # 한 칸 어긋난 값을 뺀다
```

왜: 창이 `a[i-k+1 .. i]`로 옮겨가면 새로 들어온 값은 `a[i]`, 빠져나간 값은 그 직전 창의 왼쪽 끝인 `a[i-k]`다. `a[i-k+1]`은 아직 창 안에 남아 있는 값이라, 이를 빼면 합이 계속 틀어진다.

```python
# ✅ 고친 코드
for i in range(k, n):
    s += a[i] - a[i - k]         # 들어온 값 a[i], 나간 값 a[i-k]
```

**7) 기록 배열 크기를 최댓값 그대로 잡는다**

```python
# ❌ 틀린 코드
seen = [False] * n           # 번호가 1..n 인데 칸이 0..n-1 뿐
seen[n] = True               # IndexError
```

왜: 인덱스는 0부터 시작하므로 값 `n`을 담으려면 칸이 `n+1`개 있어야 한다. 0번 칸 하나를 버리더라도 `n+1`로 잡는 편이 "1번부터 쓴다"는 문장을 그대로 옮기는 길이다.

```python
# ✅ 고친 코드
seen = [False] * (n + 1)     # 0번은 버리고 1..n 을 그대로 사용
seen[n] = True
```

**다음 챕터로**

- Ch06은 "상태를 굴리며 훑는다"에서 "**후보를 빠짐없이 나열한다**"로 관점을 옮긴다. Ch05의 한 번 훑기가 O(n)짜리 영리한 순회였다면, 완전탐색은 정직하게 전부 세는 대신 "다 세도 되는가"를 먼저 계산한다.
- 여기서 익힌 격자 순회와 경계 검사는 Ch06 이후의 탐색(BFS/DFS)에서 그대로 재사용된다. dx/dy는 앞으로 계속 쓰는 도구이니 지금 확실히 손에 익혀 두자.

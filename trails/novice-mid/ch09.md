> 개요: 하나의 문제를 서로 겹치지 않고 빠짐없는 "경우(케이스)"들로 쪼개어 다루는 법을 배운다. 겹치는 구간을 정리하고, 주어진 결과로부터 원인을 추론하고, 여러 후보 전략 중 좋은 것만 추려내고, 가능한 상황을 체계적으로 나열해 답을 찾는 사고법을 익힌다.

## L1. 겹치는 경우

**개념**

- 여러 조건이 동시에 참이 될 수 있을 때, 경우를 그냥 더하면 겹치는 부분이 이중으로 세어진다. 이를 정리하는 것이 이 레슨의 핵심이다.
- 대표 도구는 두 가지다. 첫째, 포함-배제(A와 B 둘 다 세고, 겹친 A∩B를 한 번 뺀다): `|A ∪ B| = |A| + |B| − |A ∩ B|`. 둘째, "경계를 새는" 아이디어(각 원소가 정확히 한 번만 카운트되도록 조건을 배타적으로 나눈다).
- 구간이 겹치는 문제라면, "덮인 길이"는 겹친 부분을 한 번만 세야 한다. 이럴 땐 좌표를 정렬하거나 칠하기 배열(imos/누적)을 쓴다.

```python
# 1..N 중 a의 배수 또는 b의 배수의 개수 (포함-배제)
def count_multiples(N, a, b):
    import math
    lcm = a * b // math.gcd(a, b)   # math.gcd(a, b): 최대공약수를 바로 계산해 주는 표준 함수
    return N // a + N // b - N // lcm
```

**접근 전략**

- 먼저 "이 원소가 여러 조건에 동시에 해당될 수 있는가?"를 자문한다. 그렇다면 단순 합산은 틀린다. 겹치는 영역을 명시적으로 정의(A∩B가 무엇인지 말로 써 보기)하고, 포함-배제로 빼거나, 조건을 서로 배타적인 케이스로 다시 나눈다.
- 구간 덮개 유형은 정렬 후 스위핑이 정석이다. 구간을 시작점 기준 정렬하고 현재까지 덮은 오른쪽 끝(`cover_end`)을 유지하며, 새 구간이 `cover_end`와 겹치면 이어붙이고 아니면 새 덩어리로 센다. 값의 범위가 작으면 칠하기 배열이 더 단순하다.
- 복잡도: 포함-배제는 조건 수 k에 대해 부분집합 O(2^k), 구간 스위핑은 정렬이 지배해 O(M log M).

**문제**

**1) 3 또는 5의 배수 합** · Easy

- **요구사항**: 1 이상 N 이하의 정수 중 3의 배수이거나 5의 배수인 수들의 합을 구한다. 15처럼 둘 다인 수를 두 번 더하지 않도록 주의한다.
- **입력**: 첫 줄에 정수 N (1 ≤ N ≤ 10^9).
- **출력**: 조건을 만족하는 수들의 합.
- **예제**: `10` → `33` (3+5+6+9+10=33) / `15` → `60` (3+5+6+9+10+12+15=60)
- **셀프체크**: 15의 배수를 한 번만 빼는지 확인. N이 크므로 반복문 대신 등차수열 합 공식으로 계산해야 시간 초과가 없다. `k의 배수 합 = k * (m*(m+1))//2`, 여기서 `m = N//k`.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    N = int(data[0])
    def s(k):
        m = N // k
        return k * (m * (m + 1)) // 2
    print(s(3) + s(5) - s(15))
solve()
@@TESTS

@@EXPL
(1) 접근·핵심 아이디어

- "3의 배수이거나 5의 배수"의 합은 포함-배제로 구한다: (3의 배수 합) + (5의 배수 합) − (15의 배수 합). 15의 배수는 양쪽에 모두 들어가므로 한 번 빼야 이중 계산이 사라진다. N이 최대 10^9이니 반복문 대신 등차수열 합 공식으로 O(1) 계산.

(2) 코드 단계별

- `s(k)`: 1..N 중 k의 배수 합 = `k * (m*(m+1))//2`, `m = N//k` (즉 `k*(1+2+...+m)`).
- 답 = `s(3) + s(5) - s(15)`.

(3) 다시 짤 때 생각 순서

- "동시에 두 조건을 만족하는 수(15의 배수)가 이중으로 세어진다"를 먼저 인식한다 → 포함-배제.
- 각 k의 배수 합을 반복문 없이 등차수열 공식으로 바꾼다(큰 N 대비).
- 겹치는 부분은 `lcm(3,5)=15`의 배수 합이고, 정확히 한 번만 뺀다.
```

**2) 겹치는 페인트 구간의 총 길이** · Medium

- **요구사항**: 수직선 위에 N개의 페인트 구간 [Lᵢ, Rᵢ]가 칠해진다. 서로 겹칠 수 있을 때, 실제로 색이 칠해진 총 길이를 구한다.
- **입력**: 첫 줄에 N (1 ≤ N ≤ 100,000). 이어 N개의 줄에 Lᵢ, Rᵢ (0 ≤ Lᵢ < Rᵢ ≤ 10^9).
- **출력**: 색이 칠해진 총 길이.
- **예제**: `3 / 1 4 / 2 6 / 8 10` → `7` (1~6 덮여 길이 5, 8~10 덮여 길이 2) / `2 / 0 5 / 5 9` → `9` (맞닿은 구간은 이어져 0~9)
- **셀프체크**: 구간을 L 기준 정렬 후, `cover_end`보다 R이 크면 `R - max(L, cover_end)`만 더하는 방식이 안전하다. 좌표가 10^9까지이므로 칠하기 배열은 메모리 초과 — 정렬+스위핑을 써야 한다. 완전히 포함되는 구간(길이 0 추가)을 빠뜨리지 않는지 확인.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.buffer.read().split()
    idx = 0
    N = int(data[idx]); idx += 1
    segs = []
    for _ in range(N):
        L = int(data[idx]); R = int(data[idx + 1]); idx += 2
        segs.append((L, R))
    segs.sort()
    total = 0
    cover_end = -1
    for L, R in segs:
        if R <= cover_end:
            continue
        start = L if L > cover_end else cover_end
        total += R - start
        cover_end = R
    print(total)
solve()
@@TESTS

--IN

@@EXPL
(1) 접근·핵심 아이디어

- 겹칠 수 있는 구간들의 덮인 총 길이를 구할 때는, 겹친 부분을 한 번만 세야 한다. 좌표가 10^9까지라 칠하기 배열은 불가 — L 기준 정렬 후 스위핑으로 "지금까지 덮은 오른쪽 끝(cover_end)"을 유지하며 새로 덮이는 길이만 더한다.

(2) 코드 단계별

- 모든 구간을 읽어 `(L, R)`로 저장하고 L 기준 정렬.
- `cover_end = -1`로 시작. 각 구간에서 `R <= cover_end`면 이미 다 덮였으니 건너뜀.
- 아니면 새로 덮이는 시작점 `start = max(L, cover_end)`부터 `R`까지 길이 `R - start`를 더하고 `cover_end = R`로 갱신.

(3) 다시 짤 때 생각 순서

- "덮인 길이 = 겹침을 한 번만 세기"임을 인식하고 정렬+스위핑을 택한다.
- 정렬 후 cover_end로 이미 덮은 영역과의 겹침을 잘라내고 새 부분만 더한다.
- 완전히 포함되는 구간(`R <= cover_end`)은 길이 0을 더하지 않고 넘어가도록 처리한다.
```

**3) 두 원 겹침 판정** · Medium

- **요구사항**: 좌표평면 위 두 원의 중심과 반지름이 주어진다. 두 원이 "만나지 않음 / 한 점에서 접함 / 두 점에서 만남 / 한 원이 다른 원을 포함(내부, 안 만남)"의 네 경우 중 어디에 해당하는지 판정한다.
- **입력**: 첫 줄에 x1, y1, r1, 둘째 줄에 x2, y2, r2 (모두 정수).
- **출력**: 만나지 않으면 `0`, 접하면 `1`, 두 점에서 만나면 `2`, 한 원이 다른 원 내부에 완전히 포함되어 안 만나면 `-1`.
- **예제**: `0 0 3 / 5 0 1` → `0` (중심거리 5 > 3+1) / `0 0 5 / 3 0 1` → `-1` (중심거리 3 < 5−1) / `0 0 3 / 4 0 2` → `2` (거리 4, 3+2=5>4>3−2=1)
- **셀프체크**: 중심거리 d와 (r1+r2), |r1−r2|를 비교하는데, 실수 오차를 피하려면 제곱해서 비교한다(d² vs (r1+r2)², d² vs (r1−r2)²). 두 원이 완전히 같은 경우(d=0, r1=r2)의 처리 기준을 정해 둔다. 경계(정확히 접함)를 `<`가 아니라 `==`로 잡는지 확인.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    x1, y1, r1, x2, y2, r2 = map(int, data[:6])
    d2 = (x1 - x2) ** 2 + (y1 - y2) ** 2
    s = (r1 + r2) ** 2
    diff = (r1 - r2) ** 2
    if d2 > s:
        print(0)
    elif d2 == s:
        print(1)
    elif d2 < diff:
        print(-1)
    elif d2 == diff:
        print(1)
    else:
        print(2)
solve()
@@TESTS

--IN

--IN

4 0 2
--OUT

--IN

--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 두 원의 관계는 중심거리 `d`를 `r1+r2`(외접 경계)와 `|r1−r2|`(내접 경계)와 비교해 결정된다. 실수 오차를 피하려고 모든 비교를 제곱값(`d²`, `(r1+r2)²`, `(r1−r2)²`)으로만 한다.

(2) 코드 단계별

- `d2 = (x1−x2)² + (y1−y2)²`, `s = (r1+r2)²`, `diff = (r1−r2)²`.
- `d2 > s` → 서로 밖에 떨어짐, `0`.
- `d2 == s` → 외접(한 점에서 접함), `1`.
- `d2 < diff` → 한 원이 다른 원 내부에 포함, 안 만남 `-1`.
- `d2 == diff` → 내접(한 점에서 접함), `1`.
- 나머지(`diff < d2 < s`) → 두 점에서 만남, `2`.

(3) 다시 짤 때 생각 순서

- 두 경계값 `r1+r2`, `|r1−r2|`를 기준선으로 삼아 수직선을 5개 구간으로 나눈다.
- 각 구간·경계에 어떤 판정이 대응하는지 하나씩 매핑한다.
- 오차 없는 정수 비교를 위해 처음부터 전부 제곱해서 다룬다(접함은 `<`가 아닌 `==`).
```

## L2. 일어난 상황에 대한 추론

**개념**

- 결과나 부분 정보만 주고 "무슨 일이 있었는지" 혹은 "원래 값이 무엇인지"를 역으로 알아내는 유형이다. 정방향으로 시뮬레이션하는 대신, 관찰된 결과가 만들어질 수 있는 조건을 거꾸로 따진다.
- 핵심은 "이 결과를 만들 수 있는 상황은 유한하며, 각 상황을 검증할 수 있다"는 점이다. 후보를 세우고 각 후보가 관찰과 모순되지 않는지 확인한다.

```python
# 관찰: 두 수의 합 s와 곱 p를 알 때 원래 두 수를 복원
# x + y = s, x * y = p  ->  x는 t^2 - s*t + p = 0 의 근
def recover(s, p):
    disc = s * s - 4 * p
    if disc < 0:
        return None
    import math
    r = int(math.isqrt(disc))
    if r * r != disc:
        return None
    if (s - r) % 2:
        return None
    return ((s - r) // 2, (s + r) // 2)
```

- `math.isqrt(x)`는 `x`의 정수 제곱근(제곱근 이하의 최대 정수)을 부동소수점 오차 없이 정확히 계산한다. `int(x ** 0.5)`는 큰 수에서 오차로 1이 어긋날 수 있어, 완전제곱수 판정(`r * r == disc`)에는 반드시 `math.isqrt`를 쓴다.

**접근 전략**

- "정방향으로 가면 결과, 역방향으로 가면 원인"이라는 대응을 먼저 세운다. 결과를 만드는 규칙을 식으로 적고, 그 식을 미지수에 대해 푼다. 방정식이 안 되면, 원인의 후보 범위를 좁혀 하나씩 대입 검증한다.
- 관찰이 여러 개면 각 관찰이 후보 집합을 걸러내는 필터가 된다. 모든 필터를 통과하는 후보가 답이며, 후보가 0개면 "불가능", 2개 이상이면 "유일하지 않음"으로 보고해야 하는 문제도 많다.
- 복잡도: 후보 수 × 검증 비용. 후보를 방정식으로 직접 얻으면 O(1)~O(log), 범위를 훑으면 O(범위)이므로 범위를 얼마나 좁히느냐가 관건.

**문제**

**1) 사라진 점수 복원** · Easy

- **요구사항**: 어떤 반 학생 N명의 시험 점수 중 하나가 지워졌다. 지워지기 전 전체 평균이 정수 A였다는 사실과, 남은 N−1개의 점수를 안다. 지워진 점수를 복원한다.
- **입력**: 첫 줄에 N과 A, 둘째 줄에 남은 N−1개의 점수(0~100 정수).
- **출력**: 지워진 점수. 만약 0~100 범위의 정수로 복원이 불가능하면 `-1`.
- **예제**: `4 80 / 90 70 100` → `60` (합 320 필요, 남은 합 260) / `3 50 / 40 100` → `10` / `2 50 / 5` → `95`
- **셀프체크**: 전체 합은 `N*A`, 지워진 점수는 `N*A − 남은합`. 그 값이 0~100 정수 범위 밖이면 `-1`. 평균이 정수라는 조건 덕에 전체 합은 반드시 정수임을 이용한다.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    N, A = int(data[0]), int(data[1])
    rest = list(map(int, data[2:2 + (N - 1)]))
    x = N * A - sum(rest)
    print(x if 0 <= x <= 100 else -1)
solve()

@@EXPL
(1) 접근·핵심 아이디어

- 평균이 정수 A였다면 전체 합은 `N*A`로 확정된다. 지워진 점수 하나만 미지수이므로 `지워진 값 = 전체합 − 남은합`으로 곧장 역산한다. 결과가 유효 범위(0~100)를 벗어나면 복원 불가.

(2) 코드 단계별

- `N`, `A`를 읽고 남은 `N−1`개 점수를 리스트로 읽는다.
- `x = N*A − sum(rest)`로 지워진 점수를 계산.
- `0 <= x <= 100`이면 `x`, 아니면 `-1` 출력.

(3) 다시 짤 때 생각 순서

- "평균 → 전체합" 관계로 미지수를 하나로 줄인다.
- 방정식 `전체합 = 남은합 + 지워진값`을 지워진값에 대해 푼다.
- 복원 결과가 문제의 도메인 제약(0~100)을 만족하는지 마지막에 검증한다.
```

**2) 정렬 전 배열이 될 수 있었나** · Medium

- **요구사항**: 어떤 배열을 인접한 두 원소만 한 번 교환(swap 0회 또는 1회)했더니 지금의 배열 B가 되었다. 원래 배열은 오름차순 정렬 상태였다고 한다. B가 이런 과정으로 만들어질 수 있는지 판정한다.
- **입력**: 첫 줄에 N, 둘째 줄에 B의 N개 원소(서로 다른 정수).
- **출력**: 가능하면 `YES`, 불가능하면 `NO`.
- **예제**: `4 / 1 3 2 4` → `YES` (정렬본 1 2 3 4에서 3,2 인접 교환) / `4 / 1 2 3 4` → `YES` (교환 0회) / `4 / 2 4 1 3` → `NO`
- **셀프체크**: 정렬된 배열과 B를 비교해 서로 다른 위치를 모은다. 다른 위치가 0개면 YES(교환 안 함), 정확히 2개이고 그 둘이 인접하며 값이 서로 뒤바뀐 관계면 YES, 그 외는 NO. "인접"과 "값이 서로 스왑됨" 두 조건을 모두 확인해야 하는 함정.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    N = int(data[0])
    B = list(map(int, data[1:1 + N]))
    S = sorted(B)
    diff = [i for i in range(N) if B[i] != S[i]]
    if len(diff) == 0:
        print("YES")
    elif len(diff) == 2:
        i, j = diff
        if j == i + 1 and B[i] == S[j] and B[j] == S[i]:
            print("YES")
        else:
            print("NO")
    else:
        print("NO")
solve()

- 원래 배열은 정렬 상태였고 인접 교환을 0회 또는 1회 했다. 정렬본 `S`와 관찰 `B`를 자리별로 비교하면 "달라진 자리"의 개수가 곧 어떤 교환이 있었는지 알려준다. 가능한 결과는 매우 제한적이다.

(2) 코드 단계별

- `S = sorted(B)`로 원래(정렬) 상태를 복원.
- `S`와 `B`가 다른 인덱스 목록 `diff`를 만든다.
- `diff`가 0개 → 교환 안 함, YES.
- `diff`가 정확히 2개이고 두 인덱스가 인접(`j==i+1`)하며 값이 서로 뒤바뀐(`B[i]==S[j]`, `B[j]==S[i]`) 관계면 YES.
- 그 외(1개·3개 이상, 인접 아님, 스왑 아님)는 NO.

(3) 다시 짤 때 생각 순서

- "역추론: 결과 B에서 무슨 교환이 있었나"로 뒤집는다. 원래 상태는 sorted(B).
- 달라진 자리 수로 케이스를 가른다(0개 / 2개 / 그 외).
- 2개일 때는 "인접" + "값 스왑" 두 조건을 모두 확인하는 함정을 놓치지 않는다.
```

**3) 신호등이 만든 대기 시간** · Hard

- **요구사항**: 한 신호등이 초록불 g초 → 빨간불 r초를 무한 반복한다(시각 0에 초록불 시작). 어떤 차가 시각 t에 도착해 관찰된 "대기 시간"이 w였다. 이 관찰이 가능한지 판정하고, 가능하다면 g, r로 설명되는 사이클 내 도착 위치를 구한다.
- **입력**: 첫 줄에 g, r (1 ≤ g, r ≤ 10^9), 둘째 줄에 t, w (0 ≤ t, 0 ≤ w).
- **출력**: 관찰이 규칙과 일치하면 사이클 내 도착 오프셋(`t mod (g+r)`)을 출력, 모순이면 `-1`.
- **예제**: `5 3 / 12 1` → `4` (사이클 8, 오프셋 4는 빨간불(5~7)이라 대기 3? 아래 확인) / `5 3 / 4 0` → `4` (오프셋 4는 초록 구간 0~4, 대기 0)
- **셀프체크**: 오프셋 `o = t mod (g+r)`을 구한다. `o < g`이면 초록불이라 대기 0이어야 하고, 아니면 빨간불이라 대기는 `(g+r) − o`여야 한다. 관찰 w가 이 값과 다르면 `-1`. 첫 예제는 o=4<5라 대기 0이 맞아 관찰 1은 모순 → 실제로는 `-1`이 정답이다. 예제의 함정을 스스로 검산해 규칙을 정확히 세우는 것이 이 문제의 핵심.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    g, r, t, w = int(data[0]), int(data[1]), int(data[2]), int(data[3])
    period = g + r
    o = t % period
    if o < g:
        expected = 0
    else:
        expected = period - o
    print(o if w == expected else -1)
solve()

(1) 접근·핵심 아이디어

- 신호는 주기 `g+r`로 반복하므로, 도착 시각 `t`는 사이클 내 오프셋 `o = t mod (g+r)` 하나로 상황이 결정된다. 관찰된 대기 `w`가 규칙과 일치하는지 역으로 검증한다.

(2) 코드 단계별

- 오프셋 `o = t % (g+r)`를 구한다.
- `o < g`이면 초록 구간 → 대기 0이어야 함. 아니면 빨간 구간 → 대기 `(g+r) − o`여야 함.
- 이 기대 대기와 관찰 `w`가 같으면 `o`를, 다르면 `-1`을 출력.

(3) 다시 짤 때 생각 순서

- "정방향: 오프셋 → 대기 시간" 규칙을 먼저 정확히 세운다(예제의 함정을 손으로 검산).
- 관찰이 그 규칙으로 설명되는지 확인하는 역방향 검증으로 뒤집는다.
- 초록/빨강 경계(`o < g` vs `o >= g`)를 명확히 나눈다.
```

## L3. 좋은 전략을 추려내기

**개념**

- 답이 될 수 있는 후보 전략(선택지)이 여럿일 때, 명백히 손해인 것들을 논리로 배제하고 "좋은 후보"만 남겨 그중에서 답을 찾는 유형이다. 모든 경우를 다 계산하기엔 많지만, 좋은 후보만 남기면 몇 개 안 된다.
- 자주 쓰는 배제 논리는 교환 논증(exchange argument): "만약 A 대신 B를 골라도 결과가 나빠지지 않는다"를 보이면 A는 굳이 볼 필요가 없다. 또 "극단(최소/최대)에서 답이 나온다"는 관찰로 후보를 양 끝으로 좁히기도 한다.

```python
# 예: 두 물건 중 하나만 살 때, 항상 (가격 대비 이득)이 큰 쪽이 후보
# 지배당하는(어떤 다른 선택보다 모든 면에서 나쁜) 선택을 걸러내기
def prune_dominated(items):  # items: (cost, value)
    items.sort(key=lambda it: (it[0], -it[1]))
    best_value = -1
    kept = []
    for cost, value in items:      # 비용이 작을수록 먼저
        if value > best_value:     # 더 싸면서 가치도 낮으면 지배당함 -> 버림
            kept.append((cost, value))
            best_value = value
    return kept
```

**접근 전략**

- "이 후보가 다른 후보에게 지배당하는가?"를 판단 기준으로 삼는다. 어떤 선택 X가, 다른 선택 Y에 비해 모든 평가 축에서 같거나 나쁘면 X는 절대 유일 최적이 아니므로 버려도 된다. 남은 비지배(파레토) 후보만 비교하면 된다.
- 극값 관찰도 강력하다. 목적함수가 단조롭거나 볼록/오목이면 최적은 경계나 정렬 후 양 끝, 혹은 한 번의 전환점에서 발생한다. "정렬해 놓고 앞/뒤/전환점만 보라"가 전형적 패턴이다.
- 복잡도: 후보 정렬 O(n log n) 후 한 번 훑어 지배 제거 O(n). 좋은 후보가 상수 개로 줄면 최종 비교는 O(1)~O(k).

**문제**

**1) 어떤 쿠폰을 쓸까** · Easy

- **요구사항**: 상품 가격이 P다. 정액 할인 쿠폰(a원 할인)과 정률 할인 쿠폰(b% 할인) 중 하나만 쓸 수 있다. 최종 지불액이 더 작은 쪽을 골라 그 금액을 출력한다(할인 후 음수면 0원).
- **입력**: 첫 줄에 P, a, b (정수, 0 ≤ b ≤ 100).
- **출력**: 더 저렴한 최종 지불액(정수, 정률 할인은 내림).
- **예제**: `10000 3000 20` → `7000` (정액 7000 vs 정률 8000) / `10000 1000 20` → `8000` (정액 9000 vs 정률 8000)
- **셀프체크**: 두 후보 금액을 각각 계산해 `min`을 취하면 된다. 정률 할인액은 `P*b//100`, 정액 후 음수 방지는 `max(0, P-a)`. 두 전략을 "명시적으로 나열해 비교"하는 가장 단순한 형태다.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    P, a, b = int(data[0]), int(data[1]), int(data[2])
    flat = max(0, P - a)
    rate = P - P * b // 100
    print(min(flat, rate))
solve()

(1) 접근·핵심 아이디어

- 후보 전략이 딱 둘(정액 쿠폰, 정률 쿠폰)뿐이므로, 각각의 최종 지불액을 계산해 더 작은 쪽을 고르면 된다. "좋은 전략 추려내기"의 가장 단순한 형태 — 나열이 2개다.

(2) 코드 단계별

- 정액: `flat = max(0, P - a)` (할인 후 음수는 0원으로 막음).
- 정률: `rate = P - P*b//100` (할인액을 내림해서 뺌).
- `min(flat, rate)` 출력.

(3) 다시 짤 때 생각 순서

- 선택지를 전부 나열한다 → 여기선 두 개.
- 각 선택지의 결과값 공식을 정확히 세운다(음수 방지, 정률 내림 주의).
- 최종적으로 min을 취한다.
```

**2) 회의실 하나, 최대 회의 수** · Medium

- **요구사항**: 회의실 하나에 N개의 회의 신청이 있다. 각 회의는 시작·종료 시각이 있고 시간이 겹치면 동시에 못 연다. 열 수 있는 회의의 최대 개수를 구한다.
- **입력**: 첫 줄에 N (1 ≤ N ≤ 100,000). 이어 각 줄에 시작 s, 종료 e (0 ≤ s < e).
- **출력**: 최대 회의 개수.
- **예제**: `3 / 1 3 / 2 5 / 4 6` → `2` (1~3, 4~6) / `3 / 1 4 / 1 4 / 1 4` → `1`
- **셀프체크**: 좋은 전략은 "끝나는 시각이 빠른 회의를 먼저 고른다"이다. 왜 시작 시각이나 길이 기준이 아닌지 교환 논증으로 스스로 납득해 볼 것. 종료 시각으로 정렬하고, 마지막으로 선택한 회의의 종료 시각 이상으로 시작하는 회의만 골라 카운트한다. 종료=다음 시작이 허용인지(`e ≤ s`) 경계 규칙을 정한다.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    N = int(data[0])
    idx = 1
    meetings = []
    for _ in range(N):
        s = int(data[idx]); e = int(data[idx + 1]); idx += 2
        meetings.append((e, s))
    meetings.sort()
    cnt = 0
    last = -1
    for e, s in meetings:
        if s >= last:
            cnt += 1
            last = e
    print(cnt)
solve()

(1) 접근·핵심 아이디어

- 고전적 활동 선택(activity selection) 그리디다. "종료 시각이 가장 빠른 회의를 먼저 고르면 뒤에 남는 시간이 최대"라는 교환 논증이 핵심. 종료 시각 오름차순으로 보며 겹치지 않는 회의를 탐욕적으로 잡는다.

(2) 코드 단계별

- 각 회의를 `(종료 e, 시작 s)`로 저장하고 종료 시각 기준으로 정렬한다.
- `last`(마지막으로 선택한 회의의 종료 시각)를 −1로 두고, 시작이 `last` 이상인 회의만 선택하며 `last`를 그 종료 시각으로 갱신.
- 선택한 개수 `cnt`를 출력.

(3) 다시 짤 때 생각 순서

- "무엇으로 정렬해야 손해가 없나?" → 종료 시각. (시작·길이 기준이 왜 틀리는지 반례로 확인)
- 정렬 후 한 번 훑으며 `s >= last`이면 잡는다.
- 경계 규칙(이전 종료 = 다음 시작 허용)을 `>=`로 처리한다.
```

**3) 두 그룹으로 나눠 차이 최소화** · Hard

- **요구사항**: N개의 물건 무게가 주어진다. 이를 두 그룹으로 나눠 두 그룹 무게 합의 차이를 최소로 만들고 싶다. 단 N이 작다(N ≤ 20). 최소 차이를 구한다.
- **입력**: 첫 줄에 N, 둘째 줄에 N개의 무게(양의 정수).
- **출력**: 두 그룹 합 차이의 최솟값.
- **예제**: `4 / 1 6 11 5` → `1` ({11,1} vs {6,5}=합 12,11) / `2 / 3 3` → `0`
- **셀프체크**: N이 20 이하라 각 물건을 A/B에 넣는 2^N 경우를 다 볼 수 있지만, 절반씩 나눠(meet in the middle) 후보를 추려 정렬·이분탐색하면 더 빠르다. 우선 완전탐색으로 정확성을 잡고, 겹치는 부분합을 정리하는 방식으로 후보를 줄이는 감각을 익힌다. 전체합 S에 대해 한 그룹 합 h가 정해지면 차이는 `|S − 2h|`임을 이용.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    N = int(data[0])
    w = list(map(int, data[1:1 + N]))
    S = sum(w)
    best = S
    for mask in range(1 << N):
        h = 0
        for i in range(N):
            if mask & (1 << i):
                h += w[i]
        d = abs(S - 2 * h)
        if d < best:
            best = d
    print(best)
solve()
@@TESTS
--IN

1 6 11 5
--OUT
1
--IN
2
3 3
--OUT
0
--IN

1 2 3 4 5
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 한 그룹에 들어갈 물건 집합을 정하면 나머지는 자동으로 다른 그룹이다. 한 그룹 합을 `h`라 하면 두 그룹 차이는 `|S − 2h|`. N ≤ 20이니 각 물건을 A/B에 넣는 모든 `2^N` 조합을 비트마스크로 나열해 최소 차이를 찾는다.

(2) 코드 단계별

- 전체합 `S`를 구하고 `best`를 S로 초기화(한 그룹이 비면 차이 = S).
- `mask`를 0부터 `2^N−1`까지 돌며, 켜진 비트에 해당하는 물건만 한 그룹으로 골라 합 `h`를 만든다.
- `|S − 2h|`가 지금까지의 `best`보다 작으면 갱신한다.

(3) 다시 짤 때 생각 순서

- "두 그룹으로 나눈다 = 한 그룹을 정하는 부분집합 선택"이라는 대응을 먼저 세운다.
- 차이를 `|S − 2h|` 한 식으로 표현해 두면 각 부분집합을 O(1)로 평가할 수 있다.
- N이 작을 때는 정확성 우선으로 완전탐색을 짜고, 필요하면 meet-in-the-middle로 가속한다.
```

## L4. 가능한 상황을 나열하기

**개념**

- 경우의 수가 크지 않을 때, 가능한 모든 상황을 빠짐없이·중복 없이 나열하고 각각을 평가해 답을 고르는 유형이다. 앞의 완전탐색과 닮았지만, 여기서는 "상황을 몇 개의 굵직한 케이스로 분류"하는 것이 초점이다.
- 나열의 축을 잘 잡는 것이 관건이다. 무엇을 기준으로 케이스를 가르면 각 케이스가 서로 겹치지 않고(배타적) 모두를 덮는지(완전) 설계한다.

```python
# 예: 동전 몇 종류로 금액 만들기 - 각 동전 개수를 나열
# 3원, 5원 동전으로 정확히 금액 T 만들기가 가능한지
def can_make(T):
    for a in range(T // 3 + 1):        # 3원 동전 개수를 나열
        rem = T - 3 * a
        if rem >= 0 and rem % 5 == 0:  # 나머지를 5원으로
            return True
    return False
```

**접근 전략**

- "케이스를 가르는 축"을 먼저 정한다. 예: 부호(양/음/0), 크기 관계(a<b, a=b, a>b), 개수의 홀짝, 어떤 원소가 그룹의 최댓값이냐 등. 각 축은 상호배타적이고 합쳐서 전체를 덮어야 한다(빠짐·중복 검사).
- 각 케이스 안에서는 문제가 훨씬 단순해진다. 케이스별로 답을 구한 뒤 전체 답으로 합치거나(합·최대·최소), "가능한 케이스가 하나라도 있으면 YES" 식으로 종합한다.
- 나열이 유한하고 작을 때 쓴다. 케이스 수 C × 케이스당 처리 비용으로 복잡도를 잡는다. C가 상수면 사실상 O(케이스당 비용).

**문제**

**1) 삼각형이 될 수 있는가** · Easy

- **요구사항**: 세 막대 길이가 주어진다. 이 세 막대로 (넓이가 양수인) 삼각형을 만들 수 있는지 판정한다.
- **입력**: 한 줄에 세 정수 a, b, c (1 ≤ 각 값 ≤ 10^9).
- **출력**: 삼각형이 되면 `YES`, 아니면 `NO`.
- **예제**: `3 4 5` → `YES` / `1 2 3` → `NO` (1+2=3, 일직선) / `10 1 1` → `NO`
- **셀프체크**: 세 변 중 가장 긴 것을 M이라 할 때, 나머지 두 변의 합이 M보다 커야만 삼각형이다(같으면 일직선이라 NO). 세 부등식을 다 확인해도 되지만 "가장 긴 변 하나만 검사"로 케이스를 줄이는 아이디어가 핵심. 합이 int 오버플로 우려 없는지(파이썬은 무관하지만 사고 습관으로) 점검.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    a, b, c = int(data[0]), int(data[1]), int(data[2])
    x, y, z = sorted((a, b, c))
    print("YES" if x + y > z else "NO")
solve()

(1) 접근·핵심 아이디어

- 삼각형 부등식은 원래 세 개("각 변 < 나머지 두 변의 합")지만, 가장 긴 변에 대한 부등식만 통과하면 나머지 둘은 자동으로 성립한다. 그래서 정렬해 가장 큰 변 `z`에 대해 `x + y > z` 한 번만 검사하면 된다.

(2) 코드 단계별

- 세 값을 `sorted`로 정렬해 `x <= y <= z`를 얻는다.
- `x + y > z`이면 넓이가 양수인 삼각형(`YES`), 같거나 작으면 일직선/불가(`NO`).

(3) 다시 짤 때 생각 순서

- "케이스를 줄이는 축"을 먼저 찾는다 → 가장 긴 변 하나만 보면 된다.
- 정렬로 가장 큰 변을 맨 뒤로 보낸 뒤 부등식 하나만 검사한다.
- 경계(`x+y == z`, 일직선)는 삼각형이 아니므로 `>` (엄격)로 잡는 것을 잊지 않는다.
```

**2) 두 직선의 교점 상황** · Medium

- **요구사항**: 두 직선 a₁x + b₁y = c₁, a₂x + b₂y = c₂가 주어진다. 두 직선이 "한 점에서 만남 / 평행하고 서로 다름(교점 없음) / 완전히 겹침(교점 무한)" 중 어떤 상황인지 판정한다.
- **입력**: 첫 줄에 a₁ b₁ c₁, 둘째 줄에 a₂ b₂ c₂ (정수).
- **출력**: 한 점에서 만나면 `1`, 평행·별개면 `0`, 완전히 겹치면 `-1`.
- **예제**: `1 1 2 / 1 -1 0` → `1` (교점 (1,1)) / `1 1 2 / 2 2 5` → `0` (평행, 별개) / `1 1 2 / 2 2 4` → `-1` (같은 직선)
- **셀프체크**: 행렬식 `D = a₁b₂ − a₂b₁`을 본다. D≠0이면 유일 교점(`1`). D=0이면 평행인데, `a₁c₂ − a₂c₁`과 `b₁c₂ − b₂c₁`이 모두 0이면 같은 직선(`-1`), 아니면 별개(`0`). 계수가 0인 퇴화 케이스(a=b=0 등)를 입력으로 안 준다고 가정할지 문제에서 명시하는지 확인.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    a1, b1, c1 = int(data[0]), int(data[1]), int(data[2])
    a2, b2, c2 = int(data[3]), int(data[4]), int(data[5])
    D = a1 * b2 - a2 * b1
    if D != 0:
        print(1)
    elif a1 * c2 - a2 * c1 == 0 and b1 * c2 - b2 * c1 == 0:
        print(-1)
    else:
        print(0)
solve()
@@TESTS
--IN
1 1 2
1 -1 0
--OUT
1
--IN
1 1 2
2 2 5
--OUT
0
--IN
1 1 2
2 2 4
--OUT

@@EXPL
(1) 접근·핵심 아이디어

- 두 직선의 관계는 계수 행렬식 `D = a₁b₂ − a₂b₁` 하나로 케이스가 갈린다. D≠0이면 유일 교점, D=0이면 평행(같은 직선이거나 별개). 실수 나눗셈 없이 정수 곱만으로 판정해 오차가 없다.

(2) 코드 단계별

- `D`를 계산해 0이 아니면 `1`(한 점에서 만남).
- D=0이면 두 방정식이 상수배 관계인지 확인: `a₁c₂ − a₂c₁`과 `b₁c₂ − b₂c₁`이 모두 0이면 같은 직선(`-1`).
- 그 외 D=0이면 평행하지만 별개(`0`).

(3) 다시 짤 때 생각 순서

- "겹침 판정은 나눗셈이 아니라 행렬식으로"라는 원칙을 먼저 떠올린다.
- D≠0 / D=0을 큰 분기로 두고, D=0 안에서 "같은 직선 vs 별개"를 상수배 조건으로 세분한다.
- 상수배 조건은 c에 대한 교차곱 두 개가 모두 0인지로 확인한다.
```

**3) 주사위 세 개로 상금 계산** · Medium

- **요구사항**: 1~6이 적힌 주사위 세 개를 굴려 나온 눈 a, b, c로 상금을 계산한다. 규칙: (1) 세 눈이 모두 같으면 10000 + 그 눈×1000, (2) 두 눈만 같으면 1000 + 같은 눈×100, (3) 셋 다 다르면 (가장 큰 눈)×100. 상금을 출력한다.
- **입력**: 한 줄에 세 정수 a, b, c (1 ≤ 각 값 ≤ 6).
- **출력**: 규칙에 따른 상금.
- **예제**: `2 2 2` → `12000` / `3 3 6` → `1300` / `6 2 5` → `600`
- **셀프체크**: 세 케이스가 서로 배타적이고 전부를 덮는지 확인 — "모두 같음", "정확히 둘만 같음", "모두 다름"이 그 셋이다. 세 값을 집합으로 만들어 원소 수가 1/2/3인지로 케이스를 가르면 깔끔하다. 두 눈이 같은 경우 "같은 눈"이 무엇인지(빈도 2인 값) 정확히 골라내는지, 셋 다 다를 때 최댓값을 쓰는지 점검.

```runner
@@SOLUTION
import sys
def solve():
    data = sys.stdin.read().split()
    a, b, c = int(data[0]), int(data[1]), int(data[2])
    vals = {a, b, c}
    if len(vals) == 1:
        print(10000 + a * 1000)
    elif len(vals) == 2:
        for v in vals:
            if [a, b, c].count(v) == 2:
                same = v
                break
        print(1000 + same * 100)
    else:
        print(max(a, b, c) * 100)
solve()

(1) 접근·핵심 아이디어

- 세 눈의 상황은 "모두 같음 / 정확히 둘만 같음 / 모두 다름" 세 가지로 배타적이며 전부를 덮는다. 이 축을 서로 다른 값의 개수(집합 크기 1/2/3)로 잡으면 케이스 분류가 자연스럽다.

(2) 코드 단계별

- `vals = {a, b, c}` 로 서로 다른 값의 개수를 센다.
- 크기 1 → 세 눈이 모두 같음: `10000 + 눈*1000`.
- 크기 2 → 정확히 둘만 같음: 세 값 중 빈도가 2인 값을 찾아 `1000 + 같은눈*100`.
- 크기 3 → 모두 다름: `max*100`.

(3) 다시 짤 때 생각 순서

- 먼저 "케이스를 무엇으로 가를까?"를 정한다 → 서로 다른 값의 개수.
- 각 케이스 공식을 규칙 그대로 옮긴다.
- 크기 2일 때 "같은 눈"은 빈도 2인 값임을 잊지 않는다(빈도 1인 값이 아님).
```

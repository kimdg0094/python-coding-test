## L5. 추가 연습 — 핵심 반복 × 유형 확장

**개념**

- 이 레슨은 Ch1(함수)의 핵심 — 반환 없는/있는 함수, 여러 값 반환, 기본 인자, 값 전달 vs 참조 전달, 변수의 영역 — 을 **반복 훈련**하고, 코딩테스트 단골 유형을 "함수로 쪼개서 푸는" 연습으로 **확장**하는 세트다.
- **반복 훈련 개념**
- 반환 없는 함수(부수 효과만): `def show(x): print(...)` — 호출한 쪽은 반환값을 쓰지 않는다.
- 반환 있는 함수·여러 값 반환: `return a, b, c` → `x, y, z = f(...)` 로 튜플 언패킹.
- 기본 인자: `def f(price, rate=10)` — 인자를 생략하면 기본값 `10`이 쓰인다.
- 참조 전달(리스트 인자 제자리 수정): `arr[i] = v` 는 바깥에 반영되지만 `arr = [...]` 재대입은 반영되지 않는다.
- 변수의 영역: 함수 안에서 전역 정수를 바꾸려면 `global cnt` 선언이 필수. 매 질의마다 전역을 **초기화**하는 것도 잊기 쉽다.
- **코딩테스트 출제 맵**: 백준 「단계별로 풀어보기」의 '함수' 단계(자기 자신을 만드는 수, 자릿수 규칙 판정 유형), 프로그래머스 「코딩테스트 고득점 Kit」의 '완전탐색'(모든 쌍 검사), 『이것이 취업을 위한 코딩테스트다』의 '구현' 파트(명령 처리 시뮬레이션) — 모두 "판정/계산 부품을 함수로 떼어낸 뒤 메인에서 조립"하는 형태로 풀린다.
- **문제 구성표**

**문제**

**1) 막대 그래프 출력기** · Easy

- **요구사항**: 항목 이름 `label`과 값 `value`를 받아 `label|` 뒤에 `#`을 `value`개 이어 붙인 한 줄을 출력하는, 값을 반환하지 않는 함수 `print_bar(label, value)`를 만들어라. 메인은 입력 줄마다 이 함수를 호출만 한다.
- **입력**: 첫 줄에 항목 수 `n`(1 ≤ n ≤ 20). 다음 `n`개 줄에 `label value`(`label`은 공백 없는 알파벳 1~10자, 0 ≤ value ≤ 30).
- **출력**: 항목마다 한 줄씩 `label|####` 형식(`#`은 `value`개). `value`가 0이면 `label|`만 출력한다.
- **예제**: `3 / mon 3 / tue 0 / wed 5` → `mon|###` / `tue|` / `wed|#####`
- **셀프체크**: `value`가 0일 때 `'#' * 0`이 빈 문자열이 되어 `label|`만 나오는가? `label`과 `|` 사이에 공백이 끼지 않았는가(`print(label, ...)`처럼 쉼표로 넘기면 공백이 생긴다)? 함수가 값을 돌려주지 않는데 메인이 `x = print_bar(...)`처럼 반환값을 기대하지 않았는가?

```runner
@@SOLUTION
def print_bar(label, value):
    print(label + '|' + '#' * value)

def main():
    n = int(input())
    for _ in range(n):
        parts = input().split()
        print_bar(parts[0], int(parts[1]))

main()

@@EXPL
(1) 접근·핵심 아이디어

- "한 항목을 한 줄로 그리는 일"은 결과값이 필요 없는 순수한 출력 작업이므로 반환 없는 함수 `print_bar`가 자연스럽다. 메인은 무엇을 그릴지(입력 파싱)만 맡고, 어떻게 그릴지는 함수에 위임한다.
- 막대는 문자열 곱 `'#' * value`로 만든다. `value == 0`이면 빈 문자열이 되어 `label|`만 남는 것이 경계값이다.

(2) 코드 단계별

- `print_bar`: `label + '|' + '#' * value`를 문자열 덧셈으로 이어 붙여 한 번에 출력. `print(label, '|', ...)`처럼 쉼표로 넘기면 사이에 공백이 끼므로 덧셈으로 붙인다.
- `main`: 첫 줄 `n`을 읽고, 각 줄을 `split()`으로 나눠 `parts[0]`(이름)과 `int(parts[1])`(값)을 함수에 전달. 반환값은 받지 않는다.

(3) 스스로 다시 짤 때 생각 순서

- "출력만 하는 일"인지 확인 → 반환 없는 함수로 결정 → 달라지는 부분(이름·값)을 매개변수로 뽑는다 → 값 0인 경계를 손으로 찍어 형식(`label|`)을 확인.
```

**2) 초를 시·분·초로** · Easy

- **요구사항**: 초 단위 정수 `sec`를 받아 `(시, 분, 초)` 세 값을 **한 번에 반환**하는 함수 `to_hms(sec)`를 만들어라. 메인은 반환된 튜플을 `h, m, s`로 받아 출력한다. 시는 24를 넘어도 그대로 둔다(날짜로 넘기지 않는다).
- **입력**: 첫 줄에 질의 수 `n`(1 ≤ n ≤ 100). 다음 `n`개 줄에 정수 `sec`(0 ≤ sec ≤ 1,000,000).
- **출력**: 질의마다 한 줄에 `h m s`(공백 구분).
- **예제**: `2 / 3661 / 59` → `1 1 1` / `0 0 59` · `1 / 0` → `0 0 0`
- **셀프체크**: 분은 `(sec % 3600) // 60`처럼 "시를 뗀 나머지"에서 구했는가(`sec // 60`을 그대로 쓰면 분이 60을 넘는다)? `sec = 0`에서 `0 0 0`이 나오는가? 함수가 세 값을 `return h, m, s`로 돌려주고 메인이 `h, m, s = to_hms(...)`로 받는가?

```runner
@@SOLUTION
def to_hms(sec):
    h = sec // 3600
    m = (sec % 3600) // 60
    s = sec % 60
    return h, m, s

def main():
    n = int(input())
    for _ in range(n):
        h, m, s = to_hms(int(input()))
        print(h, m, s)

main()

@@EXPL
(1) 접근·핵심 아이디어

- 시·분·초는 하나의 계산에서 동시에 나오는 세 결과이므로, 함수 하나가 튜플 `(h, m, s)`로 묶어 반환하고 호출한 쪽에서 언패킹하는 것이 깔끔하다.
- 함정은 분 계산이다. `sec // 60`은 "전체 분"이라 60을 넘을 수 있다. 시(3600초)를 먼저 떼어낸 나머지 `sec % 3600`에서 분을 구해야 0~59 범위가 된다.

(2) 코드 단계별

- `to_hms`: `h = sec // 3600`, `m = (sec % 3600) // 60`, `s = sec % 60`을 계산해 `return h, m, s`(튜플).
- `main`: 질의마다 정수를 읽어 `h, m, s = to_hms(...)`로 세 값을 한꺼번에 받고 `print(h, m, s)`.
- `90000`처럼 하루(86400)를 넘는 값도 `h = 25`로 그대로 두는 것이 요구사항이다.

(3) 스스로 다시 짤 때 생각 순서

- "결과가 여러 개"이면 튜플 반환을 떠올린다 → 시/분/초 공식을 세우고 분에서 `% 3600`을 먼저 적용하는지 확인 → `0`과 `86399`(23 59 59)로 경계를 검산.
```

**3) 기본 할인율 계산기** · Easy

- **요구사항**: 가격 `price`와 할인율 `rate`(%)를 받아 할인 후 가격을 반환하는 함수 `discounted(price, rate=10)`을 만들어라. 할인율이 입력에 없으면 **기본 인자** `10`이 적용되어야 한다. 할인액은 `price * rate // 100`(정수 나눗셈, 소수점 버림)으로 계산한다.
- **입력**: 첫 줄에 질의 수 `n`(1 ≤ n ≤ 100). 다음 `n`개 줄에 `price` 하나만 있거나 `price rate` 두 값(1 ≤ price ≤ 1,000,000, 0 ≤ rate ≤ 100).
- **출력**: 질의마다 할인 후 가격을 한 줄에 하나씩.
- **예제**: `3 / 1000 / 1000 25 / 999` → `900` / `750` / `900` · `2 / 500 0 / 500 100` → `500` / `0`
- **셀프체크**: 값이 하나뿐인 줄에서 `discounted(price)`처럼 두 번째 인자를 생략해 기본값이 쓰이게 했는가? `999`의 10%는 `99`(버림)이라 `900`이 되는가? `rate = 100`이면 `0`, `rate = 0`이면 원가 그대로가 나오는가?

```runner
@@SOLUTION
def discounted(price, rate=10):
    return price - price * rate // 100

def main():
    n = int(input())
    for _ in range(n):
        parts = input().split()
        if len(parts) == 1:
            print(discounted(int(parts[0])))
        else:
            print(discounted(int(parts[0]), int(parts[1])))

main()

@@EXPL
**이 풀이의 새 문법**

- 기본 인자 `def discounted(price, rate=10)`: 매개변수에 `=값`을 붙이면 호출할 때 그 인자를 생략할 수 있고, 생략하면 적힌 기본값이 들어간다. 기본값이 있는 매개변수는 없는 매개변수보다 뒤에 둬야 한다.

(1) 접근·핵심 아이디어

- "대부분은 10% 할인, 가끔만 다른 할인율"이라는 상황은 기본 인자의 전형적 쓰임이다. 호출하는 쪽은 특별한 경우에만 `rate`를 넘기고, 나머지는 함수가 알아서 기본값을 쓴다.
- 할인액을 `price * rate // 100`으로 곱셈을 먼저 한 뒤 정수 나눗셈을 해야 버림 오차가 작다(`price // 100 * rate`는 결과가 달라질 수 있다).

(2) 코드 단계별

- `discounted(price, rate=10)`: `price - price * rate // 100`을 반환. 연산 우선순위상 `*`와 `//`가 먼저, 뺄셈이 나중이다.
- `main`: 줄을 `split()`한 토큰 수가 1이면 `discounted(price)`(기본값 사용), 2이면 두 번째 토큰을 `rate`로 넘긴다.
- 경계: `rate = 0`이면 할인액 0, `rate = 100`이면 가격 전액이 할인되어 `0`, `price = 7`이면 `7 * 10 // 100 = 0`이라 그대로 `7`.

(3) 스스로 다시 짤 때 생각 순서

- "생략 가능한 인자"가 보이면 기본 인자를 떠올린다 → 토큰 수로 생략 여부를 판단해 호출 방식을 나눈다 → 곱셈 먼저·나눗셈 나중 순서를 확인하고 `999`, `7`로 버림 경계를 검산.
```

**4) 가위바위보 전적 집계** · Medium

- **요구사항**: 한 판의 결과를 판정하는 값 반환 함수 `judge(a, b)`(A가 이기면 `1`, 지면 `-1`, 비기면 `0`)와, 전체 판을 훑어 `(승, 패, 무)` 세 값을 튜플로 반환하는 함수 `tally(A, B)`를 만들어라. 메인은 전적을 출력한 뒤 승이 많으면 `A`, 패가 많으면 `B`, 같으면 `DRAW`를 출력한다. `R`(바위)은 `S`(가위)를, `S`는 `P`(보)를, `P`는 `R`을 이긴다.
- **입력**: 첫 줄에 A의 손 문자열, 둘째 줄에 B의 손 문자열(각각 `R`/`P`/`S`로만 구성, 길이 1~1000, 두 줄의 길이는 같다).
- **출력**: 첫 줄에 A 기준 `승 패 무`(공백 구분), 둘째 줄에 `A`/`B`/`DRAW` 중 하나.
- **예제**: `RPS / SPR` → `1 1 1` / `DRAW` · `RRPS / SSSS` → `2 1 1` / `A`
- **셀프체크**: `judge`가 같은 손일 때 `0`을 가장 먼저 반환하는가? 이기는 조합 세 가지(`R>S`, `S>P`, `P>R`)만 `1`이고 나머지는 `-1`로 떨어지는가? `tally`가 세 카운터를 튜플로 한 번에 돌려주고 메인이 `w, l, d = tally(A, B)`로 받는가? 전부 비긴 경우 `DRAW`가 나오는가?

```runner
@@SOLUTION
def judge(a, b):
    if a == b:
        return 0
    if (a == 'R' and b == 'S') or (a == 'S' and b == 'P') or (a == 'P' and b == 'R'):
        return 1
    return -1

def tally(A, B):
    win = 0
    lose = 0
    draw = 0
    for i in range(len(A)):
        r = judge(A[i], B[i])
        if r == 1:
            win += 1
        elif r == -1:
            lose += 1
        else:
            draw += 1
    return win, lose, draw

def main():
    A = input().strip()
    B = input().strip()
    w, l, d = tally(A, B)
    print(w, l, d)
    if w > l:
        print('A')
    elif l > w:
        print('B')
    else:
        print('DRAW')

main()

@@EXPL
(1) 접근·핵심 아이디어

- 문제를 두 층으로 쪼갠다. 아래층 `judge(a, b)`는 "한 판의 승패"라는 작은 질문에 `1/-1/0`으로 답하고, 위층 `tally(A, B)`는 이 부품을 판마다 호출해 세 카운터를 누적한 뒤 튜플로 돌려준다. 메인은 튜플을 받아 출력·판정만 한다.
- 이기는 조합은 딱 세 가지뿐이므로, 같은 손(무승부)을 먼저 걸러낸 뒤 세 조합만 `1`, 나머지는 자동으로 `-1`이 되게 조기 반환으로 짧게 쓴다.

(2) 코드 단계별

- `judge`: `a == b`면 `0`, 세 가지 이기는 조합이면 `1`, 그 외 `-1`.
- `tally`: 인덱스 `i`로 두 문자열을 같은 위치끼리 짝지어 `judge` 결과에 따라 `win/lose/draw`를 늘리고 `return win, lose, draw`.
- `main`: `w, l, d`로 언패킹해 첫 줄 출력, `w`와 `l`의 대소로 둘째 줄 출력. 같으면(전부 무승부 포함) `DRAW`.

(3) 스스로 다시 짤 때 생각 순서

- "한 판 판정"과 "전체 집계"를 분리 → 판정 함수는 무승부부터 조기 반환 → 집계 함수는 세 값을 튜플로 반환 → `RRR/RRR`(전부 무) 같은 경계로 `DRAW` 분기를 검산.
```

**5) 구간 뒤집기 명령 처리** · Medium

- **요구사항**: 리스트 `arr`와 구간 `[l, r]`을 받아 그 구간의 원소 순서를 **제자리에서** 뒤집는, 값을 반환하지 않는 함수 `reverse_range(arr, l, r)`를 만들어라. 함수 안에서 `arr = ...` 재대입이나 새 리스트 반환 없이, 인덱스 교환만으로 원본이 바뀌게 한다. 메인은 명령마다 함수를 호출하고 마지막에 리스트를 출력한다.
- **입력**: 첫 줄에 `n q`(1 ≤ n ≤ 100, 1 ≤ q ≤ 100). 둘째 줄에 정수 `n`개. 다음 `q`개 줄에 `l r`(0-based, 0 ≤ l ≤ r < n).
- **출력**: 모든 명령을 적용한 뒤의 리스트를 공백으로 구분해 한 줄에.
- **예제**: `5 2 / 1 2 3 4 5 / 0 4 / 1 3` → `5 2 3 4 1` · `3 1 / 7 8 9 / 1 1` → `7 8 9`
- **셀프체크**: 함수 안에서 `arr = arr[::-1]`처럼 재대입하면 지역 이름만 바뀌어 바깥이 그대로다 — 인덱스 교환(`arr[l], arr[r] = arr[r], arr[l]`)으로 제자리 수정했는가? `l == r`이면 아무 일도 안 일어나는가? 같은 구간을 두 번 뒤집으면 원래대로 돌아오는가(검산용)?

```runner
def reverse_range(arr, l, r):
    while l < r:
        arr[l], arr[r] = arr[r], arr[l]
        l += 1
        r -= 1

def main():

    arr = list(map(int, input().split()))
    for _ in range(q):
        l, r = map(int, input().split())
        reverse_range(arr, l, r)
    print(' '.join(map(str, arr)))

- 리스트는 가변 객체라 함수에 넘기면 참조처럼 동작한다. 양 끝 인덱스 `l`, `r`을 안쪽으로 좁혀 가며 `arr[l]`과 `arr[r]`을 맞바꾸면, 반환 없이도 메인의 `arr`가 그대로 바뀐다.
- 함정: 함수 안에서 `arr = arr[::-1]`이나 `arr = 새 리스트`로 재대입하면 지역 이름만 새 객체를 가리켜 바깥은 변하지 않는다. "재대입은 안 되고 인덱스 수정은 된다"가 이 문제의 핵심이다.

(2) 코드 단계별

- `main`: 명령마다 `l, r`을 읽어 함수를 호출만 하고, 마지막에 `' '.join(map(str, arr))`로 출력.
```

**6) 우박수 단계 수 세기** · Medium

- **요구사항**: 전역 정수 `steps`(호출 횟수)를 두고, 다음 값을 돌려주는 함수 `next_value(x)`가 호출될 때마다 `global`로 `steps`를 1 늘리게 하라. 규칙은 짝수면 `x // 2`, 홀수면 `3x + 1`. 함수 `count_steps(x)`는 `steps`를 0으로 초기화한 뒤 `x`가 1이 될 때까지 `next_value`를 반복 호출하고 최종 `steps`를 반환한다. 질의가 여러 개이므로 **질의마다 전역을 초기화**해야 한다.
- **입력**: 첫 줄에 질의 수 `n`(1 ≤ n ≤ 20). 다음 `n`개 줄에 정수 `x`(1 ≤ x ≤ 1,000,000).
- **출력**: 질의마다 1에 도달하기까지 `next_value`가 호출된 횟수를 한 줄에 하나씩.
- **예제**: `3 / 6 / 1 / 27` → `8` / `0` / `111` · `2 / 6 / 1` → `8` / `0`

**7) 가장 가까운 두 점** · Medium

- **요구사항**: 두 점의 거리 제곱을 반환하는 함수 `dist2(p, q)`와, 점 리스트에서 모든 두 점 쌍을 검사해 가장 작은 거리 제곱을 반환하는 함수 `closest_pair(points)`를 만들어라. 제곱근을 쓰지 않고 정수인 거리 제곱으로만 비교한다.
- **입력**: 첫 줄에 점의 수 `n`(2 ≤ n ≤ 100). 다음 `n`개 줄에 좌표 `x y`(−1000 ≤ x, y ≤ 1000, 같은 점이 두 번 나올 수 있다).
- **출력**: 가장 가까운 두 점 사이 거리의 제곱.
- **예제**: `4 / 0 0 / 3 4 / 1 1 / 10 10` → `2` · `2 / 5 5 / 5 5` → `0`
- **셀프체크**: 쌍을 `i < j`로만 돌려 같은 쌍을 두 번 세거나 자기 자신과 비교하지 않았는가? "최솟값" 초기값을 0으로 두면 어떤 쌍도 갱신되지 않는다 — 첫 쌍으로 초기화하거나 `-1` 같은 표식을 썼는가? 같은 점이 겹치면 `0`이 나오는가? 복잡도는 O(n²)이므로 `n = 100`이면 약 5,000쌍뿐이다.

```runner
@@SOLUTION
def dist2(p, q):
    dx = p[0] - q[0]
    dy = p[1] - q[1]
    return dx * dx + dy * dy

def closest_pair(points):
    best = -1
    for i in range(len(points)):
        for j in range(i + 1, len(points)):
            d = dist2(points[i], points[j])
            if best == -1 or d < best:
                best = d
    return best

def main():
    n = int(input())
    points = []
    for _ in range(n):
        x, y = map(int, input().split())
        points.append((x, y))
    print(closest_pair(points))

main()

- "가장 가까운 쌍"은 모든 쌍을 다 재 보면 확실하다(완전탐색). 점이 100개면 쌍은 약 5,000개라 충분히 빠르다.
- 거리 계산을 `dist2` 부품으로 분리하면 메인 루프는 "모든 쌍을 돌며 최솟값 갱신"이라는 뼈대만 남아 읽기 쉽다. 제곱근 없이 거리 제곱으로 비교해도 대소 관계는 같으므로 정수만으로 정확하게 푼다.

(2) 코드 단계별

- `dist2(p, q)`: `dx`, `dy`를 구해 `dx*dx + dy*dy` 반환. 점은 `(x, y)` 튜플이라 `p[0]`, `p[1]`로 접근.
- `closest_pair`: `best = -1`(아직 없음 표식)에서 시작해 `i < j`인 모든 쌍을 돌며 더 작은 거리가 나오면 갱신. 초기값을 0으로 두면 어떤 양수도 갱신되지 않으니 주의.
- `main`: 점을 튜플로 모아 리스트에 담고 결과를 출력.

(3) 스스로 다시 짤 때 생각 순서

- "모든 쌍"이면 이중 루프 `j = i + 1`부터 → 거리 부품을 먼저 완성해 `(0,0)-(3,4) = 25`로 검산 → 최솟값 초기값 표식 방식을 정한다 → 같은 점 두 개(`0`)로 경계 확인.
```

**8) 이웃 합이 가장 큰 칸** · Medium

- **요구사항**: 격자 안 좌표인지 판정하는 함수 `in_range(r, c, R, C)`와, 어떤 칸의 상·하·좌·우 이웃 값 합을 반환하는 함수 `neighbor_sum(grid, r, c)`를 만들어라. 격자 밖 이웃은 없는 것으로 친다. 모든 칸에 대해 이웃 합을 구해 최댓값과 그 칸의 위치를 출력한다. 최댓값이 여러 칸이면 행 번호가 작은 칸, 같으면 열 번호가 작은 칸을 고른다.
- **입력**: 첫 줄에 `R C`(1 ≤ R, C ≤ 20). 다음 `R`개 줄에 격자 값(각 0 ≤ v ≤ 100, 공백 구분).
- **출력**: 첫 줄에 최대 이웃 합, 둘째 줄에 그 칸의 `r c`(0-based).
- **예제**: `3 3 / 1 2 3 / 4 5 6 / 7 8 9` → `21` / `2 1` · `1 1 / 5` → `0` / `0 0`
- **셀프체크**: 이웃 네 방향 각각을 `in_range`로 걸러 격자 밖 인덱스를 읽지 않는가(음수 인덱스는 에러가 아니라 뒤에서부터 읽어 **틀린 답**을 낸다)? 최댓값 동률일 때 먼저 만난 칸(행 우선 순회)을 유지하려면 `>`로만 갱신해야 한다(`>=`면 뒤 칸으로 바뀐다)? 1×1 격자는 이웃이 없어 `0`인가?

```runner
@@SOLUTION
import sys

def in_range(r, c, R, C):
    return 0 <= r < R and 0 <= c < C

def neighbor_sum(grid, r, c):
    R = len(grid)
    C = len(grid[0])
    total = 0
    if in_range(r - 1, c, R, C):
        total += grid[r - 1][c]
    if in_range(r + 1, c, R, C):
        total += grid[r + 1][c]
    if in_range(r, c - 1, R, C):
        total += grid[r][c - 1]
    if in_range(r, c + 1, R, C):
        total += grid[r][c + 1]
    return total

def main():
    data = sys.stdin.read().split('\n')

    grid = []
    for i in range(1, R + 1):
        grid.append(list(map(int, data[i].split())))

    br = 0
    bc = 0
    for r in range(R):
        for c in range(C):
            s = neighbor_sum(grid, r, c)
            if s > best:
                best = s
                br, bc = r, c
    print(best)
    print(br, bc)

(1) 접근·핵심 아이디어
```

**9) 계좌 이체 시뮬레이션** · Hard

- **요구사항**: 잔액 리스트 `balance`를 여러 함수가 **참조로 공유**하며 갱신하는 시뮬레이션을 설계하라. `deposit(balance, a, x)`는 계좌 `a`에 `x`를 입금하는 반환 없는 함수, `transfer(balance, a, b, x)`는 `a`의 잔액이 `x` 이상일 때만 `a`에서 `b`로 옮기고 `True`를, 부족하면 아무 변화 없이 전역 `fail_count`를 1 늘리고 `False`를 반환한다. 메인은 성공한 이체 수를 반환값으로 세고, 실패 수는 전역에서 읽는다.
- **입력**: 첫 줄에 계좌 수 `n`과 명령 수 `q`(1 ≤ n ≤ 50, 1 ≤ q ≤ 100). 둘째 줄에 초기 잔액 `n`개(0 ≤ 잔액 ≤ 10,000). 다음 `q`개 줄에 `D a x`(입금) 또는 `T a b x`(이체, `a ≠ b`). 계좌 번호는 0-based, 1 ≤ x ≤ 10,000.
- **출력**: 첫 줄에 최종 잔액 `n`개(공백 구분), 둘째 줄에 `성공한 이체 수 실패한 이체 수`.
- **예제**: `3 4 / 100 50 0 / T 0 1 30 / T 1 2 100 / D 2 5 / T 2 0 10` → `70 80 5` / `1 2` · `2 1 / 10 0 / T 0 1 10` → `0 10` / `1 0`
- **셀프체크**: 잔액이 정확히 `x`인 경우 이체가 성공하는가(`<` 와 `<=` 경계)? 실패 시 잔액이 전혀 바뀌지 않는가(빼기 전에 검사)? `fail_count`를 늘리는 함수에 `global`이 있는가, 반면 `balance`는 `global` 없이 인덱스 수정만으로 공유되는 이유를 설명할 수 있는가? 입금·이체 합계로 총액이 보존되는지(입금액만큼만 늘어남) 검산했는가?

```runner
@@SOLUTION
import sys

fail_count = 0

def deposit(balance, a, x):
    balance[a] += x

def transfer(balance, a, b, x):
    global fail_count
    if balance[a] < x:
        fail_count += 1
        return False
    balance[a] -= x
    balance[b] += x
    return True

def main():
    data = sys.stdin.read().split('\n')
    n, q = map(int, data[0].split())
    balance = list(map(int, data[1].split()))
    ok = 0
    for i in range(2, 2 + q):
        parts = data[i].split()
        if parts[0] == 'D':
```

**10) 생성자 없는 수** · Hard

- **요구사항**: 양의 정수 `m`에 대해 `gen(m) = m + (m의 각 자릿수 제곱의 합)`을 "m이 만드는 수"라 하자. 예를 들어 `gen(12) = 12 + 1 + 4 = 17`이다. `1` 이상 `N` 이하의 수 중 **어떤 `m`으로도 만들어지지 않는 수**의 개수와, 그런 수 중 가장 작은 것과 가장 큰 것을 출력하라. 자릿수 제곱합을 반환하는 함수 `digit_square_sum(m)`, `gen(m)`을 반환하는 함수, 그리고 "만들어진 수" 표시 리스트 `made`를 인자로 받아 제자리에서 표시하는 반환 없는 함수 `mark(made, m, N)`으로 나눠 구현한다.
- **입력**: 한 줄에 정수 `N`(1 ≤ N ≤ 5000).
- **출력**: 첫 줄에 개수, 둘째 줄에 `가장 작은 수 가장 큰 수`(공백 구분). `1`은 어떤 수로도 만들어지지 않으므로 답이 없는 경우는 없다.
- **예제**: `10` → `8` / `1 10` · `30` → `19` / `1 29`
- **셀프체크**: `gen(m)`이 `N`을 넘으면 리스트 범위를 벗어나므로 `mark`에서 `g <= N`일 때만 표시했는가? `made`는 크기 `N + 1`로 잡아 인덱스 `N`까지 쓸 수 있는가? `mark`가 리스트를 재대입하지 않고 `made[g] = True`로 제자리 수정하는가? `N = 30`에서 30은 `gen(5) = 30`으로 만들어지므로 가장 큰 답이 29임을 손으로 확인했는가?

```runner
def digit_square_sum(m):
    s = 0
    while m > 0:
        d = m % 10
        s += d * d
        m //= 10
    return s

def gen(m):
    return m + digit_square_sum(m)

def mark(made, m, N):
    g = gen(m)
    if g <= N:
        made[g] = True

def main():
    N = int(input())
    made = [False] * (N + 1)
    for m in range(1, N + 1):
        mark(made, m, N)
    cnt = 0
    smallest = -1
    largest = -1
    for x in range(1, N + 1):
        if not made[x]:
            cnt += 1
            if smallest == -1:
                smallest = x
            largest = x
    print(cnt)
    print(smallest, largest)

(1) 접근·핵심 아이디어

- "만들어지지 않는 수"를 직접 찾기는 어렵지만, 반대로 "만들어지는 수"는 `m = 1..N`을 돌며 `gen(m)`을 계산해 표시하면 전부 알 수 있다. 표시되지 않은 수가 답이다. `gen(m) > m`이므로 `N`보다 큰 `m`은 볼 필요가 없다.
- 세 함수의 책임: `digit_square_sum`(계산 부품, 값 반환) → `gen`(부품 조립, 값 반환) → `mark`(표시 리스트를 참조로 받아 제자리 수정, 반환 없음). 메인은 이 부품들을 순서대로 호출하고 집계만 한다.
- 함정: `gen(m)`이 `N`을 넘을 수 있으므로 `mark`에서 `g <= N` 검사가 없으면 인덱스 에러가 난다.

(2) 코드 단계별

- `digit_square_sum`: `m % 10`으로 한 자리씩 떼어 제곱을 더하고 `m //= 10`으로 줄인다.
- `mark(made, m, N)`: `g = gen(m)`이 `N` 이하일 때만 `made[g] = True`. 리스트를 제자리 수정하므로 `global`도 반환도 필요 없다.
- `main`: `made = [False] * (N + 1)`로 인덱스 `N`까지 확보 → 모든 `m`에 `mark` → `1..N`을 훑으며 표시 안 된 수를 세고, 처음 만난 것을 `smallest`, 마지막으로 만난 것을 `largest`로 기록.
- `N = 5000`이어도 `gen` 계산은 5,000번뿐이라 즉시 끝난다.

(3) 스스로 다시 짤 때 생각 순서

- "없는 것을 세기"를 "있는 것을 표시하기"로 뒤집는다 → 계산 함수·조립 함수·표시 함수로 책임을 나눈다 → 표시 리스트 크기와 `g <= N` 경계를 못 박는다 → `N = 10`을 손으로(2와 6만 만들어짐 → 8개) 검산.
```
